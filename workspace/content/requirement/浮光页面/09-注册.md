# PG-09 注册

依据：[浮光画板 10-2](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT/?node-id=10-2)；对应新页面 `/register`，源码 `frontend/src/components/fuguang/auth-pages.tsx`。页面为本地 mock，字段和可见行为用于需求分析；固定样例值和成功提示不证明真实业务已实现。

## 展示字段与数据量

表中的存储名称是本轮新设计的逻辑表，未建表；建议分页量不是既有API合同。

| 区域     | 必须承载的字段                              | 设计归属                        | 一次读取 / 保存的量                            |
| -------- | ------------------------------------------- | ------------------------------- | ---------------------------------------------- |
| 建号输入 | 显示名≤32、登录名、密码、确认密码、可用提示 | user_account；确认密码只验证    | 一账号；可用提示需真实检查且提交时仍靠唯一约束 |
| 密码规则 | 至少10位、同时含字母与数字、两次一致        | 密码hash；不存明文/confirmation | 客户端提示和服务端验证同规则                   |

## 功能与失败边界

| 当前动作 | 必须产生的结果                       | 边界与失败                                               |
| -------- | ------------------------------------ | -------------------------------------------------------- |
| 创建账号 | 自助注册制作者，成功建立会话进入首页 | 管理员角色只能管理员创建；登录名不可改，重复返回字段错误 |
| 返回登录 | 直接切换认证入口                     | 不预设邀请码、邮件验证或组织创建；这些未出现在当前设计   |

## 最小设计结论

注册保留为当前需求，不能再以旧接口没有公开注册为理由降级或取消。 物理字段与关系见[新数据设计](../../design/浮光页面数据设计.md)，请求/响应见[新接口设计](../../design/浮光页面接口设计.md)。

## 验收证据

- 逐项核上述字段与动作，包括空值、失败和权限；业务写入须刷新后保留，冲突不覆盖他人修改。静态/临时状态不套用持久化验收。
- 返回数据只服务当前显示或操作；统计需能复算；mock数值与真实值明确分开。
- 验收遵循[新页面验收](../浮光页面非功能与验收.md)。本轮只形成设计，没有宣称真实功能完成。
