# PG-16 系统健康

依据：[浮光画板 19-2](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT/?node-id=19-2)；对应新页面 `/health`，源码 `frontend/src/components/fuguang/admin-pages.tsx`。页面为本地 mock，字段和可见行为用于需求分析；固定样例值和成功提示不证明真实业务已实现。

## 展示字段与数据量

表中的存储名称是本轮新设计的逻辑表，未建表；建议分页量不是既有API合同。

| 区域   | 必须承载的字段                                          | 设计归属                          | 一次读取 / 保存的量                              |
| ------ | ------------------------------------------------------- | --------------------------------- | ------------------------------------------------ |
| 健康卡 | 降级原因、15分钟失败率、unknown/manual、Outbox积压/最旧 | generation_job + 可观测数据适配器 | 固定卡片，返回window/as_of/availability          |
| 分组   | 供应商1小时结果、队列积压/Worker/负载                   | 供应商调用结果和部署监控          | 实际分组摘要，不返回原始日志                     |
| 入口   | 30秒刷新、去处理、Grafana/Temporal UI链接               | 部署配置的可用链接                | 未部署组件显示不可用；这些标签不强制整个旧技术栈 |

## 功能与失败边界

| 当前动作        | 必须产生的结果                         | 边界与失败                                                 |
| --------------- | -------------------------------------- | ---------------------------------------------------------- |
| 刷新 / 自动刷新 | 查询真实指标；局部错误保留最后成功时间 | 不能像mock点击就恢复正常；不可用不是0                      |
| 去处理 / 监控   | 跳到对应凭据或任务上下文，监控只读     | 任务处理可先在当前页面上下文呈现，不据此添加旧全局任务产品 |

## 最小设计结论

不建health/queue_snapshot表；监控设施选型另行按真实运行需求决定。 物理字段与关系见[新数据设计](../../design/浮光页面数据设计.md)，请求/响应见[新接口设计](../../design/浮光页面接口设计.md)。

## 验收证据

- 逐项核上述字段与动作，包括空值、失败和权限；业务写入须刷新后保留，冲突不覆盖他人修改。静态/临时状态不套用持久化验收。
- 返回数据只服务当前显示或操作；统计需能复算；mock数值与真实值明确分开。
- 验收遵循[新页面验收](../浮光页面非功能与验收.md)。本轮只形成设计，没有宣称真实功能完成。
