# PG-13 供应商凭据

依据：[浮光画板 16-2](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT/?node-id=16-2)；对应新页面 `/providers`，源码 `frontend/src/components/fuguang/admin-pages.tsx`。页面为本地 mock，字段和可见行为用于需求分析；固定样例值和成功提示不证明真实业务已实现。

## 展示字段与数据量

表中的存储名称是本轮新设计的逻辑表，未建表；建议分页量不是既有API合同。

| 区域     | 必须承载的字段                                                   | 设计归属                                       | 一次读取 / 保存的量                    |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| 供应商卡 | 名称、能力摘要、可用/测试失败/未配置、密钥掩码、最近测试、操作者 | provider当前配置与安全测试摘要                 | 所有已接入供应商的少量摘要；密钥不回显 |
| 新密钥   | API Key、可选Group ID、保存并测试                                | 仅服务端短时测试输入；成功才替换provider加密值 | 一次候选请求，失败不写为活动密钥       |

## 功能与失败边界

| 当前动作              | 必须产生的结果                                  | 边界与失败                                                             |
| --------------------- | ----------------------------------------------- | ---------------------------------------------------------------------- |
| 配置 / 更新：先测后换 | 用新输入测试，成功后原子替换旧值并记操作者/时间 | 这是当前页面明确语义，不改成旧接口的先保存后测试；测试超时也保留旧密钥 |
| 测试当前连接          | 读取当前凭据在服务端测试并更新安全结果          | 连通、配额、鉴权失败分别归类；费用未知不能标免费                       |

## 最小设计结论

一次测试与替换足以承载页面，无需通用审批平台；需防并发覆盖。 物理字段与关系见[新数据设计](../../design/浮光页面数据设计.md)，请求/响应见[新接口设计](../../design/浮光页面接口设计.md)。

## 验收证据

- 逐项核上述字段与动作，包括空值、失败和权限；业务写入须刷新后保留，冲突不覆盖他人修改。静态/临时状态不套用持久化验收。
- 返回数据只服务当前显示或操作；统计需能复算；mock数值与真实值明确分开。
- 验收遵循[新页面验收](../浮光页面非功能与验收.md)。本轮只形成设计，没有宣称真实功能完成。
