# 浮光全页面需求总览

本次依据 2026-10-08 用户要求，将 18 个画板对应的页面逐项拆为 139 条功能需求。目标是把已提交的视觉原型转为可评审、可实施、可验证的需求。用户授权的是需求和设计整理；新增产品政策、公开认证、建表及业务实现仍须依据本次评审结论推进。

## 阅读顺序与事实来源

1. [产品需求 PRD](../../prd/PRD-浮光全页面.md)：问题、用户、价值、范围、目标和发布顺序。
2. 本页与下方 18 份页面需求：功能表、规则、状态、失败处理、验收条件。
3. [数据库设计](../../design/浮光页面数据设计.md)与[接口设计](../../design/浮光页面接口设计.md)：当前可复用合同、规划增量、事务和错误。
4. [非功能与验收](../浮光页面非功能与验收.md)及[需求追踪矩阵](../../test/浮光页面需求追踪.md)：指标、测试数据、场景和逐项覆盖。

## 功能性分析：跨页闭环

| 链路       | 起点 → 结果                                 | 必须保持的业务事实                                             | 主要依赖                 |
| ---------- | ------------------------------------------- | -------------------------------------------------------------- | ------------------------ |
| 身份       | 管理员建账号 → 登录 → 强制改密 → 工作台     | 账号状态/角色/会话服务端判断；当前本机身份与未来消费者认证分开 | PG-08～12、D-01          |
| 项目与剧本 | 首页建项目 → 导入 → 确认分集/结构           | 创建成功不等于导入成功；正式剧本版本可追溯                     | PG-01；已有 SCR 页面合同 |
| 资产定稿   | 设定条目 → 造型 → 上传/生成 → 确认参考/音色 | 原始素材、候选、当前正式引用分离；授权有效                     | PG-06/07、D-05           |
| 镜头生产   | 分镜 → 镜头编辑 → 报价 → 确认 → 候选 → 选定 | 固定输入/模型/价格版本；不重复付费；任务不覆盖人工配置         | PG-03/04、Operation/预算 |
| 画布精修   | 引入同一镜头 → 配参考 → 生成 → 提升正式结果 | 与分镜一份事实；布局保存不能代替业务写入                       | PG-02/03                 |
| 运维追溯   | 分析异常 → 原任务 → 审计/健康               | unknown不当失败重发；聚合缺失不显示成功或零                    | PG-05/15/16              |

剧本、资产定稿、独立配音、任务中心、项目设置、影响清单和成本虽然出现在导航或既有业务需求中，但没有本轮对应独立 Figma 画板。它们仍按既有 REQ/SCR/GEN/PRJ 合同实施；不因“18页齐全”宣称完整生产链已验收。新增画板由后续设计补充，不在本轮伪造视觉依据。

## 通用交互与权限

| 使用者 / 状态          | 可读                           | 可写                                | 禁止                             |
| ---------------------- | ------------------------------ | ----------------------------------- | -------------------------------- |
| 未认证成员（目标模式） | 登录、明确开放的激活入口       | 认证、受限激活                      | 项目/媒体/管理数据               |
| 必须改密的成员         | 本人受限状态                   | 改密、登出                          | 项目与费用动作                   |
| producer               | 当前组织有权项目和自己的个人库 | 制作、报价确认、候选选定、本人设置  | 管理账号/凭据/注册表/审计/健康   |
| admin                  | producer范围与管理页面         | 管理命令，仍受版本/最后管理员等约束 | 绕过审计、读取密钥、改写历史账本 |
| 已归档/回收项目        | 依正式读取合同                 | 仅允许明确的恢复等管理动作          | 继续生成或修改正式内容           |
| Agent                  | 当前会话获准的只读工具         | 提案由人确认后通过原业务命令        | 直接写库、直接付费、越项目读取   |

共享导航：项目切换、全局搜索/命令面板、通知、账号菜单必须有范围。通知与命令面板在原型中部分为 toast，正式接入遵循 NTF-01 与 REQ-05；不得用“所有更改已保存”的静态文案替代命令确认。所有写按钮遵循 G1/G2，生成遵循 G3/G4，过期传播遵循 G5，审计遵循 G6，异步状态遵循 G7。
