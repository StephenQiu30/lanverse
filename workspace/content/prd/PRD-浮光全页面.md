# PRD 浮光全页面需求

## 1. 摘要

将已复现的18个Figma画板转成可落地的页面需求、数据库增量和接口合同，形成从项目、资产、镜头到生成结果的可追踪闭环。页面完整是视觉基线；真实数据、权限、费用和恢复能力按逐项需求验收。

本PRD按 pm-execution 的 create-prd 与 user-stories 方法整理；正文按现有项目分类保存。完整页面表与139条功能需求见[页面总览](../requirement/浮光页面/index.md)。

## 2. 参与者与责任

| 角色       | 责任                                   | 负责人                   |
| ---------- | -------------------------------------- | ------------------------ |
| 产品负责人 | 准入政策、页面口径、范围和D-01～11决策 | 用户指定；本轮由用户审阅 |
| 制作者     | 核验剧本到镜头/配音流程及失败可恢复性  | 待指定，不假定已有访谈   |
| 设计/前端  | Figma、shadcn语义、响应式和交互证据    | 实施时指定               |
| 后端/数据  | owning模块、事务、Schema、Handler/DTO  | 实施时指定               |
| QA/运维    | 幂等、权限、真实集成、性能与恢复验收   | 实施时指定               |

## 3. 背景与问题

目前18页在 `/preview` 以fixture展示，可视化了布局和操作，但不代表这些操作已有正式路由、公开API或持久化。例如镜头详情、分镜、统计、健康和账号公开入口仍有接入缺口；项目、素材、设定、目录模型已存在可复用合同。逐页临时补接口会产生两份状态、错误口径和重复付费风险。

已有产品方向仍是内部团队的AI短剧生产工具，优先一致性、可控性和成本透明。此次用户要求详细需求整理，未授权改成公开多租户SaaS，也未授权把所有规划立即实现。

## 4. 目标与衡量

| 目标         | 本轮交付指标                                     | 后续产品验收指标                            |
| ------------ | ------------------------------------------------ | ------------------------------------------- |
| 页面无遗漏   | 18/18独立需求文件；所有功能行可追踪              | 每个P0有真实成功、失败和权限证据            |
| 合同可执行   | 每页关联数据/API组、规则与异常；新增字段标记规划 | 公开API与生成客户端无漂移；刷新后结果一致   |
| 生产安全     | 报价、确认、候选、正式选定和unknown路径明确      | 重复计费0；跨项目越权0；并发无静默覆盖      |
| 可复算与恢复 | 定义统计分母、空值、审计和恢复场景               | 指标fixture复算一致；恢复演练达到REQ-02门槛 |

时间界限：文档在本轮整理完成后评审；实施按依赖切片，不承诺未估算的日历日期。没有访谈、活跃用户或收入数据，不能虚构增长目标或节省百分比。

## 5. 用户与场景

- 制作者：已有剧本，需要批量产生一致的镜头和配音，也需要在画布精修单个镜头。
- 管理员：管理账号、模型和凭据，控制费用、追查异常，避免密钥与权限泄露。
- 运维/验收人员：区分业务异常与基础设施故障，能查到原任务、版本和审计证据。
- 设计/开发人员：使用两张规范画板检查共享组件，规范页不引入业务数据库。

约束：现有单工作区、模块化Go后端、单一Schema、注解/DTO生成Swagger及客户端、shadcn/Radix、现有Operation/账本。真实供应商能力以核验为准。

## 6. 价值与功能性分析

| 用户任务           | 获得的价值               | 需要避免的问题                         |
| ------------------ | ------------------------ | -------------------------------------- |
| 找到项目并导入剧本 | 可恢复的统一起点         | 创建成功但导入失败被隐藏               |
| 确认角色与素材     | 同一版本跨集复用         | 换脸、素材失效、无授权引用             |
| 编辑和批量生成镜头 | 集中参数、引用和候选对比 | 一键生成没有报价、重试重复扣费         |
| 看清质量和进度     | 能定位到具体对象的指标   | mock数字、零分母误报、缺数据当健康     |
| 管理平台           | 权限和变更可追查         | 密钥回显、最后管理员被禁用、历史被改写 |

这是基于现有页面和仓库合同的产品分析，没有新增竞品优劣或市场验证结论。

## 7. 解决方案

### 7.1 页面与流程

18页详见[页面总览](../requirement/浮光页面/index.md)。核心流程：项目/剧本 → 设定与资产确认 → 分镜 → 镜头编辑 → 报价确认 → 候选 → 正式选定 → 跨页统计；画布操作引用同一业务对象。全局导航中的剧本、独立配音、任务中心等沿用既有功能需求，不因缺少本次画板而删除。

### 7.2 功能切片与验收

页面功能行使用 PG-xx-Fxx，与现有 ACC/PRJ/BIB/SB/GEN 等编号关联。每行包含操作、规则、持久化和异常验收；按优先级和依赖交付，不把整页当作不可测试的大任务。详见[追踪矩阵](../test/浮光页面需求追踪.md)。

### 7.3 技术设计

[数据设计](../design/浮光页面数据设计.md)区分已实现表和规划表，不复制执行DDL。[接口设计](../design/浮光页面接口设计.md)描述页面组合需求与新接口提案；当前公开合同由Handler/DTO决定。现有API生成物与数据库不在本轮改动。

### 7.4 假设与决策

注册准入、1:1画幅、Markdown导入、凭据先测后换、参考锁定粒度、统计口径、个人收藏/提示词/会话、手机编辑范围均见D-01～11。建议不等于决策；冲突处保持现有合同，受影响新能力只设计不启用。

## 8. 发布与交付

第一阶段复用已有数据能力接入项目/媒体/设定/目录；第二阶段接入镜头与候选正式事实；第三阶段接入受控生成与配音；第四阶段完成分析、管理和账号扩展。每阶段在真实数据、失败恢复与相关NFR通过后再移除对应mock，不一次性切换全部页面。

不在本轮范围：直接执行SQL、写生产数据、开放注册、真实供应商付费、发布网站、改变框架或引入新服务。文档就绪仅表示可供产品和工程评审，不宣称产品验收完成。
