## 2. 处理流程

```text
已确认的集 ≥ 1 → 发起抽取（报价确认）→ extract_bible Skill（输入：各集解析结构摘要）
→ 候选：角色（名称、别名、描述、出场集、状态变化 → 造型建议）、场景、道具
→ 用户合并 / 拆分 / 编辑 / 删除 → 确认设定集
→ 经 script owning 用例发布新的不可变结构版本，按别名绑定 character_id（未匹配的列出供人工指定）
后续新确认的集 → 增量抽取：只对新出现的称呼给出“归入已有角色 / 新建”建议
```

## 5. 异步与工作流

`OperationWorkflow`（`target_type = bible_extract`）的 LLM 同步分支（DES-04 §3）：`llm.run_skill(extract_bible)`（可分块，见 DES-17-Q1）→ `flow.ApplyStructuredResult`（写设定集候选；合并到已有条目时只生成建议，不修改已确认条目）。

## 6. 事件与实时

`bible.entries_changed.v1`（realtime）；合并 / 拆分写审计。

## 7. 界面

三栏列表（角色 / 场景 / 道具）；多选合并；条目详情：别名标签、描述、出场集时间轴、造型卡片；说话人映射对话框。

## 8. 权限与审计

制作者。审计：`bible.merged`、`bible.split`、`bible.confirmed`、`look.created/updated/deleted`。

## 9. 非功能要求

AIQ-02（主要角色召回 100%，别名合并准确率 ≥ 90%）；CAP-01（≥ 200 造型）。

## 10. 测试设计

合并 / 拆分对引用与台词回填的影响；分块抽取的合并正确性（评测集）。

## 12. 角色与主体版本合同

Bible 拥有稳定角色、场景、道具身份与不可变完整版本，造型、参考图和声音绑定均为版本化内容。手工候选与真实 AI 抽取严格区分，AI 抽取和形象生成须经统一 Operation 采用真实结果；尚未装配的 storyboard/audio/lineage 不得报告已实现或影响为零。

### 12.1 身份、版本与参考

Bible 使用 project/org scope、当前 active actor/admin/producer、workspace 同事务内容锁与 TouchContent。稳定条目 ID、可变 current/confirmed version 指针及 revision 与 INSERT-only typed version 分离。每次设定、造型、参考和声音绑定变化都发布完整新版本；保留 actor、时间、来源、前版本和内容 SHA，不更新旧版本。定义采用闭合字段，承接名称/别名、剧情定位、外貌/体型/服装/性格、固定道具、一致性与三视图约束、声音描述；不保存任意未校验 provider JSON。

角色至少有一个默认造型，适用范围为正式集/场身份；场景和道具有各自闭合版本。参考用途覆盖 primary/front/side/back/turnaround_sheet/expression_sheet，最多八个图片表示；关联正式同项目 ready/passed image 与实际 rendition，当前授权、真人许可及媒体删除边界仍由 media owning 验证。历史引用保持原版本与媒体身份，替换当前参考不覆盖旧绑定。角色合并保留已确认 redirect，当前解析沿有界无环链；拆分发布新角色及新版本，不重写历史文稿或旧镜头。

### 12.2 台词归属与下游影响

Script 采用 episode_structure、scene、dialogue_line 与 action_line 的 INSERT-only 合同。角色绑定必须由 script 消费方端口验证当前项目/确认角色/重定向后，通过已有 structure CAS 创建新的 typed StructureDocument 与一致的物化行；scene_key、line_key、原文、scalar span 和 source hash 保留。确认、脚本头及 workspace invalidation 在同一事务推进，旧确认和原台词完全保留。跨模块接口由各消费方声明，组合根显式转换，禁止 script↔bible 导入循环或跨模块通用 SQL。

替换已采纳剧本、修改已确认结构或删除被引用造型，必须读取真实 owning Impact 并按冻结修订失效；缺少 storyboard/audio/lineage 等实际证据继续阻断，不能将未知影响报告为零。发布独立新角色版本不伪造镜头或音频失效数量；历史 pinned 版本继续可解析，current 投影依据真实当前版本标示变化。

### 12.3 声音与完整 Copy

声音区分 catalog 与 sample 两种闭合来源。Catalog 绑定当前已配置模型和其真实 voice 枚举；兼容导入的十三个 voice key 可保留为明确来源的候选说明，不在 GET 中写入种子或声称供应商可执行。Sample 绑定正式同项目 ready/passed audio、真实 SHA/revision 与 instructions；它表示样本绑定，不能冒充声音克隆、TTS 或试听完成。声音变化生成不可变角色/声音版本，真实生成仍按 DES19 与 Operation 处理。

Bible 提供自身 ReferencedMedia/Freeze/Transfer/Register/Verify/Cleanup，受 workspace 同事务 trusted Copy authority 与当前 worker fence 约束。完整复制角色、场景、道具、造型、参考与声音版本及确认/重定向历史，映射稳定身份及版本身份后才交 Script/Canvas 重写各自声明的引用；不复制任务、费用或供应商身份。新可空扩展须维持旧无 Bible 快照/永久回执的逐字兼容。原件缺失、未知版本或映射不完整拒绝受理或发布，不输出空主体。

Schema 中项目 Copy 的 Bible 结构包含可空 `bible_receipt`、真实 `bible` 阶段及该列 UPDATE 权限。受理顺序为媒体完整历史事实冻结、Script 正式适用范围计划、Bible 全历史冻结、Script 历史角色绑定冻结；外观的 episode/scene 与台词的角色/版本映射由所属模块提供，根不猜 UUID。执行顺序为 `media → bible → script → canvases → finalizing`，各 owning 回执逐项匹配冻结15项/13项历史计数，整个目标最后才 active。Bible 的 `bible_transfer` 只准当前 worker 的 bible 阶段，`bible_register` 只准 bible/finalizing，`bible_verify` 只准已有 Bible 回执的 finalizing；清理仍要求真实 cancel_requested/cleanup。finalizing 再在 SQL 事务外实际核 source/target 私有原件及衍生物，随后在新当前权限事务中核完整 owner 回执并发布；旧 proof 不替代实际 bytes 核验。

复制执行者和原创建者分别记录：Schema 定义可空 `execution_actor_id`，旧任务回退原创建者；已授权的新 cancel 命令及保留取消意图的 reconcile 才能转交清理执行者；retry 和普通 reconcile 必须仍由原执行者提交，其他当前管理员或制片人不能借命令接管发布。worker 每个私有读取、写入和发布检查当前执行者权限，旧 worker 不能借新控制者的权限继续。实际同步 I/O 已返回的 worker 可以凭 org/job/worker 精确栅栏封存停止结果，即使其用户已停用；该内部路径只记录失败和停止，不读取 owner 私有内容、不发布、不代替取消或恢复授权。超时中断保留原 worker，只有原同步执行确认退出后才释放。Bible 清理是 caller transaction 内的 SQL 封存，在独立短事务里绑定 cleanup 权限后执行。

### 12.4 数据、接口与验收

当前稳定条目头、版本、造型/参考/声音、确认、永久命令和 Copy 事实由 Schema 维护；只为实际消费建立端口。API 覆盖列表/详情/版本与实际命令，通过 Gin→swag→在线 Swagger→生成客户端装配。永久 UUID key 重放前复核当前权限，CAS、同键异输入、零行写入、失效依赖和撤权均有明确失败。

先 Red→Green 验证闭合领域与不可变版本，再用隔离非 owner PostgreSQL、真实媒体/私有对象、HTTP、并发/故障、完整历史 Copy 和浏览器检查；gofmt/goimports/vet/lint/race/govuln、严格 TypeScript、适用前端门禁分别记录。手工候选和引用测试不证明 AI 抽取、三视图生成或 TTS，未装配下游的 503 继续列为BACKLOG 未决项。

## 13. 不可变历史读取与角色绑定

历史定义、materialized result_source、造型 applies_to、声音绑定、完整复制清单和永久命令回执采用严格 JSON 边界：拒绝未知字段、重复键、尾随数据和非法 UTF-8。单个版本最多 4MiB、树深度 64、节点 200000；完整 Source/Target manifest 遵守其独立总量预算，不套用单版本大小限制。读取验证不得更新历史正文、SHA、物化行或原始回执。

造型适用范围中，省略的 applies_to、解码后的 nil 和显式 [] 具有相同空集合语义；非空集合或其它定义差异仍判为损坏历史。兼容读取只比较语义，不重新编码、不回填旧版本，不修改原字节或摘要。

剧本角色选择器只能绑定明确确认的不可变角色版本，名称/别名随该版本读取。选择时并行复核当前实体与工作区，保留既有历史 pin；清除绑定必须同时清除实体身份、版本身份与 pin。过期 scope 和晚到响应不能覆盖当前选择。

## 故障约束与专项验证

- 专项验证：用“小李/李明/李队”、两个“王总”、双造型角色与已引用造型执行 TC-14-01～04；验证合并/拆分后的引用、台词映射、长剧分块及 AIQ-02/CAP-01（REQ-14 §3；DES-17 §10；TST-02/TST-03）。

- 别名歧义可能误合并角色：仅自动处理唯一匹配，歧义回到人工说话人映射。
- 合并后旧镜头引用可能失联：保留重定向，迁移未核验前不删除旧标识，必要时撤销候选合并。
