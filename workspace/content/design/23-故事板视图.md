| 领域事件     | `operation.status_changed.v1`                              |
| 测试用例     | TC-20-xx（[TST-02](../test/02-需求追踪矩阵.md)）           |

## 2. 数据

复用 `storyboard.shot`（`progress`）、`shot_version`、`operation_output` 与 `media.rendition`（封面）、`lineage.stale_mark`。`shot.progress` 由 `storyboard-progress` 消费者根据 `operation.status_changed.v1` 更新（只写进度字段，符合 GEN-10）。

## 3. 接口

复用 `GET /api/episodes/{eid}/shots`，增加 `?view=board` 返回精简字段（封面 URL、进度、状态），单次响应 ≤ 150 条、≤ 200 KB：

```json
{
  "items": [
    {
      "id": "…",
      "shot_no": "3-12",
      "mode": "omni_reference",
      "cover_url": "…",
      "take_preview_url": "…",
      "progress": "awaiting_selection",
      "candidates": 3,
      "stale": true,
      "missing_refs": 0,
      "revision": 5
    }
  ]
}
```

## 4. 异步与工作流

无。

## 5. 事件与实时

SSE `shot.updated`、`operation.updated`、`stale.changed` → 局部刷新对应格子。

## 6. 界面

网格（TanStack Virtual 行虚拟化）；按场分组标题；筛选栏；多选（Shift 连选）后底部操作栏：批量生成关键帧 / 视频、批量改参数（跳镜头表）。

## 7. 权限与审计

制作者；只读视图无审计。

## 8. 非功能要求

PERF-04（150 格首次渲染 ≤ 1 秒、滚动 ≥ 50 fps）；PERF-03（状态更新 ≤ 2 秒）。

## 9. 测试设计

进度状态机单元测试；前端性能录制（150 格）。

## 10. 待确认

| 编号      | 问题                                                                   | 拟采用方案                                                       | 确认时机  |
| --------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------- | --------- |
| DES-23-Q1 | 封面优先级（已选片段 > 已选关键帧 > 最新候选）在后端计算还是前端计算？ | 后端计算并返回 `cover_url`，前端不重复实现规则。                 | M3 实施中 |
| DES-23-Q2 | `shot.progress` 由消费者异步更新，SSE 事件可能乱序，前端如何处理？     | 按对象 `revision` 单调比较，丢弃旧版本事件；断线重连后整页刷新。 | M3 实施中 |

需求层面的待确认问题见 [REQ-20](../requirement/20-故事板视图.md) 的“待确认”。

## 故障约束与专项验证

- 事件乱序造成网格状态倒退：按 revision 忽略旧事件，断线后重新取整页快照。
- 150 镜视频预览拖慢页面：视口外禁载视频、同一时刻只播一格；性能门禁失败时关闭悬停预览并保留静态封面与详情入口。
