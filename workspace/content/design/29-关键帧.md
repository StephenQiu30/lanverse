## 2. 数据

`operation.operation`（`target_type = shot_frame`、`capability = image.generate`）；`operation_output`；`storyboard.shot.selected_frame_output_id`；上传关键帧：创建 `origin = upload` 的 Operation（`capability = image.upload`、`mode = upload`、`status = completed`、费用 0，模型版本与区域为空，受 `ck_operation_upload` 约束）及其 `operation_output`，与生成结果统一为候选。

## 3. 接口

```http
POST /api/projects/{pid}/quotes { "items": [ { "target_type": "shot_frame", "target_id": "<shot_id>", "capability": "image.generate", "output_count": 4 } ] }
POST /api/shots/{id}/frames:upload   { "media_asset_id": "…", "crop": { "x": 0, "y": 120, "w": 1080, "h": 1920 } }
201 { "output_id": "…", "operation_id": "…" }
POST /api/shots/{id}:select-frame    { "output_id": "…", "expected_revision": 7 }
```

## 4. 异步与工作流

生成：OperationWorkflow（图片同步或异步视供应商）；上传裁剪：`media` 队列 `CropImage` Activity。

## 5. 事件与实时

同 REQ-22。

## 6. 界面

镜头详情“关键帧”标签页：生成按钮（数量、模型、参数）、上传区（裁剪框）、候选对比、选定。

## 7. 权限与审计

制作者；审计 `shot.frame_selected`。

## 8. 非功能要求

PERF-09。

## 9. 测试设计

输入展开正确性；上传裁剪；审核拒绝路径。

## 10. 待确认

| 编号      | 问题                                            | 拟采用方案                                                              | 确认时机  |
| --------- | ----------------------------------------------- | ----------------------------------------------------------------------- | --------- |
| DES-29-Q1 | 上传关键帧的裁剪在服务端还是前端执行？          | 服务端 `media.CropImage` 执行，保证画幅与分辨率精确；前端只提交裁剪框。 | M3 开始前 |

需求层面的待确认问题见 [REQ-26](../requirement/26-关键帧.md) 的“待确认”。

## 故障约束与专项验证

- 上传图片画幅或分辨率不足：提示裁剪/质量风险；处理失败时不进入可选候选，保留原上传供重新处理。
- 审核拒绝或关键帧改选后旧视频继续使用：拒绝选定不合规帧并标记依赖片段过期；保留旧候选供追溯。
