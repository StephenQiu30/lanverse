# 本地知识库文档站

`workspace/` 用于维护和阅读当前产品知识库，Nextra 展示同一批 Markdown。页面范围与业务事实由当前需求文档定义。

## 目标与内容

`workspace/content/` 保存当前知识库正文；旧产品、接口、页面和工程资料隔离在 `workspace/history/`，不被Nextra读取或搜索。计划和实施方案作为普通 Markdown 文档阅读、编辑和维护。历史原文与许可保留；历史不进入当前需求来源，当前进度按新页面独立验证。

Nextra 使用标准文档主题提供目录导航、搜索、正文和页内目录。入口直接进入文档，按已有分类查找内容。站点不承担任务状态筛选、执行管理或业务系统功能，不需要账户、业务后端或部署；当前只供本地访问。

## 文件分工

```text
workspace/
  content/
    index.md       文档首页
    KNOWLEDGE.md   本地使用说明
    prd/           产品文档；其余既有分类保持
  Dockerfile       默认 Compose 文档服务镜像
  app/             Nextra 页面入口与本机原文读取适配
  mdx-components.tsx
  next.config.mjs
  package.json
```

| 位置                  | 职责                                                      |
| --------------------- | --------------------------------------------------------- |
| `workspace/content/`  | 人和 AI 共同读取的 Markdown 正文；Obsidian 编辑同一份文件 |
| `workspace/` 其余文件 | Nextra 配置、页面入口和依赖；按 Nextra 标准文档站方式组织 |
| 根 `BACKLOG.md`       | 记录当前工作事项；不派生任务管理界面                  |

站点按 Nextra 原生内容约定读取 `content/index.md` 与分类文档，使用原生页面映射组织导航，由文档主题提供正文、页内目录与搜索。不另建一套知识库数据库、自定义内容治理系统或强制文档状态/摘要校验。已有元数据暂予保留，用于文档属性，不作为阅读文档的额外门槛。AI 可以直接读取所需 Markdown，无须专用导出接口。

正文继续使用标准 Markdown 相对链接。对 `content/` 外的根 AGENTS、PROJECT、BACKLOG 等文件，以及 `.txt` 许可，站点只做必要的链接适配，通过本机只读原文链接打开；不复制正文或把这些文件变成新的管理页面。此适配只处理已有文档链接，不开放任意本机文件读取。

## Obsidian 使用

继续使用当前 Vault，无须为阅读站改动个人设置：

- 以 `workspace/content/` 为 Vault 时，集中管理知识库正文；指向仓库根 AGENTS、PROJECT、BACKLOG 的相对链接超出 Vault，不保证能在 Obsidian 内解析，可从文件系统或编辑器打开。
- 以仓库根为 Vault 时，上述根文档与正文处于同一 Vault，可使用现有标准相对链接。

两种方式都编辑同一批文件，按使用需要选择。此修订不要求切换 Vault，也不修改本机 Obsidian 配置。

## 本地使用与验收

默认使用根 `docker-compose.yml`，由 `docker compose up -d --build --wait` 一起启动前端、后端和 `workspace` 文档服务；文档服务独立于业务依赖，使用只读挂载的正文、站点代码和已有原文白名单；不挂载整个仓库或根 `.env`。Next.js 采用 Webpack 轮询文件变化，文档与站点代码保存后热更新。

宿主方式在仓库根运行 `pnpm --dir workspace install --frozen-lockfile` 安装依赖，再用 `pnpm --dir workspace exec next dev --webpack --hostname 127.0.0.1 --port 3210` 开发预览。正文保存后更新；开发搜索只反映上次构建的索引。完整本地阅读依次运行 `next build --webpack`、Pagefind 索引和 `next start`，准确命令见 [PROJECT](../../../PROJECT.md) 和[使用说明](../KNOWLEDGE.md)。两种方式均访问 <http://127.0.0.1:3210>，切换前停止占用该端口的服务。

验收检查文档入口、分类导航、中文文件路径、正文与表格、页内目录、搜索及保存后的内容刷新。Obsidian 保存的正文应能在本地站点阅读；有效的文档链接应到达对应文档。原许可字节和当前任务状态只在 BACKLOG 维护。

本设计说明当前范围；站点是否完成由实际实现和上述操作结果判断，不沿用此前执行管理界面的验证结论。
