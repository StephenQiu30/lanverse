# DES-08 技术选型决策

- 依赖：[PRD-01](../prd/01-产品需求文档.md)、[REQ-02](../requirement/02-非功能需求规格.md)、[工作台设计](工作台设计.md)、[PRD-02 产品能力与架构原则](../prd/02-产品能力与架构原则.md)、[DES-01](01-系统架构设计.md)
- 范围：前端、后端、Agent 服务、工作流、中间件、AI 模型、基础设施的明确选型与职责边界
- 约定：已安装版本以锁文件和镜像为准；计划选型在接入前核验官方兼容性、许可与维护状态，验收后写入锁文件和 CI。

## 3. 后端（Go 全家桶）

| 关注点       | 选型                                                                                         | 用途与约束                                                                                                                    |
| ------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| HTTP 框架    | Gin                                                                                          | 路由、中间件（鉴权、请求 ID、限流、恢复、日志）；Handler 只做参数解析、调用用例、映射响应                                     |
| 参数校验     | go-playground/validator（Gin 内置）                                                          | 请求 DTO 校验                                                                                                                 |
| ORM          | GORM + PostgreSQL 驱动（pgx）                                                                | 仓储层使用；复杂查询（递归 CTE、报表）用 GORM Raw SQL；GORM 模型只在仓储适配器内，不作为领域对象或 API 响应                   |
| 数据库结构   | `backend/db/schema.sql` 最终态 SQL，当前已实现结构的唯一事实源                               | 单事务初始化空库；既有库审阅增量升级；生产禁止 GORM AutoMigrate                                                               |
| 配置         | Viper                                                                                        | 环境变量优先；启动时集中校验                                                                                                  |
| 日志         | Zap（已确认，不使用标准库 slog）                                                             | 结构化 JSON；统一字段 `trace_id`、`project_id`、`operation_id`；不记录凭据与剧本全文                                          |
| 依赖注入     | Wire（已确认；编译期生成）                                                                   | 组合根装配；`wire_gen.go` 为生成物，禁止手改，CI 校验生成一致；禁止全局单例                                                   |
| API 文档     | swag + gin-swagger                                                                           | 从 Gin Handler 注解与 DTO 自动生成 Swagger 2.0，并由后端在线提供 `/swagger/doc.json`；禁止手动维护规范文件，CI 校验生成物一致 |
| 工作流       | Temporal Go SDK                                                                              | 编写全部工作流；承担写库、媒体处理等 Go Activity                                                                              |
| Redis 客户端 | go-redis v9 + redis_rate + redsync                                                           | 缓存、会话、限流、分布式锁、Pub/Sub                                                                                           |
| Kafka 客户端 | franz-go                                                                                     | Outbox 投递与事件消费；幂等生产者；消费者组                                                                                   |
| 对象存储     | minio-go v7                                                                                  | 预签名上传 / 下载、对象管理                                                                                                   |
| 鉴权         | Redis 会话 + HttpOnly Cookie；密码 bcrypt                                                    | 管理员创建账号；两种角色在应用层用例入口校验                                                                                  |
| 可观测       | OpenTelemetry Go（otelgin、otelgorm、Temporal 拦截器）+ Prometheus client                    | 链路贯穿 API → 工作流 → Activity → Agent 服务                                                                                 |
| 测试         | testing + testify + testcontainers-go（PostgreSQL、Redis、Kafka、MinIO）+ Temporal testsuite | 单元、集成、工作流回放测试                                                                                                    |
| 质量         | gofmt、goimports、go vet、golangci-lint、`go test -race`、govulncheck                        | 与 `AGENTS.md` 一致                                                                                                           |

后端采用 Gin + GORM 生态、Wire 构造组合根和 Zap 结构化日志，保持模块化单体与 `adapter → application → domain`，不增加无实际消费的 RPC 或服务发现。

Wire v0.7.0 按当前接受的工具链锁定。生成器维护与后续 Go 兼容风险须在升级时核验；若不可继续使用，先评审并更新本设计，再替换组合根。

## 4. Go 执行与 Harness

工作流与 owning Activity 使用 Go；供应商调用遵守类型化端口、context、发送证据、原键恢复、预算和错误分类。AG-UI 是对话事件协议，Harness 负责版本化 Skill、冻结上下文、只读工具、结构校验与有界修复，详细合同见 [DES-05](05-Agent与Harness.md)和[生成执行设计](生成执行设计.md)。

真实供应商、业务 Skill、审核和对话运行链未接入前保持不可用，状态见 BACKLOG。原生媒体可按实际模型依赖使用受控 Python/C++ 子进程，资源预算、权限、取消、退出与结果接管归 owning Go 模块，不新增独立业务服务。

| 人工确认   | 业务状态写 PostgreSQL；工作流通过 Signal / Update 接收用户决定后继续                                                                                                    |
| 批量       | 父工作流 + 子工作流（每镜头一个），单镜失败独立处理                                                                                                                     |

| 测试       | Go testsuite 单元测试 + 历史回放测试                                                                                                                                    |

## 6. 中间件职责

| 中间件                                        | 负责                                                                                                                                        | 不负责                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **PostgreSQL**                                | 全部业务事实（按上下文分 schema）、版本与依赖、Operation、模型注册表、账本、画布文档、Outbox 表；Temporal 持久化（独立库）                  | 媒体字节；缓存                                     |
| **Redis**                                     | 会话存储；热点查询缓存（模型注册表、项目概览）；API 与供应商配额限流；分布式锁（批量提交互斥）；实时事件 Pub/Sub（SSE 跨实例扇出）          | 任何业务事实；丢失后必须可从 PostgreSQL 重建       |
| **Kafka**                                     | 领域事件总线：Outbox 可靠投递已提交事件；消费者包括实时通知、依赖过期传播、成本汇总与报表、审计归档、模型调用明细、将来的检索索引与数据分析 | 同步 RPC；工作流编排（归 Temporal）；模型 token 流 |
| **对象存储（开发 MinIO / 生产火山引擎 TOS）** | 全部媒体对象（上传素材、参考图、关键帧、视频、音频）；预签名直传与下载；按项目前缀组织；生命周期规则清理临时对象                            | 元数据（在 PostgreSQL）                            |
| **Temporal**                                  | 长流程编排：生成操作、剧本解析、批量、媒体处理、人工确认等待、重试、超时、对账                                                              | 业务事实（以 PostgreSQL 为准）                     |

**事件链路**：业务事务写业务表 + Outbox → Go relay 投递到 Kafka → 消费者处理（实时通知消费者把事件发布到 Redis Pub/Sub → 各 API 实例的 SSE Hub 推送给浏览器）。

**Kafka 主题约定**：`lanverse.<上下文>.<事件>.v<N>`，如 `lanverse.operation.completed.v1`；键为 `project_id`，保证同一项目内有序；消费者按事件 ID 去重。

## 7. 画布

画布使用 DOM/SVG/rAF InfiniteCanvas、空间索引、LOD 与媒体调度，交互状态和业务事实分离。Next.js、shadcn/Geist、next-themes 与正式 Go 命令端口分别拥有页面、组件、主题及保存；业务内容不存 IndexedDB。

正式资源、UUID、revision、持久幂等、Outbox、world 绝对坐标、删组解组、zoom 映射和完整工具合同见 [DES-38](38-画布功能.md)与[工作台设计](工作台设计.md)。性能保留500节点（300图、40视频、600连线）内存场景，并按 PERF-06 测500/800与2000节点；静态、合成与真实媒体分别验证。外部来源与许可留在 [NOTICE](../../../THIRD_PARTY_NOTICES.md)。

## 8. AI 模型

- 平台内部按 `capability + mode` 调用，模型由注册表决定（DES-01 §4.4）。
- **P0 第一优先级：全能参考（含参考音频）**，写实与风格化分别测单角色、双角色同框、动作参考、运镜参考、音频参考。
- **已有账号与接入范围（PRD-01 P18）**：

| 供应商       | 接入方式        | P0 评测范围                                                          | 区域 |
| ------------ | --------------- | -------------------------------------------------------------------- | ---- |
| 火山引擎方舟 | 官方 API        | Seedance（全能参考 / 图生视频）、Seedream（生图）、豆包（LLM、语音） | 境内 |
| MiniMax      | 官方 API        | 海螺 H3 系列（全能参考 / 图生视频）、Speech（TTS、音色）             | 境内 |
| OpenRouter   | OpenAI 兼容 API | GPT Image（生图）、海外版 Seedance（满血版本）                       | 境外 |

- P0 按写实 + 日系动漫、国风 / 仙侠、3D 卡通、韩漫 / 条漫共 5 种风格评测。
- 其他候选（按需补充账号）【待核实】：可灵 3.0 Omni、Wan 3.0、Vidu Q 系列；审核服务 —— 阿里云、网易易盾、数美。
- 境外模型：注册表标注 `region=overseas`，项目可禁用；调用记录标明数据发送区域；对外发布前法务确认（REQ-02 CMP-06）。
- 接入前核实：参考数量与类型及时长上限、角色映射、时长 / 画幅 / 分辨率、异步查询与回调、幂等、结果链接有效期、取消、计费口径、限流、数据条款、服务区域。

## 9. 基础设施与部署
