## 2. 处理流程

```text
选择范围 → POST /api/projects/{pid}/quotes（多项）→ 批次报价（逐项费用与错误）→ 剔除错误项 / 不需要的项 → 确认
→ BatchWorkflow：按项目并发上限与供应商配额启动子 OperationWorkflow
→ 汇总：成功 / 失败 / 结果未知 / 已取消 → batch.finished → 一条汇总通知
→ 失败项“重试” = 对失败项重新报价（新批次）
```

## 3. 数据

`operation.batch`（`scope`、`status`、`total/succeeded/failed/unknown_count`、`quote_total_micros`、`workflow_id`）；`operation.operation.batch_id`。批次的暂停原因由 `paused_reason text` 保存（DES-02）。

## 4. 接口

```http
POST /api/projects/{pid}/quotes         （多项，见 [DES-24](24-报价与二次确认.md)）
POST /api/batches/{id}:confirm          { "exclude_operation_ids": ["…"] }
GET  /api/batches/{id}
200 { "id": "…", "status": "running", "total": 20, "succeeded": 12, "failed": 1, "unknown": 0, "running": 5, "queued": 2,
      "paused_reason": null, "items": [ { "operation_id": "…", "target_label": "3-12", "status": "completed" } ] }
POST /api/batches/{id}:cancel
POST /api/batches/{id}:resume           （暂停后继续）
POST /api/batches/{id}:retry-failed     → 为失败项生成新的批次报价
```

## 5. 异步与工作流

`BatchWorkflow`（`batch/{id}`）：子工作流 `operation/{op_id}`，`ParentClosePolicy = ABANDON`（父工作流异常不影响已提交的子项）；使用信号 `cancel`、`resume`；熔断计数在工作流状态中（DES-04）。

## 6. 事件与实时

`batch.finished.v1` → notify；SSE `batch.updated`。

## 7. 界面

批量工具栏；报价对话框（逐项列表可剔除）；批次进度条（在任务中心与发起页面顶部）；完成后结果摘要与“重试失败项”。

## 8. 权限与审计

制作者；审计 `batch.confirmed`、`batch.cancelled`。

## 9. 非功能要求

CAP-02（≥ 200 并发任务平台不成为瓶颈）；PERF-10（150 项报价 ≤ 5 秒）。

## 10. 测试设计

父子工作流回放测试；熔断暂停；取消与预留释放。

## 故障约束与专项验证

- 连续供应商错误导致整批浪费：按同类错误阈值暂停未开始项，由用户继续或取消；已开始项继续追踪结算。
- 父工作流重启或取消时丢子项：按持久化批次和子任务恢复；禁止重复提交，未开始项释放预留。
