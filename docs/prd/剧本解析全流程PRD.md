# 剧本解析全流程 PRD

## 1. 用户与问题

目标用户是需要把整本短剧剧本快速转成可拍摄/可生成分镜表的创作者。当前最重要的问题不是平台后台或通用 Agent，而是用户上传后必须跨多个页面、手工补齐结构，且无法一眼确认人物出场集数和每集分镜是否完整。

## 2. 产品结果

一次成功旅程结束时，用户能够看到：

- 原始剧本和固定来源版本；
- 连续的剧集列表以及每集原文范围；
- 每集场景、人物、对白和制作任务；
- 全剧人物清单与人物出场集数；
- 每集一张可编辑、可批准的分镜表；
- 任何失败的阶段、原因和下一动作。

## 3. 体验流程

1. 用户在项目页选择 DOCX/Markdown 文件或粘贴文本，确认预览并导入。
2. 系统启动剧本结构 Skill，页面展示上传、分集、结构提取、人物聚合和分镜生成进度。
3. 用户审阅分集边界；显式且连续的集标记可以一键确认，异常边界必须修正。
4. 系统展示结构化结果：左侧剧集，主区场景/任务，侧栏全剧人物与出场集数。
5. 系统按集生成分镜候选表；用户逐行接受、修改或忽略。
6. 所有必需叙事单元已覆盖后，用户批准并应用该集分镜表。

## 4. 产品规则

- 自动化结果永远标记为候选；应用前必须经过明确决定。
- 解析页面显示的是持久 Task/Batch 状态，刷新或服务重启后继续同一流程。
- 同一个剧本版本和同一个动作的重复点击不创建重复剧集、候选或分镜。
- 人物出场集数来自场景/对白证据聚合；模型给出的无证据集数必须被拒绝。
- 分镜表未覆盖必需叙事单元或引用过期输入时不能批准。
- 不提供 Admin、邀请、独立 Agent 控制台或旧服务入口。

## 5. 成功指标

| 指标 | P0 目标 |
| --- | --- |
| 上传到可审阅分集 | 显式标记样本 100% 无缺口、无重叠、原文守恒 |
| 人物出场集数 | 黄金样本精确匹配，且每个集数能回溯场景/对白证据 |
| 分镜叙事覆盖 | 批准前必需叙事单元覆盖率 100% |
| 重复执行 | 同输入同幂等键不增加逻辑事实数量 |
| 恢复 | 页面刷新、API/Worker 重启后状态与结果不丢失 |
| 浏览器主流程 | DOCX 上传到至少一集分镜批准全程无控制台错误和阻断可访问性问题 |

## 6. 非目标

本 PRD 不交付媒体生成、通用聊天、团队邀请、组织管理后台、可视化 Agent 画布、旧 API 兼容、Docker 部署或未来模块占位实现。
