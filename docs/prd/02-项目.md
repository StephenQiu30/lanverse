# PRD 02：项目

执行编号：02；来源需求模块：07。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

建立真实项目身份，并在首页、画布与创作页面始终保持同一上下文。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/07-项目需求.md)中的业务规则。对应[模块Plan](../plan/02-项目.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

固定项目名称与跳转无法证明内容归属和刷新恢复。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

建立真实项目身份，并在首页、画布与创作页面始终保持同一上下文。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为制作者，我希望创建项目后打开自己的画布，避免跳到样例作品。
- 作为制作者，我希望搜索和排序找到自己的项目，两种视图结果一致。
- 作为制作者，我希望导入或复制后获得独立且可继续创作的项目。

## 6. 价值与范围取舍

先完成空白创建、本人项目查询和打开同一项目画布；带剧本创建与复制随后接入。

剧本创建和复制保留为后续切片，不要求Demo先具备分集/镜头。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/07-项目需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/07-项目需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-PROJECT-01：创建并打开空白项目

作为制作者，我希望创建项目后打开自己的画布，避免跳到样例作品。

范围追踪：FR-PROJECT-01、FR-PROJECT-05，原始规则见[功能需求](../requirement/07-项目需求.md#3-功能性需求)。

1. 项目唯一身份与规格持久。
2. 刷新能打开同一项目。
3. 名称/画幅/风格按确认基线校验。
4. 他人ID及不存在对象安全失败。

### US-PROJECT-02：按范围查找项目

作为制作者，我希望搜索和排序找到自己的项目，两种视图结果一致。

范围追踪：FR-PROJECT-03，原始规则见[功能需求](../requirement/07-项目需求.md#3-功能性需求)。

1. 授权范围先筛选后分页。
2. 网格/列表ID与总数一致。
3. 排序使用确认口径。
4. 空列表/无匹配/失败分别提示。

### US-PROJECT-03：从剧本或已有项目开始

作为制作者，我希望导入或复制后获得独立且可继续创作的项目。

范围追踪：FR-PROJECT-02、FR-PROJECT-04，原始规则见[功能需求](../requirement/07-项目需求.md#3-功能性需求)。

1. 导入任务可查询且失败保留项目。
2. 复制产生新身份。
3. 编辑副本不改原内容。
4. 重复复制定位同次操作且引用权限有效。

### 依赖、假设与质量

- 必要依赖：06用户；带剧本创建依赖11，复制媒体需要08的授权引用。
- 尚待决定：风格四类/五项差异、最近打开/最近更新、空名称默认、复制内容与历史范围。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/07-项目需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/07-项目需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
