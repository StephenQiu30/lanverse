## 1. 切片原则

每个切片必须从真实入口走到用户可观察结果，同时交付后端事实、OpenAPI、生成客户端、前端 View/ViewModel、失败路径和自动化验证。不得先创建九个模块空壳，也不得以“页面存在”或“所有表都有 CRUD”作为完成。

纵向切片决定 PT 的组合和交付顺序，PRD-004 至 PRD-006 说明模块产品边界，PRD-007 至 PRD-009 定义产品范围与接受单元；工程领取、估算和完成只使用 PLAN-000 的 `DEV-*`。切片退出必须同时通过本文件的用户闭环和全部所含 PT；不能以一条 E2E 掩盖某项任务的权限、并发或恢复缺口。

切片只按依赖顺序前进：`S0 工程基线 → S1 立项 → S2 剧本资产 → S3 分镜准备 → S4 镜头生产 → S5 成片交付 → S6 发布加固`。后续切片可以探索，但前序退出条件未通过时不能宣告后续完成。

## 3. S0 可运行工程基线

目标：开发者在不污染系统环境的前提下，使用本机版本和显式依赖启动最小 API/前端，并能区分进程存活与依赖就绪。

范围：根命令入口；backend/frontend 最小配置；Python 3.11.15 + PyCharm 标准 `.venv`/pip；Node 22.23.1 + npm 10.9.8；Vercel 官方 create-next-app 生成 React 19 + Next.js App Router + Tailwind 基线，再接入 shadcn/ui/Radix UI；PostgreSQL 18.4、Redis 8.8.1、RabbitMQ 4.3.4 复用本机服务；MinIO 固定镜像由用户主动 Compose；空库初始化；JSON 日志/trace 基线；OpenAPI 生成到 `frontend/src/api`；测试与生产目录分离。

退出条件：

- `setup` 使用调用者已有的 Python 3.11.15 创建 `backend/.venv`，只在该环境内用 pip 安装提交的 requirements 锁；不下载 Python、不全局安装、不隐式启动容器，缺解释器时明确失败。
- S0 只运行 API；Scheduler、I/O Worker、Media Worker 在 S2 首个真实异步用例中加入且复用同一 backend 项目/镜像，不创建空入口。`healthz` 只表示进程存活；`readyz` 按运行角色区分硬依赖与降级能力，API 的 Redis/MQ/MinIO 局部故障不得让无关普通读写整体 unavailable。
- 空数据库可显式初始化；非空且结构不符时拒绝“自动修复”。
- S0 只验证单 Metadata 和增量注册机制，不创建九个业务模块的 Model；每个后续切片验证本切片新增 Model 与已接受表设计一致，PT-DAT-003 从 S1 的真实租户外键开始累计证据。
- FastAPI 输出 OpenAPI，前端 client 可重复生成且生成后无未提交漂移。
- 架构测试拒绝 `backend/src/lanverse`、源码内测试、跨模块 ORM 导入、手写 API DTO 和受管目录外缓存/数据。

## 4. S1 单人立项闭环

用户故事：作为首次进入平台的 owner，我可以获得个人空间，创建一部短剧和一个 Episode，并始终只访问自己的事实。

范围：本地注册、密码登录、短期 JWT、注销/改密；UserAccount/Workspace/Membership/ActorContext；个人空间；Project/Episode CRUD、预算命令、归档/恢复；生产概览的空状态和下一动作；项目入口页面。

退出条件：

- 并发注册同一邮箱只创建一个 UserAccount、一个个人 Workspace 和一个 owner Membership，三者原子成功；注销后旧 JWT 立即失效。
- owner 能创建/修改 Project 与 Episode；阶段来自服务端快照，前端不能 PATCH 阶段或预算字段。
- 跨 Workspace 的详情、列表和写入均不可探测；viewer/editor/owner 能力矩阵自动验证。
- Project/Workspace 归档后禁止新写入但历史可读；空白草稿删除与 blockers 可解释。
- 浏览器 E2E 完成“注册 → 登录 → 创建项目 → 创建单集 → 看见导入剧本下一动作 → 注销”。

## 5. S2 剧本结构与资产准备

用户故事：作为创作者，我可以导入已有剧本，确认 AI 提取结果，并建立有来源、授权和私有参考媒体的项目资产。

范围：ScriptSource/Version；Scene/Dialogue；最小 Task/Outbox/提取 Worker 与异步 ExtractionBatch；候选决议；UploadSession/MediaVersion/Lineage；Consent；六类 Asset/Version/readiness；剧本与资产工作区页面。这里只实现文本提取实际需要的任务阶段，Attempt 对账、费用和镜头生成在 S4 扩展。

退出条件：

- 导入并发布不可变 ScriptVersion；修改正文只创建新版本，旧版本及引用保持可读。
- 启动提取同事务写 Batch、Task 和 Outbox 并快速返回；刷新/Worker 重启后从服务端恢复；重复消息、重复启动和重复候选决议不创建重复下游事实。
- 文本提取只允许通过 LangChain DeepSeek 调用 `deepseek-v4-pro` 非思考结构化输出；未配置 `DEEPSEEK_API_KEY` 时，提取 Task 必须进入可解释的失败/阻断状态，不得用其他模型、静态候选或假成功替代；完成真实提取后才允许 S2 退出。
- 必需 Scene/Dialogue 候选全部决议后才可确认结构；Asset/Shot 候选在稳定结构版本后创建或关联。
- 私有对象直传完成时校验大小、MIME、sha256；失败不创建“可用”MediaVersion，访问能力短期且不跨空间。
- 角色、场景、声音等 AssetVersion 经类型化字段、媒体和 Consent 计算 draft/ready/blocked；切换当前版本不改旧引用。
- E2E 完成“导入 → 提取 → 人工决议 → 确认结构 → 建立至少一个 ready 角色、场景和声音资产”。

## 6. S3 分镜准备闭环

用户故事：作为导演，我可以逐镜头确认叙事、画面、动作、声音和固定资产版本，并知道每个镜头为什么能或不能生成。

范围：Shot、ShotSpecVersion、AssetReference、重排/复制/拆分/合并、readiness、资产升级预检、分镜页面与批量阻塞摘要。

退出条件：

- 可从已确认结构中的 `kind=shot` Candidate 或手工幂等建立 Shot；未确认/跨 Episode 来源拒绝，单集 active 上限 120。
- 保存 ShotSpec v1 完整类型化规格产生新 ShotSpecVersion；固定 Script/Scene/Dialogue 和 AssetVersion，500～15,000 ms；版本冲突返回服务端最新版本，不覆盖用户或历史输入。
- 重排携带完整 active Shot ID 集合和 expected order_hash；缺失、重复、跨集或陈旧顺序均整体失败并返回服务端顺序。
- readiness 明确列出字段、资产、授权、媒体、时长 blockers/warnings/next_actions；依赖不可用不能误报 ready。
- 切换 ScriptVersion、AssetVersion 当前指针或撤销授权只产生影响清单，不自动改变既有 ShotSpec。
- copy 不复制下游证据；split/merge 必须以最新 impact_hash 确认完整目标 Spec，并写只追加 ShotTransform，Candidate、Task、Media、费用、审核和时间线均不迁移。
- E2E 完成“结构化剧本 → 镜头重排 → 固定资产版本 → 所有验收镜头 readiness=true”。

## 7. S4 单镜头生产闭环

用户故事：作为生成操作员，我可以看到真实能力和预计成本，为 ready 镜头生成候选；即使刷新、超时或 Worker 重启，也能恢复并安全选择结果。

范围：ModelCapability；生成预检；GenerationRequest；Task/Attempt；Reservation/CostEntry；Outbox/Inbox/RabbitMQ；ProviderAdapter；Candidate/Lineage；任务与费用页面。

退出条件：

- 预检校验固定 ShotSpec、授权、参数、媒体和额度，并返回预计成本；高成本确认缺失时无副作用。
- 提交在一个事务中写 Request、Task、Reservation/CostEntry 和 Outbox，并在 1 秒基线内返回 Task。
- RabbitMQ 至少一次投递、重复回调和消费者重启只产生一次业务结果；结果提交后才 ack。
- 发送结果不明进入 unknown，使用原 provider_request_key 对账；未确认不存在前不得创建第二次外部发送。
- 候选输出、MediaVersion、Lineage 和费用可追踪；选择过期规格的候选返回版本冲突且不删除其他候选。
- 批量生成逐镜头独立收敛；一个失败不抹掉其他成功结果；终态费用满足预占、结算和释放不变量。
- 真实默认 Image/Video Provider 的 E2E 完成“提交 → 刷新恢复 → 候选选择”，fake adapter 只算契约证据。

## 8. S5 成片审核与交付闭环

用户故事：作为创作者和审核人，我可以把已选镜头、配音和字幕组成时间线，定位问题返工，批准固定版本并下载可验证交付物。

范围：已上传/登记的声音资产与字幕候选（不新增 AI 语音/音效供应商）；Timeline 草稿与 operations；预览；TimelineVersion；Review/Issue/Decision；FFmpeg Render；Moderation/Label；DeliveryManifest；时间线与审核页面。

退出条件：

- 时间线按镜头选择初始化，缺失媒体返回具体 Shot；刷新来源只展示差异，不覆盖用户编辑。
- 批量 Clip/Cue 操作使用 revision 原子提交；发布前校验来源、时间范围、轨道、字幕和完整镜头。
- Review 绑定固定 TimelineVersion；阻塞 Issue、授权或内容检查失败时不能批准，新版本不继承旧批准。
- 最终 Render 快速返回 Task；固定输入经 FFmpeg/ffprobe 产生 MP4/SRT 和不可变媒体血缘，重试不覆盖成功输出。
- 标识写入和 hash 验证完成后才创建 DeliveryManifest；清单逐 Clip 关联 ShotSpec、资产、Task/Attempt、费用和审核。
- 浏览器 E2E 完成“初始化 → 编辑 → 预览 → 退回 Issue → 新版本批准 → 渲染 → 下载 MP4/SRT/Manifest”。

## 9. S6 发布加固

目标：在工作基线、依赖故障和重启条件下重复完成 S1–S5，不依赖人工修数据库、清队列或让客户端猜状态。

退出条件：

- Redis 清空/不可用时普通读安全回源，高成本限流失去保护时 fail closed；缓存永不改变业务结果。
- Publisher、RabbitMQ、Worker、Scheduler 和 FFmpeg 在受控边界中断后从 PostgreSQL/对象事实恢复，无重复副作用。
- Schedule 多实例领取只生成一个 ScheduleFire/Task；misfire、lease 回收和 manual_attention 有自动化证据。
- 日志脱敏、trace 关联、指标基数、告警入口和 exporter 故障降级通过；不记录 token、提示正文或预签名 URL。
- 基准数据达到 PRD-001 的 API、异步可见性和并发目标；浏览器核心流程键盘可操作。
- 固定验收剧本连续完成两次，第二次包含局部返工和至少一次受控恢复演练；无 P0/P1 未解决缺陷。

## 10. 切片变更规则

新增能力只有同时说明用户结果、事实所有者、前置依赖和自动化退出证据，才能进入某个切片。P1 能力不得借“顺手实现”进入 MVP；未量化或外部依赖未选择时记录阻塞，不用占位代码伪装完成。
