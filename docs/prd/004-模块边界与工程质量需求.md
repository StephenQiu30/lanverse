# 模块边界与工程质量需求

## 1. 目标

在不提前拆微服务的前提下，使 identity、ingestion、catalog、search、creation、generation、asset、governance 可独立测试、替换基础设施并避免循环依赖。

## 2. 模块要求

| 模块 | 唯一职责 |
| --- | --- |
| identity | 用户、邀请、会话、角色 |
| ingestion | 来源、采集运行、解析候选 |
| catalog | 模板、示例、分类、发布状态 |
| search | 可重建目录搜索投影 |
| creation | 草稿、模板预填、参数编辑 |
| generation | 模型能力、job、attempt、配额 ledger |
| asset | 来源/用户对象、variant、作品、receipt |
| governance | 准入、审核、suppression 决策 |

## 3. 工程规则

| ID | 规则 |
| --- | --- |
| M-BR-01 | 依赖只允许 apps → application → domain，Adapter 实现 Port |
| M-BR-02 | 模块不导入其他模块内部 domain/repository/ORM，不跨 schema 写入 |
| M-BR-03 | 模块公开入口只暴露 command、result、use case、Port 和事件 |
| M-BR-04 | 跨模块同步协作通过公开 Port，耗时/可重试协作通过版本化事件 |
| M-BR-05 | Workflow 只编排流程，不复制治理、生成、资产或目录领域规则 |
| M-BR-06 | shared 只放 ID、Clock、Result、分页和基础错误 |
| M-BR-07 | 事件只携带 ID、版本、时间、trace，不携带大文本、媒体和 secret |
| M-BR-08 | 每个模块独立 schema、迁移目录、repository 和单元测试 |

## 4. 必需 Port

- `SourceConnector`：首个 Adapter 为 DiffusionDB。
- `GenerationProvider`：首个 Adapter 为 Seedream 5.0 Lite。
- `ObjectStore`：MinIO S3 Adapter。
- `TaskBus/EventBus`：RabbitMQ Adapter。
- `SearchRepository`：PostgreSQL FTS/pg_trgm Adapter。
- `ModerationProvider`、`Clock`、`IdGenerator`：生产与测试实现可替换。

## 5. 必需 Workflow

CatalogPublicationWorkflow：candidate → governance → source asset → catalog → search。

GenerationWorkflow：draft → input governance → generation → generated asset → output governance → completed work。

两个 Workflow 只通过实体 ID 关联，不共享 ORM 或供应商 SDK。

## 6. 工程验收标准

| ID | 标准 |
| --- | --- |
| AC-M01 | 自动架构测试阻止 core 导入 FastAPI/Celery/SQLAlchemy/MinIO/供应商 SDK |
| AC-M02 | 自动架构测试阻止模块导入其他模块内部 domain/repository/ORM |
| AC-M03 | 每个模块只写自己的 schema，跨 schema 写入测试失败 |
| AC-M04 | Source、Generation、ObjectStore、EventBus、Search 均有 fake 和真实 Adapter 契约测试 |
| AC-M05 | Command/Event/OpenAPI 版本化，破坏性变更必须创建新版本 |
| AC-M06 | CatalogPublicationWorkflow 在重复事件和中断后幂等完成 |
| AC-M07 | GenerationWorkflow 在重复事件、超时和补偿后只产生一个终态 |
| AC-M08 | search 投影可由 catalog 事件从空库完整重建 |
| AC-M09 | shared 中不存在业务实体、供应商类型或万能 repository |
| AC-M10 | 单体进程可按队列拆 Worker，且不改变领域或事件契约 |

## 7. 测试要求

Domain 单元测试不启动外部服务；Adapter 分别运行集成测试；Workflow 使用 fake Port 做故障矩阵；端到端测试只走公开 API/Port。架构测试和契约测试必须进入 `make verify`。

## 8. 非目标与演进

MVP 不拆服务、不建立跨模块数据库直连兼容层。只有独立扩容、故障隔离或发布节奏成为真实需求时，才沿既有 Port、事件和数据所有权拆分。

## 9. 发布门禁

AC-M01 至 AC-M10 全部通过；无循环依赖、跨 schema 写入或供应商类型泄漏；架构测试在 CI 强制执行。
