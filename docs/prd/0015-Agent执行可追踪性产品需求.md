# Agent 执行可追踪性产品需求

日期：2026-09-08。依据：用户要求继续 Agent 实现，并在编码前具备 Spec、Checklist 和完成后的审查工作。

## 目标与使用者

平台服务需要在生成前知道本次运行采用哪些阶段与审阅门，在调用后查到具体执行尝试，在服务重启后仍能恢复同一份事实。最终创作工作台通过 Go 公共接口消费这些事实；本轮首先交付 Agent 可信内部接口。

## 本轮范围

1. 发布上一轮已实现的持久 Attempt 账：并发领取、结果关联、未知结果与签名查询。发布前验证精确提交快照。
2. 新增初始 ExecutionManifest：在执行策略冻结、首次调用之前持久保存文本四阶段、必要审阅门和动态集合占位；查询保存的清单，不随服务发布重新生成旧运行的清单。
3. 使用独立测试库验证迁移、原子性、并发、刷新和权限边界，并完成需求逐项复核。

## 成功标准

已冻结的新运行即使尚未调用模型，也可查询四阶段及审阅门；重复冻结与重启不改变清单和摘要。失败不得留下半份策略或清单，也不得新增模型调用。历史运行没有清单时明确返回不可用。接口不返回原稿、提示词、凭据或候选正文。

本轮不承诺浏览器画布已展示，不新增动态逐集/逐场实例、审批操作、自动重试、费用结算、Kafka Publisher、多版本产物或媒体生产。这些仍属于 Design 的后续切片。
