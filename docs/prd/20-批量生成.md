规则与验收以 [REQ-23](../requirement/23-批量生成.md) 为准，以下为产品摘要。

## 1. 问题与价值

整场或整集逐项点击生成、确认和检查结果耗时，少数错误项还可能阻塞全部工作。批量入口一次给出逐项报价，剔除错误后一次确认，各项独立执行并汇总。对应 PRD-01 §2 的**效率、成本透明**，支撑 S1 的逐集生产与 S2 的多镜推进；P21 保证付费前人工确认，P29 保证失效项不拖累有效项。

## 2. 目标用户与场景

- 选整场或整集进行报价。
- 查看批次中成功与失败的明细。
- 连续错误时决定继续或取消。

## 3. 范围

- **做（MVP）**：多选或按范围（场 / 集 / 筛选结果）批量报价、剔除、确认、并发执行、汇总、失败重试、整批取消。
- **不做**：不做跨项目批量；V2 见 REQ-34。

## 4. 用户体验与流程

1. 在镜头表、故事板或其他批量入口选择整场、整集或筛选结果，打开逐项报价，查看错误项与总额。
2. 剔除错误或不需要的项后一次确认；页面顶部及任务中心显示批次进度和每项结果。
3. 结束后收到一条汇总通知，可查看成功/失败原因，并将失败项重新报价为新批次。
4. 超过 300 项时提示缩小范围；连续 5 项同类供应商错误时提示已暂停，可继续或取消；整批取消时提示未开始项释放预留、进行中项按取消结果结算；重启后返回原批次查看恢复进度。

## 5. 产品规则

- 单批最多 300 项（REQ-23 R1）
- 有错误的项不进入可确认列表，其余项可确认（REQ-23 R2）
- 每项独立执行、独立结算，一项失败不影响其他项（REQ-23 R3）
- 批次内并发 = min(项目并发上限 20, 供应商剩余配额)，其余排队（REQ-23 R4）
- 整批取消：未开始的项取消并释放预留；进行中的项按 REQ-24 取消规则处理（REQ-23 R5）
- 批次结束只发一条汇总通知（REQ-23 R6）
- 重试失败项生成新批次，需重新确认（REQ-23 R7）

## 6. 成功标准

- Given 整场 20 个镜头批量生成，其中 2 个失败，When 查看批次，Then 18 个成功、2 个失败各有原因，失败项可单独重试。（[TST-02](../test/02-需求追踪矩阵.md) TC-23-01）
- Given 批量报价中 3 项有错误，When 确认，Then 只执行其余项，错误项不产生费用。（[TST-02](../test/02-需求追踪矩阵.md) TC-23-02）
- Given 执行中取消批次，When 检查，Then 未开始项已取消且预留释放。（[TST-02](../test/02-需求追踪矩阵.md) TC-23-03）

以上为 [REQ-23](../requirement/23-批量生成.md) §3 的 TC-23-01～03；关联质量要求见 [REQ-02](../requirement/02-非功能需求规格.md) CAP-02、PERF-10。跟踪 PRD-01 §10 的剧本到镜头成品耗时与单分钟镜头成本；并发与报价性能按 REQ-02 验证。

## 7. 依赖与风险

- **依赖**：[PRD-18](18-报价与二次确认.md)、[PRD-21](21-任务中心与对账.md)。
- **风险**：大批量与供应商持续故障可能放大费用损失。
