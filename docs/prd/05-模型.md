# PRD 05：模型

执行编号：05；来源需求模块：10。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

为生图与生视频提供真实可选能力及不可变模型版本。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/10-模型需求.md)中的业务规则。对应[模块Plan](../plan/05-模型.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：管理员、制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

画布中的占位模型名和固定时长不能作为真实供应商支持证据。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

为生图与生视频提供真实可选能力及不可变模型版本。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为管理员，我希望编辑同一份模型草稿，使表单、JSON和差异视图不互相矛盾。
- 作为制作者，我希望只看到可运行的发布模型，并按其能力设置生成参数。
- 作为管理员，我希望停用模型后阻止新调用，同时保留既有任务事实。

## 6. 价值与范围取舍

先提供可用生图、图生视频模型版本及各自参数约束；候选数、画幅、时长取实际发布版本，不硬编码×2或4s。

完整JSON/差异维护体验可在最小发布链后补齐，不能跳过实际能力校验。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/10-模型需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/10-模型需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-MODEL-01：管理模型草稿

作为管理员，我希望编辑同一份模型草稿，使表单、JSON和差异视图不互相矛盾。

范围追踪：FR-MODEL-02～03，原始规则见[功能需求](../requirement/10-模型需求.md#3-功能性需求)。

1. 创建持久草稿。
2. 供应商/标识有效。
3. 参数冲突不发布。
4. 并发失败保留输入且历史按需读取。

### US-MODEL-02：发布可选能力

作为制作者，我希望只看到可运行的发布模型，并按其能力设置生成参数。

范围追踪：FR-MODEL-01、FR-MODEL-04，原始规则见[功能需求](../requirement/10-模型需求.md#3-功能性需求)。

1. 发布版本不可变。
2. 图片与图生视频能力可分辨。
3. 未发布/停用不可新提交。
4. 历史任务定位原版本且不同入口约束一致。

### US-MODEL-03：控制新任务可选性

作为管理员，我希望停用模型后阻止新调用，同时保留既有任务事实。

范围追踪：FR-MODEL-05，原始规则见[功能需求](../requirement/10-模型需求.md#3-功能性需求)。

1. 停用真实持久。
2. 新提交服务端拒绝。
3. 历史版本不删除。
4. 在途任务按已确认政策处理。

### 依赖、假设与质量

- 必要依赖：06、09；与14共同校验发布能力。
- 尚待决定：模型key格式/唯一性、参数校验、区域默认与限制、停用对在途任务的影响。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/10-模型需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/10-模型需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
