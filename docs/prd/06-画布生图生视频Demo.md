# PRD 06：画布生图生视频 Demo

## 1. 概述

首轮最重要的结果是：制作者进入真实项目，在画布建立图片生成节点，提交提示词得到真实图片，明确选择其中一张接入视频生成节点，再生成并播放真实视频；刷新和服务重启后仍能找到原画布、输入、任务与结果。

本文件细化本次用户明确优先的跨模块闭环，对应[Demo Plan](../plan/06-画布生图生视频Demo.md)。需求依据为[项目](../requirement/07-项目需求.md)、[素材](../requirement/08-素材需求.md)、[供应商](../requirement/09-供应商需求.md)、[模型](../requirement/10-模型需求.md)、[生成](../requirement/14-生成需求.md)与[画布](../requirement/16-画布需求.md)。节点类型、输入边与采用方式属于本次具体化提案，尚待接受；本文件不是已接受的数据/接口Design。

## 2. 参与者与责任

| 角色       | 本闭环责任                                       | 当前情况                             |
| ---------- | ------------------------------------------------ | ------------------------------------ |
| 制作者     | 编辑节点、比较图片、确认视频输入与费用、播放结果 | 真实演示账号及验收人待落实           |
| 管理员     | 配置凭据/发布模型，按权限核对未知任务            | 不能用页面固定管理员身份替代         |
| 产品负责人 | 接受首轮范围、选图/连线语义、费用与外发规则      | 用户已明确Demo优先，具体政策仍待确认 |
| 工程负责人 | 评审模块边界、供应商可行性、Design和运行条件     | 人员与产能待落实                     |
| 测试负责人 | 核真实媒体、持久恢复、故障和浏览器证据           | 人员、环境与质量阈值待落实           |

## 3. 背景与现状证据

当前[画布实现](../../frontend/src/app/canvas/_components/canvas-page.tsx)使用固定镜头fixture、项目名称、占位模型与本地React状态。生成按钮只设置generated并显示“2个演示候选已生成”，保存标签固定显示“所有更改已保存”。这些是本次源码观察，说明页面不能作为真实生成/保存证据；不据此断言旧后端完全没有可复用逻辑。

[PROJECT](../../PROJECT.md)明确：新业务数据/接口方案尚未接受，旧Schema、API与模块拓扑不得反向约束当前设计。因此先核真实生图和图生视频能力及费用，再以当前需求形成Design；复用已接受工具链，不恢复旧工作台、旧报价平台或未来DAG框架。

## 4. 目标与成功标准

目标是完成一条用户可亲自复现的真实生成链，先证明节点、输入、任务和媒体之间的关系，再扩大创作范围。

| 结果         | 首轮验收尺度                                                                               |
| ------------ | ------------------------------------------------------------------------------------------ |
| 生图         | 至少一项接受的真实图片模型产出可解码图片；文件、媒体身份与任务冻结输入一致                 |
| 图片驱动视频 | 至少一项真实图生视频能力使用用户明确选择的图片，产出可播放视频；不能偷偷退化成无图文生视频 |
| 持久与恢复   | 同一项目/画布/节点/任务在刷新及服务重启后读回；旧结果仍可打开                              |
| 正确性       | 未就绪/越权/能力不匹配在调用前拒绝；同次重复请求不产生重复任务/候选或再次付费调用          |
| 安全恢复     | 供应商受理后丢响应进入未知并先核对；迟到结果不覆盖手工选择或更新草稿                       |
| 可操作       | 在确认的桌面环境中关键操作键盘可达、错误和等待可辨；移动端展示限制另记录                   |

以上“至少一项”是本次最小样本范围提案，不是覆盖全部供应商、模型或SLA。窗口、演示设备/浏览器、具体模型、费用上限和性能阈值待确认；不编造完成日期或成功率。全部接受的D-AC通过才可标Demo验收，文档检查、mock测试与真实业务验收分别记录。

## 5. 使用者与场景

核心使用者是希望先做出一段短视频的制作者。他可以从空白项目与提示词开始，不必先导入剧本、建立分集或形成镜头。管理员只提供可用生成条件和风险核对，不能代替制作者的选图与费用确认。

完整剧本→设定→镜头链仍保留在[模块执行顺序](../plan/00-执行顺序.md)，不会因为本轮Demo先完成就宣称完整创作系统已完成。外部供应商输出质量与价格尚无本次实测证据，不作竞品或商业结论。

## 6. 价值与首轮范围

制作者可以在同一画布理解“这张图来自哪次生成、这个视频用了哪张图”，并在失败后保留已完成工作。这个最小结果能验证当前产品的核心节点生成体验。

| 首轮必须                                        | 本轮后续范围                                             |
| ----------------------------------------------- | -------------------------------------------------------- |
| 真实身份、空白项目与项目归属                    | 注册/账号管理完整体验、项目复制、带剧本创建              |
| 可用生图与图生视频发布模型、服务端凭据          | 多供应商覆盖、复杂模型管理体验                           |
| 图片/视频生成节点的新增、编辑、移动、保存、读回 | 镜头/设定/故事板等业务节点和其他媒体节点                 |
| 明确选图、图片到视频输入边、手动分别提交        | 自动执行整图、多路聚合、并行调度、尾帧、多图、多视频输入 |
| 真实任务状态、候选媒体、图片预览、视频播放      | 配音、Agent建议、导出、全局搜索/通知、时间轴             |
| 必要费用确认、权限、幂等、核对、关键事件记录    | 完整报价/支付/退款平台与历史数据迁移                     |

未进入首轮的已有需求不删除。首轮节点删除、撤销/重做与视口持久范围需要在Design决定是否纳入；暂不纳入时入口必须准确说明状态，不能展示假成功。

## 7. 方案、用户故事与验收

### 7.1 用户主流程

1. 制作者真实登录，创建或打开本人空白项目，进入同一项目的空画布。
2. 新增图片生成节点，输入提示词，选择真实发布的图片模型及支持画幅/数量，保存草稿。
3. 查看本次输入与必要费用/外发说明，明确确认后提交；节点展示真实排队/运行/失败或未知状态。
4. 图片产出并达到接受的媒体可用条件，节点展示实际候选缩略图。用户预览并明确选择一张。
5. 新增视频生成节点，从上述已选图片建立输入关系；在视频节点中展示输入图片缩略图、来源节点/候选与用途。
6. 输入运动描述，选择支持该输入方式的发布视频模型、画幅和时长；再次确认本次输入与费用，手动提交。
7. 视频节点出现实际候选，用户播放真实视频并查看任务来源；继续修改草稿不影响历史任务。
8. 刷新、退出再打开及服务重启后，仍能找回节点、引用、选图事实、冻结任务和实际媒体。

用户可先只完成步骤1～4验收生图，再完成5～8验收全链。生图阶段不能命名为完整Demo通过。

### 7.2 节点与连线合同提案

| 对象             | 最小内容与可观察行为                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 画布             | 项目身份、画布身份、结构revision、节点与边；保存结果区分未保存/保存中/已保存/失败/冲突              |
| 图片生成节点     | 节点身份/类型/位置；图片草稿（提示词、模型发布版本、支持参数）；关联任务、候选及用户明确选中的图片  |
| 视频生成节点     | 节点身份/类型/位置；视频草稿（运动描述、模型发布版本、支持画幅/时长）；图片输入绑定、关联任务与候选 |
| 图片到视频输入边 | 明确源图片节点、候选、媒体身份/版本，目标视频节点与图片输入用途；边代表输入关系，不只是装饰线       |
| 任务             | 服务端可查询身份、输入快照、模型版本、必要确认事实、执行状态、安全原因及真实结果                    |
| 媒体/候选        | 真实字节、类型/尺寸或时长、就绪/审核事实、项目授权、来源任务；不是将供应商临时URL长期写入节点       |

首轮建议使用单张图片作为视频首帧，必须先验证模型支持该方式。若实际只支持其他图片参考模式，应先修改并接受输入用途，不静默替换；本轮不假定所有视频模型都接受首帧。

连线最小行为：

- 用户必须明确选中可用图片候选后才能建立视频输入边；一个视频节点只绑定一个此类图片输入。拒绝越权、缺图、未就绪、类型不符、自连及不支持的边。
- 建立边或点击选图只更新草稿，不调用供应商。视频必须由用户单独提交并确认本次费用。
- 边绑定明确候选/媒体版本。上游重新生图或改选不自动改变边；显示来源已变化，用户明确“更新输入图片”后再保存。
- 下游已提交任务始终使用原冻结图片；更新草稿或连线不改旧任务。旧视频可播放，显示与当前输入不同，不自动重生成。
- 同一节点多次生成时保留历史任务；返回结果关联原任务，不挪到其他节点或覆盖新草稿/人工选择。
- 切换项目不保留旧项目的选中媒体与请求缓存；刷新从服务端恢复身份和关系。缩放/适应只改变视口，不能重置节点坐标。

该表描述业务信息，不预定表名、HTTP路由、队列或存储选型。技术Design需落实版本冲突、事务边界、授权媒体访问、临时链接更新与任务恢复。

### 7.4 输入、确认与状态

每次提交冻结：项目/画布/节点身份、提示词及适用后缀、模型发布版本、画幅/时长/候选数等实际参数、参考用途/顺序及媒体版本、用户确认事实与幂等请求标识。收费确认必须与该快照一致；改变输入后旧确认不能直接执行新任务。

| 事实                               | 界面及恢复要求                                               |
| ---------------------------------- | ------------------------------------------------------------ |
| 草稿未保存/保存中/已保存/失败/冲突 | 回执前不报已保存；失败留本地输入；冲突让用户核对版本         |
| 提交中但尚未收到任务回执           | 使用本次请求标识核对原提交，不能直接创建新收费请求           |
| queued / running                   | 查同一任务；进度/已耗时来自真实事实，不播放固定倒计时        |
| 生成输出已返回但媒体未可用         | 可显示结果处理中；图片不可选作输入，视频不能报可播放         |
| 成功且媒体可用                     | 展示真实候选；人工选择与任务成功是两件事                     |
| failed                             | 显示已确认的失败事实及安全原因；是否可重试依供应商与费用规则 |
| unknown / manual                   | 显示尚未确认/待核对与下一步；禁止用通用“重试”再次收费        |
| 候选选中/输入来源已变              | 用户明确动作持久化；旧任务输入只读，不随上游修改             |
| 原件不可用或媒体访问失效           | 重新授权或安全失败，保留任务来源，不以占位媒体替代结果       |

生成状态与媒体就绪/审核必须分别表达；不为页面增加没有实际处理依据的状态机。取消、自动重试与费用返还在政策明确前不加入首轮。

## 8. 分阶段交付

- **阶段A：最小基础**。真实身份/空白项目，媒体授权，可用供应商与两类模型，接受节点/费用/恢复Design。

- **阶段C：图片到视频**。输入边、参数冻结、视频生成/播放与恢复，执行全部接受场景。

阶段只表达依赖顺序，不承诺周期；人员和真实外部条件明确后再估算。完成标准及证据表见[Demo Plan](../plan/06-画布生图生视频Demo.md)，模块完整范围见[执行顺序](../plan/00-执行顺序.md)。
