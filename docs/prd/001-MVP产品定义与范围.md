## 1. 产品结论

MVP 服务一名可以兼任编剧、导演、生成操作员和审核人的 owner，把一份已有单集剧本制作成可完整播放、可审核、可局部返工且来源与成本可追溯的竖屏短剧。完成标准不是“模型返回了视频”，而是交付 MP4、独立字幕和可验证 DeliveryManifest。

平台按项目、单集和镜头组织生产；AI 结果先成为候选，只有人工确认后才成为下游事实。页面刷新、断线、Worker/Scheduler 重启或供应商超时后，用户必须从服务端看到真实状态、阻塞原因和下一动作。

## 2. 目标用户与核心任务

| 用户 | 核心任务 | MVP 边界 |
| --- | --- | --- |
| owner | 创建个人空间、项目和单集，控制预算并完成全部生产与交付 | 首个闭环唯一必须支持的用户 |
| editor | 编辑剧本、资产、分镜、时间线，发起生成和审核 | 权限模型保留；成员邀请不进入 MVP |
| viewer | 查看进度、任务和成片 | 权限模型保留；外部审片不进入 MVP |

用户核心路径：`首次登录 → 创建项目/单集 → 导入剧本 → 确认结构与资产 → 确认 ShotSpec → 逐镜头生成并选用候选 → 编排时间线 → 审核返工 → 渲染交付`。

## 3. MVP 工作基线

以下数值是首个可执行版本的工作基线，不是对所有生产环境的永久承诺；实测无法满足时必须先修订本 PRD，不能在实现中静默放宽。

| 项目 | MVP 基线 |
| --- | --- |
| 单集 | 1 个 Project 至少完成 1 个 Episode；目标成片 60–180 秒 |
| 镜头 | 典型 12–36 个 active Shot，单集硬上限 60；单镜头建议 3–10 秒 |
| 剧本 | 单个 ScriptVersion 正文不超过 20,000 个 Unicode 字符；超限拒绝并给出拆分建议 |
| 资产 | 支持 character、location、prop、costume、visual_style、voice 六类固定版本资产 |
| 候选 | 单次生成默认 2 个、最多 4 个候选；批量生成逐镜头返回独立结果 |
| 并发 | 单 Workspace 默认最多 2 个外部生成 Attempt、1 个媒体渲染；均可配置但必须有界 |
| 上传 | 单文件上限 2 GiB；对象默认私有，必须校验 MIME、大小和平台 sha256 |
| 交付 | 9:16、1080×1920、H.264/AAC MP4；独立 UTF-8 SRT；帧率默认 25 fps |
| API | 基准数据下普通 CRUD P95 ≤ 500 ms，生产概览 P95 ≤ 1 s，不含外部模型/FFmpeg 时间 |
| 异步可见性 | 提交命令 P95 ≤ 1 s 返回 Task；依赖正常时 queued 工作 P95 ≤ 5 s 对 Worker 可见 |
| 恢复 | API/Publisher/Worker/Scheduler 重启后 60 s 内恢复领取；unknown 必须显示对账动作而非自动重发 |
| 可访问性 | 核心流程可仅用键盘完成；焦点、错误和状态不能只依赖颜色表达 |

性能基线使用固定规模数据和固定本机/CI 环境验收；供应商生成耗时只记录和展示，不承诺由平台控制的完成时限。

## 4. MVP 必须具备的业务结果

1. 身份与立项：首次 OIDC 登录幂等建立个人 Workspace/owner Membership，并能创建 Project/Episode。
2. 剧本与结构：导入正文、发布不可变 ScriptVersion、异步提取并人工决议 Scene/Dialogue/Asset/Shot 候选。
3. 资产与分镜：登记授权与私有媒体，建立类型化 AssetVersion，保存不可变 ShotSpecVersion 并获得可解释 readiness。
4. 镜头生产：预检能力、授权、输入和预算；创建可恢复 Task，处理候选、取消、unknown 对账和成本收敛。
5. 时间线与审核：组合视频、声音和字幕，发布 TimelineVersion，围绕固定版本创建 Issue、批准或退回。
6. 交付：从获批版本异步渲染，写入并验证生成标识，生成带 hash、字幕和来源链的 DeliveryManifest。
7. 平台保障：跨 Workspace 隔离、幂等、Outbox/Inbox、缓存故障回源、持久调度、结构化日志和恢复验证成立。

## 5. 关键产品规则

- ScriptVersion、AssetVersion、ShotSpecVersion、MediaVersion、TimelineVersion 和 DeliveryManifest 只追加，不原地覆盖。
- readiness、current_stage、blocking_reasons 和 next_actions 由服务端事实计算，前端不得自行判定。
- 高成本生成必须先返回预计消耗并获得明确确认；预检失败不产生 Task、预占或供应商副作用。
- Task 的 `unknown` 不等于失败；必须用原 provider_request_key 对账，确认未产生副作用后才能重试。
- Candidate 选用和重选保留全部历史；已发布 TimelineVersion 不随当前候选变化而漂移。
- 授权失效、阻塞 Issue、内容检查未通过或标识验证失败必须阻止新的生成或交付。
- 只有无引用、无费用、无审核的空草稿可硬删除；其他业务历史只能归档或按受控留存策略清理。

## 6. 产品成功指标

| 指标 | MVP 通过条件 |
| --- | --- |
| 主链路完成率 | 固定验收剧本能从新建项目走到可下载 MP4/SRT/Manifest，关键 E2E 连续通过 |
| 局部返工 | 任一镜头退回后只创建该镜头的新规格/任务/候选，不要求整集重跑 |
| 恢复正确性 | 刷新、重复消息和受控进程重启后不丢已确认事实，不产生重复供应商调用或重复结算 |
| 追溯完整性 | DeliveryManifest 中每个 Clip 可追溯到 ShotSpec、资产、Task/Attempt、Media、费用和审核决定 |
| 租户隔离 | 自动化跨 Workspace 读取/写入用例全部拒绝且不泄露资源存在性 |
| 成本一致性 | 每个终态 Reservation 的结算、释放和调整可解释收敛；unknown 可保留但必须显示原因 |
| 质量门禁 | Ruff、Pyright、Pytest、Vitest、Playwright、真实基础设施契约和架构测试全部通过 |

## 7. MVP 非目标

- 不做团队邀请、项目级 ACL、实时协作、外部审片、移动端、社区、市场或自动渠道发布。
- 不做一句话无人审核成片、专业 NLE、无限画布、任意工作流/cron、模型训练或自托管 GPU 调度。
- 不拆微服务，不引入第二任务系统、第二消息队列、事件溯源或通用审批/CRUD 引擎。
- 不保证模型绝对一致；通过固定资产版本、参考输入、候选选择、审核和局部返工降低漂移。

## 8. 外部决策门禁

| 决策 | 最迟完成时间 | 未完成时的处理 |
| --- | --- | --- |
| OIDC issuer、audience、测试租户和恢复渠道 | S1 开始前 | 只允许身份契约测试，不实现伪登录进入产品主链路 |
| 默认 Text/Image/Video/Speech 供应商、模型、参数和价格 | Text 在 S2 前，其余在 S4 前 | 可使用确定性 fake adapter 验证流程，但对应切片不得宣告完成 |
| 目标上线地区、授权材料、审核责任、标识与留存规则 | S2 权利录入前初选，S5 交付前冻结 | 不得把未知合规状态默认为通过 |
| RabbitMQ、MinIO 的本机或显式 Compose 提供方式与安全配置 | S0 基础设施验收前 | setup 失败并给出前置条件，不自动安装或启动 |
| 固定性能环境和供应商测试额度 | S4/S6 压测前 | 只记录功能通过，不报告性能或真实供应商验收通过 |

## 9. MVP 发布判定

只有 S0–S6 全部满足退出条件、外部决策已关闭、固定验收剧本完成端到端演练且没有 P0/P1 缺陷，才能标记 MVP 可发布。P0 指跨空间泄露、凭据泄露、数据丢失、重复扣费或主链路整体不可用；P1 指核心切片无法完成、事实/恢复/交付错误且没有安全替代路径。实现未完成、测试中断、真实依赖缺失或仅 fake provider 通过时，都不得创建“已验收”结论。
