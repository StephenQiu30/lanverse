## 1. 概述

**一句话定位**：Lanverse 是以已有剧本为起点、以可发布成片为终点的 AI 短剧生产线，并提供 LibTV 式的无限画布与对话式 Agent 作为探索与精修界面。**首个版本（MVP）**做到“每个镜头的选定视频与每句台词的选定配音”，同时提供流水线、画布与对话式 Agent（P25、P27）；剪辑与成片在 V2。

1. **首先是内部生产工具**：服务自己的 1–2 人制作小组，把成品剧本高效、可控地做成可发布成片；对外产品化在内部跑通之后。
2. **核心价值排序：一致性 > 可控性 > 成本透明 > 生成效率。** 生成质量主要由第三方模型决定，平台负责让它稳定、可控、可追溯。
3. **两种视图、一份数据**：流水线视图负责按阶段批量生产，画布视图负责探索与精修；MVP 同时交付流水线视图、画布与对话式 Agent（P27）。
4. **范围优先于时间**：以完整业务流程功能的确定为准，时间不作硬约束（P13）。

## 2. 背景与问题

内部团队已有成品剧本，希望用 AI 替代实拍或传统动画制作短剧。现有做法是在多个工具之间手工搬运：大模型拆剧本 → 生图工具定角色 → 视频模型逐镜头生成 → 配音工具 → 剪辑软件。

| 问题 | 表现 | 后果 |
| --- | --- | --- |
| 角色不一致 | 同一角色换镜头就换脸，服装、场景漂移 | 成片不可用，反复重拍 |
| 不可控 | 抽卡式生成，画面不符合分镜；改一处要全部重来 | 效率低、成本高 |
| 素材混乱 | 版本、文件散落各处 | 不知道成片用的是哪一版，无法追溯 |
| 成本不清楚 | 重试、重复生成的花费无法按镜头统计 | 无法做预算与定价 |
| 规模化难 | 60 集的剧，角色与场景要在每集重复处理 | 长剧无法量产 |

## 3. 产品目标

### 3.1 目标

| 类型 | 目标 |
| --- | --- |
| 业务目标 | 用平台替代多工具手工流程，使内部团队能以可预期的成本量产短剧；为之后的对外产品化积累能力与数据 |
| 用户目标 | 制作者在一个平台内完成从剧本到成片的全部工作；每一步可控、可回退、可追溯；随时知道花了多少钱 |
| MVP 目标 | 1 人在平台内用流水线、画布或对话式 Agent，把一集已有剧本做到**全部镜头有选定视频、全部台词有选定配音**（写实与风格化）；具备首尾帧、改图、片段续接、模型切换等生成增强；全过程成本可查 |
| V2 目标 | 剪辑与成片交付、字幕、真人音轨替换、BGM / 音效；对外产品化：多组织、角色协作、开放接口、支付与套餐 |

### 3.2 非目标

- 不自研视频、图像、语音大模型；只做模型编排、选择与记录（P5 之外的长期可能性在 V2 后再评估）。
- 不做通用视频剪辑软件；剪辑（V2）只服务于从镜头到成片的必要步骤。
- 不做 AI 编剧与小说改编（V2 起评估）。
- 不做 3D 导演台、社区、积分会员（对照 PRD-02 §5.1）。

## 7. 产品方案概览

### 7.1 业务流程

```text
整部剧导入 → 全剧解析（集 / 场 / 台词）→ 全剧设定集（角色 / 造型 / 场景 / 道具）
                                              │
                           ┌──────────────────┴── 逐集生产（每集重复）──────────────────┐
                           │ 本集资产定稿 → 分镜 → [关键帧] → 视频 → 配音 → 剪辑 → 交付 │
                           └──────────────────────────────────────────────────────────────┘
```

每个阶段遵循同一模式：**AI 产出候选 → 人工审阅 / 修改 → 选定为正式版本**。十个阶段的输入、输出与确认点见 [REQ-03 §3](../requirement/03-业务流程与用例模型.md)。

### 7.2 视频生成的两种模式

| 模式 | 输入 | 适合 |
| --- | --- | --- |
| 图生视频 | 选定关键帧 + 镜头参数 + 运动描述 | 构图要求精确、需要先确认静帧的镜头 |
| **全能参考**（必须） | 参考组合：多角色造型图、场景图、道具图、动作 / 运镜参考视频、参考音频 + 镜头参数 + 画面描述 | 多角色同框、复杂动作、模仿参考运镜、按音频节奏表演 |

### 7.3 贯穿全流程的产品规则

1. **依赖传播**：上游版本变化，下游标记为“过期”，**不自动重新生成**；给出影响范围和预估费用，由用户决定。
2. **候选与正式分离**：AI 结果先是候选，人工选定后才被正式引用；历史版本可查。
3. **局部重做**：失败或修改只影响真实依赖。
4. **先锁定输入再生成视频**：关键帧或参考组合确认后才能生成视频。
5. **付费必须二次确认**：任何入口发起的付费生成都要用户确认报价（P21）。

### 8.2 MVP 定义

**一句话**：导入整部剧，选择其中一集，在流水线视图、画布或对话式 Agent 中完成前 8 个阶段（导入 → 解析 → 设定集 → 资产定稿 → 分镜 → 关键帧 → 视频 → 配音，REQ-03 §3），得到每个镜头的选定视频与每句台词的选定配音。范围为 REQ-01 中所有 MVP 需求，以及 REQ-02 中所有 MVP 非功能需求。

**MVP 验收场景**（全部通过才算完成）：

1. **写实项目一集**：导入一部至少 10 集的写实剧本，第 1 集（1–2 分钟体量）全部镜头有选定视频、全部台词有选定配音；可按分镜顺序在故事板中逐镜预览。
2. **风格化项目一集**：同上，风格化画风（4 种风格化各至少完成一段样例镜头）。
3. **全能参考**：写实与风格化项目中各至少 3 个镜头使用全能参考生成，其中至少 1 个双角色同框、1 个使用动作 / 运镜参考视频、1 个使用参考音频，并满足 REQ-01 VID-04。
4. **修改传播**：修改一个角色造型，系统列出受影响镜头；只重做选中镜头；旧版本可查。
5. **恢复与计费**：生成过程中重启服务、模拟供应商超时，任务恢复且账本无重复费用。
6. **第 2 集复用**：第 2 集直接使用第 1 集锁定的角色与场景进入分镜。
7. **成本**：两个项目都能查看每镜头、每集的费用明细与单分钟镜头成本（§10），并能查看跨项目成本报表。
8. **画布**：在画布上用参考连线为镜头组合参考、运行生成并把结果提升为镜头片段，流水线中同步可见；500 节点画布流畅。
9. **对话式 Agent**：让 Agent 调整一场镜头的参数并准备批量生成；提案确认后才修改，付费生成须二次确认。

**MVP 明确不做（均在 V2）**：剪辑（粗剪、时间线）与成片渲染、字幕与 SRT、真人音轨替换、BGM / 音效 / 转场、模型自动故障切换、多人协作与权限、自助注册与多组织、支付与套餐、AI 编剧、声音克隆、剪辑工程导出、项目模板、逐帧拉片、LoRA、开放接口；口型同步待定。

### 8.3 V2 范围

剪辑与成片交付（剪辑、渲染、字幕，REQ-34）、真人音轨替换（AUD-02）、BGM / 音效与转场，以及开放接口、项目模板、逐帧拉片、多成员协作、对外多组织与支付、声音克隆、剪辑工程导出、LoRA。V2 内部的先后顺序在 MVP 验收后排定。

## 10. 成功指标

MVP 期间只跟踪，不设硬性目标（P15、P16）：

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 单分钟镜头成本 | 某集全部模型费用 ÷ 该集选定片段总时长（分钟），按风格分别统计；V2 有成片后按成片时长 | 决定成本上限与模型选择 |
| 剧本到镜头成品耗时 | 从导入到一集全部镜头与配音选定的日历时间与有效操作时间 | 衡量效率 |
| 镜头一次通过率 | 首次生成即被选定的镜头占比 | 衡量可控性 |
| 平均每镜重拍次数 | 每个镜头视频生成次数的平均值 | 成本杠杆 |
| 一致性抽检通过率 | 抽检镜头中角色外观与锁定造型一致的比例 | 衡量一致性 |
| 预估与实际费用偏差 | 报价与结算的差额比例 | 衡量成本透明 |

## 11. 商业模式与成本

- **计费模式**：按量计费 + 项目预算（P4）。内部阶段只做成本核算与预算控制；对外阶段增加充值、套餐与支付。
- **成本结构**：视频生成是最大成本项【推断】；其次为生图、TTS、LLM。存储与算力为次要成本。
- **成本杠杆**：锁定输入后再生成、相同输入复用结果、控制重拍率、按镜头选择生成模式。

**规模估算【推断，P0 校准】**：

| 作品形态 | 集数 | 单集时长 | 每分钟镜头数 | 单集镜头数 | 全剧镜头数 |
| --- | --- | --- | --- | --- | --- |
| 竖屏短剧 | 60–100 | 1–3 分钟 | 20–30 | 20–90 | 1,200–9,000 |
| 中短片 / 漫剧 | 10–30 | 3–10 分钟 | 10–20 | 30–200 | 300–6,000 |
| 单片 | 1 | 1–5 分钟 | 10–25 | 10–125 | 10–125 |

以一部 80 集 × 2 分钟的竖屏短剧计：约 4,000 个镜头、约 1 万次视频生成、约 1.5 万段对白音频。容量类非功能需求见 REQ-02。

## 12. 范围取舍

**原则**：以完整业务流程功能的确定为优先，时间不作硬约束（P13）；取舍只决定实现顺序与实现深度，不删减 MVP 业务流程。

1. **优先使用模型现成能力，不自研**：全能参考、画风通过选择具备该能力的供应商实现。
2. **MVP 支持同一能力在多家模型间手动切换**（GEN-08）；自动故障切换在 V2。
3. **界面从简**：MVP 流水线视图以表格、列表、卡片为主；不做时间线（V2）。
4. **运维可由少数人承担**：统一的一键部署、监控与备份恢复（见 OPS 运维文档）。

| 需求 | 处理 | 理由 |
| --- | --- | --- |
| 写实与 4 种风格化 | MVP | 主要是模型与预设差异；P0 评测量增加 |
| **全能参考（含参考音频）** | **MVP 必须，不可降级** | 核心能力；P0 找不到可用模型时重新评估方案或时间 |
| 口型同步 | 待定 | 产品负责人确认暂不考虑 |
| 整部剧导入与解析 | MVP | 跨集一致性依赖全剧信息 |
| 批量生成 | MVP | 一集 20–90 个镜头，逐镜操作不可行 |
| 画布与对话式 Agent | MVP | P9、P20、P27 |
| 剪辑、成片、字幕 | V2 | P25 |
| 真人音轨替换 | V2 | P26 |
| 模型切换 | MVP | P27（GEN-08） |
| 自动故障切换 | V2 | 不影响出片 |

## 13. 合规要点

内部自用阶段同样按发布端要求设计。具体合规需求（CMP-01～06）见 [REQ-02 §12](../requirement/02-非功能需求规格.md)：

- 生成的图片与视频在下载时写入 AIGC 隐式标识；成片（V2）带显式与隐式标识；
- 写实人物默认使用 AI 生成的虚构人物，真人素材须授权并留存；
- 生成内容安全审核；
- 剧本版权由使用方负责，平台记录来源；
- 第三方模型备案责任确认（对外发布前）；
- 境外模型调用标注区域、项目可禁用，对外发布前法务确认数据出境。
