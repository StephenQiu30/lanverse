# 剧本到分镜 MVP 产品需求

- 状态：本轮实施基线
- 日期：2026-08-25
- 设计依据：[剧本到分镜 MVP 垂直切片设计](../design/0009-剧本到分镜MVP垂直切片设计.md)

## 产品目标

让创作者不离开一个 Web 工作台，就能把一份拥有合法使用权的整剧原稿转换为可审核、可追溯、可恢复并可导出的正式分镜数据。MVP 的价值是证明真实生产链可用，不追求一次覆盖完整短剧生产平台。

## 核心场景

创作者上传带连续集标记的 Markdown/DOCX 剧本，确认预览后固定原稿。系统生成跨剧集统一制作圣经，用户确认角色、场景、道具和世界观，再审阅分集并批量发布。进入单集后，系统提取场次、对白、叙事单元和制作任务；用户确认结构，生成分镜草案，逐镜审核并原子写入，最后导出机器可读和人工可读分镜包。

## MVP 范围

- 邮箱验证注册、创建项目和刷新恢复。
- Markdown/DOCX 上传、预览、不可变 Revision 与格式体检。
- 本地 Codex 制作圣经任务、进度恢复、实体摘要、逐项阻断决议、风险接受记录和人工确认。
- 可追溯分集建议、人工确认、原子创建与批量发布。
- 单集场次、对白、叙事单元、制作任务提取与确认；每个场次至少给出一个可审核的分镜拆解任务。
- 本地 Codex 分镜候选、逐镜决议、整批批准、Apply 预检与原子写入。
- 分镜覆盖/准备度摘要和 JSON、CSV、HTML、manifest 导出；Workflow 导出必须覆盖已应用 Draft Set 的全部剧集，不得只导出首集即报告成功。
- 独立测试数据库和 MinIO 的可重复 E2E 启动；私有 Agent 使用同一 Backend 执行契约。
- Workflow 失败节点允许从旧 Run 派生新的局部重跑 Run，只执行目标节点的下游依赖闭包并复用必要上游不可变输出；旧成功/失败 Run 不得原地重置。

## 发布门

- 浏览器刷新后仍能恢复当前项目、五集与首集制作状态。
- 未确认 Bible 时分集发布失败；blocking 问题必须逐项“接受风险”或“保留阻断”，存在未决/保留项时确认失败，全部明确接受后确认与分集发布成功。
- Bible 人工审核状态本身不能放行 Workflow；只有 Production Bible Owner 返回可追溯确认回执和正式版本引用后，下游分集任务才可读取该版本继续执行。
- Workflow 生成的分集计划必须先进入独立人工确认任务；创建候选的 Activity 不得自动确认、物化或发布，只有 Planning Owner 返回可追溯 `episode_plan.confirm` 回执和正式 confirmed Plan 引用后才能进入 Episode 创建与结构阶段；重复决议或 Signal 不得重复确认。
- Episode 创建与结构提取只能消费上述正式 confirmed Plan；物化和发布必须由 Planning Owner 分别留下可重放回执，服务中断后继续原 ImportCommit，不得重复创建 Episode。发布成功后必须形成一个可追溯的结构批次候选并进入独立结构人工审核，不能在提取节点内自动确认结构。
- 未确认结构批次时不能生成可应用分镜；Storyboard Workflow 必须为该批次全部剧集固定同一个可追溯 Draft Set，服务重试不得退化为只生成首集或改读最新草案。未经人工审核不能创建正式 Shot。批次确认必须由 Planning Owner 原子确认全部结构并返回一个可追溯回执。
- 任一场次缺少制作任务、缺少分镜拆解任务或仍有未接受的必要任务时不得确认结构；任务必须具体、可执行且能追溯到对应场次。
- 真实本地 Codex 至少完成一次 Bible 和一次 Storyboard 结构化候选，不使用模型桩。
- 同一输入导出包内容可复现，且包含来源、时间、镜头语言和资产引用。
- 节点局部重跑必须保持原 Definition/Snapshot，产生新的 Run/Temporal 身份；无关节点不执行，必要上游只作为带源 NodeRun 引用的可追溯输入，重复重跑命令不得产生第二个 Run。
- 核心 API、数据库、对象存储和 Agent Worker 的状态可检测；依赖故障不得显示成功。
- 浏览器业务 API 必须由 Go Backend 提供；Python Agent 只接受 Backend 发起的受限执行请求并返回候选，不得直接写注册、项目、剧本、Bible、结构、分镜、Shot 或导出事实。
- 运行时只能有一个 PostgreSQL 业务事实源；Backend 使用统一成熟 ORM 与一份 Model Catalog，不得维护手写 SQL Schema/Migration、Python ORM 业务模型或第二数据库写入链路。
- 只有全部开发与资源 Writer 切换完成后，才执行本轮最终浏览器验收；迁移前兼容运行时的历史证据不得用于宣称本轮发布通过。

## 非目标与风险

本轮不承诺图片、视频、声音或成片渲染，不承诺媒体 ShotWorkflow 或 60 集质量通过。单 Shot 媒体重跑必须等待真实 Generation/Shot 节点接入，不能由节点级局部重跑的基础能力替代宣称完成。模型非确定性可能产生人工阻断问题；本地 Codex 登录、计算耗时和本机 MinIO 端口均是验收外部条件，测试环境必须隔离而不能复用污染的数据库或对象存储。
