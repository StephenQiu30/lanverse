## 1. 任务边界

editing 任务交付用户可见的时间线、审核返工、渲染与下载闭环；平台保障任务交付这些业务任务可以依赖的可验证能力。平台任务不创建面向业务用户的通用 CRUD，不拥有业务状态，也不能用基础设施状态替代 PostgreSQL 事实。

除明确标注的 PT-STO-002 外，本文件任务均为 MVP P0/proposed。平台任务由使用它的第一个业务任务拉动，不预建万能框架；例如 RabbitMQ 先满足剧本提取，再扩展镜头生成和渲染的真实故障场景。

## 8. 剪辑交付与平台里程碑

- M7 成片交付：PT-EDT-001–007 accepted，固定验收 Episode 完成“初始化 → 编辑 → 预览 → Issue 返工 → 新版本批准 → 渲染 → MP4/SRT/Manifest 下载”。
- M8 故障保障：相关 PT-DAT、PT-MQ、PT-CCH、PT-STO-001、PT-SCH、PT-OBS 全部 accepted；依次清空 Redis、暂停 RabbitMQ、重启 Scheduler/Worker 后，M7 从服务端事实恢复且无重复外部效果。
- PT-STO-002 是上线选择 OSS 后的条件门禁，不阻塞 MinIO MVP；一旦部署目标声明 OSS，它就必须 accepted 才能发布。

平台任务只有“端口/类存在”或 mock 通过不能 accepted；必须在当前真实 PostgreSQL、RabbitMQ、Redis、MinIO、FFmpeg 和已选 Provider 上取得对应证据。
