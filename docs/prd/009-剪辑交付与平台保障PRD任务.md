## 1. 任务边界

editing 任务交付用户可见的时间线、审核返工、渲染与下载闭环；平台保障任务交付这些业务任务可以依赖的可验证能力。平台任务不创建面向业务用户的通用 CRUD，不拥有业务状态，也不能用基础设施状态替代 PostgreSQL 事实。

除明确标注的 PT-STO-002 外，本文件任务均为 MVP P0/proposed。平台任务由使用它的第一个业务任务拉动，不预建万能框架；例如 RabbitMQ 先满足剧本提取，再扩展镜头生成和渲染的真实故障场景。

2026-08-04 按用户“无 Ark Key 时完成其他功能”的授权，上传会话到期清理首先证明 one-off Schedule/Fire、Task/Outbox、RabbitMQ、Media Worker、MinIO 删除、跨空间拒绝和前端运维；`cleanup_expired_uploads` 随后证明每 Workspace 唯一 interval/run_once 补偿；`retire_media_location` 又证明位置保护窗口的一次性到期退役。这三份局部证据分别保留在 Acceptance 010、012、013。

在这些业务 handler 之上，`cleanup_expired_uploads` 已支持 owner 专用的 interval/数字五段 cron 配置、IANA timezone、显式恢复策略和有界 catch-up。Spring gap 不触发、fall fold 只触发一次；skip/run_once/catch_up 均以 PostgreSQL 时钟推进到未来，不在后续循环继续补发已丢弃历史点。

多 dispatcher 竞争、过期 lease 接管、Task/Outbox/Fire 事务回滚、RabbitMQ 断连后的 Outbox 重投、Worker/Inbox 重放、第五次失败停止和非法配置首次人工处置均已在真实 PostgreSQL 与隔离 RabbitMQ 上通过；指标只使用 handler/result/policy/reason 等低基数标签，日志与 `last_error` 不保存依赖原文。

PT-SCH-001/002/003 的本地 MVP 范围 accepted，完整证据见[持久调度、故障恢复与受控运维验收](../acceptance/014-持久调度故障恢复与受控运维验收.md)。该接受不包含用户自定义 cron/DAG、Provider Attempt/unknown 对账、PT-MQ-003/004、PT-CCH-002、条件性 OSS 上线或 S4/S6 整体里程碑。

同一授权下，PT-CCH-001 已以 Workspace 详情 cache-aside 接受：先以 PostgreSQL 校验账号和 Membership，再读无角色缓存投影；写提交后失效，Redis 故障回源，并提供低基数指标与受控 namespace CLI。真实本机 Redis 的 cold/hit/TTL/namespace 清理/断连/monotonic revision、PostgreSQL API 跨空间与完整 E2E 均通过。PT-CCH-002 的高成本生成保护仍依赖 PT-PROD-004，不在本增量内。

`DEV-S6-01` 的 PT-CCH-002 无 Provider 工程增量已完成：复用 DEV-S4-01 的真实 PostgreSQL GenerationRequest/Task/Reservation/CostEntry/Outbox 提交事实，以 Redis Lua 原子限制全局与 Workspace 高成本新请求，并用请求摘要去抖事务失败后的同输入重试。本机真实 Redis 并发/TTL/断连和 Redis + FastAPI + PostgreSQL 联合契约均通过；默认方舟能力仍不可用，测试 active Capability 只触发提交前保护和数据库事实，不执行 Worker 或生成结果。工程证据见[高成本生成原子限流与去抖验收](../acceptance/020-高成本生成原子限流与去抖验收.md)；PT-CCH-002 产品任务、PT-PROD-004 与 S4 仍未接受。
