## 1. 任务规则

本文件中的 PT（Product Task）是 PRD 的最小交付单元，不是后端表或页面任务。每项必须同时形成服务端事实、公开接口、生成的前端 client、需要的用户交互、错误/恢复动作和自动化验收；无用户界面的内部能力也必须由上游用例和可观测结果验收。

所有任务均为 P0，并按切片逐项激活。状态只允许 `proposed → ready → in_progress → accepted`，外部条件缺失时为 blocked；Design 未接受、依赖任务未 accepted、验收 fixture 未确定时不能进入 ready。PT-IDN-001～004、PT-PRJ-001～003 已由 [S1 验收](../acceptance/002-S1单人立项验收.md) 接受；PT-PRJ-004/005、PT-MED-001～003 已有工程增量但尚未产品接受，保持 `in_progress`；2026-07-30 D-005 关闭后 PT-GOV-001/002 进入 `in_progress`；其余任务仍按依赖保持 `proposed`。产品负责人接受用户结果，工程负责人负责跨层交付，QA 对验收证据负责，不能把“后端完成”当作任务完成。

## 6. 基础模块里程碑验收

- M1 身份与立项：PT-IDN-001–004、PT-PRJ-001–003 accepted，真实本地账号完成“注册/登录 → Project → Episode”，JWT 撤销、跨空间与归档门禁通过。
- M2 内容基础：PT-MED-001–003、PT-GOV-001–002 accepted，完成“私有上传 → 探测 → 授权 → RightsGate”，刷新和重复请求不产生重复事实。
- M3 贯穿追踪：PT-PRJ-004/005、PT-MED-004/005、PT-GOV-003–006 随依赖切片 accepted，能够从概览进入具体 blocker，并从交付证据反查 actor、版本、媒体与审核。

任一里程碑若只有数据库 CRUD、接口 200 或页面占位而没有上述业务结果与失败验收，状态仍为 in_progress，不能 accepted。
