# 技术功能与运行需求

## 1. 目标

提供可构建、可运行、可观测的 Web/API/Worker/Scheduler 系统，完成模板采集、公开目录、异步图片生成和私有作品闭环。

## 2. 功能组件

| 组件 | 必需能力 |
| --- | --- |
| Web | `frontend/` 内的标准 Next.js App Router；页面和状态组件基于 shadcn/ui + Radix UI |
| API | 公共目录、会话、创作、生成、作品和管理端点 |
| Worker | crawl、media、index、generation 四类队列 |
| Scheduler | 单实例创建到期采集/维护任务，不处理内容 |
| PostgreSQL | 业务事实、任务、幂等、配额和词法搜索 |
| RabbitMQ | 持久投递、manual ack、有限重试、DLQ |
| MinIO | 来源文件与用户作品分区、私有对象和短时访问 |
| Seedream | 5.0 Lite 北京区域，通过 GenerationProvider 调用 |

## 3. 页面与 API 要求

- 页面覆盖加载、空、错误、配额不足、供应商不可用、审核拒绝和资源删除状态。
- 公共列表使用 cursor，`limit <= 50`；错误统一为 `{code,message,trace_id,details}`。
- `POST /generation-jobs` 要求登录、draft version 和 `Idempotency-Key`。
- 任务查询和作品端点强制 owner；管理写端点要求权限、CSRF 和审计。
- Web 类型只由 OpenAPI 生成，不手写重复 DTO。

## 4. 运行规则

| ID | 规则 |
| --- | --- |
| T-BR-01 | PostgreSQL 是业务与 job 最终事实源，RabbitMQ 不保存唯一结果 |
| T-BR-02 | 四类队列独立并发和重试，generation 不被 crawl 积压阻塞 |
| T-BR-03 | 生成提交使用稳定供应商幂等 key，未知结果必须 reconcile |
| T-BR-04 | 对象只有 `ready` 且业务允许时才能产生签名 URL |
| T-BR-05 | 搜索先用 FTS/pg_trgm，只有指标不达标才引入 pgvector |
| T-BR-06 | 依赖和镜像固定版本，CI frozen install，不使用 `latest` |
| T-BR-07 | 普通 CI 使用 fake provider；live 测试单独启用并限制最多 10 张 |
| T-BR-08 | 日志串联 trace/run/job/source/user，指标不包含私有正文 |

## 5. 技术验收标准

| ID | 标准 |
| --- | --- |
| AC-T01 | 全新环境可用统一命令启动 PostgreSQL/RabbitMQ/MinIO 并完成迁移 |
| AC-T02 | Web、API、Worker、Scheduler 可构建启动且 health/readiness 正确 |
| AC-T03 | DiffusionDB 1K 重复导入不增加模板、示例、对象或 search document |
| AC-T04 | 公共目录 API/UI 支持关键词、分类、模型、比例、来源和 cursor |
| AC-T05 | 同一幂等键并发提交只产生一个 job 和一次供应商提交 |
| AC-T06 | Worker 在供应商提交边界崩溃后恢复，job 与费用最终一致 |
| AC-T07 | Seedream 成功结果经媒体处理写入 MinIO 并生成本人作品 |
| AC-T08 | 用户/全局/月度配额并发下不超发，达到上限立即拒绝新任务 |
| AC-T09 | 1K 数据搜索 P95 <1 秒，生成提交 P95 <2 秒，错误率 <1% |
| AC-T10 | 队列年龄、供应商耗时/错误、生成费用、审核和删除 SLA 可观测 |
| AC-T11 | `make verify` 覆盖测试、lint、类型、构建、契约、集成和 E2E |
| AC-T12 | 迁移、kill switch、供应商切换和对象恢复均有可执行回滚路径 |

## 6. 非功能要求

- API/Worker 无本地持久状态；单实例 Scheduler 使用锁防重复调度。
- 相同 fixture 和锁文件产生可重复结果。
- 生成成功率目标 ≥95%（排除取消/审核拒绝），终态一致率 100%。
- 100K 性能只在 S7 验证，失败前不引入新基础设施。

## 7. 非目标

Redis、OpenSearch、Kafka、Airflow、Kubernetes、本地 GPU、自训练模型、视频生成和公开作品 CDN 不属于 MVP。

## 8. 发布门禁

AC-T01 至 AC-T12 全部通过；live provider 测试有成本证据；生产配置无默认 secret，回滚与监控完成演练。
