## 1. 问题与价值

管理员核查预算调整、报价确认或候选锁定时，若只能看到当前状态，就无法回答是谁在何时做了变更，也难以核对支出和误操作。审计列表以可筛选、可导出的变更摘要连接操作与责任人，支撑 S2 的人工确认、S3 的改锁追溯，以及 S7 的恢复后核对；对应“可控性”和“成本透明”（PRD-01 §1、§5；P2、P21；REQ-09 §1）。

## 2. 目标用户与场景

- 管理员按时间、操作人、项目、对象及动作查询。
- 管理员查看前后值摘要并跳转对象。
- 管理员导出筛选结果用于核对。

## 3. 范围

- **做（MVP）**：关键操作留痕、管理员查询与 CSV 导出（REQ-09 §1.3）。
- **不做**：以 REQ-09 §1.3 的排除项为准；V2 见 [REQ-34](../requirement/34-V2与待定需求池.md)。

## 4. 用户体验与流程

1. 成员在各业务页完成需留痕的操作后，管理员进入“管理·审计日志”，按时间、操作人、项目、对象和动作筛选列表。
2. 管理员打开一条记录查看前后值摘要及操作者类型，点击仍存在的对象进入详情；需要核对时按当前筛选导出 CSV。
3. 刚完成的操作若尚未出现在列表，页面说明审计可能短暂延迟，用户可刷新；事件链路恢复后记录补齐。
4. 已删除对象只保留标签摘要并显示“已删除”，不提供失效跳转；筛选导出范围过大时提示缩小范围后重试。任何详情与导出均不展示凭据、完整剧本或预签名地址（REQ-09 §2.1–2.4；DES-12 §4、§7、§11）。

## 5. 产品规则

- 登录与账号、凭据、注册表和价格、预算、报价确认、取消、人工核对、选定/锁定/确认、删除/恢复必须审计（REQ-09 R1）。
- 记录只追加；前后值仅存变更摘要，不存剧本全文、凭据或预签名 URL（REQ-09 R2–R3）。
- 区分 user/agent/system；用户确认 Agent 提案时记录用户与提案关系（REQ-09 R4）。
- 记录保留 3 年（REQ-09 R5）。

## 6. 成功标准

完成 REQ-09 §3 / TC-09-01～03；覆盖选定记录、报价确认记录、数据库拒绝篡改。覆盖率与保留期以 REQ-02 SEC-10、DAT-03 为准。

## 7. 依赖与风险

依赖 M1 命令层与事件链路；事件积压会使审计延迟，脱敏遗漏会泄露隐私（REQ-09 §2.4–2.5；DES-12 §5）。

## 8. 待确认

无产品待确认。审计保留 3 年和变更摘要范围依据 REQ-09 R3、R5；异步写入的短暂可见延迟依据 REQ-09 §2.4、DES-12-Q4，页面提示口径以 DES-12 §7 为准。
