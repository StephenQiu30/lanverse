## 1. 设计结论

editing 是业务模块，拥有“哪些固定素材按什么时间关系组成哪个可交付版本”的事实。RabbitMQ、Redis、对象存储、Scheduler 和可观测性是平台能力，不是五个业务模块，也不提供面向用户的通用 CRUD；它们只为已存在的业务事务提供可靠通知、加速、字节存放、到期触发和证据。这样可以避免建立没有业务所有者的 `queue_service`、`cache_service` 或 `common_storage` 空层。

## 2. editing：剪辑、审核衔接与交付

### 2.1 产品事实和版本边界

| 对象 | 用户价值 | 生命周期/约束 |
| --- | --- | --- |
| Timeline | Episode 的主时间线和可变 draft_document | 每个 Episode 一个；操作原子比较 revision；草稿不是审核对象 |
| TimelineVersion | 一次不可变发布快照 | 固定轨道、Clip、Cue、来源 MediaVersion 和 ShotSpec 引用 |
| TimelineSource | 每个已发布 Clip 的固定来源 | 关系化记录 Candidate、MediaVersion、ShotSpec 和 Task，不使用漂移指针 |
| Render | 对固定 TimelineVersion 的渲染任务 | `queued → running → succeeded/failed/cancelled`；成功输出不可覆盖 |
| DeliveryManifest | 一次可下载交付的证据清单 | 固定 MP4/SRT/标识版本、hash、审核决定和完整血缘 |

Timeline/TimelineVersion 只负责编辑组合；Review/Issue/Decision 属于 governance，媒体字节和血缘属于 media，Task/Attempt/费用属于 production。editing 保存 TimelineSource 等稳定引用或读取摘要，不复制这些模块的状态。

### 2.2 编辑与发布用例

1. 初始化时间线：从每个 Shot 已选 Candidate 建立建议轨道；缺失来源时返回具体 Shot 和下一动作，不建立伪 Clip。
2. 编辑操作：增加、删除、移动、裁剪 Clip，调整音轨和字幕 Cue；一批 operations 使用 expected revision 原子提交，失败返回服务端最新状态。
3. 刷新来源：比较当前候选与 Draft 固定来源，展示新增/过期/缺失差异；由用户选择替换，不自动覆盖已有编辑。
4. 预览：生成低成本临时结果或结构化播放清单；它不是 Delivery，不继承审核或交付有效性。
5. 发布版本：校验来源可访问、时间范围、轨道冲突、字幕、完整镜头和授权后创建不可变 TimelineVersion。
6. 提交审核：调用 governance 为固定 Version 创建 Review；阻塞 Issue 需回到 Draft 修复、重新发布新 Version、重新审核。
7. 最终渲染：为已批准 Version 创建 Render/Task；固定 FFmpeg 参数产生 MP4/SRT，经 ffprobe 和 hash 验证后由 media 登记版本与 Lineage。
8. 标识与交付：governance 对渲染输出执行 Moderation/Label；验证完成后 editing 创建 DeliveryManifest 并提供受控下载。

### 2.3 模块验收

- 初始化对缺失候选可解释；同一命令重复执行不重复建轨道；来源更新不覆盖用户编辑。
- revision 冲突不丢操作；TimelineVersion 及其 TimelineSource 永不漂移；旧版本可复现。
- Review 只绑定固定版本；open blocking Issue、失效授权、Moderation unknown 或标识验证失败均阻止交付。
- Render 重试不覆盖成功文件；进程中断时根据临时对象、Task 阶段和 output hash 恢复；部分输出不创建 Manifest。
- Manifest 可从每个 Clip 追溯 ShotSpec、AssetVersion、Candidate、Task/Attempt、费用、MediaVersion/Lineage、审核和标识。
- 固定 9:16、1080×1920、25fps、H.264/AAC、SRT 验收样片可由 FFmpeg/ffprobe 自动核验；下载权限和过期能力跨空间不可探测。

## 3. RabbitMQ：异步工作通知

RabbitMQ 只传递“某个持久化工作可领取”的通知，PostgreSQL 才保存 Task、Attempt、业务状态、Outbox/Inbox 和重试决定。消息正文不得承载剧本、提示词、预签名 URL、授权证明或媒体字节。

| 能力 | 必须行为 | 失败处理 |
| --- | --- | --- |
| Outbox 发布 | 业务事务内写 Outbox，Publisher 领取后发布 | publish confirm 前不标记完成；超时可安全重投 |
| 消息信封 | message_id、event_type/version、aggregate_ref、trace_context、occurred_at | 不支持版本进入受控失败，不猜字段 |
| Worker 消费 | Inbox/message_id 防重，领取数据库 Task | 业务结果提交后 manual ack；断连允许重投 |
| 重试 | 仅瞬态故障按策略重试 | 业务拒绝直接终态；不确定外部发送进入 unknown 对账 |
| 毒消息 | 次数/年龄越界后停止自动处理 | 记录原因和 next_action，进入 manual_attention |

完成条件：Publisher 崩溃、confirm 丢失、重复投递、消费者在提交前后崩溃、乱序、毒消息、RabbitMQ 暂停/恢复均有真实集成证据；任一场景不能产生重复外部发送、重复 Candidate 或重复费用。

## 4. Redis：可丢失的加速与保护

Redis 只用于可重建缓存、短时限流/去抖和非权威进度加速；Workspace 权限、余额、任务状态、锁、幂等、调度和 current version 不以 Redis 为事实来源。

- 读取采用 cache-aside，键包含环境、workspace、资源、版本和 schema 版本；写事务提交后失效，TTL 只是兜底。
- 普通列表/详情在 Redis 清空或不可用时安全回源 PostgreSQL，返回正确结果并记录降级。
- 保护外部高成本操作的限流/预算防线失效时 fail closed；不能因为 Redis 故障放行未知成本。
- 禁止缓存预签名 URL、token、完整剧本、授权证明和无限增长的高基数任务键。

完成条件：冷缓存、脏失效竞态、清库、断连、恢复和热点并发均不改变业务事实；回源压力与 fail-closed 入口有指标和自动化验证。

## 5. 对象存储：MinIO 到 OSS 的稳定边界

本地和当前部署使用 MinIO；上线可切换 OSS。二者都通过 ObjectStoragePort 提供受控上传/分片完成、HEAD、流式读写、短期访问、临时对象删除和连通性检查；业务代码只识别 MediaVersion，不识别 bucket、key、endpoint 或厂商 SDK。

存储成功不等于业务成功：对象必须经 media 校验并登记 Location 后才可用。删除只由 media 根据引用、保留期、审核/交付/费用证据和清理任务决定；平台能力不得暴露通用“按 key 删除”业务接口。MinIO 与目标 OSS 必须分别通过同一契约套件，宣称 S3 兼容不能替代真实 OSS 验证。

## 6. Scheduler：基于数据库的到期触发

Scheduler 读取 PostgreSQL Schedule，用数据库租约/跳锁竞争到期项，为每次触发写唯一 ScheduleFire，并通过现有 Task/Outbox 进入执行链。RabbitMQ 不保存未来时间，Redis 不承担分布式锁，进程内定时器不作为可靠调度。

MVP 用途只包括 Outbox 唤醒、Task/Attempt 超时扫描、provider unknown 对账、上传过期、对象清理、授权/审核到期提示和媒体修复。必须定义 misfire、最大补跑次数、退避、租约过期和 manual_attention；多实例、时钟偏移和进程重启不能产生重复业务副作用。

## 7. 日志、追踪、指标与审计

四类证据分工固定：JSON 日志解释一次执行；trace 串联 API → Outbox → Publisher → Worker → Provider/FFmpeg；Prometheus 指标反映吞吐、延迟、积压、错误、unknown、费用异常和降级；AuditEvent 记录受控业务行为。日志不能替代 AuditEvent，AuditEvent 也不复制请求正文。

所有入口生成/继承 trace_id，并关联 workspace_id、actor_id、task_id、attempt_id、provider_request_key 等可控标识；不得记录 token、cookie、密钥、完整提示词/剧本、授权证明、预签名 URL、二进制或无限增长 label。Exporter 不可用只降级遥测，不阻塞业务；日志磁盘/采集失败需告警并有容量边界。

完成条件：HTTP、消息、调度、Provider 和 FFmpeg 的成功/失败/重试可串联；低基数指标可形成 RabbitMQ 积压、Task unknown、调度延迟、存储错误和费用不变量告警；脱敏样例、故障注入、exporter 中断和审计访问控制通过。

## 8. 交付与平台联合验收

固定场景为：已选镜头初始化 Timeline → revision 编辑 → 发布并经历一次 Issue 返工 → 批准新 TimelineVersion → RabbitMQ 触发 Render → Worker 中断恢复 → FFmpeg 输出并登记媒体 → Moderation/Label → 创建 Manifest → 下载 MP4/SRT/Manifest。演练中依次清空 Redis、短暂停 RabbitMQ、重启 Scheduler/Worker，最终业务事实和费用不重复，页面从服务端恢复，trace 能解释全过程。

若目标 OSS、合规规则或真实故障环境尚未提供，对应验收必须标记为外部阻塞；不得用 MinIO、mock 或“代码路径存在”替代上线结论。
