# PRD 13：分析

设计入口：[Design 13](../design/13-分析.md)。当前是待评审方案，接受后再按本次闭环细化技术工作项；原始需求与验收标识不变。

执行编号：13；来源需求模块：17。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

从真实项目任务、镜头和版本事实得到可复算进度与待处理入口。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/17-分析需求.md)中的业务规则。对应[模块Plan](../plan/13-分析.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

静态曲线和完成率不能代表当前项目实际进展。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

从真实项目任务、镜头和版本事实得到可复算进度与待处理入口。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为制作者，我希望筛选后看到可复算的进度和趋势。
- 作为制作者，我希望从失败或失效摘要打开实际对象继续处理。
- 作为制作者，我希望导出与页面相同的范围，避免拿到固定样例。

## 6. 价值与范围取舍

首轮只保留任务状态和安全关联标识；完整分析在生成与内容事实稳定后实施。

阶段判据未定的指标显示未接入，不填假0，不承诺未经测量的性能阈值。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/17-分析需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/17-分析需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-ANALYTICS-01：计算一致范围的统计

作为制作者，我希望筛选后看到可复算的进度和趋势。

范围追踪：FR-ANALYTICS-01～02，原始规则见[功能需求](../requirement/17-分析需求.md#3-功能性需求)。

1. 所有卡片采用同范围。
2. 返回窗口/as_of/样本或分母。
3. 模型版本可解释。
4. 0分母/未知/依赖故障分开。

### US-ANALYTICS-02：定位待处理对象

作为制作者，我希望从失败或失效摘要打开实际对象继续处理。

范围追踪：FR-ANALYTICS-03，原始规则见[功能需求](../requirement/17-分析需求.md#3-功能性需求)。

1. 数量来自当前项目事实。
2. 失败/未知/失效原因可辨。
3. 跳转保留授权对象。
4. 已处理后读取最新状态。

### US-ANALYTICS-03：展开或下载同一趋势

作为制作者，我希望导出与页面相同的范围，避免拿到固定样例。

范围追踪：FR-ANALYTICS-04，原始规则见[功能需求](../requirement/17-分析需求.md#3-功能性需求)。

1. 明确格式与范围。
2. 数据同筛选。
3. 缺数据/无权/超限失败可见。
4. 下载内容可核对且无秘密。

### 依赖、假设与质量

- 必要依赖：13、14、15/16的业务事实；不要求新增全局通知平台。
- 尚待决定：完成/阶段判据、分母、环比基期、P95算法、时间/时区、下载格式与通知关系。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/17-分析需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/17-分析需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
