规则与验收以 [REQ-24](../requirement/24-任务中心与对账.md) 为准，以下为产品摘要。

## 1. 问题与价值

供应商提交超时后，制作者无法判断任务是否已受理；重新点击可能重复生成和扣费，离开页面后也难找回任务。任务中心展示状态、费用、调用时间线，并将未知结果先对账再人工处理。对应 PRD-01 §2 的**可控性、成本透明**，直接服务 S7 的中断恢复，也支撑 S2/S4 查看生成进展；费用终态遵循 P30。

## 2. 目标用户与场景

- 制作者筛选任务与失败原因。
- 取消排队或进行中任务。
- 管理员核实无法自动对账的任务。

## 3. 范围

- **做（MVP）**：任务列表与详情、实时状态、取消、结果未知对账、待人工核对处理、卡死任务检测。
- **不做**：任务执行算法以 DES-04 为准；V2 见 REQ-34。

## 4. 用户体验与流程

1. 从项目进入任务中心，按项目、集、能力、模型、状态或时间筛选；表格展示状态、进度、费用和耗时。
2. 打开详情抽屉查看时间线、输入缩略图和调用明细；可对可取消项发起取消，对失败项按提示重试。
3. 结果未知时看到“对账中”，系统先查询供应商；无法确定时进入待人工核对，管理员填依据结案。
4. 提交超时不得提示直接重试；取消不保证供应商停机时显示实际取消结果；过期结果链接提示重新查询或人工申诉；无权限查看原始供应商信息时只显示脱敏摘要。

## 5. 产品规则

- 状态：排队中、进行中、成功、失败（附原因）、结果未知、待人工核对、已取消（REQ-03 §6.5）（REQ-24 R1）
- 付费请求只在“确定未提交”时自动重试；结果未知永不自动重新提交（REQ-24 R2）
- 提交、查询、取消与回调的供应商调用均留有可追溯记录。（REQ-24 R3）
- 任务超出模型预期时进入对账；人工核对超过 24 小时告警。（REQ-24 R4）
- 失败原因使用平台错误码 + 中文说明 + 是否可重试；原始供应商错误只给管理员看（REQ-24 R5）
- 人工核对只能由管理员处理，必须填写依据（供应商任务 ID 或说明），写审计（REQ-24 R6）
- 列表可按项目、集、能力、模型、状态、来源、时间筛选；默认显示当前项目（REQ-24 R7）

## 6. 成功标准

- Given 任务进行中时服务重启，When 服务恢复后刷新任务中心，Then 任务状态正确并继续推进。（[TST-02](../test/02-需求追踪矩阵.md) TC-24-01）
- Given 模拟供应商提交超时但实际已受理，When 对账完成，Then 任务状态与供应商一致，账本只记录一次费用。（[TST-02](../test/02-需求追踪矩阵.md) TC-24-02）
- Given 排队中的任务，When 取消，Then 状态为已取消，预留全部释放。（[TST-02](../test/02-需求追踪矩阵.md) TC-24-03）
- Given 不支持查询的供应商提交超时，When 查看任务，Then 状态为“待人工核对”，管理员收到通知；处理为“未执行”后预留全部释放。（[TST-02](../test/02-需求追踪矩阵.md) TC-24-04）

以上为 [REQ-24](../requirement/24-任务中心与对账.md) §3 的 TC-24-01～04；关联质量要求见 [REQ-02](../requirement/02-非功能需求规格.md) REL-01、REL-02、REL-10、AVL-04、OBS-05、PERF-03。跟踪 PRD-01 §10 的预估与实际费用偏差；任务恢复与去重按 REQ-02 REL-01、REL-02 验证。

## 7. 依赖与风险

- **依赖**：[PRD-18](18-报价与二次确认.md)、[PRD-20](20-批量生成.md)、[PRD-30](30-站内通知.md)。
- **风险**：供应商无查询能力、取消不生效或回调与轮询竞态。

## 8. 待确认

已决定：结果未知先自动对账，仍无法确定则转人工核对（REQ-24 R2、DES-27-Q1）；普通用户调用明细须脱敏（REQ-24 R5、DES-27-Q2）。具体重试次数与字段脱敏实现留在 DES；无其他产品待确认项。
