# PRD 01：用户

执行编号：01；来源需求模块：06。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

建立真实身份和可撤销会话，使画布与媒体访问有明确授权。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/06-用户需求.md)中的业务规则。对应[模块Plan](../plan/01-用户.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：访客、制作者、管理员。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

现有认证页面不证明身份、受限账号和设备会话已真实生效。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

建立真实身份和可撤销会话，使画布与媒体访问有明确授权。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为访客，我希望注册或登录后进入本人工作区，避免把演示身份当成真实权限。
- 作为制作者，我希望修改密码、资料与偏好后仍能读回，避免丢失个人设置。
- 作为管理员，我希望建号、启停、解锁和重置有不同结果，保留历史责任。

## 6. 价值与范围取舍

先交付登录、会话校验、退出与角色隔离；Demo账号取得方式须确认，不能用前端固定身份绕过认证。注册、资料、头像、偏好和完整管理随后补齐。

头像、偏好和完整账号管理不能阻塞生成链，但仍属于模块完整范围。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/06-用户需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/06-用户需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-USER-01：进入真实会话

作为访客，我希望注册或登录后进入本人工作区，避免把演示身份当成真实权限。

范围追踪：FR-USER-01～03，原始规则见[功能需求](../requirement/06-用户需求.md#3-功能性需求)。

1. 合法输入建立真实会话。
2. 重复登录名/错密不建立会话。
3. 受限账号只能改密。
4. 刷新、到期与退出后访问符合授权。

### US-USER-02：维护本人账号

作为制作者，我希望修改密码、资料与偏好后仍能读回，避免丢失个人设置。

范围追踪：FR-USER-04～06，原始规则见[功能需求](../requirement/06-用户需求.md#3-功能性需求)。

1. 密码统一校验且失败不解除限制。
2. 成功按确认规则撤销会话。
3. 资料与偏好重登录保留。
4. 越权修改被拒绝。

### US-USER-03：安全管理账号

作为管理员，我希望建号、启停、解锁和重置有不同结果，保留历史责任。

范围追踪：FR-USER-07～08，原始规则见[功能需求](../requirement/06-用户需求.md#3-功能性需求)。

1. 管理员建号真实持久。
2. 普通用户管理被拒绝。
3. 禁用立即撤销且不删除历史。
4. 最后管理员保护有效且临时凭据不回显。

### 依赖、假设与质量

- 必要依赖：无前置业务模块；管理员初始身份取得方式需在Design明确。
- 尚待决定：登录名归一化、失败统计窗口、改密后当前设备处理、临时凭据交付、头像规格和主题同步。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/06-用户需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/06-用户需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
