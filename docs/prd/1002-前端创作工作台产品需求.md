# 前端创作工作台产品需求

## 结论

Lanverse 前端创作工作台需要让不同经验的创作者在同一套生产事实之上完成 AI 短剧制作。普通创作者通过 Guided Studio 按业务步骤推进，高级创作者通过 Canvas Studio 编排相同内容；审核者、Workspace 管理者和只读成员使用与其职责相符的工作区。所有用户看到的成功、失败、等待、成本和产物都必须来自可恢复、可审计的服务端事实。

前端产品分两个发布门交付：`Guided MVP` 先完成从剧本到成片的可恢复业务闭环；`Platform Complete` 再完成 Canvas、多人协作、Copilot 和完整治理体验。两者继承平台级发布范围，不建立独立于平台的第二套产品路线。

## 1. 产品问题

AI 短剧生产跨越剧本、角色、场景、分镜、镜头、媒体、审核和导出。用户面临的主要问题不是缺少单个生成按钮，而是：

- 不清楚生产事实、阻塞原因和下一步动作；
- 生成任务耗时长且可能失败，刷新或服务重启后容易失去上下文；
- 候选、修改、审核和最终采用结果缺少清晰关系；
- 普通创作者不希望理解节点和工作流术语，高级创作者又需要局部编排与重跑；
- 资产、版本、成本、权限和审计分散，难以判断一次操作的影响；
- 网络断开或异步结果未知时，界面容易把“请求已发送”误报为“业务已完成”。

本产品需要把这些问题收敛为可继续、可恢复、可审核的创作旅程。

## 2. 目标用户与核心任务

| 用户 | 核心任务 | 期望结果 |
|---|---|---|
| 普通创作者 | 导入剧本并按业务步骤完成一集短剧 | 不理解 DAG 也能知道所处阶段、阻塞和下一步 |
| 高级创作者 | 查看和调整节点、依赖、局部运行与版本 | Guided 与 Canvas 之间切换不丢失业务语义 |
| 审核者 | 领取审核任务、比较候选和证据、提交决议 | 决议唯一、可追踪，并能安全恢复等待中的生产 |
| Workspace Owner | 管理成员、授权、预算、配额和审计 | 高影响动作有权限依据，所有变更可查询 |
| Editor | 在授权范围内编辑、发布、运行和处理资产 | 无权动作不可误触，权限变化及时生效 |
| Viewer | 浏览项目、版本、运行和允许公开的审核摘要 | 只读体验完整，不通过隐藏错误伪装成空数据 |

## 3. 产品目标

### 3.1 Guided MVP

Guided MVP 必须让普通创作者完成以下结果：

1. 注册或登录后进入可访问的 Workspace。
2. 创建或恢复 Project，并导入完整剧本。
3. 审阅剧本结构、Production/Story Bible、角色、场景和分镜。
4. 生成并选择图片、动态镜头、声音和字幕候选。
5. 在人工审核点暂停、比较证据、提交决议并继续。
6. 对失败 Shot 或节点局部重跑，不无条件重跑整集。
7. 在刷新、网络中断或服务重启后恢复真实进度。
8. 查看产物来源、版本、成本和执行状态并导出成片。

### 3.2 Platform Complete

Platform Complete 在 Guided MVP 之上必须让高级创作者和团队完成以下结果：

1. 在 Canvas 中编辑与 Guided 相同的 Authoring Draft。
2. 发布不可变 Revision，并从明确 Revision 发起全部或局部运行。
3. 多客户端协作编辑、断线恢复和权限撤销后保持可解释的一致性。
4. 使用 Copilot 获取建议、预览高影响操作，并在确认后应用。
5. 在统一运行、资产、审核、成本、配额和治理界面追踪全链路事实。

## 4. 产品范围

### 4.1 Account Access

- 注册、登录、会话恢复、退出和账户安全操作；
- 安全返回原目标页面；
- 权限撤销或会话失效后的明确恢复路径。

### 4.2 Workspace 与 Project

- 选择、创建和管理可访问的 Workspace；
- 创建、搜索、恢复和归档 Project；
- 从可分享链接恢复 Workspace、Project、Episode 和所选业务上下文。

### 4.3 Guided Production

- 以剧本、Bible、角色、场景、分镜、镜头、声音、审核和导出展示生产步骤；
- 展示每一步的前置条件、确认事实、失败原因和下一动作；
- 支持候选比较、局部修复和可恢复运行。

### 4.4 Canvas 与 Copilot

- 使用节点、连线、分组、布局和局部运行表达高级创作；
- Guided 与 Canvas 共享内容和发布版本；
- Copilot 只提出或预览建议，高影响操作必须由用户确认。

### 4.5 Review、Asset 与 Run

- 统一审核任务、候选证据和不可变决议；
- 区分可复用 Asset 身份、版本与不可变 Artifact；
- 展示 Workflow、Node、Provider、Artifact、Cost 和 Trace 的业务关联。

### 4.6 Governance

- 显示成员能力、Consent、Budget、Quota 和审计事实；
- 权限不足、依赖降级和合法空数据具有不同体验；
- 高影响动作可追踪并由服务端最终裁决。

## 5. 核心用户旅程

### 5.1 新项目到首次运行

```text
注册/登录
→ 选择 Workspace
→ 创建 Project
→ 导入剧本
→ 审阅结构与分集
→ 准备资产和分镜
→ 发布生产版本
→ 启动运行
→ 查看状态与下一动作
```

### 5.2 候选审核与继续生产

```text
生产进入人工等待
→ 打开审核任务
→ 比较候选、来源、质量和成本
→ 提交决议
→ 服务端确认并恢复运行
→ 重新读取真实终态
```

### 5.3 失败 Shot 局部修复

```text
定位失败 Shot/Node
→ 查看输入、错误和影响范围
→ 修正配置或选择历史候选
→ 估算成本
→ 仅重跑受影响范围
→ 验证新的 Artifact 与下游状态
```

### 5.4 Guided 与 Canvas 切换

```text
Guided 编辑业务步骤
→ 在 Canvas 打开同一 Draft
→ 保留全部业务字段和高级节点
→ 发布不可变 Revision
→ 运行绑定该 Revision
→ 回到 Guided 仍能读取相同语义
```

### 5.5 Asset 上传与使用

```text
创建或选择 Asset
→ 直接上传媒体
→ 等待完整性与可用性校验
→ 发布固定版本
→ 查看使用影响
→ 在候选、Revision 或 Render 中引用
```

## 6. 产品体验原则

1. **业务语言优先**：Guided 不暴露用户完成任务不需要理解的基础设施术语。
2. **事实优先**：页面刷新后必须能重新读取真实状态，浏览器内状态不能冒充生产事实。
3. **不伪造成功**：请求发送、流结束或连接断开均不能单独代表业务成功。
4. **下一动作明确**：等待、失败、冲突、预算不足和权限不足都要给出可执行的下一步。
5. **高影响动作可确认**：发布、运行、审核、删除、归档、资产状态变更和 Copilot Tool 应展示目标与影响。
6. **历史可追溯**：已发布版本、采用候选、审核决议和产物来源不得被后续编辑静默覆盖。
7. **权限体验一致**：前端用于解释和减少误操作，服务端始终做最终授权。
8. **渐进复杂度**：普通创作者可以只使用 Guided，高级能力不阻断基础闭环。

## 7. 失败与恢复体验

产品必须区分以下结果，不使用同一个“操作失败”兜底所有情况：

- 未登录、无权访问和资源不存在；
- 输入校验失败和版本冲突；
- 预算或配额不足；
- Provider 结果未知、任务失败和依赖暂时不可用；
- 上传签名过期、媒体校验失败和资产被隔离；
- 实时连接中断、协作未同步和运行终态待确认；
- 审核任务已被领取、已决议、已取消或已过期。

任何恢复动作都必须保留仍然有效的用户输入，并避免重复提交高成本或不可逆操作。

## 8. 发布门

### 8.1 Guided MVP 发布门

只有以下产品结果均有真实验收证据时，才能声明 Guided MVP：

- 用户能从剧本完成到可导出的成片；
- 候选选择、人工审核、失败恢复和局部重跑成立；
- 服务重启后生产状态可恢复；
- Asset、Artifact、版本、成本和关键执行记录可追踪；
- Owner、Editor 和 Viewer 的关键旅程符合权限预期；
- 网络和依赖故障不会产生虚假成功或重复高成本操作。

### 8.2 Platform Complete 发布门

只有在 Guided MVP 基础上继续满足以下结果，才能声明 Platform Complete：

- Guided 与 Canvas 对相同输入产生等价业务 Revision；
- 发布后的 Revision 不受后续活动 Draft 编辑影响；
- 多人协作、重连、冲突和撤权行为通过验收；
- 局部执行、Dirty/Cache 解释和成本预估成立；
- Copilot 建议和高影响 Tool 经过预览、确认及最终结果对账；
- Search、运行诊断、成本、配额、治理和审计体验完整。

## 9. 成功信号

以下指标用于后续 Acceptance 建立真实基线和阈值；本文不虚构尚未测量的通过值：

- 新用户完成注册、创建 Project 和首次导入的成功率；
- 从 Project 断点恢复到下一生产动作的耗时；
- Guided 各阶段的完成率、阻塞率和恢复率；
- 失败 Shot 局部重跑相对整集重跑的比例；
- 审核任务领取、决议和 Workflow 恢复的成功率；
- 未知结果被正确对账且未重复提交的比例；
- Asset 上传、校验、发布和引用的成功率；
- Canvas 协作收敛、重连和冲突处理成功率；
- 关键页面、Canvas 和长会话性能基线。

## 10. 非目标

本 PRD 不要求：

- 通用 AI 视频平台、专业时间线、复杂 3D、MV、广告或直播制作；
- Workflow、Skill 或第三方插件市场；
- 任意代码执行节点或无限循环 Agent；
- 多地域多活或超大型企业组织权限；
- 专业剪辑、复杂合成或影视资产管理软件的全部能力；
- 与短剧创作主链无关的通用内容社区、素材市场或运营后台；
- 以自动化替代所有人工创作判断和最终审核责任。
