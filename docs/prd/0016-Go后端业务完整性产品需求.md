# Go 后端业务完整性产品需求

依据 [Design](../design/0016-Go后端业务完整性实施设计.md)。用户需要健全的 Go 业务能力：输入有版本、操作有权限、生成有预算、提案有审阅、采纳有正式结果、故障能查回，且客户端只通过 Go 公共合同获取平台数据。

全量目标包括账号/项目、源与规划、总册与分镜、审阅采纳、资产媒体、生成与费用、运行与事件查询。当前先补齐追踪和正式版本回查的公共闭环，同时复核已有业务；媒体供应商、视频/声音/合成按真实合同实施，不以空适配器、mock 输出或“配置后可用”替代。

首批旅程：有权限用户打开运行 → 看冻结阶段和实际尝试 → 查询提案审批 → 通过固定版本读取正式总册/导演意图；刷新不产生副作用，跨项目访问拒绝，服务异常明确呈现。

需求细则和完成证据分别见 [Spec](../requirement/0016-Go后端业务完整性需求规格.md) 与 [Acceptance](../acceptance/0016-Go后端业务完整性验收记录.md)。本次授权实施后端，不修改前端或发布业务实例。
