## 2. 背景与 SMART 目标

MVP 只验证一个核心价值：单个内部创作者能把获权中文故事正确转为 AI 短剧，任务在失败、重试、页面刷新和 Worker 重启后仍可判断、可恢复，最终得到可播放且可追溯的成片。

在受控本地环境中，用户输入符合 `text-normalization-v1`、规范化后 300～3000 个 Unicode 代码点且至少含一个 Han 字符的中文故事，经人工确认剧本与分镜，生成 6～10 个镜头，并完成图片、视频、逐句 TTS、源语言字幕、候选采用和服务端合成，输出 30～60 秒、720×1280、24fps、H.264/AAC MP4。确定性 Mock 全流程必须连续通过 3 次；正式 Acceptance 结论前必须至少完成 1 次真实 Provider 完整样片。

## 3. 唯一 MVP 产品清单

- 单操作者在本机 loopback 的单应用实例中完成一个项目对应一个单集的制作。
- 用户粘贴符合 `text-normalization-v1` 的 UTF-8 中文故事纯文本、声明来源权利并保存可追溯的来源版本。
- AI 生成可编辑的结构化剧本、角色/场景/风格资产和 6～10 个镜头；剧本、资产与分镜经人工确认后成为生产输入。
- 系统先生成并采用角色/场景资产参考图和镜头图，再以这些 Adoption 生成镜头视频；整体视觉风格以 confirmed 文字版本/哈希进入图片和视频输入，不建立图片 Adoption；逐句 TTS 与视频任务可并行执行。
- 每个使用位置对应独立 ProductionTask；系统重试新增 Attempt，用户重试终态失败任务时创建关联原 Task 的新 Task，局部失败不删除成功结果。
- 用户通过项目、故事、制作室、任务和交付五个工作区查看版本、任务、候选、采用与交付；非终态任务每 2 秒查询，刷新后从服务端事实恢复。
- 服务端按镜头顺序合成采用的视频、逐句 TTS 与源语言字幕，经 ffprobe 校验后交付私有 MP4、SRT 和 Manifest。
- Mock Provider 完整闭环连续通过 3 次，并以批准的真实 Provider 完成至少一部符合成片规格的样片。

本节与第 7 节 SMART 验收标准共同穷尽产品实现范围；未出现在两者及上游追踪中的能力不得创建目录、接口、数据表、开关或占位代码。

## 4. 核心用户故事

| ID | 用户、触发与价值 | 前置与主流程 | 失败/恢复 | 完成定义 |
| --- | --- | --- | --- | --- |
| US-001 | 内部创作者有一段获权故事，希望建立可持续制作入口 | 本地服务就绪；创建项目/单集→确认权利→输入 300～3000 字符→保存来源版本 | 非法/超限输入被明确拒绝；同键重放不重复创建 | 来源版本可读取、可追溯且并发重放不重复 |
| US-002 | 创作者希望把来源变成可生产镜头计划 | 来源已确认；生成剧本提案→编辑/确认→生成资产/分镜提案→调整并联合确认 | Provider 或结构校验失败可重试；历史版本不覆盖；未确认不得生产 | 获得一组当前已确认且满足规格的剧本、资产与分镜版本 |
| US-003 | 创作者希望启动整集生产并掌握每镜头进度 | 分镜已确认；先生成/采用必需图片→提交视频/TTS Task 集合→每 2 秒查看逐项状态 | 单镜头失败不影响成功镜头；刷新后恢复状态；状态未知明确展示 | 每个必需位置的独立任务状态都可从服务端恢复和判断 |
| US-004 | 创作者希望只修复失败镜头并采用满意结果 | 候选或错误可见；通过短期授权预览图片/视频/TTS→为失败位置创建重试 Task→比较并按位置采用 | 新 Task 引用原 Task；旧候选及其他镜头不变；迟到结果不自动采用 | 失败位置获得新的可采用候选，其他位置的事实保持不变 |
| US-005 | 创作者希望获得带对白和字幕的可播放样片 | 全部镜头已采用；创建固定渲染快照→FFmpeg 合成→ffprobe 校验→下载 | 渲染失败保留输入和媒体并可重试，不重新调用成功的 AI 任务 | MP4、SRT 和 Manifest 可私有下载且可追溯到全部输入 |

## 5. 用户体验与产品规则

- 页面固定为项目、故事、制作室、任务和交付五个工作区；每个操作同时显示当前阶段和下一动作。
- AI 输出始终标为提案或候选；任务成功、候选采用和成片成功是三个独立事实。
- 轮询只在页面可见且任务非终态时运行；间隔固定 2 秒，失败采用有限退避，用户可手动刷新。
- 错误必须给出镜头、阶段、稳定错误码、可否重试和下一动作，不显示密钥或原始 Provider 响应。
- 来源、剧本、分镜、提交快照、候选、采用和交付均保留版本；confirmed 内容再次编辑时显式派生 draft，新版本不得覆盖被下游引用的版本。

## 6. 状态与数据边界

| 对象 | 状态/约束 |
| --- | --- |
| 内容版本 | Source/Script/Asset/ShotSpec/Subtitle 统一 `draft → confirmed → superseded`；只有 current confirmed 且 `input_outdated=false` 可进入新生产 |
| ProductionTask | 只允许 `queued/running/cancelling/cancelled/succeeded/failed/unknown`；多项提交只是独立 Task 的 API/UI 集合 |
| ProductionAttempt | 初始执行和系统自动重试在同一 Task 下独立记录；用户重试创建新 Task；传输重放返回原记录 |
| GenerationCandidate/Adoption | 候选历史不可覆盖；每个 `usage_type+usage_id+input_version_id+input_hash` 至多一个 active Adoption；旧版本 Adoption 不满足新版本生产 |
| DeliveryVersion | `rendering → ready/failed/cancelled`；固定引用 RenderSnapshot 及 MP4/SRT/Manifest MediaVersion，用户重试新建版本 |

PostgreSQL 是业务事实源，Temporal 只保存编排历史，对象存储只保存私有媒体字节。浏览器状态、轮询缓存、Workflow 历史和对象 URL 均不得单独决定正式状态。

## 7. SMART 验收标准

| ID | 可观察行为与阈值 | 事实源、样本/环境、排除与门禁 |
| --- | --- | --- |
| AC-PRD-001 | 权利未声明被拒绝；声明后固定 300 与 3000 个规范化代码点且含 Han 的样本均可保存并从历史接口读取，299/3001、无 Han、禁用控制符/noncharacter/孤立 surrogate 被拒绝；同键并发 20 次只形成一个来源版本，NFC/LF/哈希符合 `text-normalization-v1` | API/PostgreSQL；本地集成环境；不含 AI 等待；PR 前验证 |
| AC-PRD-002 | 固定来源经 Mock 形成一份可确认剧本、角色/场景/风格资产及 6～10 镜头；总时长 30～60 秒，每镜头含稳定 ID、顺序、时长、画面提示、语音引用和明确资产版本；资产/分镜未统一确认时生产请求被拒绝 | 版本表/API；确定性 fixture；不评价艺术质量；集成门禁 |
| AC-PRD-003 | 同一使用位置的生产命令并发提交 20 次，只形成一个 ProductionTask、一个初始 ProductionAttempt 和一次 Mock 副作用；多项命令不创建 Batch 记录 | 唯一约束、Task/Attempt、Mock 调用日志与 Schema；集成门禁 |
| AC-PRD-004 | 活跃任务由 UI 每 2 秒查询；服务端进入终态后 4 秒内页面显示终态，刷新后 3 秒内恢复相同事实 | 浏览器网络记录、API、Playwright；后台页不计；E2E 门禁 |
| AC-PRD-005 | 六镜头 fixture 中第 3 镜头首次失败时其余五个成功；用户只重试第 3 镜头失败位置会新增一个带 `retry_of_task_id` 的 Task及其初始 Attempt，其他 Task、候选和 Adoption 不变 | Task/Attempt/Candidate 差异与调用计数；恢复门禁 |
| AC-PRD-006 | 在 Provider 已受理、结果落库前终止 Worker，重启后用原请求键对账，120 秒内进入终态或明确 `unknown`，不得增加供应副作用 | Temporal history、OutboxEvent、Mock 对账日志；故障注入门禁 |
| AC-PRD-007 | 每个角色/场景资产、镜头图片、镜头视频和语音 usage slot 最多一个 active Adoption；整体视觉风格没有媒体 slot；视频 Task 缺少必需图片 Adoption 或风格版本/哈希时被拒绝，重做生成新候选且不覆盖历史媒体、Attempt 或其他镜头 | PostgreSQL 唯一约束、输入快照和媒体哈希；集成门禁 |
| AC-PRD-008 | 全镜头采用后 120 秒内生成 720×1280、24fps、H.264 yuv420p/AAC 48k stereo MP4；时长为 30～60 秒且与镜头时长总和误差≤1秒，逐句 TTS 与对应字幕起止误差≤100ms；源视频音轨被移除，视频超出目标±1秒时在 Candidate ready/Adoption 前被拒绝，渲染防御性复检失败不反写历史媒体状态 | ffprobe、RenderSnapshot/Manifest、SHA-256、浏览器播放；Mock 媒体环境；媒体门禁 |
| AC-PRD-009 | 干净本地栈从创建项目到浏览器播放 Mock 成片的 E2E 连续 3 次成功，每次≤10分钟且无数据库、Temporal 或对象存储人工操作 | 三次独立 Playwright run、trace、日志和样片；真实供应等待不计；CI 门禁 |
| AC-PRD-010 | 正式 Acceptance 结论前，使用批准凭据至少完成 1 个 6～10 镜头、30～60 秒的真实 Provider 完整样片，全部必需模态真实执行，成片满足 AC-PRD-008 且日志无密钥 | 脱敏 Provider 请求 ID、Task/Attempt、ffprobe、样片 URI；供应失败不得排除；Acceptance 门禁 |
