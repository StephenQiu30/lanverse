> PRD ID：PRD-000

> 上游：[系统 Requirement](../requirement/000-AI视频生产平台目标需求总览.md)
> 设计约束：[目标系统架构](../design/000-AI视频生产平台目标系统架构设计.md)、[目标产品与功能模块](../design/002-AI视频生产平台目标产品与功能模块设计.md)、[实施基线](../design/005-AI视频生产平台服务与模块实施基线.md)

## 1. 产品决策

首轮试点验证的是“可控制、可审阅、可恢复的 AI 视频生产闭环”，不是功能数量或一键成片。系统必须在一个真实多集项目中证明：整本来源可以校对并拆成稳定剧集；生产事实与 AI 提案分离；高消耗执行前可审查；外部任务可恢复；候选由人选择；问题可局部修复；审阅与交付绑定冻结版本。

试点采用 A—F 纵向切片。A 是所有后续切片的手工事实基线；B 与 C 在 A 通过后可独立推进；D 依赖 C 的真实候选；E 依赖稳定的选择与质量事实；F 中每项组织扩展单独通过证据 Gate。任何页面演示、Mock 或代码存在都不能替代切片退出证据。

## 2. 目标用户与核心任务

| 角色 | 核心任务 | 必须掌握的决定 |
| --- | --- | --- |
| 主创/导演 | 校对叙事、人物和镜头，比较候选，确认创作结果 | Narrative、人物身份、Shot、Selection、质量风险 |
| 制片人 | 组织项目、控制资源、批准外调和交付 | Brief、资源上限、GenerationPlan、DeliverySnapshot |
| 制作操作员 | 导入、结构整理、任务接管、媒体检查与装配 | 草稿编辑、任务恢复、候选准备；不能替代批准 |
| 审片人 | 针对冻结内容评论并做出审阅决定 | ReviewPackage 范围内的评论和批准/拒绝 |
| 权利/治理负责人 | 判断来源、外发、分享和交付是否允许 | PolicyEvaluation、PolicyException、LegalHold |
| 组织管理员 | 管理成员、服务身份和组织级扩展 | Membership、Scope、撤销和高风险授权 |

角色可以由同一试点成员兼任，但系统中的权限和决定事实不得因此合并。

## 3. 试点假设与产品边界

| 项目 | 当前基线 | 影响 |
| --- | --- | --- |
| 团队 | 5—15 人的小型中文视频制作团队 | 默认职责、审阅强度与协作规模 |
| 项目 | 一份可拆为不少于 3 集的整本剧本 | 验证跨集人物、地点和资产一致性 |
| 深度样本 | 选定 1 集完成 3—5 分钟、10—40 Shot 的 A—E 闭环 | 真实生成、质量、审阅和交付的共同样本 |
| 来源 | DOCX、Markdown、TXT | PDF/OCR 在独立 Gate 通过前关闭 |
| 外部能力 | 一个真实图像能力、一个真实视频能力 | 只验证真实接入，不宣称多模型路由完成 |
| 交付 | 审阅 MP4、有序镜头素材包、Manifest | 正式母版/NLE 交换格式在 E 前签认 |
| 敏感内容 | 真人、未公开 IP、品牌素材默认禁止外发 | 必须先取得 M14 声明与允许结论 |

架构、运行时、数据库、消息、对象存储和检索选型只以 Design 为准，不作为可由 PRD 替换的产品配置。

## 4. 产品目标与非目标

### 4.1 目标

| ID | 产品结果 |
| --- | --- |
| PRD-000-O-001 | 用户可以从整本来源建立可追溯、可校对、可版本化的生产事实。 |
| PRD-000-O-002 | Agent、手工界面与 API 只能提出或提交同一业务命令，不能产生第二事实源。 |
| PRD-000-O-003 | 高消耗、外发、风险接受、审阅批准和交付发布分别由具名责任人决定。 |
| PRD-000-O-004 | 网络、进程、消息和外部提供商故障后，用户可以恢复、对账或明确接管。 |
| PRD-000-O-005 | 上游变化只使真实受影响范围待复核，历史批准、主选和交付保持可重读。 |
| PRD-000-O-006 | 项目内检索与未来 ToC 公开检索遵守权限、发布状态和权利边界，且不改变业务事实。 |

### 4.2 非目标

- 商业计费、订阅、支付、公共市场、推荐流和增长系统；
- 专业 NLE 的完整剪辑、调色、混音、特效或工程协作能力；
- 任意代码节点、自动接受 AI 提案、无人审阅自动发布；
- 首轮即支持 PDF/OCR、一键整季、多模型最优路由、公开模板市场或通用模型训练；
- 为试点建立旧 API、旧数据库、旧消息或旧目录兼容链。

## 5. 全局产品规则

| ID | 规则 |
| --- | --- |
| PRD-000-BR-001 | AI 输出默认是提案；“生成完成”不等于事实批准、候选主选、风险接受或交付批准。 |
| PRD-000-BR-002 | 用户看到的长操作状态必须来自持久化 Operation，不使用进程、队列或 Agent 会话状态冒充完成。 |
| PRD-000-BR-003 | 任何外调前展示目标、输入版本、Prompt/参考、能力、资源区间、数据外发和治理结论。 |
| PRD-000-BR-004 | 任何上游修改在提交前展示影响；影响无法计算时不得宣称下游仍有效。 |
| PRD-000-BR-005 | 历史批准、Selection、RiskAcceptance、ReviewDecision 和 DeliverySnapshot 绑定冻结版本且不可原地覆盖。 |
| PRD-000-BR-006 | 每个 P0 动作提供列表/表单/键盘路径；画布不是完成核心流程的前置条件。 |
| PRD-000-BR-007 | failed、partial、unknown、stale、not_analyzed 和零结果必须分别表达并给出安全下一动作。 |

## 6. A—F 产品增量

| 切片 | 用户可获得的新结果 | 依赖 | 明确不宣称 |
| --- | --- | --- | --- |
| A | 无 Agent/真实 Provider 时，从整本剧本到批准叙事、全剧人物/资产、镜头、Fixture Candidate 和预演 | 无 | Agent 自动化、真实生成 |
| B | 对拆集、叙事和生产知识获得逐项可接管的 Agent 提案 | A | 自治工作流、自动批准、完整画布 |
| C | 批准一个真实图像和一个真实视频任务并安全取得候选 | A；B 非前置 | 同类多模型路由完成 |
| D | 发现有证据的问题并只修复真实受影响镜头 | C | 自动总分替代人工决定 |
| E | 对冻结版本审阅、基础装配并发布不可变交付 | C/D | 完整 NLE、外部匿名审片 |
| F | 按证据启用团队职责、外部审片、画布、模板和集成 | A—E + 单项 Gate | 所有组织能力同时上线 |

## 7. 指标体系

| ID | 指标 | 口径与目标 |
| --- | --- | --- |
| PRD-000-M-001 | 首个可审阅结构时间 | 从 SourceRevision 接纳到首个可校对结构；首轮建立基线，不预设虚假目标。 |
| PRD-000-M-002 | 人工修正率 | 分别统计 Scene、Beat、Mention、Entity、Shot 与 Agent Proposal 的接受/修改/拒绝。 |
| PRD-000-M-003 | 外部执行确定性 | unknown、重复提交、重复 Candidate、失败/未知用量分别统计；重复昂贵副作用目标为 0。 |
| PRD-000-M-004 | 局部返工率 | 实际重算对象数/ImpactReport 预测对象数，并记录漏算与多算。 |
| PRD-000-M-005 | 审阅周转 | 包创建到终态决定的时间、修改轮次和未解决 blocker。 |
| PRD-000-M-006 | 交付完整性 | Snapshot 必需文件、Manifest 与 hash 一致率，硬目标 100%。 |
| PRD-000-M-007 | 隔离与治理 | 跨 Workspace 命中/访问、未授权外调和无权交付成功数，硬目标 0。 |

容量、时延、资源和模型质量目标必须由签认数据集形成基线；未签认前保持 proposed。

## 8. 发布与验收原则

切片进入实施前必须同时具备：被接受的 Requirement/PRD/相关 Design、具名责任人、授权测试数据、真实外部条件、P0 范围和停止条件。切片发布必须同时通过功能主线、权限负向、并发幂等、故障恢复、可观察性、可访问性和治理验证。

| ID | 基线验收标准 |
| --- | --- |
| PRD-000-AC-001 | 给定 Agent 与真实 Provider 全部关闭，用户仍能完成 PRD-A 手工事实闭环。 |
| PRD-000-AC-002 | 给定同一业务意图被 UI、API、消息或重试重复提交，系统不产生第二个不可区分事实或外部副作用。 |
| PRD-000-AC-003 | 给定跨 Workspace 已知 ID、媒体引用或异步任务，访问结果不泄漏对象且审计可以定位尝试。 |
| PRD-000-AC-004 | 给定长操作在关键阶段重启或依赖中断，用户能看到权威状态、证据和安全恢复动作。 |
| PRD-000-AC-005 | 给定一个已交付项目发生后续编辑，旧 ReviewDecision、Selection、Snapshot 和 Manifest 保持不变。 |
| PRD-000-AC-006 | 给定公共接口变化，Swagger、Go 边界、前端生成 API 与契约一致，生成漂移检查能够失败。 |

每条验收必须按 [Acceptance 证据规范](../acceptance/README.md) 保存真实命令、数据、环境、结果和残余风险。未执行项状态只能是 `not_run` 或 `blocked`，不得写成通过。

## 9. 开发前待签认配置

1. 试点整本剧本、目标集、授权范围和金标负责人；
2. 第一批成员及其兼任角色、哪些高风险动作要求双人批准；
3. 图像/视频 Provider、地域、训练/保留条款和资源上限；
4. E 切片正式交付预设、帧率、音频、字幕和下载策略；
5. 试点 SLO、PostgreSQL/MinIO RPO/RTO 与容量基线；
6. 是否存在禁止外发或必须私有运行的数据类别。

这些配置改变数据集和验收阈值，不改变稳定身份、版本、提案、计划、执行、决定和快照分离的产品规则。
