# 首轮试点产品基线 PRD

> PRD ID：PRD-000
> 上游：[系统 Requirement](../requirement/000-AI视频生产平台目标需求总览.md)
> 状态：proposed，待产品负责人接受

## 1. 产品结论

首轮试点验证“可控的 AI 视频生产闭环”，不是功能数量或一键成片。系统必须在一个真实内容单元内证明：事实可校对、计划可审查、外调可恢复、候选可选择、问题可局部修复、审阅不漂移、交付可复现。

## 2. 默认试点画像

| 项目 | 默认值 |
| --- | --- |
| 团队 | 5—15 人小型中文视频制作团队 |
| 内容 | 一个 3—5 分钟 ContentUnit，10—40 个 Shot |
| 来源 | DOCX/Markdown/TXT；PDF/OCR 关闭 |
| 首个外部能力 | 一个图像、一个视频 Provider capability |
| 交付 | 审阅 MP4、有序镜头包、Manifest；正式母版预设在 E 签认 |
| 敏感内容 | 真人、未公开 IP、品牌素材默认禁止外发，直至 M14 通过 |
| 技术 | Go 业务后端 + 独立 Go Worker + Python/LangGraph Agent Worker + PostgreSQL/Outbox/RabbitMQ + MinIO |

团队规模、内容、来源、Provider 和交付预设是试点配置，可通过 PRD/Plan 评审调整；`frontend/` TypeScript、`backend/` Go、`agent/` Python 的技术职责是冻结架构，不属于可替换试点配置。

## 3. 角色与默认决定权

| 决定 | 默认责任 |
| --- | --- |
| 叙事、人物、镜头批准 | 主创/导演 |
| 生成计划、资源上限 | 制片人 |
| 候选主选 | 主创，可由操作员准备比较 |
| QualityRiskAcceptance | 具名主创或制片人，按严重度策略 |
| PolicyException | 权利/治理负责人，必要时双人批准 |
| ReviewPackage 批准 | 指定审片人/批准策略 |
| DeliverySnapshot 发布 | 制片人，且所有门禁通过 |

## 4. 全局用户体验原则

1. 每个 AI 结果显示为提案，不伪装成批准事实；
2. 每个长操作显示权威状态、最近证据、失败原因和下一动作；
3. 每个外调在执行前显示输入、外发、能力、资源和治理结论；
4. 每个上游修改在提交前显示影响，不能静默整批失效；
5. 每个 P0 操作有列表/表单/键盘路径，不强制画布；
6. 所有历史批准、主选、风险和交付都绑定版本且不可漂移。

## 5. 核心指标

- 首个可审阅结构/分镜时间；
- Scene/Beat/实体/镜头人工修正率；
- 首轮候选采用率和每镜候选数；
- unknown、重复提交、失败/未知资源消耗率；
- 连续性一次通过和局部返工比例；
- 审阅周转/修改轮次；
- DeliverySnapshot 完整性与可复现率（硬目标 100%）。

指标目标值必须由第一轮试点形成基线，不提前编造。

## 6. 发布 Gate

每个切片必须具备：通过的 Requirement/Design 追踪、真实验收数据集、故障/权限负向测试、已知风险、回退/降级方式和产品负责人范围签认。前一切片未通过时，后续只允许做不依赖它的研究/PoC，不能宣称完成。

## 7. 非目标

商业计费、公共市场、完整 NLE、任意代码节点、自动发布、一键整季、通用基础模型训练和按 M01—M15 预拆微服务均不进入首轮试点。
