# PRD 11：故事板

执行编号：11；来源需求模块：15。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

在同一集场查询镜头，并仅对明确选择的范围执行批量修改与生成。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/15-故事板需求.md)中的业务规则。对应[模块Plan](../plan/11-故事板.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

演示列表、固定选中数和统一成功提示不能证明批量范围与逐项任务结果。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

在同一集场查询镜头，并仅对明确选择的范围执行批量修改与生成。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为制作者，我希望网格与表格显示同一镜头集合，并打开正确详情或画布。
- 作为制作者，我希望只修改明确选择的镜头，任一冲突不产生部分修改。
- 作为制作者，我希望每个所选镜头都有任务结果，单项失败不遮蔽其他结果。

## 6. 价值与范围取舍

不是首轮单链生成前置；在镜头与生成合同可用后接入，验证真实多镜头组织。

不保存另一份故事板镜头状态，不把批量任务成功等同于人工选定。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/15-故事板需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/15-故事板需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-BOARD-01：读取同一集场并导航

作为制作者，我希望网格与表格显示同一镜头集合，并打开正确详情或画布。

范围追踪：FR-BOARD-01、FR-BOARD-05，原始规则见[功能需求](../requirement/15-故事板需求.md#3-功能性需求)。

1. 查询/排序及数量一致。
2. 缩略图与状态真实。
3. 不加载全部历史。
4. 跳转保持项目/集场/镜头且无权拒绝。

### US-BOARD-02：明确选中并批量改时长

作为制作者，我希望只修改明确选择的镜头，任一冲突不产生部分修改。

范围追踪：FR-BOARD-02～03，原始规则见[功能需求](../requirement/15-故事板需求.md#3-功能性需求)。

1. 展示实际选中ID与数量。
2. 空/超限按规则拒绝。
3. 全部权限/版本/模型校验。
4. 任一冲突整批不写且保留输入。

### US-BOARD-03：逐镜头追踪批量生成

作为制作者，我希望每个所选镜头都有任务结果，单项失败不遮蔽其他结果。

范围追踪：FR-BOARD-04，原始规则见[功能需求](../requirement/15-故事板需求.md#3-功能性需求)。

1. 费用确认对应明确范围。
2. 每镜头独立可查任务。
3. 重复提交不重复收费。
4. 成功/失败/未知逐项可见且不自动采用。

### 依赖、假设与质量

- 必要依赖：13；批量任务使用14，打开画布使用16同项目上下文。
- 尚待决定：跨页/筛选选择范围、批量上限、费用确认范围与空选择反馈。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/15-故事板需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/15-故事板需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
