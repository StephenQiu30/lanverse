# PRD 04：供应商

执行编号：04；来源需求模块：09。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

让生成任务使用服务端可用凭据，并在配置失败时保留原可用状态。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/09-供应商需求.md)中的业务规则。对应[模块Plan](../plan/04-供应商.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：管理员。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

凭据表单或固定测试成功无法证明实际鉴权、配额与可调用性。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

让生成任务使用服务端可用凭据，并在配置失败时保留原可用状态。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为管理员，我希望看到真实配置摘要，避免把未配置当成可用。
- 作为管理员，我希望候选凭据测试通过后再替换，避免损坏正在使用的配置。
- 作为管理员，我希望重测当前配置，判断生成入口是否可用。

## 6. 价值与范围取舍

至少验证承载生图与图生视频的供应商配置，是否同一家由真实能力决定；凭据不写入PRD、浏览器或日志。

供应商覆盖扩展随后评估，不以配置一种供应商证明支持全部能力。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/09-供应商需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/09-供应商需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-PROVIDER-01：看清当前配置状态

作为管理员，我希望看到真实配置摘要，避免把未配置当成可用。

范围追踪：FR-PROVIDER-01，原始规则见[功能需求](../requirement/09-供应商需求.md#3-功能性需求)。

1. 未配置/可用/失败分开。
2. 只返回掩码与安全摘要。
3. 普通用户读取被拒绝。
4. 最近测试对应真实时间与操作者。

### US-PROVIDER-02：测试后替换凭据

作为管理员，我希望候选凭据测试通过后再替换，避免损坏正在使用的配置。

范围追踪：FR-PROVIDER-02，原始规则见[功能需求](../requirement/09-供应商需求.md#3-功能性需求)。

1. 候选只在服务端测试。
2. 鉴权/配额/超时失败保留旧值。
3. 通过后原子替换且留操作者。
4. 并发冲突与测试费用按确认规则处理。

### US-PROVIDER-03：核验活动配置

作为管理员，我希望重测当前配置，判断生成入口是否可用。

范围追踪：FR-PROVIDER-03，原始规则见[功能需求](../requirement/09-供应商需求.md#3-功能性需求)。

1. 测试不无故替换活动值。
2. 鉴权/配额/连通错误分开。
3. 迟到结果不能覆盖新配置状态。
4. 时间与安全原因可追踪。

### 依赖、假设与质量

- 必要依赖：06管理员授权；真实供应商条件属于外部依赖。
- 尚待决定：测试具体操作/费用/超时、短密钥掩码、结果有效期、并发替换和测试期间调用规则。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/09-供应商需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/09-供应商需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
