## 1. 模块组合结论

四个基础业务模块不等于“公共代码”：identity 提供可信 actor，projects 提供创作边界，media 提供不可变文件事实，governance 提供权利/审核/标识证据。它们必须各自拥有事实和业务命令，不能合并成全局 common/service，也不能把下游状态复制进自己的表。

| 模块 | 用户结果 | 唯一事实 | 明确不能拥有 | 主切片 |
| --- | --- | --- | --- | --- |
| identity | 登录后获得可用且隔离的个人空间 | UserAccount、Workspace、Membership | 项目内容、任务、费用 | S1 |
| projects | 建立短剧和单集并看到真实生产下一动作 | Project、Episode、ProductionSnapshot 规则 | 剧本正文、任务状态、审核决定 | S1–S5 |
| media | 安全上传、访问和追踪每个文件版本 | MediaObject、MediaVersion、MediaLocation、Lineage、UploadSession | 角色、镜头、时间线规则 | S2–S5 |
| governance | 在生成和交付前完成权利与质量门禁 | Consent、Review、Issue、Decision、Moderation、Label、AuditEvent | 被审正文、业务版本 | S2/S5 |

## 2. identity：用户与空间

### 2.1 产品职责与对象

首次注册必须原子建立稳定 UserAccount、个人 Workspace 和 owner Membership；后续登录只验证本地密码并签发短期 JWT。ActorContext 是每次请求根据已验证 JWT、账号 token_version、workspace_id 和有效 Membership 计算的只读结果；客户端提交的角色永不可信。

| 对象 | 可执行操作 | 生命周期/约束 |
| --- | --- | --- |
| UserAccount | 注册/登录/注销/改密、读取/修改显示资料、停用账户 | `active → deactivated`；邮箱唯一；只保存 Argon2 摘要；token_version 单调递增 |
| Workspace | 创建、列表、详情、改名、归档、恢复 | `active ↔ archived`；归档禁止新业务写入但历史可读 |
| Membership | MVP 只自动创建 owner；角色查询 | owner/editor/viewer；邀请、改角色、移除属于 P1 |
| ActorContext | 选择/解析当前 Workspace | 请求级只读，不持久化，不跨模块重复解析 token |

### 2.2 MVP 接口与交互

- 注册/登录/请求依赖：注册三项事实同事务；登录校验 Argon2；请求验证固定 JWT 算法、issuer、audience、exp、subject 和 token_version。
- `GET/PATCH /api/v1/me`：只允许 display_name、avatar_url；账户停用使用明确命令，不用 PATCH status。
- Workspace 列表/创建/详情/修改/归档/恢复：多空间时必须显式选择；单一有效空间可默认进入。
- 权限拒绝先于业务详情读取；跨 Workspace 统一 NOT_FOUND，前端只显示无权/不存在的稳定结果。
- 归档空间的运行 Task 由 production 继续按事实收敛，但不允许产生新 GenerationRequest。

### 2.3 模块交接与验收

identity 只向其他模块提供 `ActorContext(user_id, workspace_id, membership_id, role)` 和能力检查；不返回 ORM User/Workspace，也不管理预算余额。

模块完成必须证明：并发注册不留下重复或部分事实；错误凭据响应一致；非法/过期/旧版本令牌不创建事实；注销/改密立即撤销旧令牌；角色能力矩阵正确；停用后不能写但历史不删除；归档空间拒绝下游写；跨空间 API 与数据库集成测试不可探测。

## 3. projects：项目与单集

### 3.1 产品职责与对象

Project 表达一部短剧/系列的默认制作设置与预算上限；Episode 是剧本、镜头、生产和交付的单集边界。ProductionSnapshot 由下游公开摘要实时组合，不能由前端编辑或持久化成第二份阶段事实。

| 对象 | CRUD/命令 | 核心规则 |
| --- | --- | --- |
| Project | 创建、列表、详情、改元数据、改预算、归档/恢复、删除空草稿 | budget 仅 owner 命令；默认值变化不回写历史版本 |
| Episode | 创建、列表、详情、改元数据、重排、归档/恢复、删除空草稿 | 同 Project position 连续唯一；当前版本引用比较更新 |
| ProductionSnapshot | 读取 Project/Episode 概览 | current_stage、blockers、next_actions、任务/审核/成本摘要和 partial_failures |

### 3.2 阶段计算和交接

阶段规则固定为：缺当前剧本 → 剧本入库；存在未决议候选 → 结构确认；资产/镜头未就绪 → 准备；任务运行或缺已选候选 → 生产；时间线未发布 → 合成；审核未批 → 审核；否则可交付。任何依赖 unavailable 必须进入 partial_failures，不能解释为数量为零或已完成。

projects 只保存 current_script_version_id/current_timeline_version_id 等稳定指针；设置指针前通过所属模块取得 VersionRef 并比较 expected old ID。它从 scripts/assets/storyboards/production/governance/editing 读取摘要，但不能借概览接口修改这些模块。

### 3.3 模块验收

- owner/editor 能按权限创建 Project/Episode；viewer 只读；父 Project 归档后所有下游写被拒绝。
- Episode 重排必须提交完整 ID 集合并原子生成连续 position；并发冲突返回服务端最新顺序。
- 预算上限命令与普通 Project PATCH 分离；editor 不能夹带预算字段。
- 删除前返回版本、任务、费用、审核和交付 blockers；并发新增引用时删除失败且不级联。
- Snapshot 在依赖部分失败时仍返回可解释结果；典型规模满足 PRD-001 性能基线，无逐 Episode N+1。

## 4. media：媒体与对象位置

### 4.1 产品职责与对象

media 管理上传和所有生成/转码/渲染文件。业务模块只能保存 MediaVersion ID；bucket、object key、预签名 URL 和 SDK 异常只能出现在 media/适配器内部。

| 对象 | 作用 | 生命周期/约束 |
| --- | --- | --- |
| UploadSession | 一次受控直传意图 | `pending → completed/expired/failed`；完成幂等 |
| MediaObject | 同一逻辑媒体身份 | `active ↔ archived`；历史版本仍可读 |
| MediaVersion | 不可变字节与探测元数据 | sha256、大小、MIME、规格确认后不可修改/删除 |
| MediaLocation | 版本的物理存储位置 | `verified → active → retiring → retired`，异常可 quarantined |
| Lineage | 输入、输出与 Task/Render 的转换证据 | 输出必须可解释，不形成孤立文件 |

### 4.2 上传、访问和登记流程

1. 初始化上传：校验 actor、Workspace、媒体类型、声明大小/MIME/hash 和 PRD-001 上限，返回 UploadSession 与受限直传能力。
2. 完成上传：锁定 Session，经 ObjectStoragePort HEAD/stream 校验对象、大小、类型和平台 sha256；不把 ETag 当 hash。
3. 登记版本：同事务创建 MediaObject/Version/active Location，并为探测写 Task/Outbox；校验失败进入 failed/quarantined，不创建可用版本。
4. 短期访问：按用途和权限产生临时能力；过期后重新申请，数据库和前端不得保存永久 URL。
5. 生成输出：以 Task/Render、输入版本、稳定输出槽幂等登记 Version/Location/Lineage；供应商成功但下载失败只重试下载。

存储迁移只为同一 MediaVersion 增加并验证新 Location，再原子切 active；原位置在留存门禁后 retired。MVP 不提供用户迁移 UI，但 MinIO/未来 OSS 不能改变业务 ID 和访问契约。

### 4.3 模块验收

真实 MinIO 契约必须覆盖直传、HEAD、分片、私有访问、hash 不符、重复完成、对象/数据库半失败和孤立对象清理。业务模块导入存储 SDK、持久化预签名 URL或使用 object key 作为业务 ID，均视为架构失败。上线选择 OSS 时同一端口契约必须在真实 OSS 重跑，不能只修改 endpoint 宣称兼容。

## 5. governance：授权、审核与交付治理

### 5.1 产品职责和门禁

governance 只接受枚举受控对象及固定版本 ID。它不判断“内容正文是什么”，而是记录该版本在某用途/时间是否具备权利、是否通过检查、有哪些问题和谁作出了决定。

| 能力 | 产品操作 | 通过条件 |
| --- | --- | --- |
| Consent | 登记证明、追加授权范围、撤销 | subject/usage/地域/期限匹配，证明媒体可访问 |
| RightsGate | 内部查询 allowed/blockers/consent_ids | 新生成和交付时实时检查，不缓存永久许可 |
| Review/Issue | 提交固定版本、建问题、指派、解决/重开 | Issue 定位 Shot/Clip/time range，变化使用 revision |
| Decision | 批准、退回、撤销批准 | 无 open blocking Issue，权利有效，Moderation 通过 |
| Moderation | 异步检查、人工处置 | 超时进入 unknown，不得默认为通过 |
| Label | 写入/验证显式或隐式标识与内容编号 | 产生新 MediaVersion，验证 hash 后才能交付 |
| AuditEvent | 受控查询 actor/target/action/time | 只追加、脱敏，不复制正文或授权证明 |

### 5.2 阶段交接

- S2：剧本来源和真人/声音/参考素材先登记 Consent；权利缺失允许保存 draft，但必须阻止资产 ready 和新的生产。
- S3/S4：Shot readiness 与生成预检都调用 RightsGate；撤销授权立即使新请求 blocked，不篡改历史任务和费用。
- S5：Review 绑定 TimelineVersion；修改后必须发布新版本并重新审核。Render 成功后标识处理产生新的交付媒体，再由 editing 创建 Manifest。

### 5.3 模块验收

必须验证授权过期/撤销、Review 幂等提交、并发批准与新增 Issue、Decision/Audit 只追加、Moderation 重复回调与 unknown、标识写入/验证失败阻止交付、跨空间 Subject 不可探测。目标地区和责任规则未冻结时，不能把治理模块或 S5 标记为完成。

## 6. 基础模块联合验收

固定场景必须贯穿四模块：注册建立 Workspace → 登录 → 创建 Project/Episode → 上传授权证明和参考媒体 → 登记 Consent → 建立下游版本引用 → 归档 Workspace/撤销授权后新写入被阻止，同时历史 Project、MediaVersion 和 AuditEvent 仍可读取。联合验证失败时不能用各模块单独 CRUD 测试代替。
