# PRD 09：镜头

执行编号：09；来源需求模块：13。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

形成可定位的镜头输入版本，比较候选并人工选定真实结果。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/13-镜头需求.md)中的业务规则。对应[模块Plan](../plan/09-镜头.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

固定镜头fixture、播放器样例和选定样式无法证明镜头来源、生成与采用。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

形成可定位的镜头输入版本，比较候选并人工选定真实结果。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为制作者，我希望从明确来源的镜头编辑输入，保留每次版本与参考用途。
- 作为制作者，我希望比较真实候选后再采用，避免新任务覆盖已有作品。
- 作为制作者，我希望复用素材或参数并读取旧版本，保留可解释的创作历史。

## 6. 价值与范围取舍

首轮画布草稿可独立于镜头；镜头绑定不是Demo前置。后续镜头与画布使用同一14生成合同，不建立第二套任务。

完整镜头历史与只读台词后补，不新增逐句编辑或配音平台。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/13-镜头需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/13-镜头需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-SHOT-01：定位并保存镜头输入

作为制作者，我希望从明确来源的镜头编辑输入，保留每次版本与参考用途。

范围追踪：FR-SHOT-01～02，原始规则见[功能需求](../requirement/13-镜头需求.md#3-功能性需求)。

1. 首次来源与项目/集/场可追踪。
2. 首尾/不存在/越权明确。
3. 模型校验及参考用途/顺序保存。
4. 冲突保留草稿且不改冻结版本。

### US-SHOT-02：生成、比较与采用

作为制作者，我希望比较真实候选后再采用，避免新任务覆盖已有作品。

范围追踪：FR-SHOT-03～04，原始规则见[功能需求](../requirement/13-镜头需求.md#3-功能性需求)。

1. 复用14冻结任务。
2. 候选可真实预览。
3. 就绪且有权才可选定。
4. 采用新版本显式标出下游失效但不自动再收费。

### US-SHOT-03：复用候选并查历史

作为制作者，我希望复用素材或参数并读取旧版本，保留可解释的创作历史。

范围追踪：FR-SHOT-05～06，原始规则见[功能需求](../requirement/13-镜头需求.md#3-功能性需求)。

1. 保存素材建立授权条目。
2. 复制参数只形成草稿不执行。
3. 历史只读且按需加载。
4. 真实音频才播放且不复制签名URL/秘密。

### 依赖、假设与质量

- 必要依赖：07、08、10、12；首次形成与11确认；候选生成使用14。
- 尚待决定：首次镜头形成、首尾/缺失导航、采用与失效、媒体回收对候选和选定的影响。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/13-镜头需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/13-镜头需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
