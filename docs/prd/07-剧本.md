# PRD 07：剧本

执行编号：07；来源需求模块：11。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

将支持格式的剧本原件转为可追踪的分集与设定候选，为镜头链提供明确来源。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/11-剧本需求.md)中的业务规则。对应[模块Plan](../plan/07-剧本.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：制作者。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

导入进度与固定镜头不能证明解析、结构确认和首次镜头形成。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

将支持格式的剧本原件转为可追踪的分集与设定候选，为镜头链提供明确来源。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为制作者，我希望上传剧本后能查询同一导入任务，失败时保留项目。
- 作为制作者，我希望核对解析出的分集和设定，避免自动覆盖已有确认结果。
- 作为制作者，我希望离开后仍能读取导入结果并继续建立镜头。

## 6. 价值与范围取舍

不是首轮画布自由生图→图生视频的前置；Demo完成后按模块顺序接入剧本创作链。

不能用复制样例分集替代导入，也不预建独立剧本工作台。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/11-剧本需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/11-剧本需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-SCRIPT-01：保存原件并追踪导入

作为制作者，我希望上传剧本后能查询同一导入任务，失败时保留项目。

范围追踪：FR-SCRIPT-01～02，原始规则见[功能需求](../requirement/11-剧本需求.md#3-功能性需求)。

1. 支持文件真实保存。
2. 上传/解析状态分开。
3. 同键同输入定位原任务而异输入冲突。
4. 刷新/重启保留任务与安全失败。

### US-SCRIPT-02：得到可核对的内容结构

作为制作者，我希望核对解析出的分集和设定，避免自动覆盖已有确认结果。

范围追踪：FR-SCRIPT-03～04，原始规则见[功能需求](../requirement/11-剧本需求.md#3-功能性需求)。

1. 分集保留原件来源。
2. 无标题/歧义按确认规则显示。
3. 同名不自动合并。
4. 已锁定设定不被新抽取覆盖。

### US-SCRIPT-03：从结果继续创作

作为制作者，我希望离开后仍能读取导入结果并继续建立镜头。

范围追踪：FR-SCRIPT-05，原始规则见[功能需求](../requirement/11-剧本需求.md#3-功能性需求)。

1. 真实进度与结果可读回。
2. 部分结果/失败/未接入分开。
3. 项目列表不加载全文。
4. 首次镜头来源经确认后能追踪到原内容。

### 依赖、假设与质量

- 必要依赖：07、08；抽取结果由12消费，首次镜头形成与13共同确认。
- 尚待决定：PDF支持、文件限制、标题/分集/抽取规则、场与镜头首次形成、重导入/部分结果、安全重试及文件外发。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/11-剧本需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/11-剧本需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
