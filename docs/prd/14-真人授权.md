规则与验收以 [REQ-17](../requirement/17-真人授权.md) 为准，以下为产品摘要。

## 1. 问题与价值

制作者把演员照片或声音作为写实角色参考时，若只看到素材文件而没有授权状态，就无法判断能否用于后续镜头；授权事后作废还会影响已报价和在途结果。本功能在上传、引用与作废处展示并校验授权，让制作者先取得可追溯许可，再安全地锁定参考。对应 PRD-01 §2 的**可控性**，支撑 S2 的资产定稿与 S6 的跨集复用：两者使用同一真人素材前都需确认授权；P34 决定作废后在途任务的处理。

## 2. 目标用户与场景

- 上传写实人物素材时声明真人属性并附授权材料。
- 锁定参考时查看授权状态。
- 管理员作废无效授权并查看受影响对象。

## 3. 范围

- **做（MVP）**：授权声明记录、授权文件上传与受限访问、素材与声明关联、引用前校验。
- **不做**：不做人脸自动识别、电子签署；V2 见 REQ-34。

## 4. 用户体验与流程

1. 在媒体库上传图片或音频时，写实项目先回答“是否包含真实人物”；需要授权时填写声明并上传材料，完成后在媒体详情查看授权状态。
2. 在造型锁定或参考选择器选素材时，未授权项置灰并说明原因；有效授权可关联同一人的多份素材。
3. 管理员作废声明后，用户看到关联素材不可再引用及“合规问题”提示，并可查看影响清单；报价和在途任务按 P34 处理。
4. 未填写声明时提示补齐后再引用；授权文件不可访问时提示稍后重试或联系管理员；无权限查看材料时显示拒绝访问，项目成员与管理员可按权限查看且留审计。

## 5. 产品规则

- 写实项目上传图片或音频时必须回答“是否包含真实人物”；风格化项目默认否，可主动声明（REQ-17 R1）
- 包含真实人物的素材必须关联授权声明才能被引用（REQ-17 R2）
- 声明文本快照保存（不随模板变化）（REQ-17 R3）
- 授权文件只有项目内用户与管理员可访问，每次访问写审计（REQ-17 R4）
- 一个声明可关联多个素材（同一人的多张照片）（REQ-17 R5）
- 授权作废时，未确认的报价失效，未提交的任务不计费结束，已提交任务的产出标过期。（PRD-01 P34；DES-20 §3）

## 6. 成功标准

- Given 写实项目，When 上传人物照片且未勾选授权声明，Then 无法保存为参考，提示需要授权声明。（[TST-02](../test/02-需求追踪矩阵.md) TC-17-01）
- Given 已声明授权的素材，When 锁定为造型参考，Then 成功，媒体详情显示授权声明。（[TST-02](../test/02-需求追踪矩阵.md) TC-17-02）
- Given 授权文件，When 用户查看，Then 审计记录该访问。（[TST-02](../test/02-需求追踪矩阵.md) TC-17-03）

以上为 [REQ-17](../requirement/17-真人授权.md) §3 的 TC-17-01～03；关联质量要求见 [REQ-02](../requirement/02-非功能需求规格.md) CMP-02、PRV-04。本功能以 REQ-02 CMP-02、PRV-04 验证合规与访问控制；PRD-01 §10 无直接单项指标。

## 7. 依赖与风险

- **依赖**：[PRD-12](12-参考定稿与跨集复用.md)、[PRD-27](27-媒体库.md)。
- **风险**：漏报真人属性、材料访问和作废后的在途任务处理。

## 8. 待确认

待确认：REQ-17-Q1 授权声明文本模板须经法务评审；评审前使用通用模板（PRD-01 Q6）。

已决定：MVP 仅用户自报、不做自动人脸判断（REQ-17 范围、DES-20-Q2）；作废后的报价和在途任务按 PRD-01 P34，已有内容标记合规影响（DES-20-Q3）。授权材料的加密与签名链接属于 DES-20-Q1 实施细节。
