# 项目与来源产品需求

## 1. 问题、价值与范围

创作者需要一个稳定的制作入口，并必须在任何 AI 调用前证明故事来源权利和保存可追溯原文。产品交付一个 Project 对应一个 Episode 的本地入口、严格文本校验、不可变来源历史和明确的当前确认版本。

范围包含创建/列表/打开项目、粘贴来源、权利声明、保存/确认/回看来源版本；不包含第二集、文件导入、URL 抓取、用户上传媒体、协同编辑或删除历史。

## 2. 用户故事

| ID | 用户与触发 | 前置条件 | 主流程 | 失败/恢复 | 完成定义 |
| --- | --- | --- | --- | --- | --- |
| US-PROJECT-001 | 创作者开始制作一部短剧 | 应用已连接本地环境 | 输入 1～120 代码点标题→创建 Project→系统原子创建 Episode | 重复点击返回原项目；非法标题明确提示 | 项目列表和详情显示同一稳定 Project/Episode |
| US-PROJECT-002 | 创作者有一段获权中文故事 | 已打开 Episode | 选择 `original/licensed`→粘贴正文→保存 draft→确认 | 非法/超长/无 Han/无权利声明不保存 | confirmed Source 可回读且字符数/哈希可对照 |
| US-PROJECT-003 | 创作者要修订已确认故事 | 已有 confirmed Source | 保存新 draft→比较→确认新版本 | 冲突时刷新，不覆盖他人/旧版本 | 新版本成为 current，旧版本保留且下游只显示 outdated |

## 3. 产品流程与界面反馈

1. 创建项目成功后直接进入该 Episode 的 Story 工作区；阶段摘要显示“待输入来源”。
2. 来源编辑器持续显示规范化后字符数、允许范围和权利声明；前端提示不替代服务端校验。
3. 保存成功显示版本号、创建时间、状态和内容哈希摘要；确认前二次提示“后续生产固定该版本”。
4. 历史列表可读取任意版本但 confirmed/superseded 只读；修订必须明确创建新 draft。
5. 服务重启、页面刷新或 Redux 清空后从 URL 与 API 恢复项目和全部来源历史。

## 4. 业务与数据规则

- 标题按 NFC 和首尾空白规范化，长度 1～120 Unicode 代码点。
- 制作规格固定 9:16、720×1280、24fps、30～60 秒，对用户只读。
- 来源按 `text-normalization-v1` 处理；规范化后 300～3000 代码点、至少一个 Han，拒绝禁用控制符、noncharacter 和孤立 surrogate。
- 权利依据只允许 `original/licensed`；未声明不创建 SourceRevision。
- 每次有效保存新建不可变版本；每 Episode 最多一个 current confirmed。
- 新来源确认不修改旧 Script/Shot/Task/Candidate/Adoption，只在兼容性投影显示 `input_outdated=true`。

## 5. 状态与异常

| 情况 | 用户反馈 | 下一动作 |
| --- | --- | --- |
| 输入不合法 | 字段级原因和边界，不创建版本 | 修正原输入 |
| 重复提交 | 返回原资源，无重复版本 | 继续当前流程 |
| ETag 冲突 | 显示服务端已更新，不自动覆盖 | 刷新并重新确认 |
| 已确认版本编辑 | 明确只读 | 派生新 draft |
| 服务暂不可用 | 保留未提交编辑，正式事实不变 | 重连后重新读取/提交 |
