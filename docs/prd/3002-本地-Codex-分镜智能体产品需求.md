- 方案来源：[本地 Codex 分镜智能体执行框架设计](../design/3002-本地-Codex-分镜智能体执行框架设计.md)

## 产品结论

本地 Codex 分镜智能体把已确认剧本转换为可审核、可追溯、可恢复的关键分镜候选。它服务于
导演和分镜师的决策，不自动批准候选，也不直接生成图片、视频或正式 Shot。

产品价值来自完整的受控工作流，而不是一次模型调用：

```text
确认剧本与 Bible 上下文
→ 场景理解与视觉计划
→ 分镜候选
→ 确定性硬门
→ 独立复核
→ 有限定向修复
→ needs_review
→ 人工决策与原子应用
→ 可复现关键分镜表
```

## 目标用户与核心任务

| 用户 | 核心任务 | 期望结果 |
|---|---|---|
| 导演 / 分镜师 | 将场景、动作和对白拆成可拍摄镜头 | 获得来源明确、时长连续、包含画面与声音意图的关键分镜表 |
| 剧本统筹 | 核查剧情覆盖、对白引用和连续性 | 每个镜头可反查确认剧本与叙事单元 |
| 资产管理员 | 核查人物、地点和道具状态是否使用正确 | 镜头只绑定固定输入中的资产版本 |
| 制片人 | 审阅风险、选择候选并决定是否落地 | 所有警告和阻断有明确作用域，不自动写正式 Shot |
| 运行维护者 | 处理长任务、重投、重启和取消 | 从合法 checkpoint 恢复，旧 Worker 无法重复提交 |

## 用户问题

直接让模型生成镜头表容易遗漏剧情、跨场景引用、伪造资产、产生不连续时间码，或者在自动
修复时重写已经正确的内容。长任务还可能因 Worker 重启或重复投递生成多份互相冲突的候选。

用户需要一个把创意判断与确定性约束分开的分镜执行框架：模型负责理解、规划、草拟和独立
复核；应用负责引用、覆盖、时长、资产、checkpoint、所有权和正式写入。

## 产品范围

### 固定输入

- 消费确认脚本、叙事单元、场景/对白标识和 required coverage。
- 自动消费目标剧集 Production Bible occurrence 派生的资产状态与相关世界观。
- 冻结目标时长、画幅、视觉风格和输入哈希；运行中输入变化必须被拒绝。

### 分阶段生成

- 按场景完成来源理解、视觉计划和分镜草拟，多场景可并行。
- 系统统一生成全局镜号、连续时间码和结果哈希。
- 确定性硬门检查来源、场景、对白、required coverage、时长、基础连续性和资产绑定。
- 独立 Reviewer 只提出有证据的问题，不能伪造 Tool 结论。
- 阻断问题只修复受影响场景，总修复轮次有明确上限。

### 人工审核与交付

- 成功结果只进入 `needs_review`，不会自动批准或写正式 Shot。
- 用户可逐项接受或拒绝候选，完成审批后通过预检和原子应用写入正式分镜。
- 关键分镜表至少提供机器可读与人工可读格式，并包含来源与资产引用。
- Warning 以稳定风险码进入候选，同时保留完整 issue 证据供人工复核。

### 失败与恢复

- 结构错误、硬门失败、Reviewer blocker、Provider 不确定和输入漂移必须有不同结果。
- 服务重启只恢复身份、版本和哈希全部匹配的 checkpoint。
- 活跃 lease 的重复投递不能启动第二个 Codex；失去 lease 的旧 Worker 不能保存或提交。
- 用户可显式取消长运行，取消结果不能被后续 Provider 返回覆盖。

## 关键用户旅程

1. 用户选择已确认的单集剧本并发起分镜草拟。
2. 系统自动冻结剧本、Bible、occurrence、世界观、时长和视觉参数。
3. 用户查看运行状态；系统按场景执行多阶段生成并保存 checkpoint。
4. Tool Gate 拒绝不完整或非法引用，有限修复仍失败则不给出半成品。
5. 独立 Reviewer 的 warning 和合法 blocker 被归一化并精确定位。
6. 通过最终门禁的候选进入 `needs_review`。
7. 用户完成逐项决策、审批、影响预检和原子应用。
8. 用户导出带时间码、镜头语言、动作、声画、连续性、帧、来源和资产的交付包。

## 主题交付门

只有同时满足以下条件，才能宣称“本地 Codex 分镜智能体可用”：

- 真实本机 Codex 完成至少两个场景、动作、对白、跨空间动作和关键道具的合约。
- required 叙事单元全部覆盖，引用不跨场景，关键道具按来源位置绑定。
- 总时长、镜号和时间码通过确定性门禁。
- Reviewer 幻觉不能触发错误的全局修复。
- checkpoint、lease、heartbeat、重投、恢复、fencing 和显式取消均有自动化证据。
- 候选经人工审核后原子应用，导出结果可复现。
- Production Bible 资产与世界观在真实输入中完成端到端验收。
- 60 集机器统计和代表集人工细查完整通过。

## 成功判定

- required narrative unit 漏覆盖数为 `0`。
- 非法 scene/dialogue/asset 引用进入可审核候选的数量为 `0`。
- 全局镜号或时间码断裂数量为 `0`。
- 同一 active lease 并行运行的 Codex 实例数不超过 `1`。
- 旧 run token 成功保存 checkpoint 或提交结果的次数为 `0`。
- 未经人工审批写入正式 Shot 的数量为 `0`。
- 相同固定输入的交付包内容哈希保持一致。

## 非目标

- 不生成场景图、人物三视图、道具图或视频。
- 不自动批准候选，不替代导演或分镜师最终判断。
- 不建立通用 Agent 平台、跨领域 Tool Registry 或第二套 Markdown 状态机。
- 不运行上游仓库脚本，不依赖 DeepSeek 或外部 Provider registry。
- 不把复杂轴线、视线、动作匹配和音画桥在缺少规则与验收前宣称为确定性通过。

## 约束与风险

- 模型结果具有非确定性；产品必须暴露 issue，不能静默放宽引用和覆盖规则。
- 基础 Tool Gate 不能替代复杂导演语法与人工连续性审核。
- 本机 Codex 登录状态和本地运行环境是合约验收的外部条件，缺失时只能验证 Harness。
- 真实小样本不能替代完整原稿的批量效果与恢复验证。
