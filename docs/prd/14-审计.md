# PRD 14：审计

执行编号：14；来源需求模块：18。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

追踪关键变更的真实责任与结果，提供脱敏查询和导出。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/18-审计需求.md)中的业务规则。对应[模块Plan](../plan/14-审计.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：管理员。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

业务先运行再补日志会丢失生成确认、配置和采用的关键证据。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

追踪关键变更的真实责任与结果，提供脱敏查询和导出。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为管理员，我希望关键动作有可信责任记录，能追踪生成和配置变化。
- 作为管理员，我希望按范围查记录并核对变更前后内容。
- 作为管理员，我希望导出当前筛选记录，保留一致口径与安全字段。

## 6. 价值与范围取舍

关键业务事件随06～10、14、16同时接入；本模块后置的是管理员查询和导出界面。

不建立可编辑/删除审计页面，查询后置不能作为缺记录理由。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/18-审计需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/18-审计需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-AUDIT-01：随业务留下关键事实

作为管理员，我希望关键动作有可信责任记录，能追踪生成和配置变化。

范围追踪：FR-AUDIT-01，原始规则见[功能需求](../requirement/18-审计需求.md#3-功能性需求)。

1. 操作者/对象/项目/版本真实。
2. 事件只追加。
3. 关键业务与审计按接受策略一致。
4. 重复与失败动作按确认清单处理且脱敏。

### US-AUDIT-02：查询和打开脱敏详情

作为管理员，我希望按范围查记录并核对变更前后内容。

范围追踪：FR-AUDIT-02～03，原始规则见[功能需求](../requirement/18-审计需求.md#3-功能性需求)。

1. 服务端仅管理员可读。
2. 先筛选后稳定分页。
3. 详情缺失显式为空。
4. 账号停用保留责任且不泄露凭据。

### US-AUDIT-03：导出授权CSV

作为管理员，我希望导出当前筛选记录，保留一致口径与安全字段。

范围追踪：FR-AUDIT-04，原始规则见[功能需求](../requirement/18-审计需求.md#3-功能性需求)。

1. 范围与列表一致。
2. 字段/编码/上限按确认合同。
3. 公式注入得到处理。
4. 无权/超限明确失败且无秘密。

### 依赖、假设与质量

- 必要依赖：各写入模块提供事件；06管理员授权；业务与记录一致性在各Design明确。
- 尚待决定：必录动作/失败范围、记录失败是否阻断业务、稳定排序、保留期、CSV编码/字段/限额。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/18-审计需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/18-审计需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
