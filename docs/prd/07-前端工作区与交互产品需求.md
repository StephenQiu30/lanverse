# 前端工作区与交互产品需求

## 1. 问题、价值与范围

AI 短剧制作跨越多个长任务和人工确认点。创作者需要在一个连续工作区中始终看见当前阶段、缺失条件、任务进度和下一动作；刷新、断网或授权过期不能让正式状态丢失或误报。

范围包含 Projects、Story、Studio、Tasks、Delivery 五个工作区、响应式桌面布局、表单/版本冲突反馈、2 秒 Task 轮询、局部重试回跳、候选预览和私有下载。MVP 不包含移动端专项设计、WebSocket、离线编辑、通知中心或多用户协作。

## 2. 用户故事

| ID | 用户与触发 | 前置条件 | 主流程 | 失败/恢复 | 完成定义 |
| --- | --- | --- | --- | --- | --- |
| US-UI-001 | 创作者打开应用 | API 可达 | Projects 查看阶段→进入对应 Story/Studio/Delivery | 空状态给出唯一首要动作 | 不依赖记忆即可知道当前阶段 |
| US-UI-002 | 创作者启动长任务 | 异步命令已返回 task_id | 立即显示 Task→每 2 秒更新→终态停止 | 网络错误与 Task failed 分开显示 | 终态在 4 秒内可见 |
| US-UI-003 | 创作者刷新或重开页面 | URL 含 Project/Episode/Task 上下文 | 从 API 恢复版本、任务、采用和交付 | Redux 为空不影响正式事实 | 3 秒内恢复同一服务端状态 |
| US-UI-004 | 一个镜头/语音失败 | Task 集合部分失败 | 查看错误→回跳准确 slot→只重试该位置 | 其他成功位置保持可用 | 用户无需重走整集流程 |
| US-UI-005 | 媒体授权过期 | Candidate/Delivery 事实仍存在 | 原位重新申请授权→继续预览/下载 | 不创建新媒体或 Delivery | 操作恢复且历史不变 |

## 3. 信息架构与阶段出口

| 工作区 | 必须展示 | 主要动作 |
| --- | --- | --- |
| Projects | 项目标题、单集、来源/故事/媒体/交付摘要 | 创建、打开 |
| Story | 当前来源、Script、Assets、Storyboard 版本与校验 | 生成、编辑、确认、派生 |
| Studio | 按 asset/shot/speech 分组的 Task、Candidate、Adoption | 生成、预览、采用、局部重试 |
| Tasks | Episode、位置、状态、阶段、错误、下一动作 | 取消、重试、回跳 |
| Delivery | 字幕状态、缺项、Render Task、质检、三件制品 | 编辑确认字幕、渲染、下载 |

## 4. 交互与状态规则

- AI 输出明确标记“提案/候选”；Task succeeded、Adoption active、Delivery ready 不使用同一个“完成”状态。
- 非终态 Task 有活跃订阅时每 2 秒查询；终态立即停止；短暂网络失败有限退避并可手动刷新。
- `unknown` 显示等待对账，`cancelling` 显示取消已请求；两者都不能伪装终态。
- ETag 冲突不自动覆盖，必须显示当前服务端版本和重新确认动作。
- 错误至少包含位置、阶段、稳定 code、retryable 和 next_action，不显示密钥、Prompt 或 Provider 原始响应。
- 未提交编辑可留在 Redux Slice；正式版本、Task、采用、交付和签名 URL 不持久化到浏览器。
- 关键交互可键盘操作，有可见焦点、ARIA label 和非干扰任务 live region。

## 5. 非目标

不提供 Zustand/TanStack Query 双状态、浏览器正式渲染、离线持久化、拖拽专业时间线、实时多人光标、全局 WebSocket 或隐藏管理员入口。

| ID | 可观察行为与阈值 | 事实源、样本/环境与门禁 |
