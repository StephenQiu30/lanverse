# PRD 15：健康

执行编号：15；来源需求模块：19。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 1. 概述

根据真实运行事实区分可用、降级与无法判断，定位生成风险。

本文件是本次进一步拆解的待评审稿，细化用户结果及交付切片，不替代[模块需求](../requirement/19-健康需求.md)中的业务规则。对应[模块Plan](../plan/15-健康.md)；整体顺序与Demo优先级见[执行顺序](../plan/00-执行顺序.md)。未接受的新规则不能作为实施合同。

## 2. 参与者

使用者：管理员。产品负责人确认范围与政策；工程负责人评审Design与可行性；测试负责人验证真实结果。实际承担者待落实，可一人兼任，不虚构姓名或已承诺产能。

## 3. 背景

固定失败阈值、样例积压和点击刷新变绿不能证明系统健康。

来源是当前模块规格及其第8节页面/源码定位；现有页面和旧后端仅作为现状线索，不能作为新业务合同或已验收证据。

## 4. 目标与完成尺度

根据真实运行事实区分可用、降级与无法判断，定位生成风险。

本轮成功以接受切片的验收逐条通过为准：用户结果可观察，持久结果可读回，异常/越权有证据，无mock成功。真实外部调用、浏览器和自动化证据分开记录。人员、周期与质量阈值未定，当前不填上线日期、故事点或商业KPI；实施前补测量环境和完成窗口。

## 5. 使用场景

- 作为管理员，我希望看到真实窗口与供应商结果，判断当前风险。
- 作为管理员，我希望刷新真实状态，局部查询失败时知道最后成功时间。
- 作为管理员，我希望打开授权配置或风险任务，入口不可用时有明确说明。

## 6. 价值与范围取舍

首轮要有任务故障原因与安全关联标识；完整健康页及监控入口随后接入实际部署事实。

不因页面出现队列/Worker/Outbox标签而要求新部署旧技术栈。 上述取舍只调整交付顺序，不删除[原始完整范围](../requirement/19-健康需求.md#2-范围与边界)，也不把后续能力标为已完成。

## 7. 解决方案与验收切片

### 用户流程与界面

现有入口和视觉定位见[模块来源](../requirement/19-健康需求.md#8-页面与实现来源)；共享交互遵循[交互需求](../requirement/05-界面与交互需求.md)及[视觉规范](../../DESIGN.md)。本轮不重新设计页面，也不把沿用的Figma链接视为本次核验。涉及画布图片/视频的规则在[Demo PRD](06-画布生图生视频Demo.md)统一维护。

### US-HEALTH-01：读取真实健康摘要

作为管理员，我希望看到真实窗口与供应商结果，判断当前风险。

范围追踪：FR-HEALTH-01～02，原始规则见[功能需求](../requirement/19-健康需求.md#3-功能性需求)。

1. 15分钟/1小时既有窗口可核。
2. 返回as_of/availability及样本口径。
3. 未部署/无指标与0分开。
4. 错误/摘要不含秘密。

### US-HEALTH-02：刷新但保留故障事实

作为管理员，我希望刷新真实状态，局部查询失败时知道最后成功时间。

范围追踪：FR-HEALTH-03，原始规则见[功能需求](../requirement/19-健康需求.md#3-功能性需求)。

1. 手动/30秒刷新读真实数据。
2. 未修复不变正常。
3. 局部失败保留时间及安全错误。
4. 刷新不发起收费或业务写入。

### US-HEALTH-03：跳转实际处理入口

作为管理员，我希望打开授权配置或风险任务，入口不可用时有明确说明。

范围追踪：FR-HEALTH-04，原始规则见[功能需求](../requirement/19-健康需求.md#3-功能性需求)。

1. 跳实际凭据/任务上下文。
2. 监控只读且来源已配置。
3. 缺链接显示不可用。
4. 普通用户与无权目标均拒绝。

### 依赖、假设与质量

- 必要依赖：14真实状态、09可用配置与实际运行指标；06管理员授权。
- 尚待决定：指标来源、分母、事件时间、过期时限、失败阈值、待人工告警及监控访问范围。
- 功能追踪以以上FR为准；完整质量条件及测试方法见[模块第4节](../requirement/19-健康需求.md#4-非功能性需求)，原始组合场景见[第5节](../requirement/19-健康需求.md#5-验收场景)。拆解不撤销安全、恢复、数据真实性和可访问要求。
- 性能/容量/恢复阈值及运行条件未确定的部分单列，不能报告为质量达标。
