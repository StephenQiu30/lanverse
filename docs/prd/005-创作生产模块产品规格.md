## 1. 模块组合结论

创作链不是一个“AI 生成模块”。scripts 把来源文本变成经人确认的结构；assets 固定跨镜头复用的创作要素；storyboards 把单镜头意图冻结为可执行规格；production 才负责把固定输入提交给外部能力并记录结果和费用。任何模块绕过上一模块的稳定版本，都会让刷新恢复、返工和成本追踪失真。

| 模块 | 用户结果 | 唯一事实 | 不能拥有 | 主切片 |
| --- | --- | --- | --- | --- |
| scripts | 导入剧本并确认可编辑的结构 | ScriptSource/Version、Scene、Dialogue、ExtractionBatch、Candidate/Decision | 资产定义、镜头规格、生成任务 | S2 |
| assets | 建立有来源和授权的可复用创作资产 | Asset、AssetVersion、MediaReference、ConsentReference、readiness | 媒体字节、授权决定、镜头引用 | S2/S3 |
| storyboards | 把叙事意图变成固定输入的可生成镜头 | Shot、ShotSpecVersion、AssetReference、ShotTransform、readiness | 供应商参数、生成结果、费用 | S3 |
| production | 可靠提交外部生成并选择可追踪候选 | ModelCapability、GenerationRequest、Task/Attempt、Candidate/Action、Reservation/CostEntry | 剧本/资产/镜头正文、媒体位置 | S4 |

## 2. scripts：剧本结构与人工决议

### 2.1 产品对象和用例

ScriptSource 记录上传、粘贴或外部导入来源；ScriptVersion 保存不可变正文和来源快照；Scene/Dialogue 是已确认结构；ExtractionBatch 表示一次异步提取；Candidate/Decision 保存机器建议与人工取舍，而不是覆盖原始版本。

| 用户动作 | 业务结果 | 关键规则 |
| --- | --- | --- |
| 创建来源、导入正文 | 建立 draft ScriptVersion | 文本上限 20,000 字；正文不进入日志和事件 |
| 编辑并发布 | 创建新 Version 并设置 current | 已发布版本不可改；比较更新 current，旧引用不漂移 |
| 启动结构提取 | 创建 Batch、Task、Outbox | 同 Version + 配置幂等；请求快速返回 task_id |
| 查看/决议候选 | 接受、拒绝、修改或合并候选 | Decision 只追加；重复提交不重复建 Scene/Dialogue |
| 确认结构 | 冻结可供下游读取的结构版本 | 必需候选已决议；未决议项和阻塞原因可见 |
| 删除草稿 | 删除无引用、无运行任务的未发布版本 | 发布版本、已产生费用或下游引用时只允许归档 |

提取允许重新运行，但每个 Batch 必须绑定固定 ScriptVersion、输入 hash，以及包含 DeepSeek `deepseek-v4-pro` 非思考模式、`langchain-deepseek==1.1.0`、prompt/schema 版本的提取器快照。提取结果必须经过 LangChain 结构化输出与 Pydantic 二次校验；失败或结果未知时，客户端通过 Task/Batch 状态恢复，不自行判断是否重发。未配置 `DEEPSEEK_API_KEY` 时明确返回能力不可用；S2 只实现当前文本提取需要的 `ChatDeepSeek` 适配，不使用 LangGraph 或通用 Provider 路由。S2 只建立文本提取所需的最小 Task/Outbox/Worker；Attempt 对账、费用和完整任务中心由 production 在 S4 扩展。

### 2.2 模块交接和验收

scripts 对外只发布已确认 Scene/Dialogue 引用、结构版本和影响摘要。创建或关联资产、生成初始 Shot 必须调用 assets/storyboards 的公开命令；scripts 不直接写其表，也不因 current ScriptVersion 变化而修改既有下游版本。

模块完成必须证明：重复导入/提取/决议幂等；并发发布和 current 比较更新不丢数据；Worker 中断后可恢复；必需候选未决议时不能确认；确认后 Scene/Dialogue 稳定可追溯；切换版本只产生影响清单；跨空间不可访问；旧版本始终可重放其结构。

## 3. assets：类型化创作资产

### 3.1 资产类型和成熟度

MVP 资产固定为角色、场景、道具、服装、声音和风格六类。Asset 是跨镜头逻辑身份；AssetVersion 是不可变规格；MediaReference 和 ConsentReference 只引用 media/governance 的稳定 ID。不同类型使用各自受约束字段，不能把核心信息塞入任意 JSON。

| 类型 | 最小规格重点 | ready 的额外门禁 |
| --- | --- | --- |
| 角色 | 名称、外观、身份、性格、连续性特征 | 真人/脸部参考授权和至少一份可用参考媒体 |
| 场景 | 时空、环境、光线、天气、连续性 | 参考媒体可用，地点/商标风险已处理 |
| 道具 | 外观、尺度、材质、用途 | 必需参考或文字规格完整 |
| 服装 | 款式、颜色、材质、穿着主体 | 与角色版本和连续性要求一致 |
| 声音 | 语言、音色、节奏、情绪、主体 | 声音授权有效，样本媒体可访问 |
| 风格 | 画面风格、色彩、镜头语言、负面约束 | 不包含具体供应商私有参数 |

### 3.2 操作、交接和验收

- 支持 Asset 创建/列表/详情/改名/归档/恢复，以及 AssetVersion 创建、比较、设为 current；删除只适用于无引用草稿。
- readiness 由类型字段、MediaVersion 可用性、Consent/RightsGate 和依赖状态确定，返回 blockers、warnings、next_actions；依赖不可用不能误报 ready。
- 反向使用查询列出哪些 ShotSpec 固定引用该版本；升级预检展示影响，用户确认后由 storyboards 创建新的 ShotSpecVersion。
- current AssetVersion 只影响新选择默认值，不自动改历史 ShotSpec、Candidate、Render 或 DeliveryManifest。
- media 管理文件事实，governance 管理许可，assets 只保存引用和创作规格；三个模块状态不能互相复制。

模块完成必须证明六类字段校验、版本不可变、current 并发冲突、readiness 确定性、授权撤销后阻断新生产、依赖故障可解释、反向引用完整、升级不改旧版本和跨空间隔离。仅有通用 Asset CRUD 或一列 JSON 不算完成。

## 4. storyboards：分镜与镜头规格

### 4.1 镜头事实和业务命令

Shot 表示 Episode 内可排序的镜头身份；ShotSpecVersion 固定某次生成所需的叙事、画面、动作、摄影机、声音、时长和连续性；AssetReference 必须指向具体 AssetVersion。供应商 model_id、私有参数和费用不进入 ShotSpec。

| 命令 | 前置 | 结果/限制 |
| --- | --- | --- |
| 从结构创建/手工新建 Shot | confirmed `kind=shot` Candidate 或明确手工幂等键 | 返回稳定 Shot；未确认/跨 Episode 来源拒绝；active 上限 120 |
| 保存规格 | expected current spec、ShotSpec v1 完整类型化输入 | 创建新 SpecVersion；固定 Script/Scene/Dialogue/AssetVersion；冲突返回最新版本 |
| 重排 | 同 Episode 完整 ID 集合、expected order_hash | 原子生成连续 position，不接受局部或陈旧猜测 |
| 复制 | 用户选择叙事/规格范围 | 不复制 Candidate、Task、费用、媒体和审核 |
| 拆分/合并 | 最新 impact_hash、完整目标 Spec | split 新建两个、merge 仅相邻两个合一；归档来源并写 ShotTransform，不迁移证据 |
| 升级资产引用 | 新版本 ready、expected Spec/preflight hash | 整批全有或全无地创建新 SpecVersion，不改旧引用 |

readiness 必须返回结构化 status/blockers/warnings/next_actions/evaluated_dependencies/evaluation_hash，覆盖 confirmed Script/Scene/Dialogue、字段、500～15,000 ms 时长、AssetVersion、声音、授权、参考媒体和依赖可用性。warning 只允许长镜头、动作密度和可选风格参考三类；依赖 unavailable 必须阻断。批量摘要只能聚合同一套服务端规则，前端不得复制判断。

### 4.2 模块交接和验收

storyboards 向 production 提供不可变 ShotSpecRef、输入摘要和 readiness 结果；production 只能为固定 SpecVersion 建请求。production 的候选、失败和费用不回写 ShotSpec，仅通过摘要查询展示。

模块完成必须证明：order_hash 重排并发和完整集合约束；规格乐观并发；变换幂等和只追加证据；readiness 对同一事实确定；依赖故障不误报 ready；资产/剧本变更只产生影响；拆分/合并不复制生产事实；跨空间隔离；36/120 镜头无 N+1，并按 PLAN-000 §7.5.1 分别达到 P95 ≤800 ms/2 s。

## 5. production：生成任务、候选与成本

### 5.1 事实和状态

ModelCapability 是供应商能力、参数约束和价格的版本化快照；GenerationRequest 固定 ShotSpec、输入版本和用户意图；Task/Attempt 记录平台任务与每次外部尝试；Candidate 保存不可变输出，CandidateAction 追加标记/选择事实；Reservation/CostEntry 形成可核对账本。

Task 状态固定为 `queued → running → waiting_provider → succeeded/failed/cancelled/unknown`，允许按明确恢复规则从 unknown 收敛。取消是请求而非保证；外部已产生的实际费用仍需结算。Candidate 被选择时必须比较其 ShotSpecVersion 与当前操作目标，过期候选不得静默覆盖。

### 5.2 用户用例与事务边界

1. 能力查询：只展示当前可用能力、限制、预计时长和价格版本；供应商枚举不散落前端。
2. 生成预检：校验固定 ShotSpec、readiness、RightsGate、媒体、能力参数、预算/额度和预计成本；纯读取，不预占费用。
3. 提交生成：高成本确认后，一个数据库事务写 Request、Task、Reservation/CostEntry 和 Outbox；稳定 idempotency key 返回同一 Task。
4. 执行与对账：Worker 领取 Task 后创建 Attempt；外部发送使用稳定 provider_request_key。发送结果不明进入 unknown，先查询/对账，确认不存在后才能再次发送。
5. 结果登记：一次事务登记 Candidate、MediaVersion/Lineage 引用、Task 终态和实际费用；供应商成功但下载失败只重试下载。
6. 选择候选：原子设置选择事实并保留未选候选；批量生成逐 Shot 独立收敛，局部失败不回滚其他成功。

### 5.3 模块交接和验收

production 读取 storyboards/governance/media 的公开快照，使用 Outbox 通知 RabbitMQ；当前实际 AI 服务只包含 LangChain DeepSeek 文本提取和方舟图片/视频生成，AI 语音/音效生成不在 MVP 内。S4 公开候选固定为 `doubao-seedream-5-0-lite-260128`/`doubao-seedance-2-0-260128`、`cn-beijing` 和 `volcengine-python-sdk[ark]==5.0.43`，但只有 D-004 通过真实账号契约后才引入这一套 SDK 和唯一 ArkMediaAdapter；不并存手写 HTTP、`openai` 运行时与第二 SDK。production 把结果交给 media 登记，不能保存 object key、修改 ShotSpec 或替代审核决定；projects/editing 只读 Task、Candidate 和费用摘要。

模块完成必须证明：预检无副作用；提交幂等且事务原子；重复消息/回调只结算一次；消费者重启安全；已有 Seedance task ID 时用原 ID 对账，无 task ID 或 Seedream 同步结果丢失时进入人工处理而不盲重发；取消竞态正确；费用满足 `reserved + adjustments = settled + released + remaining_reserved` 且终态余量归零；候选与媒体血缘完整；能力/价格快照可追溯；真实默认 Image/Video Provider 契约及各自端到端生成通过，fake 不能替代。

## 6. 创作生产联合验收

固定场景为：导入并发布剧本 → 异步提取并人工决议 → 建立六类中验收所需的角色/场景/声音资产 → 固定版本形成 ready ShotSpec → 预检并提交生成 → 中途刷新和重启 Worker → 对账或恢复 → 登记多个候选和成本 → 选择一个候选。最终必须从 Candidate 反查到 Attempt、Task、GenerationRequest、ShotSpecVersion、AssetVersion、ScriptVersion、MediaVersion/Lineage 和 CostEntry；任一环节只能靠日志猜测即判失败。
