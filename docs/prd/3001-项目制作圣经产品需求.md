## 产品结论

项目制作圣经（Production Bible）是完整剧本进入分集、资产和分镜生产前的项目级事实来源。
它必须把同一角色、地点、道具、服装、声音、视觉风格和世界观统一成可审阅、可修订、
可追溯的项目身份与阶段状态，避免逐集分析重复创建资产或让同一身份在不同镜头中漂移。

本主题的完成对象不是一次模型调用或一份不可查询的提示词，而是：

```text
固定完整原稿
→ 项目级 Bible 候选
→ 阻断问题审阅与正式修订
→ 唯一资产/状态原子物化
→ 分集冻结同一 Bible snapshot
→ occurrence 锚定
→ 分镜自动消费相关资产与世界观
```

## 目标用户与核心任务

| 用户 | 核心任务 | 期望结果 |
|---|---|---|
| 创作者 / 制片人 | 导入完整剧本并判断是否可以进入生产 | 看见运行状态、问题和可确认的项目制作圣经 |
| 剧本统筹 / 连续性负责人 | 合并别名、区分身份与阶段状态、处理世界观冲突 | 所有决定有原文证据，修订后可以继续确认 |
| 资产管理员 | 复用项目资产或创建新的唯一资产 | 一个故事身份只对应一个 Asset，不产生静默重复 |
| 分镜师 / 导演 | 基于目标剧集实际出现的身份和状态制作分镜 | 无需手工重新选择全项目资产，镜头引用可反查原文 |
| 运行维护者 | 处理长时间运行、服务重启和重复投递 | 从最近有效 checkpoint 恢复，不重复正式写入 |

## 用户问题

逐集独立理解会把称谓、别名、服装、伤势、年龄阶段或阵营变化误判成不同身份，也可能把
同名但不同的主体错误合并。结果是资产重复、镜头状态选择错误、世界规则前后矛盾，且人工
无法从最终分镜反查判断依据。

用户需要一个在分集之前完成的项目级审阅门：模型只提出候选，系统保留证据并执行确定性
门禁，用户通过正式业务命令消除阻断问题，确认后才把结果传播到下游。

## 产品范围

### 完整原稿理解

- 对一个不可变 document revision 执行整剧理解，不把每集或每场景当成彼此独立的项目事实。
- 提取带绝对来源区间的身份、状态、世界观事实和规则。
- 合并别名和跨集描述，同时保留无法安全判断的歧义。
- 把稳定身份与服装、伤势、年龄、伪装、阵营等阶段性变化分开。

### 审阅与确认

- 用户可查看实体、状态、世界观、证据和 blocking/warning issue。
- 每一种会阻止确认的问题都必须有对应的正式修订或链接命令，不能依靠直接改库绕过。
- 确认必须带 expected revision、expected result hash 和幂等键。
- 确认事务要么完整物化资产、状态、版本和审计事实，要么全部回滚。

### 下游传播

- 导入发布前必须确认同一原稿 revision 的 Bible。
- 同一导入批次的全部分集冻结同一个 Bible id、revision 和 result hash。
- 分集抽取只创建场景、对白和引用 Bible entity/state 的 occurrence。
- 分镜只消费目标剧集 occurrence 关联的资产状态与相关世界观，不注入无关的全项目资产。
- 新原稿形成新 Bible 时，系统要标记旧版本并说明对已发布结构、资产和分镜的影响。

### 运行可靠性

- 长运行可持续数小时，不把 lease 或 heartbeat 时长当成业务超时。
- 服务重启、Worker 失联和不确定 Provider 结果不得产生伪成功或重复正式数据。
- 用户可以显式取消仍在运行的任务；旧 run token 在失去所有权后不能再保存或提交。

## 关键用户旅程

1. 用户固定完整原稿，系统保存 document revision 与内容哈希。
2. 用户发起 Bible 生成并持续查看 `queued/running` 状态。
3. 系统完成证据提取、跨段统一和独立复核，返回 `needs_review` 候选。
4. 用户逐项处理阻断问题，包括状态边界、身份合并/拆分、世界观修订和项目资产链接。
5. 用户确认 Bible；系统原子物化唯一资产、状态和版本。
6. 用户发布导入批次；所有分集与抽取批次冻结同一 Bible snapshot。
7. 结构确认将 occurrence 锚定到正式叙事单元版本。
8. 分镜从 occurrence 自动选择资产状态和世界观，最终结果可反查 Bible 与原文证据。
9. 原稿更新时，用户先审阅新 Bible 及影响，再决定是否传播到下游。

## 主题交付门

只有同时满足以下条件，才能宣称“项目制作圣经闭环可用”：

- 一个真实完整原稿可以从固定 revision 生成可审阅 Bible。
- 所有 blocking issue 都可以通过公开业务命令闭环并留下审计证据。
- 同一身份只物化一个 Asset，阶段变化只物化为其 AssetState/AssetVersion。
- 发布的所有分集冻结同一 Bible snapshot，重复请求不产生重复资产或 occurrence。
- 分镜无需调用方手工传入 Bible 资产，并可从镜头反查 occurrence、状态和原文。
- 中断运行可恢复，显式取消和 fencing 不允许旧 Worker 写入。
- 真实 60 集验收矩阵完整通过。

以上交付门属于平台 [Guided MVP](0001-产品范围与验收基线.md) 的剧本到分镜前置能力，
不代表图片、视频、声音、合成或完整平台已经验收。

## 成功判定

- 基准原稿中的同一故事身份重复资产数为 `0`。
- 每个正式实体、状态和世界观条目都至少有一条可验证原文证据。
- 同一发布批次引用不同 Bible snapshot 的 ExtractionBatch 数为 `0`。
- blocking issue 未清零时成功确认次数为 `0`。
- 幂等重放新增的 Asset、AssetState、AssetVersion 或 occurrence 数为 `0`。
- 60 集机器覆盖统计完整；代表集人工细查不能替代全量统计。

## 非目标

- 不在本主题生成人物三视图、场景图、道具图、视频或声音。
- 不把全部世界观压缩成一个不可查询的提示词文件。
- 不允许模型直接写正式资产、结构或分镜。
- 不建立外部 Skill 仓库、运行时 checkout 或万能 Agent 平台。
- 不以固定执行时长、模型调用次数或少量样本代替业务效果验收。

## 约束与风险

- 长篇模型输出具有非确定性，必须依靠证据、严格 schema、Tool Gate 和人工确认共同控制。
- 同名、称谓、双胞胎、伪装和跨时间线身份可能无法自动消歧，产品必须允许安全停下。
- 如果阻断问题没有公开修订命令，用户旅程会在 `needs_review` 死锁；不得把直接改库视为替代方案。
- 60 集原稿与独立人工基线属于验收输入，缺失时只能报告阶段能力，不能报告完整闭环。
