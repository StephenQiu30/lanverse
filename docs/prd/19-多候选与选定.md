规则与验收以 [REQ-22](../requirement/22-多候选与选定.md) 为准，以下为产品摘要。

## 1. 问题与价值

模型常给出多个质量不一的图片、视频或音频结果，制作者需要并排比较并明确哪个结果正式用于下游；改选时也要知道影响范围。候选对比和带历史的选定动作让选择可复查。对应 PRD-01 §2 的**可控性、一致性**，服务 S2 的选片与 S4 的单镜重拍；选定后下游变化需按 P32 所述影响处理。

## 2. 目标用户与场景

- 比较多个视频、图片或音频候选。
- 改选前查看下游影响。
- 两处同时改选时处理冲突。

## 3. 范围

- **做（MVP）**：候选数量设置、候选展示与对比播放、选定 / 改选、选定历史、冲突处理。适用对象：参考槽位（REQ-15）、关键帧（REQ-26）、片段（REQ-27、REQ-28）、台词音频（REQ-29）。
- **不做**：各类候选的生成由对应功能负责；V2 见 REQ-34。

## 4. 用户体验与流程

1. 在镜头、参考槽位或配音页打开候选对比，查看图片/视频/音频候选和当前“已选定”标记；视频可同步播放和逐帧比较。
2. 选择审核通过且任务完成的候选，页面和故事板更新正式结果并保留选定历史。
3. 改选时先查看下游影响数量，确认后相关下游标记过期；基于旧镜头版本的候选显示版本来源。
4. 审核中候选显示“审核中”且不可选；审核拒绝显示原因占位；代理视频未就绪时显示处理中；另一页面已改选时提示内容已变更并刷新后重试。

## 5. 产品规则

- 候选数量至少为 1，最多受模型能力限制；超过单次上限时分次生成并按总数报价。（REQ-22 R1）
- 只有审核通过且任务完成的候选可选定。（REQ-22 R2）
- 并发改选发生冲突时提示刷新，避免覆盖他人的新选择。（REQ-22 R3）
- 未选中的候选永久保留（受 DES-02 §9 存储策略约束）；可随时改选（REQ-22 R4）
- 选定历史可查。（REQ-22 R5）
- 改选会使下游过期（关键帧 → 视频；片段 → 引用它的后续镜头，REQ-39），改选前提示影响数量（REQ-22 R6）
- 基于镜头旧版本生成的候选可以选定，但显示“基于 v3 生成（当前 v5）”并保留过期标记（REQ-22 R7）
- 选定是业务确认，不能撤销，只能改选（REQ-22 R8）

## 6. 成功标准

- Given 4 个视频候选，When 选定第 3 个，Then 镜头的选定视频指向候选 3；刷新后不变；另一个浏览器中基于旧版本改选时提示“内容已被修改”。（[TST-02](../test/02-需求追踪矩阵.md) TC-22-01）
- Given 3 个视频候选，When 并排播放并选定其中一个，Then 镜头详情与故事板封面显示该片段为已选定，镜头进度变为“已选定”。（[TST-02](../test/02-需求追踪矩阵.md) TC-22-02）
- Given 一个审核未通过的候选，When 尝试选定，Then 被拒绝。（[TST-02](../test/02-需求追踪矩阵.md) TC-22-03）

以上为 [REQ-22](../requirement/22-多候选与选定.md) §3 的 TC-22-01～03；关联质量要求见 [REQ-02](../requirement/02-非功能需求规格.md) DES-25 §8 对比播放要求。跟踪 PRD-01 §10 的镜头一次通过率与平均每镜重拍次数；播放体验按 DES-25 §8 验证。

## 7. 依赖与风险

- **依赖**：[PRD-18](18-报价与二次确认.md)、[PRD-28](28-依赖传播与影响清单.md)。
- **风险**：代理媒体未就绪、审核变化和并发改选。

## 8. 待确认

已决定：审核未通过的候选不能选定（REQ-22 R2、DES-25-Q2）。代理生成时机属 DES-25-Q1 技术细节；无其他产品待确认项。
