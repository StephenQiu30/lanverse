## 规格化结构

每份模块 PRD 必须依次包含：

1. 输入、状态、产品问题、用户价值、范围与非目标。
2. 用户故事；每条包含用户、触发、前置、主流程、失败/恢复和完成定义。
3. 业务规则、状态/数据边界以及用户可见错误和下一动作。
4. SMART 验收；每条 `AC-PRD-*` 包含可观察行为、量化阈值、事实源、样本/环境、排除和最迟门禁。
5. Requirement→Design→Plan/Test→Evidence 双向追踪。

## 唯一解释规则

- 产品范围由 PRODUCT-01～07 正向清单穷尽；未被活动 Requirement/Design 接受的能力不得进入 PRD。
- `AC-PRD-001～010` 编号稳定且恰有一份 owning PRD；模块拆分不改变既有验收语义。
- PRD 描述“用户为什么需要、看到什么、什么算完成”，实现结构与事务细节只引用 Design。
- 真实运行结果不能写入 PRD，只能在接受的 Plan 实施后进入 ACCEPTANCE-01。
- 任一 P0 决策未关闭、用户故事字段缺失、验收不可测或追踪断裂时，相关 PRD 不得转为 `accepted`。
