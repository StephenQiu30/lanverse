# 领域语言与模块命名规范

- 目标状态：已接受
- 落地状态：命名基线已建立，代码迁移尚未开始
- 适用范围：文档、Frontend feature、Go Backend、Python Agent、API、事件、数据库与可观测字段
- 决策依据：[ADR-0002](../adr/0002-采用中文语义化文档与模块命名.md)

## 结论

Lanverse 的名称必须表达业务能力或运行职责，不能只表达技术形态。产品入口使用 Guided/Canvas，业务事实统一使用 Authoring；模型供应商调用统一使用 Generation；后端生产域使用 Production，不能继续把 UI 概念 `studio` 当作领域边界。

同一个概念只有一个规范名。历史名称只出现在迁移映射中，不建立别名 DTO、兼容 package 或重复数据库模型。

## 文档文件命名

文档文件名直接使用中文语义短语，使读者无需打开文件即可判断用途。新增目标文档不添加 `Lanverse`、`V1` 等项目名或版本前缀；只有去除后会改变含义的技术专有名词才保留，例如“本地 Codex 分镜智能体”。语义段之间使用连字符：

```text
docs/prd/产品范围与验收基线.md
docs/architecture/系统总体架构.md
docs/architecture/前端应用架构.md
docs/architecture/后端服务架构.md
docs/architecture/领域语言与模块命名规范.md
docs/designs/后端领域模块功能设计.md
docs/designs/前端功能模块设计.md
docs/plans/平台迁移与服务整合计划.md
docs/adr/0002-采用中文语义化文档与模块命名.md
```

规则如下：

1. 文件名直接采用 `业务主题-文档用途.md`，若主题本身已经包含用途则不重复堆词；禁止为了统一外观添加项目名或版本前缀。
2. 文档用途必须明确，例如“范围与验收基线”“系统总体架构”“模块功能设计”“实施计划”“需求规格”“验收记录”。
3. ADR 使用四位编号和中文决策短语，例如 `0002-采用中文语义化文档与模块命名.md`。
4. 不把日期、状态、`最终版`、`最新版`、`新文档`、`其他`、`杂项`、`相关说明` 写入文件名。
5. 权威设计基线同样按用途命名，例如 `AI短剧制作平台完整设计基线.md`；精确来源标题、版本与 Hash 写在正文元数据和导航中，不塞进日常文件名前缀。若未来必须并存多个不可变版本，先通过 ADR 约定归档目录或消歧规则，禁止直接覆盖同名基线。
6. `README.md` 作为目录入口保留行业惯例；`designs/plans/requirements/acceptance` 等既有分类目录保持稳定，不另建中文同义目录。
7. 文档标题与文件名使用同一中文主题；代码标识符、协议字段和代码路径仍使用规范英文名。

## 名称层级

同一能力可以有不同展示层，但语义必须可追溯：

| 层级 | 示例 | 规则 |
|---|---|---|
| 文档文件名 | `后端领域模块功能设计.md` | 中文主题直接说明使用目的 |
| 产品显示名 | 引导式制作、画布创作、审核工作台 | 面向用户任务，可本地化 |
| 业务能力名 | Guided Production、Authoring、Review | 用于设计和边界讨论 |
| 代码模块名 | `production`、`authoring`、`review` | 单数、稳定、无技术后缀 |
| 运行单元名 | `workflow-worker`、`model-gateway` | 表达部署职责，可包含 worker/gateway |
| 协议标识 | `PublishAuthoringRevision` | Command 使用动词，类型使用名词 |
| 存储标识 | `authoring_revision` | snake_case，不泄漏框架名称 |

UI 名称不能反向决定领域名。例如 Canvas 是一种编辑体验，不产生 `CanvasRevision`；规范业务对象始终是 `AuthoringRevision`，来源用 `authoring_mode=CANVAS` 记录。

## 规范模块目录

目标 Go Module 使用以下业务边界；`bootstrap`、`config`、`database`、`cache` 与 `telemetry` 是装配/基础设施，不是业务领域：

```text
backend/internal/
├── bootstrap/
├── access/
├── production/
├── preset/
├── authoring/
├── workflow/
├── review/
├── generation/
├── agent/
├── asset/
├── media/
├── cost/
├── quota/
├── eventing/
├── search/
├── config/
├── database/
├── cache/
└── telemetry/
```

| 业务能力 | 规范 package | 拥有的事实 | 取代或吸收的含糊名称 |
|---|---|---|---|
| Access & Membership | `access` | 身份、Session、Workspace Membership、Role/Access Capability | `identity`、认证散落逻辑 |
| Production Management | `production` | Workspace、Project、Episode、Scene、Shot、Script、Production Bible | Backend `studio`、`projects`、部分 `scripts/storyboards` |
| Production Preset | `preset` | Preset/Style/Policy 版本与 Effective Snapshot | 分散的 style/model/qc/render 配置 |
| Authoring | `authoring` | Draft、Revision、Node Catalog、GraphPatch、Graph Validation | Backend `canvas` |
| Workflow Execution | `workflow` | Compiler、Compilation Receipt、Definition Version、Run、Node Run、Temporal 协调和 Cache | 泛化 `task`、`scheduling` |
| Review | `review` | Human Task、Review Decision、审核历史 | 分散的 candidate/draft decision |
| Generation Gateway | `generation` | Generation Request、Provider Job、Candidate、Generation Capability、Routing | Backend `model`、部分 `production` |
| Agent Orchestration | `agent` | Agent/Skill/Prompt 版本引用、Invocation、Budget、Tool Policy | 进程内 harness 调用逻辑 |
| Asset Registry | `asset` | Asset、Asset Version、Artifact、Lineage、Storage Location、Rights/Consent | `file`、`media_asset`、孤立 URL 字段、分散 governance consent |
| Media Processing | `media` | Probe、Derivative、Render Manifest、Render/Export Job | 泛化 `processor`、`media task` |
| Cost Control | `cost` | Price、Estimate、Reservation、Ledger、Budget | 分散的费用预留与结算逻辑 |
| Quota Control | `quota` | Quota Policy、Usage Window、Usage Counter、Decision | 分散的限额与高成本保护逻辑 |
| Event Delivery | `eventing` | Outbox、Inbox、Envelope、DLQ、Replay、Projection Checkpoint、Audit Projection | Backend `event`、技术 Topic 调度、同步散落 Audit Writer |
| Search Projection | `search` | Search Document、Index Version、Reindex Job | 泛化查询工具 |
| Platform Runtime | `config/database/cache/telemetry` | 配置、持久化适配、Cache、Telemetry、Health | 逻辑归类，不合并设计基线中的物理 package |
| Composition Root | `bootstrap` | 各 Binary 的装配和生命周期 | 含糊的 `app` |

迁移文档可以保留旧名称作为来源列；新设计、契约和新代码只使用规范名。尚未创建的目标 package 不需要兼容旧目标名。

## 前端功能模块

Frontend feature 按用户任务命名，不能按页面框架或通用技术命名：

```text
frontend/apps/web/src/features/
├── account-access/
├── workspace-shell/
├── project-shell/
├── guided-production/
├── authoring-canvas/
├── review-workbench/
├── asset-library/
├── run-observability/
├── ai-copilot/
└── workspace-governance/
```

共享 package 保留最新设计已经接受的短名称，但必须通过语义 subpath 暴露能力：

```text
@lanverse/ui/primitives
@lanverse/ui/feedback
@lanverse/ai/stream
@lanverse/ai/tool-approval
@lanverse/canvas/graph-patch
@lanverse/canvas/run-overlay
@lanverse/sdk/rest
@lanverse/sdk/query
@lanverse/sdk/stream
@lanverse/auth/session
@lanverse/auth/capabilities
```

`ui`、`ai`、`canvas`、`sdk`、`auth` 是已接受的 package 边界，不再二次创建 `design-system`、`api-client` 等别名 package。业务语义由 feature 和 subpath 提供。

禁止 feature/package 名称：`common`、`shared`、`misc`、`utils`、`services`、`manager`、`store`、`helpers`、`studio`。若代码只有一个消费者，先保留在该 feature 内，不为“可能复用”抽包。

## 核心领域对象

| 规范名 | 含义 | 不再使用 |
|---|---|---|
| `Project` | 一部短剧项目及其生产边界 | 含糊的 `Job`、`Work` |
| `AccountEntitlement` | 不依赖 Workspace Membership 的账户级资格，例如创建 Workspace | 把 `workspace:create` 塞入不存在的 Membership |
| `AccessCapabilityDefinition` | Access 发布的用户动作权限定义 | 含糊的 `Capability`、模型能力 |
| `GenerationCapabilityDefinition` | Generation 发布的模型/Provider 能力定义 | Access 权限、UI Feature Flag |
| `Episode` | 项目中的集 | `Chapter`（除非产品另有章节概念） |
| `Scene` | 剧本/时间空间连续场景 | `Location`；Location 是可复用地点身份 |
| `Shot` | 可独立生产和重跑的镜头 | `Clip`；Clip 只用于媒体时间片 |
| `ScriptVersion` | 不可变剧本版本 | 原地更新的 `Script` 文本 |
| `ProductionBibleVersion` | Story/Character/Location 等生产约束快照 | 未版本化 `Bible` |
| `PresetVersion` | 一组可发布的创作策略引用 | 运行时可变 `Preset` 配置 |
| `EffectiveStyleSnapshot` | 解析 Shot/Project/Preset/Default 后的不可变画风快照 | 运行时可变 Style map |
| `EffectivePolicySnapshot` | 包含 EffectiveStyleSnapshot、Skill/Prompt/Model/QC/Motion/Render 版本的不可变策略集合 | 运行时重复解析的配置 map |
| `AuthoringDraft` | Guided/Canvas 共用的可变编辑态 | `CanvasDraft` |
| `AuthoringRevision` | 发布后的不可变创作快照 | `CanvasRevision` |
| `WorkflowDefinitionVersion` | Compiler 输出的不可变执行定义 | 泛化 `DAG` JSON |
| `WorkflowRun` | Definition 的一次执行 | `Task` |
| `NodeRun` | Workflow 节点的一次执行 | `Job`（Provider Job 除外） |
| `GenerationSubmissionIntent` | Cost/Quota 准备事务中持久化、供跨 Binary 提交与 Claim 对账的逻辑生成意图 | `GenerationRequest`、Outbox 中的短时 Token |
| `GenerationRequest` | Execution Claim 成功后由 Model Gateway 建立的规范生成请求 | 提交前的预算/工作流意图、`ModelTask` |
| `ProviderJob` | Provider 侧异步任务 | `GenerationRequest` 的别名 |
| `GenerationCandidate` | 可被 QC/人工选择的结果候选 | 直接覆盖当前结果的 URL |
| `CandidateSelection` | Generation 对唯一选择槽位固化的候选绑定 | Review 模块中的第二个 `selected` 标记 |
| `Asset` | 可复用的创作身份 | `Artifact` |
| `AssetVersion` | Asset 的不可变已发布版本 | 禁止把 `AssetState` 当作版本；State 单独表示剧情阶段 |
| `Artifact` | 一次执行产生的不可变文件或结构化输出 | `Asset`、`MediaFile` 混用 |
| `ArtifactReadiness` | Artifact 内容身份之外的校验、隔离、可用与保留状态 | `AssetState`、含糊的 `available` 布尔值 |
| `RenderManifestVersion` | 固定画布、轨道、输入 Artifact 与输出配置的不可变合成规格 | 当前 ZIP 包使用的 `StoryboardExportManifest` |
| `QualityGateResult` | Workflow 按冻结 QC Policy 对技术/语义报告作出的唯一门禁结果 | Media/Agent 各自保存的最终通过标记 |
| `HumanTask` | 等待、领取、过期和终止的人工任务 | `ReviewTask`、用 Decision 记录领取状态 |
| `ReviewDecision` | 对精确对象版本的不可变人工决议 | 可覆盖的 review status |
| `ExecutionAuthorization` | Worker 在线原子领取 Execution Claim 后，由 Intent Claim Version 与 Cost/Quota Reservation 派生签名、且不独立持久化的限范围授权 | 在 Outbox 预生成 Token、第三套授权状态表、先执行后补账、Redis 限流结果 |
| `CostReservation` | 高成本操作执行前的预算预留 | Redis 中的最终余额 |
| `CostLedgerEntry` | 不可变费用账本条目 | 可原地修改的 cost total |
| `QuotaReservation` | 高成本操作执行前的使用量预留 | Cost Reservation、Redis Counter |

## Command、Query 与 Event

### Command

Command 使用祈使动词 + 业务对象，表达一个原子意图：

```text
CreateProject
ImportScript
PublishAuthoringRevision
StartWorkflowRun
ApplyCandidateSelection
RecordReviewDecision
ReserveCostBudget
```

外部可重试 Command 必须携带 `idempotency_key`；修改并发聚合时携带 `expected_revision`。禁止 `HandleData`、`ProcessItem`、`UpdateStatus` 等无法说明业务效果的名称。

### Query

Query 的动词必须说明只读计算类型：单对象使用 `Get`，集合使用 `List`，全文检索使用 `Search/Suggest`，版本解析使用 `Resolve`，差异使用 `Diff`，只读校验使用 `Validate`，诊断说明使用 `Explain`：

```text
GetAuthoringRevision
ListHumanTasks
SearchArtifacts
ResolveEffectivePolicy
DiffAuthoringRevisions
ValidateAuthoringGraph
ExplainWorkflowFailure
```

Query 不产生业务副作用；`Validate` 只返回临时报告，若要保存报告必须改为 Command。Query 不使用 `Create`、`Ensure`、`GetOrCreate`。

### Domain Event

Event 使用 `<context>.<aggregate>.<past-tense>.vN`，描述已经提交的事实：

```text
production.project.created.v1
authoring.revision.published.v1
workflow.run.started.v1
generation.candidate.created.v1
review.decision.recorded.v1
asset.artifact.registered.v1
cost.reservation.settled.v1
```

Event 名称不能使用命令语气、UI 动作或 Provider 名称。破坏性 payload 变化发布新版本，不原地改变旧 Schema。

## 状态与失败语义

状态只描述一个聚合自身，不把其他系统的推测写成本地成功：

- Workflow Run：`DRAFT / RUNNING / PAUSED / WAITING / SUCCEEDED / FAILED / CANCELLED`。
- Node Run：`READY / QUEUED / RUNNING / WAITING_PROVIDER / WAITING_HUMAN / SUCCEEDED / FAILED / CACHED / CANCELLED / STALE`。
- Provider Job 必须保留 `UNKNOWN`，不能把回调丢失当作 `FAILED`。
- Human Task：`WAITING / CLAIMED / RESOLVED / CANCELLED / STALE`。
- Artifact Readiness：`PENDING_VALIDATION / READY / QUARANTINED / UNAVAILABLE / TOMBSTONED`。
- Media Job：`QUEUED / RUNNING / SUCCEEDED / FAILED / CANCELLED / UNKNOWN`。
- Generation Submission Intent：`PENDING / EXECUTION_CLAIMED / CANCEL_REQUESTED / ACCEPTED / REJECTED / CANCELLED / OUTCOME_UNKNOWN`。
- Cost Reservation：`RESERVED / EXECUTION_CLAIMED / SETTLED / RELEASED / EXPIRED / RECONCILING`。
- Quota Reservation：`RESERVED / EXECUTION_CLAIMED / CONSUMED / RELEASED / EXPIRED / RECONCILING`。

统一错误码使用稳定 snake_case：

```text
unauthenticated
forbidden
not_found
validation_failed
state_conflict
version_conflict
dependency_unavailable
rate_limited
budget_exceeded
outcome_unknown
manual_attention_required
```

错误消息用于用户阅读，错误码用于客户端分支；客户端不得解析中文或英文消息判断状态。

## API、数据库与可观测字段

- REST 资源使用复数名词：`/projects`、`/authoring-revisions`、`/workflow-runs`、`/human-tasks`。
- OpenAPI `operationId` 使用规范 Command/Query 名称，生成 SDK 不重新命名 DTO。
- ID 字段使用 `<entity>_id`；版本使用 `<entity>_revision` 或明确的 `<entity>_version_id`，不使用含糊 `version`。
- PostgreSQL 新对象使用 snake_case 业务名，不在表名中出现 `sqlalchemy`、`temporal`、Provider 名或 UI 路由名。
- Trace/Log 使用统一关联字段：`workspace_id`、`project_id`、`episode_id`、`shot_id`、`authoring_revision_id`、`workflow_run_id`、`node_run_id`、`generation_request_id`、`artifact_id`。
- 已存在的物理表/API/Event 通过迁移映射保持兼容，不为追求命名统一直接重命名生产对象。

## 执行约束

1. 新模块创建前必须有首个真实用例、Owner、契约和测试，不创建空目录。
2. Architecture Test 禁止新代码导入旧目标名 `studio/canvas/model/event/app`；迁移适配器目录可临时例外并必须登记删除门禁。
3. API/事件/生成 SDK 增加命名漂移检查，禁止同义 DTO。
4. Code Review 遇到新名词时先更新本文或对应模块设计，再写实现。
5. 现有 FastAPI 代码名称不在本轮批量重命名；它们按 [平台迁移与服务整合计划](../plans/平台迁移与服务整合计划.md) 随写入所有权切换退出。
