# REQ-004 媒体模块需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`002-用户与空间模块需求.md`
- 输出：媒体上传、版本、私有访问、探测、血缘、存储迁移和清理需求
- 下游：REQ-007、REQ-009、REQ-010、REQ-013

## 1. 需求概述

媒体模块必须统一管理用户上传和模型/渲染产生的图片、视频、音频、字幕及交付文件。数据库只保存业务元数据和对象引用，媒体字节进入对象存储；其他模块只能引用稳定 MediaVersion ID。

媒体模块不理解 Character、Shot 或 Timeline 的业务规则，也不通过可变 URL 充当跨模块事实。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| MED-ENT-001 | MediaObject | 表示同一逻辑媒体身份，保存 Workspace、媒体类型、来源和生命周期状态。 |
| MED-ENT-002 | MediaVersion | 表示不可变文件版本，保存 hash、MIME、大小、尺寸/时长、格式和创建来源。 |
| MED-ENT-003 | Lineage | 保存输入 MediaVersion、输出 MediaVersion、产生它的 Task/Render 和转换类型；不得形成无法解释的孤立输出。 |
| MED-ENT-004 | UploadSession | 表示一次受控上传意图、限制、过期时间和完成状态；不是长期业务资产。 |
| MED-ENT-005 | MediaLocation | 表示 MediaVersion 在某个 StorageProfile 的物理位置与验证状态；迁移可追加新位置，不改 MediaVersion 内容。 |

object key、内部桶信息和预签名 URL 不得替代 MediaVersion ID 暴露给业务模块。预签名 URL 是短期访问结果，不是持久字段。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| MED-FR-001 | editor/owner 必须能为允许的媒体类型初始化上传，并获得受限上传信息和 UploadSession。 |
| MED-FR-002 | 完成上传时必须验证对象存在、大小、类型和 hash，并为合法对象创建 MediaObject/MediaVersion。 |
| MED-FR-003 | 系统必须探测图片尺寸、视频/音频时长、编码和容器等必要元数据；探测失败必须给出可处理状态。 |
| MED-FR-004 | 用户必须能按类型、来源、时间和业务引用列表/读取有权访问的媒体元数据。 |
| MED-FR-005 | 授权用户必须能获取短期上传/下载/预览访问能力；对象默认不得公开。 |
| MED-FR-006 | 替换文件必须创建新 MediaVersion；不得覆盖既有版本的字节、hash 或探测结果。 |
| MED-FR-007 | 模型、转码和渲染输出必须记录 Lineage，并能从输出反查输入和产生任务。 |
| MED-FR-008 | 无引用且过期的临时上传可以清理；被版本、审核、血缘或交付引用的媒体只能归档。 |
| MED-FR-009 | 系统必须支持在不改变 MediaVersion ID、hash 和权限契约的前提下迁移存储位置，且在校验完成前保留原存储可读。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| MED-IF-001 | 初始化上传 | ActorContext、媒体类型、文件名、声明大小/MIME/hash | UploadSession 与受限上传信息；类型或大小不允许时拒绝 |
| MED-IF-002 | 完成上传 | UploadSession ID、对象确认信息 | MediaVersion；对象缺失、过期或校验不一致时失败 |
| MED-IF-003 | 列表/详情 | ActorContext、筛选、分页、MediaVersion ID | 元数据、可用状态和血缘摘要，不返回永久公开 URL |
| MED-IF-004 | 获取访问能力 | MediaVersion ID、用途 | 短期访问结果；归档、隔离或无权访问时拒绝 |
| MED-IF-005 | 登记生成/转换输出 | Task/Render ID、输入版本、输出对象、转换类型 | 新 MediaVersion 与 Lineage；重复登记必须幂等 |
| MED-IF-006 | 新建版本 | MediaObject ID、已验证上传/输出 | 新版本；原版本保持不变 |
| MED-IF-007 | 归档/清理 | MediaObject/UploadSession ID、原因 | 归档结果或引用阻塞；清理仅允许临时无引用对象 |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| MED-NFR-001 | 安全 | 对象必须默认私有；访问能力必须短期、限用途、限对象且不可跨 Workspace。 |
| MED-NFR-002 | 完整性 | MediaVersion 的 hash 和大小一经确认不得改变；MediaLocation 只经校验迁移流程变更 active 状态，下载或渲染前可验证完整性。 |
| MED-NFR-003 | 一致性 | 上传完成、版本登记和业务引用必须处理数据库成功但对象缺失以及对象存在但数据库失败两类情况。 |
| MED-NFR-004 | 可恢复 | 探测/转码失败必须保留原始对象和错误信息，允许在不重复上传的情况下安全重试。 |
| MED-NFR-005 | 可追溯 | 每个生成或转换输出必须关联 Task/Render、输入版本和工具/供应商信息。 |
| MED-NFR-006 | 性能 | 大文件字节不得经过 FastAPI 进程中转；上传大小、并发、访问时效和探测时限在 PRD 量化。 |
| MED-NFR-007 | 可维护 | 业务模块不得依赖桶名、文件系统路径或对象存储 SDK；对象存储异常转换为稳定模块错误。 |
| MED-NFR-008 | 可移植 | 开发/MVP MinIO 与已选生产 OSS 必须通过同一对象存储端口契约；不得把供应商特性泄漏给业务模块。 |

## 6. 生命周期与失败路径

- UploadSession：`pending → completed | expired | failed`；完成操作必须幂等。
- MediaObject：`active ↔ archived`；MediaVersion 只追加，不设置可覆盖的“最新文件内容”。
- MediaLocation：`verified → active → retiring → retired`，校验/读取异常可进入 `quarantined`；每个 MediaVersion 同时最多一个 active 位置。
- 上传校验失败的对象进入隔离/待清理状态，不得出现在可选择资产中。
- 对象存储暂时不可用时返回可重试错误，不得创建声称可用但实际不存在的 MediaVersion。
- 预签名访问过期后客户端必须重新申请，不得把 URL 持久化为业务事实。

## 7. 非目标与待确认

- 不建立公共素材市场、CDN 发布系统、任意网盘目录或媒体编辑器。
- 不允许业务模块直接操作对象存储或自行拼接 object key。
- 待确认允许格式、单文件/Workspace 容量、上传并发、临时对象保留期、病毒/敏感文件扫描和访问 URL 时效。
