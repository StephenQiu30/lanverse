# 业务术语表

| 术语            | 本轮含义                                          |
| --------------- | ------------------------------------------------- |
| 项目            | 一份创作的规格、内容和媒体上下文                  |
| 设定/造型       | 角色、场景、道具及其外观版本                      |
| 镜头版本        | 一次不可变输入；不等于生成结果                    |
| 候选            | 任务输出；尚未必正式采用                          |
| 选定            | 用户明确采用的画面/视频输出                       |
| 失效            | 当前依赖与冻结版本不一致；不自动重新生成          |
| 收藏            | 当前用户对素材库条目的偏好                        |
| 未知/待人工核对 | 不能确认实际执行结果的任务，不能直接重提收费      |
| 历史实现        | 与本次浮光设计无默认约束关系的旧页面/接口/表/文档 |

| 需求与过程术语      | 含义                                                                        |
| ------------------- | --------------------------------------------------------------------------- |
| 原始需求            | 用户希望解决的问题及所需结果；页面仅是获取这些需要的一类证据                |
| 功能性需求（FR）    | 在明确条件下系统应执行的行为、业务规则和可观察结果                          |
| 非功能性需求（NFR） | 安全、可靠、性能、容量、兼容、可访问、恢复等质量/运行条件                   |
| 数据/业务约束       | 字段含义、权限、格式、版本、保留和已确认的业务数值；不等于表结构            |
| 需求基线            | 明确获接受的范围及版本；Git保存或页面完成本身不表示批准                     |
| 待确认/假设         | 尚无确定规则/目标或未经验证的前提；不能当作已接受功能或达标证据             |
| 用户故事            | 角色、需要及价值的描述，以讨论和验收确认；不是完整模块必须一个Sprint完成    |
| Design              | 对已确认问题的技术/交互方案与取舍，获接受后才细化当次实施                   |
| 验收场景（AC）      | 可执行的角色/起始条件/操作顺序/预期结果；编写场景不等于测试已运行           |
| 验证与验收          | 分别检查实现是否符合规格、结果是否解决用户原始需要；记录实际证据            |
| 可追踪性            | 产品目标/来源→需求/质量→方案/变更→测试/证据可互相定位                       |
| P50/P95             | 测量样本的50/95百分位；统计对象、窗口、样本与算法需明确                     |
| RPO/RTO             | 恢复时可接受的数据损失窗口/恢复时限；本项目目标尚待确认                     |
| 原子批量            | 批量编辑整体成功或整体不写；逐项生成任务不表示整批副作用是一个事务          |
| 幂等                | 同一次意图的同键同输入重复提交定位同次操作，不重复副作用；范围/有效期待设计 |
| 未接入/不可用       | 数据源或能力尚未接入，或目前不能获取；不同于真实0和已知失败                 |

模块内部使用业务词汇；`user_account`等存储名及HTTP错误码来自原资料/方案建议，不能代替产品行为。需求/实现/验收状态分开维护，规则见[生命周期方法](../软件生命周期与需求管理.md)。
