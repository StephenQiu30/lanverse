# 剧本到分镜 MVP 需求规格

- 状态：本轮实施基线
- 日期：2026-08-25
- 产品依据：[剧本到分镜 MVP 产品需求](../prd/0009-剧本到分镜MVP产品需求.md)
- 设计依据：[剧本到分镜 MVP 垂直切片设计](../design/0009-剧本到分镜MVP垂直切片设计.md)

## 功能需求

- `MVP-FR-001`：用户可注册、创建项目；刷新后仍能从服务端读取项目状态。
- `MVP-FR-002`：用户可上传 Markdown/DOCX，预览成功前不能固定原稿；确认后生成不可变 Revision 和可解释格式体检。
- `MVP-FR-003`：系统可为 Revision 创建本地 Codex Production Bible 任务，浏览器可恢复 queued/running/needs_review/failed/unknown 状态。
- `MVP-FR-004`：Bible 必须展示实体、集数、状态和审阅问题；存在 blocking issue 时禁止确认，确认时校验 expected revision 与 result hash。
- `MVP-FR-005`：未确认 Bible 时禁止发布 Episode 剧本；确认后可原子创建并批量发布全部审阅通过的分集。
- `MVP-FR-006`：每集结构提取必须产生来源锚定的场次、对白、叙事单元和制作任务；每个场次必须有 1–4 个不重复的可执行任务且至少包含一个 `shot_breakdown`，缺失或空数组必须由结构化契约拒绝；必需候选未决时禁止确认。
- `MVP-FR-007`：Storyboard 只消费已确认结构和当前 Bible occurrence，生成结果只能进入 needs_review，不能直接创建正式 Shot。
- `MVP-FR-008`：用户必须逐镜决议、批准整批草案、执行影响预检，再以 expected hash 原子 Apply；冲突时正式 Shot 数不变化。
- `MVP-FR-009`：导出包至少包含 manifest、JSON、CSV、HTML，固定输入相同时内容哈希一致。
- `MVP-FR-010`：项目、任务和导出页面必须明确展示依赖失败、可恢复动作和真实服务端状态。

## 非功能需求

- `MVP-NFR-001`：所有写操作幂等；重复提交不产生重复 Episode、Task、Bible、Draft、Shot 或 Export。
- `MVP-NFR-002`：Codex 使用 ephemeral、read-only sandbox 和严格 JSON Schema；运行时不读取浏览器或领域写凭据。
- `MVP-NFR-003`：E2E 使用独立测试数据库迁移、临时 Kafka 与临时 MinIO，退出后清理临时数据，不消费本机历史消息。
- `MVP-NFR-004`：核心页面具备可访问名称、键盘可操作控件和可读状态提示；浏览器测试使用角色/标签定位。
- `MVP-NFR-005`：健康检查区分进程存活与依赖就绪；任何跳过、超时或外部条件缺失不得报告为通过。
