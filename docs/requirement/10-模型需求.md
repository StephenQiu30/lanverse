# 模型需求

## 1. 需求概述

**需求目标：** 管理员能维护供创作使用的模型定义和不可变发布版本。

**使用者与价值：** 作为管理员，我希望统一维护模型能力、参数与发布版本，让制作者选择有效配置且历史任务可以解释。

**问题背景：** 模型编辑与差异页面未证明表单/JSON同源、真实能力校验及不可变发布。

| 属性     | 内容                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 业务角色 | 管理员；制作者消费已发布模型                                                |
| 文档状态 | 原始需求整理稿，待评审；不是已接受的设计或已验收功能                        |
| 范围来源 | 本文件第7、8节保留的原规格、现有页面代码，以及已整理的跨模块流程            |
| 完成依据 | 第3节功能结果、第4节质量条件、第5节验收场景；待确认项解决后才能验收相应能力 |

## 2. 范围与边界

本模块包含：列表/能力/区域/模式、建草稿、参数表单与JSON、版本差异、发布及启停；不建设价格平台。

维护模型定义、编辑/发布版本及新任务可选性，不扩展为价格管理产品。

业务模块一份文档，内部需求编号仅用于追踪，不对应独立文件、接口、类或开发任务。编号不承诺排期。原资料中的存储名、组件名和分页建议不作为已接受架构。

## 5. 验收场景

下列是可执行的业务场景定义，尚未运行。实际测试按[生命周期方法](../软件生命周期与需求管理.md#测试与证据)记录环境、步骤、逐步预期与实际结果；功能行已给出独立验收条件，场景可联合验证多个相关功能。

| 场景        | 关联需求                              | 角色与初始条件           | 操作顺序                                    | 预期结果                                             |
| ----------- | ------------------------------------- | ------------------------ | ------------------------------------------- | ---------------------------------------------------- |
| AC-MODEL-01 | FR-MODEL-01、FR-MODEL-02、FR-MODEL-03 | 管理员；合法供应商归属   | 建草稿→表单编辑→切JSON→看差异；提交非法JSON | 三种视图同源；非法输入留存并定位，未成为可选发布模型 |
| AC-MODEL-02 | FR-MODEL-03、FR-MODEL-04              | 两个管理员及已发布模型   | 并发编辑发布→创建后续草稿→查看旧发布版本    | 冲突显式，旧发布不可变且历史任务版本可定位           |
| AC-MODEL-03 | FR-MODEL-01、FR-MODEL-05              | 制作者；模型已有在途任务 | 管理员停用→新任务尝试提交→查询旧任务        | 新提交受控；历史仍可解释；在途行为符合先确认策略     |

质量验收还需执行第4节的权限、故障、边界及数据量验证，并记录自动化、真实持久化、浏览器与外部条件各自的证据。静态数据、成功提示与文档检查不构成产品验收。

## 6. 依赖、假设与待确认

依赖供应商归属与管理员权限；生成任务以后引用发布版本。

**原有待确认：** 参数schema校验细节需要在方案评审中明确，不从演示模型名推断供应商能力。

**本轮发现的需求缺口：** 模型key的唯一性/格式；停用对排队或运行任务的影响；区域选择的业务限制与默认值。

**质量目标待确认：** 本模块适用设备/浏览器/版本、典型与边界数据规模、网络/冷热缓存条件、响应P50/P95、交互/Web Vitals与内存目标，以及格式/大小/并发/批量/导出限额须明确后才能质量验收。持久数据备份范围/周期、RPO/RTO与恢复责任人待确认。运行环境、可用性/维护窗口、数据用途/地域/保留及观测口径/日志策略仍待确认；不臆造SLA或规模。

这些问题统一纳入[总表缺口登记](01-需求总览.md#需求缺口与确认)，由产品负责人确认业务政策，工程/测试负责人补验证条件。责任角色尚未落实到人员，未给出答复的范围维持待确认；不自动新增平台、渠道或旧页面能力。
