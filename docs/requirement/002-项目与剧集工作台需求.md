## 1. 模块定位

项目与剧集工作台是用户进入 AI 短剧制作流程的统一入口。它负责稳定地组织 Workspace、Project 和 Episode，展示各集从剧本、资产、分镜到镜头视频选择与素材包导出的进度、阻塞和下一动作。

本模块只拥有项目和剧集自身事实。剧本正文、资产设定、镜头规格、生成任务、候选视频、当前视频选择及导出文件分别由对应模块拥有；工作台只能读取其摘要，不得复制或代替下游事实。

### 1.1 产品目标

1. 用户在首次进入后能够快速创建项目和首集，并进入明确的下一制作动作。
2. 用户能在一个页面判断每集缺少什么、为何被阻塞以及应去哪里处理。
3. 项目默认设置只约束未来输入，绝不静默改写已经确认的剧本、资产、镜头或视频候选。
4. 用户能安全地重排、归档和恢复剧集，历史版本和已导出的镜头包始终可追溯。
5. 工作台不制造第二套“制作阶段真相”，所有进度都能回到对应模块事实。

### 1.2 产品 KPI

以下目标均为 proposed，基线样本和测量窗口在可用性测试计划中确认：

| KPI ID | 指标 | 目标 |
| --- | --- | --- |
| CUR-PRJ-KPI-001 | 首次创建项目至进入首集工作区的任务完成率 | ≥ 90% |
| CUR-PRJ-KPI-002 | 首次创建项目至看到可执行下一动作的中位用时 | ≤ 2 分钟 |
| CUR-PRJ-KPI-003 | 生产概览中无法解释来源的状态或数字 | 0 |
| CUR-PRJ-KPI-004 | 用户从阻塞项进入正确处理页面的成功率 | ≥ 95% |
| CUR-PRJ-KPI-005 | 剧集重排后出现重复、缺失或顺序漂移 | 0 |
| CUR-PRJ-KPI-006 | 因修改项目默认设置导致历史制作事实被改写 | 0 |

## 2. 范围与非范围

### 2.1 当前范围

- 创建、读取、搜索、修改、归档和恢复项目。
- 创建、读取、修改、重排、归档和恢复剧集。
- 项目级名称、简介、语言、目标画幅、视觉方向和默认生成偏好的管理。
- 项目与剧集生产概览。

- 对项目默认设置变更的影响说明。
- 基于 Workspace 的 owner、editor、viewer 最小权限。
- 空白项目或空白剧集的受控删除。

### 2.2 明确非范围

- 套餐、支付、账单、优惠、渠道、CRM 或商业运营后台。

- 在工作台中直接编辑剧本、资产、镜头规格或生成候选正文。
- 自动排期、工时管理、资源排班和项目管理甘特图。
- 自动发布到短视频平台。

## 3. 角色与权限

当前使用 Workspace owner、editor、viewer 三类产品角色；其权限边界由本文件和 CUR-PLT 共同定义，不继承旧需求状态。

| 能力 | owner | editor | viewer |
| --- | :---: | :---: | :---: |
| 查看项目、剧集与生产概览 | ✓ | ✓ | ✓ |
| 创建和修改项目 | ✓ | ✓ | — |
| 创建、修改和重排剧集 | ✓ | ✓ | — |
| 修改项目默认制作设置 | ✓ | ✓ | — |
| 归档/恢复剧集 | ✓ | ✓ | — |
| 归档/恢复项目 | ✓ | — | — |
| 删除符合条件的空白项目/剧集 | ✓ | — | — |
| 从阻塞项进入对应只读详情 | ✓ | ✓ | ✓ |

权限不因用户知道资源 ID 而改变。无权限用户不得获知其他 Workspace 中项目或剧集是否存在。

## 4. 核心用户场景

### CUR-PRJ-US-001 创建第一部短剧

独立创作者进入个人 Workspace，填写项目名称、语言、目标画幅和视觉方向，创建项目及首集，系统直接展示“导入剧本”作为下一动作。

### CUR-PRJ-US-002 管理多集结构

创作者为一部 3–5 集短剧添加剧集、修改标题并重排顺序。操作完成后，每集稳定 ID、剧本和镜头引用不变化，仅展示顺序变化。

### CUR-PRJ-US-003 定位生产阻塞

创作者看到某集“镜头视频选择 18/24”，其中 2 镜未生成、3 镜未选择、1 镜因资产变更过期。用户选择某一分类即可进入对应镜头或资产处理入口。

### CUR-PRJ-US-004 修改默认画幅

创作者把项目默认画幅从 16:9 改为 9:16。系统先说明该变化只影响以后创建或显式升级的镜头规格，既有镜头和候选视频保持原输入。

### CUR-PRJ-US-005 暂停并恢复项目

owner 归档项目后，团队仍可查看历史事实和镜头素材包，但不能创建新版本或提交新生成；恢复后继续制作。

| 下游 | 角色/场景/道具资产 | 资产完整度、阻塞项、受影响镜头摘要 |
| 下游 | 分镜与镜头设计 | 当前分镜版本、镜头数量、覆盖率、过期镜头 |

## 7. 详细功能需求

### CUR-PRJ-FR-001 创建项目并进入首个下一动作

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户已登录，已选择 active Workspace，角色为 owner 或 editor。 |
| 主流程 | 用户填写项目名称以及当前阶段要求的最少制作设置；系统即时校验；用户确认创建；系统创建稳定 Project；若用户选择同时建立首集，则创建 Episode 1；成功后进入项目工作台并展示“导入剧本”。 |
| 备选流程 | 用户可以只创建空项目，稍后添加剧集；未填写可选设置时使用清晰可见的默认值。 |
| 失败流程 | Workspace 已归档、权限变化、必填项缺失或重复提交时，系统不得创建半成品或重复项目，并保留用户可恢复的表单输入。 |
| 业务规则 | 同一 Workspace 允许项目重名；项目 ID 不依赖名称；创建首集失败时不得留下“项目成功但用户误以为已有首集”的模糊结果。 |
| 输入 | 项目名称、可选简介、主要语言、目标画幅、视觉方向、是否创建首集。 |
| 输出 | Project 摘要、可选 Episode 摘要、明确下一动作。 |
| UI 要求 | 首屏只展示当前必需字段；不可逆或高影响设置必须解释影响；创建按钮在提交期间避免重复触发；成功页只提供一个主下一动作。 |

### CUR-PRJ-FR-002 项目列表、搜索与详情

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户拥有目标 Workspace 的有效 Membership。 |
| 主流程 | 用户查看有权访问的项目，按名称搜索，按最近活动或创建时间排序，并进入项目详情。 |
| 备选流程 | 用户可切换显示归档项目；无搜索结果时可以清空筛选。 |
| 失败流程 | 概览依赖暂不可用时仍展示项目自身信息，并为受影响摘要标记“暂不可获取”。 |
| 业务规则 | 默认不显示归档项目；列表不得混入其他 Workspace 项目；项目摘要中的数字必须标明统计范围。 |
| 输入 | Workspace、搜索词、归档筛选、排序、分页。 |
| 输出 | 项目摘要、剧集数、制作摘要、最近活动与权限允许的动作。 |
| UI 要求 | 空列表、无结果和加载失败是三种不同状态；不得用 0 代替加载失败。 |

### CUR-PRJ-FR-003 修改项目元数据与默认制作设置

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Project active；用户为 owner/editor；读取时保存的项目修订仍为当前。 |
| 主流程 | 用户修改名称、简介、语言、目标画幅、视觉方向或默认生成偏好；系统展示变更摘要；用户确认后保存最新设置。 |
| 备选流程 | 纯文本元数据修改可直接保存；可能影响以后镜头输入的设置必须先展示影响范围。 |
| 失败流程 | 并发变化、字段非法或项目被归档时拒绝修改，并显示最新值与重新比较入口。 |
| 业务规则 | 默认设置只作用于以后创建的剧本派生、资产版本、镜头规格或生成请求；不得改写任何既有版本。需要升级旧内容时必须由所属模块显式执行。 |
| 输入 | 允许修改字段、用户读取到的修订标识。 |
| 输出 | 更新后的项目设置、影响说明和需要显式处理的下游数量。 |
| UI 要求 | 区分“仅显示信息”和“影响未来制作”的字段；不能用“保存后全部同步”这类模糊文案。 |

### CUR-PRJ-FR-004 创建和维护剧集

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Project active；用户为 owner/editor。 |
| 主流程 | 用户创建 Episode，填写标题和可选目标说明；系统分配当前末尾顺序；用户可修改标题和目标说明。 |
| 备选流程 | 从确认的分集方案批量建立剧集时，本模块接受整批结果并显示来源；用户仍可后续修改显示标题。 |
| 失败流程 | 项目被归档、并发创建冲突或分集方案过期时，整次操作失败并返回可处理原因。 |
| 业务规则 | Episode ID 稳定；标题不是身份；显示顺序在项目内唯一；修改元数据不得改变已引用的剧本或镜头版本。 |
| 输入 | Project、标题、目标说明、可选来源方案。 |
| 输出 | Episode 摘要、显示顺序和下一动作。 |
| UI 要求 | 新集创建后清晰展示为空白、待导入剧本；不得显示为制作完成度 0% 而不解释下一动作。 |

### CUR-PRJ-FR-005 原子重排剧集

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Project active；用户为 owner/editor；用户看到的剧集集合和顺序仍为当前。 |
| 主流程 | 用户拖动或使用键盘命令调整剧集顺序；系统展示新顺序；用户保存后全部顺序一次生效。 |
| 备选流程 | 用户可以取消修改恢复到保存前顺序；键盘用户可通过“上移/下移”完成同一任务。 |
| 失败流程 | 任一 Episode 缺失、重复、已归档状态冲突或有人并发调整时，整体不生效，并展示最新顺序。 |
| 业务规则 | 重排只修改显示顺序，不改变 Episode ID、内部版本引用、镜头身份或历史导出；禁止部分成功。 |
| 输入 | Project、完整有序 Episode ID 集合、读取时的顺序修订。 |
| 输出 | 最新有序剧集列表。 |
| UI 要求 | 保存前明确显示未保存状态；失败后不得让页面继续展示未落地顺序为成功。 |

### CUR-PRJ-FR-006 项目与剧集生产概览

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户可读取 Project/Episode。 |
| 主流程 | 工作台聚合展示剧本确认、资产准备、分镜确认、视频生成和当前视频选择、镜头包导出的最新摘要。 |
| 备选流程 | 用户可按全部、阻塞、生成中、失败、待选择、选择已过期和可导出筛选剧集。 |
| 失败流程 | 某一依赖不可用时，该分区显示 unavailable 及最后成功获取时间；其他分区继续可用。 |
| 业务规则 | 生产阶段和完成度是派生值，不可手工编辑；完整包镜头选择覆盖率的分母是目标 StoryboardBaseline 的全部 active Shot。暂不交付的镜头须先归档，临时只交接部分镜头时使用 `scope=partial`，不得从完整包分母中隐式排除“创作性非必需镜头”。 |
| 输入 | Project/Episode、筛选条件。 |
| 输出 | 分模块摘要、阻塞数、生成任务状态、已选择/全部 active 镜头数、最近导出。 |
| UI 要求 | 状态、任务和结果必须分开展示；不得因已有历史候选而把正在重新生成的镜头显示为“无结果”。 |

### CUR-PRJ-FR-007 阻塞原因和下一动作导航

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 概览至少有一个 blocked、failed、stale 或 incomplete 事实。 |
| 主流程 | 用户展开阻塞分类，查看具体 Episode、Shot 或 Asset、原因和建议动作；选择条目后进入拥有该事实的模块及目标对象。 |
| 备选流程 | 用户可只看阻塞项，或按模块、严重程度筛选。 |
| 失败流程 | 目标对象已变化或用户无写权限时，进入最新只读详情并说明无法执行原动作的原因。 |
| 业务规则 | 下一动作是建议，不得自动执行高成本生成、删除、换主选或升级版本；每个原因必须有事实来源和更新时间。 |
| 输入 | 阻塞分类、目标对象。 |
| 输出 | 原因、证据摘要、所属模块、允许动作。 |
| UI 要求 | 原因文案必须具体，例如“镜头 12 未选择当前视频”，不能只显示“未完成”；一个主动作配必要次动作。 |

### CUR-PRJ-FR-008 归档、恢复和受控删除

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 归档/恢复项目由 owner 执行；归档剧集可由 owner/editor 执行；删除由 owner 执行。 |
| 主流程 | 用户查看影响摘要并确认归档；归档后禁止创建新业务事实和提交生成，但允许读取历史及下载仍有效的导出；用户可恢复继续制作。 |
| 备选流程 | 用户只归档单个 Episode；Project 归档时其 active Episode 一并进入只读门禁，但不改变各 Episode 历史状态。 |
| 失败流程 | 有状态未知或无法安全处理的生成任务时，系统阻止归档并列出任务；删除条件不满足时返回全部阻塞引用。 |
| 业务规则 | 只有无 Episode、版本、任务、候选、选择和导出的空白项目可硬删除；空白 Episode 同理；归档不删除、不取消授权读取历史。 |
| 输入 | 目标、期望状态、确认。 |
| 输出 | 新状态或完整阻塞清单。 |
| UI 要求 | “归档”和“删除”视觉、文案和确认层级必须不同；删除确认须说明不可恢复。 |

### CUR-PRJ-FR-009 权限一致的工作台访问

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户具有当前 Workspace 的有效 Membership。 |
| 主流程 | 系统按角色展示允许的读取和操作；viewer 可以查看生产状态，但不出现可执行写命令。 |
| 备选流程 | 用户角色在页面打开期间改变时，下一次读取刷新权限；尚未提交的编辑内容可复制保存，但不得越权写入。 |
| 失败流程 | Membership 被移除、Workspace 被归档或请求指向其他 Workspace 时，拒绝访问且不泄露目标存在性。 |
| 业务规则 | 所有下游导航沿用同一 Workspace 和角色上下文，不建立项目级第二套角色。 |
| 输入 | 当前用户、Workspace、目标 Project/Episode、动作。 |
| 输出 | 允许的页面信息和动作，或稳定的拒绝结果。 |
| UI 要求 | 禁止访问与资源不存在使用不泄露存在性的表现；只读模式必须明确，不能仅依赖按钮置灰。 |

## 8. 领域实体与关系

| 实体 ID | 产品实体 | 说明 |
| --- | --- | --- |
| CUR-PRJ-ENT-001 | Workspace | 项目隔离与权限边界；作为 Project 的唯一上级协作范围。 |
| CUR-PRJ-ENT-002 | Project | 一部短剧项目的稳定身份与默认制作上下文。 |
| CUR-PRJ-ENT-003 | Episode | Project 下单集的稳定身份和显示顺序。 |
| CUR-PRJ-ENT-004 | ProductionSnapshot | 按当前下游事实即时或近实时形成的只读生产摘要，不是可编辑业务记录。 |
| CUR-PRJ-ENT-005 | BlockingReason | 指向来源模块和具体对象的可解释阻塞事实。 |
| CUR-PRJ-ENT-006 | NextAction | 基于权限和阻塞事实计算的建议导航，不代表动作已经执行。 |

~~~mermaid
erDiagram
    WORKSPACE ||--o{ PROJECT : contains
    PROJECT ||--o{ EPISODE : contains
    PROJECT ||--o{ PRODUCTION_SNAPSHOT : summarizes
    EPISODE ||--o{ PRODUCTION_SNAPSHOT : summarizes
    PRODUCTION_SNAPSHOT ||--o{ BLOCKING_REASON : explains
    BLOCKING_REASON ||--o{ NEXT_ACTION : suggests
~~~

Project/Episode 只保存自身事实和当前引用标识；ProductionSnapshot 不得成为第二份剧本、资产、镜头、任务或导出事实。

## 9. 状态机与不变式

### 9.1 生命周期

~~~mermaid
stateDiagram-v2
    [*] --> Active
    Active --> Archived: 明确归档
    Archived --> Active: 明确恢复
    Active --> Deleted: 仅空白且无引用
~~~

Project 和 Episode 均使用 active/archived 生命周期。Episode 的“剧本准备中、资产阻塞、镜头生成中、可导出”等均是派生展示状态，不建立可被用户随意修改的阶段状态机。

### 9.2 不变式

1. Project 和 Episode ID 在重命名、重排和归档后保持不变。
2. 同一 Project 内 active Episode 的显示顺序不得重复。
3. 项目默认设置变化不得改变任何已经存在的版本化输入或生成结果。
4. ProductionSnapshot 的每个值必须能够返回来源模块、统计口径和更新时间。
5. 下游 unavailable 不得被解释为 0、空或 ready。
6. 归档对象的历史内容可读，禁止新增或修改业务事实。
7. 只有完全空白且无引用对象可硬删除。
8. 工作台不拥有或改写下游 current 选择。

## 10. 产品接口、事件与文件需求

### 10.1 产品接口契约

| IF ID | 能力 | 必要输入 | 用户可观察输出 |

| CUR-PRJ-IF-004 | 剧集重排 | 完整顺序、期望顺序修订 | 全量最新顺序或零写入冲突 |

接口名称只表达产品能力，不规定 URL、协议框架或服务拆分。

### 10.2 领域事件

下游需要感知以下已确认事实变化：

- CUR-PRJ-EVT-001 ProjectCreated
- CUR-PRJ-EVT-002 ProjectDefaultsChanged
- CUR-PRJ-EVT-003 EpisodeCreated
- CUR-PRJ-EVT-004 EpisodeOrderChanged
- CUR-PRJ-EVT-005 ProjectArchivedOrRestored
- CUR-PRJ-EVT-006 EpisodeArchivedOrRestored

事件必须带稳定对象 ID、变化前后修订、操作者和发生时间；事件通知失败不得让已成功的用户命令显示为失败或被重复执行。

### 10.3 文件需求

本模块当前不导入或导出业务文件。剧本文件属于 CUR-SCR，镜头视频和素材包文件属于后续导出模块。工作台仅提供对应入口和状态。

## 12. 异常与恢复

| 异常 | 用户可观察行为 | 恢复要求 |
| --- | --- | --- |
| 重复提交创建 | 不出现两个相同意图产生的项目 | 返回首次成功结果或明确未成功状态 |
| 创建 Project 成功、首集失败 | 不显示模糊成功 | 明确项目已创建、首集未创建，并提供重试创建首集；不得重复项目 |
| 剧集重排并发冲突 | 新顺序不生效 | 展示最新顺序，允许用户重新调整 |
| 下游概览不可用 | 对应分区显示 unavailable | 保留其他分区；提供重试和最后成功时间 |
| 归档时存在生成中或状态未知任务 | 阻止或要求先处理 | 列出任务及允许动作，不自动取消高成本任务 |
| 删除存在引用 | 删除失败 | 返回全部主要阻塞类型及进入处理页面的入口 |
| 用户权限中途变化 | 当前写操作失败 | 保留可复制的未提交输入，重新加载为最新只读/有权状态 |

## 13. 验收条件

### AC-CUR-PRJ-001（关联 CUR-PRJ-FR-001）

Given owner 位于 active Workspace，When 使用合法名称创建项目并选择创建首集，Then 只产生一个 Project 和一个 Episode，页面进入首集并显示“导入剧本”。

### AC-CUR-PRJ-002（关联 CUR-PRJ-FR-001、CUR-PRJ-FR-009）

Given viewer 位于 active Workspace，When 尝试创建项目，Then 系统拒绝写入，项目列表不增加，且页面明确处于只读模式。

### AC-CUR-PRJ-003（关联 CUR-PRJ-FR-002）

Given Workspace 同时有 active 和 archived 项目，When 使用默认列表，Then 只显示 active；When 打开“包含归档”，Then 归档项目以明确状态出现。

### AC-CUR-PRJ-004（关联 CUR-PRJ-FR-003）

Given 一个 Episode 已有 16:9 镜头规格和视频候选，When 用户把项目默认画幅改为 9:16，Then 历史镜头规格和候选保持 16:9，页面显示未来输入生效和受影响提示。

### AC-CUR-PRJ-005（关联 CUR-PRJ-FR-004）

Given active Project，When editor 创建新 Episode，Then 新集位于当前末尾、具有稳定 ID，并显示待导入剧本。

### AC-CUR-PRJ-006（关联 CUR-PRJ-FR-005）

Given 三个已有下游引用的 Episode，When 用户把第三集移至第一位并保存，Then 只改变显示顺序，三集 ID 与下游引用完全不变。

### AC-CUR-PRJ-007（关联 CUR-PRJ-FR-005）

Given 用户正在重排且另一会话已改变顺序，When 用户提交旧顺序修订，Then 整次重排零写入并展示最新顺序。

### AC-CUR-PRJ-008（关联 CUR-PRJ-FR-006）

Given 目标 StoryboardBaseline 有 24 个 active Shot，其中 18 个已有有效当前视频、3 个未选择、2 个未生成、1 个选择过期，When 打开概览，Then 展示 18/24 及三个互不混淆的问题分类。

### AC-CUR-PRJ-009（关联 CUR-PRJ-FR-006）

Given 资产摘要暂不可用，When 打开概览，Then 资产分区显示 unavailable，剧本和镜头分区仍显示真实状态，资产数不显示为 0。

### AC-CUR-PRJ-010（关联 CUR-PRJ-FR-007）

Given 镜头 12 未选择当前视频，When 用户点击该阻塞项，Then 进入镜头 12 的候选选择上下文，不自动选择或生成视频。

### AC-CUR-PRJ-011（关联 CUR-PRJ-FR-008）

Given Project 有历史版本和镜头包，When owner 归档，Then禁止新建和生成但仍可读取历史、下载有效镜头包；恢复后可继续制作。

### AC-CUR-PRJ-012（关联 CUR-PRJ-FR-008）

Given Project 存在任一 Episode 或版本引用，When owner 请求硬删除，Then 删除失败并返回阻塞类型；Given 完全空白项目，Then 明确二次确认后可删除。

## 14. 开放问题

| ID | 问题 | 决策所需证据 | 未决期间处理 |
| --- | --- | --- | --- |
| CUR-PRJ-OQ-001 | 是否需要“漫剧/真人/3D”项目类型以及能否修改？ | 真实用户流程、资产约束和迁移成本 | 当前不增加不可逆项目类型，只保存可修改视觉方向 |
| CUR-PRJ-OQ-002 | 当前容量是否固定为每项目最多 10 集？ | 首批 10 个真实项目规模 | 以 10 集作为性能基线，不做商业套餐限制 |
| CUR-PRJ-OQ-003 | 归档时运行中任务应允许完成还是要求取消？ | Provider 取消能力、成本和用户预期 | 状态未知时阻断归档；其余由任务模块返回明确可选动作 |
| CUR-PRJ-OQ-004 | viewer 是否允许下载镜头素材包？ | 团队交接场景和最小权限评审 | 当前 proposed 假设为 viewer 可读历史；下载权限在导出模块确定 |
| CUR-PRJ-OQ-005 | 移动端是否需要编辑能力？ | 用户设备研究 | 当前仅承诺桌面完整创作，小屏只读概览 |

### 14.1 已决策事项

- Project 与 Episode 使用稳定身份；名称、展示顺序、阶段摘要和默认制作设置都不能代替身份或改写历史。
- 项目默认设置只影响未来输入；修改画幅、视觉方向等默认值必须展示影响，不静默改写既有 ShotSpec 或 Candidate。
- 生产阶段和完成度只由下游事实派生；依赖未知时显示 unavailable/partial failure，不显示 0 或“已完成”。
- `scope=complete` 覆盖率分母固定为目标 StoryboardBaseline 的全部 active Shot；临时交接部分镜头使用显式 `scope=partial`。
- 当前工作台不引入套餐、账单、商业运营、时间线、剪辑或成片概念。

## 15. 术语

| 术语 | 定义 |
| --- | --- |
| Project | 一部 AI 短剧制作项目的稳定业务身份。 |
| Episode | Project 下的一集，拥有稳定身份和可变显示顺序。 |
| 默认制作设置 | 供以后创建输入使用的项目级默认值，不回写历史事实。 |
| ProductionSnapshot | 从下游当前事实计算的只读制作摘要。 |
| BlockingReason | 阻止用户进入下一结果的具体、可定位事实。 |
| NextAction | 根据阻塞和权限给出的导航建议，不代表命令已经执行。 |
| 当前视频选择覆盖率 | 目标 StoryboardBaseline 全部 active Shot 中，已有有效或经当前输入重新确认的当前视频所占比例。 |
| 镜头素材包 | 有序逐镜视频及 Manifest；不是拼接后的成片。 |
