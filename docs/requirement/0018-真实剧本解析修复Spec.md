# 真实剧本解析修复 Spec

- CT-01：3981 块、约 14 万字符的合成稿及指定实际稿在固定字节预算内装配；恢复所有块后与原文逐字符一致，空行与 Unicode 不丢失。
- CT-02：新编码对应新 release；未安装旧 release 的请求明确拒绝，不将旧运行重新绑定新 release。
- DB-01：分集采纳保存 N 个正式剧集、版本和 N 个发布事件，事件绑定同一实际 OwnerReceipt。
- DB-02：采纳重放不增加事件；Outbox 插入失败时无剧集、版本、事件或采纳回执残留。
- UI-01：导入后进入新 Creation；刷新找到原运行，失败保持原稿，旧历史可查询。
- RT-01：实际 Creation API/Worker/源桥/采纳桥可用；数据库已发布剧集经 Kafka/ES 可查询并核验版本和项目权限。
- SEM-01：逐集场次、人物/别名/关系/状态及可见细节保留来源；对照 0017 及原稿独立基准审阅，明确待决项。

- WIRE-01：实际 Python 执行快照包含输出角色、条目标识、步骤定位时，Go 闭合合同仍可正确接收；保留未知字段拒绝。
- UI-02：已执行且尚未全部同步的逐集草案，页面按持久化步骤展示进度，不显示“尚未开始”。
- SEM-02（待实现）：时间分支继承与采纳前修订协议见 Design/0018；不批准已确认存在时间分支错误的第一集候选。
