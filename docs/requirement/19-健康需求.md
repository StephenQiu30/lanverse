# 健康需求

## 目标与范围

管理员能查看真实降级、执行风险及运行指标。

本模块范围：固定窗口健康卡、供应商/队列/Worker摘要、30秒及手动刷新、去处理与配置监控链接。

建议执行顺序为编号顺序；编号不代表排期或已批准实施。本文件按业务模块整体维护，内部功能在同一文档列出，不为每个按钮、接口或技术层建立单独需求文件。

## 功能与数据要求

<a id="req-f-16"></a>

### 系统健康

#### 字段与数据量

| 区域   | 必须承载的字段                                          | 设计归属                          | 一次读取 / 保存的量                              |
| ------ | ------------------------------------------------------- | --------------------------------- | ------------------------------------------------ |
| 健康卡 | 降级原因、15分钟失败率、unknown/manual、Outbox积压/最旧 | generation_job + 可观测数据适配器 | 固定卡片，返回window/as_of/availability          |
| 分组   | 供应商1小时结果、队列积压/Worker/负载                   | 供应商调用结果和部署监控          | 实际分组摘要，不返回原始日志                     |
| 入口   | 30秒刷新、去处理、Grafana/Temporal UI链接               | 部署配置的可用链接                | 未部署组件显示不可用；这些标签不强制整个旧技术栈 |

#### 功能与失败边界

| 用户动作        | 必须产生的结果                         | 边界与失败                                                 |
| --------------- | -------------------------------------- | ---------------------------------------------------------- |
| 刷新 / 自动刷新 | 查询真实指标；局部错误保留最后成功时间 | 不能像mock点击就恢复正常；不可用不是0                      |
| 去处理 / 监控   | 跳到对应凭据或任务上下文，监控只读     | 任务处理可先在当前页面上下文呈现，不据此添加旧全局任务产品 |

## 范围边界

- 不建health/queue_snapshot表；监控设施选型另行按真实运行需求决定。

## 依赖与待确认

依赖实际任务与指标；未部署组件显示不可用，不据标签强制部署旧技术栈。

待确认：实际部署指标来源、监控地址及可用设施需要按运行条件确认。

以上缺口只是评审问题，不构成新增产品能力或架构决策。既有功能和约束不因旧接口支持不足而删除或降级。

## 模块验收

1. 本文列出的字段和功能由真实数据及操作结果承载，成功/失败/权限/未接入状态明确，mock不作为业务通过。
2. 需要持久化的写入可刷新恢复；版本冲突保留输入，重复副作用按幂等合同核对；只读/瞬时状态不强加持久化。
3. 当前用户/项目范围服务端验证；管理动作限管理员，秘密不进入响应、普通日志、审计明文或导出。
4. 实现时补与本模块风险匹配的成功、失败、冲突/重复、越权场景，分别记录自动化、真实持久化、浏览器及外部供应商证据，未执行不得报通过。

统一要求见[非功能规格](02-非功能需求规格.md)和[交互需求](05-界面与交互需求.md)；当前均待评审、未完成真实功能验收。本阶段不列Sprint、工时或固定用例数量。
