# 需求总览

## 当前状态与使用方式

本轮把原始需要整理成产品目标、用户场景、功能性需求、非功能性需求、数据/业务约束和可执行验收定义。页面已实现，真实业务尚未逐项接入和验收；文档仍为待评审稿，需求内容和质量指标的缺口必须显式保留。

产品意图与角色见[PRD-浮光](../prd/00-浮光.md)；格式、需求获取/评审/基线、设计、开发、测试、发布、运行维护与退役见[软件生命周期与需求管理](../软件生命周期与需求管理.md)。本总览只负责模块导航、建议顺序与缺口索引；功能性需求、非功能性需求及验收均归属相应业务文件，不按需求类别另建规格。

总览、流程、术语与界面文件只维护各自职责，业务模块06～19按建议顺序维护，一模块一份文档。每份统一包含概述、范围、功能性需求、非功能性需求、验收场景、依赖/待确认、原始字段动作和来源。FR/质量/AC编号只在模块内部追踪；需求阶段不按按钮、接口或技术层建立独立文件。

编号不是排期、工时或开工授权。原始业务规则先评审确认，复杂方案形成Design获接受后再细化当次技术需求、计划与测试。当前没有已接受的新数据/接口设计；被删除的文档不能继续引用为现行方案。

### 本轮源码差异与全局缺口

- 项目原表为写实/动漫/国风/胶片四类；当前`projects-page.tsx`可选写实电影感、日系胶片、国风水墨、赛博霓虹、温暖插画五项。原文最近更新排序，代码是最近打开。两组来源不能同时作为合同，须产品确认后统一。
- 原七类问题保留PDF歧义；当前上传input只有txt/md/docx。不能把旧问句当作当前代码仍支持PDF，也不能未经决定删除待支持问题。
- 首页写“文件只保存在本机”，导入/生成需求涉及存储与供应商处理；数据外发、存放/地域/用途须在剧本/素材/生成需求的数据治理条件及对应方案明确。
- 账号页主题文案强调浏览器保存，原需求要求跨登录持久化；当前实现事实不取消账号偏好需要，同步优先规则待定。
- 5%失败阈值、待人工超过24小时等健康数值属于源码样例；不自动变成SLO或已批准告警。
- 每个模块第4节与第6节直接记录性能/规模、备份恢复、运行环境/兼容、数据保留及观测口径的质量条件和参数缺口。首发范围、实际责任人/时间和质量目标也尚未接受。

解决一项需写明决定、依据、接受者和基线版本。其他未确认项可保留并隔离范围；与当前闭环有关的缺口必须解决，不能全模块标已完成。

## 通用验收与范围边界

逐项核对字段、动作、空值、失败与权限。业务写入须刷新后保留，冲突保留输入；统计可复算；生成不能替代人工选定。静态示例与临时交互状态不要求业务持久化。功能、非功能与验收条件均在对应模块；执行证据按[生命周期方法](../软件生命周期与需求管理.md#测试与证据)记录。

历史的组织/邀请/支付/协作角色、独立剧本工作台、导演台、时间轴、深度工具、素材包和永久清理不进入本次范围。旧页面、接口、表和技术拓扑不能反向裁剪本需求；删除的历史资料如需核查从Git历史读取，不恢复为当前基线；旧数据迁移仅在另行安排的任务中使用。本次仅整理文档，不修改前后端业务代码、数据库或用户数据。
