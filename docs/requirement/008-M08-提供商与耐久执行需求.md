# M08 提供商与耐久执行需求

> Requirement ID：REQ-EXE
> 状态：proposed v1
> 日期：2026-08-20
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)、[M07](./007-M07-生成规划提示编译与路由需求.md)
> 对应模块：M08 提供商与耐久执行

## 1. 需求结论

外部生成是高消耗、长时间、可能重复回调或提交结果未知的副作用。系统必须先持久化用户可见执行意图，再可靠调度；一个逻辑任务可以有多个 Attempt，但重复请求、消息和回调不能产生第二个逻辑任务或候选。

`unknown` 是正式状态：当无法判断提供商是否收单时必须先对账，不能把超时当失败并盲目重发。

## 2. 用户结果与范围

用户可以启动、观察、取消和恢复批准计划，查看每个目标的排队、提交、外部等待、下载、成功、失败、取消或 unknown 状态，以及错误类别、已消耗资源和安全下一动作。

本模块负责逻辑 Job、Attempt、提供商执行、回调、轮询、取消、限流、租约、对账和失败恢复；不决定候选主选、不修改计划、不实现商业账单。

## 4. 状态语义

逻辑 Job 至少表达 `accepted | queued | running | partial | succeeded | failed | cancel_requested | cancelled | unknown | blocked`。Attempt 可表达 `created | submitting | waiting_provider | downloading | succeeded | failed | cancelled | unknown`。

- Job 表示用户的一次逻辑执行目标；Attempt 表示一次具体尝试。
- 排队、租约和 Worker 状态不能冒充提供商结果。
- 外部标识一旦获得必须持久保存；下载失败优先复用该标识重新下载，而非重新生成。
- Job 完成只说明执行结束，不说明候选已采用、审阅通过或交付完成。

## 5. 重试、取消与对账

自动重试只允许在已确认未收单、提供商明确可安全重试、批准资源仍有余额且错误分类允许时发生。所有其他情况先对账或要求人工确认。

取消采用请求/确认分离：用户请求后停止新步骤；如供应商无法确认取消，Job 保持 `cancel_requested/unknown`，后续成功结果仍需摄取和说明，不能丢弃外部费用证据。

对账至少使用幂等键、外部任务 ID、请求时间窗和提供商查询能力。人工处理必须记录依据，不能直接把 unknown 改成 failed 后重发。

## 6. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 入队/调度失败 | Job 可查询且显示调度失败 | 安全重新调度同一 Job |
| Worker 崩溃 | 运行状态保留，租约过期后回收 | 续做同一 Attempt 或明确新 Attempt |
| 提交超时 | unknown，不显示 failed | 查询对账或人工处理 |
| 回调重复/乱序 | 只应用合法状态推进 | 记录重复并忽略 |
| 下载中断 | 保留 external ID 和已知结果 | 断点或重新下载，不重生成 |
| 批量部分失败 | 成功候选保留，汇总 partial | 只重试失败目标 |
| 取消结果未知 | 显示可能仍在提供商运行 | 持续对账并限制新尝试 |

## 7. 安全与审计

提供商凭据不得进入浏览器、计划正文、日志、事件、Prompt 或导出。回调验证来源和重放；所有提交、取消、重试、人工对账和错误覆盖记录主体、计划、Attempt、资源和理由。

支持人员只能看到诊断所需摘要；查看完整外部请求或敏感响应需要额外授权和审计。

## 8. 非功能需求

| ID | 要求 |
| --- | --- |
| EXE-NFR-001 | 队列不是唯一真相；调度状态可从持久事实恢复。 |
| EXE-NFR-002 | 消息至少一次投递下业务副作用保持幂等。 |
| EXE-NFR-003 | Worker、网络和数据库故障注入覆盖所有关键状态边界。 |
| EXE-NFR-004 | 每个 Job/Attempt 具有端到端 trace、最近进展和停滞检测。 |
| EXE-NFR-005 | 提供商状态映射版本化，未知新状态进入隔离而非误判。 |
| EXE-NFR-006 | 具体并发、轮询、超时和租约值由 Provider PoC 与容量基线签认。 |

## 9. 验收条件

| ID | 场景 |
| --- | --- |
| AC-EXE-001 | 重复启动同一计划项只对应一个逻辑 Job。 |
| AC-EXE-002 | 提交超时不会自动创建第二个昂贵任务。 |
| AC-EXE-003 | 重复回调不产生重复状态推进、候选或资源消耗条目。 |
| AC-EXE-004 | Worker 在提交前、提交后、轮询和下载阶段重启均可恢复。 |
| AC-EXE-005 | 下载失败复用 external task，不重新生成媒体。 |
| AC-EXE-006 | 批量部分失败保留成功项并只允许重试失败目标。 |
| AC-EXE-007 | 取消请求未确认时保持 unknown/cancel_requested 并可对账。 |
| AC-EXE-008 | 提供商账户撤销停止该连接新任务但不破坏其他连接。 |
| AC-EXE-009 | 任一 Attempt 可还原批准计划、请求、外部标识、状态和错误。 |

## 10. 指标与待确认项

指标包括排队时间、提交延迟、unknown 比例与持续时间、重试率、重复回调数、下载恢复率、按错误类型失败率和失败/未知资源消耗。每个 Provider 接入前必须签认幂等、回调、轮询、取消、数据保留和计量语义。
