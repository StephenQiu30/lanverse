# 分析需求

## 1. 需求概述

**需求目标：** 制作者能从真实事实了解当前项目进度和待处理内容。

**使用者与价值：** 作为制作者，我希望按一致口径了解项目进度与待处理内容，以决定接下来处理哪些镜头和任务。

**问题背景：** 统计卡和趋势来自样例，缺少来源、窗口、分母及真实跳转依据。

| 属性     | 内容                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 业务角色 | 制作者                                                                      |
| 文档状态 | 原始需求整理稿，待评审；不是已接受的设计或已验收功能                        |
| 范围来源 | 本文件第7、8节保留的原规格、现有页面代码，以及已整理的跨模块流程            |
| 完成依据 | 第3节功能结果、第4节质量条件、第5节验收场景；待确认项解决后才能验收相应能力 |

## 2. 范围与边界

本模块包含：统计卡、时间/分集口径、任务趋势、按模型结果、分集阶段、待处理与跳转。

提供当前项目真实进度、趋势与待处理；不新增独立经营报表或通知投递产品。

业务模块一份文档，内部需求编号仅用于追踪，不对应独立文件、接口、类或开发任务。编号不承诺排期。原资料中的存储名、组件名和分页建议不作为已接受架构。

## 5. 验收场景

下列是可执行的业务场景定义，尚未运行。实际测试按[生命周期方法](../软件生命周期与需求管理.md#测试与证据)记录环境、步骤、逐步预期与实际结果；功能行已给出独立验收条件，场景可联合验证多个相关功能。

| 场景            | 关联需求                         | 角色与初始条件                                     | 操作顺序                                      | 预期结果                                                 |
| --------------- | -------------------------------- | -------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------- |
| AC-ANALYTICS-01 | FR-ANALYTICS-01、FR-ANALYTICS-02 | 已确定公式且有成功/失败/未知任务与镜头的固定事实集 | 按时间/分集筛选→手工复算统计与趋势→核模型版本 | 分子分母窗口一致；P95方法按确认口径；阶段由实际事实计算  |
| AC-ANALYTICS-02 | FR-ANALYTICS-01、FR-ANALYTICS-02 | 零任务、未知数据源及局部故障三组条件               | 逐组查询同窗口                                | 真实0、无样本、未接入和故障可区分，带as_of，不伪造正常值 |
| AC-ANALYTICS-03 | FR-ANALYTICS-03、FR-ANALYTICS-04 | 有权待处理对象和已确认下载格式                     | 展开待处理→跳目标→下载相同筛选；试跨项目目标  | 数量/原因/目标可追踪，下载同源；越权失败                 |

质量验收还需执行第4节的权限、故障、边界及数据量验证，并记录自动化、真实持久化、浏览器与外部条件各自的证据。静态数据、成功提示与文档检查不构成产品验收。

## 6. 依赖、假设与待确认

依赖镜头/任务/版本事实；没有真实数据的指标明确未接入。

**原有待确认：** 阶段完成判据与分母；趋势展开/下载格式范围；待处理与通知入口关系。

**本轮发现的需求缺口：** 完成镜头与阶段判据、任务环比基期、成功率样本/排除项、P95方法、时间字段/时区与空分母显示。

**质量目标待确认：** 本模块适用设备/浏览器/版本、典型与边界数据规模、网络/冷热缓存条件、响应P50/P95、交互/Web Vitals与内存目标，以及格式/大小/并发/批量/导出限额须明确后才能质量验收。运行环境、可用性/维护窗口、数据用途/地域/保留及观测口径/日志策略仍待确认；不臆造SLA或规模。

这些问题统一纳入[总表缺口登记](01-需求总览.md#需求缺口与确认)，由产品负责人确认业务政策，工程/测试负责人补验证条件。责任角色尚未落实到人员，未给出答复的范围维持待确认；不自动新增平台、渠道或旧页面能力。
