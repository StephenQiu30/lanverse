> 对应模块：M11 资源配额与用量治理

## 1. 需求结论

资源治理回答“计划最多消耗什么、执行实际消耗什么、失败和重试消耗归因到哪里、何时必须停止或重新批准”。它不是商业计费系统，不产生客户价格、套餐、账单、支付、发票或收入确认。

所有用量必须使用明确数量和单位；提供商返回的实际费用可以作为运维对账值，但不能演化为客户账单事实。

## 2. 用户结果与范围

制片人和操作员在批准前看到项目/计划的预计区间和硬上限，在执行中看到预留、已消耗和剩余额度，在执行后按项目、内容单元、镜头、计划、Attempt 和错误类型解释实际资源。

本模块包含资源政策、配额、估计、预留、释放、实际用量、调整、异常和归因；不决定模型路由，不执行外部任务，也不承担商业收费。

## 4. 数量、单位与估计

用量使用 `quantity + unit` 表达，例如 token、image_generation、video_second、audio_character、gpu_second、storage_byte_day。不同单位不能在没有显式换算版本时相加。

Estimate 保存输入、能力、假设、区间、最大值和估计器版本。预留按批准最大值或策略值建立；实际用量来自提供商回报或可复核本地计量。若保存货币型提供商对账值，必须标记币种、来源和费率版本，并与客户价格模型隔离。

## 5. 预留、结算与调整规则

1. 同一计划项重复启动复用同一活动预留，不重复占用。
2. Attempt 可能消耗资源但未产生候选；不能只按成功产物计量。
3. unknown 状态保持预留或按保守政策冻结，不假设资源为零。
4. 用量和调整只追加；纠错通过补偿条目，不覆盖原记录。
5. 资源上限变化不追溯改写已批准计划，但会影响尚未启动的计划预检。
6. 资源治理拒绝不能通过切换入口、重试或 Agent 绕过。

## 6. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 估计不可用 | 不显示虚假精确值并按策略阻止/保守上限 | 重算或人工批准明确上限 |
| 并发预留冲突 | 一个成功，其余显示剩余额度变化 | 缩小计划或等待释放 |
| 提供商用量迟到 | 标记 provisional | 对账后追加实际条目 |
| unknown 长期未决 | 显示冻结资源和风险 | 人工对账或具名调整 |
| 用量矛盾 | 保留双方来源和差异 | 调查并追加调整 |
| 硬上限命中 | 停止新外部提交，不中断已收单任务 | 扩大授权或等待资源释放 |

## 7. 权限与审计

查看项目用量、修改资源政策、批准例外和录入人工调整分别授权。所有例外和调整记录主体、依据、原条目、影响范围和有效期；不得让普通操作员通过人工调整隐藏失败消耗。

## 10. 指标与待确认项

指标包括估计误差、预留利用率、硬上限阻止数、失败/unknown 消耗率、每交付分钟资源、对账差异和调整率。待确认各 Provider 单位映射、unknown 预留释放策略、组织/项目上限继承和货币对账值是否首期展示。
