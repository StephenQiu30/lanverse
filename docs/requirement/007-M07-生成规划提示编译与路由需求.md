> 对应模块：M07 生成规划、提示编译与路由

## 1. 需求结论

任何外部生成前都必须形成可审查、可冻结、可复现的 GenerationPlan。计划负责固定目标、输入版本、参考、编译提示、能力、模型、参数、资源区间、最大上限、权利结论和允许降级；计划批准不等于启动任务，也不等于采用结果。

## 2. 用户结果与范围

用户需要知道“将为哪些镜头生成什么、读取了哪些事实和参考、为什么选择该能力、会外发什么、最多消耗多少、失败后允许怎样处理”，然后选择批准并立即启动或仅冻结待后续启动。

本模块不执行供应商调用、不保存媒体结果、不自动选择候选，也不实现客户定价、套餐或账单。

## 4. 提示编译

提示编译从批准的 ShotPlan、实体状态、参考绑定、世界/风格规则、禁止项和提供商能力生成。自由文本 Prompt 是可读/可覆盖的编译产物，不是人物、镜头或风格的唯一事实源。

每次编译保存编译器版本、输入引用、规则优先级、被省略字段及原因、提供商限制、最终请求文本/结构和负向规则。人物秘密、完整剧本或无关项目数据不得因为“可能有帮助”而外发。

## 5. 路由与能力选择

Capability 至少声明媒体类型、模型、版本、输入限制、参考能力、时长/尺寸、地区、许可、内容策略、健康、用量单位和支持的恢复方式。

路由先过滤不满足硬约束的能力，再在允许集合中按质量目标、延迟、资源和用户偏好排序。人工覆盖只能选择仍通过权利和安全硬门禁的能力。

“一个图像能力 + 一个视频能力”只证明外部接入和耐久执行，不证明视频多模型路由。路由完成定义至少需要两个可替代的同类视频能力，覆盖选择理由、一个能力不可用、提示差异和批准范围内降级。

## 6. 状态与业务规则

GenerationPlan 为 `draft → preflight_ready | blocked → awaiting_approval → approved | rejected → superseded | cancelled`。提交、运行、完成、失败和 unknown 属于 M08 执行对象，不写回计划状态。

1. 预检结果绑定计划内容哈希和策略版本，任一输入变化后过期。
2. 批准命令必须显示批准人、资源上限、允许能力集合和 `start_now/hold`。
3. `hold` 计划启动前重新校验能力健康、权利和资源，但不静默改变冻结输入。
4. 批量计划允许部分 blocked，但已批准项和阻塞项必须分别可见。
5. 计划幂等键在冻结时确定，重复启动不能创建第二个逻辑任务。

## 7. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 缺少必要参考/状态 | 指向具体镜头和字段 | 返回 M04/M05 修正 |
| 能力已下线 | 原计划保留并标不可启动 | 创建替代路由计划 |
| 提示超过限制 | 显示被影响字段和编译诊断 | 调整镜头/规则或选择能力 |
| 资源超过上限 | 显示区间和超出量 | 缩小范围、改规格或重新批准 |
| 权利不允许外发 | 显示受限输入和政策依据 | 更换输入/能力或授权处理 |
| 批准后输入变化 | 原计划仍冻结并提示当前上下文不同 | 使用原计划或创建新计划 |

## 8. 非功能需求

| ID | 要求 |

| PLN-NFR-005 | 资源估计的误差、覆盖率和版本必须可统计。 |

## 9. 验收条件

| ID | 场景 |

| AC-PLN-007 | 任一计划可还原编译器、输入、规则、路由和估计依据。 |
| AC-PLN-008 | 两个同类视频能力下可以解释首选，故障时只在批准集合内降级。 |

## 10. 指标与待确认项

指标包括预检阻塞率、计划批准率、估计误差、路由覆盖率、人工覆盖率、提示编译人工修改率和计划过期率。待确认首批真实能力、允许的降级维度、资源估计置信表达和计划批准职责。
