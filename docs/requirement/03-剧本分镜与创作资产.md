# 剧本分镜与创作资产

## 1. 范围

本能力把已确认来源转成结构化剧本、最小角色/场景/风格资产和 6～10 个可执行 ShotSpec。AI 结果必须先作为提案，由操作者确认后才能进入图片、视频和 TTS 生产。

## 2. 主流程

1. 操作者基于已确认 SourceRevision 发起剧本生成。
2. 文本 Provider 返回符合固定 schema 的场次、动作、对白和旁白提案。
3. 操作者编辑并确认唯一当前 ScriptVersion。
4. 系统基于 confirmed ScriptVersion 同时形成角色/场景/风格 CreativeAssetVersion 草稿和含 6～10 个 ShotSpec 的分镜草稿。
5. 操作者编辑资产文字设定、镜头顺序、时长、提示和引用；确认分镜时原子确认其引用的 CreativeAssetVersion 与唯一当前 ShotSpecVersion。

## 3. 功能需求

| 编号 | P0 需求 | 验证 |
| --- | --- | --- |
| FR-002-001 | 系统应以明确 SourceRevision、文本 Provider、模型和 Prompt 版本生成结构化剧本提案。 | AC-002-001 |
| FR-002-002 | ScriptVersion 应包含有序场次；场次包含地点、时间、动作；每条对白/旁白语音条目包含稳定 speech_line_id、文本、所属场次、顺序和服务端批准的逻辑 voice_id，对白另含说话角色。 | AC-002-002 |
| FR-002-003 | 系统应允许操作者编辑提案并确认唯一当前 ScriptVersion；确认后修改必须创建新草稿版本。 | AC-002-003 |
| FR-002-004 | 系统应在分镜生成中为角色、场景和整体视觉风格建立稳定资产标识及 CreativeAssetVersion 草稿，允许编辑名称、类型和文字设定；被 confirmed ShotSpecVersion 引用后不得修改。 | AC-002-004 |
| FR-002-005 | 系统应根据当前剧本和资产生成 6～10 个有序 ShotSpec 提案，镜头稳定标识不得随排序变化。 | AC-002-005 |
| FR-002-006 | 每个 ShotSpec 应包含顺序、叙事目的、3～8 秒期望时长、画面提示、动作、对白/旁白引用及角色、场景、风格版本引用；时长使用 90,000 ticks/秒且必须对齐 24fps 帧边界。 | AC-002-006 |
| FR-002-007 | 系统应要求全部镜头期望时长之和为 30～60 秒、至少存在一条对白或旁白语音条目，且每条语音条目恰好归属一个镜头，才能确认分镜。 | AC-002-007 |
| FR-002-008 | 系统应允许编辑、排序、增加或删除 ShotSpec，并在确认时原子确认其引用的全部 CreativeAssetVersion 与唯一当前 ShotSpecVersion，不覆盖历史版本。 | AC-002-008 |
| FR-002-009 | 系统应把 AI 生成结果的 schema 校验失败、截断或缺字段显示为失败，不得保存为可确认提案。 | AC-002-009 |
| FR-002-010 | 来源或剧本当前版本变化后，系统应保留既有版本；受影响的下游资产、分镜、候选和已受理 Task 保持原内容、状态与快照，仅通过查询投影显示 `input_outdated=true`。 | AC-002-010 |

## 4. 业务规则

- BR-002-001：AI 调用成功不等于剧本或分镜已确认。
- BR-002-002：CreativeAssetVersion 的资产类型集合只有角色、场景和整体视觉风格。
- BR-002-003：ShotSpec 表达生产意图，不绑定供应商名称；具体能力在任务创建时确定并固定。
- BR-002-004：每个单集任一时刻只有一个当前确认剧本和一个当前确认分镜。
- BR-002-005：媒体结果不得反向静默修改剧本、资产设定、镜头目的或对白。

## 5. 数据要求

- DR-002-001：ScriptVersion 保存标识、父版本、来源版本、Provider/模型/Prompt 版本、origin Task、结构化内容及哈希、状态和时间戳。
- DR-002-002：CreativeAssetVersion 保存稳定资产标识、父版本、来源 ScriptVersion、origin Task、类型、名称、文字设定及哈希、`draft/confirmed/superseded` 状态和时间戳；`input_outdated` 单独计算，当前参考媒体由 generation 的 Adoption 表达。
- DR-002-003：ShotSpecVersion 是 Episode 级不可变分镜版本，保存标识、父版本、剧本版本、origin Task、资产版本集合、6～10 个有序 ShotSpec、内容哈希、总时长和状态；每个 ShotSpec 内含跨版本稳定的 `shot_id` 与自身 canonical content hash，同一版本内 `shot_id` 和 ordinal 分别唯一且 ordinal 为从 1 开始的连续整数。
- DR-002-004：ShotSpec 使用 90,000 ticks/秒的整数 `duration_ticks` 保存时长；24fps 下必须为 3,750 ticks 的整数倍，并以稳定标识引用语音条目和资产版本。

## 6. 异常与恢复

| 场景 | 必须行为 |
| --- | --- |
| 文本 Provider 失败或返回非法 JSON | 保留失败任务和诊断，不创建可确认 ScriptVersion。 |
| 剧本缺少对白归属 | 阻止确认并定位到具体场次或对白。 |
| 镜头数或总时长越界 | 阻止确认并返回实际值与允许范围。 |
| 已确认版本被编辑 | 创建新草稿，原版本及运行任务输入保持不变。 |

## 7. 验收标准

- AC-002-001：任一剧本提案可反查 SourceRevision、Provider、模型和 Prompt 版本。
- AC-002-002：契约测试验证场次、动作、speech_line_id、逻辑 voice_id、对白和旁白的必填字段、类型、归属及顺序；未知或克隆 voice_id 被拒绝。
- AC-002-003：确认剧本 A 后修改对白只产生草稿 B；A 及其下游引用不变。
- AC-002-004：分镜生成同时产生资产草稿；编辑资产只创建/更新尚未确认的版本，同名角色和场景在镜头间引用相同稳定标识及明确版本。
- AC-002-005：AI 提案含 6～10 个镜头；重复 `shot_id`、重复 ordinal 或不连续 ordinal 均被拒绝，合法重排后镜头标识不变而顺序更新。
- AC-002-006：缺少任一最小字段或时长未对齐 3,750 ticks 的 ShotSpec 无法确认；270,000/720,000 ticks 边界可通过并能序列化回读一致。
- AC-002-007：镜头数、单镜时长、总时长、语音条目数量或归属任一不合规时确认失败；边界值可通过。
- AC-002-008：确认分镜的事务同时确认其全部资产版本；任一步故障均全不确认；旧分镜/资产仍可读取，运行任务仍引用创建时版本。
- AC-002-009：非法、截断和缺字段三类 Provider 响应均进入失败状态且不产生可确认提案。
- AC-002-010：确认新来源或剧本后，仅直接受影响的下游版本、候选和 Task 显示 `input_outdated=true`；各对象状态枚举与 Task 快照不变，历史结果不被删除。
