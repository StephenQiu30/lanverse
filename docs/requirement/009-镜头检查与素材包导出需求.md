### 1.1 证据与产品决策边界

- **公开页面或已授权只读客户端可见事实：** VibeReels 客户端显示 Episode 下的有序 Shot、每镜多个视频版本、一个主版本、星标和逐镜版本批量下载；文件名可标记 selected／star。
- **尚未被公开证据证明：** 批量下载是否只取主选、压缩包内是否严格按镜头顺序、是否冻结选择和媒体版本、是否包含可复现 Manifest，以及是否存在服务端整集成片渲染。
- **Lanverse 产品推导：** 当前产品只交付逐镜原始视频素材包；导出必须先冻结目标 Shot 顺序、每镜显式 VideoSelection 和固定原始 Media；缺少显式主选时禁止以最新成功 Candidate 兜底；包内包含独立原始视频、JSON Manifest、CSV Manifest 和 README，不包含拼接视频或成片。

## 二、模块定位、目标与 KPI

### 2.1 模块定位

本模块回答两个问题：

1. 当前 Episode 的每个目标 Shot 是否已有明确、可用、与当前输入一致的视频主选？
2. 如何把这些主选按当前镜头顺序、以不修改原始媒体的方式交给外部后期？

它是“逐镜检查与素材交接”，不是剪辑和成片模块。

### 2.2 用户结果

导演或制作人应能：

1. 按选定目标 StoryboardBaseline 的固定顺序逐镜检查主选、缺失、过期和阻塞；
2. 从问题镜头跳转到 CUR-VID 显式更换主选；
3. 选择整集或一组明确 Shot 作为导出范围；
4. 在导出前看到完整阻塞和文件规模；
5. 原子冻结顺序、选择和媒体；
6. 获得包含独立原始视频、JSON、CSV 与 README 的可验证素材包；
7. 从历史记录重下同一包或基于新当前状态创建新导出。

### 2.3 KPI 与质量门槛

| 指标 | 当前目标 |
| --- | --- |
| 主选完整率 | 整集正式导出时目标 active Shot 100% 有唯一显式有效主选 |
| 最新成功候选兜底 | 0 次 |
| 文件—镜头映射正确率 | 100%；包内每个视频文件恰好对应一个冻结 Shot 和 Candidate |
| 顺序一致率 | 100%；Manifest 和文件名前缀均与冻结时镜头顺序一致 |
| 原始媒体保持率 | 100%；导出文件完整性摘要与被选 Candidate 原始媒体一致 |
| 历史漂移 | 0 次；导出后重排、重选或媒体状态变化不改写历史 Snapshot／Manifest |
| 阻塞解释率 | 100% missing、stale、blocked、unavailable 均定位到 Shot、Candidate／Media 和下一动作 |
| 素材包自说明率 | 100% 素材包同时包含 JSON Manifest、CSV Manifest 和 README |

## 三、范围与非范围

### 3.1 范围

- Episode 级有序镜头检查视图；
- 每镜当前主选播放、来源摘要、完整性和状态检查；
- missing、stale、blocked、unavailable 问题列表及跳转修复；
- 整集或显式 Shot 子集导出；
- 导出前预检与规模预估；
- 原子冻结 Storyboard 顺序、VideoSelection 和原始 Media；
- 包内独立原始视频文件；
- JSON Manifest、CSV Manifest 和 README；
- 导出任务进度、失败恢复、历史、过期提示和重下载；
- 文件完整性校验和审计追溯。

### 3.2 非范围

- 视频裁切、拼接、变速、转码、滤镜、调色和转场；
- 字幕、配音、音效、BGM、混音和任何音频处理；
- 时间线、连续预览文件、整集 MP4、成片渲染或发布；
- 自动替用户挑选候选、最新成功候选兜底或导出时静默跳过问题镜头；
- EDL、XML、AAF、剪映工程或其他专业剪辑工程文件；
- 商业下载额度、套餐、支付、账单和客户交付门户；
- 固定压缩库、对象存储、任务系统或下载协议。

### 3.3 不属于“成片”的明确说明

素材包即使包含一整集所有镜头，也只是按顺序编号的独立原始文件集合。系统不得：

- 额外生成一个拼接视频；
- 把浏览器依次播放称为“成片”；
- 修改时长、画幅、编码或音轨以制造一致性；
- 承诺外部播放器直接连续播放即可达到最终叙事节奏。

## 四、用户角色与权限意图

| 角色 | 核心任务 | 允许的产品动作 |
| --- | --- | --- |
| 导演／分镜师 | 逐镜确认当前采用版本 | 检查、播放、定位问题；通过 CUR-VID 显式更换主选 |
| 制作人／项目负责人 | 确认导出范围和交接版本 | 运行预检、冻结、创建素材包、查看历史和重下载 |
| 生成操作员 | 修复缺失或不可用候选 | 查看问题、跳转任务／候选，不得在导出时隐式代选 |
| 平台外后期接收者 | 使用 owner/editor 已下载并在平台外交接的离线素材 | 不是 Workspace 角色，在 Lanverse 内无读取、分享或下载动作 |
| 观察者 | 审阅状态 | viewer 只读查看检查结果、历史摘要和 Manifest 摘要，不返回原始文件或素材包 |

上述名称是制作 persona，不是新增授权角色。当前 CUR-IAM owner/editor 可运行预检、冻结、创建和下载素材包；viewer 不得下载原始候选或素材包。平台不提供外部接收者账号、匿名分享或受控公开下载；owner/editor 下载后在平台外自行完成交接。

## 六、依赖与交接

### 6.1 前置依赖

- Episode 必须存在一个有效、显式发布的目标 StoryboardBaseline、对应 OrderRevision 和完整有序 active Shot 集合；工作中未发布顺序不得用于正式冻结；
- 每个导出范围内的 Shot 必须有 CUR-VID 显式 VideoSelection；
- 被选 Candidate 必须属于同一 Shot，媒体 valid、可读取且完整性可验证；
- needs_reconfirmation、needs_reselection、未重新确认的 stale、blocked 或 unavailable 选择不得进入正式冻结；显式重新确认/重选后 Selection 恢复 selected，但 Snapshot/Manifest 必须保留相应决定和 warning；
- 项目和媒体访问权限必须在预检与实际下载时均有效。

### 6.2 对外交接原则

- 包内路径和 Manifest 共同说明顺序与来源；
- 接收者无需访问 Lanverse 页面也能知道每个文件属于哪个 Episode／Shot；
- 不在包中包含供应商凭据、临时访问地址、内部诊断正文或无关个人数据；
- 包内原始视频可由外部工具自行剪辑，但 Lanverse 不声明任何外部工程兼容性。

CUR-CAN 可将 ExportSnapshot、PackageBuild、逐镜问题与构建进度投影为节点和叠层，并跳转本模块预检/重建；画布不改变范围、冻结顺序或媒体。列表/详情仍可完成全部 P0 导出任务。

## 八、详细功能需求

### 8.1 CUR-EXP-FR-001 按目标基线固定顺序检查 Episode 镜头

**目标：** 在一个可扫描的列表中看清本次素材交接的完整范围。

**主流程：**

1. 用户进入 Episode 的镜头检查页；
2. 系统只读取目标 StoryboardBaseline 内冻结的 StoryboardOrderRevision；
3. 按顺序显示 Shot 编号、稳定标识、画面摘要、预计时长、当前视频主选、媒体状态和问题；
4. 用户可按 ready、missing_selection、stale、blocked、unavailable 筛选；
5. 页面汇总目标镜头数、ready 数、原始视频总时长和预计总字节。

**备选流程：**

- 用户可查看历史基线，但默认只读且不可误认为当前；
- 用户可在工作中预览新顺序，但历史基线始终使用自身冻结顺序；只有发布新 StoryboardBaseline 后，检查页才能把新顺序用于新的正式 ExportSnapshot，视频选择本身不因重排失效；
- 数据量大时可分页或虚拟化，但顺序和汇总必须完整。

**失败与恢复：**

- 任一依赖未知时显示 unavailable，不把未知镜头从总数中隐藏；
- 当前基线不存在时阻断检查并指向分镜发布；
- 刷新后恢复服务端顺序和状态。

**业务规则：**

- 列表顺序来自 StoryboardOrderRevision，不由 Candidate 创建时间决定；
- 当前视频只能来自 CUR-VID 的显式 VideoSelection；
- 镜号是冻结时可读标签，Shot ID 才是长期追溯身份。

### 8.2 CUR-EXP-FR-002 检查每镜当前主选并跳转修复

**目标：** 让用户逐镜确认“现在采用哪个视频”，但不在导出模块重复选择规则。

**主流程：**

1. 用户选择一个 Shot；
2. 系统播放当前显式主选并显示 Candidate、媒体、选择时间／人、固定输入和重新确认状态；
3. 用户查看其他候选摘要；
4. 若需更换，执行“前往候选选择”；
5. CUR-VID 完成显式选择后，用户返回并重新读取当前状态。

**备选流程：**

- 无主选时显示 missing_selection 和明确修复动作；
- 可逐镜上一条／下一条导航，但不拼接或保存连续播放结果；
- 播放器不可用时显示 blocked／unavailable 和原始媒体信息。

**失败与恢复：**

- 页面不得直接把最新成功或星标 Candidate 当当前视频；
- 候选选择并发变化时，返回页面必须显示服务端最新主选；
- 播放失败不自动更换 Candidate。

**业务规则：**

- 选择动作由 CUR-VID 拥有，本模块只消费结果并提供导航；
- 星标候选可显示，但不得出现在“当前采用”字段；
- “下一镜”只是检查导航，不是时间线。

### 8.3 CUR-EXP-FR-003 运行导出就绪度预检

**目标：** 在冻结前一次性列出全部阻塞，避免生成残缺包。

**主流程：**

1. 用户选择整集或当前候选 Shot 子集；
2. 系统读取目标基线、完整顺序、每镜 VideoSelection 和媒体；
3. 对每个目标 Shot 校验 active、唯一显式主选、选择已针对当前输入确认、Candidate valid、媒体可读和完整性；
4. 计算文件数量、总字节、总原始时长和格式分布；
5. 返回 ready、warning 或 blocked 及逐镜问题和下一动作。

**备选流程：**

- Shot 子集只要求子集全部 ready；
- 不同原始容器或画幅可作为 warning，因为当前产品不转码；
- 超出单包限制时可缩小范围或创建多个显式导出，不静默拆包。

**失败与恢复：**

- 任一目标 Shot 无主选时必须 blocked，不使用最新成功 Candidate；
- 媒体读取未知时 unavailable，不继续冻结；
- 预检不创建 Snapshot 或包。

**业务规则：**

- `scope=complete` 必须包含目标基线的全部 active Shot；`scope=partial` 必须包含用户显式选择的非空 active Shot 子集；
- 系统不得静默排除 failed、missing 或 blocked Shot；
- warning 确认必须保留决定人和理由。

### 8.4 CUR-EXP-FR-004 选择整集或明确 Shot 子集

**目标：** 允许用户按制作需要导出整集或局部镜头，同时保持 Episode 顺序。

**主流程：**

1. 用户选择“整集”或“选择镜头”；
2. 选择镜头时在当前有序列表中勾选目标 Shot；
3. 系统显示选择数量、Episode 原始位置和预计规模；
4. 用户确认范围；
5. 系统保存明确范围供预检与冻结。

**备选流程：**

- 子集可连续或不连续；
- 子集包内使用连续文件序号，同时 Manifest 保存原 Episode 顺序号；
- 用户可全选、清空或只看问题镜头。

**失败与恢复：**

- 空范围不得提交；
- 包含归档、重复或其他 Episode 的 Shot 时拒绝；
- 选择过程中顺序变化时提示刷新并重新确认。

**业务规则：**

- 用户不能在导出页面自定义新顺序；如需改变，应回到 CUR-SBD 重排；
- 子集是显式范围，不代表其他 Shot 被删除或已交付；
- 当前范围必须固定 Shot ID，而不是仅保存镜号。

### 8.5 CUR-EXP-FR-005 原子冻结顺序、选择和媒体

**目标：** 形成不会被后续重排、重选或媒体变化篡改的导出事实。

**主流程：**

1. 用户基于有效预检确认创建导出；
2. 系统重新校验目标基线、顺序修订、Shot 范围、每镜 VideoSelection 和 Media；
3. 全部一致时，一次性创建 ExportSnapshot；
4. Snapshot 为每个 Shot 固定 Episode 顺序、ShotSpecVersion、Selection、Candidate、Media、原始路径信息和完整性摘要；
5. 冻结完成后进入素材包构建。

**备选流程：**

- 用户确认 warning 时，Snapshot 保存警告和理由；
- 基于同一当前状态再次导出仍产生新的、可区分的 Snapshot；
- 可从历史 Snapshot 重新构建包，不重新读取当前选择。

**失败与恢复：**

- 预检后任一顺序、选择、媒体或输入确认变化，冻结冲突且零 Snapshot；
- 冻结成功后当前主选变化不影响该 Snapshot；
- Snapshot 必须包含本次 ExportScope 中的全部目标 Shot；`partial` 可以不含范围外 Shot，但不得遗漏范围内任一项。任一目标项失败则整体不冻结。

**业务规则：**

- 冻结是正式导出的单一事实边界；
- Snapshot 不保存会漂移的“current”引用；
- 不得在冻结时使用最新成功 Candidate 兜底或修改 VideoSelection。

### 8.6 CUR-EXP-FR-006 构建独立原始视频素材包

**目标：** 将冻结媒体无修改地组织成可下载素材包。

**主流程：**

1. 系统按 ExportSnapshot 的冻结顺序读取每个原始视频；
2. 逐文件核对完整性摘要；
3. 使用三位顺序前缀和稳定 Shot／Candidate 短标识生成包内文件名；
4. 将所有独立原始视频放入 videos 目录；
5. 加入 manifest.json、manifest.csv 和 README.md；
6. 完成包级完整性检查并将导出标记 ready。

**备选流程：**

- `partial` 导出使用 001～N 的包内连续序号，同时 Manifest 保存 episode_order，并列出 included/excluded 数量与 Shot ID；
- 不同原始扩展名保持不变；
- 产品可提供目录式下载或 ZIP，若为 ZIP 只做封装，不改变内部视频字节。

**失败与恢复：**

- 任一冻结媒体丢失、摘要不匹配或不可读取时整个包失败，不用其他 Candidate 替换；
- 构建中断可从同一 Snapshot 恢复；
- 部分临时产物不得暴露为 ready 下载。

**业务规则：**

- 包内每个视频必须与冻结原始媒体逐字节一致；
- 当前素材包每个目标 Shot 只包含冻结时的唯一主选；星标备选不随包导出；
- 禁止裁切、拼接、转码、变速、抽取／删除音轨或写字幕；
- 禁止额外生成整集视频；
- 包内建议目录如下：
  - videos/001_镜头短标识_候选短标识.原扩展名
  - videos/002_镜头短标识_候选短标识.原扩展名
  - manifest.json
  - manifest.csv
  - README.md

### 8.7 CUR-EXP-FR-007 生成 JSON、CSV Manifest 与 README

**目标：** 让素材包无需依赖产品页面也可理解、核对和自动处理。

**主流程：**

1. 系统从 ExportSnapshot 生成结构化 JSON；
2. 生成一镜一行的 CSV；
3. 生成面向人的 README；
4. 核对三者的 Shot 数量、顺序、文件路径和摘要一致；
5. 作为同一素材包发布。

**备选流程：**

- 部分导出在三份文件中明确标记 `scope=partial`，并列出 included/excluded 数量与 Shot ID；
- warning 和人工确认以结构化字段和 README 摘要同时表达；
- 中文名称保留用于阅读，稳定 ID 用于机器追踪。

**失败与恢复：**

- 任一 Manifest 与 Snapshot 不一致时包不得 ready；
- CSV 中包含换行、逗号或 Unicode 时必须保持可正确解析；
- README 生成失败不能只交付视频文件。

**业务规则：**

- JSON 顶层至少包含：格式版本、Export ID、`snapshot_created_at`／冻结人、Project、Episode、目标基线、范围、冻结顺序摘要、文件数、总字节、总时长、警告和逐镜条目；不得写入 PackageBuild 创建/完成时间等重建会变化的字段；
- 每镜 JSON 条目至少包含：package_order、episode_order、Shot ID、显示镜号、ShotSpecVersion、VideoSelection、Candidate、Media、包内路径、原文件名／扩展名、大小、时长、宽高、完整性摘要、选择人／时间、输入匹配状态和来源追踪摘要；
- CSV 至少包含上述可扁平化的逐镜字段，一镜一行，顺序与 JSON 一致；
- README 至少说明：这是原始逐镜素材而非成片、范围和顺序规则、目录说明、如何用摘要校验、不同格式／画幅警告、音频未处理声明、Snapshot 冻结时间和 Export ID；PackageBuild 时间只在平台历史元数据中显示，不进入要求跨重建相同的 Manifest/README 内容；
- Manifest 不包含供应商凭据、临时访问地址或内部敏感诊断。

### 8.8 CUR-EXP-FR-008 查看导出历史、校验与重下载

**目标：** 让团队区分不同素材版本，并能复查当时选择。

**主流程：**

1. 用户查看 Episode 的导出历史；
2. 每条记录分别显示 ExportSnapshot 的冻结人/时间与 PackageBuild 的创建/完成时间，并显示 Export ID、PackageBuild ID、范围、目标基线、Shot 数、总字节、状态和由 CUR-SEC 数据生命周期策略给出的 `retention_at`；
3. 用户打开详情查看冻结顺序、Candidate／Media 和 Manifest；
4. 在 `retention_at` 前重下载同一 ready PackageBuild；
5. 系统提供 container hash 和文件级 Manifest 供校验。

**备选流程：**

- 当前已发布 StoryboardBaseline/OrderRevision 或主选已变化时，历史记录显示“与当前不同”，但不标记历史错误；工作中未发布顺序不参与该比较；
- 包已过期但 Snapshot 仍在时，可明确请求基于同一 Snapshot 创建新 PackageBuild，不复用或覆盖旧记录；
- 用户可复制 Export ID 进行外部交接说明。

**失败与恢复：**

- 无下载权限时可按权限查看摘要，但不返回文件；
- 历史包损坏或摘要不匹配时标记 unavailable 并停止下载；
- 重下载不得基于当前主选临时重建不同内容。

**业务规则：**

- ExportSnapshot、Manifest、PackageBuild 记录和 ready 包字节的保留、归档或删除必须遵循 CUR-SEC 按业务引用、对账／申诉、安全事件与 legal hold 等维度给出的 DataLifecycleDecision，本模块不设全局固定天数；
- 历史列表和详情必须向用户显示当前 `retention_at`；策略变化可更新保留状态，但不得改写旧 Snapshot、Manifest、PackageBuild 内容或摘要；
- `retention_at` 前重下同一 PackageBuild 必须返回同一容器字节和 container hash；
- 基于历史 Snapshot 重建时必须创建新 PackageBuild；Manifest 内容和每文件 hash 必须与原构建一致，container hash 可因容器封装差异而不同，旧 PackageBuild 记录及其 hash 不得被覆盖；若冻结原始媒体已不可用则明确失败。

### 8.9 CUR-EXP-FR-009 处理导出失败、恢复和过期

**目标：** 在大文件或中断场景下保持 Snapshot 与交付结果一致。

**主流程：**

1. 用户创建导出后查看 PackageBuild 的 requested、validating、packaging、ready、failed 或 expired 状态；ExportSnapshot 创建即 frozen 且不属于 PackageBuild 流程状态；
2. 系统显示当前阶段、已处理文件数／总数、失败对象和下一动作；
3. 可恢复失败基于同一 Snapshot 重试；
4. 成功后只暴露完整 ready 包；
5. 到期后将当前 PackageBuild 显示为 expired，不改写其历史内容与 hash；历史 Snapshot、Manifest 和 PackageBuild 记录的继续保留、归档或删除遵循 CUR-SEC DataLifecycleDecision。

**备选流程：**

- 下载中断由客户端重新请求同一 ready 包，不创建新 Snapshot；
- 包超过单包限制时预检即阻断，引导缩小范围；
- 重新构建历史 Snapshot 形成新 PackageBuild 记录，不覆盖旧记录，两者的业务内容仍指向同一 Snapshot。

**失败与恢复：**

- Snapshot 冻结失败不得进入 packaging；
- packaging 失败不得回退读取当前主选；
- 媒体摘要变化必须失败并指明具体文件；
- 过期不得覆盖旧 PackageBuild 记录；历史审计和 Manifest 摘要的保留、归档或删除遵循 CUR-SEC DataLifecycleDecision。

**业务规则：**

- ExportSnapshot 状态一旦 frozen，其内容不可修改；
- retry 只恢复包构建，不重新选择媒体；
- 同一 PackageBuild 重下必须保持 container hash；过期重建必须新建 PackageBuild 并保持 Manifest 与逐文件 hash，不覆盖旧记录；
- 用户想采用新顺序或新主选时必须创建新的 ExportSnapshot。

## 九、实体、状态机与不变式

### 9.1 产品实体

| ID | 实体 | 产品含义 |
| --- | --- | --- |
| CUR-EXP-ENT-001 | ShotInspectionReport | 目标基线下逐镜主选、媒体和问题的派生报告 |
| CUR-EXP-ENT-002 | ExportScope | `complete`（目标基线全部 active Shot）或 `partial`（显式非空 active Shot 子集） |
| CUR-EXP-ENT-003 | ExportPreflight | 冻结前的完整就绪度、规模、警告和输入摘要 |
| CUR-EXP-ENT-004 | ExportSnapshot | 原子冻结目标 StoryboardBaseline/OrderRevision、ExportScope、有序 Shot ID、每镜 ShotSpecVersion、VideoSelection、Candidate、Media 字节版本/hash、重新确认/warning、冻结人和时间 |
| CUR-EXP-ENT-005 | PackageBuild | 一次基于固定 ExportSnapshot 构建具体素材包的不可覆盖记录，含构建时间、状态、container hash 与 retention_at；同一 Snapshot 可有多个 Build |
| CUR-EXP-ENT-006 | ExportFileEntry | 包内一个文件的路径、媒体来源和完整性证据 |

### 9.2 状态机

- PackageBuild：requested → validating → packaging → ready；validating／packaging 可进入 failed，ready 可进入 expired。重试恢复同一 Build 的安全步骤；过期重建产生新 PackageBuild，不回退或覆盖旧记录。
- ExportSnapshot：创建即 frozen 且不可变；不因 Package failed 或 expired 改写。
- 单镜检查：ready、missing_selection、stale、blocked、unavailable。

### 9.3 核心不变式

1. 正式导出只读取显式 VideoSelection，永不使用最新成功 Candidate 兜底。
2. 每个目标 Shot 在冻结时必须恰有一个有效主选。
3. ExportSnapshot 同时固定目标 StoryboardBaseline/OrderRevision、ExportScope、有序 Shot ID、每镜 ShotSpecVersion、VideoSelection、Candidate、Media 字节版本/hash、重新确认/warning、冻结人和时间。
4. 冻结后当前重排、重选或媒体状态变化不得改写历史 Snapshot。
5. 包内每个视频文件必须与冻结原始媒体逐字节一致。
6. 包内顺序、JSON、CSV 和文件名前缀必须一致。
7. 任一目标文件失败时不得发布残缺 ready 包。
8. 不静默跳过问题 Shot，不静默拆包，不静默替换 Candidate。
9. 不生成裁切、拼接、转码、字幕、音频或成片结果。
10. 新顺序或新选择只能通过新 ExportSnapshot 导出。
11. ExportSnapshot 的冻结时间属于不可变 Manifest；PackageBuild 创建/完成时间属于 Build 历史元数据，不得写入要求跨重建相同的 Manifest/README。

## 十、接口与文件需求

### 10.1 产品接口

| ID | 产品接口 | 必需输入 | 必需输出 |
| --- | --- | --- | --- |
| CUR-EXP-IF-001 | 镜头检查读取 | Episode、目标基线、筛选 | 有序 Shot、当前主选、媒体状态、问题和汇总 |
| CUR-EXP-IF-002 | 单镜检查／修复导航 | Shot、当前 Selection | Candidate 来源、选择证据、播放器状态和 CUR-VID 跳转 |
| CUR-EXP-IF-003 | 范围与预检 | 整集／Shot ID 集合、目标基线 | 完整 ready／warning／blocked、规模和输入摘要 |
| CUR-EXP-IF-004 | 冻结创建 | 有效预检、期望顺序／选择／媒体摘要 | 不可变 ExportSnapshot 或零写入冲突 |
| CUR-EXP-IF-005 | 包构建与状态 | ExportSnapshot | 阶段、文件进度、失败、ready PackageBuild、container hash 和 `retention_at` |
| CUR-EXP-IF-006 | 历史与重下载 | Episode／Export ID、权限 | 历史摘要、PackageBuild ID、Manifest、container hash、`retention_at`、下载或到期状态 |
| CUR-EXP-IF-007 | 历史 Snapshot 重建 | ExportSnapshot、明确重建意图 | 指向同一 Snapshot 的新 PackageBuild（Manifest／逐文件 hash 相同，container hash 可不同）或缺失媒体清单 |

### 10.2 包与文件命名

- 包名应包含可读 Project／Episode 标识和 Export ID，并避免仅依赖可变名称；
- 包内视频使用三位 package_order 前缀；同一包内不得重名；
- 保留每个原始视频扩展名；
- JSON 文件固定命名 manifest.json；
- CSV 文件固定命名 manifest.csv；
- 人类说明固定命名 README.md；
- 文件名非法字符应以确定、可逆说明的方式规范化，原文件名仍保存在 Manifest；
- 文件名和目录不得包含访问令牌、供应商任务密钥或敏感提示词正文。

### 10.3 Manifest 一致性

- JSON、CSV 和 README 的 Export ID、范围、镜头数和冻结时间必须一致；
- JSON 与 CSV 的逐镜行数、package_order、episode_order、Shot ID、Candidate ID、文件路径和摘要必须一致；
- Manifest 列出的每个视频必须存在，包内不得存在未列出的额外视频；
- container hash 在每个 PackageBuild ready 后生成，用于验证同一 PackageBuild 的重下载；历史重建的新 PackageBuild 保持 Manifest 和逐文件 hash，但不要求 container hash 与旧构建相同。

## 十二、异常与恢复总则

| 异常 | 产品行为 |
| --- | --- |
| 目标 Shot 无显式主选 | 预检 blocked；跳转 CUR-VID，禁止兜底 |
| Selection stale／待重新确认 | 预检 blocked；要求人工重审 |
| 冻结前顺序或主选变化 | 版本冲突，零 Snapshot |
| 冻结后当前状态变化 | 历史 Snapshot 不变，包继续使用冻结媒体 |
| 冻结媒体丢失／摘要不符 | 包构建 failed，定位文件；不换其他 Candidate |
| 包构建中断 | 基于同一 Snapshot 恢复 |
| 下载中断 | 重下同一 ready 包，不新建导出 |
| 包到期 | 按 CUR-SEC DataLifecycleDecision 保留历史事实；媒体仍可用时按同一 Snapshot 新建 PackageBuild，不覆盖旧记录 |

ZIP 与目录式逐文件下载的载体选择只由跨模块 `CUR-DEC-001` 跟踪，本模块不建立第二个决策事实源。

### 14.1 已决策事项

- `scope=complete` 覆盖目标 StoryboardBaseline 的全部 active Shot；`scope=partial` 是显式非空子集，两者都按该基线固定 OrderRevision 排序。
- 正式包每个目标 Shot 只包含唯一冻结主选；星标备选不随包导出，也不存在 latest-success fallback。
- 导出保持原始视频全部字节，包括原文件已有音轨；不得裁切、拼接、转码、抽取/删除音轨或添加字幕。
- 同一 PackageBuild 重下载保持容器字节和 container hash；过期后从同一 Snapshot 重建必须新建 PackageBuild，Manifest/逐文件 hash 相同而 container hash 可不同。
- ExportSnapshot 与 PackageBuild 分离：Snapshot 固定业务内容和冻结时间，Build 记录每次具体构建时间/状态；重建时 Manifest/README 不写入变化的 Build 时间。
- viewer 只读检查和历史/Manifest 摘要，不下载原始候选或包；平台不提供外部账号或匿名分享，owner/editor 下载后在平台外交接。

## 十五、术语

| 术语 | 定义 |
| --- | --- |
| 镜头检查 | 按当前分镜顺序查看每镜显式主选和问题，不是时间线播放 |
| ExportScope | 整集或显式 Shot 子集 |
| ExportPreflight | 冻结前对顺序、主选、媒体和规模的只读检查 |
| ExportSnapshot | 一次原子冻结目标基线/顺序、范围、有序 Shot、ShotSpecVersion、Selection、Candidate、Media/hash、重新确认/warning、冻结人和时间的事实 |
| PackageBuild | 一次基于固定 ExportSnapshot 生成的具体包构建记录；同一 Snapshot 可因过期重建拥有多个不可覆盖的 PackageBuild |
| container hash | 某一 PackageBuild 的完整容器字节摘要；同一 PackageBuild 重下不变，同 Snapshot 的不同 PackageBuild 可不同 |
| retention_at | 由 CUR-SEC DataLifecycleDecision 给出、必须向用户显示的当前包字节保留截止时间 |
| package_order | 当前包内从 1 开始的连续顺序 |
| episode_order | 冻结时 Shot 在 Episode 中的原始顺序 |
| 原始视频 | 被选 Candidate 登记的原始媒体字节，未经裁切、拼接或转码 |
| latest-success fallback | 在缺少显式主选时自动采用最近成功 Candidate；当前产品严格禁止 |
