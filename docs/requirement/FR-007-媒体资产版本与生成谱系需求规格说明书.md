# FR-007 媒体资产版本与生成谱系需求规格说明书

## 1. 目的与范围

管理参考素材和生产媒体的文件版本、代理文件、来源、派生关系、完整性和生成谱系，使任一候选或交付文件可追溯到输入与生产上下文。

## 2. 主业务流程

1. 用户上传媒体，或制作任务产生媒体结果。
2. 系统检查类型、大小、完整性、哈希和重复项。
3. 系统把媒体关联到稳定资产身份并创建不可变版本。
4. 生成媒体记录模型能力、输入版本、参数、成本和输出哈希。
5. 系统创建必要代理文件和媒体摘要。
6. 下游镜头、候选、时间线和交付引用明确媒体版本。

## 3. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-007-001 | 系统应在媒体被修改、替换、派生或重新生成时创建新版本。 | P0 |
| FR-007-002 | 系统应保留前序版本、关键参考、创建主体和创建方式。 | P0 |
| FR-007-003 | 系统应禁止新版本覆盖仍被内容、任务、审核、采用或交付引用的旧版本。 | P0 |
| FR-007-004 | 系统应计算媒体内容哈希并识别重复上传或重复返回。 | P0 |
| FR-007-005 | 系统应在媒体存储地址变化后保持资产身份和业务引用。 | P0 |
| FR-007-006 | 系统应支持原始文件与代理文件分离，并保持版本对应关系。 | P0 |
| FR-007-007 | 系统应保存媒体类型、尺寸、分辨率、帧率、时长、音轨、色彩和编码摘要。 | P0 |
| FR-007-008 | 系统应从生成媒体追溯到项目、镜头、任务、尝试和输入版本。 | P0 |
| FR-007-009 | 系统应记录生成能力、模型版本、提示摘要、参数、种子、许可证快照、成本引用和输出哈希。 | P0 |
| FR-007-010 | 系统应允许登记平台外产生的媒体，并明确外部来源和未知字段。 | P0 |
| FR-007-011 | 系统应支持从任一媒体版本反查候选、审核、采用、时间线和交付使用。 | P0 |
| FR-007-012 | 系统应为不可访问、损坏或隔离媒体保留引用并标识阻塞。 | P0 |

## 4. 业务规则

- BR-007-001：媒体文件不是业务资产身份。
- BR-007-002：未知谱系必须明确为未知，不得由系统推断补全。
- BR-007-003：候选、审核和采用状态由各自模块维护，媒体版本只关联这些事实。
- BR-007-004：媒体在模块间流转时必须保持稳定版本身份和完整性证据，不得产生无法追溯来源的副本。

## 5. 数据要求

- DR-007-001：保存媒体版本、父版本、哈希、媒体摘要、存储引用和代理关系。
- DR-007-002：生成媒体保存能力、模型、工作流、插件、提示、参数、种子、输入、成本和输出哈希。
- DR-007-003：保存隔离、损坏、停用、替代和删除生命周期记录。

## 6. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 新文件与已有版本哈希相同 | 提示复用，避免建立无意义副本。 |
| 供应回调重复返回 | 按尝试和输出哈希去重，不重复创建候选。 |
| 代理与原始文件不一致 | 阻止正式输出，并要求重建或重新校验。 |
| 来源链部分不可得 | 允许受限登记，明确未知并限制用途。 |

## 7. 验收标准

- AC-007-001：替换媒体时创建新版本，历史镜头仍引用原版本。
- AC-007-002：同一供应结果重复回调不会产生重复媒体或重复消费。
- AC-007-003：任一交付视频可反查所用镜头媒体及其生成输入和模型版本。
- AC-007-004：媒体位置迁移后，项目引用和谱系保持有效。
