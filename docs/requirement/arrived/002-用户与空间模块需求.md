# REQ-002 用户与空间模块需求

- 状态：S1 accepted
- 输入：[REQ-001 平台总体需求](../001-平台总体需求概述.md)
- 输出：身份映射、Workspace、Membership、角色和 ActorContext 需求
- 下游：REQ-003 至 REQ-010

## 1. 需求概述

用户与空间模块负责本地账号注册、注册邮箱所有权验证、密码登录、JWT 签发与注销，并为所有业务操作提供 Workspace 隔离和最小角色权限。模块不承担项目内容、任务、计费、通知邮件、找回密码邮件或短信业务。

MVP 优先支持单个用户注册后立即获得个人 Workspace 并完成创作；成员邀请延后，但 Membership 和角色边界必须从第一版成立。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| IDN-ENT-001 | UserAccount | 必须以规范化邮箱作为登录唯一键，保存 Argon2 密码摘要、显示资料、状态、令牌版本和最近登录时间；不得保存明文密码。 |
| IDN-ENT-002 | Workspace | 必须保存名称、拥有者语义、状态和必要时间；是业务数据与额度隔离边界。 |
| IDN-ENT-003 | Membership | 必须唯一关联 UserAccount 与 Workspace，角色仅允许 owner/editor/viewer，并保留加入与移除事实。 |
| IDN-ENT-004 | ActorContext | 必须由已验证身份、当前 Workspace 和有效 Membership 计算，是请求级只读上下文，不是第二份用户记录。 |

UserAccount ID 是跨业务引用的唯一稳定标识。邮箱用于登录且修改必须经过重新验证；手机号和显示名称不得作为业务外键。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| IDN-FR-001 | 首次注册必须原子创建 UserAccount、个人 Workspace 和 owner Membership；重复邮箱不得重复创建。登录必须只验证已有账号并签发短期 JWT。 |
| IDN-FR-002 | 用户必须能登录、注销、修改密码，并读取和修改自己的显示名称、头像等平台资料；邮箱修改不进入 MVP。 |
| IDN-FR-003 | 用户必须能列表、创建、读取、修改、归档和恢复自己有权管理的 Workspace。 |
| IDN-FR-004 | 用户必须能选择当前 Workspace；服务端必须验证其 Membership 仍有效。 |
| IDN-FR-005 | [P1] owner 必须能查看成员、修改 editor/viewer 角色并移除成员；不得移除或降级最后一个 owner。 |
| IDN-FR-006 | viewer 只能读取；editor 能进行创作和审核；只有 owner 能管理 Workspace、成员和预算上限。 |
| IDN-FR-007 | 归档 Workspace 后必须禁止新建或修改业务事实及提交生成，但允许授权用户读取历史和交付物。 |
| IDN-FR-008 | 用户必须能停用自己的平台账户；停用不得删除其创建的项目、版本、任务、费用或审核历史。 |
| IDN-FR-009 | 新账号注册必须先通过 6 位邮箱验证码确认邮箱所有权并取得短期一次性注册票据；验证码、票据和重发冷却必须短期保存且不可绕过。现有账号登录不得依赖 SMTP 或 Redis。 |

成员邀请、接受邀请和过期处理属于 P1；进入 P1 时必须扩展 Membership 生命周期，不得建立第二套“项目成员”身份体系。

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| IDN-IF-001 | 注册/登录/注销 | 邮箱、密码、允许的资料字段或当前 JWT | 注册返回账号与个人空间；登录返回短期 JWT；凭据无效统一返回未认证；注销使当前账号既有 JWT 失效 |
| IDN-IF-002 | 读取/修改当前资料 | ActorContext、允许修改的资料字段 | 更新后的用户；身份键字段出现时返回输入无效 |
| IDN-IF-003 | Workspace 列表/详情 | 当前用户、分页、是否包含归档 | 仅返回存在有效 Membership 的 Workspace |
| IDN-IF-004 | 创建/修改 Workspace | 名称等允许字段 | Workspace 和 owner Membership；重名不作为全局冲突 |
| IDN-IF-005 | 归档/恢复 Workspace | Workspace ID、期望当前状态 | 新状态；状态不匹配或无 owner 权限返回冲突/禁止访问 |
| IDN-IF-006 | [P1] 成员列表/改角色/移除 | Workspace ID、Membership ID、目标角色 | 最新成员列表或阻塞原因；最后 owner 操作必须失败 |
| IDN-IF-007 | 内部权限检查 | ActorContext、能力、资源 Workspace ID | 允许或拒绝；拒绝不得泄露其他 Workspace 是否存在 |
| IDN-IF-008 | 发送/确认注册验证码 | 规范化邮箱；邮箱与 6 位验证码 | 发送返回通用接受结果；确认返回短期一次性注册票据；已注册邮箱、过期、错误次数、冷却和依赖故障使用稳定且不可枚举的结果 |

除登录成功响应外，接口输出不得包含访问令牌；任何接口和日志均不得返回密码、密码摘要、JWT 签名密钥或其他用户的非必要个人信息。

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| IDN-NFR-001 | 安全 | 密码必须使用 Argon2；登录失败使用统一响应和虚拟摘要校验；JWT 必须验证固定算法、签名、发行方、受众、类型、有效期、subject 和令牌版本，不得仅解码不验证。 |
| IDN-NFR-002 | 隔离 | 所有后续模块的公开接口必须使用同一 ActorContext 规则，跨 Workspace 访问测试必须覆盖。 |
| IDN-NFR-003 | 最小权限 | 默认角色不得拥有 owner 权限；权限拒绝必须发生在读取业务详情之前。 |
| IDN-NFR-004 | 一致性 | 注册创建的三个事实必须原子成功或全部失败；注销、修改密码和账户停用必须递增令牌版本以立即撤销既有 JWT；Membership 角色更新不得产生无 owner 窗口。 |
| IDN-NFR-005 | 审计 | 登录映射、账户停用、Workspace 生命周期和成员变更必须记录 actor、目标、前后状态和时间。 |
| IDN-NFR-006 | 隐私 | 日志不得记录令牌、完整身份声明或非必要个人信息；个人数据导出/删除范围在上线地区确认。 |
| IDN-NFR-007 | 性能 | ActorContext 解析不得调用其他业务模块；认证只依赖本服务和 PostgreSQL，Redis 故障不得导致无法登录。 |
| IDN-NFR-008 | 注册验证 | 验证码只保存与邮箱及注册用途绑定的 HMAC 摘要，10 分钟过期、60 秒重发冷却、最多 5 次错误；票据至少 32 字节、10 分钟过期且只能消费一次。SMTP、Redis、日志和前端均不得持久化或暴露不必要的验证码、票据和凭据。 |

## 6. 生命周期与失败路径

- UserAccount：`active → deactivated`；重新启用必须经过明确账户恢复流程，不能仅凭再次登录自动恢复。
- Workspace：`active ↔ archived`；存在运行中任务时归档应先阻止新命令，并明确现有任务的处理结果。
- Membership：`active → removed`；历史审计仍引用原 Membership/UserAccount ID。
- JWT：`issued → expired|revoked`；账号令牌版本变化后，旧版本 JWT 立即失效。
- 注册挑战：`pending → verified|expired|attempts_exhausted`；确认后签发的票据 `issued → consumed|expired`，任一终态都不可恢复为可用。

## 7. 非目标与待确认

- MVP 只实现注册邮箱所有权验证，不实现邮件/短信找回密码、MFA、第三方登录、设备管理或细粒度会话列表；已登录用户可修改密码，管理员恢复流程留待运营后台任务。
- 不实现 SCIM、部门、用户组、自定义角色、项目级 ACL 和外部审片账号。
- 注册发信复用已确认的 SMTP 配置；公开找回密码仍需单独设计，个人数据请求和 Workspace 归档后运行任务策略仍待确认。
