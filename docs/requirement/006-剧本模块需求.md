# REQ-006 剧本模块需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`003-项目模块需求.md`、`005-审核治理模块需求.md`
- 输出：剧本来源、版本、结构化内容、AI 提取和候选决议需求
- 下游：REQ-007、REQ-008

## 1. 需求概述

剧本模块必须把用户原文转化为可版本化、可审核的单集内容基线，并通过 AI 提取辅助形成场景、对白及资产/镜头候选。AI 输出先是候选，只有用户决议后才能创建或关联下游事实。

模块不直接拥有 AssetVersion、ShotSpecVersion 或 GenerationRequest；它只保留提取来源、候选和决议证据。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| SCR-ENT-001 | ScriptSource | 必须归属 Episode，记录输入类型、原始来源、标题、权利声明和必要媒体引用。 |
| SCR-ENT-002 | ScriptVersion | 必须是不可变正文版本，保存版本号、来源、创建人、结构化结果摘要和内容 hash。 |
| SCR-ENT-003 | Scene | 必须在 ScriptVersion 内具有稳定 ID、顺序、地点/时间、剧情摘要和对白引用；跨版本不假设 ID 自动相同。 |
| SCR-ENT-004 | Dialogue | 必须记录说话主体候选、文本、类型、情绪/表演提示和所属 Scene；确认主体前允许未解析。 |
| SCR-ENT-005 | ExtractionBatch | 必须绑定一个 ScriptVersion、提取能力/规则版本、Task、状态和完成摘要。 |
| SCR-ENT-006 | ExtractionCandidate | 必须记录候选类型、来源片段、结构化建议、置信/提示信息和当前决议。 |

ScriptVersion 的正文、Scene 和 Dialogue 一经发布不得原地覆盖；任何文本修改产生新版本。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| SCR-FR-001 | editor/owner 必须能通过粘贴文本、创建草稿或受支持文件导入 ScriptSource。 |
| SCR-FR-002 | 用户必须能读取版本历史、比较必要差异并把某个 ScriptVersion 设为 Episode 当前版本。 |
| SCR-FR-003 | 修改当前剧本必须创建新 ScriptVersion，并保留原版本及其下游引用。 |
| SCR-FR-004 | 用户必须能对固定 ScriptVersion 发起结构化提取，获得 Scene、Dialogue、资产和镜头候选。 |
| SCR-FR-005 | 用户必须能逐个或批量确认、关联现有对象、合并、修改后确认或忽略 ExtractionCandidate。 |
| SCR-FR-006 | 系统必须展示未决议候选、冲突、重复实体和可能的剧情/角色连续性问题。 |
| SCR-FR-007 | 只有当前提取批次的必需候选全部决议后，结构确认阶段才能完成。 |
| SCR-FR-008 | 对同一候选重复提交相同决议不得重复创建 Asset 或 Shot；改变已决议结果必须显式处理下游影响。 |
| SCR-FR-009 | 已被 ShotSpec 引用的 ScriptVersion 不得删除；未引用草稿可在明确确认后删除。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| SCR-IF-001 | 创建/读取 ScriptSource | ActorContext、Episode、输入文本/媒体、权利声明 | ScriptSource；Episode 归档或授权不完整时拒绝 |
| SCR-IF-002 | 追加/列表/读取 ScriptVersion | Source ID、正文、期望当前版本 | 新版本/版本列表；期望版本不匹配返回冲突 |
| SCR-IF-003 | 设置当前版本 | Episode ID、ScriptVersion ID、期望旧 ID | 当前引用；跨 Episode 版本或并发变化时拒绝 |
| SCR-IF-004 | 启动提取 | ScriptVersion ID、提取范围、幂等键 | ExtractionBatch 与 Task；不得等待模型完成 |
| SCR-IF-005 | 查询提取结果 | Batch ID、候选类型/状态、分页 | 批次状态、候选和下一动作 |
| SCR-IF-006 | 提交候选决议 | Batch ID、候选 ID、决议、必要修订/目标 ID | 决议结果和下游创建/关联 ID；重复请求返回相同结果 |
| SCR-IF-007 | 连续性检查 | ScriptVersion ID、检查范围 | 问题列表和证据位置；不得自动篡改剧本事实 |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| SCR-NFR-001 | 不可变 | 已发布 ScriptVersion 及其结构化内容不得 PATCH；当前指针变化不改变历史版本。 |
| SCR-NFR-002 | 幂等 | 提取启动和候选决议必须支持安全重试，不产生重复批次副作用或下游对象。 |
| SCR-NFR-003 | 可追溯 | 每个候选必须能追溯到 ScriptVersion、文本位置、提取规则/模型、Task 和用户决议。 |
| SCR-NFR-004 | 一致性 | 确认批量候选时，决议与下游对象创建/关联必须原子或提供可恢复结果。 |
| SCR-NFR-005 | 可解释 | AI 冲突/连续性提示必须展示依据位置，不得把概率结果表述为已确认事实。 |
| SCR-NFR-006 | 性能 | 导入、版本读取和差异展示规模由单集字符数决定；上限、P95 和大文本处理策略在 PRD 量化。 |
| SCR-NFR-007 | 安全 | 剧本文本和导入文件按 Workspace 私有处理，不进入无关日志、提示样例或跨租户缓存。 |

## 6. 生命周期与失败路径

- ScriptSource：`active ↔ archived`；归档不影响已引用版本的读取。
- ExtractionBatch：`queued → running → succeeded | failed | cancelled | unknown`；状态来自 Task，不以页面轮询次数推断。
- ExtractionCandidate：`pending → accepted | linked | merged | ignored`；已决议候选的变更必须显示下游影响。
- 提取失败保留 ScriptVersion 和批次错误，允许以新 Batch 重试；不得覆盖已完成人工决议。
- 切换当前 ScriptVersion 后，既有 ShotSpec 保持原引用，并由系统提示哪些镜头可能需要升级。

## 7. 非目标与待确认

- 不做通用在线文档、多人实时协同、小说版权判定或自动改写已确认剧本。
- 不承诺一次提取完全正确；人工决议是进入资产和分镜事实的门禁。
- 待确认剧本输入格式、字符上限、对白/旁白类型、差异展示粒度和重新提取覆盖范围。
