## 1. 模块定位

剧本分析与叙事结构模块负责保护用户原稿，将整部剧本文档转化为可确认的分集方案、单集剧本版本以及 NarrativeScene、动作、对白和旁白等稳定叙事事实，并为 LocationAsset 识别和分镜规划提供可追溯来源。

模块解决的核心问题不是“AI 能否生成一段文本”，而是：

1. 原稿是否完整保留；
2. 分集、改写和结构化过程中是否丢失叙事内容；
3. AI 建议是否经过人工决议；
4. 改稿后哪些资产、镜头和历史导出需要复核；
5. 每一个下游镜头是否能回到明确的剧本来源。

### 1.1 产品目标

1. 用户可以导入一份整剧原稿并在物化 Episode 前解决格式和分集问题。
2. 原文、AI 改写候选和已发布剧本版本彼此分离，不发生静默覆盖。
3. 分集和叙事拆解能够证明正文无未解释缺口和重叠。
4. 资产候选及叙事镜头提示能回到精确来源并接受逐项人工决议或生产处置。
5. 新剧本版本发布后，旧资产提取、分镜和视频选择的影响可见且不会被自动迁移。

## 2. 范围与非范围

### 2.1 当前范围

- 上传 DOCX 或 Markdown 整剧文件。
- 原始文档修订、格式体检和问题定位。
- 显式集标记的确定性分集。
- 无集标记时的可解释 AI 分集建议。
- 人工移动边界、拆集、合集、改标题和确认分集方案。
- 将确认方案整批转化为 Episode、单集原始剧本和稳定来源关系。
- 单集剧本版本、版本比较和 current 发布。
- AI 改写候选、差异查看、人工编辑及显式发布。
- 每集的剧本理解候选：标题、logline、摘要、hook、关键节拍、场景、人物、世界观、资产和制作任务建议。
- NarrativeScene、动作、对白、旁白和叙事单元结构化。
- 角色、LocationAsset、道具候选及 ShotCueCandidate 的提取与人工决议。
- 为每个 NarrativeUnitVersion 明确 `must_cover` 或经理由确认的 `may_omit_with_approval` 生产处置。
- 连续性、重复实体、低置信和结构冲突提示。
- 新版本发布后的影响和 stale 提示。

### 2.2 明确非范围

- 小说生成、灵感社区、通用大纲写作和完整在线编剧软件。
- 多人实时协同编辑、批注流和外部审稿。
- PDF、TXT、扫描件、图片 OCR、手写识别和粘贴文本导入；MVP 只接受 DOCX 与 Markdown 文件。
- 自动版权判定或代替用户确认输入权利。
- AI 自动发布改写结果或自动覆盖用户原稿。
- 自动把旧镜头、旧资产或旧视频选择迁移到新剧本。
- 音频、配音、字幕、时间线、视频拼接和成片。
- 以字符位置或显示镜号作为跨版本长期身份。

## 4. 核心用户场景

### CUR-SCR-US-001 导入有明确集标记的整剧

创作者上传包含“第 1 集、第 2 集……”标记的 UTF-8 文本。系统确定性识别集边界、报告空集或跳号，并在用户确认前不创建正式 Episode。

### CUR-SCR-US-002 为无集标记剧本确认分集

创作者上传连续长文本，系统按目标单集时长提出候选边界并显示依据、预计时长和置信度。创作者移动边界后确认，正文不丢失。

### CUR-SCR-US-003 短剧化改写但保留原稿

编剧为单集填写改写目标，系统生成候选。编剧并排查看原文和候选差异、编辑候选并发布新版本；原始版本仍可查看。

### CUR-SCR-US-004 确认资产提取

系统从固定剧本版本识别角色、LocationAsset 和道具候选。创作者把“林夏”和已存在角色关联、合并“老宅/林家老宅”地点资产候选，并忽略错误候选。

### CUR-SCR-US-005 改稿后的影响处理

编剧发布新版本，系统指出旧资产提取、分镜覆盖、当前视频选择和镜头素材包分别基于哪个旧版本。历史结果保留，但当前剧集进入待复核状态。

## 7. 详细功能需求

### CUR-SCR-FR-001 导入并保护整剧原稿

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Workspace active；Project active；用户为该 Workspace 的 owner/editor；文件扩展名和实际格式为 DOCX 或 Markdown。 |
| 主流程 | 用户选择 DOCX 或 Markdown 文件；系统显示文件名、格式、字符数和内容摘要，并在确认动作旁说明“上传即确认有权用于本项目制作与分析”；用户确认导入；系统以当前 actor、时间和固定声明版本登记输入权利声明，保存不可变原稿修订并进入格式体检。 |
| 备选流程 | 用户可以为同一整剧追加新修订；重复上传相同内容时系统提示已有相同修订，允许直接进入该修订而不制造重复。 |
| 失败流程 | 空文本、非法编码、安全策略拒绝、文件读取失败或 Project 状态变化时不进入分集；页面保留问题位置和可重试入口。 |
| 业务规则 | 原稿一经保存不得原地修改；修正文本产生新修订；原始文件名不是身份；正文不得出现在普通日志、通知或分析指标标签中。 |
| 输入 | DOCX 或 Markdown 文件；可选标题/来源说明。权利声明由确认上传动作和固定声明版本产生，不要求用户重复输入。 |
| 输出 | ScriptDocument、不可变 DocumentRevision、格式体检入口。 |
| UI 要求 | 上传前展示支持格式、安全校验和预计处理提示；不增加独立权利复选框或重复表单；不展示未经安全策略确认的业务导入上限；错误必须定位到文件、行或字符范围；用户能预览开头/结尾以识别错文件。 |

### CUR-SCR-FR-002 格式体检与确定性分集

| 项目 | 需求 |
| --- | --- |
| 前置条件 | DocumentRevision 已安全保存。 |
| 主流程 | 系统检查编码、空白、集标记、集号顺序、空集、异常长段和无法归类内容；合法显式集标记形成确定性 EpisodePlan 候选。 |
| 备选流程 | 存在可安全自动修正的纯格式问题时，系统提供修正候选，用户确认后形成新修订再分析。 |
| 失败流程 | 缺号、重复集号、空集或正文落在任何集之外时，计划不能确认，并列出问题位置和下一动作。 |
| 业务规则 | 同一修订和同一规则版本重复分析必须产生同样的集数、边界和问题；分集不能丢弃非空正文。 |
| 输入 | DocumentRevision、可选显式集标记规则。 |
| 输出 | NarrativeBlock、格式问题、确定性 EpisodePlan 候选。 |
| UI 要求 | 以问题列表和正文定位联动展示；明确区分错误、警告和建议；不把“未发现集标记”显示成系统失败。 |

### CUR-SCR-FR-003 AI 分集建议与人工边界编辑

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 修订没有可用显式集标记，或用户明确选择重新规划；格式问题不阻止分析。 |
| 主流程 | 用户设置目标单集时长或集数倾向；系统基于固定修订产生一个分集建议，逐个显示边界证据、预计时长、理由和置信度；用户移动边界、拆集、合集或修改标题。 |
| 备选流程 | AI 任务失败时，用户仍可手工添加和移动边界；低置信边界必须突出而不是自动确认。 |
| 失败流程 | 结果无法覆盖全部正文、产生重叠、空集或超出容量时，建议标记不可确认并给出具体问题。 |
| 业务规则 | 建议是候选，不自动建立 Episode；任何编辑后必须重新校验 gap=0、overlap=0；边界操作不得截断 Unicode 字符或丢失对白/动作。 |
| 输入 | DocumentRevision、目标时长/集数、内容偏好、当前计划修订。 |
| 输出 | 可编辑 EpisodePlan、边界证据、预计时长和问题。 |
| UI 要求 | 同时展示全文位置、集预览和预计时长；边界可以键盘移动；保存前明确显示未确认状态。 |

### CUR-SCR-FR-004 确认分集并整批建立剧集来源

| 项目 | 需求 |
| --- | --- |
| 前置条件 | EpisodePlan 覆盖完整、无重叠、无空集，Project active，计划修订仍为当前。 |
| 主流程 | 用户查看将创建或追加的 Episode 清单和正文范围；确认后系统整批建立 Episode、每集 ScriptSource 和原始 ScriptVersion，并记录本次导入结果。 |
| 备选流程 | 向已有 Project 追加后续集时，只创建计划中明确的新 Episode；与已有集冲突时先解决映射。 |
| 失败流程 | 任一标题/顺序冲突、权限或状态变化、计划过期时，整批不产生半完成 current 引用。 |
| 业务规则 | 同一确认意图安全重试不得重复建立 Episode；每集正文可以回到同一 DocumentRevision 的精确范围；确认后原计划不可覆盖，只能由新计划取代。 |
| 输入 | 已确认 EpisodePlan、预期 Project/Episode 状态、确认意图。 |
| 输出 | ImportCommit 摘要、Episode 和原始 ScriptVersion 引用。 |
| UI 要求 | 确认前显示新增、已有冲突和不会改变的内容；成功后显示每集入口和整批结果。 |

### CUR-SCR-FR-005 单集剧本版本与 current 发布

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户可编辑 active Episode，且读取到的 current ScriptVersion 仍为当前。 |
| 主流程 | 用户从当前版本创建修订草稿，修改内容并保存为新不可变版本；查看差异后显式设为 Episode current。 |
| 备选流程 | 用户可把一个历史版本重新设为 current，但必须先查看对当前下游的影响。 |
| 失败流程 | 并发 current 变化、版本属于其他 Episode、正文非法或被归档时，发布失败且原 current 不变。 |
| 业务规则 | 已发布版本正文、NarrativeScene、Dialogue 和 NarrativeUnit 不原地覆盖；current 是可变引用，不等于删除历史；已被下游引用的版本不得删除。 |
| 输入 | Episode、基线版本、修订正文、变更说明、预期 current。 |
| 输出 | 新 ScriptVersion、差异摘要、current 变化和影响预览。 |
| UI 要求 | 始终能看到“当前版本”“正在编辑的候选”“来源版本”；离开未发布编辑时必须提示。 |

### CUR-SCR-FR-006 AI 改写候选、差异与显式发布

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 固定 ScriptVersion 已发布；用户为 owner/editor；改写目标合法。 |
| 主流程 | 用户填写节奏、时长、风格和保留事实等改写目标；系统启动异步改写；完成后用户查看原文/候选差异，编辑候选并显式发布新版本。 |
| 备选流程 | 用户可放弃候选、基于同一原文重新生成另一候选，或只把候选保存为草稿。 |
| 失败流程 | 输出结构无效、事实约束失败、任务状态未知或用户已切换 current 时，不得自动重试或发布；保留失败证据和安全下一动作。 |
| 业务规则 | 改写候选固定输入版本和约束；模型输出不得覆盖原文；发布前必须展示删除、增加和修改的内容；状态未知时先对账再决定重试。 |
| 输入 | ScriptVersion、改写目标、必须保留事实、期望 current。 |
| 输出 | AdaptationRun、候选正文、差异、问题和可发布结果。 |
| UI 要求 | 差异支持按增加/删除/修改筛选；AI 建议和人工编辑可区分；发布按钮与“重新生成”分开。 |

### CUR-SCR-FR-007 叙事单元结构化与人工修正

| 项目 | 需求 |
| --- | --- |
| 前置条件 | ScriptVersion 已发布。 |
| 主流程 | 系统把固定版本结构化为有序 NarrativeScene 及场标题、动作、对白、旁白等叙事单元；用户检查低置信项，修正类型、说话主体、顺序或来源范围后确认。 |
| 备选流程 | 无法可靠解析的文本可保留为“待分类叙事单元”，用户手工拆分或归类；不能因未知类型丢弃。 |
| 失败流程 | 单元来源范围越界、重叠冲突、正文不守恒或结构任务失败时，结构不能标记确认，原剧本不受影响。 |
| 业务规则 | 每个单元有稳定身份和不可变版本；来源文本范围是证据，不作为跨修订身份；跨版本关联需要显式映射或人工确认。 |
| 输入 | ScriptVersion、结构化结果、人工修正及期望修订。 |
| 输出 | NarrativeScene、Dialogue、NarrativeUnitVersion、有序结构和未解决问题。 |
| UI 要求 | 原文和结构树联动高亮；用户可从单元跳回来源；低置信与未分类项有统一问题过滤。 |

### CUR-SCR-FR-011 标记叙事单元生产处置语义

## 9. 状态机与不变式

### 9.1 EpisodePlan

~~~mermaid
stateDiagram-v2
    [*] --> Draft
    Draft --> ReviewReady: 校验通过
    ReviewReady --> Draft: 编辑边界
    ReviewReady --> Confirmed: 人工确认
    Confirmed --> Materialized: 整批建立成功
    Draft --> Superseded: 新计划取代
    ReviewReady --> Superseded: 新计划取代
~~~

### 9.2 AI 运行

AdaptationRun 和 ExtractionBatch 只记录业务输入、候选与对应 CUR-PLT WorkTask 引用。用户看到的执行状态必须投影 CUR-PLT canonical 状态：`queued → running → waiting_external → succeeded | failed | cancelled | unknown`，其中 `unknown → succeeded | failed | manual_attention`；本模块不得增加第二套终态。刷新、重试与对账均针对同一 WorkTask 事实。

### 9.3 候选决议

~~~mermaid
stateDiagram-v2
    [*] --> Pending
    Pending --> Accepted
    Pending --> Linked
    Pending --> Merged
    Pending --> Ignored
~~~

已决议结果不原地改成另一个终态。改变决定必须记录新的显式决定及其下游影响。

### 9.4 不变式

1. DocumentRevision、已发布 ScriptVersion 和 NarrativeUnitVersion 不可原地覆盖。
2. 任何已确认 EpisodePlan 对非排除正文必须 gap=0、overlap=0。
3. AI 输出在人工发布或决议前不得成为正式 current 或下游事实。
4. 每个结构化单元和候选都能回到固定版本及明确来源证据。
5. 同一确认或决议意图安全重试不得创建重复 Episode、Asset 或 ShotCueCandidate；正式 ShotDraft/Shot 只能由 CUR-SBD 创建。
6. 新 ScriptVersion 成为 current 不改变历史版本和历史导出。
7. 版本变更导致的 stale 不能通过前端隐藏或自动标记已处理。
8. 字符位置只作为特定修订内的证据，不是跨版本长期身份。
9. 每个进入正式分镜覆盖计算的 NarrativeUnitVersion 必须有唯一 production_disposition；`may_omit_with_approval` 必须保留显式理由和 actor。
10. 深度理解成功必须为每个目标 Episode 提供非占位标题、logline、摘要、hook、关键节拍和完整类型化候选引用；缺失范围只能显示 partial/needs_review，不能显示完成。

| 集标记缺号/重复/空集 | 阻止确认并定位问题行 | 用户修正为新修订或改用手工边界 |
| AI 分集/改写失败 | 原稿与 current 不变 | 保留失败运行、错误类别和重新发起入口 |
| AI 状态未知 | 不显示成功，也不盲目重试 | 先对账；无法确认时进入人工处理 |
| EpisodePlan 并发变化 | 用户提交被拒绝 | 展示最新计划，允许比较后重做 |
| 整批物化中任一项失败 | 不产生半批 current | 返回整批失败或可证明的恢复结果 |
| 候选下游创建失败 | 不把候选显示为已完整接受 | 保留决议意图和失败步骤，安全恢复同一结果 |
| 发布新版本时影响分析不可用 | current 不切换 | 等待恢复或明确取消 |
| 连续性检查不可用 | 显示未执行/unavailable | 不得显示“无问题” |

## 13. 验收条件

### AC-CUR-SCR-001（关联 CUR-SCR-FR-001）

Given 合法 UTF-8 整剧文本，When editor 导入，Then 保存不可变原稿修订并显示字符数；再次修改必须形成新修订，旧正文不变。

### AC-CUR-SCR-002（关联 CUR-SCR-FR-001、CUR-SCR-FR-002）

Given 非 UTF-8 文件，When 用户导入，Then 系统在建立 Episode 前阻断，说明编码问题且不产生乱码 ScriptVersion。

### AC-CUR-SCR-003（关联 CUR-SCR-FR-002）

Given 含连续独占集标记的固定修订，When 在同一规则版本下重复分析 100 次，Then 集数、每集边界和错误列表完全一致。

### AC-CUR-SCR-004（关联 CUR-SCR-FR-002）

Given 剧本存在“第 1 集、第 3 集”而缺第 2 集，When 格式体检，Then 计划不可确认并定位缺号，而不是静默创建两集。

### AC-CUR-SCR-005（关联 CUR-SCR-FR-003）

Given 无集标记长文本，When AI 返回三个建议边界，Then 每个边界显示依据、预计时长和置信度，且没有人工确认前不创建 Episode。

### AC-CUR-SCR-006（关联 CUR-SCR-FR-003、CUR-SCR-FR-004）

Given 用户移动边界并确认三集，When 系统校验和物化，Then全部非排除正文 gap=0、overlap=0，并一次建立三集及各自原始版本。

### AC-CUR-SCR-007（关联 CUR-SCR-FR-004）

Given 同一确认意图因网络超时被再次提交，When 第二次请求到达，Then 返回第一次整批结果，不重复创建 Episode。

### AC-CUR-SCR-008（关联 CUR-SCR-FR-005）

Given 当前版本 V1 已被分镜引用，When 用户发布 V2，Then V1 与其引用保持可读，current 指向 V2，影响清单指出旧分镜基于 V1。

### AC-CUR-SCR-009（关联 CUR-SCR-FR-006）

Given 固定 V1 发起改写，When AI 候选完成，Then 原文未变化；只有用户查看差异并确认发布后才产生新 ScriptVersion。

### AC-CUR-SCR-010（关联 CUR-SCR-FR-007）

Given 一段无法判定为动作或旁白的文本，When 结构化，Then 形成待分类单元并保留原文来源，不得丢弃。

### AC-CUR-SCR-011（关联 CUR-SCR-FR-008）

Given “林夏”候选已被关联到现有角色，When 同一决议重复提交，Then 返回同一角色引用，不创建第二个角色。

### AC-CUR-SCR-012（关联 CUR-SCR-FR-008、CUR-SCR-FR-009）

Given “老宅”和“林家老宅”可能重复，When 查看候选，Then 系统展示两者来源证据和合并建议，用户可合并或保留为两个对象。

### AC-CUR-SCR-013（关联 CUR-SCR-FR-009）

Given 连续性检查服务不可用，When 打开问题视图，Then 显示“未执行/暂不可用”，不得显示“未发现连续性问题”。

### AC-CUR-SCR-014（关联 CUR-SCR-FR-010）

Given V1 下已有资产、分镜、视频选择和历史导出，When 用户准备切换到 V2，Then 切换前按类型展示影响；确认后历史不变，当前对象进入待复核。

### AC-CUR-SCR-015（关联 CUR-SCR-FR-011）

Given 固定 NarrativeUnitVersion U1 尚未有处置，When editor 确认结构，Then U1 必须得到唯一 `must_cover` 或带 actor、理由和时间的 `may_omit_with_approval`，否则结构不得交接 CUR-SBD。

### AC-CUR-SCR-016（关联 CUR-SCR-FR-008、CUR-SCR-FR-011）

Given 提取产生 ShotCueCandidate C1 且 U1 为 must_cover，When 用户保留 C1，Then CUR-SCR 只保存提示与来源，不创建 ShotDraft/Shot；CUR-SBD 仍须规划正式镜头并证明 U1 被覆盖。

### AC-CUR-SCR-017（关联 CUR-SCR-FR-012）

Given 固定 60 集剧本已完成分集物化，When 深度理解完成，Then 60 集均有非“第 N 集”占位的语义标题、logline、摘要、hook、关键节拍和合法来源范围；任何缺失集使 Project 级结果显示 partial/needs_review。

### AC-CUR-SCR-018（关联 CUR-SCR-FR-012）

Given 模型返回人物、世界观、资产、镜头和任务建议，When 聚合与保存，Then 每项以对应显式候选类型保存并能回到固定原文；不会用 continuity/asset 通用类型混装，也不会自动创建正式 Asset、Shot 或 WorkTask。

### AC-CUR-SCR-019（关联 CUR-SCR-FR-012、CUR-SCR-FR-010）

Given Episode 3 深度候选基于 V1，When Episode 3 current 切为 V2，Then 只将受影响候选和 StageRun 标记 stale/待复核，其他 Episode 的有效候选和决议保持不变。

### 14.1 已决策事项

- 原始整剧文本和每次修订均不可原地覆盖；清洗、分集和改写必须保留逐字符来源范围。
- AI 分集、改写、资产/镜头提取都先形成候选；只有人工确认、决议或显式发布才能改变正式事实。
- EpisodePlan 确认必须保证非排除正文 gap=0、overlap=0，并以整批原子结果建立 Episode 与原始 ScriptVersion。
- current ScriptVersion 只能由显式发布改变；切换 current 不改写历史资产、分镜、候选、主选或导出包，只产生影响与待复核状态。
- 当前不自动猜测跨版本 NarrativeUnit 对应，也不引入音频、字幕、时间线、视频拼接或成片需求。
- NarrativeScene 是剧本内叙事场次，LocationAsset 是 CUR-AST 的可复用地点资产；二者不得以“Scene”混为同一事实。
- ShotCueCandidate 只向 CUR-SBD 提供叙事制作提示；正式 ShotDraft/Shot 及覆盖结论由 CUR-SBD 唯一拥有。

## 15. 术语

| 术语 | 定义 |
| --- | --- |
| ScriptDocument | Project 内整部剧本文档的稳定身份。 |
| DocumentRevision | 不可变的整剧原稿修订。 |
| EpisodePlan | 基于固定修订的分集候选和人工确认边界。 |
| EpisodeUnderstandingCandidate | 固定单集版本的语义标题、摘要、hook、关键节拍和类型化子候选引用；不是正式 Episode/资产/分镜事实。 |
| ImportCommit | 确认分集向 Episode 和原始版本转化的整批结果。 |
| ScriptVersion | 单集不可变剧本版本。 |
| current ScriptVersion | Episode 当前用于后续生产的显式版本引用。 |
| NarrativeUnit | 场标题、动作、对白或旁白等最小可追溯叙事事实的稳定身份。 |
| NarrativeScene | 固定 ScriptVersion 内的有序叙事场次，不等同于可复用 LocationAsset。 |
| production_disposition | NarrativeUnitVersion 的 `must_cover` 或带理由的 `may_omit_with_approval` 生产处置。 |
| ShotCueCandidate | AI 从固定版本提出的叙事镜头提示，不是正式 ShotDraft/Shot。 |
| ExtractionCandidate | AI 从固定版本提出、尚待人工决议的资产候选或 ShotCueCandidate。 |
| CandidateDecision | 人工对候选的接受、关联、合并、修改后接受或忽略。 |
| stale | 下游事实仍保留，但其输入已不是当前版本，需要复核。 |
