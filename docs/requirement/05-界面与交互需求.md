# 界面与交互需求

## 共享交互

业务行为以[需求总览](01-需求总览.md)为准，视觉约束见[DESIGN](../../DESIGN.md)。

- 表单保存有进行中/成功/错误；只有持久回执才能显示已保存；冲突保留输入。
- 列表空、筛选无匹配、未接入、加载失败四种状态分开；null不显示为0。
- 导航/面包屑保持当前项目；旧工作台路由不作为新导航结构。
- 对话框、菜单、抽屉复用shadcn语义组件；键盘、焦点、关闭和错误关联完整。
- 画布适应视口不改变节点位置，生成不自动选定，刷新健康不自动变正常。
- 具体新接口必须满足当前控件；按正式功能需求实现，缺失能力须作为未完成项记录。

## 共享功能性需求

这些行为横跨模块，由各模块同时满足；不另建布局/搜索/通知产品，也不按控件建立独立文件。

| 编号     | 角色/触发与前置                          | 系统行为                                                                        | 可观察结果与失败边界                                                         |
| -------- | ---------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| FR-UI-01 | 有权用户在项目页面导航、面包屑或抽屉切换 | 系统应保持当前项目/对象上下文，目标按同一权限读取                               | 不跳固定样例；无权/不存在明确失败；手机可关闭导航抽屉                        |
| FR-UI-02 | 用户提交编辑，或读取列表/详情            | 系统应区分进行中、真实保存成功、错误/冲突，区分空数据、无匹配、未接入与读取失败 | 成功须持久回执；冲突保留输入；未知不显示为0；用户知道操作是否生效            |
| FR-UI-03 | 用户查看设计语言/布局示例                | 系统应展示实际组件状态、交互和键盘行为                                          | 示例不保存业务数据；布局不建立业务数据副本；样例标签不能作为业务达标证据     |
| FR-UI-04 | 用户使用现有搜索/通知入口                | 系统应按经确认的范围查询及跳转，授权上下文与模块一致                            | 当前具体范围未确定，保留缺口；在确认前只标入口/演示，不报已接入全局搜索/通知 |

## 共享非功能性需求与验收

共享界面的质量条件直接列在本文件，具体业务对象的功能、质量和验收归属各业务模块。

| 编号       | 类别             | 需求                                                                                | 验证方法                                                                               |
| ---------- | ---------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| MNFR-UI-01 | 上下文与权限     | 身份/项目隔离，目标由服务端授权；导航和导出不因知道ID而绕过访问范围。               | 两个制作者交叉导航/查询；切换身份和项目后缓存不串读。                                  |
| MNFR-UI-02 | 加载与状态真实性 | 共享摘要去重，详情与原件按需；保存成功来自真实回执；空/null/0/未接入/失败分别呈现。 | 查Network请求/字节和实际写入；构造慢网、保存冲突及局部故障，未测响应阈值不报性能达标。 |
| MNFR-UI-03 | 键盘与可访问     | 控件有可访问名称，错误关联输入；菜单/对话框关闭返回焦点，关键操作键盘可达。         | 键盘、读屏与长错误检查；画布拖动的等价操作及可访问等级待确认，lint不代替验收。         |
| MNFR-UI-04 | 响应式与主题     | 1440设计宽、1280桌面、390手机检查；宽表局部滚动；深/浅/跟随系统下关键内容可读。     | 逐模块状态截图/操作对照确认设计；浏览器/设备支持矩阵及性能目标待确认。                 |
| MNFR-UI-05 | 可诊断           | 请求/任务有安全关联标识；失败可解释，查询有时间/来源，局部错误保留最后成功信息。    | 注入故障核安全反馈，不以刷新按钮或固定成功提示改变实际健康状态。                       |

| 场景     | 关联                             | 初始条件与操作                                                                             | 预期结果                                                                                |
| -------- | -------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| AC-UI-01 | FR-UI-01、02；MNFR-UI-01、03、04 | 用户有项目A，项目B无权；1280/390宽用键盘开菜单/抽屉/对话框、切页面，构造保存冲突和列表失败 | 当前项目身份正确；B被拒绝；菜单关闭返回焦点；关键操作可达；冲突留输入，失败不作空数据   |
| AC-UI-02 | FR-UI-03、04；MNFR-UI-02、04     | 浅/深/跟随系统检查示例/布局，使用搜索/通知入口；在规则确认后用真实查询验证                 | 示例不改业务；主题/状态可读；未接入明确；真实查询范围和跳转符合确认合同，未确认不填通过 |

### REQ-F-18 布局规范

#### 字段与数据量

| 区域       | 必须承载的字段                                             | 设计归属                                      | 一次读取 / 保存的量               |
| ---------- | ---------------------------------------------------------- | --------------------------------------------- | --------------------------------- |
| 布局与导航 | 72px主导航、220px上下文栏、页头/详情栏、搜索/通知/账号入口 | 路由配置 + 当前用户/项目摘要；宽度为设计token | 共享摘要去重；菜单/焦点为临时状态 |

#### 功能与失败边界

| 用户动作             | 必须产生的结果                                      | 边界与失败                                     |
| -------------------- | --------------------------------------------------- | ---------------------------------------------- |
| 导航 / 抽屉 / 面包屑 | 在新页面间保持当前项目与对象上下文                  | 不把旧路由树当新导航；手机关键操作可达         |
| 搜索 / 通知入口      | 当前只有入口/演示反馈；具体查询范围和待处理呈现待补 | 保留需求缺口，先不建全局搜索引擎或通知投递平台 |

#### 关联设计与边界

布局只消费上下文，不把导航状态存为业务表。 具体实现方案在需求获接受后另行评审。

### 原验收条件与反例

以下保留原验收来源；跨模块组合在各自第3～5节拆明职责，样例/规则差异仍以待确认项处理。

| 原范围        | 必须验证的结果                                     | 不可接受的反例                                 |
| ------------- | -------------------------------------------------- | ---------------------------------------------- |
| 设计语言/布局 | 状态、响应式、键盘与焦点一致；新导航只含新页面范围 | 为兼容旧路由重新加入旧页面，或新增纯规范业务表 |
