# REQ-007 资产模块需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`003-项目模块需求.md`、`004-媒体模块需求.md`、`005-审核治理模块需求.md`、`006-剧本模块需求.md`
- 输出：角色、场景、道具、服装、风格和声音的身份、版本与引用需求
- 下游：REQ-008、REQ-009

## 1. 需求概述

资产模块必须建立项目级“资产圣经”，让同一角色、场景、道具、服装、风格和声音在多个镜头中引用固定版本。资产身份可持续演进，但已进入 ShotSpec 的版本不得随“当前版本”变化而漂移。

不同资产类型共享身份、版本和生命周期规则，但各自字段必须类型化校验；不得用任意 JSON 或万能 Asset 吞掉差异。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| AST-ENT-001 | Asset | 必须归属 Workspace/Project，保存类型、名称、别名/标签、状态和当前版本 ID。 |
| AST-ENT-002 | AssetVersion | 必须不可变，保存类型化设定、提示描述、参考 MediaVersion、来源和授权引用。 |
| AST-ENT-003 | CharacterSpec | 必须表达稳定身份、外观、年龄/气质、服装关系、声音选择和必要参考视角。 |
| AST-ENT-004 | LocationSpec | 必须表达空间、时间/天气、视觉元素、光照和必要环境参考。 |
| AST-ENT-005 | Prop/CostumeSpec | 必须表达外观、材质、使用主体/场景和参考媒体；服装变体不能覆盖角色身份。 |
| AST-ENT-006 | Style/VoiceSpec | 必须表达视觉风格或声音来源、语言、表演特征和允许使用范围。 |

资产使用关系由 ShotSpec 等引用方拥有。资产模块可以提供反向使用查询，但不得要求双方双写 AssetUsage 状态。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| AST-FR-001 | editor/owner 必须能按支持类型创建、列表、搜索、读取和修改 Asset 的名称、别名与标签。 |
| AST-FR-002 | 用户必须能从剧本候选创建 Asset，或把候选关联到既有 Asset，且重复决议不得重复创建。 |
| AST-FR-003 | 用户必须能为 Asset 追加 AssetVersion，关联上传/生成参考媒体和有效授权。 |
| AST-FR-004 | 用户必须能比较必要版本信息并把一个版本设为当前版本；既有引用保持原版本。 |
| AST-FR-005 | 系统必须按资产类型校验必填设定、参考媒体和授权，并给出 `draft/ready/blocked` 的可解释准备结果。 |
| AST-FR-006 | 用户必须能查询 AssetVersion 被哪些 Episode/ShotSpec 使用，并显式将选定引用升级到新版本。 |
| AST-FR-007 | 用户必须能归档/恢复 Asset；被引用版本保持可读，归档资产不得用于新的 ShotSpec。 |
| AST-FR-008 | 只有没有版本、媒体、授权和下游引用的 Asset 草稿可硬删除；AssetVersion 不允许普通删除。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| AST-IF-001 | Asset CRUD/归档 | ActorContext、Project、资产类型、允许字段 | Asset；类型非法、项目归档或存在删除阻塞时返回明确错误 |
| AST-IF-002 | 追加 AssetVersion | Asset ID、类型化规格、MediaVersion/Consent ID、期望当前版本 | 新版本；媒体/授权/类型不匹配时拒绝 |
| AST-IF-003 | 版本列表/详情/设为当前 | Asset/Version ID、期望旧 ID | 版本或最新 Asset；并发变化返回版本冲突 |
| AST-IF-004 | 准备度查询 | AssetVersion ID、用途 | ready、blocking_reasons、next_actions |
| AST-IF-005 | 反向使用查询 | AssetVersion ID、分页 | 引用它的 Episode/ShotSpec 摘要，不复制引用方内容 |
| AST-IF-006 | 批量升级引用预检 | 旧/新 AssetVersion、目标 Shot 列表 | 可升级项、冲突和预计影响；实际修改由 storyboards 完成 |
| AST-IF-007 | 从提取候选创建/关联 | Candidate ID、目标 Asset 或新资产规格 | Asset/Version ID；相同决议幂等 |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| AST-NFR-001 | 一致性 | Asset 当前版本切换不得自动修改任何 ShotSpecVersion；升级必须显式、可预检、可追溯。 |
| AST-NFR-002 | 类型安全 | 每种 AssetVersion 必须使用受控类型和类型化字段校验；未知字段/类型不能静默持久化。 |
| AST-NFR-003 | 可追溯 | 版本必须关联来源 Script/Candidate、参考媒体、授权、创建人和生成任务（如有）。 |
| AST-NFR-004 | 隔离 | Asset、MediaVersion、Consent 和引用方必须属于允许的 Workspace/Project 范围。 |
| AST-NFR-005 | 可解释 | readiness 必须返回具体缺失字段、媒体或授权，不仅返回布尔值。 |
| AST-NFR-006 | 性能 | 资产列表、反向引用和批量升级预检必须分页/限量；典型资产与镜头规模在 PRD 量化。 |
| AST-NFR-007 | 可维护 | 共享流程只能复用身份/版本机械逻辑；角色、场景、服装、声音的业务校验保持显式。 |

## 6. 生命周期与失败路径

- Asset：`active ↔ archived`；AssetVersion 为追加历史，不单独归档删除。
- 资产准备结果由当前版本、参考媒体和授权计算；任何依赖失效后必须变为 blocked，并影响新的生成预检。
- 媒体探测或生成失败不得覆盖已有参考版本；用户可以追加新版本或重新发起生成。
- 撤销授权后，既有历史仍可审计，但相关版本不得用于新生成/交付。
- 批量升级部分目标冲突时默认不执行，除非后续 PRD 明确支持逐项结果模式。

## 7. 非目标与待确认

- 不做跨 Workspace 公共素材市场、自动合并不同角色身份、LoRA 训练或无限层级资产树。
- 不保证模型绝对一致；平台提供固定版本、参考输入、候选和人工审核来降低漂移。
- 待确认各资产类型的最小字段、角色参考视角、声音授权规则、项目/系列复用范围和 ready 门槛。
