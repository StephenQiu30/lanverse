# REQ-15 参考定稿与跨集复用

| 项 | 内容 |
| --- | --- |
| 需求 | BIB-03 参考图生成、上传与锁定；BIB-05 跨集复用；BIB-06 按集聚焦定稿 |
| 优先级 | MVP |
| 用例 | UC-08 |
| 页面 | 设定条目详情、资产定稿 |
| 依赖功能 | REQ-14、REQ-21、REQ-22、REQ-30、REQ-31、REQ-17 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

一致性靠“锁定的参考”：每个造型、场景、道具生成或上传若干参考图（定妆照、三视图、场景图），选定一张后锁定为版本，所有镜头使用同一锁定版本。锁定后跨集复用；需要改时产生新版本并告知影响。

### 1.2 用户故事

- 作为**制作者**，我希望为造型、场景、道具生成或上传参考图，选定后锁定，以便所有镜头使用一致的参考。
- 作为**制作者**，我希望后续集自动使用已锁定的资产，只需为本集新出现的条目定稿。

### 1.3 范围

- 包含：参考槽位、生成候选（报价确认）、上传候选、锁定、改锁（新版本 + 影响提示）、版本历史、本集定稿清单。
- 不包含：LoRA 训练（V2）、参考图局部编辑（见 REQ-39 IMG-03）。

## 2. 需求分析

### 2.1 业务流程

```text
进入本集“资产定稿”→ 列出本集用到的造型 / 场景 / 道具（episode_asset_usage）及每个参考槽位的锁定状态
→ 对未锁定槽位：批量报价生成（每槽 N 个候选）或上传
→ 候选到达 → 对比 → 选定锁定 → reference_version vN
→ 全部锁定 → 本集资产定稿完成
改锁：选择新候选 → 预估影响（引用旧版本的镜头数）→ 确认 → vN+1 → 过期传播（REQ-31）
```

槽位按类型：造型 `portrait`（定妆照，必需）、`turnaround`（三视图，可选）、`closeup`（特写，可选）；场景 `scene_wide`（必需）、`scene_detail`（可选）；道具 `prop_main`（必需）。

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 生成输入 = 条目描述 + 项目风格预设 + （可选）该角色其他已锁定槽位作为参考 | 同角色不同槽位一致 |
| R2 | 只有审核通过的候选或就绪的上传素材能被锁定 | CMP-03 |
| R3 | 写实项目中上传的人物照片必须关联授权声明（REQ-17） | BIB-07 |
| R4 | 锁定产生不可变的 `reference_version`；槽位指向当前版本；旧版本保留 | BIB-03 |
| R5 | 改锁前展示影响：引用旧版本的镜头（参考组合或关键帧依赖）数量与列表 | BIB-03、LIN-02 |
| R6 | 镜头引用参考时引用具体版本；分镜生成或新建镜头时默认引用当前锁定版本 | BIB-05 |
| R7 | “本集需要”的判定：本集分镜引用 + 抽取时标注的出场 + 手动添加；只阻塞本集 | BIB-06 |
| R8 | 必需槽位未锁定的条目，在分镜中被引用时显示“缺失”，报价被阻止 | SB-01 |

### 2.3 状态

槽位：空 → 生成中 → 有候选 → 已锁定(vN) → 已锁定(vN+1)…（REQ-03 §6.3）。

### 2.4 异常与边界

- 生成全部审核不通过：提示调整描述后重试。
- 锁定后源候选被删除：不允许（被引用保护）。

### 2.5 前置与依赖

设定集已确认（REQ-14）；图片生成模型已配置（REQ-08）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `bible.reference_slot` | `owner_type`、`owner_id`、`kind`、`current_version_id`、`revision` | 槽位与当前锁定 |
| `bible.reference_version` | `version_no`、`media_asset_id`、`source_output_id`、`create_by` | 锁定历史、依赖上游版本 |
| `bible.episode_asset_usage` | 本集用到的条目 | 定稿清单 |
| `operation.operation` | `target_type = reference_slot` | 候选生成 |
| `lineage.dependency` | 镜头版本 → `reference_version`（`upstream_key = reference_slot_id`） | 过期传播 |

### 3.2 接口

```http
GET /api/episodes/{eid}/asset-readiness
200 { "ready": false, "items": [ { "owner_type": "look", "owner_id": "…", "name": "李明 / 日常装",
        "slots": [ { "slot_id": "…", "kind": "portrait", "required": true, "locked_version_no": 1, "candidates": 0, "inflight": 0 },
                   { "slot_id": "…", "kind": "turnaround", "required": false, "locked_version_no": null, "candidates": 4, "inflight": 0 } ] } ] }

GET /api/reference-slots/{sid}
200 { "slot_id": "…", "kind": "portrait", "revision": 3,
      "current": { "version_no": 1, "media_asset_id": "…", "thumb_url": "…", "locked_by": "…", "create_time": "…" },
      "versions": [ … ], "candidates": [ { "output_id": "…", "operation_id": "…", "thumb_url": "…", "moderation_status": "passed" } ] }

GET /api/reference-slots/{sid}/impact
200 { "shots": 20, "episodes": [1,2], "shot_ids": [ … ] }

POST /api/reference-slots/{sid}:lock
{ "output_id": "…", "expected_revision": 3 }          // 或 { "media_asset_id": "…" }
200 { "version_no": 2, "revision": 4, "stale_shots": 20 }
422 input_not_ready（未审核通过 / 缺授权声明）
```

生成候选：`POST /projects/{pid}/quotes`，`target_type = reference_slot`、`capability = image.generate`。

### 3.3 异步与工作流

候选生成使用通用 OperationWorkflow（DES-04）。锁定为同步命令；事务内写 `reference_version`、更新槽位、写 Outbox `bible.reference_locked.v1`。

### 3.4 事件与实时

`bible.reference_locked.v1` → lineage（过期传播）、realtime、audit；SSE `reference_slot.locked`、`stale.changed`。

### 3.5 界面

资产定稿页：按角色 / 场景 / 道具分组的卡片，每卡显示槽位锁定状态；批量“为未锁定槽位生成”；槽位详情：候选网格（REQ-22 组件）、锁定按钮、版本历史、改锁影响确认框。

### 3.6 权限与审计

制作者。审计：`reference.locked`（含前后版本）。

### 3.7 非功能要求

AIQ-04（一致性抽检）；PERF-09（候选可见 ≤ 30 秒）。

## 4. 验收标准

- Given 造型“日常装”生成了 4 个定妆照候选，When 选定第 2 个，Then 该造型参考版本为 v1，候选 1、3、4 仍可查。
- Given 已有 20 个镜头引用该造型 v1，When 改选为另一候选，Then 生成 v2，20 个镜头标记过期并显示影响范围。
- Given 第 1 集已锁定角色 A 的造型，When 生成第 2 集分镜，Then 第 2 集镜头引用 A 的同一锁定版本，无需重新定稿。
- Given 角色 B 只在第 10 集出场且未定稿，When 生产第 1 集，Then B 不阻塞第 1 集的任何步骤。

## 5. 测试要点

锁定并发冲突；改锁过期传播覆盖（参考组合、关键帧、视频）；本集清单计算。
