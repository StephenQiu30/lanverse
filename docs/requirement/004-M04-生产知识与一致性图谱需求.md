# M04 生产知识与一致性图谱需求

> Requirement ID：REQ-KNO
> 状态：reviewed v2（ready_for_design，待产品负责人接受）
> 日期：2026-08-22
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)、[M03 导入与叙事理解](./003-M03-导入与叙事理解需求.md)
> 对应模块：M04 生产知识与一致性图谱

## 1. 需求结论

生产知识层必须把“对象是谁”“长期设定是什么”“某个范围处于什么状态”“生产上如何表现”分开。人物、地点、道具、服装、妆造、载具、品牌元素、视觉/声音风格和世界规则，以及它们与 M03 NarrativeScene 的关联，都必须成为可版本化、可引用、可追溯的项目事实；NarrativeScene 本身仍归 M03。

ProductionEntity 默认在项目内跨内容单元共享；跨项目复用必须先发布为 Workspace 资产，再由目标项目显式关联，不能直接读取另一项目草稿。

## 2. 范围与非目标

包含实体身份与别名、人物档案、人物提及消歧、场景/地点/道具资料、状态时间线、语义关系、人物弧光、世界/风格规则、生产需求清单、生产参考绑定、实体出现投影、有效范围、证据、冲突、依赖投影和影响报告。

不包含通用图数据库产品、自动训练 LoRA、直接生成参考图、镜头设计、模型路由或用聊天记忆替代正式事实。

## 5. 人物详细拆解

人物身份必须处理姓名、别名、职务、亲属称谓、代词、群体称呼、隐藏身份和同名不同人。低置信聚类保持待确认；合并、拆分和移动 Mention 前显示人物资料、状态、关系、弧光和下游引用影响。

人物长期档案至少支持：叙事定位、年龄阶段、性别表达、稳定外观、背景、长期目标、动机、性格、能力、秘密、语言特征、禁用特征和备注。每个字段区分 `explicit | strong_inference | weak_inference | user_supplied | unknown | explicit_empty`。

首期必须审核身份、别名、人物定位、稳定外观、关键状态和被下游引用的高影响关系；人物弧光为 P1，不阻塞基础分镜。无证据的年龄、性格或动机不能由模型填满。

人物对应剧集不是 Profile 字段，而是由已批准 NarrativeRevision 中的 Scene→ContentUnit 关系、ProductionElementMention、UnresolvedSubjectRevision 和 MentionResolution 重建。尚未形成 ProductionEntity 的人物也必须以 revision-bound 未决主体行进入矩阵，不能因缺少 entity ID 从“全剧人物清单”消失；该未决主体的 Mention 成员集合是 M04 不可变权威事实，拆分/合并产生新 revision，完成 create/link 后再投影到正式实体行。对每个 approved character Mention，M04 必须且只能保留一个 current MentionResolution：指向正式 entity、指向一个 active UnresolvedSubjectRevision，或以具名理由 explicit reject；未决成员集与 Resolution 引用必须一致。缺失 current 结果、同时属于多个 active 未决主体、或 current Resolution 与成员集不一致，都必须计入 resolution coverage 缺口，使 EntityOccurrenceProjection 为 `incomplete` 并阻止正式预检，不能静默从清单或矩阵消失。出现类型至少区分 `on_screen`、`dialogue_speaker`、`off_screen_voice`、`action_subject`、`mentioned_only` 和 `unresolved`；`mentioned_only` 不得自动推断为需要准备形象资产。只有该 ContentUnit 的分析完整度为 complete，且不存在已解析或待解析的该人物 Mention 时，空单元才能标 `confirmed_absent`；否则必须显示 `unresolved`、`conflict` 或 `not_analyzed`。

## 6. 场景、地点和道具

1. NarrativeScene 是某个 NarrativeRevision 内的结构节点；LocationEntity 是可跨场复用的地点身份，两者不能合并。
2. 地点别名需要消歧，例如“仓库”“旧仓库”“城西仓库”是否为同一地点。
3. 地点状态至少覆盖时间、天气、光照、陈设、入口、损坏、拥挤和禁止区域。
4. 道具需要区分唯一物、可替代物、消耗品、品牌物和集合物；独占物同一范围不能被多个主体同时持有。
5. 道具转移、消耗、损坏、丢失和恢复必须关联 Scene/Beat 证据。
6. 品牌标识、受限物品和版权元素在参考绑定与交付前进入治理检查。
7. 全剧生产清单至少覆盖 character identity、costume、makeup、location、prop、vehicle、voice、style 和 VFX，并允许通过不可变 ProductionCoverageSchemaRevision 扩展；每项必须回到 ContentUnit、NarrativeScene/Beat 和 SourceAnchor。
8. NarrativeScene、LocationEntity、ProductionRequirementItem 与 MediaArtifact 分属叙事节点、稳定身份、生产需要和实际素材，任何一个都不得用另一个代替。
9. Inventory 覆盖全集至少包含全部 approved ProductionElementMention，以及按投影绑定的 ProductionCoverageSchemaRevision 需要地点/布景判断的每个 approved NarrativeScene；每个成员必须有不可变 ProductionCoverageDecision，显式记录生产相关性、`required | deferred | not_required | rejected` 处理结果及零个或多个 RequirementRevision 引用。缺少该权威决定或引用不完整均计入 `unassessed`，清单不得标 complete 或通过正式下游批准预检。Schema 换版必须使旧 Inventory stale；历史投影仍按原 schema revision/hash 可重复重建。
10. RequirementReadinessProjection 的取值为 `unknown | missing | partial | ready | blocked | not_applicable`：仅 `required` 检查 Reference/Media；`deferred` 返回 blocked 并带 `decision_deferred` 原因；`not_required/rejected` 返回 not_applicable，不因没有媒体显示 missing。

## 7. 有效范围与冲突

ContentUnit/Shot 使用稳定 ID；Scene/Beat 使用“不可变 NarrativeRevision + 修订内成员 ID”。默认覆盖优先级为 `project < content_unit < narrative_scene < beat < shot`。跨叙事范围和镜头范围无法比较时，发布预检必须要求用户选择。

语义关系可以双向或成环；只有声明为有向无环的依赖类型才进行环检测。`A 信任 B` 不推出 `B 信任 A`，人物关系也不能被依赖图规则拒绝。

同一实体、同一属性面、同一成员和同一优先级的互斥 current 状态必须阻止发布。冲突可以修正、选择一项、标 unknown，或由有权限用户形成具名 `KnowledgeConflictAcceptance`；该决定不能替代质量风险或治理例外，也不能静默按创建时间取最后值。

## 8. 证据、发布与影响

- AI 结果先作为 Proposal；accepted AI 事实至少有一个有效来源锚点。
- 用户补充事实记录输入者和理由，不伪造为原文明示。
- 发布版本不可编辑，纠错创建新 Revision。
- 影响报告区分 hard/soft 依赖、已冻结历史和建议动作；报告本身不自动重做或替换主选。
- 删除或撤销参考不删除实体身份；只阻止需要该参考的新计划并标记受影响范围。

## 9. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 人物身份证据不足 | 保持候选和未决 Mention | 补证据、关联、拆分或暂缓 |
| 同范围互斥状态 | 阻止发布并显示冲突成员 | 调整范围或解决值 |
| 影响计算超时 | 显示计算中并阻止高风险传播 | 后台完成或缩小范围 |
| 参考媒体缺失 | 实体仍存在，新计划 blocked | 修复媒体或更换绑定 |
| 来源换版无法迁移 | 标记待复核而非复制事实 | 人工确认新锚点和范围 |
| 并发发布 current | 一个成功，另一个收到版本冲突 | 比较后创建新修订 |
| 剧集边界或叙事换版 | 历史出现矩阵保持绑定旧修订，新矩阵标记 rebuilding/stale | 只重建受影响 occurrence，并在完成后原子切换投影版本 |
| 全局清单存在未分析范围或未评估 Mention/Scene | Inventory 显示 incomplete、failed scopes 和 unassessed 数，数量不解释为零 | 完成缺失范围并逐项决议；有权限的延期仍是显式 `deferred`，不自动标 ready |
| approved character Mention 缺少唯一 current 消歧结果 | 人物清单/矩阵显示 incomplete、failed scopes、unassigned/overlap 数并阻止预检 | 为缺失 Mention 建立 entity、active 未决主体或 explicit reject；修复重叠成员/Resolution 后重建投影 |
| ReferenceBinding 或 MediaArtifact 可用性变化 | ProductionRequirementRevision 保持不变，旧 readiness 投影标 stale | 按相同需求修订重建 RequirementReadinessProjection，并原子切换可见版本 |

## 12. 指标与金标

指标包括 Mention 解析率、merge/split 修正率、accepted 事实证据覆盖率、状态/关系冲突率、地点和道具消歧修正率、影响报告精确率、资产复用率和从导入到首个可审阅知识包的时间。金标至少包含同名、别名、隐藏身份、换装、伤痕、知识揭示、地点改造、唯一道具转移、消耗道具和关系反转。
