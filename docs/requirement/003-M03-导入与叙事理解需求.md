# M03 导入与叙事理解需求

> Requirement ID：REQ-NAR
> 状态：reviewed v1（ready_for_design，待产品负责人接受）
> 日期：2026-08-20
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)
> 对应模块：M03 导入与叙事理解

## 1. 需求结论

模块必须把固定来源转换为可校对、可追溯、可版本化的叙事结构，而不是返回一份不可解释的模型 JSON。原始来源、确定性解析、AI 提案、人工决议和批准后的 NarrativeRevision 必须分离。

## 2. 范围与非目标

包含 DOCX、Markdown、纯文本和签认结构化脚本的导入/粘贴、来源保全、完整性报告、文本锚点、内容单元、Scene、Beat、Dialogue、Action、Narration、人物/地点/道具 Mention、结构提案、人工校对、版本差异和迁移。

PDF/OCR 不是默认首期能力；只有页码映射、部分失败、OCR 置信和证据回跳验收通过后才可按 Workspace 启用。本模块不发布正式人物/场景/道具身份，不创建镜头，也不执行媒体生成。

## 3. 用户价值流

```text
上传或粘贴来源
  → 固定 SourceRevision 与完整性标识
  → 确定性解析和 ParseReport
  → 结构/Mention 提案
  → 原文对照校对
  → 冲突与覆盖检查
  → 批准 NarrativeRevision
  → 向 M04/M05 发布版本事件
```

## 5. 结构语义

- Scene 表达相对稳定时空、叙事目的、参与者、地点、时间、内外景、冲突、转折和结果。
- Beat 是目标、行动、反应、信息或状态发生变化的最小叙事单元，不自动等于一个 Shot。
- Dialogue 必须关联人物 Mention 或明确 unknown；不能因为缺少说话人而继承上一句人物。
- Action 中涉及换装、受伤、持有物、位置和关系变化的内容形成带证据提案，由 M04 决定是否成为事实。
- 非空来源必须被结构节点覆盖，或由用户明确标记忽略原因。

## 6. 证据与决议规则

1. SourceAnchor 绑定 SourceRevision，并支持页、段、文本范围和内容哈希复核。
2. 字符 offset 只作为内部定位，不作为主要用户交互。
3. 置信度只用于排序，不能代替人工批准或覆盖检查。
4. 同一提案的模型解释不是来源证据；证据必须返回原文。
5. 批准后修改结构创建新 NarrativeRevision，不原地编辑 current。
6. 下游只消费批准版本；新 NarrativeRevision 只能使相关下游待复核，不能静默改写镜头。

## 7. 状态与恢复

SourceRevision 为不可变事实。Import/Analysis 运行可表达 `queued | parsing | analyzing | waiting_user | partial | failed | cancelled | completed | superseded`。NarrativeRevision 为 `draft → proposed → approved/current → superseded | archived`。

模型调用结果未知时必须先对账；重复消息和页面重试不能创建第二套 SourceRevision、AnalysisRun 或提案。阶段输入哈希未变时可以复用已通过结果，变化时必须创建新运行记录。

## 8. 失败与恢复路径

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 文件损坏/加密 | 文件级原因，不显示为空剧本 | 更换文件或解除保护 |
| 部分页段失败 | 已成功和缺失范围分别显示 | 重跑缺失范围或人工补录 |
| 结构模型失败 | 保留确定性解析和失败阶段 | 手工校对或只重跑阶段 |
| 来源审核时被替换 | 显示当前基线过期 | 完成旧审、切新版本或迁移 |
| 并发结构编辑 | 显示 Scene/Beat 差异 | 刷新并基于新修订提交 |

## 9. 非功能需求

| ID | 要求 |
| --- | --- |
| NAR-NFR-001 | 同一固定输入和解析规则的文本覆盖与基础锚点可复现。 |
| NAR-NFR-002 | Unicode、中英文、emoji 和组合字符定位不得越界。 |
| NAR-NFR-003 | 日志、事件和任务载荷不复制无控制的完整剧本。 |
| NAR-NFR-004 | 结构校对支持键盘和屏幕阅读器，不依赖画布或拖拽。 |
| NAR-NFR-005 | 长篇来源分块不能切断场次且全局 Reduce 不按局部名称定案。 |
| NAR-NFR-006 | 具体长度、时延、并发和文件大小由代表性语料签认。 |

## 10. 验收条件

| ID | 场景 |
| --- | --- |
| AC-NAR-001 | DOCX 导入后原件和哈希不被结构编辑覆盖。 |
| AC-NAR-002 | 部分页面失败不会被解释成空剧情，并可只恢复失败范围。 |
| AC-NAR-003 | 两场被误合时用户可视化拆分并保持来源覆盖守恒。 |
| AC-NAR-004 | 无说话人对白保持 unknown 并进入待确认。 |
| AC-NAR-005 | 每个 Scene、Beat、Dialogue、Action 和 Mention 可以回到正确原文。 |
| AC-NAR-006 | 未批准提案不能进入正式人物知识或分镜输入。 |
| AC-NAR-007 | 新来源只迁移精确对应决议，可能匹配项全部要求确认。 |
| AC-NAR-008 | Worker 在各阶段重启后恢复，不重复创建来源、运行或提案。 |
| AC-NAR-009 | PDF 能力关闭时系统明确不支持；启用后页码、OCR 缺口和锚点通过独立验收。 |

## 11. 指标与金标

指标包括来源覆盖率、Scene/Beat 人工修正率、无说话人率、提案接受/修改/拒绝率、锚点复核失败率、部分解析恢复时间和从导入到首个可审阅结构的时间。验收语料必须包含跨页场次、同页多场、无标题、多人对白、混合语言、格式噪声和版本改写。
