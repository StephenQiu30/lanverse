# M03 导入与叙事理解需求

> Requirement ID：REQ-NAR
> 状态：reviewed v3（ready_for_design，待产品负责人接受）
> 日期：2026-08-22
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)
> 对应模块：M03 导入与叙事理解

## 1. 需求结论

模块必须把固定来源转换为可校对、可追溯、可版本化的叙事结构，而不是返回一份不可解释的模型 JSON。原始来源、确定性解析、AI 提案、人工决议和批准后的 NarrativeRevision 必须分离。

## 2. 范围与非目标

包含项目级整本剧本以及已拆内容单元的 DOCX、Markdown、纯文本和签认结构化脚本导入/粘贴、来源保全、完整性报告、文本锚点、剧集边界提案、Scene、Beat、Dialogue、Action、Narration、人物/地点/道具/服装等 ProductionElementMention、全局出现索引、结构提案、人工校对、版本差异和迁移。

PDF/OCR 不是默认首期能力；只有页码映射、部分失败、OCR 置信和证据回跳验收通过后才可按 Workspace 启用。本模块不发布正式人物/场景/道具身份，不创建镜头，也不执行媒体生成。

## 3. 用户价值流

```text
上传或粘贴来源
  → 固定 SourceRevision 与完整性标识
  → 确定性解析和 ParseReport
  → 整本来源的剧集边界提案与人工确认
  → M02 物化稳定 ContentUnit 与顺序
  → 每集结构/Mention 提案与全局 Reduce
  → 原文对照校对
  → 冲突与覆盖检查
  → 批准 NarrativeRevision
  → 按剧集/场次/人物/地点/生产类型检索并回跳原文
  → 向 M04/M05 发布版本事件
```

## 5. 结构语义

- Scene 表达相对稳定时空、叙事目的、参与者、地点、时间、内外景、冲突、转折和结果。
- Beat 是目标、行动、反应、信息或状态发生变化的最小叙事单元，不自动等于一个 Shot。
- Dialogue 必须关联人物 Mention 或明确 unknown；不能因为缺少说话人而继承上一句人物。
- Action 中涉及换装、受伤、持有物、位置和关系变化的内容形成带证据提案，由 M04 决定是否成为事实。
- 非空来源必须被结构节点覆盖，或由用户明确标记忽略原因。
- EpisodeCandidate 是拆集审核期的临时叙事边界，不是 M02 ContentUnit；只有批准后的 EpisodeBreakdownManifest 才能请求物化稳定 ContentUnit。
- 剧集边界必须保存来源锚点、识别规则/版本、分段哈希和人工决议；缺标题或标题冲突时只能进入待校对，不能按篇幅平均切分后自动批准。
- ProductionElementMention 表示来源中出现了什么，不等于正式 ProductionEntity、生产需求或已经生成的媒体资产。

## 6. 证据与决议规则

1. SourceAnchor 绑定 SourceRevision，并支持页、段、文本范围和内容哈希复核。
2. 字符 offset 只作为内部定位，不作为主要用户交互。
3. 置信度只用于排序，不能代替人工批准或覆盖检查。
4. 同一提案的模型解释不是来源证据；证据必须返回原文。
5. 批准后修改结构创建新 NarrativeRevision，不原地编辑 current。
6. 下游只消费批准版本；新 NarrativeRevision 只能使相关下游待复核，不能静默改写镜头。

## 7. 状态与恢复

SourceRevision 为不可变事实。Import/Analysis 运行只表达执行状态：`queued | parsing | analyzing | waiting_user | partial | failed | cancelled | completed | superseded`。相同输入哈希通过 `RetryImportStage` 可使 `partial → analyzing → waiting_user | completed | partial | failed`；输入、解析规则或 Schema 变化时创建 successor Run，并将旧 Run 标为 superseded。EpisodeBreakdownRevision 为 `draft → proposed → approved → superseded`；Proposal 决议另行表达 `pending | accepted | edited | rejected | deferred | stale`；NarrativeRevision 为 `draft → proposed → approved/current → superseded | archived`，四套状态不得混用。

模型调用结果未知时必须先对账；重复消息和页面重试不能创建第二套 SourceRevision、AnalysisRun 或提案。阶段输入哈希未变时可以复用已通过结果，变化时必须创建新运行记录。

## 8. 失败与恢复路径

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 文件损坏/加密 | 文件级原因，不显示为空剧本 | 更换文件或解除保护 |
| 部分页段失败 | 已成功和缺失范围分别显示 | 重跑缺失范围或人工补录 |
| 结构模型失败 | 保留确定性解析和失败阶段 | 手工校对或只重跑阶段 |
| 来源审核时被替换 | 显示当前基线过期 | 完成旧审、切新版本或迁移 |
| 并发结构编辑 | 显示 Scene/Beat 差异 | 刷新并基于新修订提交 |
| 无剧集标题或标题冲突 | 显示未分配范围、候选边界和证据，不自动伪造剧集 | 人工新增、移动、合并或拆分边界后重新校验 |
| 单集分析失败 | 全局清单标记 `incomplete` 并列出失败剧集/范围，不显示成 0 人物或 0 资产 | 只重跑失败范围，成功剧集结果保持可校对 |
| 已确认边界被修改 | 受影响 Scene、Mention 和全局索引标记 stale，未受影响范围保持原锚点 | 创建新 EpisodeBreakdownRevision 并预览 M02/M04 影响后重新确认 |

## 9. 非功能需求

| ID | 要求 |
| --- | --- |
| NAR-NFR-001 | 同一固定输入和解析规则的文本覆盖与基础锚点可复现。 |
| NAR-NFR-002 | Unicode、中英文、emoji 和组合字符定位不得越界。 |
| NAR-NFR-003 | 日志、事件和任务载荷不复制无控制的完整剧本。 |

| NAR-NFR-005 | 长篇来源分块不能切断场次且全局 Reduce 不按局部名称定案。 |
| NAR-NFR-006 | 具体长度、时延、并发和文件大小由代表性语料签认。 |
| NAR-NFR-007 | 长篇来源按剧集和完整场次分块并执行全局 Reduce；全局清单可分页，且每页显式携带 source revision set、EpisodeBreakdownRevision、NarrativeRevision、完整度和失败范围。 |
| NAR-NFR-008 | 检索索引必须可从 PostgreSQL approved 事实与 MinIO 来源重建；索引不可用或滞后不能阻止导入、校对和批准，跨 Workspace 查询不得返回命中。 |

| AC-NAR-006 | 未批准提案不能进入正式人物知识或分镜输入。 |

## 11. 指标与金标

指标包括来源覆盖率、Scene/Beat 人工修正率、无说话人率、提案接受/修改/拒绝率、锚点复核失败率、部分解析恢复时间、从导入到首个可审阅结构的时间，以及检索 p95、零结果率、索引滞后与重建一致率。验收语料必须包含跨页场次、同页多场、无标题、多人对白、混合语言、格式噪声和版本改写。
