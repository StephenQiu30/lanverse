# 审计需求

## 目标与范围

管理员能追查变更并导出授权的脱敏记录。

本模块范围：关键事件只追加、筛选/详情、before/after及版本、同筛选CSV与公式注入防护。

建议执行顺序为编号顺序；编号不代表排期或已批准实施。本文件按业务模块整体维护，内部功能在同一文档列出，不为每个按钮、接口或技术层建立单独需求文件。

## 功能与数据要求

<a id="req-f-15"></a>

### 审计日志

#### 字段与数据量

| 区域       | 必须承载的字段                                     | 设计归属                         | 一次读取 / 保存的量                         |
| ---------- | -------------------------------------------------- | -------------------------------- | ------------------------------------------- |
| 筛选与日志 | 时间范围、操作人、项目、对象、动作；结果/时间/描述 | audit_event不可变事件            | 建议每页40；筛选先于分页，时间稳定排序      |
| 详情与CSV  | before/after、revision、对象ID、操作者、时间、结果 | 同一事件的脱敏快照；导出同一筛选 | 按需详情；导出建议最多1万条，超限提示缩范围 |

#### 功能与失败边界

| 用户动作    | 必须产生的结果                        | 边界与失败                             |
| ----------- | ------------------------------------- | -------------------------------------- |
| 筛选 / 详情 | 显示真实事件；缺失字段显式为空        | 不得编辑审计；权限不因知道event_id绕过 |
| 导出        | 只输出授权和脱敏字段并处理CSV公式注入 | 无须为有限日志导出预建任务平台         |

## 范围边界

- 一份审计记录服务表格、详情和导出。

## 依赖与待确认

业务关键操作产生审计，各模块实现时一起接入；查询与导出可随后验证，不把审计推迟到业务已无记录。

待确认：动作清单、失败事件范围及业务提交与审计的一致性方案。

以上缺口只是评审问题，不构成新增产品能力或架构决策。既有功能和约束不因旧接口支持不足而删除或降级。

## 模块验收

1. 本文列出的字段和功能由真实数据及操作结果承载，成功/失败/权限/未接入状态明确，mock不作为业务通过。
2. 需要持久化的写入可刷新恢复；版本冲突保留输入，重复副作用按幂等合同核对；只读/瞬时状态不强加持久化。
3. 当前用户/项目范围服务端验证；管理动作限管理员，秘密不进入响应、普通日志、审计明文或导出。
4. 实现时补与本模块风险匹配的成功、失败、冲突/重复、越权场景，分别记录自动化、真实持久化、浏览器及外部供应商证据，未执行不得报通过。

统一要求见[非功能规格](02-非功能需求规格.md)和[交互需求](05-界面与交互需求.md)；当前均待评审、未完成真实功能验收。本阶段不列Sprint、工时或固定用例数量。
