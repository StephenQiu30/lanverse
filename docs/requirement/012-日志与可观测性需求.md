# REQ-012 日志与可观测性需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`005-审核治理模块需求.md`、`009-生产模块需求.md`、`011-消息队列与异步投递需求.md`、`013-缓存存储与任务调度需求.md`
- 输出：结构化日志、trace、指标、告警、脱敏和留存需求
- 下游：日志与可观测性详细设计、运维与验收 Plan

## 1. 需求概述

日志服务必须帮助开发和运维从一次 HTTP 请求追踪到缓存/存储、Schedule/Fire、Outbox、RabbitMQ、Task/Attempt、供应商请求、媒体和费用结果，并快速回答“在哪里失败、是否可以重试、下一动作是什么”。

运行日志不是业务事实或审计证据。治理模块 AuditEvent 负责不可抵赖的业务审计；Task/Attempt 保存任务恢复事实；日志可以按保留策略清理，不能被业务代码依赖来恢复状态。

## 2. 事实与分类需求

| 编号 | 事实/分类 | 需求 |
| --- | --- | --- |
| LOG-ENT-001 | LogEvent | 必须包含时间、level、service、environment、event_name、message、trace/span、request/task/event 等关联 ID 和受控 attributes。 |
| LOG-ENT-002 | CorrelationContext | 必须贯穿 HTTP、应用用例、数据库事务、Outbox、RabbitMQ Consumer、供应商和媒体工具，不依赖线程本地猜测。 |
| LOG-ENT-003 | LogPolicy | 必须定义事件名称、级别、允许字段、脱敏规则、采样与留存类别，禁止业务代码随意打印对象。 |
| LOG-ENT-004 | Metric/Trace | 指标必须低基数并可聚合；trace 表达跨进程阶段与耗时，不把高基数正文放入标签。 |

日志至少分为 access、application、worker、integration、security 五类；AuditEvent 单独存 PostgreSQL，不与运行日志混为一张通用表。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| LOG-FR-001 | 每个 HTTP 请求必须生成或接收合法 trace/request ID，并记录完成状态、路由模板、方法、耗时和响应类别。 |
| LOG-FR-002 | 关键业务命令必须记录开始/完成/拒绝事件、actor/workspace、目标 ID、结果码和耗时，但不复制业务正文。 |
| LOG-FR-003 | Outbox 发布、RabbitMQ 消费、重试和拒绝必须记录 event_id、task_id、attempt、routing key 与可重试结论。 |
| LOG-FR-004 | 供应商调用必须记录 provider_request_key、能力/模型标识、阶段、耗时、归一化结果和费用关联，不记录密钥或完整请求。 |
| LOG-FR-005 | MinIO/OSS、ffprobe 和 FFmpeg 必须记录输入/输出 MediaVersion ID、存储/工具阶段、退出码、耗时和受限错误摘要。 |
| LOG-FR-006 | 未处理异常必须记录稳定错误码、异常类型、trace 和堆栈；对外仍返回统一 ApiError，不返回内部堆栈。 |
| LOG-FR-007 | 运维必须能以 trace_id、task_id、event_id、provider_request_key 或 media_version_id 关联查询完整链路。 |
| LOG-FR-008 | 服务必须暴露 HTTP、数据库、Redis、存储、调度、队列、Task、供应商和媒体处理指标，支持积压、schedule lag、错误率与未知任务告警。 |
| LOG-FR-009 | 日志策略必须自动脱敏 Authorization、Cookie、密钥、预签名 URL、个人资料、授权证明、剧本和提示正文。 |

## 4. 接口需求

| 编号 | 交接面 | 输入 | 输出/约束 |
| --- | --- | --- | --- |
| LOG-IF-001 | 应用日志 API | event_name、level、CorrelationContext、白名单 attributes | 一行 JSON LogEvent；未知/敏感字段拒绝或脱敏 |
| LOG-IF-002 | HTTP trace | W3C traceparent、可选请求 ID | 合法上下文继续传播；非法值重建且不回显原值 |
| LOG-IF-003 | RabbitMQ trace | Envelope/header 中 trace context | Consumer 新建 span 并关联 producer，不复用已结束 span |
| LOG-IF-004 | OpenTelemetry | traces、spans、resource attributes | OTLP exporter；失败不得阻断主业务 |
| LOG-IF-005 | Prometheus | 受控指标与 labels | `/metrics` 仅对受信网络/鉴权暴露 |
| LOG-IF-006 | 日志采集 | 容器 stdout/stderr JSON | 由部署环境采集；应用不直接依赖具体日志厂商 SDK |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| LOG-NFR-001 | 结构化 | 生产日志必须是一事件一行 JSON，字段和 event_name 稳定；禁止依赖自由文本解析告警。 |
| LOG-NFR-002 | 安全隐私 | 默认最小记录；脱敏在格式化前执行，错误路径同样生效；日志读取遵守最小权限。 |
| LOG-NFR-003 | 可用性 | 日志/trace exporter 故障不得使 API 或 Worker 失败；本地缓冲必须有界，超限可丢运行日志但要计数。 |
| LOG-NFR-004 | 性能 | 日志序列化、trace 采样和指标开销必须有界；开销上限在 PRD/压测中量化。 |
| LOG-NFR-005 | 关联性 | 同一链路的稳定 ID 必须一致；不得使用文件名、用户输入或完整 URL 作为关联键。 |
| LOG-NFR-006 | 基数 | Prometheus label 禁止 user_id、workspace_id、task_id、URL 实参和错误正文；这些信息只进日志/trace attribute。 |
| LOG-NFR-007 | 时间 | 所有时间使用 UTC、带时区 ISO 8601；各进程必须使用可靠时钟并记录 duration_ms。 |
| LOG-NFR-008 | 留存 | access/application/security/trace 的保留与访问周期必须可配置，具体期限在上线地区和容量确认后量化。 |
| LOG-NFR-009 | 可测试 | 自动测试必须验证关联字段、脱敏、未知异常、exporter 故障降级和指标基数白名单。 |

## 6. 告警、失败路径与非目标

- 必要告警：API 5xx、数据库/Redis 连接耗尽、存储错误/孤立对象、schedule lag/misfire、RabbitMQ/Outbox 积压、Task unknown/超时、供应商/媒体失败和日志丢弃。
- exporter 不可用：业务继续，增加 telemetry_export_failures_total；不得递归记录造成日志风暴。
- 敏感字段检测失败：安全相关事件优先拒绝字段并保留 event_name/trace，不输出原值。
- 不在 MVP 自研日志搜索 UI、APM、SIEM 或告警平台；具体 OpenTelemetry Collector 与日志后端由部署环境选择。
- 不把完整请求/响应 body、SQL 参数、RabbitMQ payload、模型提示或媒体内容作为默认调试日志。
