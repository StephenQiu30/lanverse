# 剧本解析全流程需求

## 1. 目标

用户上传一份整本剧本后，系统必须在同一项目上下文中完成来源固化、分集、场景/人物/制作任务提取、人物出场集数聚合和逐集分镜表生成。任何自动化结果都必须带来源证据、可审阅、可重放，失败不得伪装成完成。

## 2. 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| REQ-UPL-001 | 支持上传 DOCX、Markdown 和直接文本；保存原始内容、内容哈希、来源版本、语言和权利声明。 | P0 |
| REQ-UPL-002 | 上传与导入必须幂等；相同幂等键和相同输入回读同一结果，不同输入冲突。 | P0 |
| REQ-ANA-001 | 解析由 FastAPI 进程内的 Skill Harness 执行；显式集标记通过确定性 Tool 保序拆分，语义理解通过结构化 Skill 完成。 | P0 |
| REQ-ANA-002 | 解析结果至少包含剧集、场景、人物、对白、制作任务和候选镜头；所有结果引用原文 code point 范围。 | P0 |
| REQ-ANA-003 | 人物结果包含规范名、别名、首次出现集数和完整出场集数；跨分块同一人物必须稳定合并。 | P0 |
| REQ-ANA-004 | 每个场景包含所属集数、场景标题、地点、时段、人物、道具、摘要和制作任务。 | P0 |
| REQ-ANA-005 | Skill 只产出结构化候选，不能直接写业务事实；业务服务校验输入哈希、范围、引用和版本后再持久化。 | P0 |
| REQ-ANA-006 | 长剧本必须按集/场景分块并行解析后确定性聚合，不得截断原文或遗漏显式剧集。 | P0 |
| REQ-BRD-001 | 每个已物化剧集都能通过 Skill Harness 生成分镜表，覆盖该集所有必需叙事单元。 | P0 |
| REQ-BRD-002 | 分镜行至少包含序号、标题、叙事目的、景别、机位、运镜、画面构图、动作、对白/旁白、时长、音频意图、资产引用和连续性风险。 | P0 |
| REQ-BRD-003 | 分镜生成输入冻结到剧本版本、叙事结构版本和资产版本；输入变化使旧结果过期，不能静默覆盖。 | P0 |
| REQ-BRD-004 | 用户可以逐条接受、修改或忽略候选分镜，并在批准后原子写入正式分镜表。 | P0 |
| REQ-RUN-001 | 上传、解析和分镜生成的状态必须持久化，至少区分 queued、running、needs_review、succeeded、failed、unknown 和 cancelled。 | P0 |
| REQ-RUN-002 | 超时或响应丢失必须进入 unknown 并要求对账；不可区分外部副作用不得盲目重试。 | P0 |
| REQ-UI-001 | 前端提供一条连续主路径，用户能看到当前阶段、失败原因、下一动作和最终逐集分镜表。 | P0 |
| REQ-UI-002 | 用户不需要进入 Admin、Agent 或内部任务页面才能完成剧本解析。 | P0 |

## 3. 非功能需求

| ID | 需求 |
| --- | --- |
| REQ-NFR-001 | 所有业务服务使用 Python 3.11 + FastAPI；不保留 Go 服务或独立 Agent 运行时。 |
| REQ-NFR-002 | PostgreSQL 是业务事实源；Redis、RabbitMQ 和 MinIO 只承担缓存/协调、异步投递和对象存储职责。 |
| REQ-NFR-003 | Workspace/Project 边界在 API、Worker、Skill 输入和对象存储路径中一致执行。 |
| REQ-NFR-004 | OpenAPI 由 FastAPI 导出，前端客户端由同一契约生成，CI 阻止漂移。 |
| REQ-NFR-005 | 不使用 Docker 作为开发或验收前提，直接复用本机依赖。 |
| REQ-NFR-006 | 不实现旧接口、旧数据结构或旧运行时兼容层。 |
| REQ-NFR-007 | 日志、错误和追踪不得记录完整剧本、凭据、签名 URL 或模型密钥。 |

## 4. 范围边界

身份、Workspace、项目和对象存储仅作为剧本主流程的支撑能力保留。独立管理后台、邀请、团队扩展、通用聊天 Agent、画布、媒体生成和未来平台模块不属于当前交付。
