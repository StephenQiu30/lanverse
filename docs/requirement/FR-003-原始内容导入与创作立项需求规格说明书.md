# FR-003 原始内容导入与创作立项需求规格说明书

## 1. 目的与范围

接收创意、梗概、小说片段、故事或已有剧本，保全原始内容和来源，并在高成本制作前形成可确认的创作任务书。

## 2. 主业务流程

1. 用户提交原始内容、来源和使用权声明。
2. 系统固定原始内容版本，识别内容类型、完整程度和导入失败范围。
3. 用户定义题材、受众、单集规模、语言、画幅、风格、节奏、预算、交付目标和禁用项。
4. 系统检查目标缺失和显性冲突。
5. AI 可提出改编和补充建议，但均保持待确认。
6. 有权责任人确认唯一当前立项基线。

## 3. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-003-001 | 系统应接收平台支持的文本粘贴或文件导入。 | P0 |
| FR-003-002 | 系统应保存不可被整理或改编结果覆盖的原始内容版本。 | P0 |
| FR-003-003 | 系统应识别输入属于创意、梗概、小说、故事、分场剧本或其他类型。 | P0 |
| FR-003-004 | 系统应生成导入报告，列明成功、失败和无法判断的范围。 | P0 |
| FR-003-005 | 系统应记录原作名称、作者、来源、取得方式、权利声明和允许用途。 | P0 |
| FR-003-006 | 系统应把派生内容关联到原始内容片段，或明确标识为新增内容。 | P0 |
| FR-003-007 | 系统应记录题材、受众、平台、语言、集数、目标时长、画幅、分辨率和交付范围。 | P0 |
| FR-003-008 | 系统应记录叙事基调、视觉风格、节奏、参考方向和禁用内容。 | P0 |
| FR-003-009 | 系统应记录项目预算上限、目标日期和质量目标。 | P0 |
| FR-003-010 | 系统应检查立项目标中的必填缺失和显性冲突。 | P0 |
| FR-003-011 | 系统应将 AI 生成的分集、删减、合并、增写或目标补充标识为待确认提案。 | P0 |
| FR-003-012 | 系统应允许责任人确认、重新打开或废止立项基线，并保留历史版本。 | P0 |

## 4. 业务规则

- BR-003-001：原始内容是不可变来源事实，整理和改编结果是派生版本。
- BR-003-002：无法判断的原著事实不得由系统虚构为确定事实。
- BR-003-003：立项确认只表示生产目标明确，不表示剧本、资产或制作条件已就绪。
- BR-003-004：禁用项的优先级高于普通创作偏好。
- BR-003-005：来源或权利未知不得默认视为可商用。

## 5. 数据与权限要求

- DR-003-001：保存原始文件或文本、哈希、来源片段、顺序和导入报告。
- DR-003-002：保存派生内容到来源片段的映射、增删改类型和人工决定。
- DR-003-003：保存创作任务书、版本、确认人、确认时间和影响关系。
- 只有内容创作者可编辑草稿；立项确认权限必须单独授予。

## 6. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 文件损坏、加密或不支持 | 导入失败，不创建伪成功记录。 |
| 仅部分解析成功 | 保留已完成范围，并允许补充或重试失败范围。 |
| 权利声明缺失 | 允许保存受限草稿，但阻止商业制作和正式交付。 |
| 立项目标冲突 | 阻止确认并列出冲突；不得擅自修改目标。 |

## 7. 验收标准

- AC-003-001：修改改编稿后，原始内容和哈希保持不变。
- AC-003-002：任一改编段落均可反查原文依据或显示“新增内容”。
- AC-003-003：缺少目标时长或交付范围时，立项不能被确认。
- AC-003-004：已确认立项被编辑时，系统创建新草稿且旧基线不变。

## 8. 非目标与依赖

不定义文本解析模型、文件解析库或创作页面。依赖 [FR-018](FR-018-内容权利安全与AI标识合规需求规格说明书.md)。
