## 1. 需求概述

Lanverse 需要用 Redis 降低可重建热点读的压力，用对象存储保存媒体字节，并使延迟、周期和恢复任务在进程重启后继续执行。PostgreSQL 仍是业务、Task 和调度事实源；Redis、对象存储和 RabbitMQ 不得替代这些事实。

2026-08-04 已确认并实现当前首个真实调度用例：每个未完成 UploadSession 在同一数据库事务中建立 one-off 到期计划；到期后由 PostgreSQL lease 与唯一 ScheduleFire 创建 Task+Outbox，经 RabbitMQ 和 Media Worker 幂等删除 MinIO 临时对象。运维端只可查询、暂停、恢复和立即触发已登记的 `expire_upload_session`，不开放任意 handler、函数路径、pickle 或用户 cron。该局部接受不代表 interval/cron、三种 misfire、完整租约故障矩阵或 PT-SCH-001/002 已整体 accepted。

同日完成第二个真实 handler `cleanup_expired_uploads`：每 Workspace 唯一 interval Schedule 以 UTC 固定秒数/run_once 补偿 one-off 缺失或暂停留下的过期上传，只删除 pending、已到期且未形成版本的临时对象。真实 PostgreSQL/RabbitMQ/MinIO 契约证明版本化对象与 active Location 不受影响，存储故障会回滚并重投。该局部接受仍不代表 cron、skip/catch_up/DST、完整故障矩阵或 PT-SCH-001/002/003 整体 accepted。

同日完成 PT-MED-005 所需的第三个白名单 handler `retire_media_location`：位置迁移经服务端复制与 size/sha256 校验后切换唯一 active，旧位置保存 `retire_after` 并创建 one-off 退役计划；窗口内回滚会重排 active/retiring 并重新开始完整窗口。真实 PostgreSQL/RabbitMQ/MinIO 证明提前触发不删除、到期后真实删除和 Storage 故障回滚重投。该业务用例 accepted 仍只构成 Scheduler 的局部证据，不接受通用 cron/DST/misfire 故障矩阵。

2026-08-04 全量 Scheduler 收口的产品语义已固定：cron 使用数字五段表达式与 IANA timezone，时区数据必须由锁定的 `tzdata` 提供；DST 春季不存在的本地分钟不触发，秋季重复的本地分钟只在第一个 fold 触发一次。`skip` 丢弃超出宽限的历史时点，`run_once` 把全部到期时点合并为最接近当前的一次，`catch_up` 只触发最接近当前的有界 `max_catch_up`。三种策略收敛后 `next_fire_at` 都必须严格晚于本次数据库时钟，禁止跨循环无界补发。

同日上述语义已完成实现和真实验收：生产 dispatcher 以 PostgreSQL `CURRENT_TIMESTAMP` 为权威时钟，数字五段 cron/IANA/DST、三种 misfire、多实例 `SKIP LOCKED`、租约回收、Fire/Task/Outbox 原子边界、2/4/8/16 秒退避、第五次失败人工处置、未登记 handler/非法 payload 首次停止、RabbitMQ 断连恢复和重复消息幂等均通过。Studio 只允许 owner 配置已存在的 `cleanup_expired_uploads`，不开放通用创建、函数路径或用户 payload。PT-SCH-001/002/003 的本地 MVP 范围 accepted，证据见[持久调度、故障恢复与受控运维验收](../acceptance/arrived/014-持久调度故障恢复与受控运维验收.md)。

当前开发与 MVP 对象存储固定使用 MinIO。生产上线可以根据地域、合规、可用性和成本选择阿里云 OSS，但切换不得改变 MediaVersion ID、权限、完整性或访问契约。

PT-STO-001 的接受范围固定为本机已配置 MinIO 的真实私有 bucket：八项 ObjectStoragePort 操作、网络调用前的 key/TTL 校验、有界线程与操作超时、缺对象/拒绝访问/完整性不匹配/依赖不可用四类稳定错误，以及统一的 size/MIME/流式 SHA-256 校验。必须用实际预签名 PUT/GET、匿名 GET 拒绝、服务端 copy、大于 5 MiB 的 multipart、ETag 与 SHA-256 差异、删除幂等、错误凭据、不可达 endpoint 和上传半失败取得证据；默认 skipped 或内存 fake 只能辅助开发，不能接受任务。环境中只使用已配置凭据，不读取、输出或写回 `.env`。

2026-08-04 上述范围已完成实现和真实验收：MinIO 端口契约 6/6、PostgreSQL/RabbitMQ/MinIO/ffprobe 媒体栈 4/4、空 Provider Key 浏览器 9/9 通过；错误内容不创建 MediaVersion，原 one-off 到期事实可真实删除临时对象。PT-STO-001 accepted，证据见[MinIO 对象存储端口验收](../acceptance/arrived/022-MinIO对象存储端口验收.md)；PT-STO-002 因尚未选定 OSS/地域/RAM 权限保持 `conditional/not-applicable`。

高成本生成保护只能使用 Redis 作为可丢失的原子计数与短期去抖，不得把它变成请求、幂等或费用事实源。服务端必须先回读 PostgreSQL 幂等事实并重算价格/确认项；只有高成本新提交才消费全局和 Workspace 窗口。相同幂等键与相同输入在数据库事务失败后可安全重试且不重复计数，相同键绑定不同输入必须冲突。Redis 不可用或窗口不足时高成本命令必须零业务写入并返回可解释重试信息，低成本命令继续由 PostgreSQL 规则执行。

上述无 Provider 工程增量已由本机真实 Redis 与 PostgreSQL 联合契约证明：并发脚本严格收敛全局/Workspace 数量，同摘要不重复计数，PostgreSQL 成功事实优先回放；重新预检后的新请求在 Redis 断连时零新增 GenerationRequest/Task/Reservation/CostEntry/Outbox。默认 Seedream/Seedance 仍不可用，因此这里只接受工程增量，不提前接受 PT-CCH-002 产品任务或 S4。

首个缓存用例固定为已登录用户读取单个 Workspace 详情：PostgreSQL 必须先完成账号有效性与 Membership 授权，Redis 只缓存不含角色的 Workspace 投影。缓存 key 使用登记 namespace、schema version、Workspace scope 和业务 revision；更新、归档、恢复在数据库事务提交后失效当前 revision 指针。Redis miss、过期、清库、超时、断连或失效失败都回源/保留 PostgreSQL 结果，不改变写事务。2026-08-04 真实本机 Redis、PostgreSQL API、指标、受控 namespace CLI 和完整浏览器回归均通过，PT-CCH-001 已接受；高成本保护 PT-CCH-002 仍等待生成提交能力。

## 2. 事实与实体需求

| 编号 | 事实/实体 | 需求 |
| --- | --- | --- |
| INF-ENT-001 | CacheEntry | 是带 namespace、schema version、scope、TTL 的可丢弃副本，不是数据库实体或审计证据。 |
| INF-ENT-002 | StorageLocator | 由 storage profile、bucket、object key 组成，只在 media 内部使用，不替代 MediaVersion ID。 |
| INF-ENT-003 | StorageProfile | 表示当前 MinIO 或已批准 OSS 适配配置；凭据不得入库或进入日志。 |
| INF-ENT-004 | Schedule | 归属 Workspace，保存稳定 key、一次性/周期规则、时区、下次触发时间、过期策略、状态和 revision。 |
| INF-ENT-005 | ScheduleFire | 表示 Schedule 在某个计划时刻的唯一触发证据，并关联由此创建的 Task/Outbox。 |

## 3. 缓存功能需求

| 编号 | 需求 |
| --- | --- |
| INF-FR-001 | 系统可缓存能从 PostgreSQL 重建的热点读模型、短期权限投影和供应商静态能力元数据；未经明确登记的查询不得自动缓存。 |
| INF-FR-002 | 缓存必须使用有限 TTL 和版本化 key；数据库写入提交后必须失效受影响 key，不得先删缓存后回滚数据库。 |
| INF-FR-003 | 缓存命中后仍必须校验 ActorContext 和 Workspace 边界；不得缓存预签名 URL、token、密钥、Task 真实状态或费用账本。 |
| INF-FR-004 | Redis 不可用时，普通已授权读取必须回源 PostgreSQL；高成本命令的限流失去保护时必须拒绝或降级，不得无限放行。 |
| INF-FR-005 | 运维必须能按 namespace 失效缓存和查看命中/未命中、延迟、错误与内存压力，但不得浏览用户业务正文。 |

## 4. 对象存储功能需求

| 编号 | 需求 |
| --- | --- |
| INF-FR-006 | MinIO 和 OSS 适配必须共同支持私有对象、受限直传/下载、HEAD、分片上传、临时对象删除和服务端完整性校验；MVP 的 multipart 由 `put` 内部的 SDK 自动分片，不向业务暴露厂商 upload-id/part。 |
| INF-FR-007 | 业务模块只使用 MediaVersion ID；仅 media 可解析 StorageLocator、调用 SDK 或生成短期访问能力。 |
| INF-FR-008 | 新对象必须绑定明确 StorageProfile；上线切换默认只影响新写入，旧对象在完成复制、hash 校验和原子切换前仍从原存储读取。 |
| INF-FR-009 | 不得把 ETag 等同内容 hash；单次上传和分片上传都必须保留平台 sha256、大小和类型校验。 |
| INF-FR-010 | 对象存储不可用时不得产生“已可用”MediaVersion；孤立对象必须通过可重试登记或受控清理收敛。 |

## 5. 任务调度功能需求

| 编号 | 需求 |
| --- | --- |
| INF-FR-011 | 系统必须支持一次性到期任务和受控周期任务，用于过期上传清理、unknown 对账、失败补偿、留存清理和运维扫描。 |
| INF-FR-012 | Schedule 和下次触发时间必须持久化；Scheduler 重启、多实例或短时停机不得遗失或重复产生同一 ScheduleFire。 |
| INF-FR-013 | 每次到期触发必须在同一 PostgreSQL 事务中写 ScheduleFire、业务 Task 和 Outbox；Scheduler 不直接调用供应商、FFmpeg 或执行重业务。 |
| INF-FR-014 | 过期策略必须显式选择 skip、run_once 或有上限 catch_up；恢复后不得无界补发历史任务。 |
| INF-FR-015 | 暂停 Schedule 只阻止新触发，不伪装取消已创建 Task；手动立即触发产生新的唯一 ScheduleFire 和审计事件。 |
| INF-FR-016 | 调度领取或 Task/Outbox 创建失败必须保存受限错误、次数和下次尝试时间；重试必须退避且达上限后告警/人工处置，不得忙循环。 |

## 6. 接口与非功能需求

| 编号 | 交接面 | 需求 |
| --- | --- | --- |
| INF-IF-001 | 应用 ↔ Redis | 类型化 get/set/delete/namespace invalidate；超时与错误不泄漏 key 中的租户信息。 |
| INF-IF-002 | media ↔ ObjectStorage | 统一八项端口操作；`stat` 返回大小、类型和诊断用 ETag；稳定区分 not-found、access-denied、integrity-mismatch、unavailable。 |
| INF-IF-003 | Scheduler ↔ PostgreSQL | 领取到期 Schedule、唯一写入 Fire、推进 next_fire_at 和回收超时 lease。 |
| INF-IF-004 | Scheduler → RabbitMQ | 仅经 Outbox Publisher 发布到期工作通知；RabbitMQ 不保存未来计划。 |

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| INF-NFR-001 | 一致性 | Redis 丢失或过期不得改变业务结果；ScheduleFire 必须使用数据库唯一约束保证一次业务触发。 |
| INF-NFR-002 | 安全 | Redis 和对象存储使用最小权限、受控网络和 secret 注入；生产 OSS 使用 RAM 最小权限，bucket 默认私有。 |
| INF-NFR-003 | 可用性 | 缓存故障允许可控回源；存储或调度故障必须按运行角色和受影响能力降级、告警并从持久事实恢复。API 的可选能力故障不得让无关普通读写整体 unavailable。 |
| INF-NFR-004 | 性能 | 缓存 TTL/命中率、Redis 连接数、对象存储并发、调度漂移和每批领取量在 PRD/压测中量化。 |
| INF-NFR-005 | 可观测 | 必须监控缓存命中/延迟/错误、存储操作/孤立对象、schedule lag/misfire/fire 结果，且不使用高基数 ID 作指标 label。 |
| INF-NFR-006 | 可维护 | 业务代码不得导入 Redis、MinIO 或 OSS SDK；缓存 namespace、StorageProfile 和 Schedule handler 必须显式登记。 |

## 7. 失败路径、非目标与待确认

- Redis 清空或故障：从 PostgreSQL 重建，不修复“丢失的业务状态”。
- MinIO/OSS 超时：保留 UploadSession/Task 可恢复状态，对未知写入先 HEAD/hash 对账；凭据/签名拒绝不得误报为瞬态不可用。
- Scheduler 超时：过期 lease 由其他实例回收；唯一 Fire 约束阻止重复 Task。
- MVP 不开放用户自定义 cron、工作流画布、Redis 队列/业务状态、跨云双写或自动多云切换。
- 待确认生产地域与 OSS 选型、数据迁移窗口、缓存容量/TTL、后续周期业务清单和发布环境恢复 SLO；Scheduler 的本地 MVP misfire 语义不再待确认。
