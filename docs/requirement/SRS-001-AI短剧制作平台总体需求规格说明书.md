# AI 短剧制作平台总体需求规格说明书

## 1. 编制目的

本文件定义 Lanverse AI 短剧制作平台的产品定位、系统边界、用户角色、端到端业务流程、统一状态语义、需求编号、功能目录和 MVP 范围。

本套规格参考 ISO/IEC/IEEE 29148:2018 对需求应当明确、单一、可验证和可追踪的原则，但不声明标准认证。

## 2. 产品定位

Lanverse 是面向短剧创作者和制作团队的 **AI 短剧制作操作系统**。平台不把“一次生成一段视频”等同于“完成一集短剧”，而是管理从内容、资产、分镜、生成、声音、剪辑、审核、成本、合规到交付的完整生产闭环。

平台目标：

- 把创意、小说或剧本整理为可版本化的分集、场次和镜头生产计划。
- 以带来源证据的事件理解、改编策划和受控 Agent 协作降低长篇内容改编成本。
- 建立角色、场景、服装、道具、风格和声音的稳定资产身份。
- 以镜头为主要高成本生产单元，支持多候选、局部返工和完整生成谱系。
- 把配音、口型、字幕、音乐、音效和基础粗剪纳入同一项目。
- 在生成前说明能力限制和预计成本，在生成后记录实际成本与失败责任。
- 把审核、权利、安全、AI 标识和技术质检作为正式交付门禁。

## 3. 首发产品范围

建议首发范围为：

- 画幅：9:16。
- 单集时长：60～180 秒。
- 内容形态：风格化漫剧或轻量动画。
- 生产方式：按 3～8 秒镜头生成候选，再在时间线上组成单集。
- 交付目标：可完整观看、可审、具备基础发布规格的单集视频及配套文件。

首发非目标：

- 自研基础视频大模型。
- 无需人工判断的一键整集成片。
- 完整专业级非线性编辑器、调色和混音工作站。
- 开放任意节点、插件或模型市场。
- 观众端付费播放、复杂广告系统和创作者分账。

## 4. 主要用户角色

| 角色 | 核心责任 |
| --- | --- |
| 工作空间所有者 | 成员、归属、预算、模型策略、敏感操作和空间存续 |
| 制片人/项目负责人 | 立项、范围、进度、预算、审批责任和交付 |
| 编剧 | 故事、分集、剧本、对白和剧情事实 |
| 导演/分镜师 | 场次拆镜、镜头语言、节奏、分镜和艺术审核 |
| AI 制作人员 | 资产参考、制作参数、候选生成、选片和局部返工 |
| 声音/后期人员 | 配音、口型、音乐、音效、字幕、时间线和输出 |
| 审核/法务人员 | 艺术审核、整集批准、权利、安全和合规门禁 |
| 外部审片人 | 在指定版本和期限内查看或评论，不获得成员权限 |
| 平台运营人员 | 在明确事件授权下处理故障、费用、风险和申诉 |

岗位名称不直接产生权限。所有者、管理员、创作者、审核者、查看者和运营事件身份必须映射到明确操作权限。

## 5. 端到端业务流程

1. 建立账户、工作空间、项目和创作目标。
2. 导入创意、小说或剧本，固定原始内容和权利声明。
3. 适用时形成带证据的来源事件提案、故事骨架和改编策略，并经人工确认。
4. 形成结构化剧本、分集、场次、对白和剧情节拍。
5. 建立故事圣经以及角色、场景、服装、道具、风格和声音资产。
6. 确认剧本基线和视觉圣经基线。
7. 编制分镜与镜头生产计划，并完成分镜审批。
8. 检查权限、资产、能力、预算、权利和安全条件。
9. 按镜头生成图片或视频候选，进行比较、选片和局部返工。
10. 完成对白、配音、口型、字幕、音乐、音效和基础粗剪。
11. 进行候选审核、整集复核、技术质检和合规门禁。
12. 形成固定交付版本，导出成片和发行材料。

## 6. 生产门禁

| 门禁 | 适用来源 | 进入条件 | 通过结果 |
| --- | --- | --- | --- |
| GATE-01 剧本基线确认 | 产品流程 | 适用项目的分集、场次、动作、对白与剧情事实完整 | 形成唯一当前剧本基线 |
| GATE-02 视觉/声音基线确认 | 产品流程与一致性风控 | 适用项目的角色、场景、造型、道具、风格和声音基准就绪 | 形成可引用的视觉/声音基线 |
| GATE-03 分镜审批 | 产品流程与成本风控 | 适用项目的镜头目的、镜头语言、时长和资产引用完整 | 允许进入高成本镜头生产 |
| GATE-04 成片批准 | 法定义务、渠道规则与企业风控 | 整集、技术、权利、安全与标识门禁通过 | 允许形成正式交付版本 |

GATE-01～03 是默认生产模板，可按项目类型、内容形态和风险等级配置为必需或不适用；不适用时必须记录原因。GATE-04 中适用于当前地区、渠道和用途的强制项不得绕过。

## 7. 统一状态语义

| 业务事实 | 正式含义 | 不得自动等同于 |
| --- | --- | --- |
| 内容基线已确认 | 一个叙事范围存在唯一当前可生产版本 | 资产已就绪或允许生成 |
| 任务执行完成 | 一次生产尝试结束 | 候选可用或审核通过 |
| 候选已产生 | 一次尝试形成待判断结果 | 审核通过或正式采用 |
| 候选审核通过 | 固定候选满足本轮审核目标 | 当前采用或整集通过 |
| 当前采用 | 一个使用位置选择了明确版本 | 正式交付 |
| 整集复核通过 | 固定单集版本通过整体质量判断 | 权利、安全或 AI 标识通过 |
| 正式交付 | 固定版本通过强制门禁并形成交付记录 | 外部渠道已经上线 |
| stale/待复核 | 上游变化使下游依据可能失效 | 自动删除、替换或重做 |

## 8. 全局业务规则

- BR-SRS-001：所有经确认的内容、资产、候选、审核、采用和交付版本均不得原位覆盖。
- BR-SRS-002：AI 生成的文本、分镜、媒体、翻译和检测结果在人工确认前均为提案或候选。
- BR-SRS-003：机器任务状态与创作审核状态必须分离。
- BR-SRS-004：上游变化只产生影响记录和 `stale/待复核` 状态，不自动删除、替换或重新生产。
- BR-SRS-005：每项消费操作必须绑定用户、项目、业务对象、输入版本、制作尝试和用量记录。
- BR-SRS-006：权利状态未知不得默认视为可商用。
- BR-SRS-007：供应能力不得在未获授权时静默切换。
- BR-SRS-008：查看、编辑、生成、审核、采用、导出和费用管理必须分别授权。
- BR-SRS-009：个人项目可由同一人兼任多个角色，但仍须执行明确的自审和批准动作。
- BR-SRS-010：所有正式交付必须能够追溯到内容、资产、任务、模型能力、成本、审核和合规证据。
- BR-SRS-011：Agent 的计划、执行结果、复核报告和记忆均不得自动成为内容基线、审核决定、当前采用或正式交付。

## 11. MVP 验收目标

- 用户能够从已有故事或剧本完成一集 60～180 秒短剧的可审粗剪。
- 基准规模为 12～20 个镜头、目标成片 60 秒的项目，其平台处理时间目标为 P50 不高于 45 分钟、P90 不高于 2 小时；其他 60～180 秒项目必须按时长和镜头数分段报告，在另行接受阈值前不得混入该基准判定；人工等待和外部供应超时单独统计。
- 主角跨镜人工一致性通过率目标不低于 85%。
- 每个镜头最多 3 个候选时，获得可用候选的比例目标不低于 60%。
- 镜头级局部重做成功率目标不低于 90%，且不得改变无关镜头、时间线片段或采用关系。
- 平台控制面任务可靠完成率目标不低于 98%，重复扣费为零。
- 90% 的已结算任务，其生成前成本预估与实际结算相对误差目标不高于 15%。
- 导出成功率目标不低于 99%，音画同步误差目标不高于 100ms。
- 100% 真人肖像和声音克隆任务存在有效授权，并在适用时具备个人信息处理的单独同意证据。
- 100% 需要标识的交付版本包含适用的显式标识和文件元数据中的隐式标识，并记录内容编号等制作要素信息。

指标计算口径：

正式验收采用预先冻结且连续 14 个 UTC 自然日的窗口，纳入窗口内全部符合条件样本，不得挑选成功样本；事实源为服务端权威 Project/Episode/Shot、Task/Attempt、Review、追加成本账本、授权/同意记录、ComplianceEvidenceManifest、Delivery Manifest 和质检记录，客户端遥测仅作诊断。平台自动重试按原逻辑任务合并，用户重新授权的收费重试计新逻辑任务；用户取消、业务拒绝和外部供应失败按下表处理并分别报告，禁止改记为平台成功。比例指标以全窗口汇总分子/分母计算，不平均各项目比例；每项分别判定，任一目标未达即失败。

| 指标 | 验收口径 |
| --- | --- |
| 平台处理时间 | 判定样本仅为窗口内完成、12～20 个镜头且目标成片 60 秒的基准项目；从生产批次持久化受理至固定可审粗剪生成，扣除有起止证据的用户暂停，供应等待计入端到端值并另报分段，供应超时终止样本记失败；P50≤45 分钟且 P90≤2 小时才通过。其他 60～180 秒项目按时长和镜头数分段报告，在阈值另行接受前不参与本项判定。 |
| 主角跨镜一致性 | 样本为 120 个镜头中预先登记的全部主角相邻/跨场检查项；分子为固定样片版本经具名人工评审通过项，分母为全部可评审项，无主角项在抽样前登记排除；全窗口汇总比例≥85% 才通过。 |
| 可用候选比例 | 分母为已授权最多 3 个候选尝试的全部有效镜头，分子为其中至少一个固定候选通过审核的镜头；自动重试不增加 3 个候选上限，用户在首个尝试前取消可排除，供应失败占用对应尝试并单列归因；汇总比例≥60% 才通过。 |
| 镜头级局部重做能力 | 分母为窗口内已受理且非用户取消、明确绑定一个目标镜头版本的逻辑重做请求，自动重试合并；分子为目标镜头形成新候选且所有无关镜头、时间线片段和采用关系均未变化的请求，以 Shot/版本差异与 ReworkLink 为事实源，汇总比例≥90% 才通过。 |
| 控制面可靠完成率 | 分母为已到声明截止时间的唯一已受理控制面逻辑任务，自动重试合并；用户取消、业务拒绝和确认的供应失败排除并分别报告，平台超时、丢失或不可恢复错误计失败；Task/Attempt 对账的汇总比例≥98% 才通过。 |
| 成本预估误差 | 样本为具有提交前冻结预估和实际非零结算的逻辑计费任务；免费技术重试合并、重新授权收费重试分开、取消/供应失败无结算者单列；逐笔计算 `abs(实际结算－提交前预估) ÷ max(实际结算, 最小计价单位)`，至少 90% 样本误差≤15% 才通过。 |
| 导出成功率 | 分母为非用户取消的逻辑导出请求，系统重试合并，分子为目标规格下 Delivery Manifest 完整且全部校验通过的请求；固定输入外的重新导出计新请求，汇总比例≥99% 才通过。 |
| 音画同步误差 | 样本为每个正式验收单集预先固定的片头、中段、片尾及口型关键点；以质检记录的音视频绝对时间差为事实，取所有点最大值，最大值≤100ms 才通过。 |
| 真人肖像/声音授权完整率 | 分母为窗口内全部使用可识别真人肖像、人脸替换、声音克隆或生物特征参考的任务及其交付版本；分子为执行和交付时均存在可核验、未过期且绑定主体、用途、地区/渠道、对象版本的授权及适用单独同意证据的样本，以版本化授权/同意记录和 ComplianceEvidenceManifest 为唯一权威证据；完整率必须为 100%，任一适用样本缺失、过期、不匹配或不可核验即 `failed` 并阻断执行/交付。 |
| AI 生成/合成交付标识完整率 | 分母为适用法规或渠道规则判定含 AI 生成/合成内容的全部交付版本；分子为显式标识、文件元数据隐式标识及适用制作要素信息均经 Delivery Manifest、ComplianceEvidenceManifest 和文件质检一致验证的版本；完整率必须为 100%，任一适用版本缺失、不可读取或不可核验即 `failed` 并阻断交付。 |

首轮正式验收样本应覆盖不少于 3 类代表性项目、10 个完整单集和 120 个镜头；`insufficient/观察` 仅用于预先登记后确无适用样本或数量未达到统计最低要求，不得用于掩盖适用门禁证据缺失。真人授权或 AI 标识任一适用样本缺失、过期、不匹配或不可核验必须记为 `failed` 并保持执行/交付阻断。验收报告须保存窗口、纳入/排除清单与理由、归因、重试合并关系、分子/分母、聚合查询和源记录版本。以上数值是首发可验证目标；SRS 转为 `accepted` 前须评审目标、口径、样本计划和容量假设，真实样片、供应能力与首发规模验证只能在已接受的可执行 Plan 后开展，并作为 Acceptance 与 `implementation_release` 证据。

## 13. 评审和变更控制

- 文档状态从 `review` 进入 `accepted` 前，产品、业务、架构、研发和测试必须共同评审。
- 涉及费用、肖像、声音、内容安全和监管的需求，必须增加财务、法务或治理人员评审。
- 未量化的“高成本、长期无进展、代表性项目”等词必须转换为明确阈值或可配置规则。
- TCR 只固定首发技术基线和约束；偏离基线必须通过 ADR 说明候选比较、影响、迁移、回滚和验证证据。
- 正式实现开始前，适用 Requirement、Design、PRD 和可执行 Plan 必须均为 `accepted`，且 Design 已通过 [ADG-001](ADG-001-前后端集成契约与设计完整性评审门禁.md) 的 `design_entry`；`implementation_release` 只在实现和 Acceptance 证据完成后执行。
- 上游规格变化时，应先更新受影响需求和验收标准，再推进 Design、PRD、Plan 和 Acceptance。
