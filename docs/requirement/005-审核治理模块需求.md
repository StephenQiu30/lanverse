# REQ-005 审核治理模块需求

- 状态：部分 accepted（S2：GOV-ENT-001、GOV-FR-001/002/009、GOV-IF-001/002、GOV-NFR-002/005/007）；其余范围 proposed
- 输入：`001-平台总体需求概述.md`、`arrived/002-用户与空间模块需求.md`、`003-项目模块需求.md`、`004-媒体模块需求.md`

- 下游：REQ-006 至 REQ-010

## 1. 需求概述

审核治理模块必须提供贯穿剧本、资产、生成和交付的权利与质量门禁。它通过受控资源类型和固定版本 ID 记录授权、审核和决定，不复制被审对象正文，也不替代业务模块的版本管理。

MVP 必须支持用户登记素材权利、对镜头/时间线提出问题、批准或退回版本、记录内容检查结果并为交付生成必要标识与审计链。

2026-07-30，产品负责人通过 D-005 签认接受 S2 的 Consent、撤回、证明媒体和 RightsGate 需求范围；审核、内容检查、交付标识和审计查询仍在后续切片按真实证据接受。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| GOV-ENT-001 | Consent | 必须记录权利主体、授权类型、使用范围、有效期、证明媒体、状态和撤销原因。 |
| GOV-ENT-002 | Review | 必须引用受控资源类型、固定版本 ID、提交人、审核状态和当前阻塞问题数量。 |
| GOV-ENT-003 | Issue | 必须记录问题类型、严重度、目标位置、描述、责任人、状态和解决说明。 |
| GOV-ENT-004 | Decision | 必须以追加记录表达批准、退回或撤销，关联 Review、actor、依据和时间。 |
| GOV-ENT-005 | ModerationResult | 必须记录检查对象版本、规则/服务版本、结果、命中项和人工处置。 |
| GOV-ENT-006 | Label | 必须记录显式/隐式生成标识、内容编号、适用文件和写入验证结果。 |
| GOV-ENT-007 | AuditEvent | 必须记录受控动作的 actor、Workspace、目标、结果、时间和关联 trace；不得保存无关敏感正文。 |

受控资源类型在契约中枚举；不得接受任意字符串引用未知表或绕过所属模块权限。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| GOV-FR-001 | editor/owner 必须能登记、读取、修改授权范围和撤销 Consent，并关联证明媒体。 |
| GOV-FR-002 | 剧本、资产、生产和交付模块必须能查询固定版本在指定用途与时间是否具备有效授权。 |
| GOV-FR-003 | editor/owner 必须能把 ShotSpecVersion、Candidate/MediaVersion 或 TimelineVersion 提交审核。 |
| GOV-FR-004 | 审核人必须能创建、修改、指派、关闭和重开 Issue，并定位到具体镜头、时间范围或资产。 |
| GOV-FR-005 | 审核人必须能批准或退回 Review；存在阻塞 Issue、授权失效或内容检查未通过时不得批准。 |
| GOV-FR-006 | 系统必须对规定的输入和交付版本执行内容检查，并保留自动结果和人工处置。 |
| GOV-FR-007 | 交付前必须生成并验证适用的显式/隐式标识及内容编号，失败时阻止交付成功。 |
| GOV-FR-008 | owner 必须能按 actor、资源、动作和时间查询必要审计记录；普通 editor/viewer 只看业务所需记录。 |
| GOV-FR-009 | 撤销授权后必须阻止新的生成和交付，并在相关项目/镜头上返回明确阻塞原因。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| GOV-IF-001 | Consent 登记/修改/撤销 | ActorContext、主体、范围、期限、证明 MediaVersion | Consent 与有效状态；范围非法或证明无权访问时拒绝 |
| GOV-IF-002 | 权利门禁查询 | Workspace、资源类型/版本、用途、时间 | allowed、blocking_reasons、适用 Consent ID |
| GOV-IF-003 | 提交 Review | 受控资源类型、固定版本、审核范围 | Review；重复提交同一未变化版本必须幂等 |
| GOV-IF-004 | Issue CRUD 与状态命令 | Review ID、目标位置、描述、严重度、责任人 | 最新 Issue/Review 摘要；已批准版本变更返回冲突 |
| GOV-IF-005 | 批准/退回 Review | Review ID、期望状态、说明 | 追加 Decision 和最新 Review；门禁未通过返回阻塞清单 |
| GOV-IF-006 | 登记/查询内容检查 | 资源版本、规则版本、结果 | ModerationResult；重复回调不得重复产生处置 |
| GOV-IF-007 | 生成/验证标识 | Delivery/MediaVersion、内容编号信息 | Label 与验证结果；写入或验证失败时返回不可交付 |
| GOV-IF-008 | 审计查询 | owner ActorContext、受控筛选、分页 | 脱敏 AuditEvent 列表 |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| GOV-NFR-001 | 不可抵赖 | Decision、ModerationResult、Label 和 AuditEvent 只追加，修改必须产生新记录而非覆盖历史。 |
| GOV-NFR-002 | 权限 | 审核和审计查询必须遵守 Workspace 与角色边界；不能通过资源引用探测其他空间数据。 |
| GOV-NFR-003 | 一致性 | 审核决定必须绑定固定版本；被审版本变化后原批准不得自动适用于新版本。 |
| GOV-NFR-004 | 可追溯 | 每个交付标识必须关联审核决定、授权结果、内容检查和最终 MediaVersion hash。 |
| GOV-NFR-005 | 隐私 | 授权证明和审计内容按最小必要原则展示，日志不得复制身份证明或人脸/声音原始材料。 |
| GOV-NFR-006 | 可用性 | 外部内容检查不可用时必须进入明确待处理/未知状态，不得默认为通过。 |
| GOV-NFR-007 | 留存 | 授权、审计和内容标识的期限或删除触发条件必须按事实类型集中配置；用途终止且引用、计费/对账、申诉、争议、安全事件、法定义务与 legal hold 全部解除前不得清理。 |

## 6. 生命周期与失败路径

- Consent：`active → expired | revoked`；续期产生可追溯的新有效范围，不覆盖撤销历史。
- Review：`draft → submitted → approved | changes_requested`；新版本需要新 Review 或明确重新提交。
- Issue：`open ↔ resolved`；关闭必须记录说明，退回后仍保留历史。
- 外部检查超时进入 `pending/unknown`，允许查询和人工处理；不得伪造失败或通过。
- 已交付内容随后发生授权撤销时必须产生审计和风险提示，历史交付不自动删除，由人工处置决议和已接受留存触发条件决定后续处置。

## 7. 非目标与后续切片门禁

- 不提供法律结论、自动版权判定、企业 DLP 或复杂多级审批流。
- 不建立任意资源类型的通用审批引擎；只支持短剧主流程中明确枚举的对象和动作。
- D-005 已接受中国大陆首发、产品负责人合规责任角色、授权 fixture、未成年人/无标识导出门禁和逐类删除触发条件；真实敏感内容规则、生成标识样片、算法备案/安全评估适用性和其他上线材料仍由后续切片验收。
