# AI 视频生产平台目标需求总览

> 文档 ID：REQ-SYS
> 状态：reviewed v1（ready_for_design，待产品负责人接受）
> 日期：2026-08-20
> 范围：系统目标、产品边界、模块结果、全局规则与系统级验收
> 下游：[目标产品与功能模块设计](../design/002-AI视频生产平台目标产品与功能模块设计.md)

## 1. 需求结论

平台需要解决的不是单次“文生视频”，而是连续内容从来源、结构化生产知识、镜头规划、生成、选择、质量修复、审阅到交付的可控生产过程。

用户必须能够理解并修改 AI 的分析结果；在昂贵或不可逆动作发生前看见输入、影响、资源上限和权利风险；在任务失败、超时或局部变化后只恢复受影响范围；在任何时候追溯一个交付结果使用了什么来源、设定、镜头、模型输出和人工决定。

## 2. 目标与成功结果

### 2.1 系统目标

1. 把创意、剧本或品牌简报转成可人工校对的结构化生产知识。
2. 把人物、场景、道具、世界规则和风格从提示词中分离为稳定、可版本化的事实。
3. 把叙事意图转换为有覆盖关系、可编辑和可局部重做的镜头方案。
4. 在调用外部模型前冻结输入、能力、参考、资源上限和授权范围。
5. 保存多个候选及其来源，让人工选择、拒绝和替代成为显式决定。
6. 把技术问题、语义偏差和跨镜连续性问题转成有证据的局部修复闭环。
7. 让评论、批准和风险接受绑定正确版本，而不是绑定会漂移的“当前结果”。
8. 生成可复现、不可变且通过权利与完整性检查的交付快照。

### 2.2 用户可观察的完成结果

对于一个目标内容单元，用户可以：

- 从原始来源定位到场景、节拍、人物、镜头和候选；
- 修正人物身份、状态、关系和跨场连续性；
- 预览镜头覆盖与低消耗初稿；
- 审批一批明确上限的生成任务；
- 比较候选并记录采用理由；
- 定位质量问题并只重做选定范围；
- 在冻结版本上完成审阅和批准；
- 获得成品、素材及其清单组成的不可变交付快照。

### 2.3 成功指标

| ID | 指标 | 定义 |
| --- | --- | --- |
| SYS-KPI-001 | 首个可审阅初稿时间 | 从来源可解析开始，到目标范围具有结构、人物和镜头初稿的时间 |
| SYS-KPI-002 | 首轮候选采用率 | 无额外生成即被采用的候选占比 |
| SYS-KPI-003 | 连续性一次通过率 | 首轮审阅无高严重度连续性问题的镜头占比 |
| SYS-KPI-004 | 局部返工率 | 修复仅影响所选镜头或区段的次数占全部返工次数比例 |
| SYS-KPI-005 | 失败与未知消耗率 | 失败、重复或未知任务产生的外部资源消耗占比 |
| SYS-KPI-006 | 交付可复现率 | 可从清单解析全部固定输入、决定和输出的交付占比，目标 100% |

具体目标值必须由真实试点基线确定；没有样本时不得用任意百分比宣称已达标。

## 3. 用户和职责

| 用户职责 | 主要结果 | 受限动作 |
| --- | --- | --- |
| 组织所有者/管理员 | 管理空间、成员、模型准入和组织策略 | 不能代替项目创作决定，除非同时具有项目职责 |
| 制片人 | 管理范围、资源上限、进度、批准和交付 | 不能绕过权利、安全和完整性门禁 |
| 主创/导演 | 决定叙事、人物、镜头、候选和修复方向 | 不能修改组织安全策略或无限授权资源消耗 |
| 编剧/叙事编辑 | 校对来源、场景、节拍、人物和关系 | 默认不能批准高消耗生成或正式交付 |
| 制作操作员 | 执行已批准计划、处理异常、比较候选 | 不能扩大冻结计划的输入、模型或资源上限 |
| 审片人 | 在冻结版本上评论、请求修改或批准 | 默认不能修改生产事实或启动生成 |
| 访客 | 查看被授权项目和交付摘要 | 不能下载原始受限媒体或执行写操作 |

角色名称可以在实施时合并，但以下权限必须保持独立：查看、编辑生产事实、发起外部调用、批准资源越界、接受质量风险、批准权利/安全策略例外、批准正式交付和管理组织策略。

## 4. 系统范围

### 4.1 包含范围

- 连续短剧、广告系列、品牌内容和栏目化短视频；
- 创意、脚本、小说改编稿、品牌简报和结构化脚本来源；
- 人物、场景、道具、服装、风格、世界规则和生产参考；
- 场景、节拍、对白、动作、镜头、分镜帧和预演；
- 图像、视频、语音、音乐、音效和字幕的生成记录与候选选择；
- 生成预检、资源上限、外部调用、失败恢复和未知结果对账；
- 技术、语义、连续性、安全和品牌质量检查；
- 评论、审阅、批准、基础装配、渲染、交换包和不可变交付；
- 工作区协作、权利、安全、审计、用量治理、模板和受控集成。

### 4.2 明确非目标

- 替代完整专业非线性剪辑系统；
- 提供任意代码节点或无限制自动化脚本；
- 一句话无审阅生成并自动发布整季内容；
- 训练通用基础模型；
- 建设公共模板、模型或素材交易市场；
- 自动发布到所有外部平台；
- 定价、套餐、订阅、账单、发票、支付、增长和融资计划。

基础装配用于完成平台内审阅与可复现交付，不扩展为专业 NLE 的完整替代品。

## 5. 端到端价值流

```text
建立项目目标
  → 导入并保全来源
  → 校对场景、节拍和人物身份
  → 发布生产知识与连续性约束
  → 规划镜头并生成低消耗预演
  → 预检并批准高消耗生成计划
  → 执行、摄取和比较候选
  → 发现质量问题并局部修复
  → 冻结审阅版本并做出决定
  → 基础装配、渲染和交付快照
```

每一步都必须允许手工完成。Agent 可以提高首稿速度，但 Agent 不可用时，已建立的项目事实、决定和后续操作仍然可用。

## 6. 模块级需求基线

### SYS-FR-001 组织、身份与访问（M01）

详细需求：[M01 组织、身份与访问](./001-M01-组织身份与访问需求.md)。

系统必须以工作区隔离成员、内容、任务、媒体、策略和审计；必须分别授权编辑、外部调用、风险接受和交付批准；成员失效后不得继续通过旧会话或直接对象 ID 操作。

### SYS-FR-002 项目组合与内容单元（M02）

详细需求：[M02 项目组合与内容单元](./002-M02-项目组合与内容单元需求.md)。

用户必须能按项目、系列和内容单元组织目标、格式、语言、时长、质量、截止时间和资源上限，并从项目概览定位当前阻塞、待决定事项和影响范围。

### SYS-FR-003 导入与叙事理解（M03）

详细需求：[M03 导入与叙事理解](./003-M03-导入与叙事理解需求.md)。

系统必须保留原始来源和版本，生成可回到原文证据的结构化提案；用户必须能修正场景、节拍、对白、动作、人物提及和歧义，而不是只能接受整份 AI 输出。

### SYS-FR-004 生产知识与一致性（M04）

详细需求：[M04 生产知识与一致性图谱](./004-M04-生产知识与一致性图谱需求.md)。

系统必须区分人物或资产的稳定身份、资料版本、剧情状态、关系、有效范围和生产参考；任何上游改变必须能在提交前显示受影响镜头、计划、候选、审阅与交付。

### SYS-FR-005 分镜与镜头规划（M05）

详细需求：[M05 分镜与镜头规划](./005-M05-分镜与镜头规划需求.md)。

用户必须能把叙事节拍转换成稳定镜头，手工或通过提案创建、拆分、合并、重排和锁定镜头；系统必须显示覆盖缺口、引用状态和跨镜连续性约束。

### SYS-FR-006 Agent 与可视化画布（M06）

详细需求：[M06 Agent 与可视化画布](./006-M06-Agent与可视化画布需求.md)。

Agent 必须区分说明、建议和待执行操作，逐项展示目标、影响与风险；画布、表格和 API 必须操作同一领域事实，布局和任意连线不得成为第二事实源。

### SYS-FR-007 生成规划、提示编译与路由（M07）

详细需求：[M07 生成规划、提示编译与路由](./007-M07-生成规划提示编译与路由需求.md)。

外部调用前，系统必须显示并冻结目标、输入版本、参考、能力、模型、参数、资源用量区间、最大上限、权利结论和允许的降级范围；批准计划不等于启动任务或采用结果。

### SYS-FR-008 提供商与耐久执行（M08）

详细需求：[M08 提供商与耐久执行](./008-M08-提供商与耐久执行需求.md)。

系统必须处理提交、回调、轮询、取消、限流、重复消息、下载中断和对账；超时但无法判断外部任务是否存在时必须显示未知并先对账，不得盲目重发。

### SYS-FR-009 媒体、候选与选择（M09）

详细需求：[M09 媒体、候选与选择](./009-M09-媒体候选与选择需求.md)。

每个媒体结果必须有完整性状态、来源和派生关系；候选评分只能推荐，人工采用、备选、拒绝和替代必须保留为独立历史决定。

### SYS-FR-010 质量、连续性与修复（M10）

详细需求：[M10 质量、连续性与修复](./010-M10-质量连续性与修复需求.md)。

系统必须把技术、语义、连续性、安全和品牌问题绑定到确定版本及证据位置；用户必须能确认、驳回、接受风险或创建局部修复，并在新结果到达后定向复检。

### SYS-FR-011 资源配额与用量治理（M11）

详细需求：[M11 资源配额与用量治理](./011-M11-资源配额与用量治理需求.md)。

系统必须在任务前显示资源用量区间和上限，在任务后按项目、镜头、计划和失败类型解释实际消耗；本模块不得形成客户账单、订阅或支付功能。

### SYS-FR-012 审阅、协作与批准（M12）

详细需求：[M12 审阅、协作与批准](./012-M12-审阅协作与批准需求.md)。

评论和决定必须绑定冻结审阅版本、对象和时间码；审片人必须能批准、请求修改或拒绝，历史决定不得因项目当前版本变化而漂移。

### SYS-FR-013 装配与交付（M13）

详细需求：[M13 装配与交付](./013-M13-装配与交付需求.md)。

用户必须能进行完成平台闭环所需的基础画面、音频、字幕装配；正式交付必须经过完整性、质量和权利预检，并在全部输出完成后形成不可变快照和清单。

### SYS-FR-014 权利、安全与治理（M14）

详细需求：[M14 权利、安全与治理](./014-M14-权利安全与治理需求.md)。

上传、外发、分享和交付必须按来源声明、许可范围、肖像/IP、内容策略、地域和保留期检查；拒绝、例外和风险接受必须可审计。

### SYS-FR-015 模板与集成接口（M15）

详细需求：[M15 模板与集成接口](./015-M15-模板与集成接口需求.md)。

已批准的项目结构、风格、镜头和规则可以受控复用；外部 API、Webhook 和私有能力必须使用可撤销身份、版本化契约和与界面相同的权限及业务规则。

## 7. 全局业务规则

| ID | 规则 |
| --- | --- |
| SYS-BR-001 | AI 输出默认是提案，不能直接成为已批准事实、主选、风险接受或交付批准。 |
| SYS-BR-002 | 稳定身份、内容修订、人工决定、执行过程和交付快照必须分别表达。 |
| SYS-BR-003 | 已批准版本和已交付快照不得原地覆盖；变化通过新版本或新决定表达。 |
| SYS-BR-004 | 高消耗或外发动作必须基于已批准且冻结的计划。 |
| SYS-BR-005 | 未知状态不能折算为失败或成功，必须提供对账和人工处理路径。 |
| SYS-BR-006 | 上游修改前必须计算影响；计算不可用时不得宣称下游仍然有效。 |
| SYS-BR-007 | 任何入口都必须执行相同鉴权、并发、幂等、权利和状态规则。 |
| SYS-BR-008 | 工作区隔离覆盖查询、写入、异步执行、媒体、事件、审计和备份恢复。 |
| SYS-BR-009 | 评分、排序、推荐和质量检测不能自动替代人工采用或批准。 |
| SYS-BR-010 | 商业计费与系统资源用量治理严格分离。 |
| SYS-BR-011 | 所有外部模型调用都必须先固定调用范围、输入版本、数据外发、资源上限和治理结论；媒体生成进入 M07/M08，Agent 推理进入 M06 AgentRun，二者不得互相伪装或绕过门禁。 |
| SYS-BR-012 | 质量风险接受、权利/安全策略例外、资源例外和审阅决定是不同责任事实，权限、范围和到期规则不得复用为一个通用“批准”。 |

## 8. 交付优先级

模块编号表示责任边界，不表示按模块建设十五个服务。实施必须按纵向闭环推进：

1. **切片 A：手工事实主线**——工作区、项目、来源、结构、人物、最小镜头、假候选、人工选择和顺序预演；
2. **切片 B：受限 Agent 提案**——结构分析、人物拆解和拆镜提案，可逐项接受、编辑和拒绝；同时提供最小关系/影响接管视图，不建设完整空间画布；
3. **切片 C：一次真实生成**——一个图像能力、一个视频能力、冻结计划、权利门禁、未知对账和候选摄取；
4. **切片 D：质量与局部修复**——连续性、影响报告、问题证据、修复计划和定向复检；
5. **切片 E：审阅与不可变交付**——冻结审阅包、时间码评论、基础装配、渲染、清单和交付快照；
6. **切片 F：团队与组织扩展**——项目角色、外部审片、画布、模板、企业治理和受控集成。

M01—M15 已分别建立详细 Requirement 和对应模块 Design；产品交付与实施按 PRD/Plan 的 A—F 纵向切片推进，首先验收切片 A 的手工事实主线，再分别进入 B 的受限 Agent 和 C 的真实生成。

## 10. 系统级验收场景

### AC-SYS-001 从来源到可审阅初稿

给定包含多个场景、同名人物和人物别名的来源，当用户完成结构与身份校对并批准首稿时，系统产生有来源证据的场景、节拍、人物和不少于目标数量的镜头；任何低置信结果仍明确标记为待处理。

### AC-SYS-002 冻结生成计划

给定一组可生成镜头，当用户审批外部调用时，系统先显示输入版本、参考、路由、资源用量区间、最大上限和权利结论；审批后修改项目当前设定不改变已批准计划的冻结内容。

### AC-SYS-003 未知外部结果

给定外部提交在响应前超时，当系统无法确认任务是否已创建时，用户看到未知和对账入口；在确认未创建前系统不会自动再次提交。

### AC-SYS-004 局部人物状态变化

给定人物服装状态只在部分场景生效，当用户发布新状态时，系统列出受影响镜头、未执行计划、审阅和装配；用户只更新选定范围，其他镜头和历史交付保持不变。

### AC-SYS-005 冻结审阅与修复

给定审片人在冻结版本的时间码指出人物不一致，当制作人员创建修复并生成新候选时，旧审阅决定仍绑定旧版本，新候选通过定向复检后进入新的审阅包。

### AC-SYS-006 不可变交付

给定交付输入完整且权利有效，当渲染和清单校验全部完成时，系统才创建交付快照；之后重排、重选或修改设定不会改变该快照和清单。

### AC-SYS-007 工作区隔离

给定另一工作区的已知对象 ID、媒体地址或后台操作 ID，当用户、Worker 或集成尝试访问时，系统拒绝并不泄露对象是否存在，审计能够定位尝试来源。

### AC-SYS-008 Agent 降级

给定 Agent 或模型不可用，当用户继续制作时，已批准事实、手工工作台、候选选择、质量处理和交付流程仍可使用，且不会丢失已提交决定。

### AC-SYS-009 固定脚本端到端基准

给定同一份经过人工金标的 3—5 分钟中文短剧脚本，当系统完成导入、结构/实体校对、分镜、计划、候选、审阅和交付时，验收证据必须记录首个可审阅结构与分镜时间、人工修正、Prompt 可见性、参考绑定粒度、首轮候选采用、外部资源消耗、失败重试和最终交付完整性；未执行的阶段不得报告为通过。

### AC-SYS-010 中途变更与最小重算

给定已完成首轮候选的项目，当用户依次改变人物服装、地点状态并重排两个镜头时，系统必须分别展示真实依赖和预计资源，只使必要的镜头、计划、评估、审阅或装配待复核；未受影响候选和历史交付保持不变，验收保存变更前后清单和实际重算范围。

## 11. 首轮试点默认基线

在产品负责人签认更具体配置前，Design、PRD 和 Plan 使用以下可替换默认值，不把它们编码为不可变业务规则：

| 配置 | 默认基线 | 变化影响 |
| --- | --- | --- |
| 首批使用者 | 5—15 人的小型中文视频制作团队 | 默认职责、协作和审阅强度 |
| 试点内容 | 单个 3—5 分钟 ContentUnit，10—40 个 Shot | 容量、分页、验收数据和资源上限 |
| 首期来源 | DOCX、Markdown、纯文本；PDF/OCR 默认关闭 | 解析器、锚点和失败恢复验收 |
| 首个交付组合 | 审阅 MP4 + 有序镜头素材包 + Manifest；正式母版预设在切片 E 签认 | M13 预检、渲染和快照内容 |
| 外部能力 | 一个真实图像能力和一个真实视频能力；不宣称多模型路由完成 | M07/M08 的验收边界 |
| 敏感内容 | 真人肖像、未公开 IP 和品牌客户素材默认阻止外发，直到 M14 声明与授权通过 | 上传、Agent、生成、分享和交付门禁 |
| 默认批准职责 | 主创批准叙事/镜头/主选，制片人批准资源与交付，审片人批准 ReviewPackage，权利负责人批准治理例外 | M01、M07、M10—M14 权限矩阵 |

## 12. 开发前必须确认的产品配置

1. 第一批目标用户是独立主创、小型制作团队还是品牌内容团队；
2. 第一种内容单元和试点规模，包括集数、镜头数、时长和媒体规格；
3. 首个正式交付格式：审阅 MP4、正式母版、剪辑交换包或组合；
4. PDF/OCR 输入能力的启用条件、语言、页码映射和人工复核范围；
5. 是否包含真人肖像、未公开 IP 或品牌客户素材；
6. 首批模型、地域、数据保留策略和外部资源上限；
7. 哪些动作需要制片人、主创、审片人或组织管理员分别批准。

这些配置会改变验收数据与默认策略，但不得改变稳定身份、版本、提案、计划、执行、决定和快照分离的全局规则。
