# AI媒体任务与候选采用

## 1. 范围

本能力以持久任务运行文本、图片、视频和逐句 TTS Provider 调用，保存不可变候选，并支持 2 秒轮询、失败定位、重启恢复、取消和明确重试。

## 2. 主流程

1. 操作者基于固定输入和已配置能力，为每个明确使用位置提交独立生成命令；前端可并行提交并展示 ProductionTask 集合。
2. 系统为每条命令原子持久化一个 ProductionTask、初始 ProductionAttempt 和待调度事实，再由持久工作流执行。
3. 前端每 2 秒查询权威任务状态，显示进度、错误和可执行动作。
4. Provider 结果写入对象存储并登记为不可变 MediaVersion/Candidate。
5. 操作者为角色/场景资产参考、镜头图片、镜头视频和每条语音选择唯一当前候选，形成 Adoption。
6. 自动重试在原 Task 下创建新 Attempt；用户重试失败项时创建引用原 Task 的新 Task，不改变无关 Adoption。

## 4. 业务规则

- BR-003-001：ProductionTask 表示业务目标，ProductionAttempt 表示一次明确执行，GenerationCandidate 表示结果，Adoption 表示操作者选择；四者不得合并。
- BR-003-002：执行成功不等于候选已采用；只有 active Adoption 能进入下游固定快照。
- BR-003-003：运行中 Attempt 永远使用创建时输入，不读取“最新版本”。
- BR-003-004：每个使用位置对应一个独立 ProductionTask；多项生成只以 ProductionTask 集合展示和调度，任何 Task 可独立失败或由用户新建重试 Task。
- BR-003-005：TTS 只能使用服务端批准的非克隆合成音色。
- BR-003-006：不得因供应失败静默切换 Provider 或模型。
- BR-003-007：usage slot 唯一键为 `usage_type + usage_id + input_version_id + input_hash`；类型只允许 `asset_image/shot_image/shot_video/speech_audio`，且 `input_hash` 必须覆盖该类型的全部兼容性输入。旧版本或旧输入哈希的 active Adoption 不得满足新生产。
- BR-003-008：`input_outdated` 是只读版本兼容投影，不是任何版本、Candidate 或 ProductionTask 状态；Task 只使用 FR-003-002 的枚举。
- BR-003-009：每个媒体 Task 只有一个名为 `primary` 的输出槽且最多一个 ready Candidate；Provider 多余输出和取消后的迟到输出只可登记为 blocked，不可供采用。需要其他可选结果时创建新 Task。
- BR-003-010：`speech_audio` 的唯一当前 voice_id 来自 confirmed ScriptVersion 的 SpeechLine，并必须存在于服务端批准的非克隆逻辑音色目录；改变音色必须创建并确认新 ScriptVersion，旧语音候选不得满足新哈希。
- BR-003-011：`asset_image` 只允许角色或场景 CreativeAssetVersion；整体视觉风格没有图片 Candidate/Adoption，其 confirmed version ID 与 content_hash 必须进入相关镜头图片、镜头视频的 Prompt、SubmissionSnapshot 和 `input_hash`。

## 5. 数据要求

- DR-003-001：ProductionTask 保存目标、项目、使用位置、类型、状态、进度、错误、幂等作用域和可选 `retry_of_task_id`；当前 Attempt 从所属 ProductionAttempt 的状态与 `attempt_no` 投影，不在 Task 中保存冗余外键。
- DR-003-002：ProductionAttempt 保存父尝试、输入快照、能力配置、`provider_request_key`、调度/发送证据、状态和输出引用。
- DR-003-003：MediaVersion 保存对象键、媒体类型、大小、时长、尺寸/编码摘要、SHA-256 和来源 ProductionAttempt。
- DR-003-004：GenerationCandidate 保存 `usage_type/usage_id/input_version_id/input_hash`、媒体版本和创建来源；Adoption 对同一版本化 usage slot 实施最多一个 active 的唯一约束。

## 6. 异常与恢复

| 场景 | 必须行为 |
| --- | --- |
| 同键同载荷并发提交 | 返回同一 Task/Attempt，只产生一次供应副作用。 |
| 同键不同载荷 | 返回稳定冲突错误，不创建新记录或供应请求。 |
| Provider 超时或结果未知 | 进入 `unknown` 或对账流程，不伪装成功、不盲目重发。 |
| 取消后结果迟到 | 保存为隔离证据，不自动成为可选候选。 |
| 单个子任务失败 | 其他子任务继续，失败项显示可重试动作。 |

## 7. 验收标准

- AC-003-001：数据库故障注入证明 Task、Attempt、待调度记录全成或全不成，不存在孤立任务。
- AC-003-002：状态机契约测试覆盖全部状态、合法转换、终态不可回退和未知状态。
- AC-003-003：浏览器连续观察三次 2 秒轮询；刷新页面后仍显示相同标识和权威终态。
- AC-003-004：四类 Mock Adapter 通过同一契约套件；业务 API 响应不含供应商私有结构。
- AC-003-005：每个角色/场景资产和镜头均可取得并采用图片候选；整体视觉风格提交 `asset_image` 被拒绝且没有 Candidate/Adoption。缺少任一必需角色/场景或镜头图片 Adoption 时视频 Task 被拒绝，受理后其 Attempt 固定引用全部图片版本及 confirmed 风格版本/哈希。
- AC-003-006：6～10 个镜头各有通过探测的视频候选和唯一 active Adoption，重复采用不会产生两个 active 值；实际时长分别短/长 90,000 ticks 的候选可 ready，超出 90,000 ticks 的候选直接进入 MediaVersion invalid/Candidate blocked 且不能采用。
- AC-003-007：一条语音条目首次失败后，用户可创建仅针对该条目的新 Task 并成功；其他语音条目的 Task/Attempt 和音频哈希不变。
- AC-003-008：从任一候选可反查完整生成链；同一媒体 Task/usage slot 最多一个 ready Candidate，多余或迟到输出 blocked；新 Task 生成候选后旧候选及哈希仍可读取。
- AC-003-009：同一命令并发提交 20 次只形成一个 Task、一个初始 Attempt 和一次 Provider 调用；可重试错误只按上限增加 Attempt，用户重试只增加一个带 `retry_of_task_id` 的新 Task及其初始 Attempt。
- AC-003-010：在 Provider 受理后终止 Worker，恢复时使用原请求键对账且没有第二次可计费调用。
- AC-003-011：分别重启 API，并在 TaskJob 领取前后、Provider 提交、下载和结果登记中重启同一 `backend-worker`；过期租约被安全领取，已受理任务恢复到可判断状态且无需手工改库，后端入口仍只有 API 与 Worker。
- AC-003-012：对一个镜头执行失败、取消和重试后，比较证明其他镜头/语音条目的 Adoption 和媒体哈希完全不变。
