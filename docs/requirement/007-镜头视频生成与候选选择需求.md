### 1.1 证据与产品决策边界

- **公开页面或已授权只读客户端可见事实：** VibeReels 在 Episode 下以有序 Shot 组织视频制作；单镜头可见多个生成历史版本、一个主版本、多个星标入口和单版本／批量下载入口。
- **公开事实不能证明：** 其主选是否固定当时的资产版本、批量下载是否只取主选、下载包是否按镜头顺序冻结、服务端任务恢复和成本账本是否准确。
- **Lanverse 产品推导：** 每个视频结果是不可变 Candidate；星标和主选是两种独立人工决定；一个 Shot 在制作中允许没有主选，但同时至多一个当前主选，进入正式导出时必须恰有一个显式、有效主选；生成成功、最新成功、星标或最高评分均不得自动成为主选。

## 二、模块定位、目标与 KPI

### 2.1 模块定位

本模块把固定的镜头规格、关键帧和视觉参考提交给受控视频生成能力，形成可恢复的逐镜生产任务和多个原始视频候选，并让用户显式选择每个镜头当前采用的视频。它不负责剪辑或将多个视频组成一条成片。

### 2.2 用户结果

生成操作员或导演应能：

1. 在提交前知道固定输入、阻塞和预计消耗；
2. 为单镜头或选定镜头集合提交生成；
3. 刷新、断线或任务失败后继续了解真实状态；
4. 对同一 Shot 保留多个原始视频候选；
5. 比较、星标、拒绝和下载单个候选；
6. 显式指定一个当前采用版本，并在输入变化后重新确认；
7. 把每镜唯一有效主选交给素材包导出。

### 2.3 KPI 与质量门槛

| 指标 | 当前目标 |
| --- | --- |
| 候选不可变率 | 100%；重生成、重试或重选不覆盖已有候选媒体与输入快照 |
| 主选显式率 | 100%；所有 export-ready Shot 均有人工显式选择证据 |
| 星标误作主选 | 0 次 |
| 最新成功兜底 | 0 次；任何正式主选读取和正式导出均禁止 |
| 任务恢复准确率 | 刷新、重复消息和重复回调不产生重复候选或重复外部提交 |
| 局部失败隔离 | 单 Shot 失败不撤销同批其他 Shot 已成功的任务或候选 |
| 输入追溯率 | 100% Candidate 可追溯到 ShotSpec、关键帧、视觉参考、生成约束、尝试和媒体 |
| 内部消耗可解释率 | 100% 已完成或已终止任务显示预计、实际或未知原因，不设置商业收入指标 |

## 三、范围与非范围

### 3.1 范围

- 逐镜视频生成模式与输入预检；
- 单 Shot 和显式选定 Shot 集合的生成提交；
- CUR-PLT 唯一 WorkTask/ExecutionAttempt 的视频业务投影、进度阶段、取消、重试和未知状态处理；
- 生成结果和合法外部上传形成不可变视频候选；
- 单候选播放、信息查看、原始文件下载和并排比较；
- 星标、取消星标、拒绝和撤销拒绝；
- 每个 Shot 唯一显式当前主选及重新确认；
- 输入变化影响、镜头级视频就绪度与向 CUR-EXP 交接；
- CUR-PLT CostRecord 的任务级预计／实际消耗投影，仅用于产品打磨和额度保护；本模块不建立第二套成本事实。

### 3.2 非范围

- 视频裁切、拼接、变速、转码、滤镜、调色和转场；
- 字幕、配音、口型、音效、BGM、混音或音轨处理；
- 时间线、连续播放结果的录制、整集渲染或成片；
- 以最新成功候选、最近候选、星标候选或评分最高候选自动主选；
- 套餐、支付、账单、退款、毛利、商业 SLA 和运营后台；
- 训练模型、自托管 GPU 平台、通用工作流编排器；
- 固定供应商、SDK、数据库、消息系统或对象存储实现。

### 3.3 原始视频边界

本模块产生或接收“单镜头原始视频”：

- 原始媒体字节在登记后不可替换；
- 产品可生成预览封面或播放器信息，但不得以派生文件替代原始文件；
- 原始文件中若自带音轨，当前产品既不提取、编辑也不保证其质量；导出时保持原文件不变；
- 任何需要裁切、拼接或转码才能满足要求的视频，在当前阶段应被标记为不符合，而不是在本模块内处理。

## 四、用户角色与权限意图

| 角色 | 核心任务 | 允许的产品动作 |
| --- | --- | --- |
| 生成操作员 | 提交、监控和恢复逐镜视频任务 | 预检、提交、取消、按安全规则重试、上传、星标和标记问题 |
| 导演／分镜师 | 评估候选是否符合镜头目的 | 播放、比较、拒绝、显式设置或更换当前主选 |
| 制作人／项目负责人 | 控制范围、消耗和进入导出条件 | 查看任务／消耗摘要、确认高成本操作、查看或批准例外 |
| 观察者 | 查看逐镜生产进度 | 只读任务、候选、主选、来源和阻塞 |

上述名称是制作 persona，不是新增授权角色。当前 owner/editor 可执行生成、上传、任务命令、标记、主选与重新确认，viewer 只读；任何“制作人批准”仅表达职责，不得绕过 owner/editor/viewer 的统一授权事实。

## 五、核心使用场景

| 场景 | 成功结果 |
| --- | --- |
| 单镜生成 | 固定输入产生一个任务和若干不可变 Candidate，默认无主选 |
| 批量生成 | 每个 Shot 独立返回任务／失败，局部重试不重跑成功镜头 |
| 多轮候选 | 同一 Shot 的多次生成历史并存，可按输入和批次比较 |
| 外部视频补充 | 合法原始视频作为独立 Candidate，来源可追溯 |
| 星标与主选 | 可星标多个；只有显式“设为当前采用”改变唯一主选 |
| 输入变化 | 旧 Candidate 保留，当前选择变为待重新确认，导出被阻断 |
| 任务 unknown | 先对账或人工确认，不盲目生成第二次并产生双重费用 |

## 六、依赖与交接

### 6.1 前置依赖

- Shot 必须属于明确的当前或指定分镜基线；
- ShotSpecVersion 必须固定且满足视频生成必填要求；
- 视频模式要求的关键帧槽位必须有显式有效主选；
- 有序视觉参考必须固定且可用；
- 视频生成能力必须公开显示可用性、输入限制和预计消耗规则；
- 媒体登记、完整性检查和项目隔离必须可用。

### 6.2 向 CUR-EXP 的交接

每个 Shot 的导出读取必须获得：

- Shot 稳定身份及目标 StoryboardBaseline 内固定的 StoryboardOrderRevision；
- 当前 ShotSpecVersion；
- 显式 VideoSelection；
- 被选 VideoCandidate 及固定原始媒体；
- Candidate 的媒体状态、完整性摘要、原始扩展名和大小；
- 选择时间、选择人、输入匹配／重新确认状态；
- 任务和来源追溯摘要。

CUR-EXP 不得自行选择 Candidate，也不得以最新成功候选补缺。

## 八、详细功能需求

### 8.1 CUR-VID-FR-001 视频生成模式选择与提交前预检

**目标：** 在产生高成本任务前确认输入完整、能力可用和消耗可知。

**主流程：**

1. 用户选择 text_to_video、start_frame_to_video 或 start_end_frame_to_video 等产品模式；
2. 系统根据模式展示并固定 ShotSpec、关键帧主选和有序视觉参考；
3. 用户设置当前产品允许的时长、画幅、运动意图和候选数量；
4. 系统校验输入版本、媒体、权利、能力限制、项目额度与预计消耗；
5. 系统返回 ready、warning 或 blocked，逐项列出原因和下一动作；
6. 用户确认警告和预计消耗后方可提交。

**备选流程：**

- 无结束帧时可改选只要求开始帧的模式；
- 能力暂不可用时允许保存生成意图，待恢复后重新预检；
- 预计消耗无法可靠计算时显示 unknown，并按产品策略阻断或要求明确确认。

**失败与恢复：**

- 预检不创建生成任务或费用事实；
- 预检结果过期或依赖变化后必须重新预检；
- 不支持的参数不得静默忽略。

**业务规则：**

- 模式决定必需关键帧槽位；
- 预检展示的是内部制作消耗，不是向用户收费的商业报价；
- 预检必须固定 Candidate ID 和媒体版本，而非“当前关键帧”模糊指针。

### 8.2 CUR-VID-FR-002 为单 Shot 提交视频生成

**目标：** 为一个固定镜头创建可恢复、可追踪的生成任务。

**主流程：**

1. 用户从有效预检确认提交；
2. 系统重新核对 ShotSpec、关键帧、视觉参考、能力和消耗；
3. 系统创建一次不可变生成请求和持久任务；
4. 页面快速返回任务 ID、当前状态、固定输入摘要和取消能力；
5. 执行完成后按结果登记 Candidate 和实际消耗；
6. Candidate 默认未星标、未拒绝、未主选。

**备选流程：**

- 用户可明确提交多个候选数量，结果分别登记；
- 同一 Shot 可在不同固定输入下多次生成；
- 供应商同步返回时，页面仍以同一任务事实呈现，不形成特殊旁路。

**失败与恢复：**

- 重复确认同一提交不得创建第二次外部副作用；
- 执行失败必须给出是否可重试和下一动作；
- 结果状态不明时进入 unknown，不得自动重发。

**业务规则：**

- 请求创建后输入不可修改；
- 生成成功不自动改变 VideoSelection；
- 实际消耗以真实结果记录，不能用预计值伪装结算值。

### 8.3 CUR-VID-FR-003 为选定 Shot 集合批量提交

**目标：** 提升多镜生产效率，同时保持每镜独立恢复。

**主流程：**

1. 用户从当前 Episode 有序列表勾选一个或多个 Shot；
2. 系统逐镜预检并显示 ready、warning、blocked 和预计消耗；
3. 用户确认只提交 ready／已确认 warning 的 Shot；
4. 系统为每个 Shot 创建独立请求和任务，并返回批次引用及逐项结果；
5. 页面按 Shot 展示状态和失败原因。

**备选流程：**

- 用户可排除 blocked Shot 后继续其余项；
- 批次部分提交失败时，已成功创建的任务继续；
- 用户可只重试创建失败或安全失败的 Shot。

**失败与恢复：**

- 某 Shot 失败不得回滚其他 Shot 的已确认任务或候选；
- 批次页面刷新后必须从逐项任务事实恢复；
- 重试批次不得重提已成功或 unknown 的 Shot。

**业务规则：**

- 批量是独立单镜任务的集合，不产生模糊的全有或全无生成状态；
- 每项保存自己的输入和预计消耗；
- 用户必须看到将要提交的 Shot 数量和总预计消耗。

### 8.4 CUR-VID-FR-004 查询、恢复、取消、重试和对账任务

**目标：** 让用户始终基于真实任务状态行动，而不是靠页面等待时间猜测。

**主流程：**

1. 用户查看 Episode、Shot 或任务中心；
2. 系统显示 queued、running、waiting_external、succeeded、failed、cancelled 或 unknown，以及可验证进度阶段；`waiting_external` 面向用户显示为“Provider 处理中”；
3. 用户根据可用动作取消、重试或请求对账；
4. 系统返回最新事实和下一动作；
5. 刷新、断线或重新登录后恢复同一任务。

**备选流程：**

- 尚未发送到外部的 queued 任务可立即取消并释放未使用消耗；
- 外部已受理时取消显示 requested、accepted 或 rejected；
- 明确失败且无外部副作用时才允许重试并形成新 Attempt；
- unknown 先查询／对账，无法自动确定时进入人工处理。

**失败与恢复：**

- 取消失败不得伪装 cancelled；
- unknown 不得因超时自动变为 failed；
- 重复消息、重复回调和重复取消不得生成重复 Candidate 或重复释放。

**业务规则：**

- 进度只表示真实阶段，不以时间推算虚假百分比；
- 终态和实际消耗必须可解释；
- 用户刷新或播放器错误不是重提生成的依据。

### 8.5 CUR-VID-FR-005 登记并验证生成视频候选

**目标：** 将每个成功视频结果变成不可覆盖、可检查的镜头候选。

**主流程：**

1. 生成任务取得视频结果；
2. 系统保存原始媒体并检查可读性、时长、画幅、容器、视频轨和完整性；
3. 验证通过后登记 Candidate，固定来源任务、Attempt、输入和媒体；
4. 页面显示 Candidate 可用；
5. 候选等待人工播放、标记和选择。

**备选流程：**

- 一次 Attempt 可产生多个有序 Candidate；
- 媒体保存成功但部分元数据暂不可用时 Candidate 为 validating，不可主选；
- 视频带原始音轨时保持原字节，并标记“音频未处理”。

**失败与恢复：**

- 原始媒体损坏、缺视频轨或无法完整读取时 Candidate blocked，不得主选；
- 外部临时地址不得直接作为长期 Candidate；
- 媒体已保存但登记中断时必须基于同一结果恢复，不重新生成。

**业务规则：**

- Candidate 媒体和输入快照不可原地替换；
- 任务 succeeded 只有在结果可持续读取并完成必要登记后才成立；
- 候选顺序不代表优先级或主选。

### 8.6 CUR-VID-FR-006 上传外部单镜头原始视频候选

**目标：** 在生成能力不足或已有外部结果时补充可追溯候选。

**主流程：**

1. 用户选择目标 Shot 并上传单个或多个原始视频；
2. 填写来源、权利和可选生成说明；
3. 系统逐文件验证类型、大小、时长、视频轨、可播放性和完整性；
4. 合法文件各自登记为不可变 Candidate；
5. 新 Candidate 默认不成为主选。

**备选流程：**

- 重复媒体提示既有 Candidate，用户可直接查看；
- 文件包含未处理音轨时可保留，但页面明确当前产品不审核音频；
- 部分文件失败不影响其他文件登记。

**失败与恢复：**

- 不支持、损坏、超过已关闭并 accepted 的文件限制或无权利说明的文件拒绝进入 valid；
- 上传中断不产生可主选 Candidate；
- 当前产品不会为不兼容文件自动转码。

**业务规则：**

- 初始接受 MP4、WebM、MOV；单文件 500 MiB、时长 1～30 秒是 proposed 样片／验收假设。在 CUR-VID-OQ-003 关闭前，这两个数值只能用于样片验证和边界提示，不得成为需求进入 accepted 的 blocker 或正式拒绝依据；
- 当前正式验收至少保证 MP4／H.264 可播放、可选择和可导出；
- 其他格式若无法在产品内完成视觉检查，只能显示 blocked，不得设为当前主选；
- 上传 Candidate 与生成 Candidate 使用同一比较、标记和选择规则。

### 8.7 CUR-VID-FR-007 播放、比较和下载单个候选

**目标：** 让导演基于画面和固定输入作出可解释选择。

**主流程：**

1. 用户打开某 Shot 的候选历史；
2. 系统显示候选播放器、时长、尺寸、来源、生成时间、固定 ShotSpec、关键帧和视觉参考摘要；
3. 用户可选择 2～4 个候选进行同步或独立播放比较；
4. 当前主选、星标、拒绝、stale 和 blocked 分别显示；
5. 用户可下载某一个候选的原始文件。

**备选流程：**

- 支持按批次、输入、状态、星标和时间筛选；
- 无当前主选时明确显示“未选择当前视频”；
- 播放器不支持某文件时仍可显示来源与下载，但该 Candidate 不可成为当前主选。

**失败与恢复：**

- 单个媒体加载失败不影响其他候选；
- 下载必须返回目标 Candidate 的原始文件，不以代理预览替代；
- 比较或播放操作不得改变主选。

**业务规则：**

- 页面默认排序可以按时间，但不得把首项解释为当前；
- 原始下载文件名可读且包含稳定候选标识；
- 当前产品不提供在播放器中设入点、出点或保存裁切。

### 8.8 CUR-VID-FR-008 星标、取消星标和拒绝候选

**目标：** 支持候选筛选与质量反馈，同时不混淆正式采用。

**主流程：**

1. 用户星标或取消星标一个 Candidate；
2. 系统保存标记，VideoSelection 不变；
3. 用户可拒绝 Candidate，选择问题类型并填写可选说明；
4. Candidate 保留在历史，可通过筛选查看。

**备选流程：**

- 多个 Candidate 可同时星标；
- 当前主选也可星标；
- 用户可撤销拒绝，但旧决定继续可追溯。

**失败与恢复：**

- 标记冲突时回读最新状态并提示；
- blocked Candidate 可查看旧标记但不能新选；
- 标记保存失败不能误导用户认为主选已改变。

**业务规则：**

- starred ≠ selected；
- rejected ≠ deleted；
- 质量问题标签供产品打磨和后续重生成参考，不自动决定供应商或 Prompt。

### 8.9 CUR-VID-FR-009 显式设置每镜唯一当前主选

**目标：** 明确回答“这个镜头当前采用哪一个原始视频”。

**主流程：**

1. 用户完整播放或检查目标 Candidate；
2. 执行“设为当前采用”；
3. 系统展示旧主选、目标 Candidate、固定输入差异及未冻结导出影响；
4. 用户确认；
5. 系统验证 Candidate 属于同一 Shot、媒体 valid、输入匹配或已有明确重新确认；
6. 目标 Candidate 成为该 Shot 唯一当前主选，旧选择保留历史。

**备选流程：**

- 用户可取消当前主选，使 Shot 回到 missing_selection；
- 重选旧 Candidate 仍形成新的明确选择决定；
- 若 Candidate 输入与当前规格不同，可在产品允许时填写理由重新确认；未确认前不得选为 export-ready。

**失败与恢复：**

- Candidate 跨 Shot、跨 Project、stale 未确认、blocked 或媒体不可用时拒绝；
- 并发选择发生时，后请求必须看到冲突和最新主选；
- 重复选择当前 Candidate 返回既有当前状态，不制造多个当前主选。

**业务规则：**

- 制作中每 Shot 允许 0 或 1 个当前主选；export-ready 时必须恰好 1 个；
- 只有显式选择命令能改变当前主选；
- 生成成功、最新成功、星标、拒绝撤销、下载或播放均不能改变主选；
- 旧 Candidate、旧选择、星标和消耗记录不得因重选删除。

### 8.10 CUR-VID-FR-010 处理输入变化并形成导出就绪度

**目标：** 防止上游变化后继续把旧视频误认为当前有效结果。

**主流程：**

1. ShotSpec、分镜顺序、关键帧主选或视觉参考发生变化；
2. 系统定位受影响 Candidate 和当前 VideoSelection；
3. Candidate 历史和固定输入保持不变，输入匹配派生为 stale，当前选择进入 needs_reconfirmation；
4. 用户查看新旧输入差异；
5. 用户选择重新生成、选择其他 Candidate，或在查看差异后显式重新确认旧 Candidate；重新确认追加绑定当前输入摘要、操作者和理由的决定；
6. 系统重新计算每 Shot video_ready 状态并向 CUR-EXP 输出。

**备选流程：**

- 工作中仅顺序变化不使视频 Candidate stale；它只改变预览。新顺序必须随新的 StoryboardBaseline 显式发布后，才能成为新 ExportSnapshot 的目标顺序；
- 与画面无关且经产品规则确认的元数据变化可不影响选择；
- 批量查看可按 missing、stale、blocked、ready 筛选。

**失败与恢复：**

- 影响计算未知时状态 unavailable，正式导出必须阻断；
- 重新确认时当前输入再次变化，返回冲突；
- 不得自动生成新视频或自动切换到最新成功 Candidate。

**业务规则：**

- video_ready 至少要求：Shot 在目标基线 active、恰有一个显式当前主选、Candidate 媒体 valid、选择已针对当前输入确认；
- 输入变化的影响范围必须可解释到具体 Shot 和字段；
- 内部消耗不因主选变化而删除或重算历史。

## 九、实体、状态机与不变式

### 9.1 产品实体

| ID | 实体 | 产品含义 |
| --- | --- | --- |
| CUR-VID-ENT-001 | VideoGenerationIntent | 用户选择的视频模式与允许业务参数 |
| CUR-VID-ENT-002 | VideoGenerationRequest | 固定 Shot、规格、关键帧、参考和能力的一次不可变请求 |
| CUR-VID-ENT-003 | VideoTaskProjection | CUR-PLT WorkTask 在视频生成场景的类型化只读投影；不拥有或复制任务终态 |
| CUR-VID-ENT-004 | VideoAttemptReference | 对 CUR-PLT ExecutionAttempt 的类型化引用与脱敏摘要；不建立第二套执行尝试 |
| CUR-VID-ENT-005 | VideoCandidate | 一次生成或上传得到的不可变单镜头原始视频 |
| CUR-VID-ENT-006 | VideoCandidateDecision | 星标、拒绝、撤销和质量说明 |
| CUR-VID-ENT-007 | VideoSelection | Shot 当前显式主选、替换、取消和重新确认历史 |
| CUR-VID-ENT-008 | VideoReadiness | 基于当前基线、输入、主选和媒体的派生状态 |

### 9.2 状态机

- WorkTask/ExecutionAttempt：唯一状态事实由 CUR-PLT 定义；canonical 状态统一使用 `waiting_external`，本模块面向用户显示为“Provider 处理中”，不得另造同义 canonical 状态。取消、重试、unknown 对账均调用同一事实。
- Candidate：validating → valid／blocked／unavailable；`stale` 是固定输入相对当前目标输入的派生判断，不改原媒体或 Candidate 状态事实。
- 标记：unmarked ↔ starred；active ↔ rejected，彼此及主选相互独立。
- Selection：missing_selection → selected → needs_reconfirmation → selected；重新确认必须追加当前输入摘要、操作者和理由。重选产生 superseded 历史，取消回到 missing_selection。
- Readiness：incomplete、ready、stale、blocked、unavailable。

### 9.3 核心不变式

1. VideoCandidate 一旦登记，原始媒体、来源和固定输入不可替换。
2. 一个 Shot 同时至多一个当前 VideoSelection。
3. export-ready Shot 必须恰有一个人工显式、有效且已针对当前输入确认的主选。
4. 星标不等于主选，拒绝不等于删除。
5. 最新成功候选不得作为当前主选或正式导出兜底。
6. 生成、播放、下载、上传和比较都不自动改变主选。
7. 批量任务逐 Shot 独立恢复，局部失败不破坏其他结果。
8. unknown 未对账前不得盲目重试。
9. 输入变化保留历史 Candidate，并使受影响选择待重新确认；重新确认只恢复 Selection 有效性，不改写 Candidate 的固定来源。
10. 任何裁切、拼接、转码、字幕、音频和成片处理均不在本模块发生。

## 十、接口与文件需求

### 10.1 产品接口

| ID | 产品接口 | 必需输入 | 必需输出 |
| --- | --- | --- | --- |
| CUR-VID-IF-001 | 模式与能力查询 | Shot、目标用途 | 可用模式、输入要求、参数边界、可用性和消耗单位 |
| CUR-VID-IF-002 | 生成预检 | 固定基线、ShotSpec、关键帧、视觉参考和业务参数 | ready／warning／blocked、预计消耗、输入摘要和有效期 |
| CUR-VID-IF-003 | 单镜／批量提交 | 有效预检、目标 Shot、确认信息 | 逐 Shot 请求、任务、失败和批次引用 |
| CUR-VID-IF-004 | 任务查询与命令 | Task、期望状态、取消／重试／对账意图 | 最新任务、Attempt 摘要、消耗、错误和下一动作 |
| CUR-VID-IF-005 | 候选登记／上传 | 固定请求结果或 Shot＋原始文件＋来源 | Candidate、媒体验证状态或逐文件错误 |
| CUR-VID-IF-006 | 候选列表／比较／原始下载 | Shot、筛选、Candidate 集合 | 媒体、来源、输入、标记、选择和原始文件 |
| CUR-VID-IF-007 | 标记与主选 | Candidate、目标 Shot、期望当前输入／主选 | 最新决定、唯一当前主选或冲突 |
| CUR-VID-IF-008 | 视频就绪度 | 目标基线、有序 Shot、当前选择和媒体 | 每 Shot ready／missing／stale／blocked 及导出交接摘要 |

### 10.2 视频文件需求

- 生成结果与外部上传都必须保留单镜头原始文件；
- 初始外部上传接受 MP4、WebM、MOV；单文件 500 MiB、时长 1～30 秒是 proposed 样片／验收假设。在 CUR-VID-OQ-003 关闭前，这两个数值不得成为需求进入 accepted 的 blocker 或正式拒绝依据；
- 当前产品正式验收至少覆盖 MP4／H.264 的播放、选择、原始下载和导出；
- 每个 valid Candidate 必须记录原始扩展名、文件大小、时长、宽高、视频轨信息和完整性摘要；
- 仅有封面、临时地址、损坏字节或无视频轨的结果不能成为 valid Candidate；
- 文件名不作为 Candidate 身份；
- 不改变或剥离原文件中的音轨；当前产品不对音频内容作质量承诺。

## 十一、量化非功能需求

| ID | 类别 | 要求 |

| CUR-VID-NFR-001 | 容量 | 单 Episode 至少支持 120 个 active Shot；单 Shot 至少 20 个视频 Candidate |

## 十二、异常与恢复总则

| 异常 | 产品行为 |
| --- | --- |
| 视频能力不可用 | 预检 blocked，显示原因；不创建伪任务 |
| Provider 拒绝 | Task failed，显示是否可安全重试和实际消耗 |
| 外部状态 unknown | 保留预占／状态并先对账，不盲目重发 |
| 媒体下载或登记中断 | 基于同一外部结果恢复；不重新生成 |
| Candidate 损坏 | blocked，不能主选；保留来源用于排查 |
| 上游输入变化 | 选择 needs_reconfirmation；导出 blocked |
| 主选并发冲突 | 返回最新主选和差异；不形成双主选 |
| 外部上传不兼容 | 拒绝或 blocked；当前模块不自动转码 |

### 14.1 已决策事项

- 视频生成和受控上传都形成不可覆盖 Candidate；成功结果不自动成为当前采用版本。
- WorkTask、ExecutionAttempt 和 CostRecord 只归 CUR-PLT；本模块只保留视频业务投影和类型化引用。
- 每个 Shot 同一视频用途同时最多一个显式当前主选；最新成功、星标、播放和下载都不得代选。
- 输入变化使 Selection 进入 `needs_reconfirmation`；重新确认必须追加当前输入摘要、操作者和理由。
- 原始视频自带音轨时按原始媒体字节完整保存和导出；当前产品不得抽取、删除、替换、混音或承诺音频效果。

## 十五、术语

| 术语 | 定义 |
| --- | --- |
| VideoGenerationRequest | 固定单镜业务输入的一次不可变生成请求 |
| VideoTaskProjection | CUR-PLT WorkTask 在视频业务中的只读投影，用于展示固定输入、状态与下一动作，不拥有终态 |
| VideoAttemptReference | 对 CUR-PLT ExecutionAttempt 的类型化引用与脱敏摘要，不形成第二套外部尝试事实 |
| VideoCandidate | 不可覆盖的单镜头原始视频结果 |
| starred | 可同时标记多个的关注状态，不代表采用 |
| VideoSelection／当前主选 | 用户为一个 Shot 显式指定的唯一当前采用 Candidate |
| latest successful | 最近成功 Candidate；只是一种排序信息，不能用于正式主选或导出 |
| needs_reconfirmation | 上游输入已变化，旧选择必须人工重审 |
| video_ready | 目标 Shot 有且仅有一个有效、显式、已针对当前输入确认的主选 |
