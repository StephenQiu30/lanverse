## 使用规则

- 文件名使用 `01`～`08` 表示阅读和评审顺序，标题直接描述文档职责；`REQ-01`～`REQ-08` 仅保存在元数据和追踪关系中，不写入文件名或正文标题。
- 为保持既有追踪矩阵稳定，文档内的 P0、BR、DR 和 AC 条款 ID 保持不变；功能义务使用 `FR-xxx-yyy`，业务规则使用 `BR-xxx-yyy`，数据要求使用 `DR-xxx-yyy`。
- 当前实现契约只由本目录活动文档中明确编号的 P0、BR、DR 和 AC 组成；背景、说明和流程文字只帮助理解这些编号，不产生额外能力。
- 未被上述编号明确列出的能力，不得创建模块、表、接口、后台任务、Feature Flag、空目录、依赖或测试占位；新增能力必须先修改 Requirement 并重新通过下游流程。
- 每个 P0 条目必须映射到 Design AC、PRD AC、Plan Test/Evidence；断链即不能实现。
- 外部 Provider 的延迟与生成质量不作为平台自动化测试的稳定断言；平台必须以 Mock Provider 验证编排，以真实 Provider smoke 验证集成。
- Requirement 进入 `accepted` 只表示本层契约已通过评审；仍需 Design、PRD 和 Plan 均为 `accepted` 才能开始代码实现。
