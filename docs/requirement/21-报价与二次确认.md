## 1. 需求说明

### 1.1 背景与目标

视频生成是最大成本项，费用必须透明且可控：生成前看到费用，由用户明确确认后才花钱（P21，“存在消费的问题，需要让用户二次确认”）；执行中预留预算，结束后按实际结算，任何终态都不残留预留。这是所有付费生成的统一入口，流水线、批量、画布、Agent 都走同一套。

### 1.2 用户故事

- 作为**制作者**，我希望在生成前看到模型、数量、预估费用与剩余预算。
- 作为**制作者**，我希望任何会产生费用的生成都经过我的明确确认，不存在自动确认。
- 作为**管理员**，我希望每次生成的费用先预留、后按实际结算，账本始终平衡。

### 1.3 范围

- 包含：单项与批量报价、输入与参数校验、复用判断、报价有效期、确认、预留、结算、释放、确认审计。
- 不包含：批量执行调度（REQ-23）、任务执行与对账（REQ-24、DES-04）、成本报表（REQ-32）。

## 2. 需求分析

### 2.1 业务流程

```text
入口（单个生成按钮 / 批量 / 画布 / Agent 草稿）→ 请求报价（1..n 项）
  对每一项：
    1. 取目标对象（镜头、台词、槽位）的当前版本，组装生成输入
    2. 确定模型：显式指定 > 镜头 / 项目默认；检查模型已启用、凭据可用、符合项目境外设置
    3. 校验：生成模式、输入数量 / 类型 / 时长、参数、素材就绪、授权、前置条件（如图生视频需要关键帧）
    4. 相同输入已有完成结果且未要求强制重做 → 标记为复用，费用 0
    5. 按生效价格计价；报价 15 分钟内有效
  汇总：合计、可用预算、是否可以确认
→ 用户在确认对话框中点击“确认”（可剔除个别项）
→ 系统一次完成：检查报价未过期 → 检查预算足够 → 预留报价金额 → 记账 → 审计 → 开始执行
→ 任务结束（任一终态）：按实际费用结算，释放剩余预留；失败 / 取消按供应商实际计费
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 所有付费生成必须先报价、后确认；服务端没有任何自动确认参数或配置 | GEN-11 |
| R2 | 确认只能由用户会话发起；Agent 服务令牌等非用户会话调用确认接口返回 403 | 防绕过 |
| R3 | 报价 15 分钟有效；过期确认返回 `quote_expired`，前端自动重新报价并再次请求确认 | 价格与输入可能变化 |
| R4 | 确认时再次核对：目标对象版本未变、模型版本与价格未变；任一变化则报价作废，返回 `quote_expired` 并附原因 | 防止按旧输入执行 |
| R5 | 复用（`reused = true`）的项确认后不调用供应商，直接把已有输出关联为新 Operation 的输出，费用 0 | GEN-05 |
| R6 | 批量确认可剔除项；剔除项状态变为 `expired` | GEN-03 |
| R7 | 预留金额 = 报价；结算金额 = 供应商实际用量 × 报价时价格规则；差额释放 | CST-03 |
| R8 | 任一终态（completed / failed / cancelled / manual 处理后）必须完成结算，残留预留为 0 | REL-08 |
| R9 | 报价与确认都要求 `Idempotency-Key`；重复确认返回首次结果 | G1 |
| R10 | 报价显示服务区域；境外模型在对话框中显示数据出境提示 | PRV-03 |
| R11 | 非付费操作（上传探测、抽帧、转码）不走本流程 | 只针对供应商付费 |

### 2.3 状态

Operation：`draft` → `quoted` → `confirmed` → …（DES-04）；`quoted` → `expired`（过期或剔除）。预留：`held` → `settled` / `released`。

### 2.4 异常与边界

- 余额不足：该批不可确认，显示差额；剔除部分项后重新计算。
- 并发确认：预算行锁 + 约束，后到者 `budget_insufficient`。
- 确认成功但执行未能立即开始（如调度服务暂不可用）：任务保持“已确认”，服务恢复后自动开始执行，且只执行一次。
- 按 token 计费的 LLM：报价按输入估算 + 输出上限计算，预留取上限，结算按实际，偏差 ≤ 30%（COST-02）。

### 2.5 前置与依赖

REQ-08 价格规则；REQ-11 预算；REQ-10 项目境外设置。

## 3. 验收标准

- Given 报价已生成 20 分钟，When 用户点击确认，Then 提示报价已过期并重新计算。
- Given 任意入口发起生成，When 用户未点击确认，Then 不产生任何供应商调用，也不产生预留。
- Given Agent 建议批量生成 10 个镜头，When 用户未确认，Then 不产生费用；确认后才执行。
- Given 报价后镜头参数被修改，When 确认，Then 报价作废并提示重新报价。
- Given 任务结束（任一终态），When 检查账本，Then 该任务不存在未释放的预留。
- Given 同一 `Idempotency-Key` 的确认请求发送两次，When 检查，Then 只有一笔预留、一个工作流。
