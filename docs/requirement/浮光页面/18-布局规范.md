# PG-18 布局规范

依据：[浮光画板 2-2](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT/?node-id=2-2)；对应新页面 `/layout`，源码 `frontend/src/app/layout/_components/layout-guide-page.tsx`。页面为本地 mock，字段和可见行为用于需求分析；固定样例值和成功提示不证明真实业务已实现。

## 展示字段与数据量

表中的存储名称是本轮新设计的逻辑表，未建表；建议分页量不是既有API合同。

| 区域       | 必须承载的字段                                             | 设计归属                                      | 一次读取 / 保存的量               |
| ---------- | ---------------------------------------------------------- | --------------------------------------------- | --------------------------------- |
| 布局与导航 | 72px主导航、220px上下文栏、页头/详情栏、搜索/通知/账号入口 | 路由配置 + 当前用户/项目摘要；宽度为设计token | 共享摘要去重；菜单/焦点为临时状态 |

## 功能与失败边界

| 当前动作             | 必须产生的结果                                      | 边界与失败                                     |
| -------------------- | --------------------------------------------------- | ---------------------------------------------- |
| 导航 / 抽屉 / 面包屑 | 在新页面间保持当前项目与对象上下文                  | 不把旧路由树当新导航；手机关键操作可达         |
| 搜索 / 通知入口      | 当前只有入口/演示反馈；具体查询范围和待处理呈现待补 | 保留需求缺口，先不建全局搜索引擎或通知投递平台 |

## 最小设计结论

布局只消费上下文，不把导航状态存为业务表。 物理字段与关系见[新数据设计](../../design/浮光页面数据设计.md)，请求/响应见[新接口设计](../../design/浮光页面接口设计.md)。

## 验收证据

- 逐项核上述字段与动作，包括空值、失败和权限；业务写入须刷新后保留，冲突不覆盖他人修改。静态/临时状态不套用持久化验收。
- 返回数据只服务当前显示或操作；统计需能复算；mock数值与真实值明确分开。
