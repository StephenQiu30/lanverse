# M12 审阅、协作与批准需求

> Requirement ID：REQ-REV
> 状态：proposed v1
> 日期：2026-08-20
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)、[M09](./009-M09-媒体候选与选择需求.md)、[M10](./010-M10-质量连续性与修复需求.md)
> 对应模块：M12 审阅、协作与批准

## 1. 需求结论

评论和批准必须绑定冻结 ReviewPackage、确定对象版本和稳定时间码。项目当前内容后续变化不能让旧评论漂移到另一版媒体，也不能把旧批准自动继承给新版本。

## 2. 用户结果与范围

制片人可以冻结待审范围、邀请内部或外部审片人、收集对象/时间码/区域评论、分派修改并得到批准、请求修改或拒绝决定。审片人只看到被授权审阅包，不需要获得整个项目编辑权限。

本模块不修改镜头或候选、不自动创建修复结果、不完成渲染，也不以聊天消息替代正式决定。

| REV-FR-002 | 为内部/外部审片人授予有期限、可撤销的最小访问 | P0 |
| REV-FR-003 | 评论绑定对象版本、时间码/区域、作者和状态 | P0 |

## 4. 冻结范围与时间语义

ReviewPackage 至少固定项目/内容单元、镜头顺序、主选候选、装配版本、时间基、质量/权利摘要和审阅目的。评论时间使用项目明确的帧率或音频采样时间基，不以浮点秒作为权威坐标。

画面区域评论保存规范化区域和媒体尺寸；文本评论绑定字段或来源锚点。媒体代理重新生成时，评论仍通过原版本和坐标映射定位。

## 5. 决定与权限规则

1. 评论“已解决”不等于 ReviewPackage 已批准。
2. 批准只对冻结包有效，新包必须重新决定。
3. 审片人无权改变主选、镜头或交付；其修改请求进入正式业务流程。
4. 外部访问默认不能查看原始来源、模型 Prompt、人物秘密或其他项目。
5. 决定提交时重新校验成员状态、包版本和批准策略。
6. 撤回决定保留旧记录，并说明后续包是否受影响。

## 6. 状态与并发

ReviewPackage 为 `draft → in_review → changes_requested | approved | rejected | withdrawn → superseded`。Annotation 为 `open → resolved | dismissed → reopened`。

并发决定按策略处理：互斥最终决定使用 expected revision；多人批准分别保存每个决定，再由策略计算包状态。审片人在等待期间被停用或链接撤销后不能继续提交。

## 7. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 媒体代理不可用 | 评论与包保留，显示预览故障 | 重做代理或下载授权版本 |
| 审阅链接过期/撤销 | 明确无访问权 | 申请新邀请 |
| 包基线变化 | 当前审阅仍固定旧版并提示有新版 | 完成旧审或创建新包 |
| 并发最终决定 | 显示已提交决定和冲突 | 刷新后按策略处理 |
| 通知失败 | 不影响评论/决定事实 | 从投递日志重发 |
| 时间码映射失败 | 阻止错误定位并显示版本 | 使用原代理或重建映射 |

## 8. 非功能需求

| ID | 要求 |
| --- | --- |
| REV-NFR-001 | ReviewPackage、评论和决定在项目变化后仍可完整重读。 |
| REV-NFR-002 | 外部访问链接可撤销、最小权限并防重放。 |
| REV-NFR-003 | 时间码和区域定位使用精确时间基与版本。 |
| REV-NFR-004 | 评论列表和播放器满足键盘、字幕和屏幕阅读器需求。 |
| REV-NFR-005 | 通知失败不回滚业务决定，投递可观察可重试。 |

## 9. 验收条件

| ID | 场景 |
| --- | --- |
| AC-REV-001 | 评论在镜头新版本出现后仍指向原候选和正确时间码。 |
| AC-REV-002 | 旧包批准不会自动批准包含新候选的新包。 |
| AC-REV-003 | 外部审片人只能访问指定审阅包。 |
| AC-REV-004 | 请求修改形成可追踪责任和问题入口，不直接改媒体。 |
| AC-REV-005 | 多人批准按明确策略计算，缺少必要角色时不通过。 |
| AC-REV-006 | 审片人被停用后旧链接不能提交新评论或决定。 |
| AC-REV-007 | 通知失败后评论和批准事实仍存在且可重发。 |
| AC-REV-008 | 分数帧率视频的评论定位在重开页面后不漂移。 |

## 10. 指标与待确认项

指标包括审阅周转时间、首次批准率、修改轮次、未解决评论时间、外部链接撤销时间和通知失败率。待确认默认批准矩阵、外部审片人是否可下载、评论保留策略和修改请求到 RepairPlan 的自动化边界。
