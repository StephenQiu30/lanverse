# 用户需求

## 1. 需求概述

**需求目标：** 访客、制作者与管理员能按角色登录、维护自己账号并执行必要的账号管理。

**使用者与价值：** 作为使用者，我希望安全进入产品、管理自己的资料和设备；作为管理员，我希望管理账号状态，使创作内容和操作责任都有明确归属。

**问题背景：** 当前认证与账号页面提供演示交互，尚不足以证明账号、权限、会话和偏好真实生效。

| 业务角色 | 访客、制作者、管理员                                                        |
| 文档状态 | 原始需求整理稿，待评审；不是已接受的设计或已验收功能                        |
| 范围来源 | 本文件第7、8节保留的原规格、现有页面代码，以及已整理的跨模块流程            |
| 完成依据 | 第3节功能结果、第4节质量条件、第5节验收场景；待确认项解决后才能验收相应能力 |

## 2. 范围与边界

本模块包含：账号认证与会话；注册/登录/改密/退出、资料与个人偏好、设备会话、管理员建号/启停/解锁/重置。

本模块只包括当前制作者/管理员账号、认证、会话及本人偏好，不增加组织、邀请、邮件/短信找回、动态角色管理或账号删除。

业务模块一份文档，内部需求编号仅用于追踪，不对应独立文件、接口、类或开发任务。编号不承诺排期。原资料中的存储名、组件名和分页建议不作为已接受架构。

## 6. 依赖、假设与待确认

本模块是其他业务权限的基础；不要求先实现项目或生成。

**原有待确认：** 改密后当前设备的认证处理；头像规格与裁切；临时凭据生成/展示/交付；管理员联系方式。

**本轮发现的需求缺口：** 登录名的字符、长度、大小写/空白归一化；失败次数统计窗口；主题本地缓存与账号偏好的冲突策略。

**质量目标待确认：** 本模块适用设备/浏览器/版本、典型与边界数据规模、网络/冷热缓存条件、响应P50/P95、交互/Web Vitals与内存目标，以及格式/大小/并发/批量/导出限额须明确后才能质量验收。持久数据备份范围/周期、RPO/RTO与恢复责任人待确认。运行环境、可用性/维护窗口、数据用途/地域/保留及观测口径/日志策略仍待确认；不臆造SLA或规模。

这些问题统一纳入[总表缺口登记](01-需求总览.md#需求缺口与确认)，由产品负责人确认业务政策，工程/测试负责人补验证条件。责任角色尚未落实到人员，未给出答复的范围维持待确认；不自动新增平台、渠道或旧页面能力。

### 原范围与方案笔记

- 账号与会话是新设计明确需要的业务能力。
- 注册保留为当前需求，不能再以旧接口没有公开注册为理由降级或取消。
- 普通主动改密与受限改密用同一密码规则和会话失效语义。
- 少量个人偏好直接放账号行；不建泛化偏好中心，也不丢掉跨登录保存需求。
- 角色闭集只有当前页面的管理员/制作者；无需动态RBAC或组织平台。

以上为旧资料原文；技术存储限制需在当次Design评审，不从原笔记自动建立新架构。
