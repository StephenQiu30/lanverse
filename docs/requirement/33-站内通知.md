## 1. 需求说明

### 1.1 背景与目标

批量生成动辄数分钟到数十分钟，用户不会一直盯着页面。需要在关键结果与异常发生时提醒，并一键跳转。

### 1.2 用户故事

- 作为**制作者**，我希望在批量任务完成、失败、进入待人工核对、以及预算余额不足时收到通知，点击直达。

### 1.3 范围

包含：站内通知、未读计数、已读、跳转、去重。不包含：邮件、短信、IM 推送（后续按需作为新消费者接入）、通知偏好设置。

## 2. 需求分析

### 2.1 通知类型

| 类型 | 触发 | 接收人 | 去重键 |
| --- | --- | --- | --- |
| `batch_finished` | 批次结束（解析批次除外） | 批次确认人 | `batch:{id}` |
| `operation_failed` | 非批次的单个任务失败 | 确认人 | `op:{id}` |
| `operation_manual` | 任务进入待人工核对 | 全部管理员 + 确认人 | `manual:{id}` |
| `budget_low` / `budget_overrun` | 可用余额跨越 20% / 超支 | 项目相关用户（MVP：最近 7 天在该项目有操作的用户）+ 管理员 | `budget:{pid}:{阈值}:{日期}` |
| `import_finished` | 剧本导入 / 解析批次完成（解析批次只发本类型） | 发起人 | `import:{import_id}` / `import-batch:{batch_id}` |
| `consent_revoked` | 真人授权被作废（REQ-17） | 受影响对象的最近操作人 | `consent:{id}` |
| `reconciliation_diff` | 每日对账发现差异（REQ-32 R6） | 全部管理员 | `recon:{run_date}` |

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 同一批次只发一条汇总通知 | NTF-01 |
| R2 | 通知保留 90 天 | 控制数据量 |
| R3 | 点击通知跳转到对象（批次、任务、预算），对象已删除时提示 | NTF-01 |

## 3. 验收标准

- Given 整场批量生成结束（18 成功、2 失败），When 查看通知，Then 收到一条汇总通知，点击跳转到该批次。
- Given 可用余额跌破 20%，When 同一天再次跌破，Then 不重复通知。
