# REQ-13 逐集结构解析

| 项 | 内容 |
| --- | --- |
| 需求 | SCR-03 逐集结构解析；SCR-04 解析结果人工修改；SCR-05 解析按集独立执行 |
| 优先级 | MVP |
| 用例 | UC-06 |
| 页面 | 剧本 · 单集解析 |
| 依赖功能 | REQ-12、REQ-21、REQ-31 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

分镜、配音、字幕都以“场 → 台词”为单位。剧本文本是自由格式，需要 AI 解析出场次、台词（说话人、内容、情绪）、动作描述、时间地点；AI 可能出错，因此每条结果都要能定位原文、可人工修改，并按集确认。

### 1.2 用户故事

- 作为**制作者**，我希望系统按集解析出场次、台词、动作、时间地点，以便后续拆分镜头。
- 作为**制作者**，我希望点击任一台词就能看到原文位置，并能拆场、合场、修改说话人与台词、调整情绪。
- 作为**制作者**，我希望单集解析失败不影响其他集，并能单独重试。

### 1.3 范围

- 包含：批量发起解析（报价确认）、逐集独立执行、原文定位、人工编辑、“待处理”台词、版本化、按集确认。
- 不包含：剧本原文改写、AI 润色台词。

## 2. 需求分析

### 2.1 业务流程

```text
选择集（全部 / 部分）→ 批量报价（按字数估算 token）→ 确认
→ 每集一个 EpisodeParseWorkflow：parse_episode Skill（校验：原文位置真实存在、每句台词只出现一次）→ 保存为 candidate 结构版本
→ 用户审阅：左原文 / 右结构树；编辑 → 保存为新版本（candidate，origin = user）
→ 处理完“待处理”台词 → 确认本集 → confirmed
→ 若本集已有分镜：受修改影响的镜头标记过期（REQ-31）
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 每条解析结果（场、台词、动作）必须带原文起止偏移，且偏移范围内的原文与内容一致（台词允许去掉引号与说话人前缀） | 可追溯、防幻觉 |
| R2 | 原文中每一句台词被解析且只被解析一次；无法归属的放入“待处理” | SCR-03 |
| R3 | 存在“待处理”台词时不能确认 | 保证分镜完整 |
| R4 | 每次保存产生新的结构版本，旧版本可查可对比 | SCR-04 |
| R5 | 修改时保持稳定键：未改变身份的场与台词沿用 `scene_key` / `line_key`；拆分时前半沿用、后半新键；合并时保留第一句的键 | 让分镜与配音的引用跨版本有效（DES-02 §4.3） |
| R6 | 说话人文本保留原文称呼；设定集确认后回填 `character_id` | 与 REQ-14 别名合并衔接 |
| R7 | 每集独立任务；失败保留原因与模型原始输出（管理员可见）；重试不影响已确认的集 | SCR-05 |
| R8 | 已确认的集再次修改：生成新版本（candidate），需重新确认；确认时计算与上一确认版本的差异，按 `line_key` 的 `content_hash` 变化发布过期事件 | LIN-01 |

### 2.3 状态

`episode.parse_status`：`not_started` → `running` → `awaiting_review` → `confirmed`；`running` → `failed` → 重试 → `running`；`confirmed` → 修改 → `awaiting_review`。

### 2.4 异常与边界

- LLM 输出偏移不符：Harness 最多修复 2 轮；仍失败则按“场”为单位切片重试一次；仍失败标记失败，保留原始输出。
- 单集超长（> 3 万字）：按场景标记预切分后分段解析，再合并。
- 两个页面同时编辑同一集：`expected_revision` 冲突。

### 2.5 前置与依赖

分集已确认（REQ-12）；Skill `parse_episode`（DES-05）；报价确认（REQ-21）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `script.episode` | `parse_status`、`parse_error`、`current_structure_id`、`revision` | 状态与当前版本指针 |
| `script.episode_structure` | `version_no`、`review_status`、`origin`、`operation_id`、`unassigned_lines`、`confirmed_at` | 版本化与确认 |
| `script.scene` | `scene_key`、`seq_no`、`heading`、`location_text`、`time_of_day`、`span_*` | 场 |
| `script.dialogue_line` | `line_key`、`kind`、`speaker_text`、`character_id`、`content`、`emotion`、`content_hash`、`span_*` | 台词及稳定键 |
| `script.action_line` | `content`、`span_*` | 动作描述（分镜画面依据） |
| `lineage.dependency` | 分镜版本 → `dialogue_line`（`line_key` + `content_hash`） | 过期判断 |

### 3.2 接口

```http
POST /api/projects/{pid}/quotes
{ "items": [ { "target_type": "episode_parse", "target_id": "<episode_id>", "capability": "text.structured" }, … ] }
→ 批量报价（REQ-21），确认后启动解析

GET /api/episodes/{eid}/structure
200 { "episode_id": "…", "version_no": 3, "review_status": "candidate", "revision": 5,
      "scenes": [ { "scene_key": "…", "seq_no": 1, "heading": "1-1 医院走廊 日 内", "span": [120, 980],
                    "items": [ { "type": "action", "content": "…", "span": [140, 190] },
                               { "type": "line", "line_key": "…", "kind": "dialogue", "speaker_text": "小李", "character_id": null,
                                 "content": "你怎么来了？", "emotion": "惊讶", "span": [192, 205] } ] } ],
      "unassigned_lines": [ { "content": "…", "span": [..] } ] }

POST /api/episodes/{eid}/structure
{ "expected_revision": 5, "base_version_no": 3, "scenes": [ …完整结构，已有项带原 scene_key / line_key… ] }
201 { "version_no": 4, "revision": 6 }

POST /api/episodes/{eid}/structure:confirm   { "expected_revision": 6 }
200 { "review_status": "confirmed", "changed_lines": 3, "stale_shots": 5 }
422 validation_failed { "code": "unassigned_lines_remaining" }

GET /api/episodes/{eid}/source-text?from=100&to=1200   → 原文片段
POST /api/episodes/{eid}/parse:retry                   → 重新报价
```

### 3.3 异步与工作流

`EpisodeParseWorkflow`（`episode-parse/{episode_id}/{operation_id}`）：`llm.run_skill(parse_episode)`（`agent`，10 分钟，重试 2 次）→ `SaveEpisodeStructure`（`flow`）。批量由 `BatchWorkflow` 启动子工作流，单集失败不影响其他集。

### 3.4 事件与实时

`script.episode_structure_confirmed.v1`（含 `changed_line_keys[]`）→ lineage；SSE `episode.updated`。

### 3.5 界面

双栏：原文（虚拟滚动，高亮当前选中条目）/ 结构树（场 → 动作与台词，行内编辑说话人、情绪、内容；拖拽调整归属；拆场 / 合场按钮）；“待处理”抽屉；版本下拉与差异对比；确认按钮（未处理完禁用并说明）。

### 3.6 权限与审计

制作者。审计：`episode_structure.saved`、`episode_structure.confirmed`。

### 3.7 非功能要求

AIQ-01（台词召回率 ≥ 99%、说话人准确率 ≥ 95%、场次边界准确率 ≥ 90%）；PERF-05（60 集解析 ≤ 30 分钟，受供应商限流约束）。

## 4. 验收标准

- Given 第 1 集原文有 48 句台词，When 解析完成，Then 台词列表共 48 条，每条可定位到原文，“待处理”为 0 或列出具体台词。
- Given 某条台词，When 点击其原文位置，Then 原文面板滚动并高亮对应文字。
- Given 第 3 场已生成分镜，When 修改第 3 场一句台词的说话人并确认，Then 生成新的结构版本，引用该台词的镜头显示“过期”。
- Given 60 集中第 7 集解析失败，When 查看解析状态，Then 其余 59 集正常完成，第 7 集显示失败原因与“重试”按钮。

## 5. 测试要点

- 单元：稳定键保持算法（编辑、拆分、合并）；`content_hash`；偏移校验。
- 评测：样例剧本解析指标（TST-03）。
- 集成：确认 → 过期事件 → 镜头过期。
