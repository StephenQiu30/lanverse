# FR-005 故事圣经与叙事连续性需求规格说明书

## 1. 目的与范围

维护世界规则、剧情事实、叙事时间线、角色状态、人物关系、服装阶段、道具状态、场景状态和未闭合线索，为剧本、创作资产、分镜和成片连续性提供唯一叙事事实基线。视觉、声音和媒体版本由 FR-006 与 FR-007 管理，并引用本模块的叙事事实。

## 2. 参与角色

- 主创、编剧和导演。
- 连续性审核者。
- 需要引用已确认事实的分镜、资产和制作人员。

## 3. 主业务流程

1. 主创登记世界规则和稳定剧情事实。
2. 系统从剧本提取待确认事件、人物关系和状态变化。
3. 连续性责任人确认、修正或标记不确定项。
4. 剧本、场次和镜头引用明确的故事圣经版本。
5. 系统检测显性冲突并交由人工裁决。
6. 圣经变化时，系统标记受影响内容、资产、镜头和成片版本。

## 4. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |

## 5. 业务规则

- BR-005-001：故事圣经管理叙事事实，不管理具体媒体文件。
- BR-005-002：自动检测只产生问题，不作正式裁决。
- BR-005-003：同一生效范围内互斥事实不能同时为有效状态。
- BR-005-004：有意设置的悬念不能被当作普通信息缺失。
- BR-005-005：剧情例外必须记录对象、范围、理由和批准人。
- BR-005-006：人物关系及角色、服装、道具和场景的剧情状态只在故事圣经中形成正式叙事事实，创作资产不得维护独立冲突副本。

## 6. 数据要求

- DR-005-001：保存世界规则、剧情事实、事件、相对或绝对时间关系和来源。
- DR-005-002：人物关系必须保存方向、类型、生效剧情节点和版本。
- DR-005-003：保存实体状态、伏笔、冲突、人工裁决和下游影响。

## 7. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 多个来源事实冲突 | 保持冲突状态，要求责任人选择或批准例外。 |
| 叙事时间无法确定 | 保存相对顺序或待定，不虚构精确时间。 |
| 故意违反世界规则 | 要求记录剧情例外及适用范围。 |
| 新圣经与已交付版本冲突 | 保留原交付依据，并评估更正或重新交付。 |

## 8. 验收标准

- AC-005-001：角色上一集受伤而下一集无伤时，系统产生可定位连续性问题。
- AC-005-002：问题被批准为剧情例外后，系统保留检测结果、理由和批准人。
- AC-005-003：修改世界规则后，直接引用它的剧本和镜头显示待复核。
- AC-005-004：历史交付版本能够显示制作时使用的故事圣经版本。
