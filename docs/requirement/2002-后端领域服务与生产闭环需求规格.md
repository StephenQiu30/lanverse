# 后端领域服务与生产闭环需求规格

- 状态：派生自已接受设计，待独立评审
- 日期：2026-08-25
- 产品依据：[产品范围与验收基线](../prd/0001-产品范围与验收基线.md)
- 设计依据：[后端服务架构](../design/2001-后端服务架构.md) · [后端领域模块功能设计](../design/2002-后端领域模块功能设计.md) · [领域语言与模块命名规范](../design/0006-领域语言与模块命名规范.md)

## 结论

本规格从空项目出发，定义 14 个 Backend 业务模块的唯一事实所有权、应用契约、跨模块协调和最小完整生产闭环。全部条款都是尚待实施和独立验收的目标契约。

## 全局应用契约

| ID | 目标契约 | 验收方式 |
|---|---|---|
| `BE-APP-001` | 已认证业务、已认证账户级、匿名认证、Provider Callback、内部服务和运维六类 Command 必须有各自的必填 Context。 | 六类 Command Envelope Schema 与缺失/伪造 Context 负向测试。 |
| `BE-APP-002` | 修改权威事实的 Command 必须在一个 PostgreSQL 事务中修改 Owner 事实并写 Outbox；Query 不得产生业务副作用。 | 事务提交/回滚与 Query 前后无写入测试。 |
| `BE-APP-003` | 跨模块只能调用公开 Application Interface；Coordinator 可组合共享 Unit of Work，但不得直接访问任一 Repository 或表。 | Import Direction/AST 架构测试与 Coordinator 事务 Contract Test。 |
| `BE-APP-004` | 跨 Binary 不使用分布式数据库事务，必须使用持久 Intent、幂等 Receipt、Outbox 和可补偿 Saga。 | 远程调用前/后崩溃与重复投递测试。 |
| `BE-APP-005` | 远程调用必须区分 `known_failure` 与 `outcome_unknown`；未知结果必须按稳定 ID 对账，不得盲目重提。 | 超时、断连、丢回调与迟到 Receipt 故障矩阵。 |
| `BE-APP-006` | 跨模块引用必须使用 ID + Version 或不可变 Snapshot；每次运行必须冻结 Authoring、Workflow、Policy、Skill/Prompt、Capability/Model、Price 和输入 Artifact 版本。 | 运行期修改活动配置后旧 Run Hash/行为不变的历史还原测试。 |
| `BE-APP-007` | 所有 Workspace 资源 Command 必须重新授权；跨 Workspace 失败不得泄漏资源是否存在。 | 全 Command 无权/跨租户错误等价矩阵。 |

## 模块所有权

| ID | 目标 Owner 契约 | 最小验收 |
|---|---|---|
| `BE-MOD-001` | `access` 唯一拥有 Identity、Session、Membership 和 Access Capability；Workspace 生命周期不归 Access。 | Session 轮换/重放、Token Version、成员权限和跨租户测试。 |
| `BE-MOD-002` | `production` 唯一拥有 Workspace→Project→Episode→Scene→Shot、Script/Bible/规格版本和生产绑定。 | 归档只读、版本不可变、Shot 拆合排序守恒与 Snapshot 还原。 |
| `BE-MOD-003` | `preset` 唯一拥有 Preset/Style/Override 版本并解析不可变 EffectivePolicySnapshot。 | 解析优先级、相同输入 Hash 与发布前引用强校验。 |
| `BE-MOD-004` | `authoring` 唯一拥有 Draft/Revision、Node Catalog、Graph Validation 和 GraphPatch Intent/Receipt；协作日志不是发布事实源。 | Guided/Canvas 同 Schema、端口/环校验、Patch 冲突和结果未知对账。 |
| `BE-MOD-005` | `workflow` 唯一拥有 Compiler、Definition、Run/Node 业务投影、Node Cache、Quality Gate 和 Temporal 协调。Node Executor 输出必须使用 `node-output-v1` 端口绑定，Runtime 负责 canonical Output Hash，并在 Claim fencing 事务内完成 NodeRun 输出投影；Node Cache 必须覆盖全部冻结执行输入、按 Workspace 隔离并绑定该输出。 | 输出端口重复/字段无效、Executor 伪造 `CACHED`、失败遗留半成品、完成重放输出漂移、Cache Key 字段漂移、并发首次写收敛、同 Key 异输出冲突、跨 Workspace 隔离、Replay、重启恢复、单 Shot 重跑、跨日 Human Wait 和取消竞态。 |
| `BE-MOD-006` | `review` 唯一拥有 HumanTask、Claim Lease 和不可变 ReviewDecision；不得直接修改被审核聚合。 | Claim 过期、Stale 对象、唯一终态决议和一次 Signal。 |
| `BE-MOD-007` | `generation` 唯一拥有 Capability/Model/Provider/Intent/Request/Job/Candidate/Selection；不拥有金额账本或 Episode Workflow。 | 路由冻结、Provider Key 幂等、验签/重放、Fallback 预算与 Unknown 对账。 |
| `BE-MOD-008` | Go `agent` 模块拥有 Manifest/Invocation/Grant/Budget/会话记录；Python Runtime 只执行受限 Executor。 | Grant 作用域、步数/调用/费用/deadline 上限、Tool Allowlist 和结构化输出。 |
| `BE-MOD-009` | `asset` 唯一拥有 Asset/Version、Artifact/Readiness/Lineage/Location、Upload 和 Rights/Consent。 | Hash/位置不变性、直传、Readiness 门禁、Consent 范围和位置迁移回滚。 |
| `BE-MOD-010` | `media` 唯一拥有 Probe/Derivative/Job/RenderManifest/Receipt；不得保存第二份 Artifact 血缘或决定候选选择。 | 损坏文件、Codec、超时、Worker 丢失、UNKNOWN 对账和输出 Hash。 |
| `BE-MOD-011` | `cost` 唯一拥有 Price/Estimate/Reservation/Ledger/Budget，金额使用 Decimal + Currency。 | 并发超预算、幂等预留/结算/释放、币种和 Unknown Usage 对账。 |
| `BE-MOD-012` | `quota` 唯一拥有 Policy/Window/Counter/Reservation/Decision；Quota 不保存金额，PostgreSQL 是事实源。 | 并发限额、无负 Counter、幂等消费/释放和 Redis 故障 fail closed。 |
| `BE-MOD-013` | `eventing` 拥有 Outbox/Inbox 协议、DLQ/Replay/Checkpoint 和 Audit Projection；不承担 Workflow Timer/Human Wait。 | 事件提交/回滚、重复/乱序、Poison Message、DLQ Replay 和投影重建。 |
| `BE-MOD-014` | `search` 唯一拥有 Elasticsearch 业务投影/Index Version/Alias/Reindex；不参与 Command 正确性。 | Workspace Filter、revision 乱序栅栏、degraded 响应和全量 Reindex/Alias 切换。 |

## 跨模块业务旅程

| ID | 目标契约 | 验收方式 |
|---|---|---|
| `BE-JRN-001` | 注册必须在共享 Unit of Work 中原子创建 UserAccount、Workspace、Owner Membership、RegistrationReceipt 和 Outbox；Session 创建失败只补发，不重建已提交账户。 | PostgreSQL 失败/结果未知、Session 失败、并发和幂等重放。 |
| `BE-JRN-002` | Production Bible 发布必须在一个 Unit of Work 中发布不可变 Bible Version，物化/绑定 Asset/State/Version，写 MaterializationReceipt 和双方 Outbox。 | 任一不变量失败整体回滚；幂等重试返回同 Receipt。 |
| `BE-JRN-003` | Guided 与 Canvas 都必须发布同 Schema 的 AuthoringRevision，由 Compiler 生成不可变 Definition，再以稳定 Workflow ID 和 Start Intent/Receipt 启动 Temporal。 | Graph/Policy 校验、Already Started Hash 对账、Start 结果未知和 Replay。 |
| `BE-JRN-004` | 所有付费 Provider、Agent 模型调用和高成本 Media Job 必须执行 Intent + Cost/Quota Reservation → Execution Claim → Authorization → Receipt → Settle/Consume/Release/Reconcile。 | 准备事务原子性、Claim/取消竞态、Token 过期、执行崩溃和迟到 Receipt。 |
| `BE-JRN-005` | Provider 输出必须经过 Staging → Artifact Readiness → GenerationCandidate → QCReport/QualityGate → ReviewDecision → CandidateSelection → Production/Asset Binding。 | 每个边界前后崩溃重试、唯一约束和未 READY 输入拒绝。 |
| `BE-JRN-006` | ReviewDecision 必须绑定精确对象版本；修改 Production 的决议必须先产生 ApplyReceipt，Workflow 只在该 Receipt 后发幂等 Signal。 | Stale 对象、重复 Decision/Event/Signal、Signal 结果未知和一次生产效果。 |
| `BE-JRN-007` | Media 必须使用不可变 RenderManifest 冻结全部输入版本，输出先校验再由 Asset 登记新 Artifact/Lineage，不覆盖输入。 | 同 Manifest + 幂等键重试、Worker 重启、UNKNOWN 对账、临时对象清理和输出 Hash。 |
| `BE-JRN-008` | Search/Audit/分析投影必须可从 PostgreSQL Snapshot + Event 重建，投影失败不回滚业务事实。 | 乱序/重复/缺口、DLQ Replay、全量 Reindex、Alias 切换和投影依赖故障。 |

## 最小完整闭环

| ID | 目标契约 | 验收方式 |
|---|---|---|
| `BE-E2E-001` | 必须以真实剧本完成注册/登录 → Workspace/Project/Episode → Preset/Script/AuthoringRevision → Compiler/Temporal → Agent 分镜 → Generation/Artifact/QC/Review/Selection → Media Render/Export → Cost/Quota → Event/Search 闭环。 | 全链 E2E；最终媒体、Artifact、Cost/Quota 和 Search 证据。 |
| `BE-E2E-002` | 闭环必须重复注入 HTTP Command、Temporal Activity、Provider Callback 和 Kafka Delivery，并重启各 Worker；不得产生重复领域事实、费用、Candidate、Artifact 或生产效果。 | 全链故障注入矩阵和 Count/Hash/金额/状态机/租户不变量报告。 |
