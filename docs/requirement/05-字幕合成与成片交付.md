# 字幕合成与成片交付

## 1. 范围

本能力从已确认对白/旁白、active TTS Adoption 和镜头视频 Adoption 生成源语言字幕，以固定输入在服务端完成顺序合成、质检和 MP4 导出。

## 2. 主流程

1. 系统以确认对白和当前 TTS 音频生成带时间码的源语言字幕草稿。
2. 操作者修正 draft 字幕文本和 Episode 全局起点，系统按未变速 TTS 时长计算终点，再确认 SubtitleVersion；确认后再次编辑必须显式派生新 draft。
3. 系统按 ShotSpec 顺序固定视频、TTS、字幕及渲染参数为 RenderSnapshot。
4. FFmpeg Worker 合成画面、对白/旁白语音音轨和烧录字幕，并生成配套 SRT。
5. 系统使用 ffprobe 和哈希执行技术质检，通过后提供播放和下载。

## 3. 功能需求

| 编号 | P0 需求 | 验证 |
| --- | --- | --- |
| FR-004-001 | 系统应为每条确认对白或旁白语音条目使用其当前 TTS 音频时长生成源语言字幕条目，保存稳定标识、文本、以 90,000 ticks/秒表示的 Episode 全局整数起止时间、音色角色和文本版本。 | AC-004-001 |
| FR-004-002 | 系统应只允许操作者编辑 draft SubtitleVersion 的字幕文本与全局起点；终点必须等于起点加未变速 TTS 时长，字幕修改不得改变确认剧本对白或 TTS 音频；confirmed 版本只能通过显式派生新 draft 后修改。 | AC-004-002 |
| FR-004-003 | 系统应检测字幕负时长、倒序、越出所属镜头、相互重叠、缺少语音映射，以及 TTS 按确认起点放置后超出镜头，并在问题解决前阻止确认。 | AC-004-003 |
| FR-004-004 | 系统应确认唯一当前 SubtitleVersion；剧本、镜头顺序或 TTS Adoption 变化后，旧字幕保持不变并显示 `input_outdated=true`，不得扩展版本状态枚举。 | AC-004-004 |
| FR-004-005 | 系统应按 ShotSpec 顺序为全部 6～10 个镜头固定 active 视频 Adoption、逐句 TTS Adoption、字幕版本和渲染参数，创建不可变 RenderSnapshot。 | AC-004-005 |
| FR-004-006 | 缺少任一镜头视频 Adoption、任一语音条目 TTS Adoption 或已确认字幕时，系统应阻止创建 RenderSnapshot 并定位缺项。 | AC-004-006 |
| FR-004-007 | 系统应只把 FR-003-006 已验证且已采用的镜头视频写入 RenderSnapshot，并在服务端用 FFmpeg 归一化、顺序合成：缩放后居中补边至 720×1280、移除源音轨，短/长不超过 90,000 ticks 时末帧补齐/trim；防御性复检发现哈希、可解码性或时长不符时本次渲染失败，但不得反向修改 ready Candidate、ready MediaVersion 或历史 Adoption。TTS 不变速不裁剪，按 confirmed SubtitleVersion 起点放置，并烧录同一字幕。 | AC-004-007 |

| FR-004-011 | 系统应以 DeliveryVersion 保存 MP4、SRT 与 JSON Manifest 三个 MediaVersion 的对象存储引用、大小、SHA-256、ffprobe 摘要、FFmpeg 版本和来源 ProductionAttempt。 | AC-004-011 |
| FR-004-012 | 系统应允许操作者在本地页面播放和下载成功成片，并从成片反查全部镜头、视频、TTS、字幕、Task 与 Attempt。 | AC-004-012 |

## 4. 业务规则

- BR-004-001：字幕的唯一文本来源是确认对白或旁白，时间来源是当前 TTS 音频；任何其他来源不得新增剧本事实。
- BR-004-002：RenderSnapshot 创建后不得随当前 Adoption 变化；输入变化后的重新合成必须创建新快照。
- BR-004-003：预览成功不等于导出成功，只有固定文件通过技术质检才可下载为成片。
- BR-004-004：渲染重试不得修改输入、重复选择候选或覆盖历史导出文件。
- BR-004-005：基础 TTS 语音和源语言字幕是 MVP 成片必需组成，不能以静音视频或仅字幕视频替代。
- BR-004-006：Render 提交采用两阶段幂等恢复：外层键唯一固定 RenderSnapshot，Task 使用由 snapshot_id 派生的内部幂等键；任一阶段崩溃后重放必须复用二者。
- BR-004-007：`createSubtitles` 根据当前 confirmed ScriptVersion 与 active TTS Adoption 生成新的字幕 draft；已有 confirmed 字幕需要只改文字或起点时，`deriveSubtitleDraft` 复制该版本并建立 parent 引用，返回新 draft。SubtitleVersion 不含 `origin_task_id`；两种创建方式均不得覆盖 confirmed/superseded 内容。

## 5. 数据要求

- DR-004-001：SubtitleVersion 保存父版本、语言、条目、Episode 全局起止 tick、对白/TTS 引用、状态和时间戳。
- DR-004-002：RenderSnapshot 使用 `timebase=90000` 保存每镜 start/end/duration、视频/TTS Adoption、字幕版本、归一化策略、720×1280、24fps、AAC 48k stereo 和编码参数。
- DR-004-003：ProductionAttempt 保存任务、快照、FFmpeg 参数摘要、工具版本、状态、错误和输出引用。
- DR-004-004：DeliveryVersion 保存 ProductionTask、可选父交付、RenderSnapshot、MP4/SRT/Manifest MediaVersion 引用、大小、哈希、媒体探测摘要、`rendering/ready/failed/cancelled` 状态和创建时间；终态版本不得被用户重试原位复活。

## 6. 异常与恢复

| 场景 | 必须行为 |
| --- | --- |
| 字幕或媒体缺失 | 阻止快照并返回镜头/语音条目标识及缺少类型。 |
| FFmpeg 中途失败 | 保留失败 ProductionAttempt 和诊断；自动恢复使用同一 Task/快照，用户重试使用引用原 Task 的新 Task和同一快照。 |
| Worker 重启 | 原导出任务恢复或进入可重试终态，不产生伪成功文件。 |
| 输出质检失败 | 隔离文件并显示具体不合规字段，不开放下载为成片。 |
| 当前候选变化 | 已创建快照和历史导出不变，新导出必须创建新快照。 |

## 7. 验收标准

- AC-004-001：基准单集每条对白或旁白语音条目恰有一个字幕条目，条目可反查文本和当前 TTS 音频版本。
- AC-004-002：draft 可按 ETag 修改字幕文本/起点且剧本对白、TTS 文件及其哈希不变；对 confirmed/superseded 直接 `PUT` 返回 `409 VERSION_IMMUTABLE`，对 confirmed 调用 `deriveSubtitleDraft` 后只修改新 draft，父版本内容/状态不变。
- AC-004-003：分别注入负时长、倒序、越界、重叠、缺映射和 TTS 溢出镜头，确认均被阻止并定位准确。
- AC-004-004：确认新 TTS Adoption 后旧 SubtitleVersion 内容/状态不变且显示 `input_outdated=true`；调用 `createSubtitles` 基于新输入生成带 parent 的新 draft 后可另行确认。
- AC-004-005：快照恰好包含 6～10 个有序视频 Adoption、全部语音条目 TTS Adoption 和一个确认字幕版本。
- AC-004-006：逐项删除一个镜头视频 Adoption、一个 TTS Adoption 或字幕确认，系统均阻止快照且无 ProductionTask。
- AC-004-007：对短 90,000 ticks、长 90,000 ticks 的已采用输入分别验证末帧补齐和 trim；超差媒体在候选门禁被阻止采用，强制注入的哈希/探测不一致快照使 Render Attempt/Delivery 失败且不修改输入 Candidate、MediaVersion 或 Adoption。输出无源视频音轨，TTS 不变速不裁剪，播放时按镜头顺序听见语音并在同一区间看到字幕。
- AC-004-008：输出 MP4/SRT；机器检查证明分辨率、帧率、编解码器和时长全部符合固定规格。
- AC-004-009：对错误分辨率、无音轨、损坏文件和错误编码样本，质检均失败且不开放成功下载。
- AC-004-010：分别在 RenderSnapshot 保存后、Task 创建后和 task_id 回写前终止 API，重放均复用一个 Snapshot/Task；注入可自动重试渲染失败时只在原 Task/DeliveryVersion 增加 Attempt，用户重试只增加一个引用原 Task 的新 Task、新 DeliveryVersion及初始 Attempt，全部引用同一 Snapshot。
- AC-004-011：分别下载 MP4、SRT 与 Manifest，重新计算三个 SHA-256 均与记录一致，并可读取对应 ffprobe 与 FFmpeg 版本证据。
- AC-004-012：从成片详情可遍历到全部镜头、媒体、字幕、Task/Attempt；链接不存在断链。
