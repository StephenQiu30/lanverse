# 生成需求

## 目标与范围

制作者能以明确输入执行生成，追踪结果并避免不确定状态下重复收费。

本模块范围：执行前能力/权限/费用校验、冻结输入及模型版本、幂等任务、真实候选、unknown/manual核对；不自动选定。

建议执行顺序为编号顺序；编号不代表排期或已批准实施。本文件按业务模块整体维护，内部功能在同一文档列出，不为每个按钮、接口或技术层建立单独需求文件。

## 功能与数据要求

| 内容       | 必须产生的结果                                                       | 失败与边界                                                               |
| ---------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 执行前校验 | 校验目标权限、输入版本、模型能力与参考限制；候选数量按表单及模型限制 | 未声明真人声音不能执行相关生成；真实收费必须执行前确认，未知费用不标免费 |
| 提交与冻结 | 冻结输入、模型与引用版本；使用request_key创建可追踪任务              | 同键同输入定位同任务，异输入409；提交不是生成完成                        |
| 状态与恢复 | queued/running/成功/失败/unknown/manual可区分，刷新及重启可查询      | 供应商已执行但丢响应先核对，不直接再次收费或假失败重提                   |
| 候选与媒体 | 真实输出关联原任务及输入，候选与媒体就绪/审核分开                    | 重复回执不重复发布；生成只追加候选，不替代正式选定或参考锁定             |
| 费用与核对 | 确认结果、执行与核对事实可解释，实际费用另取证                       | 核对方法、权限、确认凭据及安全重试条件待定，不预建完整报价/对账平台      |

## 依赖与待确认

依赖供应商、发布模型、授权目标和媒体；镜头/画布/设定/批量入口使用同一合同。

待确认：价格提示/确认与费用不可知策略；供应商核对方式、人工权限及安全重试；媒体就绪/审核规则。

以上缺口只是评审问题，不构成新增产品能力或架构决策。既有功能和约束不因旧接口支持不足而删除或降级。

## 模块验收

1. 本文列出的字段和功能由真实数据及操作结果承载，成功/失败/权限/未接入状态明确，mock不作为业务通过。
2. 需要持久化的写入可刷新恢复；版本冲突保留输入，重复副作用按幂等合同核对；只读/瞬时状态不强加持久化。
3. 当前用户/项目范围服务端验证；管理动作限管理员，秘密不进入响应、普通日志、审计明文或导出。
4. 实现时补与本模块风险匹配的成功、失败、冲突/重复、越权场景，分别记录自动化、真实持久化、浏览器及外部供应商证据，未执行不得报通过。

统一要求见[非功能规格](02-非功能需求规格.md)和[交互需求](05-界面与交互需求.md)；当前均待评审、未完成真实功能验收。本阶段不列Sprint、工时或固定用例数量。
