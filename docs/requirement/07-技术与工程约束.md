# 技术与工程约束

## 1. 技术基线

| 编号 | P0 约束 |
| --- | --- |
| TCR-001-001 | 后端必须使用 Python 3.13、`uv`、Setuptools `src-layout`、`pyproject.toml`、严格类型检查和唯一 `backend/uv.lock`；前端必须使用 TypeScript strict、Node.js 24 LTS、pnpm 和唯一 `frontend/pnpm-lock.yaml`。两个生态分别冻结依赖，不建立根 pnpm workspace 或第三份依赖清单。 |
| TCR-001-002 | 应用根目录只允许 `backend/` 与 `frontend/`；API 和单一 Worker 均位于 `backend/`。不创建根 `src/`、`build/`、`data/`、`env/`、`deploy/`、顶层 `apps/packages`、独立 Worker 仓库或非 MVP 运行目录；编译产物、模型、MinIO 字节、运行数据和环境配置不得作为源码提交。 |
| TCR-001-003 | 前端必须由官方 `create-next-app` 生成 Next.js App Router、React、TypeScript、Tailwind CSS 与 ESLint 基线，再以 shadcn/ui CLI 显式 `--base radix` 初始化 Radix UI；状态只使用 Redux Toolkit、React-Redux 和 RTK Query。`@umijs/openapi` 必须从运行中 FastAPI 的 Swagger/OpenAPI URL 生成请求与 DTO，RTK Query 只在封装层调用生成函数并管理服务端缓存/轮询，普通 Slice 只保存未提交编辑、选区和面板状态。 |
| TCR-001-004 | 后端必须使用 FastAPI 模块化单体、Pydantic v2、asyncpg、Alembic 和 PostgreSQL；PostgreSQL 是业务状态唯一事实源。根 `sql/` 是 DDL 唯一实现源，目标为 `lanverse` 数据库的 `public` schema，20 张表按依赖顺序拆为 `NN_<table>.sql`；PK/UQ/FK/CHECK 直接写入所属表的 `CREATE TABLE`，索引也保存在所属表文件，不设置公共关系/索引 SQL。Alembic 只负责版本顺序和执行。运行时 Repository 使用参数化 SQL，不建立 ORM Model、Declarative Metadata、autogenerate 或通用 BaseRepository。 |
| TCR-001-005 | MVP 长任务由单一 `backend-worker` 基于 PostgreSQL `TaskJob` 租约执行：`FOR UPDATE SKIP LOCKED` 领取、周期心跳续租、租约过期恢复、稳定 Provider request key 对账。PostgreSQL 是任务恢复唯一事实源；不引入 Temporal、Celery/Redis、LangGraph 或第二套工作流状态。 |
| TCR-001-006 | 非 Render 异步受理在同一事务写 SubmissionSnapshot、ProductionTask、初始 ProductionAttempt、TaskEvent、TaskJob 和 IdempotencyRecord；Render 使用 Tx1 pending Idempotency+RenderSnapshot、Tx2 Submission+Task/Attempt/Event/TaskJob、Tx3 CAS initial_task+完成回执。Worker 重放同一 TaskJob 时复用 Task/Attempt 稳定键，Render Delivery 只由首次执行 Render Job 的幂等用例创建。 |
| TCR-001-007 | 媒体必须进入私有 MinIO 对象存储；bucket、object_key、元数据、哈希、谱系和采用关系保存在 PostgreSQL，MinIO URL 不是业务事实。 |
| TCR-001-008 | 合成与探测必须由服务端 FFmpeg/ffprobe 完成，使用参数数组而非拼接 Shell；浏览器不是正式渲染器。 |
| TCR-001-009 | FastAPI 路由与 Pydantic 是唯一 HTTP 契约源；本地默认启用 `/docs` Swagger UI 与 `/openapi.json`，生产后缀配置默认关闭。固定 `@umijs/openapi` 直接读取 `LANVERSE_OPENAPI_URL`（本地默认 `http://127.0.0.1:8000/openapi.json`），请求函数与 DTO 直接写入 `frontend/src/services/`，不得套 `generated/` 或 `api/` 子目录；仓库不得提交或消费静态 OpenAPI 中间副本。自动生成文件必须带固定标识且不得手改，生成命令只替换这些文件，不得覆盖同目录的手写 RTK Query 层；前端经唯一 `request.ts` 发送且不得另写 URL、DTO 或第二客户端。 |
| TCR-001-010 | 任务状态同步通道只有 `GET /v1/tasks/{task_id}` 的 2 秒权威轮询。 |
| TCR-001-011 | AI 调用必须经服务端能力端口与 `AiModelRegistry`：MVP 基线只使用 `langchain-core` 的模型/Runnable 接口，文本模型使用该统一接口，图片、视频和 TTS 使用受同一 Registry 管理的 LangChain Provider 集成或直接 Python SDK Adapter。每类能力可登记多个已批准 Provider/模型配置和确定性 Mock；model_profile 不可原位修改，Task 受理前必须解析并冻结 `model_profile_id/provider_id/model_id/parameters_hash`，受理后不得静默切换或自动 fallback。不得直接依赖完整 `langchain` 或任何 `langgraph*` 包。 |
| TCR-001-012 | Provider 密钥只来自现有服务端环境配置；TaskJob、数据库业务字段和日志只能保存不可反解引用或脱敏摘要。LangSmith tracing 强制关闭且不得加载 key/endpoint，Prompt 外发域名只允许已批准 Provider。 |
| TCR-001-013 | 后端源码直接位于 `backend/src/`，不得额外封装 `src/lanverse/`。采用成熟 FastAPI 模块化单体的单一技术分层：`api/core/db/schemas/services/repositories/domain/workers/integrations`，入口只允许 `main.py` 与 `worker.py`。HTTP 路由按资源位于 `api/routes`；业务用例位于 `services`；参数化 SQL 与 Row Mapper 位于 `repositories`；AI/MinIO/FFmpeg Adapter 位于 `integrations`。禁止为每个业务功能复制 `domain/application/infrastructure/transport/public.py` 五层目录，也不得保留 `bootstrap/entrypoints/shared_kernel/modules/jobs/infrastructure` 旧根、`other`、运行时 `test` 路由、重复 utils/lib 层、通用基类、消息总线、Service Locator、第三方 DI、Event Sourcing 或微服务。 |
| TCR-001-014 | 依赖方向固定为 `api → services → repositories/domain` 与 `workers → services/integrations`；`services` 不得导入 `api`，`repositories` 不得导入 `services/api`。Domain 使用纯 Python 实体、值对象与 `Protocol`，不得依赖 FastAPI、Pydantic、asyncpg、Alembic、LangChain、Provider SDK、MinIO SDK 或 FFmpeg。持久化 Row DTO、Pydantic Schema 与 Domain Entity 不得复用为同一类型。 |
| TCR-001-015 | 不创建 `deploy/`。Compose 文件位于仓库根：默认 `docker-compose.yml`，其他环境只用 `docker-compose-<env>.yml` 后缀，生产为 `docker-compose-prod.yml`；MVP 默认文件只含 `frontend/backend-api/backend-worker`，通过现有 shell 环境引用本机 PostgreSQL/MinIO，不复制或提交 secret/本地 env 文件。后缀文件仅在对应环境进入正式范围时创建。 |
| TCR-001-016 | 后端测试使用 pytest、pytest-asyncio、HTTPX、asyncpg/Alembic 与真实 PostgreSQL/MinIO 夹具，Ruff/mypy 严格检查；SQL 门禁静态校验文件/表/FK/partial exact-set，并在隔离空库按顺序执行根 SQL 后比对 `pg_catalog`。前端使用 Vitest、Testing Library 和 Playwright；完整 Mock E2E 可重复执行。 |

## 2. 任务与数据约束

- BR-TCR-001：所有高成本命令要求 `Idempotency-Key`；版本编辑要求 ETag/`If-Match`。
- BR-TCR-002：Task、Attempt、Candidate、Adoption、Delivery 分别建模；不得用一个状态字段代替。
- BR-TCR-003：Provider 提交超时且无法证明未受理时进入 `unknown` 并对账，不得盲目重发。
- BR-TCR-004：Task 终态不可回退；自动重试新建 Attempt，用户重试新建 Task 并引用原 Task。
- BR-TCR-005：媒体对象与版本不可原位覆盖；Provider URL 不得作为永久事实。
- BR-TCR-006：应用只使用现有 PostgreSQL 中的 `lanverse` 数据库；asyncpg 与 Alembic 只连接该库。初始迁移只增加 DESIGN-06 的 20 张应用表、约束、索引及 `alembic_version`；Schema exact-set 排除该元数据。回滚不得执行破坏性 down migration。

## 3. 技术实现边界

技术实现只包含 TCR-001-001～016 与 BR-TCR-001～006 明确要求的运行单元、目录、模块和基础设施。未被活动 Requirement 编号要求的技术对象不得预建。

## 4. 验收标准

- AC-TCR-001：ADR/ARCH/Plan 中的技术、目录、模块和运行单元与 TCR-001-001～016 完全一致。
- AC-TCR-002：架构测试自动检查根目录、Python 单一技术分层、入口、依赖方向、根 Compose 命名/三服务、Domain 纯净性、SQL 文件 exact-set、TaskJob 租约和基于实时 Swagger URL 的 Radix/umi-openapi 基线；不存在旧五层业务模块、静态 OpenAPI 副本、`deploy/`、Temporal/Redis/Celery、ORM 或非 loopback 应用绑定。
- AC-TCR-003：Plan 必须明确数据库详细设计前置门禁、两个生态的精确依赖与 lockfile、资源上限、FFmpeg、统一根命令，以及“数据库 Design 接受后才能执行 PLAN-02、真实 Provider/模型/凭据和必需 SDK 在 PLAN-09 P09-T009 真实 smoke 前锁定”的可执行失败条件。
