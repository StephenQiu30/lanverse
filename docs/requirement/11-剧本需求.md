# 剧本需求

## 目标与范围

制作者能将支持格式的剧本转成可追踪的项目内容。

本模块范围：txt/md/docx上传原件、导入任务与状态、自动分集、设定抽取；PDF仍待确认。

建议执行顺序为编号顺序；编号不代表排期或已批准实施。本文件按业务模块整体维护，内部功能在同一文档列出，不为每个按钮、接口或技术层建立单独需求文件。

## 功能与数据要求

| 内容       | 必须产生的结果                                                      | 失败与边界                                                        |
| ---------- | ------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 格式与原件 | 支持txt/md/docx，原件与解析结果关联项目；上传走文件流               | PDF是否支持待定，不因旧接口裁掉md；实际字节上限和探测规则待细化   |
| 导入提交   | 建项目后建立可追踪任务；request_key重复同输入定位原任务，异输入冲突 | 导入失败保留项目，不能用本地样例或进度假装成功                    |
| 自动分集   | 从同份原件产生可追踪分集结构，保留输入来源                          | 分集规则、无标题及场/镜头形成规则待确认，不能臆造解析成功         |
| 抽取设定   | 从原件抽取角色/场景/道具，交由设定模块编辑与确认                    | 同名不自动实体合并；抽取/确认规则待定，不覆盖已锁定版本           |
| 状态与读取 | 读取真实任务进度、结果及安全失败说明                                | 刷新/重启仍能找到同一任务；未接入和失败分开；不在项目列表带回全文 |

## 依赖与待确认

依赖已建项目与授权文件存储；抽取结果由设定模块消费。

待确认：PDF是否支持、允许文件限制、分集识别/无标题处理、抽取规则、场与镜头的首次形成及确认方式。

以上缺口只是评审问题，不构成新增产品能力或架构决策。既有功能和约束不因旧接口支持不足而删除或降级。

## 模块验收

1. 本文列出的字段和功能由真实数据及操作结果承载，成功/失败/权限/未接入状态明确，mock不作为业务通过。
2. 需要持久化的写入可刷新恢复；版本冲突保留输入，重复副作用按幂等合同核对；只读/瞬时状态不强加持久化。
3. 当前用户/项目范围服务端验证；管理动作限管理员，秘密不进入响应、普通日志、审计明文或导出。
4. 实现时补与本模块风险匹配的成功、失败、冲突/重复、越权场景，分别记录自动化、真实持久化、浏览器及外部供应商证据，未执行不得报通过。

统一要求见[非功能规格](02-非功能需求规格.md)和[交互需求](05-界面与交互需求.md)；当前均待评审、未完成真实功能验收。本阶段不列Sprint、工时或固定用例数量。
