### 0.1 事实边界

- CUR-CAN 拥有 `CanvasView`、`CanvasLayoutRevision`、`CanvasGroup`、`CanvasFilterPreset` 和 `AgentActionProposal` 等画布视图与执行确认事实。
- Episode、NarrativeScene、Asset、Shot、Keyframe、VideoCandidate、ExportSnapshot、PackageBuild、WorkTask、readiness、主选和治理决定仍由原业务模块拥有；画布只读取并投影，不复制第二套业务实体或状态机。
- 列表页、详情页与画布必须读取同一领域事实并发出同一业务命令。画布不是独立数据库、独立工作流引擎或可绕过领域规则的低代码编排器。
- 本模块不是 Timeline、剪辑台或成片工具。节点位置、连线方向和画布分组不表达帧级时间，不得据此裁切、拼接、变速、转场、混音或渲染成片。

### 0.2 证据声明

- 参考成熟 AI 视频产品将复杂制作过程以类型化步骤、状态和局部动作可视化的公开交互方向；竞品事实、GitHub 固定证据与推导记录在 Research，不在本文件重复声明为已验证事实。
- 画布具体性能容量、最合适的默认分组和 Agent 高成本阈值必须通过真实项目样本与 PoC 冻结；本文件给出进入 PoC 的明确最低样本和验收方法。

## 1. 模块定位

### 1.1 用户问题

短剧项目会同时存在多集、叙事场景、资产、镜头、关键帧、视频候选、任务和导出记录。只有列表时，用户很难快速回答：某镜头依赖什么、为何 blocked、上游改动影响哪里、哪一批任务正在运行、应从哪个节点修复。只有自由画布时，用户又容易把布局误当业务事实，或因节点过多无法完成稳定操作。

CUR-CAN 提供“可视化理解 + 精确定位 + 原地局部动作”的第二种工作视图，同时保证非画布列表仍能完成全部核心任务。它帮助用户看清生产网络，不改变产品终点和模块事实归属。

### 1.2 用户结果

1. 用户可在同一 Episode 范围内查看从叙事结构、资产、镜头、关键帧、视频候选到导出结果的类型化节点和依赖。
2. 用户可叠加查看 readiness、任务进度、blocked、stale、needs_reconfirmation、needs_reselection、selected 等不同维度，而不会把它们压成一个含糊状态。
3. 用户可从任一问题节点直接进入业务详情，完成允许的局部修复、重跑、重选或重新确认，并在 5 秒内看到服务端事实变化。
4. 团队可共享一份稳定布局，使用自动布局、分组、筛选、缩放、小地图和定位处理大规模 Episode，同时能从并发冲突和刷新中恢复。
5. Agent 只能先提出方案、影响、预计消耗和风险；高成本或破坏性动作必须经有权用户明确确认后，才通过同一业务命令执行。
6. 不使用画布、使用键盘或辅助技术的用户仍能在列表/详情完成全部 P0 核心任务。

### 1.3 产品 KPI

| KPI ID | 指标 | proposed 目标 |
| --- | --- | --- |
| CUR-CAN-KPI-001 | 画布与对应列表对同一对象显示不同业务终态、主选或 blocker | 0 次 |
| CUR-CAN-KPI-002 | 画布命令绕过权限、并发、治理、成本确认或领域不变式 | 0 次 |
| CUR-CAN-KPI-003 | 从项目级 blocker 到具体业务对象和允许下一动作 | 不超过 2 次用户导航 |
| CUR-CAN-KPI-004 | 服务端事实变化到画布和列表可观察 | P95 ≤ 5 秒 |
| CUR-CAN-KPI-005 | 刷新、断线或布局冲突造成已确认业务命令重复执行 | 0 次 |
| CUR-CAN-KPI-006 | 非画布路径无法完成的 P0 核心任务 | 0 个 |

## 2. 范围与非范围

### 2.1 当前范围

- Project/Episode 级画布入口、范围切换和恢复最近有效视图；
- Episode、NarrativeScene、Asset、Shot、Keyframe、VideoCandidate、ExportSnapshot/PackageBuild 等类型化业务节点；
- 依赖、覆盖、输入血缘三类边及其方向、来源和解释；
- readiness、WorkTask 进度、blocked、stale、needs_reconfirmation、needs_reselection、selected 等独立叠层；
- Workspace 共享布局、布局修订、自动布局、手动定位、分组、折叠、筛选、缩放、小地图、搜索与定位；
- 节点详情摘要、跳转业务详情、局部修复、局部重跑、主选/重新确认等允许动作；
- Agent 方案提议、影响/预计消耗/风险预览、确认、拒绝、过期和执行结果；
- 画布与列表等价、键盘替代、刷新/断线恢复、并发冲突和部分摘要不可用处理；
- 为至少 120 个 active Shot 的真实复杂 Episode 建立可测性能基线。

### 2.2 明确非范围

- Timeline、Track、Clip、帧级时间标尺、剪辑、拼接、转场、调色、字幕、音频后期和成片渲染；
- 允许用户创建任意脚本节点、任意 Provider 技术节点或任意连线以改变领域事实；
- 以节点坐标、连线或分组替代 Episode 顺序、StoryboardBaseline、ShotOrderRevision 或导出顺序；
- 把多个业务状态合并为单个颜色、百分比或“完成/失败”总状态；
- 画布内实时共同拖拽、光标跟随、评论、白板或演示文稿能力；
- 只能经 Agent 完成的功能、未经确认自动批量生成、自动删除、自动重选或自动导出；
- 依赖画布才能使用的隐藏核心命令。

## 3. 角色与权限

授权角色与成员状态完全消费 CUR-IAM，不建立画布专属角色。

| 能力 | owner | editor | viewer |
| --- | --- | --- | --- |
| 查看有权 Project/Episode 的画布与业务摘要 | ✓ | ✓ | ✓ |
| 保存 Workspace 共享布局、分组和共享筛选预设 | ✓ | ✓ | — |
| 保存仅本人可见的视口与临时筛选 | ✓ | ✓ | ✓ |
| 发起普通业务命令 | ✓ | ✓ | — |
| 确认高成本或破坏性 Agent 提议 | ✓ | ✓，但仍受原业务权限限制 | — |
| 查看预计消耗、风险和执行结果 | ✓ | ✓ | 只读摘要，粒度遵循 CUR-PLT/CUR-IAM |
| 下载原始候选或素材包 | ✓ | ✓ | — |

权限在读取、命令提交和结果访问时均重新检查。成员移除、角色降低、Workspace 归档或治理阻断后，已打开画布不得继续发出旧权限命令；无法确认权限时 fail-closed。

## 4. 核心用户场景

### CUR-CAN-US-001 从全局发现阻塞镜头

导演打开一集画布，开启 blocked 和 task 叠层，定位到缺少关键帧主选的 Shot，查看来源并跳到关键帧详情修复。

### CUR-CAN-US-002 理解上游变化影响

资产设计修改某角色固定版本后，画布显示关联 Shot 的输入血缘与 stale 叠层；用户查看影响，决定逐镜沿用、升级或重新确认。

### CUR-CAN-US-003 批量组织复杂 Episode

用户对 120 个 active Shot 的 Episode 自动布局，按 NarrativeScene 分组，筛选生成中镜头并通过小地图定位；保存为 Workspace 共享布局供团队复用。

### CUR-CAN-US-004 从 Agent 方案安全执行

Agent 提议为 12 个 blocked Shot 补生成 start_frame。用户先看到固定目标、原因、预计消耗、可能覆盖/失效影响和不可逆风险；确认后系统逐目标执行，局部失败不污染其他镜头。

### CUR-CAN-US-005 无画布完成同一任务

使用键盘和列表视图的用户可筛选同一 blocked Shot、查看相同叠层文字、执行同一修复命令并获得相同结果。

### CUR-CAN-US-006 从断线与布局冲突恢复

用户拖动和分组后网络中断，恢复时能看到未保存变化；若他人已保存新修订，系统提供保留个人草稿、加载共享版本或基于最新修订重新应用的明确选择，且不重复业务命令。

## 6. 类型化视图模型

### 6.1 节点类型

| 类型 | 最小展示事实 | 默认允许跳转 |
| --- | --- | --- |
| Episode | 标题、顺序、生产摘要、blocker 数 | Episode 工作台 |
| NarrativeScene | 固定 ScriptVersion、场次、叙事范围、生产处置摘要 | 剧本结构详情 |
| Asset | 类型、状态、固定版本、参考选择、readiness | 资产详情 |
| Shot | 镜号投影、固定 ShotSpec、覆盖、readiness | 分镜/镜头详情 |
| Keyframe | 用途、固定输入、当前图片选择、stale/blocked | 关键帧详情 |
| VideoCandidate | 来源任务、固定输入、媒体可用性、selected/starred/rejected | 视频候选详情 |
| ExportSnapshot | 范围、冻结顺序、逐镜选择摘要、冻结时间 | 导出快照详情 |
| PackageBuild | 构建状态、文件进度、完整性、过期时间 | 包构建详情 |
| WorkTask | 业务用途、canonical 状态、阶段、消耗摘要、下一动作 | 任务详情 |

第一版可折叠隐藏低层级节点，但不得把多条 Candidate 或多项 WorkTask 合并为一个可被误认为真实业务对象的节点。聚合节点必须标记“视图聚合”，展开后可定位每个稳定对象。

### 6.2 边类型

| 边类型 | 含义 | 约束 |
| --- | --- | --- |
| dependency | 目标在当前用途上依赖来源对象或固定版本 | 必须显示依赖用途和 blocker 传播解释；不能表示任意执行顺序 |
| coverage | Shot/ShotSpec 覆盖某 NarrativeUnitVersion 或生产处置 | 必须可定位未覆盖、重复覆盖和允许省略的叙事单元 |
| input_lineage | Candidate、选择或 Snapshot 使用的固定输入来源 | 必须来自 CUR-PLT/拥有模块的稳定血缘；不得用 current 指针回填历史 |

边必须可被筛选、隐藏和解释。删除画布边只改变允许的视图隐藏/分组，不删除业务依赖、叙事覆盖或输入血缘；改变业务关系必须调用原模块受控命令。

### 6.3 独立叠层

| 叠层 | 事实来源 | 示例值 |
| --- | --- | --- |
| readiness | 对应业务模块 | ready、blocked、unavailable |
| task_progress | CUR-PLT WorkTask | queued、running、waiting_external、succeeded、failed、cancelled、unknown、manual_attention |
| blocking | 对应业务模块/CUR-SEC | blocker 类别、对象、原因、下一动作 |
| freshness | 血缘与业务模块 | current、stale、needs_reconfirmation、needs_reselection |
| selection | AST/KFR/VID | unselected、selected、starred、rejected；星标与主选独立 |
| governance | CUR-SEC | allowed、warning、blocked、under_review |

叠层不得被压成单个“节点状态”。例如一个 Candidate 可同时是 `selected + stale + media ready`，对应 WorkTask 已 `succeeded`；界面必须分别显示并解释，而不是选择其中一个覆盖其他事实。

## 8. 详细功能需求

### CUR-CAN-FR-001 在列表与画布投影同一领域事实

| 项目 | 要求 |
| --- | --- |
| 前置条件 | 用户有权读取目标 Project/Episode；相应模块可返回稳定对象或明确不可用结果。 |
| 主流程 | 用户从项目工作台进入画布；系统按固定范围读取与列表相同的对象、版本、状态、选择、任务、blocker 和更新时间，并显示数据范围及读取时点。 |
| 备选流程 | 用户从列表切换到画布或从画布切回列表时保留 Project/Episode、筛选和定位对象。 |
| 失败/恢复 | 某模块摘要不可用时，仅对应节点/叠层显示 unavailable 和重试入口；其他事实保持可读。手动刷新重读服务端事实，不用本地旧值冒充最新。 |
| 业务规则 | 相同稳定 ID 在两种视图中代表同一对象；业务终态、主选、readiness 和 blocker 不得由 CUR-CAN 重算为第二事实。 |
| 输入/输出 | 输入范围、筛选、对象修订；输出类型化投影、来源模块、更新时间和部分失败。 |

### CUR-CAN-FR-002 展示类型化节点、边和来源解释

| 项目 | 要求 |
| --- | --- |
| 前置条件 | 上游返回节点类型、稳定 ID、固定版本和关系类型。 |
| 主流程 | 系统按第 6 节显示节点和 dependency/coverage/input_lineage 边；用户选择节点或边时看到类型、来源、固定版本、方向、业务含义和跳转入口。 |
| 备选流程 | 节点过密时以明确标识的视图聚合折叠；用户可展开到真实对象。 |
| 失败/恢复 | 关系缺少稳定来源或形成自相矛盾时显示 lineage_gap/blocking，不猜测连线；刷新后重新获取。 |
| 业务规则 | 用户不得新建任意技术节点或任意连线改变领域关系；坐标不表达制作顺序或时间轴。 |
| 输入/输出 | 输入业务对象与关系；输出可解释图及来源证据。 |

### CUR-CAN-FR-003 独立叠加状态、任务、阻塞、新鲜度和选择信息

| 项目 | 要求 |
| --- | --- |
| 前置条件 | 相应状态事实可读，或来源明确 unavailable。 |
| 主流程 | 用户分别开关 readiness、task_progress、blocking、freshness、selection、governance 叠层；节点可同时呈现多个状态及文字说明。 |
| 备选流程 | 用户筛选组合条件，如“blocked 且无运行任务”或“selected 且 stale”。 |
| 失败/恢复 | 某一叠层不可用时只将该叠层标记 unknown/unavailable，不把整个节点设为失败；恢复后在 5 秒目标内更新。 |
| 业务规则 | task succeeded 不等于业务 ready；starred 不等于 selected；stale 不等于任务 failed；治理 blocked 不改写历史任务终态。 |
| 输入/输出 | 输入各模块事实；输出独立叠层、汇总计数和逐项解释。 |

### CUR-CAN-FR-004 共享布局、修订、自动布局与恢复

| 项目 | 要求 |
| --- | --- |
| 前置条件 | owner/editor 有权修改目标 Workspace 共享视图；viewer 仅可修改个人视口。 |
| 主流程 | 用户移动节点、创建视图分组或执行自动布局，预览后以期望布局修订保存；系统形成新的不可变 CanvasLayoutRevision 并使之成为共享 current。 |
| 备选流程 | 用户可撤销未保存的视图变化、恢复上次共享修订、保存个人视口；自动布局可按 Scene、Shot 阶段或 blocker 分组，但不改变业务顺序。 |
| 失败/恢复 | 网络失败保留本地布局草稿和基于修订；并发冲突返回最新共享修订与差异，用户选择放弃草稿、保留为个人草稿或基于最新修订重新应用。不得静默覆盖。 |
| 业务规则 | 共享布局属于 Workspace；布局修订只保存位置、视图分组、折叠和可见性，不复制业务正文、Prompt、媒体或领域状态。 |
| 输入/输出 | 输入 CanvasView、位置/分组变化、期望修订；输出新修订或零写入冲突。 |

### CUR-CAN-FR-005 分组、折叠、筛选、缩放、小地图和定位

| 项目 | 要求 |
| --- | --- |
| 前置条件 | 目标范围至少有一个可读节点。 |

## 9. 领域实体与状态

| ID | 实体 | 定义 |
| --- | --- | --- |
| CUR-CAN-ENT-001 | CanvasView | 某 Workspace/Project 范围的共享可视化视图身份、名称和默认范围。 |
| CUR-CAN-ENT-002 | CanvasLayoutRevision | 不可变的节点位置、视图分组、折叠和可见性修订；不包含业务事实副本。 |
| CUR-CAN-ENT-003 | CanvasGroup | 仅用于理解和导航的视图分组，可按类型、Scene、阶段或用户定义主题组织。 |
| CUR-CAN-ENT-004 | CanvasFilterPreset | 共享或个人筛选、叠层和范围偏好。 |
| CUR-CAN-ENT-005 | CanvasViewportPreference | 个人最近视口、缩放和焦点；不改变共享布局。 |
| CUR-CAN-ENT-006 | AgentActionProposal | 对固定事实、目标和成本上限的一次不可变动作方案。 |
| CUR-CAN-ENT-007 | ProposalDecision | 有权用户对固定提议的确认、拒绝或范围修改决定。 |
| CUR-CAN-ENT-008 | CanvasProjectionIssue | 节点、边、叠层或来源暂不可用的可恢复视图问题。 |

### 9.1 CanvasView

`draft → active → archived → active`。仅满足 CUR-CAN-FR-012 的空白个人 draft 可进入 deleted；deleted 不可恢复。active 共享视图必须始终有一个 current CanvasLayoutRevision。

### 9.2 CanvasLayoutRevision

创建即 immutable。共享 current 是可变引用；保存新修订必须携带期望 current，冲突时零写入。个人未保存草稿使用 `clean → dirty → saving → saved | save_failed | conflict`，刷新后可恢复 dirty/save_failed 草稿，但不得自动覆盖共享 current。

### 9.3 AgentActionProposal

`draft → proposed → confirmed | rejected | expired`；`confirmed → executing → completed | partially_failed | failed | unknown`。事实版本、权限/治理结果、动作集合或成本上限变化后原 proposed 必须 expired；confirmed 不等于业务动作成功，逐项结果以原模块事实为准。

### 9.4 核心不变式

1. 画布与列表对同一稳定 ID 读取同一领域事实源。
2. CanvasLayoutRevision 不得保存业务正文、完整 Prompt、媒体字节、临时 URL、任务终态或主选副本。
3. 节点位置、分组和边的显示顺序不改变 Episode/Shot 顺序或导出顺序。
4. readiness、Task、blocking、freshness、selection 和 governance 是可组合叠层，禁止合并成单一领域状态。
5. 画布发出的命令必须使用与列表相同的授权、治理、期望修订、幂等与审计规则。
6. 高成本或破坏性 Agent 动作必须基于固定提议由有权用户明确确认；不得默认确认或扩大范围。
7. 星标是 Workspace 共享决定，viewer 只读；画布个人视图偏好不得改变星标或主选。
8. 当前主选被拒绝时必须显示 needs_reselection，不能在画布中自动连到另一个 Candidate。
9. 不使用画布时仍能完成全部 P0 业务闭环。
10. CUR-CAN 不拥有 WorkTask、Provider、Media、Lineage、Cost 或安全治理终态。

### 14.1 已决策事项

- 画布和列表共享同一领域事实与命令，列表可完成全部核心任务。
- 画布不是 Timeline、剪辑台、低代码编排器或第二套工作流引擎。
- 只支持有稳定业务语义的类型化节点与 dependency/coverage/input_lineage 边。
- 多种状态使用独立叠层，不合并为单一节点状态。
- Workspace 共享布局采用不可变修订和显式并发冲突恢复。
- Agent 高成本或破坏性动作必须先形成固定提议，再由有权用户确认。

## 15. 术语

| 术语 | 定义 |
| --- | --- |
| 画布投影 | 将原业务模块事实按类型化节点、边和叠层呈现的可视化读取结果，不是事实副本。 |
| 共享布局 | Workspace 内 owner/editor 发布、成员共同读取的节点位置和视图组织修订。 |
| 个人视口 | 仅个人可见的缩放、焦点和临时筛选，不改变共享布局。 |
| 视图聚合 | 为控制复杂度而折叠显示的明确视图对象，展开后必须定位真实业务对象。 |
| dependency | 当前用途上目标依赖来源对象/固定版本的关系。 |
| coverage | Shot/ShotSpec 对 NarrativeUnitVersion 生产处置的覆盖关系。 |
| input_lineage | 输出、候选、选择或快照到固定输入的来源关系。 |
| AgentActionProposal | Agent 对固定目标、影响、预计消耗、风险和动作集合形成的待确认方案，不代表已执行。 |
