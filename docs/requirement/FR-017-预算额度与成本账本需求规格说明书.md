# FR-017 预算、额度与成本账本需求规格说明书

## 1. 目的与范围

在 AI 生产开始前给出成本预估，在执行过程中控制预算和可用额度，并以不可抵赖的账本记录预占、结算、释放、退款和补偿，使每笔成本都能追溯到项目、任务、执行尝试和结果。

本能力不规定供应商采购合同、会计总账或具体支付渠道；套餐购买、支付和开票属于 P1 扩展范围。

## 2. 主业务流程

1. 项目负责人设置项目或分集预算及预警阈值。
2. 系统根据模型能力、参数和预计产出计算本次生产成本。
3. 用户确认高成本操作后，系统预占对应额度。
4. 任务结束后，系统按有效计量事实结算实际成本。
5. 未使用预占额度被释放，符合规则的失败或取消产生退款或补偿记录。
6. 用户按项目、分集、镜头、模型和时间查看成本明细。

## 3. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-017-001 | 系统应分别维护额度余额、预算、预计成本、实际用量、价格和支付交易。 | P0 |
| FR-017-002 | 系统应允许授权用户为项目和分集设置预算上限及预警阈值。 | P0 |
| FR-017-003 | 系统应在任务提交前基于明确能力版本、参数和计价规则计算预计成本。 | P0 |
| FR-017-004 | 系统应在预计成本达到配置阈值时要求用户明确确认。 | P0 |
| FR-017-005 | 系统应在任务受理时以幂等方式预占可用额度。 | P0 |
| FR-017-006 | 系统应在取得有效计量事实后以幂等方式结算实际成本。 | P0 |
| FR-017-007 | 系统应释放未被实际结算使用的预占额度。 | P0 |
| FR-017-008 | 系统应按规则为失败、取消、重复扣费或无有效结果的任务生成退款或补偿记录。 | P0 |
| FR-017-009 | 系统应将每笔账本记录关联到项目、分集、任务、执行尝试、能力版本和结果。 | P0 |
| FR-017-010 | 系统应提供按项目、分集、镜头、模型和时间范围汇总的成本查询。 | P0 |
| FR-017-011 | 系统应在预算或可用额度不足时阻止新的可计费任务，并说明阻断原因。 | P0 |
| FR-017-012 | 系统应支持套餐、额度购买、支付状态、退款和开票申请。 | P1 |

## 4. 业务规则

- BR-017-001：同一计费事件不得产生重复预占或重复结算。
- BR-017-002：账本采用追加更正，不得修改或删除已生效记录。
- BR-017-003：预估成本不是实际结算事实，实际成本必须依据有效计量结果。
- BR-017-004：预算不足与额度不足是两个独立阻断原因。
- BR-017-005：免费重试、收费重试、退款和补偿应由明确规则区分。
- BR-017-006：供应商成本、平台对用户计价和用户支付金额应分别记录。

## 5. 数据要求

- DR-017-001：保存预算、阈值、币种、额度账户和余额快照。
- DR-017-002：保存价格版本、成本预估、预占、结算、释放、退款、补偿和更正记录。
- DR-017-003：保存计量依据、幂等键、任务与尝试关联、操作人和发生时间。

## 6. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 任务提交成功但预占失败 | 不启动可计费执行，并返回明确失败原因。 |
| 供应商迟到结果到达 | 根据任务最终状态和计费规则决定是否结算，不重复扣费。 |
| 计量事实暂不可用 | 保持待结算状态并重试核对，不估算为最终金额。 |
| 发现历史重复扣费 | 追加冲正或补偿记录，不改写原账本。 |

## 7. 验收标准

- AC-017-001：重复提交同一幂等请求只产生一次额度预占。
- AC-017-002：任务实际成本低于预占金额时，差额被释放且账本可解释。
- AC-017-003：额度不足时任务不进入供应商执行队列，也不产生实际结算。
- AC-017-004：任一实际成本均可追溯到执行尝试、能力版本、计价规则和结果。
- AC-017-005：更正历史扣费后，原记录仍可查询且余额由追加记录正确调整。
