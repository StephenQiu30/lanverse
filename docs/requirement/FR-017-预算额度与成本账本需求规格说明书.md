# FR-017 预算、额度与成本账本需求规格说明书

## 1. 目的与范围

在 AI 生产开始前给出成本预估，在执行过程中控制预算和可用额度，并以不可抵赖的账本记录预占、结算、释放、账本退款和补偿，使每笔成本都能追溯到项目、任务、执行尝试和结果。

本能力 P0 只覆盖额度、预算、成本账本及账本关联的支付引用元数据，不发起或处理支付渠道交易；完整套餐购买、支付状态处理、支付渠道退款和开票属于 P1 扩展范围。本能力不规定供应商采购合同或会计总账。

## 2. 主业务流程

1. 项目负责人设置项目或分集预算及预警阈值。
2. 系统根据模型能力、参数和预计产出计算本次生产成本。
3. 用户确认高成本操作后，系统预占对应额度。
4. 任务结束后，系统按有效计量事实结算实际成本。
5. 未使用预占额度被释放，符合规则的失败或取消产生额度账本退款或补偿记录。
6. 用户按项目、分集、镜头、模型和时间查看成本明细。

## 3. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-017-001 | 系统应分别维护额度余额、预算、预计成本、实际用量、价格和追加式账本；P0 只保存账本关联的支付交易引用、渠道、结算币种与状态快照，不发起或推进支付交易。 | P0 |
| FR-017-002 | 系统应允许授权用户为项目和分集设置预算上限及预警阈值。 | P0 |
| FR-017-003 | 系统应在任务提交前基于明确能力版本、参数和计价规则计算预计成本。 | P0 |
| FR-017-004 | 系统应在预计成本达到配置阈值时要求用户明确确认。 | P0 |
| FR-017-005 | 系统应在任务受理时以单个数据库原子操作完成额度与预算检查、并发条件写入和预占；任一检查失败时不得创建任务或部分预占。 | P0 |
| FR-017-006 | 系统应在取得有效计量事实后以幂等方式结算实际成本。 | P0 |
| FR-017-007 | 系统应释放未被实际结算使用的预占额度。 | P0 |
| FR-017-008 | 系统应按规则为失败、取消、重复扣费或无有效结果的任务生成额度账本退款或补偿记录；P0 不调用支付渠道执行原路退款。 | P0 |
| FR-017-009 | 系统应将每笔账本记录关联到项目、分集、任务、执行尝试、能力版本和结果。 | P0 |
| FR-017-010 | 系统应提供按项目、分集、镜头、模型和时间范围汇总的成本查询。 | P0 |
| FR-017-011 | 系统应在预算或可用额度不足时阻止新的可计费任务，并说明阻断原因。 | P0 |
| FR-017-012 | 系统应在 P1 支持完整套餐购买、支付发起与状态/回调处理、支付渠道退款和开票申请，并把结果以引用元数据关联到 P0 账本。 | P1 |
| FR-017-013 | 系统应为每个预占、计量、结算、释放、账本退款、补偿或冲正事实生成稳定计费事件键，并以数据库唯一约束保证跨重试、回调和对账导入只生效一次。 | P0 |
| FR-017-014 | 系统应只允许计费对象按已定义状态机转换；重复、迟到或乱序事件不得回退终态、绕过前置状态或重复影响余额。 | P0 |
| FR-017-015 | 系统应以 `currency_code + amount_minor` 的整数表示入账金额；价格版本必须固定最小货币单位指数、十进制计算精度和舍入模式，禁止以二进制浮点数形成账本事实。 | P0 |
| FR-017-016 | 系统应为每次跨币种换算固定经批准的汇率权威来源、来源版本、汇率标识、报价/结算币种、汇率值和 `effective_at`，不可用、过期或不适用的汇率不得用于预占或结算。 | P0 |
| FR-017-017 | 系统应对跨币种多明细先按冻结规则计算并对总额舍入一次，再以最大余数法分配最小单位差额；余数相同时按稳定明细标识排序，分配后明细之和必须等于入账总额。 | P0 |
| FR-017-018 | 系统应通过同一版本化换算服务处理预估、预占、部分/最终结算、释放、账本退款、补偿和冲正；预占固定报价汇率快照，结算按冻结的结算汇率策略记录快照，释放按预占币种回补，退款/冲正复用原结算快照，汇率差额单独追加 `fx_variance`。 | P0 |

## 4. 业务规则

- BR-017-001：同一计费事件不得产生重复预占或重复结算。
- BR-017-002：账本采用追加更正，不得修改或删除已生效记录。
- BR-017-003：预估成本不是实际结算事实，实际成本必须依据有效计量结果。
- BR-017-004：预算不足与额度不足是两个独立阻断原因。
- BR-017-005：免费重试、收费重试、退款和补偿应由明确规则区分。
- BR-017-006：供应商成本、平台对用户计价和用户支付金额应分别记录；P0 的“退款”仅指额度账本退款/冲正，P1 支付渠道退款不得伪装为账本状态转换。
- BR-017-007：`可用额度 = 账户净余额 - 生效预占总额`，`预算可用额 = 预算上限 - 已结算成本 - 生效预占总额`；原子预占提交后两者均不得为负，冲突请求必须重新读取后失败或重试。
- BR-017-008：预占状态仅允许 `created → reserved → pending_settlement → partially_settled → settled`，或未发生结算时从 `reserved/pending_settlement → released`；部分结算后的剩余金额须经结算或释放后进入 `settled`，且 `结算累计 + 释放累计 = 预占金额`。`settled/released` 为终态，退款、补偿和冲正必须追加独立关联事件。
- BR-017-009：计费事件键至少绑定工作空间、额度账户、任务尝试、事件类型和计量修订；供应商事件还须绑定供应商请求/对账标识，字段规范化规则发布后不得随重试变化。
- BR-017-010：终态后的迟到计量不得把 `released` 改为 `settled`；系统应按冻结的计费规则记为忽略、平台承担或人工对账，且不得在没有新授权预占的情况下再次扣减用户额度。
- BR-017-011：金额换算和差额分配规则只能随价格/汇率策略新版本生效；历史预占、结算、释放和账本退款不得因当前汇率或舍入规则变化被重算。

## 5. 数据要求

- DR-017-001：保存预算、阈值、账本币种、额度账户、整数最小单位金额和余额快照。
- DR-017-002：保存价格版本、计算精度、舍入模式、成本预估、预占、部分/最终结算、释放、账本退款、补偿、冲正和 `fx_variance` 记录。
- DR-017-003：保存计量依据、稳定计费事件键、预占状态与版本、任务与尝试关联、操作人、供应商事件时间、平台接收时间及账本关联支付引用元数据。
- DR-017-004：跨币种记录必须保存原币金额、账本币金额、汇率来源/版本/标识/值/生效时间、换算策略版本、舍入前结果、余数分配和原结算引用。

## 6. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 任务提交请求通过业务校验但原子预占失败 | 整体事务回滚，不创建可执行任务或部分预占，并返回明确失败原因。 |
| 供应商迟到或乱序结果到达 | 先按计费事件键去重，再校验当前状态和冻结计费规则；终态不回退，不能合法结算的事件进入忽略、平台承担或人工对账。 |
| 计量事实暂不可用 | 保持待结算状态并重试核对，不估算为最终金额。 |
| 汇率缺失、过期、币种对不匹配或精度规则未知 | 失败关闭预占或结算并进入可追踪对账，不使用当前汇率、默认汇率或浮点近似兜底。 |
| 发现历史重复扣费 | 追加冲正或补偿记录，不改写原账本。 |

## 7. 验收标准

- AC-017-001：重复提交同一幂等请求只产生一次额度预占。
- AC-017-002：任务实际成本低于预占金额时，差额被释放且账本可解释。
- AC-017-003：额度不足时任务不进入供应商执行队列，也不产生实际结算。
- AC-017-004：任一实际成本均可追溯到执行尝试、能力版本、计价规则和结果。
- AC-017-005：更正历史扣费后，原记录仍可查询且余额由追加记录正确调整。
- AC-017-006：以两个总预占额大于剩余额度或项目预算的并发请求验证原子不变量；最多只有可被余额和预算共同覆盖的请求成功，且任一提交点的可用额均不为负。
- AC-017-007：对同一供应商计量并发发送重复回调和对账导入，数据库中只存在一个生效计费事件且余额只变化一次。
- AC-017-008：在预占已释放、已结算以及待结算三种状态下注入迟到和乱序计量；仅合法转换可结算，终态不回退、不重复扣费，其他事件形成可追溯处置记录。
- AC-017-009：在同一额度/预算上并发提交超过可用额的预占，并对成功预占发送多币种部分结算、重复/乱序计量和对账导入；验证仅可覆盖的预占成功，每个部分结算只入账一次，最终 `结算累计 + 释放累计 = 预占金额`，明细之和等于总额，`fx_variance` 可解释且账本重算余额一致。
- AC-017-010：对同一原结算执行账本退款/冲正时复用原汇率快照和舍入分配；P0 不产生支付渠道请求，只有启用 P1 支付能力后才可把渠道退款结果引用到账本。
