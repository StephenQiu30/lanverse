# TCR-003 前端应用架构与工程约束需求规格说明书

## 1. 目的与产品边界

本规格定义 Lanverse Web 前端的技术栈、渲染边界、状态分层、媒体交互、安全和工程质量要求。

首发客户端边界：

- 桌面浏览器提供完整的内容、资产、分镜、生成、后期、审核和交付工作台。
- 平板和移动浏览器提供项目查看、任务查看、审片、评论与批准；不承诺完整时间线编辑。
- 首发支持当前及前一个稳定主版本的 Chrome、Edge 和 Safari；Firefox 支持普通管理与审片流程，复杂媒体编辑须经兼容性验证后纳入。
- 完整创作工作台的设计基线为不小于 1280×720 的视口；较小视口必须给出明确降级提示，不得造成数据损坏。

## 2. 前端技术与分层基线

| 层次 | 强制技术或模式 | 责任边界 |
| --- | --- | --- |
| 应用框架 | React、Next.js App Router、TypeScript 严格模式 | 路由、服务端渲染、客户端交互和构建 |
| 视觉系统 | Tailwind CSS、shadcn/ui，基于设计令牌扩展 | 通用组件、主题、响应式和可访问状态 |
| 服务端状态 | TanStack Query | 查询缓存、失效、重试和服务端状态同步 |
| 编辑器本地状态 | Zustand | 未保存操作、选区、面板、播放头和撤销栈 |
| 表单与校验 | React Hook Form、Zod | 表单状态、客户端提示和共享契约校验 |
| API 客户端 | 由接受的 OpenAPI 3.1 契约生成 | 请求类型、错误类型和版本兼容 |
| 测试 | Vitest、Testing Library、Playwright | 单元、组件、关键流程和跨浏览器验证 |
| 可观测性 | OpenTelemetry 兼容的前端遥测 | 发布版本、性能、错误和请求关联 |

## 3. 渲染、路由与模块边界

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-001 | Next.js 页面默认使用 Server Components；仅在需要事件、浏览器 API 或短期交互状态时声明 Client Component。 | P0 |
| TCR-003-002 | 供应商密钥、服务端令牌和敏感策略只能在服务端运行边界使用，不得进入客户端 Bundle 或公开环境变量。 | P0 |
| TCR-003-003 | 前端功能模块必须映射 FR-001～FR-020 的业务边界，不得把任务完成、审核通过、当前采用和正式交付合并为一个页面状态。 | P0 |
| TCR-003-004 | 项目路由必须包含明确的工作空间和项目上下文，并支持刷新、深链、前进和后退后重建可分享的导航状态。 | P0 |
| TCR-003-005 | 无权访问时不得通过页面、缓存、错误信息或预加载行为泄露对象是否存在。 | P0 |
| TCR-003-006 | 公共页面、登录态工作台和外部审片入口必须具有不同的会话、缓存和安全边界。 | P0 |
| TCR-003-007 | 高成本编辑器依赖必须按路由或功能延迟加载，不得进入所有用户的初始公共 Bundle。 | P0 |

## 4. 客户端状态、保存与并发

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-008 | 前端必须区分服务端正式事实、服务端草稿、客户端未保存修改、异步任务状态和纯 UI 状态。 | P0 |
| TCR-003-009 | TanStack Query 缓存不得被当作正式事实源；写入成功后必须按契约更新或失效相关查询。 | P0 |
| TCR-003-010 | Zustand 只保存编辑会话与 UI 状态，不得复制账户权限、费用余额、审核结论或交付状态作为权威数据。 | P0 |
| TCR-003-011 | MVP 并发编辑采用版本号或 ETag 的乐观并发；冲突必须允许刷新比较、合并或另存新版本，禁止静默覆盖。 | P0 |
| TCR-003-012 | 自动保存必须显示保存中、已保存、失败和离线状态，且不得等同于确认基线、提交审核或批准。 | P0 |
| TCR-003-013 | 可编辑页面必须在网络恢复后重新取得服务端版本并解决冲突，不得假定断线期间的服务端状态未变化。 | P0 |
| TCR-003-014 | 退出登录、切换账户、切换工作空间或权限撤销时，必须清理相应查询缓存、本地草稿和媒体访问凭据。 | P0 |
| TCR-003-015 | 浏览器持久存储默认只保存非敏感偏好；保存业务草稿必须另有加密、过期、清理和用户告知设计。 | P0 |

## 5. 异步任务与实时状态

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-016 | 提交生成、渲染或导出后，前端必须立即展示任务标识、受理状态、可执行动作和费用状态。 | P0 |
| TCR-003-017 | 任务进度默认通过 SSE 接收，并使用事件游标续接；断线时必须显示状态未知并通过权威查询收敛。 | P0 |
| TCR-003-018 | 事件可能重复或乱序时，前端必须按事件版本和服务端资源版本幂等合并。 | P0 |
| TCR-003-019 | WebSocket 仅用于未来经批准的共同编辑、在线状态或低延迟协同，不得替代正式任务状态查询。 | P0 |
| TCR-003-020 | 取消、重试、补做和局部返工必须作为不同动作展示，禁止用一个含糊的“重新生成”改变既有证据。 | P0 |

## 6. 媒体上传、预览与时间线

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-021 | 大文件必须使用服务端授权的对象存储分片直传，支持进度、暂停、取消、恢复、重试和上传后校验。 | P0 |
| TCR-003-022 | 上传完成但安全扫描或完整性校验未通过的媒体必须保持隔离，不得作为可生产资产使用。 | P0 |
| TCR-003-023 | 预览默认使用代理媒体、缩略图和音频波形；代理失效时必须保留编辑位置并明确说明阻断原因。 | P0 |
| TCR-003-024 | 视频预览必须支持授权后的字节范围读取和拖动定位，签名 URL 过期后仅能通过重新授权恢复。 | P0 |
| TCR-003-025 | 时间线的权威位置必须使用服务端契约规定的 timebase 与整数 tick/帧，前端不得以浮点秒保存正式剪辑结果。 | P0 |
| TCR-003-026 | 剪切、移动、替换、增益和字幕调整必须非破坏性，并支持会话内撤销/重做；不得撤销他人已确认的正式决定。 | P0 |
| TCR-003-027 | 时间线拖拽操作必须提供键盘或数值输入的等价方式。 | P0 |
| TCR-003-028 | 浏览器只负责交互预览，正式转码、混音、质检和交付渲染必须请求后端执行。 | P0 |
| TCR-003-029 | 不支持必要媒体能力的浏览器必须在编辑前检测并降级为查看或审片，禁止在导出时才暴露不兼容。 | P0 |

## 7. 安全、可访问性与体验质量

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-030 | 浏览器会话必须使用 Secure、HttpOnly、适当 SameSite 属性的 Cookie 或等效 BFF 方案，并具备 CSRF 防护和明确到期行为。 | P0 |
| TCR-003-031 | 前端必须实施 CSP、输出编码、点击劫持防护、受限 CORS 和第三方脚本治理。 | P0 |
| TCR-003-032 | 外部审片链接必须限时、可撤销且范围最小，访问令牌不得进入引用来源、分析参数、日志或可复制页面内容。 | P0 |
| TCR-003-033 | 登录、项目导航、费用确认、任务监控、审核批准和导出下载必须达到 WCAG 2.2 AA，并可完整使用键盘操作。 | P0 |
| TCR-003-034 | 焦点、验证错误、保存状态、任务进度和审核结论必须可由辅助技术感知；动画必须尊重减少动态效果偏好。 | P0 |
| TCR-003-035 | 普通页面在已确认基线环境中的 P75 应达到 LCP≤2.5s、INP≤200ms、CLS≤0.1。 | P0 |
| TCR-003-036 | 编辑器必须分别定义首次可操作时间、播放启动、拖动响应、丢帧、内存峰值和长任务预算，并以代表性 180 秒项目验证。 | P0 |
| TCR-003-037 | 前端遥测不得采集完整剧本、提示词、媒体签名 URL、令牌或无必要的个人数据。 | P0 |

## 8. 工程与发布门禁

| 编号 | 规范性约束 | 优先级 |
| --- | --- | --- |
| TCR-003-038 | 前端 CI 必须执行冻结依赖安装、格式和静态检查、严格类型检查、单元/组件测试、契约测试、关键 E2E、可访问性检查、安全扫描和生产构建。 | P0 |
| TCR-003-039 | 关键 E2E 必须覆盖登录、建项目、导入、分镜、提交生成、断线恢复、选片、审核、费用确认和导出下载。 | P0 |
| TCR-003-040 | 发布制品必须携带不可变版本，运行时错误与性能数据可回溯到提交和 Source Map；Source Map 不得公开暴露源码。 | P0 |
| TCR-003-041 | 前端发布必须兼容服务端声明的契约窗口，并处理浏览器仍缓存旧 HTML 或静态资源时的版本不一致。 | P0 |
| TCR-003-042 | 核心流程必须在预发布环境使用真实规格媒体完成跨浏览器与网络降级验证。 | P0 |

## 9. 验收标准

- AC-TCR-003-001：状态清单能够把每项前端状态归类并指明权威来源、保存、失效和恢复行为。
- AC-TCR-003-002：并发编辑、断线、重复事件、权限撤销和签名 URL 过期场景不存在静默覆盖或越权读取。
- AC-TCR-003-003：代表性 180 秒项目在支持矩阵内完成上传、预览、镜头编辑、任务恢复、审片和导出闭环。
- AC-TCR-003-004：核心流程通过自动可访问性扫描、全键盘操作和至少一种屏幕阅读器人工测试。
- AC-TCR-003-005：普通页面和编辑器分别满足已接受的性能预算，测量记录包含设备、网络、浏览器、数据规模和 P75 口径。
