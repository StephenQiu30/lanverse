## 1. 模块定位

本模块建立项目级“视觉资产圣经”，让同一角色、场景和道具在多个 Episode 与 Shot 中使用明确的身份、剧情状态和固定版本。它负责把剧本提取候选转化为可维护资产，为每种剧情状态准备可复用参考图，并在改名、禁用或换图前展示对镜头的影响。

模块的核心价值不是保存图片，而是避免四类生产损失：

1. 同名或别名造成身份重复；
2. 角色服装、伤势、年龄及场景时间等剧情状态被混为一张图；
3. 更换“当前图”后旧镜头输入静默漂移；
4. 资产不完整却进入高成本镜头视频生成。

### 1.1 产品目标

1. 用户能从剧本候选快速建立角色、场景和道具的唯一项目身份。
2. 用户能按剧情状态维护描述、出现证据、图片候选和当前参考版本。
3. 下游镜头始终引用固定 Asset、AssetState 与 AssetVersion，而不是名称或会漂移的“最新图”。
4. 用户在换图、改名、禁用和归档前能够理解影响并决定是否升级下游引用。
5. 资产准备度按使用目的给出具体缺失项和下一动作，阻止无效生成但不阻碍草稿整理。

## 2. 范围与非范围

### 2.1 当前范围

- 项目内角色、场景和道具的创建、查看、搜索、修改、归档和恢复。
- 从剧本提取候选创建新资产、关联既有资产、合并或忽略候选。
- 资产别名、标签和来源证据。
- 角色、场景和道具的剧情状态及出现 Episode/NarrativeUnit 证据。
- 不可变的类型化资产版本。
- 上传或通过统一生成能力获得参考图片候选。
- 图片候选预览、比较、星标、淘汰和当前选择。
- 分用途准备度检查：进入分镜、图片生成和镜头视频生成。
- 资产改名、状态禁用、当前版本切换、归档前的影响预览。
- 查看哪些 Episode、ShotSpec 和生成输入引用固定资产版本。
- 对选定下游引用进行显式升级预检；真正修改由引用方模块确认。
- 面向长列表的筛选、批量问题视图和只看阻塞。

### 2.2 明确非范围

- 声音、角色配音、声音克隆、TTS、BGM、音效和任何音频后期。
- 独立服装资产体系；当前服装、伤势、年龄等外观变化作为角色剧情状态表达。
- 通用视觉风格市场；项目视觉方向属于项目设置，必要参考图可作为项目级输入。
- 跨 Project 或跨 Workspace 公共资产库、素材市场和商业授权交易。
- LoRA 训练、模型微调、三维模型、骨骼、动作捕捉和数字人训练。
- 复杂图片编辑、抠图、分层绘制、修图、拼图和画布节点编排。
- 自动保证模型生成结果绝对一致。
- 时间线、多轨剪辑、转场、字幕、视频拼接和整集成片。
- 自动把新版资产批量替换进所有历史镜头。

## 4. 核心用户场景

### CUR-AST-US-001 从剧本候选建立角色

创作者查看剧本提取出的“林夏”，系统同时提示项目中已有别名“夏夏”的角色。用户查看两者来源，决定关联现有角色，避免重复身份。

### CUR-AST-US-002 建立角色剧情状态

创作者为“林夏”建立“日常”和“受伤后”两个状态，分别填写外观变化、出现集和来源叙事单元，为每个状态选择不同参考图。

### CUR-AST-US-003 为场景和道具选择参考图

美术操作者为“林家老宅·夜”和“祖传怀表·破损”状态上传或生成多张图片，比较候选后选择当前图并保留备选。

### CUR-AST-US-004 资源审核门禁

用户准备生成镜头视频，系统指出该镜头引用的“祖传怀表·破损”没有可用当前参考图。用户可直接进入该状态补齐，而不是在视频任务失败后才发现。

### CUR-AST-US-005 换图前理解影响

用户准备把“林夏·日常”的当前参考图从 V2 换成 V3。系统列出引用 V2 的 Episode、Shot 和尚未完成的生成任务；确认后只更新未来默认选择，旧 ShotSpec 保持 V2。

## 7. 详细功能需求

### CUR-AST-FR-001 创建、查找和维护资产身份

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Project active；用户为 owner/editor。 |
| 主流程 | 用户选择角色、场景或道具类型，填写名称和最少身份信息；系统在当前 Project 内提示相似名称/别名；用户确认创建；之后可修改显示名称、别名和标签。 |
| 备选流程 | 用户可以先保存信息不完整的草稿资产，后续补齐；从搜索结果进入已有资产而不创建重复项。 |
| 失败流程 | Project 已归档、名称为空、类型非法、并发变更或用户无权限时拒绝写入并保留表单。 |
| 业务规则 | Asset ID 是身份；名称、别名和标签均不能作为长期引用键；同项目允许经用户确认的同名资产，但必须有可区分信息；资产类型创建后当前阶段不直接转换。 |
| 输入 | Project、资产类型、名称、别名、标签、简要说明。 |
| 输出 | 稳定 Asset、草稿准备状态和建议下一动作。 |
| UI 要求 | 创建过程中展示可能重复项及来源；角色、场景、道具使用不同表单，不用一个无限字段表单掩盖类型差异。 |

### CUR-AST-FR-002 从剧本候选创建、关联或合并资产

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 固定 ScriptVersion 的 ExtractionCandidate 为 pending；用户有写权限。 |
| 主流程 | 用户查看候选名称、类型、描述和所有来源证据；选择创建新资产、关联既有资产、与候选合并、修改后创建或忽略；系统记录人工决定及目标对象。 |
| 备选流程 | 用户可按角色/场景/道具或 Episode 批量处理；批量关联前必须逐项显示匹配对象和冲突。 |
| 失败流程 | 候选已被另一会话决议、目标资产已归档、跨 Project 或下游创建失败时，不显示虚假成功并提供最新状态。 |
| 业务规则 | 同一候选重复提交相同决定不得重复创建；AI 相似度不能自动合并身份；合并候选只合并未决议建议，不删除已存在 Asset 历史。 |
| 输入 | Candidate、决定类型、目标 Asset 或新资产字段、期望候选状态。 |
| 输出 | CandidateDecision、Asset 引用和来源证据关系。 |
| UI 要求 | 证据文本与候选/目标资产并列；“创建”“关联”“合并”“忽略”使用不混淆的动作文案；批量操作显示将影响数量。 |

### CUR-AST-FR-003 管理资产剧情状态与出现证据

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Asset active；用户为 owner/editor。 |
| 主流程 | 用户在 Asset 下创建剧情状态，填写状态名称、变化描述和出现的 Episode/NarrativeUnit 证据；可编辑描述、启用或禁用状态。每个新资产至少有一个基础状态。 |
| 备选流程 | 用户可从剧本候选创建状态；可复制已有状态作为新状态起点，但复制后两者具有独立稳定身份。 |
| 失败流程 | 状态重名无法区分、来源跨 Project、被引用状态准备禁用或并发修订冲突时，必须先展示问题/影响并拒绝静默修改。 |
| 业务规则 | 状态名称不是身份；角色状态表达服装、伤势、年龄、情绪或身份阶段，场景状态表达时间、天气、损毁等，道具状态表达完好、破损、持有人等；状态禁用不删除历史引用。 |
| 输入 | Asset、状态名称、描述、出现证据、期望修订。 |
| 输出 | AssetState、出现矩阵、准备度和影响摘要。 |
| UI 要求 | 资产身份和剧情状态分层展示；支持按 Episode 查看状态出现；不得把多个状态隐藏为同一图片轮播。 |

### CUR-AST-FR-004 创建类型化不可变资产版本

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Asset/AssetState active；用户有写权限。 |
| 主流程 | 用户为固定状态填写类型化规格并保存草稿；补齐后发布新的不可变 AssetVersion；用户可比较版本并选择该状态未来使用的 current version。 |
| 备选流程 | 用户从旧版本创建新修订；未达到某一用途 ready 的版本仍可保存为草稿，且明确列出缺失项。 |
| 失败流程 | 类型字段不合法、跨类型字段、引用其他 Project 对象、期望 current 已变化或依赖媒体不可用时，发布/切换失败且旧 current 不变。 |
| 业务规则 | 角色版本至少表达身份、外观、年龄印象和气质；场景版本至少表达空间、时间/天气、视觉元素和光照；道具版本至少表达外观、材质和使用语境，持有人可选但存在时必须是同 Project 角色。已发布版本不原地编辑。 |
| 输入 | AssetState、类型化规格、来源、可选固定参考媒体、期望 current。 |
| 输出 | AssetVersion、版本差异、当前引用和准备结果。 |
| UI 要求 | 表单标签使用创作语言，不暴露内部字段名；版本比较突出影响画面一致性的变化；发布和设为 current 是两个明确动作。 |

### CUR-AST-FR-005 上传或生成参考图片候选

| 项目 | 需求 |
| --- | --- |
| 前置条件 | AssetState active；基本语义描述足以说明生成/上传用途；用户有写权限和输入图片使用权。 |
| 主流程 | 用户上传图片或基于固定 AssetVersion 发起图片生成；每个成功结果形成独立候选，显示来源、生成时间、输入版本和基础媒体信息。 |
| 备选流程 | 用户可一次生成多个候选、从已有项目媒体选择，或不使用图片输入直接生成；任务失败不影响既有候选。 |
| 失败流程 | 文件不可解码、类型/容量不支持、生成失败、状态未知或输入权利不满足时，不产生可选择的成功候选，并给出恢复动作。 |
| 业务规则 | 候选必须固定生成时使用的 AssetVersion、Prompt/约束摘要和参考媒体；供应商临时结果在被选择前必须成为平台可持续访问的媒体事实；失败候选不得覆盖成功历史。 |
| 输入 | AssetState、固定 AssetVersion、上传图片或生成参数、可选参考媒体、使用权声明。 |
| 输出 | 图片候选、任务状态、来源和可用性。 |
| UI 要求 | 上传与 AI 生成是两个明确入口；生成中、失败、成功和状态未知分开显示；不以页面刷新丢失真实任务。 |

### CUR-AST-FR-006 比较候选并选择当前参考版本

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 同一 AssetState 至少有一个可用图片候选；用户有写权限。 |
| 主流程 | 用户查看候选网格或对比视图，放大检查，星标备选、淘汰不可用候选，并选择一个候选作为该状态的当前参考；系统形成固定选择决定和对应不可变版本。 |
| 备选流程 | 用户可更换当前选择或撤销为未选择；历史选择保留且可回看。 |
| 失败流程 | 候选已不可用、属于其他状态、期望当前选择变化或影响预览过期时，切换失败并展示最新选择。 |
| 业务规则 | 每个 AssetState 同一用途最多一个 current 参考选择，可有多个星标备选；更换 current 不改写旧 ShotSpec；选择必须保留操作者、时间和输入版本。 |
| 输入 | AssetState、Candidate、选择用途、期望当前选择、有效影响预览。 |
| 输出 | SelectionDecision、current AssetVersion、受影响对象和准备度。 |
| UI 要求 | 当前、星标、淘汰和普通候选视觉语义明确；不能只靠卡片顺序表示 current；切换前展示影响数量。 |

### CUR-AST-FR-007 分用途准备度与生成门禁

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户查看 AssetState/Version 或下游请求检查可用性。 |
| 主流程 | 系统分别计算“可用于分镜描述”“可用于图片生成”“可用于镜头视频生成”的 readiness，并返回每一项缺失字段、媒体、使用权、生命周期或依赖问题及下一动作。 |
| 备选流程 | 纯文本完整但无图片时可以进入分镜草稿，但不能被标记为镜头视频生成 ready；依赖临时不可用时返回 unavailable。 |
| 失败流程 | readiness 所需事实无法读取时 fail closed，不回退为 ready；页面不得把 unavailable 显示为缺失 0 项。 |
| 业务规则 | readiness 是按当前事实和用途计算的结果，不是用户可编辑状态；Asset/State 归档或禁用、current 版本缺失、必填规格缺失、参考媒体无效或使用权失效必须阻断对应新生成。 |
| 输入 | AssetState/Version、用途、目标 Episode/Shot 上下文。 |
| 输出 | ready/blocked/unavailable、blocking_reasons、next_actions。 |
| UI 要求 | 一个总状态下展开分用途结果；阻塞原因直接链接到对应字段、图片或声明；不得只显示红点。 |

### CUR-AST-FR-008 高影响变更预览与确认

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户准备改名、禁用状态、切换 current 版本/图片或归档资产，且对象可能有下游使用。 |
| 主流程 | 系统列出受影响 Episode、ShotSpec、Prompt 编译、当前视频选择、非终态任务和历史结果分类；用户查看后确认或取消；执行时再次校验预览仍有效。 |
| 备选流程 | 用户可只完成名称修改并保留旧固定引用；需要升级的镜头在后续所属模块逐项或整批确认。 |
| 失败流程 | 影响依赖 unavailable、对象或引用已变化、存在无法安全处理的非终态任务时，变更不执行并要求刷新预览或处理任务。 |
| 业务规则 | 改名不得改变 Asset ID；禁用和归档不得静默删除引用；切换 current 只改变未来默认入口；高成本任务不得仅因显示名变化被盲目取消或重发。 |
| 输入 | 目标变更、期望对象修订、影响预览标识、确认。 |
| 输出 | 影响清单、已应用变化或零写入冲突、后续待处理项。 |
| UI 要求 | 影响按“当前生产受阻”“需复核”“历史不受影响”分组；确认文案说明不会自动替换历史镜头。 |

### CUR-AST-FR-009 使用关系与显式版本升级

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户可读取 AssetVersion；下游存在固定引用或用户希望升级引用。 |
| 主流程 | 用户查看某个版本被哪些 Episode、ShotSpec 和生成输入使用；选择目标镜头与新版本进行升级预检；引用方模块展示规格差异并由用户确认实际升级。 |
| 备选流程 | 用户可只升级部分镜头，或确认某些镜头继续沿用旧版本并记录理由。 |
| 失败流程 | 任一目标镜头已变化、新版本不 ready、跨 Project 或预检过期时，该次整批升级不执行，返回冲突清单。 |
| 业务规则 | 反向查询不建立第二份使用关系；实际升级创建新的 ShotSpecVersion，不覆盖旧版本；整批模式必须全有或全无，避免用户误以为全部完成。 |
| 输入 | 旧/新 AssetVersion、目标 Shot 集合、期望 ShotSpec/预检。 |
| 输出 | 使用摘要、可升级项、冲突、预计 stale 影响和引用方处理入口。 |
| UI 要求 | 按 Episode 和镜头分组，显示当前引用版本；批量确认前列出将成功和将阻塞的数量。 |

## 10. 状态机与不变式

### 10.1 Asset 生命周期

~~~mermaid
stateDiagram-v2
    [*] --> Active
    Active --> Archived: 明确归档
    Archived --> Active: 明确恢复
    Active --> Deleted: 仅完全空白草稿
~~~

### 10.2 AssetState 生命周期

~~~mermaid
stateDiagram-v2
    [*] --> Enabled
    Enabled --> Disabled: 明确禁用
    Disabled --> Enabled: 明确恢复
~~~

### 10.3 图片候选与选择

生成或上传工作使用 CUR-PLT 的唯一 WorkTask 状态；成功且已登记的候选才成为 Candidate。Candidate 可处于 available、blocked、unavailable，固定输入相对当前目标的 stale 是派生判断，不改写候选媒体。available 候选可以被星标、淘汰或成为 current；更换 current 时旧决定进入历史，不删除旧候选。失败任务不会伪造 failed Candidate。

### 10.4 不变式

1. Asset、AssetState 和 AssetVersion 均使用稳定身份；显示名称不是外键。
2. 已发布 AssetVersion 不可原地覆盖，所谓编辑产生新版本。
3. 每个 AssetState 在同一用途最多一个 current 参考选择，可有多个星标备选。
4. current 版本或图片切换不得改写任何已有 ShotSpecVersion。
5. 资产改名、状态禁用、current 切换和归档不得静默删除下游引用。
6. readiness 按固定版本、用途和当前依赖事实计算，不由用户手工设置。
7. 候选失败或任务 unknown 不得覆盖已有成功候选或 current。
8. 所有下游镜头引用必须固定 Asset、AssetState 和 AssetVersion。
9. 反向使用查询来自引用方事实，资产模块不得维护第二份可编辑使用记录。
10. AI 候选和相似度不得自动合并身份或自动选择 current。

## 13. 异常与恢复

| 异常 | 用户可观察行为 | 恢复要求 |
| --- | --- | --- |
| 重复候选被重复接受 | 不产生第二个 Asset | 返回首次决定和目标对象 |
| 图片上传中断/解码失败 | 不出现可选择的成功候选 | 保留失败原因并允许重传，不影响已有候选 |
| 图片生成失败 | 失败候选与成功历史并存 | 可基于固定输入重新发起，不覆盖 current |
| 图片任务状态未知 | 不显示失败或成功，不盲目重试 | 先对账；无法确认时进入人工处理 |
| current 切换并发冲突 | 旧 current 保持 | 展示最新选择和重新比较入口 |
| 影响预览后引用发生变化 | 高影响变更零写入 | 要求刷新预览，不沿用过期确认 |
| readiness 依赖不可用 | 返回 unavailable | 阻止新生成，保留资产编辑与历史读取 |
| 下游版本批量升级部分冲突 | 整批不执行 | 返回逐项冲突，用户调整范围后重试 |
| 归档时存在非终态任务 | 不自动取消或忽略 | 列出任务及安全处理动作 |
| 媒体后续不可用 | 历史记录仍可审计，预览明确失败 | current 对对应用途转为 blocked，并引导替换 |

## 14. 验收条件

### AC-CUR-AST-001（关联 CUR-AST-FR-001）

Given active Project，When editor 创建名称为“林夏”的角色，Then 获得稳定 Asset 和基础状态；之后改名不改变 Asset ID。

### AC-CUR-AST-002（关联 CUR-AST-FR-001）

Given 项目已有别名“夏夏”的角色，When 用户创建“林夏”，Then 系统展示可能重复项及证据，未经用户确认不得自动合并。

### AC-CUR-AST-003（关联 CUR-AST-FR-002）

Given “林夏”ExtractionCandidate 已关联现有角色，When 相同决定因网络重试再次提交，Then 返回同一 Asset，不创建重复角色。

### AC-CUR-AST-004（关联 CUR-AST-FR-003）

Given 角色“林夏”，When 用户创建“日常”和“受伤后”状态，Then 两个状态具有独立身份、描述、出现证据和 current 版本，名称修改不混淆彼此。

### AC-CUR-AST-005（关联 CUR-AST-FR-004）

Given 已发布角色版本 V1，When 用户修改外观并发布 V2，Then V1 正文和固定媒体保持不变，用户可比较 V1/V2。

### AC-CUR-AST-006（关联 CUR-AST-FR-004）

Given 道具版本引用另一个 Project 的持有人角色，When 用户尝试发布，Then 发布失败并说明关系跨 Project。

### AC-CUR-AST-007（关联 CUR-AST-FR-005）

Given 状态已有一个成功参考图，When 新图片生成失败，Then 原成功候选和 current 均保持，失败结果有独立原因和重试入口。

### AC-CUR-AST-008（关联 CUR-AST-FR-005）

Given 用户上传无法解码但扩展名为 png 的文件，When 媒体检查，Then 不形成 available 候选且不能被选择为 current。

### AC-CUR-AST-009（关联 CUR-AST-FR-006）

Given 同一状态有三个 available 候选，When 用户将 C2 设为 current 并星标 C3，Then current 只有 C2，C3 保持备选，原选择进入历史。

### AC-CUR-AST-010（关联 CUR-AST-FR-006、CUR-AST-FR-008）

Given C1 已被 12 个 ShotSpec 固定引用，When 用户把 current 换为 C2，Then 切换前显示 12 个引用；确认后这 12 个 ShotSpec 仍引用 C1。

### AC-CUR-AST-011（关联 CUR-AST-FR-007）

Given 角色语义完整但没有 current 参考图，When 查询用途，Then“分镜描述”可 ready，“镜头视频生成”blocked，并指向选择参考图动作。

### AC-CUR-AST-012（关联 CUR-AST-FR-007）

Given 使用权依赖暂不可读取，When 查询 readiness，Then 返回 unavailable 并阻止新生成，不得显示 ready 或“无阻塞”。

### AC-CUR-AST-013（关联 CUR-AST-FR-008）

Given 影响预览后另一个用户新增引用，When 原用户确认禁用状态，Then 操作零写入并要求刷新预览。

### AC-CUR-AST-014（关联 CUR-AST-FR-009）

Given 120 个 Shot 中一个规格已并发变化，When 用户请求整批升级到新 AssetVersion，Then 全部不执行并返回冲突镜头；旧引用完整保留。

### AC-CUR-AST-015（关联 CUR-AST-FR-010）

Given 项目有未决议候选、缺图片状态和已 ready 资产，When 用户选择“只看阻塞”，Then 只显示阻止当前制作的对象，并可进入具体修复位置。

### AC-CUR-AST-016（关联 CUR-AST-FR-011）

Given Asset 有任一版本或下游引用，When owner 请求硬删除，Then 删除失败并返回阻塞；归档后历史仍可读但不能用于新镜头。

### 15.1 已决策事项

- 当前资产身份只包含角色、场景和道具；服装先作为角色剧情状态，声音、TTS、BGM 和音效不进入本模块。
- Asset、AssetState 与 AssetVersion 分离；版本不可覆盖，下游必须引用稳定身份、剧情状态和固定版本。
- 生成和上传都形成不可覆盖图片 Candidate；星标不等于 current，切换 current 不静默升级已有 ShotSpec。
- readiness 按 storyboard、image generation、video generation 等具体用途派生，不存在可替代所有用途的单一 ready。
- 高影响禁用、归档、current 切换和批量升级必须先展示引用影响并进行并发复核；历史引用和决定不得删除。

## 16. 术语

| 术语 | 定义 |
| --- | --- |
| Asset | Project 内角色、场景或道具的稳定身份。 |
| AssetState | 资产在特定剧情阶段的稳定状态，例如“受伤后”“夜晚”“已破损”。 |
| AssetVersion | 某状态的一次不可变类型化设定及固定参考输入。 |
| ImageCandidate | 上传或生成得到、尚可被人工选择的独立图片结果。 |
| current 参考版本 | 该状态未来新镜头默认建议使用的固定版本；不改写历史镜头。 |
| 星标备选 | 用户希望保留比较的候选，不等于 current。 |
| readiness | 针对固定版本和具体用途计算的可用性结果。 |
| 使用关系 | ShotSpec 等下游事实对固定资产状态/版本的引用。 |
| 影响预览 | 高影响变更前对下游引用、任务和 stale 结果的只读计算。 |
| 镜头素材包 | 有序逐镜视频及 Manifest；不是拼接后的成片。 |
