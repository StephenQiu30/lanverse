# REQ-22 多候选与选定

| 项 | 内容 |
| --- | --- |
| 需求 | GEN-02 多候选与选定；VID-03 候选预览与选片 |
| 优先级 | MVP |
| 用例 | UC-11、UC-12、UC-13 |
| 页面 | 镜头详情、参考槽位、配音（候选对比组件） |
| 依赖功能 | REQ-21、REQ-31 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

AI 生成结果不稳定，一次生成多个候选、并排对比、选最好的一个，是提高质量与控制成本的主要手段。选定是“候选 → 正式”的唯一通道（PRD-01 §7.3 规则 2）。

### 1.2 用户故事

- 作为**制作者**，我希望一次生成多个候选并排对比，选定最合适的一个，并可随时改选。

### 1.3 范围

包含：候选数量设置、候选展示与对比播放、选定 / 改选、选定历史、冲突处理。适用对象：参考槽位（REQ-15）、关键帧（REQ-26）、片段（REQ-27、REQ-28）、台词音频（REQ-29）。

## 2. 需求分析

### 2.1 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 候选数量 1 至模型 `max_outputs`；超过模型单次上限时拆成多次调用，报价按总数 | GEN-02 |
| R2 | 只能选定审核通过（`passed`）且所属 Operation `completed` 的候选 | CMP-03 |
| R3 | 选定命令携带 `expected_revision`；冲突返回 409 | GEN-02 |
| R4 | 未选中的候选永久保留（受 DES-02 §9 存储策略约束）；可随时改选 | GEN-02 |
| R5 | 选定写选定历史（`shot_selection_log` / `reference_version` / `line_audio_selection` 版本） | 审计 |
| R6 | 改选会使下游过期（关键帧 → 视频；V2 起片段 → 剪辑），改选前提示影响数量 | LIN-01 |
| R7 | 基于镜头旧版本生成的候选可以选定，但显示“基于 v3 生成（当前 v5）”并保留过期标记 | GEN-10 |
| R8 | 选定是业务确认，不能撤销，只能改选 | REQ-05 §4.7 |

### 2.2 异常与边界

两个页面同时选定：后者冲突；审核中候选不可选定，显示“审核中”。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `operation.operation_output` | `media_asset_id`、`moderation_status`、`seq_no` | 候选 |
| `storyboard.shot` | `selected_frame_output_id`、`selected_take_output_id`、`revision` | 当前选定 |
| `storyboard.shot_selection_log` | `slot`、`output_id`、`shot_version_no`、`create_by` | 选定历史 |
| `media.rendition` | `poster`、`proxy_720p` | 对比播放 |

### 3.2 接口

```http
GET /api/shots/{id}/candidates?slot=take
200 { "items": [ { "output_id": "…", "operation_id": "…", "based_on_version_no": 3, "current_version_no": 5,
                   "poster_url": "…", "proxy_url": "…", "duration_ms": 5040, "moderation_status": "passed",
                   "model_key": "…", "create_time": "…", "selected": false } ] }

POST /api/shots/{id}:select-take   { "output_id": "…", "expected_revision": 6 }
200 { "revision": 7, "stale": { "edit_plan": 1 } }
409 revision_conflict     422 input_not_ready（审核未通过）
```

槽位与台词音频的选定接口分别见 REQ-15、REQ-29。

### 3.3 异步与工作流

无；选定为同步命令。

### 3.4 事件与实时

`storyboard.selection_changed.v1` → lineage、realtime、audit。

### 3.5 界面

`CandidateCompare` 组件：2–4 列网格；视频同步播放、逐帧（`← →`）、静音切换；数字键 1–9 聚焦，`S` 选定（REQ-05 §7）；“已选定”角标；改选确认框（影响数量）。

### 3.6 权限与审计

制作者；审计 `shot.frame_selected`、`shot.take_selected`（前后 output）。

### 3.7 非功能要求

对比播放：4 个 720p 代理同时播放不卡顿（代理码率 ≤ 2 Mbps）。

## 4. 验收标准

- Given 4 个视频候选，When 选定第 3 个，Then 镜头的选定视频指向候选 3；刷新后不变；另一个浏览器中基于旧版本改选时提示“内容已被修改”。
- Given 3 个视频候选，When 并排播放并选定其中一个，Then 镜头详情与故事板封面显示该片段为已选定，镜头进度变为“已选定”。
- Given 一个审核未通过的候选，When 尝试选定，Then 被拒绝。

## 5. 测试要点

选定命令并发；改选下游过期；前端同步播放。

## 6. 待确认

无。
