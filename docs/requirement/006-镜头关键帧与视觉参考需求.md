### 1.1 证据与产品决策边界

- **公开页面或已授权只读客户端可见事实：** VibeReels 的单镜头页面把 Prompt 中的图片、视频、音频序号与有序资源卡对应，并允许上传或选择资源；可见页面也展示角色基础图和剧情状态图。
- **公开事实不能证明：** 资源卡是否固定不可变媒体版本、生成候选如何持久化、选择是否有审计历史、图片与视频输入是否始终按同一规则处理。
- **Lanverse 产品推导：** 每次生成或上传的关键帧都是不可变 Candidate；星标只是个人或团队关注标记，不等于当前主选；每个被视频模式要求的关键帧槽位在进入视频生成前必须有且仅有一个显式主选；系统不得以“最新成功图片”自动替代主选。

## 二、模块定位、目标与 KPI

### 2.1 模块定位

本模块把固定镜头规格和资产状态转化为可用于视频生成的视觉输入。它负责关键帧创作说明、图片生成／上传、候选比较、星标、显式主选、首尾帧槽位和有序视觉参考，不负责修改镜头叙事规格，也不负责生成视频。

### 2.2 用户结果

美术或导演应能：

1. 在单镜头上下文中看到固定的画面目标与资产状态；
2. 为开始帧和按需使用的结束帧建立关键帧候选；
3. 上传合法自有图片或生成多个不可变候选；
4. 比较候选，星标关注项，并显式选择每个必需槽位的当前主选；
5. 管理供视频模型参考的有序视觉资源；
6. 在镜头规格或资产变化后准确知道哪些视觉输入需要重审。

### 2.3 KPI 与质量门槛

| 指标 | 当前目标 |
| --- | --- |
| 候选来源可追溯率 | 100% 可用关键帧候选可追溯到固定 ShotSpec、资产版本、视觉说明、生成／上传来源和操作者 |
| 星标误作主选 | 0 次；任何星标变化不改变当前主选 |
| 隐式主选 | 0 次；无显式选择时必须显示“未选择”，不得取最新成功候选 |
| 必需槽位选择完整率 | 进入相应视频生成模式前达到 100% |
| 历史候选保留 | 重生成、重选和取消选择均不覆盖或删除历史候选 |
| 影响可解释率 | 上游变化后 100% 受影响槽位显示 stale／blocked 原因和下一动作 |

## 三、范围与非范围

### 3.1 范围

- 单镜头视觉上下文和固定输入摘要；
- 关键帧创作说明与不可变修订；
- 开始帧、可选结束帧等明确用途槽位；
- 图片生成任务、上传图片和不可变候选；
- 候选预览、并排比较、质量信息、星标和拒绝；
- 每个必需槽位唯一显式主选；
- 有序视觉参考绑定、资源用途和 Prompt 显示别名；
- 关键帧就绪度、过期影响和向视频生成交接。

### 3.2 非范围

- 修改 Shot 的叙事目的、对白、顺序或 ShotSpec；
- 角色、场景、道具资产身份与剧情状态治理；
- 图片精修、局部涂抹、图层编辑、抠图、调色或专业画布；
- 视频生成、视频候选、视频主选和视频导出；
- 裁切、拼接、转码、字幕、音频、时间线和成片；
- 把星标、候选卡高亮、最近生成或最近查看等同当前主选；
- 供应商模型、API、数据库、队列或存储技术的固定实现。

## 四、用户角色与权限意图

| 角色 | 核心任务 | 允许的产品动作 |
| --- | --- | --- |
| 美术／视觉操作员 | 生成、上传和比较关键帧候选 | 编辑视觉说明、提交生成、上传、星标、拒绝、提出主选 |
| 导演／分镜师 | 确认画面是否符合镜头目的 | 查看固定镜头上下文、显式选择或更换主选、管理视觉参考 |
| 制作人／项目负责人 | 控制进入视频生成的条件和风险 | 查看就绪度、批准必要例外、追踪影响 |
| 观察者 | 查看当前关键帧状态 | 只读查看候选、主选、来源和阻塞 |

上述名称是制作 persona，不是新增授权角色。当前 owner/editor 可执行生成、上传、标记、选择和重新确认，viewer 只读；导演/制作人职责若未形成 accepted 业务决定，不得成为隐藏权限门禁。

## 五、关键概念与使用场景

### 5.1 关键帧槽位

| 槽位 | 产品含义 | 当前规则 |
| --- | --- | --- |
| start_frame | 视频开端的主画面 | 图生视频模式下必需；必须显式唯一主选 |
| end_frame | 视频结尾的目标画面 | 仅在所选视频模式要求或用户启用时必需；必须显式唯一主选 |
| visual_reference | 角色、场景、道具、风格或构图参考 | 可有多个并保持顺序；不是关键帧主选 |

未来增加新槽位必须先明确其用途、是否必需、选择基数和下游行为，不得复用“当前图”这一模糊概念。

### 5.2 核心场景

| 场景 | 成功结果 |
| --- | --- |
| 根据镜头规格生成开始帧 | 生成多个不可变候选，用户明确选择一个 start_frame 主选 |
| 使用外部设计稿 | 原始图片验证后登记为候选，来源和权利说明可追溯 |
| 首尾帧控制 | start_frame 与 end_frame 分别选择，二者不会互相覆盖 |
| 比较与收藏 | 用户并排查看候选，星标若干项但当前主选保持不变 |
| 更换主选 | 新选择成为当前主选，旧候选和旧选择历史保留 |
| 上游资产换状态 | 受影响关键帧显示 stale，视频生成前必须重审或显式保留 |

## 六、依赖与交接

### 6.1 前置依赖

- Shot 必须属于有效的 CUR-SBD 当前分镜基线；
- 目标 ShotSpecVersion 必须固定；
- 其角色、场景、道具固定版本与 Project 视觉方向修订／ShotSpec 视觉说明必须可读取；视觉方向不是 CUR-AST 资产类型；
- 图片生成能力不可用时，上传候选路径仍可使用；
- 上传者必须确认素材来源和当前项目用途。

### 6.2 向 CUR-VID 的交接

每次视频生成预检必须获得：

- 固定 Shot 与 ShotSpecVersion；
- 视频模式要求的关键帧槽位；
- 每个必需槽位的显式主选 Candidate 和固定媒体版本；
- 有序视觉参考及其固定媒体版本；
- 关键帧创作说明版本；
- 就绪度、过期状态和输入摘要。

CUR-VID 不得重新推断关键帧主选，也不得在缺少主选时选择最新成功候选。

## 八、详细功能需求

### 8.1 CUR-KFR-FR-001 查看镜头视觉上下文与槽位状态

**目标：** 让用户在生成图片前确认自己正在为哪个固定镜头和用途工作。

**主流程：**

1. 用户从分镜进入目标 Shot；
2. 系统显示当前分镜基线、ShotSpecVersion、画面目标、资产状态、Prompt 意图和预计时长；
3. 系统按用途展示 start_frame、end_frame 和 visual_reference；
4. 每个关键帧槽位显示未生成、已有候选、未选择主选、ready、stale 或 blocked；
5. 用户可查看历史候选和上游变化摘要。

**备选流程：**

- 视频模式尚未选择时，end_frame 显示为可选而非缺失；
- Shot 暂无候选时显示上传和生成两个动作；
- 部分资产参考不可用时，其余上下文仍可读，但整体状态明确 degraded。

**失败与恢复：**

- Shot 不属于当前分镜基线时默认只读并提示切换或重新确认；
- 上游依赖未知时不得显示 ready；
- 刷新后恢复服务端槽位、候选和选择事实。

**业务规则：**

- 页面高亮和最近查看不改变任何选择；
- 候选数量和主选状态必须分别展示；
- 同名资产必须能通过类型、状态和稳定标识区分。

### 8.2 CUR-KFR-FR-002 创建和修订关键帧创作说明

**目标：** 固定本轮图片候选应满足的镜头视觉要求。

**主流程：**

1. 用户选择目标关键帧槽位；
2. 系统以 ShotSpec 和资产状态预填画面、构图、角色动作、表情、光线、风格和禁止项；
3. 用户编辑创作说明；
4. 系统展示本次引用的固定上游版本；
5. 用户保存，形成新的不可变说明版本并成为该槽位当前说明。

**备选流程：**

- start_frame 和 end_frame 可共享基础说明，但各自保存独立差异；
- 用户可从历史说明复制为新版本；
- 用户可保存未完成草稿，但不能用于正式生成。

**失败与恢复：**

- 保存时 ShotSpec 已变化，返回差异并要求基于新版本重审；
- 必需资产引用失效时说明可保存为 blocked，但不能提交生成；
- 并发修改不能最后写入覆盖。

**业务规则：**

- 说明版本不包含生成结果；
- 修改说明不覆盖已生成候选的输入快照；
- 自由文本不得替代固定资产引用。

### 8.3 CUR-KFR-FR-003 提交关键帧图片生成

**目标：** 基于固定说明产生一个或多个可追溯图片候选。

**主流程：**

1. 用户选择槽位、当前说明版本、生成数量和允许的业务参数；
2. 系统预检 ShotSpec、资产媒体、权利、能力可用性和预计消耗；
3. 用户确认后提交；
4. 系统快速返回任务并持续显示可验证状态；
5. 每个成功结果登记为独立不可变 Candidate；
6. 候选默认未星标、未拒绝且未主选。

**备选流程：**

- 用户可为同一槽位多次生成，历史候选持续累积；
- 一次请求部分结果失败时保留成功候选，并允许只重试失败部分；
- 能力不可用时引导到上传，不伪造成功结果。

**失败与恢复：**

- 刷新或重复提交不得造成同一确认被重复计费或登记重复候选；
- 外部结果状态不明时显示 unknown 并先对账，禁止盲目重发；
- 结果到达时输入已变化，候选仍登记但标记 stale。

**业务规则：**

- 生成成功不自动成为主选；
- 预计消耗仅用于本次制作控制，不构成商业计费功能；
- 每个候选必须保留生成说明、固定输入、能力摘要和媒体来源。

### 8.4 CUR-KFR-FR-004 上传外部关键帧候选

**目标：** 允许用户将合法外部设计稿作为同等可追溯的关键帧候选。

**主流程：**

1. 用户选择目标 Shot 和关键帧槽位；
2. 选择图片文件并填写来源／授权说明；
3. 系统验证文件类型、大小、尺寸、完整性和可预览性；
4. 用户确认上传；
5. 系统保留原始文件并登记不可变 Candidate；
6. 候选保持未主选，等待人工选择。

**备选流程：**

- 用户可批量选择多个文件，但每个文件独立得到结果；
- 重复文件可提示已存在，并允许用户回到既有候选；
- 图片包含透明通道时保留原始内容，并明确预览背景。

**失败与恢复：**

- 文件无法安全解码或未通过 CUR-PLT 通用媒体安全校验时拒绝登记；仅超出 proposed 格式／25 MiB／512～8192 像素假设时返回明确测试边界，当前 proposed 路径不登记 valid Candidate，但 CUR-KFR-OQ-004 关闭前不得据此宣称 accepted blocker；
- 上传中断可继续或重试，不产生只有记录没有媒体的可用候选；
- 权利说明缺失时不得进入 ready。

**业务规则：**

- PNG／JPEG／WebP、单文件 25 MiB、宽高 512～8192 像素均为 proposed 样片与验收假设；CUR-KFR-OQ-004 关闭前不得作为 accepted blocker 或已接受的生产硬限制；
- 原始文件不可被后续上传覆盖；
- 上传候选和生成候选在比较与选择规则上平等，但来源必须明确。

### 8.5 CUR-KFR-FR-005 查看和比较不可变候选

**目标：** 帮助用户基于画面质量和输入证据进行选择。

**主流程：**

1. 用户打开目标槽位的候选历史；
2. 系统显示缩略预览、原始尺寸、来源、时间、说明版本、固定资产版本、生成状态和质量备注；
3. 用户选择 2～4 个候选并排比较；
4. 系统同步缩放并允许查看原始图片；
5. 当前主选、星标和拒绝状态以不同文字和图形表达。

**备选流程：**

- 支持按生成批次、来源、星标、拒绝和过期状态筛选；
- 当前没有主选时明确显示“未选择”；
- 原图暂不可访问时显示 unavailable，不使用其他图片代替。

**失败与恢复：**

- 单个候选加载失败不阻塞其他候选；
- 候选元数据与媒体不一致时标记 blocked，并禁止成为主选；
- 关闭比较后不自动保存选择。

**业务规则：**

- Candidate 媒体与输入快照不可替换；
- 比较操作没有业务副作用；
- 当前主选必须有明确标识和选择时间，不以卡片排序推断。

### 8.6 CUR-KFR-FR-006 星标、取消星标和拒绝候选

**目标：** 将“值得关注”和“正式采用”严格分开。

**主流程：**

1. 用户在候选上执行星标或取消星标；
2. 系统保存标记并保持当前主选不变；
3. 用户可拒绝候选并选择结构化原因、可选补充说明；
4. 拒绝后候选仍保留，可在筛选中查看。

**备选流程：**

- 当前主选可同时被星标，两个状态分别显示；
- 用户可撤销拒绝，形成新的决议而非删除旧记录；
- 多个候选可同时星标。

**失败与恢复：**

- 标记保存失败时界面恢复服务端状态并提示重试；
- 已不可用候选仍可查看历史标记，但不能新选为主选；
- 并发标记以最新有效动作展示，同时保留决定历史。

**业务规则：**

- 星标数量不限于 1；
- 星标、取消星标、拒绝都不改变主选；
- 拒绝不是删除，不能破坏历史生成或既有导出追溯。

### 8.7 CUR-KFR-FR-007 为必需槽位显式选择唯一主选

**目标：** 为视频生成建立明确、唯一且可追溯的关键帧输入。

**主流程：**

1. 用户预览目标 Candidate；
2. 选择“设为当前 start_frame”或“设为当前 end_frame”；
3. 系统展示被替换的旧主选及受影响的未完成视频请求；
4. 用户确认；
5. 系统验证 Candidate 属于目标 Shot／槽位、媒体可用、输入未过期；
6. 新 Candidate 成为该槽位唯一当前主选，旧选择保留为历史。

**备选流程：**

- 用户可取消主选，槽位进入 missing_selection；
- 同一 Candidate 若满足用途要求，可由用户分别选入多个槽位，但每个槽位独立记录决定；
- 更换主选后，不自动取消已完成的视频候选，只标记其输入与当前选择不同。

**失败与恢复：**

- Candidate 过期、损坏、跨 Shot 或跨项目时拒绝选择；
- 选择时 ShotSpec 已变化，返回版本冲突并要求重审；
- 重复选择同一 Candidate 返回当前结果，不产生重复状态。

**业务规则：**

- 每个槽位在制作中允许 0 或 1 个当前主选；进入要求该槽位的视频生成前必须正好为 1；
- 主选只能通过显式用户动作改变；
- 系统不得以最新成功、星标、最高分或最近查看候选自动补主选。

### 8.8 CUR-KFR-FR-008 管理有序视觉参考

**目标：** 让用户明确视频生成时还应参考哪些资产或图片。

**主流程：**

1. 用户在镜头中添加角色、场景、道具、风格或构图参考；
2. 每个引用选择固定资产／媒体版本和用途；
3. 用户调整参考顺序；
4. 系统展示对应的可读别名，并在 Prompt 预览中按同类型顺序编号；
5. 用户保存新的参考绑定修订。

**备选流程：**

- 可从资产库、关键帧候选或已授权上传媒体中选择；
- 可为同一资产添加不同状态版本，但必须区分用途；
- 移除引用前展示受影响的关键帧说明和未完成视频请求。

**失败与恢复：**

- 引用媒体不可用、无权利或跨 Workspace 时拒绝进入 ready；
- 顺序并发变化时返回冲突，不静默重编号并覆盖；
- 显示别名变化不改变固定媒体引用。

**业务规则：**

- @图片N 等序号只是 Prompt 和 UI 显示别名；
- 重排参考不改变媒体身份；
- visual_reference 可以有多个，不存在“唯一主选”；其顺序和用途必须固定到视频请求。

### 8.9 CUR-KFR-FR-009 计算就绪度、处理过期并交接视频生成

**目标：** 只让完整、明确且未漂移的视觉输入进入视频生成。

**主流程：**

1. 用户选择目标视频生成模式；
2. 系统根据模式确定必需关键帧槽位；
3. 系统检查当前主选、媒体可用性、权利、ShotSpec、资产版本和视觉参考；
4. 返回 ready、stale、blocked 或 incomplete 及完整原因；
5. ready 时形成固定视觉输入摘要，供 CUR-VID 预检使用。

**备选流程：**

- 文本生成视频模式可不要求 start_frame，但仍必须显式选择该模式；
- 仅首帧模式不要求 end_frame；
- 上游变化后用户可重选、重新生成，或在查看差异后显式确认继续使用旧候选；重新确认必须追加绑定当前输入摘要、操作者和理由的决定。

**失败与恢复：**

- 任一必需槽位无主选时必须阻断，不得使用最新成功候选；
- 依赖状态未知时返回 unavailable，不得默认为 ready；
- 交接前输入发生变化时旧摘要失效，CUR-VID 必须重新预检。

**业务规则：**

- 就绪度是基于选定视频模式和固定版本的派生结果；
- 确认继续使用旧候选必须保存理由，并不改变该候选的历史输入；
- 视觉输入摘要只描述事实，不创建视频任务。

## 九、实体、状态机与不变式

### 9.1 产品实体

| ID | 实体 | 产品含义 |
| --- | --- | --- |
| CUR-KFR-ENT-001 | KeyframeSlot | Shot 下具有明确用途和基数的关键帧槽位 |
| CUR-KFR-ENT-002 | KeyframeBriefVersion | 某槽位一次不可变创作说明 |
| CUR-KFR-ENT-003 | KeyframeGenerationRun | 固定说明与输入的一次图片生成请求 |
| CUR-KFR-ENT-004 | KeyframeCandidate | 一次生成或上传得到的不可变图片候选 |
| CUR-KFR-ENT-005 | KeyframeCandidateDecision | 星标、拒绝、撤销等追加式人工决定 |
| CUR-KFR-ENT-006 | KeyframeSelection | 某槽位的显式主选、替换或取消历史 |
| CUR-KFR-ENT-007 | VisualReferenceRevision | 有序固定视觉参考及用途的不可变修订 |

### 9.2 状态

- 生成工作引用 CUR-PLT 的唯一 WorkTask/ExecutionAttempt 状态；本模块只显示 `queued → running → waiting_external → succeeded／failed／cancelled／unknown` 的业务投影，不拥有或扩展第二套状态机。
- Candidate 媒体：valid、blocked、unavailable；媒体与原始输入快照不原地变更。`stale` 是 Candidate 固定输入相对当前目标输入的派生判断，不是对媒体事实的改写。
- 人工标记：unmarked ↔ starred；active ↔ rejected，二者均独立于主选。
- 槽位选择：missing_selection → selected → needs_reconfirmation → selected；最后一步必须追加绑定当前输入摘要、操作者和理由的重新确认。更换主选产生 superseded 历史，取消回到 missing_selection。
- 就绪度：incomplete、ready、stale、blocked、unavailable。

### 9.3 核心不变式

1. 生成或上传候选一旦登记，不得替换原始媒体或输入快照。
2. 星标不等于主选；拒绝不等于删除。
3. 每个关键帧槽位同时至多一个当前主选。
4. 必需槽位进入视频生成前必须恰有一个显式主选。
5. 不得使用最新成功候选、最高分或星标自动补主选。
6. start_frame、end_frame 和 visual_reference 的用途与选择规则彼此独立。
7. 上游变化不删除候选；它使输入匹配判断变为 stale、选择进入 needs_reconfirmation、就绪度进入 stale。只有显式重新确认或重选后才能恢复 ready。
8. 历史视频请求始终解释其当时固定的关键帧和视觉参考。

- 实际类型识别、安全解码、大小与 hash 校验、媒体隔离、完整性和受控访问统一由 CUR-PLT-FR-004／CUR-PLT-IF-005／CUR-PLT-IF-006 提供；本模块不得建立第二套通用媒体安全判定；
- 对关键帧用途，PNG／JPEG／WebP、每文件 25 MiB、宽高 512～8192 像素均为 proposed 样片与验收假设；CUR-KFR-OQ-004 关闭前不得作为 accepted blocker 或已接受的生产硬限制；
- 本模块只增加关键帧用途约束：候选必须绑定 Shot、槽位、来源和固定输入，能够作为单张关键帧预览，并展示实际尺寸、格式、文件大小和透明通道信息；
- 原始上传文件必须保留，不以压缩预览替代；文件名仅用于显示，不作为 Candidate 身份；
- 通用媒体校验未通过的 MediaArtifact 不得成为 valid KeyframeCandidate。

以上为产品输入契约，不固定媒体库、对象存储或图像处理技术。

### 14.1 已决策事项

- 生成和上传都形成不可覆盖 Candidate；比较、播放、星标或生成时间都不得自动改变主选。
- 每个关键帧槽位同时至多一个显式主选；visual_reference 是有序多项引用，不套用唯一主选规则。
- `stale` 是固定输入相对当前目标的派生判断；Selection 必须经过 `needs_reconfirmation → selected` 的追加式重新确认后才能恢复 ready。
- 长任务、实际尝试和媒体安全分别引用 CUR-PLT 的唯一事实，本模块不复制第二套状态或校验。

## 十五、术语

| 术语 | 定义 |
| --- | --- |
| KeyframeSlot | 具有明确视频用途和选择基数的关键帧位置 |
| KeyframeBriefVersion | 固定某次关键帧创作要求的不可变说明 |
| KeyframeCandidate | 一次生成或上传得到、不可被覆盖的图片候选 |
| starred | 值得关注的标记，可同时存在多个，不代表采用 |
| selected／主选 | 用户为一个关键帧槽位显式指定的唯一当前候选 |
| visual_reference | 有序的补充视觉输入，不适用唯一主选规则 |
| missing_selection | 有候选但没有显式主选，或根本没有候选 |
