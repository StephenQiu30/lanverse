# 非功能需求规格与验收

范围由[功能需求总表](01-功能需求总表.md)和[交互需求](05-界面与交互需求.md)定义。以下记录待验证目标与方法；页面已实现不代表真实业务完成，文档检查、旧接口测试与 mock 交互均不能替代真实认证、持久化、供应商及部署验收。

## 功能验收与关键反例

| 业务模块       | 必须验证的结果                                                                     | 不可接受的反例                                                          |
| -------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 首页           | 当前三种画幅与四种风格可保存；txt/md/docx导入真实处理；空白项目和复制可恢复        | 因旧接口不支持而去掉1:1/胶片/md；本地数组复制当成功                     |
| 画布           | 节点位置可刷新恢复；适应视口不改布局；生成候选与建议结果真实                       | 沿用mock适应画布重置节点；自动带入旧导演台/深度/时间轴                  |
| 镜头与故事板   | 输入版本不可变，历史只读，候选需明确选定；下游引用失效可见；批量时长原子保存       | 新生成覆盖选定；一项冲突却部分改参数；为省表丢掉页面明确的版本/失效需求 |

## 非功能条件

| 维度         | 当前要求                                                                        | 验证方式                                                         |
| ------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 权限         | 当前用户/项目范围服务端检查；管理接口限admin；知道UUID不代表有权                | 两个制作者与一个管理员交叉读取/写入/预览；检查缓存切换隔离       |
| 密码与凭据   | 密码只存hash；会话只存token hash；供应商密钥加密且仅服务端使用；日志/CSV无秘密  | 使用合成标记检查响应、生成包、日志与导出，不读取真实凭据         |
| 并发与幂等   | 普通编辑CAS；生成/复制/导入同键同输入只创建一个任务；异输入409                  | 并发保存、重复提交、丢响应、服务重启；刷新核真实状态             |
| 异步与费用   | queued/running/成功/失败/unknown/manual可区分；未知先核对；真实收费需执行前确认 | 模拟供应商超时/已执行丢响应；禁止直接重提；实际费用另外验证      |
| 数据保留     | 版本与审计只追加；回收素材保留引用；新设计不授权删除旧用户数据                  | FK/不可变/引用测试；对象存储与数据库故障恢复独立验证             |
| 字段真实性   | 未知/null/真实0/未接入分开；媒体尺寸时长和审核来自真实结果                      | 与固定事实集和实际文件比对；不接受fixture或扩展名充当证据        |
| 加载与数据量 | 列表只摘要；详情/历史/候选/原件按需；媒体缩略图优先                             | Network核响应字段、字节和请求；慢网/空/大图/长文场景             |
| 交互可达     | 控件有名称，错误关联输入；菜单/对话框键盘可操作，关闭返回焦点                   | 键盘、读屏、长错误文案逐页检查                                   |
| 响应式与视觉 | 1440设计宽、1280桌面、390手机检查；宽表局部滚动，关键操作可达                   | 当前Figma节点与截图对照；浅/深主题和状态检查；lint不证明视觉一致 |
| 可观测       | 任务/请求有安全request_id；统计附as_of，缺指标明确不可用                        | 人工构造局部故障，检查部分降级及排障上下文                       |

## 性能与容量

先由当前数据消费方式限制单次响应：素材40项；其他列表的20/40、候选6、历史10是新设计建议，不继承旧接口限额。图表最多建议366个时间桶，超出按周/月聚合。它们是待评审上限，不是已测得能力。

实现后记录设备/网络/数据集、冷热缓存、请求数、字节、接口P50/P95、LCP/INP/CLS与内存。先消除请求瀑布、重复取数和全量媒体；依据测量再决定缓存、虚拟化或汇总表。当前没有足够使用规模证据来承诺旧方案中的大项目容量、可用率或复杂集群。

## 完成标准与证据层次

1. 文档：当前页面/控件对应齐全，字段/接口/表可互相追踪，链接与实际阅读正确；历史不在当前导航/搜索。
2. 实现：每项功能需求给出实际合同、领域/数据库测试、真实浏览器结果和失败恢复。
3. 外部条件：真实供应商、媒体字节、权限/费用、性能和设备验证分别记录；未执行项明确未验收。

本次文档检查不能填充第二、三层证据；旧测试通过也不能替代新合同的验收。
