# F26 自动粗剪与时间线

| 项 | 内容 |
| --- | --- |
| 需求 | EDT-01 自动粗剪；EDT-02 时间线编辑 |
| 优先级 | MVP |
| 用例 | UC-14 |
| 页面 | 剪辑 |
| 依赖功能 | F17、F24、F25、F29 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

镜头片段、对白音频、字幕要按顺序组装成一集。自动粗剪给出第一版，制作者在简化的时间线上调顺序、入出点与对白位置（0101 §12：时间线只做顺序、入出点、对白与字幕）。

### 1.2 用户故事

- 作为**制作者**，我希望系统按分镜顺序自动排好片段与对白，再在时间线上调整并预览。

### 1.3 范围

包含：自动粗剪、视频轨排序与裁剪、对白轨位置、字幕轨（F25）、保存版本、浏览器内预览。不包含：转场（V1）、BGM / 音效（V1）、多轨视频叠加、调色。

## 2. 需求分析

### 2.1 业务流程

```text
自动粗剪：按镜头顺序放置各镜选定片段（入点 0，出点 = 镜头时长与片段时长的较小值）
  → 对白：按台词所在镜头放在该片段起点 + 偏移（多句依次排列，间隔 200 ms）
  → 片段时长不足以容纳对白：提示“对白超出片段 x 秒”
  → 缺少选定片段的镜头放占位（显示“缺失”，时长 = 镜头时长）
→ 时间线编辑（拖动排序、拖边裁剪、对白拖动、字幕微调）→ 保存 = 新版本
→ 预览：浏览器按播放清单顺序播放代理视频与音频
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 剪辑计划只引用选定对象（镜头 → 选定片段，台词 → 选定音频），保存时冻结为具体 `media_asset_id` | 渲染可复现 |
| R2 | 每次保存产生新版本；版本不可变 | EDT-02 |
| R3 | 上游改选（片段、音频）后，当前剪辑计划中对应条目标记过期；用户可“更新到最新选定”一键刷新（产生新版本） | LIN-01 |
| R4 | 自动粗剪可在已有计划上重新执行，覆盖前提示（产生新版本，旧版本保留） | 防误操作 |
| R5 | 预览不渲染成片：前端按时间线驱动 `<video>` / Web Audio 播放代理文件 | 快速反馈 |
| R6 | 时间精度 1 毫秒存储，界面按帧（项目帧率 25 fps）吸附 | 剪辑习惯 |

### 2.3 状态

剪辑计划：草稿 vN → 保存 vN+1；可渲染状态由 F27 校验决定。

### 2.4 异常与边界

- 片段被逻辑删除或审核撤回：条目标记“不可用”，渲染阻止。
- 大时间线（150 片段 + 300 对白）：前端虚拟化渲染时间线条目。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `edit.edit_plan` | `episode_id`、`current_version_no`、`revision` | 每集一个 |
| `edit.edit_plan_version` | `version_no`、`origin`、`total_duration_ms`、`validation` | 版本 |
| `edit.timeline_item` | `track`、`seq_no`、`start_ms`、`duration_ms`、`shot_id`、`line_key`、`media_asset_id`、`source_in_ms`、`source_out_ms`、`text` | 条目与冻结引用 |
| `lineage.dependency` | 剪辑版本 → 镜头选定 / 台词音频选定 | 过期 |

### 3.2 接口

```http
POST /api/v1/episodes/{eid}/edit-plan:auto          { "expected_revision": 2 }
GET  /api/v1/episodes/{eid}/edit-plan
200 { "version_no": 3, "revision": 4, "total_duration_ms": 92000,
      "tracks": { "video": [ { "id": "…", "shot_id": "…", "shot_no": "1-1", "start_ms": 0, "duration_ms": 4000, "source_in_ms": 0, "source_out_ms": 4000,
                               "media_asset_id": "…", "state": { "stale": false, "missing": false } } ],
                  "dialogue": [ { "line_key": "…", "start_ms": 300, "duration_ms": 1830, "media_asset_id": "…" } ],
                  "subtitle": [ { "line_key": "…", "start_ms": 300, "duration_ms": 1830, "text": "你怎么来了？" } ] },
      "warnings": [ { "code": "dialogue_overflow", "shot_no": "1-3", "overflow_ms": 700 } ] }
POST /api/v1/episodes/{eid}/edit-plan/versions      { "expected_revision": 4, "tracks": { … } }
POST /api/v1/episodes/{eid}/edit-plan:refresh-selections   → 更新到最新选定（新版本）
GET  /api/v1/episodes/{eid}/edit-plan/preview       → 播放清单（代理 URL，1 小时有效）
```

### 3.3 异步与工作流

无（保存为同步命令；自动粗剪在 API 内计算，150 镜头 < 200 ms）。

### 3.4 事件与实时

`edit.plan_version_created.v1`；SSE `edit_plan.updated`。

### 3.5 界面

预览播放器（上）+ 时间线（下，三轨）；条目拖拽（dnd-kit）、边缘裁剪；缺失 / 过期标记；“自动粗剪”“更新到最新选定”“保存”“渲染前校验”。

### 3.6 权限与审计

制作者。

### 3.7 非功能要求

预览启动 ≤ 2 秒；时间线交互 ≥ 50 fps（150 条目）。

## 4. 验收标准

- Given 30 个镜头中 28 个已选定视频，When 自动粗剪，Then 时间线含 28 个片段，另 2 个位置显示“缺失”。
- Given 片段 5 的入点从 0 秒改为 1.2 秒，When 保存并预览，Then 预览从 1.2 秒开始播放该片段，剪辑计划版本加 1。
- Given 镜头 7 改选片段，When 打开剪辑，Then 镜头 7 条目显示过期，点击“更新到最新选定”后使用新片段。

## 5. 测试要点

自动粗剪算法（对白溢出、缺失占位）；时间线保存校验（重叠、负时长）；预览同步。
