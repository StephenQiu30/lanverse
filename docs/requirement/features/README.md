# 功能需求说明（按功能特性）

每个文件描述**一个完整的功能特性**：它要满足哪些需求、为什么这样定规则，以及实现它**背后还需要什么**（数据表、接口、工作流、事件、界面、权限、非功能要求、测试点）。

- 需求编号（如 `VID-04`）不变，是跨文档引用的唯一标识；一个功能文件包含一条或多条需求。
- [0201 功能需求规格](../0201-功能需求规格.md) 是总表与索引；需求正文以本目录的功能文件为准。
- 全局规范仍在集中文档：数据库约定与全量表结构见 [0302](../../design/0302-领域与数据模型.md)，接口约定、错误码与全量端点见 [0303](../../design/0303-接口设计.md)。功能文件写本功能用到哪些表和接口、为什么需要、关键字段与请求响应，并链接回集中文档。
- 两处不一致时：需求以功能文件为准，表结构与接口签名以 0302 / 0303 为准；发现不一致须同时修正。

## 文件模板

```markdown
# Fnn 功能名

| 项 | 内容 |
| --- | --- |
| 需求 | 需求编号列表 |
| 优先级 | MVP / V1 / V2 |
| 用例 | UC-xx（0203） |
| 页面 | 0205 中的页面 |
| 依赖功能 | Fxx |
| 状态 | 草案 / 已接受 / 已实施 |

## 1. 需求说明
### 1.1 背景与目标      为什么需要这个功能，解决什么问题
### 1.2 用户故事        作为…我希望…以便…
### 1.3 范围            包含 / 不包含

## 2. 需求分析
### 2.1 业务流程        主流程与分支
### 2.2 业务规则        编号的规则（R1、R2…）及理由
### 2.3 状态            本功能涉及的状态与流转
### 2.4 异常与边界      失败、冲突、极限输入时的行为
### 2.5 前置与依赖      依赖哪些功能、数据、外部能力

## 3. 实现所需
### 3.1 数据            用到的表与关键字段，为什么需要（链接 0302）
### 3.2 接口            端点、关键请求与响应、错误码（链接 0303）
### 3.3 异步与工作流    Temporal 工作流、Activity、重试与超时
### 3.4 事件与实时      发布的领域事件、SSE 事件
### 3.5 界面            页面、组件、交互要点（链接 0205）
### 3.6 权限与审计      谁能做、写哪些审计
### 3.7 非功能要求      本功能适用的 0202 条目与具体目标

## 4. 验收标准          Given / When / Then
## 5. 测试要点          单元、集成、端到端、故障注入
## 6. 待确认
```
