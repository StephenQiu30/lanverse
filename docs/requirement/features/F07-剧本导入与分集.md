# F07 剧本导入与分集

| 项 | 内容 |
| --- | --- |
| 需求 | SCR-01 导入整部剧；SCR-02 分集识别与调整 |
| 优先级 | MVP |
| 用例 | UC-05 |
| 页面 | 剧本 |
| 依赖功能 | F05、F16（AI 分集需报价确认）、F28 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

用户已有成品剧本（P7），作品从单片到 60 集以上的竖屏短剧（P6）。跨集一致性依赖全剧信息，所以要一次导入整部剧，并准确切成集，作为后续逐集生产的单位。

### 1.2 用户故事

- 作为**制作者**，我希望一次导入整部剧（单个文件或按集的多个文件），以便平台掌握全剧信息。
- 作为**制作者**，我希望系统自动识别集边界，并允许我合并、拆分、重命名集后确认。

### 1.3 范围

- 包含：docx / txt 导入、编码识别、规范化、内容指纹去重、原文件保存、多文件排序、规则分集与 AI 分集、人工调整、确认。
- 不包含：PDF / Final Draft / Fountain 格式（待定）、在线编辑剧本原文、剧本修订对比（V1，F35）。

## 2. 需求分析

### 2.1 业务流程

```text
选择文件（1..n）→ 前端校验格式与大小 → 上传到对象存储（F28 上传流程）→ 勾选“我确认拥有该剧本的使用权”
→ POST 导入 → ScriptImportWorkflow：
     1. 逐文件抽取文本（docx → 段落文本；txt → 编码识别 UTF-8 / GBK / GB18030）
     2. 规范化（统一换行、全半角标点保留、去除页眉页脚与多余空行）
     3. 多文件按文件名集号排序拼接（插入“第 N 集”标记）
     4. 计算内容指纹；与已有版本相同 → 结束并提示
     5. 保存 script_version（全文写对象存储）
     6. 分集：先按规则（“第 X 集”“EP X”等标记）；规则未命中或结果异常时调用 split_episodes Skill
     7. 生成 episode 候选（split_status = candidate）
→ 用户在分集界面查看每集起止原文、字数；合并 / 拆分 / 重命名 / 调整顺序 → 确认 → split_status = confirmed
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 支持 docx、txt；单文件 ≤ 20 MB；一次导入总字数 ≤ 150 万字；最多 200 个文件 | SCR-01；覆盖 100 集以上 |
| R2 | 原始文件永久保存（随项目），可下载 | 版权与追溯（CMP-04） |
| R3 | 导入须确认拥有使用权，记录导入人与时间 | CMP-04 |
| R4 | 规范化文本内容指纹相同视为同一版本，不重复创建 | SCR-01 |
| R5 | 多文件导入时按文件名中的集号排序（支持“第12集”“EP12”“12.”），无法识别集号的按文件名自然排序，用户可调整 | 常见交付习惯 |
| R6 | 分集结果为候选，必须由用户确认后才能开始逐集解析 | 分集错误会影响全部下游 |
| R7 | 每集记录在规范化全文中的起止偏移；集与集不重叠、不遗漏（首集之前的“人物表 / 大纲”作为第 0 部分，可选择是否作为全剧设定参考） | 可追溯 |
| R8 | 规则分集免费；需要 LLM 分集时，按 GEN-11 先报价并由用户确认（导入界面直接显示“AI 分集预估 ¥X”，一次确认） | GEN-11 无例外 |
| R9 | 已确认的分集可以重新调整，但若已有集解析已确认，调整会使受影响集的解析失效，需要二次确认提示 | 防止误操作 |

### 2.3 状态

```text
导入任务：uploading → importing → done | duplicate | failed（逐文件结果）
集：split_status candidate → confirmed
```

### 2.4 异常与边界

- 部分文件损坏 / 编码无法识别：逐文件报告原因，其余照常导入（至少 1 个成功才产生版本）。
- 全文无任何集标记且 LLM 分集失败：整部作为 1 集，提示用户手动拆分。
- 超大 docx（含图片）：只抽文本，忽略图片，提示“已忽略 N 张图片”。
- 重复导入相同内容：返回 `duplicate_content` 与已有版本 ID。

### 2.5 前置与依赖

- 媒体上传（F28）用于原始文件。
- Harness Skill `split_episodes`（0305）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `script.script_source` | `file_name`、`media_asset_id`、`rights_confirmed` | 原文件与版权声明 |
| `script.script_version` | `content_hash`（项目内唯一）、`text_object_key`、`char_count`、`encoding_detected`、`source_ids` | 不可变全文版本、去重 |
| `script.episode` | `seq_no`、`title`、`span_start`、`span_end`、`split_status` | 集边界与确认状态 |
| `operation.operation` | `target_type = episode_split` | 分集 LLM 调用的记录与计费 |
| 对象存储 `projects/{pid}/script/{version_id}.txt` | 规范化全文 | 大文本不入库（0302 DM1） |

### 3.2 接口

```http
POST /api/v1/projects/{pid}/script-imports
{ "source_asset_ids": ["…", "…"], "rights_confirmed": true, "order": ["…", "…"] }
202 { "import_id": "…", "workflow_id": "script-import/…", "status": "importing" }

GET /api/v1/projects/{pid}/script-imports/{import_id}
200 { "status": "done", "script_version_id": "…", "files": [ { "asset_id": "…", "file_name": "第1集.docx", "result": "ok", "chars": 5210 },
                                                            { "asset_id": "…", "file_name": "第7集.docx", "result": "failed", "reason": "file_corrupted" } ] }

GET /api/v1/projects/{pid}/episodes?script_version_id=
200 { "items": [ { "id": "…", "seq_no": 1, "title": "初遇", "span_start": 0, "span_end": 5210, "chars": 5210,
                   "split_status": "candidate", "preview_head": "…", "preview_tail": "…" } ] }

POST /api/v1/projects/{pid}/episodes/split:confirm
{ "script_version_id": "…", "episodes": [ { "seq_no": 1, "title": "初遇", "span_start": 0, "span_end": 5210 }, … ],
  "expected_revision": 3 }
200 { "confirmed": 61 }      422 validation_failed（重叠 / 遗漏 / 越界）
```

`expected_revision` 使用分集集合的版本号（存于 `script_version` 对应的分集计数器，Redis 不可用时以数据库行锁为准）。

### 3.3 异步与工作流

`ScriptImportWorkflow`（Workflow ID `script-import/{import_id}`）：

| 步骤 | 队列 | 超时 / 重试 |
| --- | --- | --- |
| `ExtractText`（docx / txt 解析、编码识别） | `media` | 2 分钟 / 3 次 |
| `NormalizeAndHash` | `media` | 1 分钟 / 3 次 |
| `SaveScriptVersion` | `flow` | 30 秒 / 5 次 |
| `SplitByRules` | `flow` | 30 秒 |
| 等待报价确认 Signal（按需） | — | 24 小时未确认则结束，候选保留为规则分集结果 |
| `llm.run_skill(split_episodes)`（按需） | `agent` | 5 分钟 / 2 次 |
| `SaveEpisodeCandidates` | `flow` | 30 秒 / 5 次 |

### 3.4 事件与实时

`script.version_imported.v1`；SSE `episode.updated`（分集完成）。

### 3.5 界面

- 剧本页：导入按钮 → 多文件拖拽区（显示每个文件的校验结果与顺序）→ 版权确认复选框。
- 分集编辑器：左侧集列表（集号、标题、字数、首尾预览），右侧原文；在原文中点击“在此处拆分”、在列表中“与下一集合并”、编辑标题；顶部“确认分集”。

### 3.6 权限与审计

制作者。审计：`script.imported`、`episode.split_confirmed`。

### 3.7 非功能要求

PERF-05（60 集约 60 万字导入与分集 ≤ 5 分钟）；AIQ（分集准确率：P0 样例 100% 正确，否则规则优先）。

## 4. 验收标准

- Given 一个 60 集的 docx 剧本，When 导入，Then 生成一个剧本版本，原文件可下载，分集候选为 60 集且每集起止与原文一致。
- Given 再次导入内容完全相同的文件，When 导入完成，Then 系统提示“与已有版本相同”，不新增版本。
- Given 同时导入 3 个文件，其中 1 个损坏，When 导入，Then 另外 2 个成功导入，损坏文件显示“文件无法解析”。
- Given 系统将第 12、13 集识别为一集，When 用户在分界处拆分并确认，Then 集列表增加一集，拆分位置与原文一致。
- Given 未勾选版权确认，When 提交导入，Then 被拒绝。

## 5. 测试要点

- 单元：编码识别（UTF-8、GBK、GB18030、带 BOM）；集号识别正则；边界校验（重叠、遗漏）。
- 评测：10 部样例剧本的分集准确率（0503）。
- 集成：导入工作流中断续跑；重复导入。
