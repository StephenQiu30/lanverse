# F31 站内通知

| 项 | 内容 |
| --- | --- |
| 需求 | NTF-01 站内通知 |
| 优先级 | MVP |
| 用例 | UC-17 |
| 页面 | 应用外壳 · 通知中心 |
| 依赖功能 | F06、F18、F19、F27 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

批量生成、渲染动辄数分钟到数十分钟，用户不会一直盯着页面。需要在关键结果与异常发生时提醒，并一键跳转。

### 1.2 用户故事

- 作为**制作者**，我希望在批量任务完成、失败、进入待人工核对、成片完成，以及预算余额不足时收到通知，点击直达。

### 1.3 范围

包含：站内通知、未读计数、已读、跳转、去重。不包含：邮件、短信、IM 推送（后续按需作为新消费者接入）、通知偏好设置（V1）。

## 2. 需求分析

### 2.1 通知类型

| 类型 | 触发 | 接收人 | 去重键 |
| --- | --- | --- | --- |
| `batch_finished` | 批次结束 | 批次确认人 | `batch:{id}` |
| `operation_failed` | 非批次的单个任务失败 | 确认人 | `op:{id}` |
| `operation_manual` | 任务进入待人工核对 | 全部管理员 + 确认人 | `manual:{id}` |
| `delivery_ready` / `delivery_failed` | 渲染完成 / 失败 | 发起人 | `delivery:{id}` |
| `budget_low` / `budget_overrun` | 可用余额跨越 20% / 超支 | 项目相关用户（MVP：最近 7 天在该项目有操作的用户）+ 管理员 | `budget:{pid}:{阈值}:{日期}` |
| `import_finished` | 剧本导入 / 解析批次完成 | 发起人 | `import:{id}` |

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 同一批次只发一条汇总通知 | NTF-01 |
| R2 | 通知保留 90 天 | 控制数据量 |
| R3 | 点击通知跳转到对象（批次、任务、成片、预算），对象已删除时提示 | NTF-01 |

## 3. 实现所需

### 3.1 数据

`notify.notification`（`user_id`、`kind`、`title`、`body`、`link`、`dedupe_key`（部分唯一）、`read_at`）。

### 3.2 接口

```http
GET  /api/v1/notifications?unread=true&limit=20
200 { "items": [ { "id": "…", "kind": "batch_finished", "title": "第 1 集第 3 场视频生成完成", "body": "成功 18，失败 2",
                   "link": { "type": "batch", "id": "…", "project_id": "…" }, "read": false, "create_time": "…" } ], "unread_count": 3 }
POST /api/v1/notifications/{id}:read
POST /api/v1/notifications:read-all
GET  /api/v1/me/events   （SSE：notification.created）
```

### 3.3 异步与工作流

`notify` 消费者（`backend-relay`）订阅 §2.1 的事件，生成通知并发布 SSE。

### 3.4 事件与实时

SSE `notification.created`（`/me/events`）。

### 3.5 界面

顶栏铃铛（未读数）→ 下拉列表（分组：今天 / 更早）→ 点击跳转；Sonner toast 即时提示。

### 3.6 权限与审计

用户只能看到自己的通知；无审计。

### 3.7 非功能要求

PERF-03（事件到通知可见 ≤ 2 秒）。

## 4. 验收标准

- Given 整场批量生成结束（18 成功、2 失败），When 查看通知，Then 收到一条汇总通知，点击跳转到该批次。
- Given 可用余额跌破 20%，When 同一天再次跌破，Then 不重复通知。

## 5. 测试要点

去重；接收人计算。

## 6. 待确认

无。
