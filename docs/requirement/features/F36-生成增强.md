## 1. 需求说明

### 1.1 背景与目标

MVP 保证能出片；V1 提升可控性与连续性：用上一镜的片段 / 尾帧衔接下一镜，用首尾帧控制动作走向，局部修改关键帧，在多家供应商之间比较选择。

### 1.2 用户故事

- 作为**制作者**，我希望用上一镜的片段或其最后一帧作为下一镜的参考，保持连续性。
- 作为**制作者**，我希望指定视频的首帧与尾帧。
- 作为**制作者**，我希望圈选关键帧的局部区域修改，而不是整张重生成。
- 作为**制作者**，我希望同一能力切换到其他供应商的模型，比较质量与价格。

### 1.3 范围

四项增强。不包含：模型自动路由、自动故障转移。

## 2. 需求分析

| # | 规则 | 需求 |
| --- | --- | --- |
| R1 | 参考组合增加 `ref_type = operation_output`（已选定片段）与用途 `first_frame` / `last_frame`；片段作为参考时，可选“取尾帧”（`media` 队列抽帧生成图片候选） | VID-05 |
| R2 | 被引用的前一镜片段改选后，后一镜过期 | VID-05、LIN-01 |
| R3 | 首尾帧模式 `frames2video`：需要选定首帧与尾帧（均来自关键帧候选或上传）；模型须支持该模式 | VID-06 |
| R4 | 改图：`image.edit` 能力，输入 `source`（原关键帧）+ 蒙版 + 描述；结果为新候选，不覆盖原图 | IMG-03 |
| R5 | 模型切换：同一镜头可对不同模型分别报价，候选标注模型；对比视图可按模型筛选 | GEN-08 |
| R6 | 以上都走 F16 报价确认 | GEN-11 |

## 3. 实现所需

- 数据：`storyboard.reference_item` 已预留 `operation_output` 与 `first_frame` / `last_frame`（0302 §5.6）；`storyboard.shot_version.generation_mode` 增加 `frames2video`（CHECK 迁移）；新增 `operation_input` 的 `mask_asset_id`（改图蒙版，0302 同步）。
- 接口：`POST /shots/{id}/frames:extract-from-take`（`{ "take_output_id": "…", "position": "last" }` → 图片候选，免费）；报价项支持 `mode = frames2video`、`capability = image.edit`（`params.mask_asset_id`、`params.instruction`）；`GET /shots/{id}/candidates?model_key=`。
- 工作流：抽帧 `media.ExtractFrame`；其余复用 OperationWorkflow。
- 界面：参考选择器新增“前一镜片段”；首尾帧槽位；关键帧编辑器（画笔蒙版 + 描述）；候选对比按模型筛选。
- 权限与审计：同 F16、F17。

## 4. 验收标准

- Given 镜头 4 引用镜头 3 已选片段的尾帧作为首帧，When 生成，Then 片段记录该引用；镜头 3 改选后镜头 4 标记过期。
- Given 模型支持首尾帧，When 选定首帧与尾帧并生成，Then 片段首尾与所选图片一致（人工判断）。
- Given 关键帧，When 圈选人物手部并描述“握着一把伞”，Then 得到新候选，原图保留。
- Given 同一镜头分别用两个模型生成，When 对比，Then 可按模型筛选候选并看到各自费用。

## 5. 测试要点

抽帧精度；新模式在注册表与适配器中的映射；过期传播扩展。
