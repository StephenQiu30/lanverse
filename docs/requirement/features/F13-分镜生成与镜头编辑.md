## 1. 需求说明

### 1.1 背景与目标

镜头是生成与剪辑的最小单位。AI 按场生成镜头表初稿（画面、镜头语言、时长、台词分配、引用资产、建议模式与参考组合），制作者用结构化参数精确修改（P10），以镜头语言参数控制画面而不是靠自由提示词。

### 1.2 用户故事

- 作为**制作者**，我希望系统按场生成镜头表，并给出建议的生成模式与参考组合。
- 作为**制作者**，我希望用固定选项编辑景别、机位、运镜、时长，并多选批量修改。
- 作为**制作者**，我希望增删、排序、合并、拆分镜头，每次修改都可回溯。
- （V1）作为**制作者**，我希望套用“对话正反打”等模板快速生成一组镜头参数。

### 1.3 范围

- 包含：按场生成（报价确认）、按场确认、镜头表编辑（行内、批量）、镜头版本历史与差异、增删排序合并拆分、@实体引用。
- 不包含：生成模式与参考组合的细节（F14）、故事板网格（F15）、逐帧拉片（V2）。

## 2. 需求分析

### 2.1 业务流程

```text
本集结构已确认 → 选择场（全部 / 部分）→ 报价确认 → 每场 storyboard Skill
  输入：场结构（台词、动作、原文）、本场出现的角色 / 场景 / 道具与已锁定造型、项目风格与画幅、镜头语言词表
  输出：镜头列表 [画面描述（含 @实体）、景别、机位、运镜、时长、台词分配、引用造型 / 场景 / 道具、建议模式、默认参考组合]
  校验：台词一且仅一、引用在设定集中、时长在默认模型范围内
→ 保存为该场镜头（shot + shot_version v1，origin = ai），scene_board = awaiting_review
→ 编辑 → 确认本场（校验通过）→ confirmed
→ 后续逐镜修改 → 新版本 → 已生成的候选 / 片段标记过期
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 本场每句台词分配到且只分配到一个镜头（确认时校验） | SB-01 |
| R2 | 引用的资产必须是本项目设定集条目；引用造型而非角色 | BIB-02 |
| R3 | 引用了未锁定必需槽位的镜头显示“缺失：〈名称〉”，不阻止编辑与确认，阻止报价 | 允许先分镜后定稿 |
| R4 | 镜头语言参数取值为固定枚举（0302 `shot_version` CHECK）；时长 1–60 秒，生成时再与模型范围求交集 | SB-02、VID-02 |
| R5 | 每次修改产生镜头新版本；版本记录 `origin`（ai / user / agent）与修改说明 | SB-03 |
| R6 | 重新生成某场分镜：已确认的场需二次确认；旧镜头逻辑删除（`is_delete`），版本与已生成素材保留 | 防止误覆盖 |
| R7 | 合并：新镜头包含两者台词，原镜头逻辑删除；拆分：用户指定台词分配，前段沿用原镜头 ID（新版本），后段为新镜头 | 保持引用尽量稳定 |
| R8 | 排序使用 `position` 间隔插入，镜号 `场号-序号` 在排序后重算（仅展示字段） | 避免大量重排写入 |
| R9 | 批量修改逐项带 `expected_revision`，逐项返回成功或冲突 | 部分成功可见 |
| R10 | 镜头参数变化反映到提示词：`compose_prompt` 以镜头当前版本为输入；用户改写的 `prompt_override` 优先 | SB-02 |

### 2.3 状态

`scene_board.status`：`not_started` → `generating` → `awaiting_review` → `confirmed`；失败 → `failed`。镜头进度见 F15。

### 2.4 异常与边界

- Skill 输出不满足 R1 / R2：Harness 自动修复（≤ 2 轮），仍失败则该场失败，保留原始输出。
- 单场台词很多（> 60 句）：Skill 分段生成再拼接。
- 编辑中镜头被 Agent 或另一页面修改：冲突提示。

### 2.5 前置与依赖

F08 集结构已确认；F09 设定集已确认（未确认时仍可生成，但引用会指向候选条目并提示）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |

| `storyboard.scene_board` | `episode_id`、`scene_key`、`status`、`operation_id` | 按场生成与确认 |

| （V1）`storyboard.shot_template` | `name`、`shots[]` 参数模板 | SB-06 |

### 3.3 异步与工作流

`SceneStoryboardWorkflow`：`llm.run_skill(storyboard)` → `SaveSceneShots`（`flow`）。批量为子工作流。

### 3.4 事件与实时

`storyboard.shot_version_created.v1`（lineage、realtime）；SSE `shot.updated`。

### 3.5 界面

镜头表（TanStack Table + Virtual）：按场分组、行内编辑（下拉、时长步进器）、多选工具栏（批量改参数、批量生成、删除）、拖拽排序（dnd-kit）；画面描述使用 Tiptap + Mention（@造型 / @场景 / @道具）；版本抽屉；场确认按钮与校验提示。

### 3.6 权限与审计

制作者。审计：`scene_board.confirmed`、`shot.deleted`、`shot.merged`、`shot.split`（普通参数修改由版本表本身留痕，不重复写审计）。

### 3.7 非功能要求

PERF-04（150 镜头渲染 ≤ 1 秒、滚动 ≥ 50 fps）；AIQ-03（台词分配完整率 100%）。

## 4. 验收标准

- Given 第 2 场有 12 句台词，When 生成分镜，Then 12 句台词全部出现在镜头中且无重复；引用未定稿资产的镜头显示“缺失：角色 C”。
- Given 镜头景别由“中景”改为“特写”，When 请求报价，Then 生成提示中包含“特写”对应描述。
- Given 镜头 5 与 6，When 合并，Then 新镜头包含两者的台词，原镜头 5、6 的历史可查。
- Given 多选 10 个镜头批量改为固定机位，其中 1 个已被他人修改，When 提交，Then 9 个成功，1 个显示冲突。

## 5. 测试要点

台词分配校验；合并拆分对 `shot_line` 与引用的影响；批量部分成功；分镜 Skill 评测（0503）。
