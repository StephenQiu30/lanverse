# F01 账号与会话

| 项 | 内容 |
| --- | --- |
| 需求 | ACC-01 管理员创建账号、密码登录；ACC-03 会话管理与登出；ACC-04 禁用账号、重置密码；ACC-05 修改本人密码 |
| 优先级 | MVP |
| 用例 | UC-01、UC-02 |
| 页面 | 登录、管理 · 账号（0205 §3） |
| 依赖功能 | F04 审计日志 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

平台先供内部团队使用（P2），不对外开放注册（P17）。账号由管理员创建，成员使用账号密码登录。平台会调用付费模型，账号安全直接关系到费用安全，因此需要锁定、会话失效、强制改密等基本保护。

### 1.2 用户故事

- 作为**管理员**，我希望为团队成员创建账号并指定角色，以便只有授权人员能使用平台。
- 作为**管理员**，我希望禁用离职成员的账号、为忘记密码的成员重置密码，以便及时收回访问权限。
- 作为**制作者**，我希望用账号密码登录，长时间不操作后自动退出，并可随时修改自己的密码。

### 1.3 范围

- 包含：账号的创建、修改、禁用、启用、重置密码；登录、登出、会话过期；首次登录强制改密；修改本人密码；登录失败锁定。
- 不包含：自助注册、手机验证码、第三方 / 企业身份登录（SSO）、多因素认证、多组织、项目级角色权限（V2，见 F38 PRJ-04）。

## 2. 需求分析

### 2.1 业务流程

```text
管理员创建账号（登录名、显示名、角色、初始密码）
  → 成员首次登录 → 强制修改密码 → 进入项目列表
  → 日常：登录 → 操作（每次请求续期空闲计时）→ 登出 / 空闲 12 小时失效 / 7 天绝对失效
管理员禁用 / 重置密码 → 该账号所有会话立即失效
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 只能由管理员创建账号 | P17 |
| R2 | 登录名在组织内唯一，不区分大小写，创建后不可修改 | 审计记录以登录名识别操作人 |
| R3 | 角色为 `admin` 或 `producer`；管理员同时具备制作者全部能力 | MVP 只需两种角色 |
| R4 | 密码至少 10 位，含字母与数字；新密码不能与当前密码相同 | 基本强度 |
| R5 | 首次登录、被重置后必须先改密，改密前只能访问改密接口 | 初始密码由管理员知晓 |
| R6 | 连续 5 次密码错误锁定 15 分钟；登录成功后清零 | 防暴力破解 |
| R7 | 登录名不存在与密码错误返回相同提示 | 不暴露账号是否存在 |
| R8 | 会话空闲 12 小时失效，绝对有效期 7 天 | 平衡便利与安全 |
| R9 | 禁用、重置密码、本人改密后，该账号其他会话立即失效（改密时保留当前会话） | 及时收回权限 |
| R10 | 不能禁用最后一个启用的管理员，不能把最后一个管理员降级 | 避免无人可管理 |
| R11 | 账号不物理删除；禁用账号的历史操作记录保留 | 审计 |

### 2.3 状态

```text
账号：active ⇄ disabled
登录：正常 → 锁定中（locked_until 未到）→ 正常
密码：需修改（must_change_password = true）→ 正常
```

### 2.4 异常与边界

- 锁定期间即使密码正确也拒绝登录，返回剩余秒数。
- 禁用中的账号登录返回与密码错误相同的提示（R7），审计中记录真实原因。
- 两位管理员同时修改同一账号：`expected_revision` 冲突，后者提示刷新。
- Redis 不可用：登录与会话校验不可用，返回 503；不降级为无会话校验（安全优先）。

### 2.5 前置与依赖

- 系统初始化时通过命令行工具创建第一个管理员（`lanverse admin bootstrap`），不提供默认账号密码。
- 审计写入依赖 F04。

## 3. 实现所需

### 3.1 数据

| 存储 | 用途 | 关键字段 |
| --- | --- | --- |
| `identity.user`（[0302 §5.1](../../design/0302-领域与数据模型.md#51-identity)） | 账号 | `login_name`（citext，部分唯一索引）、`role`、`status`、`password_hash`、`must_change_password`、`failed_login_count`、`locked_until`、`session_epoch`、`revision` |
| Redis `sess:{sha256(token)}` | 会话 | `user_id`、`session_epoch`、`create_time`、`last_seen`；TTL = 12 小时，每次请求续期，但不超过创建后 7 天 |
| Redis `login_fail_ip:{ip}` | IP 维度限流 | 计数，TTL 1 分钟 |

为什么需要 `session_epoch`：会话存在 Redis 中，逐个删除某账号的全部会话需要额外索引；改为在账号上维护一个递增的“会话纪元”，会话记录创建时的纪元，校验时不一致即失效（R9），实现简单且可靠。

### 3.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/login` | 登录 |
| POST | `/api/v1/auth/logout` | 登出 |
| GET | `/api/v1/auth/me` | 当前用户 |
| POST | `/api/v1/auth/password` | 修改本人密码 |
| GET / POST | `/api/v1/admin/users` | 账号列表 / 创建 |
| PATCH | `/api/v1/admin/users/{id}` | 修改显示名、角色（Rev） |
| POST | `/api/v1/admin/users/{id}/disable`、`/enable` | 禁用 / 启用 |
| POST | `/api/v1/admin/users/{id}/reset-password` | 重置密码 |

登录：

```http
POST /api/v1/auth/login
{ "login_name": "alice", "password": "…" }

200 OK   Set-Cookie: lv_session=…; HttpOnly; Secure; SameSite=Lax
         Set-Cookie: lv_csrf=…; Secure; SameSite=Lax
{ "user": { "id": "…", "login_name": "alice", "display_name": "Alice", "role": "producer" },
  "must_change_password": true }

401 invalid_credentials      423 account_locked { "meta": { "retry_after_s": 540 } }
```

创建账号：

```http
POST /api/v1/admin/users
{ "login_name": "alice", "display_name": "Alice", "role": "producer", "initial_password": "…" }
201 { "id": "…", "login_name": "alice", "status": "active", "revision": 1, "create_time": "…" }
409 validation_failed（登录名已存在）
```

错误码：`invalid_credentials`、`account_locked`、`password_change_required`、`unauthenticated`、`forbidden`、`state_conflict`（禁用最后一个管理员）、`revision_conflict`。

### 3.3 异步与工作流

无工作流。账号变更事务内写 Outbox 事件 `identity.user_changed.v1`，由审计消费者归档。

### 3.4 事件与实时

| 事件 | 触发 | 消费者 |
| --- | --- | --- |
| `identity.user_changed.v1` | 创建、修改、禁用、启用、重置、改密 | audit |

会话失效不依赖事件：`session_epoch` 在同一事务中递增，下一次请求即失效。

### 3.5 界面

- 登录页：登录名、密码、错误与锁定提示（剩余时间）。
- 强制改密页：当前密码、新密码、确认新密码，实时显示强度规则。
- 管理 · 账号：列表（登录名、显示名、角色、状态、最后登录）、创建对话框、操作菜单（修改、禁用 / 启用、重置密码）。
- 应用外壳用户菜单：修改密码、登出。

### 3.6 权限与审计

| 操作 | 权限 | 审计 action |
| --- | --- | --- |
| 登录成功 / 失败 / 锁定 | 任何人 | `auth.login_succeeded` / `auth.login_failed` / `auth.locked` |
| 登出 | 本人 | `auth.logout` |
| 创建、修改、禁用、启用、重置密码 | 管理员 | `user.created` / `user.updated` / `user.disabled` / `user.enabled` / `user.password_reset` |
| 修改本人密码 | 本人 | `user.password_changed` |

审计中不记录任何密码或哈希。

### 3.7 非功能要求

| 条目 | 本功能的目标 |
| --- | --- |
| SEC-01、SEC-03 | 除登录与健康检查外全部接口要求会话；bcrypt cost 12 |
| SEC-05 | Cookie 带 `Secure`、`HttpOnly`、`SameSite=Lax` |
| PERF-02 | 登录 P95 ≤ 500 ms（bcrypt 约 250 ms） |
| PRV-01、PRV-02 | 只保存登录名、显示名、角色；日志不记录密码与会话令牌 |

## 4. 验收标准

- Given 管理员已登录，When 创建登录名为 `alice` 的制作者账号，Then 账号列表出现 `alice`，状态为启用，审计记录包含此操作。
- Given `alice` 首次登录，When 输入正确的初始密码，Then 系统要求先修改密码才能进入；改密前调用其他接口返回 `password_change_required`。
- Given 某账号连续输错 5 次密码，When 第 6 次尝试登录，Then 提示“账号已临时锁定，请 15 分钟后再试”，即使密码正确也不能登录。
- Given 未登录用户，When 访问项目页面地址，Then 跳转登录页，登录成功后回到该项目页面。
- Given 已登录用户，When 点击登出后使用浏览器后退，Then 无法访问受保护页面。
- Given 管理员禁用某账号，When 该账号在另一浏览器继续操作，Then 下一次请求被拒绝并跳转登录页。
- Given 系统只剩 1 个启用的管理员，When 该管理员尝试禁用自己，Then 操作被拒绝并提示原因。
- Given 管理员重置 `alice` 的密码，When `alice` 使用新密码登录，Then 系统要求修改密码，且 `alice` 此前的所有会话已失效。
- Given 用户在两个浏览器登录，When 在其中一个修改密码，Then 另一个浏览器的会话失效，当前浏览器保持登录。

## 5. 测试要点

- 单元：密码规则、锁定计数与解锁时间、会话纪元比较、最后一个管理员保护。
- 集成（testcontainers PostgreSQL + Redis）：登录 → 会话 → 禁用 → 会话失效；并发修改同一账号的版本冲突。
- 安全：未认证访问全部接口返回 401（遍历 OpenAPI）；登录名枚举不可区分；CSRF 头缺失的写请求被拒绝。
