# F09 设定集抽取与造型

| 项 | 内容 |
| --- | --- |
| 需求 | BIB-01 全剧设定抽取与别名合并；BIB-02 角色造型 |
| 优先级 | MVP |
| 用例 | UC-07 |
| 页面 | 设定集、设定条目详情 |
| 依赖功能 | F08、F16 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

跨集一致性的前提是“同一个角色 / 场景 / 道具在全剧只有一份设定”。剧本中同一角色常有多种称呼（“小李”“李明”“李队”），角色在不同阶段外观也不同（换装、受伤、年龄段）。需要从全剧抽取并合并，再细分为造型。

### 1.2 用户故事

- 作为**制作者**，我希望系统从全剧抽取角色、场景、道具，并合并同一角色的不同称呼。
- 作为**制作者**，我希望一个角色可以有多个造型，并标注适用的集与场。

### 1.3 范围

- 包含：AI 抽取、别名合并 / 拆分、人工增删改、造型管理、出场集统计、确认、台词说话人回填。
- 不包含：参考图生成与锁定（F10）、音色（F11）。

## 2. 需求分析

### 2.1 业务流程

```text
已确认的集 ≥ 1 → 发起抽取（报价确认）→ extract_bible Skill（输入：各集解析结构摘要）
→ 候选：角色（名称、别名、描述、出场集、状态变化 → 造型建议）、场景、道具
→ 用户合并 / 拆分 / 编辑 / 删除 → 确认设定集
→ 回填各集台词的 character_id（按别名匹配，未匹配的列出供人工指定）
后续新确认的集 → 增量抽取：只对新出现的称呼给出“归入已有角色 / 新建”建议
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 每个条目显示出场集号与首次出场位置（可定位原文） | 判断重要程度 |
| R2 | 合并：被合并方的别名、出场集并入保留方，被合并方 `merged_into_id` 指向保留方并逻辑删除；已引用被合并方的镜头与造型改指保留方 | 保持引用有效 |
| R3 | 拆分：从一个角色的别名中拆出新角色，已回填的台词按别名重新归属 | 纠正误合并 |
| R4 | 每个角色至少一个默认造型；造型可声明适用范围（集、场） | BIB-02 |
| R5 | 镜头引用角色时引用具体造型；分镜生成时按适用范围推荐造型，否则用默认造型 | BIB-02 |
| R6 | 已被镜头引用的造型不能删除，只能停用（逻辑删除前检查引用） | 引用保护 |
| R7 | 设定集确认后仍可增改；新增条目为 candidate，需再次确认 | 全剧制作是渐进的 |

### 2.3 状态

条目 `review_status`：`candidate` → `confirmed`；合并后被合并方 `is_delete = true`。

### 2.4 异常与边界

- 100 集剧本的全量抽取超过上下文：按 10 集分块抽取，再做一次合并 Skill 调用（Harness 内部两阶段）。
- 同名不同人（两个“王总”）：合并建议只基于别名与上下文，用户可拆分；拆分后在台词归属界面逐句指定。

### 2.5 前置与依赖

F08 集已确认；Skill `extract_bible`（0305）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `bible.character` | `name`、`aliases`、`description`、`review_status`、`episode_seqs`、`first_episode_seq`、`merged_into_id` | 角色与别名 |
| `bible.look` | `character_id`、`name`、`description`、`is_default`、`applies_to` | 造型与适用范围 |
| `bible.location`、`bible.prop` | `name`、`aliases`、`description`、`episode_seqs` | 场景、道具 |
| `bible.episode_asset_usage` | `episode_id`、`owner_type`、`owner_id`、`source` | 本集用到哪些条目（F10 资产定稿清单） |
| `script.dialogue_line.character_id` | 回填 | 配音按角色取音色 |

### 3.2 接口

```http

200 { "items": [ { "id": "…", "name": "李明", "aliases": ["小李","李队"], "episode_seqs": [1,2,3,7], "review_status": "candidate",
                   "looks": [ { "id": "…", "name": "日常装", "is_default": true, "locked_slots": 1, "total_slots": 2 } ], "revision": 2 } ] }

POST /api/v1/characters/{id}:merge   { "from_ids": ["…"], "expected_revision": 2 }

```

### 3.3 异步与工作流

`BibleExtractWorkflow`：`llm.run_skill(extract_bible)`（可分块）→ `SaveBibleCandidates`（`flow`，合并到已有条目时只生成建议）。

### 3.4 事件与实时

`bible.entries_changed.v1`（realtime）；合并 / 拆分写审计。

### 3.5 界面

三栏列表（角色 / 场景 / 道具）；多选合并；条目详情：别名标签、描述、出场集时间轴、造型卡片；说话人映射对话框。

### 3.6 权限与审计

制作者。审计：`bible.merged`、`bible.split`、`bible.confirmed`、`look.created/updated/deleted`。

### 3.7 非功能要求

AIQ-02（主要角色召回 100%，别名合并准确率 ≥ 90%）；CAP-01（≥ 200 造型）。

## 4. 验收标准

- Given 剧本中“小李”“李明”“李队”指同一人，When 抽取完成，Then 三个称呼合并为一个角色并列出别名，用户可拆分。
- Given 角色 A 有“日常装”“战斗受伤”两个造型，When 在第 5 场的镜头中引用 A，Then 可选择具体造型，默认按适用范围推荐。
- Given 角色 B 被合并入 A，When 查看原引用 B 的镜头，Then 引用显示为 A。
- Given 造型已被镜头引用，When 删除造型，Then 被拒绝并列出引用的镜头。

## 5. 测试要点

合并 / 拆分对引用与台词回填的影响；分块抽取的合并正确性（评测集）。
