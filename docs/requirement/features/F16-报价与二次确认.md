# F16 报价与二次确认

| 项 | 内容 |
| --- | --- |
| 需求 | GEN-01 生成前报价；GEN-11 付费生成二次确认；CST-03 预留与结算 |
| 优先级 | MVP |

| 页面 | 全局“报价确认”组件（所有生成入口） |
| 依赖功能 | F03、F05、F06、F20、F30 |

## 1. 需求说明

### 1.1 背景与目标

视频生成是最大成本项，费用必须透明且可控：生成前看到费用，由用户明确确认后才花钱（P21，“存在消费的问题，需要让用户二次确认”）；执行中预留预算，结束后按实际结算，任何终态都不残留预留。这是所有付费生成的统一入口，流水线、批量、画布、Agent、开放接口都走同一套。

### 1.2 用户故事

- 作为**制作者**，我希望在生成前看到模型、数量、预估费用与剩余预算。
- 作为**制作者**，我希望任何会产生费用的生成都经过我的明确确认，不存在自动确认。
- 作为**管理员**，我希望每次生成的费用先预留、后按实际结算，账本始终平衡。

### 1.3 范围

- 包含：单项与批量报价、输入与参数校验、复用判断、报价有效期、确认、预留、结算、释放、确认审计。
- 不包含：批量执行调度（F18）、任务执行与对账（F19、0304）、成本报表（F30）。

## 2. 需求分析

### 2.1 业务流程

```text
入口（按钮 / 批量 / 画布 / Agent 草稿）→ POST /quotes（1..n 项）
  对每一项：
    1. 解析目标对象的当前版本 → 构造输入（镜头：展开参考组合；台词：文本 + 音色；槽位：描述 + 风格）
    2. 选择模型：显式指定 > 镜头 / 项目默认；校验模型启用、凭据可用、项目境外设置
    3. 校验：模式、输入数量 / 类型 / 时长、参数（param_schema）、就绪、授权、前置条件（如图生视频需关键帧）
    4. 计算 input_hash；命中已完成的相同输入且未要求强制重做 → reused，报价 0
    5. 计价：按生效价格规则 × 数量 × 参数系数 → quote_micros
    6. 创建 Operation(status = quoted, quote_expires_at = now + 15 min)
  汇总：合计、可用余额、是否可确认
→ 用户在确认对话框中点击“确认”（可剔除个别项）
→ POST /operations/{id}:confirm 或 /batches/{id}:confirm
  一个事务：检查未过期 → 锁预算行 → 余额足够 → 创建 reservation(held) → budget.reserved += 报价 → Operation = confirmed
           → 生成 provider_request_key → 写 ledger(reserve) → 写 Outbox(operation.confirmed) → 审计
  事务后：启动工作流 operation/{id}（ID 重复则忽略）
→ 终态（0304）：settle(实际费用) + release(预留 − 实际)；失败 / 取消按供应商实际计费
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 所有付费生成必须先报价、后确认；服务端没有任何自动确认参数或配置 | GEN-11 |
| R2 | 确认只能由用户会话发起；Agent 服务令牌、开放接口令牌调用确认接口返回 403 | 防绕过 |
| R3 | 报价 15 分钟有效；过期确认返回 `quote_expired`，前端自动重新报价并再次请求确认 | 价格与输入可能变化 |
| R4 | 确认时再次核对：目标对象版本未变、模型版本与价格未变；任一变化则报价作废，返回 `quote_expired` 并附原因 | 防止按旧输入执行 |
| R5 | 复用（`reused = true`）的项确认后不调用供应商，直接把已有输出关联为新 Operation 的输出，费用 0 | GEN-05 |
| R6 | 批量确认可剔除项；剔除项状态变为 `expired` | GEN-03 |
| R7 | 预留金额 = 报价；结算金额 = 供应商实际用量 × 报价时价格规则；差额释放 | CST-03 |
| R8 | 任一终态（completed / failed / cancelled / manual 处理后）必须完成结算，残留预留为 0 | REL-08 |
| R9 | 报价与确认都要求 `Idempotency-Key`；重复确认返回首次结果 | G1 |
| R10 | 报价显示服务区域；境外模型在对话框中显示数据出境提示 | PRV-03 |
| R11 | 非付费操作（渲染、剪辑、上传探测）不走本流程 | 只针对供应商付费 |

### 2.3 状态

Operation：`draft` → `quoted` → `confirmed` → …（0304）；`quoted` → `expired`（过期或剔除）。预留：`held` → `settled` / `released`。

### 2.4 异常与边界

- 余额不足：该批不可确认，显示差额；剔除部分项后重新计算。
- 并发确认：预算行锁 + 约束，后到者 `budget_insufficient`。
- 确认后工作流启动失败（Temporal 暂不可用）：Operation 保持 `confirmed`，由 relay 的“待启动扫描”在恢复后启动（以 Outbox 事件驱动），不重复启动。
- 按 token 计费的 LLM：报价按输入估算 + 输出上限计算，预留取上限，结算按实际，偏差 ≤ 30%（COST-02）。

### 2.5 前置与依赖

F03 价格规则；F06 预算；F05 项目境外设置。

### 3.3 异步与工作流

确认事务提交后启动 `OperationWorkflow`（单项）或 `BatchWorkflow`（批量）；结算由工作流最后一步 `flow.SettleOperation` Activity 执行（0304）。定时任务 `QuoteExpirySchedule` 每 5 分钟把过期报价置为 `expired`。

### 3.4 事件与实时

`operation.confirmed.v1`（audit、billing-report）；SSE `budget.updated`、`operation.updated`。

### 3.5 界面

`QuoteConfirmDialog` 组件（0205 §4.1）：逐项费用（可展开）、合计、剩余预算、倒计时、区域提示、错误项列表与“剔除”操作；确认按钮不响应回车；按钮文案“生成（约 ¥X）”由 `useQuote` 钩子统一计算。

### 3.6 权限与审计

制作者与管理员。审计：`operation.confirmed`（金额、模型、区域、确认人、来源入口）、`batch.confirmed`。

### 3.7 非功能要求

PERF-10（单项报价 P95 ≤ 1 秒，150 项 ≤ 5 秒）；REL-02（重复计费 0）；REL-04（幂等）；REL-08；COST-02（报价偏差 ≤ 5%）。

## 4. 验收标准

- Given 报价已生成 20 分钟，When 用户点击确认，Then 提示报价已过期并重新计算。
- Given 任意入口发起生成，When 用户未点击确认，Then 不产生任何供应商调用，也不产生预留。
- Given（V1）Agent 建议批量生成 10 个镜头，When 用户未确认，Then 不产生费用；确认后才执行。
- Given 报价后镜头参数被修改，When 确认，Then 报价作废并提示重新报价。
- Given 任务结束（任一终态），When 检查账本，Then 该任务不存在未释放的预留。
- Given 同一 `Idempotency-Key` 的确认请求发送两次，When 检查，Then 只有一笔预留、一个工作流。

## 5. 测试要点

- 单元：计价（各计价单位、系数）、`input_hash` 规范化、报价失效判断。
- 集成：确认事务（预算约束、并发）；工作流启动失败恢复；复用路径。
- 故障注入：确认后立即重启 API 与 Worker，任务仍被执行一次。
