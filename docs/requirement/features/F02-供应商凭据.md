# F02 供应商凭据

| 项 | 内容 |
| --- | --- |
| 需求 | ACC-02 管理员配置模型供应商凭据 |
| 优先级 | MVP |
| 用例 | UC-03 |
| 页面 | 管理 · 供应商凭据 |
| 依赖功能 | F01、F03、F04 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

平台通过火山方舟、MiniMax、OpenRouter 调用模型（P18）。凭据直接对应付费额度，泄露即产生经济损失。管理员需要在界面中配置、测试、停用凭据，且凭据在任何地方都不以明文出现。

### 1.2 用户故事

- 作为**管理员**，我希望为每个供应商配置凭据并测试连通性，以便平台可以调用模型。
- 作为**管理员**，我希望停用可能泄露的凭据，使依赖它的模型立即不可被新任务使用。

### 1.3 范围

- 包含：供应商登记、凭据设置 / 替换 / 停用、连通性测试、凭据状态展示。
- 不包含：多凭据负载均衡与自动切换（V1 与 GEN-08 一起考虑）、供应商余额查询。

## 2. 需求分析

### 2.1 业务流程

```text
管理员新增供应商（key、名称、适配器、区域、并发与速率上限）
  → 设置凭据（明文只出现在这一次请求中）→ 后端用 Agent 服务公钥加密后落库
  → 测试连通性（经 agent-worker 用凭据调用供应商的免费接口）→ 记录结果
  → 模型注册表（F03）中该供应商的模型可启用
停用凭据 → 该供应商模型的新报价失败（model_unavailable）；进行中任务按原凭据完成
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 每个供应商同一时刻最多一个启用的凭据 | 计费归属清晰 |
| R2 | 凭据保存后界面只显示末 4 位与更新时间，任何接口都不返回明文或密文 | SEC-04 |
| R3 | `backend-api` 不能解密凭据：用 Agent 服务的公钥封装，私钥只在 `agent-worker` 运行环境 | 缩小泄露面（0307 §5） |
| R4 | 连通性测试只调用不计费接口（如模型列表），不产生付费调用 | ACC-02 |
| R5 | 替换凭据是“新增一条 + 停用旧的”，旧记录保留（`is_delete = false`，`status = disabled`） | 审计可追溯 |
| R6 | 进行中的任务在 Activity 开始时读取凭据；停用后新提交的 Activity 失败为不可重试的 `credential_disabled`，已提交的任务继续查询至完成 | 不丢结果、不重复付费 |

### 2.3 状态

```text
凭据：active → disabled
测试结果：untested → ok | auth_failed | unreachable | timeout
```

### 2.4 异常与边界

- 测试失败显示错误类别，不显示供应商原始报错中的敏感内容。
- Agent 服务不可用时测试返回 503，凭据仍然保存（状态 untested）。
- 封装密钥轮换：新凭据用新 `key_id`；旧凭据可由运维工具批量重新封装。

### 2.5 前置与依赖

- 部署时生成 Agent 服务的密钥对；公钥配置给 `backend-api`，私钥只注入 `agent-worker` / `agent-api`（0307）。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `catalog.provider` | `key`、`adapter_key`、`region`、`concurrency_limit`、`rate_limit_per_min`、`status` | 适配器选择、境外标注、限流配置 |
| `catalog.provider_credential` | `ciphertext`、`key_id`、`last4`、`status`、`last_tested_at`、`last_test_result` | 加密存储与状态展示；部分唯一索引保证 R1 |

### 3.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / POST | `/api/v1/admin/providers` | 列表 / 新增供应商 |
| PATCH | `/api/v1/admin/providers/{id}` | 修改并发、速率、状态（Rev） |
| POST | `/api/v1/admin/providers/{id}/credentials` | 设置凭据 |
| POST | `/api/v1/admin/providers/{id}/credentials/test` | 测试当前启用的凭据 |
| POST | `/api/v1/admin/providers/{id}/credentials/{cid}/disable` | 停用 |

```http
POST /api/v1/admin/providers/{id}/credentials
{ "label": "方舟主账号", "secret": { "api_key": "…" } }
201 { "id": "…", "label": "方舟主账号", "last4": "a9F2", "status": "active", "last_test_result": null }
```

`secret` 为对象，不同供应商字段不同（方舟：`api_key`；MiniMax：`api_key`、`group_id`；OpenRouter：`api_key`），字段定义由适配器声明、在 `GET /admin/providers/{id}` 的 `credential_schema` 中返回。

### 3.3 异步与工作流

- 测试：`backend-api` 直接执行一个短工作流 `CredentialTestWorkflow` → Activity `provider.test_credential`（`agent` 队列，超时 15 秒，不重试）。
- 供应商 Activity 在执行时按 `credential_ref`（凭据 ID）读取密文并解密；解密结果只保存在进程内存中，缓存 5 分钟。

### 3.4 事件与实时

`catalog.credential_changed.v1`（新增、停用、测试结果）→ audit、注册表缓存失效。

### 3.5 界面

供应商列表：名称、区域、凭据状态（末 4 位、最后测试结果与时间）、模型数量；凭据对话框为密码输入框，保存后不可查看。

### 3.6 权限与审计

仅管理员。审计 action：`provider.created`、`provider.updated`、`credential.set`、`credential.disabled`、`credential.tested`；只记录 `last4`。

### 3.7 非功能要求

SEC-04（凭据不出现在日志、响应、前端、追踪中，CI 扫描验证）；OBS-02（日志脱敏）。

## 4. 验收标准

- Given 管理员保存火山方舟凭据，When 再次打开配置页，Then 只显示凭据末 4 位，接口响应中不含明文或密文。
- Given 管理员停用 MiniMax 凭据，When 制作者对使用 MiniMax 模型的镜头请求报价，Then 报价失败并提示“该模型当前不可用”。
- Given 凭据有效，When 点击测试，Then 显示“连接正常”，供应商侧无计费记录。
- Given 数据库备份被泄露，When 攻击者只持有数据库内容与 `backend-api` 配置，Then 无法解密凭据。

## 5. 测试要点

- 单元：封装 / 解封；`secret` 按适配器 schema 校验。
- 集成：停用后新报价失败、进行中任务继续查询；日志与响应敏感词扫描。
