# F32 系统健康视图

| 项 | 内容 |
| --- | --- |
| 需求 | ADM-03 系统健康视图 |
| 优先级 | V1 |
| 用例 | UC-17 |
| 页面 | 管理 · 系统健康 |
| 依赖功能 | F19；06xx 监控 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

1–2 人团队维护全部组件（P14）。管理员需要在产品内一眼看到生成链路是否健康，不必每次打开 Grafana。

### 1.2 用户故事

- 作为**管理员**，我希望看到各队列积压、失败率、结果未知与待人工核对数量、各供应商可用性，异常时高亮。

### 1.3 范围

包含：只读汇总视图、跳转 Grafana / Temporal UI。不包含：告警配置（在 0603）。

## 2. 需求分析

| # | 规则 |
| --- | --- |
| R1 | 数据来自 Prometheus 查询与业务库统计，30 秒刷新 |
| R2 | 阈值（与 0603 告警一致）：队列积压 > 100、失败率 15 分钟 > 20%、`unknown` > 10、`manual` > 0 超过 24 小时、Outbox 积压 > 1,000 |
| R3 | 只读；不提供重启、清队列等操作 |

## 3. 实现所需

- 数据：无新表；Prometheus 指标（0202 OBS-03）、`operation` 状态计数。
- 接口：`GET /api/v1/admin/health` → `{ "queues": [ { "name": "agent.ark", "backlog": 12, "workers": 2 } ], "operations": { "failed_rate_15m": 0.03, "unknown": 0, "manual": 1 }, "providers": [ { "key": "ark", "success_rate_1h": 0.98, "p95_latency_ms": 42000, "status": "ok" } ], "outbox_backlog": 3, "kafka_lag": { "lineage": 0 } }`
- 界面：卡片 + 表格，异常红色高亮，外链到 Grafana、Temporal UI。
- 权限：仅管理员。

## 4. 验收标准

- Given 模拟供应商失败率 50%，When 打开系统健康，Then 该供应商高亮为异常。
- Given 存在超过 24 小时的待人工核对任务，When 打开页面，Then 显示数量并可跳转到任务列表。

## 5. 测试要点

阈值判断单元测试。
