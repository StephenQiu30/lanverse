# 项目制作圣经需求规格

- 状态：旧派生文档已冻结；由 `SG-D17`–`SG-D21` 的统一链路替代
- 日期：2026-08-25
- 产品来源：[项目制作圣经产品需求](../prd/3001-项目制作圣经产品需求.md)
- 设计来源：[项目制作圣经生成执行框架设计](../design/3001-项目制作圣经生成执行框架设计.md)

## 目的

本规格把项目制作圣经的产品目标转化为稳定、可测试的业务契约。需求完成与否只由独立的
[验收标准](../acceptance/3001-完整剧本业务闭环验收标准.md)判定，本文件不声明实施结果。

## 术语

- `document revision`：固定且不可变的完整剧本文本版本。
- `Production Bible`：绑定一个 document revision 的项目级理解候选及其审阅状态。
- `entity`：跨集稳定的角色、地点、道具、服装、声音或视觉风格身份。
- `entity state`：同一 entity 在指定集数或阶段的可见状态。
- `world entry`：带来源证据、可查询的世界观事实或规则。
- `snapshot`：`production_bible_id + revision + result_hash` 的不可变组合。
- `occurrence`：某个已确认资产状态在具体叙事单元版本中的出现事实。
- `blocking issue`：未通过正式修订或决议前禁止确认的业务问题。

## 功能需求

### 输入、生成与查询

| ID | 需求 | 可测试条件 |
|---|---|---|
| `PB-FR-001` | 系统必须以不可变 document revision 创建 Bible；创建命令携带幂等键，并持久化 document revision、input hash、Task 和 Outbox 事实。 | 相同幂等输入只返回同一 Bible/Task；内容变化不能复用原任务；事件不携带完整剧本文本。 |
| `PB-FR-002` | 系统必须连续覆盖完整原稿并提取绝对来源区间、逐字 anchor、hash 和可确定时的集号；模型只能引用已提供的 evidence catalog。 | 首区间从 `0` 开始、末区间等于正文长度；拼接区间等于原文；伪造、越界或 hash 不匹配证据被拒绝。 |
| `PB-FR-003` | 系统必须把稳定 entity 与阶段性 entity state 分开，并支持角色、地点、道具、服装、声音、视觉风格和 world entry。 | 同一 entity 可含多个 state；所有 entity/state/world entry 均有证据；world entry 不得引用未知 entity key。 |
| `PB-FR-004` | 生成链必须包含证据提取、跨区间统一和独立复核；所有模型输出只能成为候选。 | 各阶段使用严格 schema；reconcile 不得引入 evidence 阶段没有的证据；review 只能返回 issue，不能修改或确认候选。 |
| `PB-FR-005` | Tool Gate 必须验证 schema、证据、key、同类型名称/别名唯一性、状态时间线和 world rule 一致性。 | 同类型别名冲突、互斥状态重叠、无证据事实、悬空 world 引用或规则冲突都会形成稳定 blocker，且不能只依赖模型自报通过。 |
| `PB-FR-006` | 用户必须能按 Bible id 查询状态、版本、checkpoint 摘要、issue、entity/state/world entry，并查询项目有效的已确认 Bible。 | 跨 workspace 访问不可见；私有 run token、lease 和私有 receipt 不出现在公开响应。 |

### 审阅、修订与确认

| ID | 需求 | 可测试条件 |
|---|---|---|
| `PB-FR-007` | `failed` 或 `unknown` 且存在合法 checkpoint 的 Bible 必须支持正式 resume。 | resume 校验 expected revision 和幂等键，创建新 Task，保留旧 Task 终态和审计历史，只恢复未完成阶段；无 checkpoint 时 fail closed。 |
| `PB-FR-008` | 每一种 blocking issue 必须有带类型的正式 resolution command，至少覆盖状态集数、身份合并/拆分、名称/别名、entity kind、state 增删、world entry 修订和 issue 判定。 | 命令携带 issue key、判断依据、目标字段、expected revision/result hash 和幂等键；重放返回同一结果；不同输入复用幂等键返回冲突。 |
| `PB-FR-009` | 确认前必须验证所有 blocking issue 已清零，并执行原子、幂等的资产物化。 | 一个 entity 对应一个 Asset；多个 state 对应该 Asset 下不同 AssetState/AssetVersion；任一冲突不产生半写入。 |
| `PB-FR-010` | 与项目内同类型规范名或唯一别名匹配时，系统必须要求用户通过正式命令显式链接；不得字符串近似自动合并。 | 未链接的匹配阻止确认；越 workspace/project/kind、不可用资产或一个资产被两个 entity 复用均被拒绝；合法链接可完成确认。 |

### 发布与下游传播

| ID | 需求 | 可测试条件 |
|---|---|---|
| `PB-FR-011` | ImportCommit 发布必须以同一 document revision 的 confirmed Bible 为硬门，并为该批次所有分集冻结同一 snapshot。 | Bible 未确认时不发布且不创建分集 extraction；成功发布的全部 ExtractionBatch 具有相同 Bible id/revision/result hash。 |
| `PB-FR-012` | Bible-bound 分集抽取只允许 scene、dialogue、occurrence 和 continuity 候选；occurrence 必须引用已确认 entity/state。 | 独立 asset candidate、未知 entity/state、类型不匹配或 snapshot 漂移被拒绝；合法 occurrence 在结构确认时锚定 narrative unit version。 |
| `PB-FR-013` | 分集发现未知或歧义身份时，系统必须持久化可审阅的 Bible reconciliation issue，而不是静默新建资产或只丢弃 Provider 结果。 | issue 包含来源区间、集号、候选引用和后续动作；处理 issue 前结构确认保持阻塞；幂等重放不重复创建 issue。 |
| `PB-FR-014` | Storyboard 创建必须从目标剧集 occurrence 自动派生资产状态，并携带相关 world entry 与固定 Bible snapshot。 | 调用方无需手工传 Bible 资产；无 occurrence 的全项目资产不进入场景；occurrence 或 snapshot 变化使旧输入冲突。 |
| `PB-FR-015` | 更新原稿的 confirmed Bible 必须使旧项目 Bible 进入 `superseded`，并提供对已发布结构、occurrence、资产版本和分镜的影响分析。 | 项目有效 Bible 唯一；旧 snapshot 保持可追溯且不被原地修改；用户确认传播前不得静默替换下游固定引用。 |

### 取消与失败

| ID | 需求 | 可测试条件 |
|---|---|---|
| `PB-FR-016` | 用户必须能显式取消 `queued/running` Bible；Provider 结果不确定时进入 `unknown`，确定失败进入 `failed`。 | 取消会 fencing 所属 run token 并终止本地 Codex；取消、失败或 unknown 后不得提交成功结果；重复命令幂等。 |

## 非功能需求

| ID | 需求 | 可测试条件 |
|---|---|---|
| `PB-NFR-001` | 长任务不得设置固定业务墙钟超时；运行所有权使用可续租 lease、heartbeat 和 run token fencing。 | 心跳正常可连续续租；短暂续租失败在 lease 内重试；活跃重投不启动第二运行；过期后新 token 恢复，旧 token 不能保存或提交。 |
| `PB-NFR-002` | 所有状态变更必须幂等、可审计且具有乐观锁或固定输入哈希。 | 创建、resume、resolution、confirm、publish 和 occurrence 重放不产生重复事实；内部 confirm 结果返回本次持久化或重放命中的同一 Receipt，公开 HTTP 不暴露私有 Receipt；冲突返回有效 revision 或 next action。 |
| `PB-NFR-003` | Skill 和本地 Codex 只能读取固定输入并返回结构化候选，不得写文件、数据库或调用业务 Tool。 | Codex 使用 ephemeral/read-only sandbox；Skill 禁止隐式调用和副作用；正式写入只由应用服务完成。 |
| `PB-NFR-004` | workspace、project、document、Bible、Asset 和 Task 的作用域必须一致。 | 跨作用域引用、查询、恢复、确认和链接均被拒绝，公开响应不泄漏其他 workspace 资源。 |
| `PB-NFR-005` | 完整原稿验收必须覆盖 139,723 字、60 集和代表集人工细查，不以执行时长为质量指标。 | 机器统计覆盖全部 60 集；E01、E07、E09、E31、E36、E60 只作人工细查；缺少原稿或独立基线时保持未验收。 |

## 接口最低契约

- `POST /api/document-revisions/{revision_id}/production-bibles`
- `GET /api/production-bibles/{bible_id}`
- `POST /api/production-bibles/{bible_id}/resume`
- `POST /api/production-bibles/{bible_id}/review-issue-resolutions`
- `POST /api/production-bibles/{bible_id}/confirm`
- `GET /api/projects/{project_id}/production-bible`

取消、完整 issue resolution 和影响分析必须遵循统一命令边界，并满足上述需求；不得以直接
数据库修改作为公开接口。

## 状态契约

主流程：

```text
queued → running → needs_review → confirmed
```

异常或替代状态：

- `failed`：确定失败，可修正后发起新运行或在合法 checkpoint 上 resume。
- `unknown`：Provider 结果不确定，只能对账或正式 resume。
- `cancelled`：用户明确取消，旧运行不得再写入。
- `superseded`：项目存在更新 document revision 的 confirmed Bible。
