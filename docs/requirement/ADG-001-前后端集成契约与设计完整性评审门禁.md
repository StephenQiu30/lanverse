# ADG-001 前后端集成契约与设计完整性评审门禁

## 1. 目的与适用范围

本门禁用于判断需求是否就绪、是否已转化为足够完整的设计，以及实现是否具备发布证据。它不代替具体架构设计、实现 Plan 或 Acceptance，而是规定各检查点必须回答的问题。

Design 草案可在需求处于 `review` 且无已知 P0 冲突时编写；Design 转为 `accepted` 或进入 PRD 前，适用需求必须 `accepted` 并通过 `design_entry` 门禁。实现只能在 Design、PRD 与可执行 Plan 均被接受后开始；实现完成后先回填并验证 Acceptance，再以运行证据通过 `implementation_release` 门禁并形成发布结论。

## 2. 强制前后端集成契约

| 编号 | 契约主题 | 必须明确的内容 |
| --- | --- | --- |
| ADG-001-001 | 身份与租户 | 登录方式、会话、主体、工作空间、项目上下文、权限错误和撤销传播 |
| ADG-001-002 | 标识与版本 | 公开对象标识、不可变版本、当前基线、当前采用、ETag/版本号和冲突处理 |
| ADG-001-003 | 命令幂等 | 幂等键的适用操作、作用域、有效期、重放结果和并发行为 |
| ADG-001-004 | 错误模型 | HTTP 状态、稳定错误码、用户可读信息、字段问题、可重试性和请求关联标识 |
| ADG-001-005 | 查询与分页 | 过滤、稳定排序、游标、页大小、空结果、权限过滤和最大结果范围 |
| ADG-001-006 | 时间与数值 | UTC RFC 3339、时区展示、货币最小单位、比例精度、timebase 与整数 tick/帧 |
| ADG-001-007 | 文件传输 | 允许类型、大小、分片、断点、校验和、隔离、签名授权、过期和删除传播 |
| ADG-001-008 | 异步任务 | 任务、批次、尝试、候选、状态机、进度、SSE 游标、取消、重试和迟到结果 |
| ADG-001-009 | 实时协同 | 是否启用、连接授权、消息版本、顺序、重放、掉线恢复和权威状态收敛 |
| ADG-001-010 | 缓存与兼容 | 客户端及边缘缓存、失效条件、契约版本窗口、弃用期和旧制品行为 |
| ADG-001-011 | 审计与遥测 | 关联标识、关键操作、前后端版本、敏感字段排除和证据查询入口 |
| ADG-001-012 | 安全响应 | 会话过期、权限撤销、CSRF、CSP、外部审片令牌、上传隔离和用户提示 |

所有 HTTP 契约必须纳入 OpenAPI 3.1；SSE、WebSocket、供应商回调和事件契约必须使用可版本化的机器可读模式。Design 阶段提供模式、示例和契约测试计划，实施阶段再以生产者/消费者测试结果验收。

### 4.5 实现后发布验收门禁

`implementation_release` 只在实现和 Acceptance 验证完成后执行，用于授权发布而非授权开始实现；实现开始条件是适用 Requirement、Design、PRD 和可执行 Plan 均为 `accepted`，且 Design 已通过 `design_entry`。

| 编号 | 通过条件 |
| --- | --- |
| ADG-001-043 | Design、PRD 和 Plan 均为 `accepted`，实现范围与版本和需求追踪一致。 |
| ADG-001-044 | OpenAPI 生成客户端、模式校验及生产者/消费者契约测试在 CI 中通过。 |
| ADG-001-045 | 代表性单集 E2E 和规定的失败恢复、兼容、性能、安全及可访问性测试通过。 |
| ADG-001-046 | staging 证据可从用户动作追踪至 API、Workflow、Activity、Provider、成本和输出，SLO 告警可触发。 |
| ADG-001-047 | 发布/回滚、备份恢复和至少一个供应商故障手册已演练；证据、责任人及残余风险进入 Acceptance。 |

## 5. 评审结论与否决条件

每次结论必须注明 `gate_scope: requirement_readiness | design_entry | implementation_release`，且仅允许：

- `passed`：该 scope 的全部 P0 条件已满足，可进入其规定的下一阶段。
- `conditional`：不存在安全、数据完整性或不可逆阻断；每个缺口均有责任人、完成日期、影响范围和关闭证据。
- `failed`：不得进入该 scope 的下一阶段。

出现任一情况必须判定为 `failed`：

- 未解释或未追踪的 P0 需求。
- 同一正式事实存在多个可写来源，或没有明确事实源。
- 长任务、费用、审核、交付或删除缺少失败恢复与幂等设计。
- 缺少租户、安全、隐私或外部供应数据边界。
- 不可逆数据迁移、供应商锁定或技术替换没有退出方案。
- Design 缺少可执行验证方案，或实施后无法提供测试、演练、样片及运行指标证据。

## 6. 评审职责与记录

| 责任方 | 必须确认的内容 |
| --- | --- |
| 产品与业务 | 范围、流程、角色、状态、例外和验收结果 |
| 架构 | 边界、事实所有权、质量属性、权衡和 ADR |
| 前后端研发 | 可实现性、契约、迁移、兼容和工程门禁 |
| QA | 可测试性、环境、样本、自动化与证据充分性 |
| 安全与治理 | 威胁、租户、隐私、权利、合规和残余风险 |
| 运维 | 部署、观测、告警、恢复、容量、成本和运行手册 |

评审记录必须保存评审范围、输入版本、结论、条件、责任人、目标日期、残余风险和批准人。任何影响公开契约、事实所有权、安全边界或恢复目标的变更均须重新执行受影响门禁。

## 7. 验收标准

- AC-ADG-001：`design_entry` 时，第 3 节的 14 类交付物均可定位到评审版本，且没有“待设计”占位符掩盖 P0 决策。
- AC-ADG-002：`design_entry` 时，第 2 节契约均有目录、字段规则、代表性机器可读模板、示例、错误场景和测试计划；`implementation_release` 时完整机器可读契约及对应自动测试通过。
- AC-ADG-003：随机抽取任意 P0 需求，Design 时可追踪到设计与计划验证位置，实施后可继续追踪到实现计划和验收证据。
- AC-ADG-004：评审结论、条件和残余风险符合第 5 节状态语义并由相应责任方确认。
- AC-ADG-005：任何运行测试、样片、演练、观测或运行手册验收，只能在接受的可执行 Plan 之后作为实施证据产生。
