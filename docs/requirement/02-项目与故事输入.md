# 项目与故事输入

## 1. 范围

本能力让单一操作者创建一个仅含一集的本地项目，输入中文故事并形成可被剧本生成固定引用的来源版本。

## 2. 主流程

1. 操作者创建项目，填写标题并使用固定制作规格。
2. 操作者选择 `original` 或 `licensed` 权利依据，并粘贴规范化后 300～3000 个 Unicode 代码点且至少含一个 Han 字符的中文故事。
3. 系统按 `text-normalization-v1` 规范化并校验范围，创建不可变来源快照及内容哈希。
4. 操作者确认当前来源版本；后续编辑产生新草稿，不覆盖旧版本。
5. 剧本生成只引用明确的已确认来源版本。

## 3. 功能需求

| 编号 | P0 需求 | 验证 |
| --- | --- | --- |
| FR-001-001 | 系统应在创建项目时原子建立具有稳定标识、1～120 Unicode 代码点标题和唯一 Episode 的项目；标题按 NFC 与首尾空白规则规范化，不得提供创建第二集的 MVP 接口。 | AC-001-001 |
| FR-001-002 | 系统应把画幅 9:16、分辨率 720×1280、帧率 24fps、目标时长 30～60 秒记录为项目制作规格。 | AC-001-002 |
| FR-001-003 | 系统应只在权利依据为 `original` 或 `licensed` 之一时接收规范化后 300～3000 个 Unicode 代码点、至少含一个 Han 字符且不含禁用代码点的纯文本故事；否则拒绝且不创建版本。 | AC-001-003 |
| FR-001-004 | 系统应为每次有效保存建立不可变 SourceRevision，记录正文、字符数、SHA-256、创建时间和父版本引用。 | AC-001-004 |
| FR-001-005 | 系统应允许操作者确认唯一当前 SourceRevision；修改已确认内容只能创建新草稿。 | AC-001-005 |
| FR-001-006 | 系统应在项目重新打开或服务重启后恢复项目、当前来源和全部历史来源版本。 | AC-001-006 |
| FR-001-007 | 系统应在来源变化后保留原剧本、分镜和任务输入；引用旧来源的下游版本、候选与已受理 Task 状态均不得改写，只通过查询投影显示 `input_outdated=true`。 | AC-001-007 |

## 4. 业务规则

- BR-001-001：每个 Project 恰好包含一个 Episode，所有操作发生在同一受信本地操作者运行边界内。
- BR-001-002：自动保存不等于来源确认。
- BR-001-003：`text-normalization-v1` 先要求输入是 Unicode 标量序列，将 CRLF/CR 转为 LF、执行 Unicode NFC、移除正文首尾 Unicode `White_Space`，再按全部 Unicode 代码点计数。规范化正文必须至少含一个 `Script=Han` 代码点，并拒绝除 LF/U+000A 与 TAB/U+0009 外的 C0/C1 控制符（U+0000～001F、U+007F～009F）、Unicode noncharacter 和孤立 surrogate；Unicode 数据版本与规范化实现以 PLAN-02 锁定的 Python 3.13 运行时为准，前端只能使用同一组边界夹具预校验，服务端结果始终权威。SHA-256 对规范化 UTF-8 字节计算，保存内容必须与哈希输入一致。
- BR-001-004：来源版本一经被剧本或任务引用不得修改或删除。
- BR-001-005：来源确认只表示创作输入固定，不表示剧本、镜头或媒体已经完成。

## 5. 数据要求

- DR-001-001：Project 只保存 `project_id`、标题、固定画幅/分辨率/帧率/时基、`active` 状态和时间戳；项目读取投影从唯一 Episode 合并目标时长，不在两表复制同一时长事实。
- DR-001-002：Episode 至少保存 `episode_id`、`project_id`、目标时长范围和当前来源引用。
- DR-001-003：SourceRevision 至少保存稳定标识、父版本、规范化正文、规范化规则版本、字符数、SHA-256、`rights_basis`、`rights_declared_at`、状态和创建时间。
- DR-001-004：下游对象只保存来源版本引用，不复制并修改来源正文。

## 6. 异常与恢复

| 场景 | 必须行为 |
| --- | --- |
| 文本越界或无效 | 不创建来源版本；越界返回规范化后实际代码点数和允许范围，无 Han 或禁用代码点返回稳定字段错误及首个违规位置。 |
| 相同提交被重放 | 返回原保存结果，不创建重复版本。 |
| 保存后响应丢失 | 重新查询可取得已形成的来源版本。 |
| 已确认来源被编辑 | 创建新草稿，旧版本及其下游引用保持不变。 |

## 7. 验收标准

- AC-001-001：标题 0/1/120/121 代码点分别被拒绝/接受/接受/拒绝；创建项目的单次事务同时返回 Project 与唯一 Episode，OpenAPI 不含创建 Episode Operation，应用用例或数据库尝试写入第二集均被稳定约束拒绝。
- AC-001-002：读取项目可得到 9:16、720×1280、24fps 和 30～60 秒完整规格，调用方不能保存冲突值。
- AC-001-003：未声明权利时任何正文均被拒绝；声明后，含 Han 的 299/300/3000/3001 个规范化代码点分别被拒绝/接受/接受/拒绝；各 300 代码点的全非 Han、含禁用 C0/C1、noncharacter 或孤立 surrogate 夹具均被拒绝且不产生 SourceRevision，合法中文正文可包含 LF、TAB、数字、中文标点和拉丁字母。
- AC-001-004：NFC/NFD、CRLF/LF 和首尾空白夹具得到规范规定的正文、字符数和哈希；编辑有效正文后产生不同标识和哈希，旧 SourceRevision 不变。
- AC-001-005：确认版本 A 后编辑只产生草稿 B，当前确认仍为 A，直至显式确认 B。
- AC-001-006：重启 API 与数据库连接后重新打开项目，项目、当前来源和版本历史与重启前一致。
- AC-001-007：确认新来源后，引用旧来源的下游版本、候选和 Task 内容/状态均未改变，相关查询统一显示 `input_outdated=true`。
