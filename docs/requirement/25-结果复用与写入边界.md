# REQ-25 结果复用与写入边界

| 项 | 内容 |
| --- | --- |
| 需求 | GEN-05 相同输入复用结果；GEN-10 任务不覆盖人工配置 |
| 优先级 | MVP |
| 用例 | UC-16 |
| 页面 | 报价确认组件、镜头详情 |
| 依赖功能 | REQ-21 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

两个跨功能的规则：一是完全相同的输入不重复付费（成本杠杆，PRD-01 §11）；二是异步任务只写自己的结果，不覆盖用户在任务期间做的修改（LibTV 的 `registerWritableByTask` 做法，PRD-02 D3）。

### 1.2 用户故事

- 作为**制作者**，我希望重复提交完全相同的生成请求时不再重复付费，需要时可以强制重新生成。
- 作为**制作者**，我在任务运行期间修改镜头参数，不希望任务完成后把我的修改覆盖。

### 1.3 范围

包含：输入指纹、复用判断、强制重做、任务写入白名单。

## 2. 需求分析

### 2.1 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 输入指纹 `input_hash` = sha256(能力、模式、供应商模型 ID、规范化参数、按序的输入（用途、引用类型、引用 ID、版本、媒体 sha256）、最终提示词) | 相同即相同 |
| R2 | 规范化参数：去除默认值、键排序、数值统一格式；`seed` 为空时视为“随机”，**随机种子的请求不复用** | 随机生成用户期望不同结果 |
| R3 | 同项目内存在相同指纹的 `completed` 操作 → 报价 0，确认后把其输出关联为新操作的输出 | GEN-05 |
| R4 | 用户选择“强制重新生成”→ 忽略复用，正常报价 | GEN-05 |
| R5 | 任务可写字段白名单：`operation.*` 的状态与结果字段、`operation_output`、`media_asset`（生成结果）、`shot.progress`、`canvas.node.last_operation_id`；其他业务字段只由用户命令修改 | GEN-10 |
| R6 | 任务结果关联的是创建时的目标版本（`target_version_no`）；目标已有新版本时，结果仍作为候选出现并标记“基于旧版本” | GEN-10 |

### 2.2 异常与边界

- 复用的原输出后来审核被判定违规：复用同样不可选定。
- 复用跨项目：不允许（数据隔离）。

## 3. 实现所需

### 3.1 数据

`operation.operation.input_hash`、`reused_from_id`、`force_regenerate`、`target_version_no`；索引 `ix_operation_reuse (project_id, input_hash) WHERE status = 'completed'`。复用时新建 `operation_output` 行指向同一 `media_asset_id`（不复制对象）。

写入边界在代码层实现：工作流的 `flow` Activity 只能调用 `operation` 模块的结果写入端口与 `storyboard` 的 `UpdateProgress` 端口；架构测试（`go-arch-lint` 规则）禁止 Activity 包依赖其他模块的命令用例。

### 3.2 接口

报价响应项含 `reused: true`、`reused_from_operation_id`；请求项支持 `force_regenerate: true`（见 REQ-21）。

### 3.3 异步与工作流

复用项确认后不启动供应商流程：`OperationWorkflow` 直接执行 `flow.CompleteFromReuse`。

### 3.4 事件与实时

同 REQ-21。

### 3.5 界面

报价对话框中复用项显示“复用已有结果 ¥0”与“强制重新生成”开关；候选卡片显示“基于 vN 生成”。

### 3.6 权限与审计

审计 `operation.confirmed` 中记录 `reused_from`。

### 3.7 非功能要求

REL-02、COST-01。

## 4. 验收标准

- Given 镜头 3 已用相同输入（固定种子）生成成功，When 再次请求报价，Then 报价显示“复用已有结果，费用 0”。
- Given 视频任务进行中，When 用户修改该镜头时长并保存，Then 任务完成后镜头时长仍为用户修改后的值，结果作为新候选出现并标记基于旧版本。
- Given 种子为空（随机），When 用相同参数再次报价，Then 正常计费。

## 5. 测试要点

`input_hash` 规范化的表驱动测试（等价与不等价用例）；架构依赖规则测试。
