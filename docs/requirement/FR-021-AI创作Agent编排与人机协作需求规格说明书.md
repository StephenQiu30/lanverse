# FR-021 AI 创作 Agent 编排与人机协作需求规格说明书

## 1. 目的与范围

让 AI Agent 协助完成来源理解、故事骨架、改编策略、剧本、导演规划、资产提案和分镜策划，同时保证正式产物、权限、费用和阶段流转仍由平台契约及有权人员控制。

本能力管理 Agent 协作、结构化产物、工具调用、复核和记忆；不允许 Agent 自行批准基线、采用媒体、交付成片或改变角色权限。

## 2. 参与角色与职责

| 角色 | 职责 | 禁止事项 |
| --- | --- | --- |
| Planning Agent | 理解目标并提出结构化执行计划 | 直接修改正式产物或批准阶段 |
| Execution Agent | 在指定阶段调用白名单工具，产生候选修订版 | 扩大任务范围或绕过领域规则 |
| Review Agent | 独立检查来源、结构、连续性和质量，形成复核报告 | 修改被审产物或代替人工批准 |
| 创作责任人 | 发起、修改、接受、退回或拒绝 Agent 产物 | 越过自身业务权限 |
| 管理/治理角色 | 发布 Skill/Prompt、配置工具及模型策略、审计异常 | 读取无授权项目内容 |

## 3. 主业务流程

1. 用户选择项目、阶段、业务目标和输入版本。
2. Planning Agent 提出范围、依赖、步骤、预计费用和需人工决定事项。
3. 用户确认计划；系统校验权限、工具、模型、预算、权利和安全策略。
4. Execution Agent 通过领域命令产生一个或多个结构化候选修订版。
5. Review Agent 依据独立规则形成问题、严重度、证据和建议，不修改产物。
6. 有权责任人接受、要求修改或拒绝；接受只选定或形成领域草稿，基线确认仍须执行 FR-004 定义的独立授权命令。
7. 系统保留运行、工具、费用、产物、复核和人工决定的完整追踪。

## 4. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-021-001 | 系统应明确区分 Planning、Execution 和 Review Agent 的职责及可调用工具。 | P0 |
| FR-021-002 | 系统应允许不同创作阶段绑定独立的模型、Prompt、Skill、工具白名单和预算策略。 | P0 |
| FR-021-003 | 系统应在执行前展示目标、输入版本、步骤、预计用量、风险和人工门禁。 | P0 |
| FR-021-004 | 系统应要求用户明确确认会产生费用或修改业务草稿的执行计划。 | P0 |
| FR-021-005 | 系统应把 Agent 生成的事件、骨架、策略、剧本、导演规划、资产和分镜保存为结构化候选修订版。 | P0 |
| FR-021-006 | 系统应将 Agent 写操作限定为已授权领域命令，并在服务端重新校验主体、对象、版本和动作。 | P0 |
| FR-021-007 | 系统应记录每次 AgentRun 的业务输入、Agent 类型、模型、Provider、Prompt、Skill、工具权限和配置版本。 | P0 |
| FR-021-008 | 系统应记录每个工具步骤的参数摘要、结果引用、耗时、用量、错误和关联业务对象。 | P0 |
| FR-021-009 | 系统应允许取消、重试或从失败步骤重新执行，并保留既有运行和产物。 | P0 |
| FR-021-010 | 系统应在输入版本变化时把未执行计划或既有结果标记为过期，并阻止静默继续。 | P0 |
| FR-021-011 | 系统应由独立 Review Agent 形成带规则、证据、严重度和建议的复核报告。 | P0 |
| FR-021-012 | 系统应阻止 Review Agent 批准自身或其他 Agent 的产物。 | P0 |
| FR-021-013 | 系统应允许有权责任人接受、要求修改或拒绝候选，并记录理由与决定时间；接受不得隐式确认基线。 | P0 |
| FR-021-014 | 系统应确保 Agent 对话、摘要或检索记忆不被用于决定权限、余额、审核、采用、交付或正式叙事事实。 | P0 |
| FR-021-015 | 系统应按工作空间、项目、用户、Agent 和用途隔离记忆，并保存来源、保留期限及删除状态。 | P0 |
| FR-021-016 | 系统应允许用户查看本次运行实际引用的记忆和业务来源，并排除无权或已失效内容。 | P0 |
| FR-021-017 | 系统应把素材中的指令视为内容，不得因此扩大工具、网络、数据或审批权限。 | P0 |
| FR-021-018 | 系统应为 Prompt 和 Skill 提供草稿、发布、停用、版本比较、回归验证和回滚。 | P0 |
| FR-021-019 | 系统应提供不依赖对话的结构化页面入口，使用户可查看、编辑、复核和批准所有正式候选。 | P0 |
| FR-021-020 | 系统可提供生产画布展示实体、依赖、来源、产物和复核关系，但画布不得成为业务内容唯一事实源。 | P1 |
| FR-021-021 | 系统应允许从权威业务数据重建画布，并只把布局、折叠、缩放和实体引用作为画布状态。 | P1 |
| FR-021-022 | 系统应在切换项目或分集前提示仍在运行的 Agent/生产任务，并保证异步结果写回原作用域。 | P0 |

## 5. 业务规则

- BR-021-001：Agent 运行成功不等于内容正确、复核通过、基线确认、媒体采用或交付批准。
- BR-021-002：决策建议、执行产物、复核报告和人工决定是四类独立事实。
- BR-021-003：Prompt 负责创作方法，不承担权限、事务、状态机或合规门禁。
- BR-021-004：记忆和检索结果只能提供上下文，正式事实必须引用权威对象及版本。
- BR-021-005：模型或 Agent 的显示名称不产生系统权限。
- BR-021-006：画布和聊天记录丢失不得造成正式产物、任务或审核证据丢失。

## 6. 数据与权限要求

- DR-021-001：保存 AgentRun、AgentStep、AgentReview、输入/输出版本、状态、父运行和重试关系。
- DR-021-002：保存 PromptVersion、SkillVersion、模型能力、工具授权快照、发布审批和回滚关系。
- DR-021-003：保存引用的来源片段、故事事实、记忆快照及其作用域、版本、置信度和保留状态。
- DR-021-004：P1 画布保存视图、节点、连线、实体引用、布局和 schema 版本，不复制完整业务对象。
- 创作责任人只能在其项目权限内发起和决定；Skill/Prompt 发布、工具开放和记忆策略由工作空间管理员或治理角色单独授权。

## 7. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 模型、工具或结构化输出失败 | 保留已完成步骤并说明可重试范围，不把半成品标记为通过。 |
| 输入在执行中发生变化 | 保留原输入运行并将结果标记待复核，不自动换入新版本。 |
| Review Agent 与创作责任人意见不同 | 同时保留报告与人工理由，由人工门禁决定，不改写报告。 |
| 检索到无权、过期或来源不明内容 | 排除该内容并记录诊断，不将其注入 Agent。 |
| 画布数据损坏或版本不兼容 | 从权威实体重建默认视图，不修改业务事实。 |
| 用户切换项目或分集 | 运行继续绑定原作用域；新页面不得接收错误上下文的结果。 |

## 8. 验收标准

- AC-021-001：任一 Agent 候选可反查输入来源、模型、Prompt/Skill、工具步骤、用量、复核和人工决定。
- AC-021-002：Review Agent 无法调用批准、采用、交付或权限变更命令。
- AC-021-003：输入版本变化后，旧计划无法未经再次确认继续产生正式候选。
- AC-021-004：提示注入样本无法扩大工具白名单、访问其他项目或读取秘密。
- AC-021-005：清空 Agent 记忆和画布后，已确认产物、任务、审核和费用保持不变且可恢复展示。
- AC-021-006：切换分集期间完成的异步结果只出现在原分集，并可从任务和运行记录回跳。
- AC-021-007：Prompt/Skill 回滚后，新运行使用目标版本，历史运行仍显示原版本。
