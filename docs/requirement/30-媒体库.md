# REQ-30 媒体库

| 项 | 内容 |
| --- | --- |
| 需求 | MED-01 上传素材；MED-02 浏览、检索与预览；MED-03 删除素材；MED-04 来源与合规信息 |
| 优先级 | MVP |
| 用例 | UC-20 |
| 页面 | 媒体库、上传对话框、媒体详情 |
| 依赖功能 | REQ-17 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

全能参考需要动作 / 运镜参考视频、参考音频；关键帧、音轨也可上传。所有媒体（上传、生成、渲染）统一管理：可检索、可追溯来源与合规状态，被正式引用的素材不能误删。

### 1.2 用户故事

- 作为**制作者**，我希望上传图片、视频、音频，快速找到并预览素材，删除不用的素材，并能看到每个素材的来源与合规信息。

### 1.3 范围

包含：直传上传（含分片）、自动探测、缩略图 / 代理 / 波形、内容审核、浏览筛选检索、预览、引用保护删除、回收与清理、来源与合规展示。不包含：素材标签体系与 AI 检索（后续）、跨项目共享素材库。

## 2. 需求分析

### 2.1 业务流程

见 [DES-03 §4.13](../design/03-接口设计.md#413-上传流程)：申请上传 → 预签名直传 → 完成通知 → MediaIngestWorkflow（按内容识别类型 → ffprobe → sha256 → 缩略图 / 代理 / 波形 → 审核）→ `ready` / `rejected` / `failed`。

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 格式与大小：图片 jpg / png / webp ≤ 20 MB；视频 mp4 / mov ≤ 500 MB 且 ≤ 60 秒；音频 mp3 / wav / m4a ≤ 100 MB；文档 docx / txt ≤ 20 MB（剧本） | MED-01 |
| R2 | 选择文件时前端先校验；服务端按文件内容（magic bytes + ffprobe）再校验，不信任扩展名 | SEC-07 |
| R3 | 只有 `ready` 且审核通过的素材可被引用 | SB-04 |
| R4 | 被正式对象引用（锁定参考、参考组合当前版本、选定关键帧 / 片段 / 音频、剪辑计划当前版本、成片）的素材不能删除，返回引用位置 | MED-03 |
| R5 | 删除为逻辑删除，30 天后清理对象存储与记录 | DAT-05 |
| R6 | 同一项目内 sha256 相同的上传提示“已存在相同文件”，可选择复用 | 节省存储 |
| R7 | 生成结果自动入库（`origin = generated`），记录供应商、模型、区域、生成操作 | MED-04、CMP-06 |
| R8 | 媒体访问一律使用 ≤ 1 小时的预签名 URL | SEC-06 |

### 2.3 状态

`uploading` → `processing` → `ready` | `rejected` | `failed`；`ready` → 逻辑删除 → 清理（REQ-03 §6.7）。

### 2.4 异常与边界

- 上传中断：分片上传可续传（24 小时内）；普通上传重新开始。
- 审核服务不可用：素材停留在 `processing`，审核恢复后继续；超过 1 小时提示。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `media.media_asset` | `kind`、`origin`、`status`、`object_key`、`mime_type`、`byte_size`、`sha256`、宽高时长帧率编码、`source_operation_id`、`provider_key`、`model_key`、`region`、`moderation_status`、`aigc_marked`、`consent_record_id`、`contains_real_person`、`is_delete`、`delete_time`、`purge_after` | 统一媒体元数据 |
| `media.rendition` | `thumb_256`、`thumb_640`、`poster`、`proxy_720p`、`waveform` | 列表与预览性能 |
| 对象存储 | `projects/{pid}/{kind}/{yyyy}/{mm}/{id}.{ext}`；渲染版本 `…/{id}/{rendition}.{ext}` | 按项目前缀便于清理 |

新增 `media_asset.upload_id text`（分片上传 ID）与 `sha256` 部分索引（`project_id, sha256 WHERE NOT is_delete`，DES-02 同步）。

### 3.3 异步与工作流

`MediaIngestWorkflow`（`media-ingest/{id}`）：`media.DetectAndProbe` → `media.Hash` → `media.MakeRenditions`（并行）→ `agent: moderation.check` → `flow.MarkMediaReady`。`MediaPurgeSchedule` 每日清理。

### 3.4 事件与实时

`media.asset_status_changed.v1` → realtime；SSE `media.updated`。

### 3.5 界面

媒体库网格 / 列表切换（虚拟滚动）、筛选栏、搜索；拖拽上传区（多文件进度、失败原因）；预览（图片灯箱、视频播放器、音频波形）；详情抽屉（来源、合规、引用位置）。

### 3.6 权限与审计

制作者；审计 `media.deleted`、`media.restored`。

### 3.7 非功能要求

PERF-07（上传速度 ≥ 带宽 70%，处理 ≤ 30 秒）；PERF-04（2,000 条筛选 ≤ 1 秒）；SEC-06、SEC-07；CMP-03。

## 4. 验收标准

- Given 上传 300 MB 视频，When 上传完成，Then 显示时长、分辨率与缩略图，状态为就绪。
- Given 项目有 2,000 个媒体条目，When 按“视频、已被引用”筛选，Then 1 秒内返回结果并可预览。
- Given 某视频被镜头 8 选定，When 删除，Then 被拒绝并提示“被第 1 集镜头 8 使用”。
- Given 一段经 OpenRouter 生成的视频，When 查看详情，Then 显示供应商、模型、服务区域“境外”。
- Given 把 exe 文件改名为 mp4 上传，When 处理，Then 状态为失败，原因“文件类型不符”。

## 5. 测试要点

内容类型识别；分片上传续传；引用检查覆盖全部引用来源（表驱动）；清理任务。
