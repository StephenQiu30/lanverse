## 1. 产品定义

### 1.1 要解决的核心问题

AI 短剧制作不是“输入一句话得到一条成片”的单次生成。创作者需要把剧本转换为稳定的人物、场景、道具、叙事单元和有序镜头，逐镜尝试多个结果，根据表演、一致性和生成质量选择当前视频，并能将一集所有已选镜头交给外部后期。

现有工具的常见失败是：

- AI 分析和生成结果没有稳定身份，修改上游后无法知道哪些镜头已过期；
- 一个镜头的多个候选、星标备选和当前主选语义混乱；
- 任务失败、断线或重试时，用户不知道是否已产生外部 Provider 消耗、是否可安全重试；
- 批量下载结果缺少固定顺序、版本、hash 和来源，无法稳定交接；
- 连续预览、批量下载、时间线和成片被混为同一件事，造成范围失控。

### 1.2 产品承诺

> 创作者可以在一个 Workspace 内从原始剧本出发，得到可人工修订的资产和分镜，逐镜生成并选择视频，最终导出严格按镜头顺序组织、来源可追溯的独立视频素材包。

本产品的当前完成结果不是成片。用户获得的是一组可交给外部剪辑工具或后期人员继续处理的镜头视频素材。

## 2. 产品目标与成功指标

### 2.1 核心目标

1. 将“剧本到镜头包”变为一条用户能理解、能暂停、能恢复、能局部返工的稳定流程。
2. 用稳定 ID、不可变版本和影响提示保持角色、场景、道具和镜头的连续性。
3. 使每个镜头的候选、主选、失败、过期和恢复动作清晰可解释。
4. 使每个导出包都能回答“导出了哪些镜头、每镜用了哪个结果、结果从何而来”。
5. 在不引入剪辑与成片的前提下，把产品的创作体验、可靠性和对外交接打磨完整。
6. 由唯一的 Production Harness 管理从剧本导入、深度理解、资产、分镜、生成、审核到交付的阶段、门禁、人工确认、恢复和重入；项目页只展示其可解释快照。

### 2.2 产品验收指标

以下是进入开发前的目标值，正式数值须在用户研究和 Provider PoC 后签认：

| 维度 | 目标 | 测量方式 |
| --- | --- | --- |
| 任务完成性 | 新用户在无人代操时可完成“打开待处理镜头 → 比较候选 → 设为主选 → 发起导出” | 至少 5 名目标用户任务测试，成功率目标 ≥90% |
| 问题可定位 | 完整包被阻断时，用户可从摘要一步进入具体问题镜头 | 缺主选、失败、生成中、已过期、媒体异常各至少 1 个用例 |
| 局部返工 | 一镜重做不破坏其他镜头的成功候选、主选或历史包 | 独立失败/重试/重选验收 |
| 导出完整性 | `scope=complete` 包中独立视频数量等于目标 StoryboardBaseline 的全部 active Shot 数，Manifest 可解析，每个 hash 可复核 | 自动契约与真实持久媒体故障验收 |
| 历史不漂移 | 导出 ready 后重选或重排镜头，既有 PackageBuild 及其清单/hash 不变；包过期后基于同一 Snapshot 重建必须新建 PackageBuild，并按 CUR-EXP 的双层 hash 规则验收 | 前后比较、同构建重下与过期重建验收 |
| 生成可解释 | 任务失败或未知时展示错误概要、是否可重试和下一动作 | 真实 Provider 与故障注入用例 |
| 范围守恒 | 任何当前验收不依赖时间线、拼接、字幕、音频后期或成片 | Requirement/Design/Plan 追踪检查 |

## 3. 用户与角色

### 3.1 主要用户

**一体化创作者（owner/editor）**：可能同时承担编剧、导演、AI 生成操作和内部质检。他关心的不是底层模型调用，而是镜头是否表达正确、主体是否一致、哪些镜头需要重做、是否可以安全导出。

### 3.2 次要用户

**只读查看者（viewer）**：可查看项目、镜头进度、候选、当前主选和已生成包摘要/Manifest 摘要，但不能提交会产生外部 Provider 消耗的任务、改变主选、冻结新包或下载原始候选/素材包。

### 3.3 当前不建立的角色体系

- 外部客户审片人；
- 财务、订阅或营销运营人员；
- 发行、备案或平台投放人员；
- 企业多级管理员与自定义权限策略编辑器。

## 4. 端到端价值流

```mermaid
flowchart LR
    W["Workspace"] --> A["剧本导入与确认"]
    A["剧本导入与确认"] --> B["剧本理解与分集语义"]
    B --> C["角色/场景/道具资产"]
    C --> D["有序分镜与 ShotSpec"]
    D --> E["关键帧/参考图主选"]
    E --> F["逐镜视频生成"]
    F --> G["候选比较与每镜唯一主选"]
    G --> H["完整性/兼容性预检"]
    H --> I["冻结镜头素材包"]
```

Production Harness 控制上述阶段的顺序、输入版本、门禁、人工等待、恢复和重入；项目页只消费其快照。CUR-CAN 属于 post-MVP 的可视化投影，不是当前流程控制面。

每个阶段必须返回：

- 当前固定的输入；
- 已完成、待处理和阻断数量；
- 具体阻断对象和原因；
- 用户当前可执行的下一动作；
- 上游变化对当前结果的影响。

## 6. 跨模块不变式

**Workspace 是制作流程的顶层授权与隔离作用域**：所有 Project、Episode、ProductionRun、StageRun、DocumentRevision/ScriptVersion、Candidate、WorkTask、Media 和 Export 都必须绑定当前 Workspace；一个 Workspace 可以包含多个相互隔离的短剧项目。ProductionRun 属于 Project 而不是 Episode，Episode/Shot/Package 通过 StageRun 的显式 scope 独立推进；Workspace 之间不共享制作事实，任何跨 Workspace 关系、查询、写入或外发都必须拒绝。

1. **稳定身份**：名称、显示镜号和当前排序都不得代替长期身份。
2. **版本不可变**：已被下游固定的剧本、资产、ShotSpec、关键帧、候选和包输入不得就地覆盖。
3. **人工决定显式**：AI 结果是候选；发布、当前主选、确认沿用和导出冻结都必须有明确决定。
4. **星标不等于主选**：星标是 Workspace 内 owner/editor 共享的追加式关注决定；一个镜头可有多个星标备选，但同一视频用途同时最多一个有效主选。
5. **正式导出不兜底**：工作台可临时预览最新成功候选；正式导出只能读取显式主选。
6. **上游变化不静默传播**：上游固定输入变化后，下游结果必须进入 stale 或返回影响提示，不自动改写历史。
7. **单镜头失败隔离**：一镜头的失败、取消或重试不得删除其他镜头已成功结果。
8. **历史包不漂移**：包冻结后，后续重排、重选或生成新候选不得改变既有 ExportSnapshot 或 PackageBuild；同一 PackageBuild 重下保持容器 hash，过期后从同一 Snapshot 重建必须形成新 PackageBuild，Manifest/逐文件 hash 相同而容器 hash 可不同。
9. **媒体不靠临时 URL 成为事实**：所有可选/可导出媒体必须已经持久化、探测并可校验。
10. **权限与治理 fail-closed**：CUR-IAM 授权或 CUR-SEC 权利/内容安全/Provider 数据处理准入无法确认时，不得默认允许新生成、主选、冻结、原始下载或新导出。
11. **拒绝主选必须失效**：当前主选被追加 `rejected` 决定后，Selection 必须进入 `needs_reselection`，对应 readiness 立即 blocked；拒绝动作不能静默改选其他 Candidate。
12. **Production Harness 是唯一流程控制面**：项目级运行、按作用域的阶段、门禁、人工等待、恢复和重入只能由 CUR-PROD/Production Harness 决定；任何页面或 Skill 不得自行推进阶段。单个 Episode/Shot 的阻塞不得回滚或强制等待其他已满足依赖的范围。
13. **Agent 先提议后执行**：高成本或破坏性动作必须先固定目标、影响、预计消耗、风险和有效期，由有权用户明确确认后才执行。
14. **长任务终态唯一**：CUR-PLT canonical 终态仅为 `succeeded`、`failed`、`cancelled`、`manual_attention`；`unknown` 是待对账状态，不得出现模块自造的 `reconciled_*` 等终态。
15. **容量语义分离**：CUR-SEC 安全硬上限、各业务模块真实样本签认的产品容量、低于产品容量的 UI 预警阈值必须分别记录与验收，不得与 Provider/商业额度混写。

## 7. 范围

### 7.1 当前必须包含

- 已验证 UserAccount、Workspace、Session、owner/editor/viewer 成员协作和统一授权；
- Project/Episode 稳定工作上下文与生产摘要；
- 剧本导入、分集、叙事结构、AI 候选与人工发布；
- Production Harness 从剧本导入开始的完整阶段控制、门禁、人工确认、恢复和重入；
- 每集标题、logline、摘要、hook、关键节拍、场景、人物、世界观、资产和制作任务建议等可追溯剧本理解候选；
- 角色、场景、道具的身份、剧情状态、视觉候选和版本影响；
- 有序分镜、镜头变换、叙事覆盖、readiness 和固定 ShotSpec；
- 镜头关键帧/参考图候选、当前选择和影响提示；
- 一个真实图片 Provider 和一个真实视频 Provider 的最小可验证能力；
- 逐镜任务、多候选、星标、唯一主选、stale、重生成和安全恢复；
- 单候选下载、`scope=partial` 镜头导出、`scope=complete` Episode 镜头包、Manifest 和历史重下；
- 使上述流程可靠所必需的权限、权利、内容安全、Provider 数据处理准入、媒体、血缘、长任务、数据生命周期和内部 Provider 消耗证据；不提供项目预算、币种或预算上限功能。

### 7.2 当前明确排除

- Timeline、Track、Clip、多轨剪辑、trim、变速、转场、特效、调色；
- 视频拼接、整集渲染、单一成片 MP4；
- 独立 TTS、配音、BGM、音效、字幕编辑、口型或音画同步；
- 剪映、Premiere、Final Cut Pro 工程文件；
- 对外发布、发行、备案工作台或短视频平台直投；
- 订阅、套餐、支付、发票、账单、退款、营销、CRM 与商业运营；
- 复杂企业组织、项目 ACL、实时多人协作、客户审片门户和匿名公开分享；
- 自托管 GPU 集群、模型训练、通用低代码工作流、任意技术节点编排或模型市场。
- Canvas/画布式制作视图、可视化编排器和画布内 Agent 操作；这些能力在业务闭环稳定后另行评审。

## 8. 发布切片与 Gate

切片只用于表达产品依赖，不在需求总览中承诺日历工期。

| Gate | 必须产生的用户结果 | 不能外推的结论 |
| --- | --- | --- |
| G-0 身份与治理基线 | 登录/会话、Workspace 授权、Provider 数据处理、权利和内容安全门禁可验证 | 已完成任一创作模块 |
| G-A 可信剧本理解与分镜 | 原稿、分集语义候选、场景/对白/人物/世界观/资产引用、资产状态、分镜覆盖/readiness 和固定分镜包可追溯 | 已生成图片、视频或短剧 |
| G-B 真实图片 | 真实图片候选、主选、媒体血缘、失败恢复和真实消耗闭环 | 已有视频结果 |
| G-C 逐镜视频 | 单镜/选定镜头生成、多候选、唯一主选、stale 和局部重做可用 | 已完成剪辑或成片 |
| G-D 镜头素材包 | `complete`/`partial` 导出、固定快照、原始独立视频、Manifest、hash 和历史重下可用 | 已获得连续成片或可直接发布内容 |

Production Harness 不是一个额外的业务产物 Gate，而是贯穿 G-0～G-D 的唯一控制面；每个 Gate 都必须由对应作用域的 StageRun、领域 readiness、WorkTask canonical 状态和人工决议共同关闭。Project 级状态聚合 Episode/Shot/Package 子范围，但不要求无关范围全局串行。CUR-CAN 暂不进入当前 Gate。

每个 Gate 只能在对应模块 Requirement 和 AC 已 accepted、真实外部条件已验证、成功/失败/边界/恢复经真实验收后关闭。

## 9. 跨模块失败原则

| 失败 | 必须呈现给用户 | 系统禁止做的事 |
| --- | --- | --- |
| AI 分析失败 | 原稿仍可读，失败批次、原因和重试/人工处理入口 | 把部分候选冒充为已发布结构 |
| Provider 不可用 | 不可用范围、原因、是否已发送、是否发生消耗和下一动作 | 伪造成功候选或盲目重发 |
| 媒体下载/登记失败 | 保留供应商任务或隔离媒体等可恢复证据 | 重新生成并再次产生 Provider 消耗 |
| 单镜生成失败 | 具体 Shot、错误、可否重试和当前可用候选 | 回滚同批其他 Shot 成功结果 |
| 导出预检失败 | 按 Shot 归类的 blocker/warning 与可导航修复入口 | 用最新候选补位、忽略 stale 或创建伪成功包 |
| 打包失败 | 固定快照、已完成步骤、错误和重试入口 | 重新生成视频或修改冻结选择 |

## 10. 需求完整性 Gate

一份模块需求进入 `accepted` 前必须满足：

1. 模块范围和非范围与本总览一致；
2. 所有 FR 均有稳定 ID、主流程、失败/边界流程和可测 AC；
3. 涉及 AI 或外部 Provider 的需求已明确人工决议、超时、失败、重试、不明状态与消耗语义；
4. 涉及版本的需求已明确稳定身份、当前投影、历史不可变和 stale 传播；
5. 涉及导出的需求已明确范围、顺序、冻结、完整性、幂等、失败恢复、权限与历史不漂移；
6. NFR 包含测量环境、样本规模、阈值或阈值待确认责任人；
7. 开放问题不得影响已宣称的硬边界。

## 11. 已决策与待决策

### 11.1 已决策

- 当前不实现剪辑、时间线和成片；
- 当前不建设商业运营与支付计费；
- 以逐镜候选、每镜唯一主选和有序镜头包为当前产品终点；
- 正式导出不得使用“最新成功候选”静默兜底；
- 当前产品不得在导出包中裁切、拼接、转码、添加字幕或处理音轨。
- CUR-DEC-002：Candidate 相对当前输入过期时，Selection 必须先进入 `needs_reconfirmation`；用户查看差异并追加绑定当前输入摘要、操作者和理由的重新确认后，Selection 才可恢复 `selected` 并进入正式导出，`complete` 与 `partial` 使用同一规则。
- CUR-DEC-003：正式素材包只包含每个目标 Shot 的唯一冻结主选；星标备选仅保留在候选历史并可单候选下载，不提供“备选包”变体。
- CUR-DEC-007：星标是 Workspace 内 owner/editor 共享的追加式决定；viewer 只读，星标不自动改变主选。
- CUR-DEC-008：当前主选被拒绝后进入 `needs_reselection` 并阻断正式生成交接/导出；系统不得自动选择其他 Candidate。
- CUR-DEC-009：viewer 不得下载原始候选或素材包；当前不提供匿名公开分享，owner/editor 下载后在平台外完成交接。
- CUR-DEC-010：MVP 不实现画布或可视化编排器；后续若引入，必须只作为原领域事实投影，不能成为第二流程控制面。
- CUR-DEC-011：ProductionRun 属于 Project；一个 Project 同时最多一个 current ProductionRun，Episode/Shot/Package 通过 StageRun scope 独立推进并保留历史。

## 12. 术语

| 术语 | 定义 |
| --- | --- |
| Candidate | 一次生成或受控上传形成的不可覆盖媒体候选 |
| 星标备选 | 用户认为值得保留的候选标记，不产生当前主选效力 |
| 当前主选 | 同一 Shot + 视频用途当前唯一生效的显式选择 |
| needs_reselection | 当前主选已被拒绝、不可用或不再允许作为选择，必须人工选择另一个 Candidate 的状态 |
| stale | 上游固定输入已变化，旧结果仍可追溯，但不得默认当作当前有效结果 |
| `scope=partial` 镜头包 | 只冻结并导出用户显式勾选的非空 active Shot 子集；Manifest/README 必须列出 included/excluded 数量与 Shot ID，不能暗示整集完成 |
| `scope=complete` Episode 镜头包 | 冻结目标 StoryboardBaseline 的全部 active Shot，且每镜都有合法主选的独立视频包 |
| 成片 | 经剪辑、时间编排、音画处理和渲染后的连续视频；不属于当前产品输出 |
