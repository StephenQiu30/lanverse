# 供应商需求

## 目标与范围

管理员能配置可用凭据，在更新失败时保留原配置。

本模块范围：供应商状态、安全摘要、候选密钥先测试后替换、测试当前连接。

建议执行顺序为编号顺序；编号不代表排期或已批准实施。本文件按业务模块整体维护，内部功能在同一文档列出，不为每个按钮、接口或技术层建立单独需求文件。

## 功能与数据要求

<a id="req-f-13"></a>

### 供应商凭据

#### 字段与数据量

| 区域     | 必须承载的字段                                                   | 设计归属                                       | 一次读取 / 保存的量                    |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| 供应商卡 | 名称、能力摘要、可用/测试失败/未配置、密钥掩码、最近测试、操作者 | provider当前配置与安全测试摘要                 | 所有已接入供应商的少量摘要；密钥不回显 |
| 新密钥   | API Key、可选Group ID、保存并测试                                | 仅服务端短时测试输入；成功才替换provider加密值 | 一次候选请求，失败不写为活动密钥       |

#### 功能与失败边界

| 用户动作              | 必须产生的结果                                  | 边界与失败                                                             |
| --------------------- | ----------------------------------------------- | ---------------------------------------------------------------------- |
| 配置 / 更新：先测后换 | 用新输入测试，成功后原子替换旧值并记操作者/时间 | 这是当前页面明确语义，不改成旧接口的先保存后测试；测试超时也保留旧密钥 |
| 测试当前连接          | 读取当前凭据在服务端测试并更新安全结果          | 连通、配额、鉴权失败分别归类；费用未知不能标免费                       |

## 范围边界

- 一次测试与替换足以承载页面，无需通用审批平台；需防并发覆盖。

## 依赖与待确认

依赖管理员授权与安全凭据存储；实际测试需具备真实供应商条件。

待确认：连接测试的具体操作、可能费用、超时与安全确认细节。

以上缺口只是评审问题，不构成新增产品能力或架构决策。既有功能和约束不因旧接口支持不足而删除或降级。

## 模块验收

1. 本文列出的字段和功能由真实数据及操作结果承载，成功/失败/权限/未接入状态明确，mock不作为业务通过。
2. 需要持久化的写入可刷新恢复；版本冲突保留输入，重复副作用按幂等合同核对；只读/瞬时状态不强加持久化。
3. 当前用户/项目范围服务端验证；管理动作限管理员，秘密不进入响应、普通日志、审计明文或导出。
4. 实现时补与本模块风险匹配的成功、失败、冲突/重复、越权场景，分别记录自动化、真实持久化、浏览器及外部供应商证据，未执行不得报通过。

统一要求见[非功能规格](02-非功能需求规格.md)和[交互需求](05-界面与交互需求.md)；当前均待评审、未完成真实功能验收。本阶段不列Sprint、工时或固定用例数量。
