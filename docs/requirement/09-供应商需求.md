# 供应商需求

## 1. 需求概述

**需求目标：** 管理员能配置可用凭据，在更新失败时保留原配置。

**使用者与价值：** 作为管理员，我希望验证供应商配置后安全替换凭据，使创作调用可用且更新失败不影响旧配置。

**问题背景：** 凭据卡和测试反馈尚为演示，不能证明服务器测试、秘密保护与原子替换。

| 属性     | 内容                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 业务角色 | 管理员                                                                      |
| 文档状态 | 原始需求整理稿，待评审；不是已接受的设计或已验收功能                        |
| 范围来源 | 本文件第7、8节保留的原规格、现有页面代码，以及已整理的跨模块流程            |
| 完成依据 | 第3节功能结果、第4节质量条件、第5节验收场景；待确认项解决后才能验收相应能力 |

## 2. 范围与边界

本模块包含：供应商状态、安全摘要、候选密钥先测试后替换、测试当前连接。

只管理当前供应商配置与测试，不新增审批平台；真实测试操作及费用仍须确认。

业务模块一份文档，内部需求编号仅用于追踪，不对应独立文件、接口、类或开发任务。编号不承诺排期。原资料中的存储名、组件名和分页建议不作为已接受架构。

## 5. 验收场景

下列是可执行的业务场景定义，尚未运行。实际测试按[生命周期方法](../软件生命周期与需求管理.md#测试与证据)记录环境、步骤、逐步预期与实际结果；功能行已给出独立验收条件，场景可联合验证多个相关功能。

| 场景           | 关联需求                                       | 角色与初始条件                             | 操作顺序                                              | 预期结果                                              |
| -------------- | ---------------------------------------------- | ------------------------------------------ | ----------------------------------------------------- | ----------------------------------------------------- |
| AC-PROVIDER-01 | FR-PROVIDER-01、FR-PROVIDER-02                 | 管理员；已有可用旧配置，准备有效及无效候选 | 提交无效/超时候选→查旧配置可用；提交有效候选→刷新摘要 | 只在测试成功后替换；响应/日志只见掩码，操作者时间正确 |
| AC-PROVIDER-02 | FR-PROVIDER-02、FR-PROVIDER-03                 | 两个管理员；两组候选及延迟测试结果         | 并发更新→使旧测试晚返回→测试当前连接                  | 冲突可见，当前状态与活动配置对应，迟到结果不逆转配置  |
| AC-PROVIDER-03 | FR-PROVIDER-01、FR-PROVIDER-02、FR-PROVIDER-03 | 制作者；知道供应商标识                     | 访问摘要、提交配置及发起测试                          | 全部管理操作服务端拒绝，秘密不泄露                    |

质量验收还需执行第4节的权限、故障、边界及数据量验证，并记录自动化、真实持久化、浏览器与外部条件各自的证据。静态数据、成功提示与文档检查不构成产品验收。

## 6. 依赖、假设与待确认

依赖管理员授权与安全凭据存储；实际测试需具备真实供应商条件。

**原有待确认：** 连接测试的具体操作、可能费用、超时与安全确认细节。

**本轮发现的需求缺口：** 短密钥掩码、测试结果有效期、测试期间是否暂停新调用、并发冲突后的用户处理方式。

**质量目标待确认：** 本模块适用设备/浏览器/版本、典型与边界数据规模、网络/冷热缓存条件、响应P50/P95、交互/Web Vitals与内存目标，以及格式/大小/并发/批量/导出限额须明确后才能质量验收。持久数据备份范围/周期、RPO/RTO与恢复责任人待确认。运行环境、可用性/维护窗口、数据用途/地域/保留及观测口径/日志策略仍待确认；不臆造SLA或规模。

这些问题统一纳入[总表缺口登记](01-需求总览.md#需求缺口与确认)，由产品负责人确认业务政策，工程/测试负责人补验证条件。责任角色尚未落实到人员，未给出答复的范围维持待确认；不自动新增平台、渠道或旧页面能力。
