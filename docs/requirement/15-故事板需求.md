# 故事板需求

## 1. 需求概述

**需求目标：** 制作者能在集场范围查看镜头，并对明确选中范围批量操作。

**使用者与价值：** 作为制作者，我希望在集场范围比较镜头并对明确选择的镜头批量编辑或生成，减少重复操作。

**问题背景：** 列表视图和批量提示尚未证明选择范围、原子编辑和逐镜头执行结果。

| 属性     | 内容                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 业务角色 | 制作者                                                                      |
| 文档状态 | 原始需求整理稿，待评审；不是已接受的设计或已验收功能                        |
| 范围来源 | 本文件第7、8节保留的原规格、现有页面代码，以及已整理的跨模块流程            |
| 完成依据 | 第3节功能结果、第4节质量条件、第5节验收场景；待确认项解决后才能验收相应能力 |

## 2. 范围与边界

本模块包含：网格/表格同查询、筛选、选择范围、原子批量时长、逐镜头批量生成。

故事板是同一镜头内容的网格/表格视图；批量编辑与逐镜头生成结果分别表达，不建立第二份业务状态事实。

业务模块一份文档，内部需求编号仅用于追踪，不对应独立文件、接口、类或开发任务。编号不承诺排期。原资料中的存储名、组件名和分页建议不作为已接受架构。

| 编号        | 功能           | 前置条件与输入                          | 需求与业务规则                                                         | 验收结果与异常边界                                          |
| ----------- | -------------- | --------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| FR-BOARD-01 | 集场查询       | 用户按集/场、状态、模式查看网格或镜头表 | 系统应返回编号、描述、时长、模式、缩略图、画面/视频状态和正确镜头数    | 两视图同一查询排序；失败与无匹配可区分；不读取全部候选历史  |
| FR-BOARD-02 | 明确选择       | 用户逐项选择、取消或全选                | 系统应显示明确所选ID与数量；仅对明确范围执行批量操作                   | 不暗含未加载项；空选择不能提交；换筛选后保留/清除规则需确认 |

| FR-BOARD-04 | 批量生成       | 用户确认所选范围并发起生成              | 系统应按生成合同创建每镜头独立可追踪任务，呈现逐项进度、成功/失败/未知 | 重复提交不重复收费；一项失败不隐藏其他结果；不自动选定候选  |
| FR-BOARD-05 | 打开镜头与画布 | 用户点镜头或在画布中打开                | 系统应传递同一项目/集场/镜头上下文到相应页面                           | 不跳固定样例镜头；目标越权/不存在明确失败                   |

## 5. 验收场景

下列是可执行的业务场景定义，尚未运行。实际测试按[生命周期方法](../软件生命周期与需求管理.md#测试与证据)记录环境、步骤、逐步预期与实际结果；功能行已给出独立验收条件，场景可联合验证多个相关功能。

| 场景        | 关联需求                              | 角色与初始条件                   | 操作顺序                                         | 预期结果                                                     |
| ----------- | ------------------------------------- | -------------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| AC-BOARD-01 | FR-BOARD-01、FR-BOARD-02、FR-BOARD-05 | 项目有跨集场和超过一页镜头       | 筛选→换视图→选当前可见项→取消/再选→打开镜头/画布 | 查询一致；所选ID数量与目标正确；未加载项无隐式选择           |
| AC-BOARD-02 | FR-BOARD-03                           | 两个选中镜头，其中一项版本已变化 | 统一时长提交→核两项→修正冲突后再提交             | 失败时两项均不写，冲突ID明确；修正后原子完成                 |
| AC-BOARD-03 | FR-BOARD-02、FR-BOARD-04              | 合法选择、真实生成结果与一项未知 | 批量生成→重复提交→刷新看每项状态                 | 每镜头一个可追踪任务；未知先核对，其他结果不隐藏且不自动选定 |

质量验收还需执行第4节的权限、故障、边界及数据量验证，并记录自动化、真实持久化、浏览器与外部条件各自的证据。静态数据、成功提示与文档检查不构成产品验收。

## 6. 依赖、假设与待确认

依赖镜头；批量生成依赖14；不另存故事板状态副本。

**原有待确认：** 批量读取上限仍为建议，需随实际数据消费评审。

**本轮发现的需求缺口：** 跨页/切筛选的选择保持规则；空选择与超限反馈；批量费用展示与确认。

**质量目标待确认：** 本模块适用设备/浏览器/版本、典型与边界数据规模、网络/冷热缓存条件、响应P50/P95、交互/Web Vitals与内存目标，以及格式/大小/并发/批量/导出限额须明确后才能质量验收。持久数据备份范围/周期、RPO/RTO与恢复责任人待确认。运行环境、可用性/维护窗口、数据用途/地域/保留及观测口径/日志策略仍待确认；不臆造SLA或规模。

这些问题统一纳入[总表缺口登记](01-需求总览.md#需求缺口与确认)，由产品负责人确认业务政策，工程/测试负责人补验证条件。责任角色尚未落实到人员，未给出答复的范围维持待确认；不自动新增平台、渠道或旧页面能力。
