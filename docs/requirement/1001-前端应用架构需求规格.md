# 前端应用架构需求规格

- 状态：派生自已接受设计，待独立评审
- 日期：2026-08-25
- 上游基线：[前端应用架构](../design/1001-前端应用架构.md) · [系统总体架构](../design/0003-系统总体架构.md) · [前端创作工作台产品需求](../prd/1002-前端创作工作台产品需求.md)

## 结论

本规格把已接受的前端架构转化为稳定、可测试的契约。Requirement ID 一经分配不得重排或复用；设计变化需要先更新上游 Design，再显式新增、替代或废弃 Requirement。

Requirement 只描述目标契约与验收方式。0→1 交付顺序与唯一 Checklist 由 [前端应用与功能交付实施计划](../plan/1001-前端应用与功能交付实施计划.md) 维护。

## 1. 工作区与依赖边界

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-001` | Frontend 必须是单一 pnpm Workspace，并且只存在一个 package manager 声明和一个 pnpm lockfile。 | 架构测试检查工作区、package manager、lockfile 和任务入口。 |
| `FE-ARCH-002` | 浏览器产品入口必须位于 `apps/web`；URL、认证、API 请求和用户行为必须符合正式产品契约。 | 路由合同、构建、视觉回归和端到端验收。 |
| `FE-ARCH-003` | `apps/collab` 只承担协作连接、恢复投影和连接治理，不得成为业务 Backend。 | import boundary、进程合同测试和数据库权限检查。 |
| `FE-ARCH-004` | `ui`、`sdk`、`auth`、`ai`、`canvas` 只能随首个真实消费者、运行入口和测试建立，不得预建空 package。 | 架构测试检查 package 内容、消费者和测试入口。 |
| `FE-ARCH-005` | 允许依赖方向必须符合 `apps/web → auth/ai/canvas → ui/sdk`；`sdk` 不依赖 React 状态，任何 package 不得导入 `apps/*`。 | ESLint/import boundary、循环依赖和 package dependency test。 |
| `FE-ARCH-006` | Feature 不得导入其他 Feature 的私有 Query、Store 或组件；跨 Feature 组合只能经公开入口。 | 架构测试扫描公开 subpath 和私有路径。 |
| `FE-ARCH-007` | Next Route Handler 只能处理必要 Web 适配，不得建立领域代理、事实源或第二套 Backend。 | 路由静态扫描和集成测试。 |

## 2. API、SDK 与协议

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-010` | Backend REST 类型和 Client 必须由正式 OpenAPI 生成；生成代码与手写适配分离，重新生成不得覆盖手写代码。 | OpenAPI Drift Gate、生成后 clean diff、类型检查。 |
| `FE-ARCH-011` | Feature 只能通过 SDK 使用 Backend contract，不得重复 DTO、直接拼接 `/api/v1` 或建立第二请求层。 | import/文本扫描、DTO 重复检测、受影响 Feature 测试。 |
| `FE-ARCH-012` | SDK 必须为资源定义唯一 Query Key/Base Options；Feature 只可增加页面选择和失效关系。 | Query key 单一性架构测试和缓存合同测试。 |
| `FE-ARCH-013` | REST 错误必须至少保留 `code`、安全消息、下一动作、字段或节点路径、可重试性和 request/trace ID。 | 错误 envelope 合同测试和组件测试。 |
| `FE-ARCH-014` | SSE 必须使用结构化事件、稳定 Event ID、Run ID、终态和恢复游标；重连按 ID 去重或重取 Snapshot。 | SSE schema/重连/重复/乱序合同测试。 |
| `FE-ARCH-015` | Collaboration 协议必须精确绑定 workspace、project、draft、document epoch 和读写能力；过期或撤权后停止接受更新。 | 双客户端集成、Grant 过期和撤权 E2E。 |
| `FE-ARCH-016` | 大文件必须通过 Presigned URL 从 Browser 直接上传对象存储；Web 与 Public API 不得中转媒体字节。 | 网络断言、上传集成测试、对象元数据核对。 |
| `FE-ARCH-017` | 前端必须传播并展示 Backend 返回的安全 request/trace ID，不得展示敏感诊断原文。 | 错误组件测试、日志脱敏检查。 |

## 3. 状态所有权

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-020` | Backend 服务端事实只能由 TanStack Query 缓存；缓存可丢弃并从 Backend 重建。 | 状态定义扫描、Query 集成测试。 |
| `FE-ARCH-021` | 每个服务端资源必须只有一个 Query Owner、Query Key 体系和缓存入口；同一实体不得被多个 Query Client 或缓存系统并行持有。 | Query Owner 架构测试和缓存一致性验收。 |
| `FE-ARCH-022` | 跨组件瞬时 UI 才可进入 feature-scoped Zustand；不得保存服务端实体、Token、表单字段或 Yjs Graph。 | Store 类型扫描和单元测试。 |
| `FE-ARCH-023` | 未提交业务表单由 React Hook Form + Zod 持有并校验；服务端字段错误必须映射回原表单。 | 表单组件测试和 422 合同测试。 |
| `FE-ARCH-024` | 可分享且稳定的 workspace/project/episode/draft/task/run/tab/filter/sort 状态进入 URL；Token、拖拽态、Presence 和未提交敏感输入不得进入 URL。 | 深链刷新 E2E、URL 安全扫描。 |
| `FE-ARCH-025` | 活动 Canvas 房间内 Graph/Layout 的唯一可变共享状态是 Yjs；不得同时镜像到 Query Cache 或 Zustand。 | 状态所有权架构测试、双客户端集成测试。 |
| `FE-ARCH-026` | 未完成 AI 流由流式 Controller 持有；只有服务端可确认的终态才能替换为持久 Query 事实。 | reducer 单测、断线和未知结果 E2E。 |
| `FE-ARCH-027` | 组件私有 hover、弹层、输入法和短动画保持 React local state，不得无原因提升为全局 Store。 | Code review 规则和 Store 使用扫描。 |

## 4. 认证与授权

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-030` | Access Token 必须只驻留认证运行时内存，不得进入 URL、Local/Session Storage、Query Cache、Zustand 或日志。 | 单元测试、浏览器存储和日志扫描。 |
| `FE-ARCH-031` | Refresh Session 必须使用 HttpOnly Cookie；并发 401 只能合并为一次 Refresh，失败后清理会话。 | request 单测、并发刷新合同测试、浏览器 Cookie 检查。 |
| `FE-ARCH-032` | 登录 Return URL 必须只允许安全站内目标，禁止开放重定向。 | 恶意 URL 单元/E2E。 |
| `FE-ARCH-033` | 路由守卫和按钮禁用只改善体验；Backend RBAC/Capability 始终做最终裁决。 | 直接调用被禁止命令的 E2E。 |
| `FE-ARCH-034` | 退出、撤权、账户停用和 Workspace 切换后，相关 Query、SSE、上传与 Collaboration 连接必须停止或隔离。 | 多连接 E2E 和缓存隔离测试。 |
| `FE-ARCH-035` | 模型、数据库、对象存储凭据与私有 Bucket 地址不得进入浏览器 Bundle 或协作消息。 | Bundle secret scan 和运行配置测试。 |

## 5. Authoring、Canvas 与运行边界

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-040` | Guided 与 Canvas 必须读取和修改同一 Draft Schema，不得形成两套 Workflow 或互不兼容的数据模型。 | 同 fixture 双入口合同测试。 |
| `FE-ARCH-041` | 每次运行必须绑定不可变 Revision ID/Hash；可变 Draft 不得直接执行。 | 请求合同测试和 E2E 数据核对。 |
| `FE-ARCH-042` | Node Definition、配置 Schema、权限、成本和缓存策略只能来自 Backend Node Catalog；Frontend 不得写死执行分支。 | Catalog fixture 架构测试和动态节点组件测试。 |
| `FE-ARCH-043` | Graph Validation、Publish、Workflow Compile、局部执行闭包、Dirty/Cache 和重试裁决必须由 Backend/执行系统负责。 | API 合同测试、前端 import 扫描和 E2E。 |
| `FE-ARCH-044` | Prompt、输入 Artifact、策略、节点配置、Skill、连接和候选选择改变执行 Dirty；坐标、颜色、Frame、Comment 和 Viewport 不得改变执行 Hash。 | 纯函数/合同测试和 Revision Hash E2E。 |
| `FE-ARCH-045` | GraphPatch 必须经过 Validate、Preview、User Confirm、一次性 Apply Grant 和持久 Receipt；未知结果按 Application ID 对账，不得客户端重放。 | 故障注入和双客户端 E2E。 |
| `FE-ARCH-046` | Web/Canvas/Collab 不得直接调用 Temporal、Provider、Agent Runtime 或写 PostgreSQL。 | 依赖扫描、网络测试和凭据检查。 |

## 6. 错误、恢复与一致性

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-050` | 主要路由必须分别提供 loading、empty、error、forbidden、not-found 和 stale/conflict 状态。 | 路由状态组件测试和视觉测试。 |
| `FE-ARCH-051` | Review、Revision 发布、生成完成、权限变更和不可逆动作在服务端确认前不得显示成功。 | 延迟/失败/重复响应组件测试。 |
| `FE-ARCH-052` | 网络断开、Provider 未知结果或回执缺失必须显示“待确认/需对账”，不得直接归类 FAILED 或 SUCCEEDED。 | 故障注入 E2E。 |
| `FE-ARCH-053` | 409 必须触发刷新、Diff 或可解释 Rebase；不得最后写入静默覆盖。 | 冲突合同和并发 E2E。 |
| `FE-ARCH-054` | 429 必须尊重 Retry-After，并阻止重复提交；上传只可重试幂等阶段。 | 限流和上传故障测试。 |

## 7. 性能与可访问性

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-060` | 普通路由不得加载 Canvas、Konva、ELK、Tiptap 或 AI 大依赖；相关能力按路由/功能动态加载。 | Bundle 分析和路由加载测试。 |
| `FE-ARCH-061` | 常规页面以 p75 LCP≤2.5s、INP≤200ms、CLS≤0.1 作为初始校准目标；变更必须记录真实设备、fixture 和原因。 | Web Vitals 基准。 |
| `FE-ARCH-062` | Canvas 基准必须覆盖 100/500/1000 nodes；500-node 本地平移/缩放在基线设备目标≥50 FPS 且无连续长任务。 | 可重复 Canvas benchmark。 |
| `FE-ARCH-063` | 本地协作反馈初始目标 p95≤100ms；网络传播单独记录；长 AI 会话 DOM 与重渲染必须有上界。 | Collaboration/AI 性能测试。 |
| `FE-ARCH-064` | UI Primitive 和关键业务交互必须通过 Keyboard、Focus、ARIA、Theme 和视觉回归检查。 | 组件测试、axe/键盘 E2E、视觉快照。 |

## 8. 测试与发布门禁

| Requirement ID | 必须成立的契约 | 验收方式 |
|---|---|---|
| `FE-ARCH-070` | Workspace 根命令必须覆盖 lint、typecheck、unit、build 和 E2E，且干净仓库可重复执行。 | CI/本地 clean run。 |
| `FE-ARCH-071` | 必须固定 package/import、DTO、Query owner、Canvas 边界、Revision 绑定和无双缓存架构测试。 | 可重复执行的架构测试。 |
| `FE-ARCH-072` | OpenAPI、SSE、GraphPatch、Node Registry、Room Grant 和上传协议必须有合同测试。 | Contract suite。 |
| `FE-ARCH-073` | 必须覆盖登录与 Workspace、Guided、Guided/Canvas 同 Revision、Review/Human Gate、失败恢复和权限撤销的端到端旅程。 | 真实浏览器端到端验收。 |
| `FE-ARCH-074` | 每个发布门必须在 Acceptance 中记录命令、输入、环境、结果、未运行项和残余风险。 | Acceptance 审阅。 |

## 9. 非目标

本规格不定义：

- 10 个 Feature 的用户功能细节，详见 [前端功能模块需求规格](1002-前端功能模块需求规格.md)；
- Backend、Workflow、Agent、Model Gateway 或 Media Worker 的内部实现；
- 易变页面文案、视觉稿和业务排期；
- 以兼容 Facade、永久双状态桥接或空 package 达到表面目录完整；
- 计划勾选或未执行测试的通过声明。
