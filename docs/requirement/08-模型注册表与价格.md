## 1. 需求说明

### 1.1 背景与目标

视频模型迭代极快，各家的生成模式、参考数量上限、时长、参数都不同（PRD-02 §3.4：LibTV 以声明式注册表驱动界面与校验）。如果把这些写进代码，每接一个新模型都要发版。注册表把“模型能做什么、要什么参数、多少钱”变成配置，前端按它渲染表单，报价按它校验和计价。

### 1.2 用户故事

- 作为**管理员**，我希望登记模型的能力、生成模式、参考上限、参数表单与价格，以便新模型不发版就能上线。
- 作为**制作者**，我希望参数面板随所选模型自动变化，只显示该模型支持的参数与范围，超出限制时在提交前就得到提示。
- 作为**管理员**，我希望调整价格只影响之后的报价，已确认的任务按原价格结算。

### 1.3 范围

- 包含：能力（capability）字典、模型登记与版本化、参数表单定义、输入限制、价格规则版本化、启用 / 停用、按项目过滤可用模型。
- 不包含：模型自动路由与质量评分（手动切换见 REQ-39 GEN-08）、供应商价格自动同步。

## 2. 需求分析

### 2.1 业务流程

```text
管理员新增模型（标识、供应商、能力、显示名）→ 发布模型版本（支持的模式、输入限制、参数、是否支持查询 / 取消 / 回调、预计最长时长）
  → 发布价格规则（计价单位与规则、币种、汇率）→ 启用
制作者选择模型 → 看到该模型当前版本的参数表单与输入限制
报价 → 按当前模型版本校验输入与参数、按生效的价格规则计价 → 任务记录所用的模型版本与价格版本
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 模型内容（模式、限制、参数表单等）只能通过发布新版本修改；Operation 引用创建时的版本 | 可追溯、可复现 |
| R2 | 参数组件类型固定为：`input`、`textarea`、`select`、`slider`、`switch`、`segmented`、`voice` | 对齐 LibTV 的组件集；前端只需实现这几种 |
| R3 | 每个参数可声明 `for_modes`，只在对应模式下出现 | 同一模型不同模式参数不同 |
| R4 | 限制按输入用途声明：`max_count`、`types`、`max_ms`、`max_bytes`、`min_resolution` | 全能参考的参考上限因模型而异（如 9 图 / 3 视频 / 3 音频） |
| R5 | 价格规则变更产生新版本，`effective_from` 生效；报价取报价时刻生效的版本，确认后预留按报价金额 | CST-04 |
| R6 | 境外币种价格须填写记账汇率，报价换算为人民币微元 | DES-02 D5、DM3 |
| R7 | 停用模型不影响进行中任务；新报价返回 `model_unavailable` | ADM-01 |
| R8 | 发布前校验：字段名唯一、默认值在范围内、`for_modes` 为模型支持的模式、价格规则字段完整 | 防止错误配置上线 |
| R9 | 供应商凭据不可用时，其模型在模型选择中显示为不可用并给出原因 | 界面给出明确提示 |

### 2.3 状态

`model_profile.status`：`disabled`（新建默认）⇄ `active`。版本与价格规则只追加。

### 2.4 异常与边界

- 模型无价格规则时不可启用。
- 前端缓存的注册表过期：报价以服务端当前版本为准，版本变化时报价响应带 `model_version_changed`，前端刷新表单。

### 2.5 前置与依赖

- REQ-07 凭据可用。
- Agent 服务存在对应 `adapter_key` 的适配器；适配器声明它支持的 `provider_model_id` 模式与参数映射。

## 3. 验收标准

- Given 管理员新增一个与已有模型同供应商的视频模型配置，When 保存并启用，Then 制作者在镜头生成面板中可以选择它，参数表单按定义渲染，无需发布新版本代码。
- Given 某模型的参考图上限为 9，When 制作者为该模型配置 10 张参考图并请求报价，Then 报价被拒绝并提示“参考图最多 9 张”。
- Given 已有进行中的任务使用模型 M，When 管理员停用 M，Then 该任务继续完成，新的报价请求被拒绝。
- Given 从模型 A 切换到模型 B，When 打开参数面板，Then 面板字段与取值范围按 B 的定义显示，A 独有的字段不再出现。
- Given 价格从 1.0 元 / 秒调整为 1.2 元 / 秒，When 查看调整前已确认的任务，Then 其预留按 1.0 元 / 秒计算。
