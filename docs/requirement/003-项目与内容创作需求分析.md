# 项目与内容创作需求分析

## 1. 本模块负责什么

本模块负责把创作者的故事、梗概或已有剧本整理为一套可确认、可追溯、可供后续生产使用的内容基线。它回答“这部作品要讲什么、分成哪些场次、每个镜头要表达什么”，不负责回答“使用哪份具体素材、如何生成、采用哪个媒体结果或如何完成交付”。

MVP 的核心不是自动写完整部短剧，而是让个人创作者把一集已有内容稳定推进到已确认镜头计划，并在修改后知道哪些后续工作需要复核。

## 2. 内容层级与概念边界

```mermaid
flowchart LR
  S["原始内容"] --> P["项目"]
  P --> R["系列/剧集（可选）"]
  P --> E["单集"]
  R --> E
  E --> C["场次"]
  C --> H["镜头计划"]
  H --> A["资产需求"]
```

| 概念 | 在本模块中的含义 | 关键边界 |
| --- | --- | --- |
| 原始内容 | 用户输入的创意、梗概、小说片段、故事或已有剧本 | 是整理依据，不能被整理结果静默覆盖 |
| 项目 | 一次短剧创作的目标、范围、内容约束与共同归属 | 不等同于某一集或某个生产任务 |
| 系列/剧集 | 共享世界观、角色和连续叙事目标的多集集合 | MVP 单集创作可不建立该层级 |
| 单集 | 可独立确认、生产、审核和交付的叙事单元 | MVP 的主要内容范围 |
| 场次 | 在相对连续时间和空间中完成一个剧情目的的内容段落 | 不等同于场景图片或地点资产 |
| 镜头计划 | 将场次表达拆为有顺序、有叙事目的的最小生产意图 | 不是分镜图片、生成任务或视频素材 |
| 资产需求 | 内容对角色、服装、地点、道具、风格或声音的需要 | 资产、版本和来源关联由 REQ-004 管理，权利与治理状态由 REQ-007 管理 |
| 内容基线 | 经授权用户确认、供后续模块共同引用的当前内容版本 | 不代表资产已就绪、生产已完成或媒体已采用 |

## 3. 功能目录

| 功能 | 触发或输入 | 业务结果 | 协作关系 | 阶段 |
| --- | --- | --- | --- | --- |
| 建立项目创作范围 | 用户开始一部短剧创作 | 明确题材、受众、内容形态、目标时长、画幅、语言和本轮交付范围 | REQ-002 确认归属与操作责任 | MVP |
| 继续未完成项目 | 用户离开后返回，或其他模块状态发生变化 | 恢复当前内容基线，汇总资产、制作、审核和保障阻塞，并指出下一责任动作 | REQ-004—REQ-007 提供各自事实 | MVP |
| 归档或结束项目 | 用户不再继续当前生产 | 停止新活动；运行中任务和未完成审核不得静默取消，由有权用户选择等待、取消或完成；历史事实继续保留 | REQ-002 负责权限，REQ-004—REQ-006 处置各自事实，REQ-007/008 处理删除与保留 | P1 |
| 接收并保留原始内容 | 用户粘贴或导入梗概、故事或剧本 | 原文作为来源保留，后续整理可说明依据 | REQ-007 判断权利与内容限制 | MVP |
| 识别输入性质与完整程度 | 原始内容进入项目 | 区分创意、故事、分场剧本等类型，并提示缺失、冲突与不确定项 | 为后续整理提供约束 | MVP |
| 整理为结构化剧本 | 原始内容可理解且用户允许整理 | 形成叙事顺序、人物、动作、对白和场次草稿，用户可继续修改 | 向 REQ-004 提供叙事实体需求 | MVP |
| 统一叙事实体称谓 | 同一角色、地点或道具有别名或歧义 | 避免后续场次、镜头和资产错误关联，同时保留来源称谓 | 与 REQ-004 对齐资产需求 | MVP |
| 建立和调整单集 | 项目已有本轮内容范围 | 明确本次生产所覆盖的故事起止、目标时长与叙事目标 | 向 REQ-005、REQ-006 提供单集边界 | MVP |
| 辅助长内容分集 | 用户输入小说或长篇故事 | 给出可编辑的多集划分提案，不替用户作最终叙事决定 | 与后续各模块按集协作 | P1 |
| 规划和编辑场次 | 单集内容已明确 | 每个场次具备剧情目的、地点与时间、参与角色、动作、对白及前后承接 | REQ-004 获取场次资产需求 | MVP |
| 拆分和编辑镜头计划 | 场次内容足以进行视觉表达 | 镜头具备顺序、叙事目的、动作与对白、预期时长及画面和声音意图 | REQ-005 获取生产意图，REQ-006 获取审核顺序 | MVP |
| 声明镜头资产需求 | 场次或镜头引用角色、服装、地点、道具、风格或声音 | 后续资产准备可判断已匹配、缺失或需要新增 | REQ-004 负责具体资产和版本 | MVP |
| 检查内容完整程度 | 用户准备确认单集、场次或镜头 | 明确缺失、矛盾和超出本轮范围之处，不把内容完整误报为生产就绪 | REQ-004、REQ-005 分别判断资产和生产条件 | MVP |
| 确认当前内容基线 | 内容完整且操作人具有确认责任 | 后续模块获得明确、稳定且可追溯的单集与镜头依据 | REQ-002 授权；REQ-004—REQ-006 引用 | MVP |
| 重新打开已确认内容 | 创作者需要调整剧情或镜头意图 | 旧基线继续可追溯，新修改进入待确认状态并启动影响识别 | REQ-004—REQ-006 接收影响提示 | MVP |
| 保留内容演进关系 | 内容被整理、修改、确认或重新打开 | 用户能区分原始内容、历史结果与当前基线 | REQ-005、REQ-006 继续引用原依据 | MVP |
| 识别修改影响 | 已确认内容发生变化 | 列出可能受影响的资产、生产、审核与交付对象及变化原因 | REQ-004—REQ-006 分别决定无需处理、复核、返工或阻断 | MVP |
| 维护跨集叙事连续性 | 系列包含多个单集 | 世界观、人物关系、剧情事实和未完成线索可延续并显式变更 | 与 REQ-004 的资产连续性区分协作 | P1 |

## 4. 内容导入与整理要求

1. 原始内容与整理结果必须可区分；整理、改写或拆分不能破坏用户提供的来源。
2. 系统应说明识别出的输入类型、可直接使用的部分和需要用户补充的部分，不能假定所有文本都是完整剧本。
3. AI 提供的角色、场次、台词或镜头拆分均是待确认内容提案，不得直接成为有效内容基线。
4. 用户应能纠正人物称谓、顺序、对白归属、场次边界和镜头意图；被纠正内容不得在后续整理中无提示恢复。
5. 整理结果需要保留与来源片段的合理关联，使用户能够判断增写、删减和改写发生在哪里。
6. 内容中的矛盾、缺口和不确定信息应显式呈现；无法可靠判断时应请求用户决定，而不是虚构确定事实。
7. 版权、真人身份或受限题材等问题交由 REQ-007 判定，但本模块必须保留来源及用户声明供其判断。

## 5. 从剧本到镜头计划的完整条件

| 内容层级 | 至少需要表达的业务信息 | 完整的含义 |
| --- | --- | --- |
| 单集 | 本集目标、剧情范围、目标时长、主要冲突、开端与结尾 | 创作者知道这一集讲什么以及在哪里结束 |
| 场次 | 剧情目的、地点和时间、参与角色、动作、对白、情绪与前后变化 | 能解释该场为何存在以及改变了什么 |
| 镜头计划 | 所属场次、顺序、叙事目的、动作和对白、预期时长、画面与声音意图、所需资产 | 后续生产能理解要表达什么且不脱离剧情上下文 |

“内容可确认”“资产已就绪”“可以开始生产”是三个不同判断：本模块只确认叙事内容；REQ-004 判断具体资产是否满足需要；REQ-005 综合内容、资产及其他业务门禁判断是否可生产。

## 6. 内容确认规则

- 确认操作必须由 REQ-002 允许承担相应责任的人完成；个人 MVP 中可以由同一人创作和确认，但两种行为仍需区分。
- 当前有效基线必须唯一明确，后续模块不得自行选择某个历史内容作为新依据。
- 可以按单集确认整体内容，并在必要时对场次或镜头重新打开；局部调整不得无故取消不相关内容的确认。
- 确认后的内容仍可修改，但必须形成新的待确认内容并说明原因，不覆盖旧基线。
- 内容确认只表示创作意图可供后续使用；媒体候选的批准、采用和成片终审属于 REQ-006。
- 后续生产结果不得反向静默改写台词、镜头目的或故事事实；需要变更时必须回到本模块形成新基线。

## 7. 变更影响

| 变更 | 直接影响 | 需要协作的模块 |
| --- | --- | --- |
| 题材、受众、画幅、语言或目标时长变化 | 本轮单集范围、场次和镜头约束可能失效 | REQ-004 复核资产适用性；REQ-005 复核生产范围；REQ-006 复核交付范围 |
| 剧情事实、人物关系、动作或对白变化 | 相关场次、镜头与资产需求需要复核 | REQ-004 复核引用资产；REQ-005 处置相关任务；REQ-006 复核字幕、音频和已采用片段 |
| 场次顺序、地点、时间或参与角色变化 | 场次承接、镜头顺序和连续性要求变化 | REQ-004—REQ-006 复核各自负责的结果 |
| 镜头目的、动作、对白或预期时长变化 | 该镜头的资产需求、生产意图和成片节奏变化 | REQ-004、REQ-005、REQ-006 分别判断是否返工 |
| 名称、备注或不改变含义的编辑 | 引用可保持，但需要确认确实不改变业务含义 | 后续模块不应因此自动重新生产 |

影响识别不得自动删除历史资产、任务或成片结果。MVP 至少识别明确的直接影响，并由用户决定保留、复核或返工；跨多层的间接影响分析列为 P1。

## 8. 与核心模块的协作边界

| 模块 | 本模块提供 | 对方返回或负责 |
| --- | --- | --- |
| REQ-002 用户、组织与权限 | 内容操作、确认和影响处置所对应的项目上下文 | 判断谁能查看、修改或确认；本模块不自行扩大权限 |
| REQ-004 创作资产管理 | 角色、服装、地点、道具、风格与声音需求及其剧情上下文 | 管理具体资产、版本、来源、引用和匹配情况，并返回缺失或不适用结果 |
| REQ-005 AI 制作与任务管理 | 已确认单集与镜头计划、顺序、意图和预期范围 | 管理生产任务、候选与重试，返回生产限制和变更影响；不得改写内容基线 |
| REQ-006 审核与成片交付 | 单集结构、镜头顺序、对白及当前内容基线 | 管理媒体审核、采用、成片与交付，并将叙事或结构问题反馈回来 |
| REQ-007 平台保障与运营 | 原始内容来源、素材用途和本轮内容范围 | 管理权利声明、安全与 AI 标识状态，并返回限制或复核要求 |

## 9. MVP 边界与待验证项

MVP 聚焦“已有故事或剧本 → 单集 → 场次 → 镜头计划 → 内容确认”的闭环，包括来源保留、人工修改、资产需求声明、当前内容基线、历史可追溯和直接变更影响。首轮不以长篇小说自动改编、多集规划或多人协作为成立前提。

P1 再考虑长文本辅助分集、多集连续性、系列级世界观、更丰富的版本比较、间接影响分析和多人内容协作。

本模块不建设专业编剧或剪辑能力，不管理具体图像、视频和声音资产，不发起生成任务，不批准媒体候选，不完成成片交付，也不在需求阶段决定页面、接口、数据表、模型、提示词或工作流实现。

仍需要验证：首发用户的真实输入主要是梗概、小说还是剧本；镜头进入资产准备前的最小必填内容；用户接受怎样的 AI 增写边界；单集目标长度和镜头数量；内容确认需要一人还是多人；多集连续性是否会成为首轮阻断问题。
