# REQ-09 审计日志

| 项 | 内容 |
| --- | --- |
| 需求 | ADM-02 审计日志查询；REQ-01 G6 审计约定 |
| 优先级 | MVP |
| 用例 | UC-23 |
| 页面 | 管理 · 审计日志 |
| 依赖功能 | 被全部写操作功能依赖 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

平台涉及付费确认、预算、价格、凭据、正式版本选定等关键操作，出现费用争议或结果错误时必须能回答“谁在何时做了什么、改之前是什么”。

### 1.2 用户故事

- 作为**管理员**，我希望按时间、操作人、对象、项目、动作查询审计记录，以便追溯问题与费用。

### 1.3 范围

- 包含：审计写入约定、查询、导出 CSV。
- 不包含：审计告警规则（运维监控负责）、用户行为分析。

## 2. 需求分析

### 2.1 业务流程

```text
业务命令事务内写 Outbox 事件 → Kafka → audit 消费者按事件生成审计记录（幂等）→ audit.audit_log
管理员 → 审计页面筛选 → 查看前后值摘要 → 跳转对象
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 必须审计的动作：登录与账号变更、凭据、注册表与价格、预算、报价确认、取消、人工核对处理、所有选定 / 锁定 / 确认、删除与恢复、成片渲染与下载 | REQ-01 G6 |
| R2 | 审计记录只追加，应用账号无删除与修改内容的权限 | SEC-10 |
| R3 | `before` / `after` 只存摘要（变更字段），不存剧本全文、凭据、预签名 URL | PRV-02 |
| R4 | 记录 `actor_kind`：`user` / `agent` / `system`；Agent 提案由用户确认执行时，actor 为用户，并在 `after` 中记录 `via_agent_proposal_id` | 分清责任 |
| R5 | 保留 3 年 | DAT-03 |

### 2.3 状态

无。

### 2.4 异常与边界

- Kafka 暂不可用：Outbox 积压，审计延迟写入但不丢失（REL-07）。
- 登录失败等不产生业务事务的动作：直接写 Outbox（独立小事务）。

### 2.5 前置与依赖

`infra.outbox` 与 relay 就绪。

## 3. 实现所需

### 3.1 数据

`audit.audit_log`（按月分区）：`org_id`、`project_id`、`actor_id`、`actor_kind`、`action`、`object_type`、`object_id`、`before`、`after`、`request_id`、`trace_id`、`ip`。消费者幂等依赖 `infra.processed_event`。

### 3.2 接口

```http
GET /api/admin/audit-logs?from=2026-09-01T00:00:00Z&to=…&actor_id=…&project_id=…&object_type=shot&action=shot.take_selected&limit=50&cursor=…
200 { "items": [ { "id": "…", "create_time": "…", "actor": { "id": "…", "display_name": "Alice" }, "action": "shot.take_selected",
                   "object_type": "shot", "object_id": "…", "object_label": "第 1 集 3-12", "before": { "selected_take_output_id": "…" },
                   "after": { "selected_take_output_id": "…" }, "request_id": "…" } ], "next_cursor": "…" }
GET /api/admin/audit-logs:export?…   → CSV（最多 10 万行）
```

### 3.3 异步与工作流

audit 消费者（`backend-relay`）；分区维护定时任务（Temporal Schedule，每月创建未来 3 个月分区、删除 3 年前分区）。

### 3.4 事件与实时

消费全部 DES-03 §6.2 中标注 audit 的事件。

### 3.5 界面

筛选栏（时间范围、操作人、项目、对象类型、动作）+ 虚拟滚动表格 + 详情抽屉（前后值差异）。

### 3.6 权限与审计

仅管理员可查询；查询与导出本身也写审计（`audit.exported`）。

### 3.7 非功能要求

SEC-10（100% 覆盖 R1 动作，以自动化测试遍历命令验证）；DAT-03；查询 30 天范围 P95 ≤ 1 秒。

## 4. 验收标准

- Given 制作者选定了镜头 3 的视频候选，When 管理员按项目与“选定”操作筛选审计日志，Then 能看到该记录，包含操作人、时间、镜头与候选标识。
- Given 任意一次报价确认，When 查询审计，Then 存在 `operation.confirmed` 记录，包含金额与确认人。
- Given 应用数据库账号，When 尝试 `UPDATE audit.audit_log SET after = …`，Then 被数据库拒绝。

## 5. 测试要点

- 命令覆盖测试：遍历 R1 中每个命令，断言产生对应审计记录。
- 消费者幂等：重复投递同一事件只产生一条记录。
