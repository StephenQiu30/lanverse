# 创作资产管理需求分析

## 1. 资产域需要守住什么

本模块管理可被内容和制作持续引用的创作资产，保存以下业务事实：

- 这是什么资产，属于哪一类，代表哪个稳定的角色、场景、道具、风格或声音身份。
- 它有哪些版本，每个版本从何而来，与哪些参考、生产活动和历史版本有关。
- 哪个项目、单集、场次、镜头或生产活动正在使用它的哪个版本。
- 它能否继续使用、复用或停用，变化会影响哪些内容、任务和交付结果。
- 它关联了哪些权利声明、授权证据、使用限制和 AI 标识要求。

候选事实由 REQ-005 管理；正式审核、采用和交付事实由 REQ-006 管理。本模块只关联并呈现这些事实，不复制结论或自行改变状态。REQ-007 负责解释权利与安全规则并形成平台限制，REQ-003 负责内容结构和内容基线。

本文不决定页面、接口、数据表、存储、检索、转码、模型训练、提示词或生成工作流。

## 2. 资产分类不是文件分类

分类应表达资产在短剧生产中的身份和用途，而不是文件格式。

| 资产类别 | 需要稳定表达的内容 | 典型边界 |
| --- | --- | --- |
| 角色 | 人物身份、核心外观和连续性基准 | 不把一次换装或某张角色图当成新角色 |
| 服装与造型 | 角色在剧情阶段、场次或镜头中的外观变化 | 与角色关联，但拥有自己的版本和使用范围 |
| 场景 | 地点、空间结构、环境、时间与氛围基准 | 同一地点的昼夜或破损状态可形成变化版本 |
| 道具 | 需要在剧情和镜头间保持身份或状态的物件 | 普通临时画面元素不必全部资产化 |
| 风格 | 项目或局部范围遵守的视觉、声音和表现约束 | 不替代具体角色、场景和声音资产 |
| 声音 | 角色声音、对白表现、旁白、音乐、音效及参考 | 声音身份、演绎版本和成片采用需要区分 |
| 参考素材 | 用于表达意图或约束创作的图片、音视频和文本 | 必须与生成媒体区分，并保留来源 |
| 生产媒体 | 制作形成的图片、视频、音频和衍生内容 | 是否为候选看 REQ-005，是否采用看 REQ-006 |

故事、剧本、场次和镜头意图属于 REQ-003，不因以文本形式存在就成为资产。一个对象可以具有用途标签，但必须有唯一主类别和稳定身份，避免通过重复建档表达同一对象。

## 3. 资产身份、版本与来源

| 业务概念 | 必须回答的问题 |
| --- | --- |
| 资产身份 | 用户讨论的是哪个角色、地点、物件、风格或声音，而不是哪一个文件 |
| 资产版本 | 同一身份发生了什么变化，哪些历史表现仍被引用 |
| 来源关系 | 版本来自用户创作、外部导入、既有版本派生，还是 REQ-005 的某次制作尝试 |
| 使用引用 | 哪个业务范围实际使用了该资产的哪个版本 |
| 权利关联 | 来源主体、权利声明、授权证据和使用限制与哪个资产或版本相关 |
| 可用条件 | 资产是否可供新内容引用，或因停用、权利、安全原因受到限制 |

资产身份在版本变化时保持稳定；需要表达不同剧情身份时才建立新资产。版本不得覆盖历史版本，也不得因文件移动或重新导入失去来源关系。资产版本本身不等于候选、审核通过或当前采用。

## 4. 核心功能地图

| 核心功能 | 触发与输入 | 业务行为和可见结果 | 依赖或输出 | 阶段 |
| --- | --- | --- | --- | --- |
| 登记与分类 | REQ-003 提出资产需求，用户导入素材，或 REQ-005 产生媒体 | 识别类别、用途、归属和稳定身份；提示可能重复对象；形成可被引用的资产 | 向 REQ-003、REQ-005 提供资产身份 | MVP |
| 版本与来源追溯 | 资产被修改、替换、派生或收到新生产媒体 | 建立新版本并保留前序、参考、创作者和生产上下文；旧版本继续可解释 | REQ-005 使用明确输入版本，REQ-006 定位待审版本 | MVP |
| 组织与发现 | 用户按角色、场景、镜头、用途或可用范围寻找资产 | 找到正确身份和版本，区分参考、生产媒体及受限内容 | 服务 REQ-003 内容引用和 REQ-005 制作准备 | MVP 基础；P1 组合与批量整理 |
| 建立使用引用 | 内容或任务选择资产，交付结果关联实际使用资产 | 记录使用范围及明确版本，并支持从资产反查使用位置 | 输入 REQ-003、REQ-005；关联 REQ-006 采用事实 | MVP |
| 项目内复用 | 后续镜头需要沿用已确认设定或媒体 | 复用同一身份和来源链，不制造失去历史的副本；明确新使用范围 | 向 REQ-003、REQ-005 输出复用基线 | MVP 单集内；P1 多集与跨项目 |
| 变化影响识别 | 版本替换、引用调整、资产停用或权利条件变化 | 列出受影响内容、任务、候选、采用和交付范围，交由责任人判断 | 输出到 REQ-003、REQ-005、REQ-006、REQ-007 | MVP 直接影响；P1 连锁影响与批量处置 |
| 权利关联 | 用户导入受保护素材、声明权利，或授权条件变化 | 将声明、证据、主体和限制关联到资产或版本；未知状态不得默认为可商用 | REQ-007 判断规则和风险，REQ-006 执行交付门禁 | MVP 基础声明；P1 期限、区域、渠道等细化 |
| 停用与归档 | 资产错误、失效、不再推荐使用或项目阶段结束 | 阻止未经确认的新使用，保留历史引用、来源和交付证据 | 通知 REQ-005、REQ-006、REQ-007 处理影响 | MVP；P1 批量治理 |

## 5. 引用与复用规则

1. 项目、单集、场次、镜头和生产活动引用资产时，都必须能说明资产身份及实际使用版本。
2. 项目级引用表达共同基准，局部引用表达特定内容需要；具体继承方式留给 Design 决定。
3. 重复使用同一资产不得生成无法追溯的新身份；确需独立演化时应保留与原资产的来源关系。
4. 参考素材与生产媒体必须区分，生产媒体应能追溯关键参考、镜头和制作尝试。
5. REQ-005 产生候选后，本模块可登记其媒体和来源，但候选判断仍留在 REQ-005。
6. REQ-006 改变审核、采用或交付关系后，本模块更新关联视图，不把该决定改写为资产版本属性。
7. 已被采用或交付版本使用的资产不能被静默替换；停用后仍要保留历史使用证据。
8. MVP 只要求同一单集后续镜头复用，并沉淀未来可用基线；多集连续性和跨项目复用属于 P1。

## 6. 影响识别与权利闭环

资产变化至少需要区分身份变化、表现版本变化、使用引用变化、来源或权利变化。影响结果要指出对象、使用位置、所用版本和影响原因，不自动替换、不自动返工，也不自动撤销已交付事实。

- 内容或镜头引用受影响时，交给 REQ-003 判断内容基线是否调整。
- 未开始、进行中或已有候选的制作受影响时，交给 REQ-005 判断继续、取消或重做。
- 已审核、采用或交付内容受影响时，交给 REQ-006 判断复核、替换或重新交付。
- 权利、安全或 AI 标识条件受影响时，交给 REQ-007 判断限制、例外或运营处置。

资产模块保存权利材料与资产的关联，不自行解释法律有效性。MVP 至少要表达来源主体、用户权利声明、允许用途、未知或受限状态；更细的期限、地域、渠道、撤回和证据有效期在 P1 验证。

## 7. 责任与权限

- 项目创作者可以登记、整理、形成版本和建立获授权范围内的引用。
- 项目审核者可以确认专业基准并查看使用影响；改变正式采用必须进入 REQ-006。
- 项目负责人、资产管理者、美术、声音创作者和生产成员都是业务职责，按 REQ-002 映射为项目创作者或审核者，职责名称本身不增加权限。
- 平台运营只在明确权利、安全或故障事件中访问和处置，不替用户做创作选择。
- MVP 可以由一人兼任创作和确认责任，但关键版本、来源、采用与运营处置仍需可区分。

## 8. MVP 完整闭环

MVP 通过标准是：用户可登记核心资产，区分身份、版本、参考和生产媒体；把明确版本引用到单集与镜头；从资产反查直接使用范围；追溯来源和基础权利声明；在资产变化时看见直接影响；关联查看 REQ-005 候选和 REQ-006 采用结论；在同一单集中复用资产而不丢失历史。

不纳入 MVP：多集连续性治理、跨项目资产库、公共素材或版权市场、专业媒体编辑、模型训练与生成编排，以及任何具体存储和检索方案。

## 9. 需要真实生产验证的问题

- 首发内容实际需要哪些资产类别，哪些对象不值得资产化。
- 用户能否稳定区分资产身份、版本、候选和采用结果。
- 哪些变化只需提示，哪些必须阻断新制作或要求复核。
- 角色与服装、场景与状态、声音身份与演绎版本的边界是否符合用户心智。
- 商业交付所需的肖像、声音、参考素材和 AI 标识证明到什么粒度。
- 项目内复用能否支持首发，何时必须升级到多集或跨项目管理。
