### 0.1 事实与责任边界

- CUR-SEC 是当前产品中 RightsDecision、ContentSafetyDecision、DataLifecycleDecision 和受控 AuditRecord 的唯一产品事实源。
- 业务模块只提交固定资源、用途和动作上下文并消费 allowed/blockers/warnings，不复制权利、内容安全、保留或审计终态。
- 本文件不提供法律意见，也不在 Requirement 中固定审核供应商、加密算法、扫描引擎、日志平台或特定地区法律条文；首发地区的有效政策版本必须在发布前由负责人签认。
- 安全与合规不是商业运营模块。它只服务当前创作、生成、媒体和素材交接的必要门禁、用户解释和恢复。

## 1. 模块定位

CUR-SEC 负责确保：用户提交的剧本、Prompt、图片、视频和权利证明只在被允许的 Workspace、用途、地区和时间范围内使用；不允许的内容在产生新外部副作用前被阻断；必要的人审和申诉有明确状态；Provider 对输入数据的处理满足已接受策略；数据保留、删除、下载和审计具有可解释边界。

### 1.1 用户结果

1. 用户在上传或生成前知道需要声明哪些来源、真人授权和使用范围。
2. 内容或权利被阻断时，用户看到具体对象、政策类别和安全下一动作，而不是模糊“审核失败”。
3. 用户可以修正输入、替换媒体、补充权利证明或请求人工复核，不会因重试绕过门禁。
4. Provider 不得在未知数据保留、训练使用或处理地域的情况下被标记为可处理敏感创作输入。
5. 历史任务、候选和导出不会因后续政策变化被篡改，但新访问、新生成和新导出按当前政策重新判断。
6. 用户能请求数据导出或删除，并理解业务引用、争议、安全事件和 legal hold 对处理时限的影响。

## 2. 范围与非范围

### 2.1 当前范围

- 剧本、Prompt、图片、视频、权利证明和导出包的数据分类与最小使用。
- CanvasLayoutRevision、画布投影摘要和 AgentActionProposal 的最小化、跨 Workspace 隔离与高风险动作治理；画布/Agent 确认不替代本模块决定。
- 输入来源、使用权、真人肖像/形象同意、期限、地区和用途声明。
- 生成预检、正式提交、主选、导出冻结和媒体下载的权利门禁。
- 基于版本化政策的内容安全预检、Provider 结果检查和导出检查。
- 对违法/受限类别、未成年人风险、未经同意的真人仿冒、性内容、极端暴力、仇恨/骚扰及其他首发政策类别的可解释阻断。
- 误判复核、补证、申诉、人工处置和决定历史。
- Provider 数据处理、保留、训练使用、处理地域和删除能力准入。
- AIGC/来源标识和 Manifest 治理摘要。
- 数据查看、下载、保留、归档、删除、账号删除交接和 legal hold。
- 安全审计、脱敏诊断、越权拒绝、下载与高影响治理动作记录。
- 安全事件和滥用报告的受控入口与处置状态。

### 2.2 明确非范围

- 自动给出版权归属、肖像权或地区法律结论。
- 面向外部客户的法律服务、合同管理或知识产权交易市场。
- 商业广告审核、发行备案、平台投放审核和营销运营后台。
- 通用企业 DLP、SIEM 产品、全公司 GRC 平台或任意审批引擎。
- 允许普通用户查看 Provider 原始审核响应、内部规则细节或他人证明材料。
- 通过“仅供参考”文案绕过明确的内容、权利、隐私或安全 blocker。
- 把安全派生预览、转码或水印文件当成当前产品的成片编辑能力。

## 4. 核心用户场景

### CUR-SEC-US-001 上传真人参考图

用户上传可识别真人参考图，填写来源、本人/授权关系、允许用途、地区和期限。缺少必要同意时，该媒体可以隔离保存以便补证，但不能进入生成 ready。

### CUR-SEC-US-002 内容预检被阻断

用户提交视频生成，系统指出具体 Prompt/媒体触发的政策类别、当前不可执行动作和允许的修正/复核入口，不把 Provider 原始审核响应直接暴露。

### CUR-SEC-US-003 权利在预检后撤销

用户已通过导出预检，但冻结前某参考媒体授权被撤销。冻结重新校验并失败，历史候选和旧包不被篡改。

### CUR-SEC-US-004 Provider 数据政策不满足

一个 Provider 能生成目标视频，但会把用户媒体用于训练且无法关闭。该能力不得处理当前受保护输入，并显示不可用原因。

### CUR-SEC-US-005 删除账号数据

用户请求删除账号。系统列出必须先完成的 owner 转移、运行任务、历史包、争议/安全事件和保留决定；blocker 关闭后在目标窗口内执行并提供结果摘要。

## 6. 详细功能需求

### CUR-SEC-FR-001 分类并最小化使用敏感创作数据

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 系统将要接收、显示、记录、发送或导出剧本、Prompt、媒体、证明、身份、画布布局或 Agent 提议数据。 |
| 主流程 | 系统按当前数据分类识别内容正文、个人/真人信息、权利证明、凭据/签名地址、生成输入输出、Canvas/Agent 上下文、诊断和公开元数据；只向当前动作、操作者和 Provider 发送最小必要字段；用户可查看用途摘要。 |
| 备选流程 | 用稳定 ID、摘要、枚举和脱敏诊断替代完整正文；确需处理原媒体时使用受控临时能力。 |
| 失败流程 | 分类未知、用途不明确或最小必要范围无法确认时，不向外部 Provider 发送，也不把内容写入普通日志/指标。 |
| 业务规则 | 完整剧本、完整 Prompt、敏感证明和原媒体默认私有；不能用调试便利扩大收集；用途变化必须重新判断。 |
| 输入 | 固定对象、数据类别、动作、用途、接收者和时间。 |
| 输出 | 允许处理字段、禁止字段、保留类别和 blocker。 |
| UI 要求 | 用创作语言说明数据用途，不显示内部字段清单；高风险外发前明确提示接收方类别和用途。 |

### CUR-SEC-FR-002 登记、验证、撤销和重新判断权利

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户准备上传/使用剧本、参考媒体、真人形象或外部候选。 |
| 主流程 | 用户登记来源、权利主体关系、允许用途、地区、有效期、可选证明和真人同意；系统固定到具体资源版本；在预检、正式提交、主选、导出冻结和原始下载时重新判断 allowed/warning/blocked。 |
| 备选流程 | 信息不足时资源进入 evidence_required，可保存但不能用于受阻用途；用户补证或替换资源后重新判断。 |
| 失败流程 | 权利依赖 unavailable、证明失效、用途/地区/期限不匹配、真人同意缺失或跨 Workspace 时 fail closed。 |
| 业务规则 | RightsDecision 固定资源版本、用途、政策版本和判断时间；撤销/过期阻止新的副作用，不改写历史 Candidate/Selection/Snapshot。 |
| 输入 | actor、Workspace、资源版本、来源、用途、地区、期限、证明引用和当前时间。 |
| 输出 | RightsDecision、blockers/warnings、依据摘要和下一动作。 |
| UI 要求 | 不使用“系统确认你拥有版权”之类法律结论文案；显示需要用户完成的具体声明或证明。 |

### CUR-SEC-FR-003 在生成与导出前执行内容安全门禁

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 已固定生成/上传/导出范围及当前有效内容政策版本。 |
| 主流程 | 系统检查固定剧本/Prompt 摘要、相关媒体、真人/未成年人风险、目标用途和 Provider 能力；返回 allowed/warning/blocked；正式 Provider 提交和导出冻结必须重新校验。Provider 返回结果后在成为可主选媒体前执行结果检查。 |
| 备选流程 | 对可修正输入提供定位和修改入口；低风险但需要确认的 warning 保存确认人、理由和政策版本。 |
| 失败流程 | 检查服务 unavailable、政策版本未知、输入无法检查或命中 disallowed 类别时阻断新副作用；不得自动切换 Provider 绕过。 |
| 业务规则 | disallowed 类别由首发政策版本定义并至少覆盖违法内容、未成年人性风险、未经同意的真人仿冒、性内容、极端暴力、仇恨/骚扰等评审类别；用户自述不能覆盖硬 blocker。 |
| 输入 | 固定内容/媒体版本、用途、政策版本、Provider 和目标动作。 |
| 输出 | ContentSafetyDecision、命中类别摘要、对象定位、允许动作和复核入口。 |
| UI 要求 | 不展示可用于规避规则的内部阈值或 Provider 原响应；同时避免只显示“审核失败”。 |

### CUR-SEC-FR-004 处理补证、人工复核和申诉

| 项目 | 需求 |
| --- | --- |
| 前置条件 | RightsDecision/ContentSafetyDecision 为 evidence_required、review_required 或用户认为存在误判。 |
| 主流程 | 用户查看可申诉范围，补充必要来源/证明或说明，提交 ReviewCase；受控审查者查看最小必要证据并追加维持、允许指定用途或继续阻断的决定；用户收到结果和下一动作。 |
| 备选流程 | 用户可不申诉而修改输入/替换媒体；ReviewCase 未完成前原 blocker 保持。 |
| 失败流程 | 证明跨 Workspace、已撤销、无法验证或审查者权限不足时不改变原决定；审查依赖 unavailable 时显示等待。 |
| 业务规则 | 人工决定必须固定对象、用途、政策版本、审查人、理由枚举和有效期；不能“全局白名单”一个用户或对象；后续内容变化需要新决定。 |
| 输入 | 原决定、补充证据、请求理由和指定用途。 |
| 输出 | ReviewCase、追加治理决定、有效范围和用户可见摘要。 |
| UI 要求 | 明确状态 pending_review/needs_evidence/resolved；不承诺未配置人员和时区的虚假即时 SLA。 |

### CUR-SEC-FR-005 管理 Provider 数据处理准入

| 项目 | 需求 |
| --- | --- |
| 前置条件 | CUR-PLT 准备把真实创作输入交给图片/视频 Provider。 |
| 主流程 | 受控负责人登记并验证 Provider 对输入/输出保留、训练使用、处理地域、子处理方、删除、审核和安全事件通知的当前证据；形成 DataProcessingProfile；业务预检按数据分类和用途检查是否允许使用。 |
| 备选流程 | 同一 Provider 的不同能力/账号/地域可有不同 Profile；能力可因输入敏感级别而部分可用。 |
| 失败流程 | 训练使用无法关闭且当前数据策略不允许、地域/保留未知、证据过期或处理目的不匹配时能力对该输入 unavailable。 |
| 业务规则 | Provider 技术可调用不等于数据处理准入；Profile 必须版本化并有复核日期；变更不篡改历史请求，但阻止不符合的新提交。 |
| 输入 | Provider/能力配置版本、合同/官方证据摘要、地域、保留、训练、删除和数据类别。 |
| 输出 | DataProcessingProfile、允许数据类别/用途、blocker 和复核时间。 |
| UI 要求 | 普通创作者看到“可用于当前内容/不可用原因”，高级详情只显示必要政策摘要，不显示合同或凭据。 |

### CUR-SEC-FR-006 记录 AIGC 来源与交付标识决定

| 项目 | 需求 |
| --- | --- |
| 前置条件 | Candidate 或素材包含 AI 生成/修改内容，目标地区和交付用途已明确。 |
| 主流程 | 系统记录每个 Candidate 的生成/上传来源、Provider/能力摘要和必要 AIGC 元数据；导出预检根据政策决定包/文件/Manifest/README 是否必须携带可见或机器可读标识；冻结时固定决定。 |
| 备选流程 | 外部上传结果来源未知时标记 source_unverified，并按政策 warning/blocked；当前无需修改原始视频字节时，可在文件名、Manifest/README 或独立元数据中表达。 |
| 失败流程 | 首发政策要求标识但无法形成或验证时导出 blocked；不得为了添加标识而静默转码或修改原始媒体。 |
| 业务规则 | AIGC 标识决策属于治理事实，不等于成片加工；原始字节不因标识要求被改写；标识规则必须固定政策版本和用途。 |
| 输入 | Candidate/ExportSnapshot、来源、地区、用途和政策版本。 |
| 输出 | ProvenanceLabelDecision、Manifest/README 所需字段、warning/blocker。 |
| UI 要求 | 导出前说明标识将出现在哪里；不要把“已标识”表述为自动满足所有法律义务。 |

### CUR-SEC-FR-007 管理数据保留、导出、删除和 legal hold

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 数据对象、业务引用、账号/Workspace 状态、争议/安全事件和保留依据可查询。 |
| 主流程 | 系统按数据类别和引用计算 retention_at/删除资格；用户可请求自己的可携带数据摘要和删除；处理前列出 blocker；blocker 关闭后执行删除/匿名化并保留可证明结果；legal hold 只冻结必要范围。 |
| 备选流程 | ready 包字节可先过期而保留 Snapshot/Manifest 摘要；历史媒体仍被冻结包引用时按策略延长；用户可取消尚未执行的请求。 |
| 失败流程 | 保留决策 unavailable、仍有 owner 归属、unknown 外部副作用、有效争议/安全事件或 legal hold 时暂停并解释，不伪装已删除。 |
| 业务规则 | 一个全局固定天数不得替代分类保留；策略变化可更新 retention_at，不改写旧 Snapshot/Manifest/hash；历史 actor 可被最小化但不能错误归因他人。 |
| 输入 | actor、数据范围、请求类型、业务引用、保留依据和政策版本。 |
| 输出 | DataLifecycleDecision、retention_at、blocker、处理状态和结果摘要。 |
| UI 要求 | 清楚区分包字节过期、业务历史保留、账号停用和数据删除；显示当前目标日期及延迟原因。 |

### CUR-SEC-FR-008 保护媒体、证明、下载和敏感访问

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户/Worker 将上传、探测、预览、下载或导出媒体/证明。 |
| 主流程 | 系统在隔离区接收文件，执行实际类型、完整解码/探测、大小/hash、安全硬上限和恶意内容检查；通过后按用途和当前权限提供短期私有访问能力；敏感证明采用更严格查看权限。 |
| 备选流程 | 探测/扫描暂不可用时保持 quarantined，不删除证据也不进入 ready；原始媒体与预览派生物分别标识。 |
| 失败流程 | 超出安全硬上限、类型伪造、恶意/不可安全解析、跨 Workspace、权限/权利失效时拒绝 ready 或访问；不得自动执行不受控转码。 |
| 业务规则 | 安全硬上限是防止资源耗尽/解析风险的 accepted 门禁；产品容量目标和 UI warning 阈值与其分离；临时 URL/令牌不进入业务事实、Manifest、日志或审计。 |
| 输入 | actor/Worker、Workspace、字节、声明规格、用途、目标对象和当前授权。 |
| 输出 | 安全接收结果、quarantined/ready/blocked、短期能力或统一拒绝。 |
| UI 要求 | 区分文件不安全、超安全上限、超当前产品容量和仅需 warning；不向用户暴露扫描规则细节。 |

### CUR-SEC-FR-009 受控审计与脱敏诊断

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 发生身份/成员、Provider 提交、任务命令、媒体登记/访问、权利/安全决定、主选、导出、下载、数据删除或越权拒绝。 |

### CUR-SEC-FR-010 报告并处置安全事件或滥用

| 项目 | 需求 |
| --- | --- |
| 前置条件 | 用户或系统识别账号异常、越权、敏感数据暴露、恶意媒体、未经同意的真人仿冒或其他安全/滥用风险。 |

## 8. 状态机与不变式

### 8.1 状态

- RightsDecision/ContentSafetyDecision：`pending → allowed | warning | blocked | review_required | evidence_required | unavailable`；输入/用途/政策变化后重新计算新决定，旧决定不覆盖。
- ReviewCase：`submitted → in_review → needs_evidence | resolved_allowed | resolved_blocked | withdrawn`。
- DataProcessingProfile：`unverified → active | restricted | unavailable | expired`。
- DataLifecycleDecision：`requested → assessing → blocked | scheduled → executing → completed | failed`。
- SecurityCase：`received → in_review → action_required | contained → resolved`。

### 8.2 不变式

1. 新 Provider 副作用、主选、导出冻结和原始下载均只消费当前对象/用途的有效治理决定。
2. 权利、安全或数据处理依赖未知时 fail closed，不自动换 Provider 绕过。
3. 人工复核追加决定，不修改原证据、原输入或历史任务。
4. 治理决定必须固定对象版本、用途、政策版本、判断时间和决定来源。
5. 撤销/过期阻止新的动作，不篡改历史 Candidate、Selection、ExportSnapshot、PackageBuild 或消耗。
6. Provider 技术可用性与数据处理准入是两个独立 Gate。
7. 安全硬上限、产品容量目标和 UI warning 阈值是三个独立概念。
8. 任何普通日志、指标、前端错误或 Manifest 不包含凭据、签名能力或内部敏感诊断。
9. AIGC 标识不得通过静默修改原始媒体实现；当前产品仍导出原始逐镜素材。
10. 审计、ReviewCase 和 SecurityCase 只追加，不因用户删除请求伪造或错误归因。

### 13.2 已决策事项

- CUR-SEC 唯一拥有权利、内容安全、Provider 数据处理准入、数据生命周期和受控审计决定；CUR-PLT 不复制治理终态。
- 新 Provider 副作用、媒体 ready、主选、导出冻结和原始下载均需当前有效治理决定。
- Provider 技术可调用不等于可处理当前数据；保留、训练、地域或删除证据未知时对受保护输入 fail closed。
- 人工复核只追加限定对象/用途/期限的决定，不允许全局白名单，也不改写用户业务对象。
- AIGC 标识不能通过静默修改、转码或拼接原始媒体实现；当前导出仍是逐镜原始素材包。
- 安全硬上限、产品容量目标和 UI warning 阈值必须分开评审和验收。

| RightsDecision | 固定资源在指定用途、地区、时间和政策版本下的权利判断。 |
| ContentSafetyDecision | 固定内容/媒体在指定动作和政策版本下的安全治理判断。 |
| DataProcessingProfile | Provider/能力配置对数据保留、训练、地域和删除的准入事实。 |
| ReviewCase | 补证、误判复核或申诉的受控状态与追加决定。 |
| legal hold | 因争议、安全事件或受控义务暂缓删除必要范围数据的决定。 |
| 安全硬上限 | 防止资源耗尽或解析风险、必须在实现前 accepted 的输入上限。 |
| 产品容量目标 | 首发用户场景希望稳定支持的业务规模，不等于安全硬上限。 |
| UI warning 阈值 | 在达到硬上限前向用户提示成本、等待或兼容风险的交互阈值。 |
