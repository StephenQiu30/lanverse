# REQ-23 批量生成

| 项 | 内容 |
| --- | --- |
| 需求 | GEN-03 批量生成 |
| 优先级 | MVP |
| 用例 | UC-16 |
| 页面 | 镜头表、故事板、资产定稿、配音、影响清单的批量操作 |
| 依赖功能 | REQ-21、REQ-24 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

一集 20–150 个镜头、数十句台词，逐个操作不可行（PRD-01 §12）。批量是一次报价、一次确认、逐项独立执行、汇总结果。

### 1.2 用户故事

- 作为**制作者**，我希望对整场或整集的镜头一次发起生成，剔除个别项，并看到汇总结果，对失败项单独重试。

### 1.3 范围

包含：多选或按范围（场 / 集 / 筛选结果）批量报价、剔除、确认、并发执行、汇总、失败重试、整批取消。不包含：跨项目批量。

## 2. 需求分析

### 2.1 业务流程

```text
选择范围 → POST /quotes（多项）→ 批次报价（逐项费用与错误）→ 剔除错误项 / 不需要的项 → 确认
→ BatchWorkflow：按项目并发上限与供应商配额启动子 OperationWorkflow
→ 汇总：成功 / 失败 / 结果未知 / 已取消 → batch.finished → 一条汇总通知
→ 失败项“重试” = 对失败项重新报价（新批次）
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 单批最多 300 项 | 控制单次风险与报价耗时 |
| R2 | 有错误的项不进入可确认列表，其余项可确认 | 部分可执行 |
| R3 | 每项独立执行、独立结算，一项失败不影响其他项 | GEN-03 |
| R4 | 批次内并发 = min(项目并发上限 20, 供应商剩余配额)，其余排队 | CAP-06 |
| R5 | 整批取消：未开始的项取消并释放预留；进行中的项按 REQ-24 取消规则处理 | GEN-07 |
| R6 | 批次结束只发一条汇总通知 | NTF-01 |
| R7 | 重试失败项生成新批次，需重新确认 | GEN-11 |

### 2.3 状态

`batch.status`：`quoted` → `confirmed` → `running` → `finished`；`quoted` → 过期；任意 → `cancelled`。

### 2.4 异常与边界

- 批次执行中 Worker 重启：父工作流从历史恢复，已完成子项不重做。
- 供应商大面积失败（连续 5 项同类错误）：暂停未开始项并通知，由用户决定继续或取消（避免批量浪费）。

## 3. 实现所需

### 3.1 数据

`operation.batch`（`scope`、`status`、`total/succeeded/failed/unknown_count`、`quote_total_micros`、`workflow_id`）；`operation.operation.batch_id`。批次新增 `paused_reason text`（DES-02 同步）。

### 3.2 接口

```http
POST /api/projects/{pid}/quotes         （多项，见 REQ-21）
POST /api/batches/{id}:confirm          { "exclude_operation_ids": ["…"] }
GET  /api/batches/{id}
200 { "id": "…", "status": "running", "total": 20, "succeeded": 12, "failed": 1, "unknown": 0, "running": 5, "queued": 2,
      "paused_reason": null, "items": [ { "operation_id": "…", "target_label": "3-12", "status": "completed" } ] }
POST /api/batches/{id}:cancel
POST /api/batches/{id}:resume           （暂停后继续）
POST /api/batches/{id}:retry-failed     → 为失败项生成新的批次报价
```

### 3.3 异步与工作流

`BatchWorkflow`（`batch/{id}`）：子工作流 `operation/{op_id}`，`ParentClosePolicy = ABANDON`（父工作流异常不影响已提交的子项）；使用信号 `cancel`、`resume`；熔断计数在工作流状态中（DES-04）。

### 3.4 事件与实时

`batch.finished.v1` → notify；SSE `batch.updated`。

### 3.5 界面

批量工具栏；报价对话框（逐项列表可剔除）；批次进度条（在任务中心与发起页面顶部）；完成后结果摘要与“重试失败项”。

### 3.6 权限与审计

制作者；审计 `batch.confirmed`、`batch.cancelled`。

### 3.7 非功能要求

CAP-02（≥ 200 并发任务平台不成为瓶颈）；PERF-10（150 项报价 ≤ 5 秒）。

## 4. 验收标准

- Given 整场 20 个镜头批量生成，其中 2 个失败，When 查看批次，Then 18 个成功、2 个失败各有原因，失败项可单独重试。
- Given 批量报价中 3 项有错误，When 确认，Then 只执行其余项，错误项不产生费用。
- Given 执行中取消批次，When 检查，Then 未开始项已取消且预留释放。

## 5. 测试要点

父子工作流回放测试；熔断暂停；取消与预留释放。
