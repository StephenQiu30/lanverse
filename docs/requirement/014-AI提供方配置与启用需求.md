## 1. 需求概述

Workspace owner 必须能从主流 AI 平台预设中创建和维护提供方配置，把敏感凭据安全保存为服务端事实，并明确检查连接、选择模型能力、启用到业务用途、切换、停用、轮换和归档。配置管理不能要求每次修改部署环境，也不能把 API Key 暴露给浏览器、普通日志或其他 Workspace。

产品必须区分以下事实：平台出现在预设目录、用户已保存配置、凭据可用、连接检查健康、模型契约通过、某个业务用途已启用、真实任务执行成功。前一状态不自动证明后一状态；未通过真实 Provider 契约的模型即使已配置凭据也必须保持不可用。

首批预设固定为 DeepSeek、火山方舟、OpenAI、Anthropic Claude、Google Gemini、阿里云百炼、Moonshot Kimi、智谱 GLM、MiniMax、OpenRouter 和自定义 OpenAI-compatible。除现有 DeepSeek 文本能力外，其他预设先提供安全配置入口，不承诺已经具备生产执行能力；火山方舟图片/视频继续受 D-004 约束。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| AIP-ENT-001 | ProviderPreset | 必须以稳定 ID 和版本描述平台名称、官方资料、协议、认证字段、地域/端点模板、模型发现策略和能力提示；不得包含用户凭据。 |
| AIP-ENT-002 | ProviderConnection | 必须属于唯一 Workspace，保存预设版本、显示名、地域、端点、非敏感配置、配置状态、revision 和生命周期；归档不得抹除历史引用。 |
| AIP-ENT-003 | ProviderCredentialVersion | 必须表示一次只追加的凭据版本，服务端只持久化经过认证加密的密文、密钥版本和必要完整性元数据；明文不得持久化或返回。 |
| AIP-ENT-004 | ProviderBinding | 必须把一个已验收 ModelCapability 和一个凭据版本绑定到 Workspace 的明确 usage_type，并保存激活/停用人、时间和不可变版本引用。 |
| AIP-ENT-005 | ProviderHealthCheck | 必须只追加保存被检查的连接/凭据版本、检查类型、安全状态、延迟、受控错误和有效期；不得保存探针请求/响应正文。 |

ProviderPreset 不等同 ModelCapability。预设回答“可怎样配置平台”，ModelCapability 回答“哪一个模型契约已被系统验证并允许执行”，ProviderBinding 回答“这个 Workspace 当前用哪一套已验证配置”。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| AIP-FR-001 | 登录成员必须能查看首批 ProviderPreset 的名称、协议、地域、能力提示、目录版本、官方文档和当前准入状态；预设列表不得包含凭据或把 catalog-only 显示为可执行。 |
| AIP-FR-002 | Workspace owner 必须能基于预设创建、查看和更新 ProviderConnection；系统必须校验预设允许的地域、端点和非敏感配置，并以 revision 防止并发覆盖。 |
| AIP-FR-003 | Workspace owner 必须能写入和轮换 Provider 凭据；提交字段必须 write-only，成功后只显示“已配置”、凭据版本和轮换时间，不能回显、复制或下载原值。 |
| AIP-FR-004 | Workspace owner 必须能显式获取平台支持的模型候选；发现结果只用于辅助选择，未知模型不得自动成为 active ModelCapability。 |
| AIP-FR-005 | Workspace owner 必须能显式检查连接和凭据；系统必须区分认证失败、模型无权限、限流、超时、不可达、不支持无副作用探针和响应不合法。 |
| AIP-FR-006 | Workspace owner 必须能把健康 Connection、current CredentialVersion 和 active ModelCapability 启用到 `script_structure`、`image_generation` 或 `video_generation`；任一门禁不满足时必须返回明确 blocker。 |
| AIP-FR-007 | Workspace owner 必须能原子切换或停用某个 usage_type 的当前绑定；切换只影响随后创建的新请求，不取消、迁移或重发运行中任务。 |
| AIP-FR-008 | Workspace owner 必须能查看每个 Connection 的配置、健康、模型契约和用途绑定状态；editor/viewer 只能通过业务能力/预检看到执行可用性，不得查看 Provider 管理细节。 |
| AIP-FR-009 | 系统必须提供一次性受控流程，把当前 DeepSeek 环境配置迁移为数据库 Connection、加密 CredentialVersion 和 `script_structure` Binding；切换成功后新请求不得继续静默读取旧 Provider Key。 |
| AIP-FR-010 | Workspace owner 必须能归档不再使用的 Connection 和撤销凭据；active Binding、retiring 凭据或非终态任务仍引用时必须阻断并说明影响。 |
| AIP-FR-011 | Workspace 设置必须提供完整 Provider 管理页面，明确分离“保存配置”“检查连接”“启用到用途”，并展示切换影响、阻断原因、版本冲突和无权限状态。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| AIP-IF-001 | 预设目录查询 | ActorContext、可选协议/能力筛选 | 脱敏 ProviderPreset 列表、版本、官方资料和 catalog-only/available 状态 |
| AIP-IF-002 | Connection 查询与命令 | ActorContext、Workspace、预设/地域/端点/非敏感配置、expected revision | Connection 状态与版本；跨空间、非法端点、陈旧 revision 和归档冲突使用稳定错误 |
| AIP-IF-003 | 凭据写入与轮换 | ActorContext、Connection、write-only credential、expected revision | 新 CredentialVersion 的 ID、版本、状态和时间；响应/错误不得包含提交值 |
| AIP-IF-004 | 模型发现与健康检查 | ActorContext、Connection/credential revision、检查类型、幂等键 | 有界候选或 HealthCheck；认证、限流、超时、不可达、解析和不支持状态归一化 |
| AIP-IF-005 | Binding 启用/切换/停用 | ActorContext、usage_type、Connection/Credential/Capability 版本、expected revision | 唯一当前 Binding 或 blocker；并发冲突回读服务端当前事实 |
| AIP-IF-006 | 运行时 Provider 解析 | Workspace、usage_type、请求创建时的固定 Capability | 不可变 Binding/Connection/Credential/adapter 引用或 `provider_binding_unavailable`；不返回明文凭据 |
| AIP-IF-007 | 审计与运维查询 | Workspace、actor、target、action、时间范围 | 不含凭据、完整 endpoint query、prompt 或上游正文的配置/检查/切换/轮换审计 |
| AIP-IF-008 | 前端生成契约 | FastAPI OpenAPI schema | 由 `umi-openapi` 生成的 Provider client/typing；页面不得手写平行 DTO 或直连上游平台 |

## 5. 状态与业务语义

Provider 管理必须组合展示三条独立状态：

- 配置：`incomplete | valid | invalid`；
- 健康：`unchecked | healthy | degraded | unreachable`；
- 用途绑定：`unavailable | inactive | active`。

凭据版本至少支持 `current | retiring | revoked`。轮换产生新的 current，旧版本只有在没有非终态任务引用后才能正常撤销；owner 明确选择立即撤销时，受影响任务必须以类型化错误进入人工处理，不能自动改用新 Key 重发。

同一 `(workspace_id, usage_type)` 同时最多一个 active Binding。启用/切换必须校验 Connection revision、CredentialVersion、健康检查有效期、ModelCapability 状态和 adapter contract version，并把旧 active Binding 与新 Binding 在一个事务中切换。

## 6. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| AIP-NFR-001 | 租户与权限 | Connection、CredentialVersion、Binding 和 HealthCheck 必须按 Workspace 隔离；只有 owner 可写配置、凭据和绑定，跨空间 ID 不得泄露存在性。 |
| AIP-NFR-002 | 凭据保密 | Provider 凭据不得以明文进入数据库、备份、API 响应、OpenAPI 生成文件、浏览器存储、日志、trace、metric、AuditEvent、消息或错误正文。 |
| AIP-NFR-003 | 密文完整性 | 凭据必须使用带认证的加密和记录级关联数据；密文、nonce、tag、Workspace/Connection/版本被篡改或互换时必须拒绝解密。 |
| AIP-NFR-004 | Fail closed | 主密钥/KMS 不可用、配置不完整、健康过期、Capability 未验收或契约版本不匹配时，不得启用或执行，也不得回退到未知环境 Key。 |
| AIP-NFR-005 | 并发与幂等 | 创建、更新、轮换、检查、启用、切换、停用和归档必须有幂等/expected revision 语义；并发命令不得产生两个 active Binding 或覆盖配置。 |
| AIP-NFR-006 | 网络安全 | 自定义端点和所有 Provider I/O 必须防 SSRF、DNS rebinding、重定向绕过、私网/元数据访问、无限响应、无限等待和不受控重试。 |
| AIP-NFR-007 | 脱敏与可观测 | Provider 操作必须可按 trace、Workspace、Connection 和 safe error code 关联，但指标维度有界且任何遥测故障不能泄露凭据或改变业务状态。 |
| AIP-NFR-008 | 运行一致性 | 请求创建后必须固定 Provider 配置与凭据版本；切换/轮换不能使已有 Request/Task/Attempt 漂移，恢复时必须读取原快照。 |
| AIP-NFR-009 | 性能与容量 | 不含外部平台时间的目录、Connection 查询/保存和 Binding 命令遵守普通 API P95 ≤500 ms；健康/模型发现必须有固定总超时和每 Connection 限流。 |
| AIP-NFR-010 | 备份与恢复 | 数据库备份只含密文；主密钥轮换、恢复验证和凭据撤销必须可审计。MVP 不提供带凭据的导入/导出。 |
| AIP-NFR-011 | Provider 准入 | 预设、模型发现或成功鉴权均不能替代真实模型参数、价格、权限、失败和副作用契约；每个新执行能力必须单独验收。 |
| AIP-NFR-012 | 前端安全与可访问性 | Key 成功提交后必须从控件和客户端状态清除；管理操作可用键盘完成，状态、错误、禁用原因和确认 Dialog 对辅助技术可读。 |

## 7. 失败路径

- 凭据加密失败时 Connection 非敏感配置和 CredentialVersion 不得局部提交；错误响应不得包含提交值。
- 健康检查失败只追加失败事实，不删除配置、不改 endpoint、不自动停用或切换运行中 Binding。
- active Binding 健康检查过期时，新启用被阻断并显示 degraded；已有任务仍按原快照收敛，不自动故障转移。
- 模型发现返回空、未知或超大结果时不得创建 ModelCapability；响应超限或解析失败返回受控错误。
- 并发切换只有一个事务成功，失败方获得版本冲突和当前 active Binding，不出现短暂双 active。
- 主密钥不可用时允许 owner 查看非敏感配置状态，但凭据写入、检查、启用和运行必须 fail closed。
- 存量数据库没有已接受迁移方案时不得运行 Provider 回填；空库实现通过不能冒充生产存量升级通过。

## 8. 非目标与外部门禁

- 不实现通用 AI Gateway、协议转换代理、本机应用配置切换、个人订阅/OAuth Token 复用、自动 Provider 故障转移或多 endpoint 自动选路。
- 不允许前端自定义 Header、保存任意 secret JSON、直接调用 Provider 或把 `/models` 结果自动升级为执行契约。
- 首批除 DeepSeek 外均允许以 catalog-only 完成配置控制面验收，但真实执行必须逐 Provider/模型/用途另行接受。
- 火山方舟 Seedream/Seedance 的真实账号权限、额度、参数、账单、回调和取消竞态继续由 D-004 阻断；录入 Ark Key 不关闭门禁。
- 当前数据库仍只承诺空库初始化。存在不可丢失数据的环境必须先接受独立 DDL/备份/演练/回滚方案。

## 9. 接受边界

本 Requirement 的业务范围已经接受，但实现状态仍为未开始。后续只能按 PRD-011 的 `PT-AIP-*` 逐项接受：Provider 管理控制面通过不等于 S4 图片/视频生成通过，预设目录通过不等于任何 catalog-only Provider 执行通过，DeepSeek 切换通过也不外推到其他 Provider。
