# REQ-010 剪辑交付模块需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`003-项目模块需求.md`、`004-媒体模块需求.md`、`005-审核治理模块需求.md`、`008-分镜模块需求.md`、`009-生产模块需求.md`
- 输出：时间线、音画编排、预览、审核交接、渲染和交付需求
- 下游：MVP PRD、接口契约和实施 Plan

## 1. 需求概述

剪辑交付模块必须把已选镜头、对白/旁白、字幕、音乐和音效编排为可播放 Timeline，发布不可变版本，经审核后渲染为成片并生成可验证 DeliveryManifest。

MVP 提供完成短剧闭环所需的基础剪辑能力，不追求专业 NLE。Track、Clip、SubtitleCue 和转场是 Timeline 聚合的类型化子项，不分别扩张为独立顶层模块和全套 CRUD。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| EDT-ENT-001 | Timeline | 必须归属 Episode，表示当前可变草稿并保存当前发布版本 ID。 |
| EDT-ENT-002 | Track/Clip | 必须在 Timeline 内表达视频、对白、旁白、音乐、音效和字幕的顺序、入出点、位置、音量及来源版本。 |
| EDT-ENT-003 | SubtitleCue | 必须表达起止时间、文本、说话人/类型和样式语义，且能导出独立字幕文件。 |
| EDT-ENT-004 | TimelineVersion | 必须不可变，保存完整编排快照、来源 MediaVersion/Candidate 和发布人。 |
| EDT-ENT-005 | Render | 必须引用固定 TimelineVersion、输出规格、Task、状态和产生的 MediaVersion。 |
| EDT-ENT-006 | DeliveryManifest | 必须引用获批 TimelineVersion、最终媒体、字幕、hash、内容编号、标识、审核和来源链。 |

Clip 只能引用可访问的固定 MediaVersion；Candidate 当前选择变化不得静默替换已发布 TimelineVersion。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| EDT-FR-001 | 系统必须能根据 Episode 镜头顺序和已选候选建立/刷新 Timeline 草稿，并列出缺失镜头媒体。 |
| EDT-FR-002 | editor/owner 必须能批量新增、移动、裁剪、替换和删除 Clip，调整基础转场、音量和轨道顺序。 |
| EDT-FR-003 | 用户必须能为对白/旁白选择声音、使用生产候选，并编辑/校对 SubtitleCue。 |
| EDT-FR-004 | 用户必须能生成和播放低成本预览，定位到具体 Shot/Clip/时间位置。 |
| EDT-FR-005 | 用户必须能把 Timeline 草稿发布为不可变 TimelineVersion；缺媒体、越界 Clip 或时长冲突必须阻止发布。 |
| EDT-FR-006 | 用户必须能提交固定 TimelineVersion 审核，并根据 Issue 返回具体 Clip/Shot 修改后发布新版本。 |
| EDT-FR-007 | 只有审核批准、授权/内容检查通过且无阻塞 Issue 的 TimelineVersion 才能提交最终渲染。 |
| EDT-FR-008 | 用户必须能查询、取消允许取消的 Render，并在失败后从同一 TimelineVersion 安全重试。 |
| EDT-FR-009 | 渲染成功后系统必须生成 MP4、字幕和 DeliveryManifest，写入并验证适用生成标识。 |
| EDT-FR-010 | 用户必须能下载有权访问的交付文件并验证 hash；历史交付版本保持可追溯。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| EDT-IF-001 | 获取/初始化 Timeline 草稿 | ActorContext、Episode ID | Timeline 草稿、缺失媒体和来源变化提示 |
| EDT-IF-002 | 批量编辑 Timeline | Timeline ID、期望 revision、受控 Clip/Cue 操作列表 | 新草稿 revision；任一非法操作默认整体失败 |
| EDT-IF-003 | 预览清单/预览任务 | Timeline 草稿或版本、预览规格 | 可播放清单或 Render Task；不等待媒体处理完成 |
| EDT-IF-004 | 发布 TimelineVersion | Timeline ID、期望 revision | 新不可变版本、可渲染检查和下一动作 |
| EDT-IF-005 | 提交/查询审核 | TimelineVersion ID、审核说明 | governance Review/Issue 摘要；版本变化需重新提交 |
| EDT-IF-006 | 提交最终渲染 | 获批 TimelineVersion、输出规格、幂等键 | Render 与 Task；门禁失败返回完整阻塞清单 |
| EDT-IF-007 | Render 列表/详情/取消/重试 | Render/Task ID、期望状态 | 最新状态、错误、输出 MediaVersion 和下一动作 |
| EDT-IF-008 | 生成/读取 DeliveryManifest | Render ID、标识与交付要求 | 固定清单；文件/标识/hash 验证失败不得成功 |

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| EDT-NFR-001 | 不可变 | TimelineVersion 和 DeliveryManifest 只追加；修订必须从历史版本建立新草稿后重新发布。 |
| EDT-NFR-002 | 一致性 | 批量编辑和发布必须使用 revision 防止静默覆盖；发布快照必须与预检内容一致。 |
| EDT-NFR-003 | 确定性 | 相同 TimelineVersion、输入媒体、工具版本和输出规格应产生可解释一致的编排结果。 |
| EDT-NFR-004 | 可追溯 | 每个交付 Clip 必须追溯到 Shot、Candidate、MediaVersion、ShotSpecVersion、Task 和审核决定。 |
| EDT-NFR-005 | 恢复 | 渲染是持久 Task；进程重启或重复消息不得产生不可解释的重复交付或覆盖文件。 |
| EDT-NFR-006 | 完整性 | DeliveryManifest 中的文件、hash、时长、字幕、内容编号和标识必须在交付成功前验证。 |
| EDT-NFR-007 | 性能 | 编辑操作不得同步执行最终 FFmpeg 渲染；预览生成、单集渲染时限和并发在 PRD 量化。 |
| EDT-NFR-008 | 兼容 | MVP 输出至少支持目标竖屏 MP4 和独立字幕；精确编码、分辨率和音频规格待确认。 |
| EDT-NFR-009 | 可访问 | 基础播放、时间定位、字幕编辑和审核操作必须支持键盘访问及清晰状态反馈。 |

## 6. 生命周期与失败路径

- Timeline 草稿持续产生 revision；TimelineVersion 为不可变发布快照。
- Render：`queued → running → succeeded | failed | cancelled`；供应商未知语义不适用于纯本地渲染，但进程中断必须可判定/重试。
- TimelineVersion 获批后若重新发布新版本，旧批准不自动继承；交付必须绑定实际获批版本。
- 某个源 MediaVersion 不可用时，预览/渲染必须失败并指出具体 Clip，不得静默跳过。
- 渲染成功但标识或清单验证失败时 Render 输出可保留排障，但 Delivery 不得标记成功。

## 7. 非目标与待确认

- 不做多机位专业剪辑、复杂调色、关键帧动画、插件市场、实时协作或任意脚本执行。
- 不自动发布到外部内容平台，也不把交付文件默认公开。
- 待确认画幅/分辨率、帧率、编码、音频响度、字幕格式、转场集合、预览质量和目标渲染时限。
