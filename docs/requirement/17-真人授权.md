## 1. 需求说明

### 1.1 背景与目标

写实项目默认使用 AI 生成的虚构人物；若使用真人照片或声音作为参考，涉及肖像权与声音权益，必须有授权声明并留存材料（CMP-02）。

### 1.2 用户故事

- 作为**制作者**，我在写实项目中上传真人照片作为参考时，需要声明已获授权并可附授权文件。

### 1.3 范围

- 包含：授权声明记录、授权文件上传与受限访问、素材与声明关联、引用前校验。
- 不包含：人脸识别自动判断是否真人（上传时由用户选择“真人 / 非真人”）、电子签署流程。

## 2. 需求分析

### 2.1 业务流程

```text
上传人物图片 / 音频 → 选择“包含真实人物”→ 填写授权声明（被授权人姓名、授权范围：肖像 / 声音 / 两者、声明文本确认）→ 可附授权文件
→ 创建 consent_record → 素材关联 consent_record_id → 可用于锁定参考 / 参考组合
未声明的真人素材：可上传与浏览，但不可锁定为参考、不可加入参考组合
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 写实项目上传图片或音频时必须回答“是否包含真实人物”；风格化项目默认否，可主动声明 | 写实项目风险高 |
| R2 | 包含真实人物的素材必须关联授权声明才能被引用 | BIB-07 |
| R3 | 声明文本快照保存（不随模板变化） | 留存 |
| R4 | 授权文件只有项目内用户与管理员可访问，每次访问写审计 | PRV-04 |
| R5 | 一个声明可关联多个素材（同一人的多张照片） | 减少重复操作 |

### 2.3 状态

无。

### 2.4 异常与边界

声明后发现无授权：管理员可将声明标记为无效（逻辑删除），关联素材恢复为不可引用；已被引用的对象标记“合规问题”并通知。

### 2.5 前置与依赖

REQ-30 上传。

## 3. 验收标准

- Given 写实项目，When 上传人物照片且未勾选授权声明，Then 无法保存为参考，提示需要授权声明。
- Given 已声明授权的素材，When 锁定为造型参考，Then 成功，媒体详情显示授权声明。
- Given 授权文件，When 用户查看，Then 审计记录该访问。
