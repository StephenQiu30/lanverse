# FR-004 改编策划、结构化剧本与版本基线需求规格说明书

## 1. 目的与范围

把原始内容及已确认事件整理为故事骨架、改编策略、分集大纲、剧情节拍、场次、动作、对白和旁白，并管理草稿、提案、比较、确认、重新打开、恢复和变更影响。

本能力不管理分镜图、生成媒体或成片时间线。

## 2. 主业务流程

1. 从原始内容、已确认事件或空白创建故事骨架与改编策略提案。
2. 用户确认取舍、主线、人物弧、集数分配、单集目标和禁用改编方向。
3. 系统据此创建分集剧本草稿并识别人物、地点、道具、场次、动作、对白和旁白。
4. 用户修正别名、顺序、对白归属和场次边界；系统检查缺失、矛盾和不确定项。
5. 用户比较版本并提交内容确认。
6. 有权责任人确认当前剧本基线；后续修改创建新草稿并标记下游影响。

| FR-004-003 | 系统应为对白记录说话角色、文本、语气、所属场次和来源。 | P0 |

| FR-004-006 | 系统应把 AI 生成、删减和改写内容保存为待确认提案。 | P0 |

## 4. 业务规则

- BR-004-001：每个单集任一时刻只能有一个当前剧本基线。
- BR-004-002：自动保存不等于内容确认。
- BR-004-003：AI 提案未经确认不得进入正式生产基线。
- BR-004-004：后续媒体结果不得反向静默修改故事事实、台词或镜头目的。
- BR-004-005：内容完整、资产就绪和制作就绪是三种不同判断。
- BR-004-006：故事骨架确认、改编策略确认和剧本基线确认是独立决定，不得由 Agent 运行成功自动代替。

## 5. 数据要求

- DR-004-001：保存剧本版本、父版本、来源、状态、确认人、确认时间和原因。
- DR-004-002：场次、对白和关键叙事实体使用跨版本稳定标识。
- DR-004-003：保存版本差异、恢复关系和下游影响清单。
- DR-004-004：保存分集大纲、剧情节拍、钩子类型以及对原始内容和场次的映射。
- DR-004-005：保存故事骨架、改编策略、父版本、来源事件/片段、AI 运行、人工决定和下游影响。

## 6. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 台词归属或人物别名冲突 | 保持待确认，不自动选择。 |
| 内容存在强制缺失 | 允许保存草稿，但阻止基线确认。 |
| 并发确认两个版本 | 只允许一个成为当前基线，另一版本要求重新评估。 |
| 已确认对白被修改 | 创建新草稿，并把相关资产、镜头、配音、字幕、时间线和交付版本标记为待复核。 |

## 7. 验收标准

- AC-004-001：确认剧本后修改一句对白，原基线不变并产生新草稿。
- AC-004-002：版本比较能够定位新增、删除和修改的场次与对白。
- AC-004-003：恢复历史版本后产生新版本，而不是改变历史记录。
- AC-004-004：改变对白后，相关资产、镜头、配音、字幕、时间线和交付版本被标记待复核；无关对象不得被全量标记。
- AC-004-005：任一已确认剧本能够显示其开场钩子、核心冲突、高潮和结尾悬念或收束，并反查相关场次。
- AC-004-006：修改改编策略后，既有剧本基线保持不变并显示待复核范围。
- AC-004-007：任一新增情节均显示原文依据或“新增创作”，且未经确认不会进入剧本基线。
