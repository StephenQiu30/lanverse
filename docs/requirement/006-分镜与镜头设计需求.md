### 1.1 证据与产品决策边界

以下内容必须分开理解：

- **公开页面或已授权只读客户端可见事实：** VibeReels 在 Episode 下展示有序 Shot，单镜头集中显示导演信息、详细 Prompt、资产引用与生成历史；这些表面证据不能证明其服务端镜头身份、修订血缘或删除恢复机制。
- **Lanverse 产品推导：** Shot 必须拥有独立于镜号的稳定身份；剧本叙事单元与 Shot 是多对多关系；AI 只能生成待人工决议的分镜草案；插入、拆分、合并和重排不得静默丢失叙事来源。
- **不应外推：** 不把 VibeReels 的页面结构、字段名或未公开算法视为 Lanverse 的实现要求，也不声称其已证明稳定 ID、严格并发控制或完整历史恢复。

## 二、模块定位、目标与 KPI

### 2.1 模块定位

本模块把已确认的单集剧本、叙事单元和资产状态转换为一组有序、可解释、可人工修订的镜头。它负责“这一集要拍哪些镜头、每个镜头为什么存在、引用哪些固定上游事实、当前采用哪一版镜头规格”，不负责生成关键帧或视频。

### 2.2 用户结果

导演应能在不丢失剧本事实的前提下完成以下闭环：

1. 查看剧本叙事单元与现有镜头；
2. 生成或手工建立分镜；
3. 对 AI 草案逐镜接受、修改或忽略；
4. 插入、复制、拆分、合并和重排镜头；
5. 按 CUR-SCR production_disposition 解释每个 NarrativeUnitVersion 的镜头去向；
6. 固定一个可供关键帧与视频制作使用的当前分镜基线。

### 2.3 KPI 与质量门槛

| 指标 | 当前目标 |
| --- | --- |
| 叙事生产处置说明率 | 当前分镜基线发布前达到 100%；`must_cover` 必须被镜头覆盖，`may_omit_with_approval` 必须带 CUR-SCR 固定批准证据 |
| 镜头来源可追溯率 | 100% 当前镜头可追溯到固定剧本版本及至少一个来源叙事单元；纯创意镜头必须有人工说明 |
| 静默覆盖或丢失 | 0 次；AI 应用、并发编辑和拆合镜头发生冲突时必须零部分写入 |
| 局部返工率 | 修改一个镜头时，除显式选择的拆合或批量操作外，不改变其他镜头规格 |
| 顺序稳定性 | 重排只改变显示顺序，不改变 Shot 身份及历史规格 |
| 首轮任务成功信号 | 受控样本中，导演无需技术人员协助即可完成草案审阅、覆盖检查和基线发布 |

## 三、范围与非范围

### 3.1 范围

- Episode 级分镜工作区与有序镜头列表；
- 手工创建、编辑、插入、复制、归档、拆分、合并和重排镜头；
- AI 分镜草案生成、逐镜决议、预览差异和原子应用；
- 镜头规格，包括叙事目的、画面、景别、机位、运动、动作、对白、预计时长、视觉说明和资产状态引用；
- 叙事单元与镜头的多对多覆盖；
- 资产引用就绪度、阻塞原因和下一动作；
- 分镜当前基线、版本冲突、变更影响与过期提示。

### 3.2 非范围

- 角色、LocationAsset、道具资产身份或状态的创建与媒体生成；
- 关键帧生成、上传、候选选择和视觉参考管理；
- 视频生成、视频候选选择、星标或成本结算；
- 视频裁切、拼接、转码、转场、字幕、音频、时间线或成片；
- 商业套餐、支付、账单、退款和运营后台；
- AI 自动覆盖正式镜头、按镜号作为长期身份、段落与镜头严格一一对应；
- 任意白板/技术节点编排、实时共同拖拽或通用审批引擎；CUR-CAN 的同源制作画布不在此排除项内。

## 四、用户角色与权限意图

| 角色 | 核心任务 | 允许的产品动作 |
| --- | --- | --- |
| 导演／分镜师 | 设计镜头、审阅 AI 草案、处理覆盖和发布当前基线 | 创建与修订镜头、拆合重排、决议草案、提交基线 |
| 制作人／项目负责人 | 控制范围、风险和进入下一阶段的条件 | 查看全量事实和 CUR-SCR 处置理由、发布当前基线 |
| 编剧／资产负责人 | 核对来源文本和资产状态 | 查看双向引用、提出修订；无权静默修改正式镜头 |
| 观察者 | 了解当前制作状态 | 只读查看镜头、覆盖、版本和阻塞 |

上述名称是制作 persona，不是新增授权角色。当前统一映射为 CUR-IAM owner/editor 可执行本模块写操作，viewer 只读；“导演确认”“制作人批准”只描述职责，当前所有发布/创意镜头确认由 owner/editor 执行，不得成为隐藏的第二套权限门禁。当前不要求完整企业角色体系或项目级自定义权限。

## 五、核心使用场景

| 场景 | 触发 | 成功结果 |
| --- | --- | --- |
| 从确认剧本建立分镜 | Episode 已有当前剧本与稳定叙事单元 | 形成待审阅草案或空白手工分镜工作区 |
| 逐镜审阅 AI 草案 | 草案生成完成 | 每条草案都有接受、修改后接受或忽略决定 |
| 手工局部返工 | 导演发现单镜头不合适 | 只产生该 Shot 的新规格，旧规格及下游影响可见 |
| 拆镜与合镜 | 一个节拍需多镜或多个节拍需合镜 | 叙事引用按明确规则守恒，冲突时不应用 |
| 重排镜头 | 节奏需要调整 | Shot 身份不变，顺序修订原子更新 |
| 发布当前分镜 | 覆盖与所引用资产的 `storyboard_ready` 满足门槛 | 产生固定分镜基线，下游读取同一组版本；图片/视频生成用途准备度另行展示 |
| 上游变化 | 剧本、叙事单元或资产状态变化 | 受影响镜头和基线标记为待复核或过期，不自动重建 |

## 六、依赖与交接

### 6.1 前置依赖

- Project 与 Episode 必须处于可制作状态；
- Episode 必须有明确的当前剧本版本；
- 每个 NarrativeUnitVersion 必须有 CUR-SCR 固定的 `must_cover` 或 `may_omit_with_approval` production_disposition；
- 角色、LocationAsset、道具等资产必须能返回身份、剧情状态、固定 AssetVersion、ImageCandidate 选择与就绪度；
- AI 能力不可用时，手工分镜流程仍必须可完成。

### 6.2 下游交接

本模块向下游提供：

- Episode 的当前有序 Shot 集合；
- 每个 Shot 的稳定身份、当前 ShotSpecVersion 与顺序；
- 固定的剧本、叙事单元和资产状态引用；
- 镜头视觉说明、Prompt 意图、预计时长和就绪度；
- 当前分镜基线 ID、输入摘要和过期状态。

post-MVP 的 CUR-CAN 才将上述正式 Shot/ShotSpec、NarrativeUnit 覆盖、readiness 和 WorkTask 投影为同源节点、关系和叠层；从画布修改仍调用本模块相同命令、期望修订和并发规则。列表/详情必须可独立完成全部 P0 分镜任务。

下游不得只保存镜号、资产名称或当前页面文本作为引用。

## 八、详细功能需求

### 8.1 CUR-SBD-FR-001 打开分镜工作区并查看来源上下文

**目标：** 让导演在同一工作区理解“来源文本—镜头—资产状态”关系。

**前置条件：** 用户可读取目标 Episode；Episode 已有当前剧本版本。

**主流程：**

1. 用户进入 Episode 的分镜工作区；
2. 系统显示当前剧本版本、叙事单元列表、有序镜头列表和当前分镜基线状态；
3. 用户选择一个叙事单元，系统高亮所有相关镜头；
4. 用户选择一个镜头，系统显示其来源叙事单元、当前规格、资产状态、阻塞和历史版本摘要；
5. 用户可按未覆盖、孤儿、过期、阻塞等状态筛选。

**备选流程：**

- 尚无镜头时显示空状态，并提供手工创建和 AI 草案两个下一动作；
- AI 能力不可用时仅隐藏或禁用 AI 动作，不阻塞手工创建；
- 上游部分数据暂不可用时保留已取得事实并明确显示缺失来源。

**失败与恢复：**

- 当前剧本不存在或已失效时禁止建立新镜头，提示先确认剧本；
- 组合读取失败不得把未知状态显示为“无阻塞”或“零镜头”；
- 刷新后必须从服务端事实恢复同一当前版本和筛选结果。

**业务规则：**

- 镜号只表示当前顺序；
- 选择关系必须支持一个单元对应多镜、一个镜头对应多单元；
- 历史版本默认只读，不与当前规格混淆。

### 8.2 CUR-SBD-FR-002 基于固定输入生成 AI 分镜草案

**目标：** 在不修改正式镜头的前提下获得可审阅的镜头建议。

**主流程：**

1. 用户选择生成范围、镜头密度或目标时长等业务约束；
2. 系统展示本次固定的剧本版本、叙事单元版本和资产状态摘要；
3. 用户确认后提交草案生成；
4. 系统返回可持续查询的任务状态；
5. 完成后由本模块生成独立 StoryboardDraftBatch；每条正式 ShotDraft 具有稳定草案身份，包含目的、画面、景别、机位／运动、动作、对白、预计时长、资产引用建议、来源 NarrativeUnitVersion 和所参考的 ShotCueCandidate。

**备选流程：**

- 用户可只对选定场景或叙事单元生成；
- 部分草案生成失败时，成功条目仍可审阅，失败范围可单独重试；
- 无 AI 能力时允许用户从空白镜头开始。

**失败与恢复：**

- 输入版本变化后，尚未执行的任务应停止或标记输入已变化；
- 结果到达时若当前输入已变化，草案保留但标记过期，不得自动应用；
- 刷新、断线或重复提交不得产生无法区分的重复正式镜头。

**业务规则：**

- AI 结果始终是候选；
- ShotCueCandidate 是 CUR-SCR 的叙事提示，正式 ShotDraft/StoryboardDraftBatch 由 CUR-SBD 唯一创建；ShotDraft 仍不是 Shot；
- 每个草案批次必须固定输入版本与生成约束；
- 预计镜头数和时长是建议，不是自动发布条件。

### 8.3 CUR-SBD-FR-003 逐镜决议并原子应用草案

**目标：** 让人工对每条草案作出可追踪决定，并安全转成正式镜头。

**主流程：**

1. 用户打开草案批次及相对当前镜头的差异；
2. 对每条草案选择接受、修改后接受或忽略，并可填写理由；
3. 系统持续显示尚未决议的条目和预计应用结果；
4. 用户提交应用；
5. 系统重新核对当前镜头顺序、规格与来源版本；
6. 无冲突时一次性创建或修订正式镜头，并保存草案决定。

**备选流程：**

- 用户可放弃整个草案批次；
- 用户可保存未完成决议，稍后继续；
- 产品若允许逐项应用，必须明确每次应用边界，已应用项不得被后续批次重复创建。

**失败与恢复：**

- 任一相关镜头或输入版本变化时返回差异冲突，整次应用零正式写入；
- 草案缺少必需来源或业务字段时不得应用，并定位具体条目；
- 重复提交同一应用决定返回既有结果，不创建第二组镜头。

**业务规则：**

- 忽略草案不等于批准省略叙事单元；
- 修改后接受产生人工修订后的正式规格，仍保留 AI 来源；
- 正式 Shot 身份由系统建立，不能使用草案序号充当长期身份。

### 8.4 CUR-SBD-FR-004 手工创建与修订镜头规格

**目标：** 支持导演精确控制单镜头内容。

**主流程：**

1. 用户在指定位置创建镜头或打开现有镜头；
2. 填写或修改叙事目的、画面、景别、机位、运动、动作、对白、预计时长、视觉说明和资产状态引用；
3. 系统即时校验必填项与引用有效性；
4. 用户保存；
5. 新镜头获得稳定身份；已有镜头产生新的不可变规格版本并成为当前规格。

**备选流程：**

- 可从另一个镜头复制规格作为新 Shot 起点；
- 可先保存未就绪规格，状态明确为草稿或阻塞；
- 可查看历史规格并以历史内容创建新修订，但不得原地回写历史。

**失败与恢复：**

- 保存时当前规格已被他人修改，系统返回差异并保留用户未提交内容；
- 引用的叙事单元或资产状态已失效时拒绝成为就绪规格；
- 网络失败后不得显示已保存，用户可安全重试同一修改。

**业务规则：**

- 预计时长必须大于 0；1～30 秒是 proposed 产品容量样本，25 秒起显示 UI 预警，超出签认产品容量时需明确修订镜头或由有效能力给出允许范围。CUR-PLT Capability/CUR-SEC 安全硬上限独立生效；CUR-SBD-OQ-001 关闭前不得把该样本宣称为 accepted 硬限制；
- 修改 ShotSpec 不改变 Shot 身份；
- 镜头描述与 Prompt 意图属于规格，关键帧和视频媒体不属于本模块。

### 8.5 CUR-SBD-FR-005 插入、复制、归档、拆分与合并镜头

**目标：** 支持分镜结构变化，同时守住来源与历史。

**主流程：**

1. 用户选择目标镜头和结构操作；
2. 系统预览新顺序、来源叙事引用、对白／动作分配及下游影响；
3. 用户确认；
4. 系统原子应用结构变化并返回新顺序。

**备选流程：**

- 插入：在目标位置建立空白或基于上下文的新 Shot；
- 复制：复制当前规格和引用作为新 Shot，不复制关键帧、视频候选或主选；
- 拆分：建立两个或多个新 ShotSpec，并要求明确分配来源、对白与动作；
- 合并：建立一个承接来源并集的新 Shot；跨场景默认禁止，确认例外时记录理由；
- 归档：从当前顺序移除，但保留历史规格和下游证据。

**失败与恢复：**

- 拆分后来源、对白或动作出现未分配或重复时拒绝应用；
- 合并存在互斥 NarrativeScene、资产状态或预计时长不大于 0 时返回阻塞；达到 25 秒显示 UI 预警，超出 proposed 1～30 秒产品容量样本时按当前已验证 Capability 返回明确修订动作，但 CUR-SBD-OQ-001 关闭前不得仅据该样本形成 accepted blocker；
- 目标顺序已变化时返回最新差异，不进行部分操作。

**业务规则：**

- 结构操作不得硬删除已有历史；
- 复制镜头不复制生成费用、关键帧或视频；
- 拆分后的引用并集必须等于来源镜头引用；合并后的引用集合必须等于来源并集，显式移除需另有人工决定。

### 8.6 CUR-SBD-FR-006 原子重排镜头

**目标：** 调整叙事节奏而不改变镜头身份或内容。

**主流程：**

1. 用户拖动或以列表命令调整一个或多个镜头顺序；
2. 系统显示调整后的完整顺序和总时长；
3. 用户确认；
4. 系统一次性保存新顺序修订；
5. 所有 Shot ID、当前规格和历史媒体引用保持不变。

**备选流程：**

- 支持移动到首部、尾部、指定镜头前后；
- 支持键盘完成同等重排；
- 大批量重排可先进入预览再统一应用。

**失败与恢复：**

- 请求包含缺失、重复、归档或其他 Episode 的 Shot 时全部拒绝；
- 并发顺序变化时返回最新顺序，不采用最后写入覆盖；
- 保存失败后继续显示用户拟议顺序，但明确标记未保存。

**业务规则：**

- 顺序修订必须覆盖当前全部 active Shot，不能只传模糊的镜号变化；
- 镜号由当前顺序派生，不作为下游身份；
- 重排只更新工作中预览；正式生成和导出仍读取最近一次显式发布的 StoryboardBaseline。只有发布包含该新顺序的基线后，新 ExportSnapshot 才能使用新顺序；历史导出永不改写。

### 8.7 CUR-SBD-FR-007 建立并检查叙事覆盖

**目标：** 证明每个固定叙事单元均按 CUR-SCR production_disposition 得到明确镜头去向。

**主流程：**

1. 用户查看叙事单元与镜头的双向关系；
2. 系统计算 covered、uncovered、approved_omitted、orphan 和 stale；
3. 用户为镜头添加或移除来源关系；若认为单元应可省略，跳转 CUR-SCR 修改 production_disposition 并提供理由；
4. 系统读取 CUR-SCR 当前固定处置与批准证据；
5. 系统重新计算覆盖报告和当前输入摘要。

**备选流程：**

- 一个叙事单元可拆到多个镜头；
- 一个镜头可覆盖多个相邻或有关联的叙事单元；
- 纯创意镜头可无必拍来源，但必须填写创作目的并由人工确认。

**失败与恢复：**

- 来源版本变化时旧报告标记过期，不得继续显示 100%；
- 关系依赖暂不可用时状态为未知／不可用，不得默认为已覆盖；
- `must_cover` 单元不能仅靠“忽略草案”或本模块本地决定变为批准省略；CUR-SCR 处置不可用时覆盖报告 unavailable。

**业务规则：**

- 100% 表示全部按处置被说明，不表示单元与镜头一一对应；
- approved_omitted 只能投影 CUR-SCR 对固定 NarrativeUnitVersion 的 `may_omit_with_approval`、理由和决定人；CUR-SBD 不拥有第二份省略决定；
- orphan 镜头必须绑定来源或获得创意镜头批准。

### 8.8 CUR-SBD-FR-008 固定资产状态引用并检查就绪度

**目标：** 确保镜头引用的是明确的角色／场景／道具状态，而不是会漂移的名称或“当前图”。

**主流程：**

1. 用户在镜头中选择资产身份、剧情状态和可用版本；
2. 系统显示该引用的出现范围、媒体和使用就绪度；
3. 用户确认后保存新 ShotSpecVersion；
4. 系统计算镜头级就绪度、阻塞原因和下一动作。

**备选流程：**

- 同一资产可在一个镜头中引用多个不同用途槽位；
- 资产缺失时允许保存阻塞规格并跳转到资产补全；
- 资产发布新版本后，用户可预览影响并显式升级指定镜头。

**失败与恢复：**

- 资产归档、状态无效、叙事描述必填字段缺失或当前用途权利阻断时，所引用资产的 `storyboard_ready` 为 blocked，镜头不得进入分镜 ready；`image_generation_ready`/`video_generation_ready` 缺失只作为下游明确 warning/blocker，不伪装为分镜门禁已满足；
- 改名不得破坏引用；
- 资产当前版本切换不得静默改写既有 ShotSpec。

**业务规则：**

- 固定引用至少能区分资产身份、剧情状态和具体版本；
- Prompt 中的序号或显示名只是可读别名；
- 就绪度必须来自可解释事实，不能由前端按钮状态代替。

### 8.9 CUR-SBD-FR-009 发布当前分镜基线并处理影响

**目标：** 为关键帧和视频制作提供一组明确、可复现的当前镜头输入。

**主流程：**

1. 用户发起基线预检；
2. 系统检查镜头必填规格、叙事覆盖、所引用资产的 `storyboard_ready`、顺序完整性和输入过期状态，并单独汇总 `image_generation_ready`/`video_generation_ready` 差额；
3. 系统返回完整阻塞清单和警告；
4. 阻塞为零后，有权限用户确认发布；
5. 系统冻结有序 Shot、当前 ShotSpecVersion、来源和资产引用，形成当前分镜基线；
6. 下游可读取该固定基线。

**备选流程：**

- 警告可在填写理由后继续，阻塞不可绕过；
- 已发布基线可保持历史可读，并以当前内容另发新基线；
- 上游发生无影响变化时可经预检确认继续有效。

**失败与恢复：**

- 预检与发布之间任一依赖变化时返回版本冲突，零发布；
- 发布失败不得让下游看到半套新基线；
- 上游变化后受影响基线标记过期，并列出需要重审的镜头。

**业务规则：**

- “当前”由明确发布动作改变，不由最后编辑时间推断；
- 新基线不删除历史基线；
- 下游只能选择明确基线或明确当前基线，不能分别读取会漂移的最新镜头。

## 九、实体、状态机与不变式

### 9.1 产品实体

| ID | 实体 | 产品含义 |
| --- | --- | --- |
| CUR-SBD-ENT-001 | Shot | Episode 内稳定的镜头身份；镜号和顺序可变，身份不变 |
| CUR-SBD-ENT-002 | ShotSpecVersion | 某次不可变镜头规格，固定来源、资产、视觉说明和时长 |
| CUR-SBD-ENT-003 | StoryboardOrderRevision | 一次完整有序 active Shot 集合 |
| CUR-SBD-ENT-004 | StoryboardDraftBatch | 固定输入的 AI 镜头草案及人工决议 |
| CUR-SBD-ENT-005 | ShotNarrativeReference／CoverageProjection | 镜头与叙事单元的覆盖边、创意镜头决定及 CUR-SCR 已批准 production disposition 的只读投影；本模块不拥有第二份省略决定 |
| CUR-SBD-ENT-006 | StoryboardBaseline | 对有序镜头、当前规格和依赖的固定发布快照 |
| CUR-SBD-ENT-007 | ShotDraft | StoryboardDraftBatch 内具有稳定身份的单条正式分镜草案，固定来源与建议规格；仍不是 Shot |

### 9.2 状态

- Shot：active ↔ archived；归档后历史只读，不进入当前顺序。
- AI 草案生成工作使用 CUR-PLT 的唯一 WorkTask canonical 状态：`queued → running → waiting_external → succeeded | failed | cancelled | unknown`，`unknown → succeeded | failed | manual_attention`。只有产生可审阅结果后才建立草案批次/ShotDraft；草案批次领域状态为 reviewable → applied／discarded，固定输入变化时附加 stale。生成失败属于 WorkTask，不伪造 failed 草案批次。
- 覆盖项：covered、uncovered、approved_omitted、orphan、stale、unavailable。
- 分镜基线：valid → stale；历史基线不回到 valid，重新确认产生新基线。

### 9.3 核心不变式

1. Shot ID 不因插入、复制、拆合、重命名或重排而复用。
2. ShotSpecVersion 不原地修改；编辑产生新版本。
3. AI 草案在应用前不得成为正式 Shot。
4. 剧本叙事与镜头是多对多关系。
5. 重排只改变顺序修订，不改变 ShotSpec 或下游媒体。
6. 拆分与合并必须证明来源、对白和动作守恒。
7. 当前分镜基线只能通过显式发布改变。
8. 上游变化使受影响结果过期，不自动删除或重建历史。
9. 正式 ShotDraft/StoryboardDraftBatch 只由 CUR-SBD 创建；CUR-SCR ShotCueCandidate 不能直接进入 Shot 顺序或基线。
10. approved_omitted 只消费 CUR-SCR production_disposition，不在本模块复制省略批准终态。

- 未来若新增分镜文档文件，必须另行定义版本固定、来源追溯、字符编码、完整性与验收，不得从页面内容临时拼出后宣称可复现。

### 14.1 已决策事项

- Shot 使用稳定身份，镜号只表示工作顺序；编辑规格必须产生不可变新版本。
- AI 分镜始终先形成候选草案，只有人工决议和显式应用才能改变正式镜头。
- 工作中顺序只用于预览；正式下游只能读取显式发布的 StoryboardBaseline 及其固定 OrderRevision。
- 本模块只设计镜头规格与顺序，不引入 Timeline、Clip、剪辑、视频加工或成片。
- 正式 ShotDraft/StoryboardDraftBatch 由 CUR-SBD 唯一创建；CUR-SCR ShotCueCandidate 只作为固定来源提示。
- CUR-CAN 画布与列表读取相同 Shot/覆盖/readiness 并调用相同命令；布局和任意连线不能改变顺序或领域不变式。

## 十五、术语

| 术语 | 定义 |
| --- | --- |
| Shot | 拥有稳定身份的单个镜头，不等同当前镜号 |
| ShotSpecVersion | 一次固定的镜头创作规格 |
| 叙事单元 | 从固定剧本版本中形成的稳定场景、动作、对白或节拍事实 |
| 覆盖 | `must_cover` 被一个或多个镜头承接，或固定 NarrativeUnitVersion 已由 CUR-SCR 标记 `may_omit_with_approval` |
| 草案 | AI 或其他建议产生、尚未写入正式镜头的候选集合 |
| ShotDraft | CUR-SBD 草案批次内的稳定镜头草案条目，不是正式 Shot |
| 当前分镜基线 | 经显式发布、供下游读取的一组固定镜头顺序与规格 |
| stale | 输入已变化，结果仍保留但必须复核，不能继续宣称有效 |
