# FR-001 账户、工作空间与访问控制需求规格说明书

## 1. 目的与范围

本能力负责账户身份、工作空间归属、成员关系、工作空间角色、项目角色、操作授权和平台事件临时访问。

本能力只回答“谁在什么上下文中可以对什么对象执行什么操作”，不替代预算、权利、安全或交付门禁。

## 2. 参与角色

- 账户主体。
- 工作空间所有者或管理员。
- 项目创作者、审核者和查看者。
- 受明确运营事件授权的平台人员。

## 3. 前置与结束状态

前置条件：主体完成身份验证；操作对象具有稳定工作空间和项目归属。

成功结束状态：账户、工作空间、成员、角色和访问决定均有稳定标识、明确状态和审计记录。

## 4. 主业务流程

1. 用户建立或恢复持续账户身份。
2. 用户创建或加入工作空间。
3. 所有者配置成员、工作空间角色、项目角色和参与范围。
4. 系统在每次业务操作前解析账户、工作空间、项目、对象和动作。
5. 系统给出允许或拒绝结果；权限通过后，再交由相应业务门禁判断。
6. 成员退出、角色调整、工作空间关闭或临时访问到期时，系统终止未来访问并保留历史责任。

## 5. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-001-001 | 系统应为每个账户建立全局唯一且不可复用的业务标识。 | P0 |
| FR-001-002 | 系统应区分会话结束、账户冻结、停用、注销和个人数据删除。 | P0 |
| FR-001-003 | 系统应为项目、资产、任务、用量和交付物建立唯一工作空间归属。 | P0 |
| FR-001-004 | 系统应保证任一有效工作空间始终存在至少一个有效所有者。 | P0 |
| FR-001-005 | 系统应支持所有者、管理员和成员等工作空间角色。 | P1 |
| FR-001-006 | 系统应支持创作者、审核者和查看者等项目角色及项目参与范围。 | P1 |
| FR-001-007 | 系统应允许同一成员兼任多个业务角色，但每个正式动作仍需独立授权。 | P0 |
| FR-001-008 | 系统应分别判定查看、编辑、生成、审核、采用、导出、费用和组织管理权限。 | P0 |
| FR-001-009 | 系统应区分“无权限”和“有权限但业务门禁未通过”。 | P0 |
| FR-001-010 | 系统应阻止主体通过可猜测标识、名称、链接或关联关系访问其他工作空间数据。 | P0 |
| FR-001-011 | 系统应在成员离开后停止未来访问，并保留其历史成果和责任记录。 | P1 |
| FR-001-012 | 系统应只允许平台人员针对明确事件获得有目的、对象、范围和期限的临时访问。 | P0 |
| FR-001-013 | 系统应阻止平台人员代替用户作出创作、审核、采用或交付决定。 | P0 |

## 6. 业务规则

- BR-001-001：邀请待接受不等于有效成员关系。
- BR-001-002：工作空间角色不自动产生项目内容访问。
- BR-001-003：岗位名称不直接产生权限，必须映射到正式角色和操作范围。
- BR-001-004：角色变化只影响后续操作，不改写历史责任。
- BR-001-005：工作空间关闭不等于历史数据立即物理删除。

## 7. 数据与审计要求

- DR-001-001：保存账户、工作空间、成员关系、角色分配、项目参与范围和状态历史。
- DR-001-002：敏感授权决定保存主体、上下文、对象、动作、策略版本、原因和结果。
- DR-001-003：临时访问保存关联事件、批准人、访问范围、期限、操作记录和撤销结果。

## 8. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 唯一所有者申请退出或注销 | 阻止操作，并要求转让所有权或关闭工作空间。 |
| 成员离开时仍有运行任务 | 终止其访问，保留任务并移交给有权责任人。 |
| 对象归属无法校验 | 默认拒绝，不根据名称或地址推断归属。 |
| 临时运营访问过期 | 立即终止访问，并保留期间操作审计。 |

## 9. 验收标准

- AC-001-001：无项目权限的用户访问项目时，系统拒绝且不泄露项目是否存在。
- AC-001-002：成员角色被撤销后不能执行新操作，历史创作和审核记录仍显示原责任人。
- AC-001-003：权限通过但预算不足时，系统返回预算门禁失败而不是权限错误。
- AC-001-004：运营人员只能访问事件批准范围内的对象，越界访问被阻止和记录。

## 10. 非目标与依赖

不定义登录技术、认证供应商、接口和权限存储实现。

依赖 [NFR-001](NFR-001-跨模块非功能质量需求规格说明书.md) 的租户隔离、安全和审计要求。
