# M05 分镜与镜头规划需求

> Requirement ID：REQ-SHT
> 状态：proposed v1
> 日期：2026-08-20
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)、[M03](./003-M03-导入与叙事理解需求.md)、[M04](./004-M04-生产知识与一致性图谱需求.md)
> 对应模块：M05 分镜与镜头规划

## 1. 需求结论

Shot 是生成、候选选择、质检和局部返工的稳定生产单元；显示编号和顺序可以改变，身份不能复用。镜头意图、具体拍法、播放顺序、关键帧、预演和执行结果必须分离。

## 2. 用户结果与范围

用户需要从批准叙事和生产知识创建、校对、拆分、合并、重排和锁定镜头，检查 Beat/对白覆盖与连续性，生成低消耗分镜和可播放预演，并在单镜头修改时只影响真实依赖下游。

本模块不提交高消耗生成任务、不采用视频候选、不做完整非线性剪辑，也不让 Agent 提案绕过人工批准。

## 4. 镜头内容契约

每个可批准 ShotPlan 至少声明：叙事目的、覆盖 Beat、主体与状态、场景/地点、构图、景别、机位、运动、主要动作、表演意图、预计时长、必要参考、连续性要求和未知项。

字段允许 unknown，但进入高消耗 GenerationPlan 前由 M07 Readiness 决定是否阻塞。Prompt 不是 ShotPlan 的权威事实；提示编译必须从批准镜头和知识版本生成。

## 5. 覆盖、顺序与连续性

1. 一个 Beat 可以由多个 Shot 覆盖，一个 Shot 也可覆盖多个相邻 Beat，但必须显式记录。
2. 覆盖率分别计算 Beat、Dialogue、Action 和强制设定，不能只统计镜头数量。
3. 重排只产生新 ShotOrderRevision；旧 Animatic、审阅和交付继续使用旧顺序。
4. 相邻镜头连续性至少检查人物状态、视线/轴线、位置、动作接续、道具持有和时间/天气。
5. 锁定镜头仍允许创建替代草稿，但不能原地改变批准版本。

## 6. 状态与并发

Shot 是稳定身份；ShotPlanRevision 为 `draft → proposed → approved/current → superseded | archived`。StoryboardFrame 和 Animatic 是有来源的派生产物，不能自动成为最终视频主选。

并发重排基于同一 ShotOrderRevision；并发批准同一 Shot 新 current 时只允许一个成功。删除已有计划、候选或交付引用的 Shot 必须先显示影响，并通过归档/替代保留历史。

## 7. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| Agent 只生成部分镜头 | 保留已生成提案并显示覆盖缺口 | 手工补充或重跑缺失 Beat |
| 分镜帧生成失败 | 镜头规划仍可编辑和批准 | 上传参考或稍后重试 |
| 上游人物状态变化 | 显示受影响镜头而非全片失效 | 选择保留、修订或接受风险 |
| 并发重排 | 显示新增、删除、移动差异 | 基于当前顺序重放操作 |
| 删除被引用镜头 | 阻止级联删除历史 | 归档、替代或先处理引用 |

## 8. 权限与审计

镜头编辑、批准、锁定、拆分/合并和高影响删除分别授权。所有批准、锁定、覆盖缺口接受和影响忽略记录操作者、基线、理由和结果。审片人默认只读镜头方案，不能修改正式顺序。

## 9. 非功能需求

| ID | 要求 |
| --- | --- |
| SHT-NFR-001 | 大型镜头表使用分页或虚拟化并支持批量选择。 |
| SHT-NFR-002 | 顺序、镜头方案和覆盖计算可重建且结果可解释。 |
| SHT-NFR-003 | 所有 P0 编辑可用键盘完成，不强制使用画布或拖拽。 |
| SHT-NFR-004 | 重复提案接受和重排命令不创建重复 Shot 或顺序项。 |
| SHT-NFR-005 | 具体镜头数量、预演长度和并发编辑目标由真实项目签认。 |

## 10. 验收条件

| ID | 场景 |
| --- | --- |
| AC-SHT-001 | 批准叙事可以手工形成至少 10 个带来源和实体绑定的镜头。 |
| AC-SHT-002 | 插入和重排镜头只改变显示顺序，不改变已有 Shot ID。 |
| AC-SHT-003 | 拆分一个镜头后保留父子谱系和下游影响说明。 |
| AC-SHT-004 | 未覆盖 Beat、对白和必要动作分别可见并能定位。 |
| AC-SHT-005 | 人物换装只标记引用该状态范围的镜头待复核。 |
| AC-SHT-006 | 分镜帧失败时用户仍可完成手工镜头规划。 |
| AC-SHT-007 | 旧 Animatic 在新顺序发布后仍按旧版本播放。 |
| AC-SHT-008 | 并发批准和重排返回明确版本冲突，不覆盖他人结果。 |
| AC-SHT-009 | 删除被计划/候选/交付引用的镜头不会物理删除历史。 |

## 11. 指标与待确认项

指标包括首个可审阅分镜时间、Beat/对白覆盖率、镜头提案人工修改率、锁定后变更率、局部修改比例、连续性预检问题数和 Animatic 完成时间。待确认首期镜头字段必填集合、关键帧是否要求首尾帧、音频意图进入 P0 还是 P1，以及镜头拆分/合并对既有候选的默认处理。
