## 1. 需求概述

Lanverse 必须帮助个人创作者或小型制作团队，把已有故事/分集剧本制作成一集可完整播放、可审核、可局部返工、可追溯成本与来源的 AI 竖屏短剧。平台价值是组织生产闭环，而不是封装一次模型调用或复刻竞品页面。

MVP 的完成结果是：用户能够从剧本建立角色/场景等资产，确认分镜，逐镜头生成并选择候选，完成音画时间线、审核和渲染，最终获得 MP4、字幕及交付清单。

## 2. 用户与权限边界

| 角色 | 核心目标 | MVP 权限边界 |
| --- | --- | --- |
| owner | 管理个人空间、项目、预算和交付 | 全部业务操作及 Workspace 管理 |
| editor | 完成剧本、资产、分镜、生成和审核 | 除成员、空间和预算上限外的创作操作 |
| viewer | 浏览项目进度、任务和成片 | 只读，不触发生成或修改事实 |

MVP 首先保证单个 owner 独立完成全流程。邀请、外部审片、自定义角色和项目级 ACL 不得阻塞首个闭环。

## 3. 业务范围与阶段

`项目立项 → 剧本入库 → 结构确认 → 资产准备 → 分镜准备 → 镜头生产 → 时间线合成 → 审核返工 → 渲染交付`

每个阶段必须由服务端事实计算完成条件、阻塞原因和下一动作。允许退回到具体镜头、资产或时间线版本，但不得跳过权限、授权、readiness、费用或审核门禁。

## 4. 模块与唯一事实

| 模块 | 唯一拥有的事实 | 不得拥有的事实 |
| --- | --- | --- |
| identity | UserAccount、Workspace、Membership | 项目内容、任务和费用 |
| projects | Project、Episode、生产概览 | 剧本正文、媒体字节和任务状态 |
| media | MediaObject、MediaVersion、Lineage | 角色、镜头和时间线业务规则 |
| governance | Consent、Review、Issue、Decision、Label、AuditEvent | 被审对象正文和业务副本 |
| scripts | ScriptSource、ScriptVersion、Scene、ExtractionBatch/Candidate | 已确认资产版本和生成候选 |
| assets | Asset、AssetVersion | ShotSpec 内的资产使用关系 |
| storyboards | Shot、ShotSpecVersion、镜头顺序和 readiness | 生成任务、候选媒体和费用 |
| production | GenerationRequest、Task/Attempt、Candidate、CostEntry | ShotSpec 和媒体文件内容 |
| editing | Timeline/Version、Render、DeliveryManifest | 审核决定和媒体字节 |

## 5. 平台功能性需求

| 编号 | 需求 |
| --- | --- |
| SYS-FR-001 | 用户必须能在一个 Workspace 内创建项目和单集，并只访问有权访问的数据。 |
| SYS-FR-002 | 用户必须能导入或编辑剧本，通过版本保存历史，并人工处理 AI 提取候选。 |
| SYS-FR-003 | 用户必须能建立版本化资产，并让 ShotSpec 引用固定资产版本。 |
| SYS-FR-004 | 用户必须能创建、编辑、重排、拆分、合并和校验镜头，不因单镜头返工重做整集。 |
| SYS-FR-005 | 用户必须能提交图片、视频、语音或音效生成，查询真实任务状态并选择候选。 |
| SYS-FR-006 | 用户必须能在刷新、断线、Worker 重启或供应商超时后从服务端恢复任务和下一动作。 |
| SYS-FR-007 | 用户必须能组合镜头、声音和字幕，提交审核、定位问题、返工并重新发布版本。 |
| SYS-FR-008 | 用户必须能导出可验证的成片、字幕和交付清单，并追溯到规格、资产、调用、费用和审核。 |

## 6. 平台实体需求

| 编号 | 需求 |
| --- | --- |
| SYS-ENT-001 | 所有业务事实必须归属一个 Workspace；跨 Workspace 的 ID 不得被解析、引用或推断。 |
| SYS-ENT-002 | Project 包含 Episode；Episode 是剧本、分镜、生产和交付的单集边界。 |
| SYS-ENT-003 | ScriptVersion、AssetVersion、ShotSpecVersion、MediaVersion 和 TimelineVersion 必须不可变并可追溯。 |
| SYS-ENT-004 | Task/Attempt、Candidate、CostEntry、Decision 和 AuditEvent 属于证据记录，用户不得覆盖或硬删除。 |
| SYS-ENT-005 | 跨模块只保存稳定 ID、明确版本和必要快照，不复制另一模块的可变状态。 |

## 7. 平台接口需求

| 编号 | 交接面 | 需求 |
| --- | --- | --- |
| SYS-IF-001 | Web/API | 所有前端能力必须通过版本化 OpenAPI 契约访问；客户端不得手写另一套 DTO 或业务状态机。 |
| SYS-IF-002 | 身份系统 | 服务端必须验证外部身份令牌，并把稳定身份映射为 UserAccount 和 ActorContext。 |
| SYS-IF-003 | 模型供应商 | 文本、图像、视频和语音能力必须转换为内部稳定请求、任务和候选契约。 |
| SYS-IF-004 | 对象存储 | 上传、下载和生成媒体必须默认私有，通过受控上传和短期访问能力交接。 |
| SYS-IF-005 | 异步任务 | 长任务创建必须快速返回 Task；客户端通过 Task 或聚合快照恢复，不保持请求等待。 |
| SYS-IF-006 | 媒体工具 | 探测、转码和渲染结果必须回写媒体版本、hash、规格、日志摘要和失败原因。 |

所有接口错误至少区分：无权访问、不存在、输入无效、状态冲突、版本过期、额度不足、任务处理中、外部状态未知和内部失败。列表查询只支持明确的筛选、排序和分页，不提供动态查询语言。

## 8. 平台非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| SYS-NFR-001 | 安全 | 私有数据默认拒绝访问；每次查询和命令必须校验身份、Workspace、角色和资源归属。 |
| SYS-NFR-002 | 一致性 | 业务事实、Task、费用预占和待投递事件必须保持原子一致，不得出现已扣费但无任务的状态。 |
| SYS-NFR-003 | 幂等 | 可重试写命令必须识别相同业务请求，返回同一结果或明确处理中，不产生重复外部副作用。 |
| SYS-NFR-004 | 恢复 | 页面刷新、进程重启和消息重复投递不得丢失已确认事实；未知外部调用必须先对账再重试。 |
| SYS-NFR-005 | 可追溯 | 任一交付镜头必须能追溯输入版本、参考资产、模型请求、任务尝试、媒体、费用和审核。 |
| SYS-NFR-006 | 性能 | 普通读写不得等待外部模型或 FFmpeg；API、列表规模和单集基准的 P95 阈值在 PRD 中量化。 |
| SYS-NFR-007 | 可观测 | 日志、trace、任务和供应商请求必须以稳定 ID 关联，并能定位失败阶段与下一动作。 |
| SYS-NFR-008 | 可维护 | 模块依赖必须单向、公开接口显式；禁止万能 BaseCRUD、重复 DTO、全局业务 utils 和空转层。 |
| SYS-NFR-009 | 质量 | 核心规则必须覆盖单元、真实数据库集成、契约和关键端到端测试；测试与生产目录必须分离。 |
| SYS-NFR-010 | 合规 | 个人数据、真人授权、敏感内容、生成标识和审计留存必须符合目标上线地区要求。 |

## 9. 全局生命周期与删除规则

- 可变草稿允许修改；发布或被引用的版本只能追加新版本。
- 只有未被引用、未产生费用、未进入审核的草稿允许硬删除。
- 已产生业务历史的 Project、Episode、Asset、Shot 和 Media 只能归档；归档不得破坏历史读取。
- 任务、成本、审核决定、内容标识、血缘和审计记录不得由普通用户删除。
- 状态变化必须通过业务命令完成，前端不得直接 PATCH 状态字段。

## 10. MVP 非目标

- 不做自训练模型、GPU 调度、工作流市场、微服务或第二套任务系统。
- 不做专业 NLE、实时多人协作、无限画布、移动端、社区和自动渠道发布。
- 不做组织层级、SCIM、自定义角色、项目级复杂 ACL 或完整企业计费系统。
- 不承诺一句话无人审核直接成片，也不把竞品页面复刻当作业务完成。

## 11. 待确认和待量化事项

- 单集目标时长、典型/最大镜头数、剧本字符数、并发生成数和媒体容量。
- 默认模型供应商、能力参数、失败收敛时限、价格与额度口径。
- 目标上线地区、授权材料、审核责任、内容标识和日志留存周期。
- 普通 API、聚合快照、上传和渲染的性能目标及生产可用性目标。
