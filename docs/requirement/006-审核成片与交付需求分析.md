# 审核、成片与交付需求分析

## 1. 在生产链中的职责

本模块负责把“制作产生候选”推进为“有依据的审核决定、明确采用的单集版本和可证明的交付版本”。它不生成候选，不管理资产本体或权利事实，也不替代专业剪辑、调色、混音、母版和发行系统；页面、时间线、转码、接口和存储方式留待后续 Design。

业务闭环为：

`明确候选 → 提交审核 → 定位意见 → 审核决定 → 返工或可采用 → 单集组织 → 整集复核 → 交付门禁 → 交付版本`

## 2. 唯一事实源边界

| 事实 | 唯一维护方 | 本模块的责任 |
| --- | --- | --- |
| 候选、输入基线、制作尝试和制作失败 | REQ-005 | 引用明确候选；退回时产生返工请求 |
| 资产身份、版本、来源和使用关系 | REQ-004 | 记录审核、采用和交付对具体资产版本的使用 |
| 权利、安全、额度和 AI 标识状态 | REQ-007 | 消费治理结论形成交付门禁，不复制判断事实 |
| 成员、项目角色和运营访问 | REQ-002 | 使用已有角色决定提交、审核、采用和交付权限 |
| 审核轮次、意见、决定、采用、单集及交付版本 | REQ-006 | 作为这些事实的唯一维护方 |

任务结束、有候选、审核通过、当前采用、单集通过和正式交付是六个独立事实，任何一个都不能由另一个自动推导。

## 3. 审核对象与版本语义

| 对象 | 必须表达的内容 |
| --- | --- |
| 审核提交 | 具体候选版本、审核目标、提交人、审核责任人和必要创作上下文 |
| 审核轮次 | 本次提交、意见、回复、决定及其针对的固定版本范围 |
| 审核意见 | 对整体、时间点/时间段、画面区域或内容对象的明确反馈 |
| 审核决定 | 通过、需要修改、拒绝使用或终止本轮，以及决定人和理由 |
| 返工请求 | 由审核问题转成的修改对象、范围、期望和原决定引用 |
| 采用关系 | 某镜头、对白、字幕或声音使用位置当前选择的具体版本 |
| 单集版本 | 镜头顺序、采用媒体、主要时长、对白、字幕、音乐和音效的固定组合 |
| 交付版本 | 明确单集版本、交付目标、门禁结果、决定人、时间和后续状态 |

审核中的对象不得被静默替换；内容变化必须形成新版本或新一轮审核，原意见和决定继续可查。

## 4. 从提交到返工的功能契约

| 编号 | 触发 | 必须产生的结果 | 责任与协作 | 优先级 |
| --- | --- | --- | --- | --- |
| REV-01 | 创作者认为候选值得判断 | 固定审核版本、目标、上下文和责任人；缺失项明确阻塞 | 项目创作者提交，项目审核者接收 | MVP |
| REV-02 | 提交错误或审核前撤回 | 终止当前提交并保留原因；修改后重新提交新版本 | 提交者操作，已通知审核者 | MVP |
| REV-03 | 审核者发现问题 | 意见定位到版本及必要的时间、区域或内容对象 | 审核者负责清晰表达，创作者可澄清 | MVP |
| REV-04 | 创作者处理意见 | 每条意见标记已处理、未处理、存在分歧或不再适用，并引用新版本 | 创作者回复，原审核者复核 | MVP |
| REV-05 | 审核信息充分 | 形成通过、需要修改、拒绝使用或终止决定；无评论不等于通过 | 有审核责任者决定 | MVP |
| REV-06 | 决定为需要修改 | 向 REQ-005 输出对象、问题、范围、期望和优先级明确的返工请求 | 审核者提出，创作者承接 | MVP |
| REV-07 | 多名审核者结论冲突 | 保留各自结论并交指定最终责任人裁决，不能自动合并为通过 | 项目负责人须同时具备审核责任 | P1 |
| REV-08 | 新候选解决返工 | 开启新轮次，只复核受影响范围；无法确定影响时扩大人工复核 | 创作者重提，审核者判断范围 | MVP |

自动检查可以提示异常和辅助定位，但不能替有责任的人作艺术判断或正式决定。

## 5. 从采用到整集复核的功能契约

| 编号 | 触发 | 必须产生的结果 | 责任与协作 | 优先级 |
| --- | --- | --- | --- | --- |
| CUT-01 | 版本通过且决定用于作品 | 在明确使用位置建立当前采用关系；通过但未采用仍保留 | 成片整理者属于项目创作者，审核者可提要求 | MVP |
| CUT-02 | 替换当前采用版本 | 保存旧采用历史和原因，标明受影响单集与已有复核结论 | 成片整理者变更，审核者复核影响 | MVP |
| CUT-03 | 准备一集可观看内容 | 形成固定镜头顺序、采用媒体、时长、对白、字幕和声音组合 | 成片整理者组织，内容与资产模块提供事实 | MVP |
| CUT-04 | 关键组成缺失、失效或无权使用 | 单集版本显示阻塞项，不得伪装为完整版本 | 整理者处理，相关模块修复来源问题 | MVP |
| CUT-05 | 单集版本形成或关键组成变化 | 对叙事、节奏、连续性、音画、字幕和整体质量形成整集决定 | 项目审核者负责，创作者协作 | MVP |
| CUT-06 | 整集复核发现局部问题 | 意见定位到单集区间及具体镜头/声音，回到对应审核或制作环节 | 审核者定位，创作者局部回改 | MVP |
| CUT-07 | 仅局部内容变化 | 形成需重新检查的影响范围，不自动废弃无关通过结论 | 变更者说明，审核者最终确认 | MVP 直接影响；P1 间接影响 |

单集版本是内容组合的事实快照，不等同于专业剪辑工程；同一单集可以有多个历史版本，但正式交付必须明确引用其中一个。

## 6. 交付门禁与版本契约

| 编号 | 触发 | 必须产生的结果 | 责任与协作 | 优先级 |
| --- | --- | --- | --- | --- |
| DEL-01 | 用户准备正式交付 | 明确交付目标以及画幅、时长、音轨、字幕、标识等要求 | 项目负责人提出，整理者准备 | MVP |
| DEL-02 | 指定单集版本进入交付检查 | 汇总内容完整性、整集决定、规格、权利、安全和 AI 标识结论 | REQ-006 汇总，REQ-007 提供治理事实 | MVP |
| DEL-03 | 所有强制门禁通过 | 由有交付责任者形成正式交付决定和不可混淆的交付版本 | 经 REQ-002 明确授予交付决定权限的人执行 | MVP |
| DEL-04 | 非强制条件需例外继续 | 记录批准人、原因、风险、范围和期限；强制权利或安全限制不可绕过 | 授权负责人提出，治理责任者协作 | MVP |
| DEL-05 | 交付物形成或导出失败 | 保留已确认单集和交付决定，区分重新形成交付物与重新制作内容 | 整理者重试，运营处理平台异常 | MVP |
| DEL-06 | 已交付内容发现错误或限制变化 | 标记影响，必要时停止使用；更正、替换或重新交付形成新版本 | 项目负责人发起，审核与治理共同确认 | MVP |
| DEL-07 | 面向不同渠道或语言交付 | 每种要求形成独立可追溯交付版本及状态 | 整理者准备，审核者确认 | P1 |

交付版本形成后，其内容组成、门禁证据和决定不得静默覆盖；删除项目内容也不能使既有交付事实变得不可解释。

## 7. 权限与协作底线

- 项目创作者可以提交候选、回复意见和组织单集；只有同时具备项目审核者责任时才能作正式审核或单集决定。
- 项目审核者可以评论和决定获授权对象；查看、评论、决定、改变采用和正式交付是不同权限。
- 工作空间所有者或项目负责人不因头衔自动获得审核或交付决定权，须按 REQ-002 实际分配权限。
- 平台运营人员只能处理访问、传输、风险限制等明确事件，不得改变艺术决定、采用关系或用户成果。
- 外部审片者属于 P1；如真实证据要求提前，需先同步调整 REQ-001 与 REQ-002 的首发范围。

## 8. 异常处置底线

| 异常 | 必须保持的事实与行动 |
| --- | --- |
| 审核版本不可访问 | 保留提交和意见，阻塞决定，修复访问或重提新版本 |
| 部分内容通过 | 保留已通过事实，同时标明阻塞单集的未决部分 |
| 已采用版本被停用或治理状态变化 | 标记受影响单集和交付，要求替换、复核或合规处置 |
| 审核意见含糊或互相冲突 | 要求补充定位或裁决，不能直接生成无边界返工 |
| 已交付版本出现严重问题 | 保留原交付证据，记录限制范围，通过新版本更正或重新交付 |
| 外部审片访问误分享 | 立即限制后续访问并交由 REQ-007 记录和处置影响 |

## 9. MVP 边界与待验证证据

MVP 的第一种交付目标是用户可获取、可完整观看的单集可审视频，不承诺无需外部后期即可直接发行。MVP 必须走通：明确候选提交、定位意见、审核决定、返工重提、当前采用、单集组织、整集复核、交付门禁、交付物形成与导出，以及更正版本。P1 再考虑多级审核、批量审片、版本并排比较、外部客户审片、多渠道/语言版本、交付回执和更细影响分析。

首期不建设专业后期工具、发行与观众运营平台、复杂客户门户或企业审批体系，也不承诺自动审核替代导演判断、法律意见或渠道审核。

进入 `review` 前须用真实样片证明：意见可以定位并关闭；通过与采用不混淆；局部修改能确定复核范围；整集可发现单镜头之外的问题；交付版本可还原其组成和门禁证据。仍待确认首发审核粒度、定位精度、单集可审视频的第一种规格、升级为可发布成片的必要性及外部审片进入 P1 的时机。
