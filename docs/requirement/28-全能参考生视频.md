# REQ-28 全能参考生视频

| 项 | 内容 |
| --- | --- |
| 需求 | VID-04 全能参考生视频（必须，不可降级） |
| 优先级 | MVP |
| 用例 | UC-12 |
| 页面 | 镜头详情 · 视频 |
| 依赖功能 | REQ-08、REQ-15、REQ-19、REQ-21、REQ-22、REQ-29 |
| 状态 | 草案（2026-09-25） |

## 1. 需求说明

### 1.1 背景与目标

多角色同框、复杂动作、模仿参考运镜、按音频节奏表演，这些镜头用图生视频难以做到。主流视频模型已支持同时输入多图、多视频、多音频参考（PRD-02 §1：Seedance 2.x 类模型 9 图 / 3 视频 / 3 音频）。全能参考是产品核心能力（P10），写实与风格化都必须可用。

### 1.2 用户故事

- 作为**制作者**，我希望用镜头的参考组合（多角色造型图、场景图、道具图、动作 / 运镜参考视频、参考音频）加镜头参数与画面描述直接生成视频。

### 1.3 范围

包含：参考组合展开、按模型映射输入、提示词中的参考指代、生成、结果记录参考版本、过期。不包含：参考组合编辑（REQ-19）。

## 2. 需求分析

### 2.1 业务流程

```text
报价：读取镜头当前版本 → 展开参考组合为 Operation 输入（每项：用途、引用、版本、媒体）→ 按模型 limits 校验 → 提示词组装（为每个参考项生成指代，如“图1 为李明，图2 为王芳，视频1 为运镜参考”）→ 计价
执行：适配器把用途映射为供应商参数（如 reference_images[]、reference_videos[]、reference_audios[]，及各自说明文本）→ 提交 → 轮询 → 接管
结果：片段记录所用全部参考版本（operation_input 即证据）
```

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 生成输入 = 镜头当前版本参考组合展开后的**全部**项 + `prompt`；不静默丢弃任何一项（超限在报价阶段拒绝） | VID-04 |
| R2 | 片段记录所用参考的版本（`operation_input.ref_version`） | VID-04 |
| R3 | 参考组合中任一项更新（新版本、改选）后，已生成片段标记过期 | VID-04、LIN-01 |
| R4 | 提示词为每个参考项生成稳定的指代编号，与传给供应商的顺序一致 | 模型需要知道“哪张图是谁” |
| R5 | 音频参考时长超过镜头时长：截取与镜头时长相同的片段（从 0 开始，用户可在参考项上设置起点） | 模型时长限制 |
| R6 | 写实与风格化项目都必须通过验收（§4）；P0 若没有满足的模型，重新评估方案而不是降级（PRD-01 §12） | P10 |

### 2.3 状态

同 Operation。

### 2.4 异常与边界

- 供应商对多人同框返回质量差：属于质量问题，由多候选与评测解决；记录一致性抽检结果（TST-03）。
- 参考素材 URL 需供应商可访问：使用预签名 URL（有效期 ≥ 供应商预计处理时长 + 1 小时）；供应商要求上传到其存储时由适配器先上传。

### 2.5 前置与依赖

至少一个支持全能参考的模型（P0 确定）；REQ-19 参考组合有效。

## 3. 实现所需

### 3.1 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `storyboard.reference_item` | 参考组合 | 输入模板 |
| `operation.operation_input` | `seq_no`、`role`、`ref_type`、`ref_id`、`ref_version`、`media_asset_id`、`text_value` | 冻结输入、证据 |
| `operation.operation` | `mode = omni_reference`、`input_hash` | 执行与复用 |
| `lineage.dependency` | 片段 → 每个参考项上游 | 过期 |

`reference_item` 增加可选列 `trim_start_ms integer`（音频 / 视频参考起点，R5；DES-02 同步）。

### 3.2 接口

```http
POST /api/projects/{pid}/quotes
{ "items": [ { "target_type": "shot_take", "target_id": "<shot_id>", "capability": "video.generate", "mode": "omni_reference", "output_count": 2 } ] }
200 { "items": [ { "operation_id": "…", "quote_micros": 30000000, "inputs_preview": [
        { "seq": 1, "role": "subject", "label": "图1 李明 / 日常装 v1" }, { "seq": 2, "role": "subject", "label": "图2 王芳 / 默认 v2" },
        { "seq": 3, "role": "scene", "label": "图3 医院走廊 v1" }, { "seq": 4, "role": "camera", "label": "视频1 推镜参考" },
        { "seq": 5, "role": "audio", "label": "音频1 台词 3-12-1" } ],
      "prompt_preview": "图1 中的男子与图2 中的女子在图3 的走廊相遇，参考视频1 的推镜运动，按音频1 的节奏说话……" } ] }
```

Activity `provider.submit` 的 `inputs[]`（DES-03 §7.1）按 `seq_no` 传递 `role`、`media_url`、`media_type`、`duration_ms`、`label`。

### 3.3 异步与工作流

同 REQ-27（异步视频）；适配器层负责用途映射，供应商不支持某用途时在报价阶段已被 `limits` 拒绝。

### 3.4 事件与实时

同 REQ-21、REQ-22。

### 3.5 界面

镜头详情：参考组合（REQ-19）+ 提示词预览（带指代编号高亮）+ 生成；候选卡片可展开“所用参考”列表。

### 3.6 权限与审计

同 REQ-21、REQ-22。

### 3.7 非功能要求

AIQ-04、AIQ-05；PERF-09。

## 4. 验收标准

- Given 参考组合含角色 A v1、角色 B v1、场景 S v1，When 生成视频，Then 任务输入与片段记录均包含这 3 项及其版本。
- Given 双角色同框镜头，When 生成完成，Then 人工抽检两人外观与各自锁定造型一致。
- Given 参考组合含运镜参考视频，When 生成完成，Then 人工判断运镜与参考一致。
- Given 参考组合含参考音频，When 生成完成，Then 人工判断表演节奏与音频一致，片段记录所用音频版本。
- Given 写实与风格化项目，When 各执行上述场景，Then 均通过。

## 5. 测试要点

- 适配器映射单元测试（每个供应商的参数形态）；提示词指代与输入顺序一致性。
- 人工评测：TST-03 全能参考评测集（写实 + 4 种风格化 × 单角色 / 双角色 / 动作 / 运镜 / 音频）。
