# Go 后端业务完整性需求规格（Spec）

日期：2026-09-08。依据 [Design](../design/0016-Go后端业务完整性实施设计.md) 与 [PRD](../prd/0016-Go后端业务完整性产品需求.md)。本文件在本轮新增 Go 代码之前建立。

## 首批执行契约

| ID | 必须满足的行为 | 验证 |
|---|---|---|
| BG-01 | Manifest/Attempt 公共查询先重新鉴权，非法运行/步骤输入失败，未授权不请求 Agent | Application 负向/调用次数 |
| BG-02 | Go 按固定 run endpoint、精确 GET path/body 签名；保留 context、超时与响应限制，拒绝跳转/重复键/尾随 JSON | HTTP 故障服务与取消测试 |
| BG-03 | Manifest schema/run/input/source 与持久 run 绑定；template_hash、manifest_hash 按原 JSON 核验；recorded/not_frozen/unavailable 互斥，不补造历史 | 跨语言合成合同/漂移反例 |
| BG-04 | Attempt 限定 run/step，序号/ID/fence 唯一、状态/时间/结果组合合法；unavailable 必须无历史和当前指针；不泄露未定义字段 | 非法身份、状态、时间、字段反例 |
| BG-05 | GET 只读且 no-store；401/404/409/502/503/504 有明确语义；上游任意 404 不变成 queued | 公共 handler/Agent HTTP |
| BG-06 | TextWorld/TextIntent 正式版本可按项目及固定版本 ID 查询，先当前权限后读取，来源/版本/hash 漂移失败；不回退到最新版本 | Owner 单元与数据库/HTTP |
| BG-07 | OpenAPI 同步新增路径、参数、成功与错误合同，通过仓库 schema/路由检查 | OpenAPI 测试 |
| BG-09 | 规范化摘要及严格协议解码拒绝重复对象键、尾随 JSON 与过深结构；合法已有 hash 不变 | 平台合同及全模块回归 |
| BG-08 | 不修改 Agent/前端；保留基线；Go 依赖 adapter → application → domain，新增测试独立 tests/ | 架构/diff 检查 |

## 全量业务完成矩阵

下列每项必须分别证明正常路径、当前权限、非法输入、CAS/幂等、持久化/回滚和失败恢复；不因普通 go test 返回 0 自动通过。

- ALL-01 Access/Project：身份、会话、成员、项目与归档。
- ALL-02 Script/Planning：源发布、来源读取、分集和场次采纳。
- ALL-03 Bible/Storyboard/Review：世界/意图、审阅、采纳和固定版本查询。
- ALL-04 Creation/Agent/Workflow：接受、派发、执行追踪、恢复和版本边界。
- ALL-05 Authoring/StoryGraph：合法结构、发布、版本和只读投影。
- ALL-06 Asset/Media：上传接管、格式探测、READY、视频/声音派生和引用。
- ALL-07 Generation/Cost/Quota：实际供应商调用、回调/unknown 对账、费用额度与选用。
- ALL-08 Search/Eventing：权限过滤、持久事件、幂等/乱序和恢复。
- ALL-09 视频/声音/成片交付：技术质量、不可变交付版本与授权范围；目前尚缺完整实现。

## 完成定义

执行 [Plan Checklist](../plan/0016-Go后端业务完整性实施计划.md)；每项独立映射 [Acceptance](../acceptance/0016-Go后端业务完整性验收记录.md) 证据。所有修改 Go 运行 gofmt/goimports、go vet、golangci-lint、Race Detector、govulncheck 及完整测试；环境缺失须记录实际原因。收尾审查合同、并发、权限、错误链、隐私、查询副作用、依赖、OpenAPI 和 Git 状态。未运行外部条件的全量项保留未完成。

## 供应商运行 Spec

- PG-01：冻结配置按原版本读取；跨租户、摘要和凭据引用漂移必须在解密/网络前失败。
- PG-02：描述注册与可执行工厂严格区分，缺少实际实现不可提交；查询只进入原适配器 Query。
- PG-03：凭据解密不持有事务，执行结束清零；取消错误链保留；无自动重试/fallback。
- PG-04：首批图片输入不支持的能力明确拒绝；响应有界，解码实际 PNG、核验尺寸、写入私有存储才返回输出。
- PG-05：注册、Worker 注入、失败路径及真实协议模拟验收；未执行真实供应商付费调用不得报告联调成功。


## 完整实现收敛合同
- BC-01：合法正式参考资产目标可进入供应商请求，正向/排除要求均保留；领域摘要或项目范围漂移在网络前失败。
- BC-02：全量 Lint 不再携带旧错误文本规范问题；错误码/错误链不变，文本断言同步。
- BC-03：部署入口/环境文件与实际部署、测试引用一致；用户正在调整的删除不得擅自恢复。

BC-04：上传完成的第二事务重新鉴权及检查实际完成时间；读取期间撤权、过期、取消不得生成正式版本。

- BC-05：同工作区同幂等键并发初始化返回同一 UploadSession；不返回唯一键内部错误，不产生重复行。

- BC-06：死信索引首次写入前可以按 @timestamp 排序查询；新建和 rollover 索引都由独立模板约束字段。真实 ELK 验证非法日志仅保留受限字段。
