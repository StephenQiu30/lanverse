# FR-002 项目、系列与分集管理需求规格说明书

## 1. 目的与范围

建立“项目—系列—季（可选）—单集”的稳定内容层级，管理创作范围、交付目标、责任人、生命周期和跨模块进度汇总。

本能力不管理剧本正文、资产版本、制作任务或审核决定，只引用对应模块的当前事实。

## 2. 参与角色

- 工作空间所有者或管理员。
- 制片人、项目负责人和内容创作者。
- 具有项目访问权限的审核者或查看者。

## 3. 主业务流程

1. 创建项目并定义内容形态、受众、语言、画幅、时长、预算和交付范围。
2. 选择单集项目，或建立系列和可选季层级。
3. 建立单集并定义故事边界、顺序、目标时长和责任人。
4. 各功能模块在项目中形成内容、资产、任务、审核和交付事实。
5. 项目汇总当前状态、阻塞和下一责任动作。
6. 项目结束时处理运行中事项并归档。

## 4. 功能需求

| 编号 | 规范性需求 | 优先级 |
| --- | --- | --- |
| FR-002-001 | 系统应为项目、系列、季和单集建立稳定且不可复用的标识。 | P0 |
| FR-002-002 | 系统应记录项目的题材、受众、内容形态、语言、画幅、目标时长、预算引用和交付范围。 | P0 |
| FR-002-003 | 系统应允许项目在不建立系列或季时直接管理单集。 | P0 |
| FR-002-004 | 系统应允许建立系列、可选季和有唯一顺序的单集。 | P1 |
| FR-002-005 | 系统应为每个单集记录故事起止、叙事目标、目标时长、责任人和当前内容基线。 | P0 |
| FR-002-006 | 系统应允许单集继承项目规格，并显式记录经授权的局部覆盖。 | P0 |
| FR-002-007 | 系统应分别维护项目、系列、季和单集的业务状态。 | P0 |
| FR-002-008 | 系统应汇总内容、资产、制作、审核、成本和交付状态，且不得复制或改写各模块唯一事实。 | P0 |
| FR-002-009 | 系统应为每个阻塞显示来源、责任人和下一动作。 | P0 |
| FR-002-010 | 系统应在分集顺序或范围变化时标识连续性、分镜、时间线和交付影响。 | P1 |
| FR-002-011 | 系统应允许归档项目，并阻止归档项目创建新的生产活动。 | P1 |
| FR-002-012 | 系统应在归档前要求处理运行任务、未完成审核和消费争议。 | P1 |

## 5. 业务规则

- BR-002-001：标准层级为系列—季（可选）—单集—场次—镜头。
- BR-002-002：系列和季不得成为单集 MVP 的强制前提。
- BR-002-003：项目“完成”不得从一个任务或一个交付状态自动推导。
- BR-002-004：归档不等于删除，历史内容、费用和交付事实必须保持可解释。

## 6. 数据要求

- DR-002-001：保存项目层级、归属、顺序、目标、责任人、状态和生命周期记录。
- DR-002-002：项目聚合只保存下游事实引用和更新时间，不复制下游明细。
- DR-002-003：项目目标或单集边界变更保存旧值、新值、原因和影响清单。

## 7. 异常与恢复

| 场景 | 系统行为 |
| --- | --- |
| 关键项目目标缺失 | 允许保存草稿，但阻止确认生产基线。 |
| 单集顺序冲突或重复 | 阻止确认，并要求形成唯一顺序。 |
| 归档时存在运行任务 | 保持待归档状态，要求等待、取消或移交。 |
| 调整已交付单集范围 | 保留原交付，创建新的影响和交付版本需求。 |

## 8. 验收标准

- AC-002-001：单集项目无需创建系列即可进入剧本创作。
- AC-002-002：修改项目画幅后，相关分镜、时间线和交付版本显示待复核。
- AC-002-003：归档项目后历史内容可查，但不能创建新生成任务。
- AC-002-004：项目状态汇总可下钻到来源模块，且同一对象不重复计数。
