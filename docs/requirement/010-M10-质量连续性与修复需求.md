# M10 质量、连续性与修复需求

> Requirement ID：REQ-QAR
> 状态：proposed v1
> 日期：2026-08-20
> 上游：[目标需求总览](./000-AI视频生产平台目标需求总览.md)、[M04](./004-M04-生产知识与一致性图谱需求.md)、[M09](./009-M09-媒体候选与选择需求.md)
> 对应模块：M10 质量、连续性与修复

## 1. 需求结论

质量系统必须把技术、语义、连续性、安全和品牌问题绑定到确定对象、版本和证据位置。自动评估只能提出 Issue 和建议；问题只能通过复检、人工判定或具名风险接受关闭，不能用分数自动替换候选或主选。

RepairPlan 必须说明只重做哪些镜头/区段、为什么、读取哪些输入、预计消耗和保留哪些未受影响结果。

## 2. 用户结果与范围

用户可以查看问题严重度、证据、规则、影响和责任范围，确认、驳回、接受风险或创建局部修复；新候选到达后只定向复检相关问题。

本模块不直接执行生成、不拥有人工 Selection、不批准正式交付，也不把模型审美评分作为业务事实。

## 4. 问题模型与严重度

Issue 至少包含类别、严重度、对象与版本、时间码/区域/字段证据、期望与实际、规则、评估来源、置信、阻塞范围和建议动作。

严重度按对叙事正确性、连续性、技术可用性、权利安全和交付的影响定义，不能只按模型分数。自动检测的低置信问题保持建议；硬格式损坏、明确权利拒绝等确定问题可以直接阻塞，但仍需可解释证据。

## 5. 决议与修复规则

1. 自动评估不能采用候选、替换主选或批准交付。
2. 驳回自动问题要记录理由，供后续评估器校准但不修改历史结果。
3. 接受高严重度风险需要独立权限、具名主体、理由、范围和有效期。
4. RepairPlan 引用固定问题和输入版本；输入变化后必须重新计算。
5. 修复结果到达后旧问题进入待复检，不直接标 resolved。
6. 未受影响镜头、候选、选择和审阅不得因局部修复被重建。

## 6. 失败与恢复

| 场景 | 用户可见结果 | 恢复动作 |
| --- | --- | --- |
| 评估器失败 | 显示未检查范围，不等于通过 | 重跑检查或人工检查 |
| 部分镜头无法评估 | 保留已完成结果和缺口 | 只处理缺失范围 |
| 规则版本变化 | 旧结果标过期但保留 | 按新规则定向重评 |
| RepairPlan 输入过期 | 阻止执行并显示变化 | 重新计算影响和计划 |
| 修复生成失败 | 原候选、问题和主选不变 | 重试或修改 RepairPlan |
| 风险接受到期 | 相关阻塞重新出现 | 复检或重新批准 |

| QAR-NFR-005 | 指标区分误报、漏报、未评估和人工接受风险。 |

## 8. 验收条件

| ID | 场景 |
| --- | --- |
| AC-QAR-001 | 损坏视频被技术检查阻塞并定位具体错误。 |
| AC-QAR-002 | 人物服装与批准状态不符时问题关联正确镜头、状态和证据。 |

| AC-QAR-004 | 自动高分候选不会覆盖人工主选。 |
| AC-QAR-005 | 用户驳回误报后保留评估和理由历史。 |
| AC-QAR-006 | 局部修复只为选定镜头建立新计划，兄弟镜头不重跑。 |
| AC-QAR-007 | 修复候选到达后问题必须复检才能关闭。 |
| AC-QAR-008 | 规则版本变化只使相关评估过期，不删除旧证据。 |
| AC-QAR-009 | 高严重度风险接受缺少权限、理由或有效期时被阻止。 |

## 9. 指标与待确认项

指标包括技术通过率、连续性一次通过率、Issue 误报/漏报率、平均解决时间、局部修复比例、每次修复影响镜头数、定向复检命中率和风险接受率。待确认首个结构化语义检查器、严重度矩阵、允许自动阻塞的确定性规则和人工抽检方案。
