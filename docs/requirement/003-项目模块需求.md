# REQ-003 项目模块需求

- 状态：待确认
- 输入：`001-平台总体需求概述.md`、`002-用户与空间模块需求.md`
- 输出：Project、Episode、项目设置、生命周期和生产概览需求
- 下游：REQ-006 至 REQ-010

## 1. 需求概述

项目模块必须提供短剧系列与单集的稳定业务边界，并聚合展示生产阶段、阻塞项、异常任务和成本摘要。它只保存项目自身事实和其他模块的当前版本引用，不复制剧本、资产、任务或时间线正文。

MVP 必须允许单个创作者创建一部 Project 和一个 Episode，并从该 Episode 进入完整生产闭环。

## 2. 业务实体需求

| 编号 | 实体 | 需求 |
| --- | --- | --- |
| PRJ-ENT-001 | Project | 必须归属 Workspace，保存名称、简介、默认画幅、语言、视觉风格、目标时长、预算上限和生命周期状态。 |
| PRJ-ENT-002 | Episode | 必须归属一个 Project，保存名称、序号、目标信息、归档状态及当前剧本/时间线版本引用。 |
| PRJ-ENT-003 | ProductionSnapshot | 必须由各模块公开事实计算当前阶段、完成度、阻塞原因、异常任务、待审核项和成本摘要，不作为可编辑实体。 |

Project 和 Episode ID 必须稳定；重命名、重排或归档不得改变 ID。Episode 序号在同一 Project 内唯一，并由服务端维护。

## 3. 功能性需求

| 编号 | 需求 |
| --- | --- |
| PRJ-FR-001 | editor/owner 必须能创建 Project；创建时必须验证 Workspace 活跃和必填设置合法。 |
| PRJ-FR-002 | 用户必须能按权限列表、搜索、排序和读取 Project，并选择是否包含归档项目。 |
| PRJ-FR-003 | editor/owner 必须能修改 Project 元数据和默认制作设置；修改不得重写既有版本输入。 |
| PRJ-FR-004 | editor/owner 必须能创建、读取、修改元数据和重排 Episode。 |
| PRJ-FR-005 | 系统必须根据下游完成事实计算 Episode 当前阶段、阻塞原因和下一动作，前端不得直接更新阶段。 |
| PRJ-FR-006 | 项目概览必须展示单集进度、运行/异常任务、待审核项、已用/预占成本和最近活动。 |
| PRJ-FR-007 | owner 必须能归档/恢复 Project；editor/owner 能归档 Episode，归档后禁止新建生产事实。 |
| PRJ-FR-008 | 只有无 Episode、无版本、无任务和无费用的空白 Project 草稿可硬删除；Episode 同理。 |

## 4. 接口需求

| 编号 | 接口能力 | 输入 | 输出与错误 |
| --- | --- | --- | --- |
| PRJ-IF-001 | Project 列表/详情 | ActorContext、筛选、分页 | Project 摘要或详情；跨 Workspace 按不存在处理 |
| PRJ-IF-002 | 创建/修改 Project | 允许字段、Workspace、期望状态 | 最新 Project；设置无效或状态冲突返回明确错误 |
| PRJ-IF-003 | 归档/恢复/删除 Project | Project ID、期望状态 | 新状态或删除结果；有阻塞引用返回阻塞清单 |
| PRJ-IF-004 | Episode 列表/详情/创建/修改 | Project ID、允许字段 | Episode；父 Project 归档时拒绝写入 |
| PRJ-IF-005 | Episode 重排 | Project ID、有序 Episode ID 列表 | 原子更新后的顺序；缺失、重复或越权 ID 返回输入无效 |
| PRJ-IF-006 | 生产概览 | Project/Episode ID | current_stage、blocking_reasons、next_actions 与模块摘要 |
| PRJ-IF-007 | 内部当前版本引用更新 | Episode ID、版本类型、期望旧 ID、新 ID | 更新结果；旧 ID 不匹配返回版本冲突 |

生产概览是只读组合查询；它不得绕过所属模块修改状态，也不得把组合结果回写成第二份完整事实。

## 5. 非功能性需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| PRJ-NFR-001 | 隔离 | 所有 Project/Episode 查询与修改必须受 Workspace 和角色约束。 |
| PRJ-NFR-002 | 一致性 | Episode 重排、归档和当前版本引用更新必须原子完成，失败不得留下重复序号。 |
| PRJ-NFR-003 | 可解释 | current_stage、blocking_reasons 和 next_actions 必须能追溯到具体模块事实，不使用前端缓存推断。 |
| PRJ-NFR-004 | 性能 | 项目列表和概览不得逐项触发无界查询；典型/最大项目与单集规模及 P95 在 PRD 量化。 |
| PRJ-NFR-005 | 审计 | 设置、预算上限、归档、删除和当前版本引用变化必须记录 actor 与前后值。 |
| PRJ-NFR-006 | 可维护 | 新增概览字段必须标明事实来源，不得在 Project 表复制下游状态。 |

## 6. 生命周期与失败路径

- Project：`active ↔ archived`；空白草稿可删除。归档不得取消历史读取或破坏交付链接。
- Episode：`active ↔ archived`；生产阶段是派生值，不建立可任意修改的阶段状态机。
- 修改默认画幅、风格或模型策略只影响以后创建的规格/请求；既有 ShotSpecVersion 和 GenerationRequest 保持原输入。
- 概览依赖模块暂时不可用时必须返回可识别的部分失败，不得把缺失数据解释为零任务、零成本或已完成。

## 7. 非目标与待确认

- 不实现项目模板市场、多集自动排期、跨项目资产复制、实时协作和项目级成员权限。
- 不让项目模块拥有剧本正文、媒体签名、任务重试、成本结算或审核决定。
- 待确认单个 Workspace 的典型项目数、单项目 Episode 数、预算口径和归档后运行任务策略。
