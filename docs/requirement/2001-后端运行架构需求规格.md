# 后端运行架构需求规格

- 状态：统一运行入口实施基线
- 日期：2026-08-28
- 设计依据：[后端服务架构](../design/2001-后端服务架构.md)

## 范围

本规格覆盖一个 Go Backend Binary、一个私有 Candidate Agent、一个 PostgreSQL SQL 事实源，以及当前已落地的 MinIO、Temporal、Kafka、Elasticsearch/ELK 边界。不预建多 Backend Binary、Redis、gRPC、迁移平台或仅转发调用的空服务。

## 运行与职责

| ID | 必须满足的契约 | 验收方式 |
|---|---|---|
| `BE-RUN-001` | Browser 的公共业务请求只能进入 `lanverse` Backend；Go Backend 拥有认证、项目、剧本、Bible、分集、结构、分镜、Shot、导出和任务状态的全部写入权。 | 路由清单、进程启动与浏览器全旅程。 |
| `BE-RUN-002` | Python Agent 只暴露私有 `/internal/v1/invocations` 和 `/healthz`，只返回 Candidate/Proposal；不得拥有公共业务 Router、业务 Repository 或数据库/对象存储凭据。 | 入口、依赖与导入图架构测试。 |
| `BE-RUN-003` | `healthz` 只证明 Backend/API 存活；公共 `readyz` 检查 API 必需依赖，内部 Event Runtime readiness 检查 PostgreSQL、Kafka 与 Elasticsearch；SIGTERM 有界关闭 HTTP、数据库和 Runtime。 | 端点、依赖故障与停机测试。 |
| `BE-RUN-004` | 已领取的 Agent Invocation 必须具有有界 Lease；进程退出后，过期 `running` Invocation 使用相同稳定 ID 重新领取，旧 Claim 的迟到结果不得写入。 | 真实 PostgreSQL 过期回收、Claim Fencing 与进程重启测试。 |
| `BE-RUN-005` | `backend/cmd` 只能包含一个 `main.go`；镜像只包含一个 `lanverse` 可执行文件，同一进程启动 API、Workflow 与 Event Runtime，`replay`/`reindex` 只作为该 Binary 子命令。 | 目录、Docker 镜像、进程日志和子命令验收。 |
| `BE-RUN-006` | `docker-compose.yml` 只声明 Frontend/Backend 项目服务并复用已启动环境；`docker-compose-env.yml` 只声明显式 `bundled-*` profile 的隔离依赖，且不得声明 Frontend/Backend；本机不得重复启动已存在的 Homebrew Temporal、Kafka 或外部 Logstash；日志只使用 Logstash，不使用 Filebeat。`docker-compose-prod.yml` 只提供线上覆盖。任何文件都不得再声明 Workflow/Event Backend 服务或额外 Entrypoint。 | 三套 Compose 独立/组合渲染、服务清单与真实分层启动。 |

## 分层与契约

| ID | 必须满足的契约 | 验收方式 |
|---|---|---|
| `BE-ARC-001` | Handler 只处理协议/认证/错误映射；Application 持有授权、事务、幂等和状态门；Domain 不依赖 ORM/HTTP；GORM 只允许在数据库平台和 `gormdb` Adapter。 | Go AST/Import 架构测试。 |
| `BE-CON-001` | 公共 REST 唯一事实源是 `backend/api/openapi/lanverse-public-api.json`；Agent Invocation/Result 线协议由 `backend/internal/agent/contract` 所有，Python Runtime 使用禁止额外字段的 Pydantic 消费模型严格验证。 | JSON 解码、版本/字段契约测试和真实 HTTP 集成。 |
| `BE-CON-002` | Backend 以短时 HMAC Execution Grant 固定 Invocation ID、Kind、Input Hash 和过期时间；Agent 必须恒定时间校验并回显绑定字段。 | Go/Python 正反契约测试。 |

## 单一 SQL 事实源与 ORM

| ID | 必须满足的契约 | 验收方式 |
|---|---|---|
| `BE-DAT-001` | Backend 只打开一个 `DATABASE_URL`；PostgreSQL 是注册、项目、剧本、Bible、分集、结构、分镜、Shot、导出、Command Receipt 和任务状态的唯一 SQL 事实源。 | 配置测试和进程连接检查。 |
| `BE-DAT-002` | `backend/internal/platform/database/model` 中的 Owner GORM Record Catalog 是唯一表结构定义；空库由 Catalog 非破坏性同步，重复同步无副作用。 | 独立空 PostgreSQL 集成测试。 |
| `BE-DAT-003` | 仓库不得包含 Migration 目录/Binary、迁移版本/Checksum/Source 字段或元数据表、第二数据库 DSN、pgx 业务 Repository、Python SQLAlchemy Model 或第二 ORM Writer。 | 路径、依赖、表清单和标识符扫描。 |
| `BE-DAT-004` | 常规 CRUD、关联、统计、事务和行锁使用成熟 GORM API/Clause；Domain/Application/Handler 不得写 SQL。 | Import/AST 门禁、事务与并发测试。 |
| `BE-DAT-005` | 创建 AI 资源时在同一事务写业务聚合、WorkflowTask 与 AgentInvocation；Worker 按 Kind 领取，失败为 failed/unknown，Agent 成功不能直接形成 confirmed/applied 事实。 | 真实 PostgreSQL 旅程与状态测试。 |
| `BE-DAT-006` | 每次领取 AgentInvocation 必须原子递增 `claim_version` 并设置 `lease_expires_at`；完成/失败只接受当前 Claim Version，Resume 不得重置 Fencing 序号。 | 并发领取、过期回收、迟到结果和 Resume 后旧结果负向测试。 |

## 对象存储与安全

| ID | 必须满足的契约 | 验收方式 |
|---|---|---|
| `BE-STO-001` | MinIO Bucket 私有；Backend 区分内部访问地址与 Browser 预签名地址，校验声明大小和 SHA-256 后才登记不可变媒体版本。 | 临时 MinIO 上传/读取集成测试。 |
| `BE-SEC-001` | 所有业务资源检查 Workspace Membership/Role；JWT、Refresh Token、Execution Grant、数据库和对象存储 Secret 不进入日志、响应或公开契约。 | 权限矩阵与泄漏扫描。 |

## 非目标

- 不把已落地的 Kafka、Temporal、Elasticsearch 再拆为额外 Backend Binary；没有可验证的扩缩容、权限或故障隔离需求前，不增加多 Go Binary、Redis、gRPC 或通用 Agent 平台。
- 没有历史生产数据搬迁需求前，不建立 Migration 框架或兼容字段。
- 不用旧 Python Writer、手写 SQL 原型或模型桩作为目标架构完成证据。
