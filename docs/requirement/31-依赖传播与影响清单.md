| 项 | 内容 |
| --- | --- |
| 需求 | LIN-01 依赖传播；LIN-02 影响范围与批量重做 |
| 优先级 | MVP |
| 用例 | UC-18 |
| 页面 | 影响清单；所有对象上的“过期”标记 |
| 依赖功能 | REQ-13、REQ-15、REQ-16、REQ-18、REQ-19、REQ-22、REQ-23、REQ-29、REQ-34 |

## 1. 需求说明

### 1.1 背景与目标

生产是渐进的：改一句台词、换一个造型，会影响已生成的镜头、配音与剪辑。自动重做会产生大量费用且未必需要，所以只标记“过期”并给出影响清单与重做预估，由人决定（PRD-01 §7.3 规则 1）。

### 1.2 用户故事

- 作为**制作者**，我希望上游修改后能看到哪些下游内容受影响，而不是被自动重做。
- 作为**制作者**，我希望看到影响清单与重做预估费用，选择重做哪些。

### 1.3 范围

包含：依赖登记、过期标记与清除、影响清单、重做报价入口。不包含：自动重做。

## 2. 需求分析

### 2.1 依赖关系表

| 上游变化（事件） | 过期的下游 |
| --- | --- |
| 台词内容变化（`episode_structure_confirmed`，`content_hash` 变） | 引用该 `line_key` 的镜头版本 → 其片段 / 关键帧；该台词的 TTS（V2 起含真人音轨）；（V2）剪辑计划中对应条目 |
| 参考槽位改锁（`reference_locked`） | 引用旧版本的镜头（参考组合或关键帧依赖）→ 其关键帧 / 片段 |
| 角色音色变化（`voice_changed`） | 该角色的 TTS 台词音频 →（V2）剪辑条目 |
| 镜头新版本（`shot_version_created`） | 基于旧版本生成的关键帧候选与片段；（V2）剪辑条目 |
| 关键帧改选（`selection_changed` frame） | 图生视频片段 |
| （V2）片段 / 台词音频改选 | 剪辑计划当前版本对应条目 |
| （V2）剪辑计划新版本 | 成片（提示“剪辑已更新，成片不是最新”） |

### 2.2 业务规则

| # | 规则 | 理由 |
| --- | --- | --- |
| R1 | 下游版本创建时登记它依赖的上游（稳定键 + 版本） | 传播依据 |
| R2 | 过期只写 `stale_mark`，不修改任何业务数据，不自动生成 | LIN-01 |
| R3 | 过期递归传播，深度 ≤ 6 | 覆盖全链路 |
| R4 | 下游产生新版本 / 新选定且依赖已是最新时，清除对应过期标记 | 状态收敛 |
| R5 | 过期状态在镜头表、故事板、配音、影响清单（V2 起含剪辑、成片）中可见，并说明原因（哪个上游、哪个版本） | LIN-01 |
| R6 | 影响清单按集 → 场 → 镜头 / 台词分组，列出当前状态与重做预估费用；可勾选后进入批量报价 | LIN-02 |
| R7 | 过期不阻止渲染，仅提示 | EDT-03 |

### 2.3 状态

`stale_mark`：开放（`cleared_at` 为空）→ 已清除。

### 2.4 异常与边界

- 传播延迟：事件驱动，P95 ≤ 5 秒（REL-07）；传播期间界面可能短暂未显示过期。
- 同一对象多个原因：多条标记，全部清除才算不过期。
- 大规模传播（主角造型改锁影响 2,000 镜头）：消费者分批写入（每批 500），SSE 发送聚合事件。

## 3. 验收标准

- Given 造型 A 更新到 v2，When 查看第 1 集故事板，Then 所有引用 A v1 的镜头显示“过期”，未引用的镜头不受影响。
- Given 影响清单列出 20 个镜头，When 勾选其中 5 个并确认报价，Then 只为这 5 个镜头创建生成任务。
- Given 过期镜头重新生成并选定新片段，When 查看，Then 过期标记清除。
- Given 过期任何对象，When 检查业务数据，Then 没有自动生成的新任务。
