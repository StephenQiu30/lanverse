# 模块边界与工程质量验收

## 1. 当前结论

工程骨架和实现尚未开始，结论为 `not_ready`，全部 AC 为 `pending`。架构意图不能代替可失败的自动测试。

## 2. 证据规则

状态仅使用 `pending/passed/failed/blocked`。实施后记录环境戳、命令、退出码、提交和报告到 `artifacts/acceptance/004/`。所有架构与契约测试必须进入 `make verify`。

| AC | 状态 | 验收方法 | 必需证据 |

| AC-M01 | pending | 注入 core → framework/SDK 非法 import | 架构测试先失败、移除后通过 |

## 4. 强制检查

- Domain 单元测试不启动 PostgreSQL、RabbitMQ、MinIO 或供应商 SDK。
- 模块只通过公开 Port/事件协作，无循环依赖和跨 schema 写入。
- 事件只携带 ID、版本、时间和 trace，不携带 prompt、媒体或 secret。
- Source、Generation、ObjectStore、EventBus、Search 的 fake/真实实现遵守同一契约。
