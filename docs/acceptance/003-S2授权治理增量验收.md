## 1. 交付结果

1. Consent 以不可变 Revision 保存首次登记、范围修订和撤销；创建支持幂等键，修订与撤销使用 expected revision，冲突不会覆盖当前事实。
2. 授权范围固定到具体 MediaVersion 或 ScriptVersion，并保存权利类型、用途、渠道、地域、有效期和证明媒体引用；证明不可访问、未成年人主体或跨空间对象均 fail-closed。
3. RightsGate 按固定 subject、usage、time 返回 `allowed/blockers`；过期、撤销、范围不匹配和依赖不可用均不会默认为通过，历史 Revision 不会被删除。
4. Next.js 治理工作台通过生成的 OpenAPI client 读取 Workspace、媒体与授权事实，支持登记、追加修订、撤销、空态、加载态和可恢复错误；登录/注册也已从 mock 切换为真实认证接口。
5. 本地验收只复用已经安装并运行的一个 MinIO 实例；仓库 Compose 与 CI 固定到 `RELEASE.2025-09-07T16-13-09Z-cpuv1` 及镜像 digest，`make minio-up` 不会在 9000 端口健康时重复启动实例，并会校验唯一容器和发行版。

## 4. 接受边界与残余风险

1. 本文只接受 DEV-S2-04 工程增量，不提前接受 PT-GOV-001/002 或 S2；PT-MED-001～003 尚缺用户可操作的上传/探测前端闭环，因此 M2 仍为 `in_progress`。
2. RightsGate 已是可复用的内部公开契约，但真实生成与公开交付尚未进入 S4/S5；后续 Task、Review、Delivery 接入时仍必须逐一证明门禁调用不可绕过。
3. 当前授权 UI 支持 MediaVersion 选择，ScriptVersion 采用 UUID 输入；S2 剧本/资产工作台完成后应改为服务端事实选择器，不能长期依赖手工 ID。
4. 默认 `make check` 不隐式启动外部服务；本次 MinIO 真实契约单独执行并记录，不能把其他 6 项默认 skip 解释为通过。
5. 本机 MinIO 容器虽然由历史 `latest` 标签创建，但运行二进制已校验为冻结发行版；仓库后续新建与 CI 均使用 tag + digest，禁止重新引入浮动标签。
