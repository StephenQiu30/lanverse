## 1. 验收结论

1. 新增语义化 `backend/app/modules/messaging/metrics.py`，固定六个当前已发布 event type、`invalid/unregistered` sentinel、`lanverse.io/lanverse.media/unregistered` queue 和有限结果集合；未知或攻击者控制的字符串不能制造新 Prometheus label。
2. Publisher 指标为 `lanverse_outbox_publish_results_total(queue,event_type,result)` 与 `lanverse_outbox_publish_duration_seconds(queue,event_type)`。只有 RabbitMQ confirm 后且 PostgreSQL 成功标记 published 才记录 `published`；只有 PostgreSQL 成功保存退避时间后才记录 `retry_scheduled`，不会以遥测结果替代 Outbox 事实。
3. Worker 指标为 `lanverse_message_results_total(queue,event_type,result)` 与 `lanverse_message_handler_duration_seconds(queue,event_type)`。合法 Envelope 记录 `completed/duplicate/rejected/requeued`；无法解析或超限消息只记录固定 `invalid/rejected`，不解析或输出 body。
4. 日志事件固定为 `outbox.publish.completed/failed` 与 `message.consume.completed/failed`，携带 W3C trace/span、业务 request/event 关联、已归一事件类型、queue、attempt/result/duration/retryable 和错误类型。异常正文、payload、token、URL、Workspace/Task ID 不进入 event attributes 或 metric labels。
5. 默认 `app.server` 在启动 API、Scheduler 和两个 Worker 前以 `lanverse-server` 配置一次进程级 logging/telemetry；后启动角色遵循 first-writer-wins，不竞争重置 handler/provider。默认单进程 `/metrics` 因而能汇总四个角色；独立启动单角色时使用该角色 service name。

## 3. 真实基础设施、性能与全量证据

- 完整后端在本增量最终复核后为 222 passed/12 个显式外部或性能开关 skipped。
- 本机 RabbitMQ 隔离 vhost 真实契约为 2 passed；Scheduler 恢复栈为 1 passed；直接复用本机 MinIO 的 Media 栈为 4 passed。Publisher confirm、Worker ack/Inbox、Task 与存储事实均未因日志/指标接入改变。

## 4. 环境、命名与前端修正边界

`.env.example` 和 `.env.production.example` 继续精确保留 `DEEPSEEK_API_KEY=`、`ARK_API_KEY=` 空占位；Playwright 使用显式空值运行，DeepSeek 能力按设计 fail-closed，没有 Ollama、Ark SDK 或模拟供应商成功。

新增文件仅使用 `metrics.py`、`test_message_observability.py` 等职责语义名称；没有新增 `s1/s2` 阶段代号式文件、通用 utils、第二套遥测框架或 Collector 容器。前端竞态修复复用现有 RTK Query `refetch`，没有复制服务端资产到本地状态、没有增加 Effect 或兼容层；交互仍以服务端 revision 为唯一并发事实。

## 5. 未接受项与残余风险

PT-OBS-002 整体仍为 in_progress，PT-OBS-003 仍为 proposed。当前结果 Counter/Histogram 是进程内指标；默认 `app.server` 可统一暴露，但如果未来把 Scheduler/Worker 独立扩容为不同进程，必须为各角色提供独立受控 scrape endpoint 或正式 Prometheus multiprocess 架构，不能假定 API `/metrics` 自动聚合其他进程。

尚未实现 Outbox pending/oldest age、RabbitMQ ready/unacked/consumer inflight、连接/重连、Task stage/unknown、Provider、费用、Storage、MinIO、ffprobe/FFmpeg 指标；也没有 OTLP exporter 故障降级计数、生产 `/metrics` 网络/鉴权边界、告警阈值或 runbook。当前日志 formatter 对任意不可 JSON 序列化第三方值的最终降级仍待 PT-OBS-001 后续加固。

本增量不新增数据库结构，但 Acceptance 017 的 `sys_outbox_events.traceparent` 在线迁移风险继续存在。运行日志和 Prometheus 指标仍不是业务恢复事实，重试/重复/成功判断只以 PostgreSQL Outbox、Inbox、Task、ScheduleFire 和 AuditEvent 为准。
