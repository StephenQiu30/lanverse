## 4. 环境与安全边界

本增量不需要 DeepSeek 或 Ark API Key，不安装或调用 Ollama/Ark SDK，也不伪造 Seedream/Seedance 成功。示例环境文件继续使用 `DEEPSEEK_API_KEY=` 与 `ARK_API_KEY=` 空占位；无 Key E2E 明确验证 DeepSeek 提取 fail-closed。测试仅复用本机 PostgreSQL、RabbitMQ 和现有基础设施，没有启动第二套 MinIO。

新增测试 fixture 只包含虚构邮箱、名称、hash 和 trace，不保存凭据、对象 key、URL 或依赖错误原文。数据库约束名、文件名和测试名均按功能语义命名，不使用 `s1`、`s2` 等切片代号。

## 5. 未接受项与残余风险

PT-DAT-002/003 仍保持 in_progress。尚未实现的 GenerationRequest/Attempt/Reservation/Cost、Timeline/Render/Manifest 等表无法形成真实租户、并发和生命周期证据；Outbox/Inbox/ScheduleFire 的具体运维留存窗口也尚未确认，因此本次没有增加任意默认天数或清理器。

ShotTransform 的来源/结果 ID 当前按已接受设计保存为 UUID 数组，数组成员与 Episode 的业务一致性由锁内服务命令验证；本次接受的是变换证据自身的 Episode/Workspace 父级，不把数组成员描述为数据库外键。若未来要求数据库逐成员追踪，必须先把数组模型改为组成关系表并重新评审 Design，而不是添加触发器暗层。

当前工程仍只允许空库 `metadata.create_all()`，没有存量数据库在线 migration。开发/测试库会重建并获得新约束；任何包含持久数据的部署在应用本变更前必须先设计、评审并验证正式 schema migration，不得依赖 `create_all()` 自动修补。
