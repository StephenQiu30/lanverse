## 1. 交付结果

1. 资产身份支持角色、场景、道具、服装、视觉风格和声音六类受区分且类型化的规格；未知字段、跨类型字段和非法引用在进入 JSONB 前被拒绝。
2. AssetVersion 只追加不改写，current 指针使用 expected revision 比较交换；并发切换只有一个请求成功，历史版本及固定媒体引用保持不变。
3. Readiness 在读取时组合类型化字段、MediaVersion 探测状态和 RightsGate 结果；缺字段、媒体未就绪、授权撤回或治理依赖不可用均返回结构化 blocker 和 next action，不持久化会过期的派生布尔值。
4. 剧本确认后的资产候选可创建新身份或幂等关联既有资产；候选决定保留来源和固定关联，不把抽取结果直接升级为可生产资产。
5. Next.js 资产工作台通过生成的 OpenAPI client 读取真实项目、资产、版本、媒资与准备度，支持六类筛选、搜索、创建身份、追加版本、归档/恢复、版本历史与治理跳转；服务端状态由 RTK Query 缓存并在授权变化后使准备度失效重取。
6. 本地验收复用唯一已安装 MinIO，不启动第二实例；仓库新建与 CI 使用冻结 tag + digest，运行前同时校验唯一 9000 端口容器和精确二进制发行版。

## 4. 接受边界与残余风险

1. 本文只接受 DEV-S2-05 工程增量，不提前接受 PT-AST-001～003/005、WP-05 或 S2。S2 退出条件要求角色、场景、声音至少各一项 ready；本次浏览器证据只证明角色曾 ready 且撤回后 blocked、场景在未授权时 blocked，尚无 ready 声音。
2. 资产 UI 已覆盖当前 DEV 需要的创建、追加版本、归档/恢复；身份编辑和安全删除已有真实 API 与集成测试，但尚未进入 DEV-S2-06 的统一前端闭环。
3. 浏览器验收使用实际签名 PUT 写入本地 MinIO；为了只验证本增量的资产 UI，在隔离验收库中登记了媒体探测结果。RabbitMQ → Media Worker → MinIO → ffprobe → PostgreSQL 的真实链路已有 DEV-S2-03 独立契约证据，本次没有重复启动 Worker，也不把该登记冒充新的媒体全链路验收。
4. 资产工作台尚未串起“导入 → 提取 → 决议 → 确认 → ready 资产”的单一路径，项目 current ScriptVersion 和聚合 Snapshot 仍由 DEV-S2-06 完成。
5. 默认 `make check` 不隐式启动外部服务；6 项 skip 仍是显式真实依赖测试，不能解释为通过。MinIO 真实契约已另行执行，RabbitMQ/完整媒体链路沿用已记录的独立证据。
