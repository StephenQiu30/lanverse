本轮实现调用证据和发送门禁，不注册真实供应商，不改变 mock Workflow 活动顺序或 Operation 状态转换。同步完成仍不能进入接管或结算；私有对象 manifest、凭据执行、费用核定、审核、公共生成 API 和产品链由后续切片交付。

## 1. 本轮决策

- 首个收据版本只表示一个图片输出；JSON 最大 4 KiB，单产物上限 32 MiB。它们是内部边界，不代表任何供应商的支持范围。
- 新发送门禁通过显式 `dispatch_required` 与持久 `dispatch_contract=v1` 采用。旧调用没有发送时间不能证明未发送，禁止从旧行取得新发送权。
- 同步 completed 与费用可核定分开。当前同步成本保持 NULL；即使人为记零或已有人工事件，也不能将 completed 判为未执行。
- 首次 attempt 为 1，随后连续递增；只有所有前次都已确认 not_submitted 才能登记新发送 attempt。
- 已存在发送时间或收据时拒绝 down migration。回滚检查与 DDL 在同一事务内锁定分区表，防止并发发送证据丢失。
- 保留当前 mock 和旧 JSON，不在本片放宽 submitting→ingesting；后续同步 Workflow 分支须按计划实施费用门禁与历史回放。

## 2. Red 证据

1. `go test ./tests/operation/provider_receipt_test.go -run '^TestM1(SyncCompletedContract|ReceiptStrictJSON)$' -count=1`：合法 completed 被旧 Validate 拒绝；旧解码接受未知、重复、大小写变体和超容量收据，按预期失败。
2. completed usage 的新增失败样例：未知字段、重复字段、负数、null、小数和空对象被原校验放行；修复前均失败。
3. 隔离真实 PostgreSQL 的 `TestM1CompletedEvidenceBlocksManualNotExecuted`：NULL/零费用 completed 分别触发原记录、信号和成本检查错误放行，按预期失败；预算仍保持 held。
4. 独立审阅后新增 `TestM1CompletedReceiptRejectsTerminalMutation`：原实现对 completed/failed/cancelled/expired 四个终态错误返回成功并改变整行证据；增加终态门禁后通过，完全同体只读重放仍允许。

上述测试使用固定合成载荷、临时数据库及当前业务代码，不调用供应商或读取真实凭据。临时测试库由本轮新建，只对该库执行迁移与测试，不修改现有业务库。

## 4. 证据边界

- 本轮可证明技术合同、真实 PostgreSQL 的数据/并发行为和旧载荷兼容。
- 不证明可靠对象 manifest 已写入、真实图片已生成、真实审核/用量/费用成立。
- 没有新的公共 API 或页面接线；不报告首条真实文生图、完整 M1-12 或 MVP 已完成。
- 用户已确定本机 Codex imagegen 优先、火山 Seedream/Seedance、OpenRouter 扩展。只读核实 CLI 0.159.2 的公开协议；未连接运行 app-server 或生成图片，账号能力、产物和图片费用仍未验证，见 [设计 §4](../design/BeefTV生成能力迁移设计.md#4-本地优先的供应商接入)。
- 三个本轮自建数据库已按确切名称删除，删除前均无连接，删除后精确计数为 0；未终止其他连接、修改全局角色或已有数据库。
- 未读取 `.env` 或真实供应商 secret；无付费、推送、合并和发布。按用户先前授权提交本地 main，测试、实现与文档分别记录在 Git 历史。
