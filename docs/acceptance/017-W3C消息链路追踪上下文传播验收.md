## 1. 验收结论

1. HTTP middleware 使用 OpenTelemetry SDK 接收合法 `traceparent` 或创建新根 span；响应返回当前 server `traceparent`。合法入站上下文保持同一 32 位 trace ID 并生成新的 server span ID；非法值被忽略、重建且不原样回显。
2. UUIDv7 `request_id` 与 W3C 上下文职责分离：既有业务 `trace_id` 可继续保存 request ID 供 Audit/Task 关联；`sys_outbox_events.traceparent` 以独立非空字段保存标准传播上下文，不把两种 ID 强制转换或混用。
3. Outbox Publisher 从持久化上下文创建独立 producer span，将 producer 当前 `traceparent` 同时写入 MessageEnvelope 与 RabbitMQ header。发布重试会生成新 attempt span，消息确认/失败事实仍由 PostgreSQL Outbox 决定。
4. IO Worker 与 Media Worker 优先使用合法 RabbitMQ header，缺失或非法时回退 Envelope；每次投递创建新的 consumer span。重复消息保持相同 trace 和 producer parent，但 consumer span ID 不复用，Inbox 幂等结果不变。
5. 当前进程未配置 exporter 时仍生成和传播上下文；没有引入 Collector、远程 APM、Ollama、Ark SDK 或任何依赖 API Key 的运行条件。

## 4. 环境、命名与安全边界

`.env.example` 与 `.env.production.example` 都精确保留 `DEEPSEEK_API_KEY=`、`ARK_API_KEY=` 空占位；本次验收显式用空 Key 启动 E2E，没有读取或输出未提交 `.env`，也没有伪造 DeepSeek、Seedream 或 Seedance 成功。

新增实现与测试使用 `telemetry.py`、`test_trace_context_propagation.py` 等职责语义名称。仓库现存文件名检查不包含 `s0/s1/s2` 等阶段代号式 basename；历史 Acceptance 与 E2E 已以功能名称替换，删除/新增状态属于尚未提交的同一重命名集合。

span 属性只使用受控 method、模板 route、status、消息系统、登记 event type/routing key 与稳定 result；不记录 token、body、query、对象 URL、剧本、prompt、供应商错误正文或凭据。异常路径只记录异常类型并设置 error status，不调用会把异常正文写入 span 的自动 `record_exception`。

## 5. 未接受项与残余风险

PT-OBS-002 整体仍为 in_progress，PT-OBS-003 仍为 proposed。当前没有 Task/Attempt、Provider、DeepSeek、MinIO、ffprobe、FFmpeg 或完整 Scheduler 子阶段 span；没有数据库池、Outbox backlog、RabbitMQ inflight、Task/provider/storage/media 全指标，也没有采样配置、OTLP exporter/Collector 故障计数、告警阈值或 runbook。

`sys_outbox_events.traceparent` 是新的非空列；当前仅在会重建 schema 的测试库通过 `metadata.create_all()`，没有提供存量数据库在线 migration。任何保留数据的部署必须先设计、评审并验证迁移与回填策略，不能依赖 `create_all()` 修补。

MessageEnvelope.traceparent 为滚动消息演进保留可选输入；当前新 Outbox 事件始终产生非空值，旧消息缺失时 Worker 会创建新根 span，业务处理不中断但无法恢复原链路。`/metrics` 生产访问边界、日志 formatter 对任意不可序列化第三方值的最终降级以及进程级 exporter 生命周期也仍待后续验收。
