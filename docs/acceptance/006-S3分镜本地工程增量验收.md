## 1. 交付结果

1. Shot 支持 confirmed Scene/shot Candidate 或手工 creation key 建立、120 上限、完整集合重排、复制、拆分、合并、归档、恢复和受保护删除；position/order hash、revision、impact hash 与幂等键共同阻止并发覆盖。
2. ShotSpec v1 以不可变版本保存剧本、场次、对白和固定 AssetVersion 引用；current 只能显式切换，未知字段、供应商参数、跨 Episode 结构和非法资产类型在写入前被拒绝。
3. readiness 返回稳定 blocker/warning/next action 与 evaluation hash；scripts、assets、media 或 governance 依赖不可用时 fail-closed，不把草稿、过期授权或故障误报为 ready。
4. 资产版本 usage 按页区分当前与历史规格。升级必须选择当前引用并先执行服务端 preflight；apply 锁定全部目标，任一 expected Spec、Shot revision 或 preflight hash 变化时整批零写入，成功后每个 Shot 只追加一个新规格版本。
5. Next.js 分镜工作台使用生成的 OpenAPI client 和 RTK Query，提供已确认 shot 候选/手工建镜、revision 保护的标题修改、完整规格编辑、历史版本切换、拖拽重排及键盘上移/下移、复制、归档恢复、拆分/合并预检、安全删除、批量 blocker，以及资产引用/升级复核；主体站位、对白声音/表演提示、首尾帧意图和 readiness warning 均进入用户界面，没有 API Key、模型参数、供应商费用或伪造生成结果。
6. 12/36/120 镜头固定性能样本使用虚构主体和 ready 的 location、2 character、voice、visual style 固定引用；production 配置单进程通过本机 loopback PostgreSQL 运行 10 次预热、50 次采样和 120 镜头 30 次重排。
7. current ScriptVersion 切换通过 storyboards 公开读取契约返回仍固定旧版本的 active Shot ID；切换只更新剧本 current 指针，不重建 Scene，也不改写既有 ShotSpec。资产工作台则允许显式切换历史 current，并明确提示既有镜头固定引用保持不变。
8. 无密钥 Playwright 用例在独立测试库中建立与生产确认结果同构的 published v1 → confirmed v2 → current v2 关系，以及明确标记为本地测试事实、不得解释为模型输出的 accepted Scene/Shot Candidate；浏览器从候选建立并归档 Shot，再完成手工建镜、标题修改、规格 v1/v2/v3 与 current 切换、HTML5 原生拖拽、键盘重排、复制、合并、归档恢复、空镜头安全删除、拆分和刷新恢复。该用例还通过本机唯一 MinIO、RabbitMQ、Media Worker 与授权治理建立真实 ready 场景资产 v1/v2，固定 ShotSpec 对 v1 的引用，在资产 current 切到 v2 后完成 usage 选择、升级预检与批量 apply，确认旧引用转为历史、新引用成为 current、最终拆分出的两个镜头均 ready；归档镜头引用只列为历史，来源版本自动变化时旧选择立即失效。

## 4. Red → Green 记录

1. 先以 ShotSpec 判别模型测试固定字段集合、枚举、时长、action beat 和禁止供应商字段，再实现 v1 领域模型。
2. 先固定建镜、重排、生命周期和并发失败路径，再实现事务、连续位置和 order hash；有来源或规格证据的 Shot 只能归档。
3. 先固定 copy/split/merge 的 preflight、幂等、陈旧 impact 和证据保留，再实现变换事务；下游 Task、Candidate、Media、费用和时间线不复制也不迁移。
4. 先固定 readiness code、授权变化、依赖 unavailable 和 36 镜头查询上限，再实现批量读取；随后扩展到 120 镜头并执行冻结环境 P95。
5. 先固定资产升级全或无测试，再实现 usage、preflight/apply；前端同样先定义引用选择、预检和追加式确认测试，再接入现有资产工作台。
6. 前端主流程先形成失败测试，再实现规格、顺序、生命周期和结构操作；拖拽排序同样先证明把手缺失导致测试失败，再实现目标放置、完整顺序提交和源镜头选中，并保留键盘上移/下移；同时修复了重排后选择跳镜头及服务端英文 readiness 摘要不稳定的问题。
7. 对照 REQ-008 审计后，先以失败测试固定候选建镜、标题修改、warning、主体站位、对白声音/表演提示和首尾帧意图，再接入既有生成 client 与组件；标题使用 expected revision，角色/声音使用稳定 subject key，已归档候选不会被误列为可再次建镜。
8. current ScriptVersion 影响链先以集成测试证明旧版本 active Shot 未被报告，再由 scripts 依赖 storyboards 公开 reader 转 Green；资产历史 current 与安全删除同样先形成页面 Red，再复用现有资产对话框和 RTK Query 实现。
9. 状态追踪审计先以失败架构测试证明 PRD/Plan 仍把 S3 写成本地实施中，再同步切片 PRD、任务 PRD 与两级索引；守卫要求工程完成、产品未接受和 Provider 门禁三项同时存在，避免文档状态替代真实验收。
10. S3 Playwright 首先因本地 fixture 缺完整 confirmation batch/task 事实而保持“新建镜头”禁用，补齐生产同构版本与任务关系后转 Green；随后全量运行暴露首次保存成功提示早于 current/history 重读，连续保存触发 CAS 冲突，现由页面在提示成功前等待两份真实查询刷新。
11. 资产升级浏览器链路复用 S2 已验证的真实上传、探测、资产规格与授权步骤；S3 将场景资产 v1 固定进 ShotSpec 后切换资产 current 至 v2，通过 preflight/apply 追加规格版本，并断言 v1 历史引用、v2 当前引用和拆分后的两个 ready 镜头。定向 2/2 与全量 E2E 7/7 均直接通过，未为测试结果新增产品补丁。
12. 候选建镜浏览器用例先因 fixture 不存在候选按钮超时保持 Red；补入明确标记为 `test-confirmed-structure` 的 accepted Scene/Shot Candidate 与人工决议后转 Green，随后以 Playwright `dragTo` 真实触发 HTML5 拖拽，并用键盘下移/上移复核最终顺序。
13. 资产 current 反向切换的浏览器检查先暴露归档镜头仍被 usage 标为当前，集成测试复现后将 `is_current` 收紧为活动 Shot 与当前 Spec 同时成立；恢复 current 又暴露来源自动变化后沿用旧选择，组件测试先 Red，再把选择状态绑定到来源版本。两条回归均进入 S3 E2E。

## 5. 接受边界与残余风险

1. 本文只接受不依赖 API Key 的本地工程增量，不接受 PT-SBD-001～006、PT-AST-004、WP-06 或 S3 产品切片完成。S2 必须先取得一次真实 DeepSeek 提取→人工决议→结构确认→设为 current 的联合证据。
2. 自动化本地浏览器使用 `tests/support` 中的隔离关系 fixture 建立明确标记为 `test-confirmed-structure` 的 Task/ExtractionBatch、published/confirmed ScriptVersion 及本地 accepted Candidate；这些候选的 confidence note 明示“不代表模型输出”，fixture 不调用 Provider，也不把本地候选解释为真实 AI 结果。因此 DEV-S3-03 的 Provider 起点 E2E 仍为 `in_progress`。
3. 固定性能 profile 已按冻结机器和样本真实运行；它只证明本地 storyboards 查询与命令，不替代 S4 Seedream/Seedance 的供应商延迟、额度、价格或账单证据。
4. 默认 `make check` 中 6 项基础设施契约和固定性能 profile 为显式 skip；性能 profile 与 MinIO 契约已在本轮分别显式通过。MinIO 只启动本机原有唯一容器，精确运行版本由仓库守卫核验；没有重装、升级或启动第二实例。
5. 候选建镜、资产身份/版本/current/归档/删除预检、资产 v1→v2 引用升级，以及分镜手工建镜/规格/current/HTML5 拖拽/键盘重排/复制/合并/归档/删除/拆分已具备真实浏览器交互证据；候选与资产升级对话框也完成最新真实渲染复查。剧本版本影响、完整规格字段和拖拽过程中的瞬时落点态尚缺逐像素截图，该视觉残余不作为 Provider 或产品验收证据。
