## 1. 交付结果

1. Shot 支持 confirmed Scene/shot Candidate 或手工 creation key 建立、120 上限、完整集合重排、复制、拆分、合并、归档、恢复和受保护删除；position/order hash、revision、impact hash 与幂等键共同阻止并发覆盖。
2. ShotSpec v1 以不可变版本保存剧本、场次、对白和固定 AssetVersion 引用；current 只能显式切换，未知字段、供应商参数、跨 Episode 结构和非法资产类型在写入前被拒绝。
3. readiness 返回稳定 blocker/warning/next action 与 evaluation hash；scripts、assets、media 或 governance 依赖不可用时 fail-closed，不把草稿、过期授权或故障误报为 ready。
4. 资产版本 usage 按页区分当前与历史规格。升级必须选择当前引用并先执行服务端 preflight；apply 锁定全部目标，任一 expected Spec、Shot revision 或 preflight hash 变化时整批零写入，成功后每个 Shot 只追加一个新规格版本。
5. Next.js 分镜工作台使用生成的 OpenAPI client 和 RTK Query，提供镜头列表、完整规格编辑、历史版本切换、重排、复制、归档恢复、拆分/合并预检、安全删除、批量 blocker，以及资产引用/升级复核；没有 API Key、模型参数、供应商费用或伪造生成结果。
6. 12/36/120 镜头固定性能样本使用虚构主体和 ready 的 location、2 character、voice、visual style 固定引用；production 配置单进程通过本机 loopback PostgreSQL 运行 10 次预热、50 次采样和 120 镜头 30 次重排。

## 4. Red → Green 记录

1. 先以 ShotSpec 判别模型测试固定字段集合、枚举、时长、action beat 和禁止供应商字段，再实现 v1 领域模型。
2. 先固定建镜、重排、生命周期和并发失败路径，再实现事务、连续位置和 order hash；有来源或规格证据的 Shot 只能归档。
3. 先固定 copy/split/merge 的 preflight、幂等、陈旧 impact 和证据保留，再实现变换事务；下游 Task、Candidate、Media、费用和时间线不复制也不迁移。
4. 先固定 readiness code、授权变化、依赖 unavailable 和 36 镜头查询上限，再实现批量读取；随后扩展到 120 镜头并执行冻结环境 P95。
5. 先固定资产升级全或无测试，再实现 usage、preflight/apply；前端同样先定义引用选择、预检和追加式确认测试，再接入现有资产工作台。
6. 前端主流程先形成失败测试，再实现规格、顺序、生命周期和结构操作；修复了重排后选择跳镜头及服务端英文 readiness 摘要不稳定的问题。

## 5. 接受边界与残余风险

1. 本文只接受不依赖 API Key 的本地工程增量，不接受 PT-SBD-001～006、PT-AST-004、WP-06 或 S3 产品切片完成。S2 必须先取得一次真实 DeepSeek 提取→人工决议→结构确认→设为 current 的联合证据。
2. 本地浏览器使用人工建立的隔离 QA 数据验证页面和服务端持久化，不创建假 ExtractionBatch、不伪造 Provider 候选，也不把该数据解释为真实 AI 结果；因此 DEV-S3-03 的 Provider 起点 E2E 仍为 `in_progress`。
3. 固定性能 profile 已按冻结机器和样本真实运行；它只证明本地 storyboards 查询与命令，不替代 S4 Seedream/Seedance 的供应商延迟、额度、价格或账单证据。
4. 默认 `make check` 中 6 项基础设施契约和固定性能 profile 为显式 skip；性能 profile 已在本轮单独通过。当前本机 9000 端口无可用 MinIO，且没有安装 `minio`/`mc` 命令，本轮未重装、未启动第二实例，也未把 MinIO contract 记为通过。
5. 最新资产升级和变换对话框尚缺同一浏览器的最终视觉复查；自动化交互、类型检查和 production 构建已通过，但在浏览器 URL 安全策略解除前保持该视觉残余风险。
