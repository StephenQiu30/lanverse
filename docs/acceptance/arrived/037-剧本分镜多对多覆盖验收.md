## 1. 验收结论

当前正式链路为：

`published ScriptVersion → NarrativeUnitVersion ↔ ShotSpecVersion → CoverageReport → Shot readiness / ProductionSnapshot`

剧本段落与镜头不再被误建模为严格 1:1。一个叙事单元可由主镜头和反应/插入镜头共同表达，一个镜头也可覆盖多个动作或对白；稳定关系边固定不可变 UnitVersion 与 SpecVersion，而不是镜号、显示名或文本相似度。只有 required 单元全部 covered/approved omitted，且 orphan、stale 均为 0 时才可进入生产预检。依赖不可读时返回 unavailable，不降级为 ready。

## 2. 研究与准入决定

实现前固定 commit 审阅了三类一手方案：

- StrictDoc 的有类型双向 many-to-many set 证明关系应有独立身份、正反向查询和重复拒绝；采用这些不变量，不引入其文档运行时。
- Label Studio 的 RelationStore 证明人工关系需要双端定位、标签、删除和即时去重；采用双向高亮和显式编辑，不把可变客户端状态当事实源。
- drama-skills 的 coverage ledger、镜头 identity 与守恒校验器直接呈现短剧遗漏/拆合风险；采用 covered/unresolved 全集、稳定镜头身份和守恒失败分类，但其项目较新，只作领域证据。
- Doorstop 的 stamp/suspect/clear 证明过期关系应显式确认；沿用 dependency hash 与 stale 决议，不引入 LGPL 依赖。

没有复制第三方代码，也没有新增第二套 Episode、Scene、Shot、Task 或可变 Coverage 表。固定 commit、许可证、源码与失败测试链接记录在 PLAN-012 第 6.9 节。

## 3. 领域事实与失败边界

| 能力 | 已实现事实 | 失败行为 |
| --- | --- | --- |
| 不可变关系 | `ShotNarrativeReference` 固定 Workspace/Episode/Shot/Spec 与 NarrativeUnit/UnitVersion，保存 channel、role、full/partial segment、contribution、origin | 跨作用域、非 current Unit、越界 segment、镜内重复边和跨镜重复 primary 均 fail closed |
| 覆盖决议 | `CoverageDecision` 只追加，批准/撤销省略或原创镜头，固定 basis hash、reason、evidence、actor 和幂等键 | evaluation hash 冲突返回 409；底层 Unit/Spec/Reference 变化令旧决议 stale |
| 派生报告 | 批量读取 current Units、active Shots/current Specs、References 与 Decisions，派生 unit/shot 双向投影和 summary | 依赖异常返回 unavailable；不存在可被并发覆盖的 current report 行 |
| 生产门禁 | readiness 和 ProductionSnapshot 固定 narrative dependency、coverage basis/evaluation hash | uncovered、orphan、stale 或 unavailable 都形成稳定 blocker |
| 人工映射 | 分镜页显示覆盖总览、文本↔镜头定位、完整关系编辑、省略/原创批准与撤销 | 修改使用 expected shot/spec/evaluation CAS；旧边不 UPDATE/DELETE |
| 拆合守恒 | split 要求每条关系显式且唯一分配；merge 取精确并集并拒绝重复关系；copy 降为 supporting | 不静默截断、丢失或复制 required coverage；冲突先由用户修正映射 |

## 4. 根因修复而非兼容补丁

浏览器闭环依次暴露了三条会让关系断链的真实写路径，均从命令与事务根部修复：

1. 手工新建 Spec 的请求现在必须提交完整 `narrative_references`，字段没有默认值；缺失直接 422。Spec、资产引用与叙事引用在同一事务写入，不根据旧 Spec 暗中复制。
2. 资产版本升级是明确的“克隆当前 Spec 并替换资产版本”命令，因此同一事务把来源 Spec 的不可变叙事关系以 `migrated` origin 克隆到新 Spec；旧关系继续保留。
3. 人工接受或修改 AI DraftTarget 后，Apply 才把其固定 UnitVersion 建成正式关系。unit kind 确定 required channel；现有 current primary 与本批新关系共同判定第一个 `primary/required`，重复镜头为 `supporting/supporting`，避免跨批次双 primary。

没有增加旧字段别名、空默认、双写、文本匹配或运行时 shim。未经过人工 DraftDecision 的 AI 建议、历史无来源镜头和用户清空映射的镜头仍明确 blocked。

## 5. 语义短命名与 Plain Data Contract

[DES-000](../../design/000-项目顶层结构与工程规范.md) 是本项目唯一工程规范事实源，已固定以下要求：

- Python/TypeScript 的 POJO 等价物是 Plain Data Contract：只含字段、类型、序列化和无 I/O 校验；事务、ORM、Session、HTTP/SDK client、cache 和 queue 不得进入数据对象。
- 跨模块 Command/Snapshot/Result 默认不可变；HTTP 边界使用 Pydantic，前端边界只使用 OpenAPI 生成类型，不维护平行 DTO 或兼容字典。
- 文件和标识符使用当前目录下最短的业务语义；可执行源码/测试文件名含扩展名最多 64 个 ASCII 字符，不使用拼音、中文源码名或 `misc/common/helpers/manager/processor/data`。
- 内部重命名一次性修改唯一实现、引用和测试，不保留旧路径 alias、重复导出或双路径探测。

本轮新增 `coverage/rules.py`、`narrative-reference.ts`、`storyboard-coverage.tsx` 等短职责名。`test_module_boundaries.py` 新增自动门禁，覆盖后端源码、Alembic、前端源码及测试文件；现有 Plain Data Contract 的跨模块依赖、不可变 dataclass 和禁 I/O 方法检查继续生效。
