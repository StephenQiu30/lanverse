## 1. 交付结果

1. FastAPI + Argon2 + 30 分钟短期 JWT 完成本地注册、登录、注销、改密和账户停用；注册原子建立 UserAccount、个人 Workspace 与 owner Membership，token_version 使旧令牌立即失效。
2. Workspace 支持列表、创建、改名、归档和恢复；owner/editor/viewer 能力由服务端判断，跨空间资源统一不可探测，归档空间允许历史读取但拒绝已有 Project/Episode 的继续写入。
3. Project/Episode 支持创建、读取、修改、预算专用命令、完整 active 集合重排、归档/恢复、删除预检和空草稿删除；revision 冲突不会覆盖现有事实。
4. ProductionSnapshot 由服务端计算空态阶段、阻塞原因和下一动作；页面刷新后从服务端恢复 Project/Episode，前端不复制生产阶段状态机。
5. Next.js 页面直接位于 `src/app/projects`、`src/app/workspaces`，页面专属生命周期组件与动态路由同目录；移除了无独立 layout/访问边界价值的 `(main)` Route Group，并收敛为 `api-request.ts`、`server-state.ts`、`redux-store.ts`、`class-names.ts` 等语义命名。
6. 2026-08-03 后续治理增量已把 Project 的创建、修改、预算、归档/恢复、删除，以及 Episode 的创建、修改、完整排序、归档/恢复、删除接入事务内 AuditEvent。治理页只展示稳定 ID、revision、状态、位置、数量和变更字段名，不复制项目/单集名称、简介或预算金额；完整 S1 浏览器生命周期可按删除动作筛选事实。
7. 2026-08-03 S2 下游增量已把真实 Task 引用接入安全删除：Episode 预检返回 `HAS_TASKS`，DELETE 锁内重检并返回 `review_delete_blockers`；Project 预检同时汇总 `HAS_EPISODES` 和 `HAS_TASKS`。projects 只消费 production 公开批量计数，不跨模块读取 Task ORM。
8. 2026-08-03 S2 剧本增量继续补齐“有版本不可删”：scripts 公开批量统计 active/archived 来源下的所有 draft/published ScriptVersion；Episode 预检返回 `HAS_SCRIPT_VERSIONS`，DELETE 在 Episode 锁内复检；Project 同时汇总剧本版本数量。projects 通过 API 组合层注入自有读取 Protocol，不跨模块读取剧本 ORM。
9. 2026-08-03 S3 分镜增量把 active/archived Shot 及全部 ShotSpecVersion 接入持续删除约束：Episode/Project 预检以 `HAS_STORYBOARD_SHOTS` 同时返回镜头和规格版本数，DELETE 在 Episode 锁内重新查询；projects 只消费 storyboards 公开批量摘要，不跨模块读取分镜 ORM。
10. 2026-08-03 S2/S3 资产增量把 active/archived Asset 及全部 AssetVersion 接入 Project 持续删除约束：预检以 `HAS_ASSETS` 返回资产身份/版本数，DELETE 在 Project 锁内复检；assets 与 projects 通过公开摘要与 projects 自有 Protocol 交接，并发首次建资产/删项目不产生孤立事实。
11. 2026-08-11 注册安全增量把公开注册改为“发送 6 位邮箱验证码 → 确认并取得一次性票据 → 原子创建账号与个人空间”三步。验证码摘要、冷却、错误次数和票据由 Redis 原子管理，SMTP 只承担有限时发送；未经确认、过期或重复消费均不能创建账号，SMTP/Redis 故障不会阻断现有账号登录。

## 4. 接受边界与残余风险

1. PT-PRJ-004/005 只接受 S1 空版本入口和空态 Snapshot 增量；ScriptVersion、TimelineVersion、模块摘要、partial failure 和最终 N+1 证据必须随 S2～S5 接入，当前不能标记 accepted。
2. PT-DAT-003 只完成首批 identity/projects 复合租户引用与数据库拒绝证据；它是持续任务，S6 才最终接受。
3. PT-GOV-006 已在后续增量覆盖本轮身份、空间、项目和单集真实业务命令；这不提前接受仍未落地的 Review/Moderation/Label/Delivery 动作，JSON 运行日志也继续不能替代 AuditEvent。
4. 账户重新启用采用明确的运营恢复流程，MVP 不提供公开自助恢复、邮件找回、refresh token、MFA、第三方登录、设备会话和成员管理；停用页面已明确提示该边界。
5. 删除预检已判断当前存在的 Episode、current 版本入口、active/archived 来源下的全部剧本版本与 S2 Task 引用；未来 TimelineVersion、Cost、Review、Delivery 等引用模块进入实现时，必须先把对应 blocker 接入预检，再允许其切片接受。
6. 默认 `make check` 不隐式启动 MinIO；该契约已在 S0 使用真实 MinIO 单独通过，本轮没有媒体用例，不能把本次 skip 解释为新的存储验收。
7. D-003 已按“不预设 AI 供应商或配置”关闭，S2 可开始 Task、剧本和私有媒体工程；D-005 合规决定仍未关闭，因此治理、ready 资产和整个 S2 不能 accepted，真实生成与公开交付必须 fail-closed。当前边界以 [PRD-003](../../prd/003-MVP执行计划与追踪矩阵.md) 为准。
8. 邮箱验证码注册的代码与自动化闭环已经完成，但真实投递仍等待用户明确授权一个测试收件邮箱；当前只验证了 SMTP TLS、鉴权和 NOOP，不能把它表述为收件箱投递成功。
9. HotKey SMTP 参数当前只映射到本地运行进程，没有复制或提交到 Lanverse 配置文件；服务重启或部署时必须通过本地密钥环境重新注入，并为 Lanverse 配置独立的 `EMAIL_VERIFICATION_HMAC_SECRET`。
