## 1. 验收结论

本次把原来的 `Asset → AssetVersion` 根模型直接切换为：

`Asset identity → AssetState → immutable AssetVersion → ShotSpecVersion reference`

`AssetState` 不等于一张图片或一个别名。它是角色常服/受伤、场景日/夜、道具完好/破损等剧情状态的稳定身份；每个状态独立持有 current version。`AssetOccurrence` 以只追加 link/unlink 决议固定 `NarrativeUnitVersion`，读取时再派生 current/stale；依赖无法判定时由状态 readiness 显式返回 unavailable。分镜固定 `asset_id + asset_state_id + asset_version_id + binding_source`，禁止跨资产或跨状态拼接。

旧的 Asset 级 current 字段与 API 已删除，`AssetVersion.source_type=candidate` 已直接改为 `script_extraction_candidate`。代码、迁移、OpenAPI、前端和测试只保留新事实，不存在双写、旧路径探测、类型别名或兼容 DTO。

## 2. 上游证据与本地决定

实现前已核对 10 个固定 GitHub 候选的许可证、核心源码和失败测试，完整证据表见 [PLAN-012 第 6.6 节](../../plan/012-AI短剧MVP核心制作执行计划.md)。结论如下：

- ai-fusion-video、Jellyfish、wind-comic 证明短剧/漫画工作流需要资产变体、显式镜头引用和变更影响可见，但它们的可变子资产、名称/镜号匹配不能直接承担稳定血缘；
- OpenAssetIO、Kitsu/Zou、OpenPype、AYON、xStudio 共同证明稳定身份、版本、物理表示、where-used 和合法主选应分层；其中 AGPL/FSL/LGPL 或宿主运行时均不进入 Lanverse；
- 没有候选能直接替换现有 Asset/Media/Consent/Shot 事实，因此未增加第三方运行依赖，也未复制受限许可证代码；只把已证明的不变量落到当前 UUID、不可变版本、复合 FK、CAS 和 readiness 体系。

## 3. 实现事实

| 能力 | 已实现事实 | 关键失败路径 |
| --- | --- | --- |
| 状态身份 | 创建 Asset 时同事务建立 `base` 状态；可显式创建语义状态键；`asset_id + state_key` 唯一 | 重复 key、stale asset revision、归档资产、幂等键异载荷均拒绝 |
| 状态版本 | Version 继续按整个 Asset 递增以避免迁移时出现重复 v1；每个 state 独立维护版本集合和 current，append/set-current 使用 state revision 与 expected current CAS | 跨 Asset/State Version、并发 current、重复命令异载荷拒绝 |
| 出现关系 | link/unlink 决议只追加，按 state sequence 排序，固定 NarrativeUnitVersion | 跨项目/集/Workspace、非 current unit、重复异载荷拒绝；结构修正后旧决议转 stale |
| 资产圣经 | `GET /projects/{id}/asset-bible` 输出身份→状态→当前版本/出现/readiness 矩阵 | 依赖读取失败时显式 unavailable，不由前端猜 ready |
| 分镜引用 | Shot Spec 固定 Asset、State、Version 和手工绑定来源；数据库复合 FK 与服务校验一致 | 跨状态 Version 无法写入；current 切换不改历史 Spec |
| 剧本候选交接 | accepted 资产候选只进入明确 Asset 的 base state，并返回 Asset/State/Version 结果 | AI 候选不自动合并正式状态，拒绝名称充当 FK |
| 前端治理 | 状态创建、状态切换、逐状态版本/current、资产圣经、分镜“资产 · 状态”选择 | 归档身份离开生产圣经但保留独立恢复/编辑/删除入口 |

公开写接口均使用 OpenAPI 生成契约、ActorContext、幂等键和适用的 expected revision/current；状态契约对象不持有 Session、ORM、HTTP client 或 I/O 方法。

## 5. Red、缺陷与根修复

Red 首先固定状态唯一性、复合版本归属、Occurrence 跨项目拒绝、current CAS/幂等、陈旧叙事版本和 state-aware 分镜引用。Green 后浏览器真实链路又发现：归档资产被生产资产圣经排除后，原页面同时丢失恢复入口。最终设计把“生产圣经”和“身份生命周期”拆开：归档身份卡不进入 readiness/新镜头绑定，但始终提供恢复、编辑和删除治理。

另一处 E2E 暴露旧 UI 仍查找 `asset.current_changed`。实现没有保留旧审计动作，而是把唯一语义收敛到 `asset.state_current_changed`，并同步审计标签、筛选与测试。
