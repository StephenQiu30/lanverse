## 1. 验收结论

1. `POST /api/v1/tasks/{task_id}/cancel` 只允许具备 `generation:submit` 权限的 owner/editor 操作所在 Workspace 的 `image_generation|video_generation` queued Task。请求使用 `workspace_id`、`expected_revision`、幂等键和三个受控原因，不接受自由文本。
2. 服务端在一个 PostgreSQL 事务内锁定 Task 和 Reservation，然后同时将 Task 转为 `cancelled/cancelled_before_dispatch/accepted`、Reservation 转为 `released`、追加等于原预占的 `release` CostEntry 并记录 `task.cancelled` 审计；审计注入失败时四类变更全部回滚。
3. `Reservation.reserved_amount` 保留初始经批准额，当前余额从追加账本计算。验收样本的 CNY 1.250000 在取消后形成 reserve 1.250000 + release 1.250000，`remaining_reserved=0.000000`，不修改历史 reserve 条目。
4. 已取消 Task 即使使用不同命令幂等键再次请求，也回读同一 Task、Reservation 和 release CostEntry，总 CostEntry 始终为两条。原始命令幂等键不进入账本或审计；账本只保存 SHA-256 摘要组成的内部键。
5. 陈旧 revision 返回 `version_conflict/reload_task`；Worker 已把 Task 推进到 running 时返回 `state_conflict/wait_for_provider_cancellation_support`，Reservation 仍 active 且只有原 reserve 账本。其他 Workspace 不能利用 Task ID 取消或读取事实。
6. Next.js 任务中心只对服务端事实为 queued/none 的生成 Task 显示“取消任务”，使用现有 Dialog/Button 组件要求二次确认。交互副作直接由点击处理器触发，不通过 effect 模拟事件；成功后 RTK Query 同时失效 Tasks、Costs 和 AuditEvents。
