## 1. 结论

MVP-A 的工程链路已经闭合：

`整剧 Document → 分集计划/物化 → ScriptVersion → NarrativeUnitVersion ↔ ShotSpecVersion → Coverage/readiness → 固定 ExportSnapshot → 确定性 ZIP → 私有 MediaVersion/Lineage → 受控下载`

导出不在 Worker 运行时读取会漂移的 current。提交事务先固定 Script、Narrative、Asset、Shot、Coverage 和 readiness 的 ID/hash；Worker 只读取这个不可变快照。对象字节通过 size、content type 和 SHA-256 验证后，数据库事务才登记 Manifest、MediaVersion、Location、Lineage，并把 Job/Task 标记成功。

工程能力和恢复门禁均已通过。计划明确要求产品负责人对黄金短剧的节奏、情节和分镜主观质量签字；本验收不代替人类作该决定，因此 MVP-A 只能标记为 `review_ready`，不能伪报最终产品 accepted。

## 2. 上游研究与采用决定

编码前已在 PLAN-012 第 6.10 节固定 commit、许可证、源码和测试：

- LocalMiniDrama：采用每镜一行、HTML 转义、CSV 引号和 UTF-8 BOM；拒绝缺件仍成功和浏览器读取 current。
- wind-comic：采用纯预检与结构化 blocker；拒绝永久 URL 和部分成功包。
- dramai：采用 schema label、版本和机器/人类双表示；拒绝从当前 IndexedDB 临时聚合。
- BagIt Python：采用逐文件 SHA-256/size 与缺件 fail closed；不引入完整 BagIt 依赖。
- OpenTimelineIO：采用稳定序列化和明确版本拒绝；不引入 MVP-A 非目标的 Timeline/Track/Clip。
- AYON Core：采用“对象字节先写入并验证，再发布 representation”；不把对象存储和数据库误称为跨系统原子事务。

本轮未复制第三方代码，也未增加第二套 Task、Media、Episode、Shot、Candidate 或时间线运行时。

## 3. 实现事实

| 能力 | 已实现事实 | 失败语义 |
| --- | --- | --- |
| 导出预检 | 批量计算 Coverage/readiness，返回固定版本 ID/hash 和结构化 blocker | uncovered、orphan、stale、blocked 或 unavailable 均不可提交 |
| 提交与幂等 | Episode 行锁内重新计算 input hash；同键同输入回读同 Job | 旧 preflight 返回 409 且不写历史；同键异输入冲突 |
| 固定快照 | `ExportSnapshot` 固定 Script、Unit、AssetState/Version、ShotSpec、关系和评估 hash | Worker 重启或 current 变化不会重新决定输入 |
| 确定性包 | 标准库生成固定时间戳、排序和权限的 ZIP；包含 Manifest、JSON、CSV、HTML | 快照与 input hash 不一致直接失败；HTML/CSV 特殊字符安全编码 |
| 发布时序 | 确定对象键 `exports/{workspace}/{job}.zip`；put 后执行 stat + stream SHA-256 | 对象暂不可用触发消息重排；完整性不匹配终止且不登记 Manifest |
| 媒体治理 | 复用私有 MediaObject/Version/Location，新增不可变 MediaLineage | API 不返回 object key 或永久 URL；下载按工作空间授权签发临时 URL |
| 历史 | 一个 Job 对应一个不可变 Manifest 和 delivery MediaVersion | 后续 current 或剧本变化不修改历史包；重复消息不重复登记 |
| 工作台 | 分镜页提供预检、阻断、异步任务、历史、包大小和受控下载 | 未 ready 时禁用生成；失败保留稳定 error code |

## 4. 数据与契约

## 5. 语义短命名与 Plain Data Contract

[DES-000](../../design/000-项目顶层结构与工程规范.md) 仍是唯一工程规范事实源：

- `exports/{api,contracts,consumer,models,package,repository,schemas,service}.py` 使用目录内最短且明确的业务角色名；新测试名均为 ASCII 语义名且不超过 64 字符。
- `ExportSnapshot` 及成员是拒绝未知字段、冻结的 Pydantic 数据契约；`RenderedMediaCommand/Source/Result` 使用 `dataclass(frozen=True, slots=True)`。
- 镜头规格复用唯一 `ShotSpec` 类型，不保留任意 `dict[str, Any]` DTO、旧名称别名、重复 schema 或双路径兼容层。
- 数据对象不持有 ORM、Session、FastAPI Request、存储端口、queue、logger 或 I/O 方法；事务与外部调用留在 service/consumer。
- 跨模块存储能力只通过 Media 公开边界暴露，不从 Storyboards 导入 Media 内部 repository/model/service。

架构测试已自动检查短文件名、ASCII、禁用空泛词、跨模块依赖、Plain Data Contract 不可变性和禁 I/O 方法。

## 6. 联合 E2E 与恢复证据

`test_script_to_export_journey.py` 使用真实 PostgreSQL、HTTP use case 和 Worker：

1. 导入仓库原创 5 集黄金文本，确定性生成 5 集计划并原子物化、发布；
2. 第一集建立已确认来源和 ready 资产状态；
3. 写入合成 AI 草案，逐镜人工接受 12 个草案后单事务 Apply；
4. Coverage/readiness 全部 ready，第一次生成可信分镜包；
5. 第二次提交后切换同一 AssetState 的 current；
6. 注入一次对象 `stat` 暂不可用，第一次投递回队列且数据库无半成功；
7. 用新消息对象模拟 Worker 重启，重放相同任务后成功；
8. 两次不同 Job 的 ZIP 字节完全一致，第二个对象键两次 put 的字节一致；重复消息只回读，最终恰好两个 Manifest 和两个 delivery MediaVersion。

这里的剧本和 AI 草案是获准入库的原创合成材料，不冒充本轮真实模型调用；分集、改写和分镜的真实 DeepSeek 合同已经分别由 Acceptance 030、031、036 显式执行并接受。

## 8. 权限与信息安全

- 跨空间用户访问导出 MediaVersion 返回 404；owner 只能通过短期预签名 URL 下载，匿名直接访问真实 MinIO 对象被拒绝。
- Outbox 只携带 `task_id`；Task、API 历史和审计不返回剧本正文、完整 Prompt、object key、预签名 URL 或凭据。
- Manifest 数据库事实需要保存固定内容快照以实现可追溯交付，但它不进入消息、日志或公开历史响应；下载仍经过 Media 权限检查。
- 仓库未提交对象字节、数据库数据、运行日志、真实剧本或密钥。

## 10. 未决风险与产品决定

已知边界：

- 联合 E2E 按退出条件验证黄金剧至少一集；没有把 5 集全部导出当作已验证事实。
- 对象暂不可用恢复使用可控故障端口，真实 MinIO 验证成功/权限/下载；未在真实 MinIO 进程崩溃时做网络级故障注入。
- 本轮没有再次付费调用 DeepSeek；沿用 030/031/036 的真实 Provider 接受证据，合成候选只用于确定性联合回归。
- 性能样本是本机 36/120 镜基线，不是多租户生产负载、SLA、RPO/RTO 或容量承诺。
- MVP-A 不包含图片/视频生成、TTS、时间线、成片 MP4、商业计费、协作审批或公开发行。

需要产品负责人确认：是否接受当前黄金样本在节奏、情节、角色状态和分镜表达上的主观质量。建议决定为 `accepted`，因为工程 oracle、覆盖、12–24 镜门禁、真实 Provider 单条合同和联合分镜包均已通过；若不接受，应提供具体集/叙事单元/镜头及修改目标，不能用无边界的“质量不好”推翻已通过的工程事实。
