## 1. 验收结论

1. 项目页已经提供整剧导入入口。创作者可以直接粘贴文本，或沿用既有私有对象存储上传链提交严格 UTF-8、无 BOM 的 `.txt/.md`；两种输入互斥，都要求权利声明和幂等键。
2. 服务端只在 `scripts` 模块内新增 `ScriptDocument → DocumentRevision → NarrativeBlock/FormatIssue`。原始文本、identity-v1 规范化文本、内容哈希、来源媒体版本、Unicode code-point 数和分析器版本均固定到不可变修订；没有建立第二套 Episode、Task、Blob 或异常体系。
3. 规则分析只把独占一行的 `第N集/话/章`、`EP N`、`EPISODE N` 当成集标记，支持中文、全角和阿拉伯数字。正文中的“第一集结束”、标题同行、空白行、CRLF、扩展汉字和 Emoji 不丢失；块区间首尾连续，按原文切片重建后的文本与 SHA-256 必须完全一致。
4. 缺号、重复、逆序、空集、前言待决、超过 10 集、无标记和 BOM 都形成有稳定 code、行列、half-open code-point 区间和 next action 的问题。粘贴文本中的 BOM 保存为可解释的 rejected 修订；文件 BOM 在媒体探测阶段直接拒绝。
5. 项目级幂等约束保证同键同输入回读，同键异输入返回冲突；项目与媒体版本使用复合 Workspace 外键，跨空间、非 document、非 ready 或缺少 active location 都 fail closed。审计事件只写计数、状态和标识，不写正文或正文哈希。
6. 浏览器真实闭环已完成“创建项目 → 选择仓库内五集 `.txt` → 私有对象存储直传 → Media Worker UTF-8 探测 → 固定 MediaVersion → 保存不可变修订 → 显示 5 个集标记 → 刷新回读”。该阶段明确写入 **0 个 Episode**，下一步只能进入 EpisodePlan 人工确认。
7. 用户提供的私有参考 DOCX 只做了只读结构检查：确认其存在连续集标记、场标题、动作/对白交替和集尾钩子。原文件、文件名、本地路径和正文均未复制到 Git；仓库只保存原创合成的《雾港倒计时》材料。

| 交付面 | 当前事实 |

## 5. 保留边界与下一步

- 本次只接受 PT-SCR-006，不接受 PT-SCR-007。没有 EpisodePlan、边界编辑、预计时长、理由、置信度、confirm 或批量 Episode 物化。
- 无显式集标记时只返回 `ai_candidate_required`；没有调用 DeepSeek，也没有用 mock 冒充 AI 分集成功。
- P0 normalizer 是 `identity-v1`，原文与 normalized 文本一致；尚未实现复杂编码纠正、格式改写或 raw/normalized 非恒等坐标映射。
- 每次导入目前建立一个新 Document 和初始 revision；尚未提供同一 Document 的修订追加、diff、回滚或 current 指针，这些不能从不可变表结构外推。
- 只接受 UTF-8 `.txt/.md`，不支持 DOCX、PDF、Fountain、FDX、OCR 或富文本。需要此类输入时必须独立评估解析安全、版权、坐标映射和依赖体量。
- 同步规则扫描的当前上限是 100,000 code points、10 个显式集标记；更大文本或更多集数必须先重新评估分页、异步任务、性能与产品上限。

在这些边界内，PT-SCR-006 和 DEV-MVPA-03 接受。下一任务是 DEV-MVPA-04：固定 EpisodePlan、人工边界编辑和一次事务批量物化，继续保证确认前 Episode 为 0。
