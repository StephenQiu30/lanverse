## 1. 交付结果

1. 资产身份支持角色、场景、道具、服装、视觉风格和声音六类受区分且类型化的规格；未知字段、跨类型字段和非法引用在进入 JSONB 前被拒绝。
2. AssetVersion 只追加不改写，current 指针使用 expected revision 比较交换；并发切换只有一个请求成功，历史版本及固定媒体引用保持不变。
3. Readiness 在读取时组合类型化字段、MediaVersion 探测状态和 RightsGate 结果；缺字段、媒体未就绪、授权撤回或治理依赖不可用均返回结构化 blocker 和 next action，不持久化会过期的派生布尔值。
4. 剧本确认后的资产候选可创建新身份或幂等关联既有资产；候选决定保留来源和固定关联，不把抽取结果直接升级为可生产资产。
5. Next.js 资产工作台通过生成的 OpenAPI client 读取真实项目、资产、版本、媒资与准备度，支持六类筛选、搜索、创建与编辑身份、追加版本、显式切换历史 current、归档/恢复、删除预检、安全删除与治理跳转；服务端状态由 RTK Query 缓存并在身份、版本或授权变化后使关联事实失效重取。
6. 本地验收使用当前项目唯一 MinIO 服务，不启动第二实例；共享 Compose 的镜像与环境分层已由 D-006 固定为 `latest` 和生产薄覆盖层，当前部署事实以 [ACC-008](./008-D006全栈Compose部署验收.md) 为准。
7. 空 Asset 的删除预检同时覆盖 AssetVersion 与 CandidateDecision。即使资产没有版本，只要曾由剧本候选 `link_existing` 关联，预检就返回 `asset_has_candidate_decisions` 与 `decision_count`，DELETE 在 Asset 锁内复查并拒绝；候选关联和删除并发不会产生悬空决议。真实页面显示“资产已被 1 条剧本候选决议关联，只能归档。”。
8. Character Asset 还会检查全部 Prop/Costume 历史版本的 holder/wearer UUID；自身无版本但被道具/服装版本引用时返回 `asset_has_related_versions` 与 `related_version_count`。全部 Asset 写命令采用 Project → Asset 锁顺序并刷新锁定重读，追加关联版本与删除并发连续 3 轮没有悬空 UUID，也未破坏 append/current CAS 单 winner。

3. 浏览器验收使用实际签名 PUT 写入独立 `lanverse-e2e` bucket，并启动 RabbitMQ、Media Worker、MinIO、ffprobe 和 PostgreSQL 的真实链路；测试生成的普通 PCM WAV 只作为媒体夹具，不代表 AI Speech/Audio 能力。
4. current ScriptVersion、聚合 Snapshot、提取决议入口和资产工作台已由 DEV-S2-06 组合；当前缺口只是真实 DeepSeek Provider 的提取→决议→确认→设为 current 联合证据，不得用未配置服务的失败状态代替。
5. 默认 `make check` 不隐式启动外部服务；其中 6 项基础设施契约与 1 项固定性能 profile 的 skip 不能解释为通过。2026-08-02 已显式重跑 MinIO、RabbitMQ、ffprobe、媒体联合栈和分镜性能门禁并全部通过；DeepSeek 仍是唯一未运行的外部 Provider 门禁。
