## 1. 验收结论

1. 能力目录固定公开 Seedream `doubao-seedream-5-0-lite-260128` 和 Seedance `doubao-seedance-2-0-260128` 的稳定身份；D-004 前两者均为 `provider_contract_unverified`、无价格且禁止任意参数。`ARK_API_KEY` 是否为空都不会激活未经真实账号验证的契约。
2. 能力参数只接受受控的顶层 object 子集；根字段、参数字段、类型、枚举、范围、有限数值及固定 `per_request` Decimal 价格均 fail closed。可选参数的非法 schema 同样在预检前被拒绝。
3. 预检显式校验 Workspace 归属并读取真实 current ShotSpec、readiness、Capability 配置、Project 币种/预算与当前预占；结果使用服务端 HMAC-SHA256 绑定规范化事实及过期时间，且不写 GenerationRequest、Task、Reservation、CostEntry 或 Outbox。
4. 提交按 Project/Episode/Shot/Spec/Capability 重新锁定与校验；高成本或 warning 未确认时零写入。同一 Workspace 幂等键同输入回读，异输入冲突；成功时 GenerationRequest、queued Task、Reservation、首条 reserve CostEntry 和 `generation.requested` Outbox 在一个 PostgreSQL 事务内形成，任一步失败全部回滚。
5. 费用使用 `Numeric(20, 6)` 与应用层 Decimal，查询由追加 CostEntry 计算服务端汇总。任务中心复用 OpenAPI 生成 client、RTK Query 和现有 Card/Badge/Alert 组件展示能力不可用原因及预占/已结算/剩余金额，不复制服务端状态到 Effect。
