## 1. 验收结论

资产改名、停用和剧情状态当前版本切换不再是即时覆盖操作。它们统一成为：

`读取稳定事实 → 生成影响摘要与 impact_hash → 人工确认 → 事务内锁定并重扫 → 原子 Apply`

资产身份生命周期与生产可用性已分开：`status=active|archived` 管理身份是否归档，`availability=enabled|disabled` 管理是否允许新的绑定和生成。禁用不会删除 AssetVersion、ShotSpecVersion、GenerationRequest、Task、媒体或审计证据；历史镜头仍固定原 AssetVersion。名称改为只追加修订，稳定 Asset ID、State、Version、Occurrence 和分镜外键均不改变。

## 2. 上游证据与本地决定

实现前按固定 commit 阅读了成熟项目的源码、测试和许可证：

- [ArcReel 改名扫描与 dry-run](https://github.com/ArcReel/ArcReel/blob/ed71819aadf81015c0af4b3f5db0815607e04fae/lib/asset_rename.py#L29-L96)及[冲突测试](https://github.com/ArcReel/ArcReel/blob/ed71819aadf81015c0af4b3f5db0815607e04fae/tests/lib/test_asset_rename.py#L435-L674)证明预览和执行应共用扫描、冲突时整体拒绝；但其名称即身份、文件路径级联和 AGPL-3.0 代码均未进入 Lanverse。
- [OpenAssetIO EntityReference](https://github.com/AcademySoftwareFoundation/OpenAssetIO/blob/3e60be1d083ea1fc56d53080544157198976043b/src/openassetio/EntityReference.hpp)和 manager API 的 preflight/register 分离证明稳定引用与发布前校验的必要性；它是 Apache-2.0 互操作 API，不是可直接安装的资产治理服务。
- [xStudio current source 测试](https://github.com/AcademySoftwareFoundation/xstudio/blob/d60b3e87fc52fb87b4d4e545e16dcd35471c567c/src/media/test/media_test.cpp#L14-L46)与 [OpenPype Version/Representation schema](https://github.com/ynput/OpenPype/blob/f67bacf11713cadb5c46c1580ff7ef97276cf0f9/openpype/pipeline/schema/representation-2.0.json#L1-L78)支持“稳定身份、不可变版本、物理表示、合法主选”分层；没有引入其 C++/DCC/Mongo 运行时。

没有候选同时满足当前 Python/SQLAlchemy 模块边界、稳定 ID、state-aware Shot 引用、事务内影响哈希和现有生成请求模型，因此本轮未复制第三方代码，也未新增运行依赖。成熟项目只用于固定行为不变量和失败测试。

## 3. 实现事实

| 能力 | 已实现事实 | 关键失败路径 |
| --- | --- | --- |
| 名称修订 | `AssetNameRevision` 只追加；Asset 指向当前 `name_revision`；旧名去重后成为 alias | 通用 PATCH 不能改名；空名/同名、stale revision、陈旧 impact hash 拒绝 |
| 资产可用性 | Asset disable 必须预检；enable 使用 expected revision；readiness 立即产生 `asset_disabled`，Shot 映射为 `ASSET_DISABLED` | 禁用后新增版本或新分镜绑定拒绝；历史版本、引用、请求和任务不删除 |
| 状态治理 | label/description 独立编辑；state_key 不可变；State disable/enable 与 Asset 生命周期分开 | stale revision、幂等键异载荷、禁用状态新增版本/切 current 拒绝 |
| 当前版本 | current-version preflight/apply；Apply 只切 State current，不升级既有 ShotSpec | 目标不属于本 State、expected current 不符、影响变化均 409 零写入 |
| 影响中心 | 批量返回 Episode、Shot、Spec、`prompt_snapshots` 和非终态 Task；hash 固定全部依赖 revision/status | Task 从 queued 变 running 等任一事实变化后旧 hash 失效 |
| 前端 | 元数据编辑、改名、停用、归档、状态编辑和切 current 分开；影响弹窗列出数量与分镜 | 无预检摘要时确认按钮不可用；停用不调用归档接口 |

MVP-A 尚没有 C5 的 PromptRevision，因此响应使用 `prompt_snapshots` 表示 GenerationRequest 已固定的输入事实，未虚构尚不存在的领域实体。跨模块只传不可变 dataclass Snapshot/Protocol；HTTP 类型来自 OpenAPI，未创建兼容 DTO 或任意字典桥接。

## 5. Red、缺陷与根修复

Red 首先固定改名影响、Task 竞态导致 hash 失效、禁用零历史删除、State 编辑/停用和当前版本切换不漂移旧 Shot。Green 期间发现并根修复：

1. Shot readiness 原先把停用资产压扁为 `ASSET_NOT_READY`，现提升为可操作的 `ASSET_DISABLED`；
2. 旧通用 PATCH 仍保留名称分支、旧 service 仍保留直接 set-current，现均删除，不保留兼容路径；
3. Candidate 创建按 State 单独 flush 会越过新 Asset 插入顺序，现同一 flush 建立 Asset/State，再追加 Version；
4. 影响查询最初跨模块导入 Episode ORM 和 production 内部文件，现移除跨模块 ORM；生产影响快照定义为 Plain Data Contract，并通过静态公开用例边界映射，根除初始化环；
5. 历史无 Alembic 数据库接管最初不知道 AssetChange 时代，现将完整 AssetState 时代识别、部分新 schema 拒绝和前滚加入正式 migration 状态机。
