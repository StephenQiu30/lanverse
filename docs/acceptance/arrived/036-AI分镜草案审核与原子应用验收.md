## 1. 验收结论

AI 分镜不再直接写入正式 Shot。当前真实链路为：

`固定输入 → 异步 Task/Outbox → Provider 结构化草案 → DraftBatch → 逐镜人工决议 → 整批批准 → preflight diff → 单事务 Apply → 正式 Shot/Spec/Reference`

Batch 固定当前 ScriptVersion、NarrativeUnitVersion、AssetState/AssetVersion 和既有正式镜头基线。Provider 只能写 DraftShot；人工接受或修改后才能进入 Apply。任何输入漂移、镜头顺序变化、Spec 变化、未完成决议或冲突都会在正式写入前失败，现有正式镜头保持不变。

## 2. 上游研究与准入决定

实现前按固定 commit 审阅了成熟方案：

- Label Studio 的 Prediction/Annotation 分层证明模型结果和人工事实应是不同实体；采用 DraftShot→Decision→Shot 血缘，不引入 Django 或标注 DSL。
- LangGraph 的 interrupt/checkpoint 证明人工中断必须可恢复且前置副作用幂等；现有 Task/Outbox/Worker 已覆盖该职责，因此不建立第二套工作流运行时。
- AYON 的 validate/integrate 分段证明正式发布前需要独立预检；采用 preflight→apply，但拒绝数据库与文件部分提交边界。
- Jellyfish 证明结构化生成后统一写入和已有镜头 fail closed 可行；补上其缺少的持久草案、人工决议与输入 CAS。
- LocalMiniDrama 把断线后的部分正式镜头当作成功，ai-fusion-video 提供整集清空入口；两者作为反例，不采用流式写正式事实、按镜号覆盖或删除重建。

本轮没有复制第三方代码，没有新增 LangGraph、通用 Candidate/GenerationRun 或第二套 Episode/Shot/Task。第三方证据、许可证、固定 commit 与源码链接完整记录在 PLAN-012 第 6.8 节。

## 3. Red、真实 Provider 与根因修复

Red 先固定以下失败：Provider 写正式 Shot、输入版本漂移、决议覆盖而非追加、未完成决议批准、order/spec 冲突、Apply 部分写入、重复 Apply、Worker 重启、unknown 和资产状态不可用。

首次真实 DeepSeek 试跑暴露完整嵌套 ShotSpec 输出过大，在 8192 token 上限前不能形成合法结果。第二次缩小字段后又暴露两个问题：模型重复场景单元，并把部分建议时长写成 3 秒。处理方式不是增加兼容解析器，而是从协议根部收敛：

- Provider 只返回局部整数位置和短字段，服务端再确定性展开为固定 UUID 与完整 DraftProviderResult；
- 场景只需引用同场景的输入单元，不要求每镜重复覆盖场景标题；
- Provider 给出相对时长建议，adapter 收敛到产品允许的 4–15 秒，领域层继续验证整集目标时长与镜头数；
- 服务端仍强制 required NarrativeUnit 全覆盖、对白归属、资产引用只能来自固定输入、单镜 4–15 秒、总时长 ±25%，以及 60–120 秒剧集为 12–24 镜。

修复后，真实 DeepSeek 对 92 秒黄金合成单集生成结果通过全部结构和覆盖契约。该测试必须显式设置运行开关，默认回归不伪造外部 Provider 成功。

## 4. 实现事实

| 能力 | 已实现事实 | 失败行为 |
| --- | --- | --- |
| 固定输入 | Batch 保存 Script、Unit、Asset、Prompt/模型/schema、目标时长和既有镜头 order/spec/revision 基线 | Unit/Asset/current/baseline 漂移返回稳定冲突，正式写入 0 |
| 异步生成 | 复用现有 Task、Outbox、Inbox 和 I/O Worker；事件为 `storyboard_draft.requested` | 无 Provider、失败、重复消息、处理中重放和 unknown 均显式收敛 |
| 草案治理 | DraftShot 与正式 Shot 分表；Decision 只追加，支持 accepted/modified/ignored | 未逐镜决定不能 approve；修改必须提交完整目标 |
| 发布预检 | 返回 kept/created/modified/archived；当前策略只追加，modified/archived 固定为 0 | order/spec/impact hash 或 expected revision 不一致时 409 |
| 原子 Apply | 一个 PostgreSQL 事务创建 accepted/modified 的 Shot、不可变 Spec、固定资产引用和来源血缘 | 任一草案失败则整批回滚；幂等重放只回读同一结果 |
| 前端工作台 | 在正式分镜上方独立显示 AI 草案；选择 ready 资产状态、逐镜编辑/忽略、批准、预检和 Apply | queued/running/failed/unknown/applied 状态明确，不把草案冒充正式镜头 |

正式 Shot 只增加唯一 `source_draft_shot_id`，并与旧 extraction `source_candidate_id` 做数据库互斥约束；不是为旧设计增加别名或双写兼容。

## 5. 语义命名与 Plain Data Contract

本任务遵循 DES-000 的 accepted 规范：

- 目录和文件采用短业务语义名：`storyboards/drafts/`、`models.py`、`service.py`、`repository.py`、`provider_schema.py`、`draft_consumer.py`；未把整条模块路径重复进文件名；
- 可执行源码、测试和 Alembic 文件名含扩展名不超过 64 个 ASCII 字符；检查发现的超限项仅是未跟踪的 Python 缓存文件；
- 跨模块输入使用 `StoryboardDraftInput/Unit/Asset` 等不可变 `dataclass(frozen=True, slots=True)`，只含字段、类型和无 I/O 语义；
- Provider 以 Protocol 暴露，Pydantic 只留在边界 schema；事务、数据库和外部调用不进入 Plain Data Contract；
- 未新增 `Data/Info/Object/Bean/DTO`、拼音、中文迁移文件名、`common/helpers/manager/processor` 或旧名称兼容层。

`test_directory_structure.py` 与 `test_module_boundaries.py` 继续作为硬门禁；本轮不是以运行时 shim 接受历史命名。
