## 1. 验收结论

现有拆镜/合镜不再依赖前端尽力拼装或后端“对白只是来源子集”的弱校验。后端现在是内容守恒最终事实源：

`固定来源 ShotSpecVersion → preflight 可表示性检查 → 人工构造目标 → apply 再校验完整目标 → 原子写入新 Shot/Spec/Transform`

split 必须把动作、对白 ID、对白属性和动作关联按来源顺序精确分成两个目标；merge 必须把两个同场镜头完整拼接，并在确定性重编号动作 key 后保持对白关联。任何缺失、重复、乱序、跨场或超过当前 schema 容量的请求都在写入前拒绝。

## 2. 上游证据与准入决定

实现前按固定 commit 阅读了领域项目和成熟剪辑工程的源码、测试与许可证：

- [Olive 的区间拆分与依赖移动](https://github.com/olive-editor/olive/blob/7e0e94abf6610026aebb9ddce8564c39522fac6e/app/timeline/timelineundosplit.cpp#L32-L95)证明切点必须位于有效内部区间、左右范围精确覆盖来源；多块 link 重建与 undo 说明依赖更新必须处于同一命令。其 GPL-3.0 C++ 代码未进入 Lanverse。
- [Pitivi 的 action-log/timeline commit](https://github.com/pitivi/pitivi/blob/a4b19eb9114e1d2eda8180fab4cf2eda45b6eed8/pitivi/timeline/timeline.py#L2379-L2417)与[连续 split 的 undo/redo 测试](https://github.com/pitivi/pitivi/blob/a4b19eb9114e1d2eda8180fab4cf2eda45b6eed8/tests/test_undo_timeline.py#L449-L473)证明无有效切点应零写入、批量变换应作为单一事务。其 GES/GTK/LGPL 运行时未引入。
- [OpenTimelineIO 的 Timeline/Track/Clip/MediaReference](https://github.com/AcademySoftwareFoundation/OpenTimelineIO/blob/bc5fe2d78dc3f8b2a8feb7e04483d85a12e80072/docs/tutorials/otio-timeline-structure.md)和 [xStudio 的 UUID/children/range](https://github.com/AcademySoftwareFoundation/xstudio/blob/d60b3e87fc52fb87b4d4e545e16dcd35471c567c/include/xstudio/timeline/item.hpp#L47-L148)支持身份、顺序和时间范围分离；它们不提供剧本修订到镜头的覆盖关系，因此只采用概念，不新增时间线依赖。
- ai-fusion-video、Jellyfish、LocalMiniDrama 的源码证明主流 AI 短剧实现最多关联 episode/script/scene，且存在整集删除重建或摘录引用；它们没有可直接复用的 revision/unit/coverage 守恒内核。本任务保留 Lanverse 现有稳定 Shot、不可变 Spec、order CAS 与 Transform，只补真实缺口。

本轮没有复制第三方代码，没有新增运行依赖，也没有建立第二套 Shot、Episode、DTO 或异常体系。

## 3. Red 与根因

Red 先固定五类既有失败：

1. split 把全部对白留给第一镜、第二镜为空；
2. split 动作在两侧重复，而非精确分区；
3. merge 对动作 `.slice(0, 8)` 静默截断；
4. 跨 Scene merge 只保留用户选择的基础侧；
5. 后端只验证 dialogue subset，不验证两侧并集等于来源。

初始后端因 `storyboards.conservation` 尚不存在而在 collection 阶段失败；前端定向契约为 4 failed / 2 passed。实现后这些测试全部转绿。

浏览器复核又发现一个独立根因：集成测试通过 `Base.metadata.drop_all()` 删除业务表，却把不属于 Metadata 的 `alembic_version` 留在共用 `_test` 数据库。随后 E2E 初始化看到 head revision 而不执行迁移，Scheduler 才因 `sys_schedules` 缺失崩溃。修复不是增加中文表名、旧路径或缺表兼容：

- 测试夹具只在已验证 `_test` 数据库中清除全部表，schema 与迁移标记不再分离；
- `upgrade_database(..., revision="head")` 完成后强制比较真实 schema 与已注册 Metadata；
- 新测试先构造“删除 `sys_schedules`、保留 head marker”，确认旧实现未报错，再验证新实现 fail closed。

## 4. 实现事实

| 能力 | 已实现事实 | 拒绝条件 |
| --- | --- | --- |
| split 守恒 | 两目标保持同一 ScriptVersion/Scene；duration 和精确等于来源；动作 `(beat_key, description)`、对白 ID 和完整对白属性按序精确分区 | 动作/对白遗漏、重复、乱序、属性或关联变化均 422，零目标写入 |
| merge 可表示性 | preflight 先检查同剧本、同场次、总时长、动作/对白容量和重复对白身份 | 跨场、超过 15 秒、超过 8 动作/对白或重复对白直接拒绝 |
| merge 目标 | 动作描述与对白按来源镜头顺序拼接；动作 key 可确定性重编号；对白 beat link 同步映射 | 目标缺内容、乱序、改属性或错误关联均 422 |
| 原子性 | preflight 和 apply 共用同一领域 validator；既有 order hash、impact hash、幂等和事务边界保留 | stale order/impact/spec、下游依赖变化时零写入 |
| 前端 split | 明确显示前段动作数与对白数；自动寻找能保留 dialogue→beat 归属的安全分界；提交前本地阻断 | 来源少于两个动作、边界越界或对白跨分界不能表达 |
| 前端 merge | 不再截断动作；对白属性/关联完整映射；资产引用按稳定版本/角色/subject 去重，槽位碰撞确定性改名 | 服务端限制无法表示时不提交；视觉/声音/生成意图由用户明确选择基础规格 |

视觉、声音和生成意图不是本轮的合成编辑器；它们仍显式继承用户选择的基础规格。该行为在 UI 中明确展示，不冒充语义合成。NarrativeUnit 多对多引用和 CoverageReport 也未提前实现。

## 5. 命名与 Plain Data Contract

新增生产文件使用短业务语义名 `conservation.py`，未把整条模块路径重复进文件名。DES-000 已是命名和 POJO 等价规范的唯一事实源，并固定：

- 可执行源码/测试文件名含扩展名不超过 64 个 ASCII 字符；
- 禁止 `common/helpers/manager/processor/data`、拼音和切片编号等空泛命名；
- Python/TypeScript 使用 Plain Data Contract：纯字段、类型、序列化和无 I/O 校验；事务、权限与外部 I/O 留在 service/adapter；
- 跨模块契约默认不可变，不创建 `Data/Info/Object/Bean/DTO` 空泛类型，不建立旧名兼容包装。

架构测试已扫描源码、测试和 Alembic 文件，并验证不可变 dataclass、无 I/O 数据对象及依赖方向。规范正文状态和 Design 索引均为 `accepted`。

## 7. 边界与下一步

本验收只接受当前 ShotSpec 可表示范围内的拆镜/合镜守恒，不接受：

- 跨场镜头的语义合成；
- 重复同一 Dialogue identity 的合并；
- 超过现有 15 秒、8 动作、8 对白的自动拆批；
- NarrativeUnitVersion ↔ ShotSpecVersion 多对多引用、CoverageDecision/Report；
- AI 分镜候选、整集删除重建、剪辑时间线或视频生成。

下一任务 DEV-MVPA-10 必须在当前守恒和不可变 Spec 之上建立 AI DraftBatch；AI 结果先成为候选，只有人工 Apply 才能写正式 Shot。
