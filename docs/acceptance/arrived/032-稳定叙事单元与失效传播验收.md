## 1. 验收结论

1. 每个已发布 `ScriptVersion` 现在有唯一 `NarrativeStructure`；首期以可复现的行级规则生成场景标题、动作、对白和旁白，并使用 Unicode code-point half-open range 锚定原文。
2. `NarrativeUnit` 保存稳定 UUID，`NarrativeUnitVersion` 保存不可变的范围、正文、上下文、hash、顺序和必拍标记。身份不再由剧本字符位置、文本 hash 或镜号拼出。
3. 人工修正提交完整有序单元集，使用 expected revision、expected current 和 idempotency key。服务端拒绝跨空间/跨版本 Unit、类型原地漂移、重复 ID、乱序/重叠/越界范围和任何非空叙事字符遗漏；成功后只追加 revision 和 UnitVersion，历史仍可回读。
4. 所有发布、current 切换和批量物化路径都在同一事务内确保新版本结构存在，追加 `NarrativeImpactAssessment`，固定新旧 dependency hash、受影响 Shot 和 `shot_readiness/coverage/export` 失效范围。读取路径不懒创建表或补写数据，依赖缺失时直接 fail closed。
5. 现有 Shot readiness 已比较 Episode current ScriptVersion 和 narrative dependency hash；改稿后旧镜头显式返回 `SCRIPT_REVISION_NOT_CURRENT`，不自动迁移、不删除历史镜头。
6. Episode 剧本页已提供结构列表、稳定 ID、原文高亮、范围/必拍修正和 dependency hash。类型作为稳定身份属性只读，页面不再提供服务端必然拒绝的假编辑。

## 2. 数据与接口事实

| 交付面 | 当前事实 |
| --- | --- |
| 稳定身份 | `scr_narrative_units` 分离 UUID、kind、status、current version 和 revision |
| 不可变表达 | `scr_narrative_unit_versions` 固定 ScriptVersion、structure revision、position、range、exact/context/hash、required、Scene/Dialogue 映射和 origin |
| 结构根 | `scr_narrative_structures` 与 ScriptVersion 一对一，保存 parser/input/structure/dependency hash 和幂等回执 |
| 影响证据 | `scr_narrative_impacts` 按 Episode sequence 只追加新旧依赖、单元数、影响 Shot 和失效域 |
| API | 查询 ScriptVersion 结构/历史 revision；追加人工修正；查询 Episode dependency fresh/stale；查询最新影响 |
| 公开契约 | 跨模块只使用不可变 `NarrativeDependencySnapshot`、`NarrativeImpactSnapshot` 和 Protocol，不导出 ORM/Session/Router |
| 前端 | OpenAPI 生成类型是唯一 API 契约源；RTK Query 管理查询、修正和失效刷新 |

## 3. 成熟方案约束如何落地

- Tiptap UniqueID、xStudio 和 Unstructured 证明稳定 UUID 必须与顺序、位置和正文 hash 分离；实现只吸收身份不变量，没有引入富文本或 C++ runtime。
- Hypothesis 的 TextPosition/TextQuote selector 证明精确范围需与 exact/prefix/suffix 共存，但模糊重锚只能是待人工确认候选；MVP 没有伪造自动跨修订映射。
- Doorstop 的 stamp/suspect 用于固定 dependency hash 变更即 stale；历史可读但不静默清除失效。
- ProseMirror StepMap 说明只有完整编辑 step log 才能确定性重映射；当前 AI 只返回整份候选正文，因此新 ScriptVersion 使用全新 Unit 身份。
- Jellyfish 和 ai-fusion-video 只能证明“引用 episode/excerpt”或“删除派生结构重建”的局限；此类实现明确作为反例，没有被复制。

上述候选均以 PLAN-012 中的固定 commit、LICENSE、核心源码和测试为证据。调研决定了引用和失效不变量，没有被当作可盲目安装的完整短剧平台。

## 5. 工程命名与 Plain Data Contract

DES-000 现在把 POJO 在 Python/TypeScript 项目中的含义固定为 Plain Data Contract：Request/Response/Command/Query/Snapshot/Result 只含字段、序列化和无 I/O 校验，不持有 Session、ORM、FastAPI Request、SDK client、cache、queue、logger 或业务事务。Command 和跨模块 Snapshot/Result 默认拒绝未知字段且不可变；不再用 `Data/Info/Object/Bean/DTO` 代替真实角色。

源码、测试和 Alembic 使用 ASCII 语义名，单文件名含扩展名最长 64 字符。模块目录已给出上下文时保留 `api.py/service.py/schemas.py`，禁止 `misc/common/helpers/manager/processor/data` 等空泛名。重命名只修改唯一实现和引用，不保留旧文件别名、双路径或转发包装。架构测试已将长文件名、空泛文件名和 `contracts.py` 的 FastAPI/SQLAlchemy/integration 依赖视为失败。

## 7. 保留边界与下一步

- 本次只接受 PT-SCR-009，不接受 AssetState、AI 分镜草案、ShotNarrativeReference、CoverageReport 或分镜包。
- 首期 parser 是可复现的行级分类，不代表 LLM 结构理解质量。本 DEV 没有调用外部 AI，也不需要用 Mock 伪装 AI 成功。
- 同一 ScriptVersion 的人工修正当前只允许重排范围和必拍标记，不允许修改 Unit kind、新增/删除/拆合稳定 Unit。需要改变 kind 或拆合时应使用显式 replace/retire 设计，不得原地篡改历史身份。
- 新 ScriptVersion 默认使用全新 Unit 身份；跨修订重锚尚未实现，低置信模糊匹配未来也只能生成待人工确认候选。
- readiness 已为未来 Coverage/Export 固定同一 dependency hash，但多对多镜头覆盖边由 DEV-MVPA-11 实现，不在本验收中提前造表。
- 备份/恢复证据来自当前本机小数据集，不能外推为生产零停机、RPO/RTO 或大表锁时长承诺。

在这些边界内，PT-SCR-009 和 DEV-MVPA-06 接受。下一个主线任务是 DEV-MVPA-07：先核对资产领域成熟方案证据和本地 delta，再实现 AssetState/Occurrence、state current 和状态矩阵 readiness。
