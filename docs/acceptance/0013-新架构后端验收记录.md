# 新架构后端验收记录

目标与执行范围见 [0013 后端实施计划](../plan/0013-新架构后端实施计划.md)。本记录只描述实际完成的代码和验证；完整文本与分镜 MVP 尚未完成。

## 已完成的 Backend 能力

1. 原稿证据读取：固定已接受版本、Unicode code point 半开范围、最多 16,384 字符、源 hash 与片段 hash 校验；旧引用不随新原稿 Head 漂移，每次读取验证当前项目权限。
2. 分镜文本采纳接口：复用既有 Go Owner 的 FreezeIntentSet，通过已有 ReviewDecision 冻结导演意图，原子写入 Owner Receipt；补充严格 hash 格式验证。公开接口没有创建新的 Go 创作 Workflow。
3. 草案集合和正式文本恢复查询：按集合读取唯一回执并验证内容和视觉需求 hash；不再次调用模型，不要求已采纳的历史候选仍为最新 Head。文本采纳后仍可保持 needs_asset。
4. 严格 JSON 解码拒绝合法对象后附加的乱码、截断对象、多对象和超限后缀；修复 Script not-found 错误被映射成 500。
5. 同步公开 OpenAPI、生成的 TypeScript 类型和接受后的设计优先级。

当前分镜采纳仍读取 Go-owned 候选；新 Python 提案接入不能由这些测试抵扣。
