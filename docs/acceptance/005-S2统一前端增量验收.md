## 4. Red → Green 记录

1. 真实 Scheduler 刷新 Outbox 时首先暴露 `NoReferencedTableError`：后台入口只导入局部模型，`sys_outbox_events.workspace_id` 无法解析 identity 表。
2. 新增运行时模型注册架构测试，证明所有已实现外键目标都进入同一 Metadata，并约束数据库初始化、Scheduler、I/O Worker、Media Worker 四个入口执行注册。
3. 引入唯一 `app/model_registry.py` 组合根并把 Media Worker 加入 `server` 监督列表；目标测试与完整 `make check` 全绿后，再重新运行真实后台角色完成媒体探测。

## 5. 接受边界与下一步

1. 本文只接受统一前端、后台组合根和本地媒体链路的工程增量，不接受 DEV-S2-06、任一 S2 PT 或 S2 产品切片完成。
2. 项目未配置真实 AI 服务；当前明确失败是正确的 fail-closed 结果，不等于提取成功。下一步必须由用户提供实际服务配置，再完成提取候选、人工决议和结构确认。
3. 当前验收单集显示 `Ready 资产 0 / 2`，且没有 ready 声音；必须补齐授权和类型化版本，使至少角色、场景、声音各一项 ready，才能执行 S2 联合接受。
4. 默认 `make check` 仍不会隐式启动外部服务；6 项 skipped 不能解释为通过。本轮只单独通过了当前明确使用的真实 MinIO 契约和浏览器媒体链路。
5. 本机历史容器的创建标签仍可能显示 `latest`，但运行二进制已被精确发行版守卫核验；仓库不得回退浮动标签，也不得因为标签名重复拉起第二容器。
