## 验收范围

本记录验收 `.github/workflows/ci.yml` 是否作为每个提交的系统边界，而非完整发布验收平台。CI 覆盖 Go Backend、私有 Python Agent Candidate Runtime、Next.js Frontend/OpenAPI 的快速质量门，并使用空 PostgreSQL 和真实 Temporal 执行唯一一条 `Script → Evidence → Story Analysis → Bible → Episode → StoryGraph → Storyboard` 系统旅程。全量恢复矩阵、原生 Agent 跨进程交接、Compose、镜像和外部环境属于阶段/发布验收。

## 真实验证

1. Backend Quality 执行 `gofmt`、`go vet ./...` 和不注入外部环境的 `go test -count=1 ./...`，验证纯逻辑、架构与契约。
2. Agent 执行 Ruff check/format、Pyright 与全部 Pytest；只检查 `agent/app` 和 `agent/tests` 正式边界。
3. Frontend 重新生成 Backend OpenAPI Client，并执行 ESLint、TypeScript、Vitest 与 Next.js 生产构建；生成目录必须无 Diff。
4. Workflow System Boundary 仅启动固定摘要 Temporal 与空 PostgreSQL，执行 `TestSourceEvidenceAndStoryAnalysisWorkflowRecoverBoundedMapReduce`，保护当前核心剧本解析/StoryGraph DAG 边界。
5. Delivery Hygiene 拒绝 secret、数据、日志和浏览器报告进入 Git，并保持 Backend/Agent 语言边界。
6. OpenAPI 漂移并入 Frontend，仓库卫生并入 `Required / CI`；`Required / CI` 必须等 Backend、Workflow、Agent 与 Frontend 全部成功，任一 Job 失败或跳过都不能报告绿色。
