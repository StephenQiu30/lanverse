## 验收口径

本记录只承认当前目标拓扑的证据：Browser → Go Backend → 单一 PostgreSQL/GORM Catalog，Backend 可调用私有 Candidate-only Agent，并使用 MinIO 保存上传字节。历史 Python Writer、pgx Repository、Migration、Kafka 或旧页面证据不计入本轮通过。

最终浏览器验收输入固定为 `agent/tests/fixtures/mvp_a/golden_candidate_harbor_countdown.json` 对应的五集原稿。最终 `agent-browser` 必须等开发和自动化回归结束后才启动；当前没有使用该工具，也没有把页面未验证状态报告为通过。

## 已通过的自动化旅程

1. 从独立空 PostgreSQL 与空 MinIO 启动 Frontend、Backend、私有 Agent。
2. 注册/登录、创建项目、上传并固定五集原稿。
3. 使用真实 Codex 生成并确认 Production Bible。
4. 创建确定性分集计划，确认后原子创建五集并批量发布剧集剧本。
5. 进入首集，逐场接受必需 `shot_breakdown` 制作任务并确认结构。
6. 使用真实 Codex 生成分镜候选，逐镜接受、整批批准、预检并原子写入正式镜头。
7. 预检并生成分镜 ZIP，下载后验证四个固定文件、内容哈希和刷新恢复。

步骤 1–7 均已由 Playwright 在当前源码上通过。自动化过程曾真实暴露并修复两个问题：Codex Structured Outputs 的开放对象 Schema 被 API 拒绝，以及恢复生成时 Playwright 误读旧重试按钮状态。修复后最终用例首次 Bible 与 Storyboard 调用均成功，没有使用模型桩。

自动化回归已结束；下一步使用 `agent-browser` 按同一旅程验证可访问名称、键盘操作、状态提示和浏览器控制台/网络错误。

## 残余风险

- 真实 Codex 的执行时间、登录状态与输出非确定性仍是外部条件；受控恢复与可见 `generation_error` 已验证，但不会将外部不可用伪装为成功。
- 模型产生 blocking candidate 时，必须保留问题并逐项记录人工决议，不能静默降级；自动化已证明全部明确接受后可继续，但不代表任意剧本都无需人工专业审阅。
- 生产自助注册仍依赖实际验证码发送通道；本地隔离 E2E 只使用固定测试验证码，生产发送通道未配置时不能把自助注册报告为可用。
- 最终 `agent-browser` 验收尚未开始；完成前不将 `MVP-NFR-004` 或本轮验收状态标记为通过。
