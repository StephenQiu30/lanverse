# P0-05 画布性能 PoC 记录

日期：2026-09-27。范围：仅验证 [DES-38](../design/38-画布功能.md) §10 的技术方案与 [REQ-02 PERF-06](../requirement/02-非功能需求规格.md)；不是 E-36 的业务画布验收。页面为 `/poc/canvas`，不会读写业务数据。

## 样本与实现

- `@xyflow/react@12.12.0` 负责节点、连线、视口与小地图；固定数据由 `makePocGraph` 构建，支持 500 节点 / 600 连线、500 节点 / 800 连线、2,000 节点 / 3,200 连线。500 节点场景含 300 图像、40 视频、160 文本节点。
- 卡片外观与浮动工具栏交互参考 `basketikun/infinite-canvas` 固定提交 `dab19adc0847e32e39b7fc8ff90cb392561fb826`；界面在 `poc-canvas.tsx` 中重新实现，没有复制上游状态、存储、插件或执行代码。固定提交的 MIT 许可保存在 `frontend/public/licenses/infinite-canvas.txt`，并经 `/licenses` 页面呈现来源。
- 图像使用同一个本地 SVG，视频使用同一个 320×180、2 秒的本地 MP4。视频最多 3 个自动播放；平移和缩放期间暂停，结束后恢复。视口外节点由 React Flow 裁剪。重复媒体素材减少了网络与解码差异，可能低估真实项目中不同媒体的内存与首次加载成本。

## 环境与方法

- MacBook Pro / Apple M5 / 24 GB 内存；本机服务，未启动 Docker。Chromium 151.0.7922.34（agent-browser 0.33.0，有头模式），视口 1440×900。运行 `pnpm exec next build`、`pnpm exec next start --hostname 127.0.0.1 --port 3137` 后测试生产构建。
- 页面就绪：React Flow `onInit` 后经过两次 `requestAnimationFrame` 写入 `lanverse-canvas-ready-500-800` 性能标记；用 `performance.getEntriesByName` 读取导航起点到该标记的毫秒数。分别测量同浏览器缓存下的三次重载与三个新浏览器会话；新会话测量时可见图像均已加载完成。浏览器进程启动时间不计入页面打开时间。
- 缩放：在画布 pane 上每个动画帧注入交替方向的 `WheelEvent`，连续 120 帧；计算 119 个帧间隔对应的平均 fps。每次均观察到视口变换；三个场景各重复三次。这是连续程序输入的本机浏览器测量，不等同真实触控板手势。
- 平移：agent-browser 发送真实浏览器鼠标按下、连续 60 次位置更新与释放，同时逐帧采样；每轮均观察到 60 个不同视口状态。各场景重复三次。Chrome DevTools trace 在本机 `/tmp/lanverse-canvas-500-800.trace.json` 录制过优化前 500/800 场景；未将 40 MB 原始录制加入仓库。本次未使用 Playwright；E-36-06 的 Playwright 验收仍待进行。
- `performance.memory.usedJSHeapSize` 记录 JS 堆；2,000 节点场景另记录该浏览器进程及 9 个直接子进程的 `ps` RSS 合计。RSS 合计会重复计算共享页，仍不能覆盖所有独立 GPU 显存与真实媒体资产。

| 场景 | 缩放 fps（三次） | 平移 fps（三次） | 交互后播放视频数 | JS 堆观测 |
| --- | --- | --- | --- | --- |
| 500 节点 / 600 连线 | 56.2、56.4、56.4 | 63.7、65.4、64.1 | 2 | 19.1 MiB |
| 500 节点 / 800 连线 | 57.8、56.4、57.1 | 64.7、62.1、62.5 | 2 | 15.6 MiB |
| 2,000 节点 / 3,200 连线 | 60.0、60.0、60.0 | 64.8、64.3、65.2 | 1 | 64.9 MiB |

500/800 首屏就绪：缓存重载为 **151.2、129.5、131.2 ms**；新浏览器会话为 **487.8、241.7、210.7 ms**（目标 ≤ 3 秒）。三个场景的切换到就绪标记分别为 113.5、108.6、268.4 ms。2,000 节点场景浏览器进程组 RSS 合计 **1,231.4 MiB**（按十进制 1.5 GB 计算的目标 < 1,430.5 MiB；仅为本机代理指标）。浏览器控制台和页面错误检查均为空。

优化前，500/800 场景连续缩放仅约 33 fps；暂停正在播放的 2 个视频后约 58 fps。实现将视频暂停与恢复接入视口移动事件；实测移动时 0 个视频播放，结束后恢复到 2 个。这一决策是达到固定样本帧率目标的必要条件。

## 结论与限制

固定样本在本机达到 PERF-06 的 500/800 平移、缩放与打开时间目标，也达到 2,000 节点 ≥ 30 fps；DES-08 的 500/600 样本和 RSS 代理指标也低于目标。建议继续采用 React Flow 与固定 MIT 版本的界面适配方案，DES-38-Q1 的正式产品确认仍待负责人作出。真实不同图像/视频、低端设备、长时间使用、GPU 内存和完整业务画布应在 E-36-06 单独验收，不能由本 PoC 推定通过。
