## 验收结论

当前 Compose 运行拓扑不再定义独立 `database-migrate` 服务。Go `lanverse-api` 是唯一对外 HTTP 入口，启动时先在事务与 Advisory Lock 内应用内嵌版本化 Migration，成功后才开放 `/healthz`；只读 Schema Guard 随后运行，内部 Agent API 与 Workers 再启动。

对象存储已分离服务端内部地址与浏览器可达地址。服务端通过 `MINIO_ENDPOINT=minio:9000` 操作私有 Bucket，预签名 URL 使用 `MINIO_PUBLIC_ENDPOINT`；开发 MinIO 同时连接 `internal` 与 `edge` 网络，并只向宿主机回环地址发布端口。浏览器上传不再收到内部主机名或 `Failed to fetch`。

## 隔离全栈证据

验收使用独立 Compose Project、独立 Volume 和宿主机备用端口启动，不读取或修改业务 `.env`、既有数据库或既有容器。Backend 日志依次出现：

```text
database migrations applied
lanverse api started
```

随后 `/healthz` 与 `/readyz` 均返回 200，Frontend 返回 200；运行服务列表中不存在 `database-migrate`，`agent-api` 不向宿主机发布端口。

首次真实浏览器上传暴露出预签名 URL 使用 `minio:9000` 的问题；修正内部/公开地址和开发网络边界后，同一浏览器、同一账号、同一项目、同一 Markdown 文件重新上传成功，并进入内容预览与格式解析。

## 范围与残余风险

- 本记录证明“一个公共 HTTP 入口”和“Migration 作为 Backend 内部启动步骤”，不表示 `agent/openapi.json` 中的 160 个 Path、184 个 HTTP Operation 已全部从 Python 改写为 Go。
- `cmd/migrate` Binary 仅保留为发布期诊断入口，不对应常驻服务。
- 当前容器内 IO Worker 仍需要可用的 Codex CLI；本次真实剧本格式解析不调用模型，因此不覆盖需要 Codex 的结构抽取、Production Bible、改编和分镜任务。该运行依赖必须在后续 Agent 执行器切片中收敛。
