## 接口迁移的明确边界

当前 Go `/openapi.json` 仍发布静态契约，包含 116 个路径和 283 个 schema。本轮没有把静态 JSON 伪装成 Handler 注解产物，也没有宣称旧手写 API 已自动生成。

- `src/api/generated/` 完全由 umi-openapi 管理，命名空间暂为 `GeneratedAPI`，调用统一 `src/lib/request.ts`。
- 既有 `src/api/*.ts` 和 `API` 类型暂时保留，业务调用尚未切换；不得继续给旧请求层增加新接口。
- 旧类型生成脚本和 `openapi-typescript` 依赖已移除；旧类型文件仅作迁移期间兼容快照。
- 部分既有接口缺少响应 schema，生成器仍会输出 `any`。下一步须按业务模块补齐 Handler 注解与 DTO，通过 `swaggo/swag` 生成文档，同时迁移调用方，最后删除旧包装和类型快照。
- `TestFrontendGenerationFromOnlineContract` 使用当前 `bootstrap.NewAPIHandler` 提供 HTTP 文档，不启动替代业务服务。它证明在线生成可运行，不证明每个 API 的真实响应都符合 schema。

在线生成命令：

```sh
cd frontend
OPENAPI_SCHEMA_URL=http://127.0.0.1:8686/openapi.json pnpm openapi
```

CI 使用当前代码的 Handler 启动临时 HTTP 服务，运行上述生成入口，再检查 `src/api` diff。没有 URL、非 HTTP URL、HTTP 错误或无效文档均应失败，不回退到本地文件。

## 未完成与风险

1. Handler 注解 → Swagger → 全部调用方的完整闭环尚未完成；当前在线生成入口是迁移基础。
2. shadcn/Radix Form 与 Table 的业务组件迁移、React Hook Form/Zod 接入尚未实施；本轮前端组件文件变化为格式基线调整。
3. Harness 全部专业能力、真实模型预算、完整人工审批采纳链路仍须按设计逐个切片验收；此次未调用真实模型。
4. 全量 Go lint 尚有 19 条现存问题，增量通过不等于全量通过。
5. `google.golang.org/grpc@v1.82.1` 命中 [GO-2026-6348](https://pkg.go.dev/vuln/GO-2026-6348)，官方修复版本为 `v1.83.1`。HEAD 已包含该依赖，本轮未升级 Go 依赖；后续升级需验证 Temporal 兼容性。
6. pnpm 安装报告传递依赖的 peer 警告，安装、编译和测试可通过；不据此声称依赖树已无告警。
7. 未验证新 Docker 镜像构建、线上部署和远端 CI；没有执行发布。
