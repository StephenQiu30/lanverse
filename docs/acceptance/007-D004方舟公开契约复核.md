## 1. 结论

在不配置 API Key、不安装 Ark SDK、不读取凭据和不发送供应商请求的前提下，已完成火山方舟 Python SDK 5.0.43 的公开契约复核。公开来源能够证明 `AsyncArk`、北京区默认数据面、图片同步资源、视频异步 task 资源及公开响应状态；不能证明 Lanverse 账号已开通候选模型，也不能证明逐模型参数、取消竞态、配额、回调安全或账单精度。

Lanverse 的候选接入仍收窄为一个官方 SDK、一个 ArkMediaAdapter、`ARK_API_KEY` 单一认证配置、Seedream 非流式单图 `b64_json` 和 Seedance task 查询收敛。SDK 的流式、组图或其他参数不会自动暴露给前端。此前“只有 queued 可取消”和“取消状态固定保留 24 小时”的断言已降级为真实账号待验证事项。

## 4. 后续准入

只有用户未来提供受控的真实账号测试条件后，才允许继续 D-004：

1. 在 Python 3.11 项目 `.venv` 中安装并锁定 `volcengine-python-sdk[ark]==5.0.43`，验证与现有依赖兼容。
2. 证明两个精确候选模型在目标账号和 `cn-beijing` 可用，冻结实际参数白名单、输入限制、内容安全和水印行为。
3. 验证视频各状态下的取消/查询/回调竞态、查询窗口、配额/并发和错误映射。
4. 用真实账单样例冻结 pricing version、币种、精度和用量映射，再进入 S4 Red 测试与最小实现。

在上述证据完成前，不安装 SDK、不创建假 Provider、不把静态能力目录或 mock 结果解释为生产能力，也不关闭 D-004。
