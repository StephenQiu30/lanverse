## 验收范围

本记录验收 `BE-MOD-011` 的 Budget 所有权前置边界：Production Project 不再持有金额或币种；Backend `cost` 模块成为 Project BudgetPolicy 的唯一 Owner，并通过当前身份授权、Expected Revision、精确 Decimal、GORM/PostgreSQL 事务和 CommandReceipt 完成设置与读取。

本增量不包含 Price、Estimate、Cost Reservation、Ledger、GenerationIntent、Cost/Quota 共享准备事务、Execution Claim/Authorization、Provider 调用或前端预算管理页面，因此不代表 `BE-MOD-011`、`BE-JRN-004` 或阶段 6 已完成。

## 实现事实

1. Production Project 的 Domain、GORM Model、Application Service、HTTP Response 和 OpenAPI 全部移除 `BudgetLimit/Currency`；`project.budget.update` 与 `/api/projects/{project_id}/budget-limit` 直接删除，没有兼容转发、旧字段保留或双写。
2. Cost 新增显式 `domain → application → adapter/gormdb + adapter/httpapi` 边界，只复用已锁定的 `shopspring/decimal v1.4.0`、GORM、UUID、HTTP Validator 和通用 CommandReceipt，没有新增依赖或共享 `utils`。
3. `CostBudgetPolicy` 对 Project 唯一并使用 Project ID + Workspace ID 复合外键冻结租户绑定；金额保存为 `NUMERIC(20,6)`，Currency 只允许三位大写值，Revision 与 Content Hash 防止并发和事实漂移。
4. `cost.budget.set` 只有当前 Workspace Owner 可创建或更新；同一命令的并发和重放收敛到同一 Policy/Receipt，陈旧 Revision、输入漂移、撤销 Token 与跨 Workspace 访问失败关闭。未设置 Budget 明确返回 `not_found`，不回退到 Project 默认值。
5. HTTP/OpenAPI 的 `limit_amount` 输入和输出均为十进制字符串，避免浏览器 JSON Number 在到达 Backend 前丢失精度；Backend 再用 Decimal 校验非负、最多 14 位整数和 6 位小数并规范化为固定六位。
6. Project 删除预检只读取 Cost Budget 依赖数量，不复制金额；存在 BudgetPolicy 时返回 `HAS_COST_BUDGET`，避免先报告可删除再由外键产生内部错误。
7. `CostBudgetPolicy` 进入唯一 GORM Model Catalog。实现没有 Migration 文件、手写 SQL Schema、第二数据库或兼容字段；PostgreSQL 是唯一 Budget 事实源。

## 真实验收证据

- Red 阶段先执行 `go test ./tests/cost`，明确因 `internal/cost/adapter/gormdb` 不存在而编译失败；完成最小实现后同一测试包转绿。
- 真实 PostgreSQL `16.15-alpine` 旅程验证新建 `prj_projects` 不含 `budget_limit/currency` 列；未设置 Budget 返回 `not_found`，Editor 写入被拒绝，Owner 创建 `100.123456 USD` 后 Viewer 可以读取。
- 8 路并发执行相同 Revision 更新收敛为同一 Revision=2、`250.000001 USD` 与同一 Receipt；陈旧 Revision、同幂等键更换金额、七位小数、内容 Hash 漂移均被拒绝，当前 Workspace 精确为 1 个 Policy、2 个设置 Receipt。
- Token Version 撤销后读取失败；另一个 Workspace 的 Owner 可以管理自己的 Budget，而本 Workspace Viewer 读取该 Project 只得到不泄漏存在性的 `not_found`。
- Project 删除预检真实读取 Cost 表并返回唯一 `HAS_COST_BUDGET` 阻塞项；没有依赖外键异常或兼容判断完成业务语义。
- 目标旅程执行 `go test -count=3 -run TestProjectBudgetHasOneCostOwner ./tests/cost` 连续三次通过，累计约 6.8 秒；最终完整 CI 中 Cost 旅程约 2.6 秒。
- 首次启动完整后端 CI 时格式门立即失败，确认 `api/openapi/document_test.go` 未 gofmt，尚未进入 Vet/测试；格式化后从整条命令重新开始。全新 PostgreSQL + Temporal + MinIO 下，`test -z "$(gofmt -l .)"`、`go vet ./...`、`go test -count=1 -p 1 ./...` 均以退出码 0 完成，Workflow 套件约 67.3 秒，外部旅程未跳过。
- Agent 的 Ruff check/format、Pyright 零错误与 12 个 Pytest 通过；Frontend 执行锁定依赖安装、OpenAPI 重生成、ESLint、TypeScript、45 个 Vitest 和 Next.js 生产构建，生成 Client 无漂移。
- 开发/生产 Compose 与仓库卫生检查通过；Frontend、Backend、Agent 三类镜像从当前源码重新构建，并分别通过 standalone、API/Workflow Worker 双二进制和私有 Candidate Runtime 入口断言。

## 边界与残余风险

- BudgetPolicy 目前只定义项目金额上限，尚无 PriceQuote、Estimate、Reserved/Settled Amount 或追加式 Ledger；真实付费操作仍不能开始。
- Cost/Quota 尚未由 GenerationIntent 的共享准备事务原子组合；当前两个 Owner 各自可用，但不能宣称 `PrepareExpensiveOperation` 已完成。
- Currency 只验证稳定三位大写格式，实际支持币种必须由后续真实 Provider Price/Model Policy 明确；本增量不虚构汇率或 Provider 价格。
- 远端 `origin/main` 仍停留在已通过 GitHub Actions 的 `2f6e066`；本地后续提交只有在获得推送并实际运行后才能报告远端绿色。
- `agent-browser` 按约定只在全部开发完成后执行；当前仍有 Cost Reservation/Ledger、GenerationIntent、Provider、CandidateSet/Workflow 和单 Shot Workflow 后续任务，因此本切片不提前调用。
