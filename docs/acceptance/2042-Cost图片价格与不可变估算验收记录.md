## 验收范围

本记录验收 `BE-MOD-011` 的第二个前置边界：Cost 为 `generation.image` 唯一拥有追加式 PriceQuote，并通过内部 Application Command 根据当前 Budget/Quote 创建不可变 Estimate。调用方只提供稳定 Generation Intent Source 与 Units，不能自报单价、币种、总额或 Quote Revision。

本增量不包含 Cost Reservation、Ledger、GenerationIntent Coordinator、Cost/Quota 共享准备事务、Execution Claim/Authorization、Provider/Model 路由、汇率或前端价格管理页面，因此不代表 `BE-MOD-011`、`BE-JRN-004` 或阶段 6 已完成。

## 实现事实

1. `CostPriceQuote` 只支持当前真实图片链路的 `generation.image` Metric，金额使用 `shopspring/decimal` 与 PostgreSQL `NUMERIC(20,6)`；每次调价追加新的唯一 Project + Metric + Revision 行，不原地修改历史 Quote。
2. Workspace Owner 设置 PriceQuote 时先锁定当前 BudgetPolicy；报价 Currency 必须与 Budget 一致，首次创建和并发 Revision 更新在一个 GORM/PostgreSQL 事务中串行化。已有 Quote 后 Budget Currency 也不能切换，避免混币种事实。
3. `CostEstimate` 冻结 Budget Policy ID/Revision/Limit、PriceQuote ID/Revision、Metric、Source、Units、Unit/Total Amount、Currency、创建人和 Content Hash。总额只能由 Cost 读取服务端当前 Quote 后执行 `unit_amount × units` 得到。
4. 同一 Project + `generation_intent` Source 只有一个 Estimate；同命令并发返回同一 Receipt，新 Idempotency Key 的同 Source 请求仍返回第一次冻结的 Estimate，Units/Metric/Source 或已保存内容漂移失败关闭。
5. PriceQuote 管理与读取通过 Backend HTTP/OpenAPI 暴露，十进制金额保持字符串契约；Estimate 创建只暴露 Cost Application Interface，等待后续真实 GenerationIntent Coordinator 调用，没有公开可伪造 Source 的 REST 入口。
6. `CostPriceQuote` 与 `CostEstimate` 进入唯一 GORM Model Catalog，包含唯一索引、检查约束和 Project/Workspace/User/Budget/Quote 外键。实现没有 Migration 文件、DDL/Raw SQL、第二数据库、价格兼容字段或 Provider 占位事实。

## 真实验收证据

- Red 阶段先执行 `go test ./tests/cost`，明确因 `SetPriceQuoteCommand`、`CreateEstimateCommand` 和对应 Service 方法不存在而编译失败；完成最小实现后相同包转绿。
- 真实 PostgreSQL `16.15-alpine` 创建 `cst_price_quotes`、`cst_estimates` 及 GORM 声明的唯一索引、Check/FK 约束；数据库目录查询确认 Quote Revision 与 Estimate Source 唯一索引真实存在。
- Owner 在 Budget 前设置价格得到 `not_found`，Editor 设置价格得到 `forbidden`；Budget 建立后追加 `0.125000`、`0.250000`、`0.500000 USD` 三个 Quote Revision，历史行未被覆盖。不同币种、陈旧 Revision、同幂等键不同金额及 Quote 存在后的 Budget 币种切换均被拒绝。
- 8 路并发用同一 Generation Intent 创建 3 Units Estimate，收敛到同一 Estimate/Receipt；结果冻结 Quote Revision 2、Budget Revision 2、`0.250000 × 3 = 0.750000 USD` 与 `120.000000` Budget Limit。
- Estimate 创建后把当前 Quote 调整为 Revision 3、Budget 调整为 Revision 3，再用新 Idempotency Key 请求同 Source，仍返回原 Revision 2/`0.750000` 快照；Units 漂移、Receipt 输入漂移、Estimate/Quote Content Hash 篡改均被拒绝。
- Viewer 不能创建 Estimate，但可读取当前 Quote/Estimate；Token Version 撤销后读取失败，其他 Workspace Owner 读取该 Estimate 只得到不泄漏存在性的 `not_found`。
- 目标旅程执行 `go test -count=3 -run TestImagePriceAndEstimateFreezeServerFacts ./tests/cost` 连续三次通过，累计约 7.0 秒；最终完整 CI 中 Cost 套件约 4.7 秒。

## 边界与残余风险

- PriceQuote 当前只覆盖 `generation.image` 的 Project 级单位价格；Provider/Model 事实尚不存在，因此本切片不虚构具体 Provider 报价、Fallback 或汇率。后续真实路由必须扩展冻结维度并更新事实来源，不能旁路 Cost。
- Estimate 只计算并冻结金额，不占用 Budget；在 Cost Reservation/Ledger 完成前，任何真实付费执行仍必须被阻止。
- Cost/Quota 尚未由 GenerationIntent 的共享准备事务原子组合，不能宣称 `PrepareExpensiveOperation` 或 `AcquireExecutionClaim` 已完成。
- 远端 `origin/main` 仍停留在已通过 GitHub Actions 的 `2f6e066`；本地提交只有在获得推送并实际运行后才能报告远端绿色。
- `agent-browser` 按约定只在全部开发完成后执行；当前仍有 Cost Reservation/Ledger、GenerationIntent、Provider、CandidateSet/Workflow 和单 Shot Workflow 后续任务，因此本切片不提前调用。
