## Checklist 口径

- 所有条目初始均为 `[ ]`，表示尚未经过本主题的独立验收。
- 只有 Requirement 的完整正常路径、失败路径和边界条件都有可复查证据后，才可标记为通过。
- 单次模型返回、模型桩、少量样本、计划中的步骤或单独一层校验，均不能替代业务闭环验收。
- 每次勾选必须同时记录输入与哈希、环境与版本、执行步骤、预期与实际结果、失败样本、审阅人和日期。
- 运行耗时、lease 时长和 Provider 调用次数不作为业务质量通过条件。

## Requirement Checklist

### 输入、生成与查询

- [ ] `PB-FR-001`：相同 document revision 与幂等键只创建一个 Bible/Task，内容变化不复用旧任务，Outbox 不携带完整原稿。
- [ ] `PB-FR-002`：连续区间从 `0` 覆盖到正文末尾且拼接等于原文；越界、伪造或 hash 不匹配证据全部被拒绝。
- [ ] `PB-FR-003`：entity 与 entity state 明确分离；角色、地点、道具、服装、声音、视觉风格及 world entry 均有合法来源证据。
- [ ] `PB-FR-004`：evidence → reconcile → review 三阶段只产生严格 schema 候选；统一阶段不新增证据，复核阶段不修改或确认候选。
- [ ] `PB-FR-005`：同类型别名冲突、互斥状态重叠、无证据事实、悬空 world 引用和规则冲突都形成稳定 blocker。
- [ ] `PB-FR-006`：用户可查询 Bible、有效确认版本、checkpoint 摘要、issue 与候选内容；跨 workspace 数据和私有运行字段不可见。

### 审阅、修订与确认

- [ ] `PB-FR-007`：`failed/unknown` Bible 只从身份与版本匹配的合法 checkpoint resume；新 Task 保留旧 Task 终态，无 checkpoint 时 fail closed。
- [ ] `PB-FR-008`：状态边界、身份合并/拆分、名称/别名、entity kind、state 增删、world entry 和 issue 判定均有类型化 resolution command。
- [ ] `PB-FR-009`：blocker 未清零不能确认；确认事务把一个 entity 物化为唯一 Asset，并把多个 state 物化为该 Asset 下的状态/版本，失败时全部回滚。
- [ ] `PB-FR-010`：项目内同类型规范名或唯一别名匹配必须经显式链接；近似字符串、跨作用域、类型不符和一资产多 entity 复用均被拒绝。

### 发布与下游传播

- [ ] `PB-FR-011`：ImportCommit 只在同一 document revision 的 Bible confirmed 后发布，且全部分集冻结同一 Bible id/revision/result hash。
- [ ] `PB-FR-012`：Bible-bound 分集只返回 scene、dialogue、occurrence 与 continuity 候选；未知或类型不匹配引用不能确认，合法 occurrence 锚定 narrative unit version。
- [ ] `PB-FR-013`：未知或歧义身份形成带来源、集号和后续动作的幂等 reconciliation issue；处理前结构保持阻塞且不静默创建资产。
- [ ] `PB-FR-014`：Storyboard 输入从目标剧集 occurrence 自动派生资产状态和相关 world entry；无关全项目资产不注入，snapshot 漂移被拒绝。
- [ ] `PB-FR-015`：确认新原稿 Bible 后，旧 Bible 进入 `superseded`；新旧 snapshot 均可追溯，影响预检前不静默替换下游引用。

### 取消与非功能需求

- [ ] `PB-FR-016`：queued/running Bible 可显式取消；取消 fencing run token 并终止本机 Codex，取消、失败或 unknown 后不能提交成功结果。
- [ ] `PB-NFR-001`：长任务无固定业务墙钟超时；心跳可持续续租，活跃重投不并发执行，过期恢复使用新 token，旧 token 不能保存或提交。
- [ ] `PB-NFR-002`：create、resume、resolution、confirm、publish 与 occurrence 的重放不产生重复事实，冲突返回明确 revision 或 next action，审计链完整。
- [ ] `PB-NFR-003`：Skill 和本机 Codex 只能读取固定输入并返回结构化候选；无文件、数据库或业务 Tool 写权限，正式写入仅由应用服务完成。
- [ ] `PB-NFR-004`：workspace、project、document、Bible、Asset 与 Task 作用域一致，跨作用域查询、恢复、确认和链接全部被拒绝。
- [ ] `PB-NFR-005`：139,723 字、60 集机器统计完整，E01/E07/E09/E31/E36/E60 完成人工细查且不替代全量覆盖。

## 60 集真实原稿验收矩阵

未来验收输入：`He Left Our Kids to Drown—He Didn’t Know I Was the Empress.docx`。

- [ ] 固定文件哈希与不可变 revision，确认 139,723 个正文字符、60 个 marker 和连续无重叠区间。
- [ ] 用真实本机 Codex 生成 Production Bible，并记录 entity、state、world entry、evidence 与 blocker 的数量和版本。
- [ ] 仅通过公开 resolution/link 命令清零 blocker，不直接修改持久化数据。
- [ ] 确认后验证同一故事身份只有一个 Asset，阶段变化只形成其 AssetState/AssetVersion。
- [ ] 发布 60 个 Episode 与绑定同一 Bible snapshot 的分集批次。
- [ ] 逐集统计 scene、dialogue、occurrence、未知 Bible 引用、独立 asset candidate 和 reconciliation issue。
- [ ] 确认全部 occurrence 锚定 narrative unit version，且可反查 entity state 与原文证据。
- [ ] 为 60 集生成 Bible-backed Storyboard candidate，并统计镜头、required coverage、引用、issue 与状态。
- [ ] 对 E01、E07、E09、E31、E36、E60 核对身份、状态、世界规则、镜头引用和原文依据。
- [ ] 注入重启、重复投递、续租短暂失败、lease 过期、取消和版本替代，无重复资产、occurrence 或半发布。
- [ ] 对比独立基线并记录差异、人工决议、失败样本、恢复动作和未决风险。

## 验收证据包

每轮验收必须形成一份不可变记录，至少包含：

1. Requirement ID 与验收场景编号。
2. 输入名称、内容哈希、document revision、Bible snapshot 和下游版本。
3. Codex、model、Skill、schema、Harness 与运行环境版本。
4. 前置条件、执行步骤、预期结果和实际结果。
5. 自动统计、人工结论、差异、失败注入和恢复结果。
6. 审阅人、执行日期、证据位置与未决风险。
