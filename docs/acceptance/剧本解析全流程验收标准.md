# 剧本解析全流程验收标准

## 1. 自动化验收

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AC-UPL-001 | DOCX、Markdown、文本导入 | 固定原文/哈希/版本；重复请求回读同一事实；错误文件给出明确下一动作 |
| AC-ANA-001 | 显式多集剧本进入 Skill | 输出覆盖全部显式剧集，source range 无越界，聚合后原文无缺口/重叠 |
| AC-ANA-002 | 人物跨分块/跨集出现 | 同一人物稳定合并，`first_seen_episode` 正确，`episode_numbers` 去重升序且每项有证据 |
| AC-ANA-003 | 场景与制作任务 | 每个场景属于唯一剧集，人物/道具/任务引用有效，重复 Skill 结果不产生重复候选 |
| AC-ANA-004 | Skill 失败 | 超时进入 unknown；无效 schema/缺集失败；任何失败均不写已批准业务事实 |
| AC-BRD-001 | 逐集生成分镜 | 每行结构满足 schema，所有必需叙事单元被覆盖，引用剧本/叙事/资产版本存在 |
| AC-BRD-002 | 输入并发变化 | 旧批次变为 stale 或返回版本冲突，不覆盖新版本分镜 |
| AC-BRD-003 | 审阅与应用 | 接受/修改/忽略可追溯；全部决定后可批准；应用只创建一次正式 Shot/Spec |
| AC-RUN-001 | RabbitMQ 重投和 Worker 重启 | 同一 Task/Batch 收敛，无重复剧集、候选、分镜或外部调用 |
| AC-SEC-001 | 租户与内部边界 | 跨 Workspace 读取返回不可枚举结果；前端不能调用 Skill/Worker 内部入口 |
| AC-CON-001 | OpenAPI 漂移 | FastAPI schema、`backend/openapi.json` 和 `frontend/src/api` 重新生成后 Git 无差异 |

## 2. 浏览器验收

使用 `agent-browser` 在本机生产构建执行：

1. 注册或登录普通创作者账户并创建项目；
2. 上传真实 DOCX 剧本并确认预览；
3. 启动解析，确认剧集、场景、制作任务、人物和人物出场集数可见；
4. 进入任一剧集生成分镜候选，至少接受一行、修改一行，并完成该集批准/应用；
5. 刷新页面，确认阶段状态和结果保持；
6. 检查浏览器 console、page errors、可访问性和关键页面性能指标。

浏览器验收不得使用 mock API、内存数据库或手工插入结果替代业务请求。

## 3. 交付判定

只有以下条件全部满足才标记完成：

- 后端 Ruff、Pyright、核心/契约/数据库集成测试通过；
- 前端 lint、typecheck、unit test 和 production build 通过；
- 本机真实依赖下主流程通过；
- agent-browser 浏览器验收通过且无阻断错误；
- 没有 Go、独立 Agent、Admin/邀请、Docker 构建或兼容层残留；
- 最终 `git status --short` 为空。
