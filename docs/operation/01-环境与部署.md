## 1. 环境

| 环境 | 用途 | 部署形态 | 数据 | 供应商 |
| --- | --- | --- | --- | --- |
| local | 开发 | 三端进程直接启动，连接本机已运行的中间件；根目录 `.env` 配置 | 种子数据 | 模拟供应商；可选真实（个人测试凭据，严格预算） |
| ci | 自动化测试 | GitHub Actions + testcontainers / Compose | 每次重建 | 模拟供应商 |
| staging（预发） | 集成、端到端、性能、故障注入、验收预演、迁移演练 | 单台云服务器 Docker Compose（中间件自建容器） | 脱敏样例 + 合成大项目 | 模拟为主；真实供应商冒烟（每日 ¥20 上限） |
| production | 内部生产使用 | 云服务器 + Docker Compose；数据库、Redis、Kafka、对象存储使用托管服务 | 真实 | 真实 |

各环境数据、凭据、密钥、存储桶完全隔离（REQ-02 DEP-02）；staging 不允许读取生产数据。

## 2. 生产拓扑

```text
                       Internet
                           │ HTTPS（lanverse.<域名>）
                    ┌──────▼──────┐
                    │ CLB 负载均衡 │  TLS 终止、WAF 基础规则
                    └──┬───────┬──┘
          /api、SSE    │       │  /（页面）
┌──────────────────────▼───────▼──────────────── VPC（私有子网）──────────────────────────┐
│ app-1（8C16G）                           media-1（8C16G，按需扩 media-2）                 │
│   frontend（Next.js standalone）×1         backend-worker --queues=media ×1（FFmpeg）     │
│   backend-api ×2                                                                        │
│   backend-worker --queues=flow ×1        ops-1（4C8G）                                   │
│   backend-relay ×1                         OTel Collector、Prometheus、Grafana、Loki、Tempo │
│   agent-api ×1、agent-worker ×2            Temporal UI、Kafka UI（仅内网 / VPN）           │
│   temporal（frontend / history / matching / worker 服务）                                │
│                                                                                         │
│ 托管服务：云数据库 PostgreSQL（业务库 + Temporal 库，主备）· 缓存 Redis（主备）              │
│          消息队列 Kafka（3 broker）· 对象存储 TOS（私有桶）+ CDN · KMS                     │
│ NAT 网关 / 出口：agent-worker 访问模型供应商（境内出口 + 境外独立出口，白名单）               │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- MVP 内部使用（5 名并发用户），单套部署即可满足 REQ-02 §4；关键组件（API、agent-worker）双实例以支持滚动发布（AVL-04）。
- Temporal 自建（官方镜像）；持久化与可见性使用托管 PostgreSQL 的独立数据库与账号（DES-08 §5）。

## 3. 组件部署

| 组件 | 镜像 | 实例 | 资源限制 | 健康检查 | 端口（内网） |
| --- | --- | --- | --- | --- | --- |
| frontend | `lanverse/frontend` | 1 | 1C / 1G | `GET /healthz` | 3000 |
| backend-api | `lanverse/backend --role=api` | 2 | 1C / 1G | `GET /healthz`（存活）、`/readyz`（PG、Redis、Temporal 命名空间、对象存储） | 8080 |
| backend-worker（flow） | `lanverse/backend --role=worker --queues=flow` | 1 | 1C / 1G | Temporal Worker 心跳 + `/healthz` | 8081 |
| backend-worker（media） | 同上 `--queues=media` | 1 | 6C / 12G | 同上 | 8081 |
| backend-relay | `lanverse/backend --role=relay` | 1 | 0.5C / 512M | Outbox 积压 + `/healthz` | 8082 |
| agent-api | `lanverse/agent api` | 1 | 1C / 1G | `GET /internal/health` | 8090 |
| agent-worker | `lanverse/agent worker` | 2 | 1C / 2G | Worker 心跳 | — |
| temporal | `temporalio/server`（固定版本） | 1 | 2C / 4G | 自带 | 7233 |
| temporal-ui | `temporalio/ui` | 1 | 0.25C / 256M | — | 8233（仅 VPN） |

- Worker、Relay 的 `GET /healthz` 是进程存活探针；监听地址分别由 `LV_WORKER_HEALTH_ADDR`、`LV_RELAY_HEALTH_ADDR` 指定，默认 `:8081`、`:8082`。任务处理能力另看 Temporal Worker 心跳与 Outbox 积压。`media` 队列已接入；部署时须配置供应商结果来源白名单并挂载可写 `/work` 临时卷。
- 容器以非 root、只读根文件系统运行；media Worker 挂载临时卷 `/work`（DES-07 §9）。
- 本地三端直接运行，连接本机已运行的服务，不通过 Docker 启动环境。后续容器化部署保留两份独立 Compose 文件：`docker-compose.yml` 定义应用服务，`docker-compose-env.yml` 定义依赖服务；本机进程只读取根目录 `.env`。
- `docker-compose-env.yml` 完整描述 PostgreSQL、Redis、Kafka、MinIO、Temporal 及管理界面，供后续容器化部署使用；本地开发不执行该 Compose 文件。部署应用时单独执行 `docker compose up -d --build`。

## 4. 网络与域名

| 项 | 设计 |
| --- | --- |
| 域名 | `lanverse.<公司域名>`（生产）、`staging.lanverse.<公司域名>`；ICP 备案【对外发布前】 |
| 证书 | CLB 托管证书，自动续期；HSTS |
| 路由 | `/api/*` 与 SSE → backend-api；其余 → frontend；SSE 连接空闲超时 ≥ 35 分钟（DES-03 §5.1 连接 30 分钟主动关闭） |
| 安全组 | 公网只开放 CLB 443；实例间按端口最小开放；托管服务仅允许 VPC 内访问 |
| 出口 | NAT 网关；agent-worker 出站白名单为供应商域名；OpenRouter 走独立出口（可单独关闭，CMP-06） |
| 管理访问 | 运维通过 VPN / 堡垒机访问 ops-1、Temporal UI、Kafka UI、Grafana（DES-07 §9，SC-Q2） |
| 对象存储 | 浏览器直传 / 直下 TOS 使用预签名 URL；桶配置 CORS 只允许本站域名 |

本机 HTTP 开发按 DES-03 IF6 的本轮采纳合同：Next.js 同源 `/api` rewrite 到 `LV_API_BASE_URL` 的本机 Go 地址，浏览器使用 `LV_PUBLIC_ORIGIN`，后端按该配置校验登录和写命令 Origin。仅 `LV_ENV=local` 可使用 loopback HTTP 并关闭 Cookie Secure；staging/prod 强制 HTTPS 与 Secure，不从代理 Host 猜源。MVP 不注册供应商 callback/webhook，也不纳入公共 API 文档，先走轮询和对账。

## 5. 配置与密钥

- **配置**：环境变量（12-factor）；本地进程由根目录 `.env` 提供，示例键见 `.env.example`，文件不得提交。Go 使用 Viper，Python 使用 pydantic-settings；启动时集中校验当前角色必需项，缺失即退出。应用 Compose 配置在 `docker-compose.yml`，依赖环境 Compose 配置在 `docker-compose-env.yml`，所需密钥通过 shell 或受控环境文件注入。
- **配置清单**（各能力接入时逐项启用）：

| 变量 | 服务 | 说明 |
| --- | --- | --- |
| `LV_DB_DSN` | backend | API 启动必需；本地指向本机业务库，部署时可经 PgBouncer |
| `LV_PARTITION_MAINTENANCE_DB_DSN` | backend 分区维护命令 | `lanverse partitions ensure` 必需；指向同一业务库中拥有 Outbox 和审计父表的独立账号，普通进程不使用 |
| `LV_REDIS_URL` | backend、agent-worker | API 启动必需；就绪探针检查连通性，Relay 和 Agent Worker 已使用 |
| `LV_SESSION_IDLE_TTL`、`LV_SESSION_ABSOLUTE_TTL` | backend-api | Redis 会话空闲与绝对期限；默认 `12h`、`168h`，绝对期限不得短于空闲期限 |
| `LV_API_BASE_URL` | frontend 服务端 | 本机 Go API 根地址，仅供 Next.js `/api` rewrite，不公开给浏览器 |
| `LV_PUBLIC_ORIGIN` | backend-api | 精确公开前端源，登录/写命令 Origin 校验；local HTTP 仅 loopback，staging/prod 必须 HTTPS |
| `LV_KAFKA_BROKERS` | backend-relay | franz-go 已用于 Outbox 投递与实时事件消费；SASL 认证配置尚未接入 |
| `LV_TEMPORAL_ADDR`、`LV_TEMPORAL_NAMESPACE` | backend、agent-worker | API 启动必需；命名空间 `lanverse-<env>`，就绪探针检查服务与命名空间；Go 与 Agent Worker 均已连接 |
| `LV_OBJECT_STORAGE_ENDPOINT`、`LV_OBJECT_STORAGE_BUCKET`、`LV_OBJECT_STORAGE_ACCESS_KEY`、`LV_OBJECT_STORAGE_SECRET_KEY`、可选 `LV_OBJECT_STORAGE_REGION` | backend | API 启动必需；开发 MinIO / 生产 TOS（均兼容 S3 协议）；就绪探针只读检查已存在的私有桶 |
| `LV_CREDENTIAL_PUBLIC_KEY`、`LV_CREDENTIAL_KEY_ID` | backend-api | 凭据封装公钥（DES-07 §5.2） |
| `LV_CREDENTIAL_PRIVATE_KEY_REF`、`LV_CREDENTIAL_KEY_ID` | agent-worker | 凭据解封密钥引用与标识；当前开发实现为绝对路径的 PEM 私钥文件，生产 KMS 接入待实施。两项同时缺失时凭据测试返回不可用 |
| `LV_SERVICE_TOKEN_KEY` | backend、agent-api | 服务间签名密钥 |
| `LV_OTEL_ENDPOINT` | backend、agent-worker | 可选 OTLP/HTTP Collector 根地址，例如 `http://127.0.0.1:4318`；留空时禁用导出但保留跨进程追踪上下文，提供地址时校验格式并导出追踪 |

- **密钥**：生产由密钥管理服务注入（KMS 或部署机上的受控文件，权限 0400），不写入镜像、Compose 文件与仓库；`.env` 仅本地使用且在 `.gitignore` 中（DES-07 §5）。

### 5.1 审计表数据库权限

应用以非表所有者的数据库登录角色连接，迁移与分区维护使用另外的高权限角色。部署数据库管理员先创建集群级 `lanverse_app` 非登录权限角色（`CREATE ROLE lanverse_app NOLOGIN`），再创建独立的 `LOGIN INHERIT NOSUPERUSER NOCREATEDB NOCREATEROLE` 应用账号并执行 `GRANT lanverse_app TO <应用账号>`；然后由表所有者执行迁移。审计权限迁移只向 `lanverse_app` 授予 `audit` schema 的 `USAGE` 和父表 `audit.audit_log` 的 `INSERT, SELECT`；运行时权限迁移按当前仓储所需操作逐表授予其他业务表，新增业务表须在自身迁移中补充授权。应用读写审计一律经父表，未来分区由维护角色创建。应用登录角色不能是审计表所有者，也不能继承其他可修改、删除或截断审计表的角色；部署前需实测这些操作被数据库拒绝。权限迁移回滚只撤销各自的授权，不删除可供其他数据库复用的集群角色。

管理员审计读取使用 `identity."user" ... FOR SHARE` 锁定账号行；按 PostgreSQL 的权限规则，应用登录角色还需在该表拥有查询列的 `SELECT` 和至少一列的 `UPDATE` 权限，现由运行时权限迁移授予。不能为了满足这项锁权限而向 `lanverse_app` 授予审计表的 `UPDATE`。接入受限账号时，本机根目录 `.env` 的 `LV_DB_DSN` 应指向应用登录角色，部署迁移凭据由受控环境单独提供。

## 6. 本地开发环境

本机先启动 PostgreSQL、Redis、Kafka、MinIO 和 Temporal，再检查根目录 `.env` 中对应地址与本机服务一致。Go API 启动时会连接 `LV_DB_DSN` 指向的数据库；若缺失或不可达则退出。`LV_REDIS_URL`、`LV_TEMPORAL_ADDR`、`LV_TEMPORAL_NAMESPACE` 或必需的 `LV_OBJECT_STORAGE_*` 缺失或格式错误时，API 启动失败；Redis、Temporal 或对象存储暂不可达时 API 继续运行，`/readyz` 返回 503，`/healthz` 保持存活状态。对象存储的私有桶须提前创建并授予后端凭据访问权限；健康检查只验证桶存在且可访问，不创建桶或写对象。`LV_OTEL_ENDPOINT` 使用 OTLP/HTTP 根地址，Go 与 Agent Worker 均向其 `/v1/traces` 发送追踪；本机未启动 Collector 时留空禁用导出，仍传播工作流与 Activity 的追踪上下文，API 的就绪状态不依赖追踪服务。`.env` 已存在时保留原文件，不用示例覆盖；本机进程从该文件读取配置。已有本地配置若仍使用 `LV_S3_*`，需改为 `LV_OBJECT_STORAGE_*`。两份 Compose 文件供后续容器化部署使用，不作为本地开发启动命令，也不作为覆盖文件叠加。容器化部署的 `LV_OBJECT_STORAGE_ENDPOINT` 与 `LV_OTEL_ENDPOINT` 须填写后端容器可访问的地址，不能沿用指向容器自身的 `127.0.0.1` 示例地址。

```bash
pg_isready -h 127.0.0.1 -p 5432
redis-cli -h 127.0.0.1 ping
kafka-broker-api-versions --bootstrap-server 127.0.0.1:9092
curl -fsS http://127.0.0.1:9000/minio/health/live
temporal operator cluster health --address 127.0.0.1:7233
temporal operator namespace describe --address 127.0.0.1:7233 --namespace lanverse-local
```

MinIO 的 HTTP 存活探针不验证桶权限；从仓库根目录执行 `cd backend && LV_TEST_OBJECT_STORAGE=1 LV_ENV_FILE="$(pwd)/../.env" go test ./tests/objectstorage -run '^TestPingWithHostObjectStorage$' -count=1 -v`，只读验证 `.env` 中凭据对目标私有桶的访问。`go test` 在测试包目录运行，因此此处将 `LV_ENV_FILE` 展开为绝对路径。

首次使用且 `lanverse-local` 命名空间不存在时，在本机已运行的 Temporal 中执行 `temporal operator namespace create --address 127.0.0.1:7233 --namespace lanverse-local --retention 72h`。此命名空间已于 2026-09-27 在本机创建；新环境仍需按上述命令单独创建。命名空间名称应与根目录 `.env` 的 `LV_TEMPORAL_NAMESPACE` 一致。

数据库迁移完成且 Go `flow` Worker 已部署后，本机直启环境在仓库根目录执行 `cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse temporal setup`，向现有 Temporal 命名空间安装 `outbox-cleanup`、`processed-event-cleanup` 和五分钟一次的 `quote-expiry`。后续容器化部署须先独立确认迁移完成、`flow` Worker 就绪且容器内 `LV_TEMPORAL_ADDR` 可达，再显式执行 `docker compose --profile maintenance-setup run --rm backend-temporal-setup`；该一次性服务不随普通 `up` 自动启动，也不会代为启动 Worker，退出码 0 才表示安装成功。之后由 Temporal 按 UTC 每日触发清理，并每五分钟扫描过期报价。重复执行只接受定义一致的 Schedule，并保留已有暂停状态；定义漂移时报错。`partition-maintain` 尚未安装。隔离验证可加 `--prefix=验证前缀-`，验证后须删除带此前缀的测试 Schedule。

应用迁移完成、`LV_DB_DSN` 已使用真实的受限登录账号（不能以超级用户登录后切换角色）且 `LV_PARTITION_MAINTENANCE_DB_DSN` 已使用同库独立表所有者账号后，在仓库根目录手动执行 `cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse partitions ensure`。命令在同一事务内准备 Outbox 和审计当前 UTC 月及未来三个月的分区，任一方失败会整体回滚；执行时独占锁可能短暂阻塞写入，应在低流量窗口运行。该命令不做三年审计冷归档或历史分区删除，也不安装 `partition-maintain` Schedule；这两项边界完成前须由运维人员按月手动预备。

Kafka CLI 如由 Homebrew 安装但未加入 `PATH`，可用 `$(brew --prefix kafka)/bin/kafka-broker-api-versions`。该命令核验 Broker 协议；接入 Kafka 的任务仍需做生产与消费验证。确认服务可用后，分别在独立终端直接运行：

```bash
cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse --role=api
cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse --role=worker --queues=flow,media
cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse --role=relay
cd agent && uv run --env-file ../.env uvicorn app.main_api:create_app --factory --port 8090
cd agent && uv run --frozen --env-file ../.env python -m app.main_worker
cd frontend && node --env-file=../.env "$(command -v corepack)" pnpm exec next dev
```

本机也可用 `cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse --role=all` 合并运行 API、`flow` 与 `media` Worker 和 Relay；此时不要再单独启动这三个 Go 角色。任一角色失败时会停止并等待其余角色退出。

每条命令从仓库根目录起始、在独立终端执行。根目录 `.env` 供本机进程读取；不用项目脚本或 Makefile。Go Worker 的 `flow` 队列执行工作流与基础设施维护任务，`media` 队列执行媒体接管与审核 Activity；同一 Worker 进程监听两条队列，共用 `LV_WORKER_HEALTH_ADDR`，无需占用第二个健康端口。Go Relay 需要先应用 Outbox、消费标记与审计日志迁移，账号创建命令另需账号迁移。Kafka 禁止自动建主题；部署方须在启动 Relay 前预建当前 Outbox 生产或消费的 `lanverse.audit.recorded.v1`、`lanverse.identity.user_changed.v1`、`lanverse.catalog.credential_changed.v1`、`lanverse.catalog.provider_changed.v1`、`lanverse.workspace.project_changed.v1`、`lanverse.billing.budget_changed.v1`、`lanverse.billing.budget_low.v1`、`lanverse.billing.budget_overrun.v1`、`lanverse.billing.settled.v1`、`lanverse.operation.confirmed.v1`、`lanverse.batch.confirmed.v1`、`lanverse.batch.finished.v1`、`lanverse.operation.status_changed.v1`、`lanverse.operation.completed.v1`、`lanverse.operation.failed.v1`、`lanverse.operation.manual.v1`。当前 Agent Worker 监听模拟供应商的 `agent.mock` 与模拟 Skill 的 `agent` Activity 队列；真实模型与业务 Skill 尚未接入。中间件的启动、停止和数据保留由本机服务管理器负责。隔离的 PostgreSQL 逻辑备份恢复演练使用新建的临时数据库，不读取或覆盖业务库。目标：新人 30 分钟内连接完整本地环境（REQ-02 MNT-05）。

## 7. 初始化与种子数据

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 迁移 | `lanverse migrate up` | 只由部署流水线执行（OPS-02） |
| 首个管理员 | `cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse admin bootstrap --login-name <name>` | 先应用 Outbox、账号和组织迁移；从交互终端输入并确认初始密码，不接受管道或默认密码；若尚无组织则同事务创建；首次登录强制改密（REQ-06） |
| 内置数据 | `lanverse seed builtin` | 能力字典、5 套内置风格预设；复用 bootstrap 创建的组织（命令待实施） |
| 模型注册表 | `lanverse seed catalog backend/db/seed/catalog.yaml` | P0 后的模型、限制、价格（生产由管理员在界面维护，种子只用于初始化） |
| 分区 | `cd backend && LV_ENV_FILE=../.env go run ./cmd/lanverse partitions ensure` | 使用独立表所有者账号，在同一事务预备 Outbox 与审计当前及未来 3 个月分区；暂由运维按月执行 |
| Temporal | `lanverse temporal setup` | 检查现有命名空间并安装两项清理 Schedule 与 `quote-expiry`（DES-04 §11） |

`admin bootstrap` 只可在空账号库中成功一次；若组织已由先前初始化创建，命令复用唯一启用组织。测试或部署时不要把初始密码放入参数、环境变量或日志。可选 `--display-name`、`--org-name`，其中组织名称仅用于首次创建。后续账号由已登录管理员创建。
