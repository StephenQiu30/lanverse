## 2. 备份范围与策略

| 数据 | 是否备份 | 策略 | 保留 |
| --- | --- | --- | --- |
| 业务库（PostgreSQL） | 是 | 托管服务自动全量备份（每日）+ 持续日志备份（PITR）；另每周逻辑导出（`pg_dump`，加密）到异地 TOS 桶 | 自动备份 30 天；逻辑导出 12 周 |
| Temporal 库 | 是 | 同上（同实例独立库） | 30 天 |
| 对象存储（TOS） | 是 | 桶开启版本控制；关键前缀（成片、锁定参考、剧本原文、授权材料）跨区域复制；生命周期：非当前版本 30 天后删除 | 见左 |
| Redis | 否 | 可丢失、可从 PostgreSQL 重建（DES-08 §6）；托管主备保证可用性 | — |
| Kafka | 否（依赖 Outbox） | 事件以 Outbox 为源；消费者幂等，可从 Outbox 重放 | Outbox 7 天 |
| 可观测数据 | 否 | 可丢失 | — |
| 配置与部署文件 | 是 | 仓库（`deploy/`）；密钥在 KMS / 密钥管理（不入库） | Git 历史 |
| 密钥 | 是 | KMS 托管；凭据封装私钥有离线备份（加密、双人保管） | 永久 |

备份监控：每次备份结果进入指标；失败即 P1 告警（OPS-03 §6）。

## 3. 恢复流程

### 3.1 业务库时间点恢复（误操作、数据损坏）

```text
1. 宣布事件（§5），冻结写入：将 backend-api 切为只读模式（LV_READ_ONLY=true，写接口返回 503），暂停 worker 与 relay
2. 确定恢复时间点 T（损坏发生前），通过托管服务 PITR 恢复到新实例
3. 在新实例上校验：关键表行数、最近业务记录、账本对账脚本（ledger-reconcile --dry-run）
4. 选择：
   a. 整体切换：修改 LV_DB_DSN 指向新实例（Temporal 库同时恢复到同一时间点）
   b. 局部修复：只把受影响的数据从新实例导出、导入到现网（适合小范围误删）
5. 处理 T 之后的在途工作流：Temporal 与业务库一起回到 T 时，T 之后确认的操作会丢失 → 用供应商侧调用记录（provider_call 之外的供应商控制台 / 账单）核对是否已付费，已付费的通过 manual 流程补录
6. 解除只读，恢复 worker 与 relay；relay 重放 Outbox
7. 通知用户受影响范围；记录复盘
```

### 3.2 对象存储恢复

- 误删对象：从版本控制恢复非当前版本（`tos` CLI / 控制台），或从复制区域拷回。
- 与数据库不一致（数据库有记录、对象缺失）：每日 `REL-09` 校验任务报告缺失对象 → 按上述方式恢复；无法恢复的媒体标记 `failed` 并通知。

### 3.3 整站重建（区域级故障或环境损毁）

```text
1. 在同地域新可用区（或备用地域）按 OPS-01 创建资源（Compose + 托管服务）
2. 恢复 PostgreSQL（最近备份 + 日志）与 Temporal 库；TOS 切换到复制桶或原桶
3. 部署最近生产镜像 sha；执行 lanverse migrate status 确认版本一致
4. 冒烟测试（OPS-02 §4）→ 切换 DNS / CLB
5. 在途任务按 3.1 第 5 步核对
```

目标 RTO ≤ 4 小时，依赖 OPS-01 的部署脚本可一键执行。

## 4. 演练计划

| 演练 | 频率 | 环境 | 通过标准 |
| --- | --- | --- | --- |
| 业务库 PITR 到指定时间点并校验 | 每季度 | staging（用生产备份的脱敏副本或 staging 自身备份） | 数据与时间点一致；用时记录 |
| 整站重建 | 每半年 | 独立临时环境 | ≤ 4 小时完成并冒烟通过 |
| 对象误删恢复 | 每季度 | staging | 版本恢复成功 |
| 供应商故障（模拟） | 每月（夜间故障注入覆盖） | staging | TST-01 §7 期望全部满足 |
| 凭据轮换 | 每年 | production（计划窗口） | 新凭据生效，旧凭据停用，无任务失败 |

演练记录存 `docs/acceptance/drill-<日期>-<类型>.md`：步骤、耗时、问题、改进项。

## 5. 事件响应

### 5.1 事件分级

| 级别 | 定义 | 对应 |
| --- | --- | --- |
| SEV1 | 服务不可用；数据丢失或损坏；重复计费或账本不平；安全事件（凭据泄露、越权） | P1 告警、S1 缺陷 |
| SEV2 | 核心流程不可用但有替代；单一供应商全面故障；大面积任务失败或卡住 | P2 告警、S2 缺陷 |
| SEV3 | 局部功能异常、性能下降 | P3 告警、S3 缺陷 |

### 5.2 响应流程

```text
发现（告警 / 用户反馈）→ 确认并定级（15 分钟内，SEV1）
→ 指定处置负责人（1–2 人团队：值守人即负责人，产品负责人知会）
→ 止损优先：切只读、停用供应商或模型、暂停批量、回滚发布、停用凭据
→ 沟通：SEV1 / SEV2 在内部群发布状态（开始、每 30 分钟更新、恢复）；影响用户时站内公告
→ 恢复与验证 → 关闭事件
→ 复盘（SEV1 / SEV2 必须，5 个工作日内）
```

### 5.3 常用止损开关

| 开关 | 方法 | 影响 |
| --- | --- | --- |
| 全站只读 | 环境变量 `LV_READ_ONLY=true` 滚动重启 api | 所有写接口 503，浏览与下载可用 |
| 停用模型 / 供应商 | 管理界面停用模型或凭据（REQ-07、REQ-08） | 新报价拒绝，在途继续 |
| 暂停全部新提交 | 暂停 `agent.<provider>` 队列的 Worker（缩到 0） | 任务排队不丢失 |
| 暂停批量 | 对批次发送 `cancel` 或等待熔断 | 未开始项取消 |
| 关闭境外出口 | 关闭 OpenRouter 出口路由 | 境外模型调用失败（按 not_submitted 处理） |

## 6. 处置手册（Runbook）

| 编号 | 场景 | 判断 | 处置 |
| --- | --- | --- | --- |
| RB-01 | 服务不可用 / 错误率高 | 看总览看板：哪个服务、何时开始、是否与发布相关 | 与发布相关 → 回滚（OPS-02 §7）；依赖故障（PG / Redis / Kafka）→ 按 RB-05 / RB-08；资源耗尽 → 扩容或重启；持续则切只读并升级为 SEV1 |
| RB-02 | 某供应商失败率高 | 生成链路看板按供应商查看错误码分布；查供应商状态页 | 供应商故障 → 停用其模型（报价拒绝），在途任务等待恢复；错误码为参数类 → 检查注册表最近变更并回退版本；配额类 → 联系供应商 / 充值 |
| RB-03 | unknown / manual 堆积 | 任务中心筛选；看 `provider_call` 最后结果 | 供应商查询接口故障 → 等待恢复后 watchdog 自动对账；不支持查询的 → 管理员登录供应商控制台逐条核对，按 REQ-24 处理 resolve-manual |
| RB-04 | 任务队列积压 | Temporal UI 查看队列与 Worker 数 | Worker 掉线 → 重启；负载高 → 扩容 media / agent Worker；供应商限流 → 降低并发，保持排队 |
| RB-05 | Outbox 积压 / 消费延迟 | relay 日志、Kafka 健康 | Kafka 不可用 → 等待恢复（业务不受影响，事件稍后补发）；消费者报错 → 修复后重启，幂等保证可重放；需要时对单条毒消息记录并跳过（写审计） |
| RB-06 | 重复计费嫌疑 / 账本差异 | 按 `provider_request_key` 与 operation 查询全部 `provider_call` 与账本分录；对照供应商账单 | 立即暂停对应供应商新提交；确认为平台缺陷 → SEV1，修复后用 `adjust` 分录更正账本（REQ-32），联系供应商申请退款；确认为供应商重复扣费 → 申诉并记录 |
| RB-07 | 凭据疑似泄露 | 供应商用量异常、扫描命中 | 立即在供应商侧吊销该密钥 → 平台停用凭据 → 生成新凭据并在平台设置（REQ-07）→ 审计近期访问 → 查明泄露途径 → SEV1 复盘 |
| RB-08 | 数据库异常（连接满、慢、磁盘满） | 慢查询日志、连接来源 | 连接满 → 检查 PgBouncer 与泄漏的服务；慢查询 → 定位 SQL 与缺失索引（临时 `CREATE INDEX CONCURRENTLY`）；磁盘 → 清理过期分区 / 扩容；主备切换期间应用重试自动恢复 |
| RB-09 | 渲染失败增多（V2） | 失败原因类别、FFmpeg 日志摘要 | 素材问题 → 定位具体片段并在剪辑中替换；资源问题 → 扩 media 节点；FFmpeg 版本回归 → 回滚镜像 |
| RB-10 | 越权或安全漏洞报告 | 复现、影响范围 | 关闭相关入口（开关或回滚）→ 修复 → 审计受影响数据访问 → 按需通知 → SEV1 复盘 |

每个 Runbook 在 M1 起落地为 `deploy/runbooks/RB-xx.md`，包含具体命令与查询语句，并在演练中验证。

## 7. 事后复盘模板

```markdown
# 事件复盘：<标题>（SEV?）
- 时间线：发现、定级、止损、恢复、关闭（精确到分钟）
- 影响：用户、项目、费用、数据
- 根因：技术原因与流程原因（5 个为什么）
- 做得好的 / 需要改进的
- 改进项：负责人、截止时间、跟踪 Issue
```

复盘不追究个人责任，关注系统与流程改进；改进项纳入 PLN-02 任务管理。
