## 1. 环境

| 环境 | 用途 | 部署形态 | 数据 | 供应商 |
| --- | --- | --- | --- | --- |
| local | 开发 | Docker Compose（全部组件单机） | 种子数据 | 模拟供应商；可选真实（个人测试凭据，严格预算） |
| ci | 自动化测试 | GitHub Actions + testcontainers / Compose | 每次重建 | 模拟供应商 |
| staging（预发） | 集成、端到端、性能、故障注入、验收预演、迁移演练 | 单台云服务器 Docker Compose（中间件自建容器） | 脱敏样例 + 合成大项目 | 模拟为主；真实供应商冒烟（每日 ¥20 上限） |
| production | 内部生产使用 | 云服务器 + Docker Compose；数据库、Redis、Kafka、对象存储使用托管服务 | 真实 | 真实 |

各环境数据、凭据、密钥、存储桶完全隔离（0202 OPS-02）；staging 不允许读取生产数据。

## 2. 生产拓扑

```text
                       Internet
                           │ HTTPS（lanverse.<域名>）
                    ┌──────▼──────┐
                    │ CLB 负载均衡 │  TLS 终止、WAF 基础规则
                    └──┬───────┬──┘
          /api、SSE    │       │  /（页面）
┌──────────────────────▼───────▼──────────────── VPC（私有子网）──────────────────────────┐
│ app-1（8C16G）                           media-1（8C16G，按需扩 media-2）                 │
│   frontend（Next.js standalone）×1         backend-worker --queues=media ×1（FFmpeg）     │
│   backend-api ×2                                                                        │
│   backend-worker --queues=flow ×1        ops-1（4C8G）                                   │
│   backend-relay ×1                         OTel Collector、Prometheus、Grafana、Loki、Tempo │
│   agent-api ×1、agent-worker ×2            Temporal UI、Kafka UI（仅内网 / VPN）           │
│   temporal（frontend / history / matching / worker 服务）                                │
│                                                                                         │
│ 托管服务：云数据库 PostgreSQL（业务库 + Temporal 库，主备）· 缓存 Redis（主备）              │
│          消息队列 Kafka（3 broker）· 对象存储 TOS（私有桶）+ CDN · KMS                     │
│ NAT 网关 / 出口：agent-worker 访问模型供应商（境内出口 + 境外独立出口，白名单）               │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- MVP 内部使用（5 名并发用户），单套部署即可满足 0202 §4；关键组件（API、agent-worker）双实例以支持滚动发布（AVL-04）。
- Temporal 自建（官方镜像）；持久化与可见性使用托管 PostgreSQL 的独立数据库与账号（0308 §5）。

### 2.1 规格估算（初始）

| 资源 | 规格 | 依据 |
| --- | --- | --- |
| app-1 | 8 vCPU / 16 GB / 100 GB 云盘 | API、Worker、Temporal、Agent 服务均为 I/O 型 |
| media-1 | 8 vCPU / 16 GB / 500 GB 云盘（临时文件） | FFmpeg 并发 4；2 分钟成片渲染 ≤ 5 分钟（PERF-08）【P0 实测校准】 |
| ops-1 | 4 vCPU / 8 GB / 200 GB | 可观测栈，日志保留 30 天 |
| PostgreSQL | 4 vCPU / 16 GB / 500 GB SSD，主备 | 50 项目约 100–200 GB（0302 §8） |
| Redis | 4 GB 主备 | 会话、缓存、SSE 缓冲 |
| Kafka | 最小规格 3 broker，保留 7 天 | 事件量小；可靠性优先 |
| TOS | 标准存储 + 低频存储（未选定候选 90 天后转低频） | 单部 80 集剧约 250 GB（CAP-04） |

## 3. 组件部署

| 组件 | 镜像 | 实例 | 资源限制 | 健康检查 | 端口（内网） |
| --- | --- | --- | --- | --- | --- |
| frontend | `lanverse/frontend` | 1 | 1C / 1G | `GET /healthz` | 3000 |
| backend-api | `lanverse/backend --role=api` | 2 | 1C / 1G | `GET /healthz`（存活）、`/readyz`（PG、Redis、Temporal 连通） | 8080 |
| backend-worker（flow） | `lanverse/backend --role=worker --queues=flow` | 1 | 1C / 1G | Temporal Worker 心跳 + `/healthz` | 8081 |
| backend-worker（media） | 同上 `--queues=media` | 1 | 6C / 12G | 同上 | 8081 |
| backend-relay | `lanverse/backend --role=relay` | 1 | 0.5C / 512M | Outbox 积压 + `/healthz` | 8082 |
| agent-api | `lanverse/agent api` | 1 | 1C / 1G | `GET /internal/health` | 8090 |
| agent-worker | `lanverse/agent worker` | 2 | 1C / 2G | Worker 心跳 | — |
| temporal | `temporalio/server`（固定版本） | 1 | 2C / 4G | 自带 | 7233 |
| temporal-ui | `temporalio/ui` | 1 | 0.25C / 256M | — | 8233（仅 VPN） |

- 容器以非 root、只读根文件系统运行；media Worker 挂载临时卷 `/work`（0307 §9）。
- Compose 文件：`deploy/compose/base.yml`（服务定义）+ `local.yml`（本地中间件容器、模拟供应商）+ `staging.yml` + `prod.yml`（托管服务地址、实例数、资源限制）。

## 4. 网络与域名

| 项 | 设计 |
| --- | --- |
| 域名 | `lanverse.<公司域名>`（生产）、`staging.lanverse.<公司域名>`；ICP 备案【对外发布前】 |
| 证书 | CLB 托管证书，自动续期；HSTS |
| 路由 | `/api/*` 与 SSE → backend-api；其余 → frontend；SSE 连接空闲超时 ≥ 35 分钟（0303 §5.1 连接 30 分钟主动关闭） |
| 安全组 | 公网只开放 CLB 443；实例间按端口最小开放；托管服务仅允许 VPC 内访问 |
| 出口 | NAT 网关；agent-worker 出站白名单为供应商域名；OpenRouter 走独立出口（可单独关闭，CMP-06） |
| 管理访问 | 运维通过 VPN / 堡垒机访问 ops-1、Temporal UI、Kafka UI、Grafana（0307 §9，SC-Q2） |
| 对象存储 | 浏览器直传 / 直下 TOS 使用预签名 URL；桶配置 CORS 只允许本站域名 |

## 5. 配置与密钥

- **配置**：环境变量（12-factor）；Go 使用 Viper，Python 使用 pydantic-settings；启动时集中校验，缺失即退出。
- **配置清单**（示例，完整清单在 `deploy/env/*.example`）：

| 变量 | 服务 | 说明 |
| --- | --- | --- |
| `LV_DB_DSN` | backend | 业务库（经 PgBouncer） |
| `LV_REDIS_URL` | backend、agent | — |
| `LV_KAFKA_BROKERS`、`LV_KAFKA_SASL_*` | backend | — |
| `LV_TEMPORAL_ADDR`、`LV_TEMPORAL_NAMESPACE` | backend、agent | 命名空间 `lanverse-<env>` |
| `LV_S3_ENDPOINT`、`LV_S3_BUCKET`、`LV_S3_ACCESS_KEY` 等 | backend | 开发 MinIO / 生产 TOS |
| `LV_CREDENTIAL_PUBLIC_KEY`、`LV_CREDENTIAL_KEY_ID` | backend-api | 凭据封装公钥（0307 §5.2） |
| `LV_CREDENTIAL_PRIVATE_KEY_REF` | agent | KMS 密钥引用（开发为本地文件路径） |
| `LV_SERVICE_TOKEN_KEY` | backend、agent-api | 服务间签名密钥 |
| `LV_OTEL_ENDPOINT` | 全部 | OTel Collector |

- **密钥**：生产由密钥管理服务注入（KMS 或部署机上的受控文件，权限 0400），不写入镜像、Compose 文件与仓库；`.env` 仅本地使用且在 `.gitignore` 中（0307 §5）。

## 6. 本地开发环境

```bash
make up          # docker compose -f deploy/compose/base.yml -f deploy/compose/local.yml up -d
make migrate     # golang-migrate 执行迁移
make seed        # 创建管理员、内置风格预设、模拟供应商模型注册表、样例项目
make dev         # 前端 pnpm dev、后端 air 热重载、Agent 服务 uvicorn --reload
make down
```

本地 Compose 包含：PostgreSQL（业务 + Temporal 两个库）、Redis、Kafka（KRaft 单节点）、MinIO、Temporal、Temporal UI、Kafka UI、模拟供应商、可观测栈（可选 profile `obs`）。目标：新人 30 分钟内跑起完整环境（0202 MNT-05）。

## 7. 初始化与种子数据

| 步骤 | 命令 | 说明 |
| --- | --- | --- |
| 迁移 | `lanverse migrate up` | 只由部署流水线执行（0602） |
| 首个管理员 | `lanverse admin bootstrap --login-name <name>` | 交互输入密码，首次登录强制改密（F01） |
| 内置数据 | `lanverse seed builtin` | 能力字典、5 套内置风格预设、组织 |
| 模型注册表 | `lanverse seed catalog deploy/seed/catalog.yaml` | P0 后的模型、限制、价格（生产由管理员在界面维护，种子只用于初始化） |
| 分区 | `lanverse partitions ensure` | 创建当前与未来 3 个月分区 |
| Temporal | `lanverse temporal setup` | 命名空间、Schedules（0304 §11） |

## 8. 扩展路径

| 触发 | 动作 |
| --- | --- |
| 媒体队列积压持续 > 30 分钟 | 增加 media 节点（media-2），Worker 自动加入 |
| agent 队列积压 | 增加 agent-worker 实例（受供应商配额约束） |
| API P95 超标 | backend-api 扩到 3 个实例 |
| 活跃项目 > 50 或团队 > 20 人 | 评估迁移到 Kubernetes（VKE【待核实】），Compose 服务定义映射为 Deployment；Worker 按队列积压自动扩缩（0308 §9） |
