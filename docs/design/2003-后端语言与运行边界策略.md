# 后端语言与运行边界策略

- 状态：已接受设计
- 日期：2026-08-25
- 范围：Go Backend、Python Agent Runtime、契约和运行时边界
- 派生文档：[后端运行架构需求规格](../requirement/2001-后端运行架构需求规格.md) · [后端运行架构实施计划](../plan/2001-后端运行架构实施计划.md)

## 结论

Lanverse 将业务事实、可靠工作流、Provider 接入、媒体处理和事件投影实现为一个 Go Module 中的五个 Binary；将有限推理、Skill、Prompt 和工具调用实现为独立 Python Agent Runtime。语言选择由运行职责决定，不由页面、表或算法偏好决定。

```text
Browser / Frontend
        │ REST / SSE
        ▼
lanverse-api (Go)
        │
        ├── PostgreSQL / Redis / ObjectStore
        ├── Kafka ↔ event-worker (Go)
        ├── Temporal ↔ workflow-worker (Go)
        │                  ├── gRPC → agent-runtime (Python)
        │                  ├── gRPC → model-gateway (Go)
        │                  └── gRPC → media-worker (Go)
        └── Internal gRPC / Event Contracts
```

## 语言边界

### Go Backend

Go 拥有：

- 业务聚合、状态机、授权、幂等、事务和 Outbox；
- 公共 REST/SSE 和 Backend 内部 gRPC；
- Temporal Workflow/Activity 和执行投影；
- Generation Capability、Provider Job、Callback 和费用/限额协调；
- 媒体 Probe、Derivative、Render 和 Export；
- Outbox/Inbox、DLQ、Replay、Audit/Search/分析投影；
- Schema Migration、运行配置、Health、Telemetry 和优雅停机。

Go Domain 不依赖框架、数据库、Kafka、Temporal、ObjectStore 或 Provider SDK。只有 Composition Root 可装配具体 Adapter。

### Python Agent Runtime

Python 只拥有：

- Structured、ToolLoop 和受限 LangGraph Executor；
- 版本化 Agent/Skill/Prompt/Rubric/Tool Policy 定义；
- 领域 Harness、确定性 Gate、有限 Repair 和结构化输出；
- Run 范围的预算、取消、Telemetry 和 Executor 生命周期。

Python Agent 不得连接 PostgreSQL、ObjectStore、Yjs、任意 Shell 或任意网络。它只能使用签名 Execution Grant 调用 Model Gateway，并通过 Backend Tool API Allowlist 读取与当前 Run 相关的最小上下文。

## 部署与网络边界

- Browser 只访问 `lanverse-api`、SSE、协作 WebSocket 和短期 Presigned ObjectStore URL。
- Go Binary 在同一部署边界内使用 Go Interface，跨进程才使用 gRPC/Protobuf。
- Kafka 只传递已提交事件，不承担同步请求、Workflow Timer、Human Wait 或 Token Stream。
- Temporal 只编排长任务、重试、Timer、Signal 和 Compensation；不保存业务聚合内容。
- Agent Runtime 和所有内部 Binary 都不暴露给 Browser。
- 每个 Binary 只获得完成自身职责的最小凭据和网络访问权。

## 契约所有权

```text
backend/api/openapi   公共 REST/SSE 事实源
backend/api/proto     Backend Binary RPC 事实源
backend/api/event     Kafka Event Schema 事实源
backend/api/gen       生成代码，不手改
agent/api/proto       Agent RPC 事实源
agent/definitions     Agent/Skill/Prompt/Rubric/Policy 定义源
```

契约变更顺序固定为 Design → Source Schema → Compatibility Test → Generate → Implement → E2E。Go 与 Python 不得分别维护语义相同但不可验证等价的 DTO、错误体或状态枚举。

## 运行不变量

1. 业务事实只能由 Go Application 层写入，Agent 不返回任意 SQL 或可直接执行的领域命令。
2. Agent 输出永远是结构化 Candidate 或 Decision Proposal，必须经 Backend 权限、版本和确定性 Gate 后才生效。
3. Agent 不直连 Provider；所有模型调用经 Model Gateway、Cost/Quota Claim 和审计。
4. Episode 级长生命周期只由 Temporal 编排，单次 Agent 调用必须有有限步数、调用次数、Token、费用和 deadline。
5. 跨进程返回结果未知时，必须按稳定 Intent/Invocation/Job ID 对账，不得将未知结果当成失败盲目重提。
6. Trace Context 跨 HTTP、gRPC、Temporal、Agent、Provider、Media 和 Kafka 传播，Secret 和用户内容不进入非必要日志/指标。

## 结果

该策略使 Go 专注可靠业务系统和跨进程协调，使 Python 专注受限 AI 执行。两种语言通过正式契约协作，不共享数据库模型、SDK 凭据或隐式运行状态。
