# 后端语言与运行边界策略

- 状态：已接受设计
- StoryGraph 边界复核：已接受（`SG-D05`，2026-08-27）
- 日期：2026-08-27
- 范围：Go Backend、Python Agent Runtime、契约和运行时边界
- 历史派生文档：[后端运行架构需求规格](../requirement/2001-后端运行架构需求规格.md) · [后端运行架构实施计划](../plan/2001-后端运行架构实施计划.md)；StoryGraph 重叠项按 `docs/README.md` 队列冻结

## 结论

Lanverse 将全部业务事实、可靠工作流、Provider/媒体协调和 Kafka 业务投影收口在一个 Go Module；将受限 AI 候选生成实现为 Backend 私有的 Python Agent Runtime。MVP 只保留已有真实运行职责的 `lanverse-api`、`workflow-worker` 和 `event-worker`，后两者只在对应 Temporal/Kafka 消费者实施时创建入口。`model-gateway` 或 `media-worker` 只在真实负载/资源隔离证明需要时拆分，不为目录完整性预建。

```text
Browser / Frontend
        │ REST / SSE
        ▼
lanverse-api (Go, 唯一业务 Writer)
        │
        ├── PostgreSQL/GORM / ObjectStore
        ├── Outbox → Kafka ↔ event-worker (Go)
        ├── Temporal ↔ workflow-worker (Go)
        │                  └── Private HTTP → agent-runtime (Python)
        ├── Kafka → Script/StoryGraph Search Projection
        └── JSON Log → Filebeat → Kafka → Logstash/Elasticsearch/Kibana
```

## 语言边界

### Go Backend

Go 拥有：

- 业务聚合、状态机、授权、幂等、事务和 Outbox；
- 公共 REST/SSE 和已接受的 Backend 私有契约；
- Temporal Workflow/Activity 和执行投影；
- Generation Capability、Provider Job、Callback 和费用/限额协调；
- 媒体 Probe、Derivative、Render 和 Export；
- Outbox/Inbox、DLQ、Replay、Audit/Search/分析投影；
- 唯一 GORM Model Catalog、运行配置、Health、Telemetry 和优雅停机。

Go Domain 不依赖框架、数据库、Kafka、Temporal、ObjectStore 或 Provider SDK。只有 Composition Root 可装配具体 Adapter。不创建 Migration 文件、不引入 `sqlc`/第二 ORM、不手写业务 SQL；PostgreSQL 是唯一 SQL 事实源，Kafka 和 Elasticsearch 只保存传输/可重建投影。

### Python Agent Runtime

Python 只拥有：

- `agent/skills/build-storygraph/` 内置 Skill Bundle 的加载、Hash 校验和 Stage Reference 注入；
- `StoryGraphHarness`、Pydantic 严格 Candidate Schema、有界 Review/Repair 和结构化输出；
- Backend 签名 Invocation Envelope/Policy 的严格消费、预算、取消和 Telemetry；
- 受控 Provider Adapter；本地开发可以调用 Codex CLI。

Python Agent 不得连接 PostgreSQL、ObjectStore、Kafka、Elasticsearch、Yjs 或 Backend 业务写 API，也不得使用任意 Shell、Web、浏览器或文件写工具。本地 Codex Provider 只能启动固定的 Codex CLI，Guidance/Schema 由 Harness 注入，工作目录不包含仓库源码。Agent 只返回 Candidate，不返回可直接执行的业务 Command。

## 部署与网络边界

- Browser 只访问 `lanverse-api`、SSE 和短期 Presigned ObjectStore URL；协作 WebSocket 是延后边界。
- Go Binary 在同一部署边界内使用 Go Interface，跨进程才使用已接受的最小私有契约；不为未来 Binary 预生成 gRPC/Protobuf。
- Kafka 只传递已提交事件，不承担同步请求、Workflow Timer、Human Wait 或 Token Stream。
- Temporal 只编排长任务、重试、Timer、Signal 和 Compensation；不保存业务聚合内容。
- Agent Runtime 和所有内部 Binary 都不暴露给 Browser。
- 每个 Binary 只获得完成自身职责的最小凭据和网络访问权。

## 契约所有权

```text
backend/api/openapi                 公共 REST/SSE 事实源
backend/internal/<owner>            领域 Command/Query/Event 唯一语义 Owner
backend/internal/agent              Invocation Envelope/Stage/Policy Owner
backend/internal/eventing           Kafka Envelope/Outbox/Inbox Owner
agent/app/candidate_runtime         Agent 私有运行契约严格消费者
agent/skills/build-storygraph       StoryGraph Guidance 唯一运行入口
backend/tests + agent/tests         版本化 canonical wire fixtures/契约验证
```

契约变更顺序固定为 Design → Red Contract Test/Fixture → Owner Schema → Implement → Cross-language Contract → E2E。Go 与 Python 不得分别维护语义相同但不可验证等价的 DTO、错误体或状态枚举。只在已接受传输格式确实需要生成时才创建生成目录。

## 运行不变量

1. 业务事实只能由 Go Application 层写入，Agent 不返回任意 SQL 或可直接执行的领域命令。
2. Agent 输出永远是结构化 Candidate，必须经 Backend 权限、版本、确定性 Gate、Human Gate 和 Owner Apply 后才生效。
3. Agent 只能通过 Backend 冻结的 Provider Adapter/Policy 调用模型；本地 Codex CLI 是允许的开发 Provider，但不获得业务写权。高成本调用仍经 Cost/Quota 授权与审计。
4. Episode 级长生命周期只由 Temporal 编排，单次 Agent 调用必须有有限步数、调用次数、Token、费用和 deadline。
5. 跨进程返回结果未知时，必须按稳定 Intent/Invocation/Job ID 对账，不得将未知结果当成失败盲目重提。
6. Trace Context 跨 HTTP、私有 Agent 调用、Temporal、Provider、Media 和 Kafka 传播，Secret 和未脱敏剧本内容不进入日志 Topic/Elasticsearch；Filebeat → Kafka → Logstash → Elasticsearch → Kibana 只承载已脱敏结构化日志。

## 结果

该策略使 Go 专注可靠业务系统和跨进程协调，使 Python 专注受限 AI 执行。两种语言通过正式契约协作，不共享数据库模型、SDK 凭据或隐式运行状态。
