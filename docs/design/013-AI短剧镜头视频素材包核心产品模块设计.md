# DES-013 AI 短剧镜头视频素材包核心产品模块设计

- 状态：proposed
- 日期：2026-08-14
- 决策来源：产品负责人明确当前阶段不建设剪辑、时间线或成片；参考 VibeReels 的逐镜候选、主选与批量下载方式
- 输入：[当前核心产品需求集](../requirement/README.md)、[当前需求总览](../requirement/001-当前核心产品需求总览.md)、[产品发现与竞品需求分析](../requirement/产品发现与竞品需求分析.md)
- 输出：当前核心产品模块、端到端结果、状态边界、镜头素材包设计和后续需求拆解基线
- 设计边界：只服务当前逐镜视频素材包产品终点，不继承旧时间线、整集渲染或商业平台范围

## 1. 产品决策

当前产品不是剪辑软件，也不以生成一个已拼接的成片 MP4 为完成条件。当前必须完成的用户结果是：

> 创作者把剧本推进为有序镜头，为每个镜头生成并比较多个视频候选，人工选择唯一当前采用视频，最后导出按镜头顺序组织、可交给外部后期继续处理的固定视频素材包。

产品主链路固定为：

```text
剧本确认
→ 角色/场景/道具资产设定
→ 分镜与镜头规格确认
→ 镜头关键帧与参考图确认
→ 逐镜视频生成
→ 每镜选择当前视频
→ 完整性与兼容性检查
→ 导出有序镜头视频素材包
```

“镜头顺序”来自已固定的 Storyboard/Shot 顺序，不等于剪辑时间线。导出复制原始主选视频并生成清单，不裁切、不拼接、不添加转场，也不改写媒体内容。

## 2. 事实与推导边界

### 2.1 VibeReels 可确认事实

[产品发现与竞品需求分析](../requirement/产品发现与竞品需求分析.md)中的只读审计支持以下产品事实：

- Episode 下存在有序 Shot；
- 一个 Shot 可保留多个视频版本；
- 用户可设置唯一主选并星标多个备选；
- 主选优先用于当前预览；
- 支持单版本下载及按集范围批量下载逐镜版本。

### 2.2 本产品的合理推导

VibeReels 的公开证据不能证明整集服务端渲染、专业时间线或确定性成片导出。因此本设计只借鉴“逐镜生产、候选比较、当前主选、批量下载”，并进一步规定：

- 正式导出只读取每镜显式主选，不使用“最新成功版本”静默兜底；
- 导出前冻结镜头顺序、选择和媒体版本；
- 输出包含有序独立视频文件及可追溯 Manifest；
- 后续更换主选不得改变历史导出包。

这些是 Lanverse 的产品决策，不表述为 VibeReels 已验证能力。

## 3. 当前范围与非目标

### 3.1 当前必须包含

1. 项目、Episode 和有序 Shot 的稳定上下文；
2. 剧本结构化、资产设定、分镜和镜头规格；
3. 镜头首帧/尾帧/参考图候选及当前选择；
4. 单镜头或选定镜头批量提交视频生成；
5. 每镜多个不可变视频候选、平台长任务投影、失败恢复和历史；
6. 每镜唯一当前视频、备选星标和选择历史；
7. 单候选下载、所选镜头导出和完整 Episode 镜头包；
8. 导出前完整性/兼容性检查、固定快照、Manifest、失败重试和历史重下；
9. Provider、任务、媒体、血缘和内部成本可见性等必要支撑。

### 3.2 当前明确不做

- 时间线、多轨剪辑、Clip、trim、变速、转场、特效和调色；
- 视频拼接、FFmpeg 整集渲染、单一成片 MP4；
- 独立 TTS、配音、BGM、音效、字幕编辑、口型或音画同步；
- 剪映、Premiere、Final Cut Pro 工程文件；
- 发布到短视频平台、播放平台或发行渠道；
- 套餐、支付、账单、退款、营销和商业运营后台；
- 复杂企业权限、实时多人同编和外部审片。

生成视频如果自带声音，当前只按原文件保存和导出，不做音轨处理。

## 4. 用户可见核心产品模块

### 4.1 M1 项目与剧集工作台

**用户结果**：创作者在一个项目中管理多集内容，并看到每集从剧本到镜头素材包的真实进度。

**负责**：

- Project、Episode 名称、顺序、状态和稳定身份；
- 画幅、内容类型、默认风格和模型用途等项目级制作约束；
- 聚合剧本、资产、分镜、视频选择覆盖率、异常任务和导出状态；
- 从问题摘要直接跳转到对应镜头。

**不负责**：剧本正文、镜头规格、候选媒体、生成任务或导出快照本身。

### 4.2 M2 剧本分析与叙事结构

**用户结果**：原始剧本被可靠分集和结构化，AI 结果可人工确认，改稿不会静默破坏已制作镜头。

**负责**：

- 原稿、分集、场景、对白、动作和叙事单元；
- AI 解析/改写候选、差异比较和人工发布；
- 剧本修订对资产、分镜和视频选择的影响提示。

**不负责**：直接生成资产、图片或视频。

### 4.3 M3 角色、场景与道具资产设定

**用户结果**：同一角色、场景和道具在不同镜头使用明确的剧情状态及固定参考版本。

**负责**：

- 角色、场景、道具身份及服装、时间、伤势等状态；
- 基础图、状态图、参考图的生成/上传候选和当前选择；
- 使用镜头和变更影响；
- 镜头生产前的资产 readiness。

**不负责**：跨项目素材市场或通用企业数字资产管理。

### 4.4 M4 分镜与镜头设计

**用户结果**：创作者获得有序、可编辑、覆盖必拍内容并可进入生成的镜头规格。

**负责**：

- AI 分镜候选及人工确认；
- 景别、机位、运动、动作、对白、情绪、目标时长和 Prompt；
- 镜头与叙事单元、资产状态和参考图的显式关系；
- 插入、复制、拆分、合并、删除和重排；
- coverage/readiness 与固定 ShotSpecVersion。

**不负责**：剪辑时间轴。目标时长是视频生成条件，不是可裁剪 Clip。

### 4.5 M5 镜头关键帧与视觉参考

**用户结果**：每个视频生成请求都使用已确认、可追溯的首帧、尾帧或参考图。

**负责**：

- 上传或生成镜头关键帧/参考图；
- 图片候选比较和当前选择；
- 固定生成所用图片及资产版本；
- 上游图片选择改变时标记相关视频选择过期。

**不负责**：复杂图片编辑、蒙版工作台或通用设计工具。

### 4.6 M6 镜头视频生成与候选选择

**用户结果**：创作者能在单镜头上下文完成生成、恢复、比较、选择和局部重做。

**负责**：

- 单镜头/选定镜头批量预检和提交；
- 视频业务请求、平台 WorkTask/ExecutionAttempt/CostRecord 投影和失败下一动作；
- 多个不可变视频候选和媒体持久化；
- 单候选预览、星标、淘汰和下载；
- 每镜唯一当前视频及追加式选择历史；
- 上游规格变化后的过期提示、人工确认沿用或重新生成。

**不负责**：裁切、拼接、转场、字幕、混音或成片。

### 4.7 M7 镜头检查与素材包导出

**用户结果**：创作者清楚知道哪些镜头尚未完成，并能导出固定、有序、可追溯的视频素材包。

**负责**：

- `目标基线全部 active Shot / 已有主选 / 待选择 / 失败 / 生成中 / 待重新确认` 汇总；
- 下载当前镜头、导出勾选镜头、导出本集全部当前镜头；
- 导出预检、固定选择快照、打包、校验、失败重试和历史重下；
- 独立视频文件、Manifest、shot-list 和说明文件。

**不负责**：把独立镜头加工为连续成片。

## 5. 产品模块与逻辑事实归属

下表从业务不变式推导逻辑事实所有者，不引用现有代码包、数据库或部署形态。用户可见模块也不等于未来必须拆成同名技术服务；技术映射应在 Requirement 接受后的架构 Design 中另行权衡。

| 用户行为 | 事实归属 | 说明 |
| --- | --- | --- |
| Episode 与进度摘要 | 项目与剧集上下文 | 只聚合，不复制镜头或任务事实 |
| 剧本、分集与叙事单元 | 剧本与叙事上下文 | 原稿、候选和发布修订分开 |
| 角色/场景/道具及状态 | 资产上下文 | 固定版本供 ShotSpec 引用 |
| 有序 Shot、规格和 readiness | 分镜上下文 | 镜头顺序不是 Timeline |
| 视频业务请求、候选、选择和导出快照 | 镜头生产上下文 | 选择和导出均固定业务输入；不复制平台任务/尝试/成本事实 |
| 长任务、实际尝试与内部消耗证据 | 平台执行上下文 | WorkTask、ExecutionAttempt、CostRecord 是跨业务唯一事实源，视频业务只保存类型化引用/投影 |
| 视频字节、hash、探测与包文件 | 媒体上下文 | 默认私有，提供受控下载 |
| 授权、问题和审计 | 治理上下文 | 不复制被审对象正文 |

Timeline、Render 和成片 Delivery 在当前阶段整体 deferred，不为其创建占位交接或空领域实体。

## 6. 四套独立状态

### 6.1 镜头规格状态

```text
draft → confirmed → stale
          ↑           |
          └─ re-confirm
```

### 6.2 单次生成任务状态

```text
queued → running → waiting_external → succeeded
                     ├→ failed
                     ├→ cancelled
                     └→ unknown → reconcile
```

### 6.3 镜头选择状态

```text
missing_selection → selected
              ├→ selected（追加新主选决定，旧选择保留为历史）
              └→ needs_reconfirmation → selected（追加当前输入摘要、操作者与理由）
```

### 6.4 导出状态

```text
validating → frozen → packing → ready
     ├→ blocked
     └→ failed → retry
```

镜头内容状态、Task 状态、选择状态和导出状态不得合并为一个“制作中/已完成”字段。一个 Shot 可以同时存在失败 Task、成功 Candidate 和有效主选。

## 7. 候选与主选规则

1. Candidate 一旦登记不得被新结果覆盖；
2. 每个 `Shot + video usage` 同时最多一个有效主选；
3. 重选追加 VideoSelection 决定，不删除旧候选或旧选择；
4. 星标只是备选标记，不等于当前主选；
5. 工作台预览可以在无主选时显示“最新成功候选”并明确标注临时状态；
6. 正式导出禁止临时兜底，缺少显式主选必须阻断；
7. 主选必须固定 Candidate、MediaVersion、ShotSpecVersion、关键帧和资产输入版本；
8. `stale` 是候选/选择相对当前目标输入的派生判断，不是媒体状态；上游固定输入变化时主选进入 `needs_reconfirmation`，用户必须重新生成或在查看差异后追加显式确认；
9. 单镜头失败不得使同批其他镜头丢失可用结果。

## 8. 导出入口与预检

工作台只提供三个明确入口：

1. 下载当前镜头；
2. 导出已勾选镜头；
3. 导出本集全部当前镜头。

“已勾选是否导出”和“镜头当前采用哪个候选”是两个独立决定。`scope=complete` 必须覆盖目标 StoryboardBaseline 内的全部 active Shot；无需交付的 Shot 必须先归档。`scope=partial` 只校验用户显式勾选的非空 active Shot 子集，并在 Manifest/README 列出 included/excluded 数量和 Shot ID，不得称为完整本集包。两种范围都拒绝 `needs_reconfirmation`。

预检至少返回：

- 缺少主选的镜头；
- 主选已过期的镜头；
- 候选与当前 ShotSpecVersion 不匹配的镜头；
- 媒体不可读、未完成探测或 hash 不一致的镜头；
- 分辨率、画幅、帧率、编码或音频轨差异；
- 权限或授权阻塞；
- 正在生成但尚无可导出结果的镜头。

系统不得为了统一规格而静默转码。兼容性差异应明确展示并写入清单，由外部后期决定如何处理。

## 9. 镜头素材包

### 9.1 最小目录

```text
<project-slug>/
  EP001/
    videos/
      001_<shot-id>_<candidate-id>.<原扩展名>
      002_<shot-id>_<candidate-id>.<原扩展名>
    manifest.json
    manifest.csv
    README.md
```

文件名中的显示镜号用于排序和人工识别，稳定 `shot-id` 用于追溯；镜号不得充当长期身份。

### 9.2 Manifest 最小内容

- package ID、项目、Episode、目标 StoryboardBaseline 及其固定 OrderRevision；
- ExportScope（complete/partial）、included/excluded Shot、创建人和创建时间；
- 每镜稳定 ID、显示镜号、order key 和文件名；
- Candidate、VideoSelection、MediaVersion 和 GenerationRequest/Task；
- ShotSpecVersion、Prompt/模型/关键参数快照；
- 角色、场景、道具、关键帧等固定输入版本；
- 实际时长、分辨率、帧率、编码、音轨、文件大小和 hash；
- 选择时间、重新确认决定、绑定的当前输入摘要、确认人和理由；
- 兼容性警告、缺失项和权限/授权摘要。

### 9.3 冻结与恢复

- 预检通过后冻结目标 StoryboardBaseline、其固定 OrderRevision、ExportScope、有序 Shot ID、每镜 ShotSpecVersion、VideoSelection、Candidate、MediaVersion/hash、warning/重新确认决定、冻结人和时间；
- 后续重排镜头或更换主选不得改变历史包；
- 相同固定输入和幂等键必须回读同一导出事实；
- 对象写入、Manifest 写入或完整性校验失败时不得标记 ready；
- 重试只能重建缺失包文件，不重新生成镜头视频；
- 保留期内重下同一 PackageBuild 时，文件集合、逐文件 hash 与包容器 hash 均不变；
- 包过期后从同一 ExportSnapshot 重建会产生新的 PackageBuild：Manifest 事实和逐文件 hash 必须一致，容器 hash 可因打包元数据不同而变化，旧构建记录不得改写；
- 历史包允许重新下载，短期下载地址不成为业务事实。

## 10. 页面结构

项目内保持同一制作上下文：

```text
项目概览
├─ 剧本
├─ 资产
├─ 分镜
├─ 镜头视频
│  ├─ Episode/问题筛选
│  ├─ Shot 列表
│  └─ 当前 Shot：规格、资源、任务、候选与主选
└─ 镜头导出
   ├─ 完成度与阻塞项
   ├─ 导出范围和兼容性预检
   └─ 历史素材包
```

镜头视频页优先呈现创作语言；供应商通道、原始错误、模型版本等技术信息放入高级详情。长剧必须支持只看待选择、失败、生成中、已过期和不兼容镜头。

## 11. 验收 Gate

### G1 模块需求接受

- M1～M7 的用户场景、边界、失败路径和验收标准均已接受；
- “成片”“交付”和“下载包”术语不再混用；
- 真实视频 Provider、参数、权利和费用有可验证条件。

### G2 逐镜生产接受

- 一集目标 StoryboardBaseline 内 N 个 active Shot 可独立提交、恢复和产生多个候选；
- 每镜可显式选择唯一当前视频并保留历史；
- 单镜失败不破坏其他镜头。

### G3 素材包接受

- 完整包严格包含 N 个按固定镜头顺序命名的主选视频；
- 缺主选、过期、媒体不可用或权限失败会指向具体镜头并阻断；
- Manifest 可从文件追溯到镜头规格、固定资产/关键帧、生成任务和选择决定；
- 更换主选后历史 ExportSnapshot 与旧 PackageBuild 内容/hash 不变化；从同一 Snapshot 过期重建时按 9.3 的双层 hash 语义验收；
- 本 Gate 不要求 Timeline、拼接、字幕、音频后期或成片 MP4。

## 12. 工期估算前置条件

此前“完整商业平台”顶部估算随范围变化失效，不通过简单减去剪辑或商业模块修正。新的开发周期必须在以下工作完成后自底向上形成：

1. M1～M7 逐模块 Requirement 及 AC 接受；
2. 真实视频 Provider PoC 和失败/费用契约确认；
3. 逐镜候选、主选和素材包的 UX 原型通过任务测试；
4. 每条 FR 分别估算产品、UX、前端、后端、AI/媒体和 QA 工作量；
5. 外部账号、合同和内容权利等待单独列为日历风险。

在上述条件前只记录未知项和依赖，不再发布总人周或 GA 月份承诺。

## 13. 待确认问题

1. `CUR-DEC-001`：默认导出应为服务端 ZIP，还是浏览器逐文件批量下载；当前建议 ZIP + JSON/CSV Manifest，本设计不创建第二个决策事实；
2. 首发允许的原始视频容器与编码集合；
3. 镜头素材对外交接时是否必须携带 AIGC 标识或内容审核结果；该问题与商业化无关，需要单独确认；
4. 导出包的最大镜头数、总字节数、生成时限和分类保留周期。

已关闭：complete/partial 均不得冻结 stale/needs_reconfirmation；重新确认后必须追加绑定当前输入摘要的决定。正式素材包只包含每个目标 Shot 的唯一主选，星标备选只保留在候选历史和单候选下载入口。
