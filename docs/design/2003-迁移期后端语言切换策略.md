# 迁移期后端语言切换策略

- 状态：已接受并开始实施
- 日期：2026-08-24
- 范围：顶层目录、公共 API 入口、Python 兼容运行时与 Go Backend

## 背景

目标架构要求 `backend/` 是唯一 Go Module，`agent/` 是独立 Python Runtime。原有实现将 FastAPI 业务 API、SQLAlchemy 模型、Agent Harness、Scheduler 和 Worker 全部放在 `backend/`，导致顶层目录名称继续表达旧技术边界，也会让新的 Go Backend 只能放入并列或嵌套的临时目录。

最新实施要求明确为：现有 Python/FastAPI 代码迁入 `agent/`，后续 `backend/` 使用 Go 实现。由于现有 FastAPI 仍拥有全部业务写入，不能在目录迁移时把未实现的 Go 路由声明为已经接管，也不能同时运行两套 Writer。

## 决策

1. 现有 Python 源码、测试、OpenAPI 快照和运行入口整体迁入 `agent/`，在迁移期标记为“Python 兼容运行时”。
2. 顶层 `backend/` 立即建立唯一 `go.mod`，新代码只允许使用 Go；顶层语言边界由架构测试固定。
3. Go `lanverse-api` 成为浏览器访问的唯一公共入口，并自行负责 `/healthz` 和 `/readyz`。
4. 尚未迁移的 HTTP 路由由 Go 入口透明转发到仅位于内部网络的 `agent-api`。代理不得改写方法、路径、查询、请求体、幂等键或业务响应。
5. 物理目录迁移不改变资源写入所有权。当前业务表、旧 Topic 和旧任务仍只有 Python 兼容运行时写入；Go 入口在首个业务切片验收前不连接数据库、不写 Outbox。
6. 每个路由族迁入 Go 时，必须按资源写入所有权台账完成契约差异、数据对账、旧 Writer 关闭和回滚验证，再从代理范围移除该路由。
7. `agent/` 中的 FastAPI、SQLAlchemy、Scheduler 和媒体 Worker 是有删除门禁的迁移代码，不代表 Agent 终态。它们随业务所有权切换逐项退出；最终 Python 只保留受限 Agent Executor、定义、Skill 和契约。

## 运行拓扑

```text
Browser / Frontend
        │
        ▼
backend/cmd/api (Go, public :8686)
        │ unmigrated routes
        ▼
agent-api (Python FastAPI, internal only)
        │
        ├── PostgreSQL / Redis / MinIO
        └── Outbox → Kafka → legacy workers
```

Schedule Dispatcher、Outbox Publisher、IO Worker 与 Media Worker 使用同一个 `agent` 镜像但拥有独立生命周期。Go API 的就绪状态必须包含 `agent-api` 的真实就绪结果；Go 进程存活不能掩盖兼容运行时或关键依赖故障。

本机开发优先复用仓库根目录 `.env` 已配置的 PostgreSQL、Redis、MinIO 与 Kafka，只在本机启动 Python 兼容 API、Go API 和 Frontend。为避免旧 Schema 或其他工作数据被开发初始化覆盖，本机启动器在同一 PostgreSQL 实例中使用 `LOCAL_DATABASE_NAME` 指定的隔离数据库，且拒绝使用与 `DATABASE_URL` 相同的数据库名。默认本机路径不启动 Scheduler、Outbox Publisher 或 Kafka Worker，防止新隔离数据库误领共享 Topic 中属于旧数据库的任务；完整执行链只在隔离 Compose 环境中启动。Compose 中的基础设施用于干净 Volume、持久化恢复、网络隔离和生产 Override 验收，不作为日常开发的默认依赖来源。

## 退出门禁

- Go 已接管的路由不再被代理，且不存在请求镜像导致的双写。
- 对应 Python Endpoint、Service、ORM Writer 和测试只在 Go Contract/E2E、数据不变量、排空和回滚验收后删除。
- Python Schema 管理权在首个 Go 业务表落地前退出生产 `create_all`，数据库变更统一进入 Baseline Migration 之后的版本化 Migration。
- 最后一条业务路由和旧 Worker 退出后删除 `agent-api` 兼容入口；`agent/` 通过 gRPC 与 Go Backend 通信，并通过架构测试禁止数据库、对象存储和任意网络直连。

## 结果

该策略让顶层目录立即反映目标语言边界，同时保留当前可运行系统和单写入所有者。代价是迁移期存在一个受控的 Go 代理跳转，并且 `agent/` 暂时包含超出终态 Agent 权限的兼容代码；两者都必须按上述门禁持续收缩，不能演变为永久兼容层。
