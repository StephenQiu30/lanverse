# 本地文档管理与 Obsidian

按用户 2026-10-08 的决定，恢复 `docs/` 分类管理文档，保留 Obsidian 编辑同一份 Markdown 的方式。项目文档通过文件、编辑器和 Git 阅读与审阅。

## 目录与边界

```text
docs/
  README.md       当前文档入口
  KNOWLEDGE.md    文档与 Obsidian 使用说明
  prd/           产品意图
  requirement/   需求与页面规则
  design/        设计方案
  plan/          实施计划
  test/          验收标准与记录
  operation/     运行说明
  licenses/      原始许可
  templates/     Obsidian 模板
  history/       历史参考资料
.obsidian/       仓库根 Vault 的共享配置与本机个人状态
```

当前正文从原内容目录迁入 `docs/`，原历史资料迁入 `docs/history/`，保留分类、稳定编号、正文和许可。根 README、PROJECT、DESIGN、BACKLOG 等入口只维护各自职责，通过相对链接引用文档。业务需求与接口范围沿用已接受的当前设计。

## 编辑、引用与失败路径

Obsidian 以仓库根作为推荐 Vault，默认新笔记位于 `docs/`，模板位于 `docs/templates/`，使用 Markdown 相对链接、自动链接更新和原有核心插件。图谱与默认搜索聚焦当前资料。也可使用 `docs/` Vault，但仓库根文档位于其范围外，需从编辑器打开。

共享配置纳入 Git，个人窗口布局、插件、主题和缓存保持本机管理。迁移时同时更新文档、入口与共享配置的路径；已有正文 Vault 需重新选择新目录。断链应先核对目标文件与相对层级，历史失效引用不得通过恢复旧业务范围来解决。具体使用见[文档与 Obsidian 说明](../KNOWLEDGE.md)。

独立文档站实现、依赖、专用 CI 和 Compose 文档服务已移除。业务前后端服务和数据沿用现有配置。历史记录中的站点命令仅代表当时实现。

## 验收

核对文档与模板迁移清单、当前相对链接及锚点、许可文件字节和 Obsidian JSON 路径；确认默认 Compose 服务清单与本机文档服务清理结果。Obsidian 实际打开、模板插入、反向链接与图谱需通过本机应用验证，配置检查本身不替代该验收。
