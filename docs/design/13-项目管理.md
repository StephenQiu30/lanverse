## 3. 接口

| 方法        | 路径                                            | 说明                                  |
| ----------- | ----------------------------------------------- | ------------------------------------- |
| GET         | `/api/projects?status=active&deleted=true&q=`   | 列表（status 支持 active / archived） |
| POST        | `/api/projects`                                 | 创建                                  |
| GET / PATCH | `/api/projects/{pid}`                           | 详情 / 修改（Rev）                    |
| GET         | `/api/projects/{pid}/overview`                  | 概览                                  |
| POST        | `/api/projects/{pid}/archive`、`/unarchive`     | 归档 / 恢复                           |
| DELETE      | `/api/projects/{pid}`                           | 删除（Rev）                           |
| POST        | `/api/projects/{pid}/restore`                   | 从回收恢复                            |
| GET         | `/api/style-presets?style_type=&style_subtype=` | 风格预设                              |

## 4. 异步与工作流

- `project-purge`（每日）：对 `purge_after < now()` 的项目执行分批清理工作流（删除对象存储前缀、删除各 schema 数据），可断点续跑。
- 概览物化计划接入 `overview` 消费者，按事件增量更新 Redis；是否先用 SQL 聚合按 §10 确认。

## 5. 事件与实时

`workspace.project_changed.v1`（创建、修改、归档、删除、恢复）→ realtime；审计经 `audit.recorded.v1`。

创建项目时，项目、默认 0 预算、`project.created` 审计及 `workspace.project_changed.v1` 在同一事务提交。两事件均以项目 ID 分区；变更事件只含 `change=created` 与项目 ID、修订号等信封字段。审计的允许摘要见 DES-12 §5，不写入作品名称、描述、预设提示词或媒体地址。Realtime 消费者核对项目分区键、信封 ID 和修订号后，将该事件投影为 DES-03 §5.2 的 `project.updated`，只推送项目 ID、修订号和变更类型；消费者按事件 ID 去重。项目列表发起创建的页面仍需在命令成功后主动失效列表查询，因为新项目的专属 SSE 流尚未由该页面订阅。

当前内部修改命令先覆盖名称、描述、风格预设和境外模型开关；默认模型由独立的项目 model-defaults 端点维护；AIGC 标识样式计划按 REQ-10 R4 接入。应用层按 `expected_revision` 与当前状态校验，PostgreSQL 事务重新核对账号、组织、项目修订与预设可用性，项目更新、`project.updated` 审计和 `workspace.project_changed.v1`（`change=updated`）一起提交。画幅、风格类型与分辨率不在修改输入中；归档或回收项目拒绝修改。无实际变化的请求不增加修订号或产生事件。审计摘要按 DES-12 §5 只记录安全字段，名称和描述不进入 Outbox。公开 PATCH 的持久幂等与错误映射以服务端 DTO 和在线 Swagger 为准（DES-03）。

### 5.1 当前公开创建合同

`POST /api/projects`：名称 1～50 个 Unicode 字符、描述、画幅、风格类型/子风格与可选预设；组织来自当前 Workspace actor，客户端不得指定。风格化的四种子风格沿现有领域白名单；写实不带子风格。固定 `1080p`、默认境外模型关闭和预算 0，成功返回 §3 的正式项目元数据、201 与 UUID。

精确 Origin 与 UUID `Idempotency-Key` 必需；当前本机工作区不使用 session/CSRF Cookie。持久回执和项目、预算、双 Outbox 在同一事务提交；沿 DES-02 的 24 小时回执保留合同，同账号同键同请求重放首次 201 结果，同键不同请求返回 `422 idempotency_key_reused`。并发同键只能创建一个项目，失败不得留下回执或部分业务记录；重放前仍复核当前账号/组织权限。请求 ID 用于审计，不代替幂等键。

`GET /api/style-presets` 按当前组织返回未删除的组织级预设安全元数据，供创建表单按风格/子风格筛选，不返回提示词、负面提示词、对象地址或供应商凭据。现有 P0 预设内容尚未产出时，列表可真实为空，允许不选预设创建；不写入虚构内置提示词或参考图。项目级预设不可用于另一个新项目。

正式 `/projects` 读取真实项目查询，创建成功主动失效列表并进入 `/projects/{UUID}/canvas`。异步结果未知时人工重试沿用该次请求的幂等键；修改输入后作为新请求处理。创建中阻止重复提交和关闭；失败保留输入并显示产品错误。列表的进度和集数只在相应查询存在后展示，不用示例值填充真实项目。

六阶段概览、AIGC 标识样式与真实生成计划按对应模块设计接入；已装配的创建、设置、归档/删除/恢复和媒体上传分别按真实业务闭环验收。

## 6. 界面

项目列表（卡片 / 表格切换、状态筛选、回收站视图）；新建项目对话框（风格类型切换后显示子风格与预设缩略图）；项目概览矩阵（单元格点击跳转）；设置页（画幅与风格只读并说明原因）。

## 7. 权限与审计

MVP 所有制作者可访问组织内全部项目。审计：`project.created`、`project.updated`、`project.archived`、`project.unarchived`、`project.deleted`、`project.restored`、`project.purged`。

## 8. 非功能要求

PERF-01（概览首屏 ≤ 2 秒）；PERF-03（进度更新 ≤ 2 秒）；PRV-05（彻底删除含媒体）。

## 11. 完整历史引用保护

项目生命周期和物理清理必须读取 owning workspace 的两类历史引用，每类最多 100000 行、全部 JSON 合计 64MiB、单件最多 1MiB。数据库先执行数量与字节预算预检，单件读取以 CASE 限制，再逐行解码；不能先将全部 JSON 载入客户端内存后才拒绝超限。超限或历史事实不可读时拒绝受理，不把未知引用视为零。

这些上限只适用于生命周期的历史引用保护读取，不改变普通页面读取，也不把单件预算施加到完整项目 Copy manifest。项目/目录回收与恢复、永久命令回执、目录放置和完整 Copy 的具体合同见 [工作台设计](工作台设计.md)。

## 故障约束与专项验证

- 专项验证：用 16:9 国风项目、30 镜头阶段计数、进行中任务和删除第 10 天项目执行 TC-10-01～06；注入归档/删除冲突、清理中断与画幅修改，核验恢复和 PERF-01/03（REQ-10 §3；DES-13 §9；TST-02）。

- 清理工作流中断或误清理：到期前保留回收状态和对象，按项目断点续跑并核对审计。
- 概览计数过期：回源重算阶段数据并刷新显示，未修复前不把缓存值作为验收证据。
