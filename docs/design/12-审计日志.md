## 2. 处理流程

```text
业务命令事务内写 Outbox 事件 audit.recorded.v1 → Kafka → audit 消费者生成审计记录（按事件 ID 幂等）→ audit.audit_log
管理员 → 审计页面筛选 → 查看前后值摘要 → 跳转对象
```

## 3. 数据

`audit.audit_log`（按月分区）：`org_id`、`project_id`、`actor_id`、`actor_kind`、`action`、`object_type`、`object_id`、`before`、`after`、`request_id`、`trace_id`、`ip`。迁移预建当前 UTC 月及未来三个月，并保留默认分区接纳窗口外的延迟事件；维护任务挂载新分区前须由表所有者在独立事务中暂停默认分区触发器、搬迁目标月份记录，再恢复触发器后提交。数据库触发器拒绝已写记录的 `UPDATE` / `DELETE`；部署前由数据库管理员创建不登录的 `lanverse_app` 权限角色，审计权限迁移仅向该角色授予 `audit` schema 的 `USAGE` 与分区父表 `audit.audit_log` 的 `INSERT` / `SELECT`，运行时权限迁移按现有仓储访问逐表授予其他业务表所需权限。实际应用登录角色继承该权限角色，不能是审计表所有者或任何表所有者角色的成员；分区维护与归档使用独立高权限账号。消费者幂等依赖 `infra.processed_event`。

手工预备入口 `lanverse partitions ensure` 使用独立的 `LV_PARTITION_MAINTENANCE_DB_DSN` 连接两个分区父表的所有者；执行前核对它与 `LV_DB_DSN` 是同一数据库的不同角色，应用连接的真实登录身份与当前角色一致，且不具有超级用户或表所有者权限。入口将 Outbox 与审计的当前 UTC 月及未来三个月准备工作放在同一事务，任一方失败则整体回滚。该入口只预备可写分区，不删除历史审计；三年保留期删除仍须先完成冷归档并由完整 `partition-maintain` 定时任务执行（§5、§11）。

查询仓储要求显式传入 `org_id`，项目、操作人、动作、对象类型和时间范围均在该组织范围内追加过滤；详情查询也带 `org_id`。列表按 `(create_time, id)` 倒序，以末条的这两个字段作为下一页游标；`to` 为不包含的上界，单页最多 100 条。管理员身份与组织访问权由上层鉴权检查。

## 5. 异步与工作流

audit 消费者（`backend-relay`）只消费 `audit.recorded.v1`：命令层对 REQ-09 R1 列出的每个动作（登录与账号变更、凭据、注册表与价格、预算、报价确认、取消、人工核对处理、所有选定 / 锁定 / 确认、删除与恢复）在业务事务内写入该事件（通用信封：`action`、`actor`、`object`、`before`、`after`）；登录失败等不产生业务事务的动作在独立小事务中写入。审计覆盖不依赖各领域事件是否标注 audit。分区维护定时任务 `partition-maintain` 每月创建未来 3 个月分区、删除 3 年前分区。

`audit.recorded.v1` 沿用 DES-03 §6.1 信封：`event_id` 同时作为审计记录 ID，`occurred_at` 作为审计时间，`org_id` 必填，`project_id` 可空，`actor.kind` 为 `user|agent|system`，`aggregate` 为 `{type:"audit", id:event_id}`。`data` 为 `{action, object:{type,id}, before?, after?, request_id?, ip?}`；`before` / `after` 只含动作声明允许的变更字段，消费者拒绝未声明字段和超长文本。Kafka key 在有项目时为 `project_id`，否则为 `org_id`；去重标记与审计行在同一 PostgreSQL 事务中提交。Trace ID 从信封 `trace.traceparent` 提取。

M1 已接入动作的摘要白名单如下。`must_change_password` 只接受布尔值；`auth.login_failed` 的 `reason` 只接受内部原因码 `login_not_found`、`password_mismatch`、`account_disabled`、`ip_rate_limited`，对外仍按 REQ-06 R7 统一提示，不传入请求原文。`object`、`actor` 和请求信息仍按信封字段保存；密码、哈希、会话令牌不进入摘要。凭据动作只记录 `api_key` 的 `last4`，不记录 `secret`、密文、`key_id` 或供应商原始响应。其余业务动作须在生产者接入前先补充对应字段策略。

| action | 可用的 `before` / `after` 字段 |
| --- | --- |
| `auth.login_succeeded`、`auth.logout` | 无 |
| `auth.login_failed` | `reason` |
| `auth.locked` | `retry_after_s` |
| `user.created` | `role`、`status`、`must_change_password` |
| `user.updated` | `display_name`、`role` |
| `user.disabled`、`user.enabled` | `status` |
| `user.password_reset`、`user.password_changed` | `must_change_password` |
| `credential.set`、`credential.tested`、`credential.disabled` | `last4` |
| `provider.created` | `key`、`adapter_key`、`region`、`status`、`concurrency_limit`、`rate_limit_per_min` |
| `model.created` | `key`、`provider_id`、`capability`、`display_name`、`status` |
| `model.version_published` | `version_id`、`version_no`、`provider_model_id`、`revision` |
| `model.enabled`、`model.disabled` | `status`、`revision` |
| `price.published` | `version_id`、`version_no`、`unit`、`currency`、`effective_from`、`revision` |
| `project.created` | `aspect_ratio`、`style_type`、`style_subtype`、`style_preset_id`、`status`、`revision` |
| `project.updated` | `revision`、`style_preset_id`、`allow_overseas_models`、`name_changed`、`description_changed` |

`project.created` 的 `project_id` 与对象 ID 均为新项目 ID，分区键使用该项目 ID；摘要只保存项目规格与状态，不复制作品名称、描述、预设提示词或媒体地址。项目变更事件使用独立事件 ID，其下游实时消费属于 DES-13 §5 的后续任务。

`project.updated` 只记录修订号、实际改变的预设 ID 和境外模型开关前后值；名称和描述仅以 `name_changed`、`description_changed` 布尔标记出现在 `after`，不记录自由文本。未改变的设置不写入前后摘要。

异常与边界：Kafka 暂不可用时事件积压在 `infra.outbox`，relay 恢复后补发，审计延迟写入但不丢失（REL-07）。前置：`infra.outbox` 与 relay 就绪。

## 6. 事件与实时

消费 `audit.recorded.v1`（DES-03 §6.2）。

## 7. 界面

筛选栏（时间范围、操作人、项目、对象类型、动作）+ 虚拟滚动表格 + 详情抽屉（前后值差异）。

## 8. 权限与审计

仅管理员可查询；查询与导出本身也写审计（`audit.exported`）。

## 9. 非功能要求

SEC-10（100% 覆盖 R1 动作，以自动化测试遍历命令验证）；DAT-03；查询 30 天范围 P95 ≤ 1 秒。

## 10. 测试设计

- 命令覆盖测试：遍历 R1 中每个命令，断言产生对应审计记录。
- 消费者幂等：重复投递同一事件只产生一条记录。
