# Design 01：用户

执行编号：01；原始需求模块：06。依据[原始需求](../requirement/06-用户需求.md)、[PRD](../prd/01-用户.md)与[Plan](../plan/01-用户.md)。本文件把原始需要转换成项目方案，**全部新增设计选择仍待评审**；数据对象和接口为拟议合同，不表示已有表或已实现API。共同约束见[整体设计](00-项目需求设计.md)。原始FR、质量条件与AC仍须同时满足。

## 身份和会话边界

用户模块拥有账号、凭据摘要、会话、个人资料和偏好；项目模块消费已验证身份，不复制密码或会话。媒体模块仅为头像提供受控媒体引用。首轮提供真实登录/会话/退出和制作者授权；账号取得须使用已确认的注册或管理员建号方式，不能自动种植固定身份。无通知、邮件找回或账号删除平台。

| 数据对象           | 设计内容与不变量                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| Account            | 登录名规范值与显示值、角色、enabled、must_change_password、revision；规范值数据库唯一                  |
| Credential         | 单向密码摘要、credential_revision；不在查询DTO或审计快照回显                                           |
| Session            | token摘要、账号、created_at、last_active_at、expires_at、revoked_at、credential_revision、安全设备摘要 |
| LoginGuard         | 按规范登录标识及风险来源记失败/锁定；不存在账号也采用等价反馈                                          |
| Profile/Preference | 本人显示名、头像media_id、主题、提示词后缀及revision                                                   |

密码使用有盐、自适应的密码散列；具体算法/参数和速率防护在实现前安全评审，不储存可解密密码。Cookie建议HttpOnly、Secure及合适SameSite；写入入口做同源/CSRF校验，凭据不进入localStorage。保持登录控制Cookie持久化；会话服务端仍执行空闲12小时、绝对7天限制。

## 用例、接口与一致性

拟议接口：POST /sessions登录、GET /session读取本人状态、DELETE /sessions/{id}退出；PATCH /me/profile与/preferences；POST /me/password；管理员/accounts查询/创建及enable、disable、unlock、reset-password命令。受限会话仅允许改密、查询必要本人信息和退出，不能读项目。

注册的可用提示仅是预检，提交时以数据库唯一约束防并发同名。角色仅由管理员路径赋值。登录先校验锁定、凭据与enabled，成功才建会话；5次失败锁15分钟，不泄露账号存在。失败累计窗口建议采用滚动15分钟，成功清零，**待确认**。

改密在事务内核当前密码及credential_revision，改摘要、清must_change_password、撤销其他设备。建议轮换当前Session后保持当前设备登录；与管理员重置并发时只有符合版本者成功。禁用撤销全部会话；解锁只解除登录锁；重置强制改密并撤销旧会话。最后一个有效管理员检查需锁定相关管理员集合，不能只读一次数量。

## 原始需求到设计追踪

| 原始FR     | 项目设计与验收观察                                                      |
| ---------- | ----------------------------------------------------------------------- |
| FR-USER-01 | Account唯一＋注册事务；并发同名仅一成功，显示名≤32、密码≥10且含字母数字 |
| FR-USER-02 | LoginGuard＋受限Session；错误不建会话，锁定/改密限制由服务端执行        |
| FR-USER-03 | Session撤销及双期限；旧Cookie再次请求失效，列表无token                  |
| FR-USER-04 | Credential版本事务；错误/并发重置不解除限制，其他设备撤销               |
| FR-USER-05 | 本人Profile＋授权头像；角色登录名不可写，刷新读回                       |
| FR-USER-06 | 个人Preference；新草稿复制后缀版本，历史任务不改变                      |
| FR-USER-07 | 管理员建号用例；首次改密、安全摘要、临时凭据不入列表日志                |
| FR-USER-08 | 四个独立命令＋管理员保护；禁用生效、解锁不启用、不删除历史操作者        |

失败时保留可继续输入字段但不回显密码；会话过期提示重新认证并保留安全本地草稿。敏感写入与审计同事务，审计只记录状态/版本变化。验证覆盖两制作者及管理员交叉访问、并发注册/改密/最后管理员禁用、双期限边界及注销后的项目缓存清除，对照原AC和质量条款。

## 待评审选择与实施入口

登录名大小写/Unicode归一、失败窗口、当前设备轮换、初始管理员取得、临时凭据交付、头像限制未定。建议账号偏好为跨登录事实，本地主题仅未登录默认；接受前不强制覆盖未保存主题。首轮只有身份子集，完整账号/偏好随后按[Plan](../plan/01-用户.md)展开；不能因画布Demo通过而标本模块全部完成。

### 认证事务与恢复

注册靠login_key唯一最终裁决；登录按guard_key锁行清过期失败时刻、核凭据和账号，再建Session。token只在随机生成后经Cookie交付，数据库存摘要。登录失败消息不含存在/禁用/锁定差异。最后管理员操作先按稳定ID锁全部管理员行，锁后重新计算有效管理员，避免两个并发禁用都通过旧计数。

改密校验credential_revision及原密码后一次修改摘要、推进版本、撤销其他会话、轮换当前token和写安全audit；丢轮换Cookie回执后用新密码重新登录，不从回执恢复token。含密码的注册/建号/改密/重置是全局request_key的明确例外，依靠唯一或凭据版本防重复，网络断开先查状态/重新认证；普通资料/偏好/启停使用command_receipts。

## M1 T01-01实施合同（2026-10-09）

用户本轮授权继续实现M1，明确选择制作者自助注册，并确认登录名只含英文字母、数字、`.`、`_`、`-`；去首尾空白、忽略大小写，1～64字符。确认滚动15分钟内失败5次锁15分钟，以及改密轮换当前会话、撤销其他设备。这是T01-01的实施合同，不代表接受全部未来模块设计。

本片实现注册并建会话、登录、读取会话、本人退出、必要受限改密、真实可用性预检。公开角色为creator/admin；持久层暂复用identity.user，creator显式映射producer，session_epoch作为凭据版本。沿用单一本地组织仅为现存业务FK的技术范围，不增加组织产品功能；注册事务可创建空组织，但绝不创建固定账号。登录名使用全局唯一索引裁决（含现存账号），显示名在注册边界限1～32字符。旧50字字段宽度不是新需求限制。

新增identity.user_session：id UUID PK、account_id FK identity.user、token_hash bytea UNIQUE且32字节、credential_revision bigint正数、created_at/last_active_at/absolute_expires_at timestamptz、persistent bool、revoked_at timestamptz NULL。新增identity.login_guard：login_key text PK、failure_times timestamptz[]、locked_until timestamptz NULL。新增identity.auth_event：id UUID PK、account_id UUID NULL FK、action text、created_at timestamptz；仅追加成功/失败类型和安全账号ID，不写登录名、密码、token、请求体或设备隐私。完整审计查询与保留策略仍在后续模块，本片事件与身份变化同事务。

应用层通过消费方事务接口访问仓储。登录事务锁同一login_guard，然后锁账号；会话请求先锁账号再锁会话，改密采用相同顺序，避免死锁。错密、不存在、禁用及锁定统一401，失败也提交guard及安全事件；不存在账号执行同成本bcrypt比较。空闲12小时、绝对7天，以服务端时间在等号边界失效；每次认证验证账号状态和凭据版本。受限会话仅能查本人、改密、退出，其他业务403。管理员入口额外校验角色，现存业务继续执行对象权限，不用页面隐藏替代授权。

密码复用domain有盐bcrypt cost12，至少10个Unicode字符、含字母数字、最多72 UTF-8字节；新增前端提示与服务端一致。会话token由32字节密码学随机数产生，仅通过HttpOnly、SameSite=Lax、Path=/ Cookie交付，存储仅SHA-256摘要；HTTP本地Secure=false，HTTPS Secure=true。保持登录仅使Cookie持久化，绝对期限不延长。响应只含Actor、session_id、时间、persistent；Actor含id/login_name/display_name/role/must_change_password/credential_revision，无秘密。改密检查当前密码、版本、新密码规则及不得重用，在事务中更新hash/版本并撤销旧会话、插入当前新会话。DELETE仅当前本人session_id，可重复撤销，清Cookie。

接口采用上方既定资源路径，另增加GET /api/accounts/availability?login_name=，返回available:boolean（只提供注册所需预检，提交仍以唯一约束裁决）。错误422 login_name_taken/invalid_request/weak_password/password_reused/current_password_invalid，409 credential_conflict，401 invalid_credentials/session_invalid，403 password_change_required/forbidden。写入口沿用Origin与Idempotency-Key语法校验；认证秘密不进入通用回执，不承诺秘密命令重放。丢响应时前端提示结果未确认并可读会话恢复，不伪造成功。

前端使用同源Next Route Handler限定认证资源代理，服务端固定LV_BACKEND_ORIGIN，不接受用户目标地址；原样传递Cookie、Origin和Idempotency-Key，响应禁止缓存、转交Set-Cookie，超时明确503。公开注册/登录页保持Client交互，受保护ProductShell查真实会话；未取得身份不渲染工作台内容。Next文档以安装的16.3.6为准，Vercel React Best Practices覆盖异步/Effect清理及状态边界。公开DTO/Handler注解经固定版本swag生成规范，再用@umijs/openapi（openapi2ts）生成本片调用；生成物不手改。

Schema只维护backend/db/schema.sql最终态。已有库增量从新增定义导出，先检查现有登录名重复、角色权限及目标数据库，再审阅只新增索引/表/授权的事务；不重放全量Schema、不重置数据。隔离PostgreSQL测试核注册并发、登录锁定、受限访问、两人退出越权、双期限、改密撤销及事务失败；真实浏览器核注册→刷新身份→退出→登录、重复名/错密/受限改密。T01-02项目和T01-03画布持久化另行执行。

### T01-01实际落地说明

2026-10-09按上述合同完成实现。新增索引使用`lower(btrim(login_name::text))`，仓储查询使用同一表达式；新账号先按领域规则归一。认证事件追加权限与会话/guard更新权限分开；禁止运行角色删除/清空三表。单组织注册与旧bootstrap共享事务advisory lock，既有组织多于一个或非active时拒绝，不自行创建另一业务范围。

可复现生成命令在frontend运行Plan 01末节的现有工具直接命令；仅筛选当前六个资源及递归引用定义，产出auth/index/typings三文件。运行规范和中间文件在临时目录，不恢复backend/docs或在线Swagger。当前实现、增量DDL、实际运行权限和分层验证证据见[Plan 01记录](../plan/01-用户.md#t01-01实现与验证记录2026-10-09)；待人工页面改密与用户接受，不视为整个模块方案已接受。
