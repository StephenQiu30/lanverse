# M02 项目组合与内容单元详细设计

> Design ID：DES-M02
> Requirement：[REQ-PRJ](../../requirement/002-M02-项目组合与内容单元需求.md)
> 状态：proposed

## 1. 设计结论

Project 是管理和交付边界，ContentUnit 是叙事与顺序边界。M02 只保存组织结构、Brief 修订和目标，不复制其他模块状态；项目概览由可重建投影产生，并能下钻到权威对象。

## 2. 事实所有权

| 聚合 | 核心字段 | 规则 |
| --- | --- | --- |
| Project | workspace、type、lifecycle、current_brief_id | 归档不删除历史 |
| BriefRevision | goals、audience、format、duration、quality、limits、delivery | approved 后不可改 |
| Series/Season | project、stable identity、order revision | 可选层级，不强迫所有类型使用 |
| ContentUnit | project、kind、status、target、deadline、limit | 稳定 ID，显示序号可变 |
| ContentUnitMaterialization | manifest、item mapping、target order、status、result | 私有清单完成后原子发布，不复制来源边界正文 |
| ProjectVariant | source unit/branch、purpose、lineage | 不以复制目录代替谱系 |
| ProjectProjection | counts、blockers、next actions、as_of | 可丢弃重建 |

## 3. 命令、查询与事件

- Commands：`CreateProject`、`CreateBriefRevision`、`ApproveBriefRevision`、`CreateContentUnit`、`PrepareContentUnitMaterialization`、`ApplyContentUnitMaterialization`、`ReorderContentUnits`、`Archive/RestoreProject`、`CreateProjectCopyDraft`、`FinalizeProjectCopy`；
- Queries：项目列表、项目概览、阻塞下钻、Brief 差异、复制预览；
- Events：`ProjectCreated`、`BriefRevisionApproved`、`ContentUnitOrderChanged`、`ProjectArchived`；
- 拆集事件：`ContentUnitsMaterialized(manifest_id, manifest_hash, mapping, order_revision_id)`，只携带稳定引用和哈希；
- 消费 M03—M14 的状态事件更新投影，但关键交付/权利判断必须回源。

## 4. 不变量

1. `current_brief_id` 只能指向 approved BriefRevision；
2. ContentUnit 和显示顺序分离，重排不改变实体状态范围；
3. 项目完成需要匹配已签认交付目标，不能由百分比自动推断；
4. 项目复制先形成私有 draft manifest，全部对象成功后才发布副本；
5. 投影中的百分比、blocked、unknown 必须携带构成对象查询条件。
6. 只有 M03 已批准且覆盖校验通过的 EpisodeBreakdownManifest 可以创建剧集；Manifest item 在同一物化内只对应一个 ContentUnit。
7. 物化成功前新 ContentUnit 与 OrderRevision 不对普通查询可见；相同 Manifest/hash/idempotency key 重试回读同一结果。

## 5. 事务与并发

Brief 和顺序使用 expected revision；批准 Brief 时生成影响请求，但影响计算失败不得静默发布 current。项目归档前查询运行 Operation，用户选择取消、等待或保留；选择和执行结果写审计。

## 6. 失败与恢复

- 投影延迟：显示 `as_of`，关键阻塞回源，并提供重建 Operation；
- 复制中断：按 manifest item 续做，不暴露半成品；
- 归档与任务竞争：事务重新检查 Operation/Job 状态；
- Brief 影响超时：保持旧 current，新修订等待影响确认；
- 跨项目复用：只允许 M04/M15 已发布对象，源项目草稿引用直接拒绝。
- 剧集物化中断：按私有 manifest item 对账和续做；任一必需项失败时不发布 order current，也不暴露半成品。

## 7. 验证和交付

领域测试覆盖稳定身份、current 唯一、拆集物化、重排、归档、复制幂等和投影重建；集成测试覆盖 Workspace 隔离和并发批准。映射 PRJ-FR-001—011、PRJ-NFR-001—005、AC-PRJ-001—009；切片 A 完成项目、Brief、Series/Season/ContentUnit、整本拆集物化、最小内容变体身份和可解释概览，项目分支、复制及已发布资产关联在 F 交付。

## 9. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| M01 → M02 | actor 的 workspace/project action 授权；M02 提供 `ProjectAccessSubject` | M01 拥有职责与授权，M02 拥有项目身份/生命周期；概览查询在读取摘要前授权 |
| M03 → M02 | `ApprovedEpisodeBreakdownManifest(manifest_id, project_id, source_revision_ids, breakdown_revision_id, manifest_hash, items[temporary_key, ordinal, title, boundary_anchor_refs])` | M03 拥有来源边界、覆盖和批准；M02 只读取最小锚点引用以审计物化，不复制正文、Scene 或 Mention；stale/unapproved Manifest 拒绝 |
| M02 → M03 | `ContentUnitMaterializationResult(manifest_id, mapping[temporary_key, content_unit_id], order_revision_id, result_hash)` 与已批准 Brief 引用 | M02 拥有稳定 ContentUnit/顺序；M03 用 mapping 绑定 Scene，不能自行创建或按 ordinal 猜 ID；结果按 manifest/hash 幂等 |
| M02 ↔ M04 | `ProjectScope`、ContentUnit 稳定 ID；M04 返回已发布 Workspace 资产引用状态 | M04 拥有跨单元知识和资产内容；M02 仅拥有项目内显式链接及其 purpose |
| M03—M14 → M02 | `ProjectStatusFactChanged(event_id, project_id, subject_ref, status_kind, status, observed_at)` | 来源模块仍是权威事实；M02 按 event ID 幂等更新 ProjectProjection，投影可丢弃重建 |
| M08/M11 → M02 | 运行 Operation、资源预留和外部副作用摘要 | M02 归档只提交处置选择；实际取消/保留和用量对账由拥有模块执行并回报结果 |
| M13 → M02 | `DeliveryGoalAssessment(brief_revision_id, snapshot_id, outcome, unmet_items)` | 只有 M13 对签认交付目标的满足结论可支撑 `completed`；概览百分比不能替代 |
| M15 → M02 | 已发布模板/结构 manifest 的稳定发布 ID | 模板归 M15；M02 只在复制/新建时记录采用的发布版本，不复制组织草稿 |

所有事件携带 `workspace_id`、`project_id`、subject type/ID、source revision、event ID 和 occurred_at。投影消费者允许至少一次投递，但以 event ID 幂等；关键完成、归档和复制发布命令必须在提交前回源，而不是相信可能滞后的概览。

## 10. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| Project | `draft → active → paused → completed \| archived`；archived 可 restore 到显式前态 | 所有生命周期命令使用 expected revision；`CreateProject` 以 workspace + idempotency key 唯一；completed/archived 不互相推断 |
| BriefRevision | `draft → approved → superseded`；approved 不可变 | 创建绑定 base/current；批准和切换 current 分别 compare-and-set；相同命令键回读同一 revision |
| Series/Season/ContentUnit | `active → paused \| completed \| archived`，稳定 ID | parent、业务键和类型受唯一约束；更新目标用 expected revision；归档保留引用 |
| ContentUnitOrderRevision | 发布即不可变；Project/Series/Season 各自一个 current pointer | 以 base order revision 创建；item 的 stable ID/ordinal 分别唯一；重复重排不重复插 item |
| ContentUnitMaterialization | `preparing → ready → applying → completed \| partial \| failed \| cancelled \| stale`；`partial → applying` 可恢复 | manifest ID/hash + parent + idempotency key 唯一；`partial` 仅表示私有 item 清单有成功/失败结果，普通 ContentUnit/Order 查询仍不可见；Resume 只续做失败/未执行 item；item mapping 只追加；最后一步 compare-and-set 发布 OrderRevision；completed 后回读同一结果 |
| ProjectCopyDraft | `preparing → ready → publishing → completed \| failed \| cancelled` | manifest 冻结后逐 item 用 source ref + target logical key 幂等；发布 current pointer 是最后一步 |
| ProjectVariant | `draft → active → archived`，lineage 不可变 | source/purpose/idempotency key 唯一；源分支后续变化不会原地改 variant |
| ProjectProjection | `building → current \| stale \| failed`，带 as_of/cursor | event ID 去重；重建按 projection version 替换，不覆盖更新版本；失败可从权威事件/查询重建 |

Brief 批准的影响报告绑定候选 revision hash；报告完成后若 current 或下游基线变化，批准命令必须重新计算或明确显示 stale。项目归档将“处置选择 + 当时运行对象集合”写审计，再由各拥有模块对账，M02 不跨表强制更新任务。

## 11. 页面与可观察状态

| 页面/入口 | 主要动作 | 必须可观察的状态 |
| --- | --- | --- |
| 项目列表/新建 | 创建、筛选、暂停、归档、恢复 | lifecycle、type、current brief、blocked/unknown 摘要、projection as_of；无权项目不出现在计数中 |
| Project Workspace / Brief | 编辑新 Brief、比较、提交影响、批准/切换 current | draft/approved/superseded、base/current revision、字段 diff、影响 running/stale/failed、下游 Readiness 缺字段 |
| 内容结构 | 创建 ContentUnit、可选 Series/Season、重排、编辑目标 | stable ID、显示编号、order revision、状态、deadline/resource limit、并发移动差异 |
| 整本拆集物化 | 预览 M03 已确认剧集、确认创建、查看失败或对账 | source/breakdown/manifest hash、候选临时 key→稳定 ContentUnit mapping、覆盖校验、base/current order、preparing/partial/stale/completed；成功前不出现在普通内容结构中 |
| 项目概览 | 查看来源/知识/镜头/生成/问题/审阅/交付 | started/completed/running/failed/unknown/blocked/stale/deliverable 的独立计数、as_of、构成对象和跳转 |
| 阻塞中心 | 筛选责任范围并执行下一动作 | source module、subject、reason、owner scope、next action、source unavailable，不以颜色作唯一提示 |
| 归档/完成 | 预检运行任务与交付目标、选择处置 | 任务/外部副作用清单、目标满足报告、reconciling、失败项和继续对账入口 |
| 复制/变体（F） | 预览选择项、发布副本、比较谱系 | 私有 draft、manifest 每项状态、新身份、source lineage、partial failure 和恢复动作 |

通用页面状态为 `loading`、`empty`、`ready(as_of)`、`stale(refresh_action)`、`submitting`、`conflict(diff)`、`blocked(reason, next_action)`、`partial(failed_items)`、`failed(retry_action)`。概览不能把 `unknown`、`stale` 或来源不可用折算为“未开始”或“已完成”。

## 12. 逐 ID 验收映射

| Requirement ID | 设计落点 | 可执行验收 |

| PRJ-FR-005 | ProjectProjection 状态事实协议 | 注入 M03—M14 事实后分别显示来源、知识、镜头、生成、问题、审阅、交付状态 |
| PRJ-FR-006 | blocker 构成成员与 next action | 每个 blocked/unknown/stale 值均可下钻具体 subject、责任范围和动作 |
| PRJ-FR-007 | Archive/Restore 状态机 | 归档/恢复不删除来源、任务、候选、选择、审阅或交付历史 |
| PRJ-FR-008 | CopyDraft manifest（F） | 预览选择项，发布后每个复制对象有新 ID 和 source lineage，未选项不存在 |
| PRJ-FR-009 | M04/M15 发布 ID 显式链接（F） | 只能链接 published revision；源项目 draft 查询被拒绝 |
| PRJ-FR-010 | ProjectVariant lineage（F） | 新 variant 变更不改原分支 current/DeliverySnapshot，差异可查询 |
| PRJ-FR-011 | ContentUnitMaterialization + M03 Manifest 契约 | 10 集 Manifest 原子创建/关联 10 个 ContentUnit 并发布一个 OrderRevision；中断重试不重复且半成品不可见 |
| PRJ-NFR-001 | 分页 ProjectProjection/成员查询 | 大型项目概览查询有界且不加载媒体正文；记录分页与延迟基线 |
| PRJ-NFR-002 | 投影可重建、关键结论回源 | 删除读模型后重建与权威对象一致，交付/任务事实仍完整 |
| PRJ-NFR-003 | 创建/复制幂等键 | 并发重复请求只生成一个可识别 Project/CopyDraft，并回读相同结果 |
| PRJ-NFR-004 | 生命周期/职责审计 | 归档、恢复和 M01 项目职责变化均可追溯 actor、基线、理由、结果 |
| PRJ-NFR-005 | 容量基线 Gate | 用签认的项目/ContentUnit/并发样本记录分页、重排和投影重建结果 |
| AC-PRJ-001 | ContentUnit stable ID + OrderRevision | 从 Brief 创建三个单元并重排，M03/M04/M05 引用均不漂移 |
| AC-PRJ-002 | Brief 不可变版本绑定 | 新 Brief 批准后，既有 GenerationPlan 仍显示旧 brief revision ID/hash |
| AC-PRJ-003 | 可解释概览 | failed、unknown、缺主选计数分别定位到拥有模块具体对象 |
| AC-PRJ-004 | archive 非删除 | 归档后逐类历史仍可在授权只读查询中访问 |
| AC-PRJ-005 | M01 授权先于摘要读取 | 无权限 actor 获得统一拒绝，不得到他项目名称、计数或敏感摘要 |
| AC-PRJ-006 | Brief compare-and-set | 两个 actor 基于同一 revision 更新，一个成功，另一个返回 current 和字段 diff |
| AC-PRJ-007 | 私有复制 manifest | 仅确认结构发布，新业务身份和来源关系齐全，失败副本不可见 |
| AC-PRJ-008 | projection version 重建 | 重建前后各状态构成集合一致；并发新事件不被旧重建覆盖 |
| AC-PRJ-009 | 拆集 Manifest 原子物化 | 注入第三项失败后断言普通查询无新集；恢复后恰好 10 个稳定 ID；随后重排只生成新 order、不换 ID |
