# M07 生成规划、提示编译与路由详细设计

> Design ID：DES-M07
> Requirement：[REQ-PLN](../../requirement/007-M07-生成规划提示编译与路由需求.md)
> 状态：proposed

## 1. 设计结论

`GenerationPlan` 是所有真实媒体生成的冻结批准边界。M07 拥有计划、输入快照、提示编译、`CapabilityRevision`、路由决定与预检；M08 拥有 `ProviderConnection`、连接的实时健康、凭据和执行；M11 拥有资源估算/预留；M14 拥有外发与策略结论。

`CapabilityRevision` 是标准化、不可变的能力声明，包含 provider/model/version、媒体类型、输入/参考/时长/尺寸约束、地区与治理属性引用、用量单位和支持的恢复方式；不保存凭据、账户余额或连接运行状态。路由页使用的 `RoutabilityView` 是可重建读模型，显式标记 `as_of/expires_at`，由 CapabilityRevision + M08 ConnectionView + M14 PolicyEvaluation + M11 UsageEstimate 组合，不成为新事实源。

计划批准不等于执行、候选采用或交付批准。本模块保持在模块化单体内，不拆微服务。

切片 A 只建立受限 Fixture 契约：同一 `GenerationPlan/PlanItem` 类型固定批准目标、输入 hash、`execution_mode=fixture` 和零外部用量，再由 M08 建 Operation/Job/Attempt、M09 建 Candidate。它不编译 Provider Prompt、不选择真实 Capability、不外发数据，也不能作为切片 C 的编译/路由/Provider 证据。

## 2. 模块边界与跨模块契约

## 4. 状态、事务、并发与幂等

### 4.1 GenerationPlan 状态

| 当前状态 | 命令/守卫 | 下一状态 | 规则 |
| --- | --- | --- | --- |
| `draft` | 构建快照、编译、路由、预检 | `preflight_ready` / `blocked` / `cancelled` | 草稿变化增加 revision 并使旧报告过期 |
| `blocked` | 修正输入或重跑预检 | `preflight_ready` / `cancelled` | 批量 blocker 与可继续项分开展示 |
| `preflight_ready` | 提请，报告未过期 | `awaiting_approval` / `blocked` | 报告必须绑定当前 plan hash |
| `awaiting_approval` | 批准/拒绝/取消 | `approved` / `rejected` / `cancelled` | 批准时重读门禁和原子预留 |
| `approved` | M08 读取执行契约并启动，或用户创建替代计划 | `superseded` 或保持 `approved` | M07 不执行 Submit；执行任何状态不写回计划 |
| `rejected` / `superseded` / `cancelled` | 只读 | 终态 | 需变更创建新 Plan |

Plan 聚合状态不能遮蔽批量项：只要仍有可继续项，Plan 可以进入 `preflight_ready` 或 `awaiting_approval`，同时单列 `blocked_item_count`；只有全部活动项均阻塞时 Plan 才进入 `blocked`。批准命令必须显式列出全部当前可批准的 item IDs 和各自 report hash；该 selected set 在单一事务内全成或全败。首次成功批准后 Plan 全体冻结，selected items 进入 approved，未选/blocked items 进入 excluded，后者不进入 ApprovalSnapshot、approved plan execution hash 或 M08 执行契约，只能复制到 replacement Plan。

### 4.2 PlanItem 状态

| 当前状态 | 允许转换 | 不变量 |
| --- | --- | --- |
| `draft` | `preflight_ready`、`blocked`、`cancelled` | 独立引用 target/input hash；单项失败不改变兄弟项 |
| `blocked` | Plan 尚未批准时修复后回 `draft` 或 `preflight_ready`；批准兄弟项时进入 `excluded`；也可 `cancelled` | blocker/reason/恢复链接逐项保留；不得被批量批准；excluded 后只能复制到 replacement Plan |
| `preflight_ready` | `awaiting_approval`、`blocked`、`cancelled`；首次批准时未选则 `excluded` | 报告绑定当前 item hash；过期回 blocked/draft 重算 |
| `awaiting_approval` | selected item 进入 `approved`；未选进入 `excluded`；也可 `rejected` 或 `blocked` | selected set 内任一项门禁失败回滚整个批准事务，不产生部分 ApprovalSnapshot |
| `approved` | 保持 approved 或被新 PlanItem `superseded` | approved item 冻结；执行状态只在 M08，不写回本状态 |
| `rejected` / `cancelled` / `superseded` / `excluded` | 只读 | 需变化时创建新 item/replacement plan，不原地复活 |

### 4.3 原子边界与幂等

- 计划草稿使用 `revision + content_hash`乐观锁；编译唯一键为 `item + input_snapshot_hash + compiler_version + capability_revision`。
- 预检唯一键为 `plan_content_hash + policy_versions_hash + capability_view_version + estimate_version`；只复用未过期且依赖一致的报告。
- 批准命令在一个短 PostgreSQL 事务中：锁定计划、验证 selected set/hash/门禁、调 M11 端口预留、写 ApprovalSnapshot/Item states/Outbox；selected set 任一失败全部回滚。`start_now` 再通过 M08 端口只为 ApprovalItems 创建 Operation/Jobs/启动意图；编排器不直写他模块表。
- 每个 PlanItem 的 `execution_key` 在批准时冻结；`start_now` 重放或 M08 对 hold 计划重复执行 `SubmitGenerationPlan` 时只回读同一 M08 Job。
- 外部服务、对象存储、RabbitMQ 不在批准事务内调用。

## 5. 页面与可观察状态

| 页面 | 必须展示 | 动作/禁用原因 |
| --- | --- | --- |
| 生成计划列表 | purpose、范围、状态、ready/blocked/approved/excluded item 数、估算区间、批准人、上下文漂移 | 新建、把 excluded items 复制到替代计划、打开 M08 Operation |
| 计划详情/批准 | 逐项状态/报告、selected set、ApprovalSnapshot、输入/参考、外发数据、上限、并发/失败策略、`start_now` 或 `hold` | 自动选择全部当前 ready items；集合内任一失败则整次禁用/回滚；excluded 只允许复制到 replacement |
| Prompt 编译视图 | 结构来源、positive/negative、参数、omission/warning、compiler/profile 版本、人工 patch | 修改 patch、重编译、回到 M04/M05 修正事实 |
| 路由视图 | eligible/rejected 能力、硬过滤/排序原因、连接 as-of、primary/fallback、覆盖影响 | 只能覆盖为 eligible；过期 RoutabilityView 先刷新 |
| 预检报告 | 六类门禁逐项 pass/warn/block/unknown、证据引用、版本、expiry | 逐项修复链接、重跑失败项、仅选可批准项 |

可观测指标包括编译可复现不一致数、omission/人工修改率、硬过滤 reason 分布、预检阻塞/过期率、估算覆盖/误差、批准率、hold 停留时间和业务幂等重放数。

## 6. 失败与恢复

| 错误码 | 语义 | 恢复动作 |
| --- | --- | --- |
| `plan_input_incomplete` | 缺 ShotPlan/实体状态/参考/输出规格 | 返回具体 M04/M05 对象和字段 |
| `capability_unavailable` | 无能力或无可用 M08 连接 | 等待恢复或创建替代路由计划 |
| `prompt_constraint_exceeded` | Prompt/参考/参数超限 | 显示受影响字段，调整上游或选其他 eligible 能力 |
| `governance_blocked` | 权利/地区/数据条款/内容策略不允许 | 更换输入/能力或进入 M14 具名处理 |
| `usage_cap_exceeded` / `usage_estimate_unknown` | 超上限或无可签认估算 | 缩小范围、改规格或以明确保守上限重新预检 |
| `preflight_stale` / `plan_version_conflict` | 报告或计划不是当前 revision/hash | 返 current hash/diff，重新预检，不部分批准 |
| `approved_plan_not_startable` | hold 启动时动态健康/权利/资源撤销 | 保留 approved，等待恢复或创建替代计划 |

## 9. 验证与交付顺序

切片 A 先用受限 fixture purpose 验证 `Plan/Item → Operation/Job/Attempt → Candidate`、固定 input hash、零外部用量和重复命令不重复事实；不得据此验收 Prompt、路由或真实 Provider。切片 C 再用一个图像和一个视频 CapabilityRevision 完成冻结输入→编译→预检→批准→M08 执行的真实闭环；验证 Golden 编译、约束属性测试、逐项预检、并发批准和资源预留。PLN-FR-012/AC-PLN-008 只在两个真实同类视频能力通过故障切换 Gate 后验收，不提前增加调度微服务。
