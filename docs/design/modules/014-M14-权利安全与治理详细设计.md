# M14 权利、安全与治理详细设计

> Design ID：DES-M14
> Requirement：[REQ-GOV](../../requirement/014-M14-权利安全与治理需求.md)
> 状态：proposed

## 1. 设计结论与范围

M14 是有明确端口和事实所有权的横切治理模块，不是全局 `utils`。它拥有权利/同意事实、提供商条款与治理策略版本、可复现评估、`PolicyException`、保留/删除/法定保全和治理审计；上传、参考绑定、Agent、计划、Provider 提交、外部分享和交付模块在各自动作边界调用 M14。

M14 **拥有私有能力/扩展的准入策略和提供商条款，不拥有 Capability 或执行**。M07 拥有 `CapabilityRevision`、资格与路由；M08 拥有 `ProviderConnection`、健康事实、Job/Attempt 和执行；M15 只编排注册工作流。M14 返回 `allow/block/review`、理由和政策证据，不创建/启停 Capability、不选择路由、不检查连接心跳、不提交或取消任务。

### 1.1 范围内

- 来源、创建者、许可用途/地域/期限/外部模型处理与真人/IP/品牌等权利声明；
- Provider 地域、保留、训练使用、删除、内容/许可边界的条款快照；
- Workspace/项目/内容类型/Provider 的外发、内容安全、品牌、分享和交付策略；
- 绑定动作版本的可复现 PolicyEvaluation、具名例外及未来动作重评估；
- 数据保留、删除、LegalHold、治理审计与私有能力/扩展准入规则；
- AgentRun 与媒体生成分别按实际外发字段、用途和 Provider 评估。

### 1.2 非目标

- 法律意见、自动证明版权归属、商业分成或把安全评分当作创作主选；
- M07 Capability schema/资格/路由、M08 Provider 连接/健康/执行、M15 注册流程；
- 替代 M10 QualityRiskAcceptance、M11 UsageException 或 M12 ReviewDecision；
- 将管理员身份视为静默绕过策略的通行证。

## 2. 事实所有权与数据模型

| 对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| `RightsDeclaration` / `RightsRevision` | subject/source/creator、basis、uses、regions、validity、external processing、person/IP/brand/music/font flags、unknowns、evidence | 只追加修订；声明是证据不是法律证明；未知按动作政策处理 |
| `ConsentRecord` / `ConsentRevision` / `ConsentProof` | person/voice、purpose、region、validity、proof hash/location ref、revocation | 证明不可被新版本覆盖；撤销只影响未来动作并保留历史依据 |
| `ProviderTermsSnapshot` | provider/offering、region、retention、training use、deletion、data classes、content/licensing terms、source/effective time | 条款快照不可变；M08 connection 只引用，不复制为健康配置 |
| `GovernancePolicyRevision` | scope、action/content/provider selectors、rules/severity、effective range、version | 发布后冻结；规则解析确定且可重放 |
| `CapabilityAdmissionPolicyRevision` | private model/LoRA/extension required declarations、allowed regions/data、health/revocation conditions | 只拥有准入条件；不拥有 capability/connection/runtime 状态 |
| `PolicyEvaluation` | action、subject/input hash、actual outbound summary hash、provider/terms/policy revisions、result/reasons、next actions | 每次动作独立追加；早期 allow 不自动传递到后续动作 |
| `PolicyException` | evaluation、exact subject/action/provider/rule、reason、approvers、effective range、status | 范围不可扩张；到期/撤销自动失效；不能替代其他模块决定 |
| `RetentionPolicyRevision` | data class、scope、duration、delete/export/backup behavior | 发布后冻结；与 LegalHold 共同解析 |
| `LegalHold` | scope/object manifest、reason/authority、placed/released by/time、status | active hold 阻止物理删除；普通管理员不能静默解除 |
| `DataLifecycleCase` / `LifecycleItemResult` | request、DB/object/derived/backup/export manifest、hold refs、per-item result | 删除逐项记录；partial 不可标记 completed |
| `GovernanceAuditEvent` | actor/action/subject/evaluation/policy refs、result、trace、redacted summary | 只追加、Workspace 隔离；不复制敏感正文/凭据/媒体 |

## 3. 动作门禁与决策语义

| 动作 | 调用边界 | 必须冻结的最少输入 | 默认失败策略 |
| --- | --- | --- | --- |
| 来源/媒体上传接纳 | M02/M09 写入可用状态前 | source/creator、权利声明、file security、data class、retention policy | 缺失/冲突项阻止对应可用状态；可保留隔离上传 |
| 参考绑定 | M04/M05/M07 绑定前 | subject/version、用途、真人/IP/品牌/音乐/字体限制 | 未知或不兼容阻止绑定 |
| AgentRun 外发 | M06 每个实际外部调用前 | actual fields/data classes、purpose、model/provider/region、terms | 高风险/服务不可用 fail closed |
| GenerationPlan 批准 | M07 批准/路由前 | Prompt/参考/媒体摘要、purpose、候选 capability/provider terms | 返回能力级 allow/block；M07 决定资格/路由 |
| Provider Job 提交 | M08 每次新外部提交前 | frozen payload summary、chosen provider/region/terms、latest relevant rights | 重新评估；旧 Plan allow 不替代提交时 Gate |
| 外部审阅分享 | M12 F Gate 创建/使用 grant 前 | package/display fields、reviewer、download action、region/expiry | 策略不可用或字段超范围时拒绝 |
| 正式交付/下载 | M13 preflight/grant/download 前 | 全部采用输入、intended use/region/expiry、review/rights evidence | 阻止新交付/访问；历史 Snapshot 不改写 |

`allow` 只对 `action + subject versions + outbound hash + provider terms/policy versions` 有效。输入、用途、Provider、地域、条款或策略任一变化都必须新评估。`block` 返回 `rule_id`、依据版本、受影响对象、可执行下一动作；`review` 只能进入具名复核/例外流程，不能静默放行。

## 5. 模块边界与跨模块契约

### 5.1 所有权矩阵

| 事实/动作 | M14 | 其他模块 |
| --- | --- | --- |
| 权利、同意、条款、治理/准入规则、PolicyEvaluation/Exception | 拥有 | 各模块只保存引用并执行 allow/block |
| CapabilityRevision、能力资格、路由/降级 | 不拥有、不修改 | M07 拥有并消费 M14 evaluation |
| ProviderConnection、凭据、健康检查、Operation/Job/Attempt、提交/取消/对账 | 不拥有、不执行 | M08 拥有；向 M14 提供 connection/health/terms source refs |
| 私有能力/扩展注册申请与审批编排 | 不拥有流程 | M15 拥有；调用 M14/M07/M08 阶段端口 |
| QualityRiskAcceptance、UsageException、ReviewDecision | 不拥有 | 分别由 M10/M11/M12 拥有；M14 例外不能代替 |
| Candidate/Selection、DeliverySnapshot | 不拥有 | M09/M13 拥有；M14 只评估动作和引用版本 |

### 5.2 端口与事件

| 调用方/提供方 | 契约 | 方向 | 关键语义 |
| --- | --- | --- | --- |
| M02/M09 | `EvaluateUploadAdmission`、`RightsChanged` | 双向 | 可隔离保存文件，但 Gate 未通过不得成为可用来源 |
| M04/M05 | `EvaluateReferenceBinding` | → M14 | 绑定具体 subject/version/use；M14 不写实体或镜头 |
| M06 | `EvaluateAgentOutbound` | → M14 | 传实际字段类别/目的/Provider，不传“Agent 分析”泛化标签 |
| M07 | `EvaluatePlan/CapabilityAdmission`；`GovernanceEligibilityChanged` | 双向 | M07 自己发布/停用 Capability、决定路由；M14 只返回规则结果 |
| M08 | connection/health/terms source refs；`EvaluateProviderSubmission` | 双向 | M08 自己检查健康并执行；条款变化与健康变化是不同事实 |
| M10/M12/M13 | quality/review/assembly/snapshot refs；share/delivery Gate | → M14 | M14 不替代各自批准，也不修改其对象 |
| M15 | registration manifest；admission result | 双向 | M15 编排，M14 不创建 CapabilityRevision/ProviderConnection |
| M14 | `RightsChanged`、`ProviderTermsChanged`、`PolicyChanged`、`PolicyExceptionExpired`、`LegalHoldChanged` | → 消费方 | 事件提示重评；不能直接改写其他模块状态 |

### 5.3 评估契约

`PolicyEvaluationRequest` 必须包含 `workspace/project`、`action`、`actor/service identity`、`subject refs + revisions`、`canonical input/outbound hash`、`purpose/region`、可选 `provider/terms ref` 和已声明例外 refs。返回：

- `result`：`allow | block | review`；
- `rule_results[]`：rule/policy/terms refs、affected subjects、reason code、脱敏说明；
- `next_actions[]`：补声明、改 Provider/数据范围、申请受限例外或停止；
- `valid_for`：精确 action/input/provider/versions，有效期不是通配授权。

调用模块必须在动作事务边界检查返回引用仍有效。策略事件通过 Outbox/Inbox 至少一次投递；执行门禁不能只依赖异步投影。

## 6. 关键状态、并发与幂等

### 6.1 状态机

| 对象 | 合法状态与转换 | 不变量 |
| --- | --- | --- |
| RightsRevision | `draft → active`；active 可因新 revision `superseded`，或 `expired/revoked` | 历史 revision 永久可读；恢复需新 revision |
| GovernancePolicyRevision/TermsSnapshot | `draft → published → superseded/retired` | published 内容不可改；effective range 明确 |
| PolicyEvaluation | 创建即 `allow/block/review`，后续可显示 `stale` 投影 | 结论本身不改写；新输入/政策生成新 Evaluation |
| PolicyException | `requested → approved \| rejected`；approved `→ expired \| revoked` | 失效不恢复；重新批准新对象 |
| LegalHold | `active → released` | release 需要独立权限/依据；不可删除历史 |
| DataLifecycleCase | `planned → executing → completed \| partial \| blocked_by_hold \| failed`；partial/failed 可 `→ executing` | 所有 item 成功才 completed；hold 解除后重新评估再执行 |

### 6.2 并发规则

1. 政策/权利发布用 scope head `expected_revision`；并发发布只有一个成为新 head，另一方获得差异。
2. 评估先解析全部 revision，规范化输入并计算 hash；写入时若相关 head 已变化，返回 `policy_changed` 并重新评估，不能用旧 allow 提交。
3. `PolicyException` 批准事务锁 request，重新校验权限、exact scope、未过期和 evaluation 状态；重复批准不扩张范围。
4. `PlaceLegalHold` 与 Lifecycle item 物理删除竞争时，对相同 object manifest 加锁；删除前最后一次检查 active hold。
5. 条款/权利变化只发布 affected refs；M07/M08/M12/M13 对新动作同步重评，历史 Job/Evaluation/Snapshot 不更新。

### 6.3 幂等键

| 写入 | 幂等键 | 重复结果 |
| --- | --- | --- |
| Declare/ReviseRights | subject + revision request key | 回读同 revision；payload hash 不同冲突 |
| RecordPolicyEvaluation | action + canonical input hash + policy/terms set + request key | 回读同 Evaluation |
| ApprovePolicyException | exception request + approver + decision round | 回读同决定 |
| Place/ReleaseLegalHold | scope manifest hash + authority request key | 回读同 hold/释放记录 |
| Lifecycle item action | case + store + object ref + action version | 回读 per-item result，不重复物理操作 |

## 8. 失败路径与恢复约定

| 场景 | 用户结果 | 恢复 |
| --- | --- | --- |
| 权利信息缺失/冲突 | 明确受影响对象/动作和所缺声明，外发/分享/交付被阻止 | 补 RightsRevision/证据后新评估 |
| 许可到期 | 新动作阻止，历史 Evaluation/Snapshot 显示当时依据 | 更新许可形成新 revision；不改历史 |
| Provider 条款变化 | 显示受影响计划/数据，停止不兼容的新路由 | M14 新评估；M07 选择兼容能力，M08 保留已提交 Job 对账 |
| M08 健康异常 | 页面显示连接健康引用，M07/M08 停止新路由/执行 | M08 恢复健康后 M07 重算资格；M14 不操作连接 |
| 策略服务不可用/规则 unknown | 高风险动作 fail closed 并给 trace | 恢复评估；应急也必须具名、限范围、限时并追加审计 |
| 内容误报 | 保留规则和输入 hash，进入 review | 具名复核或受限 PolicyException；不修改原 Evaluation |
| 删除与 LegalHold 冲突 | case `blocked_by_hold`，说明 authority/范围（按权限脱敏） | hold 合法释放后重新评估并恢复未完成 item |
| 下游未处理 policy change event | 异步投影可 stale，但新动作仍同步 Gate | Inbox 重投；监控消费延迟，不用事件代替同步判断 |

## 11. 实施顺序与门禁

1. **A**：巩固 Rights/Consent 的追加版本、上传/参考绑定 Gate 与统一拒绝契约。
2. **C**：Provider 条款、外发披露、内容/品牌规则、Agent/媒体独立评估和 M07/M08 提交 Gate。
3. **E**：接入 M12/M13 分享、交付、下载复核，保持三类例外互不替代。
4. **F**：企业政策层级、Retention/Deletion/LegalHold/Audit export，以及 M15 注册流程中的准入规则评估。

任何阶段都由 M07/M08 执行 Capability 资格、路由、健康与任务动作；M14 只提供政策/条款和可审计决定。
