# M03 导入与叙事理解详细设计

> Design ID：DES-M03
> Requirement：[REQ-NAR](../../requirement/003-M03-导入与叙事理解需求.md)
> 专题细化：[剧本基础分析与人物拆解](../004-AI视频生产平台剧本基础分析与人物拆解详细设计.md)
> 状态：proposed

## 1. 设计结论

导入采用“不可变来源 → 确定性 ParseReport → 剧集拆解 → 结构/Mention Proposal → 人工决议 → approved NarrativeRevision → 可重建全文检索”模型。项目级整本 SourceRevision 不要求预先存在 ContentUnit：M03 先批准 EpisodeBreakdownManifest，M02 再物化稳定 ContentUnit 与顺序。解析和 Agent Worker 不能直接发布叙事；所有正式下游只读取明确批准修订。Elasticsearch 只索引 approved 节点并提供派生搜索，不参与解析、批准或 current 判定。

## 2. 组件与数据

| 组件/聚合 | 职责 |
| --- | --- |
| Source / SourceRevision | 原文件/文本、哈希、格式、语言、完整性和对象存储引用 |
| ImportRun / ParseReport | 阶段、覆盖、缺口、页段映射、错误和恢复点 |
| AnalysisRun | 整本分析的业务执行索引、根 Operation、当前门禁、stage 输入/结果引用和恢复摘要；不保存 Agent checkpoint |
| SourceAnchor | source revision + block/range/hash，提供证据回跳 |
| EpisodeBreakdownRevision / EpisodeCandidate | 整本来源的候选剧集边界、临时 key、顺序、标题、证据、覆盖和人工决议 |
| EpisodeBreakdownManifest | approved 不可变拆集清单；作为 M02 物化输入，不包含正式 ContentUnit ID |
| NarrativeDraftImport | 绑定 approved Manifest/mapping/Order 的私有 building revision 与逐 ContentUnit staging 状态；finalize 前普通查询不可见 |

## 3. 处理流水线

1. API 直传对象后提交 SourceRevision 与 Operation/Outbox；
2. 解析 Worker 进行格式识别、文本块化和确定性结构提取，并对项目级来源形成 EpisodeCandidate；
3. 结果端口幂等写 ParseReport/Anchor，部分失败保留已知覆盖；用户校对剧集 split/merge/reorder/rename/边界与具名忽略；
4. M03 批准 EpisodeBreakdownManifest，M02 原子物化稳定 ContentUnit 与 OrderRevision，M03 保存临时 key→ContentUnit mapping；
5. 切片 A 由确定性解析结果和人工命令创建/编辑/删除 Scene、Beat、Dialogue、Action、Narration 与 ProductionElementMention；切片 B 的 breakdown AgentRun 输出自包含 `CreateEpisodeBreakdownDraft`，narrative AgentRun 按稳定 ContentUnit 输出 `ApplyNarrativeContentUnitDraft`，由 `Start/FinalizeNarrativeDraftImport` 组织私有 building revision；这些均通过 M06 AgentProposal 执行，不在 M03 再写同义 NarrativeProposal；
6. 用户在原文对照界面校对结构和 Mention，M03 仅决定 Mention/Proposal 是否进入 NarrativeRevision，不解析正式实体身份；批准命令验证覆盖、冲突、权限和 expected revision，发布 NarrativeRevision、GlobalOccurrenceIndex 与最小 Outbox ref；Go operation-worker 回读 approved 节点后更新 NarrativeSearchProjection；
7. Narrative 批准后，M03 AnalysisRun Service 在切片 B 通过 Outbox 创建 knowledge AgentRun；切片 A 则进入 M04 手工工作台。M04 的 Resolution/Coverage/Requirement 门禁与三个投影均满足后，M03 通过公开 preflight 查询完成根 AnalysisRun/Operation，再通知 M05 等下游计算影响。

### 3.1 AnalysisRun 根编排

M03 `AnalysisRunService` 是整本分析根流程的唯一编排者，但不跨表写 M02/M04/M06 事实：

| 已完成事实/事件 | Service 动作 | 下一状态与幂等 |
| --- | --- | --- |
| `StartWholeScriptAnalysis` | 创建 AnalysisRun、root Operation 与 `stage_generation=1` 的 breakdown AnalysisStage；切片 A 打开确定性/手工路径，切片 B 同事务发布 stage Outbox，由 M06 消费并创建 `StartAgentRun(stage=breakdown)` | M03 在 `agent.run.created` 后保存 run/child operation refs；`analysis_run + stage + stage_generation + input_hash` 唯一；切片 A 不制造空 AgentRun |
| `EpisodeBreakdownApproved` | 调用 M02 `Prepare/ApplyContentUnitMaterialization` | root running/materializing；重复事件回读同一 materialization |
| `ApplyContentUnitMaterializationResult` | 校验 Manifest/result hash，创建 DraftImport；切片 B 发布 narrative stage Outbox，由 M06 创建新 AgentRun，切片 A 开放手工编辑 | 保存 mapping/order/draft import/stage refs；收到 M06 created 事件后记录 run/child；不按 ordinal 猜 ID |
| `NarrativeRevisionApproved` | 发布 approved view；切片 B 发布 knowledge stage Outbox，由 M06 创建新 AgentRun，切片 A 打开 M04 手工门禁 | root running/knowledge；同 narrative basis/stage generation 只建一个 child Run |
| M04 `EntityOccurrence/Inventory/Readiness` changed | 固定同一 approved view basis，查询 M04 `GetKnowledgeCompletenessSnapshot`；由 M03 `GetScriptAnalysisApprovalPreflight` 组合拆解、mapping、叙事和知识门禁，只在三个投影 current/complete、failed scopes 为空、unassessed/unassigned/overlap 为 0 时执行 `CompleteAnalysisRun` | root completed；否则 `waiting_user(gate=knowledge_review)` 并记录具名 blocker/recovery action；M04 不拥有根流程完成语义 |
| `CancelAnalysisRun` | CAS 为 cancelling，经公开端口请求取消当前 child AgentRun/Operation、未提交的 M02 materialization 和未 finalize DraftImport；等待回执或 Reconciler 收敛 | root `cancelling → cancelled`；已批准 Manifest/Narrative、已物化 ContentUnit/mapping 和已提交 item 不回滚，迟到结果仅审计 |
| `RetryAnalysisStage` | 仅对当前 failed/partial stage 的具名 scope，以完全相同 basis/input hash 创建 successor child AgentRun/Operation；成功范围与既有人工决定不重算 | root 回到 `analyzing(stage)`；`analysis_run + stage + stage_generation + input_hash` 唯一；输入变化必须创建 successor AnalysisRun |

每个 child AgentRun 结束只让根 AnalysisRun/Operation 进入对应 `waiting_user`，不能完成根流程。`RecordAnalysisStageRun`、`AdvanceAnalysisStage`、`CompleteAnalysisRun` 是 M03 Service 的受保护内部命令，均要求 expected stage/gate、current child run、basis hash 和幂等键；旧 stage/generation 的迟到 callback 只追加审计，不推进 root。手工切片 A 跳过 M06 child，但经过相同 Manifest、mapping、Narrative 和 M04 preflight 门禁。

## 5. 关键算法约束

Chunk 不切断已识别剧集或场次；全局 Reduce 汇总同名/别名候选但不创建正式实体。P0 自动边界只接受签认结构、明确集标题或签认分段元数据；缺标题/冲突只生成 Proposal，不按篇幅平均切分。Unicode Anchor 使用稳定 block + code point/grapheme 校验，offset 仅为内部优化。来源覆盖守恒：非空范围必须恰好属于一个 EpisodeCandidate/ContentUnit 或有显式忽略原因，Scene 不得跨集。

## 6. 状态、幂等与恢复

`ImportRun` 只表达文件解析执行：`queued → parsing → analyzing → waiting_user | partial | completed | failed | cancelled | superseded`。对同一阶段输入哈希执行 `RetryImportStage` 时，`partial → analyzing → waiting_user | completed | partial | failed`，已成功范围继续复用；输入、解析规则或 Schema 变化时创建 successor ImportRun，并将旧 Run 标为 superseded。

`AnalysisRun` 独立表达整本业务流程，可多次进入执行和人工门禁：

```text
queued
  → analyzing(stage=breakdown) → waiting_user(gate=breakdown_review)
  → running(stage=materializing)
  → analyzing(stage=narrative) → waiting_user(gate=narrative_review)
  → analyzing(stage=knowledge) → waiting_user(gate=knowledge_review)
  → running(stage=preflight) → completed
任一活动状态 → partial | failed | cancelling → cancelled | superseded
partial/failed → RetryAnalysisStage(same basis/input hash) → analyzing(current stage)
```

`NarrativeDraftImport` 为 `building ↔ partial → ready_to_finalize → finalized`，也可从非终态进入 `stale | cancelled`。每个 ContentUnit slot 为 `pending → applied | manual_filled | failed`；拒绝或暂缓 M06 Proposal 不改变 slot 的 `pending`，必须用 successor 提案或人工补齐。只有全部 slot 为 `applied | manual_filled`、failed scopes 为空且 coverage 完整时才能进入 `ready_to_finalize`；Finalize 后才把私有 building revision 切换为普通查询可见的 draft。EpisodeBreakdownRevision 为 `draft → proposed → approved → superseded`；M03 原生 ProposalItem 为 `pending → accepted | edited | rejected | deferred | stale`；NarrativeRevision 为 `draft → proposed → approved/current → superseded | archived`；这些对象不共用状态。unknown 模型调用先对账，不创建第二套 Proposal。

文件损坏、加密、部分页失败、模型失败和并发编辑都返回类型化错误与恢复动作；PDF/OCR feature flag 关闭时明确拒绝，开启前必须通过页码、OCR 置信和部分失败专项验收。

## 7. 安全、观测与验证

解析容器无默认外网、限制解压倍率/内存/时间；日志只保存哈希和短摘要，禁止把 Elasticsearch 检索正文复制到日志。Search Service 每次先做 M01 鉴权并从 PostgreSQL 解析 workspace/project/approved revision set，再强制注入 Elastic filter；frontend 与 Agent 均不得持有 Elastic 凭据。指标包括覆盖率、人工修正率、Anchor 失败、分阶段耗时、恢复率、搜索 p95/零结果率、投影 lag 和重建一致率。

验证映射 NAR-FR-001—015、NAR-NFR-001—008、AC-NAR-001—013；切片 A 先做 DOCX/Markdown/TXT、确定性/手工拆集、手工结构与全局索引校对；全文检索在 A10 以 approved 金标和一个 Elastic adapter 完成，切片 B 接 Agent 提案与 run-scoped Search Tool。

## 9. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| M02 → M03（已有内容单元输入） | `ProjectScope`、可选 `ContentUnitRef`、Brief revision；项目级整本来源只要求 project scope | M02 拥有内容单元身份与顺序，M03 拥有来源正文、拆解和 NarrativeRevision；尚未拆集时不得强制 `content_unit_id` |

| M04 → M03 Search | `GetNarrativeSearchEnrichmentView(narrative_revision_id/hash, occurrence/inventory basis hash, filter_completeness, node/scene→entity/unresolved-subject/location/requirement refs)` | 只用于 enrich Elasticsearch filter 字段；知识 incomplete 时全文索引仍可用但 filter 标 stale/incomplete；M03/Elastic 不复制或拥有 M04 current |
| M03 → M05 | `ApprovedNarrativeView(revision_id, scenes, beats, dialogue, actions, anchors)` | M05 只能绑定 approved revision；draft/proposal 查询不得进入 ShotPlan 正式输入；换版只发 impact，不迁移镜头 |
| M03 → M06 | `ScriptAnalysisStageRequest(analysis_run_id, stage=breakdown\|narrative\|knowledge, stage_generation, input_hash, based_on_refs, failed_scope_filter, root_operation_id, allowed_command_schema_refs/hash, idempotency_key)`，通过 `narrative.analysis_stage.requested` Outbox 发布 | M06 创建一个 AgentRun 和一个 child Operation；同 `analysis_run + stage + stage_generation + input_hash` 回读；请求不携带正文或未接受 Candidate ID |
| M03 → M06 Search Tool | run-scoped `SearchApprovedNarrative(query, exact project/revision scope, filters, limit)` 只读能力 | Python 只能经 backend Tool capability 调用；Go 重新鉴权、强制 scope/revision filter并返回 Anchor；Agent 无 Elasticsearch endpoint/API key，搜索结果不能直接成为 Proposal 证据之外的批准事实 |
| M06 → M03 | `agent.run.created` 映射为 `ScriptAnalysisStageRunRecorded(analysis_run_id, stage, stage_generation, agent_run_id, child_operation_id, input_hash)`；`agent.run.result_committed` 映射为 `ScriptAnalysisStageFinished(..., status, result_hash, failed_scopes, sequence)` | M03 Inbox 按 event ID 与 run/sequence 幂等接收并校验 current stage/generation/input hash；completed/partial 仅推进到相应 `waiting_user`，不完成 root；cancelled/superseded root 或迟到旧 generation 只追加审计 |
| M06 → M03 | breakdown 的 M06 `AgentProposalItem` 承载 `CreateEpisodeBreakdownDraft`；narrative 每个稳定 ContentUnit 的 item 承载 `ApplyNarrativeContentUnitDraft`，由 M03 已创建的 DraftImport 聚合；接受后调用 M03 `ExecuteProposedCommand` | M03 校验 schema、Anchor、Manifest/mapping/Order/input/payload hash；大 payload 只用受限 immutable ref；Apply 只写私有 building revision，Finalize 后仍只是 draft，绝不批准；M03 不创建同义 NarrativeProposal，只可在结果 Revision/ImportItem 记录 `origin_ref` |

## 10. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| SourceRevision | 创建即不可变；可被 newer revision supersede 但不删除 | `(source_id, revision_no)` 唯一；上传意图 + idempotency key 唯一；hash 相同是否复用由用户意图决定并审计 |
| ImportRun | `queued → parsing → analyzing → waiting_user \| partial \| completed \| failed \| cancelled \| superseded`；同输入重试允许 `partial → analyzing` | 只表示文件解析；stage/input hash/attempt generation 唯一，输入、规则或 Schema 变化创建 successor ImportRun |
| AnalysisRun | `queued → analyzing(breakdown) → waiting_user(breakdown_review) → running(materializing) → analyzing(narrative) → waiting_user(narrative_review) → analyzing(knowledge) → waiting_user(knowledge_review) → running(preflight) → completed`；活动态可到 `partial/failed/cancelling/cancelled/superseded`，同基线重试回当前 stage | 关联一个 root Operation，明确 `current_stage/current_gate/current_child_agent_run_id/stage_generation`；三个 M06 AgentRun 使用 child Operation；child 结束不完成 root；root 与 AnalysisRun 同步 running/waiting_user/终态；旧 generation/取消后的结果仅审计 |
| StageAttempt | `queued → running → succeeded \| failed \| unknown \| cancelled` | run/stage/sequence 唯一；结果需匹配 input hash/schema；unknown 必须对账后才能新建 attempt |
| ParseReport | 每个 run/stage/result hash 不可变，可有 partial | result port 以 `(run_id, stage, sequence, result_hash)` 去重；旧 sequence 不得覆盖新阶段状态 |
| NarrativeDraftImport | `building ↔ partial → ready_to_finalize → finalized`；非终态可到 `stale \| cancelled` | `(analysis_run, manifest, mapping, order)` 活动导入唯一；building revision 普通查询不可见；Finalize 对 import revision + 完整 slot set/hash 做 CAS，并只切换一个可见 draft pointer |
| NarrativeDraftImportItem | `pending → applied \| manual_filled \| failed` | `(draft_import_id, content_unit_id)` 唯一；Apply 只 CAS 本 slot；`(draft_import_id, content_unit_id, result_hash)` 幂等；其他 slot 的提交不使本项过期；拒绝/暂缓 Agent item 不把 slot 标完成 |
| NarrativeRevision | `draft → proposed → approved/current → superseded \| archived`，base revision 明确 | 每次编辑产生新 draft revision 并 compare-and-set；approved 内容不可变；current pointer CAS；批准幂等键返回同一 revision |
| EpisodeBreakdownRevision | `draft → proposed → approved → superseded`；approved 内容不可变 | source/rule/base hash + idempotency key 唯一；边界编辑生成新 revision；approved Manifest hash 固定，M02 mapping 不回写旧 revision |
| EpisodeContentUnitMapping | 创建即不可变；current 指向一个 manifest/result 组合 | temporary key 和 ContentUnit ID 在同 mapping 内各唯一；只接受 M02 result hash；新拆解通过新 mapping 切换 |
| GlobalOccurrenceIndex | `building → current \| incomplete \| stale \| failed`，绑定 draft/narrative/breakdown revision 与 as_of | 从 Scene/Mention 重建；页面游标绑定 projection version；旧重建不得覆盖新版本 |
| M03 原生 ProposalItem | `pending → accepted \| edited \| rejected \| deferred \| stale` | 仅 `origin=module_native`；deterministic item key 防重复；decision 追加写且 expected decision revision；不得复用 M06 AgentProposal ID/状态 |
| DecisionMigration | `prepared → confirmed \| stale \| cancelled` | manifest 固定 old/new hash；逐项迁移以 old decision + new anchor 唯一，possible match 禁止自动确认 |

ParseReport、Proposal 和 NarrativeRevision 不共用“最新一行覆盖”语义。Worker/result callback 先验证所属 ImportRun/AnalysisRun 未取消、stage generation 与 current child 匹配、sequence 未过时、输入哈希和 schema 一致，再在同一短事务写业务对象、AuditEvent 与 Outbox；迟到结果保留为可诊断 attempt/receipt，但不能成为 current、完成 slot 或推进 root。取消根 AnalysisRun 只传播取消意图并停止后续 stage，不删除已经批准或已经提交的权威事实。
