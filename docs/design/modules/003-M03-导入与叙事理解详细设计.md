# M03 导入与叙事理解详细设计

> Design ID：DES-M03
> Requirement：[REQ-NAR](../../requirement/003-M03-导入与叙事理解需求.md)
> 专题细化：[剧本基础分析与人物拆解](../004-AI视频生产平台剧本基础分析与人物拆解详细设计.md)
> 状态：proposed

## 1. 设计结论

导入采用“不可变来源 → 确定性 ParseReport → 剧集拆解 → 结构/Mention Proposal → 人工决议 → approved NarrativeRevision”模型。项目级整本 SourceRevision 不要求预先存在 ContentUnit：M03 先批准 EpisodeBreakdownManifest，M02 再物化稳定 ContentUnit 与顺序。解析和 Agent Worker 不能直接发布叙事；所有正式下游只读取明确批准修订。

## 2. 组件与数据

| 组件/聚合 | 职责 |
| --- | --- |
| Source / SourceRevision | 原文件/文本、哈希、格式、语言、完整性和对象存储引用 |
| ImportRun / ParseReport | 阶段、覆盖、缺口、页段映射、错误和恢复点 |
| SourceAnchor | source revision + block/range/hash，提供证据回跳 |
| EpisodeBreakdownRevision / EpisodeCandidate | 整本来源的候选剧集边界、临时 key、顺序、标题、证据、覆盖和人工决议 |
| EpisodeBreakdownManifest | approved 不可变拆集清单；作为 M02 物化输入，不包含正式 ContentUnit ID |
| NarrativeRevision | 绑定拆解与 ContentUnit mapping 的版本链及结构覆盖摘要；`draft/proposed` 可校对，只有不可变 `approved/current` 可供正式下游 |
| NarrativeProposal | 字段/结构变更、证据、置信、模型和过期条件 |
| GlobalOccurrenceIndex | 按剧集/场次汇总全剧人物、地点、道具、服装等 Mention 的可重建草稿索引；显示完整度，不发布实体 |
| ApprovedNarrativeAnalysisView | approved Narrative 的统一只读基线 envelope：source/breakdown/mapping/order/narrative refs/hash、completeness、failed scopes，以及 scenes/occurrences 分页查询引用 |

## 3. 处理流水线

1. API 直传对象后提交 SourceRevision 与 Operation/Outbox；
2. 解析 Worker 进行格式识别、文本块化和确定性结构提取，并对项目级来源形成 EpisodeCandidate；
3. 结果端口幂等写 ParseReport/Anchor，部分失败保留已知覆盖；用户校对剧集 split/merge/reorder/rename/边界与具名忽略；
4. M03 批准 EpisodeBreakdownManifest，M02 原子物化稳定 ContentUnit 与 OrderRevision，M03 保存临时 key→ContentUnit mapping；
5. 切片 A 由确定性解析结果和人工命令创建/编辑/删除 Scene、Beat、Dialogue、Action、Narration 与 ProductionElementMention；切片 B 的 AgentRun 可按剧集和完整场次分块、跨全剧 Reduce，只输出同契约的逐项 Proposal；
6. 用户在原文对照界面校对结构和 Mention，M03 仅决定 Mention/Proposal 是否进入 NarrativeRevision，不解析正式实体身份；批准命令验证覆盖、冲突、权限和 expected revision，发布 NarrativeRevision 与 GlobalOccurrenceIndex；
7. Outbox 通知 M04 基于 approved Mention 解析正式实体/生产需求并重建 occurrence，通知 M05 计算下游影响。

## 4. 接口契约

- Commands：`CreateSourceRevision`、`StartImportRun`、`RetryImportStage`、`StartWholeScriptAnalysis`、`ReviseEpisodeBreakdown`、`ApproveEpisodeBreakdown`、`ApplyContentUnitMaterializationResult`、`ApplyNarrativeEdit`、`Create/Edit/DeleteProductionElementMention`、`DecideProposalItem`、`ApproveNarrativeRevision`、`CancelImportRun`；
- Queries：原文/剧集/结构对照、Anchor 回跳、剧集覆盖缺口、`GetApprovedNarrativeAnalysisView`、按剧集场景、全局 ProductionElementMention、运行阶段、修订差异；
- Events：`SourceRevisionCreated`、`ImportRunPartiallyCompleted`、`EpisodeBreakdownApproved`、`NarrativeRevisionApproved`；
- Worker result 必须带 run、stage、input hash、schema version、sequence 和 result hash。

## 5. 关键算法约束

Chunk 不切断已识别剧集或场次；全局 Reduce 汇总同名/别名候选但不创建正式实体。P0 自动边界只接受签认结构、明确集标题或签认分段元数据；缺标题/冲突只生成 Proposal，不按篇幅平均切分。Unicode Anchor 使用稳定 block + code point/grapheme 校验，offset 仅为内部优化。来源覆盖守恒：非空范围必须恰好属于一个 EpisodeCandidate/ContentUnit 或有显式忽略原因，Scene 不得跨集。

## 6. 状态、幂等与恢复

ImportRun 只表达执行状态：`queued → parsing → analyzing → waiting_user | partial | completed | failed | cancelled | superseded`。对同一阶段输入哈希执行 `RetryImportStage` 时，`partial → analyzing → waiting_user | completed | partial | failed`，已成功范围继续复用；输入、解析规则或 Schema 变化时创建 successor Run，并将旧 Run 标为 superseded。EpisodeBreakdownRevision 为 `draft → proposed → approved → superseded`；ProposalItem 为 `pending → accepted | edited | rejected | deferred | stale`；NarrativeRevision 为 `draft → proposed → approved/current → superseded | archived`；四者不共用状态。unknown 模型调用先对账，不创建第二套 Proposal。

文件损坏、加密、部分页失败、模型失败和并发编辑都返回类型化错误与恢复动作；PDF/OCR feature flag 关闭时明确拒绝，开启前必须通过页码、OCR 置信和部分失败专项验收。

## 7. 安全、观测与验证

解析容器无默认外网、限制解压倍率/内存/时间；日志只保存哈希和短摘要。指标包括覆盖率、人工修正率、Anchor 失败、分阶段耗时和恢复率。

验证映射 NAR-FR-001—014、NAR-NFR-001—007、AC-NAR-001—012；切片 A 先做 DOCX/Markdown/TXT、确定性/手工拆集、手工结构与全局索引校对，切片 B 接 Agent 提案。

## 9. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| M02 → M03（已有内容单元输入） | `ProjectScope`、可选 `ContentUnitRef`、Brief revision；项目级整本来源只要求 project scope | M02 拥有内容单元身份与顺序，M03 拥有来源正文、拆解和 NarrativeRevision；尚未拆集时不得强制 `content_unit_id` |
| M03 → M02 → M03（首次拆集） | approved `EpisodeBreakdownManifest` → `ContentUnitMaterializationResult(mapping, order_revision_id, result_hash)` | M03 拥有边界/覆盖，M02 原子创建稳定 ContentUnit；M03 只接受匹配 manifest hash 的 mapping，双方不跨表直写 |
| M03 → M04 | `ApprovedNarrativeAnalysisView(narrative_revision_id/hash, source_revision_set/hash, breakdown_revision_id/hash, mapping/order refs, completeness, failed_scopes, scenes_query_ref, global_occurrences_query_ref, basis_hash)`；分页项使用 `ProductionElementMentionRef`/Scene ref | M04 必须先固定并复核同一个 basis_hash，再分页读取全部 Scene/Mention；M04 独占 UnresolvedSubject/Resolution/Entity/Coverage/Requirement；M03 只拥有来源结构与 Cluster Proposal，不写 target_entity_id |
| M03 → M05 | `ApprovedNarrativeView(revision_id, scenes, beats, dialogue, actions, anchors)` | M05 只能绑定 approved revision；draft/proposal 查询不得进入 ShotPlan 正式输入；换版只发 impact，不迁移镜头 |
| M06 → M03 | AgentRun 提交逐项 `NarrativeProposalItem` | M06 拥有 Agent 编排/checkpoint，M03 校验 schema、Anchor、input hash 后幂等接收；Agent 不调用批准命令 |
| M08 → M03 | `OperationAttemptResult(run_id, stage, sequence, input_hash, result_hash, payload_ref)` | M08 拥有耐久执行，M03 拥有业务结果；unknown attempt 先通过 M08 对账，不盲重发模型调用 |
| M14 → M03 | 上传/解析治理结论、日志最小化策略 | M14 提供允许/阻止结论；M03 仍拥有格式错误与覆盖事实，不在事件中复制完整剧本 |

M03 发布查询必须返回 `ApprovedNarrativeAnalysisView` 的 basis hash、精确 revision refs、schema version、completeness 和 failed scopes；其 scenes/global-occurrences 页必须回显相同 basis hash，混入其他修订的页直接拒绝。下游持久引用至少保存 NarrativeRevision ID 和成员稳定 ID。事件仅携带 view ref、短摘要和哈希，正文通过经授权的 Query/对象存储读取，禁止复制到通用队列载荷。

## 10. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| SourceRevision | 创建即不可变；可被 newer revision supersede 但不删除 | `(source_id, revision_no)` 唯一；上传意图 + idempotency key 唯一；hash 相同是否复用由用户意图决定并审计 |
| ImportRun | `queued → parsing → analyzing → waiting_user \| partial \| completed \| failed \| cancelled \| superseded`；同输入重试允许 `partial → analyzing` | source + pipeline/schema version + idempotency key 唯一；相同 stage input hash 复用成功范围并从 checkpoint 续做；输入/规则/Schema 变化创建 successor 并 supersede 旧 Run；取消只阻止未提交阶段 |
| StageAttempt | `queued → running → succeeded \| failed \| unknown \| cancelled` | run/stage/sequence 唯一；结果需匹配 input hash/schema；unknown 必须对账后才能新建 attempt |
| ParseReport | 每个 run/stage/result hash 不可变，可有 partial | result port 以 `(run_id, stage, sequence, result_hash)` 去重；旧 sequence 不得覆盖新阶段状态 |
| NarrativeRevision | `draft → proposed → approved/current → superseded \| archived`，base revision 明确 | 每次编辑产生新 draft revision 并 compare-and-set；approved 内容不可变；current pointer CAS；批准幂等键返回同一 revision |
| EpisodeBreakdownRevision | `draft → proposed → approved → superseded`；approved 内容不可变 | source/rule/base hash + idempotency key 唯一；边界编辑生成新 revision；approved Manifest hash 固定，M02 mapping 不回写旧 revision |
| EpisodeContentUnitMapping | 创建即不可变；current 指向一个 manifest/result 组合 | temporary key 和 ContentUnit ID 在同 mapping 内各唯一；只接受 M02 result hash；新拆解通过新 mapping 切换 |
| GlobalOccurrenceIndex | `building → current \| incomplete \| stale \| failed`，绑定 draft/narrative/breakdown revision 与 as_of | 从 Scene/Mention 重建；页面游标绑定 projection version；旧重建不得覆盖新版本 |
| ProposalItem | `pending → accepted \| edited \| rejected \| deferred \| stale` | deterministic item key 防重复；decision 追加写且 expected decision revision；来源/草稿变化标 stale |
| DecisionMigration | `prepared → confirmed \| stale \| cancelled` | manifest 固定 old/new hash；逐项迁移以 old decision + new anchor 唯一，possible match 禁止自动确认 |

ParseReport、Proposal 和 NarrativeRevision 不共用“最新一行覆盖”语义。Worker result 先验证 run 未取消、sequence 未过时、输入哈希和 schema 一致，再在同一事务写业务对象、AuditEvent 与 Outbox；迟到结果保留为可诊断 attempt，但不能成为 current。

| 批准与修订差异 | 比较 draft/current、确认影响、批准/切换 | draft/proposed/approved/current/superseded、diff、阻塞项、下游 impact running/stale/failed |
| 来源换版（P1） | 比较来源、预览并确认决议迁移 | added/deleted/moved/modified、exact/possible/unmatched、manifest progress 和待确认项 |

错误状态必须区分 `unsupported_format`、`encrypted_or_corrupt`、`partial_ranges`、`anchor_stale`、`stage_failed`、`attempt_unknown`、`edit_conflict`、`approval_blocked`。任何 partial/unknown 都不能渲染成空剧情或完成；每个失败状态至少提供换文件、局部重试、人工补录、回到原文或基于新 revision 重放中的一个明确动作。
