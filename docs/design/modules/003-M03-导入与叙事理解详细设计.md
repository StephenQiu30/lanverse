# M03 导入与叙事理解详细设计

> Design ID：DES-M03
> Requirement：[REQ-NAR](../../requirement/003-M03-导入与叙事理解需求.md)
> 专题细化：[剧本基础分析与人物拆解](../004-AI视频生产平台剧本基础分析与人物拆解详细设计.md)
> 状态：proposed

## 1. 设计结论

导入采用“不可变来源 → 确定性 ParseReport → AI Proposal → 人工决议 → approved NarrativeRevision”五层模型。解析和 Agent Worker 不能直接发布叙事；所有下游只读取明确批准修订。

## 2. 组件与数据

| 组件/聚合 | 职责 |
| --- | --- |
| Source / SourceRevision | 原文件/文本、哈希、格式、语言、完整性和对象存储引用 |
| ImportRun / ParseReport | 阶段、覆盖、缺口、页段映射、错误和恢复点 |
| SourceAnchor | source revision + block/range/hash，提供证据回跳 |
| NarrativeDraft | Scene/Beat/Dialogue/Action/Narration/Mention 草稿 |
| NarrativeProposal | 字段/结构变更、证据、置信、模型和过期条件 |
| NarrativeRevision | approved 不可变结构和覆盖摘要 |

## 3. 处理流水线

1. API 直传对象后提交 SourceRevision 与 Operation/Outbox；
2. 解析 Worker 进行格式识别、文本块化和确定性结构提取；
3. 结果端口幂等写 ParseReport/Anchor，部分失败保留已知覆盖；
4. AgentRun 按场次分块、全局 Reduce，输出逐项 Proposal；
5. 用户在原文对照界面拆分、合并、重排、标 unknown 或忽略；
6. 批准命令验证覆盖、冲突、权限和 expected revision，发布 NarrativeRevision；
7. Outbox 通知 M04/M05 计算新增提案和下游影响。

## 4. 接口契约

- Commands：`CreateSourceRevision`、`StartImportRun`、`ApplyNarrativeEdit`、`DecideProposalItem`、`ApproveNarrativeRevision`、`CancelImportRun`；
- Queries：原文/结构对照、Anchor 回跳、覆盖缺口、运行阶段、修订差异；
- Events：`SourceRevisionCreated`、`ImportRunPartiallyCompleted`、`NarrativeRevisionApproved`；
- Worker result 必须带 run、stage、input hash、schema version、sequence 和 result hash。

## 5. 关键算法约束

Chunk 不切断已识别场次；全局 Reduce 统一同名 Mention 但不创建正式实体。Unicode Anchor 使用稳定 block + code point/grapheme 校验，offset 仅为内部优化。来源覆盖守恒：非空范围必须由节点覆盖或有显式忽略原因。

## 6. 状态、幂等与恢复

ImportRun：`queued → parsing → analyzing → waiting_user | partial | completed | failed | cancelled`。相同来源哈希和阶段版本可以回读结果；输入或解析规则变化创建新 Run。unknown 模型调用先对账，不创建第二套 Proposal。

文件损坏、加密、部分页失败、模型失败和并发编辑都返回类型化错误与恢复动作；PDF/OCR feature flag 关闭时明确拒绝，开启前必须通过页码、OCR 置信和部分失败专项验收。

## 7. 安全、观测与验证

解析容器无默认外网、限制解压倍率/内存/时间；日志只保存哈希和短摘要。指标包括覆盖率、人工修正率、Anchor 失败、分阶段耗时和恢复率。

验证映射 NAR-FR-001—012、NAR-NFR-001—006、AC-NAR-001—009；切片 A 先做 DOCX/Markdown/TXT 和手工校对，切片 B 接 Agent 提案。
