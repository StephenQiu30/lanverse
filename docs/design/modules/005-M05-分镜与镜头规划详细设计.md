# M05 分镜与镜头规划详细设计

> Design ID：DES-M05
> Requirement：[REQ-SHT](../../requirement/005-M05-分镜与镜头规划需求.md)
> 状态：proposed

## 1. 设计结论

Shot 是稳定生产身份，ShotPlanRevision 是拍法，ShotOrderRevision 是播放顺序。覆盖关系、连续性依赖和分镜媒体选择分别表达；M05 不维护 Candidate 或 Selection 的副本。

## 2. 数据设计

| 对象 | 关键字段/约束 |
| --- | --- |
| Shot | content_unit、lineage、status；ID 不复用 |
| ShotPlanRevision | purpose、framing、camera、motion、action、performance、duration、unknowns、status |
| NarrativeBinding | narrative revision、scene/beat、coverage_kind |
| EntityBinding | entity、state revision、role、continuity purpose |
| ShotOrderRevision/Item | content unit、shot、ordinal；同修订唯一 |
| StoryboardFrameBinding | position/purpose、M09 selection_decision_id |
| AnimaticRevision | order、shot plan refs、frame/audio refs、timebase |
| AudioCueRevision | kind、text/intent、entity voice state、ticks |

## 3. 编辑和批准流程

手工或 Agent Proposal 创建 Shot/草稿 → 绑定 Beat/实体/参考 → 运行覆盖与连续性预检 → 逐项修订 → 批准 ShotPlan → 创建/批准顺序 → 生成手工或 Fixture 预演。真实分镜/预演媒体经 M07—M09 后，M05 只绑定对应 Selection。

拆分/合并创建新 Shot 并记录 `split_from/merged_from/replaced_by`；旧候选不自动迁移。重排只新建 OrderRevision。锁定后仍可建替代草稿，但 current 不原地修改。

## 4. 应用接口

- Commands：`CreateShot`、`CreateShotProposal`、`Split/MergeShot`、`UpdateShotPlanDraft`、`ApproveShotPlan`、`Create/ReorderShotOrder`、`BindStoryboardSelection`、`CreateAnimatic`、`ArchiveShot`；
- Queries：镜头表、覆盖缺口、连续性预检、谱系、顺序差异、Animatic；
- Events：`ShotPlanApproved`、`ShotOrderPublished`、`StoryboardBindingChanged`、`ShotArchived`。

## 5. 不变量与并发

1. approved ShotPlan 引用 approved NarrativeRevision 和可解析实体状态；
2. 一个 Shot 同时最多一个 current plan，但可有多个草稿；
3. 同 OrderRevision 中 shot/ordinal 分别唯一；
4. 分镜参考、首帧、尾帧和视频主选使用不同 M09 selection purpose；
5. 覆盖缺口接受、锁定和高影响删除都为追加决定；
6. expected revision 冲突返回字段/顺序差异，不进行 last-write-wins。

## 6. 失败与恢复

Agent 部分拆镜保留提案并计算缺口；分镜生成失败不阻塞手工 ShotPlan；实体状态变化只标记真实引用；删除被计划/候选/交付引用的 Shot 只能归档或替代；Animatic 构建失败保留旧版本。

## 7. 性能与验证

镜头表虚拟化，覆盖和顺序投影可重建；所有 P0 命令有非拖拽入口。验证覆盖 SHT-FR-001—012、SHT-NFR-001—005、AC-SHT-001—009。切片 A 完成至少 10 镜头手工闭环，B 接入拆镜提案，真实分镜媒体在 C。
