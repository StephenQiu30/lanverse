# M05 分镜与镜头规划详细设计

> Design ID：DES-M05
> Requirement：[REQ-SHT](../../requirement/005-M05-分镜与镜头规划需求.md)
> 状态：proposed

## 1. 设计结论

Shot 是稳定生产身份，ShotPlanRevision 是拍法，ShotOrderRevision 是播放顺序。覆盖关系、连续性依赖和分镜媒体选择分别表达；M05 不维护 Candidate 或 Selection 的副本。Animatic 是对已选顺序、镜头方案和帧/声音意图的只读派生预演；可编辑时间线与装配修订只归 M13。

## 2. 数据设计

| 对象 | 关键字段/约束 |
| --- | --- |
| Shot | content_unit、lineage、status；ID 不复用 |
| ShotPlanRevision | purpose、framing、camera、motion、action、performance、duration、unknowns、status |
| NarrativeBinding | narrative revision、scene/beat、coverage_kind |
| EntityBinding | entity、state revision、role、continuity purpose |
| ShotOrderRevision/Item | content unit、shot、ordinal；同修订唯一 |
| StoryboardFrameBinding | position/purpose、M09 selection_decision_id |
| AnimaticRevision | immutable input snapshot、order、shot plan refs、frame/audio intent refs、timebase；只读派生，不含可编辑时间线 |
| AudioCueRevision | kind、text/intent、entity voice state、ticks |

## 3. 编辑和批准流程

手工或 Agent Proposal 创建 Shot/草稿 → 绑定 Beat/实体/参考 → 运行覆盖与连续性预检 → 逐项修订 → 批准 ShotPlan → 创建/批准顺序 → 从固定输入快照生成只读 Fixture/低消耗预演。真实分镜/预演媒体经 M07—M09 后，M05 只绑定对应 Selection。用户要改变节奏时编辑上游 ShotPlan、ShotOrder 或意图并生成新 AnimaticRevision；M05 不提供时间线剪切、混音或装配编辑。

拆分/合并创建新 Shot 并记录 `split_from/merged_from/replaced_by`；旧候选不自动迁移。重排只新建 OrderRevision。锁定后仍可建替代草稿，但 current 不原地修改。

## 4. 应用接口

- Commands：`CreateShot`、`CreateShotProposal`、`Split/MergeShot`、`UpdateShotPlanDraft`、`ApproveShotPlan`、`Create/ReorderShotOrder`、`BindStoryboardSelection`、`BuildAnimaticRevision`、`ArchiveShot`；
- Queries：镜头表、覆盖缺口、连续性预检、谱系、顺序差异、Animatic；
- Events：`ShotPlanApproved`、`ShotOrderPublished`、`StoryboardBindingChanged`、`ShotArchived`。

## 5. 不变量与并发

1. approved ShotPlan 引用 approved NarrativeRevision 和可解析实体状态；
2. 一个 Shot 同时最多一个 current plan，但可有多个草稿；
3. 同 OrderRevision 中 shot/ordinal 分别唯一；
4. 分镜参考、首帧、尾帧和视频主选使用不同 M09 selection purpose；
5. 覆盖缺口接受、锁定和高影响删除都为追加决定；
6. expected revision 冲突返回字段/顺序差异，不进行 last-write-wins。

## 6. 失败与恢复

Agent 部分拆镜保留提案并计算缺口；分镜生成失败不阻塞手工 ShotPlan；实体状态变化只标记真实引用；删除被计划/候选/交付引用的 Shot 只能归档或替代；Animatic 构建失败保留旧版本和输入快照，恢复只会生成新只读版本。

## 7. 性能与验证

镜头表虚拟化，覆盖和顺序投影可重建；所有 P0 命令有非拖拽入口。验证覆盖 SHT-FR-001—012、SHT-NFR-001—005、AC-SHT-001—009。切片 A 完成至少 10 镜头手工闭环，B 接入拆镜提案，真实分镜媒体在 C。

## 9. Animatic 与 M13 装配边界

`AnimaticRevision` 是只读派生投影，不是轻量 NLE，也不是 `AssemblyRevision` 的早期别名。其输入快照必须固定：

1. 一个明确的 `ShotOrderRevision`；
2. 顺序中每个 Shot 对应的精确 `ShotPlanRevision`，不得用运行时“current”漂移；
3. 每个画面位置的 `StoryboardFrameBinding`，引用 M09 `SelectionDecision`，或带来源标记的 Fixture/placeholder；
4. 可选 `AudioCueRevision` 意图引用，而非可编辑音轨或混音媒体；
5. timebase、画幅和构建规则版本。

构建输出包含 immutable manifest、逐段 ticks、总时长、节奏诊断、缺帧/unknown 清单和可选的 M09 preview artifact 引用。M05 页面只允许播放、跳回对应 Shot/Plan/Order、比较两个 AnimaticRevision；不允许在 Animatic 上拖动剪切点、改镜头顺序、改转场长度、移动音轨、混音、编辑字幕或替换交付媒体。上述任何变化必须回到拥有对象创建新修订，再构建新的 AnimaticRevision。

M13 独占 `AssemblyRevision`、可编辑 timeline item/trim/transition、音轨与混音、字幕轨、渲染构建、DeliveryManifest 和 DeliverySnapshot。M13 可以把某个 AnimaticRevision 作为节奏参考或导入基线，但导入后产生的是新的 M13 AssemblyRevision；M05 不写 M13 表，M13 的编辑也不反写旧 Animatic。这样 AC-SHT-007 所要求的旧 Animatic 可重复播放，与 M13 的交付装配版本互不覆盖。

## 10. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| M02 → M05 | `ContentUnitRef` 与项目/Brief revision；M05 回报 shot/coverage/animatic 状态事实 | M02 拥有项目和内容单元，M05 拥有 Shot 身份/方案/顺序；内容单元重排不改镜头顺序 |
| M03 → M05 | `ApprovedNarrativeView(narrative_revision_id, members, anchors)` | 正式 ShotPlan 只引用 approved NarrativeRevision；M03 换版发 impact，M05 不自动迁移覆盖 |
| M04 → M05 | entity/state/rule revision 和 EffectiveScope membership hash | M05 保存精确 binding；M04 current 变化只标真实引用待复核，不改计划 |
| M06 → M05 | 逐项 `ShotProposalItem`、input revision/hash、evidence | M06 拥有 AgentRun，M05 校验并接收 proposal；Agent 不批准 plan/order，也不绕过局部 scope |
| M07/M08/M11/M14 ↔ M05 | 冻结 GenerationPlan、耐久执行、资源和治理门禁 | 任一真实外部预演生成均走这些模块；M05 的“低消耗”不表示绕开计划、用量或治理 |
| M09 ↔ M05 | M09 提供 MediaArtifact/Candidate/SelectionDecision；M05 提供 shot/plan purpose binding | M09 独占候选和主选；M05 只存 selection decision 引用。预演媒体文件也不成为 M05 第二套媒体表 |
| M10 ↔ M05 | M05 提供规划预期和相邻约束；M10 返回 issue/evaluation refs | M05 可做发布前结构化预检，但质量问题/接受/修复归 M10；coverage acceptance 不关闭质量问题 |
| M12 → M05 | ReviewPackage 对 plan/order/animatic revision 的冻结引用 | M12 拥有评论和批准决议；M05 只提供不可变查询，审片人默认不能改正式顺序 |
| M05 → M13 | `AnimaticReadModel(animatic_revision_id, immutable_manifest, input_refs)` | M13 只读引用/导入；所有可编辑装配和 DeliverySnapshot 归 M13，双方不共享 current pointer |

所有绑定携带 workspace/project/content unit 和精确 revision ID。跨模块事件用 event ID 幂等；M05 的覆盖/顺序投影可重建，但 Shot、ShotPlanRevision、ShotOrderRevision、lineage 和追加决定是权威事实。

## 11. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| Shot | `active → archived \| replaced`，stable ID 永不复用 | create/proposal decision 用 command/item ID 去重；split/merge/copy/replace 创建新 ID 和 immutable lineage edge |
| ShotPlanRevision | `draft → proposed → approved/current → superseded \| archived`；lock 为追加决定 | 编辑/批准 compare-and-set；同 Shot 最多一个 current；locked 内容不改，替代 draft 有新 revision |
| ShotOrderRevision | `draft → published/current → superseded` | base order + command ID 幂等；item shot/ordinal 分别唯一；publish current pointer compare-and-set |
| BindingRevision | `active → superseded \| revoked \| stale` | target revision + purpose + scope 为语义键；上游变化只标 stale，重新绑定创建新 revision |
| CoverageReport/GapDecision | report `current \| stale`；decision 追加不可变 | report 绑定 narrative/plan/order/rule hashes；decision 绑定 gap hash，重算变化后不可复用 |
| PlanningScope | 创建即冻结成员，`ready → stale` | scope hash + command ID 防重复；每个 item 独立 expected revision，未选对象不得写入 |
| AnimaticBuild | `queued → running → completed \| failed \| cancelled` | input snapshot hash + build rule + idempotency key 唯一；迟到结果不能覆盖新 build |
| AnimaticRevision | completed 后不可变、只读；无 editable/current timeline | manifest hash 校验；旧版本永远按旧 order/plan/binding 播放；重建只新增 revision |
| AudioCueRevision | `draft → approved → superseded` | approved intent 不可变；真实媒体/混音状态不写入本对象 |

批准 plan、发布 order、绑定 Selection、接受 gap 和锁定都在同事务写 revision/decision、AuditEvent 与 Outbox。Animatic 构建先冻结输入引用并生成 snapshot hash；Worker result 只有在 build/sequence/hash 匹配时提交 immutable manifest，失败或取消不删除输入和旧 revision。

## 12. 页面与可观察状态

| 页面/入口 | 主要动作 | 必须可观察的状态 |
| --- | --- | --- |
| 镜头表/Storyboard Workspace | 创建、分页/批选、编辑 plan、拆分/合并/复制/替代、归档 | stable Shot ID、plan draft/proposed/approved/locked/stale、lineage、unknown/readiness、expected revision diff |
| 覆盖面板 | 按 Beat/Dialogue/Action/required setup 查看与处理缺口 | 四类独立 covered/partial/uncovered、来源 Anchor、gap decision、检查基线/stale、跳转动作 |
| 顺序编辑器 | 非拖拽或拖拽重排、比较并发布 | base/current order revision、insert/delete/move diff、未保存/冲突、旧引用数量 |
| 分镜选择绑定 | 按 purpose 选择 M09 主选、查看缺失或撤销 | selection decision、artifact availability/rights、purpose、binding revision、missing/revoked/stale；Candidate 不在此编辑 |
| 连续性/Readiness 预检 | 查看人物状态、轴线、位置、动作、道具、时空和未知项 | source revision、severity/blocking、owner module、accepted/stale、next action；M10 issue 单独标识 |
| Animatic 只读预演 | 构建、播放、跳回上游、比较时长/节奏 | 明显的“只读派生预演”标签、input snapshot、queued/running/failed/ready、placeholder/unknown、总 ticks、版本差异；无 timeline edit 控件 |
| 局部规划 | 冻结选择范围、逐项执行、重放失败项 | scope member/hash、pending/applied/conflict/failed、未选对象不受影响 |

页面必须提供键盘可达的创建、编辑、重排、绑定、批准和缺口处理入口。通用状态为 `loading`、`empty`、`draft`、`checking`、`blocked`、`stale`、`conflict(diff)`、`partial(items)`、`building(progress)`、`failed(retry_action)`、`ready(as_of)`；真实分镜失败时手工 ShotPlan 操作保持可用。
