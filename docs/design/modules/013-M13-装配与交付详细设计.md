# M13 装配与交付详细设计

> Design ID：DES-M13
> Requirement：[REQ-DLV](../../requirement/013-M13-装配与交付需求.md)
> 状态：proposed

## 1. 设计结论与范围

M13 提供平台闭环所需的基础音视频/字幕装配和可复现交付，不替代专业 NLE。`AssemblyRevision` 是版本化编辑/批准事实，`DeliveryBuild/RenderRun` 是可失败、取消、恢复和重跑的耐久过程，`DeliverySnapshot/Manifest` 是全部必需输出验证成功后原子发布的不可变结果；三类事实不能合并。

M05 `AnimaticRevision` 是按镜头顺序、帧和音频意图形成的低成本规划预演，不是 M13 Assembly、审阅批准或正式交付。M13 可以从明确的 M05 ShotOrder/Animatic 引用**初始化新的 AssemblyRevision**，但不接管、不修改、不升级 M05 Animatic。切片 A 的 Animatic/Storyboard Export 也不宣称是 M13 正式 DeliverySnapshot；正式装配与交付在切片 E 建立。

### 1.1 范围内

- 从显式 ShotOrder 与 Selection 创建基础时间线版本；
- 镜头顺序、入出点、空隙、必要黑场、简单转场和画幅适配；
- 对白、旁白、环境声、音效、音乐的轨道放置与基础音量/淡入淡出/静音；
- 基础字幕的手工创建、导入、校对、样式和导出；
- 精确时间基、交付预检、冻结 Build、耐久渲染、原子 Snapshot、授权下载和有序镜头素材包。

### 1.2 非目标

- 高级调色、复杂合成/跟踪/VFX、多机位、专业混音、任意插件或多人 NLE 工程合并；
- 由 M13 直接调用模型或 Provider 生成语音、音乐、音效、字幕或媒体；
- 把 M05 Animatic、M12 ReviewPackage、M10 QualityRiskAcceptance 或 M14 PolicyException 互相替代；
- 在 Build 成功前创建“preparing Snapshot”，或在 Snapshot 发布后补写文件。

## 2. 事实所有权与数据模型

| 对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| `Assembly` / `AssemblyRevision` | project/unit、source ShotOrder/Animatic refs、timebase、raster/color/audio spec、revision/status/hash | 每次编辑形成新 revision；批准版本不可原地改 |
| `VideoTrackItem` | shot/selection/artifact version、source in/out ticks、timeline start/duration、fit、transition | 引用明确 M09 artifact version；时间范围合法且不使用浮点秒 |
| `AudioTrackItem` | purpose、selection/artifact version、source in/out、timeline ticks、gain/fade/mute | 只绑定可播放且已探测的 M09 音频版本；AudioCue 仅作意图来源 |
| `CaptionRevision` / `CaptionCue` | source kind/ref、language、integer start/end ticks、text、style preset、status | cue 不重叠规则由格式/策略定义；导入后版本冻结 |
| `AudioMixRevision` | tracks、item refs、loudness target、status/hash | 仅基础轨道参数；不保存外部 DAW 工程 |
| `ExportPresetRevision` | container/codec/raster/frame rate/color/audio/subtitle/required outputs | 发布后冻结；有序镜头包是一个显式预设 |
| `DeliveryBuild` / `DeliveryInput` | assembly/preset、review/quality/rights refs、input manifest/hash、status | start 前冻结所有输入；运行中项目变化不改 Build |
| `RenderRun` | build、run number、render engine version、plan hash、stage、diagnostics、status | 每次重跑新记录；不能覆盖历史成功/失败 Run |
| `DeliveryOutput` | run、purpose、artifact version、hash、probe/spec、required、validation | 输出先隔离；验证前不可进入 Snapshot |
| `DeliverySnapshot` / `DeliveryManifest` | build unique、input/output refs/hash、spec、approval/rights evidence、created_by | 单 Build 至多一个；与完整 Manifest/输出引用同事务发布 |
| `DeliveryAccessGrant` | snapshot、principal、actions、expiry、status | 撤销访问不修改/删除 Snapshot |

项目时间采用 rational `timebase_num/timebase_den` 与 integer ticks；音频另保存 sample rate/timebase。UI 可展示浮点或 SMPTE，但命令、校验和 Manifest 只使用整数 tick 与显式时间基。

## 3. 音频、字幕来源与 Provider Gate

### 3.1 允许的来源

| 内容 | 来源 | 进入 M13 的方式 | M13 所有权 |
| --- | --- | --- | --- |
| 对白/旁白/环境声/音效/音乐 | 用户上传、已有素材、Gate 后由生成流程产出的 M09 MediaArtifact/Selection | M09 完成上传/摄取、探测、权利检查和版本化；M13 引用 Selection/Artifact version | 仅 AudioTrackItem/AudioMixRevision，不拥有源媒体 |
| 字幕 | M13 手工创建 | `CreateCaptionRevision`，保存 cues/style | 拥有 CaptionRevision |
| 字幕文件 | 用户导入的 SRT/VTT 等受支持格式 | M09 保存源文件；M13 `ImportCaptionRevision` 解析为冻结 cues 并保留 source hash | 拥有解析后的 CaptionRevision，不改源文件 |
| 转写/翻译/生成字幕 | Provider Gate 后的 M07 Plan → M08 执行 → M09 Artifact | 用户显式选择结果后，由 M13 导入/校对为新 CaptionRevision | 不拥有模型调用或 Candidate；只拥有采用后的字幕版本 |
| M05 AudioCueRevision | 镜头/叙事中的声音意图、文案和时序建议 | 初始化 Assembly 时作为 track intent/placeholder 来源 | 不视为可播放音频，不可直接交付 |

切片 E 的必达能力是**导入/已有音频 + 手工/导入字幕**。没有通过 Provider Gate 时，界面不得声称支持真实语音、音乐、音效或字幕生成/转写；可以显示占位和“需要导入/生成能力尚未准入”。

### 3.2 Provider Gate

每一种真实音频或字幕外部能力都必须逐 `media kind + purpose + provider` 通过下列 Gate，不能用已有图像/视频 Provider 的通过结果自动继承：

1. **M07 Capability Gate**：存在已批准且可路由的 `CapabilityRevision`，输入/输出 schema、reference limits、估计单位和 purpose 明确；
2. **M08 Execution Gate**：ProviderConnection/credential/adapter 已就绪，提交幂等、回调验签、unknown 对账、取消语义、下载与健康检查通过契约测试；
3. **M14 Policy Gate**：地域、保留、训练使用、内容/权利和实际外发字段与当前策略兼容；
4. **M11 Usage Gate**：估计和 Provider 实际计量能映射到明确 unit，硬上限可在提交前原子门禁；
5. **M09/M10 Media Gate**：输出可安全摄取/探测/版本化，且适用技术质量检查可执行。

任一 Gate 未通过时，M13 只消费已授权导入/已有素材和手工字幕；M13 不提供绕过 M07/M08 的 Provider SDK 调用。

## 5. 模块边界与跨模块契约

### 5.1 M05 Animatic 边界

- M05 拥有 Shot、ShotOrderRevision、AnimaticRevision、AudioCueRevision；M13 只读稳定引用。
- M05 Animatic 是规划预览，可以使用 fixture/低成本媒体；M13 Assembly 是正式编辑与交付输入，必须引用 M09 可验证媒体版本。
- `CreateAssemblyFromSelections` 可记录 `source_animatic_revision_id` 以解释初始化来源，但所有 Video/Audio TrackItem 都重新解析为显式 Selection/Artifact；之后互不联动。
- M13 的修改不反写 Animatic；ShotOrder/Animatic 更新只提示“有新基线”，用户显式创建新的 AssemblyRevision。

### 5.2 跨模块端口

| 模块 | M13 消费/调用 | M13 提供 | 边界约束 |
| --- | --- | --- | --- |
| M03/M05 | 项目时间规格、ShotOrder/Animatic/AudioCue 稳定版本 | Assembly source refs | 不写镜头与 Animatic；AudioCue 只作 intent |
| M07/M08 | Gate 后音频/字幕生成计划与执行状态（经 M09 成果进入） | 无直接 Provider 调用 | M13 不拥有 Capability、ProviderConnection、Job/Attempt |
| M09 | Selection、MediaArtifact/Version、upload/probe/download/register rendered media | Rendered output lineage、Snapshot refs | 所有可播放输入/输出先进入 M09；M13 不直接写对象存储事实 |
| M10 | QualityReport/QualityRiskAcceptance 有效性、交付技术检查 | build/output refs 供检查 | 质量接受不能替代权利/审阅；M13 不修改质量事实 |
| M11 | Build/Run 估计与实际用量；每交付分钟查询 | Snapshot duration/build lineage | M11 只做资源治理，不决定交付成功 |
| M12 | ReviewPackage/Decision | Assembly/display proxy refs、Snapshot refs | 预检读取明确批准包；新 Assembly 不继承旧批准 |
| M14 | PolicyEvaluation/Exception、retention/download/share decisions | intended action、全部采用输入与输出摘要 | M14 拥有策略；M13 执行 block/allow，不自判权利 |
| 任务/媒体 Worker | 耐久任务、隔离工作目录、对象前缀 | Render plan、stage checkpoint | M13 拥有 Build/RenderRun 业务状态；外部 Provider execution 仍属 M08 |

### 5.3 关键契约载荷

- `AssemblySourceManifest`：ShotOrder/Selection/Artifact/Animatic refs + versions/hashes，项目 timebase/spec。
- `DeliveryPreflightRequest`：assembly/preset refs、intended use/region、M10/M12/M14 candidate evidence refs、input preview hash。
- `RenderStageCheckpoint`：build/run、engine version、plan hash、stage、input/output content hashes；不包含 Provider 凭据。
- `DeliverySnapshotCreated`：snapshot/build/manifest refs、duration ticks/timebase、required output IDs/hash、approval/rights summary refs。

渲染 Worker 使用限权临时目录和 Build 专属对象前缀。数据库事务只发布已由 M09 登记且验证成功的 output refs；跨模块事件通过 Outbox/Inbox 至少一次投递并幂等消费。

## 6. 关键状态、并发与幂等

### 6.1 状态机

| 对象 | 合法状态与转换 | 不变量 |
| --- | --- | --- |
| AssemblyRevision | `draft → approved \| superseded`；approved 可因新 revision 关系显示 `superseded` | approved 内容冻结；不能回 draft |
| DeliveryBuild | `draft → queued → rendering → validating → succeeded`；运行中可 `partial \| failed \| cancelled`；partial/failed 可通过新 Run 回到 rendering | succeeded 仅表示 Build 具备完整验证结果；Snapshot 另建 |
| RenderRun | `queued → preparing → rendering → validating → succeeded \| partial \| failed \| cancelled \| unknown` | 每次 retry 新 Run；旧状态不覆盖 |
| DeliveryOutput | `staged → validating → valid \| invalid \| quarantined` | 只有 valid 且 required set 完整可发布 |
| DeliverySnapshot | 创建即 `published`；访问另由 Grant 控制 | 无 preparing/partial；不可修改、补写或覆盖 |

### 6.2 并发与一致性

1. Assembly 更新用 `(assembly_id, expected_head_revision)` compare-and-swap；冲突产生差异，不覆盖另一作者版本。
2. `StartDeliveryBuild` 锁 Build，比较 preflight input hash 与当前解析 hash；不一致则拒绝，绝不偷偷换输入。
3. 同一 Build 同时至多一个 active RenderRun；唯一键 `(build_id, active_marker)`；retry 为新 run number。
4. 输出路径包含 Build/Run/purpose/content hash；旧 Run 无法覆盖新 Run 或已发布 Snapshot 文件。
5. `FinalizeDeliverySnapshot` 在事务内锁 Build，验证 required outputs，并以 `UNIQUE(build_id)`、`UNIQUE(manifest_hash, build_id)` 保证重复 finalize 回读同一结果。
6. Snapshot Manifest 与 required output refs 同事务写入；签名 URL 后置生成，不进入原子发布事务。

### 6.3 幂等键

| 写入 | 幂等键 | 重复结果 |
| --- | --- | --- |
| CreateAssemblyFromSelections | project + ShotOrder revision + source manifest hash + request key | 回读原 draft；hash 不同冲突 |
| StartDeliveryBuild | Build + frozen input hash | 回读现有 active/first RenderRun |
| RetryDeliveryBuild | Build + failed Run + retry request key | 回读已创建的新 RenderRun |
| RegisterDeliveryOutput | Run + purpose + content hash | 回读 M09 artifact/output ref |
| FinalizeDeliverySnapshot | Build + manifest hash | 回读唯一 Snapshot |
| Grant/RevokeDeliveryAccess | Snapshot + principal + action + request key | 回读原 grant/revocation |

| 页面/视图 | 主要动作 | 必须展示的状态 |
| --- | --- | --- |
| 基础装配工作台 | 从选择初始化、排列/裁剪、简单转场、播放 | source ready/missing/newer baseline、draft/approved/conflict、proxy unavailable、precision warning；明确“Animatic 来源”而非同一对象 |

| 交付预检 | 选择 preset、用途/地域，查看 blockers | checking/pass/warn/block/stale；按 material/selection/quality/rights/review/spec/output 分类并链接来源 |
| Build/RenderRun 详情 | 启动、取消、重跑、查看各 stage/output | queued/rendering/validating/partial/failed/cancelled/unknown/succeeded；每次 Run 独立，展示 checkpoint/diagnostics |
| Snapshot/Manifest | 查看不可变输入输出谱系、校验和下载 | publishing transaction、published、access denied/revoked/expired；不会出现 partial Snapshot |

指标：预检一次通过率及 blocker 类型、Build/Run 成功/partial/failed/unknown、阶段耗时与恢复时间、输出隔离/校验失败、Snapshot 原子性错误、可复现率、音频/字幕来源分布、Provider Gate 阻塞原因、每交付分钟分单位资源。日志不记录完整字幕/Prompt/媒体，只记录 refs/hash/spec/stage/trace。

## 8. 失败路径与恢复约定

| 场景 | 用户结果 | 恢复 |
| --- | --- | --- |
| 缺主选/媒体 | 预检阻塞到具体 Shot/purpose | 返回 M09 选择/媒体修复；新输入 hash 后重跑预检 |
| 权利/质量/审阅缺失 | 正式 Build 不启动，分别显示依据 | 在对应 M10/M12/M14 完成事实；不同例外不能互替 |
| 音频/字幕 Provider 未过 Gate | 显示“需导入/手工或等待能力准入” | 使用导入/已有素材；Gate 通过后走 M07→M08→M09，不改 M13 边界 |
| 渲染中断 | 当前 Run 失败/unknown，已确定中间物保留 | 先 reconcile unknown；从 checkpoint 恢复或新 RenderRun |
| 主文件成功、字幕失败 | Build partial，无 Snapshot | 新 Run 只重做缺失/失败附属输出，再整体验证 |
| 输出校验失败 | 文件隔离并显示 hash/spec 差异 | 修复 engine/preset 后新 Build/Run，不发布坏文件 |
| finalize 事务失败 | 用户仍只看到 succeeded Build，无半个 Snapshot | 同 manifest 重试并回读/原子创建唯一 Snapshot |
| 下载链接撤销 | 链接立即失效，Snapshot/历史不变 | 经 M14/权限重新授权新短期链接 |
| 外部 NLE 回传 | 不覆盖 Assembly/Snapshot | 经 M09 作为新来源摄取，再创建新 Assembly/Build 链 |
