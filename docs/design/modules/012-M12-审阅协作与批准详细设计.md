# M12 审阅、协作与批准详细设计

> Design ID：DES-M12
> Requirement：[REQ-REV](../../requirement/012-M12-审阅协作与批准需求.md)
> 状态：proposed

## 1. 设计结论

ReviewPackage 是一次冻结审阅 Manifest。评论、标注、分派和决定全部绑定该包和确定媒体/时间基；新版本只能创建新包。外部审片身份使用最小、到期、可撤销授权，不转化为项目成员编辑权。

## 2. 数据模型

| 对象 | 关键字段/约束 |
| --- | --- |
| ReviewPackage/Item | project/unit、purpose、subject refs/hash、display artifact、timebase、status |
| ReviewThread/Comment | package/subject、author、body revisions、status |
| Annotation | artifact revision、integer time range、normalized region/field anchor |
| ReviewDecision | approve/request_changes/reject/withdraw、actor、policy snapshot；只追加 |
| ApprovalPolicyRevision | required roles、minimum approvals、separation、status |
| ReviewAssignment/AccessGrant | reviewer、scope、expiry、revocation、access log |

## 3. 创建与决定流程

选择审阅目的/范围 → 解析当前 ShotOrder/Selections/Assembly/quality/rights → 冻结 Manifest → 验证代理可用和访问策略 → 发起 in_review → 评论/决定 → 策略计算终态。修改内容必须创建新 Package；旧评论可被引用为来源，但不迁移坐标或批准。

## 4. 状态机

`draft → in_review`；`in_review → changes_requested | approved | rejected | withdrawn`；任一冻结包在新包替代后可 `superseded`。终态不回到 in_review。Annotation 为 open/resolved/dismissed/reopened；评论解决不影响 Package 审批。

## 5. 应用接口

- Commands：`Create/StartReviewPackage`、`Grant/RevokeReviewAccess`、`Add/EditComment`、`Resolve/ReopenAnnotation`、`RecordReviewDecision`、`CreateSupersedingPackage`；
- Queries：审阅播放器、差异、未解决项、决定矩阵、访问日志；
- Events：`ReviewPackageStarted`、`ReviewDecisionRecorded`、`ReviewPackageSuperseded`、`ReviewAccessRevoked`。

修改请求可调用 M10 创建结构化 Issue/RepairPlan 入口，但 M12 不修改媒体。质量风险和治理例外不是 ReviewDecision。

## 6. 失败、安全与恢复

代理失败保留包并重建派生物；通知失败不回滚决定；时间映射失败阻止错误定位；成员/链接撤销后提交实时重授权；外部链接不暴露来源、Prompt、秘密或其他项目。

时间码使用项目 rational timebase/integer tick，区域保存媒体尺寸与规范化坐标。Webhook/邮件只含最小摘要和安全链接。

## 7. 验证

覆盖分数帧率、代理重建、并发最终决定、多人角色门槛、链接过期/撤销、旧包新版本隔离和通知重试。映射 REV-FR-001—011、REV-NFR-001—005、AC-REV-001—008；切片 E 交付。
