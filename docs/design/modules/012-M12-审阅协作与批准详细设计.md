# M12 审阅、协作与批准详细设计

> Design ID：DES-M12
> Requirement：[REQ-REV](../../requirement/012-M12-审阅协作与批准需求.md)
> 状态：proposed

## 1. 设计结论与范围

`ReviewPackage` 是一次冻结审阅 Manifest；评论、时间码/区域标注、分派和正式决定全部绑定该包及确定对象版本。项目当前内容变化不会移动旧评论，也不会让旧批准自动批准新版本。M12 记录审阅事实，不修改镜头、候选、主选、装配或媒体。

切片 E 只交付**内部审阅**；**外部审片必须等到切片 F Gate**，在外部最小授权、撤销、防重放、字段裁剪、访问日志和 M14 分享策略全部验收后开放。F Gate 前不以临时公开链接、项目成员账号或内部 reviewer 冒充外部审片能力。

### 1.1 范围内

- 从明确镜头/候选/选择/装配/规则版本冻结 ReviewPackage；
- 对确定媒体版本的评论、回复、提及、分派、时间码/区域标注与解决状态；
- 单人、角色门槛或多人批准策略与追加式决定；
- 新基线创建新包、旧包追溯、修改请求到 M10 Issue/RepairPlan 的受控入口；
- 最小通知、审阅过期/撤销、访问记录和审阅汇总；
- 切片 F Gate 后的外部审片人最小访问。

### 1.2 非目标

- 修改 M05 镜头/顺序、M09 Candidate/Selection 或 M13 Assembly；
- 自动生成修复媒体、完成渲染或以评论状态替代质量/治理决定；
- 把聊天消息、评论“resolved”或 M10 `QualityRiskAcceptance` 当作正式 ReviewDecision；
- 在切片 E 开放匿名/外部审阅链接。

## 2. 事实所有权与数据模型

| 对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| `ReviewPackage` | workspace/project/unit、purpose、baseline refs/hash、timebase、policy revision、status、revision | `start` 后 Manifest 冻结；基线变化只能新建包 |
| `ReviewItem` | package、subject type/id/version、display artifact/version、ordinal、time range | 必须解析到稳定版本；不能保存“current selection”动态引用 |
| `ReviewThread` / `ReviewCommentRevision` | item/anchor、author、body、mentions、assignment、status | 编辑以新 revision 追加；删除为受审计 tombstone，不抹去决定依据 |
| `Annotation` | artifact version、integer tick range、normalized region、media dimensions、field anchor、status | 时间基和尺寸版本必填；代理重建不改变权威坐标 |
| `ReviewDecision` | package、actor、role snapshot、decision、reason、policy snapshot、supersedes | 只追加；批准、请求修改、拒绝、撤回语义分离 |
| `ApprovalPolicyRevision` | scope、required roles、minimum approvals、separation rules、effective range | Package 启动时冻结策略版本；决定提交时复核 actor 资格 |
| `ReviewAssignment` | package/thread、assignee、due_at、status | 只代表责任，不授予项目编辑权 |
| `ReviewAccessGrant` | package、principal/audience、allowed actions、expiry、token digest、status | 仅 package scope；外部 grant 不创建项目成员身份 |
| `ReviewAccessLog` | grant/principal、action、result、occurred_at、trace | 只追加；不记录 token、完整评论或媒体内容 |
| `ReviewNotificationDelivery` | event/comment/decision ref、recipient、channel、status、attempt | 通知状态不参与评论或决定事务 |

`ReviewPackage.baseline_manifest` 至少冻结：项目/内容单元、ShotOrder、Candidate/Selection、Assembly（如有）、display artifact、时间基、质量/权利摘要、审阅目的和批准策略版本。内容哈希覆盖规范化 Manifest，防止冻结后被原地改写。

## 4. 模块边界与跨模块契约

### 4.1 所有权边界

M12 只拥有 ReviewPackage、评论/标注、审片决定、审阅策略、访问授权和投递记录。它保存其他模块的稳定 ID/版本/摘要，不复制或改写那些领域对象。

| 模块 | M12 消费/调用 | M12 提供 | 边界约束 |
| --- | --- | --- | --- |
| M01 | member/service principal 状态、`REVIEW_DECIDE` 等授权检查 | reviewer assignment/access refs | 内部决定提交时实时复核成员；外部 reviewer 不是项目成员 |
| M05 | ShotOrder/Shot 稳定版本 | 审阅结果引用 | M12 不重排镜头、不修改 Shot |
| M09 | Candidate/Selection、MediaArtifact/Version、授权代理 | 包/评论/决定引用 | 代理可重建，权威版本与时间坐标不可变 |
| M10 | QualitySummary；`CreateRepairIntake` 端口 | thread/annotation/decision source refs | M12 不创建修复媒体；M10 Issue 不等于 M12 决定 |
| M13 | AssemblyRevision/display proxy | 批准包和决定 refs，供 delivery preflight 使用 | 新 Assembly 需新包；旧批准不能继承 |
| M14 | 分享/下载 PolicyEvaluation、PolicyException 状态 | 外部分享 action/可见字段/actor 摘要 | F Gate 前外部分享永远关闭；PolicyException 不替代批准 |
| 通知基础设施 | Outbox、邮件/消息投递 | 最小 ReviewNotification intent | 投递与领域事务解耦，至少一次、消费者幂等 |

### 4.2 契约载荷

- `ReviewBaselineRef`：`subject_type`、`subject_id`、`revision_id`、`content_hash`；禁止只传 current ID。
- `ReviewAnchor`：`artifact_version_id`、`timebase_num/den`、integer `start_tick/end_tick`、可选 normalized region + source dimensions、可选 field anchor。
- `ReviewDecisionRecorded`：workspace/project/package/policy revision、decision、actor/role snapshot、trace；不携带评论正文。
- `RepairIntakeRequested`：package/decision/thread/annotation refs、结构化 issue kind/severity/owner；M10 返回稳定 intake ref。

跨模块事件使用 Outbox/Inbox；重复投递按 event ID 去重。M13 预检必须同步读取明确 Package/Decision，而不能只相信异步“approved”投影。

## 5. 关键状态、并发与幂等

### 5.1 状态机

| 对象 | 合法状态与转换 | 不变量 |
| --- | --- | --- |
| ReviewPackage | `draft → in_review`；`in_review → changes_requested \| approved \| rejected \| withdrawn`；冻结包可 `→ superseded` | 终态不回到 in_review；再次审阅创建新包 |
| Annotation | `open → resolved \| dismissed`；`resolved/dismissed → reopened`；`reopened → resolved \| dismissed` | 每次转换追加 actor/reason/revision |
| ReviewAccessGrant | `pending → active → expired \| revoked`；邀请可 `pending → expired/revoked` | expired/revoked 不恢复；发新 grant |
| ReviewNotificationDelivery | `pending → delivering → delivered \| retry_wait \| dead_letter` | 状态不影响评论/决定事实 |

### 5.2 并发规则

1. 单人互斥最终决定使用 `expected_package_revision` 条件更新；第一个有效终态胜出，后续返回冲突和现有决定。
2. 多人批准按 `(package_id, actor_id, policy_role, decision_round)` 唯一保存各自决定，再在同事务锁 Package 计算矩阵；缺必要角色不得批准。
3. 决定提交事务内重新检查 Package 状态、Membership/Grant、ApprovalPolicyRevision 和 actor role snapshot；等待期间停用/撤销即失败。
4. 评论/标注按自身 expected revision 并发，不锁整包；评论冲突不回滚已存在的其他评论。
5. 新基线创建新 Package，`old.superseded_by` 使用唯一约束；重复创建相同 baseline hash 回读同一替代包。

### 5.3 幂等键

| 写入 | 幂等键 | 重复结果 |
| --- | --- | --- |
| StartReviewPackage | package + baseline hash | 回读已启动包；hash 不同返回冲突 |
| Add/ReplyComment | package + actor + request key | 回读原 comment；body/anchor hash 不同返回冲突 |
| RecordReviewDecision | package + actor + decision round + request key | 回读原决定及矩阵状态 |
| CreateSupersedingPackage | old package + new baseline hash | 回读原新包 |
| CreateRepairIntakeFromReview | decision + selected issue refs | 回读 M10 intake ref |
| RetryReviewNotification | delivery + attempt key | 只增加一个投递 Attempt，不重复业务事件 |

## 6. 页面与可观察状态

| 页面/视图 | 主要动作 | 可观察状态 |
| --- | --- | --- |
| 审阅包列表 | 创建包、比较新旧包、查看轮次 | empty、draft、in_review、approved/changes_requested/rejected/withdrawn、superseded、expired、baseline has newer version |
| 审阅播放器 | 播放代理、按时间/区域评论、回复/解决 | proxy loading/unavailable/rebuilding、anchor ready/mapping blocked、offline/submit retry、read-only、access revoked |
| 评论与责任面板 | 筛选 unresolved/owner/mention、分派 | no comments、open/resolved/dismissed/reopened、unassigned/overdue、notification failed |
| 批准矩阵 | 查看角色门槛、提交/撤回决定 | eligible/ineligible、roles missing、pending、approved、conflict、membership changed、package terminal |
| 审阅访问管理 | 分配内部 reviewer；F 后邀请外部 reviewer | active/expiring/expired/revoked；外部功能在 F Gate 前显示 disabled + gate 原因 |
| 审阅汇总 | 未解决项、阻塞决定、责任人、周转时间 | ready、projection stale/rebuilding、no permission；数据截止时间明确 |
| 通知投递日志 | 查看失败/重试/死信 | pending/delivered/retry_wait/dead_letter，不改变业务结果 |

播放器必须支持键盘操作、字幕轨、可读焦点和屏幕阅读器标签。分数帧率以整数 tick/明确 timebase 显示；前端可格式化为 SMPTE，但提交仍发送 tick 与版本。

## 7. 安全、失败恢复与可观察性

| 场景 | 用户可见结果 | 恢复 |
| --- | --- | --- |
| 媒体代理不可用 | 包与评论保留，播放器显示预览故障 | M09 重建同版本代理；必要时下载授权版本，不改 anchor |
| 链接过期/撤销 | 明确无访问权，不泄露包是否存在 | 具权主体创建新邀请；旧 token 永久无效 |
| 包基线变化 | 当前包仍显示旧版，并提示存在新版本 | 完成旧审或创建 superseding package，绝不迁移批准 |
| 并发最终决定 | 失败方看到已提交决定、actor 和策略结果 | 刷新矩阵；需要再审则新建包 |
| 通知失败 | 评论/决定成功，显示通知待重试 | 自动重试、死信、人工重发 |
| 时间码映射失败 | 阻止错误定位，显示 artifact/timebase mismatch | 取原代理或重建映射后重试 |
| reviewer 停用 | 当前页面转只读/拒绝新写入 | 管理员重新授权新身份；不恢复旧请求 |

指标：审阅周转时间、首次批准率、修改轮次、未解决评论时长、角色门槛阻塞数、代理映射失败、链接撤销生效延迟、越权拒绝、通知失败/重试/死信。安全日志只含 package/grant/action/result/trace，不含 token、完整评论、Prompt 或媒体。

## 10. 实施顺序与 F Gate

1. **切片 E-1**：冻结 ReviewPackage、内部访问、精确评论/标注与审阅播放器。
2. **切片 E-2**：批准策略、决定并发、替代包、M10 intake、通知与汇总。
3. **切片 F Gate**：先通过跨包越权、token 重放、撤销时延、敏感字段裁剪、M14 外部分享策略与完整访问日志测试，再开放外部邀请；Gate 未通过时保持功能关闭。

外部审片不是内部审阅的配置开关，而是独立受 Gate 控制的切片 F 能力。
