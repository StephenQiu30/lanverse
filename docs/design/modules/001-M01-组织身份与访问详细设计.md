# M01 组织、身份与访问详细设计

> Design ID：DES-M01
> Requirement：[REQ-IAM](../../requirement/001-M01-组织身份与访问需求.md)
> 状态：proposed

## 1. 设计结论

M01 在 Python 模块化单体中提供统一 `AuthorizationPort`。账户认证、Workspace 成员、项目职责和临时能力授权分层计算；UI、API、Worker、媒体签名和 Agent Tool 只调用该端口，不各自解释角色。

## 2. 边界与依赖

- 拥有：Workspace、Membership、Invitation、ProjectAssignment、ServiceIdentity、Session、CapabilityGrant、PolicyRevision、AccessAudit；
- 读取：M02 Project 身份和 M14 高风险策略结论；
- 不拥有：各模块内容批准、资源例外、质量风险或交付决定；
- 存储：PostgreSQL 权威事实；短期鉴权缓存必须绑定 policy version。

## 3. 不变量与数据约束

1. 所有业务对象都带 `workspace_id`，授权请求必须同时提供 actor、workspace、action 和 subject；
2. `(workspace_id, account_id)` 最多一个活动 Membership；邀请 token 只存哈希且单次消费；
3. 最后一个 active Owner 不可被移除；历史主体不因成员停用删除；
4. CapabilityGrant 必须有 scope、purpose、expires_at 和 grantor；高风险提交时重新校验；
5. ServiceIdentity 无交互登录和通配项目权限，凭据只保存密钥引用。

## 4. 应用接口

| 类型 | 接口 | 关键输入/输出 |
| --- | --- | --- |
| Command | `CreateWorkspace` | owner account、name、idempotency key |
| Command | `InviteMember` / `AcceptInvitation` | role、expiry、expected invitation state |
| Command | `AssignProjectRole` | project、capabilities、expected revision |
| Command | `SuspendMembership` | reason、revocation mode、effective time |
| Command | `Issue/RevokeCapabilityGrant` | action scope、limit、expiry |
| Query | `Authorize` | allow/deny、reason_code、policy_version、next_action |
| Query | `ListEffectiveCapabilities` | organization + project + temporary grants |

成功写命令与 `AuditEvent`、必要 Outbox 事件在同一事务提交。拒绝不泄露对象是否存在。

## 5. 状态与流程

Invitation：`pending → accepted | expired | revoked`；Membership：`invited → active → suspended | removed`。停用流程先提交成员状态和撤销事件，再由 Reconciler 撤销会话、媒体授权和未启动任务资格；已收单外部任务进入 M08 对账而非丢弃。

## 6. 失败与恢复

- IdP 不可用：只按组织策略允许未过期短会话，禁止管理员降级；
- 撤销传播延迟：高风险命令实时回源，后台持续对账旧会话；
- 并发邀请接受：唯一约束回读同一 Membership；
- 职责冲突：返回 expected/current revision 和字段差异；
- 审计/Outbox 写失败：业务事务整体回滚。

## 7. 安全、观测与验证

RLS 使用非 owner 业务角色并覆盖负向集成测试；对象签名包含 workspace、subject、action 和 expiry。指标至少包括拒绝原因、撤销传播时间、跨租户尝试和异常服务身份调用。

验证覆盖 IAM-FR-001—012、IAM-NFR-001—005、AC-IAM-001—008；切片 A 先实现单 Workspace/项目职责和隔离，SSO/SCIM、委派、双人批准留到 F。

## 8. 功能分解与实施切片

本表把应用接口收敛为可实施用例；它们仍位于同一 Python 模块化单体，`AuthorizationPort` 是模块端口，不是新增微服务。

| 能力 | 命令或查询 | 输入 | 输出 | 业务规则 | 失败与恢复 | 切片 |
| --- | --- | --- | --- | --- | --- | --- |
| Workspace 生命周期 | `CreateWorkspace`、`DisableWorkspace`、`RestoreWorkspace`、`GetWorkspace` | actor、名称、expected revision、幂等键 | Workspace、revision、审计引用 | 创建者成为首个 Owner；停用不删除历史；最后一个 Owner 不可被移除 | 基线过期返回当前 revision；重复创建回读同一结果；停用传播失败进入对账 | A |
| 邀请与入组 | `InviteMember`、`RevokeInvitation`、`AcceptInvitation` | workspace、邮箱/账户、初始角色、期限、token hash | Invitation、Membership、消费结果 | token 单次、限时且只存哈希；接受时重新校验 Workspace 和邀请状态 | 并发接受由唯一约束收敛为一个 Membership；过期/撤销返回可重新邀请动作 | A |
| 成员与项目职责 | `ChangeMembershipRole`、`AssignProjectRole`、`RemoveProjectAssignment`、`SuspendMembership` | actor、member、project、职责/能力、理由、expected revision | Membership/ProjectAssignment 新修订、影响摘要 | 账户、Workspace 成员、项目职责分别建模；停用成员同时失去新任务资格 | 职责冲突返回字段差异；撤销异步传播由 Reconciler 续做 | A（单项目职责）/ F（扩展策略） |
| 会话与撤销 | `Login`、`RefreshSession`、`Logout`、`RevokeSessions`、`QueryRevocationStatus` | account、凭据或 refresh token、session family、撤销理由 | 短访问令牌、轮换 refresh token、revocation version | refresh token 单次轮换；密码/成员/策略变化提升版本；高风险动作实时回源 | 重放令牌撤销整个 family；缓存不可用时高风险请求失败关闭 | A |
| 动作授权 | `Authorize`、`ListEffectiveCapabilities` | actor/service identity、workspace、action、subject、context | allow/deny、reason code、policy version、next action | 组织角色、项目职责、临时授权和 M14 风险门禁分层计算；拒绝不暴露对象存在性 | policy version 失配回源；依赖不可用时不放宽权限 | A |
| 服务身份 | `CreateServiceIdentity`、`RotateCredentialReference`、`SuspendServiceIdentity` | purpose、workspace/project scope、expiry、secret reference | identity、credential version、有效范围 | 不支持交互登录或通配项目；数据库不保存明文密钥 | 轮换可并存短重叠窗口；过期/撤销后旧版本拒绝并审计 | A（内部 Worker）/ F（受控集成） |
| 临时能力与高风险授权 | `IssueCapabilityGrant`、`RevokeCapabilityGrant`、`AuthorizeHighRiskAction` | action scope、purpose、期限、limit、grantor、目标对象 | grant、消费状态、授权基线 | grant 必须最小范围且可撤销；提交时重新校验，不能只信页面加载结果 | 超限/过期明确拒绝；消费与业务提交同事务或用消费凭证对账 | A（最小门禁）/ F（委派、双人批准） |
| 审计与紧急恢复 | `ListAccessAudit`、`EmergencyRevoke`、`OpenRecoveryReadOnlySession` | 时间/主体/对象过滤、事故理由、恢复审批依据 | 可分页审计、撤销批次、限时只读会话 | 只读恢复不包含生成、外发、批准或管理动作；审计不可被业务主体改写 | 批次部分传播持续重试并显示剩余对象；审计写失败回滚业务命令 | A |
| 企业目录 | `ConfigureSSO`、`SyncDirectoryMemberships` | IdP/SCIM 配置引用、映射规则、同步游标 | 同步报告、待人工冲突 | 外部目录只提供身份/成员输入，不改变本地 action 授权语义 | IdP/同步失败保留最后已确认本地状态并禁止管理降级 | F |

## 9. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| 所有业务模块 → M01 | `AuthorizationPort.authorize(actor, workspace_id, action, subject_ref, context)` | 每个 Query、Command、Worker result、媒体签名和 Agent Tool 在读取业务正文前调用；M01 只回答“能否执行”，不替业务模块做批准决定 |
| M01 ↔ M02 | M01 只通过 `ProjectAccessSubject(project_id, workspace_id, lifecycle)` 读取项目归属；M02 消费项目职责变化用于页面投影 | Project 身份和生命周期归 M02；ProjectAssignment 及授权计算归 M01；两者不得复制角色解释器 |
| M14 → M01 | `RiskGateDecision(decision_id, action, subject, outcome, policy_revision)` | M14 拥有权利/安全事实，M01 仅把已签认门禁结论纳入高风险授权；拒绝或过期时重新回源 |
| M01 → M08/M11 | `PrincipalRevoked`、`CapabilityGrantRevoked`，包含 subject、effective_at、policy version | 与 M01 状态和 Outbox 同事务；M08/M11 对未启动任务、预留和已收单外部任务分别对账，不由 M01 直接改其表 |
| M01 → M09/M12/M13 | 统一的对象读取、冻结审阅、媒体签名、交付批准 action | M09/M12/M13 拥有媒体、审阅和交付范围；M01 不创建业务快照，只校验其 subject/scope |
| M06/Agent Tool → M01 | 每个工具调用携带 service identity、代办 actor、workspace、project、action、run ID | Agent 不能继承前端的宽权限；工具结果和授权 policy version 一起审计 |

跨模块引用统一使用带 `workspace_id` 的稳定 ID；异步载荷携带 principal、action、subject、policy version 和因果 ID。数据库外键、应用查询条件、对象存储 key 和签名声明共同隔离 Workspace，任何一层缺少范围都必须拒绝。

## 10. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| Workspace | `active → disabled → active`，revision 单调递增 | 停用/恢复使用 expected revision；`CreateWorkspace` 以 `(actor, idempotency_key)` 唯一；状态改变提升 policy version |
| Invitation | `pending → accepted \| expired \| revoked` | token hash 唯一；接受使用条件更新 `pending`，重复成功回读同一 Membership，其他终态不可逆 |
| Membership | `active → suspended \| removed`；角色变化形成审计修订 | `(workspace_id, account_id)` 唯一活动关系；Owner 计数在同事务锁定检查；移除不物理删除 |
| ProjectAssignment | `active → revoked`，revision 单调递增 | `(membership_id, project_id, duty)` 活动唯一；命令需要 expected revision 和幂等键 |
| Session family | `active → revoked \| expired`，token version 单调递增 | refresh token 轮换采用 compare-and-set；发现重放撤销 family；重复 logout 返回已撤销 |
| CapabilityGrant | `active → consumed \| revoked \| expired` | 一次性 grant 消费与高风险命令绑定同一事务凭证；多次消费返回原结果或明确冲突 |
| ServiceIdentity | `active → suspended \| expired`，credential version 单调递增 | 轮换写新 secret reference 后切换 current；旧版本只在显式重叠窗口有效 |
| PolicyRevision | `draft → active → superseded` | 激活用 expected current revision；缓存 key 必须包含 policy version，禁止覆盖旧审计基线 |

撤销事务先提交权威状态、revocation version、AuditEvent 与 Outbox；页面和高风险接口立即按新版本回源，后台消费者用事件 ID 幂等撤销会话、签名和新任务资格。传播未完成是可见的 `reconciling`，不能显示为已完全撤销。

## 11. 页面与可观察状态

| 页面/入口 | 主要动作 | 必须可观察的状态 |
| --- | --- | --- |
| 登录、注册与会话安全 | 登录、验证邮箱、退出、修改密码、查看/撤销会话 | 验证状态、会话 family、最近活动、撤销原因、是否需要重新认证；不得显示 token |
| Workspace 列表与设置 | 创建、命名、停用、恢复 | active/disabled、当前 revision、成员数、停用传播状态、失败后的重试入口 |
| 成员与邀请 | 邀请、撤销邀请、改角色、停用成员 | pending/accepted/expired/revoked、期限、单次消费结果、角色基线、撤销对账进度 |
| 项目职责与有效能力 | 分配职责、查看有效能力和拒绝原因 | 组织角色/项目职责/临时 grant 的来源、policy version、到期时间、next action |
| 服务身份 | 创建、轮换、停用 | purpose、精确项目/action scope、credential version、到期/轮换状态、最近异常调用；不显示密钥值 |
| 访问审计与紧急恢复 | 筛选审计、紧急撤销、申请只读恢复 | actor、对象、前后基线、理由、结果、关联事件/批次、传播剩余项、只读会话期限 |

页面使用统一状态：初始加载 `loading`；空集合 `empty`；授权拒绝 `forbidden(reason_code, next_action)`；对象不可见统一 `not_found_or_forbidden`；写入 `submitting`；长撤销 `reconciling(progress, as_of)`；expected revision 冲突 `conflict(current_revision, diff)`；可恢复错误 `failed(retry_action)`。UI 不根据角色名称自行隐藏后假定授权成功，服务端结果始终是最终判定。

## 12. 逐 ID 验收映射

| Requirement ID | 设计落点 | 可执行验收 |
| --- | --- | --- |
| IAM-FR-001 | Workspace 生命周期用例与状态机 | 创建、改名、停用、恢复后断言稳定 ID、revision、历史和审计 |
| IAM-FR-002 | Invitation 聚合、token hash、条件消费 | 过期/撤销 token 失败；并发接受只产生一个 Membership |
| IAM-FR-003 | Membership 与 ProjectAssignment 分层 | 同一账户在两个 Workspace/项目职责不同，能力查询按层解释来源 |

| IAM-FR-005 | revocation version 与 Reconciler | 停用后旧会话、旧 grant、媒体签名和新任务资格逐项失效并显示传播状态 |
| IAM-FR-006 | ServiceIdentity 及 credential version | 仅声明 purpose/project/action 可调用；过期、越界和旧凭据均拒绝 |
| IAM-FR-007 | deny reason 与 next action | 页面/API 返回稳定 reason code 和可申请动作，同时不泄露对象归属 |
| IAM-FR-008 | 稳定 ID、签名声明、异步载荷共同带 workspace | 用异 Workspace UUID、签名链接和队列结果做负向集成测试 |
| IAM-FR-009 | AccessAudit 与事务内 AuditEvent | 邀请、角色、职责、会话、高风险授权均可查操作者/基线/理由/结果 |
| IAM-FR-010 | EmergencyRevoke、限时只读恢复 | 紧急撤销后仅经审批打开最小只读入口，生成/外发/批准仍拒绝 |
| IAM-FR-011 | 企业目录适配端口（F） | SSO/SCIM 同步改变本地输入但相同 action 策略结果不变；同步失败不扩大权限 |
| IAM-FR-012 | 临时委派与双人批准（F） | 委派到期自动失效；双人批准拒绝同一主体重复占两个批准席位 |
| IAM-NFR-001 | 全入口 Workspace 隔离契约 | UI/API/Worker/媒体/审计分别执行跨租户负向套件 |
| IAM-NFR-002 | `not_found_or_forbidden` 和无正文前授权 | 比较不存在对象与他租户对象响应，不得出现归属、名称或时序侧漏 |
| IAM-NFR-003 | revocation 指标与高风险回源 | 容量基线下测量 p95 生效时间；超过签认窗口告警且请求不放行 |
| IAM-NFR-004 | 统一 AuthorizationPort | 对 UI、API、Worker、媒体链接、Agent Tool 建矩阵化 action 负向测试 |
| IAM-NFR-005 | 审计最小化规则 | 扫描审计/日志/事件，确认无凭据、完整 token 或无关正文 |
| AC-IAM-001 | Workspace 过滤、签名及异步校验 | 已知他租户 UUID 仍无法读写或被 Worker 采用 |
| AC-IAM-002 | 成员停用撤销流程 | 刷新旧页面、使用旧 session、提交新任务和访问旧签名均不能扩大访问 |
| AC-IAM-003 | edit 与 generate/approve 分离 | 仅 editor 可保存草稿，但高消耗计划提交返回缺少 capability |
| AC-IAM-004 | M12 冻结范围 subject | Reviewer 只读指定 ReviewPackage/Snapshot，项目草稿和来源查询拒绝 |
| AC-IAM-005 | Invitation 条件消费与唯一约束 | 两个并发请求结果指向同一个 Membership，无重复审计副作用 |
| AC-IAM-006 | ServiceIdentity 精确 scope | 越 purpose、project 或 action 的调用被拒并记录异常审计 |
| AC-IAM-007 | 提交时 policy version 重验 | 页面加载后撤销权限，再提交高风险动作必须被阻止 |
| AC-IAM-008 | AccessAudit 前后基线 | 任一角色/策略变化可还原 actor、previous/current、time、reason、result |
