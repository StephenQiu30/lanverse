# M04 生产知识与一致性图谱详细设计

> Design ID：DES-M04
> Requirement：[REQ-KNO](../../requirement/004-M04-生产知识与一致性图谱需求.md)
> 专题细化：[剧本基础分析与人物拆解](../004-AI视频生产平台剧本基础分析与人物拆解详细设计.md)
> 状态：proposed

## 1. 设计结论

M04 采用关系型权威事实加可重建 occurrence/inventory/readiness/依赖投影，不以前置图数据库承载业务真相。稳定实体、权威未决主体、名称、长期资料、范围状态、语义关系、生产需求/覆盖决定、生产参考和影响报告分别版本化，避免把一份人物 JSON 同时当身份、状态、出现集数和提示词。人物对应集数由 approved Scene/Mention、UnresolvedSubjectRevision 与 MentionResolution 重建；需求决议不可变，媒体或参考变化只重建 readiness 投影。

## 3. 地点、道具与规则结构

- Location Profile：空间类型、内外景、区域/入口、稳定视觉锚点、可用拍摄区域和禁止项；
- Location State：时段、天气、光照、陈设、拥挤、损坏、封锁区域和范围；NarrativeScene 只引用 LocationEntity，不与其合并；
- Prop Profile：唯一物/可替代物/消耗品/品牌物/集合物、数量单位、稳定外观、剧情用途和连续性策略；
- Prop State：所有者、持有人、位置、数量、完整/损坏/丢失/消耗状态和证据 Beat；独占物同一范围最多一个 holder；
- World/Style Rule：rule type、value/constraint、scope、priority、required/forbidden、evidence 和 production representation；
- 品牌、版权和受限物品只保存生产知识描述，是否允许参考/外发/交付仍由 M14 评估。
- `ProductionElementMention → ProductionEntity/UnresolvedSubjectRevision → ProductionCoverageDecision/RequirementRevision → ReferenceBinding/MediaArtifact` 是不同对象：来源提及、稳定身份/未决主体、生产覆盖决定/需要和实际素材不得折叠。
- 全剧生产需求类型至少覆盖 character identity、costume、makeup、location、prop、vehicle、voice、style 和 VFX；服装通常先作为人物状态/需求，只有明确复用身份时才单独建实体。
- 每个 approved character Mention 必须恰有一个 current MentionResolution：entity、一个 active UnresolvedSubjectRevision 或 explicit reject；同一 Mention 不得进入多个 active 未决成员集，成员集与 Resolution 引用必须一致。缺失、重叠或不一致都计入 resolution coverage 缺口，使 occurrence `incomplete` 并阻止预检。
- Inventory 的 coverage universe 至少包含全部 approved ProductionElementMention，以及投影绑定的 ProductionCoverageSchemaRevision 要求地点/布景判断的全部 approved NarrativeScene。每个成员必须有 ProductionCoverageDecision，保存 relevance、`required | deferred | not_required | rejected` 结果与零个或多个 RequirementRevision refs；缺决定或引用不完整都计入 `unassessed`。`unassessed > 0`、failed scope 或来源分析不完整时不得标 current/complete；Schema 换版使旧 Inventory stale，历史按原 revision/hash 重建。

批量传播先生成目标成员、旧值/新值、覆盖优先级、冲突、受影响 Shot/Plan/Review/Delivery 和预计资源预览；用户确认后逐项提交，部分失败保留精确结果。

## 4. 有效范围解析

范围输入先解析为可预览表达式，再冻结为成员快照。优先级为 `project < content_unit < narrative_scene < beat < shot`；Scene/Beat 必须带 NarrativeRevision。无法比较的跨版本范围阻止发布，不能用创建时间决定。

同实体、属性面、成员和优先级最多一个 current。`KnowledgeConflictAcceptance` 必须绑定具体冲突、范围、责任人和期限，不能作为通用跳过按钮。

## 5. 命令、查询与事件

- Commands：`Create/Revise/Split/MergeUnresolvedSubject`、`ResolveMention`、`Merge/SplitEntity`、`CreateProductionRequirement`、`DecideProductionRequirement`、`Create/PublishProductionCoverageSchemaRevision`、`DecideProductionCoverage`、`LinkCoverageSubjectToRequirement`、`RebuildEntityOccurrenceProjection`、`RebuildProductionRequirementInventory`、`RebuildRequirementReadiness`、`CreateProfileRevision`、`PublishEntityStateRevision`、`PublishRelationRevision`、`BindReference`、`PublishWorkspaceAsset`、`AcceptKnowledgeConflict`；
- Queries：实体时间线、人物 360、人物×剧集矩阵、全剧生产清单及覆盖 envelope、需求准备度、实体 occurrence、地点/道具状态、范围预览、冲突列表、影响报告；
- Events：`UnresolvedSubjectRevised`、`EntityResolved`、`ProductionRequirementDecided`、`ProductionCoverageSchemaPublished`、`ProductionCoverageDecided`、`ProductionRequirementInventoryChanged`、`RequirementReadinessChanged`、`EntityOccurrenceProjectionChanged`、`EntityStatePublished`、`ReferenceBindingChanged`、`WorkspaceAssetPublished`；
- 只通过 M03 SourceAnchor 引用证据，通过 M09 ID 引用媒体，通过 M05/M07/M10/M12/M13 的公开查询计算影响。

## 6. 影响计算

业务关系写入权威表；依赖投影消费者按领域事件生成 `dependency_edge`。变更预览固定 source revision hash，遍历直接引用、有效范围和硬/软规则，输出受影响 ShotPlan、GenerationPlan、Candidate 可用性、Evaluation、ReviewPackage、Assembly 和 Snapshot（历史只读）。超时进入 Operation，不允许高风险传播先行。

## 7. 失败与恢复

- Mention 证据不足：保持 pending cluster，不猜实体；
- merge/split 影响过大：生成预览，逐项迁移引用；
- 互斥状态：阻止 current，允许修订范围或具名接受；
- 投影丢失：从权威事实重建，期间显示 impact unavailable；
- 参考缺失：实体仍存在，依赖参考的新计划 blocked；
- 来源换版：Anchor/Scope 不自动漂移，进入显式迁移。
- 剧集边界、NarrativeRevision 或 MentionResolution 变化：历史 occurrence 保持旧基线，新投影进入 stale/rebuilding，只重算受影响成员；页面不能把未分析渲染为零出现。
- 全剧分析 partial 或存在未评估 Mention/Scene：Inventory 保留成功范围并标 incomplete/failed scopes/unassessed，禁止以不完整总数宣称 ready。
- ReferenceBinding、SelectionDecision 或 MediaArtifact 可用性变化：不修改 ProductionRequirementRevision；旧 RequirementReadinessProjection 标 stale，再按固定 requirement revision 重建并原子切换。

## 8. 性能、安全与验证

常用属性结构化列/版本化 Schema，长尾 JSON 带 schema version；范围成员和依赖边按 workspace/project 索引。Workspace 发布资产复制发布快照或显式绑定，不读取源项目草稿。

测试覆盖同名拆分、别名合并、人物跨集 occurrence、生产需求、换装、伤痕、唯一/消耗道具、地点变化、关系环、范围冲突和最小影响。映射 KNO-FR-001—017、KNO-NFR-001—007、AC-KNO-001—016；A 建最小人物/地点/道具事实、全剧清单和人物×剧集矩阵，D 完成弧光、高级连续性、影响与修复闭环。

## 10. 模块边界与跨模块契约

| 方向/模块 | 契约 | 一致性与边界 |
| --- | --- | --- |
| M03 → M04 | `ApprovedNarrativeAnalysisView` + 同 basis hash 的 paged Scene/`ProductionElementMentionRef`，可选 M03 Cluster Proposal ref | M03 拥有来源、Mention、叙事结构、完整度和非权威聚类建议；M04 固定 view basis 后构建 UnresolvedSubject/Resolution/Coverage/Requirement/投影。任何页 basis 不同则失败，不把 partial 当完整 |
| M02 → M04 | stable ContentUnit/OrderRevision；M04 返回 revision-bound entity coverage 状态 | M02 拥有身份/顺序；M04 矩阵按 OrderRevision 排列但不复制 ordinal 为事实，重排只换列序、不换 occurrence/entity ID |
| M04 → M05 | `EffectiveKnowledgeSnapshot(subjects, scope_membership_hash, revision_refs)` 与变更影响事件 | M05 显式绑定 entity/state/rule revision；M04 不改 ShotPlan。新知识只将真实引用标待复核 |
| M09 ↔ M04 | M09 提供 immutable MediaArtifact/SelectionDecision；M04 保存 purpose 化 ReferenceBinding | Candidate/Selection 归 M09；M04 不维护第二套候选/current media，M09 不解释人物/地点/道具语义 |
| M04 → M07 | 批准的知识 revision、有效规则和 ReferenceBinding 查询 | M07 冻结 GenerationPlan 输入；Prompt 不是 M04 事实，计划发布后 M04 变化只产生影响 |
| M04 ↔ M10 | M04 提供预期状态/规则；M10 返回结构化 issue 引用 | M10 拥有质量问题/接受，M04 的 KnowledgeConflictAcceptance 不能关闭 M10 问题，反向亦然 |
| M04 → M12/M13 | 影响查询返回 ReviewPackage/Assembly/DeliverySnapshot 边；冻结历史标 read-only | M12/M13 拥有审阅/装配/交付事实；M04 不改冻结包或快照，只报告影响 |
| M14 → M04 | 权利/品牌/受限物品治理结论 | M04 保存生产知识和证据；M14 决定参考能否生成、外发、交付，Knowledge acceptance 不构成治理例外 |
| M15 ↔ M04 | WorkspaceAssetRelease 的发布/采用版本 | M04 拥有发布的实体/规则快照；M15 可编排模板引用但不能读取源项目草稿 |

范围成员引用稳定 Project/ContentUnit/Shot ID；Scene/Beat 必须使用 `(narrative_revision_id, member_id)`。所有下游读取返回精确 revision refs 和 membership hash，禁止只返回“当前人物 JSON”。依赖事件携带 change hash 和 source revision；投影以 event ID 幂等，可重建但不反写权威关系。

## 11. 关键状态、并发与幂等

| 对象 | 状态/版本 | 并发与幂等规则 |
| --- | --- | --- |
| ProductionEntity | `active → disabled \| archived`；type 和 stable ID 不可变 | create/link/merge/split 决议用 Mention + command ID 去重；归档不删除 Mention、revision 或引用 |
| UnresolvedSubjectRevision | 创建即不可变；`active → superseded \| resolved` | narrative revision + member set hash + idempotency key 唯一；member 不可原地修改；split/merge 创建新 revision 并显式 supersede 旧组 |
| MentionResolution | 追加决定；current 可被新决定 supersede | mention + narrative revision + command ID 唯一；每个 approved character Mention 恰有一个 current；entity_id/unresolved_subject_revision_id 严格二选一（explicit reject 可均空）；未决引用与 active member 集一致；只引用 approved Mention |
| Name/ProfileRevision | `draft → published/current → superseded` | published 不可变；current pointer compare-and-set；每字段保留 evidence/epistemic status |
| EntityStateRevision | `draft → published/current → superseded` | 同 entity/facet/member/priority 最多一个 current；发布锁定 scope membership hash 和 expected current |
| EntityRelationRevision | `draft → published/current → superseded` | source/target/direction/type/scope 形成语义键；反向关系是另一事实；普通环不冲突 |
| RuleRevision | `draft → published/current → superseded` | 相同 rule key/scope/priority current 唯一；required/forbidden 预检与发布同基线 |
| EffectiveScope | `parsed → previewed → frozen \| invalid` | frozen 成员不可变且有 expression/member hash；叙事换版不原地迁移，需创建新 scope |
| ReferenceBinding | `active → superseded \| revoked` | purpose + target revision + scope 为语义键；SelectionDecision/RuleRevision 变化不原地替换历史 binding |
| ProductionRequirementRevision | `draft → decided → superseded`；decision=`required \| deferred \| not_required \| rejected` | item key + scope hash + idempotency key 唯一；decided revision 不可变；published narrative/Anchor 变化创建新 revision，不原地漂移 |
| ProductionCoverageSchemaRevision | `draft → published/current → superseded` | 项目创建时产生默认已发布 Schema；published 后规则/content hash 不可变；current pointer compare-and-set；换版使旧 Inventory stale，历史仍按原 hash 重建 |
| ProductionCoverageDecision | 创建即不可变；可被新 decision supersede | coverage subject + narrative revision + decision revision 唯一；保存 relevance/result/RequirementRevision refs/actor/reason；Inventory 不反写该事实 |
| RequirementReadinessProjection | `building → current \| incomplete \| stale \| failed`；readiness=`unknown \| missing \| partial \| ready \| blocked \| not_applicable` | required 绑定 reference/media revision set；deferred 固定 blocked/decision_deferred；not_required/rejected 固定 not_applicable；Reference/Media 变化只使 required 投影 stale；重建后原子切换 |
| ProductionRequirementInventoryProjection | `building → current \| incomplete \| stale \| failed`，绑定 M03 view basis、M04 unresolved-subject/resolution、coverage-schema/coverage-decision、requirement revision set、as_of、input_hash | `current` 必须 M03 completeness=complete、failed_scopes 为空且 unassessed=0；Schema/current 输入变化使旧投影 stale；coverage row cursor 绑定 projection version；可从 approved Scene/Mention、绑定 Schema 与 M04 决议重建 |
| EntityOccurrenceProjection | `building → current \| incomplete \| stale \| failed`，绑定 narrative view/order/resolution/unresolved-subject revision set、failed_scopes、resolution coverage counters、as_of/input_hash | item 的 entity_id/unresolved_subject_revision_id 严格二选一；current 要求 failed_scopes 为空、unassigned=0、overlap=0 且成员/Resolution 一致；从权威 Mention/UnresolvedSubject/Resolution 重建；page cursor 绑定 projection version；原子切换 current，保留历史矩阵 |
| KnowledgeConflictAcceptance | `active → expired \| revoked \| superseded` | 绑定 conflict hash、scope、actor、reason、expires_at；不同 hash 不可复用 |
| ImpactReport | `queued → running → completed \| failed \| stale` | change hash + projection version + scope 唯一；迟到结果可审计但不能确认已变化基线 |
| WorkspaceAssetRelease/BulkManifest | 发布 release 不可变；manifest `prepared → applying → partial \| completed \| cancelled` | release version 单调；bulk item 以 target + base revision 幂等，逐项 compare-and-set |

发布命令在一个事务内写 revision、current pointer、AuditEvent 和 Outbox。影响计算可异步，但 `ConfirmKnowledgeChange` 必须校验报告的 change hash、scope membership hash 和 current revisions；任一变化都要求重新预览，禁止用旧报告覆盖新事实。
