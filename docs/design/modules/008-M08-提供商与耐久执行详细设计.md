# M08 提供商与耐久执行详细设计

> Design ID：DES-M08
> Requirement：[REQ-EXE](../../requirement/008-M08-提供商与耐久执行需求.md)
> 状态：proposed

## 1. 设计结论

M08 使用 PostgreSQL Operation/GenerationJob/Attempt 状态机、事务 Outbox、RabbitMQ 和 Scheduler/Reconciler 实现首期耐久执行。队列与 Worker lease 不是产品事实；一个 PlanItem 对应一个 Job，Operation 聚合批量结果。

M08 同时拥有 `ProviderConnection` 及其连接状态、密钥引用、回调/轮询协议与限流证据；M07 只拥有不可变 `CapabilityRevision` 和路由视图。M08 不修改已批准计划、不选择候选、不保存媒体字节，也不实现商业账单。本边界属于模块化单体，进程角色可独立部署但不拆领域微服务。

## 2. 运行对象

| 对象 | 职责 |
| --- | --- |
| Operation | 用户可见长操作、进度、错误和恢复动作 |
| GenerationJob | 单 PlanItem 逻辑执行，稳定幂等键 |
| Attempt | 一次提交/重试证据，不覆盖历史 |
| ProviderSubmission | connection、request hash、external ID、result certainty |
| CallbackReceipt | 验签、event ID/body hash、状态应用结果 |
| ReconciliationCase | unknown 原因、证据、查询、人工结论 |
| RateLimitLease/CircuitState | 连接级保护，可重建运行数据 |

## 3. 提交协议

API/计划批准事务创建 Operation、每项 Job、Task 和 Outbox。Publisher 至少一次投递；Worker 领取 lease 后先回读 Job/Attempt，再调用 Adapter。提交响应必须先持久化 external ID/确定性，再推进状态。任何保存失败由 Reconciler 用 idempotency key/时间窗/Provider 查询对账。

Adapter 只映射厂商请求、状态、错误、回调、轮询和取消，不拥有业务重试规则。提供商未知新状态进入隔离，不映射成成功/失败。

## 4. 状态

Job 状态包括 `accepted`、`queued`、`running`、`partial`、`succeeded`、`failed`、`cancel_requested`、`cancelled`、`unknown`、`blocked`。Attempt 状态包括 `created`、`submitting`、`waiting_provider`、`downloading`、`succeeded`、`failed`、`cancelled`、`unknown`。Operation 统一平台长操作状态并从 Jobs 投影。

`result_certainty = created | not_created | unknown`。只有 `not_created` 或提供商明确安全重试才能自动新 Attempt；unknown 必须有 ReconciliationCase。

## 5. 回调、取消和下载

Webhook 先验签、防重放和反查 external task；重复/乱序事件只推进合法状态。取消先记录 cancel_requested，再调用 Provider；未确认保持 unknown。Provider Adapter 只提供受限输出定位符、请求头和完整性声明，M08 调度 M09 摄取端口完成字节传输、隔离和存储验证。传输失败复用 external ID 和同一摄取意图，禁止重新生成替代重下载。

## 6. 失败恢复与背压

- Outbox 未发布：Publisher 重试同一 event；
- Worker 崩溃：lease 到期由 Reconciler 续做同一安全步骤；
- 提交超时：unknown/对账，不盲目重发；
- 批量部分失败：成功项保持，Operation partially_failed；
- 提供商限流：workspace/project/provider/capability 多层队列和退避；
- 连接撤销：停止新 Job，已提交进入对账。

## 7. 安全、观测与验证

凭据仅 Worker 从密钥服务按 connection 读取；回调原文敏感字段受控。Trace 串联 operation→job→attempt→external→artifact。故障注入覆盖提交前后崩溃、重复/乱序回调、取消未知、下载中断和迟到成功。

映射 EXE-FR-001—013、EXE-NFR-001—006、AC-EXE-001—009。A 建立 Operation/假任务骨架，C 接真实 Provider。

## 8. 模块边界与跨模块契约

| 模块 | M08 读取/调用 | M08 对外承诺 | 边界失败处理 |
| --- | --- | --- | --- |
| M01/M02 | actor、workspace/project 权限和服务身份 | Operation/Job 查询按 scope 隔离 | 越权隐藏对象；服务身份只得到指定 connection/capability |
| M07 | approved Plan/Item、execution key、CapabilityRevision 及 fallback set | `CreateExecutionForApprovedPlan`、`GetProviderConnectionView` | 不接受 draft/过期/集合外能力；不回写 Plan 运行状态 |
| M09 | `IngestProviderArtifact` 传输/完整性端口 | Job/Attempt/output ordinal 和受限 locator | M09 存储失败不伪装 Provider 生成失败；复用 external ID 重试摄取 |
| M11 | Reservation/剩余上限、UsageEntry 追加端口 | Job/Attempt/provider record 归因 | unknown/迟到费用不改写旧用量证据 |
| M14 | connection policy、凭据 secret ref、提交前最终门禁 | 提交/取消/人工对账审计引用 | 凭据仅 Worker 按引用取得；策略撤销停新提交，已收单进对账 |
| 通知/前端 | Operation 查询和版本化事件 | `generation.job.changed.v1`、小型状态/恢复动作 | 前端不解释 queue delivery、lease 或外部原始状态 |

`ProviderConnection` 至少保存 `provider_code`、`credential_ref`、`region`、`protocol_revision`、`status`、`policy_revision_id`、`revision`；不保存密钥密文。`GetProviderConnectionView` 仅返回 connection ID、provider/region、supported capability refs、可用性、circuit/rate-limit 摘要、as-of/expiry，不返回凭据和敏感请求。

## 10. 关键状态、并发与幂等

### 10.1 状态守卫

| 对象 | 关键转换 | 守卫/证据 |
| --- | --- | --- |
| Operation | `accepted→queued→running/waiting_external→succeeded/partially_failed/failed/unknown/cancelled` | 只从 Jobs 和持久证据汇总；waiting/unknown 可因新证据回 running；终态不回退 |
| Job | 主路径 `accepted→queued→running`，再进入 `succeeded`、`failed`、`partial`、`unknown` 或 `cancel_requested`；unknown 经对账证据可回 `running`、进入任一有证终态，或在证明确未创建后回 `queued` 建新 Attempt | 只有 approved PlanItem；unknown 不能无证据变 failed；成功只表示执行完成，不表示候选采用 |
| Attempt | 主路径 `created→submitting→waiting_provider→downloading`，再进入 `succeeded`、`failed`、`cancelled` 或 `unknown`；unknown 经对账可进入 `waiting_provider`、`downloading` 或有证终态 | Attempt 只追加；若确认 not_created，原 Attempt 以证据结束后才可新建 Attempt；不得改写旧记录 |
| ReconciliationCase | `open→investigating`；证据充分后进入 `resolved_existing`、`resolved_not_created`、`resolved_terminal`；证据仍不足可进入 `manual_attention` 后再回 investigating | 每次观察追加证据与 actor；resolved_not_created 才允许安全新 Attempt；具名人工结论不得跳过 Provider/幂等证据 |
| ProviderConnection | `validating→active→degraded/disabled/revoked` | 状态变化审计并发出 M07 重评信号；不篡改历史 Attempt |

### 10.2 幂等和事务

- Job 唯一：`plan_item_id`；Operation 业务幂等：`workspace + actor + command_type + Idempotency-Key`。
- Attempt 唯一：`job_id + attempt_no`；Provider 提交键由 `connection_id + job_id + attempt_no + request_snapshot_hash` 稳定派生。
- Submission external 唯一：`connection_id + external_job_id`；Callback 唯一：`connection_id + provider_event_id`，同 event ID 不同 body hash 进隔离。
- 每个外部步骤分为“短事务 prepare → 事务外调用 → 短事务 finalize”；外调时不持有数据库锁。
- Outbox/Inbox 至少一次投递；消费者先按 event/delivery ID 去重并回读 Job/Attempt，不只信消息 payload。
- `result_certainty=unknown` 必须同事务创建 ReconciliationCase；网络异常不得映射为 `not_created`。

## 11. 页面与可观察状态

| 页面 | 权威数据 | 必须展示 | 动作 |
| --- | --- | --- | --- |
| 任务中心 | Operation/Job 查询 | 目标、阶段、进度、partial/unknown、错误类别、最近进展、下一动作 | 筛选、取消、安全重试、进入对账 |
| Job/Attempt 详情 | Job、Attempt、Submission、Receipt、Usage refs | approved PlanItem、request hash、connection/model、external ID（脱敏）、状态时间线、原始错误摘要 | 查询外部状态、重下载、申请敏感诊断权限 |
| Unknown 对账队列 | ReconciliationCase | 原因、时间窗、已查证据、可能仍计费警告、下次查询 | 查询、绑定外部任务、具名确认结果；无“强制失败并重发” |
| Provider 连接管理 | ProviderConnection/health/circuit/rate view | 地区、协议版本、secret ref 状态、可用性、最后验证、受影响能力 | 验证、替换密钥引用、停用；不显示密钥正文 |

指标包括 Operation 停滞、排队/提交/外部等待/摄取耗时、unknown 比例/持续时间、Attempt 重试率、重复/乱序回调数、下载恢复率、按错误/provider/connection 的失败率、lease 回收与熔断时间。Trace 串联 operation→job→attempt→external→artifact，不记密钥或媒体 URL。

### 13.1 功能需求

## 14. 验证与交付顺序

切片 A 先以假 Provider 验证 Operation/Job/Task/Outbox、重复投递和 Worker 重启；切片 C 对每个真实 Provider 签认幂等、回调、轮询、取消、保留和计量语义。故障注入覆盖提交前后崩溃、回调重复/乱序、取消未知、M09 传输中断、迟到成功和不可识别状态；任一验证缺外部条件时不报告为通过。
