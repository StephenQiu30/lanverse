# M10 质量、连续性与修复详细设计

> Design ID：DES-M10
> Requirement：[REQ-QAR](../../requirement/010-M10-质量连续性与修复需求.md)
> 状态：proposed

## 1. 设计结论

质量评估是针对冻结对象的版本化证据，不能写 Selection 或 ReviewDecision。Issue 只有在复检通过、人工判定不适用/误报或有效 QualityRiskAcceptance 后关闭；修复完成本身不等于问题解决。

## 2. 领域对象

| 对象 | 设计要点 |
| --- | --- |
| QualityPolicyRevision | scope、rule set、severity matrix、status |
| QualityEvaluation | subject/hash、policy/evaluator version、coverage、status |
| QualityIssue | category、severity、confidence、blocking scope、owner、status |
| EvidenceAnchor | artifact/timebase/range/region/field、expected/actual |
| QualityRiskAcceptance | issue、scope、reason、actor、expiry；不替代 M14 |
| RepairPlan | fixed issues/input、change set、impact、estimate、verification scope |

## 3. 检查执行

技术规则优先采用确定性 ffprobe/解码/音频/字幕检查；语义和连续性评估读取 M04/M05 冻结版本并输出结构化提案；安全/品牌结果由 M14 产生，M10 只统一展示和关联。

评估 Worker 通过受限结果端口写 Evaluation/Issue，不具备 Selection、风险接受或交付权限。规则/输入/评估器变化使旧结果 stale，但历史可重读。

## 4. 命令与流程

- Commands：`StartQualityEvaluation`、`Confirm/Dismiss/ReopenIssue`、`AcceptQualityRisk`、`Create/ApproveRepairPlan`、`RequestTargetedRecheck`；
- Queries：问题列表、证据定位、覆盖缺口、连续性链、修复影响/资源；
- Events：`QualityIssueOpened`、`RepairPlanApproved`、`CandidateRequiresRecheck`、`QualityIssueResolved`。

RepairPlan 批准后转换为 M04/M05 修订或 M07 GenerationPlan；执行成功的新 Candidate 触发定向规则和相邻依赖复检。

## 5. 状态与不变量

Evaluation：`queued → running → partial | completed | failed | cancelled → stale`。Issue：`open → confirmed | dismissed | not_applicable → pending_recheck → resolved | accepted_risk → reopened`。终态变更必须有新证据/决定。

风险接受只覆盖列出的 quality issue、对象、期限；权利/安全 blocker 必须由 M14 PolicyException 处理。未评估不能显示通过。

## 6. 失败与恢复

评估器失败保留 coverage gap；分片结果幂等合并；规则升级按受影响 rule code 重评；RepairPlan 过期重新算 impact/estimate；修复生成失败不改变原主选和 Issue；风险到期重新打开 blocker。

## 7. 验证

Golden media/标注集测技术规则、服装/道具连续性、时间区域坐标、误报处理、局部修复和定向复检；指标必须区分误报、漏报、未评估和风险接受。

映射 QAR-FR-001—011、QAR-NFR-001—005、AC-QAR-001—009；切片 D 先实现技术检查、一个结构化语义检查器和人工问题闭环。
