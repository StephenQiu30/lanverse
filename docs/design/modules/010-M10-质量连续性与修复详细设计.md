# M10 质量、连续性与修复详细设计

> Design ID：DES-M10
> Requirement：[REQ-QAR](../../requirement/010-M10-质量连续性与修复需求.md)
> 状态：proposed

## 1. 设计结论

质量评估是针对冻结对象的版本化证据，不能写 Selection 或 ReviewDecision。Issue 只有在复检通过、人工判定不适用/误报或有效 QualityRiskAcceptance 后关闭；修复完成本身不等于问题解决。

M10 只拥有质量策略、评估、问题、证据、风险接受和修复计划，不拥有媒体完整性、候选主选、领域 current、供应商执行或交付批准。M09 验证字节/存储完整性；M10 在已可读 Artifact 上判断目标时长、黑帧/静音、镜头符合性、连续性等用途质量。本模块不拆为微服务。

## 2. 领域对象

| 对象 | 设计要点 |
| --- | --- |
| QualityPolicyRevision | scope、rule set、severity matrix、status |
| QualityEvaluation | subject/hash、policy/evaluator version、coverage、status |
| QualityIssue | category、severity、confidence、blocking scope、owner、status |
| EvidenceAnchor | artifact/timebase/range/region/field、expected/actual |
| QualityRiskAcceptance | issue、scope、reason、actor、expiry；不替代 M14 |
| RepairPlan | fixed issues/input、change set、impact、estimate、verification scope |
| RepairAction | `domain_revision` / `deterministic_media` / `provider_regeneration`、target port/schema/version、input refs、expected result |

## 3. 检查执行

技术规则优先采用确定性 ffprobe/解码/音频/字幕检查；语义和连续性评估读取 M04/M05 冻结版本并输出结构化提案；安全/品牌结果由 M14 产生，M10 只统一展示和关联。

评估 Worker 通过受限结果端口写 Evaluation/Issue，不具备 Selection、风险接受或交付权限。规则/输入/评估器变化使旧结果 stale，但历史可重读。

## 4. 命令与流程

- Commands：`StartQualityEvaluation`、`Confirm/Dismiss/ReopenIssue`、`AcceptQualityRisk`、`Create/ApproveRepairPlan`、`RequestTargetedRecheck`；
- Queries：问题列表、证据定位、覆盖缺口、连续性链、修复影响/资源；
- Events：`QualityIssueOpened`、`RepairPlanApproved`、`CandidateRequiresRecheck`、`QualityIssueResolved`。

RepairPlan 批准只冻结问题、作用、输入、影响、用量和验证范围，不直接执行。`domain_revision` 类动作经 M04/M05 正式命令端口创建修订草稿，仍遵守目标模块的发布/批准规则；`deterministic_media` 类动作经 M09/M13 正式媒体处理或装配端口提交，目标模块再通过 M08 execution port 创建或关联通用 Operation，并拥有自己的派生媒体/装配结果；`provider_regeneration` 必须创建新 M07 GenerationPlan 草稿，经 M07 预检/批准后才能由 M08 执行。任何 RepairAction 都不允许 M10 直调 M08 或 Provider。执行成功的新 Candidate 触发定向规则和相邻依赖复检。

## 5. 状态与不变量

Evaluation 主路径为 `queued → running → partial | completed | failed | cancelled`；输入、规则或评估器变化可把已有结果标为 `stale`。Issue 从 `open` 可进入 `confirmed`、`dismissed`、`not_applicable` 或 `accepted_risk`；`confirmed → pending_recheck → resolved`。新证据可将 `dismissed/not_applicable/resolved` 重新打开，风险接受撤销或到期可将 `accepted_risk` 重新打开。终态变更必须有新证据或具名决定。

风险接受只覆盖列出的 quality issue、对象、期限；权利/安全 blocker 必须由 M14 PolicyException 处理。未评估不能显示通过。

## 6. 失败与恢复

评估器失败保留 coverage gap；分片结果幂等合并；规则升级按受影响 rule code 重评；RepairPlan 过期重新算 impact/estimate；修复生成失败不改变原主选和 Issue；风险到期重新打开 blocker。

## 7. 验证

Golden media/标注集测技术规则、服装/道具连续性、时间区域坐标、误报处理、局部修复和定向复检；指标必须区分误报、漏报、未评估和风险接受。

映射 QAR-FR-001—011、QAR-NFR-001—005、AC-QAR-001—009；切片 D 先实现技术检查、一个结构化语义检查器和人工问题闭环。

## 8. RepairAction 路由与跨模块契约

### 8.1 三类修复动作

| action kind | 适用范围 | 批准后调用的正式端口 | 后续批准/执行 | M10 禁止行为 |
| --- | --- | --- | --- | --- |
| `domain_revision` | 修改人物/地点/道具状态、镜头意图/方案、参考绑定 | M04 `CreateEntityStateRevision` 或 M05 `CreateShotPlanRevision` 等类型化命令 | 只建草稿；目标模块独立预览影响、发布/批准 | 不直推 current，不以 RepairPlan approval 代替领域批准 |
| `deterministic_media` | 受控裁剪、转码、音量、字幕时序或装配调整 | M09 版本化派生端口或 M13 装配/构建端口 | M09/M13 经 M08 execution port 创建/关联 Operation；各自拥有派生 Artifact 或 Assembly/Build 结果，再回 M10 复检 | M10 不创建 Operation、不直控 FFmpeg Worker、不跳过 M09/M13 端口和完整性检查 |
| `provider_regeneration` | 换参考/能力、重新编译提示/参数、重生成候选 | M07 `CreateGenerationPlan` | 必须经 M07 预检、资源/治理门禁和批准；之后 M08 才可执行 | 不直建 Job/Attempt，不自动批准 Plan，不直调 Provider |

一个 RepairPlan 可含多个 RepairAction，但每个 action 必须有单一 kind、明确 target port/schema version、独立输入 hash 和验证 scope。不同 kind 不使用跨外部副作用的伪原子事务；顶层编排器逐项调用所属模块端口，并在 RepairPlan 记录 `target_result_ref/error/recovery_action`。

### 8.2 跨模块端口

| 模块 | M10 读取 | M10 调用/发布 | 边界失败处理 |
| --- | --- | --- | --- |
| M01/M02 | actor、workspace/project、分派/风险接受权限 | 问题/计划查询按 scope 隔离 | 风险接受每次重新鉴权；越权隐藏对象 |
| M04/M05 | 冻结实体状态、ShotPlan、相邻依赖 | domain_revision 命令信封 | 版本冲突时 RepairAction 过期，重算 impact，不自动迁移 |
| M09 | Artifact/Metadata/Candidate/Selection 精确版本 | `candidate.requires-recheck.v1`、deterministic_media 派生端口；M09 经 M08 execution port 关联 Operation | M09 拥有 Artifact/派生结果且只证存储完整性；M10 不拥有运行或用途结果 |
| M07 | 资源/能力预检摘要 | provider_regeneration 的 GenerationPlan draft | Plan blocked/rejected 不改原 Issue/Selection；M10 不调 M08 |
| M13 | AssemblyRevision/交付输入快照 | deterministic_media 装配端口、交付 blocker 查询；M13 经 M08 execution port 关联 Operation | M13 拥有 Assembly/Build；构建失败保留旧事实，回 M10 显示未验证 |
| M14 | PolicyEvaluation、policy blocker 摘要和 PolicyException refs | 安全/品牌阻塞统一关联 | M10 不复制为 QualityIssue；QualityRiskAcceptance 不能覆盖权利/安全，必须进 M14 具名例外 |

M10 发布小型版本化事件 `quality.issue.opened.v1`、`repair.plan.approved.v1`、`candidate.requires-recheck.v1`、`quality.issue.resolved.v1`。事件不携带评估原文/媒体 URL，消费者回读 Evaluation/Issue/RepairPlan。

## 10. 状态、并发与幂等

### 10.1 状态机

| 对象 | 状态与转换 | 关键守卫 |
| --- | --- | --- |
| Evaluation | 主路径 `queued→running`，再进入 `partial`、`completed`、`failed` 或 `cancelled`；已有结果可标为 `stale` | partial 必须有 coverage gap；输入/策略/评估器变更只标 stale，不删历史 |
| Issue | `open` 可进 `confirmed`、`dismissed`、`not_applicable` 或 `accepted_risk`；`confirmed→pending_recheck→resolved`；新证据或风险到期可 `reopened→open` | resolved 需通过复检；accepted_risk 需有效接受；dismissed/not_applicable/resolved 仅凭新证据重开 |
| RepairPlan | `draft` 可进 `impact_ready` 或 `blocked`；`impact_ready→awaiting_approval`，再进 `approved` 或 `rejected`；未批准状态可 `superseded` 或 `cancelled` | approved 冻结 issues/input/actions/impact/estimate/verification；action 执行状态不写回为 Plan success |

### 10.2 幂等和冲突

- Evaluation 唯一：`subject hash + policy revision + evaluator version + requested rule set`；已 completed 可幂等回读，stale 时创建新 Evaluation。
- 分片结果唯一：`evaluation_id + shard_key + sequence`，同 sequence 不同 result hash 进隔离并不改 Issue。
- Issue 稳定键：`evaluation + rule_code + subject ref + normalized anchor hash`；重复检测合并证据，不创建重复问题。
- 问题决议使用 issue revision 乐观锁；风险接受必须在同事务重读权限、scope 和有效期。
- RepairPlan 批准使用 `plan revision + input_hash + impact_hash + estimate_ref`；任一依赖变化拒绝批准。
- Action dispatch 幂等键为 `repair_plan_id + action_id + target_module + action_hash`；目标模块回读既有 result，M10 只追加回执。

## 14. 验证与交付顺序

切片 D 先交付一组目标技术检查、一个结构化语义/连续性检查器、Issue 人工决议、RepairPlan 三类 action 路由和定向复检。Golden media/标注集覆盖时间码/区域/字段证据、误报、分片重启、规则升级和风险到期。重点架构测试必须证明 M10 无 M08/Provider 写路径：`domain_revision` 只调 M04/M05，`deterministic_media` 只调 M09/M13，`provider_regeneration` 只创建 M07 GenerationPlan 并等待独立批准。
