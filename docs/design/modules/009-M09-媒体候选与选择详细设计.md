# M09 媒体、候选与选择详细设计

> Design ID：DES-M09
> Requirement：[REQ-MED](../../requirement/009-M09-媒体候选与选择需求.md)
> 状态：proposed

## 1. 设计结论

对象存储保存字节，PostgreSQL 保存 MediaArtifact 完整性、派生血缘、Candidate 和追加式 SelectionDecision。文件 ready、候选可用和人工采用是三个独立判断。

M09 的媒体检查只回答“字节是否按声明完整、可安全存储并能被基础解析/解码”，不回答“对该镜头、审片或交付用途是否达标”。格式、长度、哈希、MIME/魔数、安全扫描和基础解码属于 M09 传输/存储完整性；目标时长偏差、黑帧、静音、镜头符合性、连续性和用途阻塞属于 M10。Candidate `ready` 因此可以与 M10 `unassessed/blocked` 并存。本模块不执行生成、不关闭质量问题、不批准审片或交付，也不拆为微服务。

## 2. 数据模型

| 对象 | 关键约束 |
| --- | --- |
| MediaArtifact | workspace、object key、hash、media type、status、retention |
| MediaMetadata | probe version、codec、duration/timebase、dimensions、tracks |
| DerivationEdge | source→derived、operation/params hash；禁止环 |
| Candidate | target type/id/revision、job/attempt、artifact、ordinal；不可改目标 |
| CandidateSet | 冻结比较集或查询投影，不是主选 |
| SelectionDecision | target revision、purpose、assembly context、candidate、decision、supersedes |

同 `(target revision, selection purpose, assembly context)` 最多一个 current adopted。storyboard_reference、first_frame、last_frame、video_primary、audio_primary 等 purpose 不互相覆盖。

## 3. 摄取流水线

M08 提交结果引用 → 对象下载到隔离区 → 大小/类型/哈希/恶意内容检查 → ffprobe/解码验证 → 原件 ready → 生成代理/缩略图/抽帧派生物 → 创建 Candidate → Outbox 发布 `CandidateReady`。

上述 ffprobe/解码只作为存储完整性门禁：验证容器可读、轨道/时基可解析且在安全资源限制内可解码样本；不在此判定时长是否符合 ShotPlan、是否黑帧/静音或语义质量。M10 读取 M09 的 Artifact/Metadata 精确版本后产生独立 QualityEvaluation/Issue。

上传媒体走相同验证，但 Candidate 是否创建由具体用途命令决定。代理失败不改变原件 ready；原件缺失不能只靠代理通过正式交付。

## 4. 应用接口

- Commands：`RegisterUpload`、`IngestProviderResult`、`RetryDerivation`、`CreateCandidate`、`RecordSelectionDecision`、`RebindCandidate`、`Quarantine/DeleteArtifact`；
- Queries：候选比较、媒体血缘、当前 purpose 主选、当前上下文可用性、删除影响；
- Events：`MediaArtifactReady/Quarantined`、`CandidateReady`、`SelectionDecisionRecorded`。

选择命令在 expected revision 下检查 Candidate ready、当前 context 可用、M14 权利和用户能力；预览高亮/收藏使用独立轻量对象。

## 5. 删除、复用与恢复

已被 Selection、ReviewPackage、Assembly 或 Snapshot 引用的 Artifact 禁止普通删除；保留/法定保全由 M14 决定。上游变化只返回 `usable_for_context=false + reasons`；显式 Rebind 重新做规格、质量和权利预检并创建新决定。

存储故障保持 Candidate 历史状态并把 Artifact 标 missing/verification pending，不把生成 Job 改成失败。重复回调按 `(job, output ordinal/hash)` 回读同一 Candidate。

## 6. 性能、安全与验证

列表按需加载代理，原件签名短时授权；内容哈希去重不跨租户权利边界。验证损坏媒体、重复摄取、并发选择、不同 purpose、删除引用、代理恢复和显式复用。

映射 MED-FR-001—012、MED-NFR-001—005、AC-MED-001—009；A 用 Fixture 候选验证选择，C 接真实媒体。

## 7. 模块边界与跨模块契约

| 模块 | M09 接收 | M09 输出 | 边界规则 |
| --- | --- | --- | --- |
| M01/M02 | actor、workspace/project 权限 | 受限查询/签名访问和审计主体 | 对象键不暴露租户/业务命名；跨租户 hash 不授予可见性 |
| M07 | 计划 InputRef/参考精确版本 | `GetArtifactAvailability`、Selection ref | M09 不判断计划批准或路由；仅返存储/上下文可用性 |
| M08 | Job/Attempt/output ordinal、受限 provider locator、expected declaration | ingest operation、Artifact/Candidate ref、完整性观测 | M09 执行字节传输/隔离/验证；下载失败不改 Provider Job 为生成失败 |
| M10 | 上下文质量状态和问题摘要读模型 | Artifact/Metadata/Candidate 精确版本、`candidate.ready.v1` | M09 只展示 M10 摘要，不保存或推断质量分/问题终态 |
| M12/M13 | ReviewPackage/Assembly/Snapshot 引用 | 媒体可读性、Selection 和删除影响 | 活动引用阻止普通删除；不自动改选代理或最近 Candidate |
| M14 | rights/retention/legal hold 结论 | Artifact 保留/隔离/删除证据 | 保留或法定保全优先；隔离解除需权限与审计 |

`MediaArtifact` 是字节和完整性事实；`Candidate` 是指向历史目标版本的可比较输出；`SelectionDecision` 是追加式人工决定。三者分别建表和版本约束，不在 Artifact 上增加 `selected`，不在 Candidate 上增加 current 主选字段。

## 9. 状态、并发与幂等

### 9.1 状态

| 对象 | 状态 | 关键守卫 |
| --- | --- | --- |
| MediaArtifact | `pending→verifying`；验证后进入 `ready`、`quarantined` 或 `missing`；恢复后可重回 verifying；允许删除的非终态可进 `deletion_pending→deleted` | ready 需声明大小/hash/type/security/基础解析通过；missing 恢复后重验证；legal hold 禁止删除；删除失败停在 deletion_pending |
| Candidate | `ingesting` 后进入 `ready`、`quarantined` 或 `failed`；任一非归档态可在满足引用守卫后进 `archived` | ready 只表示历史输出已完整摄取；不因上游新版转 stale；M10 状态独立；隔离解除需 Artifact 新证据 |
| SelectionDecision | 每条追加决定的值为 `adopted`、`alternate`、`rejected` 或 `cleared`，后续决定以 `supersedes` 关联 | 决定不原地修改；current 由未被 supersede 的决定投影；个人高亮/shortlist 不在此状态机 |

### 9.2 幂等与并发

- Upload 唯一：`workspace + Idempotency-Key`；相同键不同 declaration hash 返回 `idempotency_conflict`。
- Provider ingest 唯一：`generation_job_id + output_ordinal`，再校验 provider output/content hash；同 ordinal 不同结果进隔离/对账。
- Artifact 可在同 Workspace/同 purpose/同权利范围按 content hash 复用，不因 hash 相同跨租户建可见引用。
- 派生唯一：`source_artifact + operation_version + params_hash`；候选唯一：`job + output_ordinal`。
- 选择使用 `selection_context revision`乐观锁和部分唯一约束：`target revision + selection purpose + assembly context` 最多一个 current adopted。
- 对象存储调用不在领域事务内；摄取分 prepare→事务外 transfer/verify→finalize，中断由 Operation 与幂等 Worker 恢复。

## 10. 页面与可观察状态

| 页面 | 必须展示 | 动作/禁用原因 |
| --- | --- | --- |
| 媒体库/上传队列 | Artifact 类型、完整性状态、大小/hash 摘要、来源、代理状态、保留/隔离 | 上传、重试验证/派生、预览、查血缘、删除预览 |
| 候选比较 | target/plan/Attempt/model 血缘、同步播放/代理、TechnicalMetadata、M10 质量摘要与 `unassessed`、usable reasons | 高亮、shortlist、adopt/alternate/reject；不 ready/权利或上下文不符时显示原因 |
| 选择历史 | context/purpose、当前 adopted、所有决定、理由、actor/time/supersedes | 替代、清除、显式 Rebind；不提供“自动选最高分” |
| Artifact 详情/血缘 | 原件、proxy/thumbnail/frame 派生图、probe/tool 版本、所有选择/审阅/装配/交付引用 | 受限下载、重做派生、删除影响；只有原件正式可用时才允许交付依赖 |

指标包括摄取耗时/恢复率、哈希/长度/MIME/解析失败分布、隔离率、代理失败率、每目标候选数、选择周转/并发冲突、复用率、usable=false reason 和 deletion_pending 停留。不把 M10 质量通过率计入 M09 ready 指标。

### 12.1 功能需求

| MED-FR-004 | Candidate frozen provenance | 任一 Candidate 可回读 target revision/plan item/Attempt/input/model refs |
| MED-FR-005 | Candidate compare federated view | 并排播放、元数据、血缘和 M10 `unassessed/pass/block` 摘要均可见 |

## 13. 验证与交付顺序

切片 A 用上传与 Fixture 候选完成 Artifact integrity→Candidate→Selection 闭环；切片 C 接 M08 真实输出并验证中断传输、重复摄取、损坏隔离、代理恢复、并发选择、删除引用与显式 Rebind。M09 验收只证明传输/存储完整性和候选/选择契约；黑帧、静音、语义符合性和连续性必须在 M10 单独验收，不用 Artifact ready 代替。
