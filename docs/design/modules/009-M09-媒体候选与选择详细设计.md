# M09 媒体、候选与选择详细设计

> Design ID：DES-M09
> Requirement：[REQ-MED](../../requirement/009-M09-媒体候选与选择需求.md)
> 状态：proposed

## 1. 设计结论

对象存储保存字节，PostgreSQL 保存 MediaArtifact 完整性、派生血缘、Candidate 和追加式 SelectionDecision。文件 ready、候选可用和人工采用是三个独立判断。

## 2. 数据模型

| 对象 | 关键约束 |
| --- | --- |
| MediaArtifact | workspace、object key、hash、media type、status、retention |
| MediaMetadata | probe version、codec、duration/timebase、dimensions、tracks |
| DerivationEdge | source→derived、operation/params hash；禁止环 |
| Candidate | target type/id/revision、job/attempt、artifact、ordinal；不可改目标 |
| CandidateSet | 冻结比较集或查询投影，不是主选 |
| SelectionDecision | target revision、purpose、assembly context、candidate、decision、supersedes |

同 `(target revision, selection purpose, assembly context)` 最多一个 current adopted。storyboard_reference、first_frame、last_frame、video_primary、audio_primary 等 purpose 不互相覆盖。

## 3. 摄取流水线

M08 提交结果引用 → 对象下载到隔离区 → 大小/类型/哈希/恶意内容检查 → ffprobe/解码验证 → 原件 ready → 生成代理/缩略图/抽帧派生物 → 创建 Candidate → Outbox 发布 `CandidateReady`。

上传媒体走相同验证，但 Candidate 是否创建由具体用途命令决定。代理失败不改变原件 ready；原件缺失不能只靠代理通过正式交付。

## 4. 应用接口

- Commands：`RegisterUpload`、`IngestProviderResult`、`RetryDerivation`、`CreateCandidate`、`RecordSelectionDecision`、`RebindCandidate`、`Quarantine/DeleteArtifact`；
- Queries：候选比较、媒体血缘、当前 purpose 主选、当前上下文可用性、删除影响；
- Events：`MediaArtifactReady/Quarantined`、`CandidateReady`、`SelectionDecisionRecorded`。

选择命令在 expected revision 下检查 Candidate ready、当前 context 可用、M14 权利和用户能力；预览高亮/收藏使用独立轻量对象。

## 5. 删除、复用与恢复

已被 Selection、ReviewPackage、Assembly 或 Snapshot 引用的 Artifact 禁止普通删除；保留/法定保全由 M14 决定。上游变化只返回 `usable_for_context=false + reasons`；显式 Rebind 重新做规格、质量和权利预检并创建新决定。

存储故障保持 Candidate 历史状态并把 Artifact 标 missing/verification pending，不把生成 Job 改成失败。重复回调按 `(job, output ordinal/hash)` 回读同一 Candidate。

## 6. 性能、安全与验证

列表按需加载代理，原件签名短时授权；内容哈希去重不跨租户权利边界。验证损坏媒体、重复摄取、并发选择、不同 purpose、删除引用、代理恢复和显式复用。

映射 MED-FR-001—012、MED-NFR-001—005、AC-MED-001—009；A 用 Fixture 候选验证选择，C 接真实媒体。
