# M11 资源配额与用量治理详细设计

> Design ID：DES-M11
> Requirement：[REQ-USG](../../requirement/011-M11-资源配额与用量治理需求.md)
> 状态：proposed

## 1. 设计结论与范围

M11 使用带明确 `quantity + unit` 的追加式资源账本，为 `GenerationPlan`、媒体执行和 `AgentRun` 提供估计、预留、实际、释放、调整与对账。它是**生产资源治理**，不是商业计费：不拥有客户价格、套餐、余额、欠款、支付、发票或收入事实；Provider 返回的货币值只能作为带来源和费率版本的运维对账旁证，不能驱动客户收费或付款状态。

本模块作为单体应用中的逻辑模块实现，不拆为独立计费微服务。M07 决定能力与计划，M08 执行外部任务，M06 执行 Agent，M11 仅回答“是否可占用、已经消耗多少、消耗归因到哪里”。M11 的额度正确性只依赖 PostgreSQL 事务、行锁/CAS、唯一约束与追加账本；Redis GCRA 只控制调用速率，Redis 分布式锁不得用于预留、防超卖或账本守恒。

### 1.1 范围内

- Workspace、项目、能力维度的资源政策与有效期；
- 带版本和假设的资源估计区间；
- 多单位原子预留、释放、实际入账、补偿调整和异常对账；
- 失败、取消、`unknown`、重试及 AgentRun 的独立归因；
- 软阈值提醒、硬上限门禁、具名资源例外和用量查询；
- 每交付分钟资源消耗、失败/未知消耗率等生产效率指标。

### 1.2 非目标

- 模型路由、Provider Job 执行、重试策略或外部任务取消；
- 面向客户的价格换算、套餐权益、余额扣减、账单、支付、发票与收入确认；
- 把不同单位在没有版本化换算规则时折算成一个“总用量”；
- 通过释放预留假装取消 Provider 已经接收的任务。
- 用 Redis 限流计数代替期间额度、Reservation、UsageEntry 或归因。
- 用 Redis 分布式锁代替 PostgreSQL 的原子预留和唯一约束。

## 2. 事实所有权与数据模型

| 对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| `UsagePolicyRevision` | workspace、可选 project/capability scope、period、unit、soft/hard limit、effective range、inheritance | 发布后不可改写；同 scope/unit/期间不能有歧义重叠 |
| `UsageEstimate` | subject ref、line items、lower/expected/upper/max、assumptions、estimator version、status | 区间和单位必须完整；不可用时明确 `unavailable`，不得伪造精确值 |
| `UsageReservation` | subject/plan、policy revision、quantity/unit、status、idempotency key、expiry | 同一 subject + purpose + unit 至多一个活动预留 |
| `UsageEntry` | AgentRun 或 Job/Attempt、kind、quantity/unit、source ref、provisional、occurred_at | 只追加；实际消耗即使没有产物也必须记录 |
| `UsageAdjustment` | original entry refs、delta、unit、reason、actor、evidence | 不覆盖原条目；单位必须与被调条目一致 |
| `UsageException` | policy/scope/unit、extra max、reason、approver、effective range、status | 缺权限、理由、范围或期限不得生效；到期自动失效 |
| `UsageReconciliationCase` | expected/provider/local refs、difference、state、resolution | 同时保留各方证据；解决通过追加条目完成 |
| `UsageProjection` | scope/unit/period、reserved/actual/released/adjusted、checkpoint | 仅为可重建读模型，不能成为执行事实来源 |

首期标准单位为 `token`、`image_generation`、`video_second`、`audio_character`、`gpu_second`、`storage_byte_day`。增加单位只需扩展受控字典和 Provider 计量映射，不改变账本语义。货币型 Provider 对账值存入独立 `provider_reconciliation_amount` 结构，必须包含 `currency`、`source`、`rate_version`，且任何客户商业字段不得引用它。

## 4. 模块边界与跨模块契约

### 4.1 M11 拥有与不拥有的事实

M11 拥有资源政策、估计、预留、用量条目、调整、资源例外和对账。M11 不拥有 `GenerationPlan`、`AgentRun`、`Operation/Job/Attempt`、`CapabilityRevision`、`DeliverySnapshot` 或任何 Provider 凭据；只保存它们的稳定 ID、版本和必要摘要。

### 4.2 同步端口与事件契约

| 调用方/提供方 | 端口或事件 | 方向 | 契约与失败语义 |
| --- | --- | --- | --- |
| M07 | `EstimateUsage`、`ReserveUsage`、`CheckUsageGate` | M07 → M11 | 计划批准/启动前传冻结 Plan hash 和 capability revision；`block` 时不得提交 M08 |
| M08 | `AttemptUsageObserved`、`AttemptStateChanged` | M08 → M11 | 事件含 workspace、plan/job/attempt、状态、稳定 meter record ID；至少一次投递，M11 幂等消费 |
| M06 | `AgentUsageObserved`、`AgentRunCompleted` | M06 → M11 | 模型、Token、Tool、本地计算分行；AgentRun 与媒体 Job 分别归因 |
| M13 | `DeliverySnapshotCreated`；交付用量查询 | M13 ↔ M11 | M13 提供 Snapshot、Build、精确 duration ticks；M11 返回分单位效率指标 |
| M01 | actor、Workspace/项目权限 | M01 → M11 | 查看、改政策、批例外、人工调整分别授权；M11 不复制成员状态 |
| M11 | `UsageReserved`、`UsageGateBlocked`、`HardLimitReached`、`UsageRecorded`、`UsageAdjusted` | M11 → 消费方 | 事件只含引用、单位、数量、政策版本与 trace，不含客户收费语义 |

跨模块只调用公开应用端口，不跨表写入。单体内“计划启动 + 预留”使用同一数据库事务：M07 写入批准/启动事实前调用 M11 锁定并建立 Reservation；事务提交后由 Outbox 发布事件。M08/M06 的实际用量通过 Inbox 去重后追加，报表投影异步更新。

Redis `DistributedRateLimiterPort` 与 M11 `CheckUsageGate` 必须串联且语义独立：前者回答“当前时刻是否允许以该速率发起”，后者回答“当前期间是否仍有权占用这些资源”。调用模型或 Provider 前必须先通过两者；任一阻止都不调用外部服务。限流拒绝只安排 `retry_wait`，不会创建 Reservation/UsageEntry；已经收单的外部调用仍按实际证据入账。Redis 不可用不影响账本读取、结算和对账，但高成本新调用按 000 的 failure matrix fail closed。

## 5. 关键状态、并发与幂等

### 5.1 状态机

| 对象 | 状态与合法转换 | 终态/约束 |
| --- | --- | --- |
| UsageEstimate | `calculating → available \| unavailable`；Plan 变化后旧估计 `superseded` | `available` 发布后冻结；不得原地改区间 |
| UsageReservation | `active → held \| partially_settled \| settled \| released`；`held → partially_settled \| settled \| released` | unknown 进入 `held`；释放和结算都保留追加明细 |
| UsageException | `approved → expired \| revoked` | 到期按当前时间自动失效；不能恢复，需新批准 |
| ReconciliationCase | `open → investigating → resolved`；任一非终态可 `cancelled` | resolved 只表示已有追加结论，不删除证据 |

### 5.2 并发守恒

1. PostgreSQL 预留行锁粒度为 `(workspace_id, effective_scope_id, policy_revision_id, period_key, unit)`，多单位按稳定 unit 排序加锁，避免死锁；不得替换为 Redis 锁。
2. 可用量从同期间 `actual + active/held reservation - release + adjustment` 计算；缓存投影只加速读取。
3. 数据库唯一键约束 `(workspace_id, subject_type, subject_id, purpose, unit, active_marker)`，保证重复启动不产生第二个活动预留。
4. 硬上限判断和 Reservation 插入在同一事务内；任一单位失败则整组回滚。
5. 政策在锁等待中变化时，比较 `expected policy revision`，冲突返回新政策，不用旧上限继续。

### 5.3 幂等键

| 写入 | 幂等键 | 重复结果 |
| --- | --- | --- |
| ReserveUsage | workspace + subject + purpose + request key | 回读原 Reservation；输入 hash 不同返回冲突 |
| RecordAttemptUsage | provider connection + meter record ID，或 attempt + local meter version | 回读原 Entry |
| RecordAgentRunUsage | AgentRun + call/tool event ID + unit | 回读原 Entry |
| ReleaseUsageReservation | reservation + terminal cause + request key | 回读原 release entry |
| ReconcileUsageCase | case + resolution revision + request key | 回读原 adjustment/confirmation |

## 6. 页面与可观察状态

| 页面/视图 | 主要动作 | 必须展示的状态 |
| --- | --- | --- |
| 项目资源概览 | 查看政策、预留、实际、剩余量和趋势 | `loading`、`empty`、`ready`、投影 `stale`、重建中、无权限；每个数值都显示 unit 和数据截止时间 |
| 计划批准侧栏 | 查看估计并批准/缩小计划/申请例外 | 估计 `calculating/available/unavailable/superseded`、soft warning、hard blocked、并发冲突、例外到期 |
| 用量明细与归因 | 按项目/镜头/计划/能力/Attempt/错误/时间筛选 | actual、reserved、held、released、provisional、adjusted；Agent/媒体分栏；不显示跨单位“总计” |
| 资源政策 | 发布新政策版本、查看继承关系 | draft 表单、版本冲突、已生效、未来生效、已替代；商业价格字段不出现 |
| 对账工作台 | 查看缺失/迟到/矛盾计量并追加结论 | open、investigating、provider pending、resolved、证据不可用、写入冲突 |
| 资源例外 | 申请、批准、撤销 | pending、approved、expired、revoked、字段/权限不完整 |

可观察指标至少包含：估计误差分布、估计缺失覆盖率、预留利用率、并发冲突数、硬上限阻止数、failed/unknown 消耗率、Provider 计量迟到、对账差异/调整率、投影延迟和每交付分钟分单位资源。日志只记录 ID、unit、quantity、政策/估计版本和 trace，不记录 Prompt、媒体或客户商业信息。

## 7. 失败路径与恢复约定

| 场景 | 用户结果 | 系统恢复 |
| --- | --- | --- |
| 估计器不可用 | 显示“无法估计”，不显示 0 或单点精确值 | 按政策阻止或要求具名保守上限；支持相同输入重算 |
| 并发预留冲突 | 一个成功，其余看到最新剩余量和阻塞单位 | 回滚整组预留；刷新后缩小计划、等待释放或申请例外 |
| Provider 用量迟到 | 相关条目标为 provisional，剩余量保守显示 | 保持预留/held；迟到事件幂等追加确认或差异 |
| unknown 长期未决 | 显示冻结资源和风险，不假设为 0 | M08 对账完成或具名人工调整后追加结论 |
| 计量矛盾 | 同屏显示 Provider、本地和预计证据 | 建 Case；调查后追加 Adjustment，不改原记录 |
| 投影损坏/滞后 | 查询显示 checkpoint/stale | 从账本影子重建并核对，执行门禁直接读权威事实 |
| 硬上限命中 | 停止新的 M07/M08/M06 外部动作 | 不取消已收单任务；等待释放、发布新政策或批准精确例外 |
| Redis 限流不可用 | 新模型/Provider 等高成本动作暂不发起；账本与既有用量页面仍可用 | 后台任务写 retry_wait；恢复后重新同时执行 RateLimit 与 UsageGate，不回填 Redis 计数为账本 |

额外架构故障 Gate 不新增 Requirement ID：清空或中断 Redis 后，并发 Reservation 仍由 PostgreSQL 保证不超卖，高成本新调用 fail closed；该证据与 USG-NFR-001、USG-NFR-004 一并归档。

## 9. 实施顺序与门禁

1. **切片 A**：建立 unit 字典、UsagePolicyRevision、Estimate、原子 Reservation、release、hard/soft gate 和项目页面；用 fixture/fake Job 验证守恒。
2. **切片 B**：接入 M06 AgentRun 模型/Token/Tool/本地计算用量，保持与媒体主体隔离。
