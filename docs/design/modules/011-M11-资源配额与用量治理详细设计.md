# M11 资源配额与用量治理详细设计

> Design ID：DES-M11
> Requirement：[REQ-USG](../../requirement/011-M11-资源配额与用量治理需求.md)
> 状态：proposed

## 1. 设计结论

M11 使用带明确 unit 的追加式资源账本，为 GenerationPlan 和 AgentRun 提供估计、预留、实际、释放和调整。它与商业定价完全隔离；即使记录 Provider 货币对账值，也不能形成客户账单。

## 2. 对象和单位

| 对象 | 关键约束 |
| --- | --- |
| UsageEnvelope | workspace/project/capability scope、soft/hard limit、period、inheritance |
| UsageEstimate | subject、line items、lower/expected/upper/max、assumptions、version |
| UsageReservation | subject/plan、quantity/unit、status、idempotency key |
| UsageEntry | AgentRun 或 Job/Attempt、kind、quantity/unit、source、provisional |
| UsageAdjustment | original entries、delta、reason、actor；只追加 |
| UsageReconciliationCase | expected/provider/local、difference、resolution |

单位如 token、image_generation、video_second、audio_character、gpu_second、storage_byte_day。不同 unit 无版本化换算时不可相加。

## 3. 并发预留与守恒

批准计划在同一数据库事务锁定适用 Envelope，并以原子条件更新创建 Reservation；重复启动复用活动预留。可用量按有效期间、已结算、活动预留、释放和调整计算，不能只依赖缓存计数。

AgentRun 可在运行前按 token/tool/call 上限建立轻量 Reservation，结束后单独结算；媒体 Job 不与 Agent 用量混为一个条目。

## 4. 应用接口

- Commands：`EstimateUsage`、`ReserveUsage`、`RecordActualUsage`、`ReleaseReservation`、`ApproveUsageException`、`Open/ReconcileUsageCase`；
- Queries：项目/镜头/计划/Attempt/AgentRun 用量、剩余额度、估计误差、失败/unknown 消耗；
- Events：`UsageReserved`、`HardLimitReached`、`UsageRecorded`、`UsageAdjusted`。

## 5. unknown、迟到和调整

unknown 保持预留或按签认保守策略冻结；Provider 用量迟到先记录 provisional，再追加实际/差异，不覆盖估计。硬上限停止新外部提交，但不假装能取消已收单任务。资源例外必须有 scope、max、reason、actor 和 expiry。

## 6. 失败与恢复

估计不可用返回 range unavailable + conservative cap；并发冲突回读剩余额度；计量矛盾保留两方证据；用量消费者重复按 provider record/idempotency key 去重；投影报表可从账本重建。

## 7. 验证

属性测试验证预留守恒、不同单位不混算、重复启动、迟到/负向调整和并发不超卖；集成测试覆盖 Plan 批准事务。映射 USG-FR-001—012、USG-NFR-001—005、AC-USG-001—008；A 建项目硬上限/假用量，C 完成真实结算。
