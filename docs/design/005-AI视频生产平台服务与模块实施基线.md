## 1. 实施结论

Lanverse 目标实现固定为：

- `frontend/`：TypeScript/Next.js，承载 MVVC 的 View/ViewModel；`src/lib/request.ts` 是唯一 Axios 请求适配器。
- `backend/`：Go 模块化单体，承载 M01—M15 的 Controller、Service、POJO 风格 Model、数据与全部非 Agent 后台业务。
- `agent/`：使用 FastAPI/Uvicorn、但不提供公共 API/Ingress 的 Python/LangGraph 内网计算微服务，承载 Harness、Skill、模型和 backend run-scoped 只读 Tool，只向 backend 返回当前 Agent Contract，不连接 Kafka/Redis/Elasticsearch。
- 运行边界：五个 Go 常驻角色 + 一个 Python Agent 角色；不是按模块拆出的微服务。
- 数据边界：PostgreSQL 唯一业务事实、MinIO 唯一对象存储、单一 Kafka 集群是唯一消息总线、Redis 是唯一分布式协调运行态；Elasticsearch 是项目内与未来 ToC 大规模业务检索的可重建数据面，OpenTelemetry 是独立观测数据面。首期可共用一次 Elastic 部署但严格逻辑隔离，ToC 生产前拆为独立故障域；两者均不成为业务事实。
- 调用边界：公共入口只有 Go backend；Kafka 全部集成在 backend。Go operation-worker 消费 Agent Task 后，通过 `AgentExecutorPort` 的私有 HTTP adapter 启动/查询/取消 Python AgentRun；frontend 与外部调用方不能直连 Agent。
- 契约边界：`backend/api/openapi.json`、`backend/contracts/agent/`、`backend/schema/current.sql` 和 canonical MinIO key 各自唯一；Swagger UI、Go strict server 和前端 API 均消费同一提交的本地 OpenAPI。

Python 只实现 backend 可调用的私有 Run API，不实现公共/业务 API、业务规则、业务事务、Provider 执行或媒体业务；Go 不实现 Agent 推理图。AgentRun/Proposal/Decision 的业务事实属于 Go M06，LangGraph checkpoint 和节点状态属于 Python Runtime。手工与 Agent 提案接受必须汇合到同一个 Go Service。

## 2. 统一术语

| 概念 | 权威位置 | 固定含义 |
| --- | --- | --- |
| 产品能力 | Requirement、PRD | 用户需要完成的 A—F 纵向闭环 |
| 逻辑模块 | `backend/src` | M01—M15 的业务事实与写入所有权 |
| 运行角色 | `backend/cmd/main.go`、`agent/src/main.py` | 六类故障、安全与扩缩边界；Go 通过 `LANVERSE_ROLE` 选择角色 |
| MVVC | frontend View/ViewModel + Go Controller/Model | ViewModel 不复制业务规则；Controller 不实现业务事务 |
| POJO 风格 | Go Model plain struct | 无框架依赖、显式值类型、单一职责、直接可测试 |
| Service | Go `backend/src/<module>/service.go` | 一个用例的鉴权、幂等、版本、事务、Model 与 Outbox 编排 |
| Agent Harness/Skill | Python `agent/` | 单次 AgentRun 的恢复、模型、Tool 和结构化输出 |
| M06 Agent 业务 | Go `backend/src/agents` | AgentRun、Proposal、Item、Decision 和 Canvas 业务事实 |

固定规则：

1. 同一事实只有一个 Go 模块写入 owner。
2. 模块不等于服务，运行角色不取得模块事实所有权。
3. Controller、Worker 和 Agent 结果都必须调用所属模块 Service。
4. Agent、Kafka offset/lag、Redis lock/rate key、MinIO 路径和 checkpoint 都不表示业务完成。
5. 不创建 migration、兼容层、空目录、万能 Manager/Repository、全局业务 `utils` 或重复 DTO。

### 2.1 唯一物理目录规范

实现只允许使用以下物理结构；这是当前项目的最终结构，不为历史实现、未来模块或兼容性预留目录：

```text
backend/
├── cmd/main.go                         # 唯一 Go 启动入口；LANVERSE_ROLE 选择角色
└── src/
    ├── <module>/                        # 一个业务模块一个 Go package
    │   ├── model.go                     # plain struct、值对象和业务不变量
    │   ├── service.go                   # 用例 Service
    │   ├── repository.go                # PostgreSQL/外部存储映射
    │   ├── controller.go                # HTTP Controller
    │   └── ports.go                     # 仅真实用例需要的 Port
    └── platform/<capability>/           # 共享基础设施能力
agent/
└── src/main.py                         # 唯一 FastAPI/Uvicorn 私有 Agent 入口
```

业务模块内的职责文件必须属于同一个 Go package，直接位于 `backend/src/<module>`；不得再创建 `domain`、`application`、`adapters`、`transport`、`internal` 或按运行角色拆出的第二层目录。只创建真实用例需要的职责文件，不创建空模板、全局 `utils`、共享 DTO 或纯转发层。`agent/src/main.py` 同时导出 FastAPI `app` 和 Uvicorn 启动入口，提供仅 backend 调用的 `/internal/agent-runs` start/get/cancel 契约以及 `/readyz`，不提供公共 API。

文件名是统一职责入口，类型、接口、构造函数和方法必须体现模块语义。`backend/src/scripts/service.go` 使用 `ScriptAnalysisService`，`repository.go` 使用 `ScriptRepository`，`controller.go` 使用 `ScriptController`，`ports.go` 按真实用例使用 `ScriptAnalysisPort` 等最小端口；`backend/src/agents` 使用 `AgentService`/`AgentRepository`/`AgentController`/`AgentRunStore`。禁止在模块间复用无语义的 `Service`、`Repository`、`Controller`、`Store` 或 `Manager` 名称，也禁止创建全局同名实现。

### 4.1 Agent 交接边界

1. Go M03/M06 Service 创建 AnalysisRun、AgentRun、Operation 和 Outbox。
2. Go operation-worker 从唯一 Kafka 集群的 `lanverse.tasks.operation` 接管 Agent invoke Task，提交 Inbox/offset 后通过 backend `AgentExecutorPort` 冻结最小 `AgentRunInputSnapshot` 并调用私有 `POST /internal/agent-runs`。
3. Python agent-service 校验 schema/hash，以同一 run/key/hash 幂等接受，运行 Skill，只使用批准模型、只读 Tool 和 scoped object capability。
4. Go 通过私有 `GET /internal/agent-runs/{run_id}` 查询进度/结果；Python 不连接 Kafka/Redis/Elasticsearch、不调用业务数据库，也不提供公共业务接口。
5. Go operation-worker 校验 contract/input/result hash，经 M06 Service 保存 Proposal；accepted/running 的后续查询由 PostgreSQL `available_at` 和同一 operation Task 调度。
6. 用户接受 ProposalItem 时，Go Controller 调用目标 M03/M04/M05/M07/M10 Service；目标模块重新鉴权、CAS 和写事实。

## 5. 六项基础设施

| ID | 能力 | 权威用途 | 禁止 |
| --- | --- | --- | --- |
| INF-01 | PostgreSQL + RLS | 业务事实、Operation/Job/Attempt、Outbox/Inbox、审计 | 大媒体、LangGraph checkpoint、migration 历史链 |
| INF-02 | 私有 MinIO | 来源、媒体、Agent 大载荷、交付对象 | AWS S3 adapter、多存储工厂、对象 key 代替业务 ID |
| INF-03 | 单一 Apache Kafka 集群 | 只由 Go backend 接入；全部后台 Task 共用；至少一次投递、partition 顺序、consumer group、重放、背压和 dead-letter | Python Kafka client、第二消息队列、权威业务状态、延迟调度和审计 |
| INF-04 | Secret/KMS | Provider、Webhook、服务身份凭据引用 | 明文业务库凭据 |
| INF-05 | Elasticsearch 业务搜索 + Kibana 运维 + OpenTelemetry Collector | 可重建的私有 approved 内容索引与未来公共 published 内容索引；Kibana 只做搜索运维；OTel 采集 Log/Metric/Trace | 替代 Outbox、PostgreSQL AuditEvent 或业务 Query；日志写业务正文；frontend/Agent 直连；首期 Logstash/Debezium/Kafka Connect；ToC 生产让观测负载与业务搜索共用故障域 |
| INF-06 | Redis + `go-redis/v9` | 会话、一次性验证、`redislock` 短租约锁、`redis_rate` GCRA 限流、短缓存、SSE fan-out | 项目、任务、批准、额度、交付等权威事实；代替 PostgreSQL 不变量 |

Agent checkpoint 使用独立存储与独立凭据，不属于业务 INF-01 Schema。业务恢复只以 PostgreSQL 事实与 MinIO 精确版本为准。

INF-05 首期只部署一套 Elasticsearch/Kibana，业务 index 与观测 data stream 必须使用不同名称、API key、角色、生命周期和 Kibana Space。Go `operation-worker` 以 `lanverse-search-projection` consumer group 消费现有 `lanverse.domain.events` 并通过官方 `go-elasticsearch/v9` adapter 重建搜索索引，不新增 Topic、Broker、Connector 或运行角色。禁止按用户或工作区建索引；私有 approved 内容与未来公共 published 内容使用独立共享索引族并强制 visibility/publication/right basis。Log/Metric/Trace 由 OTel Collector 直接采集，不经过 Kafka；Logstash 只在未来确有无法结构化的遗留日志来源时重新评审，当前不部署。ToC 生产 Gate 前业务搜索必须迁入独立 Elasticsearch 集群/项目，观测数据迁入独立后端；应用只切换 Search/OTLP endpoint，不做业务双写或兼容层。

## 9. 平台执行契约

| 契约 | 必须明确 | 失败结果 |
| --- | --- | --- |
| `CommandEnvelope` | command/version、workspace/project、principal、idempotency、expected revision、trace | 冲突或重复回读，不产生第二副作用 |
| `Operation` | scope、状态、进度、证据、错误、恢复动作 | 刷新或重启后可继续/接管 |
| `Job/Attempt` | 逻辑任务与追加式尝试分离、外部 ID、certainty | unknown 进入对账，不盲重试 |
| `TaskEnvelope` | 当前 schema/hash、operation/job/attempt、ref、deadline、trace | 非当前契约 dead-letter |
| `AgentRunRequest/Result` | run/stage/generation、snapshot、allowlist、预算、sequence、proposal、hash | Go 拒绝保存 Proposal，业务事实不变 |
| `AgentServiceCall` | private start/get/cancel、mTLS service identity、run/request key/hash、deadline、result ref/hash | 超时按同 run/key/hash 对账；不创建第二 Run、不占 Kafka partition |
| `StorageObjectRef` | bucket/key/version/size/type/SHA-256/owner | 不完整或不匹配对象隔离 |
| `LockLease` | resource/purpose、owner token、fencing token、TTL、expires-at | 未获得/续租失败则取消受保护工作；旧 fence 写入被拒绝 |
| `RateLimitDecision` | subject/action、rule revision、cost、allowed、remaining、retry-after、reset-at | API 返回 429；后台任务进入数据库 retry_wait，不阻塞 Kafka consumer |
| `NarrativeSearchDocument/Result` | workspace/project、approved revision/node/Anchor、text hash、index schema/checkpoint/as-of/stale | Elasticsearch 不可用时返回 search_unavailable/stale；业务事实不回滚，可从 PostgreSQL/MinIO 重建 |

## 10. 首次实施 Gate

1. **架构 Gate**：`frontend/`、`backend/`、`agent/` 依赖方向和权限与 000 一致。
2. **Go 业务 Gate**：M01—M15 业务写入、事务、API、Provider 和媒体业务只有 Go 实现。
3. **Agent Gate**：Python 只有当前私有 Run 契约、模型、backend run-scoped 只读 Tool 和 checkpoint 权限；无 Kafka/Redis/Elasticsearch client、公共 API/Ingress、业务 DB/MinIO 通用凭据。
4. **Schema Gate**：`current.sql` 可初始化空库；非空库 fingerprint 不一致时全部 Go 角色拒绝 ready；没有 migration/兼容链。
5. **MVVC Gate**：View→ViewModel→`@umijs/openapi` 生成函数→`frontend/src/lib/request.ts`→Go Controller→Go Service 可追踪；ViewModel 不拼 URL/DTO、不直用 Axios、不登记 RTK Query endpoint；公共路径只用 `/api`。
6. **契约 Gate**：`backend/api/openapi.json` 是本地唯一 HTTP 契约，Swagger UI、Go strict server 与 frontend API 的 hash/生成 diff 一致；OpenAPI 与 Agent JSON Schema 分别单一生成，Go/Python golden 与 hash 负向测试通过。
7. **进程 Gate**：五个 Go 角色与一个 Python 角色独立健康、身份、网络和故障恢复；Kafka 配置只进入需要 publish/consume 的 Go 二进制，部署清单中只有一个 Kafka 集群。
8. **短事务 Gate**：MinIO、Kafka、Redis、模型、Provider、解析和 FFmpeg 均在事务外。
9. **剧本 Gate**：Manifest、Narrative 两次批准和人物/资产确定性投影完整；关闭 Agent 后手工路径通过。
10. **MinIO Gate**：私有、versioning、canonical key、exact version/hash、scoped capability、恢复与删除测试通过。
11. **调研 Gate**：新增框架/服务/目录前记录官方资料、活跃实现、采用/拒绝范围、owner 和验收。
12. **Kafka Gate**：Topic/key/group、幂等 producer、手工 offset、Inbox 接管、数据库调度重试、DLQ、ACL 和 lag/rebalance 故障测试通过；部署清单只有一个 Kafka 集群且没有第二消息队列依赖。
13. **协调 Gate**：锁具备 TTL/owner/refresh/fencing，续租失败取消；分布式限流使用 GCRA 和确定 failure policy；数据库不变量、M11 配额不依赖 Redis。
14. **Agent 隔离 Gate**：公共 OpenAPI、Ingress 和 frontend client 中不存在 Agent 服务地址；私有 start/get/cancel 只接受 operation-worker 身份；Agent 只可访问 checkpoint、受限 Tool/ModelCallGate/载荷端点和模型 allowlist。
15. **Elastic Gate**：业务事实与 Outbox 同事务，Elastic 只保存派生副本；观测与业务索引权限/生命周期隔离；搜索只经 Go 鉴权并强制 workspace/project/visibility/publication/right basis/approved revision filter；禁止每用户/工作区一索引；索引删除后可重建且不影响业务写入；ToC 生产压测证明搜索与观测位于独立故障域。
