## 1. 实施结论

Lanverse 目标实现固定为：

- `frontend/`：TypeScript/Next.js，承载 MVVC 的 View/ViewModel。
- `backend/`：Go 模块化单体，承载 M01—M15 的 Controller、Application Service、POJO 等价 Domain、数据与全部非 Agent 后台业务。
- `agent/`：Python/LangGraph，承载 Harness、Skill、模型和只读 Tool，只返回当前 Agent Contract。
- 运行边界：五个 Go 常驻角色 + 一个 Python Agent 角色；不是按模块拆出的微服务。
- 数据边界：PostgreSQL 唯一业务事实、MinIO 唯一对象存储、RabbitMQ 至少一次投递、Redis 非权威运行态。
- 契约边界：`backend/api/openapi.yaml`、`backend/contracts/agent/`、`backend/schema/current.sql` 和 canonical MinIO key 各自唯一。

Python 不实现 API、领域规则、业务事务、Provider 执行或媒体业务；Go 不实现 Agent 推理图。AgentRun/Proposal/Decision 的业务事实属于 Go M06，LangGraph checkpoint 和节点状态属于 Python Runtime。手工与 Agent 提案接受必须汇合到同一个 Go Service。

## 2. 统一术语

| 概念 | 权威位置 | 固定含义 |
| --- | --- | --- |
| 产品能力 | Requirement、PRD | 用户需要完成的 A—F 纵向闭环 |
| 逻辑模块 | `backend/internal/modules` | M01—M15 的业务事实与写入所有权 |
| 运行角色 | `backend/cmd`、`agent/.../entrypoints` | 六类故障、安全与扩缩边界 |
| MVVC | frontend View/ViewModel + Go Controller/Model | ViewModel 不复制业务规则；Controller 不实现业务事务 |
| POJO 风格 | Go Domain/Application plain struct | 无框架依赖、显式值类型、单一职责、直接可测试 |
| Application Service | Go `application/services` | 一个用例的鉴权、幂等、版本、事务、Domain 与 Outbox 编排 |
| Agent Harness/Skill | Python `agent/` | 单次 AgentRun 的恢复、模型、Tool 和结构化输出 |
| M06 Agent 业务 | Go `modules/agents` | AgentRun、Proposal、Item、Decision 和 Canvas 业务事实 |

固定规则：

1. 同一事实只有一个 Go 模块写入 owner。
2. 模块不等于服务，运行角色不取得模块事实所有权。
3. Controller、Worker 和 Agent 结果都必须调用所属模块 Application Service。
4. Agent、RabbitMQ、Redis、MinIO 路径和 checkpoint 都不表示业务完成。
5. 不创建 migration、兼容层、空目录、万能 Manager/Repository、全局业务 `utils` 或重复 DTO。

## 3. 三工程实施边界

| 工程 | 目标位置 | 必须承担 | 明确禁止 |
| --- | --- | --- | --- |
| 前端 | `frontend/src/app`、`features`、`api` | Route、View、ViewModel、生成 API 客户端、交互状态 | 领域状态机、权限裁决、手写 HTTP DTO、业务完成事实 |
| Go 公共 API | `backend/cmd/api` | `/api`、Webhook、SSE、Controller、Query、短事务 | 模型、解析、Provider 长轮询、FFmpeg |
| Go 业务模块 | `backend/internal/modules/<module>` | Domain、Application Service、Port、Postgres adapter、Controller | LangGraph、跨模块写表、SDK 类型泄漏 |
| Go 平台能力 | `backend/internal/platform` | PostgreSQL、RabbitMQ、MinIO、Redis、Secret、观测 adapter | 业务不变量、模块事实所有权 |
| Python Agent | `agent/src/lanverse_agent` | Harness、Skill、checkpoint、模型、只读 Tool、结果信封 | 业务数据库、通用 MinIO、业务 Service、批准/current |
| 共享契约源 | `backend/api`、`backend/contracts`、`backend/schema` | 唯一当前 OpenAPI、Agent Schema 和最终 DB Schema | URL 版本链、兼容 decoder、旧 Schema 演进历史 |

详细物理树、模块模板和依赖方向只以 [000 §6](./000-AI视频生产平台目标系统架构设计.md#6-固定仓库与文件结构) 为准。

## 4. 六类生产角色

| 服务 ID | runtime | 语言 | 责任 | 主要模块 | 切片 |
| --- | --- | --- | --- | --- | --- |
| SVC-01 | `api` | Go | 鉴权、HTTP/Webhook/SSE、Query、短事务、Operation/Outbox 创建 | M01—M15 transport/application | A |
| SVC-02 | `operation-worker` | Go | Outbox/Inbox、Scheduler、Reconciler、投影、Agent 请求/结果桥接 | M08 骨架；各模块后台结果提交 | A |
| SVC-03 | `import-worker` | Go | DOCX/Markdown/TXT 解析、来源结构和 ParseResult | M03/M09 | A |
| SVC-04 | `provider-worker` | Go | Provider 提交、查询、取消、下载和 unknown 证据 | M07/M08/M09 | C |
| SVC-05 | `agent-worker` | Python | LangGraph Harness/Skill、模型、只读 Tool、AgentResult、AI 评估 | 运行 M06 请求；只读目标模块快照 | B/D |
| SVC-06 | `media-worker` | Go | probe、代理、抽帧、转码、确定性检查、装配和渲染 | M05/M09/M10/M13 | A/E |

启用规则：切片 A 部署 SVC-01/02/03/06，切片 B 增加 SVC-05，切片 C 增加 SVC-04。六者必须独立启动、停止、健康检查、扩缩、授权和失败恢复。`schema-init` 是 Go 一次性 Job，不计为常驻服务。

### 4.1 Agent 交接边界

1. Go M03/M06 Service 创建 AnalysisRun、AgentRun、Operation 和 Outbox。
2. Go operation-worker 冻结最小 `AgentRunInputSnapshot`，发布当前 `AgentRunRequest`。
3. Python agent-worker 校验 schema/hash，运行 Skill，只使用批准模型、只读 Tool 和 scoped object capability。
4. Python 发布 `AgentRunProgress`/`AgentRunResult`，不调用业务数据库。
5. Go operation-worker 校验 contract/input/result hash，经 M06 Service 保存 Proposal。
6. 用户接受 ProposalItem 时，Go Controller 调用目标 M03/M04/M05/M07/M10 Service；目标模块重新鉴权、CAS 和写事实。

## 5. 六项基础设施

| ID | 能力 | 权威用途 | 禁止 |
| --- | --- | --- | --- |
| INF-01 | PostgreSQL + RLS | 业务事实、Operation/Job/Attempt、Outbox/Inbox、审计 | 大媒体、LangGraph checkpoint、migration 历史链 |
| INF-02 | 私有 MinIO | 来源、媒体、Agent 大载荷、交付对象 | AWS S3 adapter、多存储工厂、对象 key 代替业务 ID |
| INF-03 | RabbitMQ | 至少一次投递、背压、死信和消费者隔离 | 权威业务状态和审计 |
| INF-04 | Secret/KMS | Provider、Webhook、服务身份凭据引用 | 明文业务库凭据 |
| INF-05 | OpenTelemetry 后端 | Trace、Metric、结构化日志 | Prompt、正文、签名 URL、凭据和敏感内容 |
| INF-06 | Redis | 会话、一次性验证、限流、短缓存、SSE fan-out | 项目、任务、批准、交付等权威事实 |

Agent checkpoint 使用独立存储与独立凭据，不属于业务 INF-01 Schema。业务恢复只以 PostgreSQL 事实与 MinIO 精确版本为准。

### 6.1 模块内部完成标准

每个已启用模块至少具备：

1. `domain` 中无框架依赖的实体、值、不变量和错误；
2. `application/commands|queries` 中类型化输入输出；
3. `application/services/<use_case>.go` 中明确用例和事务边界；
4. 调用方定义的最小 Port；
5. `adapters/postgres` 中 pgx/sqlc 与 Domain 映射；
6. `transport/http/controllers/<use_case>.go` 中 MVVC Controller；
7. 成功、权限、并发/重复和恢复测试；
8. 架构测试阻止 adapter 泄漏、跨模块写入和循环依赖。

## 7. 七阶段业务闭环

| 阶段 | 主要模块 | 完成事实 | 运行责任 |
| --- | --- | --- | --- |
| 1. 导入与拆集 | M02/M03/M09/M14 | SourceRevision + ParseReport + approved Manifest + stable ContentUnit/Order | Go 导入/业务；Python 可提拆集 Proposal |
| 2. 剧本结构与全局清单 | M03/M04 | approved Narrative + Resolution + Requirement + Inventory/Readiness/Occurrence | Go 写事实和投影；Python 只提 Narrative/Knowledge Proposal |
| 3. 设定资产 | M04/M09/M14 | Profile/State/Reference 与有效范围 | Go 业务和对象管理 |
| 4. 分镜与预演 | M05/M09 | approved ShotPlan/Order + Animatic | Go 业务与 Media Worker |
| 5. 提示与计划 | M07/M11/M14 | approved GenerationPlan + 冻结 Prompt/Route/Preflight | Go 计划和治理 |
| 6. 生成与选择 | M08/M09/M11 | Job/Attempt + ready Candidate + SelectionDecision | Go Provider/Operation/API |
| 7. 质量、审阅与交付 | M10/M12/M13/M14 | Issue Decision + Review Decision + DeliverySnapshot | Python 可提 AI 评估；Go 决议、媒体和交付 |

剧本分析的唯一顺序为：Source → Breakdown Proposal/手工 → Manifest 批准 → M02 物化/mapping → Narrative Proposal/手工 → Narrative 批准 → Knowledge Proposal/手工 → M04 决议 → Go 确定性重建人物集数与资产清单。AgentRun 完成不等于整本分析完成。

## 9. 平台执行契约

| 契约 | 必须明确 | 失败结果 |
| --- | --- | --- |
| `CommandEnvelope` | command/version、workspace/project、principal、idempotency、expected revision、trace | 冲突或重复回读，不产生第二副作用 |
| `Operation` | scope、状态、进度、证据、错误、恢复动作 | 刷新或重启后可继续/接管 |
| `Job/Attempt` | 逻辑任务与追加式尝试分离、外部 ID、certainty | unknown 进入对账，不盲重试 |
| `TaskEnvelope` | 当前 schema/hash、operation/job/attempt、ref、deadline、trace | 非当前契约 dead-letter |
| `AgentRunRequest/Result` | run/stage/generation、snapshot、allowlist、预算、sequence、proposal、hash | Go 拒绝保存 Proposal，业务事实不变 |
| `StorageObjectRef` | bucket/key/version/size/type/SHA-256/owner | 不完整或不匹配对象隔离 |

## 10. 首次实施 Gate

1. **架构 Gate**：`frontend/`、`backend/`、`agent/` 依赖方向和权限与 000 一致。
2. **Go 业务 Gate**：M01—M15 业务写入、事务、API、Provider 和媒体业务只有 Go 实现。
3. **Agent Gate**：Python 只有当前契约、模型、只读 Tool、checkpoint 和消息权限；无业务 DB/MinIO 通用凭据。
4. **Schema Gate**：`current.sql` 可初始化空库；非空库 fingerprint 不一致时全部 Go 角色拒绝 ready；没有 migration/兼容链。
5. **MVVC Gate**：View→ViewModel→生成客户端→Go Controller→Go Service 可追踪；公共路径只用 `/api`。
6. **契约 Gate**：OpenAPI 与 Agent JSON Schema 分别单一生成；Go/Python golden 与 hash 负向测试通过。
7. **进程 Gate**：五个 Go 角色与一个 Python 角色独立健康、身份、网络、队列和故障恢复。
8. **短事务 Gate**：MinIO、RabbitMQ、模型、Provider、解析和 FFmpeg 均在事务外。
9. **剧本 Gate**：Manifest、Narrative 两次批准和人物/资产确定性投影完整；关闭 Agent 后手工路径通过。
10. **MinIO Gate**：私有、versioning、canonical key、exact version/hash、scoped capability、恢复与删除测试通过。
11. **调研 Gate**：新增框架/服务/目录前记录官方资料、活跃实现、采用/拒绝范围、owner 和验收。

## 11. 仍需产品负责人签认

1. 第一批试点团队、内容类型、金标整本剧本和镜头规模。
2. 切片 C 图像/视频 Provider、地域、数据条款、额度和失败预算。
3. 切片 D 首个确定性检查器与结构化连续性检查器。
4. 切片 E 是否包含生成音频、自动字幕、正式母版或 NLE 交换包。
5. 切片 F 外部审片的下载权限、期限、地域、通知和撤销时限。
6. 首轮 SLO、PostgreSQL/MinIO RPO/RTO 和资源用量基线。

上述待确认项只改变切片配置和验收，不改变 Go 业务后端 + Python Agent 的顶层架构。
