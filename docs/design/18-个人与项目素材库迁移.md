## 3. 已接受事实与需要根审阅的首要选择

当前正式 `media.MediaAsset` 是 **project-scoped**（`backend/internal/media/domain/asset.go:100`）；原件表 project_id NOT NULL，operation/output/reference 等存在 project_id + asset_id 复合约束；`AssetReader`、`UploadRequest`、UploadService、DocumentSources 和项目 Copy 都显式 projectID。`frontend/src/components/media/assets-workspace.tsx:24–100` 当前只有项目库、已加载筛选和实际 ready/passed 私有预览。没有个人媒体实体，不能把它包装为已完成个人库。

建议在 **同一 media owner** 自然加入 closed ownership `project|personal`，避免伪造隐藏项目、旧浏览器数据库、复制一套上传服务或跨 scope 直接使用原ID。个人资产归属 `(current_org_id,current_actor_id)`，是组织内当前个人私有素材；不向项目其他成员泄漏个人分类/收藏/备注。切换 org 不共享 personal namespace。

建议 migration：project_id 对 personal row 可空，增加 personal_actor_id/personal_org_id（项目 row 两者均空；个人 row 两者非空且 project_id 空），CHECK 闭合且继续保留既有项目 FK/复合 unique/operation FK；personal 不携带冒充项目执行的 source_operation_id。现有项目入口/UploadRequest 指纹/Domain JSON/Copy snapshot 的 nil 新字段必须逐字兼容。Go 可用 optional PersonalOwnership，旧 ProjectID 不能把 uuid.Nil 序列化成“合法个人project”。新的 Library DTO 明确 scope，不复用要求 project_id 的公开 AssetSummary 来塞空 UUID。

这是必须审阅的 Schema/owner 扩展，不是源码事实。若该改变当前 FK/consent/读取影响过大，根应先给受理的替代 owning 模型；不能用跨scope引用或虚构项目绕过它。个人真人素材同样需真实 consent owner；尚无个人consent存储时禁止它通过跨库消费门禁，不能用 source portraitCertified 替代。选择到项目后，项目授权与可参考规则仍由当前正式 media.Reference/DocumentSources 消费；Canvas 仍 image/video/audio/model，不扩成document/text/entity。

- `media.library_item`：id/library_id、**互斥** media_asset_id 或 typed plain_text、title、category闭集5、folder_id nullable、position、tags、source_label、note、favorite（personal字段）、catalog_state active/trashed、trashed_at、revision、时间。同library同asset唯一。普通现有 project media row 尚无item时按legacy默认 title=file_name/category=material/root 展示；命令首次创建metadata row，不复制资产/伪造新原件。plaintext不是media.KindDocument，也不是script正文；文本复制/用户笔记有独立闭合正文预算，项目创作版本进入正式reference owner。
- 项目角色/环境/道具与 AssetVersion：消费 bible/reference 已接受模型及实际引用，不能把角色属性、prompt、未来operation结果塞 item metadata。项目页一键“新增版本”通过该 owner 冻结实际媒体引用并生成真实版本；缺该owner会返回明确 unavailable。源text/image编辑仍可作为库描述动作保留，但会影响角色版本的必须经正式version命令。
- `media.library_command`：actor/key 唯一、org/library/action/请求hash、原始闭合response、审计时间，永久 INSERT-only；当前授权后 exactreceipt replay，metadata修订后旧key仍返旧回执，不重放动作。无须新增无消费者的 folder_changed topic；HTTP成功复用TanStack失效，必要引用/任务事件用现有实际链。

标题源SQL240字符，个人folder40、projectfolder60、batch move200为源事实；建议目标 title≤240字符，tags≤32项且每项≤64字符、note≤8000字符、plain_text≤64KiB、每命令JSON≤1MiB，均合法UTF8/NUL拒绝。后四项是资源预算建议，不冒充固定源限制。源 ArkID 用户字符串暂存为“来源说明”不能供 provider 执行；若产品仍需要操作性绑定，交 catalog/bible typed provider binding 单独完整迁移。

### 4.2 查询与动作

`LibraryQueries` 消费小端口读取 current actor + library scoped rows，返回安全 `LibraryItemSummary/FolderSummary/FacetCounts`，不出对象键、storageURL、用户同意正文或provider凭据。详情预览即时通过既有媒体owner短授权，document只有已实现attachment下载，不作为HTML预览。

完整服务端 filter：catalog_state、kind、category、folder（all/root/UUID）、favorite、recent30days、q；personal project筛选必须来自正式 transfer 来源/目标且逐一当前project授权，不能 source metadata.projectName 字符串冒充可读项目。搜索覆盖标题/标签/来源说明/备注/plain_text及MIME。排序 updated_desc/updated_asc/name_asc 在分页前执行，附 id 唯一尾键；name使用固定规范化collation并测Unicode，不能当前页 client.sort。查询total与scope facet含义分别明确，不混为过滤后总数。

页容量保留个人40/80/120、项目20/40/80，picker20/40/80；建议SQL有界offset保留“第n页”源交互，cursor可供既有无限加载接口使用但不得因此删掉页码/总数。任一cursor封闭到 actor/org/library/filter/order；scope切换清缓存/选择/unknown intent。频繁搜索250ms可保留纯交互，AbortSignal取消过期取数，晚到响应不覆盖新scope。全选只当前页；“导出全部”另受理服务器完整有界快照。

`LibraryCommands` 具体命令 createText/updateMetadata/updateTags/setFavorite/recycle/restore/deleteRequest、Folder create/update/delete、MoveItems，均携带 expected_library_revision/实体 revisions 和 UUID key。批量move1..200全部身份/存在/CAS/目录复核同Tx，无部分移动。批量清理逐项持久子结果，不用前端顺序loop报全部成功。

锁顺序必须固定：当前actor/成员复核 → 命令advisory锁 → 必要 workspace 项目UUID排序锁与既有guard → library UUID排序锁 → folder/media UUID排序和media.Reference；不要Copy worker已持target项目锁后反向取library。受理冻结catalogRevision、folder放置、目标scope及原件 facts，同一事务保存永久command；失去权限、deleted/copying project、broken guard、未知执行对象任何一项阻断。归档项目读可用、内容写禁止；未知角色拒绝，project写角色沿既有正式授权factory，personal仅本人当前org（不自行给admin跨人私库读取）。

### 4.3 上传和资源事实

保留 UploadService 一个实现，给实际消费增加 closed UploadScope 与授权/receipt接口；旧project方法与 request hash字节保持原样，personal key空间绑定actor/org，不许以ProjectID=nil走旧方法。复用原件/normalization SHA证明、prober、实际派生图、私有UploadIntents、PutIfAbsent、unknownCommit恢复与真正review；source.title/tags/category是库元数据，媒体Kind/SHA/dims/codec/origin/status不可由该编辑表单写入。

批量图片/视频上传4个并发（独立资源预算），逐文件原File/SHA/key，失败重试、撤权与unknown结果保留；显示queued/uploading/processing/review_required/ready/error等实际阶段及可证明字节进度，不继承source initial10%。Drop/paste真事件只负责选输入，随后同一上传链。source .gltf/GIF若尚无formalprober必须明确“不支持此格式”及剩余准入任务，不能改名GLB/PNG后声称完整。

## 5. 跨库“加入项目”与转移的正式合同建议

源user-global Asset 链接不能迁成 Lanverse 跨project直接引用；当前 media.Reference 对项目严格封闭，数据库 operation输出/cover/director等也依赖这一事实。目标应保持用户意图“加入项目”，但执行为 **同组织内 source冻结→实际私有 bytes/renditions 接管→新 target mediaID**。保留source个人库；从project保存到个人库可采用同一closed Transfer流程满足复用来源和主图个人picker，但应标明这是正式ownership适配，不宣称源有该独立页面。暂不引入任意外链/云盘/跨org/供应商存储迁移入口，也不提供会改变原asset ownership的原地move。

最小 `MediaTransferJob` 位于media owner，模式 personal_to_project/project_to_personal（project_to_project若后续确证用户入口再启用），sourceLibrary/targetLibrary/items及目标目录、metadata策略/expected revisions、当前actor/永久UUIDkey、状态与子结果、目标ID映射、冻结manifest hash、attempt/fence、ObjectIntent。不是Operation/paidquote，也不是伪 WorkspaceProjectCopy。

受理同Tx复核双方ACL、目标active/无guard退化、源ready/passed、实际同意/版权许可与全部依赖、目标目录CAS；无网络IO，冻结每个原件及全部rendition的 ID/revision/SHA/bytes/MIME/codec/probe/只读origin provenance。原scope不可见ID统一404；published不足或revision冲突409；owning依赖不就绪503。源在队列后变更/删除/撤权必须执行前及发布前复核，不仅检查初始actor字符串。

实际 Go/Temporal activity 复用media项目Copy的 **小端口**（current owned open/稳定 objectintent/PutIfAbsent/sha核验/OwnReference验证），不复制一套完整业务Copy层。Transfer对每个字节实际SHA/bytes和全部rendition核验，生成独立targetasset/privatekey。原operation/provider/upload凭据不带入；保留AIGC与真正readonly来源/真实consent合法映射，模型Origin约束不能被擅改。未发布target不进普通列表/selector；取消/失败等对象清理确证后结束，不把不确定写入当失败重跑新ID。重放永久key无新对象、无新target行。

源一次多选加入项目可部分成功：目标可每行稳定子结果，明确已成功/失败/未确认，整体不假回滚已发布部分；绝不让失败第二次创建一个新成功对象。target批次保存目录位置和source lineage不可依赖前端第二请求move。项目页“移除”只退出项目库目录关系，对已有正式使用的media不物理删；正式引用尚在时提示使用位置，物理删除另走引用保护。

主图个人picker、canvas/form/reference/media录入均在Transfer成功后消费target正式image/mediaID；点击浏览个人图不等于完成项目媒体授权。不将整个个人素材清单、收藏、笔记或文件夹复制进项目共享空间。

## 6. 回收、对象删除、容量与包

### 6.1 回收与删除

source status=archived 本质是库列表回收，不等于模型输出审核状态。目标 catalog_state 与 media.status/moderation分开；回收/恢复只控制库可见性，不能把processing/pending复原为ready。旧 ListReadyAssets/picker 需定义排除已回收库metadata，legacy无entry仍可见；已有冻结业务引用是否仍可读由现有Media eligibility判定，不用目录删除撤销正文/输出内容授权。

永久删除必须通过media owning ReferenceChecker聚合实际已实现的canvas当前/历史资源、Operation冻结输入/输出、项目/导演封面、timeline、script source、正式bible/storyboard/audio/edit、以及Copy/Transfer/Package活跃快照。不能由任意JSON全文猜引用；未支持的实际owner或损坏引用会503阻断。被使用返回409及当前调用者有权看到的安全用途；不吐跨项目私有名称。聚合端口根显式注入，无通用跨模块SQL。

对象清理同现有intent/fence；记录到期策略但“30天自动清理”只有真实worker/重放/故障/cancel/当前引用门禁通过后才算完成。清空回收站是有界持久批处理，pending引用保留并报逐项错误；新引用与删除命令持相同media锁，不能先删对象再写DB。failed cleanup/unknownObject必须保留真实状态/恢复原key。

### 6.2 容量与生成历史

容量按当前有权owning scope的已持有唯一原件/renditions对象计算，含trash尚未清理的实际bytes，重复库链接不重计；Transfer的实际副本按新的真实对象计入。quota从已装配策略读取，未配置返回limit=null/不可用，绝不复制本地5GiB显示为服务端上限；hardquota若本阶段启用必须锁住reservation及unknown对象，不只展示仪表。

生成历史接正式Operation输出和可读媒体来源，分日/type/time分页，下载与回收动作仍同Library owner。不会将计费/operation状态/凭据写进可编辑library metadata；sourceeditable“生成任务”label只能表示用户说明，不能造一条正式生成历史。系统音频提取/时间线/depth仍有各自真实job来源，另以origin筛选明确呈现。

### 6.3 素材包

源素材v1 (`assets.json`/files) 做具体兼容reader，自有新manifest须closed kinds/items/folders/files/sha/probe及完整ID映射；项目完整包不复用“我的素材包”伪装全部项目。源丢blob/缺entry不静默跳过。旧storageKey仅作为包内映射键，不作为目标对象路径；旧asset IDs/time/project labels/Ark/portraitCertificate不构成目标权限/事实；任何外部http/dataURI只按明确支持的包内预算规则处理，不主动远程抓取。

本轮接受的包预算：压缩文件≤500MiB、最多2500entries、展开≤2GiB、单媒体不超既有Kind预算、文本/manifest≤16MiB、路径长度≤512、根文件唯一，ZipSlip/absolutepath/symlink/duplicateentry/CRC/多层嵌套拒绝。document DOCX另遵守已接受4096entries/64MiB expanded/16MiBpart/XML预算，与包总体预算分开；不是把所有文件用扩展名转换。包出口按完整scoped快照实际读取SHA匹配bytes且提供attachment，入口有界staging→逐文件真实probe/review→发布闭合集，未知结果按原key恢复。

GLTF多文件/外部纹理、GIF动画、源entity/角色version及未来unsupported类型要明确有类型的错误或待迁子合同，不能导入metadata而称素材完整可用。正式document应保存TXT/DOCX原件，script正文只有本owner接管后实际extractor生成；其他文本条目保留plain文字不虚构文档文件。

## 7. 完整项目 Copy 影响

现有ProjectCopy已经实际复制项目所有ready/passed媒介（含document）与rendition、独立privatekey，清upload/provider/operation事实、实际sha/bytes核验；现在的新素材库不能绕过该owner，也不能在worker持target项目锁后反向取library锁。

新 `ProjectLibraryContent` 由media owner提供 Freeze/Map/Verify/Attach，Freeze在Copy受理Tx读项目library/folders/metadata/reference heads的不可变snapshot。根ProjectCopy admission先取得source/targetproject锁，再按library UUID顺序取锁，Register target媒体后同Tx绑定映射的目录/库条目，Publish重新检查actualmedia/reference/folderclosure。个人分类/favorite/私有备注不在项目content snapshot。Copy不带任务/费用/个人raw身份。

完整项目库快照包含回收目录条目、纯文本正文以及所有合法二进制条目的元数据。二进制条目声明的原件由 media 自己并入 Freeze 的实际资产选择；软删除但仍保有的原件须核实 owning revision、delete_time、purge_after、ready/passed 和真实字节后复制全部原件与衍生物，目标目录条目保留 catalog_state/trashed_at。已物理清理、缺失或不完整的原件必须拒绝整个受理，不得静默省略条目后发布。这个内部 Copy 证明不扩大普通素材读取与引用权限，也不扩大 Script 历史文件读取的 document 闭集；既有无库内容的快照、哈希和回执仍按 nil 合同保持字节兼容。

新数据字段nil/omitempty确保既有无library Copy snapshot、请求hash与永久receipt逐字兼容；source metadata schema未知/不完整folderparent/跨scopeasset/非法正文/缺roleowner一律unsupported_copy_content，不发布空壳。Map只改声明的project/library/folder/媒体/正式reference identities，内容/版本SHA如何重算交实际拥有它的owner；不能root generic rewriteUUID改变immutable事实。旧project没有LibraryEntry时target仍由已复制媒体提供legacy默认列表，不能因缺目录扩展把历史Copy回执重放判错。

整项目archive/delete/restore/copying/failed/cancelled必须同时定义library普通查询可见性，归档readOnly，deleted/copying不可读，未发布target失败不变正式空白库。Transfer/Package活动加入现有project guard factory，未知执行/退化也阻断回收；不能只登记一个不被消费的flag。

## 8. 实施文件边界、真实验收与技术审阅点

建议只在现有media owner新增 `domain/library*.go`、`application/library*.go`/`transfer*.go`/`package*.go` 实际消费端口与 `adapter/{postgres,http,workflow}` 对应小职责文件；必要修改现有asset/upload/query/project_copy owner和独立migration。新普通包/传输状态是实际媒体任务；不预建通用Importer、插件框架或存储微服务。新的library schema可能影响现有consent/ref/operation/Copy，根须先审smallownership型变更，按闭集逐文件列allowlist。migration编号由根统一分配，本文不抢占已分script050/doc051/cover052/copy053。

前端新 `components/media/library-*` 查询/目录/metadata/批量/回收/transfer/package组件，改现 `/assets` 实际personal+project切换；个人与当前项目来源picker复用该安全查询/Transfer，不再复制当前ProjectScope一个假个人页。Next薄page/Suspense，TanStack cache含origin/actor/org/library/filter/order；只对交互区Client，低频GLB/包编辑按需加载。shadcn/Radix菜单/弹窗取代源Antd；保留源已验证纯分类规范、选中规则、图片zoom、目录theme/style交互的来源notice，不搬源store/HTTP/Wails持久层。
