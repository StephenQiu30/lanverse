# Design 15：健康

执行编号：15；原始需求模块：19。依据[原始需求](../requirement/19-健康需求.md)、[PRD](../prd/15-健康.md)与[Plan](../plan/15-健康.md)。本文件把原始需要转换成项目方案，**全部新增设计选择仍待评审**；数据对象和接口为拟议合同，不表示已有表或已实现API。共同约束见[整体设计](00-项目需求设计.md)。原始FR、质量条件与AC仍须同时满足。

## 健康是读事实，不是修复按钮

健康模块读取实际任务/执行、供应商结果与运行环境观测，提供管理员摘要和授权处理链接。没有部署的Worker/队列/监控组件返回not_deployed/not_connected；旧“Outbox”等显示名不强制旧架构。

HealthSnapshot含window/as_of/availability、分组事实、reason_codes、last_success_at。建议同生成Task/Attempt事实区分业务失败、unknown/manual、积压queued及最旧等待；供应商1小时指标按实际调用/任务样本和原模型/供应商版本聚合。系统降级阈值待确认，缺数据不能判绿色。

## 指标和刷新接口

拟议管理员GET /system-health返回15分钟摘要、GET /system-health/providers读取1小时分组、GET /system-health/runtime读取已部署组件；处理入口引用授权供应商配置或具体未知任务，不新建全局任务平台。监控地址来自服务端受控配置，不能开放任意用户输入URL或暴露带token链接。

建议15分钟失败率与供应商成功率明确报告分子分母/状态集合，unknown/manual单列；P95只针对真实完整耗时样本，算法与[分析](13-分析.md)经接受后共用口径。积压从当前queued/执行意图事实读，不假定某中间件队列深度等于业务任务数。租约失效不自动转普通失败，而显示恢复/核对原因。

页面手动或每30秒只读刷新，避免重叠请求，隐藏/卸载时停止定时和订阅，晚到响应不能覆盖更新快照。每个分组独立availability/last_success_at，局部失败保留上次成功值并明确过期/错误；点击刷新不直接改健康状态、不发供应商测试或生成收费。

## 原始需求到设计追踪

| 原始FR       | 项目设计与验收观察                                               |
| ------------ | ---------------------------------------------------------------- |
| FR-HEALTH-01 | HealthSnapshot＋真实15分钟任务口径/当前积压；0与不可用区分       |
| FR-HEALTH-02 | 实際部署/供应商1小时样本分组；未部署不造运行数值，原日志不回传   |
| FR-HEALTH-03 | 只读手动/30秒刷新＋分组last_success_at；局部故障可见，无业务写入 |
| FR-HEALTH-04 | 受控只读监控链接和授权对象目标；未配置明确不可用                 |

验证非管理员、零样本/未部署/数据源故障、分组局部失败、刷新请求重叠、页面离开与项目/用户切换。运行中重启后的任务恢复由生成模块验收，健康页能展示恢复事实不等于已修复。具体性能、阈值和可用性目标须在部署条件确定后测试。

## 待评审选择与实施入口

指标创建/完成窗口、P95样本、失败率分母、降级/过期阈值、真实运行拓扑、监控入口和权限待确认。初轮只需关键诊断与任务核对信息，健康管理页后置，按[Plan](../plan/15-健康.md)接入实际观测，不预建监控微服务或复制旧栈。

## 工程合同：健康读模型与运行接口

### 数据库与运行指标来源

不新增health_status表，不把“正常”保存为手动布尔。业务源是generation_tasks/attempts/task_events、media_ingest_jobs、provider_tests；CPU/内存/实际角色活性只能来自已部署观测端口，没有来源返回not_connected/not_deployed。

| 分组           | 数据/窗口                                              | 可计算值及未知处理                                                                        | 索引/权限                           |
| -------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------------- |
| 15分钟Task结果 | 同明确时间窗口的Task cohort，窗口锚点需接受            | 成功/失败分子分母、unknown/manual单列；零分母no_sample                                    | Task时间/状态索引；仅管理员允许范围 |
| 当前积压       | 当前queued Task/待领取prepared意图、媒体转存等待分别计 | 最旧等待用最早created_at；没有队列不伪造队列深度                                          | state/next_run_at/lease_until索引   |
| 近1小时供应商  | 实际Attempt及可验证外部结果，按provider/模型版本       | 确认成功/失败才进入已知率分母，可能未发出或受理不明单列unknown；P95只有真实可解释起止样本 | attempts状态/时间索引，Task模型引用 |
| 连接测试       | 当前credential对应provider_tests事实                   | 最近真实checked_at及安全原因；过期政策未定不能永远绿                                      | tests(provider_id,created_at,id)    |
| API/执行单元   | 真实角色心跳/运行测量端口                              | last_seen_at/availability；未部署返回不可用，不能用SQL有行冒充Worker活着                  | 受控只读观测，不回传原日志          |
| 监控入口       | 受控运行配置                                           | 配置存在且有权才返回只读地址，不包含token                                                 | 管理员，不接受任意用户URL           |

降级阈值、窗口锚点、指标新鲜度为待接受配置；可先返回事实与availability，不能根据样例阈值自动判绿。实际运行和业务任务恢复分别验收。

### HTTP接口与DTO

路径统一以/api开头；字段后?表示可空/可省，其他为必需；Id/Rev/Time/Money/Page及通用错误见[全局HTTP合同](00-项目需求设计.md#工程合同http全局约定)。响应只包含所列字段，不直接序列化ORM。

| DTO                  | 字段与类型/语义                                                                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HealthMetric`       | value:number?、numerator/denominator/sample_count:integer?、availability:string、reason_code:string?、window:{from/to:Time}、as_of:Time、last_success_at:Time?                     |
| `HealthSnapshotView` | status:healthy/degraded/unknown、reason_codes:string[]、as_of:Time、metrics:{failure_rate:HealthMetric,unknown/manual/backlog/oldest_wait_ms:HealthMetric}；阈值未定status=unknown |
| `ProviderHealthView` | provider_id:Id、credential_version_id:Id?、metrics:{success_rate:HealthMetric,p95_ms:HealthMetric,unknown:HealthMetric}、last_test_at:Time?                                        |
| `RuntimeHealthView`  | components:[{name:string,role:string,availability:string,last_seen_at:Time?,metrics:Json}]、monitor_links:[{name:string,url:string,availability:string}]                           |

| 方法与路径                               | 权限   | 请求 | 响应/HTTP状态            | 错误与写入边界                             |
| ---------------------------------------- | ------ | ---- | ------------------------ | ------------------------------------------ |
| `GET /api/admin/system-health`           | 管理员 | 无   | 200 HealthSnapshotView   | 观测失败分组不可用；无本地鉴权/DB则401/503 |
| `GET /api/admin/system-health/providers` | 管理员 | 无   | 200 ProviderHealthView[] | 1小时真实样本，不触发连接测试/生成         |
| `GET /api/admin/system-health/runtime`   | 管理员 | 无   | 200 RuntimeHealthView    | 未部署不可用；不返回带密钥监控地址         |

### 读取与刷新生命周期

30秒刷新只执行这些GET；手动刷新同一读取合同。分组缓存（如确有需要）只属于管理员范围且带有效期/as_of，不能跨用户投放私有数据。当前无必要先建缓存设施，最后成功值可由页面保留并标过期。隐藏/卸载停止定时，取消旧请求，晚到响应不得覆盖新as_of。
去处理指向供应商配置或原Task的授权核对入口；没有本轮通用“修复全部/重跑全部”接口。实际Worker关闭/重启/未知任务核对测试仍由生成Design负责，健康只报告结果。
