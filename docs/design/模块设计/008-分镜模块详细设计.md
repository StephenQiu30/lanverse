# DES-MOD-008 分镜模块详细设计

- 状态：proposed
- 覆盖需求：SYS-FR-004、SYS-ENT-003；SBD-ENT-001 至 004、SBD-FR-001 至 010、SBD-IF-001 至 008、SBD-NFR-001 至 007
- 输入：[分镜模块需求](../../requirement/008-分镜模块需求.md)

## 1. 聚合与规格结构

storyboards 拥有 Episode 内 Shot 身份、顺序、不可变规格版本、固定资产引用和 readiness。生成候选、任务、媒体与费用留在 production/media，不回填成 ShotSpec 的可变字段。

| 实体/读模型 | 关键字段 | 不变量 |
| --- | --- | --- |
| Shot | id、workspace_id、episode_id、position、title、source_script_version_id、source_scene_id、status、current_spec_version_id、revision | active Shot position 连续唯一；来源可空但存在时同 Episode |
| ShotSpecVersion | id、shot_id、version_no、schema_version、spec、content_hash、input_hash、created_by、created_at | 完整规格只追加；固定引用随版本保存 |
| AssetReference | shot_spec_version_id、slot_key、role、asset_version_id、subject_key | slot_key 在规格内唯一；角色与资产 kind 匹配 |
| Readiness | ready、blocking_reasons、warnings、next_actions、evaluated_dependencies | 确定性派生，不持久化可编辑状态 |

spec 为 Pydantic 类型化整体快照并以 JSONB 保存，extra=forbid。它包含 narrative、visual、action_beats、dialogue_or_narration、duration、mood_lighting、audio_intent、generation_intent；AssetReference 单独关系化，既便于外键/反查，也避免 JSON 内引用不可检索。供应商名称和专属参数禁止进入 spec。

input_hash 由规范化 spec、ScriptVersion ID、按 slot 排序的 AssetVersion ID 和 schema_version 计算，供 production 判定同一输入；它不是只由提示文本计算。

## 2. 基础用例

| 用例 | HTTP 形态 | 关键规则 | 需求 |
| --- | --- | --- | --- |
| create/list/get/update_shot | /api/v1/episodes/{id}/shots、/shots/{id} | editor/owner 写；PATCH 仅标题等元数据 | SBD-FR-001/002、IF-001 |
| save_spec_version | POST /shots/{id}/spec-versions | 完整规格、expected_current_spec_version_id | SBD-FR-003、IF-002 |
| list/get/set_current_spec | 版本查询、POST /shots/{id}/current-spec-version | 历史只读、跨 Shot 版本拒绝 | SBD-FR-003、IF-003 |
| reorder_shots | POST /episodes/{id}/shots/reorder | 完整 active Shot ID 列表、expected_revision | SBD-FR-004、IF-004 |
| transform_shots | copy、split、merge 命令 | 创建新身份/规格，不复制媒体、任务、费用 | SBD-FR-005、IF-005 |
| get_readiness | GET /shots/{id}/readiness、批量 Episode 查询 | blockers/warnings/next_actions | SBD-FR-007/008、IF-006 |
| preflight/apply_asset_upgrade | 明确预检和执行命令 | 新规格版本，默认批量原子 | SBD-FR-006、IF-007 |
| get_production_snapshot | 内部公开查询 | 固定 DTO 与 input_hash，无供应商参数 | SBD-IF-008 |

从 ExtractionCandidate 创建 Shot 使用 scripts 的 decision_key 作为幂等键；手工创建使用客户端 idempotency_key。Shot 创建时服务端在目标位置插入并重新编号，不接受客户端直接写任意 position。

## 3. 保存规格版本

保存前校验 Episode/Shot active、expected 当前版本、ScriptVersion 属于本 Episode、AssetVersion 类型与范围、媒体可用和规格结构。事务锁定 Shot，计算 version_no/hash，写 ShotSpecVersion 与 AssetReference，比较更新 current_spec_version_id 和 revision。

授权失效可以允许保存为 blocked 规格以保留编辑结果，但响应必须返回 readiness；生产预检不能绕过 blocker。保存失败或版本冲突不改变当前指针，并返回最新 spec_version_id 供用户重新应用修改。

## 4. 顺序与镜头变换

重排事务锁定 Episode 下所有 active Shot，要求输入集合完整、无重复且同 Episode，使用临时序号后写连续最终 position。并发修改通过 Episode/排序 revision 冲突返回服务端最新顺序。

- copy：创建一个新 Shot 与新 ShotSpecVersion，复制不可变规格引用，但不复制 Candidate、Media、Task、费用或审核。
- split：按明确 action/dialogue 时间切点创建两个新 Shot 和对应规格，原 Shot 归档；原生产证据继续挂在原 Shot。
- merge：仅允许相邻 active Shot，创建一个新 Shot/规格并归档来源；合并时长和对白顺序需通过规格校验。

split/merge 若来源已有选中候选、审核或时间线引用，预检返回影响清单并要求 confirm_evidence_detached；确认只表示用户理解新 Shot 不继承这些事实，不删除原历史。整个变换与重排在一个事务中完成。

## 5. Readiness 规则

计算顺序固定：当前规格存在 → 叙事/画面/动作/声音/时长必填 → ScriptVersion 可访问 → 每个 slot 固定 AssetVersion 且类型匹配 → 资产 readiness → governance 指定生产用途授权。缺失为 blocking_reason；可能影响质量但可继续的事项为 warning，继续时生产请求保存 acknowledged_warning_codes。

readiness 返回 evaluated_dependencies 中的版本 ID 与状态摘要，使 production 能在提交事务前再次比对；任何依赖变化都重新计算，曾经 ready 不形成永久许可。模型参数和能力限制由 production 预检负责。

## 6. 资产升级与影响查询

预检要求新旧 AssetVersion 属于同 Asset 且新版本 ready，查询所有目标 Shot 当前 spec，返回兼容性、授权变化、已有关联生产/时间线事实和预计新 input_hash。执行时锁定全部目标 Shot；任一 expected_spec_version 不匹配则整体 VERSION_CONFLICT。成功为每个 Shot 创建一个新 ShotSpecVersion，不修改历史。

ScriptVersion 当前指针或 AssetVersion 状态变化时，影响查询直接按关系化引用定位 Shot，返回 needs_review；不自动切换来源或当前规格。

## 7. 持久化与删除

必要唯一约束为 active shots(episode_id, position) 的部分唯一索引、shot_spec_versions(shot_id, version_no)、asset_references(shot_spec_version_id, slot_key)。索引覆盖 source_script_version_id/source_scene_id、asset_version_id、input_hash。

Shot active ↔ archived。只有无规格历史、候选、任务、媒体、费用、审核和时间线引用的空 Shot 可硬删；否则归档。检查通过公开 blocker 查询完成，不建立通用软删除基类或级联删除。

## 8. 失败与测试

跨空间或跨 Episode 引用返回 NOT_FOUND/VALIDATION_FAILED；顺序集合错误返回字段级错误；版本冲突返回最新引用；依赖服务不可用时 readiness 为 unavailable 并阻止生产，不当作 ready=false 的普通缺字段。

- 单元：Spec 判别结构、input_hash 稳定性、readiness、slot 类型、split/merge 规格计算。
- PostgreSQL 集成：并发保存、重排唯一性、批量升级原子性、变换历史与删除阻塞。
- 契约：生产快照不含供应商参数，readiness 证据和 next_action 稳定。
- 端到端：资产固定版本 → ShotSpec → 生成后局部返工 → 历史输入仍可追溯。

无限画布、逐子项全套 CRUD、供应商参数编辑器、专业动画曲线和生成事实回填不进入 MVP。
