# DES-MOD-003 项目模块详细设计

- 状态：proposed
- 覆盖需求：SYS-FR-001、SYS-ENT-002；PRJ-ENT-001 至 003、PRJ-FR-001 至 008、PRJ-IF-001 至 007、PRJ-NFR-001 至 006
- 输入：[项目模块需求](../../requirement/003-项目模块需求.md)

## 1. 边界与聚合

projects 拥有系列与单集的稳定身份、制作默认值、排序和生命周期。生产阶段与概览是组合查询，不是可编辑字段。下游正文、任务、费用和审核只保存版本引用或通过公开查询读取。

| 聚合/读模型 | 关键字段 | 不变量 |
| --- | --- | --- |
| Project | id、workspace_id、name、description、aspect_ratio、language、visual_style、target_duration、budget_limit、status、revision | 归属 Workspace；默认值变化不回写历史输入 |
| Episode | id、workspace_id、project_id、name、position、target_duration、status、revision、current_script_version_id、current_timeline_version_id | 同 Project position 唯一且连续；版本引用必须属于本 Episode |
| ProductionSnapshot | current_stage、completion、blocking_reasons、next_actions、task/review/cost summaries、partial_failures | 请求时计算，不持久化，不反向修改模块事实 |

Project 是自身聚合根，Episode 是独立聚合根并引用 Project。current_script_version_id 和 current_timeline_version_id 是跨模块稳定 ID，使用公开用例校验后以比较更新写入，不建立跨模块 ORM 级联。

## 2. 用例与接口

| 用例 | HTTP 形态 | 关键规则 | 需求 |
| --- | --- | --- | --- |
| create/list/get/update_project | /api/v1/projects | editor/owner 写；列表显式搜索、排序、分页 | PRJ-FR-001 至 003、IF-001/002 |
| update_budget_limit | POST /api/v1/projects/{id}/budget-limit | 仅 owner；与普通 PATCH 分离 | PRJ-FR-003、IF-002 |
| archive/restore/delete_project | POST /api/v1/projects/{id}/archive、restore、delete-preflight；DELETE /api/v1/projects/{id} | 归档 owner；删除先收集 blockers | PRJ-FR-007/008、IF-003 |
| create/list/get/update_episode | /api/v1/projects/{id}/episodes、/api/v1/episodes/{id} | 父 Project active；editor/owner 写 | PRJ-FR-004、IF-004 |
| reorder_episodes | POST /api/v1/projects/{id}/episodes/reorder | 完整 ID 列表、expected_revision、单事务 | PRJ-FR-004、IF-005 |
| set_current_version | 模块内部公开命令 | version_type 白名单、期望旧 ID、新 ID | PRJ-IF-007 |
| get_snapshot | GET /api/v1/projects/{id}/production-snapshot 或 /api/v1/episodes/{id}/production-snapshot | 服务端组合，返回部分失败 | PRJ-FR-005/006、IF-006 |

Project PATCH 只允许名称、简介与默认制作设置；Episode PATCH 只允许名称和目标信息。status、position、阶段、当前版本引用不能通过 PATCH 修改。

预算上限虽然属于 Project 字段，但只能由 owner 通过独立 update-budget-limit 命令修改；editor 修改制作元数据时不能夹带预算字段。

## 3. 生命周期和删除判定

Project 与 Episode 均为 active ↔ archived。归档 Project 在一个事务内只改变 Project 自身状态；其 Episode 历史保持原状态但所有下游写用例通过父级 active 校验被阻止。恢复后下游仍按自身状态决定能否写入。

删除前调用各模块轻量 blocker 查询，结果统一为 code、resource_type、resource_id、summary。Project 只有无 Episode、版本、任务、费用、审核和交付时可删；Episode 同理。检查与删除在事务内重新确认本模块引用，若并发产生下游事实则返回 STATE_CONFLICT，不做级联删除。

S2 首个下游引用由 production 通过公开批量查询返回每个 Episode 的 Task 数量，projects 不导入 Task ORM。Episode 预检在存在任意状态 Task 时追加 `HAS_TASKS`，实际 DELETE 锁定 Episode 后再次查询并返回 `review_delete_blockers`；真实 Task 创建路径同样先锁定 Episode，因此“预检后新建 Task”和并发创建/删除只能有一个方向成功，不留下孤立 Task。Project 预检对所属 active/archived Episode 批量汇总 Task，并同时返回 `HAS_EPISODES` 与 `HAS_TASKS`，让用户看到完整影响；后续 Cost、Review、Delivery 模块按同一公开查询与锁内复检规则接入。

## 4. Episode 排序与版本引用事务

重排输入必须正好包含该 Project 全部 active Episode ID，不能重复或混入归档/外部 ID。事务锁定 Project 和 active Episode，验证 expected_revision 后按列表写入连续 position，并递增 Project revision。避免逐条唯一冲突时可先写临时负序号，再写最终序号；两步仍在同一事务。

set_current_version 的调用方先从所属模块取得 VersionRef(workspace_id, episode_id, version_id, type)。projects 锁定 Episode，比较旧 ID，验证范围后更新指针并写审计。切换只影响以后入口，不更改任何已存在 ShotSpec、GenerationRequest 或 TimelineVersion。

## 5. 生产概览组合

概览适配器并行调用 scripts、assets、storyboards、production、governance、editing 的公开摘要查询。每个模块返回 status、blocking_reasons、next_actions 和本模块计数；projects 按固定阶段规则合并：缺当前剧本 → 剧本入库，存在未决议候选 → 结构确认，资产/镜头未就绪 → 准备，任务运行或缺候选 → 生产，时间线未发布 → 合成，审核未批 → 审核，否则可交付。

Snapshot 携带 computed_at 和 partial_failures。依赖失败时对应摘要为 unavailable，整体不把未知解释为 0 或完成。为避免 N+1，Project 概览使用模块批量摘要接口传入 episode_ids；缓存仅可作为短时读优化且必须标注生成时间，不成为事实源。

## 6. 持久化与查询

必要约束为 projects(id, workspace_id)、episodes(project_id, position) 唯一；索引覆盖 projects(workspace_id, status, updated_at)、episodes(project_id, status, position)。所有资源查询同时限定 id 与 workspace_id。

预算上限使用确定精度 decimal 和币种字段，具体精度在 PRD 确认；projects 只拥有上限，已用与预占来自 production。搜索 MVP 仅名称/简介的受控模糊查询，不提供动态过滤语言。

## 7. 失败、审计与测试

父级归档返回 STATE_CONFLICT 和 restore_project 下一动作；版本范围错误返回 VALIDATION_FAILED；并发重排/指针更新返回 VERSION_CONFLICT；概览部分失败仍返回 200 与 partial_failures，资源本体查询失败才返回依赖错误。

审计覆盖预算、默认制作设置、归档/恢复、删除、Episode 重排和当前版本引用变化。

- 单元：阶段推导、blocker 合并、默认值不回写、角色规则。
- PostgreSQL 集成：position 唯一与并发重排、版本指针比较更新、删除竞争。
- 契约：列表分页/排序白名单、跨空间不可探测、partial_failures 结构。
- 端到端：建立 Project/Episode，完成下游事实后服务端 next_action 随事实变化。

模板市场、多集排期、跨项目复制、项目级 ACL 和持久化 ProductionSnapshot 不进入 MVP。
