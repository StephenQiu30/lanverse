- 状态：部分 accepted（PT-OBS-001 当前 HTTP/JSON 日志基线；PT-OBS-002 当前 Trace 传播、消息结果及 MinIO/ffprobe 遥测增量 accepted；其余范围 proposed）

- 覆盖需求：SYS-NFR-007、LOG-ENT-001 至 004、LOG-FR-001 至 009、LOG-IF-001 至 006、LOG-NFR-001 至 009
- 输入：[日志与可观测性需求](../../requirement/012-日志与可观测性需求.md)、[消息队列详细设计](./012-消息队列详细设计.md)、[缓存、对象存储与任务调度详细设计](./014-缓存对象存储与任务调度详细设计.md)
- 输出：JSON 日志、OpenTelemetry、Prometheus、关联、脱敏、告警和故障降级设计

## 1. 设计结论

日志能力属于 backend/app/core 与 Worker 组合根，不创建第十个业务模块或数据库“日志表”。Python 标准 logging 输出一事件一行 JSON 到 stdout/stderr；OpenTelemetry SDK 产生 trace；Prometheus 暴露低基数指标。具体日志检索后端和 trace 后端由部署环境选择，应用不绑定 Elasticsearch、Loki 或厂商 SDK。

治理 AuditEvent、Task/Attempt 和运行日志三者分工固定：AuditEvent 是业务审计证据，Task/Attempt 是恢复事实，运行日志用于诊断并允许按策略过期。任何业务决策不得通过搜索日志完成。

## 2. LogEvent 契约

每条日志公共字段：timestamp、level、service、component、environment、event_name、message、trace_id、span_id、request_id、workspace_id、actor_id、project_id、episode_id、task_id、attempt_id、event_id、schedule_id、fire_id、provider_request_key、media_version_id、error_code、retryable、duration_ms、attributes。

字段只在已知时出现，空值不输出。message 是稳定短摘要，机器告警使用 event_name/error_code，不解析 message。attributes 必须来自事件级白名单并保持扁平；业务对象、ORM、Request、Exception 原始字典不能直接传入 logger。

事件命名使用 domain.action.result：例如 http.request.completed、project.archive.rejected、outbox.publish.failed、task.attempt.started、provider.submit.unknown、media.render.completed。名称由常量注册，禁止把 ID 或状态详情拼进 event_name。

## 3. 关联上下文传播

HTTP middleware 校验 W3C traceparent；缺失或非法时创建新 trace。request_id 使用规范 UUIDv7：只有可解析、版本为 7 且规范字符串一致的 `X-Request-ID` 才继续使用，其他输入由服务端重新生成且不回显原值；响应回传最终 X-Request-ID。JWT 认证成功后只补充内部 actor_id/workspace_id，不记录 token claims、邮箱、密码或摘要。

应用使用 contextvars 保存请求/任务上下文；创建 asyncio task、进入 ThreadPoolExecutor 或 subprocess wrapper 时显式复制必要上下文，不依赖线程本地变量。SQLAlchemy Session 只携带 trace，不向 SQL comment 注入用户输入。

Outbox 同时保存既有业务关联 `trace_id` 与独立的规范 W3C `traceparent`。`trace_id` 当前仍可承载 UUIDv7 request ID，不得把它解析或改写成 W3C Trace ID。事务内创建 Outbox 时捕获当前 span；非 HTTP 调用没有活动 span 时创建最小根上下文，保证已持久化事件始终可继续传播。

Publisher 从持久化 `traceparent` 提取 remote parent，创建新的 producer span，再把 producer 当前上下文同时写入 MessageEnvelope.traceparent 和 RabbitMQ `traceparent` header。Consumer 优先提取 RabbitMQ header；header 缺失或非法时回退受 schema 校验的 Envelope traceparent；随后创建新的 consumer span。不能复用已经结束的 HTTP/producer span，也不能因重复投递生成错误的同一 span；每次 publish/consume attempt 是独立 span，event_id 始终可用于事实关联。

HTTP server span 只记录 method、完成后的 FastAPI 路由模板、status_code/status_class 和异常类型等受控属性，不记录 URL 实参、query、body 或 header 全量。响应返回当前 server `traceparent` 便于调用方关联；非法入站值被标准 propagator 忽略并重建，不原样回显。默认 `app.server` 在启动 API/Scheduler/IO Worker/Media Worker 前以 `lanverse-server` 一次性配置进程级日志与 SDK Provider，保证同一进程的 `/metrics` 能聚合各角色且 resource 不由协程竞态决定；单独运行某一角色时才使用角色级 service name。进程配置遵循 first-writer-wins，后启动的子角色不得重置全局 handler/provider。未配置 exporter 时仍生成、传播 span，上报为空操作且不阻断业务。

缓存、Scheduler、供应商、MinIO/OSS 和 FFmpeg 子阶段分别建立 span，attributes 只包含 namespace/handler/provider、operation、task stage、对象/版本 ID、状态和耗时。缓存 value、提示、URL、文件路径和命令实参不得进入 span。

## 4. HTTP 与应用日志

HTTP 每个请求只记录一条 completed access event；未处理异常额外记录一条 exception event。路由字段从请求完成后的 FastAPI route 读取 OpenAPI 模板 `/api/v1/tasks/{task_id}`，404 等未匹配请求统一记为 `unmatched`，不使用含实际 ID/query 的 URL。记录 method、status_class、duration_ms 的受控值，不记录 body/header 全量；响应大小在形成稳定、无流式副作用的实现前不猜测记录。

业务命令在 Application Service 记录 completed/rejected/failed 结果；普通 Repository CRUD 不重复打印。状态转换日志包含 target ID、from/to status、revision、error_code 和 next_action code。成功高频列表查询默认不记录 application event，由 access log 与指标覆盖。

异常映射器记录异常类型和内部堆栈，但对外只返回 ApiError。Validation/NotFound 等预期错误为 info/warning；不可恢复内部错误为 error；不会因为客户端 4xx 打满 error 日志。

## 5. Worker 与集成日志

| 阶段 | 必要事件 | 允许字段 |
| --- | --- | --- |
| Outbox/RabbitMQ | claimed、published、received、retry_scheduled、rejected、acked | event_id、event_type、queue、attempt、duration、result |
| Task/Attempt | started、stage_changed、unknown、completed | task/attempt、input_hash、stage、error_code、next_action |
| Provider | submit/query/cancel completed/failed/unknown | provider、capability/model ID、provider_request_key、status、duration |
| Cache/Scheduler | hit/miss/error、claimed/fired/misfired/recovered | namespace、handler、result、duration/lag；schedule/fire ID 只进日志 |
| Object Storage | head/get/put/register/migrate failed/completed | media_version_id、storage_profile、operation、size_bucket、duration、error_code |
| FFmpeg/ffprobe | started/completed/failed | task/render/media ID、tool version、exit_code、duration、stderr_digest |

供应商原始请求/响应不进普通日志；必要诊断以脱敏、限长摘要存 Attempt。FFmpeg 命令只记录参数 hash，stderr 先去路径/URL并限长，普通日志只记录 digest 与稳定摘要。

## 6. 脱敏和日志注入防护

格式化前递归过滤键名：authorization、cookie、set-cookie、token、secret、password、api_key、credential、presigned_url 及供应商同义字段。email、phone、subject 等个人字段默认不允许；确需安全事件时使用不可逆 hash 或内部 user_id。

剧本正文、prompt、negative_prompt、授权证明、Candidate 原始结果和媒体内容始终拒绝。所有字符串移除控制字符并限长，防止换行伪造 JSON 事件。SQLAlchemy echo 在所有环境关闭；数据库错误不打印绑定参数。

RedactionPolicy 的 allowlist 优先于 denylist：每个 event_name 声明允许 attributes。检测到额外字段时丢弃字段并递增 telemetry_redaction_drops_total，不递归打印被丢弃内容。字符串移除控制字符后最多保留 512 个 Unicode 字符；截断只保留处理后的前缀，不把原值或长度作为 label。

## 7. Trace 和采样

资源属性固定 service.name、service.version、deployment.environment、worker.kind。HTTP、应用命令、Redis、Scheduler、RabbitMQ publish/consume、provider、MinIO/OSS、FFmpeg 和关键数据库事务建立 span；不为每行 ORM 映射建立手工 span。

开发环境可全采样；生产采样率通过配置设置，错误与 unknown 链路应保留。采样决定不能改变 JSON error 日志和业务 AuditEvent。OTLP exporter 使用有界 BatchSpanProcessor；队列满或 endpoint 不可用时丢 telemetry 并计数，不阻塞业务线程。

## 8. Prometheus 指标

| 指标组 | 示例 | 允许 labels |
| --- | --- | --- |
| HTTP | lanverse_http_requests_total、lanverse_http_request_duration_seconds | method、route、status_class（duration 不带 status_class） |
| 数据库 | db_pool_in_use、db_pool_wait_seconds、db_errors_total | operation、result |
| 缓存/调度 | cache_requests_total、cache_duration_seconds、schedule_lag_seconds、schedule_fires_total | namespace、handler、result |
| 队列 | outbox_pending、outbox_oldest_age_seconds、rabbitmq_consumer_inflight、message_results_total | queue、event_type、result |
| Task | tasks_total、task_stage_duration_seconds、tasks_unknown | task_type、stage、status/provider |
| Provider | provider_requests_total、provider_duration_seconds、provider_cost_total | provider、capability、result、currency |
| 存储/媒体 | storage_operations_total、storage_bytes_total、media_duration_seconds、ffmpeg_failures_total | storage_profile、operation、kind、result |
| Telemetry | telemetry_export_failures_total、telemetry_redaction_drops_total | signal、reason |

禁止把 workspace_id、user_id、task_id、event_id、provider_request_key、文件名、URL 或错误正文作为 Prometheus label。`/metrics` 只绑定内部网络或经独立鉴权，不复用普通 viewer 权限。

当前消息结果增量采用以下精确契约：`lanverse_outbox_publish_results_total(queue,event_type,result)`、`lanverse_outbox_publish_duration_seconds(queue,event_type)`、`lanverse_message_results_total(queue,event_type,result)` 与 `lanverse_message_handler_duration_seconds(queue,event_type)`。queue 只能是 `lanverse.io`/`lanverse.media` 或固定 `unregistered`；event_type 只能是当前六个已发布事件或 `invalid`/`unregistered`；result 只能来自 Publisher 的 `published/retry_scheduled` 与 Worker 的 `completed/duplicate/rejected/requeued`。原始未知 event type、event_id、attempt、error_type 和 routing key 只允许进入受控日志或 span，不能成为 label。

Publisher 只在 RabbitMQ confirm 后记录 `published`，只在 PostgreSQL 成功保存下次 `available_at` 后记录 `retry_scheduled`；数据库状态更新失败不得伪报上述结果。Worker 的 handler duration 覆盖合法 Envelope 的业务处理与事务，poison/oversize 拒绝只记录固定 `invalid/rejected` 计数，不尝试解析或记录原始 body。日志事件固定为 `outbox.publish.completed/failed` 与 `message.consume.completed/failed`，字段白名单为 W3C trace/span、request/event ID、已归一事件类型、queue、attempt、result、duration、retryable 和错误类型；不自动捕获异常正文。

当前 MinIO/ffprobe 增量采用以下精确契约：

- MinIO 的八项端口操作统一创建名为 `storage.minio` 的 CLIENT span。attributes 只能是 `storage.system=minio`、归一后的 `storage.profile`、`storage.operation` 和最终 `storage.result`；不得添加 bucket、object key、endpoint、URL、凭据、文件名或异常正文。`storage.profile` 当前只登记 `default`，八项 operation 只登记 `ensure_bucket/presign_upload/presign_download/stat/put/copy/stream/delete`，其他值归一为 `unregistered`。
- ffprobe 每次调用创建名为 `media.ffprobe` 的 CLIENT span。attributes 只能是 `media.tool=ffprobe`、归一后的 `media.kind` 和最终 `media.result`；kind 只登记 `image/video/audio/subtitle`。临时路径、MIME、命令实参、stdout/stderr、codec/container 和尺寸不得进入 span。
- `start_span` 只有在调用方提供 `parent_traceparent` 时才显式提取远端父上下文；未提供时必须继承当前 span，不能用空 `Context` 把 Worker 内部集成阶段错误切成新根。因此媒体探测链固定为 RabbitMQ consumer → `media.ffprobe` → ffprobe 读取期间的 `storage.minio(operation=stream)`。
- 存储 result 只允许 `succeeded/not_found/access_denied/unavailable/rejected/cancelled/failed/unregistered`；探测 result 只允许 `succeeded/probe_timeout/probe_tool_unavailable/unsupported_media/invalid_probe_output/invalid_image_metadata/cancelled/failed/unregistered`。异常类型只映射到这些稳定类别，原始 message 不作 label。
- 指标固定为 `lanverse_storage_operations_total(storage_profile,operation,result)`、`lanverse_storage_operation_duration_seconds(storage_profile,operation)`、`lanverse_storage_bytes_total(storage_profile,operation)`、`lanverse_media_probe_results_total(kind,result)` 和 `lanverse_media_probe_duration_seconds(kind)`。存储 bytes 只在成功 `put` 或 `stream` 被完整消费后增加；`stat/copy` 等不根据元数据推测流量。
- 登记日志固定为 `storage.operation.completed/failed` 与 `media.probe.completed/failed`。允许字段分别为 trace/span、storage_profile/operation/result/duration_ms/bytes_processed/error_code，以及 trace/span、kind/result/duration_ms/error_code。观测写入采用 best-effort：指标或日志实现自身失败必须被吞掉，不得替换原业务返回或异常；span SDK 的无 exporter 路径继续保持非阻塞。

适配器层不知道 MediaVersion、Task 或 Render ID，因此本增量只通过父 span 接入现有 Worker trace，不伪造这些 ID。完整 LOG-FR-005/007 仍需在拥有业务事实的 Media/Render 编排层补齐关联事件，FFmpeg render 也必须另取真实输入输出证据。

当前 Outbox/Worker 容量增量复用消息模块的 queue 归一规则，新增四项 Gauge：`lanverse_outbox_events(queue,state)`、`lanverse_outbox_oldest_age_seconds(queue,state)`、`lanverse_worker_inflight(queue)` 和 `lanverse_worker_capacity(queue)`。Outbox 值来自 PostgreSQL `pending/claimed/manual_attention` 快照，Worker 值来自 handler 外层 `try/finally`；刷新失败必须 best-effort 隔离。I/O/Media capacity 与 RabbitMQ prefetch 分别固定使用同一 4/2 常量，并以真实 broker 的 `capacity+1` 阻塞消费验证。该增量不使用原始 routing key/ID/error label，也不接受 D-007 未量化的积压阈值、RabbitMQ ready/unacked、独立进程 scrape 或告警。

上述容量增量已按设计 accepted，证据见[Outbox 积压与 Worker 执行容量验收](../../acceptance/arrived/024-Outbox积压与Worker执行容量验收.md)。

## 9. 告警与运行手册入口

必须预留告警规则：API 5xx/延迟、数据库/Redis 池耗尽、存储错误/孤立对象、schedule lag/misfire、Outbox 最老年龄、RabbitMQ ready/unacked、Task unknown/超时、供应商/FFmpeg 失败和 telemetry 丢弃。阈值由 PRD、压测和供应商基线确定，不在 Design 猜测固定数值。

每条告警携带 runbook_key，而不是把处理命令写进日志。运行手册至少说明影响、查询 ID、判断事实源、可安全重放条件、升级路径和禁止动作；例如 unknown 任务明确禁止重新 submit。

## 10. 部署、留存与降级

Docker 中 stdout/stderr 由容器运行时采集；应用可选配置 OTEL_EXPORTER_OTLP_ENDPOINT。没有 exporter 时服务正常启动并标记 telemetry degraded。日志驱动必须轮转，禁止无限写本机文件；日志后端、Collector 和告警接收端在 deploy Plan 中按环境配置。

运行日志和 trace 的保留期分环境配置；AuditEvent 留存由 governance 政策控制，不跟随日志清理。访问日志的个人/租户标识访问需要运维最小权限并留有平台外访问审计。

日志序列化或 exporter 异常由内部降级处理，不能递归调用同一 logger。缓冲区有界，超限允许丢运行 telemetry 并增加计数；error 写 stderr 的最后保障仍必须经过脱敏。

## 11. 测试与验收

- 单元：事件 schema、allowlist、控制字符、长度限制、敏感键和嵌套脱敏。
- API：合法/非法 traceparent、X-Request-ID、路由模板、4xx/5xx 级别与 ApiError 不泄露堆栈。
- Worker：HTTP → Outbox → RabbitMQ → Task → Provider/FFmpeg 的 trace/event/task ID 连续性。
- 故障：OTLP/日志输出不可用、缓冲区满、格式化异常不影响业务且增加失败指标。
- 指标：label 白名单和基数检查，Redis/Schedule/Task/RabbitMQ/存储结果计数与各自事实可核对。

PT-OBS-001 的当前增量以 UUIDv7 request ID、登记 access event、模板路由、字段白名单和 HTTP 低基数指标为接受边界。PT-OBS-002 当前已接受三个独立增量：HTTP server → 持久化 Outbox → RabbitMQ producer/header → IO/Media Worker consumer 的 W3C traceparent 连续性与非法入站上下文重建；Outbox/Worker 的消息结果日志与指标；MinIO/ffprobe 的子 span、登记日志和五项低基数指标。三者均不等于完整 PT-OBS-002。

Trace 增量验收必须同时验证：相同 trace ID、跨阶段不同 span ID、producer/consumer 父关系、RabbitMQ 真实 header、无 header 时的 Envelope 回退、非法 traceparent 不回显、消息业务结果不因遥测缺失而变化。消息结果增量还必须以同一 PostgreSQL/RabbitMQ 事实核对 publish/duplicate/rejected/requeue 指标和日志，证明未知事件类型不会制造新 label，且错误正文不进入日志/指标。MinIO/ffprobe 增量必须以真实私有 MinIO 的成功、拒绝、不可达操作和真实 ffprobe 的成功、工具不可用路径核对 span、日志、指标与业务结果，并证明 object key/endpoint/路径/正文不泄漏、未知 label 收敛以及观测辅助函数失败不改变结果。数据库当前只执行空库 `create_all`，未提供存量表在线迁移；Task/Attempt/Provider/FFmpeg render 子 span、Scheduler 完整根 span、OTLP exporter/Collector 故障、其余指标、生产 `/metrics` 访问边界和告警 runbook 必须在 PT-OBS-002/003 后续增量取得独立真实证据。

MVP 不建设日志搜索 UI、SIEM、自研 APM 或把全部 SQL/请求 body 打开作为调试模式。
