# DES-MOD-013 日志与可观测性详细设计

- 状态：proposed
- 日期：2026-07-27
- 覆盖需求：SYS-NFR-007、LOG-ENT-001 至 004、LOG-FR-001 至 009、LOG-IF-001 至 006、LOG-NFR-001 至 009
- 输入：[日志与可观测性需求](../../requirement/012-日志与可观测性需求.md)、[消息队列详细设计](./012-消息队列详细设计.md)
- 输出：JSON 日志、OpenTelemetry、Prometheus、关联、脱敏、告警和故障降级设计

## 1. 设计结论

日志能力属于 backend/app/core 与 Worker 组合根，不创建第十个业务模块或数据库“日志表”。Python 标准 logging 输出一事件一行 JSON 到 stdout/stderr；OpenTelemetry SDK 产生 trace；Prometheus 暴露低基数指标。具体日志检索后端和 trace 后端由部署环境选择，应用不绑定 Elasticsearch、Loki 或厂商 SDK。

治理 AuditEvent、Task/Attempt 和运行日志三者分工固定：AuditEvent 是业务审计证据，Task/Attempt 是恢复事实，运行日志用于诊断并允许按策略过期。任何业务决策不得通过搜索日志完成。

## 2. LogEvent 契约

每条日志公共字段：timestamp、level、service、component、environment、event_name、message、trace_id、span_id、request_id、workspace_id、actor_id、project_id、episode_id、task_id、attempt_id、event_id、provider_request_key、media_version_id、error_code、retryable、duration_ms、attributes。

字段只在已知时出现，空值不输出。message 是稳定短摘要，机器告警使用 event_name/error_code，不解析 message。attributes 必须来自事件级白名单并保持扁平；业务对象、ORM、Request、Exception 原始字典不能直接传入 logger。

事件命名使用 domain.action.result：例如 http.request.completed、project.archive.rejected、outbox.publish.failed、task.attempt.started、provider.submit.unknown、media.render.completed。名称由常量注册，禁止把 ID 或状态详情拼进 event_name。

## 3. 关联上下文传播

HTTP middleware 校验 W3C traceparent；缺失或非法时创建新 trace。request_id 使用 UUIDv7，响应回传 X-Request-ID。OIDC 成功后只补充内部 actor_id/workspace_id，不记录 token claims。

应用使用 contextvars 保存请求/任务上下文；创建 asyncio task、进入 ThreadPoolExecutor 或 subprocess wrapper 时显式复制必要上下文，不依赖线程本地变量。SQLAlchemy Session 只携带 trace，不向 SQL comment 注入用户输入。

Outbox 保存 trace_id，Publisher 在 RabbitMQ headers 注入标准 trace context；Consumer 提取 remote context 并创建新的 consumer span。不能复用已经结束的 HTTP span，也不能因重复投递生成错误的父子关系；event_id 始终可用于关联。

供应商、MinIO 和 FFmpeg 子阶段分别建立 span，attributes 只包含 provider、capability、task stage、对象/版本 ID、状态和耗时。提示、URL、文件路径和命令实参不得进入 span。

## 4. HTTP 与应用日志

HTTP 每个请求只记录一条 completed access event；未处理异常额外记录一条 exception event。路由字段使用模板 `/api/v1/tasks/{task_id}`，不使用含实际 ID/query 的 URL。记录 method、status_class、duration_ms、request/response_size 的受控值，不记录 body/header 全量。

业务命令在 Application Service 记录 completed/rejected/failed 结果；普通 Repository CRUD 不重复打印。状态转换日志包含 target ID、from/to status、revision、error_code 和 next_action code。成功高频列表查询默认不记录 application event，由 access log 与指标覆盖。

异常映射器记录异常类型和内部堆栈，但对外只返回 ApiError。Validation/NotFound 等预期错误为 info/warning；不可恢复内部错误为 error；不会因为客户端 4xx 打满 error 日志。

## 5. Worker 与集成日志

| 阶段 | 必要事件 | 允许字段 |
| --- | --- | --- |
| Outbox/RabbitMQ | claimed、published、received、retry_scheduled、rejected、acked | event_id、event_type、queue、attempt、duration、result |
| Task/Attempt | started、stage_changed、unknown、completed | task/attempt、input_hash、stage、error_code、next_action |
| Provider | submit/query/cancel completed/failed/unknown | provider、capability/model ID、provider_request_key、status、duration |
| MinIO | head/get/put/register failed/completed | media_version_id、operation、size bucket、duration、error_code |
| FFmpeg/ffprobe | started/completed/failed | task/render/media ID、tool version、exit_code、duration、stderr_digest |

供应商原始请求/响应不进普通日志；必要诊断以脱敏、限长摘要存 Attempt。FFmpeg 命令只记录参数 hash，stderr 先去路径/URL并限长，普通日志只记录 digest 与稳定摘要。

## 6. 脱敏和日志注入防护

格式化前递归过滤键名：authorization、cookie、set-cookie、token、secret、password、api_key、credential、presigned_url 及供应商同义字段。email、phone、subject 等个人字段默认不允许；确需安全事件时使用不可逆 hash 或内部 user_id。

剧本正文、prompt、negative_prompt、授权证明、Candidate 原始结果和媒体内容始终拒绝。所有字符串移除控制字符并限长，防止换行伪造 JSON 事件。SQLAlchemy echo 在所有环境关闭；数据库错误不打印绑定参数。

RedactionPolicy 的 allowlist 优先于 denylist：每个 event_name 声明允许 attributes。检测到额外字段时丢弃字段并递增 telemetry_redaction_drops_total，不递归打印被丢弃内容。

## 7. Trace 和采样

资源属性固定 service.name、service.version、deployment.environment、worker.kind。HTTP、应用命令、RabbitMQ publish/consume、provider、MinIO、FFmpeg 和关键数据库事务建立 span；不为每行 ORM 映射建立手工 span。

开发环境可全采样；生产采样率通过配置设置，错误与 unknown 链路应保留。采样决定不能改变 JSON error 日志和业务 AuditEvent。OTLP exporter 使用有界 BatchSpanProcessor；队列满或 endpoint 不可用时丢 telemetry 并计数，不阻塞业务线程。

## 8. Prometheus 指标

| 指标组 | 示例 | 允许 labels |
| --- | --- | --- |
| HTTP | http_server_requests_total、http_server_duration_seconds | method、route、status_class |
| 数据库 | db_pool_in_use、db_pool_wait_seconds、db_errors_total | operation、result |
| 队列 | outbox_pending、outbox_oldest_age_seconds、rabbitmq_consumer_inflight、message_results_total | queue、event_type、result |
| Task | tasks_total、task_stage_duration_seconds、tasks_unknown | task_type、stage、status/provider |
| Provider | provider_requests_total、provider_duration_seconds、provider_cost_total | provider、capability、result、currency |
| 媒体 | media_operations_total、media_duration_seconds、ffmpeg_failures_total | operation、kind、result |
| Telemetry | telemetry_export_failures_total、telemetry_redaction_drops_total | signal、reason |

禁止把 workspace_id、user_id、task_id、event_id、provider_request_key、文件名、URL 或错误正文作为 Prometheus label。`/metrics` 只绑定内部网络或经独立鉴权，不复用普通 viewer 权限。

## 9. 告警与运行手册入口

必须预留告警规则：API 5xx/延迟、数据库池耗尽、Outbox 最老年龄、RabbitMQ ready/unacked、Task unknown/超时、供应商错误率、FFmpeg 失败和 telemetry 丢弃。阈值由 PRD、压测和供应商基线确定，不在 Design 猜测固定数值。

每条告警携带 runbook_key，而不是把处理命令写进日志。运行手册至少说明影响、查询 ID、判断事实源、可安全重放条件、升级路径和禁止动作；例如 unknown 任务明确禁止重新 submit。

## 10. 部署、留存与降级

Docker 中 stdout/stderr 由容器运行时采集；应用可选配置 OTEL_EXPORTER_OTLP_ENDPOINT。没有 exporter 时服务正常启动并标记 telemetry degraded。日志驱动必须轮转，禁止无限写本机文件；日志后端、Collector 和告警接收端在 deploy Plan 中按环境配置。

运行日志和 trace 的保留期分环境配置；AuditEvent 留存由 governance 政策控制，不跟随日志清理。访问日志的个人/租户标识访问需要运维最小权限并留有平台外访问审计。

日志序列化或 exporter 异常由内部降级处理，不能递归调用同一 logger。缓冲区有界，超限允许丢运行 telemetry 并增加计数；error 写 stderr 的最后保障仍必须经过脱敏。

## 11. 测试与验收

- 单元：事件 schema、allowlist、控制字符、长度限制、敏感键和嵌套脱敏。
- API：合法/非法 traceparent、X-Request-ID、路由模板、4xx/5xx 级别与 ApiError 不泄露堆栈。
- Worker：HTTP → Outbox → RabbitMQ → Task → Provider/FFmpeg 的 trace/event/task ID 连续性。
- 故障：OTLP/日志输出不可用、缓冲区满、格式化异常不影响业务且增加失败指标。
- 指标：label 白名单和基数检查，Task/RabbitMQ/媒体结果计数与数据库事实可核对。

MVP 不建设日志搜索 UI、SIEM、自研 APM 或把全部 SQL/请求 body 打开作为调试模式。
