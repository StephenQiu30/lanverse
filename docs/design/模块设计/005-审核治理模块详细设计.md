# DES-MOD-005 审核治理模块详细设计

- 状态：部分 accepted（S2 §1–2 的 Consent/RightsGate 范围）；其余范围 proposed
- 覆盖需求：SYS-NFR-005/010；GOV-ENT-001 至 007、GOV-FR-001 至 009、GOV-IF-001 至 008、GOV-NFR-001 至 007
- 输入：[审核治理模块需求](../../requirement/005-审核治理模块需求.md)

## 1. 边界与受控对象

governance 统一权利、质量和交付门禁，但不是任意审批框架。subject_type 只允许 SCRIPT_VERSION、ASSET_VERSION、SHOT_SPEC_VERSION、CANDIDATE、MEDIA_VERSION、TIMELINE_VERSION、DELIVERY；每种类型由显式 SubjectResolver 校验 Workspace、版本存在性和允许动作，不接受表名或任意字符串。

| 聚合/证据 | 关键字段 | 不变量 |
| --- | --- | --- |
| Consent | id、workspace_id、subject_identity、status、current_revision_id | 稳定授权身份；撤销不可被原地清除 |
| ConsentRevision | consent_id、revision_no、rights_type、scope、valid_from/to、proof_media_version_ids、reason | 追加历史；范围由类型化结构校验 |
| Review | id、subject_type/id、scope、status、blocking_issue_count、revision | 一个固定版本的审核流程 |
| Issue | review_id、severity、category、target_locator、description、assignee_id、status、revision | target_locator 为按受控对象判别的位置结构 |
| Decision | review_id、action、actor_id、reason、gate_snapshot、created_at | 只追加；批准/退回/撤销均保留 |
| ModerationResult | subject、rule/service_version、status、hits、manual_disposition、request_key | 只追加；重复回调幂等 |
| Label | render_id、input/output_media_version_id、label_type、content_id、write_status、verify_hash | 只追加；验证通过才可交付 |
| AuditEvent | actor、workspace、action、target、result、trace_id、occurred_at、metadata | 只追加、脱敏、无业务正文副本 |

## 2. 授权能力

| 用例 | HTTP/内部接口 | 关键规则 | 需求 |
| --- | --- | --- | --- |
| register/update_consent | POST /api/v1/consents、POST /api/v1/consents/{id}/revisions | 新 ConsentRevision，证明媒体必须可访问 | GOV-FR-001、IF-001 |
| read_consent | GET /api/v1/consents、GET /api/v1/consents/{id} | 按 Workspace 分页读取摘要/修订历史；证明只返回 MediaVersion 引用，不返回证明原文或存储地址 | GOV-FR-001、NFR-002/005 |
| revoke_consent | POST /api/v1/consents/{id}/revoke | 追加撤销 revision，更新当前状态与审计 | GOV-FR-001/009 |
| evaluate_rights | 内部 RightsGate.check | subject、usage、at_time → allowed/blockers/consent_ids | GOV-FR-002、IF-002 |

scope 使用按授权类型区分的 Pydantic 判别联合，至少表达主体、媒体/用途、地域和有效期；未知字段拒绝。RightsGate 只判断已有授权事实是否满足指定用途，不给法律结论。撤销或过期立即阻止新的生成和交付；历史 Task、费用和交付仍保留并产生风险提示。

S2 只为已经存在的固定版本实现 `MEDIA_VERSION` 与 `SCRIPT_VERSION` SubjectResolver；其他枚举值继续保留在治理契约中，但在对应业务模块落地前返回 `DEPENDENCY_UNAVAILABLE`，不得把未实现 resolver 当作 subject 不存在或默认为通过。Consent 当前 scope 绑定一个固定 subject，更新 subject 或授权范围均追加 revision；并发更新以 Consent `revision` 比较后递增。登记和更新使用相同的 `media_usage` 判别 scope：`subject_type/id`、权利持有人角色、权利类型、用途、渠道、地域和 `valid_from/to` 均为必填且拒绝未知字段。

## 3. 审核与问题闭环

提交 Review 时解析固定 subject，计算 subject_hash，并以 workspace + subject_type + subject_id + scope + subject_hash 作为活动审核幂等范围。相同未变化版本返回既有 Review；新版本必须新建 Review。

Review 状态为 draft → submitted → approved 或 changes_requested；批准后如需撤销则追加 Decision 并转为 changes_requested。Issue 为 open ↔ resolved，修改描述/指派使用 revision；关闭必须提交 resolution。blocking_issue_count 是同事务维护的查询投影，可由 Issue 重算校验。

批准事务锁定 Review，比较 expected_revision，重新检查：没有 open blocking Issue、RightsGate 允许、最新 ModerationResult 通过。通过后追加 Decision 并更新 Review；任何门禁变化返回完整 blockers，不产生部分批准。

核心接口为 POST /api/v1/timeline-versions/{id}/submit-review、GET /api/v1/reviews/{id}、POST /api/v1/reviews/{id}/issues、PATCH /api/v1/issues/{id}、POST /api/v1/issues/{id}/resolve 或 reopen、POST /api/v1/reviews/{id}/approve 或 request-changes。它们分别落实 GOV-FR-003 至 005 与 GOV-IF-003 至 005。

## 4. 内容检查与标识

内容检查通过 Outbox 创建持久任务，request_key 绑定 subject_hash 与规则版本。结果状态 pending、passed、blocked、unknown；外部超时必须 unknown，不能默认为通过。自动结果只追加；人工处置追加新的 ModerationResult 并引用被处置结果。

交付标识用例接收固定 Delivery/MediaVersion 和目标规范，写入显式/隐式标识后通过 media 创建新的不可变输出 MediaVersion 与 Lineage，再读取验证并记录输出 hash；绝不原地修改输入版本字节。写入失败、验证失败或内容编号缺失时 Label 记录 failed，editing 不得创建成功 DeliveryManifest。对应 GOV-FR-006/007 与 GOV-IF-006/007。

## 5. 审计策略

领域用例在业务事务内追加 AuditEvent；外部异步完成同样携带 actor 或 system actor 与 trace。owner 可按受控 actor、target、action、time 分页查询；editor/viewer 只从业务详情读取必要摘要，无通用审计浏览权限。

审计 metadata 使用动作级白名单，不存令牌、授权证明原文、脸/声样本、完整剧本或供应商原始响应。留存期限或删除触发条件由统一部署策略按事实类型配置；只有用途终止且引用、计费/对账、申诉、争议、安全事件、法定义务与 legal hold 全部解除后才可由受控作业删除或匿名化，不开放用户 DELETE。

## 6. 持久化、失败和一致性

唯一约束覆盖 consent_revisions(consent_id, revision_no)、活动 Review 幂等键、moderation_results(request_key, result_sequence) 和 labels(render_id, label_type, attempt_no)。常用索引以 workspace + subject、Review status、Issue review/status 和 AuditEvent time 为主。

SubjectResolver 依赖不可用时返回 DEPENDENCY_UNAVAILABLE；资源不存在或跨空间返回 NOT_FOUND；检查未知返回 EXTERNAL_STATE_UNKNOWN；批准门禁失败返回 STATE_CONFLICT 和结构化 blockers。治理模块不缓存另一模块正文，仅在 Decision.gate_snapshot 保留当时版本 ID、hash、Consent/Moderation ID。

## 7. 测试设计

- 单元：scope 判别联合、RightsGate 有效期/用途、Review 状态机、Issue 阻塞与批准规则。
- PostgreSQL 集成：并发批准与新 Issue、重复提交 Review、Consent 撤销历史、Decision/Audit 只追加。
- Worker/契约：内容检查重复回调、超时 unknown、标识写入后 hash 验证、跨空间 Subject 不可探测。
- 端到端：授权失效阻止新生成；Issue 定位返工；新 TimelineVersion 不继承旧批准；标识失败阻止交付。

法律判断、企业 DLP、多级审批编排和任意资源审批插件不进入 MVP。
