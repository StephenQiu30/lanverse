## 1. 模块边界与事实模型

production 把固定业务输入交给受控模型能力，拥有请求、任务执行、候选选择和费用证据。RabbitMQ 消息只负责唤醒 Worker，不能代表 Task；供应商响应不能直接成为前端状态。

| 实体/值对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| ModelCapability | id、provider、model、kind、input_types、parameter_schema、limits、pricing、status、config_version | 参数白名单和价格有版本；Provider 凭据不得明文入库，密文及其版本由 [DES-009](../009-AI提供方配置与启用设计.md) 的受控凭据端口管理 |
| GenerationRequest | id、workspace_id、project_id、episode_id、shot_id、shot_spec_version_id、capability_id/config_version、parameter_snapshot、shot_spec_input_hash、input_hash、preflight_hash/expires_at、idempotency_key、warning_acknowledgements、high_cost_confirmed、requested_by | 创建后不可变；同 Workspace 幂等键唯一；Project/Episode/Shot/Spec 必须属于同一 Workspace |
| Task | id、workspace_id、task_type、request_type/id、scope、status、progress_stage、error、next_action、cancel_status、revision | 服务端事实源；主状态只按合法转换变化 |
| Attempt | id、task_id、sequence、provider_request_key、provider_task_id、status、request_snapshot_hash、error/reconcile_summary、timestamps | task + sequence、provider_request_key 唯一；外部发送前持久化 |
| Candidate | id、request_id、attempt_id、media_version_id、kind、ordinal、quality_metadata、created_at | 输出不可覆盖/删除；同 Attempt 输出槽唯一 |
| CandidateAction | candidate_id、action、actor、shot_spec_version_id、created_at、idempotency_key | 标记、选择、取消选择只追加 |
| Reservation | id、request_id、currency、estimated_amount、reserved_amount、status | 请求一个预占；当前投影受账本约束 |
| CostEntry | id、reservation_id、attempt_id、entry_type、amount、provider_bill_ref、created_at | reserve/settle/release/adjust 只追加 |
| Outbox | id、topic、aggregate_id、payload、status、attempts、available_at | 与业务事实同事务；发布可重放 |

TaskScope 的公开字段固定为 episode_id、render_snapshot_id、usage_type、usage_id、input_version_id、input_hash；非适用字段可空。它使剧本提取、镜头生成、预览和渲染使用同一任务查询与恢复契约，但不把各业务请求塞入 Task。

TaskError 固定包含 code、retryable、summary、next_action；诊断 detail 只在受控内部记录。GenerationRequest 当前用于镜头图片/视频生成；script ExtractionBatch、editing Render 等仍是各自请求实体，通过 request_type/id 关联通用 Task。AI 语音/音效生成不进入当前模块实现。

## 2. 能力目录与供应商适配

ModelCapability 的 parameter_schema 是服务端维护的受控 JSON Schema/Pydantic 模型快照，前端只能提交其中字段。能力目录 GET /api/v1/model-capabilities 支持 kind/model 筛选并返回范围、可用性、计费单位和不可用原因，不返回 endpoint、密钥或原始供应商结构。

DEV-S4-01 在 D-004 前使用两条稳定 ID 的内置不可用目录项，只公开已复核的 provider/model/kind/config_version 与 `provider_contract_unverified`；`parameter_schema` 禁止任意参数，`pricing` 为空。是否存在 `ARK_API_KEY` 不改变这两条记录的状态。只有 D-004 产出经真实账号验证的参数、价格和配置版本后，才能把新的持久化 ModelCapability 标记为 active。被新版替代的记录只停用，不覆盖或删除。

当前受控参数验证只接受顶层 object schema 中的 properties/required/additionalProperties，以及 string/integer/number/boolean 的 enum/minimum/maximum/minLength/maxLength。出现未支持的 schema 关键字时能力必须保持不可用，不允许宽松放行。无 Key 默认目录不包含未经验证的参数或价格。

每个 ProviderAdapter 实现 validate、estimate、submit、query、cancel、normalize_result；输入输出均为内部 DTO。适配器不访问 Router 和业务表，不自行扣费。供应商特有状态只保存在 Attempt 的受限诊断字段，并映射为内部状态。

下表描述各能力真正进入实现后的边界，不要求提前创建四套端口、目录或适配器。每次只为当前用例建立一个最小类型化契约，禁止 `generate(kind, payload: dict)` 万能接口：

| 端口 | 实现方式 | 典型结果 |
| --- | --- | --- |
| TextModelPort | 真实服务客户端 + Pydantic 的最小类型化适配；是否加入辅助框架遵循 DES-002 准入规则 | Pydantic 校验后的提取/改写候选 |
| ImageGenerationPort | 火山方舟 Seedream 5.0 Lite 类型化适配器；候选模型 `doubao-seedream-5-0-lite-260128` | 同步图片字节、规格与用量；无 provider task ID |
| VideoGenerationPort | 火山方舟 Seedance 2.0 类型化异步适配器；候选模型 `doubao-seedance-2-0-260128` | provider_task_id、状态、视频/尾帧与用量 |

默认不建立图编排。只有真实流程同时存在多步骤恢复、条件分支或人工介入且直接实现已经不足时，才按 DES-002 重新评审并补充独立 Design。Task/Attempt、Candidate 和 CostEntry 始终由 application service 在明确事务中写入；外部调用使用既有 provider_request_key，恢复前先读取 Attempt，不能再次付费提交。

S4 公开候选契约固定为 `cn-beijing`、`ARK_API_KEY`、上述两个模型和 `volcengine-python-sdk[ark]==5.0.43`，但进入实施前仍必须以真实账号确认模型权限、参数、回调安全、取消竞态、额度/并发和计费契约。2026-07-31 公开复核确认 `AsyncArk`、`/images/generations` 与 `/contents/generations/tasks` 资源形态；公开 SDK 不证明模型开通，也不证明精确参数和账单契约，因此 D-004 仍保持 open。通过后只增加这一套官方 SDK 和一个 ArkMediaAdapter，不同时维护手写 HTTP、`openai` 运行时或控制面 SDK。

ArkMediaAdapter 内部复用一个 `AsyncArk` 客户端，但对 application 仍暴露 ImageGenerationPort 和 VideoGenerationPort 两个窄契约。Seedream 以非流式单图 `b64_json` 返回，直接写入当前唯一 MinIO 隔离对象；Seedance 保存 provider task ID，回调仅唤醒共用对账用例，Scheduler 通过 get/list 最终收敛。供应商临时 URL 只用于下载，不作为 Candidate 或 MediaLocation 保存。精确参数白名单仅能由 D-004 真实契约样例生成，不把 SDK 所有字段自动开放给前端。

## 3. 预检与提交接口

| 用例 | HTTP 形态 | 关键结果 | 需求 |
| --- | --- | --- | --- |
| preflight_generation | POST /api/v1/shots/{id}/generation-preflight | readiness、参数校验、预计成本、blockers、确认项 | PROD-FR-001/002、IF-001/002 |
| submit_generation | POST /api/v1/shots/{id}/generation-requests | GenerationRequest + Task，快速返回 | PROD-FR-003/004、IF-003 |
| list/get_tasks | GET /api/v1/tasks、/api/v1/tasks/{id} | scope、状态、阶段、error、next_action、Attempt 摘要 | PROD-FR-005、IF-004 |
| cancel/retry/reconcile_task | 具名 Task 命令 | 最新服务端事实，不盲目重发 | PROD-FR-006/007、IF-005 |
| list/mark/select_candidate | 候选查询与具名命令 | 追加动作，保留其他候选 | PROD-FR-008、IF-007 |
| get_costs | GET /api/v1/costs | 预计/预占/结算/释放明细和汇总 | PROD-FR-010、IF-008 |

预检读取 storyboards 的固定 production snapshot，批量验证 media、governance 权利、ModelCapability 和 Workspace 预算。结果包含 preflight_hash 与 expires_at，只作确认依据；提交时必须重新读取依赖和费用，不把过期预检当许可。

DEV-S4-01 的预检请求显式携带 `workspace_id`，并固定 `shot_spec_version_id`/`capability_id`/`parameters`；服务端先做 Workspace 权限与资源归属校验，再重算 current Spec、Shot readiness、能力状态、价格快照和 Project 预算。`preflight_hash` 是使用服务端密钥对规范化事实及 `expires_at` 生成的 HMAC-SHA256，不是可修改的客户端摘要。预检不写 GenerationRequest/Task/Reservation/CostEntry/Outbox；未验证的默认方舟能力返回 blocker，不返回伪造估算。

提交事务锁定 Workspace 预算投影和目标 Shot，验证 expected_shot_spec_version_id、input_hash、警告确认、高成本确认与 idempotency_key。随后一次写入 GenerationRequest、queued Task、Reservation、reserve CostEntry 和 Outbox；任一失败全部回滚。相同键和相同规范化输入返回原请求；相同键不同输入返回 STATE_CONFLICT。

DEV-S4-01 的价格快照仅支持已持久化 active Capability 中的固定 `per_request` Decimal 金额，币种必须与 Project 一致。任何未验证计费模式使 Capability 不可提交。幂等输入摘要覆盖 Workspace/Shot/Spec/Capability 配置/参数/警告确认，不包含 Key；同键同摘要回读原事实，异摘要返回 409。Outbox 仅保存 task_id，不携带参数、提示或价格。

批量提交只是在一个 batch_reference 下执行多个独立的单镜头提交结果；一个镜头失败不回滚已明确成功的其他镜头，也不建立批任务状态机。接口返回逐项结果，用户可只重试失败项。

## 4. 任务和 Attempt 状态

Task 主状态为 queued → running → waiting_provider → succeeded、failed、cancelled 或 unknown。succeeded/cancelled 不可逆；failed 只有在确认无外部副作用且 error.retryable 时，显式 retry 才能回到 queued 并创建新 Attempt；unknown 不能直接重试，必须先对账。cancel_status 单独表达 none、requested、accepted、rejected，避免新增与主状态冲突的伪状态。

### 4.1 queued 生成取消的无 Provider 子集

`POST /api/v1/tasks/{task_id}/cancel` 仅对 `request_type=generation_request`、`task_type=image_generation|video_generation` 且仍为 `queued` 的任务执行本地取消。请求必须带 `workspace_id`、`expected_revision`、稳定幂等键和受控原因枚举，不接收自由文本。服务端先鉴权，再对 Task 行加锁；锁内验证工作空间、类型、状态和 revision，不从队列广播状态。

取消成功的单一事务必须同时：Task 转为 `cancelled/cancelled_before_dispatch/accepted`并递增 revision；active Reservation 转为 `released`并递增 revision；追加一条等于原 reserve 额的 `release` CostEntry；追加 `task.cancelled` 审计。`Reservation.reserved_amount` 保留初始经批准预占额，当前余额只由追加账本的 `reserve + adjust - settle - release` 计算。任一步失败全部回滚。

对已取消的同一 Task，后续取消请求直接回读同一 Task、Reservation 和 release CostEntry，不追加第二条账本。如 Worker 先取得行锁并把状态推进到 `running/waiting_provider`，本命令返回 409 及 `wait_for_provider_cancellation_support`，不释放预占；该分支必须等 Attempt 和真实 Provider 取消契约后再实现。Worker 消费重复消息时若读到终态，只能 ack，不得创建 Attempt 或调用 Provider。

### 4.2 Attempt 预持久化与无 Provider 失败收敛

当前增量新增真实 `prod_attempts` 事实，但只领取 D-004 之前可以证明的 `prepared → failed` 路径。表固定保存 `workspace_id/task_id/sequence/provider_request_key/provider_task_id/status/request_snapshot_hash/error_code/reconcile_summary/prepared_at/submitted_at/completed_at/updated_at`；`provider_task_id`、`submitted_at` 和 `reconcile_summary` 在本增量保持空。`(task_id, sequence)`、`provider_request_key`、`(id, workspace_id)` 唯一，`(task_id, workspace_id)` 复合引用 Task；CostEntry 的可选 `(attempt_id, workspace_id)` 同样形成租户复合外键。

`generation.requested` 使用 `lanverse.io.generation.v1` consumer。首次合法消息在事务 A 中创建 Inbox processing、锁定 Task，核对 workspace、schema、payload、`image_generation|video_generation`、GenerationRequest、active Reservation、Capability 配置版本及 input hash；然后创建 sequence=1 的 Attempt，provider_request_key 使用固定版本前缀、Workspace/Task/sequence/input hash 的 SHA-256，Task 转为 `running/validating` 并追加 `attempt.prepared`、`task.started` 审计。事务 A 提交前没有 Provider 客户端、网络或对象存储调用。

当前 composition root 没有经 D-004 验证的图片/视频 Provider 端口，因此事务 B 只执行 fail closed：锁定同一 Inbox/Attempt/Task/Reservation，把 Attempt 转为 `failed/provider_dispatch_unavailable`，Task 转为 `failed/blocked` 且 next_action=`wait_for_provider_activation`，Reservation 转为 released，追加 attempt 关联的全额 release CostEntry，追加 `attempt.failed`、`task.failed` 审计并完成 Inbox。事务 B 成功后才 ack；失败则 nack/requeue，redelivery 复用 processing Inbox 和同一 prepared Attempt 再执行事务 B。该恢复有零外部调用事实，不能外推为 Provider submit unknown 恢复。

若 Task 已 cancelled/succeeded/failed/unknown，消息只完成 Inbox 并 ack；已存在 failed Attempt 和 release 的重复消息不得新增事实。任何 `submitting/accepted/polling/succeeded/unknown` Attempt、provider_task_id、自动 reconcile、新 Attempt retry、Candidate、Media 或 settle 都继续留在 D-004 后的真实 Provider 增量。

上述 `prepared → failed` 增量已按设计 accepted，证据见[生成 Attempt 预持久化与无 Provider 失败收敛验收](../../acceptance/arrived/025-生成Attempt预持久化与无Provider失败收敛验收.md)。

### 4.3 generation 协议毒消息终止收敛

`generation.requested` 的 schema 版本错误或 payload task_id 不一致时，Messaging 先按 event_id + `lanverse.io.generation.v1` 锁定 Inbox，再通过 Production 公开用例收敛已知 queued generation Task。Production 不引用 Envelope 或 Inbox ORM，Messaging 不直接修改 Reservation/Cost，两侧仍保持显式模块边界。

终止事务固定为：queued Task 转 `failed`，progress_stage=`manual_attention`，error 使用 `unsupported_message_schema|invalid_message_payload`，retryable=false，next_action=`contact_support`；active Reservation 转 released 并追加全额 release CostEntry，`attempt_id=null`；追加 `task.failed` Audit。Messaging 在同一事务把 Inbox 置 `manual_attention`，提交后 Worker 才 ack。任一失败整体回滚并 nack/requeue。

重投依靠 Inbox 唯一约束回读，只递增 delivery attempt_count。Task 已非 queued 时，该协议错误消息只留下 Inbox 结果，不覆盖正在执行或终态事实、不释放已处置预占。无法解析的 body 没有可信 event/workspace/task ID，当前仍只能固定标签拒绝并 ack；该路径、未知 event type、重试上限和运维重放另行设计验收。

上述子集已按设计 accepted，证据见[generation 协议毒消息终止收敛验收](../../acceptance/arrived/026-generation协议毒消息终止收敛验收.md)。

~~~mermaid
stateDiagram-v2
    [*] --> queued
    queued --> running
    running --> waiting_provider
    running --> failed
    running --> cancelled
    waiting_provider --> succeeded
    waiting_provider --> failed
    waiting_provider --> cancelled
    waiting_provider --> unknown
    unknown --> waiting_provider: 对账确认已受理
    unknown --> succeeded: 对账取得结果
    unknown --> failed: 确认未产生副作用
    failed --> queued: 明确且安全的重试
~~~

Attempt 状态为 prepared → submitting → accepted → polling → succeeded/failed/cancelled/unknown。进度阶段只使用 validating、dispatching、provider_processing、downloading、registering_media、settling_cost 等可验证值，不按等待时间估算百分比。

合法转换由 Domain 函数集中校验并使用 Task revision 比较更新。任何 API/Worker 更新同时写 occurred_at 和 trace；前端不能 PATCH status、error、progress 或费用。

## 5. Worker、幂等与未知发送

1. 消费者按 task_id 读取事实；终态直接 ack，非目标状态安全忽略。
2. 短事务锁定 Task，创建 Attempt 和稳定的内部 provider_request_key，状态推进至 submitting 后提交。Ark 创建契约没有可查询的客户端幂等键，不得宣称该 key 已传给供应商。
3. 事务外调用供应商。Seedance 明确接受则保存 provider_task_id 并进入 waiting_provider；Seedream 获得结果后立即写 MinIO 隔离对象；明确拒绝则 failed。
4. 网络中断、Seedance task ID 未落库，或 Seedream 字节未写入隔离对象即崩溃时，Attempt/Task 进入 `unknown/manual_attention`；不得自动创建新 Attempt 或重发。
5. 已有 Seedance task ID 的 reconcile 通过 get/list 查询供应商；无 task ID 时不得根据时间、模型或状态模糊匹配任务。只有人工核对并确认未产生副作用后，才允许显式新试。
6. 成功结果落到 MinIO 隔离对象后，调用 media 登记 Candidate/Lineage，结算费用并更新 Task 后提交，最后 ack。Seedance 下载失败使用原 task ID 重查/重下载；Seedream 只在当前进程仍持有返回字节时重试 MinIO 写入。

RabbitMQ 使用 durable message、publisher confirm、manual ack。Outbox Publisher 通过行锁加 SKIP LOCKED 领取待发事件；确认后标记 published，超时可重发。消费者重复投递依据 Task、Attempt 和输出槽唯一约束回读结果。

I/O 队列 lanverse.io 使用有界 ThreadPoolExecutor，prefetch_count 不高于 max_workers；媒体队列 lanverse.media 的 FFmpeg/下载任务用独立子进程和更小 prefetch。并发额度按 Workspace 和全局信号量控制，具体数值留给 PRD/部署配置。

## 6. 候选选择

Candidate 媒体一旦登记不可替换。用户标记和选择以 CandidateAction 追加，当前选择是每个 Shot + usage_type 的最新有效 select/unselect 投影。select 事务验证 Candidate 属于该 Shot，GenerationRequest.shot_spec_version_id 等于用户提交的 expected 当前规格，并写选择事件；过期则 VERSION_CONFLICT。

重选不删除旧 Candidate 或旧选择证据，并通知 editing 的来源变化查询；已发布 TimelineVersion 固定 MediaVersion，不随当前选择漂移。

## 7. 费用不变量

金额使用 Decimal、固定币种和已确认精度，禁止浮点。预检只是 estimate；提交产生 reserve；供应商确认费用后追加 settle，未使用部分追加 release；账单更正追加 adjust，不改旧条目。

每个 Reservation 必须满足 reserved + adjustments = settled + released + remaining_reserved，且 remaining_reserved 不小于零。Task 终态必须使 remaining_reserved 收敛为零，unknown 可保留预占并显示原因。取消后供应商仍完成时必须登记真实 Candidate 和 settle，不能伪装无费用。

DEV-S4-01 建立 Reservation 及首条 `reserve` CostEntry，金额字段使用 `Numeric(20, 6)`/应用层 Decimal，提交时 `estimated_amount = reserved_amount = reserve entry amount`。只有“尚无 Attempt 且仍为 queued”的本地取消可以在无 Provider 条件下追加全额 release；其他 settle/release/adjust 必须由 DEV-S4-02 真实 Attempt/Provider 结果驱动。该子集不把 queued 请求伪装为已生成或已结算，也不接受 PT-PROD-006/008 全量。

## 8. 失败与恢复

发布失败保留 Outbox；已有 Seedance task ID 时供应商成功而下载失败只重查/重下载；Seedream 返回丢失则进入 unknown，不伪造可恢复返回值。媒体登记成功而费用写入失败由同库事务回滚登记关系并幂等重做；回调重复使用 provider task ID + status/updated_at 归一化，不假定供应商提供 event_id。恢复始终从 API Task/Attempt 事实出发，客户端刷新或断线不触发 submit。

安全错误为 NOT_FOUND/FORBIDDEN；参数或能力不匹配为 VALIDATION_FAILED；额度不足为 QUOTA_INSUFFICIENT；重复请求处理中为 IDEMPOTENCY_IN_PROGRESS；外部发送不明为 EXTERNAL_STATE_UNKNOWN；所有错误返回 retryable 与 next_action。
