# DES-MOD-002 用户与空间模块详细设计

- 状态：S1 accepted
- 覆盖需求：SYS-FR-001、SYS-ENT-001、SYS-IF-002、SYS-NFR-001；IDN-ENT-001 至 004、IDN-FR-001 至 009、IDN-IF-001 至 008、IDN-NFR-001 至 008
- 输入：[用户与空间模块需求](../../../requirement/arrived/002-用户与空间模块需求.md)

## 1. 边界与聚合

identity 只负责本地账号、注册邮箱所有权验证、密码认证、JWT、Workspace、Membership、ActorContext 和权限判断。邮件边界只允许发送注册验证码；不承载通知邮件、找回密码、项目 ACL，也不复制额度、任务或创作事实。

| 聚合/值对象 | 关键字段 | 不变量 |
| --- | --- | --- |
| UserAccount | id、email_normalized、password_hash、token_version、display_name、avatar_url、status、last_login_at | 邮箱全局唯一；密码只保存 Argon2 摘要；token_version 单调递增；停用不级联删除 |
| Workspace | id、name、status、revision、archived_at | active/archived；任何时刻至少一个 active owner |
| Membership | id、workspace_id、user_id、role、status、joined_at、removed_at | workspace + user 唯一；角色仅 owner/editor/viewer |
| ActorContext | user_id、workspace_id、membership_id、role | 每请求计算、只读、不持久化、不信任客户端角色 |

Workspace 是聚合根；Membership 变更在其事务边界内执行。UserAccount 独立存在，一个用户可以拥有多个 Membership。Workspace 的 owner 语义由有效 Membership 推导，不另存 owner_id，避免双写。

## 2. 用例与公开接口

| 用例 | HTTP 形态 | 权限与结果 | 需求 |
| --- | --- | --- | --- |
| register | POST /api/v1/auth/register | 原子创建用户、个人空间和 owner Membership；重复邮箱冲突 | IDN-FR-001、IF-001 |
| request_registration_verification | POST /api/v1/auth/registration-verifications | 通用接受结果；60 秒邮箱冷却与客户端来源限流；不枚举已有账号 | IDN-FR-009、IF-008 |
| confirm_registration_verification | POST /api/v1/auth/registration-verifications/confirm | 验证 6 位码并签发 10 分钟一次性注册票据 | IDN-FR-009、IF-008 |
| login | POST /api/v1/auth/login | 验证邮箱与密码，签发短期 Bearer JWT | IDN-FR-001/002、IF-001 |
| logout | POST /api/v1/auth/logout | 递增账号 token_version，使既有 JWT 全部失效 | IDN-FR-002、IF-001 |
| change_password | POST /api/v1/auth/change-password | 校验旧密码、写入新摘要并撤销既有 JWT | IDN-FR-002、IF-001 |
| get/update_me | GET/PATCH /api/v1/me | 当前用户；只允许 display_name、avatar_url | IDN-FR-002、IF-002 |
| list/create_workspace | GET/POST /api/v1/workspaces | 有效成员可读；创建者成为 owner | IDN-FR-003、IF-003/004 |
| update_workspace | PATCH /api/v1/workspaces/{id} | owner，携带 expected_revision | IDN-FR-003、IF-004 |
| archive/restore_workspace | POST /api/v1/workspaces/{id}/archive 或 restore | owner，校验期望状态，返回最新事实 | IDN-FR-007、IF-005 |
| deactivate_me | POST /api/v1/me/deactivate | 当前用户明确确认；保留业务历史 | IDN-FR-008 |
| manage_membership | P1 命令集合 | owner；行锁保护最后 owner | IDN-FR-005、IF-006 |

当前 Workspace 由每次请求的受控 header 或路由上下文给出 workspace_id，服务端据此查有效 Membership；不在 UserAccount 上保存可能过期的 current_workspace_id。缺失时，只有单一有效空间可默认选择；多空间场景要求显式选择。

## 3. 注册、登录与令牌

1. 注册先规范化邮箱，通过 SMTP 发送 6 位验证码；Redis 只保存 HMAC 摘要、60 秒冷却、10 分钟过期和最多 5 次错误状态。
2. 验证码确认成功后原子删除挑战并签发至少 32 字节、10 分钟有效的一次性注册票据；票据与规范化邮箱绑定。
3. 注册接口只接受票据、密码和显示名称；先校验密码与显示名称，再原子消费票据，使用 `pwdlib` 推荐的 Argon2 配置生成摘要。
4. 同一 PostgreSQL 事务插入 UserAccount、个人 Workspace 和 owner Membership；邮箱唯一约束负责并发冲突，失败不得留下部分事实。若票据消费后事务失败，用户重新验证邮箱，不建立跨 Redis/PostgreSQL 伪事务。
5. 登录按规范化邮箱查询账号；账号不存在时仍校验固定虚拟摘要，统一返回 `UNAUTHENTICATED`，避免通过响应和明显时差枚举账号。
6. 登录成功更新 last_login_at，并用服务端 secret 签发只含 `sub`、`ver`、`type`、`iss`、`aud`、`iat`、`exp` 的短期访问 JWT。
7. 受保护请求固定使用 HS256，并完整验证算法、签名与必要声明；随后读取 active UserAccount 并比较 `ver == token_version`。
8. 注销、修改密码或停用账号递增 token_version。MVP 不实现 refresh token、Redis 登录态、设备会话表和邮件找回密码。

JWT secret 和注册验证码 HMAC secret 只能由环境变量注入，生产值分别至少 32 个随机字节且不得复用；示例配置不得可用于生产。Redis 是新账号注册验证的 fail-closed 短期依赖，但继续不是登录、ActorContext 或既有账号认证正确性的依赖。

## 4. 权限判定

能力枚举固定为 workspace:manage、budget:manage、content:read、content:write、generation:submit、review:decide。角色到能力的映射在 identity 的显式策略函数中维护，不建立可编辑权限表。

公共依赖 require_actor 先验证 JWT，再读取用户 active/token_version，查询 workspace_id + user_id + membership active，最后校验能力。后续模块只接收 ActorContext，不重新解释 token；资源所属 Workspace 不一致统一返回 NOT_FOUND。

归档 Workspace 时禁止 content:write、generation:submit 和新增审核事实，但保留 content:read 与历史交付下载。归档时运行任务如何收敛仍是 PRD 决策；MVP 实现不得自动删除或假装取消。

## 5. 持久化与并发

必要唯一约束为 user_accounts(email_normalized) 和 memberships(workspace_id, user_id)。常用索引为 memberships(user_id, status)、workspaces(status, created_at)。password_hash 永不进入 DTO、日志或审计详情；所有时间使用 UTC，枚举由数据库约束与 Pydantic 同时限制。

成员降级/移除事务锁定 Workspace 下 active owner 集合；目标为最后 owner 时返回 STATE_CONFLICT。Workspace 生命周期命令以 revision 做比较更新。账户停用只更新 UserAccount 状态并撤销后续 ActorContext，不级联更改 Membership 历史。

## 6. 失败与审计

| 场景 | 处理 |
| --- | --- |
| 注册邮箱已存在 | RESOURCE_CONFLICT，不返回该邮箱的其他账号信息 |
| 注册验证码冷却或来源超限 | RATE_LIMITED，返回可重试等待时间 |
| 注册验证码错误、次数耗尽或过期 | INVALID_VERIFICATION_CODE 或 VERIFICATION_EXPIRED，不返回摘要或内部状态 |
| SMTP 或 Redis 不可用 | DEPENDENCY_UNAVAILABLE；新注册失败关闭，既有账号登录继续可用 |
| 邮箱或密码错误 | UNAUTHENTICATED，使用同一错误和响应形态 |
| 令牌无效/过期/版本过旧 | UNAUTHENTICATED，不创建本地事实 |
| 用户停用 | FORBIDDEN，next_action 指向账户恢复渠道 |
| Membership 已移除 | NOT_FOUND，不暴露 Workspace |
| 最后 owner 被降级/移除 | STATE_CONFLICT，返回 blocker=LAST_OWNER |
| revision 已变化 | VERSION_CONFLICT，返回最新 Workspace 摘要 |

注册、登录结果、注销、密码变更、资料变更、账户停用、Workspace 生命周期及成员操作写 AuditEvent，只记录稳定 ID、结果、变更字段名和必要前后值；不记录密码、摘要、token 或完整 claims。

## 7. 测试设计

- 单元：角色能力矩阵、归档空间拒绝规则、最后 owner 不变量。
- PostgreSQL 集成：一次性票据并发消费只生成一个用户/空间/成员；注销/改密使旧 token 失效；并发降级不产生无 owner；revision 冲突。
- Redis/SMTP 契约：不保存明文验证码；冷却、错误次数、确认和票据消费原子；TLS、超时、错误净化与本地假 SMTP 邮件内容通过。
- API 契约：发送接口不可枚举、未经验证不可注册、重复邮箱、错误凭据、非法/过期/旧版本 JWT、字段白名单、跨 Workspace 一律不可探测。
- 端到端：发送验证码 → 确认 → 注册 → 登录 → 进入个人空间 → 注销；再次登录后可创建项目；停用后历史不被删除且无法继续写入。

P1 邀请、第三方身份关联、MFA、邮件找回密码、项目级 ACL 和 SCIM 不进入当前实现设计。
