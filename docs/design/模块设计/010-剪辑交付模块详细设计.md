# DES-MOD-010 剪辑交付模块详细设计

- 状态：proposed
- 覆盖需求：SYS-FR-007/008、SYS-ENT-003、SYS-NFR-005；EDT-ENT-001 至 006、EDT-FR-001 至 010、EDT-IF-001 至 008、EDT-NFR-001 至 009
- 输入：[剪辑交付模块需求](../../requirement/010-剪辑交付模块需求.md)

## 1. 聚合与持久化取舍

editing 提供完成短剧闭环所需的基础时间线、预览、发布、渲染和交付，不实现专业 NLE。Track、Clip、SubtitleCue 是 Timeline 聚合中的类型化组成，不分别建立 Router/Service/Repository。

| 聚合/实体 | 关键字段 | 不变量 |
| --- | --- | --- |
| Timeline | id、workspace_id、episode_id、draft_document、revision、current_version_id、updated_by | Episode 唯一一个主时间线；编辑比较 revision |
| TimelineVersion | id、timeline_id、version_no、document、content_hash、source_snapshot_hash、published_by/at | 完整发布快照不可变 |
| TimelineSource | timeline_version_id、clip_id、shot_id、candidate_id、media_version_id、shot_spec_version_id、task_id | 关系化追踪每个 Clip 固定来源 |
| Render | id、timeline_version_id、kind、output_spec、task_id、status、output_media_version_id、idempotency_key | 固定版本与规格；输出不覆盖 |
| DeliveryManifest | id、render_id、timeline_version_id、manifest、manifest_hash、final_media_version_id、subtitle_media_version_id、review_decision_id、label_ids、created_at | 验证完成后只追加，不可修改 |

draft_document 和 TimelineVersion.document 使用 Pydantic 类型化 JSONB 快照，包含 tracks、clips、subtitle_cues、transitions 和 time_base，extra=forbid。MVP time_base 固定为毫秒整数，禁止浮点时间；发布时额外写 TimelineSource 关系行以支持追溯和删除阻塞。只有规模测试证明 JSONB 更新不满足目标，才考虑拆分可变 Clip 表。

## 2. 时间线文档规则

Track kind 仅 video、dialogue、narration、music、sfx、subtitle。Clip 必须有稳定 clip_id、track_id、timeline_start/end、source_in/out、media_version_id，可选 shot/candidate/shot_spec 来源、gain 与基础 transition。SubtitleCue 保存 start/end、text、speaker/type 和受控样式语义。

校验至少覆盖：ID 唯一、时间非负且 end 大于 start、source 范围不越过媒体时长、同一视频主轨不非法重叠、转场不长于相邻片段、MediaVersion ready、轨道 kind 与媒体 kind 匹配。字幕可以重叠但必须由 PRD 明确允许的规则处理。

## 3. 草稿初始化与编辑

| 用例 | HTTP 形态 | 关键结果 | 需求 |
| --- | --- | --- | --- |
| get_or_initialize_timeline | GET/POST /api/v1/episodes/{id}/timeline | 草稿、缺失媒体、来源变化 | EDT-FR-001、IF-001 |
| preview_refresh | POST /api/v1/timelines/{id}/source-refresh-preflight 或 /api/v1/timelines/{id}/source-refresh-apply | 候选变化差异；显式应用，不静默替换 | EDT-FR-001 |
| apply_operations | POST /api/v1/timelines/{id}/operations | 新 revision；任一非法操作整体失败 | EDT-FR-002/003、IF-002 |
| create_preview | POST /api/v1/timelines/{id}/previews | 播放清单或异步预览 Render/Task | EDT-FR-004、IF-003 |
| publish_version | POST /api/v1/timelines/{id}/versions | 不可变版本与发布 blockers | EDT-FR-005、IF-004 |

初始化按 Episode Shot 顺序读取 production 当前选择；每个有候选 Shot 建立视频 Clip，缺失项返回 shot_id + next_action。再次刷新只计算 added、removed、changed 建议，不覆盖用户已经裁剪、替换或调整的 Clip。

操作列表只允许 add/move/trim/replace/remove_clip、set_gain/transition、reorder_track、upsert/remove_cue。事务锁定 Timeline，比较 expected_revision，在内存应用全部操作并执行全量不变量校验，成功后整体写回 document、revision + 1 和审计；不提供 JSON Patch 或任意路径更新。

## 4. 发布与预览

发布使用 expected_revision 锁定 Timeline并重新校验：所有必需 Shot 有固定媒体、Clip 范围合法、引用仍可访问、字幕/总时长规则满足。通过后写 TimelineVersion、TimelineSource、更新 current_version_id，并调用 projects 的比较更新命令设置 Episode.current_timeline_version_id；document、来源和当前指针同事务固定。

不需要转码的低成本预览可返回短期媒体访问清单；需要拼接/降码率时创建 kind=preview 的 Render，并通过 production 通用 Task/Outbox 异步执行。预览失败不改变 Timeline，定位信息必须包含 clip_id、shot_id 和时间位置。

## 5. 审核与最终渲染门禁

submit_review 把固定 TimelineVersion 交给 governance，并返回 Review/Issue 摘要。Issue.target_locator 使用 clip_id、shot_id 和可选 time_range。用户修改草稿后发布新版本，旧 Review/Decision 不自动继承。

最终渲染预检同时验证：TimelineVersion 是请求版本、Review 已 approved、无 open blocking Issue、RightsGate 对 delivery 用途允许、Moderation 通过、所有 MediaVersion ready、输出规格受支持。结果以完整 blockers 返回；任何 blocker 都不创建 Render/费用/任务。

POST /api/v1/timeline-versions/{id}/renders 接收 output_spec、idempotency_key 和确认信息，在同库事务内创建 Render、Task 与 Outbox，快速返回。Render 查询、取消和重试复用 production 的 Task 恢复规则，但 Render 业务身份仍由 editing 拥有。

## 6. FFmpeg 渲染与恢复

媒体 Worker 从固定 TimelineVersion 构建参数数组调用 FFmpeg，不拼接 shell 字符串。Render 保存 FFmpeg/字体/滤镜版本、输入 MediaVersion hash、output_spec 和命令摘要 hash；相同输入可解释复现。

Worker 先验证/下载固定输入，再生成临时 MP4 与字幕，ffprobe 校验时长、轨道和编码，随后由 media 登记输出版本与血缘。进程中断时根据临时对象、Task 阶段和 output hash 判断继续登记或从固定版本重跑，绝不覆盖已成功输出 object key。

Render 主状态 queued → running → succeeded/failed/cancelled。纯本地进程终止可确认失败；若远程渲染将来引入，必须复用 production 的 unknown 对账语义，不能直接映射 failed。

## 7. 交付清单

Render succeeded 后，以原始渲染 MediaVersion 为输入执行 governance 标识写入与验证；标识处理通过 media 产生新的交付 MediaVersion 和 Lineage，不修改 Render 原始版本。随后创建 DeliveryManifest。manifest 至少包含最终 MP4/字幕 MediaVersion 与 hash、时长/编码、内容编号、Label、Review Decision、TimelineVersion、每个 TimelineSource 及其 ShotSpec/Asset/Task/费用追踪引用、工具版本和生成时间。

创建清单前逐项读取实际媒体 hash、标识验证结果和审核绑定版本；不信任客户端提交的清单内容。渲染输出成功但标识或清单验证失败时保留 Render 与媒体用于排障，DeliveryManifest 不创建，next_action 指向修复后重试交付装配。

下载接口返回 manifest 与由 media 生成的短期访问能力；交付对象默认私有，用户可用 manifest hash 和各文件 hash 校验。历史清单不因新渲染或授权变化被覆盖。

## 8. 并发、错误和可访问性

草稿并发使用 revision；冲突返回服务端最新 revision 与 source_snapshot_hash，不自动合并操作。发布后源 Candidate 变化只产生 change 提示。重复 Render/Delivery 命令以固定版本、规格和 idempotency_key 返回既有事实。

错误必须定位到 track_id、clip_id、cue_id、shot_id 或 media_version_id。播放器、时间定位、字幕表格、审核问题和所有命令需支持键盘操作、焦点反馈和非颜色状态表达；具体可访问性验收进入 PRD。

## 9. 测试设计

- 单元：操作归约、时间范围/轨道规则、发布门禁、source snapshot、manifest 完整性。
- PostgreSQL 集成：revision 冲突、批量操作原子性、发布快照不可变、Render/Delivery 幂等。
- FFmpeg/MinIO：固定样片预览和渲染、进程中断恢复、hash/时长/字幕验证、无 shell 注入。
- 模块契约：新版本不继承审核、授权撤销阻止渲染、候选变化不漂移已发布版本。
- 浏览器端到端：初始化 → 编辑 → 预览 → 发布 → Issue 返工 → 批准 → 渲染 → 下载清单。

专业调色、关键帧动画、插件/脚本执行、实时多人剪辑、多机位和外部渠道自动发布不进入 MVP。
