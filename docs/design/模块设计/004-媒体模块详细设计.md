# DES-MOD-004 媒体模块详细设计

- 状态：proposed
- 覆盖需求：SYS-IF-004/006、SYS-NFR-005；MED-ENT-001 至 005、MED-FR-001 至 009、MED-IF-001 至 007、MED-NFR-001 至 008
- 输入：[媒体模块需求](../../requirement/004-媒体模块需求.md)

## 1. 边界与数据模型

media 管理私有对象、不可变文件版本、探测结果和血缘，不解释角色、镜头、任务或时间线规则。业务模块只持久化 MediaVersion ID；storage profile、bucket/key、MinIO/OSS SDK 和预签名 URL 留在 ObjectStoragePort 适配器内部。

| 聚合/实体 | 关键字段 | 约束 |
| --- | --- | --- |
| MediaObject | id、workspace_id、kind、source_type、status、current_version_id | 逻辑身份；active/archived；当前版本比较更新 |
| MediaVersion | id、media_object_id、version_no、sha256、size_bytes、mime_type、probe_status、width/height/duration/codec/container、created_by | 字节内容和元数据确认后不可变；同对象版本号唯一 |
| MediaLocation | id、media_version_id、storage_profile、bucket、object_key、status、verified_at、retired_at | 同物理位置唯一；一个版本最多一个 active 位置 |
| UploadSession | id、workspace_id、storage_profile、bucket、object_key、declared_kind/size/mime/hash、status、expires_at、idempotency_key | pending → completed/expired/failed；完成结果可重放 |
| Lineage | id、workspace_id、input_version_id、output_version_id、producer_type、producer_id、transform_type、tool_snapshot | 输出 + producer 唯一；输入输出不能相同 |

probe_status 为 pending、ready、failed 或 quarantined。failed 表示原始对象仍完整但探测不可用；quarantined 表示校验或安全策略未通过，不能获取普通预览和业务引用。

## 2. 上传用例

| 用例 | HTTP 形态 | 关键结果 | 需求 |
| --- | --- | --- | --- |
| initialize_upload | POST /api/v1/media/uploads | UploadSession 和限定 object key 的短期 PUT 能力 | MED-FR-001、IF-001 |
| complete_upload | POST /media/uploads/{id}/complete | 已验证 MediaVersion；相同会话返回同一结果 | MED-FR-002、IF-002 |
| list/get_media | GET /api/v1/media、/media/{version_id} | 元数据、状态、血缘摘要，无永久 URL | MED-FR-004、IF-003 |
| create_access | POST /media/{version_id}/access | 限对象、用途、时效的 GET/preview 能力 | MED-FR-005、IF-004 |
| append_version | POST /media-objects/{id}/versions | 新版本，不覆盖原字节 | MED-FR-006、IF-006 |
| retry_probe | POST /media/{version_id}/probe-retry | 复用原始对象创建探测 Task，不重复上传 | MED-FR-003、NFR-004 |
| archive_media | POST /media-objects/{id}/archive | 禁止新引用，已有固定版本仍可读取 | MED-FR-008、IF-007 |

初始化先校验角色、Workspace active、kind、声明 MIME/大小/hash 和配额，再为当前 StorageProfile 生成不可预测 object key。前端直接上传已选对象存储；FastAPI 不代理文件字节。

完成流程锁定 UploadSession，通过 ObjectStoragePort HEAD 读取实际大小与内容类型，并以流式能力核验 sha256，不把 ETag 当内容 hash。全部匹配后在一个事务中创建 MediaObject/MediaVersion/active MediaLocation、更新 session、写 probe Outbox；对象不匹配则标记 failed/quarantined 并安排清理，不创建可用版本。

## 3. 生成和转换输出登记

Worker 先把输出写入隔离 object key，计算 hash 和规格，再调用内部 register_output。该用例校验 producer 的 Workspace 与允许类型，在同一事务中创建 MediaObject/Version/Location、Lineage 并更新生产或渲染结果；producer_type + producer_id + transform_type + output_slot 形成幂等唯一键。

数据库提交失败但对象已存在时保留隔离对象，按稳定 object key 重试登记；数据库已登记但后续对象读取失败时该 MediaLocation 进入 quarantined 并告警，不静默创建第二版本。模型生成成功但下载失败时仅重试下载/登记，不重新调用模型。

## 4. 探测与访问

图片探测读取尺寸与格式；视频/音频使用 ffprobe 获取时长、流、编码、容器和必要旋转信息。探测 Worker 按 media_version_id 幂等更新唯一探测结果；失败保存稳定错误摘要与 next_action，可重试且不覆盖字节字段。

访问命令每次重新检查 ActorContext、Workspace、MediaObject 状态、MediaVersion 状态和用途。预签名 URL 只出现在响应中，短期过期，不写数据库、不进入日志。归档对象对既有业务引用和交付仍可受控读取，但不能成为新 AssetVersion、ShotSpec 或 Timeline 草稿来源。

按业务引用筛选媒体时，由 API 组合用例先通过受控 reference_type 调用该事实所有者的公开查询取得 MediaVersion ID，再由 media 批量读取元数据。media Repository 不反向查询 assets/storyboards/editing 的内部表，也不建立需要双方双写的通用 MediaUsage 表。

## 5. 版本、血缘与清理

替换上传创建同一 MediaObject 下的新 version_no，并以 expected_current_version_id 更新指针。历史版本永不覆盖。Lineage 支持一个输出关联多个输入，每条边保存输入角色；应用层拒绝直接自环，跨多步链路由查询递归展示。

存储迁移为同一 MediaVersion 创建 verified MediaLocation，在事务中将新位置切为 active、原位置切为 retiring；MediaVersion/hash 不变。原位置只在留存窗口、引用和回滚门禁通过后进入 retired/物理清理。

MVP 只硬清理过期且未完成的 UploadSession 隔离对象。已经形成 MediaVersion 的对象不提供普通硬删除：用户只能归档，避免 media 反向依赖所有业务模块维护通用引用表。未来需要物理清理时必须先有独立留存设计和跨模块引用证明。

## 6. 持久化与安全

必要唯一约束为 upload_sessions(workspace_id, idempotency_key)、media_versions(media_object_id, version_no)、media_locations(storage_profile,bucket,object_key)、每版本一个 active location 部分唯一索引、lineage(output_version_id, producer_type, producer_id, transform_type, input_version_id)。索引覆盖 workspace + kind/status/created_at、sha256 和 producer。

开发/MVP 使用私有 MinIO bucket；上线选定 OSS 后使用私有 bucket 和 RAM 最小权限。object key 不包含原始文件名、用户邮箱或业务正文；业务模块不导入任何存储 SDK 或拼接路径。具体适配、迁移和契约见 [缓存、对象存储与任务调度详细设计](./014-缓存对象存储与任务调度详细设计.md)。

## 7. 失败与测试

对象存储不可用返回 DEPENDENCY_UNAVAILABLE 和 retryable=true；声明/实际不匹配返回 VALIDATION_FAILED；上传过期返回 STATE_CONFLICT；探测失败返回版本及 probe_status=failed，而非伪装上传失败；跨空间统一 NOT_FOUND。

- 单元：状态转换、媒体类型与用途矩阵、归档访问、Lineage 自环规则。
- ObjectStoragePort/PostgreSQL 集成：MinIO 直传、hash 不匹配、重复 complete、对象/数据库两类半失败和版本并发；上线选定 OSS 时同套契约必须通过真实 OSS。
- Worker：重复 probe/register 消息只产生一个结果，失败可恢复。
- 契约：无永久 URL、短期权限、跨空间不可访问、大文件不经过 API。

公共素材市场、网盘目录、CDN 发布、媒体编辑和已确认版本的自动物理清理不进入 MVP。
