## 首批可交付闭环

1. Go 提供 `GET /api/creation-runs/{run_id}/manifest` 和 `GET /api/creation-runs/{run_id}/steps/{step_id}/attempts`。先当前用户/项目鉴权，再用保存的 run 路由访问可信 Agent；严格校验 run/step 身份、摘要、状态与时间关系。只返回业务允许字段；不透传任意 JSON、任务正文或端点。GET 无写入、无同步提案、无模型调用。
2. 查询保留明确错误：缺运行/步骤、能力未安装、数据漂移、超时各自可判定。不得把任意远端 404 冒充 queued，亦不得把查询冲突冒充“不能恢复”。新协议不支持时明确不可用，不推断执行状态。
3. 正式 TextWorld/TextIntent 固定版本查询由各 Owner 应用用例鉴权并核验版本和 hash，支持从采纳回执反查正式内容。查不到/跨项目等价，查询不改变当前 Head 或审阅决定。

## 数据、目录和失败边界

运行追踪不新增 Go 执行表；creation/domain 保存 typed wire 和验证规则，application 定义最小读取/授权接口，adapter/agenthttp 执行签名和有界解码，adapter/httpapi 提供公共接口；bootstrap 显式注入。复用 canonical 摘要、现有授权、错误返回和 OpenAPI，不建立全局 utils/重复框架。正式版本查询沿 bible/storyboard 内层规则接数据库适配器，不通过 creation 直接查询其他 Owner 表。

远端读取有 context 和时间/响应上限，拒绝重定向、重复键、多 JSON 文档和不兼容字段。内部运行配置和凭据不返回前端。普通不存在与能力缺失根据可信协议的明确错误码区别；未知错误 fail closed。

无业务库迁移、部署或外部付费调用。实测使用现有 PostgreSQL 实例中的本任务专用临时库；真实供应商合同和模型待用户给定后接入，不能用模拟返回当成功能完成。

## 多供应商网关评估（2026-09-08 用户补充）

用户提出 Seedance、Seedream、Nano Banana、GPT Image 2 等服务统一管理。建议保留 Go ProviderGateway（Preflight/Submit/Query）作为平台业务边界；用户已接受先在 Go Generation 模块内自研薄供应商适配层；当前不部署独立网关。LiteLLM/Bifrost 仅在出现跨应用共享治理需求后重新评估。统一“可治理的调用”，不把图片编辑、异步视频和语音强压成 chat completion。

官方事实：LangGraph 定位为有状态 Agent 编排；LiteLLM 提供图片、视频及虚拟密钥/观测，视频支持矩阵列 OpenAI/Azure/Gemini/Vertex/Runway；Bifrost 有 Go SDK、多模态接口和自定义 Provider。现有资料不足以证明火山 Seedance/Seedream 的全部模型和参数开箱可用，须按具体 API 验证。GPT Image 2 官方模型页已存在；具体 Nano Banana 版本应绑定模型 ID，不用营销名作为协议版本。

项目决策边界：Temporal 继续持久编排；Go 独占 Operation/Request/Call ID、快照、权限、正式费用与额度、资产 READY、回执。网关只接管协议/路由/凭据访问和观测，网关 spend 不替代平台账本。每次运行冻结实际 model/provider/adapter/price/credential revision；查询继续用原路由和任务 ID，不能因网关别名变化重新派发。媒体提交禁用网关自动重试、fallback 和生成缓存；只在能证明未发送或拥有可核验幂等保证时由 Go 决定下一步，未知结果保留查询/人工对账。模型故障切换需要显式新决策，避免重复收费或隐式改变角色画风。

网关评测必须覆盖：原始供应商任务 ID 可追溯、重启查询、同键重复提交、超时 UNKNOWN、视频回调、参考图/多图编辑/尺寸/seed 参数、取消与输出接管、脱敏观测和单一凭据事实源。不能只用文本 chat 200 作为网关验收。

## 全后端 SOP 收敛：正式输入可执行与工程门禁

用户于本轮要求按现行 SOP 完整实现后端，延续已接受的 Go 内部薄适配层与模块 Owner 边界。首先关闭已实施代码的真实断点，再推进媒体扩展；不以模型注册或协议模拟代替完整业务验收。

新核对事实：正式 ReferenceAssetTarget 要求 NegativePrompt 非空，上轮 OpenAI 适配器拒绝该字段，使所有合法目标无法执行。修正为供应商提示由固定模板组合“生成要求”和“排除要求”，完整保留两段原文；这是自然语言表达，不宣称供应商具备独立负向提示参数或能保证绝不出现排除内容。适配器首先 ValidateGenerationTarget，保持正式目标 hash/Workspace/项目绑定；不为通过测试创建绕开领域约束的 DTO。平台 frozen input 的内容不变，供应商提示映射由适配器代码管理。

工程门禁：依照 Lint 诊断仅修正 errors.New/fmt.Errorf 的错误文本首字符，保留错误值、错误码、错误链和状态。对应测试中的文本断言同步，完整 Go 测试及 Lint 复验；不关闭规则或按目录忽略。

本次沿用 0016 PRD/Spec/Plan/Acceptance 事实入口，不另建空文档。真实 CI 与部署入口删除状态待明确；未通过不得提交为已验收任务。


部署目录决定：用户确认保留 backend 下 7 个删除并调整引用。环境组件实际所需的 6 份 Kafka/ELK 配置移交 `.github/ci/observability`，由 CI 依赖编排引用；不恢复 backend/observability，也不维护独立 deploy 目录。后端入口脚本原有的 tmpfs 私钥复制与降权行为在 Dockerfile 构建镜像时生成，删除独立源码脚本，不移除凭据权限边界。同步架构合同和环境文档，历史验收记录保留原路径作为当时证据。

上传完成需要在对象校验结束后、最终写入事务内重新鉴权和读取当前时间，避免长时间读取期间被撤权或过期仍完成；取消必须保留 context 错误链。

CI 跨服务合同修正：Go 的 TestNativeAgentCommandAcceptance 由 Python 原生进程测试驱动，普通 Go 全量运行不具备该进程参数。Backend CI 先启动专用 Creation 数据库并运行原生 Agent/Go 接受与重启测试，再运行 Go 全量。skip gate 仅增加这一条已由前置步骤实际执行的外部驱动测试，不允许整体放宽集成跳过。

上传初始化幂等：不存在 UploadSession 时行锁不能串行化相同键，两个请求会同时插入并导致唯一键错误。采用 GORM OnConflict DoNothing 和原 workspace+idempotency key 唯一约束原子争用创建权，再锁定读取实际落库会话并验证声明与状态。数据库架构禁止原始 SQL，因此不引入 advisory lock SQL 或放宽门禁；不同键独立，无重试、无额外锁表。

死信索引由环境初始化独立模板，预定义时间与有限字段，并继承保留策略；模板覆盖后续 rollover 索引。启动和查询不依赖首条非法日志触发动态映射。

环境首次建索引改用 application-000001/dead-letter-000001，满足 ILM rollover 对数字尾缀的要求；只调整新建环境，不迁移已有用户索引。依据 [Elastic rollover 官方合同](https://www.elastic.co/docs/reference/elasticsearch/index-lifecycle-actions/ilm-rollover)。
