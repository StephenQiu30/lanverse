## 1. 决策结论

### 1.1 真实完成度

Lanverse 当前已经完成的是一套较扎实的“制片前准备与任务事实底座”，不是一套已经可以生成并交付整集短剧的平台：

- 以制片前准备衡量：约完成 60%–70%；
- 以“能改写、生成、剪辑、审核并交付整集”的试运营平台衡量：约完成 25%–35%；
- 以公开商业上线衡量：还没有通过真实供应商、成片质量、生产迁移和上线合规四个决定性门禁。

容易误判的地方是：代码中已经有 audio、subtitle、render_snapshot_id、current_timeline_version_id、GenerationRequest、Task、Attempt 和费用字段，但字段或数据骨架不等于可用能力。当前没有真实图像/视频输出 Candidate，没有 TTS/字幕闭环，没有 Timeline/Render 模块，也没有完整 DeliveryManifest。

### 1.2 推荐时间口径

在本 Design 固定的 MVP 范围内，从当前代码继续建设：

| 交付层级 | 6 人推荐团队 | 4 人骨干团队 | 能对外如何描述 |
| --- | ---: | ---: | --- |
| 制作治理 Alpha | 10–13 周 | 18–22 周 | 原文→改写→叙事单元→分镜覆盖→资产状态可追溯；不含真实整集生成 |
| 单镜头生成 Alpha | 15–18 周 | 23–27 周 | 可生成并选择真实图片/视频候选；不能称作成片平台 |
| 可导出整集的内部 Beta | 26–30 周 | 40–46 周 | 内部完成一集 MP4/SRT/Manifest；大幅裁剪协作、公开合规和运营保障 |
| B2B 私有试运营 MVP | 36–42 周，约 9–10.5 个月 | 54–62 周，约 13.5–15.5 个月 | 小范围客户使用制作与导出，人工审核、迁移和恢复可用 |
| 中国大陆公开商业 GA | 46–58 周，约 11.5–14.5 个月 | 66–80 周，约 16.5–20 个月 | 还需真实用户反馈、上线材料和质量/成本二次收敛 |

上表是“逐集人工输入、单项目 1–3 集”的原始基线。若接受 DES-011 的“整剧导入并规划多少集”范围，推荐对管理层使用“6 人团队 **42–48 周**达到 B2B 私有试运营，**52–64 周**达到公开商业上线”的新基准口径；详细增量见 2.0。上一版 4–7 个月只能成立于强裁剪的内部 Alpha/Beta，不适合作为完整平台或公开上线承诺。

### 1.3 推荐团队

推荐 6 人核心团队：

1. 产品负责人兼短剧制作人：范围、剧本黄金样本、质量阈值和产品接受；
2. 技术负责人兼领域后端：修订、血缘、事务、数据库迁移和架构边界；
3. 后端平台工程师：Provider、任务、费用、媒体与生产运维；
4. 前端产品工程师：剧本、分镜、资产、候选和时间线工作台；
5. AI/媒体工程师：Prompt、语义映射、图像/视频/TTS 和 FFmpeg；
6. QA/SRE/全栈工程师：真实依赖、浏览器验收、性能、故障、安全和发布。

时间线高峰期建议临时增加一名前端/媒体工程师；此外需要兼职编剧/导演每周参与评测，以及合规/法务在 Gate 评审时参与。没有真正的短剧制作人，映射准确率和角色一致性就没有可信的产品验收人。

## 2. 估算范围和假设

### 2.0 后续范围增量说明

本章原始基线默认“单项目 1–3 集，逐集人工创建并导入”，未包含从完整长剧本自动/半自动判断集数、编辑边界并批量建集的完整模块。若按 [DES-011](./011-AI短剧核心生产模块缺口与目标设计.md) 将该能力纳入正式平台范围：

- 整剧/分集模块独立为 23/29/34 人周；
- 扣除本章 C2/C3 已计算的 NarrativeUnit、修订映射和覆盖公共能力后，全平台净增加 16/22/28 人周；
- 剩余总量由 121/172/239 调整为 **137/194/267 人周**；
- 6 人 B2B 私有试运营由 36–42 周调整为 **42–48 周**，公开商业 GA 由 46–58 周调整为 **52–64 周**；
- 原始口径仍适用于明确放弃整剧导入、只保留逐集人工输入的裁剪版。

该增量在 DES-011 接受前仍为 proposed scope delta，不静默改写本章的历史估算基线。

### 2.1 本次 MVP 包含

- 单项目 1–3 集；
- 每集 60–180 秒、12–36 个镜头，主画幅 9:16；
- 一个文本、一个图像、一个视频、一个 TTS 供应商；
- AI 改写、映射、资产和候选全部人工在环；
- 资产身份、剧情状态、不可变版本、权利与审核；
- 基础时间线：排序、trim、字幕、音量、BGM/SFX 和简单转场；
- FFmpeg 输出 MP4、SRT 和 DeliveryManifest；
- 生成血缘、费用、审核、AI 显式/隐式标识；
- B2B 制作和文件导出。

### 2.2 不包含

- 自训基础模型、LoRA 训练平台或自建 GPU 调度；
- 专业 NLE、调色、任意关键帧动画、无限画布；
- 实时多人 CRDT、复杂审批流和企业 IM；
- 多供应商自动故障切换与结果等价承诺；
- 自动申报备案、自动投流、自动发布和自营微短剧播放/付费平台；
- “一句话无人审核直接商业发布”。

### 2.3 估算规则

- 人周已包含本章的领域设计、后端、前端、OpenAPI、单元/集成/E2E、必要文档和普通缺陷修复，不再额外乘测试系数；
- 已完成的 S0–S3、Generation 预检/预占、部分 Attempt/取消/消息和 Provider 凭据底座不重复计入；
- 外部账号、合同、登记和内容审查等待不计人周，但单独计入日历缓冲；
- 人员名义数量不能直接除人周：领域冻结、Provider、真实媒体和时间线存在不可压缩先后关系；
- 团队有效产能按 70%–80% 计算，保留评审、联调、缺陷和外部等待切换成本；
- 保守估算包含一次供应商切换和一次映射/一致性重大返工，不再叠加同类缓冲。

## 3. 当前能力基线

成熟度定义：

- L0：未实现或只有 Design；
- L1：字段/数据骨架；
- L2：API 或本地纵向切片；
- L3：真实基础设施或浏览器 E2E；
- L4：生产可运营。

| 能力 | 当前真实成熟度 | 已有证据 | 不能外推 |
| --- | --- | --- | --- |
| 账号、Workspace、项目/分集 | L3 | 注册登录、租户隔离、生命周期和浏览器 E2E | 没有完整成员邀请/角色管理 |
| 人工剧本版本与结构提取 | L3 | 不可变 ScriptVersion、DeepSeek 提取、候选决议、确认结构 | DeepSeek 明确只提取，AI 改写是 L0 |
| 人工资产与授权 | L3 | 六类 Asset/Version、MinIO、Consent、RightsGate、readiness | 没有 AssetState 和生成候选主选 |
| 手工分镜准备 | L3 | Shot/ShotSpecVersion、稳定 ID、拆合排序、readiness | 没有叙事单元覆盖和跨改写修订映射 |
| 生成请求事实 | L2–L3 | 预检、费用预占、Task/Outbox/Attempt、排队取消和失败收敛 | 没有真实 Provider 成功输出 |
| Provider 管理 | L1–L2 | 四类 ORM 和 AES-GCM 凭据底座 | 没有 Repository/API/UI、健康、Binding runtime |
| 图像生成 | L0 输出 / L2 底座 | Seedream Capability 仍 unavailable | 无 Candidate、媒体血缘和主选 |
| 视频生成 | L0 输出 / L1–L2 底座 | 异步 Task/Attempt 模型存在 | 无 submit/poll/download/selection E2E |
| 音频字幕 | L1 | Voice Asset、audio/subtitle 类型和意图字段 | 无 TTS、Cue、对齐、混音、导出 |
| 时间线渲染 | L0–L1 | 只有 current_timeline_version_id 等占位 | 无 editing Router/Model/页面/FFmpeg Render |
| 审核与交付 | 权利 L3；成片 L0 | Consent、Audit | 无 Review/Issue/Label/Manifest |

实际关键路径：

迁移与领域冻结 → 改写/叙事单元 → max(分镜覆盖, 资产状态) → 真实 Provider/图片 → 视频/音频 → 时间线/渲染 → 合规交付 → 生产试运营。

外部并行路径：

- 供应商账号/合同/黄金实验 → C5；
- 属地网信咨询/发行伙伴 → C8/公开 GA。

可并行：

- C1 前端与 C2 后端契约重叠；
- C3 和 C4 两队并行；
- C5 的 Provider 控制面、Candidate 数据和供应商 PoC 并行；
- C6 视频与 TTS/字幕并行；
- C7 时间线模型/前端骨架可以在 C6 后半段开始；
- C8 的权利/标识规则和 C9 的迁移/观测从早期持续推进。

不可提前接受：

- NarrativeUnit 身份未冻结前，不能稳定接受跨修订映射；
- Coverage 和 AssetBinding 未就绪前，不能声称镜头 ready for production；
- 真实参数、价格、权利和失败语义未核验前，不能接受 Provider；
- 没有已选视频/音频版本，不能接受 Timeline/Manifest；
- 没有真实样片、备份恢复、故障演练和合规出口，不能公开试运营。

## 7. 外部卡点与日历缓冲

### 7.1 供应商

供应商策略需要在 C0 重新决策。当前仓库把 Seedream/Seedance 作为唯一候选，但公开接口存在不等于商业权利成立。至少应同时评测两个可签约候选，首期只集成一个主供应商，另一个仅做已签约/已验证的降级备选，不做自动路由。本章是待接受的建议，尚未修改 DES-005 中已接受的 D-004 门禁。在拿到书面合同前，不应把任何模型写成商业生产默认值。

| 卡点 | 阻塞 | 最短 | 计划最坏值 | 验证 |
| --- | --- | ---: | ---: | --- |
| API 账号、模型权限和额度 | C5/C6 | 当天 | 2–6 周 | 企业账号真实调用和模型授权 |
| 商业发行、客户代制作和输出转授权 | C5/C8 | 3–5 日 | 2–6 周或不可获得 | 订单/补充协议，不以 API 200 代替 |
| 图像/视频质量 | C5/C6 | 5 日 | 换商与重评 4–6 周 | 24 镜头黄金实验 |
| 并发/限流和长任务 | C6 | 2–5 日 | 扩容 3–5 工作日以上 | 1/5/10/15 并发、丢回调与轮询 |
| 真实账单和失败/取消计费 | C5/C6 | 1 周 | 2–3 周 | 逐请求对账 |
| 模型下线/价格变化 | 试运营 | 持续 | 切商增加 3–6 周 | 固定模型/价格版本和回归 |

[阿里云百炼视频 API](https://help.aliyun.com/zh/model-studio/image-to-video-general-api-reference)公开说明了异步任务和结果 URL 有效期；[MiniMax 视频生成](https://platform.minimaxi.com/docs/guides/video-generation)也采用 task → status → file 的异步流程。二者只能作为候选，最终选择仍须合同、质量、价格和数据条款评审。

### 7.2 AIGC 标识与公开 AI 服务

[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)自 2025-09-01 施行。面向下载/导出的产品需设计可见标识、文件元数据、内容编号和相关日志。首个闭环工程可在 1–2 周实现，但必须经过“导出→再次转码→下载→重新检查”验证，不能只看本地播放器。

若 Lanverse 只作为团队内部/B2B 制作导出工具，公开 AI 服务登记通常不是内部 MVP 的阻塞项；若面向中国大陆公众直接提供生成 SaaS，应在 C0 就向属地网信部门确认登记/备案路径，并为公开公测预留 1–3 个月。全国公开资料没有统一办结 SLA，因此这部分不能压缩为确定开发工期。

### 7.3 网络微短剧发行

按照广电主管部门现行[网络微短剧管理提示](https://www.nrta.gov.cn/art/2025/2/5/art_113_70148.html)，播出或引流的微短剧需要相应发行许可或上线备案信息。Lanverse 首期应保持“制作和导出工具”边界，由制作方和播出平台承担具体发行流程；如果自建观看、付费或投流平台，产品责任和实施范围会显著扩大。

每部真正公开发行的作品在画面锁定后，还需要为平台/主管部门审核预留约 20–50 日；整改后按 2–3 个月计划。这是综合地方公开办事指南得出的项目规划缓冲，不是对 Lanverse 的官方 SLA：[北京指南](https://banshi.beijing.gov.cn/pubtask/task/1/110000000000/87cdb786-ae6e-404f-82ad-9611b26b844e.html)列出 20 个工作日的市级承诺环节（不含总局环节），[上海指南](https://zwdt.sh.gov.cn/govPortals/bsfw/item/0e044fff-da40-425a-9bf9-faed54a3bf1c)列出 30 个自然日承诺时限和 50 个自然日法定时限。该时间属于内容发行周期，不应混入软件开发人周。

### 7.4 权利

自有原创剧本、虚构角色和设计音色可把授权等待控制在 0–5 天。真人肖像/声音复刻、第三方网文、明星参考和商业音乐可能需要 1–3 个月，也可能最终无法授权。资产入库必须记录用途、平台、地域、期限、是否可转授权、供应商处理和撤回/删除。

## 10. 管理方式

每章不是一个长期大任务。接受本 Design 后，应按下列规则执行：

1. C0 先形成迁移决策、黄金样本和供应商 PoC，不直接创建十章全部目录；
2. 每章只拆当前可执行的 1–2 周纵向 DEV-*，同时交付后端事实、OpenAPI、前端、失败恢复和验证；
3. 每两周重估剩余工作，不改变历史基线；记录范围变化、实际人周和估算偏差原因；
4. 每个 Gate 都可裁剪或终止后续投资；外部等待时推进不依赖它的领域/UI/测试，不用 mock 冒充验收；
5. 进度分别报告“代码骨架、真实 E2E、质量通过、生产可运营”，不得用单一百分比掩盖能力差异；
6. 任何新增范围必须明确它替代或推迟哪个章节，否则不进入当前 MVP。

## 11. 推荐决策

1. 逐集人工输入裁剪版以 6 人、36–42 周作为 B2B 私有试运营基准；若接受 DES-011 整剧/分集范围，改用 42–48 周和公开 GA 52–64 周；
2. 首期保持 B2B 制作与导出工具，不自建播出/投流平台；
3. 立即先做 C0：schema migration、NarrativeUnit、统一 Candidate/Selection/MediaLineage、黄金样本和双供应商商用 PoC；
4. C1–C4 是最重要的产品差异化，不因 Provider 未到位而等待；
5. C5–C6 采用单一主供应商 + 一个已验证备选，不做首期自动路由；
6. C7 严格限制为窄时间线，否则排期至少额外增加 6–10 周；
7. 自动映射和一致性不达标时优先降级到人工在环，不牺牲血缘与可恢复性。

只有在用户接受本工期和范围基线后，才更新 PRD/PLAN 中的切片范围并进入 C0 实施。
