## 1. 结论

Lanverse MVP 的前端主产品固定为项目级 Guided Studio，不是 Episode-first 的分散工具页，也不是 StoryGraph Canvas。用户进入一个项目后，只需要理解五个稳定的决策 Gate：

```text
1. Structure & Identity
2. Bible & Continuity
3. Visual Foundation & Scope
4. Reference Selection
5. Storyboard
```

页面围绕一个问题组织：

> 当前项目距离“可直接进入分镜的视觉生产包”还缺什么，我现在需要做哪个决定，这个决定会创建什么正式事实，又会让什么结果失效？

目标信息架构：

```text
Project Overview
  → Guided Studio /production
      ├── Five-Gate Timeline
      ├── Scope Navigator（Project/Episode/Scene/Target）
      ├── Gate Work Surface
      ├── Decision/Coordination Bar
      └── Impact & Evidence Drawer
  → Asset Library（Character/Location/Prop）
  → Review Inbox（同一 Gate Renderer 的任务入口）
  → Provider Settings（次级运维入口）
  → Story Lens（次级只读追溯入口）
```

五 Gate Timeline、Reference Coverage Matrix 和所有完成状态必须来自 Backend typed Query；前端不抓取多张列表后推断 readiness，不维护自己的 Gate 状态机。用户决议后必须分别显示：

```text
决议已记录
→ 业务效果提交中/已提交
→ 工作流恢复中/已继续
```

Gate 4 不提供“批准全部参考”按钮。每个 exact Reference Target 有独立 Candidate compare/Decision/Owner Apply；整个 Gate 4 只有在基础 checkpoint、逐 Scene 组合 checkpoint 与 required coverage 都闭合后才显示完成。

MVP 首要价值是完整剧本拆解、人物多形象、地点、道具、人物拿道具组合和精确分镜输入。Provider 数量、价格、支付、Shot Video 与 Canvas 编辑不占主导航，也不阻塞产品闭环。

## 2. 设计原则、范围与非目标

### 2.1 设计原则

1. **决策优先**：页面标题、主操作和状态都围绕当前用户决定，不暴露 Agent Stage/DAG 名称；
2. **来源可见**：每个可审核值都能看到 Evidence 或 creator decision，缺失显示 Design Gap；
3. **版本精确**：UI 可以说“当前采用”，但必须同时展示 exact version/revision/hash，不以 latest URL或名称替代；
4. **影响先于提交**：split/merge、Preset switch、State/Interaction 修改、重生成和替换参考前先显示 Backend impact preview；
5. **状态分层**：Task、Decision、Effect、Resume、Owner readiness 和 Workflow status 不合并；
6. **局部可继续**：一个 Scene/Target blocked 不遮蔽无关 scope 的可处理任务；
7. **可访问且可降级**：比较图、矩阵和时间线都有等价表格/文本路径，不依赖颜色、拖拽或 Canvas；
8. **复用现有产品语言**：沿用当前 Geist、grayscale token、Card/Item/Table/Badge/Dialog/Alert、StudioShell/PageHeader 与 Lucide，不发明新主题。

### 2.2 本文范围

- 项目级 Guided Studio 路由、导航、页面壳和五 Gate 信息架构；
- 五个 Gate 的核心视图、交互、决议和结果反馈；
- Reference Coverage Matrix、Candidate Bundle compare 和 Interaction Composition 审核；
- Character/Location/Prop 卡与 Scene readiness 深链；
- Review Inbox、Provider Settings、Story Lens 的次级入口边界；
- RTK Query/URL/本地状态所有权和精确 invalidation；
- loading/empty/stale/unknown/conflict/权限/媒体失败路径；
- 响应式、无障碍、性能、安全、可观测性和验证门。

### 2.3 非目标

本文不设计或授权：

- 可写 Canvas、自由拖拽 Graph、多人协作、评论、Presence 或 Yjs；
- 新视觉品牌、配色、字体、圆角、插画体系或移动原生 App；
- 浏览器直连 Agent、Provider、Temporal、Kafka、Elasticsearch、PostgreSQL 或对象存储私有地址；
- 前端自建业务 DTO、Owner Repository、Gate 状态机、readiness 规则或 dependency closure；
- 付费墙、套餐、余额、单价比较、Cost Dashboard 或以价格控制生成；
- Shot Frame/Video、音频、口型、成片渲染和最终交付中心；
- 为未来页面预建空路由、通用 `UniversalRenderer`、第二 Query 库或兼容双路由；
- 使用 mock、静态成功 toast、占位图或旧 Draft/Detail 结构冒充新闭环。

## 3. 当前产品事实与原子切换

### 3.1 可复用事实

当前仓库已有：

- `StudioShell`、全局 header、项目 context bar、`PageHeader` 与响应式基础布局；
- `Button/Card/Table/Badge/Alert/Dialog/Command/Item` 等现有 UI primitives；
- `/projects/:projectId` 项目工作区、原稿导入、Episode 列表；
- `/projects/:projectId/reviews` Review Workbench，已能显示 Task/Decision/Owner Apply/Resume 的初步三阶段状态；
- `/studio/:episodeId/*` Episode 页面和历史 Script/Assets/Storyboard/Media/Tasks panel；
- OpenAPI 生成 Schema、RTK Query `appApi` 与独立 `frontend/tests`；
- 明/暗模式和现有 Geist/中文 fallback 字体。

### 3.2 必须替换的旧主链

以下现状不能继续成为新 run 的主流程：

- 全局顶栏“剧本解析→资产→分镜→生成→审核→交付”六阶段；
- Episode Studio 的 Bible-first、Storyboard Draft、`needs_asset`、Reference Asset、Detail Shots；
- `workflow_node_output|generation_candidate_selection` 两类宽泛 renderer；
- 页面内手写 DTO、直接 `/api` Request 和本地拼装 readiness；
- composite reference sheet、Cost/Quota/Shot Video 为主的媒体页；
- Decision 成功后只靠 toast 推断 Owner Apply/Workflow 已继续。

新 production Workflow cutover 后只进入五 Gate Guided Studio。旧非终态 run 仍由精确旧 route/runtime 恢复或明确终止；新页面不兼容读取旧 Subject 并伪装升级。旧页面引用归零后按 Plan 独立删除，不双写 legacy/production Decision、Target 或正式 Result。

### 3.3 设计系统继承

VP-D12 不定义视觉新方向。实现必须：

- 继续使用 `globals.css` 的 semantic color/radius/font token；
- 优先组合现有 UI primitives，不复制 Button/Card/Dialog；
- 继续使用 `LayoutContainer/StudioShell/PageHeader` 的内容宽度、页眉和项目上下文；
- 将五 Gate progress 作为 project-context production navigation，非项目页面不展示；
- 新增组件只因真实消费者和复用关系建立，不预建“Design System production”。

## 4. 路由与导航

### 4.1 唯一主入口

目标路由：

```text
/projects/:projectId
├── /production                         # Guided Studio 唯一主入口
│   ?gate=structure-identity|bible-continuity|visual-foundation|reference-selection|storyboard
│   &scopeKind=project|episode|scene|target
│   &scopeId={stable-id}
│   &task={human-task-id}
│   &focus={stable-field-or-issue-key}
├── /assets?kind=character|location|prop&status=...
├── /assets/:assetId
├── /reviews?status=...&gate=...&task=...
├── /provider-settings
└── /storygraph?version=...&lens=...&scopeKind=...&scopeId=...
```

`/projects/:projectId` 保留项目摘要和唯一“继续制作”入口；Backend `next_action` 决定链接到哪个 Gate/scope/task，前端不按本地优先级猜测。`/production` 是新 run 的唯一 Guided route，不再为五个 Gate 建五套独立页面状态机。

现有 `/studio/:episodeId/*` 只承载旧 run 恢复直到 cutover 完成。production Scene/Episode 深链都回到 project `/production`，scope 写入 URL；不建立新旧兼容 alias。

### 4.2 项目导航层级

项目 context 下的一级入口保持精简：

| 入口 | 用户问题 | MVP 权重 |
|---|---|---|
| 制作 | 下一步做什么决定，哪里被阻断 | 主入口 |
| 资产 | 人物/地点/道具有哪些状态与已选视觉版本 | 次入口 |
| 审核队列 | 我有哪些可处理任务 | 次入口 |
| 追溯 | 正式事实从哪里来、影响什么 | 次入口，只读 |
| 项目设置 | Provider/Project 配置是否可用 | 次入口 |

Provider 不作为制作阶段，Story Lens 不作为 Gate。全局顶部的五 Gate progress 只表达当前 Project 的产品进度，不替代页面内 scope/task 状态。

### 4.3 可分享 URL

URL 只拥有稳定导航意图：gate、scope、task、focus、版本和筛选。不得写入：

- Claim Token、Access Token、API Key、Prompt、图片 URL；
- Candidate/Owner 完整 JSON；
- 临时候选 hover/zoom/viewport；
- 未提交的 typed form 值；
- “第几个数组项”这种不稳定 identity。

越权/不存在的 scope 由 Backend 防枚举；路由不能回退到最近项目或第一个可见对象。

## 5. Guided Studio 页面壳

### 5.1 页面结构

桌面信息架构固定为：

```text
Project Context Header
Five-Gate Timeline
┌──────────────────┬────────────────────────────────┬──────────────────┐
│ Scope Navigator  │ Gate Work Surface              │ Context Rail     │
│ Episode/Scene/   │ Review View / Matrix / Compare │ status, source,  │
│ Target/Issue     │                                │ next action      │
└──────────────────┴────────────────────────────────┴──────────────────┘
Decision & Coordination Bar（sticky within content）
Impact / Evidence Drawer（按需打开）
```

不规定新的像素尺寸、颜色或 card style；实现沿用现有 layout/token。结构职责固定：

- Scope Navigator：只显示 Backend 返回的 scope tree、ready/blocked/stale/count；
- Work Surface：当前 Gate 的 typed View；
- Context Rail：exact version/read set、当前问题、允许决议、业务结果摘要；
- Decision Bar：Claim、allowed decision、expected revision、Decision/Effect/Resume 状态；
- Drawer：Evidence、Impact、Lineage、历史 Decision，不遮蔽确认风险。

### 5.2 Five-Gate Timeline

`GetGuidedStudioTimelineView` 返回每个 Gate 的：

```text
gate_key / label
status
ready_scope_count / blocked_scope_count / stale_scope_count
active_task_count
completed_checkpoint_refs[]
primary_blocker_code?
next_action
read_set_hash
```

Timeline status 只允许：

```text
not_started | preparing | ready_for_review | in_review |
decision_recorded | applying | resuming | partially_complete |
complete | blocked | stale
```

前端不从 HumanTask 数或 Workflow 百分比计算这些值。每一步同时显示 icon + text + count；颜色只是辅助。Gate 4 可以 `partially_complete`，Gate 1/2/3 的 partial scope 也必须显示明确覆盖分子/分母，不能只给一个百分比。

点击 Timeline 只改变 URL/Query，不触发 Workflow。未来 Gate 在前置未满足时仍可只读查看 blockers/历史，不自动跳转或隐藏。

### 5.3 Decision & Coordination Bar

Decision Bar 消费 D11 `HumanGateCoordinationViewProduction`：

| 阶段 | 文案 | 主操作 |
|---|---|---|
| Task OPEN | 待领取 | 领取审核 |
| CLAIMED by me | 可决策至 lease expiry | allowed decisions |
| CLAIMED by other | 正由某成员处理 | 只读/刷新 |
| Decision recorded | 决议已记录，尚未完成业务提交 | 查看 Effect steps / 恢复 |
| Effect applying | 正在提交正式业务效果 | 禁止第二 Decision，按原 Decision 对账 |
| Effect completed | 业务效果已提交，工作流恢复中 | 查看 Owner refs / 恢复 |
| Resume unknown | 是否已继续尚不可确认 | 按原 Decision 恢复 |
| Resume completed | 工作流已继续 | 打开下一个 Backend next_action |
| conflict/stale | 旧决议不能套用新事实 | 查看变化/新 Task |

`approved|selected` 只有在 Backend `allowed_decisions[]` 包含时出现。`changes_requested` 打开 gate-specific typed form；`rejected` 需要 reason code。任何 Decision 都先展示“将创建/不会创建的正式结果”和 impact preview hash。

## 6. Gate 1 — Structure & Identity

### 6.1 用户目标

用户确认整份原稿的 Episode/Scene 边界与全局 Character/Location/Prop 身份，不在此阶段设计造型。

### 6.2 Work Surface

```text
Source Coverage Panel
├── 原文段落与 code-point Evidence 高亮
├── Episode/Scene span outline
└── uncovered/overlap/boundary issues

Identity Resolution Panel
├── raw mention cluster table
├── proposed canonical identity/type/aliases
├── same-name split / alias merge / explicit reuse
└── impacted scene scopes
```

默认以 issue-first 列表引导，不要求用户浏览整个 Graph。选择一条 issue 后，原文、Scene span、mention cluster 和 Impact Drawer 使用 stable ref 同步定位。

### 6.3 允许交互

- 查看 Evidence 与候选差异；
- typed changes requested：Scene split/merge proposal、Identity merge/split/rebind、resolve/unresolve；
- approved/rejected（仅 Backend allowed 时）；
- scope 切换和历史 Candidate/Decision 对比。

split/merge 不直接移动前端数组或写正式 ID；提交 changes_requested 后显示“新候选生成中”，旧 Subject 保持只读。approved 前展示将先提交 Project Episode，再提交 StructureIdentitySet 的两个 Effect step；第一步成功/第二步恢复中必须分别可见。

### 6.4 通过反馈

完成后展示 exact Project Episode Receipt、StructureIdentitySetVersion、覆盖 scope 与下一步。未在批准 closure 的 unresolved identity 清晰标为局部 blocked，不把未决项从列表消失。

## 7. Gate 2 — Bible & Continuity

### 7.1 用户目标

用户确认人物多形象、地点/道具状态、每场 Occurrence、人物—道具 Interaction、持有/使用和前后连续性。

### 7.2 Work Surface 模式

同一 Gate View 提供五个互相深链的视图，不复制数据：

| View | 核心内容 | 关键问题 |
|---|---|---|
| Production Entity | Identity、Specification、Evidence/Design Gap | 这个对象是什么，哪些描述来自原文 |
| State Timeline | 每个 AssetState、story-time range、before/after/cause | 何时换装、受伤、损坏或恢复 |
| Scene Occurrence Matrix | Scene × Identity/State/Specification | 每场实际出现的是哪个精确状态 |
| Interaction Ledger | actor/prop/counterparty、holder、hand、grip/use/transfer | 谁在哪一刻拿着/使用/交给谁 |
| Continuity Issues | 相邻 Scene/StoryTime boundary 的 Delta/blocker | 状态变化是否有原因和闭环 |

“持有账本”是 Planning typed View，不是可拖拽前端表。双 holder、道具瞬移、无因换装和伤势恢复必须有明确 issue code、Evidence/Claim 和影响 Scene。

### 7.3 Design Gap 与 creator decision

每个缺失字段显示：原文未说明、已知约束、可选 typed value、影响 scope 和允许来源。用户补充的创作决定进入 Decision `CreatorDecisionEntryContract`，提交前预览目标 Owner/field 和下游影响；自由文本 note 不自动成为事实。

### 7.4 决议与结果

changes_requested 使用 State boundary/snapshot、Occurrence rebind、Interaction/Continuity typed form；approved 只在 expected business key/continuity blocker 闭合时出现。Effect applying 时分别展示 Bible/Planning/Asset 三 Owner 的原子组，不显示“已部分写入”。成功后展示 ProductionBibleVersion、Scene/Occurrence/Claim roots、AssetIdentity/State roots 和 partial/full scope coverage。

## 8. Gate 3 — Visual Foundation & Scope

### 8.1 用户目标

用户选择世界观/视觉基底预设，处理与剧本事实的冲突，补齐已授权视觉空白，并确认六类 Reference Target 的生成范围。

### 8.2 Preset Gallery

Preset 卡复用现有 Card/Badge/图片组件，必须展示真实策展内容：

- 名称、一句话特征、适合媒介/题材；
- 人物、地点、道具、场景的有权利预览；
- 建筑、服饰、道具、材质、色彩、光照和构图语言；
- 六类 Target/view-role capability matrix；
- 默认 faithful/world_adaptation 模式；
- 版本、来源/权利和变更摘要。

卡片不展示 Provider 品牌、价格或自由 Prompt。选择卡片只更新当前 Gate 的 typed proposal；未提交 Decision 前不改 Project Style 或触发 Generation。

### 8.3 Foundation Comparison

Work Surface 分三列/三个逻辑区域：

```text
Source Fact              Proposed Visual Design        Decision/Impact
原文/Evidence/Gap        Preset + typed override       keep/change/reject
```

faithful 模式中 source fact 冲突必须阻塞 approved；world_adaptation 每项显示 source→design mapping、语义不变量和影响 scopes。`preset_capability_missing` 时 Task 只显示 changes_requested/rejected，不显示 approved。

### 8.4 Reference Scope Matrix

矩阵行使用 stable Target business key，至少显示：

```text
target kind
identity/specification/state or scene/interaction
coverage scopes
fulfillment = required | optional | not_generated
depends_on target keys
preset capability
design gap / issue count
```

用户可以 typed 修改 fulfillment/scope，但 Backend 必须重新生成 expected target key set/new Candidate；前端不能直接增删数组行。mentioned_only 默认不生成；若要制作，界面引导返回 Gate 2 创建可审计视觉 Occurrence，不允许 Gate 3 偷加目标。

### 8.5 结果

approved Effect 同时展示 Preset/Reference 两个 Owner 的事务状态。完成后固定 EffectiveStyleSnapshot、EffectivePolicySnapshot、ApprovedReferencePlanVersion 和六类 Target coverage；主 CTA 进入 Backend 返回的首个 Wave A Target，不直接“生成全部”。

## 9. Gate 4 — Reference Selection

### 9.1 Coverage Workspace

Gate 4 默认是 Reference Coverage Matrix，不是图片瀑布流。每行代表 exact Target：

| 列 | 内容 |
|---|---|
| 目标 | kind + Identity/State/Scene/Interaction label 与 business key |
| 范围 | Episode/Scene coverage |
| 计划 | required/optional/not_generated |
| 依赖 | anchor/base target/result exact refs |
| 生成 | target round/execution/provider availability，不显示价格 |
| 审核 | CandidateSet/Task/Decision |
| 正式结果 | AssetVersion 或 ReferenceBinding exact ref |
| 状态 | planned/generating/awaiting_selection/selected/owner_applied/blocked/stale/skipped |

分组固定为 Wave A identity-anchor/location/prop、Wave B appearance、Wave C scene/interaction composition。依赖未完成的行显示所缺 exact Target 和可深链操作，不显示无效“生成”按钮。

### 9.2 Candidate Bundle Compare

打开一个 awaiting_selection 行后，Work Surface 使用“候选方向为列、required view role 为行”的比较结构：

```text
                     Candidate A   Candidate B   Candidate C
front                image         image         image
profile              image         image         image
back                 image         image         image
bundle review        issues        issues        issues
```

Location Board 为 `empty_establishing/spatial_orientation/material_scale_detail`；Prop Sheet 为 `front/side/back/state_detail`；Scene/Interaction Composition 为 `composition_master/interaction_master`。前端不得跨 Candidate 拼 front/profile/back，也不得选择单一 slot。

比较能力：

- 同步 zoom/pan、原尺寸/裁切安全区、媒体 metadata；
- exact Target/Brief/Style/Policy/dependency摘要；
- deterministic QC 与 bundle-level Vision Review 分层；
- issue 区域标注、pass/warn/fail/not_assessable；
- rights/lineage、generation round、历史 CandidateSet；
- 与当前 active Result 的差异和替换影响。

只有 complete、deterministic passed、无 Vision fail 的 Bundle 可选择。warn/not_assessable 必须逐项勾选确认；UI 不提供“忽略全部”。

### 9.3 Character 多形象审核

Identity anchor 比较突出脸部结构、体型/比例、永久标记和 front/profile/back 一致性。Appearance 比较同时固定展示所依赖 anchor AssetVersion，并把 invariant 与 variable slots 分区；出现换脸/体型漂移时不允许选择。

一个 Character 页面上只存在一个 Identity；anchor 与不同 Appearance State 以版本/状态分组，不创建多个近似角色卡。

### 9.4 地点与道具审核

Location Board 必须能并排检查拓扑、入口/出口/区域、尺度、材质和空场策略；人物污染显示 Vision fail。Prop Sheet 显示尺寸、结构、开闭/损坏/内容物 State 和 no-hands/no-people policy；手/人物污染或多个 State 混杂不能选择。

### 9.5 人物拿道具的 Interaction 审核

Interaction Composition 详情固定显示：

- actor/counterparty/prop exact Occurrence；
- selected Character Appearance/Prop AssetVersion；
- holder、hand side、grip/contact point、orientation、scale、transfer/use state；
- `interaction_master` 全图和 Vision issue region；
- 相邻 Scene 的 before/after holder/PropState；
- 选择后将创建的 InteractionReferenceBindingVersion。

用户不能把“拿着道具”保存为新 Character Appearance，也不能在此换另一个未进入 Target dependency 的 AssetVersion。request upstream change 先打开 Impact Drawer，再走新上游 Result→Brief→Target round。

### 9.6 Decision、Effect 与 Gate 完成

selected 后按 D11 显示两步：

```text
CandidateSelection recorded
→ Asset/Reference Result applying
→ Result owner_applied
→ Workflow resumed
```

changes_requested 提供 `regenerate_candidates|edit_reference_brief|request_upstream_reference_change` strict form；rejected required Target 会显示 blocked。单行完成不等于 Gate 4 完成。Timeline 只在 Backend base/per-scene checkpoint 与 required coverage 全部闭合后变为 complete。

## 10. Gate 5 — Storyboard

### 10.1 Scene Queue

Scope Navigator 以 Scene 为行，展示 production-ready、Packet build、Storyboard Candidate、Task、formal Shot set 和 stale 状态。Gate 4 未闭合的 Scene 显示 exact blocker/Target link，不出现 `needs_asset` 或从 Storyboard 发起 Generation 的按钮。

### 10.2 Storyboard Review Surface

同一 Scene 的 `direct_storyboard` Candidate 同时显示 Intent 与 Detail：

| 区域 | 内容 |
|---|---|
| Source strip | Scene/Beat/Dialogue/Evidence coverage |
| Shot list/timeline | temporary shot key、purpose、duration、camera、action、performance、dialogue/sound |
| Visual binding | exact Character Appearance/Location/Prop AssetVersion 与 Scene/Interaction Binding chips |
| Continuity | in/out State、axis、story-time boundary、Interaction/Prop transition |
| Issues | deterministic gates、ReviewIssue、repair lineage |
| Alternatives | 同 Packet 的不同 candidate slot，不与 retry混淆 |

选择 Shot/issue 同步定位 Source、Binding 和 Impact Drawer。UI 可以提供 storyboard table/filmstrip 视图，但不能自行改变 Shot 顺序/字段后直接 Apply；编辑必须形成 Gate 5 typed changes_requested/new Candidate。

### 10.3 决议与正式结果

approved 前显示 whole-Scene apply：正式 Shot 数、每 Shot 一个 ShotProductionBindingVersion、Candidate/Packet/revalidation hash。Effect applying 期间不逐镜显示“部分已发布”；任何事务失败整 Scene conflict。Resume completed 后 Query formal Storyboard Owner View；StoryGraph Compiler 延迟独立显示，不把 Graph 未更新误报为 Shot 未提交。

## 11. Impact & Evidence Drawer

Drawer 是五 Gate 共用的解释层，数据来自 Backend typed Query，不由前端遍历缓存计算。固定分区：

1. **来源**：Evidence/creator decision/Owner ref/version/hash；
2. **当前事实**：正在使用的 exact Version/State/Binding；
3. **提案变化**：typed operation、before/after、Candidate/Decision；
4. **直接影响**：Scene/Identity/Target/AssetVersion/Binding/Shot；
5. **传递影响**：按 dependency closure 分组并标 truncated/cursor；
6. **将失效的结果**：Candidate/Selection/Reference/Packet/Storyboard；
7. **批准后行为**：Owner Command/Receipt、是否新 Task/Target/round；
8. **历史决议**：旧 Subject/Decision/Effect/Resume refs。

高影响动作在提交前必须携带 `impact_preview_ref/hash`；Backend Command 再重算。preview stale 时返回 conflict 并刷新 Drawer，前端不能让用户确认旧影响范围。

Drawer 支持从 Gate、Asset Card、Reference row、Storyboard Binding 与 Story Lens打开同一 exact focus。关闭只改变本地 UI，不丢失 URL 中需要分享的 focus ref。

## 12. 资产与场景只读卡

### 12.1 Character Card

```text
Identity
├── canonical name / aliases / Evidence
├── Specification
├── identity-anchor State + AssetVersion
├── Appearance State timeline
│   └── each exact AssetVersion + anchor dependency
├── Occurrence/Interaction coverage
└── downstream Scene/Binding/Shot impact
```

一个 Character Identity 一张卡；年龄/换装/伤势/伪装/画风不是新身份。卡片不使用 `current CharacterSpecificationVersion` 宽泛字段；Backend Query 返回 active exact ref 与历史版本。

### 12.2 Location Card

显示 Specification、Location State timeline、topology/material/scale、Location Board view-role coverage、Scene Occurrence 与引用它的 Composition/Shot。Scene 是单独剧情投影，不复制 Location Identity。

### 12.3 Prop Card

显示 Prop Specification、尺寸/结构、State timeline（开闭/损坏/内容物）、Prop Sheet、holder/Interaction ledger、before/after/cause 和下游 Scene/Shot。持握姿势只在 Interaction Binding中显示，不成为 Prop 或 Character State。

### 12.4 Scene Readiness Card

显示该 Scene 的 P0–P2 exact roots、required Target fulfillment、base/composition bindings、continuity blocker、Packet readiness 和 formal Storyboard。它是 Backend `GetSceneReadinessView` 的展示，不建立 `SceneCard` 业务事实。

卡片首版只读；所有修改深链到对应 Gate/Task。禁止通用 JSON 编辑器和“使用最新版本”按钮。

## 13. Review Inbox、Provider Settings 与 Story Lens

### 13.1 Review Inbox

`/reviews` 是跨 Gate 待办入口，不是第二套审核体验。列表支持 status/gate/Episode/Scene/Target/claim owner 筛选；选择任务后：

- 默认深链到 `/production?gate=...&task=...` 的同一 renderer；
- 宽屏可在 Inbox shell 内嵌相同 renderer component，但使用同一 Query/Decision Bar；
- 不复制 candidate selection、typed change form 或协调状态机；
- unknown subject renderer 只读并禁用 Decision。

列表区分合法 empty、筛选无结果、projection delayed、403 与 dependency unavailable；count 来自 Backend，不用本地事件累加。

### 13.2 Provider Settings

Provider Settings 是次级运维页。当前 MVP 只需证明至少一条真实图片 capability 可覆盖六类 Target：

- 显示 connection/profile/binding exact version 与 capability；
- API Key 仅在创建/轮换表单内存和一次 TLS Request存在，成功立即清空；
- 零配置合法，Gate 1–3/查询不受影响；Gate 4 对需生成 Target 显示 `provider_configuration_required`；
- 不显示 PriceQuote/支付/余额，不在 Guided 主流程比较 Provider；
- 不允许任意 Host/Header/JSON、自动 fallback 或直接测试生成绕过 Target。

多 Provider/Shot Video 配置保留 Platform Complete，不在本 Design 冒充已实现。

### 13.3 Story Lens

Story Lens 继续遵循 1001：单人、只读、分层有界 Query。它用于正式事实追溯和 Impact 深链，不参与五 Gate 决策、不计算 readiness、不作为 Guided 主入口。React Flow/Dagre 依赖只随真实只读 Lens 切片加入；在此之前 Impact Drawer 和表格深链已能完成 MVP 追溯。

Story Lens 与 Workflow Run 诊断使用不同 Query/ID/renderer；不能建立 Universal Graph DTO。Guided 页可深链 Run/Node，但不嵌入 Workflow Lens Canvas。

## 14. Query、Command 与状态所有权

### 14.1 Query 清单

Frontend 只通过生成 OpenAPI + RTK Query 消费：

| Feature | Backend Query |
|---|---|
| Project Overview/continue | `GetVisualProductionPackageView` + `GetGuidedStudioTimelineView` + Backend `next_action` |
| Gate 1 | `GetGate1ReviewView` |
| Gate 2 | `GetGate2ProductionWorldReviewView` + `GetContinuityLedgerView` |
| Gate 3 | `GetVisualFoundationReviewView` + expected Reference Target matrix |
| Gate 4 | `GetReferenceCoverageMatrixView` + exact Candidate comparison/HumanTask coordination |
| Gate 5 | `GetGate5StoryboardReviewView` + `GetSceneReadinessView` |
| Cards | `GetCharacterCardView/GetLocationCardView/GetPropCardView` |
| Impact | exact version Impact/Trace typed Query |
| Reviews | D11 Task/Subject/Coordination Queries |
| Lens | StoryGraph Version/Lens/Diff/Trace Queries |

前端不得通过 N 个 endpoint 自行拼出 Owner closure。聚合 Query 不存在时页面显示真实阻塞/未交付，不用旧列表推断成功。

### 14.2 Command 边界

页面只能发送已接受的 typed intent：

- 原稿导入/接受、启动已定义 Workflow；
- D11 claim/renew/release/decision/resume；
- D10 initial generation/regenerate/execution authorization；
- Provider Connection/Profile/Binding 管理；
- 后续 Requirement 明确的 impact preflight/typed change command。

Owner Apply、CandidateSelection→Result、checkpoint、Compiler 和 Temporal Signal 均由 Backend协调，浏览器不直接调用或编排。客户端 body 不自报 Workspace/Run/Node/Owner output/wait token/effect plan。

### 14.3 状态 Owner

| 状态 | 唯一 Owner | 前端位置 |
|---|---|---|
| Owner/Gate/Target/Task/Workflow 服务端事实 | Backend + RTK Query cache | 可丢弃重取 |
| gate/scope/task/focus/version/稳定筛选 | URL | 可分享/刷新恢复 |
| 当前 compare hover、zoom、展开、Drawer open | React local state | 页面会话 |
| 未提交 typed form | React form state | 离开前提示，不持久为业务事实 |
| Claim Token | 受保护的当前 Task detail/query session | 不进 URL/localStorage/日志 |
| 图片 preview handle | 短时 Query response | 不进业务 identity |

不得把 Query response 复制到 Redux slice/Context/localStorage/IndexedDB 或第二 Query cache。服务端返回的 `allowed_actions/allowed_decisions/capabilities` 决定按钮；Frontend role label 只用于解释，不能代替 Backend authorization。

### 14.4 Mutation 后一致性

每个 mutation 持有稳定 idempotency key，网络 unknown 时重用同 key并先重取协调状态。成功只 invalidates 精确 tags：Task/Coordination、当前 Gate View、受影响 Owner Card/Target/Scene、Timeline；不能无差别清空全项目造成闪烁或读取不同时间点拼图。

轮询按 Backend `retry_after_ms/status` 有界调整，并在页面隐藏时降频；focus/reconnect 时精确 refetch。MVP 不要求 SSE；未来事件只触发 RTK Query invalidation，不成为第二事实源。

## 15. 状态、空态与失败路径

### 15.1 全局错误分类

所有主页面必须区分：

| 状态 | 用户解释 | 主动作 |
|---|---|---|
| loading | 正在读取服务端事实 | 保持结构 skeleton/aria live |
| empty | 合法尚无原稿/Target/Task/Result | 显示唯一前置动作 |
| 401 | 登录失效 | 重新登录 |
| 403/404 防枚举 | 无权限或不可见 | 返回项目列表，不泄漏对象 |
| 409 stale/conflict | 旧版本不能继续 | 打开 Impact/新 Task |
| 422 contract/blocker | 输入或前置不满足 | 显示字段/issue/目标 link |
| 429 operational limit | 暂时达到调用上限 | 按服务端时间重试，不显示付费升级 |
| dependency unavailable | Provider/Agent/Temporal/Object Store 不可用 | 保留已提交阶段，给恢复动作 |
| outcome unknown | 远程/Resume 结果不可确认 | 原 identity 对账，禁用重复动作 |
| projection delayed | Owner 已提交、Graph/Search尚未更新 | 显示 Owner Receipt 和刷新 |

空值不能显示为 0：Query 缺失/失败与真实 count=0 分开。旧缓存不得在 scope/version改变时冒充新事实。

### 15.2 Gate-specific 失败

- Gate 1：uncovered source/identity unresolved 显示影响 scope；
- Gate 2：双 holder、State gap、Interaction/Continuity blocker 深链；
- Gate 3：Preset conflict/capability missing 只能 changes requested；
- Gate 4：provider missing、dependency unfulfilled、Call unknown、bundle incomplete、QC/Vision fail、Selection/Owner Apply conflict 分层；
- Gate 5：Scene not production ready、Packet stale、Binding mismatch、whole-Scene Apply conflict、Compiler delayed 分层。

任何失败都不能变成绿色 toast后消失；错误在关联 Task/Target/Scene 状态中持续，直到新服务端事实解除。

## 16. 响应式与无障碍

### 16.1 Web 响应式

目标是 Desktop-first Web，不做移动原生 App：

- 宽屏保留 Navigator + Work Surface + Context Rail；
- 中屏将 Context Rail 收为可打开的 side sheet；
- 窄屏五 Gate Timeline 横向可滚动，Scope Navigator变为顶部 selector，Impact Drawer 全屏；
- Candidate compare 使用带 sticky row/column header 的横向表格，不能缩小到看不清；同时提供逐 Candidate 详情模式；
- 核心 Claim/Decision/Resume 在窄屏仍可用，Canvas/Lens 可退化为列表。

### 16.2 无障碍

- Timeline 使用有序列表/`aria-current=step`，状态不只靠颜色；
- Matrix/Candidate compare 使用语义 table、row/column header 和 keyboard focus；
- 图片有基于 target/view role 的 alt，不用模型生成自由描述替代业务身份；
- issue region 标注同时有文本列表和键盘定位；
- Dialog/Drawer/Decision Bar 管理 focus return、escape和 destructive confirmation；
- loading/status/unknown 使用适度 `aria-live`，避免轮询重复播报；
- 支持 200% zoom、reduced motion、light/dark token，对比度沿现有主题验证；
- 任何拖拽型视觉交互必须有按钮/表单等价路径；MVP 不依赖拖拽。

## 17. 性能与媒体加载

- Project Overview、Timeline 和当前 Gate 首屏分别使用有界聚合 Query，不预取全项目图片/Graph；
- Scope/Target/Task 列表服务端分页或按 closure 分块，前端不无限合并；
- Candidate compare 先取安全 thumbnail/metadata，用户聚焦后才取高分辨 preview；不把 Base64 放进 API/RTK cache；
- selected Bundle/影响范围切换时取消旧 preview 请求，digest/ref不变可复用浏览器 HTTP cache；
- Story Lens 动态加载，不进入 Guided 首包；
- 大表格只有真实规模证明需要时引入虚拟化，不能为未来预装另一组件框架；
- 页面隐藏时暂停媒体/高频轮询，恢复时先重取 exact task/coordination；
- Backend 返回 truncated/cursor 时明确显示，前端不能把“已加载部分”当完整 coverage。

## 18. 安全、隐私与产品分析

### 18.1 安全

- 不渲染未净化 HTML；原稿/Prompt injection 作为数据展示，不成为 UI/Agent指令；
- Preview handle 绑定用户/对象/用途/短时效，不作为 Artifact URL 或 Decision identity；
- API Key 只在 Provider form memory/TLS Request，成功/失败/卸载时清空；
- Claim/Access Token、Secret、Prompt、原稿全文、私有图片 URL 不进入 URL、localStorage、analytics、error boundary、日志或 session replay；
- user_note 只按文本显示并限制长度，不直接插入 Agent prompt；
- 下载/导出只使用 Backend授权 response，不拼对象存储路径；
- Viewer/Editor/Owner 的控件状态来自 capability，所有命令仍由 Backend 再授权。

### 18.2 产品指标

前端只上报低敏事件 identity/hash与产品阶段，不含内容：

- Gate ready→Decision、Decision→Effect、Effect→Resume 时长；
- Gate 1/2/3/5 首次 approved 率与 changes requested 原因码；
- Gate 4 Target awaiting selection→owner applied 时长、重生成原因、Interaction contact fail；
- required Reference coverage、Production-ready Scene Coverage；
- stale/conflict/unknown 恢复成功率；
- Impact Drawer 打开→Decision取消/继续比例。

图片数、Provider 数、花费和付费转化不是 MVP 北极星。Analytics 不替代 Backend审计或验收证据。
