## 结论

Frontend 按用户任务拆成 10 个 feature，另有 5 个共享 package 和 1 个 Collaboration Runtime。Feature 名称表达用户目的，不以页面框架、技术 Store 或含糊的 `studio/admin/common/services` 命名。

Frontend 负责交互和本地编辑体验；权限、业务校验、Revision、Run、Review、Candidate、Artifact 与 Cost 的最终事实由 Backend 裁决。

各节中的“验收”描述用于解释设计意图；稳定 Requirement ID 与验证方式只在[前端功能模块需求规格](../requirement/1002-前端功能模块需求规格.md)维护。

## 状态所有权

| 状态 | 唯一 Owner | 禁止 |
|---|---|---|
| 服务端实体、列表、任务、运行投影 | TanStack Query | 复制到 Zustand/Yjs |
| 可分享导航、筛选、选中资源 | URL | 只放组件内导致刷新丢失 |
| 未提交表单 | React Hook Form + Zod | 用 Zustand 做表单仓库 |
| 跨组件短期交互 | feature-scoped Zustand | 保存 Access Token 或服务端实体 |
| Canvas 活动 Graph/Layout | Yjs | 再镜像一份到 Zustand |
| AI 未完成流 | `@lanverse/ai` stream controller | 把 token buffer 当持久结果 |
| 组件私有状态 | React state | 提升为无边界全局 Store |

Feature 只能导入其他 feature 的公开组合入口，不能导入其内部 Query、Store 或私有组件。跨领域复用通过 `@lanverse/ui|ai|canvas|sdk|auth` 的公开 subpath。

## Feature 目录

```text
frontend/apps/web/src/features/
├── account-access/
├── workspace-shell/
├── project-shell/
├── guided-production/
├── authoring-canvas/
├── review-workbench/
├── asset-library/
├── run-observability/
├── ai-copilot/
└── workspace-governance/
```

每个 feature 内按实际需要使用：

```text
feature-name/
├── api/          # 组合 SDK 资源级 options、页面 mutation/invalidation；不定义 key/DTO
├── components/   # feature 私有视图
├── forms/        # Schema 与表单组合
├── model/        # 纯前端 View Model、权限展示映射
├── routes/       # route composition helper
└── test/
```

单一消费者出现前不得抽共享 package，也不要求每个 feature 机械创建上述全部目录。

## 1. Account Access (`account-access`)

### 页面与职责

路由：`/login`、`/register`、`/forbidden`、`/account/security`；账户安全设置与 Workspace 设置分离。

负责注册、登录、会话恢复、退出、安全 Return URL 和认证错误交互。共享会话能力来自 `@lanverse/auth`，Feature 不自行保存 Token。

### 数据与流程

- Refresh Session：HttpOnly Cookie；Access Token：Auth Runtime 内存。
- `/me` 和 Membership：TanStack Query。
- 登录/注册表单：RHF + Zod；Return URL：URL。

流程：注册/验证或登录 → 恢复 `/me` → 校验 Return URL → 进入 Workspace → Access Token 轮换 → 退出并撤销。

### 失败、权限与验收

- 验证码过期、限流、凭据错误、依赖不可用和 Refresh 失败使用不同错误展示。
- 禁止开放重定向；401 只触发一次并发合并的恢复流程。
- Access Token 不进入 URL、Local Storage、Zustand、Query Cache 或日志。
- 退出/撤权后，受保护 Query、SSE 和 Collaboration 连接必须失效。

Backend：Access & Membership。

## 2. Workspace Shell (`workspace-shell`)

### 页面与职责

路由：`/workspaces`、`/w/:workspaceId/projects`。

负责 Workspace 选择、成员能力上下文、项目列表/创建、Workspace 级导航和跨页面返回点；不承载某个 Project 的生产步骤状态。

### 数据与流程

- Workspace/Project 摘要：Query。
- 所选 Workspace、筛选、排序：URL。
- 菜单和创建弹层：React state。

流程：登录后列出 Membership → 选择 Workspace；创建新 Workspace 时先读取账户级 `workspace:create` Entitlement → Backend 原子创建 Workspace + Owner Membership → 刷新 Actor/Workspace 列表 → 打开 Project Shell。

### 失败、权限与验收

- 无 Workspace 显示创建/等待邀请入口；筛选无结果与真正空列表分开。
- `workspace:create` 是已验证账户的账户级 Entitlement，不依赖尚不存在的 Membership；平台数量策略拒绝时显示明确原因，不能退化为 Workspace 403。
- Workspace 已归档、权限撤销、404、403 不能伪装为空数组。
- 切换 Workspace 必须取消/隔离旧 Workspace Query、SSE、上传与协作连接。
- Viewer 不看到无权操作；直接调用仍由 Backend 拒绝。

Backend：Access、Production、Search。

## 3. Project Shell (`project-shell`)

### 页面与职责

路由：`/w/:workspaceId/projects/:projectId` 及其 Episode/模块子路由。

负责 Project/Episode 上下文、面包屑、生产入口、全局状态摘要、Preset/成本/运行告警和模块导航；不复制各 feature 的业务状态机。

### 数据与流程

- Project/Episode/Production Snapshot：Query。
- 所选 Project/Episode/Tab：URL。
- 导航展开态：组件状态。

流程：打开 Project → 选择 Episode → 进入 Guided、Canvas、Asset、Review、Run、Copilot 或 Governance。

### 失败、权限与验收

- Project 不存在、已归档、无权、部分依赖 degraded 分别显示。
- 刷新或分享任一深链后，Workspace/Project/Episode 上下文保持一致。
- Shell 只展示摘要，不能自行推进 Workflow 或修改 Review 状态。

Backend：Production、Preset、Workflow Projection、Cost、Search。

## 4. Guided Production (`guided-production`)

### 页面与职责

路由：

```text
/w/:workspaceId/projects/:projectId/episodes/:episodeId/guided
  ?stage=script|bible|characters|scenes|storyboard|shots|sound|review|export
```

用业务步骤呈现 Script → Bible → Character/Scene → Storyboard → Shot → Sound → Review → Export；编辑和发布统一 `AuthoringDraft/AuthoringRevision`，不创建 Guided 专用执行模型。`stage=review` 只展示 Human Task 摘要、阻塞原因和进入 Review Workbench 的深链，不实现 Claim/Decision 第二套审核流。

Guided 中对 Draft 内容的任何修改都使用 `authoring:edit`，发布使用 `authoring:publish`；`production:edit` 只控制 Project/Episode 层级、源 Script 导入、已发布版本绑定和其他 Production 事实。一个交互若同时导入源文件并创建 Draft，Backend Coordinator 必须同时验证两项能力，Frontend 在提交前列出缺失能力。

### 数据与流程

- Production Snapshot、Candidate、Revision、Run、Human Task Summary：Query。
- stage、选中 Shot/Candidate：URL。
- 步骤表单：RHF/Zod；局部比较弹层：React state。

主流程：导入 Script → 确认结构/Bible → 生成候选 → 发布 Revision → 启动 Run → Human Gate → 打开 Review Workbench 完成决议 → Render/Export。

### 失败、权限与验收

- 没有 Script 时只显示导入入口；上游未确认时明确展示阻塞原因和下一动作。
- Provider `UNKNOWN`、候选过期、Revision 冲突、失败 Shot 和预算不足必须分开处理。
- 单 Shot/失败节点可重跑；刷新从 Backend 恢复；所有 Run 绑定不可变 Revision。
- 在 Canvas 打开同一 Draft 后语义和高级节点不丢失；Guided 无法编辑的节点显示只读摘要。

Backend：Production、Preset、Authoring、Workflow、Agent、Generation、Asset、Media、Review、Cost、Quota。

## 5. Authoring Canvas (`authoring-canvas`)

### 页面与职责

路由：`/w/:workspaceId/projects/:projectId/canvas/:draftId`。

负责 Node/Edge/Binding/Layout 编辑、Node Catalog、Inspector、GraphPatch 预览、Graph Diff/Dirty 展示、Revision 发布和局部运行入口。Canvas 只表达 Authoring 体验，不拥有执行器。

### 数据与流程

- Draft Baseline、Revision、Node Catalog、Validation、Run Projection：Query。
- 活动 Graph/Layout：Yjs。
- 工具、瞬时多选、hover、拖拽和面板：feature Zustand；节点配置表单：RHF/Zod。
- `draftId` 与可分享的 `focusedNodeId`：URL；活动多选集合不进入 URL。

导航到带 `focusedNodeId` 的 URL 时，Route 单向设置一次本地焦点；普通点击/框选不持续回写 URL，只有用户执行“复制节点链接”时生成新的深链，避免 URL 与 Zustand 双向争抢 Owner。

流程：获取 Draft Baseline + Room Grant → 加入 Collaboration Room → 编辑 → Backend Validate → Commit Snapshot → Publish Revision → Compile → Cost Estimate → Run Node/Branch/Dirty/All。

### 失败、权限与验收

- Catalog 不可用时只读；端口/Schema 错误必须定位到 node/field/edge。
- Epoch/Base Revision 冲突进入可解释 Rebase；WebSocket 断开显示未同步/只读状态。
- 两个客户端最终收敛；服务重启恢复；旧 Epoch 不能覆盖新 Draft。
- 纯 Layout 变化不改变执行 Hash；新增 Backend Node Definition 不要求新增前端执行分支。

Backend：Authoring、Production Snapshot、Preset、Workflow、Cost、Quota、Room Grant。

## 6. Review Workbench (`review-workbench`)

### 页面与职责

路由：

```text
/w/:workspaceId/projects/:projectId/reviews
/w/:workspaceId/projects/:projectId/reviews/:humanTaskId
```

负责统一审核队列、领取/指派、候选比较、QC/Artifact/成本证据和不可变 Decision 提交。

### 数据与流程

- Human Task、Decision、Subject Snapshot、Candidate、Artifact：Query。
- 筛选、排序、选中 Task：URL；理由/编辑意见：RHF/Zod。

流程：打开 WAITING Task → Claim → 对比证据 → Record Decision → Backend 持久化 → Workflow Adapter Signal → Query 新 Run 状态。

### 失败、权限与验收

- 空队列明确“无需审核”；被他人领取、对象版本变化、Decision 已存在进入 Conflict/Stale。
- Artifact 不可预览不能默认批准；服务端确认前不能显示已完成。
- 重复提交幂等；并发审核不覆盖；关闭浏览器不丢 Human Gate。

Backend：Review、Generation、Asset、QC Snapshot、Workflow Projection。

## 7. Asset Library (`asset-library`)

### 页面与职责

路由：

```text
/w/:workspaceId/projects/:projectId/assets
/w/:workspaceId/projects/:projectId/assets/:assetId
/w/:workspaceId/projects/:projectId/artifacts/:artifactId
```

负责 Asset/State/Version、Artifact 来源血缘、使用影响、上传、版本选择、预览、归档与恢复。界面必须明确区分可复用 Asset 身份和不可变 Artifact 输出。

### 数据与流程

- Asset/Version/Artifact/Usage/Readiness：Query。
- filter、kind、selected version：URL。
- 编辑表单：RHF/Zod；上传进度：局部 Upload Controller。

流程：创建/导入 Asset → 创建 Upload Session → Presigned 直传 → Complete → `PENDING_VALIDATION` → Integrity/Probe Receipt → `READY` → 发布 Version → 设置活动版本 → 查看影响。

### 失败、权限与验收

- “尚无 Asset”和“筛选无结果”使用不同空态；签名过期可重新申请。
- `PENDING_VALIDATION` 显示可恢复等待与进度，禁止 Preview/Publish/Render；`READY` 才允许成为 Candidate、发布 Version 或进入 Render。
- `QUARANTINED` 禁止预览、下载和发布并显示安全处置原因；`UNAVAILABLE` 只展示元数据/血缘和位置恢复入口；`TOMBSTONED` 是不可恢复终态，只保留身份、血缘和审计。
- Quarantine/Restore/Tombstone 仅在 Backend 返回允许动作且具有 `asset:manage_readiness` 时展示；恢复必须等待新的完整性 Receipt，不能在客户端直接把状态改成 `READY`。
- 大文件不经过 Web/API 中转；失败重试不产生重复 Artifact。
- 历史 Revision 永远引用原固定版本和 Artifact。

Backend：Asset Registry、Media Probe、Production Usage、Access。

## 8. Run Observability (`run-observability`)

### 页面与职责

路由：

```text
/w/:workspaceId/projects/:projectId/runs
/w/:workspaceId/projects/:projectId/runs/:workflowRunId
```

负责 Workflow/Node 状态、依赖图、Retry、Human Wait、Provider Job、Artifact、Cost 和 Trace 关联。它是业务运行诊断，不是基础设施日志后台。

### 数据与流程

- Run/Node/Cost/Artifact Snapshot：Query。
- SSE Cursor/去重：SDK Stream Controller。
- run/node/filter：URL；展开态：React state。

流程：从 Guided/Canvas 打开 Run → 实时观察 → 定位失败/等待 → 查看输入输出/Trace → Retry/Cancel/Reconcile 或进入 Review。

### 失败、权限与验收

- SSE 断线按 Last-Event-ID 重连或重取 Snapshot；不得根据 token 文本猜终态。
- `UNKNOWN` 不归类为 FAILED；Trace 缺失显示诊断不完整。
- 刷新/重连不重复事件；终态与 Query 重取一致。
- Retry Failed 不误跑成功分支；Cost 可追溯到 Node 与 Artifact。

Backend：Workflow Projection/SSE、Generation、Asset、Cost、Trace Link。

## 9. AI Copilot (`ai-copilot`)

### 页面与职责

作为 Project/Guided/Canvas Shell 的侧栏；需要深链时使用 `/w/:workspaceId/projects/:projectId/copilot/:conversationId`。

负责上下文感知对话、Reasoning/ToolCall 展示、Artifact 建议、GraphPatch 预览和高影响动作确认。`@lanverse/ai` 提供交互机制，不拥有业务 Copilot 事实。

### 数据与流程

- 已持久化 Conversation/Agent Run：Query。
- 未完成响应 parts：AI Stream Controller；Prompt：RHF。
- 上下文资源：URL；面板开关：Zustand。

流程：携带 Project/Episode/Draft 上下文提问 → SSE 响应 → 展示 Tool Call → Backend `ValidateGraphPatch` → Preview → 用户确认 → Backend `ApplyGraphPatch` 建立 Intent/Apply Grant → Collab 按 Application ID 幂等执行 Yjs Transaction → Backend 提交 Draft Snapshot/Receipt → Query 对账终态。

### 失败、权限与验收

- Tool 越权、预算不足、GraphPatch 无效、对象 Stale 和流断开必须阻塞或进入待确认。
- AI 与 Frontend 都不能在 Backend 授权前直接改 Yjs；Copilot GraphPatch 必须同时具备 `copilot:apply_tool ∧ authoring:edit`。只有 Backend 返回持久 `GraphPatchApplicationReceipt(APPLIED)` 后显示成功；`outcome_unknown` 按 Application ID 对账，不在客户端重放 Patch。
- 断线按 Event ID 去重；客户端不伪造 Tool/Run 成功终态。

Backend：Agent、Generation、Authoring GraphPatch、Asset、Cost、Quota、SSE。

## 10. Workspace Governance (`workspace-governance`)

### 页面与职责

路由：`/w/:workspaceId/governance`、`/w/:workspaceId/settings`、`/w/:workspaceId/audit`。

负责成员/角色、Consent、审计、Budget/Quota 可见性、Workspace 配置和归档恢复。V1 不使用含糊的 `admin`；未来平台运营后台必须另建 `platform-operations`。

### 数据与流程

- Membership、Role、Consent、Audit、Budget/Quota：Query。
- Tab/filter：URL；配置变更：RHF/Zod。

流程：查看 Access Capability → 邀请/调整成员或 Consent → Backend 校验 → Outbox/Audit 可查询。

### 失败、权限与验收

- 无管理能力时只读/403；自身降权、最后 Owner、并发版本冲突由 Backend 阻止。
- 无审计事件是合法空态；依赖 degraded 不能显示虚假零用量。
- 权限撤销后 Query/Collaboration/Command 能力及时失效；所有高影响变更可审计。

Backend：Access、Production Workspace、Asset Rights/Consent、Cost、Quota、Eventing Audit Projection。

## 高影响动作与 Capability

以下 Access Capability 名称是 Frontend/Backend 的目标契约。Frontend 只用它决定展示和只读体验；Backend 必须在执行时基于最新 Account Entitlement 或 Membership Revision 再验证：

| 用户动作 | Backend Access Capability | 无能力时的 UI | Backend 拒绝与恢复 |
|---|---|---|---|
| 创建 Workspace | 账户级 `workspace:create` | 隐藏创建入口，保留受邀 Workspace 列表 | Entitlement/平台数量策略失败后刷新账户能力；不伪造 Membership |
| 创建 Project/Episode | `production:create` | 隐藏创建入口；列表仍可读 | 403 后刷新 Actor Access Capability 与列表 |
| 导入源 Script、调整 Production 层级/版本绑定 | `production:edit` | 对应 Production 动作只读并说明所需能力 | 403/409 保留输入并允许复制，不自动重发 |
| 编辑 Guided/Canvas Authoring Draft | `authoring:edit` | Guided/Canvas 只读，Collab 使用只读 Grant | 撤权时终止写连接并重取 Draft Baseline |
| 发布 Authoring Revision | `authoring:publish` | 保留 Validate，禁用 Publish 并显示原因 | 403 刷新 Access Capability；409 进入 Rebase/Diff |
| 启动 Workflow Run | `workflow:start` | 可看成本估算，禁用最终启动 | 403/预算/Quota 错误分别处理，不创建本地 Run |
| Retry Node/Shot | `workflow:retry` | 运行诊断只读，隐藏 Retry 菜单 | 403 或 State Conflict 后重取 Run/Node |
| Cancel Run | `workflow:cancel` | 隐藏 Cancel；保留状态查看 | 403 或终态冲突后重取 Run |
| Claim Human Task | `review:claim` | 可查看允许公开的审核摘要，禁用 Claim | 403/已领取后重取 Task 与 Assignee |
| 记录 Review Decision | `review:decide` | Decision 表单只读 | 403/STALE/已决议后保留理由草稿并重取事实 |
| 上传 Artifact | `asset:upload` | 隐藏上传入口 | 403 时取消未开始上传；已直传对象由过期清理回收 |
| 发布 Asset Version | `asset:publish` | 可预览，禁用 Publish/Set Current | 403/409 后重取 Usage 与活动版本 |
| 隔离/恢复/Tombstone Artifact | `asset:manage_readiness` | 只显示 Readiness、原因和血缘 | 403/状态冲突后重取 Readiness；禁止客户端推测 READY |
| 管理 Consent/使用权 | `asset:manage_rights` | Rights 区只读 | 403/过期/范围冲突后重取 Consent Version |
| 调用 Copilot | `copilot:invoke` | 显示只读历史，不提供 Prompt 输入 | 403/Quota 后终止流并对账 Agent Run |
| 应用 Copilot Tool/GraphPatch | `copilot:apply_tool` + `authoring:edit` | 允许预览，不显示 Confirm | 任一 403/对象 Stale 后重新 Validate，绝不自动应用 |
| 管理成员与角色 | `workspace:manage_members` | Governance 只读 | 403/最后 Owner/版本冲突后重取 Membership |
| 管理 Budget/Quota Policy | `workspace:manage_policy` | 只显示用量摘要 | 403/409 后重取 Policy Revision |
| 查看完整审计 | `workspace:view_audit` | 只显示用户自身或产品允许的摘要 | 403 后刷新 Access Capability，不泄漏 Subject 是否存在 |

动作按钮的 loading 只表示请求进行中；只有 Backend 返回持久化结果后才能显示完成。任何 403 都会使相关 Access Capability Query 失效，但不得自动重复高影响 Command。

## 共享模块

### `@lanverse/ui`

提供 Token、Primitive、Feedback、Form Appearance、Data Display 等无领域语义组件。只拥有组件私有状态，不调用 API、不读取 Auth、不包含 Canvas/AI 业务。必须通过 Keyboard、Focus、ARIA、Theme 和视觉回归验收。

### `@lanverse/sdk`

由 OpenAPI 生成类型/Client，并拥有资源级 Query Key Factory/Base Options、错误归一化、SSE、Presigned Upload、Collaboration 协议和 Trace/Request ID。Feature 只能组合这些 Options、增加页面 `select` 或声明 Mutation 后的失效关系，不能再定义同资源 key/DTO。SDK 不拥有 React 全局状态；401/403/409/422/429/5xx 保留机器字段、field/node path 和 trace ID。

### `@lanverse/auth`

提供 Session Runtime、身份恢复、登录/退出适配、Guard 与 Access Capability Reader。它不拥有 Workspace RBAC 规则，不能保存业务实体或 Provider/Storage 凭据。

### `@lanverse/ai`

提供 Chat/Message/Reasoning/ToolCall/AgentStatus/Streaming/Artifact Preview/Tool Approval，以及流式 Controller。它不启动 Workflow、不持久化最终对话事实、不直接调用 Provider。

### `@lanverse/canvas`

提供 React Flow Editor、Node/Edge、Inspector、Toolbar、Selection、Clipboard、Layout、Run Overlay 和 Collaboration Client。它不定义 Backend Node Registry、不校验最终权限、不直接调用 Temporal/Provider/数据库。

## Collaboration Runtime (`apps/collab`)

### 职责

运行 Hocuspocus/Yjs WebSocket，负责 Room Authorization、Document Lifecycle、Update/Snapshot Store、Presence、Connection Limit、Epoch、Compression、Retention/Cleanup 和 Telemetry。

Yjs update/snapshot 是可重建协作恢复投影；PostgreSQL `AuthoringDraft/Revision` 是业务事实。`apps/collab` 不导入浏览器侧 `@lanverse/auth`，通过 SDK 协议校验 Backend 签发的短期 Room Grant。

### 流程与失败

流程：申请 Grant → Join → Sync → Edit → Checkpoint/Commit → Reconnect/Rebuild。

Grant 过期、撤权、Epoch 冲突、超大 Update、慢消费者和 Store 不可用必须显式断开或降只读，不能静默丢 Update。

### 验收

- 双客户端收敛、服务重启恢复、从 PostgreSQL Baseline 重建。
- 旧 Epoch Fencing、权限撤销断连、消息/连接容量限制。
- Presence 不持久化为业务事实；Update Store 不被业务模块查询为 Revision。


## 架构验收

1. 每个 Feature 的 Server State 只由 Query 管理，Canvas Graph 只由 Yjs 管理。
2. Package Dependency Test 禁止 feature 私有导入、`ui` 反向依赖和 SDK 重复 DTO。
3. 任意深链刷新后恢复 Workspace/Project/Episode/Draft/Run 上下文。
4. 401、403、404、409、422、429、dependency unavailable、outcome unknown 有独立 UI 契约。
5. E2E 至少覆盖注册登录、Guided 发布运行、Canvas 双人协作、Review Signal、Artifact 直传、Run SSE 重连与权限撤销。
6. 同一服务端资源只能由一个 Query Owner 和一套 Query Key 管理，禁止重复缓存或并行状态入口。
