## 结论

StoryGraph MVP 不重建一套十模块前端平台。它在当前项目页、Episode Studio 和 RTK Query 基础上增加四个真实用户任务：查看角色/地点卡、完成公共审核、浏览只读 Story Lens、从内容节点进入独立的 Workflow 运行诊断。角色卡、地点卡和“场景视图”都是 Backend Owner 事实的只读组合，不建立新的 Card Record；Canvas 首版只是 StoryGraph Query 的可视化，不提供编辑、协作或模拟成功。

前端只展示并提交用户意图，Backend 负责权限、版本、状态机、Human Gate、Owner Apply、StoryGraph Compiler 和工作流恢复。任何按钮只有在 Backend 对应 Query/Command 已真实存在、OpenAPI 已生成且失败路径可验证时才出现。

## 1. 范围与当前事实

### 1.1 继续复用的现有能力

- `/projects/:projectId` 已提供项目、原稿、Production Bible 与 Episode 入口；
- `/studio/:episodeId/*` 已提供剧本结构、项目事实、分镜、媒体和任务页；
- `frontend/src/lib/server-state.ts` 已使用 RTK Query 管理部分正式 API；
- Production Bible UI 已能显示 character/location/prop 等候选实体和局部 review issue；
- Backend 已有 Artifact、Generation Candidate/Selection、Workflow Run/NodeRun、HumanTask/ReviewDecision 等部分事实；
- 前端测试已经独立位于 `frontend/tests`。

### 1.2 尚未实现的目标能力

- 正式 Character/Location Specification、AssetState、ProductionBinding 与可查询角色/地点卡；
- StoryGraphVersion/Head/Lens/Diff/Impact Query；
- 项目级公共 HumanTask 列表/详情/Decision HTTP 闭环；
- `reference_asset` composite 三视图生成、审核与 AssetVersion 发布；
- `ShotProductionBindingVersion` 与其精确视觉输入展示；
- React Flow/Dagre 的只读 Story Lens；
- 独立 Workflow Lens 页面及 Story Node → Run/NodeRun 的正式关联 Query。

因此，已有 Bible 实体列表、Episode Studio 的“项目事实”或 Storyboard 页面都不能改名充当新卡片/StoryGraph/公共审核。目标页面在 Backend 契约落地前保持不存在或显示明确未具备前置条件，不使用 fixture、静态 DTO 或成功 toast 补洞。

## 2. MVP 页面与导航

沿用当前不含 Workspace 前缀的路由，不增加兼容双路由：

```text
/projects/:projectId
├── /assets?kind=character|location|prop
├── /assets/:assetId
├── /reviews
├── /reviews/:humanTaskId
├── /storygraph?lens=...&scopeKind=...&scopeId=...
└── /runs/:workflowRunId            # 对应 Workflow 查询实施后

/studio/:episodeId
├── /script
├── /assets
├── /storyboard
├── /media
└── /tasks
```

项目页呈现全剧入口和就绪摘要；Episode Studio 呈现单集 Guided 任务；资产页呈现跨集复用身份和视觉版本；审核页完成 Human Gate；StoryGraph 页做跨对象追踪；Run 页解释执行状态。页面之间只通过稳定 ID 深链，不传递完整对象 JSON，也不各自复制业务状态机。

## 3. 项目与 Episode Guided 主链

### 3.1 项目页

项目页仍是全剧入口，按 Backend Snapshot 展示：

- 当前 ScriptDocument/Revision 与解析状态；
- 当前 Production Bible Candidate、BibleVersion 与物化状态；
- Episode 数量和各集就绪/阻塞摘要；
- Character/Location/Prop 身份数量、缺少 Specification/State/Reference 的数量；
- 待审 HumanTask 数量；
- 当前 StoryGraphVersion/Hash 是否存在；
- 进入角色/地点卡、审核队列和 Story Lens 的链接。

摘要值必须来自一个有定义的 Backend Query 或各自唯一 RTK Query endpoint；不得由页面抓取多张列表后自行推断平台就绪。某个 Query 不存在或失败时显示“尚未实现/暂不可用”，不能显示零。

### 3.2 Episode Studio

现有页面顺序继续用于 MVP：

```text
正式 EpisodeScriptVersion
→ Scene/Beat/Occurrence/Claim 候选与审核
→ Planning Owner Apply
→ Storyboard Draft / Shot Intent
→ Visual Requirement / needs_asset
→ Reference Asset 生成与审核
→ detail_shots
→ Shot + ShotProductionBindingVersion
→ shot_frame / ShotImageBindingVersion
```

各 Panel 只展示本步骤的 Backend 事实和下一动作：

| Panel | 目标职责 | 不得承担 |
|---|---|---|
| `script` | Episode、Scene、Dialogue、Beat、Occurrence/Claim 的来源和确认状态 | 用自由文本直接创建正式 Claim |
| `assets` | 本集涉及的角色/地点/道具 State、所需 view role、缺失视觉资产与角色/地点卡深链 | 建立本集私有角色身份或选择“最新资产” |
| `storyboard` | Shot Intent Candidate、风险、审核状态、正式 Shot 与 Binding 状态 | Candidate 直接进入 StoryGraph 或绕过资产 Gate |
| `media` | `shot_frame` Candidate、QC、Selection、ShotImageBindingVersion | 把生成结果写入 ShotProductionBindingVersion |
| `tasks` | HumanTask/Workflow 等待、失败与恢复深链 | 自建任务状态或用前端计时器推进工作流 |

旧 `EpisodeProductionStudio` 中手写传输 DTO 和直接 `request` 调用是当前事实，不作为新模块示范。StoryGraph 新切片必须使用生成 OpenAPI contract + RTK Query；旧页面只有在对应 `SG-Ixx` 真实改动时才按任务范围收敛，不做无关全量重写。

## 4. 角色卡

角色卡是只读 View，不是新 Record：

```text
Character Card View
= Asset(kind=character)
+ current CharacterSpecificationVersion
+ AssetState[]
+ published AssetVersion[]
+ ProductionBinding[]
+ Evidence / Rights / Lineage
```

### 4.1 列表卡片

列表至少显示稳定 Character Asset 身份、规范名、别名、来源 Evidence 摘要、状态数量、已发布 Look 数、三视图覆盖和缺失项。一个角色无论跨多少集、剧情状态或画风都只出现一个身份卡；筛选可按“缺 Specification / 缺 State / 缺 reference sheet / READY”进行。

### 4.2 详情页

详情按四轴分区，避免把概念混在一张图片上：

1. Identity：稳定 Asset 与角色身份；
2. Narrative State：年龄阶段、伤势、伪装、服装等 `AssetState`；
3. Render Style：EffectiveStyleSnapshot，不等于剧情状态；
4. Visual Version：不可变 AssetVersion、composite `reference_sheet` Artifact 和 lineage。

被选 reference sheet 必须显示 front/profile/back 三个语义区域及 QC/Selection；若只返回一张无 view-role 元数据的图片，UI 必须标为不可发布，而不是凭视觉猜测三视图。多个造型以同一 Character 下的 State/Style/AssetVersion 分组显示，不能创建多个近似角色卡。

### 4.3 用户任务

- 从 Bible/StoryGraph/Episode 查看角色卡；
- 识别哪个剧情状态缺少可用参考资产；
- 打开对应 `reference_asset` HumanTask 比较候选；
- 审核后查看唯一 Selection 与新 AssetVersion；
- 从 AssetVersion 反查被哪些 Occurrence、ShotProductionBindingVersion 和 Shot 使用。

首版卡片本身只读。Specification/State 发布和 Generation 启动由 Guided/Review 的类型化 Backend Command 驱动，不在卡片上提供通用 JSON 编辑器。

## 5. 地点卡与场景视图

地点卡同样是只读组合：

```text
Location Card View
= Asset(kind=location)
+ current LocationSpecificationVersion
+ AssetState[]
+ published AssetVersion[]
+ Evidence / Rights / Lineage
```

地点卡显示空间锚点、入口出口、区域、尺度、材质/光照约束，以及昼夜、天气、损坏、布置等 Location State。多个 Scene 可以复用同一 Location；不能因为每集或每场出现而复制地点身份。

“场景视图”必须显示：

```text
Scene + LocationState + Occurrence + Evidence
```

它是具体剧情场次的投影，不叫 `LocationCard`，也不建立 `SceneCard` 事实。页面需要清晰展示：当前 Scene 发生在哪里、使用哪个 State、有哪些角色/道具 Occurrence、哪些 Shot 冻结了哪个精确 Location AssetVersion。若 Binding 使用“当前最新”而非精确版本，UI 必须展示阻塞错误。

地点 `reference_asset` 不进入首个付费 MVP，除非 `SG-I20` 实施时真实剧本的 Shot Gate 证明不可缺少；在此前，地点卡允许展示 Specification/State 和缺图状态，但不得生成静态占位图冒充 READY AssetVersion。

## 6. 公共审核工作台

公共审核只使用两类事实：

- `HumanTask`：等待、领取、过期、完成、取消、陈旧等任务生命周期；
- `ReviewDecision`：用户对精确 Subject Revision 的不可变决议。

Production Bible 页面中已有的局部 review issue 决议是历史切片交互，不是公共 HumanTask 列表的替代。新 Bible/Episode/Storyboard/Reference/Shot Frame Gate 必须由 `SG-D16` 固定公共命令与恢复语义后再接 UI。

### 6.1 列表

`/projects/:projectId/reviews` 只读取项目内允许查看的任务，支持按 Task status、subject kind、Episode 和 assignee 筛选。每行显示 subject kind/id/revision、Workflow Run/Node、阻塞阶段、候选数量、创建/过期时间和是否已领取。

空队列、筛选无结果、无权限、投影延迟和依赖不可用是不同状态。任务数量不能通过 Kafka 消息或浏览器本地计数推断。

### 6.2 详情与决议

详情必须绑定精确 subject revision/hash，并按 subject kind 渲染：

| Subject | 核心比较内容 | 允许决议 |
|---|---|---|
| Bible/Planning Candidate | 原文 Evidence、结构化候选、歧义/风险和版本差异 | accept/reject/repair（由契约固定） |
| Storyboard Intent | Scene/Beat、视觉需求、Shot Intent、连续性和 `needs_asset` | accept/reject/repair |
| `reference_asset` | composite 候选、front/profile/back、身份/服装/画风 QC、成本与 lineage | select/regenerate/reject |
| `shot_frame` | Shot、冻结 Binding、精确 AssetVersion、候选/QC/成本 | select/regenerate/reject |

决议流程：

```text
Get HumanTask + Subject Snapshot
→ Claim（若契约要求）
→ 用户比较并确认
→ Record ReviewDecision(expected task/subject revision + idempotency key)
→ Backend 持久化 Decision
→ Workflow/Owner Apply 由 Backend/Temporal 协调
→ 重新 Query Task、Receipt、Run 与正式 Owner 事实
```

前端在 `RecordReviewDecision` 成功后只能显示“决议已记录/后续应用中”；必须读到对应 Owner Receipt 或 Workflow 新状态后才能显示“已应用/已继续”。请求超时或响应未知时按同一幂等键对账，不生成第二次决议。

## 7. 只读 Story Lens 任务流

Story Lens 使用 [1001](1001-前端应用架构.md) 固定的唯一 `/projects/:projectId/storygraph` 路由和分层 Query。

### 7.1 入口

- 项目页进入当前版本的一集 Outline；
- Episode Studio 从 Scene/Shot 深链到 Narrative/Production Lens；
- 角色/地点卡从 Asset 深链到 Entity Lens；
- 审核页从 Candidate 的 Owner/Evidence 深链到精确版本节点；
- Run 页若 Backend 提供正式关联，可从 Run/NodeRun 深链到内容节点。

### 7.2 浏览闭环

```text
选择 Project / exact StoryGraphVersion
→ 选择 Episode 或 Scene 范围
→ Backend GetStoryGraphLens
→ React Flow/Dagre 只读渲染
→ 选择稳定 story_node_key
→ Inspector 查看 Owner Ref / Evidence / version / hash
→ 请求有界 upstream/downstream 或 Version Diff
→ 深链回正式角色卡、地点卡、Shot、Binding、Artifact
```

页面没有新增、拖动保存、连线、删除、发布或通用 Patch 按钮。Dagre 坐标、viewport、折叠和颜色不进入 StoryGraph Hash。Claim 的 semantic projection 与权威边视觉上必须可区分。

### 7.3 Workflow Lens 分离

Workflow Lens 只解释 WorkflowDefinitionVersion、Run 和 NodeRun。它可以共享 viewport/Inspector shell，但必须使用独立 Query、Node ID 和 renderer；不能把 StoryGraph 节点状态染成 Workflow 终态，也不能让 Story Node 的选择直接触发 Retry/Cancel。

首个 Canvas 里程碑只实现 Story Lens。Workflow Lens 页面在对应 Backend Projection 与 Plan 任务存在时再建立；当前 Run/Tasks 列表可先用普通列表呈现，不预建空图。

## 8. 状态、权限与失败路径

状态 Owner 与 [1001](1001-前端应用架构.md)一致：服务端事实归 RTK Query，Lens/范围/稳定筛选归 URL，选择/viewport 归 React 本地状态，React Flow graph 是 Query 的纯派生 View Model。不得在新 Redux slice、Context 或 localStorage 再保存角色卡、任务、节点或边。

目标能力由 Backend Access Capability 决定；Frontend 只负责显示/隐藏和解释，不能代替授权：

| 用户动作 | 最小能力 | 无能力时 |
|---|---|---|
| 查看 Project/Asset/StoryGraph | Backend 对相应资源的 read capability | 403，不泄漏资源是否存在 |
| Claim HumanTask | `review:claim` | 详情可按授权只读，Claim 禁用 |
| Record ReviewDecision | `review:decide` | 比较可读，决议控件禁用 |
| 启动/恢复生成 | 对应 workflow/generation command capability | 仅展示阻塞原因，不创建本地 Run |
| Retry/Cancel Workflow | `workflow:retry` / `workflow:cancel` | Run 只读 |

所有主要页面必须区分 loading、empty、401、403、404、409/stale、422、429、dependency unavailable、outcome unknown 与投影延迟。Provider `UNKNOWN` 不是 FAILED；Artifact `PENDING_VALIDATION` 不是 READY；HumanTask completed 不等于 Owner Apply completed；StoryGraph current head 变化不允许静默把 Inspector 切到新版本。

## 9. 搜索、日志与业务诊断

- 项目原稿和 StoryGraph 搜索只调用 Backend `SearchScripts/SearchStoryGraph`，结果必须携带 Owner/Version/Evidence 深链；
- Elasticsearch 是可重建检索投影，不提供前端写入或直接查询凭据；
- Kafka 负责后端 Outbox 后的异步投影和日志解耦，不成为浏览器状态通道；
- ELK 页面属于运维日志诊断，不嵌入创作工作台；创作者只看到 Backend 授权后的业务错误、trace id 和安全诊断链接；
- Run 页面以 PostgreSQL/Temporal 对账后的业务投影为准，日志不能覆盖 Workflow/Owner 状态。

## 10. 验证设计

测试只进入 `frontend/tests`：

| 层级 | 必须证明 |
|---|---|
| Architecture | 新页面只经生成 OpenAPI + RTK Query；无业务 DTO 副本、直接基础设施 client、源码测试文件或写入 Canvas |
| Unit | Character/Location Card View 映射、State/Style/AssetVersion 分轴、任务状态与决议状态不混用 |
| Component | 三视图 coverage、缺失资产、stale task、unknown provider、Owner Apply pending、Lens Inspector 与错误态 |
| Contract | subject kind 与 renderer、精确 revision/hash、幂等对账、Story/Workflow ID 分离、Search 深链 |
| E2E | 角色跨集同一身份、地点跨 Scene 复用、Reference 选择后发布 AssetVersion、Shot 绑定精确版本、只读 Lens 反查 |

关键负向场景：

1. 一个角色的不同服装/画风不会生成多个身份卡；
2. Scene 不会被当作 Location；
3. 缺 front/profile/back 的 composite 候选不能显示可发布；
4. Decision HTTP 成功但 Owner Receipt 未完成时不显示业务已应用；
5. Story Lens 不存在写入控件，DOM 操作不能改变 Backend；
6. 当前无 Backend Query 时页面不以 mock 或旧 Storyboard 结构返回成功；
7. Story/Workflow Node ID、Query cache 和 renderer 不互用。

完成全部实现和真实 CI 前不运行 `agent-browser`。最终浏览器旅程必须等 `SG-I27` 通过并提交后，在 `SG-I28` 覆盖“原稿 → 剧集/场景 → 角色/地点卡 → Reference 审核 → Shot/Binding → Story Lens/Run 反查”。

## 12. 风险与事实来源

主要风险：

- 把 Production Bible 候选实体误当正式角色/地点卡；
- 为每个 Episode/Scene 复制 Character/Location 身份；
- 把 AssetState、Style 和 AssetVersion 混成“角色造型”自由 JSON；
- 把 HumanTask completed、ReviewDecision recorded、Owner Apply completed 合成一个 UI 状态；
- 用 Storyboard 页或 mock 图冒充 StoryGraph；
- 在 Backend Contract 前先实现按钮并模拟成功；
- 让浏览器直连 Kafka、Elasticsearch、Temporal 或 Provider。

角色/地点/三视图与 StoryGraph 语义以 [0010](0010-StoryGraph内容图与DAG创作画布设计.md)为事实来源；Owner、Binding 与 Query 以[后端领域模块功能设计](2002-后端领域模块功能设计.md)为事实来源；前端状态与 Lens 架构以[1001](1001-前端应用架构.md)为事实来源；公共审核命令和恢复以 `SG-D16` 接受后的 [2055](2055-Workflow公共HumanGate命令与恢复设计.md)为事实来源。
