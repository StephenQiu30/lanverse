# AI 绘画提示词知识库技术选型与功能实现设计

## 1. 状态与产品闭环

本文是待用户接受的第三份 Design，不代表已经授权开始实现。MVP 的完成定义不是“爬虫能请求网页”，而是以下闭环在固定数据修订上可恢复、可审计、可搜索、可下架：

```text
准入决定 → 采集 prompt/参数/图片 → 规范化与门禁 → 存储/索引
→ 登录用户图库 → 详情与复制 → 管理审核/重试 → 撤销与删除
```

默认假设为内部单租户知识库、成人内容完全拒绝、首年最多 100K 可发布示例；只有接受 `DESIGN-001/002/003` 后才进入 PRD。

## 2. 技术基线与版本策略

| 层 | 选择 | 固定方式与理由 |
| --- | --- | --- |
| Web | Node.js 24 LTS、Next.js 16 App Router、React 19.2、TypeScript 6、pnpm 11、Tailwind、TanStack Query 5 | Node 固定 24 major；Next/React 成组升级，TS 7 暂缓；SSR 负责首屏，客户端负责筛选状态 |
| Python | CPython 3.13、FastAPI、Pydantic 2、SQLAlchemy 2.0、Alembic | 3.13 仍在 bugfix 支持期且被 Celery 5.6 支持；FastAPI `0.x` 固定到已验证 minor，不单独钉 Starlette |
| 任务 | Celery 5.6、RabbitMQ 4.3、PostgreSQL jobs/outbox | RabbitMQ 是 Celery 默认 broker；只负责投递，消息丢失或重复不能改变 PostgreSQL 最终状态 |
| 数据 | PostgreSQL 17 最新 minor、`pg_trgm`、pgvector 0.8 | 一个事务事实源即可覆盖 100K；词法、过滤、向量、权限查询无需跨库一致性 |
| 采集 | httpx、huggingface_hub、PyArrow Dataset | MVP 流式读取固定 DiffusionDB Parquet 修订，不用 DataFrame 全量载入；网络适配器只允许白名单目标 |
| 媒体 | Pillow 12.3+、隔离临时区、MinIO AIStor Free | 通过 S3 API 访问；原图与缩略图分 bucket/权限，解码及 no-egress 沙箱遵循 `DESIGN-002` |
| 本地基础设施 | Docker Compose、PostgreSQL/RabbitMQ/MinIO | 容器、Erlang/OTP 与 AIStor release 按 digest 固定；Compose 不作为生产编排器 |
| 依赖 | Python `uv.lock`、Web `pnpm-lock.yaml` + `packageManager` | 锁文件和工具精确版本入库；CI 使用 frozen 模式，模型固定 revision 与 SHA-256 |
| 质量 | pytest、Ruff、mypy、Vitest/RTL、Playwright、Locust | 单元、真实依赖集成、契约、安全、端到端、性能分层验证 |
| 观测 | JSON 日志、OpenTelemetry、Prometheus-compatible metrics | 保持供应商中立；trace、run、job、source、item id 可串联 |

具体 patch 版本在 Plan 开始时解析并写入锁文件，不把“latest”作为可重复构建输入。常规升级只跨 patch；minor/major 或 Embedding 变更必须运行契约、回归、搜索质量和迁移/回滚验证。

RabbitMQ 使用独立 vhost/用户、TLS、持久消息、manual ack、DLX 和队列年龄告警；禁用默认 guest 远程访问。部署 provisioner 以独立短时凭证预建 exchanges、bindings、DLX 与 `fetch/pipeline/media_fetch/media_process/review_derive/index/delete` 七个 quorum queue，Celery `task_queues` 使用 `no_declare=True` 并显式 routes；设置 `task_create_missing_queues=False`、`broker_transport_options={"confirm_publish": True}`、`worker_detect_quorum_queues=True`、`task_acks_late=True`、`worker_enable_remote_control=False`、`worker_send_task_events=False`、`task_send_sent_event=False`，并以 `--without-gossip --without-mingle --without-heartbeat` 启动（保留 broker TCP heartbeat）。dispatcher 是唯一 publisher，只获 task exchange write；Worker 只获自身 queue read、无 configure/write，监控走 DB lease/OTel/Prometheus。消息仅 JSON、禁用 pickle；自定义 `worker_consumer` 的 `on_decode_error/on_unknown_task` 在 DB 审计提交后 `reject(requeue=False)`，由 broker DLX 路由 invalid-message，必须通过真实 RabbitMQ 契约测试。开发单节点；生产 HA 使用 3 节点 quorum queues。消息只含 DB 标识、不用 broker result backend，调度/重试以 PostgreSQL 为准；RabbitMQ 4.3 在社区支持结束前升级并回归。

MinIO 采用受维护的 AIStor Free，而不是已归档的 Community 二进制。Free license 不到期（`Expiry=N/A`），但 license 文件作为运行时 secret 且不得入库，仓库不分发 AIStor 二进制；启动门禁执行 `mc license info` 与 S3 CRUD 探针，缺失/无效时 fail-closed。MVP 仅单节点并禁用 versioning/object lock，生产数据/recovery 卷使用宿主机卷加密，每个 backup epoch 使用独立 envelope key。每日 epoch 获取对象引用锁、排空写入/outbox，生成只含 raw/original/display-derived/获准 quarantine 的 bucket/key/hash/rights manifest，显式排除 media-staging/review-derived，再以 manifest 驱动逻辑对象快照并记录匹配的 PostgreSQL checkpoint 与 key id/version 到异机/异故障域，目标 RPO ≤24 小时、RTO ≤8 小时。恢复到离线 namespace 后先应用当前 suppression/deletion ledger，再清除撤销/无引用 key；快照后缺失对象标记 unavailable 后安全重抓，禁止 `publishable + missing object`，清洗后才上线。副本及 epoch key 30 天内删除/crypto-shred；多节点、复制或 SLA 必须升级 Enterprise Lite/Enterprise。

## 3. 代码结构与依赖边界

```text
apps/
  web/                         # Next.js 页面与生成的 OpenAPI 类型
  api/src/thief_api/           # HTTP、会话、RBAC、依赖注入
  worker/src/thief_worker/     # Celery、scheduler 与各角色入口
packages/core/src/thief_core/
  modules/{sources,ingestion,catalog,governance,media,search}/
  infrastructure/{db,http,object_store,queue,auth,telemetry}/
  contracts/{api,events}/
migrations/
tests/{unit,integration,contract,e2e,security,performance,fixtures}/
infra/{compose,containers,postgres,observability}/
```

`api/worker → core`，core 不依赖 FastAPI、Celery 或 Next.js。六个业务模块不直接写其他模块的表，通过应用服务和事务内 Outbox 协作。API、scheduler、dispatcher、fetch、pipeline、media-fetch、media no-egress、review-derive no-egress 与 indexing 是同一模块化单体的不同运行角色，不是首版微服务；scheduler 另用 PostgreSQL advisory lock 防双调度。media/review-derive 分别只消费 `media_process/review_derive`，禁止公网但允许白名单私网 PostgreSQL/RabbitMQ/MinIO，且使用不同 MinIO 身份。MVP 来源运行只允许管理员手动触发，scheduler 仅创建到期 job、重试与 reconcile，不提供 cadence 配置。

## 4. 身份、角色与会话

首版账户由受控 CLI/一次性 seed 创建，不内置默认密码；使用同源 HttpOnly/Secure/SameSite 会话 cookie、数据库会话撤销和 Argon2id 密码散列，所有写请求校验 Origin/CSRF。浏览者可搜索和查看，复制由对象 capability 决定。`/admin/sources|runs` 需要 `source:manage`，隔离裁决需要 `review:moderation`，notice/delete 需要 `notice:manage`；即使首版同一账号持有三者，也不能在代码中合并为无边界超级权限。

## 5. MVP 功能与页面

| 页面 | 必须实现的行为 |
| --- | --- |
| `/login` | 登录、退出、失败反馈、会话过期回跳，不泄露账号是否存在 |
| `/library` | 关键词、来源/模型/语言/比例/标签/许可/时间/有图筛选，相关度/最新排序，opaque cursor 图库；完整加载/空/错误状态 |
| `/examples/[id]` | 获准效果图或来源链接、prompt/negative prompt、参数表、许可与归属；有 `can_copy_prompt` 时才显示复制 |
| `/admin/sources` | 当前准入决定、到期/最后成功时间、kill switch、固定 revision/limit 启动运行 |
| `/admin/runs`、`/admin/runs/[id]` | 发现/处理/发布/隔离/拒绝/失败计数、错误、取消和受控重试 |
| `/admin/review` | 隔离、重复候选与 notice/delete 子视图；经专用 review-media 服务查看 case-scoped 短时媒体，裁决必须有原因、审核人和审计记录 |

卡片只显示获准缩略图、截断 prompt、模型、来源和许可。Prompt 永远按纯文本渲染；图片内联需要 `create_thumbnail` 与 `display(audience=internal)` grant，API 只返回派生 variant，不返回原图。复制需要独立 `copy_prompt` grant。DTO 返回 `capabilities.can_copy_prompt/can_inline_asset`，UI 条件展示；签名 URL 最长 5 分钟且不经过会延长撤销窗口的图片优化缓存。没有图片能力时不下载或代理，只显示获准的来源详情链接。标签仅来自获准来源字段或人工审核。

## 6. API 契约

所有端点以 `/v1` 开头，错误统一为 `{code,message,trace_id,details}`；列表使用 opaque cursor 且 `limit <= 50`。OpenAPI 是前端类型唯一来源，生成文件不得手改。

| 范围 | 端点 |
| --- | --- |
| 会话 | `POST /auth/login`、`POST /auth/logout`、`GET /auth/session` |
| 浏览 | `POST /search`、`GET /examples`、`GET /examples/{id}`、`GET /sources` |
| 来源/运行 | `GET /admin/sources`、`PATCH /admin/sources/{id}`、`POST /admin/sources/{id}/runs`、`GET /admin/runs`、`GET /admin/runs/{id}`、`POST /admin/runs/{id}/cancel`、`POST /admin/jobs/{id}/retry` |
| 审核/删除 | `GET /admin/review-cases`、`POST /admin/review-cases/{id}/asset-url`、`POST /admin/review-cases/{id}/decisions`、`POST /admin/notices`、`GET /admin/notices/{id}`、`POST /admin/deletion-jobs/{id}/retry` |

`POST /search` 执行带排序的 query 检索，`GET /examples` 执行无 query 浏览；两者复用同一 visibility predicate 和卡片 DTO。搜索 filters 含 source/model/language/aspect ratio/tags/license/time/has_asset。卡片/详情输出包括 capabilities、展示 prompt、recipe、来源 revision/时间、许可/归属和当前获准 variant。所有管理写接口需要 RBAC、审计与 `Idempotency-Key`。人工 approve 不能覆盖未知/过期准入、缺失 grant 或失败的安全评估；401/403/404 不暴露隔离对象是否存在。

`POST /admin/review-cases/{id}/asset-url` 在安全 review-derived 缺失或过期时返回 `202 + {status: processing}` 并幂等路由到 `review_derive`；job 与 ready 提交使用 case-version fencing。就绪后才返回 60 秒、`no-store` URL，失败只返回可审计错误元数据。

## 7. 从采集到展示的实现契约

1. 管理员只能对 current decision 推导为 `active` 的来源启动受阶段上限约束的 run。
2. Fetch worker 领取 DB lease，重验政策/限速，获取 metadata；同一事务写 observation、下一 job 与 outbox 后才推进 cursor。
3. Pipeline 按 adapter/parser version 解析 prompt、negative prompt 与 recipe，保留 raw hash 和来源观察关系。
4. Rights、PII、文本审核 fail-closed；只有 `store_original`、`create_thumbnail` 与 `display(audience=internal)` 精确 grant 通过才创建媒体 job，`copy_prompt` 单独计算。
5. Media-fetch 下载到临时隔离区；no-egress worker 校验、清元数据、重编码并审核，不安全输入不产生可见 variant。
6. Final gate 在事务内重验 source/access/grants/PII/moderation/media/suppression，设置 `publishable`、逐对象 capabilities 并写 index outbox。
7. Search consumer 幂等生成全文、trigram 与获准 Embedding；API 每次查询再次套用 current visibility predicate，只为 `can_inline_asset` 生成 variant 签名 URL。
8. Notice/政策变化先 suppression 使所有查询立即隐藏，再异步扇出对象、索引、缓存、外部处理方和备份防复活任务。

## 8. 检索决策

S1-S3 先交付 PostgreSQL 全文 + `pg_trgm`，避免 Embedding 阻塞基本图库。S4 默认在独立 no-egress inference 角色中运行固定 revision 的 `BAAI/bge-m3`（1024 维、MIT、多语言），只处理获得 `create_embedding` grant 的展示文本；模型不可用时词法搜索仍可用，但语义请求明确降级。RRF 合并词法与向量候选；100K 先基准测试精确检索，只有性能不达标才启用 HNSW 并重新验收过滤召回。Embedding 按 model/revision/dimension 分区，新版本后台重建并原子切换，禁止不同向量空间混排。

## 9. 可独立验收的纵向切片

| 切片 | 可见产出与门禁 |
| --- | --- |
| S0 安全骨架 | Compose、迁移、登录/RBAC、fixtures-only、jobs/outbox、对象状态与 visibility predicate；真实 Rabbit 权限/DLX 契约及并发上传/最后引用删除 fixture 通过 |
| S1 DiffusionDB 1K | 仅在 DG-01/02/06 有记录后，固定 revision 流式导入、规范化、精确去重、词法搜索和 run 进度；重复导入/崩溃恢复不重复、不跳页 |
| S2 图片闭环 | 获准图片下载、no-egress 校验/审核、缩略图与安全 review-derived、签名 URL 和来源链接降级；恶意/不可解码 fixture 不生成浏览器 URL |
| S3 管理闭环 | 来源启停、运行取消/重试、隔离裁决、审计和关键告警；待审超 24h 可再生成，202 后立即结案/撤权的并发 fixture 无可签名对象且有删除 receipt |
| S4 混合检索 | 本地 Embedding、pgvector/RRF、过滤与 30+ gold queries；Top-10 ≥80%，记录 NDCG@10 |
| S5 撤销删除 | notice、suppression、delete fan-out/receipt；用户面/CDN ≤5 分钟隐藏，在线删除 ≤24 小时且恢复不复活 |
| S6 扩容硬化 | 真实获准数据扩至 10K，100K fixture/20 并发搜索 P95 <1 秒、错误率 <1%；从含已删除/新增 key 的 epoch 恢复，验证 RPO/RTO、清除 receipt、防复活、无缺失发布对象、临时 bucket 不进 backup/recovery 和 30 天清除 |

S0 的图片与内容只能使用项目自有 fixture，不代表批准外部采集；治理激活门禁未满足时来源保持 disabled。Civitai 不属于 S0-S6，必须按 `DESIGN-001` 另起阶段复审。每一切片均按 Red → Green → Refactor，并在后续 Acceptance 保存精确命令、UI 截图和故障注入证据。

## 10. 被否决的首版方案

- 全 TypeScript：页面统一，但 Python 的 Parquet、媒体审核、Embedding 与数据处理生态更直接；强行统一会增加适配成本。
- Scrapy/Playwright 主采集器：首来源是固定 Parquet，不需要 HTML crawl；未来仅在来源明确许可且 HTTP API 不足时增加专用适配器。
- OpenSearch/独立向量库：100K 规模下增加双写、删除和权限一致性风险，当前 PostgreSQL 能满足词法、向量和过滤。
- 微服务/Kafka/Airflow/Kubernetes：不改善当前最小闭环；先用多运行角色与严格权限隔离，指标证明瓶颈后再拆。
- MinIO Community 旧二进制：官方仓库已归档且旧发行版不再维护；本项目采用受维护、固定 release 的 MinIO AIStor Free，不拉取 Community `latest` 镜像。

## 11. 接受前待确认

已确认基础设施选择为 RabbitMQ + MinIO AIStor Free。其余建议默认值：内部知识库；主要运营法域为中国大陆；本地 BGE-M3；DiffusionDB 固定 1K → 10K；首年 100K；MVP 完全拒绝成人内容。当前全部 `/v1` 用户端点要求登录，不能通过配置改为匿名。公开版本必须另起 Design/PRD，增加 `display(audience=public)` 对象级 grant、公开投诉/举报与 DSAR、第三方/跨境评审、WAF/限流，并验证搜索、CDN、SEO、分享缓存统一 suppression。

Design 接受标准：三份 Design 的假设一致且无开放 P0；技术基线、页面/API、数据闭环和 S0-S6 可写成 SMART PRD。用户明确接受后，把三份状态改为 `accepted` 并创建 PRD；在此之前不创建业务代码或迁移。来源联网激活另需 DG-01/02/06 的负责人、处理角色、来源证据与违法内容 SOP 均有记录；Design 接受不能替代该批准。
