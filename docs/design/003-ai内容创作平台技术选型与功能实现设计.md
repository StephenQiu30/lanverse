# AI 内容创作平台技术选型与功能设计

## 1. MVP 产品闭环

```text
采集模板 → 发现/搜索 → 选择做同款或空白创作
→ 编辑提示词与参数 → 异步生成 → 查看个人作品
```

模板目录公开访问；生成和作品管理需要登录。MVP 只生成图片，不包含视频、社区、计费或自训练模型。

## 2. 技术基线

| 层 | 选择 | 用途 |
| --- | --- | --- |
| Web | Next.js 16、React 19、TypeScript、Tailwind、shadcn/ui、Radix UI | 模板站、创作工作台和管理后台 |
| API | Python 3.13、FastAPI、Pydantic 2、SQLAlchemy 2、Alembic | HTTP API、会话和应用用例 |
| Worker | Celery 5.6、httpx、Pillow | 采集、媒体、索引和生成任务 |
| Queue | RabbitMQ 4.3.3 | 四类队列、有限重试和死信 |
| Database | PostgreSQL 18.4、`pg_trgm`，按需 pgvector | 业务事实源、任务状态和搜索 |
| Storage | MinIO AIStor `RELEASE.2026-06-06T02-44-06Z`、Free license、S3 API | 来源示例和用户生成作品 |
| Generation | 火山方舟 Seedream 5.0 Lite、北京区域 | 真实图片生成，供应商通过 Port 隔离 |
| Quality | pytest、Ruff、mypy、Vitest、Playwright | 单元、集成、契约和端到端验证 |
| Local Infra | Docker Compose | PostgreSQL、RabbitMQ、MinIO |

依赖由锁文件固定。MVP 不引入 Redis、OpenSearch、Kafka、Airflow、Kubernetes 或本地 GPU 集群。

## 3. 代码与依赖边界

```text
frontend/                     # 标准 Next.js App Router、shadcn/ui、Radix UI
  src/{app,components/ui,lib,hooks}/
backend/
  src/thief/{api,identity,catalog,infrastructure}/
  migrations/{env.py,versions/}
  tests/{unit,integration,contract,e2e,fixtures}/
infra/compose/                # PostgreSQL、RabbitMQ、MinIO
```

API/Worker/Scheduler 从同一个 `thief` 包启动；use case 不依赖框架，基础设施实现放在模块 repository/source 或 `infrastructure`。只创建已实施模块，数据库使用单线性 Alembic 历史；详细规则见 `DESIGN-004`。

## 4. 服务与队列

| 应用角色 | MVP 进程 | 扩展方式 |
| --- | --- | --- |
| `web` | 1 | 无状态多副本 |
| `api` | 1 | 无状态多副本 |
| `worker` | 本地可用 1 个进程 | 按队列独立扩容 |
| `scheduler` | 1 | 只调度采集和维护任务 |

RabbitMQ 队列：

- `crawl`：来源发现和解析。
- `media`：示例及生成图片下载、校验、衍生处理。
- `index`：目录搜索投影。
- `generation`：模型提交、轮询、回调协调和结果归档。

消息只含 `job_id/event_id/trace_id`。PostgreSQL 保存业务状态；生成队列使用独立并发和限速，防止采集任务影响创作体验。

## 5. 用户页面

| 页面 | MVP 行为 |
| --- | --- |
| `/`、`/explore` | 推荐、搜索和分类筛选 |
| `/templates/[id]` | 示例图、提示词、参数、来源和“做同款” |
| `/create` | 模板预填或空白创作、参数编辑和提交 |
| `/create/jobs/[id]` | 排队、生成、成功、失败和取消状态 |
| `/works`、`/works/[id]` | 当前用户的作品列表、详情和删除 |
| `/login` | 用户登录和会话恢复 |
| `/admin/sources` | 来源启停、限速和手动运行 |
| `/admin/runs`、`/admin/review` | 采集/生成运行、失败重试、审核和下架 |

页面覆盖加载、空、失败、配额不足、供应商不可用和资源被删除状态。

## 6. API

所有端点以 `/v1` 开头，错误统一为 `{code,message,trace_id,details}`。

| 范围 | 端点 |
| --- | --- |
| 公开目录 | `GET /templates`、`GET /templates/{id}`、`GET /search`、`GET /categories` |
| 会话 | `POST /session`、`DELETE /session`、`GET /session` |
| 创作 | `POST /creation-drafts`、`PATCH /creation-drafts/{id}`、`POST /generation-jobs` |
| 任务 | `GET /generation-jobs/{id}`、`POST /generation-jobs/{id}/cancel` |
| 作品 | `GET /me/works`、`GET /me/works/{id}`、`DELETE /me/works/{id}` |
| 管理 | 来源、运行、审核、下架和受控重试端点 |

列表使用 cursor 分页，`limit <= 50`。`POST /generation-jobs` 必须携带 `Idempotency-Key`，验证用户、配额、draft 版本和输入审核后创建任务。

S2-T03 的公开目录契约固定如下：

- `GET /v1/templates` 接受 `category/model/aspect_ratio/source/cursor/limit`；
  `GET /v1/search` 额外要求非空 `q`，其余筛选和分页语义相同。
- 默认 `limit=20`，范围为 1-50。按 `published_at DESC, id DESC` 稳定排序；
  cursor 是包含这两个值的不透明标记，筛选条件变化时仍只解释分页位置。
- 列表返回 `items/next_cursor`。模板公开字段包含 ID、slug、标题、提示词、
  模型、比例和来源摘要；详情补充 negative prompt、原始参数、完整来源快照、
  content hash 与示例引用。
- `GET /v1/categories` 只返回至少拥有一条公开模板的分类及公开模板数量。
- 四个端点无需登录，只读取 `status=published` 且 `published_at` 非空的模板。
  无效 limit/cursor/query 使用统一 `invalid_query`；不可见或不存在的详情统一 404
  `template_not_found`，不泄露未发布记录是否存在。

S2-T04 的公开目录 UI 使用 Next.js Server Components，契约固定如下：

- 首页读取最多 6 条最新公开模板；探索页以 GET 表单维护
  `q/category/model/aspect_ratio/source`，URL 是唯一筛选状态，cursor 翻页保留筛选项。
- 模板卡展示标题、prompt、模型、比例和来源；详情页展示 negative prompt、原始参数、
  完整来源/许可、content hash、示例引用和“做同款”入口。
- 页面必须覆盖 loading、API error、空结果、无媒体和 404。SOURCE-01 未激活时不伪造
  第三方图片，示例只显示明确的“媒体待接入”状态。
- Web 数据由服务端 `fetch` 获取且不缓存搜索结果；DTO 只能引用 OpenAPI 生成类型，
  不手写第二套接口结构，也不引入客户端数据或表单状态库。
- agent-browser 在 1440×900 与 390×844 验证首页 → 探索 → 筛选 → cursor → 详情，
  并检查键盘操作、URL、空态、错误态、横向溢出、console 和框架 error overlay。

## 7. 外部适配器契约

```python
class SourceConnector(Protocol):
    async def discover(self, cursor: str | None, limit: int) -> SourcePage: ...
    async def fetch(self, item: SourceItemRef) -> SourcePayload: ...
    def parse(self, payload: SourcePayload) -> ParsedExample: ...

class GenerationProvider(Protocol):
    async def submit(self, request: GenerationRequest, key: str) -> ProviderJob: ...
    async def get(self, provider_job_id: str) -> ProviderResult: ...
    async def cancel(self, provider_job_id: str) -> CancelResult: ...
```

供应商 Adapter 负责鉴权、字段转换、限速和错误映射；领域模块只理解统一的生成请求、状态和资源引用。

## 8. 生成执行契约

1. API 校验登录、配额、输入安全和 `Idempotency-Key`，事务内创建 `generation_job=queued`。
2. Worker 领取 job 后使用稳定 provider key 提交，保存 provider job ID 和计费元数据。
3. 同步结果直接处理；异步结果通过轮询或已验证签名的 webhook 更新。
4. 结果先进入受控下载和媒体审核，通过后写 MinIO 并创建私有 `user_work`。
5. 未知结果进入 reconcile；供应商明确失败才允许按策略重试，不盲目重复提交。
6. 取消采用 best effort；供应商已完成时仍归档结果并按产品规则处理配额。

## 9. 搜索与模板兼容

首版使用 PostgreSQL 全文搜索和 `pg_trgm`，支持 prompt、分类、模型、比例、来源和标签。建立至少 30 条人工查询，Top-10 命中率目标 ≥80%；不达标后再引入 pgvector。

模板保留 `source_model` 和原始参数。Creation 层通过模型能力表映射支持的尺寸、参数和提示词格式；无法映射的字段不静默丢弃，页面明确提示参考效果可能不同。

## 11. MVP 验收基线

1. 用户能从模板“做同款”或空白创建并获得真实生成图片。
2. 重复提交同一幂等请求不会重复生成或扣费。
3. Worker 重启后任务可恢复，终态与供应商一致。
4. 用户不能查看其他用户 prompt、任务或作品。
5. 未授权模板、不安全输入/输出和已删除内容不可访问。
6. 模板查询 P95 < 1 秒，生成提交 2 秒内返回 job ID。
