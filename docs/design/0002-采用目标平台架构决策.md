# 采用目标平台架构决策

- 状态：已接受目标
- 日期：2026-08-25
- 范围：Frontend、Backend、Agent、Workflow、数据与基础设施
- 上位设计：[完整设计基线](0001-AI短剧制作平台完整设计基线.md)

## 背景

AI 短剧生产同时包含交互式创作、长任务编排、受限智能体、付费模型调用、不可变媒体、人工审核、成本治理和可重建投影。领域模块与运行职责必须明确表达不同的事实源和失败路径；部署进程只在真实隔离或扩缩容证据出现后拆分。

本决策从零定义目标平台，不以任何既有仓库结构、语言实现、表或接口作为前提。

## 决策

1. Frontend 是独立 TypeScript Workspace，承载 Guided、Canvas、Review、AI 交互和 Collaboration 连接。
2. Backend 是一个 Go Module，按领域模块组织；MVP 只构建一个 `lanverse` Binary，由唯一 `backend/cmd/main.go` 装配 API、Workflow 和 Event Runtime。`model-gateway`、`media-worker` 或独立 Worker 只有在真实隔离/扩缩容证据出现后才设计和拆分。
3. Agent 是独立 Python Runtime，只执行受限的 Structured、ToolLoop 或有限 LangGraph 推理，不拥有业务事实。
4. Temporal 是跨步骤长任务、Timer、Retry、Human Wait、Signal 与恢复的唯一 Workflow 引擎。
5. PostgreSQL 保存业务事实；ObjectStore 保存对象字节；Kafka 传输已提交事件；Elasticsearch、Redis 和 Yjs 只保存投影或临时状态。
6. Guided 与 Canvas 发布同一种不可变 Authoring Revision，并由唯一 Compiler 生成 Workflow Definition。
7. 所有模型调用经过 Model Gateway、Cost/Quota、Execution Claim 和审计；所有输出先成为 Candidate/Artifact。
8. 每个业务事实只有一个 Owner，跨模块通过公开 Application Interface、Snapshot、Intent/Receipt 或 Event 协作。

## 约束

- 不按最终目录一次性预建空项目、空服务或空抽象层。
- Browser、Agent、Provider、Media 工具和 Projection 不得直接写业务数据库。
- Kafka 不承担 Workflow Timer、Retry、Human Wait、Yjs 协作或 Token Stream。
- LangGraph 不管理 Episode 生命周期，只管理单个 Agent 的有限复杂推理。
- 真实与漫画内容共用 Production Core，以 Policy/Preset/Style/Motion/Render 配置表达差异。
- 目录、代码、Schema 或单测存在不构成交付；必须以真实业务 Acceptance 判定完成。

## 结果

该决策提供清晰的事实源、权限、故障恢复和扩缩容边界，并允许产品按 Guided MVP 与 Platform Complete 两级发布。代价是必须在实现前完成契约、所有权和跨服务失败语义设计，并为每个运行边界建立 Integration、Replay、故障注入和端到端验收。
