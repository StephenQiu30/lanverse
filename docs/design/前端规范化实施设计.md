# 前端规范化实施设计

2026-09-21。用户已授权依据 PROJECT 完整整改 frontend；本文细化已有规范的实施范围，不另建产品或技术体系。

## 问题与目标

当前 Next.js App Router、Radix Nova 与 pnpm 已确定，但业务页仍有原生交互控件、手写空态、非语义颜色与不一致表单结构；共享布局反向依赖 identity endpoint，身份 Hook 放在通用 hooks 下。整改覆盖现有路由和业务组件，不只修改首页。

## 边界与目录

- `src/app` 仅保留 Next 路由、错误/加载边界、全局主题和 provider 装配。
- `features/identity` 拥有会话 Hook、带身份请求的 StudioShell、认证与账号表单；共享布局通过回调接收退出动作，不请求业务 API。
- `components/layout`、`components/studio` 只保留展示与导航组合；`components/ui` 维护官方 shadcn/Radix 基础组件，不导入 Feature。
- Feature 公共入口明确列出，禁止用宽泛文件名规则允许跨模块内部导入；不增加转发 index 或空目录。
- 保持现有 Go API/RTK Query 所有权。上一轮记录的完整 Swagger 注解与旧调用迁移是独立的跨端事项；本轮不伪造响应 schema。

## UI 与交互

1. 保留当前无边框、留白分组、明暗主题和品牌素材，不切换 preset。新增组件来自已配置的官方 `@shadcn` Radix registry，不整批覆盖现有基础组件。
2. 全部表单使用 FieldGroup/Field/FieldLabel，相关选择使用 FieldSet/FieldLegend；复杂校验用 React Hook Form + Zod，保留原生 form 提交语义。字段错误贴近控件，容器 data-invalid 对应控件 aria-invalid；忙碌期间不可重复提交。
3. 选择控件采用 Select/RadioGroup，条目有 Group；已有表格保留 shadcn Table，不建立自定义表格框架。展开详情用 Collapsible，操作用 Button。
4. 持久错误用 Alert，短时保存成功用 Sonner；空态用 Empty，结构加载用 Skeleton，操作忙碌用 Spinner。不能把缺失数据描述为成功，也不把内部状态机诊断作为普通用户的主界面文案。
5. 基础组件用 variant/size；业务样式用语义 token、gap、cn，移除散落的色阶和逐页控件外观覆盖；官方基础组件必要的状态选择器集中保留。
6. 加入路由 loading/error 边界，恢复操作可键盘访问。移动端控件可换行，内容不能把页面撑出视口；Dialog 焦点与 Escape 关闭由 Radix 管理。

## 实施和验收

按目录边界、基础组件、表单/交互、反馈/主题顺序实施。复用业务测试验证契约，补充字段校验、标准组件交互、桌面/移动端浏览器验收。运行 frozen install、format、lint、typecheck、test、build；实际页面验证登录、项目弹窗、账户设置及审核选择控件的键盘行为。结果与剩余限制追加本文件，避免只报告静态扫描通过。

依据：[PROJECT](../../PROJECT.md)、[Next.js 项目结构](https://nextjs.org/docs/app/getting-started/project-structure)、[shadcn Field](https://ui.shadcn.com/docs/components/radix/field)、[shadcn React Hook Form](https://ui.shadcn.com/docs/forms/react-hook-form)。同时采用 Vercel nextjs/react-best-practices 与 shadcn 技能。
