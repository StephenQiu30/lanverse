## 1. 结论

1. **Lanverse 首先是内部生产工具**：服务自己的 1–2 人制作小组，把一部已有的成品剧本高效、可控地做成可发布的短剧成片。对外产品化放在内部跑通之后。
2. **核心价值排序：一致性 > 可控性 > 成本透明 > 生成效率。** 生成质量主要取决于第三方模型，平台负责让它稳定、可控、可追溯。
3. **两种视图、一份数据**：流水线视图负责按阶段批量生产，画布视图负责探索和精修，两者读写同一套项目数据。MVP 先交付流水线视图，画布紧随其后。
4. **范围优先于时间**：MVP 以“完整业务流程功能确定、可跑通”为准，时间不作硬约束（P13）。第 12 节说明取舍原则与优先顺序。

## 3. 背景与问题

### 3.1 要解决的问题

内部团队已有成品剧本，想用 AI 替代实拍或传统动画制作短剧。现有做法是在多个工具之间手工搬运：大模型拆剧本 → 生图工具定角色 → 视频模型逐镜头生成 → 配音工具 → 剪辑软件。主要问题：

| 问题 | 表现 |
| --- | --- |
| 角色不一致 | 同一角色换镜头就换脸，服装、场景漂移 |
| 不可控 | 抽卡式生成，画面不符合分镜；改一处要全部重来 |
| 素材混乱 | 版本、文件散落各处，不知道成片用的是哪一版 |
| 成本不清楚 | 重试、重复生成的花费无法按镜头统计 |
| 规模化难 | 60 集的剧，角色和场景要在每集重复处理 |

### 3.2 目标

| 阶段 | 目标 |
| --- | --- |
| MVP | 1 人在平台内把一集已有剧本做成可发布成片，写实或风格化均可，全过程成本可查（时间不作硬约束） |
| V1 | 画布视图上线；整部剧按集连续生产、跨集复用资产 |
| V2 | 对外产品化：多组织、角色协作、支付与套餐 |

## 4. 用户与使用场景

### 4.1 用户

MVP 只有一类用户：**内部制作者**，一个人兼任编剧校对、美术定稿、导演分镜、剪辑交付。另设**管理员**，负责创建账号、配置模型供应商、设置项目预算。

对外用户（工作室、个人创作者、版权方）在 V2 再设计。

### 4.2 核心场景

| # | 场景 | 版本 |
| --- | --- | --- |
| S1 | **整部剧导入，逐集生产**：导入 60 集剧本，解析出全剧角色、场景，然后从第 1 集开始逐集生产 | MVP 支持导入整部剧；MVP 验收只要求完成 1 集 |
| S2 | **一集从剧本到成片**：确认本集场次 → 确认本集用到的角色、场景定稿 → 确认分镜 → 选关键帧 → 选视频 → 配音 → 剪辑 → 导出 | MVP |
| S3 | **改角色造型**：修改造型后，系统列出受影响镜头与预估费用，用户选择重做哪些 | MVP |
| S4 | **单镜头重拍**：某一镜不满意，只重做这一镜 | MVP |
| S5 | **全能参考生成镜头**：为某一镜组合角色造型图、场景图、道具图、动作 / 运镜参考视频和参考音频，一次生成保持主体一致、动作与表演节奏符合参考的视频 | MVP（必须，见 VID-04） |
| S6 | **续集复用**：第 2 集直接复用第 1 集已定稿的角色、场景 | MVP 数据上支持；批量体验 V1 |
| S7 | **中断恢复**：生成过程中关闭浏览器或服务重启，回来后任务继续，不重复扣费 | MVP |
| S8 | **画布精修**：在画布上围绕一个镜头尝试多种方案，选定后回写分镜 | V1 |

## 5. 业务流程

### 5.1 整体流程

```text
整部剧导入 → 全剧解析（集 / 场 / 台词）→ 全剧设定集（角色 / 造型 / 场景 / 道具）
                                              │
                           ┌──────────────────┴── 逐集生产（每集重复）──────────────────┐
                           │ 本集资产定稿 → 分镜 → [关键帧] → 视频 → 配音 → 剪辑 → 交付 │
                           └──────────────────────────────────────────────────────────────┘
```

`[关键帧]` 只在“图生视频”模式的镜头中出现；“全能参考”模式的镜头由分镜直接进入视频生成（见 5.4）。

每个阶段遵循同一模式：**AI 产出候选 → 人工审阅 / 修改 → 选定为正式版本**。正式版本不可变，修改产生新版本。

### 5.2 各阶段说明

| # | 阶段 | 输入 | 系统做什么 | 人工确认 | 正式产出 |
| --- | --- | --- | --- | --- | --- |
| 1 | 剧本导入 | 整部剧的 docx / txt（单文件或多文件） | 保存原文件；规范化文本；识别集边界 | 确认分集 | 剧本版本 |
| 2 | 结构解析 | 剧本版本 | 按集解析场次、台词、动作、情绪、时间地点；每条可追溯原文 | 按集确认 | 集 / 场 / 台词行 |
| 3 | 设定集 | 全剧解析结果 | 抽取角色、造型、场景、道具；合并别名；记录状态变化（受伤、换装、年龄段） | 确认清单 | 设定集 |
| 4 | 资产定稿 | 本集用到的设定 + 项目风格 | 生成定妆照、三视图、场景图；选角色音色 | ✅ 锁定参考 | 锁定的参考资产与音色 |
| 5 | 分镜 | 本集场次 + 锁定资产 | 拆镜头；设置景别、机位、运镜、时长；分配台词；标注引用资产 | 逐镜可改 | 镜头表 |
| 6 | 关键帧（图生视频模式需要） | 镜头 + 参考 | 生成首帧候选 | 选图 | 选定关键帧 |
| 7 | 视频 | 图生视频：关键帧 + 镜头参数；全能参考：镜头的参考组合 + 镜头参数 | 按镜头选择的模式生成，多候选 | 选片 | 选定片段 |
| 8 | 声音 | 台词 + 角色音色 | TTS 生成对白；可上传真人音轨替换；生成字幕 | 试听 | 音轨、字幕 |
| 9 | 剪辑 | 片段 + 音轨 + 字幕 | 自动粗剪；用户调整顺序与入出点 | 预览 | 剪辑计划 |
| 10 | 交付 | 剪辑计划 | 渲染 1080p、加 AIGC 标识、技术质检 | 终审 | 成片版本 |

### 5.3 贯穿规则

1. **依赖传播**：上游版本变化，下游产物标记为“过期”，**不自动重新生成**；系统给出影响范围和预估费用，由用户决定重做哪些。
2. **候选与正式分离**：AI 结果先是候选，人工选定后才被正式引用；所有历史版本可查。
3. **局部重做**：失败或修改只影响真实依赖，其他镜头不受影响。
4. **视频生成前先锁定输入**：图生视频模式下，关键帧选定后才能生成视频；全能参考模式下，镜头的参考组合（每项都是已锁定版本）确认后才能生成视频。视频是最大的成本项【推断】，锁定输入能降低重拍。

### 5.4 视频生成的两种模式

| 模式 | 输入 | 适合 | 优先级 |
| --- | --- | --- | --- |
| 图生视频 | 选定关键帧（首帧）+ 镜头参数 + 运动描述 | 构图要求精确、需要先看静帧确认的镜头 | MVP |
| **全能参考** | 参考组合：角色 / 造型图（可多个角色）、场景图、道具图、动作或运镜参考视频、参考音频（驱动表演节奏、情绪或口播），加镜头参数与画面描述 | 多角色同框、动作复杂、需要模仿参考运镜或按音频节奏表演的镜头；可跳过关键帧阶段 | **MVP，必须** |

- 每个镜头选择一种模式，可随时切换；分镜生成时由 AI 建议模式，用户可改。
- 全能参考的参考组合**只能引用已锁定的资产版本或已上传的参考素材**，每项标注用途（主体 / 场景 / 道具 / 动作 / 运镜 / 音频）。参考音频可来自上传文件，也可引用本项目已生成的台词音频。
- 参考组合是镜头的正式输入：其中任一资产出新版本，该镜头已生成的视频标记过期（依赖传播规则）。
- 不同模型对参考数量、类型、时长的限制不同；超出所选模型能力时，在报价阶段提示并阻止提交。

### 6.4 分镜（SB）

| 编号 | 需求 | 优先级 | 验收标准 |

## 9. 规模估算【推断，P0 校准】

用于数据设计与成本测算，不作为验收指标。

| 作品形态 | 集数 | 单集时长 | 每分钟镜头数 | 单集镜头数 | 全剧镜头数 |
| --- | --- | --- | --- | --- | --- |
| 竖屏短剧 | 60–100 | 1–3 分钟 | 20–30 | 20–90 | 1,200–9,000 |
| 中短片 / 漫剧 | 10–30 | 3–10 分钟 | 10–20 | 30–200 | 300–6,000 |
| 单片 | 1 | 1–5 分钟 | 10–25 | 10–125 | 10–125 |

- 每镜头平均生成：关键帧 3–4 个候选、视频 2–3 次（含重拍）、对白 1–3 句。
- 以一部 80 集 × 2 分钟的竖屏短剧计：约 4,000 个镜头、约 1 万次视频生成、约 1.5 万段对白音频。
- **推论**：全剧视频生成费用是最大成本项，批量生成、结果复用和重拍率控制决定项目是否可行。P0 必须实测“单分钟成片成本”和“平均重拍次数”。

## 11. MVP 定义

### 11.1 MVP 包含

第 6 节所有标记为 **MVP** 的需求。一句话：**导入整部剧，选择其中一集，在流水线视图中完成第 5 节全部 10 个阶段，导出带 AIGC 标识的 1080p 成片。**

### 11.2 MVP 验收场景

以下场景全部通过才算 MVP 完成：

1. **写实项目一集**：导入一部至少 10 集的写实剧本，完成第 1 集（1–2 分钟）成片。
2. **风格化项目一集**：同上，风格化画风。
3. **全能参考**：写实与风格化项目中，各有至少 3 个镜头使用全能参考生成，其中至少 1 个为双角色同框、至少 1 个使用动作 / 运镜参考视频、至少 1 个使用参考音频，并满足 VID-04 的验收标准。
4. **修改传播**：修改一个角色造型，系统列出受影响镜头；只重做选中的镜头；旧版本可查。
5. **恢复与计费**：生成过程中重启服务、模拟供应商超时，任务恢复且账本无重复费用。
6. **第 2 集复用**：第 2 集直接使用第 1 集锁定的角色与场景进入分镜。
7. **成本**：两个项目都能查看每镜头、每集的费用明细与单分钟成本。

### 11.3 MVP 明确不做

画布（V1）、多人协作与权限、自助注册与多组织、支付与套餐、AI 编剧与小说改编、首尾帧、局部重绘、BGM / 音效、口型同步（待定）、声音克隆、剪辑工程导出、模型自动路由、备用供应商切换。

## 12. 范围与取舍

### 12.1 原则

产品负责人于 2026-09-25 确认：**以完整业务流程功能的确定为优先，时间不作硬约束**（P13）。因此 MVP 不因工期删减第 11 节定义的业务流程；取舍只用于决定实现顺序和实现深度。

### 12.2 取舍原则

1. **优先使用模型现成能力，不自研**：全能参考、画风都通过选择具备该能力的供应商实现；平台只做参考组合管理、编排、选择和记录。
2. **MVP 每种能力只接一家供应商**：备用供应商和切换放到 V1。
3. **界面从简**：MVP 只做流水线视图，以表格、列表、卡片为主；时间线只做顺序、入出点、对白与字幕。
4. **运维从简**：优先托管服务，减少需要自己运维的组件（第 13 节）。

### 12.3 取舍结果（已反映在第 6 节的优先级中）

| 需求 | 处理 | 理由 |
| --- | --- | --- |
| 写实与风格化两种画风 | MVP 保留 | 主要是模型与风格预设差异，开发增量小；P0 评测工作量翻倍 |
| 口型同步 | 移出 MVP，后续再定 | 产品负责人确认暂不考虑；对白镜头用镜头设计或参考音频处理 |
| **全能参考** | **MVP 必须，不可降级** | 产品负责人确认的核心能力。P0 必须找到至少一家在写实与风格化下都可用的模型；若找不到，是阻塞项目的风险，需要重新评估方案或时间，而不是降级（见 12.4） |
| 整部剧导入与解析 | MVP 保留 | 设定集需要全剧信息，否则跨集一致性无从谈起 |
| 批量生成（整场 / 整集） | MVP 保留基础能力 | 一集 20–90 个镜头，逐镜点击不可行 |
| 画布 | V1 | P9 决策；MVP 期间做画布性能 PoC |
| 备用供应商、模型切换 | V1 | 研发量大，MVP 不影响出片 |
| 首尾帧、局部重绘、BGM / 音效 | V1 | 非出片必需 |

### 12.4 全能参考的风险与应对

| 风险 | 应对 |
| --- | --- |
| 可用模型少，或只在单一画风下效果好，或不支持参考音频 | P0 第一优先级评测全能参考：写实与风格化分别测单角色、双角色同框、动作参考、运镜参考、音频参考五类镜头；至少 2 家候选 |
| 单一供应商依赖（MVP 只接一家） | 参考组合按“用途 + 锁定版本”存储，与具体模型解耦；V1 接入第二家时无需改数据 |
| 各模型参考数量、类型、时长限制不同 | 模型能力登记为配置（最多几张图、是否支持参考视频 / 音频、时长范围），报价阶段校验 |
| 费用高于图生视频【推断】 | 按镜头选择模式；成本统计区分两种模式，P0 输出两种模式的单镜成本对比 |
