# 前端工作区与交互模块设计

## 1. 设计结论

前端是一个基于官方 create-next-app 的 Next.js App Router 应用，使用 TypeScript strict、Tailwind CSS、shadcn/ui 与 Radix UI。Redux Toolkit 是唯一状态容器：RTK Query 保存服务端查询缓存，普通 Slice 只保存未提交编辑、选区和面板状态。浏览器不是 Task、Adoption、Delivery、权限或媒体 URL 的事实源。

## 2. 脚手架与目录边界

| 路径 | 责任 | 禁止 |
| --- | --- | --- |
| `src/app/` | 路由、layout、loading/error 边界 | 存放业务缓存或手写 HTTP |
| `src/features/{projects,story,studio,tasks,delivery}` | 页面组合、Feature hook/表单/投影 | 跨 Feature 直接改变内部 Slice |
| `src/components/ui/` | shadcn 生成/受控扩展的 Radix 基础组件 | 混入业务请求 |
| `src/services/generated/` | `@umijs/openapi` 确定性生成 DTO/请求 | 手工修改 |
| `src/services/api.ts` | 唯一手写 RTK Query 封装、tag 与轮询 | 复制 URL 或 DTO |
| `src/lib/request.ts` | 唯一 HTTP sender、Problem Details 转换 | 页面直接调用 |
| `src/store/` | `makeStore`、typed hooks、编辑 Slice | `redux-persist`、模块级全局 Store |

`app/providers.tsx` 是唯一 React-Redux Provider 装配点，每个应用实例调用 `makeStore()`。

## 3. 工作区和导航

| Feature / 路由 | 核心任务 | 阶段出口 |
| --- | --- | --- |
| `projects` / `/projects` | 创建/打开项目，显示单集阶段摘要 | 进入指定 Episode Story |
| `story` / `/episodes/:id/story` | 来源、剧本、资产和分镜的生成/编辑/确认 | confirmed Storyboard |
| `studio` / `/episodes/:id/studio` | 按 slot 生成、预览、重试和采用图片/视频/TTS | 必需 Adoption 齐全 |
| `tasks` / `/tasks` | 权威轮询、错误/下一动作、取消/重试/回跳 | Task 可判断 |
| `delivery` / `/episodes/:id/delivery` | 字幕编辑/确认、渲染、质检和下载 | ready MP4/SRT/Manifest |

所有页面固定显示“当前阶段、缺失条件、下一动作”。Task 行只回跳 owning Feature，任务页不提供 Prompt/采用旁路。

## 4. Redux 状态模型

| 状态 | 容器 | 生命周期 |
| --- | --- | --- |
| Project/Source/Script/Shot/Task/Candidate/Adoption/Delivery | RTK Query normalized cache | 由 API 查询、tag invalidation 和 refetch 收敛 |
| 未提交剧本/分镜/字幕表单 | Feature Slice | 进入页面从服务端基线初始化，提交/离开时明确处理 |
| 选中 shot/slot、面板开关、过滤 | Feature Slice/局部状态 | 仅影响展示 |
| Idempotency-Key | 一次用户意图对象 | 重发同意图复用，用户新意图新建 |
| 预览/下载授权 | 组件内短期内存 | 过期丢弃并重新申请 |

不使用 Zustand、TanStack Query 或第二 Store。Slice 不复制 RTK Query 的正式对象，也不持久化服务端事实。

## 5. Task 轮询与恢复交互

- 仅在有活跃订阅且 Task 为 `queued/running/cancelling/unknown` 时每 2 秒调用 `getTask`，终态立即停止。
- 短暂网络错误使用有限退避并提供手动刷新；不将通信失败写成 Task failed。
- 服务端终态变化后 4 秒内显示；刷新页面或清空 Store 后 3 秒内从 URL+API 恢复同一任务。
- `unknown` 必须显示“等待对账/人工确认”，不允许无条件重发；`cancelling` 显示取消已请求而非已取消。
- 错误视图只展示稳定 code、位置、阶段、retryable 和 next_action，不展示 Provider 响应/凭据。

## 6. 表单、无障碍与视觉状态

所有表单同时执行前端即时提示和服务端权威校验；`412` 不自动覆盖，而是对比服务端版本并要求重新确认。AI 输出统一标记“提案/候选”，Task 成功、Adoption active、Delivery ready 使用不同文案与视觉语义。

shadcn/Radix 组件保留键盘操作、焦点、ARIA label 和对话框焦点回归；动态任务区域使用非干扰的 live region。预览失败不删除候选，授权过期可原位重试。

## 7. 生成客户端与失败策略

`contracts-check` 必须完成 OpenAPI 导出→operation exact-set 检查→`@umijs/openapi` 生成→TypeScript 编译→Git 零漂移。锁定版本无法直接消费 OpenAPI 3.1 时阻断并回到 Design，不手写降级契约。应用回滚清理临时前端缓存即可，不改写服务端事实。

## 8. Design 验收标准

- AC-MOD-UI-001：官方脚手架、shadcn/Radix、五个 Feature、唯一 Provider/Store 装配和目录边界可由架构测试证明。
- AC-MOD-UI-002：页面只通过手写 RTK Query 层调用生成函数，不存在手写 URL/DTO、Zustand、TanStack Query 或第二 sender。
- AC-MOD-UI-003：非终态 Task 每 2 秒轮询，终态 4 秒内可见并停止轮询，刷新后 3 秒内恢复。
- AC-MOD-UI-004：Task、Candidate/Adoption、Delivery 在 UI 中使用独立状态语义，部分失败可精确回跳到失败 slot。
- AC-MOD-UI-005：清空 Redux、预览授权过期和短暂断网均不改变服务端事实，恢复操作明确。
- AC-MOD-UI-006：固定 E2E 可仅通过页面与公开 API 完成 Projects→Story→Studio→Tasks→Delivery 闭环，无手工改库或对象。
