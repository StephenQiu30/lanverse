## 1. 设计目标

| # | 目标 | 度量 |
| --- | --- | --- |
| C1 | 画布与流水线是同一份业务数据 | 任一侧修改 2 秒内在另一侧可见（REQ-05 §4.8） |
| C2 | 画布只拥有布局与自由生成节点配置 | 业务字段只经业务命令修改（DES-01 P1、P3） |
| C3 | 与 LibTV 同类体验 | 节点类型 × 动作分类、连线即参考、运行即生成（PRD-02 D1–D5） |
| C4 | 大画布流畅 | 500 节点 ≥ 50 fps，2,000 节点 ≥ 30 fps（REQ-02 PERF-06） |
| C5 | 可离线编辑片刻、冲突可恢复 | 乐观更新 + revision + 重放 |

## 2. 前端架构

```text
features/canvas/
  engine/        React Flow 封装：CanvasView、视口、选择、框选、小地图、对齐线
  nodes/         节点组件（每种 node_type 一个），移植自 infinite-canvas 的卡片外观
  edges/         连线组件（input / reference / promote / annotation）
  store/         Zustand + Immer：文档状态（节点、连线、revision）、本地待确认命令队列、撤销栈
  sync/          命令提交、冲突重放、增量拉取、SSE 订阅
  bindings/      业务节点数据绑定：通过 TanStack Query 读取业务对象（shot、look、media …）
  panels/        节点库、属性面板、生成面板（复用 REQ-08 参数表单与 REQ-21 报价确认组件）
  perf/          视口裁剪、LOD、媒体播放管理器
```

- **状态分工**：布局与画布元数据在 Zustand；业务对象数据在 TanStack Query 缓存（与流水线页面共享同一 query key），节点组件按 `ref_type + ref_id` 订阅。这样流水线修改镜头后，画布节点通过同一缓存失效自动更新（C1）。
- React Flow 作为依赖使用、不 Fork；节点组件用 `memo` 并只订阅自身所需切片。

## 3. 节点模型

### 3.1 类型与动作

| node_type | resource | generate | edit | 绑定 / 配置 |
| --- | --- | --- | --- | --- |
| `text` | 文本素材 / 备注 | 结构化文本生成（提示词、文案） | — | 文本存 `config.text` |
| `image` | 引用 MediaAsset | 生图（自由或绑定槽位） | 改图（MVP，REQ-39） | `ref_type = media_asset` 或 `config.generation` |
| `video` | 引用 MediaAsset / 片段 | 图生视频、全能参考、首尾帧 | MVP | 同上 |
| `audio` | 台词音频、上传音频 | TTS；音乐 / 音效（V2） | — | 同上 |
| `script` | 场 / 集的镜头表视图 | — | — | `ref_type = scene_board`，渲染只读镜头列表，镜头可拖出为 `shot` 节点 |
| `shot` | 单个镜头（参数、参考组合、选定片段） | 运行 = 为该镜头报价生成 | — | `ref_type = shot` |
| `asset` | 角色造型 / 场景 / 道具 | 运行 = 为槽位生成参考 | — | `ref_type = look | location | prop` |
| `clip` | 剪辑计划视图（V2） | — | — | `ref_type = edit_plan` |
| `reference` | 注释用参考图 | — | — | 纯画布 |
| `material_style` / `material_lens` | 风格 / 镜头语言预设 | — | — | `config.preset_id` |
| `group` | 分组框 | — | — | 纯画布 |

### 3.2 数据归属

| 字段 | Owner | 修改方式 |
| --- | --- | --- |
| `x`、`y`、`width`、`height`、`z_index`、`parent_id` | canvas | 布局命令 |
| `config`（生成节点的能力、模式、模型、参数；备注文本） | canvas | `UpdateNodeConfig` |
| `ref_type`、`ref_id` 指向的业务对象内容 | 业务模块 | 业务命令（转调对应 API） |
| `last_operation_id` | 任务（结果字段） | 工作流写入（REQ-25 R5） |

### 3.3 生成节点配置

```json
{ "generation": { "capability": "video.generate", "mode": "omni_reference", "model_key": "ark.seedance-2-pro",
                  "params": { "duration_ms": 5000 }, "prompt": "…", "output_count": 2,
                  "bind": { "target_type": "shot_take", "target_id": "…" } } }
```

- `bind` 为空：自由生成（`target_type = free`），结果显示在节点内，可通过 `promote` 连线提升。
- `bind` 指向镜头：运行等同于流水线中为该镜头生成（输入取镜头参考组合 + 节点上的 `input` 连线追加项不允许，避免两套输入来源；需要额外参考时应改镜头参考组合）。

## 4. 连线

| edge_type | 允许的源 → 目标 | 业务含义 | 创建 / 删除时 |
| --- | --- | --- | --- |
| `input` | image / video / audio / text / asset / material_* → 自由生成节点 | 自由生成的输入（用途 = `role`） | 只改画布；运行时展开为 OperationInput |
| `reference` | asset / image / video / audio → shot | 镜头参考组合的一项 | 转调 `POST /shots/{id}/versions`（追加 / 移除参考项），成功后记录 `binding = {shot_id, shot_version_no, seq_no}` |
| `promote` | 自由生成节点的结果 → shot / asset 槽位 | 选定 / 锁定 | 转调 `:select-take` / `:select-frame` / `:lock`；连线保留为历史注释 |
| `annotation` | 任意 → 任意 | 纯注释 | 只改画布 |

- 连接校验在前端即时进行（类型、用途、模型上限），服务端在命令执行时再校验。
- `reference` 连线与参考组合双向一致：流水线中修改参考组合后，画布根据镜头当前版本的参考项重建该镜头的 `reference` 连线（缺少源节点的项显示为节点上的“外部参考”角标）。
- 删除业务节点只从画布移除，不删除业务对象（删除镜头需在节点菜单中显式选择“删除镜头”，转调业务命令并确认）。

## 5. 命令与同步

### 5.1 命令

| 类别 | 命令 |
| --- | --- |
| 布局 | `AddNodes`、`MoveNodes`、`ResizeNode`、`DeleteNodes`、`Group`、`Ungroup`、`SetZIndex`、`UpdateNodeConfig`、`AddAnnotation`、`Connect`（input / annotation）、`Disconnect` |
| 业务转调 | `Connect`（reference / promote）、`Disconnect`（reference）、`CreateShotFromNode`、`DeleteShot` |

### 5.2 提交与冲突

```text
本地：操作 → 生成命令 → 立即乐观应用到 store → 加入 pending 队列（每 300ms 或队列满 50 条批量提交）
提交：POST /canvases/{id}/commands { expected_revision = base_revision, commands }
  200：base_revision = 返回的 revision；pending 出队；业务结果（如新的 shot_version_no）回写
  409：拉取 /changes?since_revision=base → 以服务端状态为底，重放仍在 pending 中的命令
       重放时若命令失效（节点已被删除、业务对象版本冲突）→ 丢弃该命令并 toast 提示
  其他失败：回滚该批命令的乐观效果并提示
```

服务端：一个事务内按顺序执行命令；布局命令写 `canvas.node/edge`；业务命令调用对应模块的应用服务（与公共 API 相同的用例，`origin = canvas`）；写 `canvas.command_log(revision)`；`document.revision + 1`；Outbox `canvas.document_changed.v1`。业务命令失败时整批回滚（保证 revision 与结果一致），返回失败命令序号。

### 5.3 增量与实时

- 打开画布：`GET /canvases/{id}`（节点、连线、revision，以及业务节点的首屏摘要）。
- 其他标签页、Agent 应用提案、流水线修改业务对象：
  - 画布命令 → SSE `canvas.updated{revision}` → 拉取 `changes`（`command_log` 中 `revision > base` 的命令，服务端返回其结果状态）。
  - 业务对象变化 → SSE 业务事件 → 失效 TanStack Query → 节点重新渲染。
- 快照：每 200 个 revision 或用户手动保存时写 `document_snapshot`（对象存储），用于恢复与 V2 模板。

## 6. 撤销与重做

- 撤销栈只记录本标签页的命令；每条命令有对应的反向命令（`MoveNodes` ↔ 原位置；`AddNodes` ↔ `DeleteNodes`；`Connect reference` ↔ `Disconnect reference`（产生镜头新版本））。
- 不可撤销：运行生成（付费）、`promote`（选定 / 锁定）、`DeleteShot`；这些命令执行后清空撤销栈中其之前的业务命令，布局命令仍可撤销（REQ-36 R7）。
- 撤销产生新命令提交（不回退 revision），因此与其他端的修改不冲突。

## 7. 性能

| 手段 | 说明 |
| --- | --- |
| 视口裁剪 | 只渲染视口 + 1 屏缓冲内的节点（React Flow `onlyRenderVisibleElements` + 自定义空间索引 R-tree） |
| LOD | 缩放 < 0.4：节点渲染为缩略色块 + 标题；< 0.15：只画占位矩形；图片按缩放选择 `thumb_256` / `thumb_640` |
| 媒体播放 | `MediaPlaybackManager` 全局限制同时播放 ≤ 3 个视频；视口外暂停并释放；视频节点默认显示海报帧 |
| 连线 | 大量连线时使用简化直线路径；拖动节点时暂停非相关连线的重算 |
| 状态订阅 | Zustand selector 精确订阅；拖动过程中只更新拖动节点，结束时一次提交 |
| 业务数据 | 业务节点摘要按视口批量拉取（`GET /shots?ids=`），不逐节点请求 |
| 内存 | 目标 < 1.5 GB（500 节点：300 图、40 视频、600 连线） |

**PoC（P0 并行，PLN-01）**：用生成的 500 / 2,000 节点数据集，在 Chrome 最新版、M1 / 8 GB 与 Windows 中端机上测平移、缩放、框选、拖动 60 秒的帧率与内存；不达标则优先调整 LOD 阈值与虚拟化策略，再考虑 Canvas 层渲染远景节点。

## 8. infinite-canvas 移植边界

| 移植 | 不移植 |
| --- | --- |
| 卡片视觉（图片 / 视频 / 文本 / 生成卡）、工具栏、节点库拖拽、选择与框选交互、连线把手样式、小地图样式 | antd 组件（改用 shadcn/ui）、插件系统、本地 Agent、WebDAV、浏览器直连供应商、本地持久化（IndexedDB）、其数据与执行层 |

- 保留 MIT 版权声明（移植文件头部 + `THIRD_PARTY_NOTICES`），在“关于 / 开源许可”页致谢（已确认，DES-08 §7）。
- 视觉按 DESIGN.md 调整（无边框优先规则只适用于内容卡片，节点保留必要的选中与焦点反馈）。

## 9. 与流水线、Agent 的互通

- **跳转**：节点菜单“在流水线中打开”→ 对应镜头 / 条目页面；流水线镜头菜单“在画布中定位”→ 打开包含该镜头节点的画布并聚焦（无节点时询问是否添加）。
- **Agent**：`canvas_commands` 提案（布局 + 业务命令）以虚线“预览层”叠加在画布上，用户应用后作为普通命令提交（`origin = agent` 记录在 command_log）。
- **生成**：运行节点使用 REQ-21 报价确认组件；任务状态通过 `last_operation_id` + SSE 在节点上显示。

## 10. 后端（canvas 模块）

- `adapter/http`：画布 CRUD、命令、增量、快照端点（DES-03 §4.12）。
- `application`：`ExecuteCommands`（事务、revision、逐条分派）、`GetChanges`。
- `domain`：命令校验（节点类型与连线规则、坐标范围、批量上限 200 条）。
- 业务命令通过其他模块暴露的应用服务接口调用（消费方定义小接口，DES-01 §3.3、AGENTS.md Go 规范）。
