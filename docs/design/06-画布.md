## 1. 已确定的约束

| # | 约束 | 对 MVP 的影响 |
| --- | --- | --- |
| C1 | 画布是视图 + 自由工作区，**只拥有布局与自由生成节点的配置**；业务对象（镜头、造型、素材）仍由各业务模块拥有 | MVP 的业务数据不为画布做任何特殊设计 |
| C2 | 节点只存 `ref_type + ref_id` 与布局；显示内容读业务数据 | MVP 业务对象保持稳定 ID 即可 |
| C3 | 连线语义：`input`（自由生成的输入）、`reference`（= 镜头参考组合中的一项）、`promote`（= 选定 / 锁定命令）、`annotation`（纯注释） | MVP 的参考组合、选定、锁定命令即画布将来调用的命令 |
| C4 | 画布上的所有业务修改都调用与流水线相同的命令层（带 `expected_revision`、幂等键）；付费生成走同一报价与二次确认 | MVP 命令层保持入口无关（DES-01 P6） |
| C5 | 画布文档用 `revision` 做乐观并发，冲突时基于最新文档重放本地命令 | — |
| C6 | 技术路线：React Flow（@xyflow/react）引擎 + 移植 infinite-canvas 的卡片与交互界面（MIT，保留版权声明） | DES-08 §7 已确认 |

## 2. V2 规划时需要补充

节点类型与配置 schema、画布表结构（`canvas` schema）、命令清单与冲突重放算法、撤销规则、性能方案（视口裁剪、LOD、媒体播放上限）与 PoC 结论、与对话式 Agent 的提案预览、测试方案。
