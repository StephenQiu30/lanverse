## 1. 问题、范围与非目标

Storyboards 模块把固定剧本、叙事单元和资产状态转换为有序 Shot，并发布可供关键帧、视频和导出固定引用的 StoryboardBaseline。它必须允许 AI 草案和人工局部返工，同时保证来源、对白/动作和必拍覆盖不静默丢失。

范围：工作区读取、AI 草案、逐镜决议、ShotSpec、插入/复制/归档/拆分/合并/重排、叙事覆盖、资产 readiness、Baseline 发布和 stale。

非目标：关键帧/视频生成、媒体选择、剪辑时间关系、自动主选、专业无限画布、实时多人协作和通用审批。

## 2. 事实所有者与模型

| 实体 | 含义 | 版本策略 |
| --- | --- | --- |
| Shot | Episode 内稳定镜头身份、active/archived | 镜号/顺序变化不改 ID |
| ShotSpecVersion | 叙事目的、画面、景别、机位、运动、动作、对白、时长、视觉说明、固定资产引用 | 不可变；current 指针分离 |
| StoryboardOrderRevision | 一次完整 active Shot 有序集合 | 不可变修订 |
| StoryboardDraftBatch | 固定输入 AI 草案、条目和人工决议 | reviewable/applied/discarded；stale 派生 |
| NarrativeReference | ShotSpec 与 NarrativeUnitVersion 多对多来源边 | 固定版本 |
| CoverageDecision | covered/approved_omitted/creative reason 等人工决定 | 追加式/版本化 |
| StoryboardBaseline | OrderRevision、每 Shot current Spec、来源、资产引用和输入摘要 | 发布即不可变 |

## 3. 核心不变式

1. Shot ID 不因插入、复制、拆合、重排或显示镜号变化而复用。
2. ShotSpecVersion 不原地修改；每个 Baseline 固定明确版本。
3. AI 草案应用前不成为正式 Shot；每条草案有显式决定。
4. 叙事单元与 Shot 是多对多；必拍单元必须 covered 或有批准的 omission。
5. 重排只创建 OrderRevision，不改 ShotSpec 和历史媒体。
6. 拆分/合并必须证明来源、对白和动作守恒；无法证明则整次拒绝。
7. Baseline 只通过显式发布改变；历史 Baseline 不回到 valid。
8. Asset current 切换不自动迁移 ShotSpec 中固定 AssetVersion。
9. 下游只能固定 Baseline，不得以工作区临时顺序或 current 文本作为输入。

## 4. AI 草案设计

固定输入包括 ScriptVersion、NarrativeUnitVersion 集合、资产 State/Version Snapshot、视觉方向修订、约束和 PromptTemplateVersion。预检计算输入 hash、Capability、预计消耗和 blocker。

草案成功后先通过结构 Schema、引用归属、叙事范围和资产引用校验，再建立 DraftBatch。每条建议具有：临时条目 ID、来源 NarrativeUnit、拟议 ShotSpec、顺序位置、理由/置信、验证问题和人工 Decision。

应用支持的最小语义由 CUR-SBD-OQ-004 关闭：

- 若整批原子应用：所有条目决议、输入/顺序/spec revision 一次验证，任一冲突零写入；
- 若逐项应用：每次只创建明确选中 Shot，但 Batch 保留全量决议和来源守恒，不能让未处理条目静默消失。

## 5. 同步命令与查询

| 能力 | 强事务结果 |
| --- | --- |
| GetStoryboardWorkspace | 指定/当前 Baseline、有序 Shot、Spec、覆盖、资产 readiness 和 partial failure |
| ApplyDraftDecisions | 正式 Shot/Spec/OrderRevision 或零写入冲突 |
| Create/ReviseShot | 新 Shot 或新 SpecVersion + 影响摘要 |
| Insert/Copy/ArchiveShot | 新结构和 OrderRevision；身份规则明确 |
| SplitShot | 新 Shot/Spec/来源分配；原 Shot 归档或 superseded 关系 |
| MergeShots | 新 Shot/Spec/来源合并；原 Shot 历史保留 |
| ReorderShots | 完整 active Shot 列表 + expected order revision → 新修订 |
| DecideCoverage | 固定 NarrativeUnitVersion/ShotSpec、决定、理由 |
| GetReadiness | 覆盖、AssetVersion 用途和依赖可用性 |
| PublishBaseline | 当前完整顺序/spec/覆盖/依赖摘要 → 不可变 Baseline |

任何结构命令都返回受影响下游数量，但不修改 Keyframe/Video Candidate 或 ExportSnapshot。

## 6. 异步工作流与事件

AI StoryboardDraft 使用 DES-012 WorkTask。任务 failed 不创建 failed DraftBatch；只有可审阅、通过基本校验的输出建立 Batch。

事件：`StoryboardDraftBecameReviewable`、`ShotCreatedOrArchived`、`ShotSpecVersionPublished`、`StoryboardOrderChanged`、`CoverageDecisionChanged`、`StoryboardBaselinePublished`、`StoryboardBaselineBecameStale`。

事件不携带完整对白/Prompt，只含固定版本、hash、影响字段分类和最小摘要。Keyframes/Videos/Exports 消费 BaselinePublished；Projects 消费 readiness 摘要。

## 7. 状态与失败恢复

```text
Shot: active ↔ archived
DraftBatch: reviewable → applied | discarded；+ stale 派生
Coverage: covered | uncovered | approved_omitted | orphan | stale | unavailable
Baseline: valid → stale（重新确认产生新 Baseline）
```

| 失败 | 行为 | 恢复 |
| --- | --- | --- |
| AI unavailable | 手工分镜完整可用 | 稍后新建 DraftRun，不阻塞人工 |
| 草案 Schema/引用非法 | Batch 不可应用，列出条目问题 | 修正输入/新 Run |
| 应用/拆合/重排冲突 | 100% 零部分写入 | 比较最新版本和本地草稿后重做 |
| 拆合来源守恒失败 | 整次拒绝 | 修正来源/对白/动作分配 |
| Asset readiness unavailable | Baseline 预检 unavailable/blocked | 恢复依赖或更换固定引用 |
| 上游 Script/Asset 变化 | 受影响 Spec/Coverage/Baseline stale | 人工修订或明确重新发布新 Baseline |

## 8. 权限与安全

- owner/editor 创建、修订、决议、重排和发布；viewer 只读。
- “导演/制作人确认”是 persona 职责，在产品决定接受前不得成为隐藏双人权限。
- 所有 Script/Narrative/Asset 引用验证同 Workspace/Project/Episode 与固定版本。
- Prompt 和对白只传给已通过 Rights/Capability 预检的 Provider；日志、事件和普通 Audit 不含正文。
- 并发命令必须带 expected Spec/Order/Baseline revision，禁止客户端拼接多次写形成假原子。

## 9. 可观测性

- 工作区读取、单镜命令、重排和 Baseline 发布延迟；
- DraftRun 状态、Schema invalid、条目接受/修改/忽略率；
- uncovered/orphan/stale/unavailable 数量及来源；
- revision 冲突、拆合守恒失败和 partial dependency；
- 列表/详情与 Canvas 对相同 Shot/Spec/Coverage/readiness/Task 的投影差异、来源修订和新鲜度；
- Trace 串联 ScriptVersion、AssetVersion、Draft Task、ShotSpec、Baseline。
