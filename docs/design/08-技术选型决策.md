| 对象存储 | minio-go v7 | 预签名上传 / 下载、对象管理 |
| 鉴权 | Redis 会话 + HttpOnly Cookie；密码 bcrypt | 管理员创建账号；两种角色在应用层用例入口校验 |
| 可观测 | OpenTelemetry Go（otelgin、otelgorm、Temporal 拦截器）+ Prometheus client | 链路贯穿 API → 工作流 → Activity → Agent 服务 |
| 测试 | testing + testify + testcontainers-go（PostgreSQL、Redis、Kafka、MinIO）+ Temporal testsuite | 单元、集成、工作流回放测试 |

**Wire 维护风险（2026-09-27 核验）**：[Google Wire 官方仓库](https://github.com/google/wire) 已于 2025-08-25 归档且声明不再维护。本项目仍按已接受的选型锁定 v0.7.0；当前 API 组合根在 Go 1.26 下生成、编译和本机运行均通过。后续 Go 升级若出现生成兼容问题，应先评审替代方案并更新本设计。

## 4. Agent 服务（FastAPI + Agent Harness）

### 4.1 选型

| 关注点 | 选型 | 用途与约束 |
| --- | --- | --- |
| 语言与依赖 | Python 3.12+、uv（锁文件 `uv.lock`） | 可复现安装 |
| Web 框架 | FastAPI + Uvicorn | 内部 API：健康检查、Harness 调试与评测、Agent 对话流 |
| Agent 协议 | ag-ui-protocol（AG-UI Python SDK）【待核实版本】 | 以 AG-UI 事件流输出对话、推理、工具调用、状态快照与自定义事件（如 `canvas_commands`） |
| 工作流接入 | Temporal Python SDK | 作为 Activity Worker 监听 `agent` 任务队列，执行 AI 步骤 |
| 数据契约 | Pydantic v2、pydantic-settings | Activity 输入输出、LLM 结构化输出、配置 |
| HTTP 客户端 | httpx | 供应商调用：统一超时、重试、连接池 |
| LLM SDK | OpenAI 兼容 SDK（DeepSeek、通义千问、豆包等国内模型） | 经 Harness 的模型路由调用 |
| Redis | redis-py（asyncio） | 供应商配额限流、短期缓存 |
| 对象存储 | 通过 Go 下发的预签名 URL 读写 | Agent 服务不持有对象存储管理凭据 |
| 可观测 | OpenTelemetry Python + 结构化日志 | 与 Go 端同一 trace |
| 质量 | Ruff（lint + format）、mypy、pytest、pytest-asyncio | — |

一个代码库、两种运行角色：`api`（FastAPI）与 `worker`（Temporal Activity Worker），共享 Harness 与适配器代码。

### 4.2 Agent Harness

Harness 是 Agent 服务内的受控执行框架，负责“一次 AI 任务”从上下文组装到结果校验的全过程。它不拥有业务状态，不直接写业务数据库。

| 组件 | 职责 |
| --- | --- |
| Skill Registry | 专业能力包（如分集、逐集解析、设定集抽取、分镜、全能参考提示词编写）：`SKILL.md` + 参考资料 + 输入 / 输出 schema；按版本与内容 hash 发布，任务记录所用版本 |
| Context Builder | 按冻结输入组装上下文：原文片段（带位置）、已锁定资产描述、镜头语言参数；控制 token 预算，超限明确失败而不静默截断 |
| Model Router | 按模型注册表选择模型与参数；封装各家 LLM 与多模态模型调用 |
| Tool Registry | 声明式工具（只读查询原文、获取参考描述、计算时长等）；每个工具声明权限，Harness 按任务白名单授予；**不提供业务写工具** |
| Execution Loop | 调用 → 校验 → 修复，最多 N 轮；支持取消与截止时间 |
| Validators | schema 校验、原文位置核对、业务规则（如每句台词只分配一次、参考数量不超限） |
| Budget | 每次任务的 token、费用、时长上限；超限终止并返回原因 |
| Trace | 每一步的提示词版本、输入 hash、模型、用量、耗时、校验结果；随结果返回给 Go 持久化 |

**供应商适配器**（生图、视频、TTS、审核）也在 Agent 服务内：负责输入角色到各家参数的映射、提交、查询、取消、用量解析。付费请求使用 Go 生成的 `provider_request_key`；结果未知时返回“未知”，**不自动重提**。

**对话式 Agent**：在 Harness 之上增加规划能力，把自然语言转为“命令提案”；提案经 Go 命令层校验并由用户确认后执行；付费生成一律由用户二次确认（DES-01 §7.4、PRD-01 P21）。

## 5. 工作流：Temporal

| 关注点 | 选型与约定 |
| --- | --- |
| 服务端 | Temporal Server 自建，持久化使用 PostgreSQL（独立数据库），可见性使用 PostgreSQL（SQL visibility）【待核实版本支持】；数据留在自有环境 |
| 工作流编写 | 全部工作流用 Go 编写，保证单一流程 Owner |
| 任务队列 | `flow`（Go：写库、流程推进）、`media`（Go：FFmpeg 处理）、`agent`（Python：LLM 与供应商调用），可按供应商再细分队列以限流 |
| 人工确认 | 业务状态写 PostgreSQL；工作流通过 Signal / Update 接收用户决定后继续 |
| 批量 | 父工作流 + 子工作流（每镜头一个），单镜失败独立处理 |
| 轮询与定时 | 工作流定时器（`workflow.Sleep`）实现供应商轮询退避；Temporal Schedules 做定期任务（对账、清理） |
| 幂等 | Workflow ID 使用业务 ID（如 `operation/{id}`）；Activity 先查已有结果再执行 |
| 版本演进 | 工作流代码变更使用 Temporal 版本化机制，保证在途工作流可回放 |
| 本地开发 | Temporal CLI dev server 或 Compose 中的 Temporal |
| 测试 | Go testsuite 单元测试 + 历史回放测试 |

## 6. 中间件职责

| 中间件 | 负责 | 不负责 |
| --- | --- | --- |
| **PostgreSQL** | 全部业务事实（按上下文分 schema）、版本与依赖、Operation、模型注册表、账本、画布文档、Outbox 表；Temporal 持久化（独立库） | 媒体字节；缓存 |
| **Redis** | 会话存储；热点查询缓存（模型注册表、项目概览）；API 与供应商配额限流；分布式锁（批量提交互斥）；实时事件 Pub/Sub（SSE 跨实例扇出） | 任何业务事实；丢失后必须可从 PostgreSQL 重建 |
| **Kafka** | 领域事件总线：Outbox 可靠投递已提交事件；消费者包括实时通知、依赖过期传播、成本汇总与报表、审计归档、模型调用明细、将来的检索索引与数据分析 | 同步 RPC；工作流编排（归 Temporal）；模型 token 流 |
| **对象存储（开发 MinIO / 生产火山引擎 TOS）** | 全部媒体对象（上传素材、参考图、关键帧、视频、音频）；预签名直传与下载；按项目前缀组织；生命周期规则清理临时对象 | 元数据（在 PostgreSQL） |
| **Temporal** | 长流程编排：生成操作、剧本解析、批量、媒体处理、人工确认等待、重试、超时、对账 | 业务事实（以 PostgreSQL 为准） |

**事件链路**：业务事务写业务表 + Outbox → Go relay 投递到 Kafka → 消费者处理（实时通知消费者把事件发布到 Redis Pub/Sub → 各 API 实例的 SSE Hub 推送给浏览器）。

**Kafka 主题约定**：`lanverse.<上下文>.<事件>.v<N>`，如 `lanverse.operation.completed.v1`；键为 `project_id`，保证同一项目内有序；消费者按事件 ID 去重。

| 方案 | 结论 |

## 11. 与旧实现的差异

| 条款 | 旧实现 | 新设计 |
| --- | --- | --- |
| HTTP / ORM | 标准库 net/http + GORM | Gin + GORM（保留 GORM，统一到 Gin 生态） |
| 迁移 | 无版本化迁移（旧 README 说明） | golang-migrate 版本化 SQL |
| 工作流 Owner | Go 与 Python 各有编排 | 全部工作流用 Go 编写；Python 只做 Activity |
| Agent | 自有执行存储 + Codex Harness | FastAPI + Temporal Activity + 新 Agent Harness（无状态，不写业务库） |
| 前端状态 | Redux Toolkit Query | TanStack Query + Zustand |
| 接口生成 | swag → `@umijs/openapi` | swag → openapi-typescript + openapi-fetch |
| 事件 | Outbox + Kafka；Elasticsearch | Outbox + Kafka；Elasticsearch 暂不引入 |
| 生成模型 | 按目标类型分别实现 | 统一 Operation + 声明式模型注册表 |
