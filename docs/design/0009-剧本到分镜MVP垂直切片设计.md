## 设计结论

本轮只交付一个可在浏览器中真实走通、可恢复、可审阅的纵向闭环：

```text
创建项目
→ 上传并确认整剧原稿
→ 本地 Codex 生成项目制作圣经
→ 人工确认统一角色/场景/道具事实
→ 审阅并发布分集
→ 单集提取场次、对白、叙事单元和制作任务
→ 人工确认结构
→ 本地 Codex 生成分镜草案
→ 逐镜决议、整批批准、影响预检、原子写入
→ 导出可复现分镜包
```

不以已有目录、接口或测试数量作为设计输入和完成证据。完成只由本设计的真实输入、状态迁移、浏览器操作和可复查产物决定。

## 用户与边界

主用户是独立创作者、编剧统筹和分镜师。一个 Workspace 内创建 Project；整剧原稿产生不可变 Revision；Production Bible 固定跨集统一事实；Episode 固定分集正文；Confirmed Structure 固定场次、对白、叙事单元与制作任务；Storyboard Draft 只产生候选；人工 Apply 后才产生正式 Shot。

本轮非目标：图片/视频/配音生成、自动批准 AI 结果、60 集批量质量结论、多人实时协作、计费、第三方模型市场和通用 Agent 平台。

## 模块边界

| 模块 | 实现位置 | 唯一职责 | 不允许承担 |
|---|---|---|---|
| Web 创作工作台 | `frontend/` | 呈现服务端事实、收集人工决议、恢复当前步骤 | 在浏览器推断任务成功或直接写正式分镜 |
| 项目与剧本域 | `backend/internal/production` | 保存不可变原稿、分集计划、Episode 与发布指针 | 生成或批准分镜 |
| Production Bible 域 | `backend/internal/production` | 管理候选、审阅、确认及项目事实/资产物化 | 在 Python Runtime 中直接写业务事实 |
| 剧本结构域 | `backend/internal/production` | 管理可追溯场次、对白、叙事单元、任务及确认 | 跨场景伪造来源或把候选直接确认为事实 |
| Storyboard 域 | `backend/internal/production` | 管理草案、决议、预检、原子 Apply、导出 | 未经批准创建正式 Shot |
| 持久任务 | `backend/internal/platform/database/model` 与各业务 Application Worker | 在同一 PostgreSQL 事实源中领取、恢复和记录失败状态 | 把 Agent 返回等同于业务确认 |
| Agent 控制面 | `backend/internal/agent` | Invocation、Grant、预算、版本和 Result Receipt | 执行本地 Codex 或拥有 Production 事实 |
| 本地 Codex Harness | `agent/` | 在只读沙箱中输出严格结构化 Candidate/Proposal | 连接业务数据库、持有领域真相或访问写接口 |
| PostgreSQL / MinIO | Backend Adapter 管理 | 领域持久化、对象与上传字节存储 | 成为绕过 Owner Application 的第二写入入口 |

## 运行与数据边界

- Browser 的公共 REST/SSE 只进入 Go `lanverse-api`；Python Agent Runtime 不暴露公共业务 HTTP。
- 本切片的注册、项目、原稿、Bible、分集、结构、Storyboard、Shot 与导出事实只能由 Go Application 写入。
- Go Backend 通过正式 Agent 契约提交固定输入和短时 Execution Grant；Agent 只返回严格结构化 Candidate/Proposal，确定性 Gate、人工确认与事务均在 Go Backend。
- 目标运行时不存在 Python FastAPI/SQLAlchemy 业务兼容层、Go→Python 公共路由代理或逐路由双 Writer。开发可以按资源顺序完成，但任何可运行目标拓扑都只有 Go 公共 API 与一个 PostgreSQL 事实源；尚未完成的 Go 资源明确不可用，不能回退到 Agent 写业务事实。
- Backend 只打开一个 `DATABASE_URL`；GORM Model Catalog 是唯一表结构定义，Schema 由 GORM 非破坏性同步。项目中不保留手写 SQL Schema/Migration、迁移元数据表或 `MIGRATION_DATABASE_URL`。
- 最终验收只针对完成上述边界后的运行拓扑；旧 Python 兼容运行时或 pgx 手写 Repository 上的历史浏览器证据不能抵扣目标架构验收。

## 状态与一致性

- 原稿 Revision、确认结构、Bible 结果和 ShotSpec 都是不可变版本；当前版本只通过显式指针切换。
- AI 任务至少区分 `queued`、`running`、`needs_review`、`confirmed/applied`、`failed`、`unknown`、`cancelled`。
- 创建、确认、发布、决议、Apply 与导出都携带幂等键；版本、revision 或 hash 漂移时 fail closed。
- Browser 刷新后只从 API 恢复状态，不依赖组件内计时器或本地成功标记。
- Production Bible 必须在分集发布前确认；每个 blocking 审阅项必须先持久记录“接受风险”或“保留阻断”的人工决议，只有全部 blocking 项明确接受风险后才允许确认。Storyboard 草案必须在结构确认后创建；正式 Shot 必须在逐镜决议、整批批准和预检后原子写入。
- 每个场次必须携带 1–4 个待人工审核的可执行制作任务，且至少包含一个 `shot_breakdown`；空任务列表属于无效结构化输出，必须纠错或失败，不能进入结构确认。

## 失败路径

- 文件类型、对象存储或格式体检失败：保留项目，允许重新选择原稿，不创建 Episode。
- Codex 不可用或输出非法：任务进入明确失败/未知状态，保留 checkpoint，允许受控恢复，不产生已确认事实。
- Bible 有尚未决议或明确“保留阻断”的 blocking 审阅问题：禁止确认和分集发布；不得把模型问题静默降级为 warning。
- 结构候选仍有必需未决项、任一场次缺少制作任务：禁止确认结构。
- 分镜仍有未决镜头、输入漂移或 Apply 预检冲突：禁止正式写入。
- PostgreSQL、MinIO 或私有 Agent 不可用：就绪检查失败或任务进入明确失败/未知状态，不伪装成功。

## 开源复用决策

复用成熟开源能力：Next.js/React、GORM、GORM PostgreSQL Driver/JSONB、shopspring/decimal、google/uuid、validator/v10、PostgreSQL、MinIO、Playwright 与 Codex CLI。版本与导入边界以[后端服务架构](2001-后端服务架构.md)为唯一依据。Python Agent 只复用 FastAPI、Pydantic、LangGraph 与 Codex CLI 等结构化候选执行依赖，不包含公共业务路由、SQLAlchemy、数据库驱动或业务 Repository。业务只实现 Lanverse 的版本、状态、审核和来源契约；本轮不引入 Ent/Atlas/GORM Gen、第二套 DAO/Schema 生成物、通用工作流引擎或第二套 UI 状态库。

## 验证策略

1. 领域正常与失败契约采用 Red → Green → Refactor。
2. 真实数据库集成验证整条业务链和确定性导出。
3. Playwright 验证可重复启动的浏览器闭环。
4. 只有本切片全部开发、路由切换和 Python Writer 删除完成后，才使用 `agent-browser` 在真实页面按 snapshot → interact → resnapshot 执行最终人工验收，并检查可访问性和关键页面证据。
