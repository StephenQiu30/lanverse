# 剧本到分镜 MVP 垂直切片设计

- 状态：本轮实施基线
- 日期：2026-08-25
- 下游：[产品需求](../prd/0009-剧本到分镜MVP产品需求.md) · [需求规格](../requirement/0009-剧本到分镜MVP需求规格.md) · [实施计划](../plan/0009-剧本到分镜MVP实施计划.md) · [验收记录](../acceptance/0009-剧本到分镜MVP验收记录.md)

## 设计结论

本轮只交付一个可在浏览器中真实走通、可恢复、可审阅的纵向闭环：

```text
创建项目
→ 上传并确认整剧原稿
→ 本地 Codex 生成项目制作圣经
→ 人工确认统一角色/场景/道具事实
→ 审阅并发布分集
→ 单集提取场次、对白、叙事单元和制作任务
→ 人工确认结构
→ 本地 Codex 生成分镜草案
→ 逐镜决议、整批批准、影响预检、原子写入
→ 导出可复现分镜包
```

不以已有目录、接口或测试数量作为设计输入和完成证据。完成只由本设计的真实输入、状态迁移、浏览器操作和可复查产物决定。

## 用户与边界

主用户是独立创作者、编剧统筹和分镜师。一个 Workspace 内创建 Project；整剧原稿产生不可变 Revision；Production Bible 固定跨集统一事实；Episode 固定分集正文；Confirmed Structure 固定场次、对白、叙事单元与制作任务；Storyboard Draft 只产生候选；人工 Apply 后才产生正式 Shot。

本轮非目标：图片/视频/配音生成、自动批准 AI 结果、60 集批量质量结论、多人实时协作、计费、第三方模型市场和通用 Agent 平台。

## 模块边界

| 模块 | 唯一职责 | 不允许承担 |
|---|---|---|
| Web 创作工作台 | 呈现服务端事实、收集人工决议、恢复当前步骤 | 在浏览器推断任务成功或直接写正式分镜 |
| 项目与剧本域 | 保存不可变原稿、分集计划、Episode 与发布指针 | 生成或批准分镜 |
| Production Bible 域 | 从整剧原稿生成统一实体、状态和世界观候选并物化 | 替用户静默解决阻断问题 |
| 剧本结构域 | 从已发布单集提取可追溯场次、对白、叙事单元和任务 | 跨场景伪造来源 |
| Storyboard 域 | 生成草案、保存决议、预检、原子 Apply、导出 | 未经批准创建正式 Shot |
| 任务与消息域 | 持久任务、幂等发布、重投、恢复和失败状态 | 把消息投递等同于业务完成 |
| 本地 Codex Harness | 在只读沙箱中输出严格结构化候选 | 持有领域真相或直接访问写接口 |
| PostgreSQL / Kafka / MinIO | 领域持久化、异步事件、对象与导出存储 | 承载浏览器本地临时真相 |

## 状态与一致性

- 原稿 Revision、确认结构、Bible 结果和 ShotSpec 都是不可变版本；当前版本只通过显式指针切换。
- AI 任务至少区分 `queued`、`running`、`needs_review`、`confirmed/applied`、`failed`、`unknown`、`cancelled`。
- 创建、确认、发布、决议、Apply 与导出都携带幂等键；版本、revision 或 hash 漂移时 fail closed。
- Browser 刷新后只从 API 恢复状态，不依赖组件内计时器或本地成功标记。
- Production Bible 必须在分集发布前确认；Storyboard 草案必须在结构确认后创建；正式 Shot 必须在逐镜决议、整批批准和预检后原子写入。
- 每个场次必须携带 1–4 个待人工审核的可执行制作任务，且至少包含一个 `shot_breakdown`；空任务列表属于无效结构化输出，必须纠错或失败，不能进入结构确认。

## 失败路径

- 文件类型、对象存储或格式体检失败：保留项目，允许重新选择原稿，不创建 Episode。
- Codex 不可用或输出非法：任务进入明确失败/未知状态，保留 checkpoint，允许受控恢复，不产生已确认事实。
- Bible 有阻断审阅问题：禁止确认和分集发布。
- 结构候选仍有必需未决项、任一场次缺少制作任务：禁止确认结构。
- 分镜仍有未决镜头、输入漂移或 Apply 预检冲突：禁止正式写入。
- Kafka、MinIO 或 Worker 不可用：健康/就绪检查失败或任务保持可恢复状态，不伪装成功。

## 开源复用决策

复用成熟开源能力：Next.js/React、Redux Toolkit Query、FastAPI、SQLAlchemy、PostgreSQL、Kafka、MinIO、Playwright 与 Codex CLI。业务只实现 Lanverse 的版本、状态、审核和来源契约；本轮不引入第二套工作流引擎、对象存储客户端、浏览器测试框架或 UI 状态库。

## 验证策略

1. 领域正常与失败契约采用 Red → Green → Refactor。
2. 真实数据库集成验证整条业务链和确定性导出。
3. Playwright 验证可重复启动的浏览器闭环。
4. `agent-browser` 在真实页面按 snapshot → interact → resnapshot 执行最终人工验收，并检查可访问性和关键页面证据。
