# Design 07：剧本

执行编号：07；原始需求模块：11。依据[原始需求](../requirement/11-剧本需求.md)、[PRD](../prd/07-剧本.md)与[Plan](../plan/07-剧本.md)。本文件把原始需要转换成项目方案，**全部新增设计选择仍待评审**；数据对象和接口为拟议合同，不表示已有表或已实现API。共同约束见[整体设计](00-项目需求设计.md)。原始FR、质量条件与AC仍须同时满足。

## 原件、解析与业务采用

剧本模块接收已建立项目的授权原件，形成可追溯解析/导入版本；媒体模块保存字节，设定模块接收抽取候选，后续镜头模块接收确认的内容结构。上传完成不等于解析完成，模型抽取不等于用户已确认，不能自动合并同名实体或覆盖锁定设定。

| 对象                | 拟议内容与边界                                                                   |
| ------------------- | -------------------------------------------------------------------------------- |
| ScriptSourceVersion | project_id、media_id/version、内容摘要、实际格式/编码、接收者/时间；保留原件来源 |
| ImportTask          | 来源版本、解析规则/模型版本、request_key、状态、阶段进度、安全错误及检查点       |
| ParsedScriptVersion | 文本/结构、来源偏移/段落、分集候选、识别依据、未确定片段                         |
| ExtractionCandidate | 角色/场景/道具类别、原文证据、候选身份及采用状态；同名可不同ID                   |

首轮支持原规格txt/md/docx；PDF仍未决定。格式探测、编码/解压安全和容量限制需接受。解析对完整原件及明确规则版本操作，不从项目列表加载全文，不靠标题正则假定所有剧本可靠分集。

## 导入接口与恢复

拟议POST /projects/{id}/script-imports提交已就绪原件版本；GET /script-imports/{id}查阶段/结果摘要；GET /projects/{id}/script-versions/{version_id}按需读结构；POST /script-imports/{id}/adoptions确认候选范围。

建议幂等范围为用户＋项目＋script.import＋request_key，记录保留到导入历史保留期结束；同来源版本及规则输入返回同Task，异输入冲突。任务创建、关联项目和审计同事务；外部解析在事务外，受控执行保存阶段检查点。任务进度采用确知已处理范围/阶段，无法得到比例时只显示阶段，不编造百分比。

解析失败保留Project/原件；部分结果按stage和可采用性标识，不标全成功。重启先查询当前Task和检查点，外部收费抽取沿用[生成的安全调用原则](10-生成.md)，不能重跑未知受理请求。建议抽取候选先隔离保存，明确采用后才通过设定模块用例建条目；并发采用幂等，原已锁定版本不变。

重导入建议产生新来源/解析版本，不覆盖已经编辑的分集/设定；差异和采用范围需要评审。场与首镜头形成规则尚未明确，不自动“补一个样例镜头”让链路看似完成。

## 原始需求到设计追踪

| 原始FR       | 项目设计与验收观察                                                     |
| ------------ | ---------------------------------------------------------------------- |
| FR-SCRIPT-01 | ScriptSourceVersion＋媒体原件；真实格式/上传和解析状态分开             |
| FR-SCRIPT-02 | ImportTask＋幂等/检查点；重复/丢回执/重启不多处理，项目保留            |
| FR-SCRIPT-03 | ParsedScriptVersion＋识别证据/不确定片段；无标题/歧义/编码异常不伪成功 |
| FR-SCRIPT-04 | ExtractionCandidate→明确采用；同名不合并、锁定设定不覆盖               |
| FR-SCRIPT-05 | 阶段结果按需查、安全错误与后续结构引用；不假定已形成镜头               |

验证真实三种原件、损坏docx/编码异常、重复导入、抽取中断、部分结果及同名/锁定设定冲突；保留原AC识别规则前提。模型外发内容与结果准确性必须另核，静态结构测试不证明抽取正确。

## 待评审选择与实施入口

文件限制/PDF、分集识别与无标题处理、抽取外发及费用、确认/重导入差异、部分结果采用和集→场→首次镜头仍是开工前政策。Demo不依赖本模块。按[Plan](../plan/07-剧本.md)先原件/任务，再接受识别与采用规则，不提前建立解析平台或新运行栈。

路径统一以/api开头；字段后?表示可空/可省，其他为必需；Id/Rev/Time/Money/Page及通用错误见[全局HTTP合同](00-项目需求设计.md#工程合同http全局约定)。响应只包含所列字段，不直接序列化ORM。

| `ScriptImportView`    | operation:Operation、source_id:Id、stage:string、progress:{done:string?,total:string?}、script_version_id:Id?、uncertain_segments:Json[]                               |

### 采用与后续镜头的事务

建议由制作者确认解析版本的集/场及设定候选，采用后形成episodes/scenes稳定ID；settings通过所属采用用例创建新实体，同名不自动合并。源区间/识别依据校验不通过不建业务结构，未接受场形成规则时不允许该部分采用。再次采用同source ordinal/candidate定位原记录，重导入生成新版本，不替换已有人工编辑。
首次镜头建议由制作者在已确认场中明确新建；如产品选择自动形成，须先接受原文分段/编号/失败规则。这是当前候选衔接方案，不能以接口存在宣称首次镜头政策已定。外部收费解析同样要保存调用意图/受理事实，不能仅以Import lease_token确保不重复；具体协议接受前该收费解析不开启。

### 集场读取与当前结构

建议采用新解析版本时显式更新projects.active_script_version_id及project revision/audit；旧episodes/scenes及镜头历史保留，项目当前集场只读该已采用结构。重导入替换/部分采用仍须产品接受，不自行抹旧结构。
