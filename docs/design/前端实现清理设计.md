# 前端实现清理

日期：2026-10-01。用户明确要求抛弃现有前端实现，并确认保留现有技术栈配置、清空全部实现。本次只清理，不创建替代页面或新架构。

## 范围与边界

- 删除 `frontend/src/`、`frontend/tests/`、`frontend/public/` 中全部页面、组件、画布引擎、状态、请求封装、生成客户端、测试和展示素材。
- 保留 Next.js、React、TypeScript、pnpm 的版本、依赖清单与锁文件，以及现有 lint、格式、组件、测试、生成器和容器工程配置。配置不等于应用可运行；没有 App Router 页面时不执行或宣称构建、浏览器及产品验收通过。
- `next.config.ts` 不再导入已删除的源码；配置自身保留后端地址校验和 API rewrite 约定，上传 Route Handler 也随前端源码删除，不保留实现兼容层。
- 停止本轮启动的旧前端 3000 进程，清除旧 `.next`、`next-env.d.ts` 和 TypeScript 缓存，防止旧页面继续以构建产物运行。保留已安装依赖与全部本地凭据。
- Go API、Worker、Relay、公开 Swagger、SQL 迁移、项目/画布/媒体记录与对象存储不清理、不回滚。后端受控媒体测试样本从前端移至 `backend/tests/canvas/testdata/`，保持原字节和覆盖。
- 历史第三方许可文本移至 `docs/licenses/`，保留来源和历史适配记录；它们不代表当前前端仍含移植代码。

## 仓库集成与失败路径

暂停 CI 的前端检查、生成客户端对比和前端镜像构建，移除 Compose 的前端服务；保留 Go 门禁、Swagger 静态生成、当前 API 的在线 Swagger 一致性及后端镜像。后续前端重建时需重新建立客户端与产品门禁，不能使用已删除代码的历史验收替代。

仅删除核实属于上述三个前端目录的文件和明确的旧构建产物。操作前后核对 Git 状态与文件清单；发现并行改动或不明文件先保留，不扩展到数据库、存储、依赖环境或无关进程。实现与当前文档同步，历史验收不改写成失败，也不作为清理后的可用证据。
