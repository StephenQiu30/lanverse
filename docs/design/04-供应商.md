# Design 04：供应商

执行编号：04；原始需求模块：09。依据[原始需求](../requirement/09-供应商需求.md)、[PRD](../prd/04-供应商.md)与[Plan](../plan/04-供应商.md)。本文件把原始需要转换成项目方案，**全部新增设计选择仍待评审**；数据对象和接口为拟议合同，不表示已有表或已实现API。共同约束见[整体设计](00-项目需求设计.md)。原始FR、质量条件与AC仍须同时满足。

## 凭据版本与连接事实

供应商模块拥有服务端凭据引用、活动配置revision和连接测试记录，模型模块拥有模型能力版本。浏览器只得到名称/能力摘要、脱敏掩码、配置状态和测试时间，不得到任何真实密钥。凭据保存建议使用运行环境受控秘密存储或加密持久化，选择、轮换和密钥管理在D0落实。

ProviderConfig包含provider_id、active_credential_version、revision；CredentialVersion是不可变秘密引用；TestAttempt含测试对象版本、操作者、意图、开始/结束、类别化结果及费用事实。新候选测试不改变活动配置，“可用”只描述被测凭据/能力和时间，不能证明所有模型始终可用。

## 候选测试后替换

拟议管理员接口GET /providers、POST /providers/{id}/credential-tests提交候选、GET /provider-tests/{id}查结果、POST /providers/{id}/tests测当前配置。普通创作者只经模型获取必要的可用能力，不读取凭据页。

1. 管理员提交候选秘密、expected_config_revision和必要测试费用确认；服务端记录安全测试意图，秘密不进入HTTP日志/审计。
2. 在事务外测试真实鉴权/能力/配额，区分认证、连通、配额失败、超时与结果未知。无成功事实不替换。
3. 通过后条件事务校验活动revision仍相同，再发布新凭据版本和测试事实/审计。并发替换冲突保留原活动值，不静默以迟到成功覆盖。
4. 失败清理候选秘密按保留政策，结果仅保留安全摘要。测试可能收费时也不能盲目重复；同测试request_key建议返回同TestAttempt。

测试当前配置先固定active_credential_version，回执仍标注该版本；若活动值已变化，旧成功仅作历史，不更新当前状态。生成任务记录调度时使用的凭据版本引用，密钥轮换不改历史任务事实；旧秘密保留到有关在途任务不再需要，安全撤销策略须确认，不在设计文档存值。

## 原始需求到设计追踪

| 原始FR         | 项目设计与验收观察                                           |
| -------------- | ------------------------------------------------------------ |
| FR-PROVIDER-01 | 安全Provider摘要＋版本化测试事实；未配置、失败与历史成功可辨 |
| FR-PROVIDER-02 | CandidateTest→条件发布；失败保留旧值，并发冲突不覆盖         |
| FR-PROVIDER-03 | 当前版本TestAttempt；旧版本晚到成功不能冒充当前成功          |

以合成秘密标记检查响应/包/日志/审计；验证候选测试失败、超时、两次并发替换、活动版本改变后的晚到回执。真实测试类型/费用/供应商支持另留证，不以mock推断连接已验证。

## 待评审选择与实施入口

实际供应商及测试动作、费用确认、超时/结果未知核对、短密钥掩码、成功状态有效期和凭据撤销/轮换待明确。建议掩码只返回固定隐藏标识及足够安全的尾部，长度规则经评审。首轮先让真实生图与首帧图生视频可用，不承诺一个凭据支持全部能力。

### HTTP接口与DTO

路径统一以`/api`开头；字段后`?`表示可空/可省，其他为必需，`Id/Rev/Time/Money/Page`及通用错误见[全局HTTP合同](00-项目需求设计.md#工程合同http全局约定)。响应只包含所列字段，不直接序列化ORM。

| DTO                | 字段与类型/语义                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ProviderView`     | id:Id、name:string、capabilities:string[]、config_revision:Rev、credential_mask:string?、status:unconfigured/available/test_failed/unknown、last_test_id:Id?、checked_at:Time? |
| `CredentialTest`   | request_key:Id、expected_config_revision:Rev、api_key:string、group_id:string?、cost_confirmation:{max_amount:Money,currency:string}?；秘密只请求端                            |
| `CurrentTest`      | request_key:Id、expected_config_revision:Rev、cost_confirmation:Json?                                                                                                          |
| `ProviderTestView` | operation:Operation、provider_id:Id、tested_config_revision:Rev、credential_version_id:Id、result_category:string?、checked_at:Time?、activated:boolean、cost:CostView         |

| 方法与路径                                                 | 权限   | 请求           | 响应/HTTP状态        | 错误与写入边界                                |
| ---------------------------------------------------------- | ------ | -------------- | -------------------- | --------------------------------------------- |
| `GET /api/admin/providers`                                 | 管理员 | 无             | 200 ProviderView[]   | 403普通用户；仅DTO掩码，不能序列化Credential  |
| `POST /api/admin/providers/{provider_id}/credential-tests` | 管理员 | CredentialTest | 202 ProviderTestView | 409配置/键冲突；422未知测试费用不允许收费测试 |
| `POST /api/admin/providers/{provider_id}/tests`            | 管理员 | CurrentTest    | 202 ProviderTestView | 固定活动credential版本；晚到不覆盖新配置      |
| `GET /api/admin/provider-tests/{test_id}`                  | 管理员 | 无             | 200 ProviderTestView | 结果未知/失败安全分类，不能返回原始供应商响应 |

### 测试结果与活动指针事务

凭据先存受控秘密引用和候选版本，测试意图持久后在事务外执行。通过时UPDATE providers WHERE revision=expected值，设置active_credential_id并推进revision/test事实/audit；不匹配409并标未激活。失败/unknown不替换活动版本。当前测试last_test_id只有仍匹配活动credential才更新；旧结果保持历史。

测试收费结果未知使用与生成同样的“意图已发出→先核对”原则；租约本身不能使供应商只执行一次。秘密存储写入成功但业务事务失败会留下未激活引用，按候选保留政策处理，不回显秘密；HMAC key引用轮换和旧键保留需D0接受，不能把密钥内容写入本表或文档。
