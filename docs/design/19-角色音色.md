## 8. 固定来源完整迁移的当前音色注册表合同（2026-10-02）

Bible catalog 声音引用使用 catalog owner 的事务端口。当前模型必须属于 `audio.tts`、已启用、有当前已发布版本，供应商已启用且当前凭据存在并通过实际测试；项目的境外模型策略与当前 active actor/org/project 同事务复核。读取声音列表不读取密文、执行供应商调用或写入默认音色。固定来源的十三个 voice key 不构成我们注册表中的可执行事实。

实际音色来自当前版本 `param_schema` 中唯一的 string/voice 字段 `voice_id` 枚举。字段、枚举和所选 speed/pitch/volume/emotion/language 按已接受的发布参数 schema 核验，未声明参数、未知枚举、过期 expected model version 和不适用任何已发布 TTS mode 的参数组合均拒绝。绑定阶段只要求至少一个已发布 mode 支持完整参数组合；真正生成时，再按用户所选 mode 执行参数核验。绑定冻结 model key、真实 version ID/version number、voice key、schema SHA 和用户提供的参数；不把默认参数静默写成用户选择，也不把样本绑定声称为克隆或试听。列表先按真实模型 key/voice key 完成筛选与排序再分页，不只筛选已加载模型。

catalog 的读取锁保留到调用者的 Bible 写事务结束，包括当前身份、项目、模型、供应商、当前版本和凭据状态，避免验证后配置撤销仍被写入。应用边界只返回安全类型化事实；组合根完成 catalog→bible 的显式转换，不让 Bible 读取 catalog SQL。真实音频生成、试听与下游过期仍由实际 Operation/audio/lineage owner 接管，依赖未就绪明确失败。
