## 2. 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `bible.voice_profile` | `character_id`（唯一）、`model_key`、`voice_id`、`params`、`revision` | 角色音色 |
| `operation.operation` | `target_type = voice_preview` | 试听 |
| `lineage.dependency` | `dialogue_audio` → `voice_profile`（`upstream_version = revision`） | 过期传播 |

## 3. 接口

```http
GET /api/models?capability=audio.tts&project_id=…   → 含 voice 参数枚举：[{ "voice_id": "…", "name": "青年男声·沉稳", "tags": ["male","young"], "sample_url": "…" }]
GET /api/characters/{id}/voice
PUT /api/characters/{id}/voice  { "model_key": "minimax.speech-02", "voice_id": "…", "params": { "speed": 1.0, "emotion": "neutral" }, "expected_revision": 2 }
200 { "revision": 3, "stale_dialogue_audios": 37 }
POST /api/projects/{pid}/quotes { "items": [ { "target_type": "voice_preview", "target_id": "<character_id>", "capability": "audio.tts", "params": { "text": "…" } } ] }
```

## 4. 异步与工作流

试听走 OperationWorkflow（同步型 TTS，秒级完成）。

## 5. 事件与实时

`bible.voice_changed.v1` → lineage、audit。

## 6. 界面

音色选择器（筛选标签、播放官方示例）；“用本角色台词试听”按钮（显示预估费用）；试听结果播放器。

## 7. 权限与审计

制作者；审计 `voice.changed`。

## 8. 非功能要求

PERF-09（试听结果 ≤ 10 秒可播放，受供应商约束）。

## 9. 测试设计

音色变更的过期范围；试听复用。

## 10. 待确认

| 编号 | 问题 | 默认方案（确认前按此实施） | 确认时机 |
| --- | --- | --- | --- |
| DES-19-Q1 | 音色列表从供应商接口实时拉取，还是在注册表中静态维护？ | 注册表静态维护（`param_schema` 中 `voice_id` 的枚举），由管理员随供应商更新。 | M3 开始前 |
| DES-19-Q2 | 试听文本的长度上限与计费？ | 最长 50 字，按字符计价，照常报价确认（GEN-11）；相同文本与音色复用已有试听。 | M3 实施中 |
| DES-19-Q3 | 更换 TTS 模型后，原 `voice_id` 通常不通用，怎么办？ | 更换模型必须重新选择音色；该角色的 TTS 音频全部标记过期。 | M3 开始前 |
