## 2. 处理流程

```text
本集结构已确认 → 选择场（全部 / 部分）→ 报价确认 → 每场 storyboard Skill
  输入：场结构（台词、动作、原文）、本场出现的角色 / 场景 / 道具与已锁定造型、项目风格与画幅、镜头语言词表
  输出：镜头列表 [画面描述（含 @实体）、景别、机位、运镜、时长、台词分配、引用造型 / 场景 / 道具、建议模式、默认参考组合]
  校验：台词一且仅一、引用在设定集中、时长在默认模型范围内
→ 保存为该场镜头（shot + shot_version v1，origin = ai），scene_board = awaiting_review
→ 编辑 → 确认本场（校验通过）→ confirmed
→ 后续逐镜修改 → 新版本 → 已生成的候选 / 片段标记过期
```

## 3. 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `storyboard.scene_board` | `episode_id`、`scene_key`、`status`、`operation_id` | 按场生成与确认 |
| `storyboard.shot` | `scene_key`、`position`、`shot_no`、`current_version_no`、`progress`、`is_delete`、`revision` | 镜头身份与顺序 |
| `storyboard.shot_version` | 画面描述、`entity_refs`、景别、机位、运镜、`duration_ms`、`generation_mode`、模型与参数、`prompt_override`、`origin`、`change_note` | 不可变内容 |
| `storyboard.shot_line` | `line_key`、`seq_no` | 台词分配（引用稳定键） |
| `storyboard.reference_item` | 见 [DES-22](22-生成模式与参考组合.md) | 参考组合 |
| `lineage.dependency` | 镜头版本 → 台词（`content_hash`）、参考版本 | 过期 |
| `storyboard.shot_template` | `name`、`shots[]` 参数模板 | SB-06 |

## 5. 异步与工作流

每场一个 `OperationWorkflow`（`target_type = scene_storyboard`）的 LLM 同步分支（DES-04 §3）：`llm.run_skill(storyboard)` → `flow.ApplyStructuredResult`（为尚未确认的场写镜头与第 1 版镜头版本，`origin = ai`；已确认的场不覆盖，只能由用户重新生成后再确认）。多场由 `BatchWorkflow` 启动子工作流。

## 6. 事件与实时

`storyboard.shot_version_created.v1`（lineage、realtime）；SSE `shot.updated`。

## 7. 界面

镜头表（TanStack Table + Virtual）：按场分组、行内编辑（下拉、时长步进器）、多选工具栏（批量改参数、批量生成、删除）、拖拽排序（dnd-kit）；画面描述使用 Tiptap + Mention（@造型 / @场景 / @道具）；版本抽屉；场确认按钮与校验提示。

## 8. 权限与审计

制作者。审计：`scene_board.confirmed`、`shot.deleted`、`shot.merged`、`shot.split`（普通参数修改由版本表本身留痕，不重复写审计）。

## 9. 非功能要求

PERF-04（150 镜头渲染 ≤ 1 秒、滚动 ≥ 50 fps）；AIQ-03（台词分配完整率 100%）。

## 10. 测试设计

台词分配校验；合并拆分对 `shot_line` 与引用的影响；批量部分成功；分镜 Skill 评测（TST-03）。
