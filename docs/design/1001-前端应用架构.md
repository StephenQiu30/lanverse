# 前端应用架构

> 目标状态：已接受；落地状态：部分
>
> 设计基线：[AI 短剧制作平台完整设计基线](0001-AI短剧制作平台完整设计基线.md)
>
> 适用范围：`frontend/` 的 Web、协作服务与共享包

## 结论

Lanverse 前端最终收敛为一个独立的 pnpm/Turborepo TypeScript 工作区：`apps/web` 承载 Guided Studio、Canvas Studio、Review 与 AI Copilot，`apps/collab` 承载 Yjs/Hocuspocus 协作连接；`packages/ui`、`ai`、`canvas`、`sdk`、`auth` 分别拥有设计系统、AI 交互、画布能力、后端契约和认证能力。

Guided Studio 与 Canvas Studio 不是两套业务和执行链。二者只是同一 `Authoring Draft` 的两种编辑视图，每次运行都绑定同一模型下不可变的 `Authoring Revision`，再由 Backend 编译为 `Workflow Definition Version` 并交给 Temporal。浏览器不直接调用 Temporal、模型 Provider、Agent Runtime 或 PostgreSQL。

前端状态遵守“一份事实、一个所有者”：服务端事实属于 Backend/PostgreSQL，浏览器通过 TanStack Query 缓存；跨组件的瞬时 UI 状态属于 Zustand；表单草稿属于 React Hook Form + Zod；协同编辑中的共享草稿属于 Yjs；可导航上下文属于 URL；未完成的 AI 流属于流式会话控制器。禁止把同一份数据长期复制到多个状态系统。

当前代码仍是 `frontend/` 下的单 Next.js + npm + Redux Toolkit Query 应用，因此本架构是目标形态而非现状描述。迁移允许 RTK Query 与 TanStack Query 在有限阶段分别服务不同业务切片，但同一 endpoint、实体或缓存键不得双写；一个切片迁移完成时必须在同一变更中删除对应 RTK Query 入口。Canvas 开始落地前应完成 Redux 退出，避免形成长期双状态体系。

## 1. 设计范围与约束

本文回答：前端工作区如何拆分、页面如何组织、组件和依赖如何分层、各类状态由谁拥有、Guided/Canvas 如何汇入同一执行系统，以及 Canvas、协作服务和 Backend 的边界。

固定约束如下：

1. Frontend 是一个 TypeScript 项目，不在仓库根目录额外建立 Canvas 项目。
2. `apps/collab` 是前端工作区内可独立部署的协作进程，不是第二套业务 Backend。
3. PostgreSQL 是业务事实源；TanStack Query、Yjs、Zustand 和浏览器存储都不是事实源。
4. Temporal 是唯一全局工作流引擎；前端只发业务命令并展示投影状态。
5. Browser → Backend 使用 REST/JSON，AI 流使用 SSE，Canvas 协作使用 Yjs WebSocket，大文件使用 Presigned URL。
6. Backend 对外接口统一位于 `/api/v1/`；生成的客户端与前端契约归 `@lanverse/sdk`。
7. 不为目标结构预建空目录。只有真实能力开始迁移或实现时，才建立对应 package、入口和测试。

本文新增而完整设计文档未规定的路由、状态交接、协作提交协议、性能预算和迁移门禁，均显式标为“本次细化”。

### 2.1 `apps/web`

`apps/web` 是唯一浏览器产品入口，负责：

- Next.js App Router、布局、页面与路由级加载/错误边界；
- Workspace、Project、Episode 等导航上下文；
- Guided Studio、Canvas Studio、Review 和 AI Copilot 的页面组合；
- Query、Auth、Theme、AI Stream 等 Provider 的装配；
- 服务端渲染、客户端交互边界和按路由拆包；
- 将共享 package 组合成具体业务功能。

业务规则、OpenAPI 手写副本、通用 UI primitive、Canvas 编辑器内核不得留在路由文件中。Next Route Handler 只处理前端自身确需的 Web 适配，不建立另一套领域 Backend 或代理事实源。

### 2.2 `apps/collab`

`apps/collab` 运行 Hocuspocus/Yjs WebSocket，负责：

- 建立、鉴权和关闭协作文档房间；
- 传播 Yjs document update 与 Awareness/Presence；
- 处理连接限额、消息大小、心跳、重连和可观测性；
- 按 Backend 签发或校验的短期授权限制 workspace、project、draft 和能力；
- 触发经 Backend 校验的草稿快照提交，而不是写业务表。

它不拥有 Node Registry、Graph Validation、Publish、Revision、Workspace RBAC 或 Workflow 执行。V1 Collaboration 必须由 `apps/collab` 在专用协作存储中持久化 Yjs update/snapshot，并负责压缩、按 epoch 隔离、保留期与清理；该日志只是可重建的协作恢复投影，不能升级为业务事实源。

### 2.3 共享 packages

| --- | --- | --- |
| `@lanverse/ui` | Radix UI + shadcn/ui + Tailwind CSS 的 Design System primitive、token 与无领域语义组件 | API 调用、鉴权、业务状态、Canvas/AI 逻辑 |
| `@lanverse/ai` | Chat、Message、Reasoning、ToolCall、AgentStatus、Streaming、ArtifactPreview、PromptInput 及流式会话控制器 | 工作流执行、模型密钥、服务端最终会话事实 |
| `@lanverse/canvas` | React Flow 编辑器、节点/边、Inspector、工具栏、选择、快捷键、剪贴板、布局、运行覆盖层、协作客户端 | 权限裁决、Node Registry 定义、图发布、Temporal/Provider 调用 |
| `@lanverse/sdk` | 生成的 OpenAPI 类型和客户端、统一错误、Query key/options、SSE/上传/协作协议类型 | UI、React 全局状态、业务规则的第二实现 |
| `@lanverse/auth` | Session Provider、身份恢复、登录/退出适配、路由/动作守卫和能力读取 | Workspace RBAC 最终裁决、业务实体缓存、模型或存储凭据 |

页面职责：

- `/workspaces`：选择或创建可访问的 Workspace。
- `/account/security`：账户密码、活动 Session 和全局撤销；不承载 Workspace 配置。
- `/w/:workspaceId/projects`：项目列表、搜索和创建入口。
- `/w/:workspaceId/projects/:projectId`：项目总览、Production Bible、Episode 与生产状态。
- `/w/:workspaceId/projects/:projectId/episodes/:episodeId/guided`：面向普通创作者的业务步骤视图。
- `/w/:workspaceId/projects/:projectId/canvas/:draftId`：面向高级创作者的统一 Authoring Draft 画布视图。

- `reviews`：统一审核队列和审核对象详情。

`projectId`、`episodeId`、`draftId`、`humanTaskId`、`workflowRunId`、稳定 tab、筛选、排序和可复现的选择可以进入 URL；Canvas viewport、拖拽中坐标、未提交表单、Access Token 和 Presence 不进入 URL。

现有 `/projects`、`/projects/:projectId`、`/studio/:episodeId`、`/governance` 可在迁移期做单向 redirect。旧路由只负责跳转，不保留第二套页面、数据加载或状态容器；redirect 删除时间应在迁移计划中明确。

## 4. 组件与依赖分层

### 4.1 页面内部分层

```text
Route / Layout（上下文、加载、错误边界）
              ↓
Feature Controller（用例编排、Query/Mutation、权限能力）
              ↓
Domain View（业务展示与用户意图事件）
              ↓
Shared Package（ui / ai / canvas / auth）
              ↓
SDK（REST / SSE / Upload / Protocol）
```

- Route/Layout 解析 URL 和认证上下文，不堆积业务交互。
- Feature Controller 调用 SDK、Query 与 mutation，将服务端模型映射为 View Props；跨领域命令仍由 Backend 保证一致性。
- Domain View 不导入生成 API 客户端，不自行决定权限和缓存失效。
- Shared Package 提供稳定能力，不反向导入 `apps/web` 的 feature。
- SDK 不依赖 React、Zustand 或 Yjs 文档实例；需要 React 集成时由上层适配。

### 4.2 包依赖方向

```text
                         apps/web
                 ┌──────────┼──────────┐
                 ▼          ▼          ▼
              auth         ai       canvas
                 │          │       ┌──┴──┐
                 │          └──────►│ ui  │
                 └─────────────────►└─────┘
                 └──────────┬──────────┘
                            ▼
                           sdk

apps/collab ───────────────► sdk（仅协议与 Backend client）
```

图表示允许依赖，不要求每个 package 都依赖所有下层。额外规则：

1. `ui` 不依赖 `ai`、`canvas`、`auth`、`sdk` 或 app。
2. `ai` 可依赖 `ui`，只通过注入的 transport 或 SDK 类型消费流，不拥有认证。
3. `canvas` 可依赖 `ui` 和少量 `ai` 展示组件；不得反向被 `ai` 依赖。
4. `auth` 可依赖 `sdk` 和 `ui`；不得依赖 `canvas` 或业务 feature。
5. `sdk` 是叶子基础设施包，不导入其他 Lanverse 前端 package。
6. 任一 package 均不得导入 `apps/*`；`apps/collab` 与 `apps/web` 互不直接导入。
7. 依赖约束由 ESLint/import-boundary 与架构测试执行，不仅写在文档中。

原设计中的主 UI 依赖关系保持不变：`web → canvas → ai → ui`；箭头表示左侧可导入右侧，`canvas` 也允许直接复用 `ui`。上图补充了 `sdk`、`auth` 和 `collab` 的边界。

## 5. 状态所有权

### 5.1 一份事实、一个所有者

| 状态类别 | 所有者 | 典型数据 | 明确禁止 |
| --- | --- | --- | --- |
| 服务端事实与缓存 | TanStack Query | Project、Episode、Asset、Review、Task、Revision、Node Catalog | 复制进 Zustand/Yjs；在多个 Query key 保存不可同步的同一实体副本 |
| 跨组件瞬时 UI | Zustand | 面板开关、工具模式、瞬时多选/hover、非共享 inspector 状态、快捷键上下文 | 保存服务端实体、表单字段、Yjs graph、Access Token |
| 表单编辑与校验 | React Hook Form + Zod | 登录、项目创建、节点配置表单、审核理由 | 用 Zustand 做表单仓库；把客户端校验当作服务端规则 |
| 协同共享编辑态 | Yjs | 当前房间的 graph/layout 变更、共享选择注释、Awareness/Presence | 保存已发布 Revision、权限、运行状态；把 graph 再镜像到 Zustand |
| 可导航状态 | URL | workspace/project/episode/draft/human task ID、tab、filter、sort、显式复制链接的 focused node | 高频多选/hover/拖拽状态、凭据、未提交敏感输入、完整对象 JSON |
| 未完成 AI 流 | AI stream controller | 当前 response parts、reasoning/tool 状态、断线与重连游标 | 把未确认流式 token 写入 Query 事实或全局 Zustand；客户端伪造成功终态 |
| 组件私有状态 | React local state | hover、单个弹层、输入法组合、短生命周期动画 | 无原因提升为全局 store |

TanStack Query 是 Backend 事实的客户端缓存，不是新的 Source of Truth。查询返回的最终状态始终可以丢弃并从 Backend 重建。

### 5.2 普通命令的数据流

```text
URL 识别资源
  ↓
TanStack Query 读取 Backend snapshot
  ↓
React Hook Form 持有未提交草稿，Zod 做即时结构校验
  ↓
Mutation 发送 intent + expected revision/idempotency key（按接口要求）
  ↓
Backend 校验、授权并提交 PostgreSQL
  ↓
更新或失效唯一 Query key，重新读取事实
```

允许对可安全回滚的纯 UI 变化做 optimistic update；Review 决策、Revision 发布、生成完成、权限变更和不可逆业务动作不在服务端确认前显示为成功。

### 5.3 Canvas 编辑的数据流

```text
TanStack Query 读取 Draft baseline / Revision / Node Catalog
                       ↓
              Yjs 成为房间内 graph/layout
                 唯一可变共享状态
                       ↓
React Flow 订阅增量视图；Zustand 只保存本地工具与选择状态
                       ↓
保存/运行时提交 canonical snapshot + base version
                       ↓
Backend 鉴权、校验、保存 Draft 或创建不可变 Revision
                       ↓
失效 Draft/Revision Query；运行只绑定 Revision
```

不要在 TanStack Query cache、Yjs document 和 Zustand 中同时维护三份 `nodes[]/edges[]`。Query 只负责进入房间前的基线与已提交结果；房间活跃时 Yjs 是共享编辑态所有者；离开或提交后，以 Backend 返回的新版本为准。

### 5.4 AI 流的数据流

```text
Query 读取已持久化 conversation / run
  ↓
用户发起命令，SSE 返回带 event id 的结构化 parts
  ↓
@lanverse/ai controller 持有 in-flight buffer
  ↓
terminal event 只表示服务端已接受的终态
  ↓
失效对应 Query，使用持久结果替换 buffer
```

本节为本次细化：SSE 事件必须可按稳定 event id 去重；重连使用服务端支持的游标或重新读取 run，不按字符串 token 猜测是否完整。断线或结果不确定时展示“连接中断/状态待确认”，不能在客户端标记成功。

### 5.5 Auth 状态

本节为本次细化：Web 采用短期 Access JWT + 旋转的 HttpOnly Refresh Session，会话材料由 `@lanverse/auth` 独占。Access Token 不得进入 URL、Zustand、Query cache 或持久化业务对象；`/me` 等身份事实由 TanStack Query 读取。前端守卫用于体验和减少无效操作，Backend RBAC 始终是最终裁决。

## 6. Guided 与 Canvas 的统一 Authoring 模型

```text
Guided Studio ───────┐
                     ▼
               Authoring Draft
                     ▲
Canvas Studio ───────┘
                     ↓
        immutable Authoring Revision
                     ↓
             Workflow Compiler
                     ↓
       Workflow Definition Version
                     ↓
                  Temporal
```

必须保持以下不变量：

1. Guided 与 Canvas 读取和修改同一 Draft schema，不生成 `GuidedWorkflow` 与 `CanvasWorkflow` 两套模型。
2. Guided 将业务步骤呈现为剧本、角色、场景、分镜、镜头、声音、审核和成片；它向 Backend 发送领域命令，不要求用户理解 Node、Port 或 DAG。
3. Canvas 将相同内容呈现为 Graph、Node、Edge、Binding 和 Layout；节点定义来自 Backend Node Registry，不在前端写死执行契约。
4. 切换视图只是切换 Authoring UI。业务字段、节点配置和绑定必须保持；纯 Canvas layout 可以按可选投影生成，不影响执行语义。
5. 每次 Run Node、Run Branch、Run Dirty 或 Run All 都必须先选择或创建不可变 Revision，并记录 revision id/hash；可变 Draft 不直接进入 Temporal。
6. Workflow Compiler 与 Temporal 均位于 Backend/执行系统，前端不重写编译或调度逻辑。
7. Prompt、输入 Artifact、模型策略、节点配置、Skill、连接和候选选择会改变执行脏状态；坐标、颜色、Frame、Comment 和 Viewport 不改变执行脏状态。

本次细化：`authoring_mode` 可以作为 Revision 的来源元数据用于审计，但不得参与生成两种不兼容 schema。Guided 中无法表达的高级节点应显示为只读摘要或“在 Canvas 中编辑”，不能静默删除；Canvas 回到 Guided 时同样保留这些节点。

## 7. Canvas、Collab 与 Backend 边界

| 能力 | Web / `@lanverse/canvas` | `apps/collab` | Backend Go / 执行系统 |
| --- | --- | --- | --- |
| 显示、拖拽、缩放、连接、选择、快捷键 | 负责 | 不负责 | 不负责 |
| Inspector、节点库、运行覆盖层 | 负责展示与发出意图 | 不负责 | 提供定义与状态 |
| Yjs update、Presence、房间连接 | 发起/消费 | 负责传播与连接治理 | 提供授权依据与提交入口 |
| Node Registry、配置 schema、permission/cost/cache policy | 消费并渲染 | 不负责 | 唯一定义与校验 |
| Draft、Revision、Template、Graph Validation、GraphPatch、Publish | 发出命令、预览结果 | 不直接拥有 | 负责 |
| Workflow 编译、局部执行、重试、Human Gate | 展示并发出业务命令 | 不负责 | Compiler + Temporal 负责 |
| Agent/模型/媒体执行 | 不直接调用 | 不调用 | Backend Gateway/Agent/Worker 负责 |
| PostgreSQL 业务写入 | 禁止 | 禁止直接写业务表 | 负责事务与事实 |

Canvas Agent 仍遵循固定确认流：

```text
User → Canvas Agent → Node Catalog → GraphPatch
     → Backend Validate → Frontend Preview → User Confirm
     → Backend ApplyGraphPatch Intent/Apply Grant
     → Collab 幂等 Yjs Transaction → Backend Draft Snapshot Receipt
```

Agent 与 Frontend 都不直接修改 Yjs，不绕过用户确认，也不把未验证 patch 写成正式 Revision。Copilot Patch 同时要求 Access Capability `copilot:apply_tool ∧ authoring:edit`；Backend 必须在 Collab 修改前验证这组 Access Capability、base revision、document epoch、state vector 和 patch hash。Collab 只接受一次性 Apply Grant，并以 application id 去重；远程结果未知时按同一 id 对账，Frontend 不重放 Patch。

### 7.1 Yjs 与 PostgreSQL 的事实边界

PostgreSQL 保存可审计的 `AuthoringDraft` snapshot、不可变 `AuthoringRevision`、权限、发布结果和运行绑定，是事实源；Canvas 来源以 `authoring_mode=CANVAS` 记录。Yjs document 表达“一个活跃协作房间当前如何共同编辑该 Draft”，是会话内共享编辑模型。

本次细化的提交协议：

1. 打开房间前，Web 先向 Backend 请求 Draft baseline、`draftVersion`、`documentEpoch` 和短期房间授权。
2. `apps/collab` 只接受授权范围内的文档与能力；Presence/Awareness 不持久化为业务事实。
3. 自动保存、显式保存、离房 checkpoint 或运行前，客户端/Collab 提交规范化 snapshot、base version、epoch、snapshot hash 和 mutation id。
4. Backend 重新做 RBAC、Node Registry schema、Graph Validation 和并发版本校验；校验成功后才更新 Draft 或创建 Revision。
5. base version/epoch 冲突时，客户端必须重取事实并执行可解释的 rebase/冲突交互，不能以最后写入静默覆盖。
6. Backend 成功响应的新版本成为下一基线；房间关闭后，Yjs 内存状态可以丢弃。

Copilot/Canvas Agent 的 GraphPatch 不能走“客户端先乐观写 Yjs”路径：Backend 先建立 `GraphPatchApplicationIntent`，Collab 返回带新 State Vector/Graph Hash 的事务 Receipt，Backend 再提交 Draft Snapshot。只有持久 Receipt 为 `APPLIED` 时 UI 才显示成功；普通人工协作编辑仍按上述 Snapshot 提交协议工作。

Hocuspocus 必须为服务重启和断线恢复持久化 Yjs update/snapshot；`apps/collab` 拥有该专用协作存储及其按 `documentEpoch` 隔离、压缩、保留期和清理策略。数据必须能从 PostgreSQL baseline 重建，且不可被其他业务模块当作 Revision 查询。

### 7.2 Canvas 运行与局部执行

前端提供 Run Node、Run To Node、Run From Node、Run Branch、Run Selection、Run Dirty、Retry Failed 和 Run All 的意图。Backend 根据选定 Revision 计算合法执行子图、缓存和 Dirty 传播；前端只显示 Backend 返回的计划、成本预估、权限门禁、运行状态和 Artifact。

视觉节点（Frame、Comment、Group 等）不进入 Workflow 执行。客户端可以提前提示明显端口错误，但只有 Backend Validation 能允许发布或执行。

## 8. 数据访问与通信

`@lanverse/sdk` 统一封装协议，而不隐藏领域含义：

- REST/JSON：OpenAPI 生成 client、类型、稳定 Query key 和错误 envelope；
- SSE：结构化事件、event id、run id、终态与重连游标；
- Yjs WebSocket：房间标识、授权交换和连接错误类型，Yjs document 本身归 Canvas/Collab；
- Presigned URL：初始化上传、直接上传、完成确认与媒体状态查询；
- Trace：保留 Backend 返回的 request/trace id，供错误反馈和 Observability 关联。

Feature 不直接拼接 `/api/v1` URL，不直接使用 Axios/fetch 建第二套错误处理，也不访问模型 Provider 或对象存储私有地址。TanStack Query 的 key 由资源身份和服务端查询参数组成；展示文案、临时筛选输入和完整对象不得进入 key。

Node Catalog、Access Capability、Generation Capability、Preset 和其他动态注册表按 Backend 响应渲染。前端 fallback 只能保证页面可恢复，不能凭本地常量宣称某节点、模型或动作可用。

## 9. 错误、权限与审核交互

### 9.1 统一错误模型

本次细化：SDK 将 HTTP、SSE、WebSocket 和上传错误归一为可判别错误，至少保留 `code`、用户安全消息、`nextAction`、field/node path、retryability、request/trace id；不得把后端诊断原文或敏感上下文直接展示给用户。

| 错误 | 前端行为 |
| --- | --- |
| 401 / unauthenticated | 清理失效会话，跳转登录并仅保存安全 return URL |
| 403 / forbidden | 路由显示 Forbidden；动作级错误回滚 pending 状态并刷新能力 |
| 404 | 资源级 Not Found；不以空白页面或无限 loading 代替 |
| 409 / revision conflict | 显示过期版本、刷新/rebase 选项；Canvas 禁止静默覆盖 |
| 422 / validation | 表单定位到字段；Canvas 定位 node/edge/port；保留用户草稿 |
| 429 / rate limited | 尊重 Retry-After，禁用重复提交并显示可恢复时间 |
| 5xx / dependency unavailable | 保留上下文，提供安全重试；不伪造成功数据 |
| SSE/WS 中断 | 标记连接状态，按游标重连或重取 run/draft；未知终态显示待确认 |
| 上传失败 | 区分签名过期、网络失败、探测失败；只重试幂等阶段 |

每个主要路由必须有 loading、empty、error、forbidden、not-found 和 stale/conflict 状态；不能只实现 happy path。

### 9.2 权限

- Backend 的 Workspace RBAC、资源权限和 Node permission 是唯一授权依据。
- Web 根据服务端 Access Capability 隐藏或禁用不可用动作，并解释原因；路由守卫不替代 Backend 校验。
- `apps/collab` 的房间授权应短期、精确绑定 workspace/project/draft 和读写能力；权限撤销或过期后停止接受 update。
- AI ToolCall、GraphPatch、发布、运行、审核和导出等高影响动作需展示目标与结果，按 Backend policy 请求确认。
- 模型密钥、数据库凭据、对象存储凭据与私有 bucket 地址永不进入浏览器 bundle 或协作消息。

### 9.3 审核与 Human Gate

统一 Review UI 必须把任务生命周期和业务决议分开：Human Task 状态为 `WAITING / CLAIMED / RESOLVED / CANCELLED / STALE`，Review Decision 类型为 `APPROVE / REJECT / SELECT / REGENERATE / EDIT / SKIP`。列表可分别按 Task 状态和 Decision 类型筛选；`APPROVED/REJECTED` 只能作为本地化展示文案，不能成为混合两类事实的机器状态。审核对象覆盖 Storyboard、Reference、Image Candidate、Video Candidate 和 Episode。

审核详情至少展示：对象版本、关联 Revision/Run、候选差异、输入与来源证据、Artifact 预览、QC 结果、成本、创建者/Agent、当前状态和审计时间线。审核命令携带目标版本、理由和幂等信息；冲突时刷新最新决策，不覆盖其他审核者。

Human Gate 的等待和恢复由 Temporal/Backend 管理。前端只通过 `RecordReviewDecision` 提交规范 Decision 类型并等待 Backend 确认；页面刷新、浏览器关闭或 SSE 断开不得使 Gate 丢失，也不得由前端计时器推进工作流。

## 10. 性能设计

### 10.1 Web 与共享包

- 默认使用 Server Component 做路由 shell 和只读首屏，只有交互边界进入 Client Component。
- Guided、Canvas、Konva、ELK、Tiptap 与 AI 面板按路由/功能动态加载，Canvas 依赖不进入普通项目列表首包。
- TanStack Query 去重并按领域定义 stale/invalidation；禁止为避免请求而复制服务端数据到全局 store。
- 大列表和消息采用窗口化；图片/视频使用缩略图、懒加载和按需 Presigned URL，不预取原始媒体。
- ELK 布局、图快照规范化和重计算量大的媒体操作移至 Web Worker 或分片调度，避免阻塞输入。
- `ui`、`ai`、`canvas` 提供可 tree-shake 的显式 exports，禁止单个全量 barrel 造成所有组件入包。

### 10.2 Canvas 与协作

- React Flow 只订阅发生变化的 node/edge；Zustand selector 与 Yjs observer 保持细粒度，避免每次 update 重建全图。
- 拖拽、连线、批量 patch 和自动布局使用 Yjs transaction 合并；Presence 更新节流且不进入 undo/业务 snapshot。
- 大图按 viewport、collapsed group/subflow 和 detail level 降低渲染量；节点内容避免无界 DOM。
- 远端更新、自动布局与运行 overlay 分通道处理，运行事件不能抢占编辑交互。
- Hocuspocus 设置文档大小、单消息大小、连接数、update 频率和慢消费者保护，并记录拒绝原因。

本次细化的初始验收预算如下；实施前用团队基线设备和真实 fixture 校准，但变更必须有记录，不能直接取消预算：

| 场景 | 初始目标 |
| --- | --- |
| 常规页面 Core Web Vitals | p75 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1 |
| Canvas 基准图 | 至少覆盖 100/500/1000 nodes 与相应 edges 三档 fixture |
| 500-node 本地平移/缩放 | 基线设备目标 ≥ 50 FPS，交互期间无连续长任务 |
| 本地协同编辑反馈 | p95 ≤ 100ms；远端可见延迟单独记录网络耗时 |
| AI 长会话 | DOM 数量有上界，流式增长不导致持续线性重渲染 |

Bundle、Web Vitals、Canvas FPS/长任务、Yjs update 大小与协作延迟进入 CI 或可重复 benchmark；只报告真实 fixture、设备和命令。

## 11. 测试与验收

### 11.1 测试层级

| 层级 | 重点 |
| --- | --- |
| Package unit | UI variant、SDK error/query key、Auth session、AI part reducer、Canvas command/dirty/selection |
| Component | 表单校验、权限态、错误态、审核决策、节点配置与 Artifact preview |
| Contract | OpenAPI 生成无漂移、SSE event schema、GraphPatch/Node Registry/Yjs room protocol |
| Collaboration integration | 两客户端收敛、重连、离线 update、epoch 冲突、权限过期、慢消费者 |
| Canvas integration | add/connect/group/layout、undo/redo、Agent patch preview/confirm、snapshot commit、局部运行 |
| E2E | 登录与 Workspace、项目生产 Guided 闭环、Guided/Canvas 同 Revision、Review/Human Gate、失败恢复 |
| Visual | Design System、Guided 主步骤、Canvas 节点/Inspector/overlay、Review diff 的关键状态 |
| Performance | 路由 bundle/Web Vitals、分档大图、长 AI 流、多人 update 与内存增长 |

### 11.2 必须固定的架构测试

1. package/import 边界符合第 4 节，不出现 app 反向依赖或循环。
2. 业务 feature 只能从 `@lanverse/sdk` 使用 Backend contract，不重复 DTO。
3. Canvas package 不导入 Temporal、Provider SDK、数据库或服务端密钥。
4. Node type/config 由 Node Catalog fixture 驱动，新增节点无需修改前端执行分支。
5. 同一业务切片不存在 RTK Query 与 TanStack Query 双入口；最终仓库无 Redux Provider/依赖。
6. `nodes/edges` 不同时出现在 Query cache、Zustand store 和 Yjs adapter 的业务状态定义中。
7. Guided 与 Canvas 对同一 Draft 生成相同语义 Revision hash；纯布局变化不改变执行 Dirty/hash。
8. 运行请求始终包含不可变 revision 标识，禁止直接提交可变 draft 执行。

### 11.3 关键 E2E 验收

- 用户在 Guided 修改一个业务步骤，切到 Canvas 可见同一变更；从 Canvas 修改可表达配置，回到 Guided 后不丢失。
- Canvas 创建 Revision 并局部运行，刷新或换客户端仍能从 Backend 查询同一 Revision、Run 和 Artifact。
- 两个客户端并发编辑能够收敛；权限撤销后只读/断开行为正确；旧 epoch 不能覆盖新 Draft。
- Review 决策能恢复对应 Human Gate；浏览器关闭再打开仍显示 Backend 中的真实等待/终态。
- SSE、WebSocket 或上传中断时，不出现重复 mutation、虚假成功或丢失已提交 Revision。
- viewer/editor/owner 的页面和动作体验与 Backend RBAC 返回一致，直接调用被禁止动作仍由 Backend 拒绝。

## 12. 从当前前端迁移

### 12.1 当前事实（2026-08-24）

| 维度 | 当前落地 | 目标 |
| --- | --- | --- |
| 工作区 | `frontend/` 单 package | pnpm workspace + Turborepo |
| 应用 | 单 Next.js，代码在 `frontend/src/app` | `apps/web` + `apps/collab` |
| 包管理 | `npm@10.9.8` + `package-lock.json` | pnpm + 唯一 `pnpm-lock.yaml` |
| 服务端缓存 | Redux Toolkit Query，单 `appApi` | TanStack Query，按领域稳定 query keys |
| 客户端全局 Provider | React Redux Provider | Query/Auth/Theme；Zustand 无全局 Provider |
| API | 生成代码在 `frontend/src/api`，手写聚合在 `src/lib/server-state.ts` | `@lanverse/sdk` 生成契约 + 手写适配 |
| UI | `frontend/src/components/ui` | `@lanverse/ui` |
| Auth | 内存 token + 自定义订阅 | `@lanverse/auth` 独占会话、Query 读取身份 |
| Canvas/AI/Collab | 尚未形成目标 package/app | 按真实功能增量建立 |
| 测试 | Vitest + Playwright，位于 `frontend/tests` | package 测试 + `frontend/test/{e2e,visual,fixture}` |

“落地状态：部分”具体表示：Next.js、React、TypeScript、Radix/shadcn/Tailwind、生成 API、基础 UI、认证/权限页面、项目与 Guided 生产页面及 Vitest/Playwright 已存在；pnpm/Turborepo、目标 packages、TanStack Query、Zustand、RHF/Zod 统一表单、React Flow、Yjs/Hocuspocus、ELK、Konva、Tiptap 和 AI UI 尚未按本架构完整落地。

### 12.2 迁移原则

1. 以可运行的垂直业务切片迁移，不做一次性目录搬迁加状态库重写。
2. 不建立空 package、兼容 facade 或通用 `utils`；首次真实消费者与 package 同一变更交付。
3. npm → pnpm 必须原子切换 lockfile 和 CI 命令，不允许两个 lockfile/包管理器长期并存。
4. RTK Query 与 TanStack Query 的短期共存只按“未迁移切片/已迁移切片”隔离；禁止同一资源双缓存、桥接同步或 mutation 双发。
5. 不为两套状态库创建永久统一 wrapper。迁移清单直接记录 endpoint、hook、tag 和新 query key 的一一替换。
6. 迁移 package 不改变 Backend contract；需要改契约时先更新正式 OpenAPI/设计，再重新生成 SDK。
7. 保留现有测试并随切片移动，Green 后才删除旧入口。无外部条件的 E2E 必须如实报告未运行。

### 12.3 迁移阶段与退出门禁

#### M0：固定基线

- 为现有路由、RTK Query endpoint、API 生成和关键 Guided E2E 建立清单。
- 增加 import/state ownership 架构测试，防止迁移期间继续扩大 `server-state.ts`。
- 记录 bundle、测试时长和核心页面性能基线。

退出门禁：现有测试真实通过；迁移范围和 endpoint owner 可追踪。

#### M1：建立 pnpm/Turborepo 与 `apps/web`

- 原子切换 pnpm lockfile、workspace 和 Turbo task。
- 将现有 Next 应用移动到 `apps/web`，先保持路由和行为不变。
- 只配置真实存在的 build、lint、typecheck、unit 和 e2e task，不创建未来空目录。

退出门禁：pnpm 单 lockfile；开发、构建、类型、单测和现有 E2E 从工作区命令可运行；npm 配置退出。

#### M2：抽取 `sdk`、`ui` 与 `auth`

- 将生成 API/类型和 request/error 适配迁入 `@lanverse/sdk`。
- 以已有组件消费者抽取 `@lanverse/ui`，保持视觉回归。
- 将会话恢复、登录/退出与能力读取迁入 `@lanverse/auth`，Backend RBAC 行为不变。

退出门禁：app 内无重复 DTO/第二请求层；package 边界测试和现有身份/权限 E2E 通过。

#### M3：逐切片迁移 TanStack Query

建议顺序：身份只读查询 → Workspace/Project → Episode/Script → Asset/Media → Storyboard/Task/Review。每个切片在一个闭环中：

1. 定义唯一 query key 与 mutation invalidation；
2. 迁移页面和测试；
3. 删除同切片 RTK endpoint、hook、tag 与 Redux 引用；
4. 运行受影响测试和缓存一致性验收。

退出门禁：`@reduxjs/toolkit`、`react-redux`、Redux Provider、`redux-store.ts` 与旧 `server-state.ts` 全部删除；架构测试证明无双入口。该门禁必须在 Canvas 功能开发前完成。

#### M4：表单与本地 UI 状态收敛

- 新建或重构的业务表单使用 React Hook Form + Zod；服务端 field error 映射回表单。
- 只有确有跨组件瞬时共享需求时建立 feature-scoped Zustand store。
- 清点 URL、React local state、Form、Query 与 Zustand，删除重复 owner。

退出门禁：无 Zustand 服务端实体缓存、无全局表单 store、关键表单错误/冲突测试通过。

#### M5：建立 `ai`、`canvas` 与统一 Revision 最小闭环

- 从一个真实 AI 流建立 `@lanverse/ai`，完成 SSE 终态对账。
- 从最小 Node Catalog → Draft → Revision → Validate → Run 建立 `@lanverse/canvas`。
- 验证 Guided 与 Canvas 使用同一 Authoring Draft/Revision；先单人闭环，不提前引入多人基础设施。

退出门禁：运行必绑 Revision，Backend 是唯一验证/执行方，Guided/Canvas E2E 通过。

#### M6：建立 `apps/collab`

- 在单人 Canvas 闭环稳定后接入 Hocuspocus、Yjs Awareness、短期房间授权和 snapshot commit。
- 完成两客户端收敛、重连、epoch 冲突、权限撤销和容量/性能测试。

退出门禁：PostgreSQL 事实可独立重建协作房间；Yjs update log 不被当作业务 Revision；故障不产生静默覆盖。

## 13. 风险与后续事实来源

当前主要风险：

- 在目录迁移中同时重写所有数据访问，导致无法区分结构问题与业务回归；
- 为了“兼容”让 RTK Query、TanStack Query、Zustand 和 Yjs 同时保存同一实体；
- 将 Hocuspocus 误当业务 Backend，绕过 RBAC、Graph Validation 和 Revision；
- 前端写死 Node 类型、模型能力或权限，逐渐形成 Backend contract 的分叉；
- 直接执行 mutable Draft，使运行无法追溯或恢复；
- Canvas/AI 大依赖进入普通页面首包；
- UI 将网络断开或 Provider 未知结果误报为成功。

后续若改变 package 边界、Authoring schema、Yjs/PostgreSQL 事实边界、路由主键、状态所有权或 RTK 退出门禁，应先更新本文件或新增 Design 决策记录，再实施代码。页面和 Feature 级功能以 [前端功能模块设计](1002-前端功能模块设计.md) 为事实来源；当 Canvas 某一独立问题需要实施时再创建对应专题设计，不预建空目录。
