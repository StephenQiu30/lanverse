## 结论

Lanverse 前端继续使用当前 `frontend/` 中的单个 npm + Next.js App Router 应用，不为 StoryGraph MVP 迁移 pnpm/Turborepo，也不预建 `apps/web`、`apps/collab`、共享 package 或可写 Canvas。首个图形能力只交付单人、只读的 Story Lens；Workflow Lens 保持为另一份查询契约和视觉投影，不能与 StoryGraph 共用万能 Graph DTO、Node ID 或事实缓存。

两种 Lens 可以复用 [`@xyflow/react`](https://github.com/xyflow/xyflow) 的视口、节点、边、MiniMap 和 Inspector 交互，以及 [`@dagrejs/dagre`](https://github.com/dagrejs/dagre) 的首屏分层布局，但不得复用业务语义。前端只通过 Backend REST/OpenAPI Query 读取 PostgreSQL/GORM 事实投影；不得直连 PostgreSQL、Temporal、Kafka、Elasticsearch、Agent 或 Provider。

服务端事实继续由现有 Redux Toolkit Query（RTK Query）单一拥有。URL 拥有可分享的 Lens 范围，React 本地状态拥有当前选择和视口，图渲染模型只是由 Query 结果确定性派生的临时 View Model。Workspace Provider Settings 与 Project Binding 使用类型化 Backend Command，是普通业务页面写入，不是 Canvas/StoryGraph 写入。MVP 不引入 TanStack Query、Zustand、Yjs、Hocuspocus、ELK 布局或前端图事实写入。

## 1. 范围与非目标

本文固定：

1. 当前单应用结构和依赖方向；
2. Story Lens 与 Workflow Lens 的事实、标识和查询边界；
3. 只读 React Flow/Dagre 适配边界；
4. URL、RTK Query、派生 View Model 和本地交互状态的唯一 Owner；
5. 有界加载、失败状态、可访问性和测试边界；
6. Workspace Provider Settings 与 Project Binding 的只写 Secret、版本化 Query/Command 和安全边界；
7. 何时才允许进入可写 Canvas 与协作设计。

本文不实现或提前设计：

- 可写 StoryGraph JSON、任意 Graph Patch 或前端 Owner Command；
- 多人协作、Yjs、Hocuspocus、Presence、评论或离线合并；
- 通用 Canvas SDK、节点插件市场、任意自定义边或图数据库；
- 前端直连 Temporal、Kafka、Elasticsearch、Agent、任意媒体 Provider 或对象存储私有地址；
- 任意 Provider URL、通用 JSON 参数编辑器、浏览器保存/回显 API Key、动态插件市场或模型通配配置；
- 为未来模块预建 monorepo、空 package、第二状态库或兼容路由；
- 一次渲染整个项目的无限画布。

类型化 Domain Intent 只有在 `SG-I32` 的只读 Lens 真实通过后，才能由 `SG-I33` 另立设计并实施；协作能力必须再单独证明业务需要，不能夹带在首版 Canvas 中。

## 3. 应用结构与依赖方向

只有 Provider Settings 与首个真实 Story Lens 的对应任务允许按实际消费者增加以下职责，名称可在实现时按现有代码风格微调，但不得先创建空目录：

```text
frontend/
├── src/
│   ├── api/                         # Backend OpenAPI 生成契约
│   ├── app/
│   │   └── projects/[projectId]/
│   │       ├── storygraph/          # 只读 Lens 路由
│   │       └── provider-settings/   # Workspace 配置入口与项目 Binding
│   ├── components/
│   │   └── storygraph/              # 首个真实 Lens 组件
│   └── lib/
│       ├── server-state.ts           # 唯一 RTK Query endpoint owner
│       └── storygraph-view-model.ts  # 纯派生适配；随消费者建立
└── tests/
    ├── architecture/
    ├── unit/
    └── e2e/
```

依赖只能单向流动：

```text
Route
  → StoryGraph Feature/View
    → 纯 View Model Adapter
      → RTK Query endpoint
        → OpenAPI 生成 client/type
          → Backend /api/v1

Provider Settings Route/View
  → RTK Query media-provider endpoints
    → OpenAPI generated client/type
      → Backend /api/v1 media-provider Commands/Queries
```

约束如下：

1. 路由解析 Project 与 URL 查询参数，不保存业务事实；
2. View 只渲染 Query 状态并发出选择、缩放、重试等只读意图；
3. View Model Adapter 只把一种 Backend Lens DTO 映射成 React Flow Node/Edge，不校验或创造业务关系；
4. `server-state.ts` 是服务端查询的唯一缓存入口；业务组件不直接拼接 `/api/v1`；
5. OpenAPI 生成类型是传输契约，组件不得再声明可漂移的 StoryGraph/Workflow DTO；
6. 布局库、React Flow 或页面都不能成为 Node/Edge 类型矩阵的事实来源；
7. Story Lens 不导入 Workflow 执行分支，Workflow Lens 不导入 StoryGraph Owner 语义。

若单文件 `server-state.ts` 因真实 endpoint 数量产生维护问题，可在当时按业务域拆出 endpoint injection 文件；首版不为此预建 SDK package 或通用 Repository。

## 4. 两种 Lens 的严格边界

| 维度 | Story Lens | Workflow Lens |
|---|---|---|
| 用户问题 | 故事与生产内容是什么、来自哪里、会影响什么 | 工作如何编排、运行到哪里、为何等待或失败 |
| 事实来源 | `StoryGraphVersion` 及 Backend StoryGraph Query | `WorkflowDefinitionVersion`、Run/NodeRun 及 Backend Workflow Projection |
| 节点标识 | `story_node_key` | `workflow_node_key`/正式 Workflow Node ID |
| 版本标识 | `story_graph_version_id + content_hash` | `workflow_definition_version_id`、`workflow_run_id` |
| 典型节点 | Episode、Scene、Beat、Claim、Occurrence、Shot、Binding、AssetVersion | Trigger、Activity、Human Gate、Branch、Workflow Node Run |
| 典型边 | StoryGraph 类型矩阵中的权威边或明确的 Claim 展示投影 | 编排依赖、端口连接、运行状态传播 |
| 允许动作 | 浏览、筛选、选择、查看 Owner/Evidence、Diff、上下游影响 | 浏览定义/运行、选择节点、查看输入输出/失败/等待状态 |
| MVP 写入 | 无 | 无；已有独立 Workflow 命令不通过 Lens 伪装成图写入 |

禁止建立 `UniversalGraphNode`、`GraphEntity` 或同时承载两类 ID 的通用业务 DTO。可以共享的只有无业务语义的展示 primitive，例如 viewport controls、空态、loading、MiniMap 容器和 Inspector shell；两个 Adapter、Query key 和 Node renderer registry 必须分开。

页面切换 Lens 时必须重新以目标 Lens 的 Query 身份取数。前端不得通过字段猜测把 Story Node 转换为 Workflow Node，也不能根据某个 Shot 的状态推导 NodeRun 成功。

## 5. Story Lens 分层加载

首版沿用 `0010` 的五种范围，不允许整项目无限展开：

| Lens | 默认范围 | 主要内容 |
|---|---|---|
| `outline` | Project 或一集 | Project → Episode → Scene |
| `narrative` | 一集或一个 Scene | Scene → Beat/Dialogue → Shot |
| `entity` | 单一 Character/Location/Prop | Specification、State、Occurrence、Claim |
| `production` | 一个 Scene 或 Shot | Shot → Binding → AssetVersion/Artifact |
| `impact` | 单一 `story_node_key` | 有界上游 Evidence 与下游影响闭包 |

默认入口只读取当前 StoryGraphVersion 的一集 Outline。继续展开必须产生新的有界 Query，Backend 返回明确 `scope`、`truncated` 和继续请求所需的稳定游标或范围；前端不得把多个响应无界合并成一个长期全项目缓存。

StoryGraph Query 返回的节点和边必须已经通过 Backend 类型矩阵、Owner Ref、Evidence、DAG 和权限过滤。前端只做展示层校验：未知 renderer 使用安全的“未知类型”卡片并保留稳定标识，不能丢弃节点、补造边或把响应视为可发布输入。

## 6. Query 与状态所有权

### 6.1 Query 身份

Requirement 阶段再冻结 HTTP 路径和字段；Design 固定以下身份维度：

```text
StoryLensQueryKey =
  projectId
  + storyGraphVersionId | current
  + lens
  + scopeKind
  + scopeId
  + direction/depth/cursor（仅适用时）

WorkflowLensQueryKey =
  projectId
  + workflowDefinitionVersionId | workflowRunId
  + projection
  + scope/cursor（仅适用时）
```

以下内容不得进入 Query key：显示语言、颜色、节点坐标、viewport、hover、完整对象 JSON、组件实例或本地选区。`current` 只是显式 Query 语义；响应必须返回实际不可变 Version ID/Hash，Diff 或详情随后绑定该精确版本，不能在长操作中反复读取漂移的“当前版本”。

### 6.2 状态 Owner

| 状态 | 唯一 Owner | 生命周期 |
|---|---|---|
| StoryGraph/Workflow 服务端投影 | RTK Query cache | 可丢弃并从 Backend 重建 |
| Lens、scope、version、稳定筛选 | URL query | 可分享、刷新后恢复 |
| 当前选中节点 | URL `focus`（需要深链时）或 React 本地状态 | 不复制节点对象 |
| React Flow nodes/edges | `useMemo` 等纯派生 View Model | Query 或 Lens 变化即重建 |
| viewport、hover、临时展开 | React/React Flow 本地状态 | 页面会话内 |
| Dagre 坐标 | 派生布局结果 | 不写 Backend、不进入 StoryGraph Hash |

不得把 Query 响应复制进 Redux slice、Context、浏览器数据库或第二 Query cache；不得把 React Flow `nodes[]/edges[]` 当作服务端事实回传。首版没有跨页面 Canvas 编辑状态，因此不引入 Zustand/Yjs。

### 6.3 Backend-only 集成

- 浏览器只调用 Backend；Backend 再读取 PostgreSQL/GORM Catalog、Temporal 投影或 Elasticsearch Search Projection；
- Search 页面只能消费 Backend `SearchScripts/SearchStoryGraph`，不得直连 Elasticsearch；
- 运行日志只能消费 Backend 授权后的查询或 Observability 链接，不能直连 Kafka/ELK 管理端；
- Kafka 事件只负责后端投影与异步解耦，不成为浏览器通知总线；
- SSE 若后续用于运行增量，只触发精确 RTK Query 更新/失效，不能成为第二事实源。

### 6.4 Provider Settings 状态与 Secret

- Catalog Query 只返回 Backend 已注册 Factory 对应的 `preset_key/version`、显示信息、受控字段和能力，不返回动态执行代码；
- Connection/Credential/ModelProfile/Project Binding 都以精确 version/revision/hash 查询和 Command，轮换产生新版本，不在前端原位改写；
- API Key 只存在于当前表单内存和一次 TLS Request，成功后立即清空；RTK Query cache、URL、localStorage、日志、telemetry、错误详情和 DOM 回显均不得保存；
- 缺少 root key、连接未验证、Profile/Binding 漂移、额度不足和 Provider outcome unknown 必须是不同状态；零配置是合法 empty state，不是全站错误；
- 前端只能选择内置火山、OpenAI、Google 连接预设及其受控 Model Profile，不允许输入任意 Host/URL 或通过自定义参数绕过 Backend capability 校验。

## 7. React Flow 与 Dagre 适配

`SG-I32` 随首个真实消费者安装并锁定 `@xyflow/react` 与 `@dagrejs/dagre`，同时更新 npm lockfile、许可证清单和真实构建。首版配置必须满足：

- node 不可拖动、不可连接、不可删除；不显示新增节点或保存按钮；
- edge 不可重连；Handle 只表达关系方向；
- 允许 pan、zoom、fit view、MiniMap、节点选择和 Inspector；
- Dagre 只根据稳定排序后的当前有界子图计算初始坐标；布局失败退化为可读列表，不伪造空图或成功；
- React Flow Node ID 使用对应 Lens 的稳定 Node Key，不使用数组下标或显示名称；
- Story Claim 的便于阅读连线必须标记为 semantic projection，与权威 Edge 可区分；
- Owner Ref、Evidence Ref、version/hash、截断状态和 Query trace id 可在 Inspector 反查；
- React Flow/Dagre 输入输出不进入 Backend Command、Canonical Hash 或 StoryGraph Version。

首版不引入 ELK Layout。只有 Dagre 在真实有界 fixture 上不能满足已记录的端口、嵌套或性能需求时，才能另做选型；日志系统中的 ELK 指 Elasticsearch/Logstash/Kibana，与图布局库无关。

## 8. 页面与交互状态

首个路由使用当前路由体系下唯一入口：

```text
/projects/:projectId/storygraph
  ?lens=outline|narrative|entity|production|impact
  &version=current|:storyGraphVersionId
  &scopeKind=project|episode|scene|entity|shot|node
  &scopeId=:stableId
  &focus=:storyNodeKey
```

无效或越权参数由 Backend/路由错误边界拒绝，不能回落到另一个项目或当前用户最后浏览对象。Workflow Lens 只有在对应 Query/页面任务被计划时建立独立入口；不得先创建空页面或把 `lens=workflow` 塞入 StoryGraph DTO。

每个只读 Lens 必须实现：

1. loading skeleton；
2. 合法 empty state；
3. 401/403/404；
4. 409 或 current head 漂移后的显式刷新；
5. 422 参数错误；
6. Backend/依赖不可用与安全重试；
7. `truncated=true` 的范围提示和继续加载入口；
8. 未知节点 renderer 的可诊断降级；
9. 键盘选择、焦点可见、列表替代视图和 reduced-motion 支持。

网络错误、空图、无权限与“当前版本尚未编译”必须是不同状态。前端不能用 fixture、缓存旧图或 Storyboard 列表拼图来模拟成功。

## 9. 性能与安全边界

- Backend 必须有界返回，前端不下载完整项目后再筛选；
- React Flow 仅在 StoryGraph 路由动态加载，不进入登录、项目列表或 Guided 页首包；
- 节点详情按已返回数据展示，重型 Artifact 预览另行按权限和需要加载；
- 相同 Query 响应与稳定排序必须产生相同 View Model 和 Dagre 初始布局；
- Node label、剧本文本、Evidence 摘要和 Provider 输出按普通文本渲染，不执行 HTML；
- 不在 URL、日志、前端错误或 telemetry 中记录 Access Token、完整原稿、Prompt、私有对象地址或 Provider 凭据；
- 前端只展示 Backend 返回的安全错误和 trace id，不展示内部栈或 Elasticsearch 查询 DSL。

首版性能验收以真实有界 fixture 为准：Episode/Scene 范围覆盖小、中、大三档；记录节点/边数量、响应大小、首图可交互时间和交互长任务。没有真实测量前不承诺全项目 1000 节点画布，也不预建虚拟化/Worker 抽象。

## 10. 验证设计

所有前端测试只能位于 `frontend/tests`：

| 层级 | 必须证明 |
|---|---|
| Architecture | 新 Lens 与 Provider Settings 只经 OpenAPI + RTK Query；无直接 Backend URL、Temporal/Kafka/Elasticsearch/Provider 依赖；源码目录无测试文件 |
| Contract | Story 与 Workflow DTO/ID 不混用；Query key 完整；截断、未知类型、版本/hash 和错误 envelope 可判别 |
| Unit | 稳定排序、两个独立 Adapter、Dagre 输入、Claim projection 标记、URL 解析和无写入控制 |
| Component | loading/empty/error/forbidden/stale/truncated、Inspector、列表替代视图与只读 React Flow 配置 |
| Security | API Key 只写不读、提交后清空，不进入 URL/cache/storage/log；任意 Provider URL 和未知 Preset 均无可提交入口 |
| E2E | 从真实项目进入一集/Scene Lens，切换范围、深链节点、Diff/影响闭包，刷新后仍反查同一精确版本 |
| Build | npm install/lockfile、lint、typecheck、unit、build 和当前真实 CI 全部通过 |

必须包含负向验收：页面不存在保存/新增/连线入口；DOM 交互不能改变 Backend；修改 URL 不得跨 Project 读取；断网不能显示旧图为新版本成功；Story Node ID 不能用于 Workflow Query；Browser bundle 不含服务端凭据或基础设施 client。

`agent-browser` 不在此 Design 或编码中提前运行。只有 `SG-I34` 完成全部实现、真实 CI 和非浏览器证据并独立提交后，才在 `SG-I35` 使用 `agent-browser` 验收完整 Web Journey。

## 11. 实施门禁

本设计只接受 SG-D14 架构边界及 2026-08-29 的 Provider Settings 同步，不声明 Provider 页面、StoryGraph API、React Flow 页面或 Workflow Lens 已实现。`SG-D15`/`SG-D16` 已完成相同变更同步；仍须按 `SG-D17`–`SG-D21` 顺序重新接受 PRD/Requirement/Plan/Acceptance，才按 `0010` 唯一 `SG-Ixx` 队列编码。

实现时继续遵守：

1. 一个完整小任务完成、局部验证和当前全量 CI 都通过后才提交；
2. 不用兼容路由、静态成功数据、跳过测试或降级检查冒充 CI 通过；
3. React Flow/Dagre 依赖只随 `SG-I32` 的真实页面与测试加入；
4. 可写 Canvas 只在只读 Lens 通过后实施，协作能力另立 Design；
5. 任何 Query/DTO/Owner 变化先更新事实来源和 Requirement，再编码。

## 12. 风险与事实来源

主要风险：

- 把 StoryGraph 和 Workflow Projection 合成万能图模型；
- 同一响应同时保存在 RTK Query、Redux slice 和 React Flow state；
- 一次读取完整项目造成不可控响应和渲染成本；
- 前端根据名称或数组下标创建不稳定 Node ID；
- 使用 Storyboard 页面或 fixture 伪造 Story Lens；
- 在 Backend Contract 之前预建可写 Canvas 或协作服务；
- 浏览器绕过 Backend 直连 Elasticsearch、Kafka 或 Temporal。
