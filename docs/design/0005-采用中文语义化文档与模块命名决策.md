# 采用中文语义化文档与模块命名决策

- 原决策编号：ADR-0002
- 状态：已接受
- 日期：2026-08-24
- 文档治理更新：2026-08-25
- 语义契约命名更新：2026-08-31
- 范围：文档、Frontend feature、Backend 模块、Agent、API 与事件

## 背景

平台概念容易混用产品入口、技术组件和领域边界，例如 Backend `studio` 来源于 UI 概念，`canvas` 只描述一种编辑方式，`model` 只描述实现资源，`app` 与 `event` 不能说明职责。文档文件名需要直接说明用途，以减少查找和评审成本。

文档采用中文语义化命名，并基于目标设计细化模块功能。在任何代码创建前同时确定文档名称和唯一领域语言，避免通过兼容别名形成两套模型。

## 决策

1. `docs/` 下的业务 Markdown 文件使用四位服务段编号与中文语义主题命名；去除后会改变含义的技术专有名词可以保留，`README.md` 作为目录入口例外。来源版本写在正文元数据和导航中。
2. Backend 规范业务模块为 `access/production/preset/authoring/workflow/review/generation/agent/asset/media/cost/quota/eventing/search`。
3. `bootstrap` 只负责 Binary 装配；`config/database/cache/telemetry` 保持设计基线中的独立基础设施 package，只做逻辑上的 Platform Runtime 归类，不合并为新物理模块。
4. Guided 与 Canvas 是产品入口，统一事实名称为 `AuthoringDraft/AuthoringRevision`。
5. `model-gateway` 运行单元名称保持不变，内部业务模块使用 `generation`；它管理 Generation Capability、Provider Job 和 Candidate，而不是 Access Capability 或抽象的“模型”。
6. Frontend 共享 package 保留设计基线已接受的 `ui/ai/canvas/sdk/auth`，业务 feature 使用 `guided-production`、`authoring-canvas`、`review-workbench` 等任务名称。
7. Command 使用祈使动词；Query 使用 Get/List/Search/Suggest/Resolve/Diff/Validate/Explain 等无副作用动词；Event 使用 `<context>.<aggregate>.<past-tense>`，不得附加数字版本段。
8. 设计基线中的物理目标名按语义作一对一细化：`app → bootstrap`、`studio → production`、Backend `canvas → authoring`、Backend `model → generation`、`event → eventing`；这些改名不删除能力、不改变运行单元数量。
9. `cost` 与 `quota` 保持两个事实 Owner：Cost 管金额/预算/账本，Quota 管限额策略/用量窗口；高成本授权由 Application 用例协调两者。
10. 仓库只保留 `prd/design/requirement/plan/acceptance` 五类目录；架构与决策记录归入 `design/`，不建立复数同义目录或其他平行事实来源。
11. 项目自有的 API 路径、OpenAPI 文件、Event、Kafka Topic/Consumer Group、Temporal Task Queue、Elasticsearch 索引/别名、日志 Schema、Agent 协议、文件、类型和内容哈希 Domain Separator 必须按业务职责或处理阶段命名，禁止使用 `v` 加序号表达发布先后。
12. 已接受契约需要改变时，先为改变后的职责选择精确语义名，再一次性切换项目内生产者、消费者、测试和配置；不保留数字版本别名、双写、双读或仅转发的兼容入口。

完整词汇、映射与禁用名称见 [领域语言与模块命名规范](0006-领域语言与模块命名规范.md)。

## 实施约束

- 本决策直接约束从零创建的文档、API、表、事件、生成 SDK 和模块边界。
- 名称一旦进入已发布契约，后续变更必须通过新的语义职责名、调用方原子切换和旧入口删除门禁完成；不使用数字版本命名建立兼容层。
- 不创建 `studio` 与 `production`、`canvas` 与 `authoring`、`model` 与 `generation` 两套目标 package；`cost` 与 `quota` 不得合并事实表或状态机。
- 研究材料中的其他名称只允许出现在术语来源说明中，不能进入正式契约。
- `StoryGraphVersion`、`WorkflowDefinitionVersion`、`version_id` 等名称表达不可变业务版本事实，不属于数字发布后缀，继续保留。
- 第三方 SDK 固有 import 路径、外部 Provider API 路径和厂商正式产品/模型名按上游契约原样使用；不得据此为 Lanverse 自有契约引入数字版本命名。

## 结果

收益是文件用途、服务归属、领域边界、运行职责和 UI 入口都能被直接识别，并可形成明确架构测试规则。代价是所有新术语都必须先完成领域评审；实现必须以本 Design 决策的语义映射作为事实来源。
