## 1. 设计结论

Lanverse MVP 的核心不再定义为“把剧本转成一张可导出分镜表”，也不以计费、配额、多 Provider 广度为首要产品价值。新 MVP 要证明：

> 创作者可以把一份完整剧本，经过少数几个清晰审核点，转成一套来源可追溯、身份不重复、人物多形象与道具交互不混淆、风格统一、可局部修改且可直接进入分镜的视觉生产包。

产品对用户呈现一条 Guided Studio 主流程：

```text
上传并固定剧本
→ 选择世界观/视觉基底预设
→ 审核剧本结构与身份
→ 审核人物多形象、地点、道具、交互与连续性
→ 确认视觉基底与生成范围
→ 生成并选择人物/地点/道具基础参考
→ 生成并选择场景/人物—道具组合参考
→ 分镜精确消费已接受版本
```

MVP 最终交付给用户的“视觉生产包”是只读聚合 View，不新建第二个业务事实 Owner：

```text
Visual Production Package View
= confirmed Script/Scene/Beat
+ ProductionBibleVersion
+ Character/Location/Prop Specification + AssetState
+ Occurrence + Interaction + Continuity
+ EffectiveStyleSnapshot
+ ApprovedReferencePlanVersion
+ published AssetVersion
+ SceneReferenceBindingVersion
+ InteractionReferenceBindingVersion
+ readiness / coverage report
```

## 2. 当前事实、公开参考与设计推断

### 2.1 仓库当前事实

- 已接受 Design 已要求稳定身份、剧情形象、渲染画风和视觉结果四轴分离，并要求分镜绑定精确 `AssetVersion`。
- 已接受基线已定义 `Preset = Style + Skills + Model/QC/Motion/Render Policy`，但当前实现只剩 `Project.visual_style` 可变字符串。
- 当前 `EffectiveStyleSnapshot` 由 Storyboard Adapter 从 Project ID/revision、`visual_style` 和 `aspect_ratio` 临时计算，仓库没有真实 `preset` Domain/Owner 与可重读不可变快照。
- 当前剧本流程在 Scene 深度分析前先确认 Bible；Scene 阶段新发现的换装、伤势、伪装和道具状态不能安全回流。
- 当前 `Occurrence` 只能表达一个身份/状态在某场出现，没有人物—道具交互、握持、传递、使用和持有账本。
- 当前 Reference Builder 只生成角色 `front/profile/back` 固定三栏 Prompt，地点、道具、Scene Composition 与 Interaction Composition 尚未形成真实产品闭环。
- 当前参考资产计划位于 Storyboard Intent 之后，而新产品需要在剧本拆解完成后、Storyboard 之前形成视觉基础。

### 2.2 LibTV 公开参考

LibTV 公开产品页和 Skill Hub 证明了一个有价值的产品心智：用户选择一张风格/导演 Skill 卡，Agent 继续完成剧本、角色、世界观和媒体创作。其公开 `libtv-skills` 仓库只提供上传、自然语言会话、轮询和下载薄客户端；身份、多形象、道具状态、连续性和资产版本结构没有公开。

因此 Lanverse 只吸收：

- 风格预设卡与能力分类的用户体验；
- 对话式补齐需求与几个关键确认点；
- 先生成候选方向、再选定视觉锚点、然后向下游展开的制作方式；
- 任务异步执行、进度可见、结果回收和画布组织经验。

Lanverse 不吸收：

- 用自然语言会话代替正式剧本/资产 Schema；
- 让远端黑盒 Agent 决定人物合并、换装、道具归属和连续性；
- 以消息中出现 URL 作为正式生产完成条件；
- 直接复制未授权的社区 Skill Prompt、艺术家/IP 风格名称或案例素材。

### 2.3 本设计的产品推断

- 产品 UI 可以将一个 `PresetVersion` 表现为“导演 Skill/世界观预设卡”，但内部不为每种风格复制剧本解析 Skill。
- 剧本事实抽取必须 style-blind；预设只能在事实 Gate 后补齐视觉设计空白或提出显式世界改编。
- 运行时的单一输入应是可哈希、可重读的 `EffectiveStyleSnapshot`，而不是 Prompt 前缀或当前 Project 字符串。
- 视觉生成必须先发布可复用的单资产版本，再生成精确的 Scene/Interaction 组合结果，避免人物×道具×场景笛卡尔积。

## 3. 产品定位与目标用户

### 3.1 产品定位

Lanverse 是“可审核的 AI 视觉制片工作台”，不是一次对话生成器。它在剧本和分镜之间建立一个可查询、可修订、可版本化的视觉世界。

### 3.2 目标用户与核心任务

| 用户角色 | 核心任务 | 期望结果 |
|---|---|---|
| 创作者 / 制片人 | 把一份完整剧本转换成可制作项目 | 看清整体进度、阻断、视觉准备度和下一个决策 |
| 剧本统筹 / 连续性负责人 | 校对场界、别名、多形象、道具持有与状态变化 | 所有正式事实有 Evidence 或明确的创作者决定 |
| 美术指导 / 资产管理者 | 选择视觉基底、完善设计空白并选择参考资产 | 人物、场景、道具及组合图在同一视觉系统内保持一致 |
| 导演 / 分镜师 | 使用精确视觉版本进行镜头设计 | 无需重新猜测人物造型、道具状态和场景连续性 |

MVP 不新建多套权限角色；同一 Workspace 成员可以同时承担上述多个产品角色。

## 4. 北极星指标与 MVP 成功标准

### 4.1 北极星指标

```text
Production-ready Scene Coverage
= 已通过审核，且拥有完整 Scene/Beat、
  Character/Location/Prop Occurrence、精确 AssetState、
  必需 Interaction、已选参考版本和连续性边界的场景数
  ÷ 已确认场景总数
```

这一指标衡量的是“多少剧本已真正可继续制作”，而不是模型调用次数、生成图数量或 Provider 成功率。

配套效率指标：

- `Time to First Production-ready Scene`；
- `Time to Approved Visual Production Package`。

两个时间指标在首批真实内测后建立基线，Design 阶段不虚构分钟数目标。

### 4.2 发布级成功标准

- 已确认 ScriptBlock/Scene 的结构覆盖率为 `100%`；
- 无 Evidence 且无明确创作者决定的正式事实数为 `0`；
- 受影响下游中 `unresolved` 或 stale 绑定数为 `0`；
- 一个故事身份被静默物化为多个 Character Asset 的数量为 `0`；
- 所有实际使用人物形象的 `front/profile/back` 覆盖率为 `100%`；
- 剧情关键地点、道具和用户明确需要的组合参考覆盖率为 `100%`；
- 未经人工选择发布正式 `AssetVersion`/组合 Binding 的数量为 `0`；
- Storyboard 使用当前指针、自由文本或未批准视觉资产的数量为 `0`；
- 幂等重放、恢复或局部修复新增重复 Owner 事实/覆盖已发布 Artifact 的数量为 `0`。

## 5. MVP 产品范围

### 5.1 MVP 内

- Markdown/DOCX 完整剧本上传、预览、格式体检和不可变 Revision；
- Episode/Scene 完整覆盖，包含 Dialogue、Beat、Mention 和绝对来源坐标；
- Character/Location/Prop 唯一身份、别名、merge/split 与安全 `unresolved`；
- 同一人物的多个完整 `AssetState`，包含服装、发型、妆容、伤势、污损、年龄/形态变化及有效范围；
- Location Specification/State，包含布局、出入口、区域、材质、时间、天气、照明、布景和损坏；
- Prop Specification/State，包含形制、尺度、材质、标记、可动部件、内容物、开闭和损坏；
- Scene/Beat 级 `Occurrence`；
- MVP 人物—道具交互：`hold/carry/wear/use/give/receive/place/drop/open/break`；
- 人物形象、地点、道具持有和道具状态的跨场连续性；
- 版本化 `PresetVersion`、结构化 `EffectiveStyleSnapshot`、项目级 typed overrides 和风格参考权利来源；
- 每个实际使用人物形象的三视图，地点板、道具板、必要的 Scene Composition 和 Character–Prop Interaction Composition；
- 单候选结构/QC、独立多模态审查建议、人工选择、不可变发布和新版本替换；
- Storyboard Intent/Detail 对精确 AssetVersion 和组合 Binding 的消费；
- 局部失效、影响预览、局部重跑、节点恢复和幂等 Owner Apply。

### 5.2 非目标

- 支付、计费产品、复杂预算优化、多 Provider 自动比价/路由；
- 完整视频、配音、字幕、剪辑、渲染、发布和成片管线；
- 无人值守自动接受身份、形象、场景、道具或生成图；
- 服装×伤势×年龄×形态的组合状态规则引擎；
- 复杂多人战斗站位、高级轴线/视线规则、通用表情/动作库、3D Rig 和骨骼姿态系统；
- 多人实时协作 Canvas 和可自由修改正式事实的通用图编辑器；
- 动态 Skill 市场、运行时安装外部 Skill 和通用 Agent 平台；
- 为没有剧本使用、用户请求或连续性风险的全库资产预生成参考图。

MVP 仍可保留一条实际可用的图片 Provider 执行路径以验证视觉闭环，但 Provider 广度、价格和计费不得成为产品主路。

## 6. 用户信息架构

MVP 以 Guided Studio 为主产品，不要求用户进入 Canvas 理解 Owner DAG 或 Stage DAG。

| 产品区域 | 用户要完成的任务 | 主要内容 |
|---|---|---|
| 项目总览 | 知道项目处于哪一步、还有什么阻断 | 五段进度、可生产场景覆盖率、待审数、stale 数、下一步主操作 |
| 剧本与结构 | 确认 Episode/Scene 边界和原文覆盖 | 原文、场次列表、Dialogue/Beat、疑似漏拆/错拆、Evidence |
| 制作圣经 | 确认人物/地点/道具身份、多形象、交互与连续性 | Identity、Specification、State 时间线、Occurrence、Interaction、Continuity Ledger |
| 视觉基底 | 选择预设、解决世界冲突、批准设计补全 | Preset 预览、参考来源、world/style 约束、typed overrides、Design Gap |
| 参考资产工作台 | 看覆盖、生成、比较、选择、拒绝或重生成 | Coverage Matrix、候选比较、QC、Lineage、版本、影响范围 |
| 分镜工作台 | 在精确视觉基础上审核 Shot | Shot Intent/Detail、连续性边界、精确 AssetVersion/Binding |
| 问题与影响抽屉 | 理解为什么阻断以及修改什么会影响哪里 | 来源、系统提案、备选项、影响闭包、批准后行为、历史决议 |

## 7. 完整用户旅程

| 步骤 | 系统行为 | 用户决策 | 正式输出 / 阻断 |
|---|---|---|---|
| 1. 创建项目 | 创建 Project，展示策展预设卡及能力覆盖 | 选择一个 PresetVersion，选择“保真”或“世界改编”，可添加有权利的参考图 | 只冻结 Preset Selection；不生成剧本事实 |
| 2. 固定原稿 | 解析 Markdown/DOCX、格式体检、保存不可变 Revision | 确认预览与版本 | 不可解析、原文为空或版本改变则阻断 |
| 3. 拆解剧本 | style-blind 地提取 SceneSpan、Dialogue、Beat、Mention、状态线索和交互事实 | 检查漏拆/错拆和来源覆盖 | 未覆盖原文、交叉场界、疑似漏拆保持待审 |
| 4. 统一身份 | 全局归并 Character/Location/Prop mention，给出 merge/split/alias 候选 | 确认身份、别名、同名拆分和未决项 | `unresolved` 只阻塞影响范围，不伪造正式 ID |
| 5. 构建生产世界 | 生成 typed Specification、完整 State 时间线、Occurrence、Interaction 和 Continuity Ledger | 确认多形象边界、道具状态、持有/使用与状态转换 | 无 Evidence 内容显示为 Design Gap；冲突和无法判定项阻塞相关下游 |
| 6. 确认视觉基底 | 用已确认 World Rules 解析 Preset + typed overrides，发现冲突并提案设计补全 | 处理世界冲突，接受/编辑/拒绝 creative fill | 发布不可变 EffectiveStyleSnapshot；未决冲突阻塞受影响视觉目标 |
| 7. 确认参考范围 | 建立用途覆盖矩阵和去重需求，避免资产笛卡尔积 | 确认必生成/可选/不生成、用户指定的 Scene/Interaction | ApprovedReferencePlanVersion；`mentioned_only` 默认不生成 |
| 8. 生成基础参考 | 先生成 Character anchor/variant、Location Board、Prop Sheet，独立完成结构与多模态 QC | 对比候选，接受、拒绝、编辑 Brief 或局部重生成 | 只有人工选择才发布 AssetVersion；旧 Candidate 不覆盖 |
| 9. 生成组合参考 | 消费精确 Character/Location/Prop AssetVersion 和 Interaction 生成 Scene/Interaction Composition | 选择必需组合版本 | 发布 SceneReferenceBindingVersion / InteractionReferenceBindingVersion；组合失败不废弃基础资产 |
| 10. 进入分镜 | 为可生产 Scene 编译精确 Production Packet，生成 Storyboard Intent/Detail | 审核镜头目的、动作、声画、连续性与视觉绑定 | 必需绑定 unresolved/stale/未选时不得标记 production-ready |

## 8. 用户侧五个决策 Gate

Backend 可以拥有更细的 Stage 和确定性门禁，但 UI 只向用户呈现五个稳定的决策时刻，不暴露内部 Stage 名称。

| Gate | 用户看到什么 | 用户能做什么 | 通过条件 |
|---|---|---|---|
| 1. Structure & Identity | Scene 覆盖、边界风险、原始 mention 聚类、同名/别名 | split/merge Scene，merge/split Identity，重绑 mention，保留 unresolved | 必需原文已覆盖，需制作身份无未决议题 |
| 2. Bible & Continuity | Specification、State 时间线、Occurrence、Interaction、持有账本、前后状态 | 调整 State 边界/快照，重绑 Occurrence，修改 Interaction，补充有审计的创作者决定 | 所有必需出现有精确 State，连续性 blocker 已裁决 |
| 3. Visual Foundation & Scope | 预设卡、世界冲突、Design Gap、设计备选、参考覆盖矩阵 | 切换预设，选 faithful/adaptation，编辑 typed override，接受设计补全，勾选生成范围 | EffectiveStyleSnapshot 和 ApprovedReferencePlanVersion 已发布，受影响冲突为 `0` |
| 4. Reference Selection | 候选图、精确输入、结构 QC、多模态建议、权利/谱系、依赖图 | accept/reject/regenerate，修改 Brief，对比历史版本，预览替换影响 | 必需资产均有唯一已选 READY 版本，组合绑定完整 |
| 5. Storyboard | Shot Intent/Detail、来源覆盖、连续性 in/out、精确资产/组合版本 | 逐项决议，调整镜头或退回受影响上游 | required coverage 完整，无非法/过期视觉绑定 |

每个 Gate 的任务行必须同时呈现：

- 原文/Evidence 或用户设计来源；
- 系统提案及其置信度；
- 替代选项和“保持未决”；
- 本决定会使哪些形象、参考图或分镜失效；
- 批准后会创建什么正式版本或触发什么任务。

## 9. 剧本拆解产品模型

### 9.1 信息依赖顺序

```text
DocumentRevision / SourceSpanIndex
→ EpisodeSpan / SceneSpan
→ SceneFactCandidate
   (Dialogue / Beat / Mention / visual assertion / state clue / interaction)
→ global Identity reconciliation
→ typed Specification + State timeline + story Claims
→ Scene semantic binding
→ Occurrence + Interaction
→ Continuity Ledger
→ confirmed production world
```

不允许先将粗粒度 Bible 锁定为全部身份/状态集合，再让 Scene 分析只能引用它。Scene 级信息必须能参与全局身份与状态调和，之后才进入 Human Gate。

### 9.2 事实与设计的来源

每个可审核字段都必须区分：

```text
source_explicit  # 原文直接支持
inferred         # 由上游事实推导，可被否决
creative_fill    # 预设/Skill 补齐的视觉设计
user_supplied    # 用户明确提供或批准
```

字段至少包含 `value`、`origin`、`evidence_refs`、`confidence`、`alternatives` 和上游断言引用。剧本没有写发色时，系统必须显示 Design Gap，不得把模型选择伪造成原文事实。

### 9.3 多形象与状态

- `CharacterSpecificationVersion` 保存稳定面部、体型、轮廓、年龄印象、永久标记和禁改锚点；
- 一个 `AssetState` 表达一个完整可生成形象，不是一组无法独立解析的差异补丁；
- 每个形象记录发型、服装层、鞋、配饰、妆容、伤势/条件、清洁/污损、轮廓、色板、有效 Scene/Beat 范围和转换原因；
- 不同服装、伤势、伪装、年龄阶段或形态不建立第二个 Character Asset；
- 瞬时表情、姿势或单镜短暂动作默认不创建 AssetState。

### 9.4 道具与人物—道具交互

- `PropState` 只表达道具自身完整/打开/损坏/内容物等状态；
- 所有者、当前持有者、画面中实际握持者必须分离；
- 持有、携带、使用、传递、接收、放置、掉落、打开、破坏等是 `Interaction`，不是 Character AssetState；
- Interaction 绑定 Actor Occurrence、Prop Occurrence、Beat 范围、手别、握法、接触点、方向、相对比例、前后 holder 和前后 PropState；
- 普通服装是 Character AssetState 的服装层；可被摘取、传递、特写或承担剧情功能的衣物作为 Prop，通过 `wear/equip` Interaction 连接。

## 10. 世界观与视觉预设产品

### 10.1 用户一次选择，内部结构化解析

UI 中的每张预设卡对应一个精确 `PresetVersion`，不对应一份重复剧本解析 Skill。

```text
PresetVersion
├─ metadata
│  ├─ key / version / content_hash
│  ├─ label / category / description
│  ├─ provenance / license
│  └─ capability_manifest
├─ world_design_basis
│  ├─ era / region / civilization language
│  ├─ technology_or_magic language
│  ├─ architecture / wardrobe / prop language
│  ├─ material system / motifs
│  └─ anachronism constraints
├─ visual_grammar
│  ├─ medium / realism / shape / proportion
│  ├─ palette / linework / texture
│  ├─ material rendering / lighting / contrast
│  └─ composition / camera / negative constraints
├─ purpose_profiles
│  ├─ character_turnaround
│  ├─ character_look_variant
│  ├─ location_board
│  ├─ prop_sheet
│  ├─ scene_composition
│  └─ interaction_composition
├─ skill_release_refs
├─ qc_policy
└─ model_capability_policy
```

### 10.2 预设卡的产品信息

用户在选择前必须看到：

- 名称、一句话特征、适合的作品类型和表现媒介；
- 人物、地点、道具与典型场景的真实示例预览；
- 它对建筑、服装、道具、材质、色彩、光照和构图的影响；
- 支持的资产能力矩阵，未支持项不得静默回退；
- 默认应用模式：保真或世界改编；
- 参考资产、模型和示例的来源/权利说明；
- 版本变更摘要。

### 10.3 两种应用模式

| 模式 | 产品行为 | 默认门禁 |
|---|---|---|
| `faithful` | 保留剧本世界事实，预设只填充未指定的视觉细节与表现媒介 | 任何与已确认剧本事实的冲突都阻塞受影响项 |
| `world_adaptation` | 允许把原故事语义重新表达到策展世界，例如现代通讯改编为仙侠传音 | 每个改编产生 source fact → production design 映射、语义不变量、影响范围并经 Human Gate |

MVP 不允许自由组合任意 world/style/model 组件；首批只发布 4–6 个通过全资产能力矩阵验收的策展套装，建议：

- 都市电影写实；
- 古装电影写实；
- 国漫仙侠；
- 日漫赛璐璐；
- 半写实幻想；
- 赛博朋克动画。

预设使用可描述、可组合的视觉语言命名，不依赖在世艺术家、导演或受保护 IP 姓名。

### 10.4 覆盖、切换与影响

- 剧本事实优先于用户设计决定，用户设计决定优先于 Preset 默认，Preset 默认优先于 Skill 建议；
- 基础 Asset Reference 只允许 Project/Asset 级 typed override，Shot override 不得反向改变人物身份、服装结构、道具形制或地点拓扑；
- 切换 Preset 生成新 EffectiveStyleSnapshot，保留旧版本与旧资产，不原地覆盖；
- 切换前先展示会 stale 的 Visual Brief、AssetVersion、Scene/Interaction Binding 和 Shot；
- 切换风格不重新拆解剧本，不使 Identity、Specification、AssetState、Scene 或 Interaction 失效；
- Aspect Ratio 属于输出格式策略，不属于角色身份画风，改变画幅不应使中性三视图整体失效。

## 11. 参考资产产品设计

### 11.1 参考覆盖矩阵

参考资产工作台必须先呈现“哪些生产对象已准备好”，而不是先呈现一串 Provider Job。

| 生产对象 | 必需参考 | 就绪条件 | 默认生成规则 |
|---|---|---|---|
| Character Identity + base State | 角色基础三视图 | front/profile/back 、身份锚点与服装一致、已选 AssetVersion | 所有实际使用主要/配角 |
| Character appearance State | 形象变体参考 | 绑定基础身份锚点，只改声明 diff；轮廓重大变化时 front/profile/back 完整 | 所有实际使用 State |
| Location + Location State | 地点板 | 布局、出入口、固定锚点、材质/状态一致，已选 AssetVersion | 重复使用或剧情关键地点 |
| Prop + Prop State | 道具板 | 3/4、侧/背、结构/可动部件、尺度、状态一致，已选 AssetVersion | 剧情关键、反复出现、特写或连续性高风险道具 |
| Character–Prop Interaction | 交互组合图 | 精确 Character/Prop AssetVersion，手别/握法/比例/接触正确，已选 Binding | 用户明确要求、反复使用、英雄道具、特写或穿帮风险高 |
| Scene Composition | 场景组合参考 | 精确 Location/Character/Prop AssetVersion 与 Occurrence/Interaction，已选 Binding | 用户指定、复杂调度、连续性风险高或重点场次 |

`mentioned_only` 不自动触发参考资产；系统不生成人物×形象×道具×场景的笛卡尔积，只根据剧情使用、重复程度、特写/英雄属性、连续性风险和用户选择创建需求。

### 11.2 生成顺序

```text
Character base anchor candidates
→ Human Selection
→ Character appearance variant references

Location boards + Prop sheets
→ Human Selection

exact Character/Location/Prop AssetVersion + Occurrence/Interaction
→ Scene Composition + Interaction Composition
→ Human Selection
→ Storyboard
```

基础角色锚点、地点板和道具板未选中前，不启动依赖它们的组合图。组合图生成失败只阻塞对应 Scene/Interaction，不让已接受基础 AssetVersion 失效。

### 11.3 不同用途的硬边界

| 用途 | 输出合同 | 不得出现 |
|---|---|---|
| 角色基础三视图 | 中性正面、严格侧面、背面全身，完整头脚，统一比例/身份/形象，可附面部锚点 | 剧情姿势、无关道具、场景光污染、三个不同脸 |
| 形象变体 | 绑定同一身份锚点，只改声明的服装/发型/妆容/伤势 | 无声明的脸、体型或配饰改变 |
| 地点板 | 空景，主方向、反向、入口/分区/固定锚点，必要的昼夜/天气状态 | 未要求角色、错误空间连接、镜头戏剧光覆盖规格事实 |
| 道具板 | 3/4 hero、侧/背/结构细节、状态面板、尺度与文字政策 | 手、人物、错误尺度、永久标记漂移 |
| 交互组合图 | 精确人物形象+道具状态，全身接触关系+必要手部/握点特写 | 新 Character State、改变基础身份/道具结构、无关 Scene 或 Camera |
| Scene Composition | 精确 Scene/LocationState/Occurrence/Interaction 与已选资产的联合构图参考 | 冒充 Location AssetVersion、未经确认的额外人物/道具 |

### 11.4 候选选择与质量审查

每个候选必须可对比：

- 生成目的与精确 Specification/State/Interaction/Scene 绑定；
- EffectiveStyleSnapshot 与相关 World Rule 投影；
- 使用的 Skill Bundle、Recipe、Model/Workflow 和参考资产版本；
- 确定性结构检查与独立多模态审查建议；
- 用户拒绝原因与后续重生成约束；
- Artifact Rights/Lineage/Content Digest。

Vision Reviewer 不自动发布；它产生五类结果：结构完整性、身份/状态一致性、风格合规性、跨资产一致性、交互/接触正确性。只有用户的唯一 CandidateSelection 才能发布正式视觉版本。

## 12. Agent 与 Skill 产品边界

### 12.1 固定 Skill Release

不为“都市写实”、“国漫仙侠”等风格复制整套 Skill。一个版本化 StoryGraph/Visual Production Skill Release 包含：

- `parse-script-structure`；
- `build-production-bible`；
- `map-scene-continuity`；
- `resolve-visual-foundation`；
- `design-reference-assets`；
- `review-production`；
- `direct-storyboard`。

每个 Stage 冻结 input/output schema hash、Skill bundle hash、Reference/Recipe/Rubric、`text|vision` runtime class 和允许工具。Preset 作为 Backend 冻结输入进入视觉阶段，不进入 style-blind 事实提取阶段。

### 12.2 成熟 Skill 的吸收流程

```text
来源/许可证审查
→ 拆分为参考知识、生成 Recipe、审查 Rubric 和失败案例
→ 映射 Lanverse typed schema
→ 黄金剧本/对抗样本 Eval
→ Shadow run
→ 固定 bundle hash 并发布
```

外部 Skill 不在运行时安装，不原样拼接到系统 Prompt，不获得 Backend 业务写权。LibTV 未公开的远程编排不作为 Lanverse 正式合同；未来可将 LibTV 作为一个黑盒图片 Provider Adapter，但返回结果只能进入 Candidate/QC/Human Selection。

## 13. 正式 Owner 与服务边界

| Owner | 拥有的正式事实 | 不拥有 |
|---|---|---|
| `production/script` | Document/Script Version 与规范化原文 | 身份归并、风格、生成结果 |
| `production/project` | Project/Episode 身份、顺序与生命周期 | Scene/Dialogue/Beat、Preset、生成结果 |
| `production/bible` | SpecificationVersion、项目级实体约束、World Rule、跨集 Claim、Evidence 与物化 Binding | Preset、Artifact、Shot |
| `production/planning` | Scene/Dialogue/Beat/Occurrence/Interaction/Continuity | Project/Episode 生命周期、AssetVersion、Preset、Provider Job |
| `preset` | PresetVersion、EffectiveStyleSnapshot、EffectivePolicySnapshot | 剧本事实、身份、资产状态 |
| `production/reference` | ApprovedReferencePlanVersion、SceneReferenceBindingVersion、InteractionReferenceBindingVersion | 基础 Character/Location/Prop AssetVersion、Provider Job |
| `asset` | Character/Location/Prop Asset、AssetState、Artifact、AssetVersion、Rights/Lineage | Scene/Interaction 语义、Prompt 决策 |
| `generation` | 严格 GenerationTarget、Provider Request/Job、Candidate | 视觉世界事实、Human Decision |
| `review` | Human Task、Decision 和审核历史 | 业务对象正式 Apply |
| `production/storyboard` | Shot Intent/Shot、ShotProductionBindingVersion 与镜头结果 Binding | 基础人物/地点/道具资产 |
| `production/storygraph` | 只投影 StoryGraph Schema 明确列入的已确认 Owner 事实，并拥有不可变 `StoryGraphVersion` 与线性 `StoryGraphHead` | 任何上游对象的 Writer；Schema 未列入的 Reference Plan/Binding |

不为本产品新建独立微服务；`preset` 和 `production/reference` 是现有 Go Backend 内的业务模块/聚合，继续使用单 PostgreSQL/GORM 事实源和 Temporal 全局工作流。

## 14. 产品状态、失败与恢复

### 14.1 用户可见状态

| 状态 | 用户含义 | 主操作 |
|---|---|---|
| 未开始 | 还没有正式任务 | 开始下一阶段 |
| 处理中 | 系统正在处理，可离开页面 | 查看进度或取消 |
| 待审核 | 结果完整，需要人做决策 | 进入对应 Gate |
| 有歧义 | 系统不能安全选择 | 处理受影响对象，无关范围继续 |
| 需要设计输入 | 剧本没写，需要 Preset/Skill/用户补齐 | 选择或编辑设计方案 |
| 生成失败 | 视觉生成或下载失败，上游 Brief 仍有效 | 仅重跑该目标或切换实际执行连接 |
| 已过期 | 上游修改使本结果 stale | 查看影响、保留旧版本或创建新版本 |
| 已就绪 | 该对象/场景已达到下游生产门禁 | 进入分镜或下一场景 |

### 14.2 失败恢复规则

- 每个 Stage/Gate 后保存精确 Revision/Hash，页面关闭、Worker 重启或 Provider 暂时不可用后可继续；
- 单 Scene、Identity、State、Interaction 或参考资产失败只阻塞相关下游，无关范围可继续审核；
- 缺视觉细节进入“需要设计输入”，不等同于 Agent 失败；
- 候选图被拒绝时保留原图、完整输入和拒绝原因，新生成产生新 Candidate；
- Provider 不可用时保持剧本解析、Visual Brief 和 Reference Plan 完成状态，资产显示“待生成”；
- 修改原稿、身份、State、Interaction、Preset 或参考版本前展示影响闭包，用户确认后再使相关下游 stale；
- Skill、Schema、Model 或 Recipe 升级不覆盖历史结果，用户主动重跑才进入新版本；
- 不确定 Provider 结果只能保持未决并以同一身份对账，不自动创建第二个生成任务。

### 14.3 局部失效语义

| 上游变化 | 必须 stale | 不应 stale |
|---|---|---|
| 更换整体 Preset/Art Direction | Visual Brief、参考资产、组合 Binding、相关 Shot | Script、Identity、Specification、AssetState、Scene、Interaction |
| 只修改 Prop purpose profile | Prop Sheet、依赖该 Prop 的 Interaction/Scene/Shot | 无关 Character Reference |
| 修改某 Character State | 该 State 参考、相关 Interaction/Scene/Shot | 其他人物/状态 |
| 修改某 Prop State | 该 Prop Sheet、相关 Interaction/Scene/Shot | 基础 Character Reference |
| 修改 Interaction | 该 Interaction Composition、相关 Scene/Shot | 基础 Character/Prop AssetVersion |
| 修改 Scene | 该 Scene Composition 和 Shot | 基础 Location/Character/Prop AssetVersion |
| 修改某 World Rule | 引用该 Rule 投影的视觉目标 | 未引用该 Rule 的资产 |
| 修改 Aspect Ratio | 依赖该画幅的 Output Format/Shot | 中性角色身份三视图 |

## 15. Storyboard 交接与场景就绪

场景只有同时满足以下条件才显示“可进入分镜”：

- Scene/Beat 原文覆盖和 Evidence 完整；
- 每个需制作 Character/Location/Prop Occurrence 都绑定精确 Identity/Specification/State；
- 需要的 Interaction 已确认，持有、手别、道具前后状态与相邻场连续；
- EffectiveStyleSnapshot 已冻结；
- Reference Plan 中标为 required 的基础/组合资产均有已选 READY 版本；
- 没有受影响 `unresolved`、stale 或未裁决 blocker。

系统为就绪场景编译一份只读 Scene Production Packet：

```text
Scene Production Packet
= exact Scene/Beat/Dialogue
+ exact Character/Location/Prop Occurrence
+ exact Specification/AssetState
+ exact Interaction/Continuity in-out
+ EffectiveStyleSnapshot ref/hash
+ exact AssetVersion refs
+ Scene/Interaction ReferenceBinding refs
+ Evidence/Rights/Lineage refs
```

Storyboard Agent 只消费该 Packet，不再从全项目资产库重新搜索，不用“最新版本”或自由文本替代精确引用。

## 16. 产品指标与运营观测

### 16.1 质量与覆盖

- Production-ready Scene Coverage；
- Source/Scene coverage；
- 无 Evidence 正式事实数；
- Identity 重复率、错合并率和人工重绑率；
- Appearance State 首次审核通过率；
- 关键 Interaction 覆盖率和 Prop possession continuity blocker 数；
- 人物三视图、地点板、道具板首次选择率；
- Scene/Interaction Composition 首次选择率；
- 跨资产风格一致性首次通过率；
- Storyboard 首次审核通过率和每场人工修改数。

### 16.2 效率与可恢复性

- Time to First Production-ready Scene；
- Time to Approved Visual Production Package；
- 单 Scene/State/Interaction 局部修改收敛率；
- 一次上游修改实际重跑目标数 / 理论影响目标数；
- 恢复后重复 Candidate、Owner Apply、Artifact 覆盖数；
- stale 产物被分镜消费数。

### 16.3 指标解读边界

- “模型返回了 JSON”不是业务成功；
- “生成了图片”不等于参考资产已发布；
- 低人工修改数不能以漏报事实或自动宽松审核为代价；
- Provider 速度和成本是运行观测，不是新 MVP 北极星。

## 17. MVP 验收场景

| ID | 场景 | 通过条件 | 阻断条件 |
|---|---|---|---|
| `VP-SCR-01` | 剧本拆场与场界歧义 | 原文无遗失，SceneSpan 全覆盖，用户可 split/merge 并局部重算 | 未确认的歧义场不得进入受影响正式绑定 |
| `VP-ID-01` | 别名与同名消歧 | 同一人可有多 alias，同名不自动合并，Occurrence 随决议重绑 | 歧义不能被伪造正式 ID 掩盖 |
| `VP-LOOK-01` | 同一人物三种形象 | 一个 Character Asset + 三个完整 AssetState，有原因/有效范围，三视图保持同一身份 | 换装、伤势或年龄变化不得静默新建角色 |
| `VP-PROP-01` | 道具开闭/损坏/内容物变化 | 一个 Prop Asset 下有可追溯 State、before/after/cause/effective range | 无原因的状态跳变阻塞相关场次 |
| `VP-INT-01` | A 将关键道具交给 B | 同一事件表达 A 释放、B 接收和 holder/PropState 变化 | 除非明确存在复制品，同时不能有两个 holder |
| `VP-INT-02` | 生成“角色右手握剑” | 精确角色 State、Prop State、右手、握点、朝向、比例和接触，结果为 Interaction Binding | 不得建立 `character_holding_sword` 人物身份/形象 |
| `VP-PRESET-01` | 保真预设与剧本事实冲突 | 显示冲突、影响和备选，用户解决后才发布 Snapshot | Preset 不得静默改写原文事实 |
| `VP-PRESET-02` | 世界改编预设 | 每个 source fact → production design 映射有语义不变量和人工决议 | 未决改编不进入正式资产生成 |
| `VP-REF-01` | 角色三视图 | front/profile/back 完整，脸、体型、服装和比例一致，且用户选择唯一候选 | 任一视图缺失/漂移、谱系不完整不得发布 |
| `VP-REF-02` | 地点板和道具板 | 地点拓扑/锚点、道具尺度/结构/状态符合规格，均有已选版本 | 地点未要求人物污染、道具手/人污染或结构漂移不得发布 |
| `VP-REF-03` | Scene/Interaction 组合图 | 只消费精确已选基础版本，结果与基础资产分开发布 | 组合失败不得废弃/覆盖基础资产 |
| `VP-CON-01` | 相邻场连续性 | 形象、伤势、道具持有/状态和地点状态连续，或有明确 Delta | 无原因换装、道具瞬移、损坏恢复阻塞相关分镜 |
| `VP-INV-01` | 已有资产后切换预设 | 新 Snapshot 与旧资产并存，展示精确 stale 范围，不重跑剧本事实 | 不原地覆盖或让新分镜混用未批准旧/新风格版本 |
| `VP-RDY-01` | 场景进入分镜就绪 | 可生产 Scene Packet 完整，任一引用可反查 Evidence、State、Preset 和 Artifact lineage | 必需引用未决/过期/未选时不得标记 ready |

## 19. 主要风险与取舍

| 风险 | 产品取舍 |
|---|---|
| 剧本歧义无法完全自动消解 | `unresolved` 是一等状态，只阻塞影响范围，不伪造置信度或 ID |
| 用户审核负担过大 | UI 收敛为五个 Gate，支持批量接受低风险项，但 Identity/State/Preset Conflict/Asset Selection 不自动批准 |
| 世界预设与剧本冲突 | 默认 faithful；world_adaptation 要求逐项映射和人工决议 |
| 图像模型不能稳定保证三视图一致 | 确定性视图覆盖+多模态审查+人工选择；不把单次生成宣称为已发布 |
| 视觉组合引起数量爆炸 | 基础资产优先；只对用户指定、反复出现、英雄/特写或高连续性风险组合生成 |
| Preset 或外部 Skill 存在权利风险 | 内置参考、案例、模型和 Recipe 都记录 provenance/license；社区 Prompt 未授权时只吸收概念并重写 |
| 外部 Provider/LibTV 是黑盒 | 平台保留自己的 Brief、Target、Artifact digest、QC 和人工决议；黑盒结果只作为 Candidate |
| 新产品与当前 `SG-I21` 实施主线冲突 | 本 Design 先独立评审；接受后在安全检查点保留已有工作，将计费/多 Provider 广度移出新 MVP，不回滚用户未提交修改 |

## 21. 已接受的核心决策

1. 新 MVP 北极星固定为 Production-ready Scene Coverage，而非图片数、Provider 数或计费闭环。
2. Guided Studio 是 MVP 主产品，UI 只呈现五个用户决策 Gate，Canvas 不进入主闭环。
3. 剧本事实抽取 style-blind，预设不得污染 Evidence、Identity、Specification、State、Scene 或 Interaction。
4. Scene Fact 优先、全局身份/状态调和在后，取代当前“先确认 Bible、Scene 只引用已知状态”顺序。
5. 人物多形象使用同一 Character Asset 下的完整 AssetState；人物拿道具使用 Interaction 和组合 Binding，不创建新人物形象。
6. 产品 UI 允许用户一次选择预设，但内部固定为结构化 PresetVersion + 同一组通用 Skill + 按用途编译的 Visual Brief/QC，不复制风格 Skill。
7. 首批只上架 4–6 个通过人物/地点/道具/组合全矩阵验收的策展预设，默认 faithful，world_adaptation 必须显式裁决。
8. Reference Plan 位于已确认生产世界之后、Storyboard 之前；先基础资产，后 Scene/Interaction Composition。
9. Vision Review 只提供建议，人工 CandidateSelection 是发布 AssetVersion 与组合 Binding 的必要条件。
10. 支付、计费、复杂预算与多 Provider 广度移出新 MVP；只保留一条验证视觉生产闭环所需的图片执行路径。
11. 本 Design 接受后立即安全暂停 `SG-I21` 后续扩展，保留当前工作区事实，先完成受影响 Design 与唯一产品/实施/验收链重排。
