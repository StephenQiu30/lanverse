## 2. 处理流程

```text
已确认的集 ≥ 1 → 发起抽取（报价确认）→ extract_bible Skill（输入：各集解析结构摘要）
→ 候选：角色（名称、别名、描述、出场集、状态变化 → 造型建议）、场景、道具
→ 用户合并 / 拆分 / 编辑 / 删除 → 确认设定集
→ 经 script owning 用例发布新的不可变结构版本，按别名绑定 character_id（未匹配的列出供人工指定）
后续新确认的集 → 增量抽取：只对新出现的称呼给出“归入已有角色 / 新建”建议
```

## 3. 数据

| `bible.look` | `character_id`、`name`、`description`、`is_default`、`applies_to` | 造型与适用范围 |

## 5. 异步与工作流

`OperationWorkflow`（`target_type = bible_extract`）的 LLM 同步分支（DES-04 §3）：`llm.run_skill(extract_bible)`（可分块，见 DES-17-Q1）→ `flow.ApplyStructuredResult`（写设定集候选；合并到已有条目时只生成建议，不修改已确认条目）。

## 6. 事件与实时

`bible.entries_changed.v1`（realtime）；合并 / 拆分写审计。

## 7. 界面

三栏列表（角色 / 场景 / 道具）；多选合并；条目详情：别名标签、描述、出场集时间轴、造型卡片；说话人映射对话框。

## 8. 权限与审计

制作者。审计：`bible.merged`、`bible.split`、`bible.confirmed`、`look.created/updated/deleted`。

## 9. 非功能要求

AIQ-02（主要角色召回 100%，别名合并准确率 ≥ 90%）；CAP-01（≥ 200 造型）。

## 10. 测试设计

合并 / 拆分对引用与台词回填的影响；分块抽取的合并正确性（评测集）。

## 12. 完整角色与主体迁移合同（2026-10-02）

来源固定 BeefTV `1ae25027` 的 `backend/internal/app/project_character.go`、角色版本与声音绑定，以及实际装配的角色页/画布工具；不迁入其 Asset 通用仓储、Wails 或 SQLite。现有 Lanverse 尚无 bible/storyboard/audio/lineage owning 实现，原文中的接口和事件不能当作当前事实。Bible 接管稳定角色、场景、道具身份与不可变版本；角色造型、参考图、声音绑定均属于版本化内容。手工创建或编辑候选与真实 AI 抽取严格区分，抽取和形象生成仍经统一 Operation 的真实结果采用。

### 12.1 身份、版本与参考

Bible 使用 project/org scope、当前 active actor/admin/producer、workspace 同事务内容锁与 TouchContent。稳定条目 ID、可变 current/confirmed version 指针及 revision 与 INSERT-only typed version 分离。每次设定、造型、参考和声音绑定变化都发布完整新版本；保留 actor、时间、来源、前版本和内容 SHA，不更新旧版本。定义采用闭合字段，承接名称/别名、剧情定位、外貌/体型/服装/性格、固定道具、一致性与三视图约束、声音描述；不保存任意未校验 provider JSON。

角色至少有一个默认造型，适用范围为正式集/场身份；场景和道具有各自闭合版本。参考用途覆盖 primary/front/side/back/turnaround_sheet/expression_sheet，最多八个图片表示；关联正式同项目 ready/passed image 与实际 rendition，当前授权、真人许可及媒体删除边界仍由 media owning 验证。历史引用保持原版本与媒体身份，替换当前参考不覆盖旧绑定。角色合并保留已确认 redirect，当前解析沿有界无环链；拆分发布新角色及新版本，不重写历史文稿或旧镜头。

### 12.2 台词归属与下游影响

050 已确定 episode_structure、scene、dialogue_line 与 action_line 的 INSERT-only 合同。角色绑定必须由 script 消费方端口验证当前项目/确认角色/重定向后，通过已有 structure CAS 创建新的 typed StructureDocument 与一致的物化行；scene_key、line_key、原文、scalar span 和 source hash 保留。确认、脚本头及 workspace invalidation 在同一事务推进，旧确认和原台词完全保留。跨模块接口由各消费方声明，组合根显式转换，禁止 script↔bible 导入循环或跨模块通用 SQL。

替换已采纳剧本、修改已确认结构或删除被引用造型，必须读取真实 owning Impact 并按冻结修订失效；缺少 storyboard/audio/lineage 等实际证据继续阻断，不能将未知影响报告为零。发布独立新角色版本不伪造镜头或音频失效数量；历史 pinned 版本继续可解析，current 投影依据真实当前版本标示变化。

### 12.3 声音与完整 Copy

声音区分 catalog 与 sample 两种闭合来源。Catalog 绑定当前已配置模型和其真实 voice 枚举；固定来源中的十三个 voice key 可保留为明确来源的候选说明，不在 GET 中写入种子或声称供应商可执行。Sample 绑定正式同项目 ready/passed audio、真实 SHA/revision 与 instructions；它表示样本绑定，不能冒充声音克隆、TTS 或试听完成。声音变化生成不可变角色/声音版本，真实生成仍按 DES19 与 Operation 处理。

Bible 提供自身 ReferencedMedia/Freeze/Transfer/Register/Verify/Cleanup，受 workspace 同事务 trusted Copy authority 与当前 worker fence 约束。完整复制角色、场景、道具、造型、参考与声音版本及确认/重定向历史，映射稳定身份及版本身份后才交 Script/Canvas 重写各自声明的引用；不复制任务、费用或供应商身份。新可空扩展须维持旧无 Bible 快照/永久回执的逐字兼容。原件缺失、未知版本或映射不完整拒绝受理或发布，不输出空主体。

### 12.4 数据、接口与验收

首个增量迁移由根分配 `202610020060_bible`，为稳定条目/版本头、不可变条目版本与造型/参考/声音版本、确认、永久命令回执和必要 Copy owning 事实提供真实持久化。只为实际用例建立表与端口；API 覆盖项目列表/详情/版本、创建/编辑/确认/合并/拆分、造型、参考及声音绑定，并通过 Gin→swag→在线 Swagger→前端生成接口装配。永久 UUID key 与当前权限在重放前复核，CAS、同键异输入、零行写入、失效依赖与撤权均有明确失败。

先 Red→Green 验证闭合领域与不可变版本，再用隔离非 owner PostgreSQL、真实媒体/私有对象、HTTP、并发/故障、完整历史 Copy 和浏览器检查；gofmt/goimports/vet/lint/race/govuln、严格 TypeScript、适用前端门禁分别记录。手工候选和引用测试不证明 AI 抽取、三视图生成或 TTS，未装配下游的 503 继续列为完整迁移未决项。
