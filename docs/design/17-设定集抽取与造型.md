## 2. 处理流程

```text
已确认的集 ≥ 1 → 发起抽取（报价确认）→ extract_bible Skill（输入：各集解析结构摘要）
→ 候选：角色（名称、别名、描述、出场集、状态变化 → 造型建议）、场景、道具
→ 用户合并 / 拆分 / 编辑 / 删除 → 确认设定集
→ 回填各集台词的 character_id（按别名匹配，未匹配的列出供人工指定）
后续新确认的集 → 增量抽取：只对新出现的称呼给出“归入已有角色 / 新建”建议
```

## 3. 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `bible.character` | `name`、`aliases`、`description`、`review_status`、`episode_seqs`、`first_episode_seq`、`merged_into_id` | 角色与别名 |
| `bible.look` | `character_id`、`name`、`description`、`is_default`、`applies_to` | 造型与适用范围 |
| `bible.location`、`bible.prop` | `name`、`aliases`、`description`、`episode_seqs` | 场景、道具 |
| `bible.episode_asset_usage` | `episode_id`、`owner_type`、`owner_id`、`source` | 本集用到哪些条目（REQ-15 资产定稿清单） |
| `script.dialogue_line.character_id` | 回填 | 配音按角色取音色 |

## 4. 接口

```http
POST /api/projects/{pid}/quotes  { "items": [ { "target_type": "bible_extract", "target_id": "<project_id>", "capability": "text.structured" } ] }

GET /api/projects/{pid}/characters?episode_id=&review_status=
200 { "items": [ { "id": "…", "name": "李明", "aliases": ["小李","李队"], "episode_seqs": [1,2,3,7], "review_status": "candidate",
                   "looks": [ { "id": "…", "name": "日常装", "is_default": true, "locked_slots": 1, "total_slots": 2 } ], "revision": 2 } ] }

POST /api/characters/{id}:merge   { "from_ids": ["…"], "expected_revision": 2 }
POST /api/characters/{id}:split   { "aliases": ["李队"], "new_name": "李队长", "expected_revision": 3 }
POST /api/projects/{pid}/bible:confirm

POST /api/characters/{id}/looks                     { "name": "战斗受伤", "description": "…", "applies_to": [ { "episode_seq": 5 } ] }
```

## 5. 异步与工作流

`OperationWorkflow`（`target_type = bible_extract`）的 LLM 同步分支（DES-04 §3）：`llm.run_skill(extract_bible)`（可分块，见 DES-17-Q1）→ `flow.ApplyStructuredResult`（写设定集候选；合并到已有条目时只生成建议，不修改已确认条目）。

## 6. 事件与实时

`bible.entries_changed.v1`（realtime）；合并 / 拆分写审计。

## 7. 界面

三栏列表（角色 / 场景 / 道具）；多选合并；条目详情：别名标签、描述、出场集时间轴、造型卡片；说话人映射对话框。

## 8. 权限与审计

制作者。审计：`bible.merged`、`bible.split`、`bible.confirmed`、`look.created/updated/deleted`。

## 9. 非功能要求

AIQ-02（主要角色召回 100%，别名合并准确率 ≥ 90%）；CAP-01（≥ 200 造型）。

## 10. 测试设计

合并 / 拆分对引用与台词回填的影响；分块抽取的合并正确性（评测集）。
