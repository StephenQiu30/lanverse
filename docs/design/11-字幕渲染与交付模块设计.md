# 字幕渲染与交付模块设计

## 1. 边界与生产前置

`delivery` 拥有 SubtitleVersion、RenderSnapshot 和 DeliveryVersion，但不拥有 Task/Attempt、Adoption 或 MediaVersion。它仅在以下条件全部满足时创建渲染快照：

- current confirmed ShotSpecVersion 含 6～10 镜且时长 30～60 秒；
- 每镜有与当前 input hash 匹配的 active `shot_video` Adoption；
- 每条 confirmed SpeechLine 有 active `speech_audio` Adoption；
- current confirmed SubtitleVersion 与同一 Script/Shot/TTS 组合兼容；
- 所有 MediaVersion ready 且可由 Worker 从 MinIO 读取。

## 2. 字幕版本设计

`createSubtitles` 以 confirmed ScriptVersion、ShotSpecVersion 和全部 TTS Adoption/时长建立 draft。Cue 含稳定 cue_id、speech_line_id、源语言文本、start/end ticks 和所属 shot_id；按时间有序、不重叠、不越出所属镜头，与 TTS 起止差不超过 100ms。

`saveSubtitles` 仅允许修改 draft，`deriveSubtitleDraft` 从 confirmed 复制为新 draft，`confirmSubtitles` 锁 Episode 并确认唯一 current 版本。Subtitle 内容、输入引用和哈希在确认后不可变；SRT 由 confirmed 内容确定性派生。

## 3. RenderSnapshot 与幂等受理

RenderSnapshot 固定：Shot 顺序/目标 ticks、每镜视频 Adoption/MediaVersion/hash、每句 TTS Adoption/MediaVersion/hash、SubtitleVersion/hash、字体与许可证、FFmpeg/ffprobe 版本、编码参数和 normalization recipe。快照不保存签名 URL。

`renderEpisode` 按 DESIGN-06 的 Tx1/Tx2/Tx3 继续式幂等协调：先建/复用 RenderSnapshot 与 pending 回执，再建/复用 Render Task，最后 CAS 绑定。任一阶段崩溃后重放都不产生第二个逻辑渲染。DeliveryVersion 只由首次执行该 Render Job 的幂等用例创建。

## 4. FFmpeg 管线与资源限制

1. 从 MinIO 下载到 run_id 隔离临时目录，逐个复核 SHA-256 和 ffprobe 数据。
2. 每镜视频使用参数数组转为 720×1280、24fps、H.264 yuv420p，移除源视频音轨并按目标 ticks 裁剪/补帧。
3. 逐句 TTS 按 Cue 定位，无语音区间填充静音，混音为 AAC 48k stereo；字幕使用受审 Noto Sans CJK SC 烧录并同时输出 SRT。
4. 输出 MP4 后执行 ffprobe 与帧/时轴检查；参数数组调用，不拼接 Shell。
5. 超时、CPU/内存、临时目录和输入字节遵循 REQ-06；超限失败保留快照和诊断摘要。

## 5. 交付事实与谱系

DeliveryVersion 使用 `rendering → ready/failed/cancelled`，引用 RenderSnapshot、Render Task 和三个交付 MediaVersion：`mp4/srt/manifest`。Manifest 包含输入版本、所有 Adoption→Candidate→MediaVersion→Attempt→Task→Snapshot 引用、Provider/model、FFmpeg 版本、字节哈希和技术规格。`getDelivery.lineage` 返回可遍历的不可变图，不包含对象 URL。

`authorizeDownload` 仅对 ready Delivery 的三类制品签发 900 秒私有读授权；授权过期不改变 Delivery。用途固定 `internal_review`。

## 6. 失败与回滚

| 失败 | 事实结果 | 恢复 |
| --- | --- | --- |
| 缺少/过期 Adoption 或字幕 | 受理前 `412/422` | 回到 Studio/Subtitle 补齐，再创建新快照 |
| FFmpeg 失败 | Attempt 失败，Delivery failed | 原 Task 自动重试增加 Attempt；用户重试新 Task/Delivery |
| ffprobe 不合格 | 不发布下载 | 保留输入快照，修复渲染实现后重试 |
| 上传中断 | 不创建 ready 交付 | 以稳定 object key/hash 对账后继续 |
| 下载授权过期 | Delivery 仍 ready | 重新申请授权 |

回滚仅切换兼容应用/FFmpeg 制品，不删除 RenderSnapshot、Delivery、媒体对象或上游采用。

## 7. Design 验收标准

- AC-MOD-DELIVERY-001：字幕 draft 由同一 confirmed Script/Shot/TTS 组合派生，Cue 有序、不重叠、不越镜且与 TTS 差值≤100ms。
- AC-MOD-DELIVERY-002：缺少任一必需视频/TTS Adoption、confirmed 字幕或输入哈希不匹配时不受理渲染。
- AC-MOD-DELIVERY-003：同幂等键在 Tx1/Tx2/Tx3 任一点重放只绑定一个 RenderSnapshot、逻辑 Task 和 Delivery。
- AC-MOD-DELIVERY-004：ffprobe 证明 MP4 为 720×1280、24fps、H.264 yuv420p/AAC 48k stereo、30～60 秒，且字幕可见。
- AC-MOD-DELIVERY-005：MP4/SRT/Manifest 哈希可对照，任一 ready Delivery 可反查至全部来源、版本、Task/Attempt、Candidate/Adoption 和媒体。
- AC-MOD-DELIVERY-006：渲染故障、质检失败或授权过期均不改写历史输入，且有可执行的局部恢复路径。
