# 剧本分镜与创作资产模块设计

## 1. 输入、输出与范围

本模块以 confirmed SourceRevision 为唯一起点，产出 confirmed ScriptVersion、CreativeAssetVersion 集合和 ShotSpecVersion。AI 只提供可校验提案，用户确认才形成新生产输入。模块不负责 Provider 执行状态、媒体 Candidate/Adoption 或渲染。

## 2. 模块结构与公开端口

| 层 | 内容 | 对外边界 |
| --- | --- | --- |
| `domain` | Script/Asset/Storyboard 版本、Shot/SpeechLine 值对象、确认策略 | 纯 Python，不依赖 AI/DB/Web |
| `application/contracts` | `ScriptContentV1`、`CreativeAssetContentV1`、`ShotSpecCollectionV1` | 生成、保存、确认和快照共用严格契约 |
| `application` | 生成命令、draft 编辑/派生、确认、版本查询 | 通过 production_jobs 公开端口受理 AI 任务 |
| `infrastructure` | 三类版本表的 SQL Repository/Row Mapper | 不查询 Candidate 或 Task 内部表 |
| `transport` | DESIGN-04 剧本/分镜 Operation | 只做 HTTP 映射 |
| `public.py` | confirmed 内容、稳定 ID、哈希与生产快照 DTO | 不暴露 draft 修改能力给其他模块 |

## 3. 用例与生成协作

| 阶段 | 入口 | 处理与出口 |
| --- | --- | --- |
| 剧本生成 | `generateScript` | 固定 Source/Prompt/Schema/model profile 快照；Task 成功后幂等建立 Script draft |
| 剧本编辑 | `saveScript/deriveScriptDraft` | 只修改 draft；confirmed 先派生再编辑 |
| 剧本确认 | `confirmScript` | 复算 Schema/哈希，使新版本成为唯一 current confirmed |
| 分镜生成 | `generateStoryboard` | 固定 confirmed Script，生成 Asset drafts + ShotSpec draft |
| 分镜编辑 | `saveCreativeAsset/saveStoryboard/deriveStoryboardDraft` | 稳定 asset_id/shot_id，重排不改变 shot_id |
| 联合确认 | `confirmStoryboard` | 一个事务验证并确认 ShotSpec 及其全部 Asset 版本 |

Worker 只调用模块公开的“登记生成结果”用例，不直接写版本表；相同 origin Task/output slot 重入返回已有版本。

## 4. 内容契约与哈希

- Script 含有序 Scene；Scene 含地点、时间、动作；SpeechLine 含稳定 `speech_line_id`、文本、顺序、所属 Scene、`voice_id`，对话另含角色。
- CreativeAsset 类型只允许 `character/scene/style`，具有稳定 `asset_id`、名称和文字设定。
- ShotSpecVersion 含 6～10 个 ordinal 连续且唯一的 Shot；每镜 3～8 秒，以 90,000 ticks/s 且对齐 24fps 帧边界。
- 每个 Shot 含叙事目的、Prompt、动作、资产版本引用和 SpeechLine 引用；每条 SpeechLine 恰属一镜。
- 完整镜头时长为 30～60 秒且至少一条 SpeechLine。`content_hash` 按 DESIGN-04/06 的 RFC 8785 包装复算。

## 5. 状态、事务与不变式

1. 三类版本均使用 `draft → confirmed → superseded`；已确认内容不可变。
2. 剧本确认锁 Episode，分镜确认按 UUID 顺序锁 Episode/资产/分镜，partial UQ 收敛并发。
3. 联合确认前重新校验所有引用同 Episode、内容哈希匹配、无缺失 SpeechLine/Asset。
4. AI 输出 Schema 失败、截断或多余字段时，Task failed，不登记可确认 draft。
5. 上游当前版本变化不改写历史，新生产仅接受 `input_outdated=false` 的 current confirmed 组合。

## 6. 失败、权限与回滚

| 失败 | 用户可见结果 | 安全恢复 |
| --- | --- | --- |
| 上游版本已变 | `412 VERSION_CONFLICT` | 刷新后基于新 confirmed 创建任务 |
| 修改已确认版本 | `409 VERSION_IMMUTABLE` | 调用显式 derive Operation |
| AI 结构无效 | Task failed + 稳定错误码 | 新 Task，旧快照/尝试保留 |
| 联合确认校验失败 | 整个事务回滚 | 修正指定 draft，不需重生其他内容 |

Prompt 与原始 AI 输出不进入普通日志。数据迁移只前滚；回滚应保留所有已确认版本和其生产引用。

## 7. Design 验收标准

- AC-MOD-STORY-001：固定 Mock 来源产生严格 Script draft，相同 Task/output slot 重入不增加版本。
- AC-MOD-STORY-002：剧本包含完整 Scene/SpeechLine/voice 契约，缺失、多余、截断输出均不可确认。
- AC-MOD-STORY-003：固定 fixture 产生 6～10 个稳定 Shot，总时长、帧对齐、资产和语音引用全部通过。
- AC-MOD-STORY-004：分镜联合确认要么原子确认全部引用资产与 ShotSpec，要么全部不变。
- AC-MOD-STORY-005：并发确认后各类聚合最多一个 current confirmed，confirmed 内容的 ETag 修改被拒绝。
- AC-MOD-STORY-006：来源/剧本变化后，旧分镜、候选和 Task 不变，仅查询投影显示 outdated。
