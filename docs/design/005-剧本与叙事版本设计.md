# DES-005 剧本与叙事版本设计

- 状态：proposed
- 版本：v1.0
- 日期：2026-08-14
- 关联需求：CUR-SCR-FR-001～011、CUR-SCR-NFR-001～011
- 关联验收：AC-CUR-SCR-001～016
- 上游：[CUR-SCR](../requirement/004-剧本分析与叙事结构需求.md)、[DES-012](./012-平台Capability与Provider耐久任务及媒体设计.md)

## 1. 问题、范围与非目标

Scripts 模块将整剧原稿可靠转换为已确认分集、单集不可变 ScriptVersion、Scene/NarrativeUnit 和带证据的资产/镜头候选。AI 只能提出候选；用户确认和发布才形成正式下游事实。

范围：UTF-8 文本/Markdown 导入、格式体检、确定性/AI 分集、整批物化、单集版本、AI 改写候选、叙事结构、提取候选、人工决议、NarrativeUnit 生产处置和版本影响。

非目标：PDF/DOCX/OCR、资产或 Shot 正式身份、自动迁移下游、字幕/配音、通用文档编辑器、自动把 AI 结果设为 current。

## 2. 事实所有者与模型

| 实体 | 所有事实 | 不可变/可变 |
| --- | --- | --- |
| ScriptDocument | Project 内整剧稳定身份 | 稳定 |
| DocumentRevision | 原始正文、来源、权利引用、内容 hash | 不可变 |
| NarrativeBlock | 特定 Revision 内有序格式块和字符范围 | 不可变 |
| EpisodePlan | 固定 Revision 的分集边界、证据、修订和状态 | draft 可修订；confirmed 不改 |
| ImportCommit | 确认计划整批物化结果 | 不可变、幂等 |
| ScriptSource | Episode 的来源身份 | 稳定 |
| ScriptVersion | 单集正文、来源范围、版本原因、hash | 不可变；current 指针分离 |
| Scene | 特定 ScriptVersion 内有序场景 | 不可变版本内事实 |
| NarrativeUnit/Version | 跨版本语义身份/特定版本表达与范围 | 身份稳定、表达不可变 |
| ProductionDispositionDecision | 固定 NarrativeUnitVersion 的 `must_cover` 或 `may_omit_with_approval`、理由、actor/time | 追加不可变决定；current 投影乐观切换 |
| AdaptationRun | 固定输入 AI 改写任务引用和候选 | 不可变 |
| ExtractionBatch/Candidate | 固定版本提取候选及来源证据 | 不可变 |
| CandidateDecision | accepted/linked/merged/ignored 人工决定 | 追加式 |

Scripts 不拥有 Asset/Shot；接受候选通过 Assets/Storyboards 的公开命令创建或关联稳定对象，结果引用回 CandidateDecision。

## 3. 原文、边界与版本不变式

1. DocumentRevision 保存规范化前原始文本字节/字符事实和 SHA-256；解析不得覆盖原稿。
2. 确认 EpisodePlan 对非排除正文必须 gap=0、overlap=0，并固定规则版本。
3. 整批物化要么创建全部 Episode/ScriptSource/初始 ScriptVersion，要么零正式事实。
4. ScriptVersion 发布只切 current 指针，不改旧版本。
5. NarrativeUnit 的字符位置只在固定 Revision/Version 内有意义；跨版本匹配不得静默复用身份。
6. AI 边界、改写、结构和提取均带“AI 建议”、固定输入和证据；未决议不进入下游。
7. 新 current 触发 Impact 计算；影响不可用时不切换 current。
8. 新 NarrativeUnitVersion 默认 `must_cover`；`may_omit_with_approval` 必须有 actor、理由和时间，不等于删除/不重要。
9. 新 ScriptVersion 不自动继承旧 NarrativeUnitVersion 的省略批准；Storyboard Coverage 仍须逐项解释覆盖或批准省略。

## 4. 确定性解析与 AI 边界

导入先运行本地确定性管线：实际类型/UTF-8 解码 → code point 和容量检查 → 换行规范的只读视图 → 集标记/场景标题识别 → NarrativeBlock → gap/overlap 报告。

确定性结果包含 parser version、规则、输入 hash 和定位错误。同一输入/规则重复运行结果必须一致。

只有无可靠显式集标记或用户主动请求时才进入 AI EpisodePlan：

- 固定 DocumentRevision、目标集数/时长和受控 PromptTemplateVersion；
- 输出结构化边界、理由、置信和证据范围；
- Schema 校验、范围校验和 gap/overlap 检查失败时保持 Task succeeded-with-invalid-output 的受控业务结果或 failed，不伪造 review-ready；
- 用户编辑边界产生 Plan revision，AI 不覆盖人工修订。

## 5. 同步命令与查询

| 能力 | 强事务结果 |
| --- | --- |
| ImportScript | DocumentRevision + 本地体检；重复内容可关联既有 Revision |
| ReviseEpisodePlan | 新 draft revision 或并发冲突 |
| ConfirmEpisodePlan | review_ready → confirmed，固定完整边界 |
| MaterializeEpisodePlan | 整批 Episode/ScriptSource/初始 Version + ImportCommit；零半成功 |
| CreateScriptVersion | 新不可变 Version，不自动发布 |
| PublishScriptVersion | 影响预检有效时原子切 current + event |
| ReviseNarrativeStructure | 新结构修订/Version，保留来源范围 |
| SetProductionDisposition | NarrativeUnitVersion、`must_cover / may_omit_with_approval`、理由、expected revision → 新不可变决定 + 覆盖影响摘要；冲突零写入 |
| DecideExtractionCandidate | 追加 Decision + 下游稳定引用或可恢复 pending handoff |
| GetImpact | 旧/新版本、下游引用、stale 分类、unavailable 分区 |

所有正文写命令使用 expected revision 与幂等键；未提交编辑草稿由前端/草稿存储恢复，不成为正式 ScriptVersion。

## 6. 异步工作流与事件

异步工作：AI 分集、AdaptationRun、结构/连续性分析、ExtractionBatch。每项使用 DES-012 唯一 WorkTask/Attempt；刷新和 Worker 重启恢复同一 Task。

```text
preflight → create immutable run + WorkTask → provider submit/query
→ validate structured output → persist candidate/batch → await human decision
```

Scripts 发布：`DocumentRevisionCreated`、`EpisodePlanConfirmed`、`EpisodePlanMaterialized`、`ScriptVersionPublished`、`CurrentScriptVersionChanged`、`NarrativeStructureConfirmed`、`ProductionDispositionChanged`、`ExtractionCandidateDecided`。

完整正文、完整 Prompt 和候选全文不进入普通事件；事件只含稳定 ID、版本、hash、actor/time 和原因。

## 7. 状态与失败恢复

```text
EpisodePlan: draft → review_ready → confirmed → materialized
             draft/review_ready → superseded
AI Run: 使用 DES-012 WorkTask canonical 状态
CandidateDecision: pending → accepted | linked | merged | ignored
ProductionDisposition: must_cover ↔ may_omit_with_approval（每次切换追加决定）
```

| 失败 | 行为 | 恢复 |
| --- | --- | --- |
| 上传后解析失败 | Revision/原文件证据保留，不创建 Episode | 新 Revision 或修正文本重试 |
| 集标记缺号/重复/空集 | 定位行并阻断确认 | 人工边界或修正原稿 |
| AI failed/unknown | current 和原稿不变 | failed 可安全新 Run；unknown 先对账 |
| Plan 并发变化 | 确认零写入 | 比较最新 revision 后重做 |
| 物化任一步失败 | 无半批 current | 同一 ImportCommit 幂等恢复或整批回滚 |
| 下游候选 handoff 失败 | Decision 显示 pending handoff，不冒充完成 | 用同一决议意图恢复，不重复对象 |
| 连续性依赖失败 | unavailable，不显示“无问题” | 单独重试检查 |
| 生产处置期间版本/影响并发变化 | 决定零写入 | 返回最新 UnitVersion/处置和覆盖影响后重做 |

## 8. 权限、安全与隐私

- owner/editor 导入、修改、运行 AI、发布和决议；viewer 只读。
- 文件实际 MIME/编码和容量必须验证；拒绝 PDF、DOCX、图片、压缩包和可执行内容。
- 原始正文、完整 Prompt、上传 URL、候选全文不得进入日志、指标标签、普通 Audit 或事件。
- Provider 只获得运行必需文本范围；数据处理地域/保留由 DES-013 Governance 门禁与 DES-012 Capability 预检共同决定。
- Script 文件下载每次按 Workspace 权限签发短期能力。

## 9. 可观测性

- 导入/解析耗时、格式错误类型、gap/overlap、Plan revision 冲突；
- AI Run 排队/外部等待/Schema invalid/unknown；
- ScriptVersion 发布、Impact 查询延迟、stale 下游数量；
- Candidate 决议和 handoff 失败率；
- Trace 记录 Revision/Version/Task/Batch ID，不记录正文。

## 10. 验证

- AC-CUR-SCR-001～007：原稿保护、体检、分集建议、确认和整批物化；
- AC-CUR-SCR-008～014：版本、AI 改写、结构、提取、连续性和 stale；
- AC-CUR-SCR-015～016：生产处置固定 NarrativeUnitVersion、必需理由/审计、并发零写入以及 CUR-SBD Coverage 交接；
- 100,000 code points proposed 样本的本地体检/确定性分集 P95 ≤5 秒；
- 同输入/规则执行 100 次边界完全一致；
- 重复/并发确认不产生重复 Episode/Asset/Shot；
- 原文、Prompt、URL 和跨 Workspace 泄露为 0；
- Worker 重启/重复回调不重复 Provider 请求；键盘可完成 P0 决议流程。
