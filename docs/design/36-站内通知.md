## 2. 数据

`notify.notification`（`user_id`、`kind`、`title`、`body`、`link`、`dedupe_key`（部分唯一）、`read_at`）。

## 3. 接口

```http
GET  /api/notifications?unread=true&limit=20
200 { "items": [ { "id": "…", "kind": "batch_finished", "title": "第 1 集第 3 场视频生成完成", "body": "成功 18，失败 2",
                   "link": { "type": "batch", "id": "…", "project_id": "…" }, "read": false, "create_time": "…" } ], "unread_count": 3 }
POST /api/notifications/{id}:read
POST /api/notifications:read-all
GET  /api/me/events   （SSE：notification.created）
```

## 4. 异步与工作流

`notify` 消费者（`backend-relay`）按下表把事件转换为通知，并发布 SSE。事件的生产方与消费者清单以 DES-03 §6.2 为准，本表只定义通知规则（类型、接收人、去重键）：

| 通知类型（REQ-33 §2.1） | 来源事件 | 接收人计算 | 去重键 |
| --- | --- | --- | --- |
| `batch_finished` | `batch.finished.v1`（解析批次除外） | 批次确认人 | `batch:{id}` |
| `operation_failed` | `operation.failed.v1`（`batch_id` 为空时） | 确认人 | `op:{id}` |
| `operation_manual` | `operation.manual.v1` | 全部启用的管理员 + 确认人 | `manual:{id}` |
| `budget_low` | `billing.budget_low.v1` | 最近 7 天在该项目有审计记录的用户 + 管理员 | `budget:{pid}:low:{日期}` |
| `budget_overrun` | `billing.budget_overrun.v1` | 同上 | `budget:{pid}:overrun:{日期}` |
| `import_finished` | 导入：`script.version_imported.v1`；解析批次：`batch.finished.v1`（批次类型为解析，只生成本类型，不再生成 `batch_finished`） | 发起人 | `import:{import_id}` / `import-batch:{batch_id}` |
| 授权作废 | `media.consent_revoked.v1` | 受影响对象的最近操作人 | `consent:{id}` |
| 对账差异 | `billing.reconciliation_diff.v1` | 全部管理员 | `recon:{run_date}` |

去重：`notify.notification.dedupe_key` 部分唯一索引，重复事件不产生重复通知。

## 5. 事件与实时

SSE `notification.created`（`/me/events`）。

## 6. 界面

顶栏铃铛（未读数）→ 下拉列表（分组：今天 / 更早）→ 点击跳转；Sonner toast 即时提示。

## 7. 权限与审计

用户只能看到自己的通知；无审计。

## 8. 非功能要求

PERF-03（事件到通知可见 ≤ 2 秒）。

## 9. 测试设计

去重；接收人计算。
