# AI 绘画提示词知识库数据治理与安全设计

## 1. 状态与适用范围

本文与 `DESIGN-001/003` 必须共同接受。它不是特定法域的法律意见；确定运营法域、数据处理角色和法务负责人之前，网络来源保持禁用。核心原则是“不先抓取、后补合规”：访问授权、内容权利、隐私与安全门禁分别判定，任何未知、过期、失败或超时都 fail-closed。

## 2. 四层准入与裁决

| 层级 | 必须回答的问题 | 失败动作 |
| --- | --- | --- |
| Access authorization | ToS、官方 API/MCP 或书面许可是否允许该身份、接口、频率和目的自动访问 | 不创建网络任务 |
| Robots | 指定 User-Agent 对实际 URL/方法的 RFC 9309 结果是什么 | HTML crawler 禁止；官方 API 的例外只能由独立、签字的 access decision 解释 |
| Content rights | prompt、metadata、原图、派生图各自是否允许保存、展示、导出、向量化、训练和商业使用 | 对应动作禁止 |
| Privacy/safety | 内容是否满足 PII、成人/未成年人、违法、注入和媒体安全政策 | 隔离或拒绝 |

ToS、robots 和书面/API 授权没有通用的自动优先级，必须分别版本化并由 `access_decision` 给出适用于“接口 × 身份 × 动作 × 期限”的结论。Civitai 在 robots 与 ToS 第 11.4 节的差异未完成审计结论前保持 `disabled_pending_review`。

政策原文/证据分别存入 `terms_snapshots`、`robots_snapshots`、`written_authorizations`；记录 URL、HTTP 状态、正文/附件 SHA-256、抓取/生效/到期时间、适用 User-Agent、审核人和结论。正文变化、到期或无法复核会暂停来源、取消未开始任务，并把受影响的已发布内容置为 `rights_pending` 重新评审。

## 3. 权利模型

来源动作矩阵至少包含：

```text
fetch_metadata, store_raw_response, store_prompt_raw, store_prompt_display,
store_original, create_thumbnail, display, review_for_safety, copy_prompt, redistribute_or_export,
create_embedding, model_training, commercial_use
```

`rights_assertions` 记录 claimant、creator、rights holder、basis、证据和争议状态；`license_grants` 记录 subject type/id、action、audience（`internal|public`）、license URI/version、territory、effective/expiry、attribution、commercial/derivative/redistribution 条件、revocable、verification status/reviewer。`copy_prompt` 与 `display` 分别裁决，复制不能由可见性推导。记录 append-only，撤销或争议生成新状态，不覆盖证据。

来源级允许只是一道上限，不替代对象级权利。每个 `published`、`embedded`、`cached` 或 `exported` 对象必须精确引用覆盖“主体 × 动作 × 受众 × 当前时间”的有效 grant。DiffusionDB 的 CC0 声明仍不自动清除商标、肖像、隐私或第三方权利；Civitai API 的访问许可也不自动授予保存或再利用用户 prompt/图片的权利。

## 4. 获取阶段与数据生命周期

1. Fetcher 首先只获取获准的 metadata/API payload，正文形成内存或加密临时 `ArtifactRef`；parser 可在 TTL 内消费，临时对象不超过 24 小时。
2. 不可变审计记录只保存 URL、状态、redirect/DNS 决策、headers 白名单、时间、hash 和任务身份，不包含 prompt、页面正文或媒体字节。
3. 只有 `store_raw_response` grant 有效时，正文才进入受控 raw bucket；无此 grant 的 parse attempt 只关联 artifact hash。“不可变”不阻止删除、许可撤销或违法内容清除。
4. Prompt/metadata 权利与文本安全预判通过后，MVP 只有精确 `store_original + create_thumbnail + display(internal)` grants 均有效才创建 `media_fetch_job`；job 固定 source observation、最终 URL、validators 与已知/首次获取 hash，允许域名出网 Worker 仅 Put 到私有 `media-staging`，未知或不可展示图片不得下载。
5. No-egress media Worker 从 staging 读取并删除，完成安全解码、PII/内容审核后才写 original/display-derived；它不能访问公网，只允许私网 PostgreSQL、RabbitMQ、MinIO。staging 默认 TTL 24 小时；若处理前过期，重抓必须新增 fetch observation 并比对 hash，变化时创建新 asset/version 且重跑 rights/PII/moderation，无法证明同一内容则隔离/置 dead，绝不覆盖或发布。decoder 临时文件 TTL ≤1 小时。
6. MinIO 中 raw、media-staging、original、display-derived、review-derived 和 policy/legal quarantine 使用不同私有 bucket、账户、权限和生命周期；staging 是传输区，quarantine 原始字节永不交给浏览器。MVP 禁用 versioning/object lock，TTL/删除由 DB jobs/Reconciler 执行；正式对象按权利主体 namespace 内容寻址，禁止跨权利主体物理去重。
7. 游标推进与 Outbox 恢复遵循 `DESIGN-001`；处理器先领取 uploading lease，再用 checksum + `If-None-Match: *` 条件写确定性 key。新写成功以 fencing 事务转 ready；冲突交 no-egress verifier 按精确 key 校验。Reconciler 只清理过期 uploading，ready→deleting 行锁阻止新引用，只有 ready 可消费。
8. RabbitMQ 消息只含 opaque 业务 ID、attempt、policy version 与 trace，不含 prompt、媒体 URL/字节、用户数据或 secret；队列 TTL/DLX 只用于传输治理，不能替代数据删除。

| 身份 | MinIO 最小动作 |
| --- | --- |
| media-fetch / media-process | 前者仅 Put staging；后者 Get/Delete staging，并按裁决 Put original/display-derived/review-derived/quarantine |
| API | 仅 Get/预签名 display-derived；不得 List、写入、删除或读取 raw/original/staging/quarantine |
| raw-writer / raw-parser | 前者仅在 grant 有效时 Put 确定 key，无 Get/List；后者仅按 job Get 精确 key，无 List/Put/Delete |
| delete worker | 仅按 deletion job 精确 Delete，不持有 List 或通配读取权 |
| verifier / Reconciler | 前者 no-egress、仅按 verify job Get 精确 key；后者受控 List/Delete 过期 uploading/orphan，均逐次审计 |
| review-derive / review-media | 前者 no-egress、按 case Get 精确 quarantine key 并 Put review-derived；后者仅 Get 精确 review-derived，均不得 List |
| legal break-glass | 常态禁用，仅按 DG-06 SOP 访问精确 quarantine key，不得 List，启用需审批和全量审计 |
| backup / restore | backup 仅按 manifest 读取 raw/original/display-derived/获准备份的 quarantine，显式拒绝 staging/review-derived；restore 常态禁用且只写离线 recovery namespace |

专用 review-media 服务只对具备 `review_for_safety` grant、已安全解码、去元数据并低分辨率重编码的 review-derived 签发 ≤60 秒、`no-store` 的 case-scoped URL；对象 TTL ≤24 小时且结案立即删除，每次请求都重验 case/grant/suppression。缺失/过期时 `asset-url` 返回 202 并创建固定 `case_id + case_version + source_hash + derive_policy_version` 的幂等 job；领取和 ready 提交均重验 case=open/current grant/允许等级/未 suppressed，并以 case_version fencing。结案/撤权事务 bump version、取消待执行 job 并创建删除任务；旧 Worker 不能提交 ready，其写入作为 orphan 立即删除且不返回 URL。解码失败/polyglot 只显示错误元数据，违法/未成年人只走 DG-06 SOP。

MVP 生产的 AIStor 数据卷与 recovery 卷使用宿主机卷加密；解锁 secret 在独立故障域双人托管，与数据、快照及应用 secret 分离，恢复演练要求 4 小时内取得。每个 backup epoch 使用独立 envelope data key 并记录 key id/version，key 不进入快照，crypto-shred 只销毁对应 epoch key；本地纯 fixtures 至少使用宿主加密卷。

## 5. 发布不变量

只有 `publishable` 可以展示、全文索引或生成 Embedding。进入该状态的同一 DB 事务必须重新验证：

```text
source = active
AND access_decision = current_and_permitted
AND exact_license_grants cover requested actions
AND pii_assessment = passed
AND moderation_decision = passed
AND (inline_media = false OR media_assessment = passed)
AND suppression_rule = absent
```

任一依赖超时、模型不可用、低置信、unknown、政策过期或 grant 争议都进入 `quarantined`，不会沿用 Run 开始时的旧结论。所有用户查询再次应用相同当前态过滤，避免已撤销内容通过详情、缓存或搜索泄漏。

## 6. 隐私与内容安全

1. MVP 默认不采集 `user_name`、handle 或作者 ID；普通 hash 仍是可关联的假名化数据，不视为匿名。如业务必须保留，需独立处理依据、目的、TTL、权限与 DSAR 映射，并使用隔离密钥 HMAC。
2. 获准保留的 raw prompt 仅限受控后台；展示/Embedding 前执行 PII 检测与必要脱敏。图片中的可识别人像也属于隐私评审对象，不做人脸识别或身份推断。
3. MVP 确定完全拒绝成人/性内容。来源自带 NSFW 分数只作不可信特征；检测器、阈值、taxonomy 和 policy 均版本化。
4. 检测不可用/低置信，或年龄不明且带性内容时，进入受限隔离：不生成缩略图、转码、Embedding，不进入普通审核队列。
5. 任何网络采集前必须由用户确认主要运营法域与法务负责人，并完成疑似 CSAM/违法内容的报告、证据最小化、legal hold 和受限访问 SOP；缺失时来源不得激活。

## 7. Fetch 与 SSRF 安全

- 只允许来源白名单 HTTPS/443，禁止 URL userinfo、自定义 Host/DNS、非标准 IP 表示和用户提供 URL；最多 3 次 redirect，每跳重新规范化与授权。
- DNS 解析结果必须在 connect time 重新校验并 pin 到实际连接，或强制通过无内网路由的 egress proxy。阻断 loopback、RFC1918、link-local、CGNAT、multicast、reserved、IPv6 ULA、IPv4-mapped IPv6 和云 metadata。
- 跨 authority redirect 永不转发 Authorization、Cookie 或来源 secret。连接超时 5 秒、总请求 30 秒；metadata 响应默认上限 10 MiB，超限流式中止。
- 安全测试必须从目标服务侧证明未收到被阻断请求，覆盖 `127.0.0.1`、`169.254.169.254`、`::1`、`fc00::/7`、十进制 IP、DNS rebinding 与重定向到内网。

## 8. 媒体沙箱

- MVP 只接受 JPEG、PNG、静态 WebP；单文件 ≤20 MiB，宽/高各 ≤8192，总像素 ≤40 MP，frame 必须为 1，解码硬超时 15 秒。
- MIME 声明、魔数和实际解码格式必须一致；SVG、PDF、GIF、动画 WebP、polyglot、畸形 ICC/EXIF 直接拒绝。Pillow `DecompressionBombWarning` 提升为 hard error。
- Decoder 运行在独立 no-egress、非 root、只读根文件系统沙箱，限制 1 CPU、1 GiB RAM、512 MiB 临时盘、32 PID；no-egress 指禁止公网但允许白名单私网 PostgreSQL/RabbitMQ/MinIO，不能与联网 Fetch Worker 共进程。
- 获准展示的派生图去 EXIF/XMP/GPS 后重编码；MinIO 服务端和浏览器签名 URL 均使用 TLS，display-derived CORS 只允许站点精确 Origin 的 GET/HEAD，禁止 List/写入，响应含 `X-Content-Type-Options: nosniff`，缓存 `max-age` 不超过最长 5 分钟的签名剩余期。

## 9. Prompt 与应用安全

prompt、DOM、alt、EXIF、C2PA/其他元数据全部是数据而不是指令；UI 只按纯文本转义，禁止原始 HTML、Markdown、data URI 和任意图片代理。若后续加入 LLM enrichment，模型运行时不得拥有工具、网络、凭据或内部检索越权能力，输入用结构化 data block，输出必须通过严格 JSON Schema，否则隔离。

## 10. Notice、删除与防复活

`notice_cases` 覆盖 rights/privacy/illegal/source_deleted/license_revoked，含法域、申诉、legal hold 和证据；它向 `deletion_jobs` 扇出，`UNIQUE(case_id, target_type, target_id)`，每个任务记录 `queued/running/succeeded/failed/held`、attempt、receipt、last_error 与告警。

目标至少包括 MinIO raw/quarantine、original/variants、DB display state、全文/向量、CDN、应用缓存、Embedding provider、export/第三方接收方和备份 suppression。来源 404/410/API 删除、政策/许可撤销触发同一流程；近似去重内容按 observation/grant 决定删单一成员还是整个 canonical group。快照只能恢复到不挂载在线端点的 recovery namespace；先用当前 suppression/deletion ledger 与有效 `object_ref` allowlist 清除已撤销/无引用 key 并生成 receipt，随后才能提升其余对象，未经清洗副本仍按备份在 30 天内删除。

除合法 legal hold 外：公共/内部用户面与 CDN 5 分钟内不可见，在线字节、索引、缓存和第三方删除请求 24 小时内完成，备份恢复立即应用 suppression，备份字节在 30 天内到期或 crypto-shred。失败任务持续重试并告警；恢复演练必须证明已下架内容不会复活。

## 11. 接受门禁

1. DG-01：运营法域、controller/processor、法务与安全负责人、第三方/跨境和保存期已签字确认。
2. DG-02：每个本阶段拟激活来源具备独立 ToS、robots、授权证据和 action-scoped access decision；Civitai 不属于 MVP/S0-S6，须另起 Design/PRD 并通过独立激活门禁。
3. DG-03：rights/grant schema 可证明同图不同许可、同 prompt 不同作者不会误合并或越权发布。
4. DG-04：raw 临时/持久、metadata/media 两阶段和 policy 变化复审有可执行状态与 TTL 测试。
5. DG-05：PII 检测、展示脱敏、无作者采集默认值、DSAR/删除映射通过隐私评审。
6. DG-06：成人完全拒绝、年龄不明隔离、检测失败和违法内容 SOP 已用 fixtures 演练。
7. DG-07：SSRF、媒体炸弹/格式欺骗和 prompt injection fixtures 全部 fail-closed。
8. DG-08：每个 publish/index/embed 路径都验证当前 access、grant、PII、moderation、suppression。
9. DG-09：notice fan-out、receipt、SLA、许可撤销与备份恢复 suppression 演练通过。
10. DG-10：来源级/全局 kill switch、密钥隔离、审计、告警与事故响应可用。
