## 2. 设计门禁

当前需求事实源为 [CUR 当前需求集](../requirement/README.md)。Requirement 接受前，Design 可以用于发现冲突和开放问题，但不能自行为用户增加范围、固定未确认阈值或触发代码实施。

设计必须明确：

- 问题、范围和非目标；
- 模块职责、所有权与依赖方向；
- 领域身份、不可变版本、状态机和不变式；
- 命令、查询、事件和文件交接；
- 并发、幂等、部分失败、重试、取消和恢复；
- 权限、权利、媒体安全、成本和可观测性；
- Requirement/AC 追踪及仍未关闭的决策。

新模块化分析产生的 Design 必须保留并按当前顺序登记；只有无法回链 CUR ID、仍绑定旧 MVP/剪辑成片范围的历史 Design 才属于清理对象。
