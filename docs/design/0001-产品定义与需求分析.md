## 1. 结论

1. Lanverse 是一条**以剧本为起点、以可发布成片为终点**的 AI 短剧生产线。画布是这条生产线的操作界面之一，不是产品本身。
2. 核心价值排序：**一致性 > 可控性 > 成本透明 > 生成质量**。生成质量主要由第三方模型决定，前三项才是平台能建立的壁垒。
3. 首要客户是短剧 / 漫剧工作室（B 端）。个人创作者模式从 B 端产品裁剪得到，不单独设计。
4. MVP 交付标准只有一个：**用户上传一集剧本，在平台内完成全部步骤，导出一条带对白和字幕、可直接发布的 MP4**。

## 2. 问题与机会

### 2.1 行业现状【推断】

- 竖屏短剧单部通常 60–100 集以上、单集 1–3 分钟，追求高频上新和低成本试错。
- 真人拍摄成本高、周期长；AI 适合低成本试拍、IP 验证，以及漫剧、动态漫、风格化短剧等品类。
- 当前 AI 制作链路割裂：大模型写剧本 → 生图工具定角色 → 视频模型逐镜头生成 → 配音工具 → 剪辑软件。素材在 5–8 个工具间手工搬运。

### 2.2 用户真正的痛点

| 痛点 | 表现 | 平台能做什么 |
| --- | --- | --- |
| 一致性差 | 同一角色换镜头就换脸，服装、场景漂移 | 锁定参考资产，生成时强制带入；跨镜头一致性检查 |
| 不可控 | 抽卡式生成，镜头语言难以符合分镜；改一处要全部重来 | 结构化分镜 + 关键帧先行 + 单镜头局部重做 |
| 流程断裂 | 多工具搬运素材、版本混乱 | 一个项目内贯通，所有产物有版本和来源 |
| 成本失控 | 视频生成贵，重试和重复购买难追踪 | 生成前报价、执行前预留、按镜头归集成本 |
| 协作困难 | 编剧、导演、美术、剪辑之间靠聊天软件传文件 | 角色分工、审阅确认、批注 |

### 2.3 竞品格局【待确认：需逐一实测】

| 类型 | 代表 | 强项 | 缺口（我们的机会） |
| --- | --- | --- | --- |
| 画布式 AI 创作 | LibTV、Flora、Weavy、Krea Nodes | 自由探索、多模型聚合 | 对“整集 / 整部剧”的结构化生产支持弱，资产与版本管理浅 |
| 节点式工作流 | ComfyUI | 可控性极强 | 门槛高，缺少剧本层与协作 |
| 单点 AI 视频 | 即梦、可灵、海螺、Vidu、Runway | 生成质量 | 以单镜头为单位，没有从剧本到成片的流程 |
| 垂直短剧 / 漫剧工具 | 若干创业产品 | 模板化流程 | 可控性和一致性有限，被模板锁死 |

**差异化定位：** 剧本驱动的结构化生产线 + 画布式自由创作，两者共享同一份项目资产图谱。

## 3. 目标用户

| 画像 | 特征 | 核心诉求 | 优先级 |
| --- | --- | --- | --- |
| A. 短剧 / 漫剧工作室 | 5–50 人，编剧、导演、美术、剪辑、制片分工 | 量产、一致性、审批协作、成本可控 | **首要** |
| B. 个人创作者 | 网文作者、自媒体 | 快速出片、低门槛 | 次要，A 的简化模式 |
| C. 版权方 / 平台方 | IP 持有者 | 批量试拍、验证 IP | 远期 |

**产品内角色（A 类客户）：** 制片（项目、预算、进度）、编剧（剧本与解析校对）、美术（角色 / 场景定稿）、导演（分镜、选图、选片）、剪辑（时间线与交付）。MVP 允许一人兼任全部角色。

## 4. 核心场景（用户旅程）

1. **从零到第一集**：上传剧本 → 确认分集分场 → 确认角色 / 场景 / 道具清单 → 定妆定景 → 确认分镜 → 选关键帧 → 选视频片段 → 试听配音 → 微调剪辑 → 导出。
2. **改一个角色**：修改主角造型后，系统列出受影响的镜头和重做预估费用，用户选择重做哪些。
3. **单镜头重拍**：第 7 镜动作不对，只重做这一镜，其他镜头保持不动。
4. **续集生产**：第 2 集直接复用第 1 集已定稿的角色与场景。
5. **画布探索**：导演在画布上围绕一个关键镜头试 5 种风格，选定结果回写正式分镜。
6. **中断恢复**：生成过程中关闭浏览器或服务重启，回来后任务继续，不重复扣费。

## 5. 端到端工作流

每个阶段遵循同一模式：**AI 产出候选 → 人工审阅 / 修改 → 选定为正式版本**。正式版本不可变，修改产生新版本。

| # | 阶段 | 输入 | AI 做什么 | 人工确认 | 正式产出 |
| --- | --- | --- | --- | --- | --- |
| 1 | 剧本导入 | txt / docx / pdf，或一句话创意 | 格式规范化；创意扩写为剧本（后置） | 可选 | 剧本版本（带内容 hash） |
| 2 | 结构解析 | 剧本版本 | 分集、分场、节拍；抽取对白、动作、情绪、时间地点 | ✅ | 集、场、台词行（可追溯到原文位置） |
| 3 | 资产抽取 | 场次 | 识别角色、场景、道具、造型；合并别名；记录状态变化（受伤、换装） | ✅ | 设定集：角色 / 造型 / 场景 / 道具 |
| 4 | 视觉定稿 | 设定集 + 项目风格 | 定妆照、三视图、表情、场景概念图 | ✅ **关键** | 锁定的参考资产版本 |
| 5 | 分镜设计 | 场次 + 资产 | 拆镜头；景别、机位、运镜、时长；分配台词；标注所需参考 | ✅ 逐镜可编辑 | 镜头表 |
| 6 | 关键帧 | 镜头 + 参考资产 | 生成首帧（必要时尾帧） | ✅ 选图 | 选定关键帧 |
| 7 | 视频 | 关键帧 + 运动描述 | 图生视频，每镜多候选 | ✅ 选片 | 选定片段（实测时长） |
| 8 | 声音 | 台词 + 角色音色 | 对白 TTS、音效、BGM；字幕时码 | ✅ 试听 | 音轨、字幕 |
| 9 | 剪辑 | 片段 + 音轨 + 字幕 | 自动粗剪：按镜头顺序、对白对齐 | ✅ 微调 | 剪辑计划 |
| 10 | 交付 | 剪辑计划 | 渲染、写入 AIGC 标识、技术质检 | ✅ 终审 | 成片版本（MP4 + 字幕 + 清单） |

**三条贯穿规则：**

1. **依赖传播**：上游版本变化，下游产物标为“过期”，**不自动重新生成**（会产生费用）；系统给出影响范围和预估费用，由用户决定。
2. **候选 / 选定 / 正式分离**：所有 AI 结果先是候选，人工选定后才被正式对象引用；旧版本全部保留可查。
3. **局部重做**：任何失败或修改只影响其真实依赖，其他镜头不受影响。

**成本设计原则【推断，P0 实测校准】：** 视频生成是最大成本项，重拍率是最大成本杠杆。因此关键帧确认必须先于视频生成，越早的人工确认越省钱。

## 7. 非功能需求

以下为初始目标值，上线后按实测数据校准。

| 类别 | 需求 |
| --- | --- |
| 可用性 | 核心 API ≥ 99.5%；供应商故障时，已完成内容可读可编辑 |
| 性能 | 页面首屏 < 2 s；任务状态推送延迟 < 2 s；画布 500 节点（300 图 / 40 视频）平移缩放 ≥ 50 fps |
| 可靠性 | 任何生成任务在服务重启、断线后可恢复；**同一请求绝不重复扣费**；供应商成功但下载失败时只重试下载 |
| 一致性 | 同一角色跨镜头相似度达到阈值【待确认：P0 确定评估方法和阈值】 |
| 成本 | 每次模型调用可追溯到项目 / 集 / 镜头；单分钟成片成本可统计 |
| 可扩展 | 新增一个模型供应商 ≤ 3 人天，不改业务代码 |
| 安全 | 租户隔离；供应商密钥只在服务端并加密存储；媒体通过短期签名地址访问 |
| 合规 | AIGC 显式与隐式标识；输入输出内容审核；肖像 / 声音授权留证；数据出境评估 |
| 可观测 | 模型调用全量记录（模型、版本、参数 hash、耗时、费用、结果）；结构化日志与链路追踪 |

## 8. 合规要求【待确认：须法务审阅】

- **AIGC 标识**：依据《人工智能生成合成内容标识办法》（2025-09-01 起施行）为成片添加显式标识与隐式标识（元数据）。
- **备案**：确认使用第三方大模型时，算法备案与深度合成备案的责任划分。
- **内容审核**：剧本输入与生成输出双向审核，拦截违法违规与侵权内容。
- **肖像与声音**：上传真人参考、使用特定音色需有授权流程并留证。
- **版权**：剧本来源由用户声明并承担责任；平台保留侵权投诉处理流程。

## 9. MVP 边界

**MVP 包含：** 第 5 节全部 10 个阶段的最小实现 + 6.x 中标记为 M 的功能，使用流水线视图，单人可完成。

**MVP 明确不做：** 画布、多人协同、AI 画布助手、口型同步、声音克隆、3D 导演台、模型市场、自动选择模型、支付套餐、开放 API、剪辑工程导出。

**MVP 完成定义：**

1. 种子用户上传一集 1–2 分钟的剧本，在平台内独立完成全部阶段，导出可发布的 MP4。
2. 成片中角色外观跨镜头一致，对白完整可听，字幕时码正确，带 AIGC 标识。
3. 修改一个角色造型后，只重做用户选中的受影响镜头；旧版本可查。
4. 过程中断线或服务重启，任务恢复且无重复扣费。
5. 每集成本可按镜头查看。

## 10. 成功指标

| 类型 | 指标 |
| --- | --- |
| 北极星 | 每周交付的合格成片分钟数 |
