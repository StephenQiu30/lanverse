## 结论

本轮只运行一个公共 Go Backend 和一个私有 Python Agent Runtime：

```text
Browser → lanverse-api → PostgreSQL
                    ├→ MinIO
                    └→ agent-runtime（私有 Candidate API）→ 本机 Codex CLI
```

- `lanverse-api` 拥有认证、项目、剧本文档、Production Bible、分集、结构、分镜、正式 Shot、导出和任务状态的全部业务写入权。
- PostgreSQL 是唯一 SQL 事实源；Backend 只打开一个 `DATABASE_URL`。
- `agent-runtime` 不连接 PostgreSQL、MinIO 或公共业务 API，只校验 Backend 签发的短时 Execution Grant，执行严格结构化 Codex 调用并返回 Candidate/Proposal。
- 长任务由 Go Backend 中的持久任务领取器处理；领取、状态、重试身份和结果回执都保存于 PostgreSQL。进程重启后重新领取未完成任务，不引入 Temporal、第二个 Worker 服务或通用工作流平台。
- MinIO 只保存文档与导出字节；对象元数据、Hash、状态和业务引用仍由 Backend 写 PostgreSQL。

Kafka、Redis、Temporal、Elasticsearch、多 Go Binary、gRPC 和通用 Agent 平台均不是本轮 MVP 的运行依赖。现有 Compose 中未被 Backend 依赖的基础设施不能计入服务可用性，也不能成为核心旅程的前置条件。

## 模块与依赖

业务模块按以下方向组织：

```text
HTTP / Worker Adapter
        ↓
Application（授权、事务、幂等、状态门禁）
        ↓
Domain
        ↑
Port ← GORM / MinIO / Agent Adapter
```

- `backend/internal/access`：身份、Session、Workspace。
- `backend/internal/media`：对象声明、预签名上传、完整性校验、媒体版本。
- `backend/internal/production`：Project、Script、Bible、Episode、Structure、Storyboard、Shot、Export。
- `backend/internal/agent`：Invocation、Execution Grant、Candidate Client 和持久领取器；不拥有 Production 事实。
- `backend/internal/platform`：数据库连接、唯一 Model Catalog、事务、Command Receipt、HTTP 错误、校验和对象存储客户端。
- `agent/`：Candidate Schema、Codex Harness、私有 API；不得出现业务 Repository、SQLAlchemy Model、数据库驱动或公共业务 Router。

Domain、Application 与 HTTP Handler 禁止导入 GORM。跨业务模块只依赖对方公开的 Application Port 或由调用方定义的窄接口，不能直接查询另一模块的表。

## 公共与内部契约

| 契约 | 唯一事实源 | 规则 |
|---|---|---|
| Browser REST/JSON | `backend/api/openapi/lanverse-v1.json` | Go 路由实现；Frontend 只从该文件生成类型 |
| 公共错误包络 | OpenAPI + `backend/internal/platform/httpapi` | `{error:{code,message,request_id,next_action,details}}` |
| Backend → Agent Invocation | `backend/internal/agent/contract` | Backend 拥有版本化线协议；请求只包含冻结输入、输入哈希、Schema 版本和 Invocation ID |
| Agent → Backend Result | `backend/internal/agent/contract` + `agent/app/candidate_runtime/schemas.py` | Agent 用禁止额外字段的 Pydantic 模型校验并回显绑定字段，只返回 succeeded/failed/unknown 与严格 Candidate；Backend 再校验身份、结果哈希和状态组合 |

内部 Agent 请求使用 JSON/HTTP，而不是为两个本地服务引入 Protobuf/gRPC 生成链。Backend 以 `HMAC-SHA256` 签发短时 Grant，Grant固定 `invocation_id`、`kind`、`input_hash` 和过期时间；Agent 使用恒定时间校验并拒绝范围外输入。共享密钥不进入请求体、日志、数据库结果或公共 API。

契约变更顺序为 `Design → Go 线协议/Python 严格消费模型 → compatibility test → implementation → integration`。线协议版本只由 Backend 所有；Python 不得扩展未经 Backend 接受的状态或字段。Codex Candidate 的业务输出 Schema 则由各 Candidate 模块的严格 Pydantic 模型生成，不另存一份无人消费的根目录 Schema。

## 数据库工具与唯一 Schema 源

Backend 依赖版本固定在 `backend/go.mod`：

| 能力 | 选型 | 固定版本 | 使用边界 |
|---|---|---:|---|
| ORM 与事务 | `gorm.io/gorm` | `v1.31.2` | GORM Adapter、数据库组合根 |
| PostgreSQL Driver | `gorm.io/driver/postgres` | `v1.6.2` | 唯一 `DATABASE_URL` |
| JSONB | `gorm.io/datatypes` | `v1.2.7` | Snapshot、Receipt、Candidate、任务载荷 |
| 精确金额 | `github.com/shopspring/decimal` | `v1.4.0` | Budget 的 `NUMERIC` 映射 |
| UUID | `github.com/google/uuid` | `v1.6.0` | ID 和 GORM Record |
| 请求校验 | `github.com/go-playground/validator/v10` | `v10.30.3` | HTTP DTO 基础格式；领域规则仍在 Application/Domain |
| JWT | `github.com/golang-jwt/jwt/v5` | `v5.3.1` | Access Token |
| 密码哈希 | `golang.org/x/crypto/bcrypt` | `v0.55.0` | 密码单向哈希 |
| CORS | `github.com/rs/cors` | `v1.11.1` | 公共 API CORS |
| 对象存储 | `github.com/minio/minio-go/v7` | `v7.3.0` | 预签名、完整性读取与导出对象 |

数据库只有一份结构定义：`backend/internal/platform/database/model` 中的 GORM Record Catalog。

1. `schema.Sync` 对 Catalog 执行 GORM 非破坏性同步。
2. 仓库不保留手写 SQL Schema/Migration、迁移版本/Checksum/Source 字段、迁移元数据表、迁移 Binary 或第二数据库 DSN。
3. 常规 CRUD、关联、计数、事务和行锁使用 GORM API/Clause；只有 GORM 无法表达且有失败测试证明的 PostgreSQL 能力才能在 Adapter 局部使用参数化 SQL。
4. MVP 没有历史生产数据搬迁；开发和验收从独立空库启动。真实生产数据搬迁成为明确需求前，不预建迁移框架。
5. 写命令在一个事务内完成 Owner 聚合、Command Receipt、Audit/Task/Invocation 状态；重复键返回同一结果，同键异参返回冲突。

选择 GORM 是因为当前闭环需要成熟 ORM、事务、行锁、关联、复合索引、JSONB 和空库同步。Ent/Atlas、GORM Gen、Bun 与 sqlc 会增加另一份 Schema/DAO/SQL 事实，不进入本轮。

## 对象存储

- Bucket 保持私有，Browser 使用短时 Presigned URL 直传。
- Backend 完成声明大小和 SHA-256 双校验后才登记不可变 `MediaVersion`。
- MinIO CORS 使用服务级 `MINIO_API_CORS_ALLOW_ORIGIN`；Backend 不调用当前社区版不支持的 Bucket CORS API。
- 公开签名地址与 Backend 内部地址分离，并显式固定 `MINIO_REGION`，避免预签名阶段从容器回连公开地址。
- Markdown/DOCX 内容由 Backend 在授权后读取；对象字节不进入 PostgreSQL。

## 持久任务与 Agent 失败语义

1. 创建 AI 业务资源时，Backend 同事务写入业务聚合、`WorkflowTask` 与 `AgentInvocation`，状态为 `queued`。
2. 单个 Backend 进程使用 PostgreSQL 行锁领取任务并标记 `running`；同一 Invocation ID 只允许一个有效领取者。
3. Agent 只能返回 `succeeded`、`failed` 或 `unknown`。Backend 对 Candidate 重算输入引用、确定性门禁和结果哈希后，才把业务资源置为 `needs_review`。
4. `failed` 保留稳定错误码和恢复动作；传输中断或进程结果不确定进入 `unknown`，不自动当作确定失败创建第二份业务结果。
5. 人工 `confirm/approve/apply` 使用独立 Command Receipt、expected revision/hash 和数据库事务。Agent 成功永远不能直接创建正式事实。

本轮不实现多节点 lease/heartbeat/Temporal History。单进程任务领取、稳定 Invocation ID、幂等结果提交和重启后重新领取构成 MVP 可恢复闭环；需要横向扩容或数小时分阶段续租时，再以独立 Design 引入租约协议。

## 运行与安全门禁

- `healthz` 只证明 Go 进程存活；`readyz` 检查 PostgreSQL 与 MinIO，返回通用依赖失败而不伪装就绪。
- Agent 不属于普通 CRUD 的启动依赖；创建 AI 任务时必须能形成明确 queued/running/failed/unknown 状态。
- Agent 容器/进程不接收 `DATABASE_URL`、MinIO 凭据、JWT 密钥或浏览器 Session。
- Codex 调用固定 `--ephemeral --sandbox read-only --output-schema`，不授予业务写工具；未配置 model 时继承本机 Codex 配置。
- 日志不得记录 JWT、Refresh Token、Execution Grant、数据库密码、对象存储密钥、预签名完整 URL 或原稿全文。
- 最终目标拓扑只启动 Frontend、Backend、PostgreSQL、MinIO 与私有 Agent；全部自动化通过后才使用 `agent-browser` 执行浏览器最终验收。

## 非目标

- 不在 MVP 预建微服务、兼容代理、迁移平台、通用工作流引擎、Provider Registry、跨域 Tool Registry 或第二套 ORM。
- 不让 Agent 承担认证、项目、剧本、Bible 确认、分集、结构、Storyboard、Shot、导出或任务状态的写入。
- 不以历史 Python Writer、pgx Repository、模型桩或旧浏览器证据证明目标架构通过。
