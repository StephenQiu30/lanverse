# DES-010 镜头检查、快照与素材包导出设计

- 状态：proposed
- 版本：v1.0
- 日期：2026-08-14
- 关联需求：CUR-EXP-FR-001～009、CUR-EXP-NFR-001～011
- 关联验收：AC-CUR-EXP-001-A～AC-CUR-EXP-009-B
- 上游：[CUR-EXP](../requirement/009-镜头检查与素材包导出需求.md)、[DES-009](./009-视频生成候选与主选设计.md)

## 1. 问题、范围与非目标

Exports 模块让用户按目标 StoryboardBaseline 检查每个镜头，明确选择 complete 或 partial 范围，原子冻结顺序、ShotSpec、VideoSelection、Candidate 和原始媒体字节版本，再构建可追溯素材包。包是独立原始视频集合，不是连续成片。

范围：逐镜检查、修复导航、范围、Preflight、ExportSnapshot、PackageBuild、ZIP64、JSON/CSV/README Manifest、历史、重下、过期重建。

非目标：重新生成/自动选择 Candidate、视频裁切/拼接/转码、字幕/音频、Timeline、单一成片 MP4、剪映/Premiere 工程、发布投放。

## 2. 事实所有者与模型

| 实体 | 含义 | 版本/所有权 |
| --- | --- | --- |
| ShotInspectionReport | 目标 Baseline 下有序 Shot、主选、媒体和问题 | 可重建派生报告 |
| ExportScope | `complete` 或明确非空 `partial` Shot 子集 | Snapshot 内固定 |
| ExportPreflight | blocker/warning、规模、权利和输入摘要 | 短期不可变、有效期 |
| ExportSnapshot | Baseline/Order、Scope、有序 Shot、Spec、Selection、Candidate、MediaVersion/hash、reconfirmation/warning、actor/time | 创建即 frozen，不可变 |
| ExportSnapshotEntry | 每个 package order 的全部固定引用和文件名输入 | 不可变 |
| ExportPackage | 用户可理解的一次导出身份，可有多个 Build | 稳定 |
| PackageBuild | 一次真实包构建、对象版本、container hash、retention | 不可变 build 记录 |
| ExportFileEntry | 包内 path、source Media、size/hash/type | 不可变 |

Exports 不拥有 VideoSelection/Media；Snapshot 只固定引用并创建媒体保留引用。

## 3. 检查与范围

- Inspection 必须按目标 Baseline 的 OrderRevision 显示，而非临时工作区顺序。
- 每 Shot 返回 selected Candidate、媒体状态、input match/reconfirmation、权利和修复路由。
- `complete` 精确等于目标 Baseline 全部 active Shot。
- `partial` 精确等于用户明确勾选的非空 active Shot 子集；Manifest/README 列 included/excluded 数量与 ID，绝不暗示整集完成。
- 筛选只改变视图，不改变 ExportScope；范围确认必须展示总镜数、总字节和警告。

## 4. Preflight 与原子冻结

Preflight 固定以下摘要并设有效期：

- Baseline/Order revision 和 Scope hash；
- 每 Shot current ShotSpecVersion、VideoSelection revision、Candidate 和 MediaVersion/hash；
- Selection 与当前输入匹配/reconfirmation；
- Media ready/size/type/video track；
- 权限、权利、包规模、命名冲突、保留策略；
- warning 确认和 blocker 列表。

Freeze 使用一个数据库事务：

1. 锁定/验证目标 Baseline、Scope、各 current Selection revision 和媒体引用；
2. 重新执行当前时点 Workspace/rights 检查；
3. 验证 Preflight input hash 未过期；
4. 创建 ExportPackage、不可变 ExportSnapshot/Entry 和 MediaRetentionReference；
5. 创建 requested PackageBuild 和 StartWorkflow Outbox；
6. 任一冲突/阻断则零 Snapshot、零 Build、零隐藏媒体替换。

对象存储不参与该事务；冻结只固定已 ready 的 MediaVersion 和保留引用，异步 Build 后续读取。

## 5. 同步命令与查询

| 能力 | 输入 | 结果 |
| --- | --- | --- |
| GetInspection | Episode、目标 Baseline、筛选 | 有序 Report、汇总、partial failure |
| GetShotIssue | Shot、Selection | 来源、播放状态、问题和 Videos 修复路由 |
| PreflightExport | Baseline、complete/Shot ID 子集 | ready/warning/blocked、规模、input hash、有效期 |
| FreezeExport | 有效 Preflight、expected revisions、确认、幂等键 | Snapshot + PackageBuild ID 或零写入冲突 |
| GetExportHistory | Episode、权限、分页 | Package/Snapshot/Build、hash、retention、状态 |
| RequestDownload | ready Build、当前 actor | 短期下载能力或过期/权限错误 |
| RebuildFromSnapshot | Snapshot、明确意图、幂等键 | 新 PackageBuild 或缺失 Media 清单 |

重复 Freeze 同一幂等键/同输入回读原 Snapshot/Build；同键异输入冲突。普通重下载不创建新 Build。

## 6. 异步 PackageBuild

```text
requested → validating → frozen → packaging → ready → expired
              └→ failed        └→ failed
```

`frozen` 表示 Worker 已重新确认 Snapshot/保留引用可读，不是新 Snapshot。Build 只读取 SnapshotEntry：

1. 逐项验证固定 MediaVersion object/version、size、SHA-256；
2. 按 package order 生成确定命名；
3. 生成 UTF-8 `manifest.json`、兼容常见表格工具的 `manifest.csv` 和 `README.md`；
4. 使用 ZIP64 将每个原始视频逐字节写入唯一 private object key；不裁切、拼接、转码或剥离音轨；
5. 流式计算 container SHA-256 和 size；
6. HEAD/读取校验对象存在后，数据库事务写 FileEntry/Build object version/hash 并标 ready；
7. ready 前不签发下载 URL；失败对象由受控 GC 清理。

对象存储 multipart ETag 不作为内容 hash。为避免 20 GiB 包的二次复制，Build 从一开始写不可预测唯一 key；“发布”由数据库 ready 状态控制，而不是公开 ACL/对象重命名。

## 7. 包结构与 Manifest

```text
<project>-<episode>-<export-id>/
├── 001_<shot-label>_<candidate-short-id>.<original-ext>
├── 002_<shot-label>_<candidate-short-id>.<original-ext>
├── ...
├── manifest.json
├── manifest.csv
└── README.md
```

- 三位 `package_order` 前缀；同包路径唯一；非法字符用确定规则规范化。
- 原文件名只存 Manifest，不作为身份；路径不得含 Token、Provider key 或 Prompt。
- JSON/CSV/README 的 Export ID、scope、镜头数、冻结时间一致。
- JSON/CSV 每行的 package/episode order、Shot、Spec、Selection、Candidate、Media hash 和 path 一致。
- 包内不得有未列文件，Manifest 不得列缺失文件。
- `complete`/`partial` 明确标识；备选 Candidate 不进包。

## 8. 历史不漂移与重建

冻结后重排、重选、生成新 Candidate、权利变化和媒体 current 变化都不修改 Snapshot/旧 Build。

- 同一 ready Build 重下载同一对象版本，container hash 相同。
- Build expired 但 Snapshot 固定媒体仍存在时，可新建 Build；Manifest 语义与逐文件 hash 相同，ZIP metadata 可能令 container hash 不同。
- 固定 MediaVersion 缺失/hash 不符时重建 failed 并列清单；不得换 current Candidate。
- 权利后续撤销不篡改历史事实，但新下载/重建按当前政策 fail-closed 并显示人工处置。

## 9. 失败与恢复

| 失败 | 行为 | 恢复 |
| --- | --- | --- |
| 缺主选/stale/blocked | Preflight blocked 并定位 Shot | 跳 Videos 修复，不兜底 |
| Freeze 前顺序/主选/权利变化 | 零 Snapshot 冲突 | 重新检查和 Preflight |
| Freeze 后 current 变化 | Build 继续读 Snapshot | 无需恢复；新状态需新 Export |
| 固定媒体丢失/hash 不符 | Build failed，列 Entry | 恢复同一媒体字节；不换 Candidate |
| Worker/进程中断 | Task 按同一 Snapshot/Build 恢复 | 已写字节可按安全 checkpoint 继续或重建同 Build object |
| 部分文件写失败 | 不标 ready | 重试同 Build 或 failed 后新 Build；无残包发布 |
| 下载中断 | ready 对象不变 | 重新签 URL/HTTP range，不新建 Export |
| 包过期 | 历史 Snapshot/Manifest 仍可读 | 允许时从同 Snapshot 新 Build |

## 10. 权限、安全与内容治理

- owner/editor 检查、Preflight、Freeze、重建和下载；viewer 只读历史与 Manifest 摘要，不得下载原始候选或素材包（CUR-PRJ-OQ-004 已关闭）。
- Freeze 和下载分别按当前 Membership/Workspace 检查；冻结权限不形成永久公开链接。
- 包/Manifest 不含凭据、签名 URL、内部诊断、完整 Prompt 或权利证明正文。
- 对象全部 private，下载 URL 极短 TTL、绑定 disposition/用途；高风险场景可通过代理下载。
- AIGC 来源/交付标识由 DES-013 `ProvenanceLabelDecision` 固定到 ExportSnapshot；它只能增加 Manifest/README 等已签认字段，不得修改原始视频字节。首发地区、用途或政策未关闭时，正式交付保持 fail-closed 或展示明确 blocker。
- ZIP 文件名和 CSV 字段执行注入防护；CSV 以可能触发公式的前缀安全转义并在 README 说明。

## 11. 可观测性

- Inspection/Preflight/Freeze 延迟、blocker 分类、revision 冲突；
- Build queue age、文件/字节进度、心跳、throughput、失败阶段和重建；
- Snapshot/Entry/Media/Build/container hash 关联；
- 下载签发、Range、失败、过期和越权；
- packaging 每 10 秒提供真实进度或心跳，不按时间伪造百分比；
- Metric 不用 Export/Shot/Media ID 作标签。
