本文把 [REQ-32](../requirement/32-成本账本与报表.md) 拆解为实现设计。需求目标、业务规则（文中 R1、R2… 指 REQ-32 §2 的规则）与验收标准以 REQ-32 为准；表结构以 [DES-02](02-领域与数据模型.md)、接口签名以 [DES-03](03-接口设计.md)、工作流与生成操作以 [DES-04](04-工作流与生成操作.md) 为准，本文说明该功能用到哪些部分、如何组合。设计发现需求问题时先改需求（[文档规则](../README.md#文档规则) 2）。

## 1. 设计清单

| 类别 | 内容 |
| --- | --- |
| 数据表 | `billing.cost_summary`、`billing.ledger_entry`、`billing.reconciliation_run` |
| 接口 | `GET /api/projects/{pid}/costs`<br>`GET /api/projects/{pid}/ledger`<br>`POST /api/admin/ledger:adjust`<br>`GET /api/admin/costs` |
| 工作流与任务 | `LedgerReconcileSchedule` |
| 领域事件 | `billing.reconciliation_diff.v1` |
| 测试用例 | TC-32-xx（[TST-02](../test/02-需求追踪矩阵.md)） |

## 2. 数据

| 表 | 关键字段 | 为什么需要 |
| --- | --- | --- |
| `billing.ledger_entry` | `entry_type`、`amount_micros`、`operation_id`、`episode_id`、`shot_id`、`model_key`、`region`、`orig_*` | 明细 |
| `billing.reconciliation_run` | `run_date`、`status`、`diff` | 对账 |
| 新增 `billing.cost_summary` | `project_id`、`episode_id`（可空）、`model_key`（可空）、`capability`、`settled_micros`、`operation_count` | 汇总读模型（DES-02 同步） |

## 3. 接口

```http
GET /api/projects/{pid}/costs?group_by=episode
200 { "total_settled_micros": 1820000000, "total_reserved_micros": 12000000,
      "items": [ { "episode_id": "…", "seq_no": 1, "settled_micros": 360000000, "delivery_minutes": 2.0, "cost_per_minute_micros": 180000000,
                   "by_capability": { "video.generate": 300000000, "image.generate": 30000000, "audio.tts": 10000000, "text.structured": 20000000 } } ] }
GET /api/projects/{pid}/costs?group_by=shot&episode_id=…
GET /api/projects/{pid}/ledger?operation_id=&episode_id=&limit=
POST /api/admin/ledger:adjust  { "project_id": "…", "amount_micros": -500000, "operation_id": "…", "note": "供应商退款" }   （管理员）
GET /api/admin/costs?from=&to=&group_by=project|model|day
```

## 4. 异步与工作流

`billing-report` 消费者；`LedgerReconcileSchedule`（每日 02:00）。

## 5. 事件与实时

消费 `operation.completed/failed.v1`；发布 `billing.reconciliation_diff.v1`（告警）。

## 6. 界面

成本页：项目总览卡（已结算、预留、预算）、按集表格（费用、选定片段总时长、单分钟成本、按能力拆分）、镜头明细下钻、账本明细。

## 7. 权限与审计

制作者可查看；调整仅管理员，审计 `ledger.adjusted`。

## 8. 非功能要求

COST-01（100% 可归集）；COST-02（报价偏差）；REL-08。

## 9. 测试设计

汇总与全量重建一致性；对账差异检测。

## 10. 待确认

无。
