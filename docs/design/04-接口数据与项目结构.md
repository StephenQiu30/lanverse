# 接口数据与项目结构

## 1. 设计结论

FastAPI 路由元数据与 Pydantic 请求/响应模型是唯一可执行 HTTP 契约源；开发环境提供 `/docs` 与 `/openapi.json`，生产后缀配置默认关闭交互文档。`frontend/openapi2ts.config.ts` 由 `@umijs/openapi` 直接读取 `LANVERSE_OPENAPI_URL`，本地默认 `http://127.0.0.1:8000/openapi.json`；`serversPath` 直接指向 `frontend/src/`，利用生成器原生创建的 `api/`，把 DTO 与请求函数发布到 `frontend/src/api/`，不得再套 `services/` 或 `generated/`。仓库不保存 `backend/openapi/openapi.json` 中间副本；生成器先写临时根目录，再整体替换只含生成物的 `src/api/`，因此契约删除可清理过期文件且不会影响其他源码。`src/api/` 不得手改或放置手写请求接口。`frontend/src/store/backend-api.ts` 是唯一手写 RTK Query 缓存/轮询层，只调用 `src/api/` 生成函数，不复制 URL 或 DTO；`frontend/src/lib/request.ts` 是唯一 HTTP sender，页面不得直接调用生成函数。FastAPI 当前导出 OpenAPI 3.1，PLAN-03 必须证明锁定版本的 `@umijs/openapi` 能从真实 HTTP URL 消费契约；PLAN-09 再证明完整 exact-set 零漂移。任一步失败即阻断，不静默维护第二份降级 Schema。TaskEvent 和 TaskJob 是 PostgreSQL 内部恢复事实，不进入 OpenAPI。

参考项目的成熟职责按当前技术栈映射，不复制其 TypeScript/Electron 物理目录：

| 参考职责 | Lanverse 位置 | MVP 约束 |
| --- | --- | --- |
| `src/agents` | `services/` + `integrations/ai/` | Agent 用例进入服务层；模型 Registry/Adapter 进入集成层 |
| `lib/middleware/routes` | `core/`、`api/`、`api/routes/` | 不建立 `other`、运行时 `test` 路由或重复工具层 |
| `types` | Pydantic 契约 + `frontend/src/api/` | OpenAPI 原生生成 DTO/请求，不手写第二份前端类型或请求接口 |
| `socket` | 无对应目录 | MVP 只使用 Task 2 秒 HTTP 轮询，不引入 WebSocket |
| `scripts` | 根 Makefile + `backend/scripts/` | 根只编排标准命令；后端脚本只承担测试服务启动、契约校验等可重复验证，不生成静态 OpenAPI 副本 |
| `build/data/env` | 仓库外运行环境或工具忽略目录 | 不提交构建产物、模型、MinIO 字节、运行数据、env 或 secret |

数据库 Design 和 `database_design_ready` 通过后，PLAN-02 才可使用 uv 0.11.31 管理 Python 3.13.14 环境与锁文件，并使用 Setuptools 83.0.0 的标准 `package-dir = src`、显式 package discovery 和 `py-modules = [main, worker]` 构建直接 `backend/src/` 布局；不得生成或保留 `src/lanverse/` 包装层。前端使用官方 `create-next-app --skip-install`，移除生成器的 `ignoredBuiltDependencies`，把 pnpm 11 项目策略改成 `saveExact: true` 与仅允许 `sharp/unrs-resolver` 的 `allowBuilds`，并把模板 manifest 的全部直接依赖由范围改为 PLAN-02 指定的精确版本。随后安装并在 `frontend/` 执行锁定版本的 `shadcn init --yes --template next --preset nova --base radix`；结果必须是 `radix-nova`，且 `shadcn preset resolve` 必须返回 preset code `b2fA`/version `b` 和 Lucide，生成 diff/依赖 exact-set 不同即失败。把 `backend/README.md` 改为真实入口/命令说明，并让 `pyproject.toml` 只声明 `lanverse-api`、`lanverse-worker` 两个入口；保留 Next.js 框架 `AGENTS.md` 和 `.gitignore`，删除 `CLAUDE.md`、默认 README、示例页面/资产，不手工仿造脚手架文件。Unicode 15.1.0 的 `Scripts.txt`、digest 与许可证固定放在 `resources` package 路径，通过 `importlib.resources` 读取；边界黄金样本放 `backend/tests/fixtures/`，不依赖宿主 Unicode 数据漂移。

后端只保留一套技术分层，不为每个功能重复建立五层目录。`api/routes` 按 HTTP 资源拆分 `projects/sources/tasks/scripts/assets/storyboards/media/delivery`，只负责参数、Header、状态码和响应映射；`schemas` 保存 Pydantic HTTP/AI 契约；`services` 保存用例、事务与跨资源编排；`repositories` 保存参数化 SQL 与 Row Mapper；`domain` 只保存纯 Python 值对象和状态机；`workers` 保存 TaskJob 执行；`integrations` 保存 LangChain、MinIO SDK 与 FFmpeg Adapter。依赖方向固定为 `api → services → repositories/domain`，`workers → services/integrations`，禁止 `repositories → services/api` 和 `services → api`。`main.py:create_app()` 使用 FastAPI lifespan 与 Depends 完成装配且无 import-time I/O，配置只由 Pydantic Settings 在入口验证。

标准能力优先采用维护中的开源项目：HTTP/路由/依赖/lifespan 使用 FastAPI，校验与配置使用 Pydantic，数据库连接与迁移使用 asyncpg/Alembic，AI 适配使用 LangChain Core，S3 协议只使用 MinIO SDK，媒体处理使用 FFmpeg/ffprobe。只实现 Lanverse 独有的版本、确认、输入哈希、Task/Attempt 和 Adoption 规则，不自建通用 HTTP 客户端、Schema 生成器、对象存储 SDK、ORM、DI 容器或工作流 DSL。MVP 保留 `TaskJob` 是因为它与 SubmissionSnapshot/Attempt/TaskEvent 构成同事务的产品恢复事实；再叠加 Procrastinate/Taskiq 会形成第二套 Job 状态和额外 Schema，待不再要求单一 PostgreSQL 事实链时另行 Design，不在本次重构中双轨接入。

每个请求或 Job Handler 独享一个从 asyncpg pool 获取的 connection，事务由应用边界显式打开且不得跨外部网络调用。TaskJob runner 只负责领取、心跳、退避和分派，业务步骤进入对应 Handler；payload 带 release_version，旧版本 Handler 在非终态任务排空前保留。MinIO 同步 SDK 由 Adapter 在受控线程执行，不阻塞 asyncio 事件循环。`integrations/ai` 只含基于 `langchain-core` Port 的 Registry、版本化 profile、Provider Adapter 和确定性 Mock，Prompt/Schema/路由规则归拥有用例的模块；`integrations/minio` 是唯一对象存储实现。完整 `langchain` 与 `langgraph*` 不在依赖 allowlist；`LANGSMITH_TRACING/LANGCHAIN_TRACING_V2` 固定为 false，不装载 LangSmith key/endpoint，网络负向测试证明 Prompt 只可发往批准 Provider 域名。

| 模式 | 解决的问题 | MVP 边界 |
| --- | --- | --- |
| 六边形分层 + Repository | Domain 与 FastAPI/asyncpg/供应 SDK 解耦 | 不创建通用 BaseRepository；按聚合定义最小 Port |
| 显式事务 + TaskJob Lease | 业务事实、TaskEvent 与可恢复 Job 同事务提交 | Handler 明确事务边界，不使用全局 connection 或进程内队列 |
| Command/Query Handler | 写入不变式与读取投影分离 | 不引入进程内消息总线或完整 CQRS 平台 |
| Adapter + Strategy/Registry | 多 AI、MinIO 与 FFmpeg 可替换且可测试 | `AiModelRegistry` 只选择已批准不可变 profile，不自动 fallback |
| Composition Root/Factory | 两个入口共享显式装配 | 不使用 Service Locator 或第三方 DI 容器 |
| 显式状态机 + Job Handler | 限制状态迁移并恢复长任务 | PostgreSQL TaskJob 是唯一恢复来源；不引入工作流平台/Event Sourcing |

前端根 `app/layout.tsx` 只挂载 `app/providers.tsx`；后者是唯一 React-Redux Provider 装配点，并用 `makeStore()` 为应用实例创建 Store，不在 Server Component 或模块级共享可变 Store。`components/ui/` 只保存 shadcn 生成和受控扩展的 Radix 基础组件；Feature 通过该层组合，不散落直接调用底层 Primitive。

## 3. 逻辑数据与哈希

数据库物理设计的唯一来源是[06 数据库表与迁移设计](06-数据库表与迁移设计.md)。`lanverse` 应用表 exact-set 固定为 20 张（19 张六模块业务事实表 + 1 张根基础设施拥有的幂等技术表 `idempotency_records`）：`projects/episodes/source_revisions/script_versions/creative_asset_versions/shot_spec_versions/idempotency_records/submission_snapshots/production_tasks/production_attempts/task_events/task_jobs/task_outputs/media_objects/media_versions/generation_candidates/adoptions/subtitle_versions/render_snapshots/delivery_versions`。不得新增通用用户、权限、审计、model profile、shot 或 speech line 表。

SourceRevision、ScriptVersion、CreativeAssetVersion、ShotSpecVersion、SubtitleVersion 统一使用 `draft → confirmed → superseded`；任一 Episode/asset 同类最多一个 current confirmed。`input_outdated` 是根据上游版本/哈希计算的兼容投影，不进入任何版本、Task 或 Candidate 状态枚举。

`shots_json`、Script 内容、字幕 Cue、快照引用与 Render 片段都是无独立生命周期的 JSONB 值对象，必须由 `schemas/` 中具名版本化 Pydantic 数据契约在生成、保存和确认入口复用校验，并把包含 required null/default 的完整 dump 持久化；只有计算哈希时才按 RFC 8785 canonicalize，不能把 JSONB 的物理编码当成 canonical bytes。`api/routes` 只做 HTTP 映射。查询键、状态、唯一键、FK、签名 URL、secret 和 Provider 私有响应不得藏入 JSON。`shots_json` 的 6～10 项、稳定 shot_id、ordinal 唯一连续、时长与引用由共享契约保护，不虚假声明为数据库行约束。

直接生成的 ScriptVersion/ShotSpecVersion 对非空 origin_task_id 唯一，CreativeAssetVersion 对 `origin_task_id+asset_id` 唯一，MediaVersion 与 GenerationCandidate 对 `attempt_id+output_slot` 唯一，使 Job Handler 恢复先命中原输出。额外 Provider 输出只允许确定性 `extra/{index}` 且状态 blocked。`TaskOutput.output_type` 只允许 `script_version/creative_asset_version/shot_spec_version/generation_candidate/delivery_version`；Task `result_refs` 只从 TaskOutput 投影，不在 Task JSON 重复保存。

### 3.1 版本化 usage slot 与哈希

`UsageType` 只允许 `asset_image/shot_image/shot_video/speech_audio`。`asset_image` 的 CreativeAssetVersion 类型只允许角色或场景；整体视觉风格不得创建 Candidate/Adoption，其 confirmed version ID/content_hash 必须进入相关 `shot_image`、`shot_video` 的 Prompt、SubmissionSnapshot 与 `input_hash`。`input_hash` 只判断候选能否用于当前内容；`parameters_hash` 只覆盖规范化生成参数；SubmissionSnapshot `content_hash` 覆盖 input_refs、Prompt、参数、model_profile_id、Provider/模型、route_version 和 schema_version 的完整请求。三者都先把字符串转 NFC，再以 RFC 8785 canonical JSON 的 UTF-8 字节计算 SHA-256。

| UsageType | usage_id / input_version_id | input_hash 的 canonical input |
| --- | --- | --- |
| `asset_image` | 角色或场景 asset_id / CreativeAssetVersion ID | usage type、asset_id、version ID、资产 content_hash |
| `shot_image` | shot_id / ShotSpecVersion ID | usage type、shot_id、version ID、该 Shot content hash、按 asset_id 排序的全部相关角色/场景/整体视觉风格 version ID/content_hash |
| `shot_video` | shot_id / ShotSpecVersion ID | `shot_image` 全部字段，加按 usage type/id 排序的相关角色/场景资产与镜头图片 adoption_id、media_version_id、sha256 |
| `speech_audio` | speech_line_id / ScriptVersion ID | usage type、speech_line_id、version ID、text_hash、confirmed SpeechLine 的逻辑 voice_id |

`TaskType` 固定为 `generate_script/generate_storyboard/generate_media/render_episode`，`CapabilityType` 固定为 `text/image/video/tts`；代码端口名使用 Text/Image/Video/TtsProvider。SpeechLine 是 ScriptVersion JSON 内的稳定值对象，不建立独立表。

服务端配置提供非克隆逻辑 VoiceCatalog；confirmed SpeechLine 恰有一个 voice_id，Adapter 只把该逻辑 ID 映射到已批准 Provider 音色。媒体命令、候选查询和 Adoption 必须与当前 SpeechLine 的 voice_id/hash 完全一致，否则返回 `412 VERSION_CONFLICT`。

## 4. HTTP 约定

- 基础路径 `/v1`，JSON 使用 `snake_case`，时间使用 UTC RFC 3339，ID 为不透明字符串。
- 创建同步资源返回 `201`；每条异步命令只受理一个逻辑目标或媒体 usage slot，并返回 `202`、`task_id/status/resource_version/status_url`。前端需要多项生成时发送多个具有独立幂等键的命令。
- `createProject`、`createSourceRevision`、`deriveScriptDraft`、`deriveStoryboardDraft`、`createSubtitles`、`deriveSubtitleDraft`、全部异步创建、取消、重试、采用和渲染要求 `Idempotency-Key`，格式为 `^[A-Za-z0-9._:-]{8,128}$`。默认 `operation_scope={OpenAPI operationId}/{target_or_parent_id}`；无父资源的 createProject 固定为 `createProject/global`，`adoptCandidate` 固定为 `adoptCandidate/{usage_type}/{usage_id}/{input_version_id}/{input_hash}`，其中四段取自校验后的请求体，candidate_id 只进入 request_hash，因此同槽同键改选另一 Candidate 必须冲突。`request_hash=SHA-256(UTF8(RFC8785({method,operation_id,path_parameters,body})))`，其中 method 大写、path_parameters 是路由解码后的具名实参映射、缺失 body 为 null，字符串先转 NFC。API 在同一数据库事务写入该步业务事实与 IdempotencyRecord，同 scope/key 同 hash 返回保存的状态与资源引用，异 hash 返回 `409 IDEMPOTENCY_KEY_REUSED`。Render 的 pending 回执先指向 RenderSnapshot，重放继续创建/绑定内部 Task，绑定后才 completed；回执不得早于对应业务事实持久化。
- `PUT` 只允许修改 draft，使用强 ETag 与 `If-Match`；冲突返回 `412 VERSION_CONFLICT`，对 confirmed/superseded 版本返回 `409 VERSION_IMMUTABLE`。confirmed 内容再次修改必须先调用对应显式派生 Operation；superseded 内容不可直接编辑或复活，禁止原位覆盖。
- 错误使用 `application/problem+json`，包含 `type/title/status/code/retryable/request_id/detail?/errors?/metadata?`，不得返回堆栈、密钥、完整 Prompt 或签名 URL。
- Task 查询返回 `poll_after_ms: 2000`；前端仅在 `queued/running/cancelling/unknown` 时轮询，终态立即停止。供应等待与后处理只进入 `progress.phase` 和 Attempt 状态，不扩展 Task 枚举。

| `adoptCandidate` | `POST /v1/adoptions`；请求含 `usage_type/usage_id/input_version_id/input_hash/candidate_id` |
| `authorizeCandidatePreview` | `POST /v1/media-versions/{media_version_id}/preview-authorizations`；只为本 Episode Candidate 签发 900 秒私有读授权 |
| `createSubtitles` / `getSubtitles` / `saveSubtitles` | `POST /v1/episodes/{episode_id}/subtitle-versions` 基于当前 confirmed ScriptVersion 与 active TTS Adoption 生成新 draft，若有 current confirmed 字幕则以其为 parent / `GET /v1/episodes/{episode_id}/subtitles` / `PUT /v1/subtitle-versions/{version_id}` |
| `listSubtitleVersions` / `getSubtitleVersion` | `GET /v1/episodes/{episode_id}/subtitle-versions` / `GET /v1/subtitle-versions/{version_id}` |
| `deriveSubtitleDraft` | `POST /v1/subtitle-versions/{version_id}/drafts`；复制 confirmed 字幕内容，返回以其为 parent 的新 draft；SubtitleVersion 不含 origin_task_id |
| `confirmSubtitles` | `POST /v1/subtitle-versions/{version_id}:confirm` |
| `renderEpisode` | `POST /v1/episodes/{episode_id}/renders` |
| `listDeliveries` / `getDelivery` | `GET /v1/episodes/{episode_id}/deliveries` / `GET /v1/deliveries/{delivery_id}`；详情内嵌不可变 `lineage` 图，不要求额外内部表查询接口 |
| `authorizeDownload` | `POST /v1/deliveries/{delivery_id}/download-authorizations`；请求 `artifact_types` 只允许 `mp4/srt/manifest`，默认 mp4，返回各 MediaVersion 的 900 秒私有读授权 |

OpenAPI 的 `(operationId, method, path)` 集合必须与本节表格完全相等；基础设施 healthcheck 不进入 HTTP，任何额外 Operation 都使契约测试失败。

`getDelivery.lineage` 必须返回 RenderSnapshot、SourceRevision、ScriptVersion、CreativeAssetVersion 集合、ShotSpecVersion、SubtitleVersion、Render ProductionTask 与全部 Attempts、各 usage 的 Adoption→Candidate→MediaVersion→origin Attempt→Task→SubmissionSnapshot 引用，以及三件交付 MediaVersion；Provider/模型、FFmpeg 版本、大小和哈希均可由该响应遍历，且不含对象 URL。来源正文上限、镜头数量、Prompt/字幕长度、媒体字节和授权 TTL 使用[《06 MVP质量标准》](../requirement/06-MVP质量标准.md) §3 的定义值并进入 OpenAPI/config Schema；来源 Schema 与 `domain` 的文本规范化函数必须逐项执行[《02 项目与故事输入》](../requirement/02-项目与故事输入.md)的 `text-normalization-v1`。候选列表不得返回对象 URL，只有 `authorizeCandidatePreview` 可签发短期预览授权。字幕契约必须逐项返回负时长、倒序、镜头越界、重叠和映射缺失错误。来源输入类型只允许正文文本；媒体字节来源只允许已批准 Provider、FFmpeg 或 delivery 的规范 SRT/Manifest 序列化器。

## 6. Task 与内部事件契约

Task 响应必须含 `id/type/scope/status/progress/input_outdated/current_attempt_id?/result_refs/error?/resource_version/poll_after_ms/created_at/updated_at/finished_at?`。`current_attempt_id` 从所属 Attempt 的状态与最大 `attempt_no` 投影，不是 `production_tasks` 冗余列；`input_outdated` 是版本兼容投影而非状态；未知状态明确返回 `unknown` 和安全处置提示，不能返回空任务或伪造 `failed`。

内部 TaskEvent 含 `event_id/task_id/task_resource_version/event_type/occurred_at/correlation_id/data`；TaskJob 含 `id/task_id/payload/state/lease_owner/lease_until/attempts/next_attempt_at`。载荷只存稳定 ID、release_version 和安全摘要，不含媒体字节、凭据或完整 Prompt。两者不进入 OpenAPI，也不由前端消费。

## 7. 前后端边界

- Server Component 只建立静态页面壳和元数据；初始项目查询、编辑器、轮询和媒体预览全部进入使用 RTK Query 的 Client Island，不建立第二请求客户端。
- `@umijs/openapi` 只在 `src/api/` 生成 DTO 与无缓存请求函数；手写 `store/backend-api.ts` 使用 RTK Query 包装它们，配置 `refetchOnReconnect=true`，Store 装配 reducer/middleware 并只调用一次 `setupListeners(store.dispatch)`。活跃 Task 设置 `pollingInterval=2000`，网络恢复后立即权威重查，终态停止轮询。
- Redux 普通 Slice 只保存未提交编辑、选区和面板状态；不得复制 RTK Query 服务端对象，也不得通过 `redux-persist` 保存 Task、Adoption、Delivery、签名 URL 或权限事实，页面刷新从 API 恢复。
- 候选图片/视频/TTS 预览和成片下载都先请求最长 15 分钟的短期授权，再访问私有对象；授权只允许当前 Episode 中可访问的 MediaVersion，对象 URL 不写入持久缓存、日志或可分享路由。
- MinIO Adapter 从现有环境读取 `MINIO_ENDPOINT`、`MINIO_PUBLIC_ENDPOINT`、bucket、region 与凭据；对象 I/O 和签名都通过正式 SDK 配置，启动时拒绝 public endpoint 的 userinfo、path、query 或 fragment，本地默认还必须是 loopback。私有 bucket 由用户现有环境提供，签名 URL 恰好 900 秒过期，不写 PostgreSQL、Redux、TaskJob、日志或路由。
- backend-api 本地 CORS allowlist 恰为 origin `http://127.0.0.1:3000`、methods `GET/POST/PUT`、request headers `Content-Type/Idempotency-Key/If-Match`、exposed header `ETag`，`allow_credentials=false`，任何 `*` 均失败。既有 MinIO 必须预先满足该 origin 的只读 `GET/HEAD` CORS；应用启动诊断只验证配置并给出脱敏错误，不修改 bucket、不提交 CORS XML、不创建基础设施容器。

## 8. TDD 与迁移

Plan 按以下证据顺序实施：`tests/architecture` 验证单一 FastAPI 分层、依赖方向、Domain 纯净性和 SQL/生成客户端边界；`tests/contract` 从真实 `/openapi.json` HTTP URL 运行 `@umijs/openapi`；`tests/migrations` 比较标准 SQL 与 PostgreSQL catalog；`tests/integration` 使用现有 PostgreSQL/MinIO；`tests/jobs` 注入租约过期、重启、超时和重复；后端 `tests/e2e` 与前端 Playwright 用 Mock 跑完整成片，再执行真实 Provider smoke。

初始 Alembic `0001_mvp` 只从仓库根 `sql/` 按 `01`～`20` 顺序执行自包含逐表 SQL；迁移脚本不复制 DDL，不使用 ORM Metadata 或 autogenerate。隔离空测试库执行两次 `upgrade head` 与 catalog exact-set 均须通过。回滚不执行破坏性 downgrade，不删除事实、对象或用户现有环境。OpenAPI、生成客户端或实现不一致时 CI 必须失败。

## 9. Design 验收标准

- AC-ARCH-003-001：实际结构与 §2 的单一 FastAPI 技术分层 exact-set 一致，不存在 `modules/*/domain/application/infrastructure/transport/public.py` 重复层级；根 Compose 仅管理三个应用服务，无 deploy 目录或示例产物。
- AC-ARCH-003-002：OpenAPI 的 Operation 集合与 §5 exact-set 一致，并覆盖成功/失败示例、幂等、ETag、Task 轮询和 Problem Details。
- AC-ARCH-003-003：逐表标准 SQL 与 `lanverse` PostgreSQL catalog 在排除 `alembic_version` 后都与 DESIGN-06 的 20 张应用表、列、约束和索引 exact-set 完全一致；共享 Pydantic Schema/应用校验器表达 JSONB 不变式，并覆盖不可变版本、Task/Attempt、采用和交付谱系。
- AC-ARCH-003-004：前端只使用 Redux Toolkit、RTK Query 和 `@umijs/openapi` 从运行中 API 的 Swagger URL 生成 DTO/请求函数；仓库无静态 OpenAPI 中间文件，2 秒权威轮询在终态停止，普通 Slice 不复制正式事实，TaskEvent/TaskJob 保持为 OpenAPI 外的后端事实。
- AC-ARCH-003-005：架构、契约、迁移、集成、Job 和 E2E 测试均有固定目录及可由 Plan 给出的一条执行命令。
- AC-ARCH-003-006：从任一 ready DeliveryVersion 可定位到 RenderSnapshot、Adoption、GenerationCandidate、MediaVersion、ProductionTask/ProductionAttempt、SubmissionSnapshot 和来源版本。
