# 接口数据与项目结构

## 1. 设计结论

`backend/contracts/openapi/openapi.yaml` 是唯一 HTTP 契约源，并生成 `frontend/src/services/generated/`；页面不得手写第二套 DTO。前端同步活跃 Task 的唯一方式是每 2 秒查询权威资源。TaskEvent 和 OutboxEvent 是 PostgreSQL 内部恢复事实，只由后端代码与数据库集成测试约束，不进入 OpenAPI。

## 3. 最小数据模型

SourceRevision、ScriptVersion、CreativeAssetVersion、ShotSpecVersion、SubtitleVersion 统一使用 `draft → confirmed → superseded`；任一 Episode/对象同类最多一个 current confirmed。`input_outdated` 是根据上游版本/哈希计算的兼容投影，不进入任何版本、Task 或 Candidate 状态枚举，UI 可将其展示为“已过期”。

| 表/聚合 | 必需字段摘要 |
| --- | --- |
| Project/Episode | Project ID/标题/固定 9:16、720×1280、24fps、30～60 秒规格/`active`/时间；Episode ID、唯一 project、current_source_revision 和时间 |
| SourceRevision | episode、version、parent、规范化 UTF-8 content、normalization_version、codepoint_count、sha256、rights_basis/declared_at、统一版本状态 |
| ScriptVersion | episode、version、parent、source_revision、schema_version、content_json/content_hash、origin_task_id、Provider/模型/Prompt 版本、统一版本状态 |
| CreativeAssetVersion | 稳定 asset_id、episode、version、parent、source ScriptVersion、角色/场景/风格类型、名称/文字设定/content_hash、origin_task_id、统一版本状态 |
| ShotSpecVersion | episode、version、parent、script_version、资产版本集合、content_hash、origin_task_id、有序 `shots_json`；每项含稳定 shot_id、canonical content_hash、ordinal、prompt、`timebase=90000`、24fps 对齐 duration_ticks、speech/visual JSON；统一版本状态 |
| IdempotencyRecord | owner_module、operation_scope、idempotency_key、request_hash、pending/completed、response_status/response_ref、created_at；由 API 幂等中间件在业务事务内唯一写入 |
| SubmissionSnapshot | type、input_refs、prompt/parameters、Provider/模型、schema_version、content_hash |
| ProductionTask | type、业务 scope、idempotency_scope/idempotency_key、snapshot、status/progress、workflow、retry_of、error、resource_version |
| ProductionAttempt | task、attempt_no、parent_attempt、status、provider_request_key/远端请求、用量/安全摘要、错误与时间 |
| TaskEvent/OutboxEvent/TaskOutput | Task/聚合版本、类型、安全 JSON、租约/退避/派发结果；TaskOutput 保存 task、output_type、output_id、ordinal，输出版本反存 origin_task_id |
| MediaObject/MediaVersion | MediaObject 来源；MediaVersion 的 object、version、origin_attempt_id/output_slot、S3 key、MIME、字节、sha256、技术状态、尺寸/时长、父版本、probe 摘要 |
| GenerationCandidate/Adoption | 版本化 usage slot、task/attempt、确定性 output_slot（`primary` 或 `extra/{index}`）、media_version_id 与单向候选状态；Adoption 为 active/superseded 持久事实 |
| SubtitleVersion | episode、version、parent、language、Cue 稳定 ID/文本/Episode 全局起止 tick/音色角色、SpeechLine/ScriptVersion/text_hash/TTS 引用、content_hash、统一版本状态 |
| RenderSnapshot | episode、外层 submission_scope/idempotency_key/request_hash、可选 initial_task_id、timebase=90000、有序片段 start/end、视频/TTS/SubtitleVersion 引用、归一化规则、输出规格和配方哈希 |
| DeliveryVersion | episode、version、render_task、可选 final_attempt/retry_of_delivery、RenderSnapshot、MP4/SRT/JSON Manifest MediaVersion、三件产物的字节/哈希摘要、FFmpeg 版本、rendering/ready/failed/cancelled、ffprobe 摘要 |

本节表格是 `lanverse` 数据库中的 Prisma 业务模型 allowlist；每张业务表都必须由至少一个 Operation、Workflow 或追踪查询使用。Compose 的同一 PostgreSQL 服务还提供隔离的 `temporal` 与 `temporal_visibility` 数据库，Prisma 永不连接或迁移它们；allowlist 测试比较 Prisma DMMF 与 `lanverse` 业务表，明确排除 Prisma 自有 `_prisma_migrations`，不得把迁移元数据或 Temporal 系统表当成业务模型。数据库核心唯一约束：`Episode.project_id`；Source/Script/ShotSpec/Subtitle/Delivery 的 `episode_id+version`；CreativeAssetVersion 的 `asset_id+version`；MediaVersion 的 `media_object_id+version` 与 `origin_attempt_id+output_slot`；GenerationCandidate 的 `media_version_id` 与 `attempt_id+output_slot`；`DeliveryVersion.render_task_id`；IdempotencyRecord 的 `operation_scope+idempotency_key`、ProductionTask 的 `idempotency_scope+idempotency_key`、RenderSnapshot 的 `submission_scope+idempotency_key` 和非空 `initial_task_id`、`task_id+attempt_no`、`task_id+event_resource_version`、`workflow_id`、`provider_id+provider_request_key`、`provider_id+provider_request_id`、`output_type+output_id`、`task_id+output_type+ordinal` 和 `outbox_event_id`。数据库 partial unique 分别保证每 Episode 最多一个 current confirmed Source/Script/ShotSpec/Subtitle、每 asset 最多一个 current confirmed CreativeAssetVersion、每完整 usage slot 最多一个 active Adoption、每 Task/完整 usage slot 最多一个 ready `primary` Candidate。DeliveryVersion.final_attempt_id 必须属于其 render_task_id。跨模块只存稳定 ID/版本，不级联删除。

`shots_json` 不是独立 Prisma 表：OpenAPI JSON Schema 与 story-development 应用校验器共同保证 6～10 项、`shot_id`/ordinal 分别唯一、ordinal 从 1 连续、字段完整、时长和引用合法；生成结果落库、`PUT saveStoryboard` 与确认必须复用同一校验器。Prisma 只持久化校验通过的 JSON，不把 JSON 数组元素唯一性声称为数据库约束。

直接生成的 ScriptVersion/ShotSpecVersion 对非空 origin_task_id 唯一，CreativeAssetVersion 对 `origin_task_id+asset_id` 唯一，MediaVersion 对 `origin_attempt_id+output_slot` 唯一，GenerationCandidate 对 `attempt_id+output_slot` 唯一，保证 Workflow 重放先查到原输出。额外 Provider 输出使用不同 output_slot 并只能进入 blocked；同一 MediaVersion 不得绑定多个 Candidate。生成 Workflow 只有在所属模块保存输出版本、production-jobs 保存 TaskOutput 并让 Task `result_refs` 指向同一稳定 ID 后才能成功。用户编辑未确认草稿时保留生成谱系、按 ETag 更新内容并重算 content_hash；Script/ShotSpec/CreativeAsset 确认后手工派生的新版本保存 parent 且 origin_task_id 为空，SubtitleVersion 只保存 parent 且不含 origin_task_id。TaskOutput 表示提案来源，不声称 Provider 生成了用户改写后的文本。

TaskOutput.output_type 只允许 `script_version/creative_asset_version/shot_spec_version/generation_candidate/delivery_version`；Task `result_refs` 是按 output_type/ordinal 从 TaskOutput 生成的查询投影。`output_type+output_id` 唯一并与输出对象 origin_task_id/task_id 一致，禁止一个输出宣称来自两个 Task。

### 3.1 版本化 usage slot 与哈希

`UsageType` 只允许 `asset_image/shot_image/shot_video/speech_audio`。`asset_image` 的 CreativeAssetVersion 类型只允许角色或场景；整体视觉风格不得创建 Candidate/Adoption，其 confirmed version ID/content_hash 必须进入相关 `shot_image`、`shot_video` 的 Prompt、SubmissionSnapshot 与 `input_hash`。`input_hash` 与 SubmissionSnapshot `content_hash` 不同：前者只判断候选能否用于当前内容，后者覆盖完整 Provider/模型/Prompt/参数请求。两者都先把字符串转 NFC，再以 RFC 8785 canonical JSON 的 UTF-8 字节计算 SHA-256。

| UsageType | usage_id / input_version_id | input_hash 的 canonical input |
| --- | --- | --- |
| `asset_image` | 角色或场景 asset_id / CreativeAssetVersion ID | usage type、asset_id、version ID、资产 content_hash |
| `shot_image` | shot_id / ShotSpecVersion ID | usage type、shot_id、version ID、该 Shot content hash、按 asset_id 排序的全部相关角色/场景/整体视觉风格 version ID/content_hash |
| `shot_video` | shot_id / ShotSpecVersion ID | `shot_image` 全部字段，加按 usage type/id 排序的相关角色/场景资产与镜头图片 adoption_id、media_version_id、sha256 |
| `speech_audio` | speech_line_id / ScriptVersion ID | usage type、speech_line_id、version ID、text_hash、confirmed SpeechLine 的逻辑 voice_id |

`TaskType` 固定为 `generate_script/generate_storyboard/generate_media/render_episode`，`CapabilityType` 固定为 `text/image/video/tts`；代码端口名使用 Text/Image/Video/TtsProvider。SpeechLine 是 ScriptVersion JSON 内的稳定值对象，不建立独立表。

服务端配置提供非克隆逻辑 VoiceCatalog；confirmed SpeechLine 恰有一个 voice_id，Adapter 只把该逻辑 ID 映射到已批准 Provider 音色。媒体命令、候选查询和 Adoption 必须与当前 SpeechLine 的 voice_id/hash 完全一致，否则返回 `412 VERSION_CONFLICT`。

## 4. HTTP 约定

- 基础路径 `/v1`，JSON 使用 `snake_case`，时间使用 UTC RFC 3339，ID 为不透明字符串。
- 创建同步资源返回 `201`；每条异步命令只受理一个逻辑目标或媒体 usage slot，并返回 `202`、`task_id/status/resource_version/status_url`。前端需要多项生成时发送多个具有独立幂等键的命令。
- `createProject`、`createSourceRevision`、`deriveScriptDraft`、`deriveStoryboardDraft`、`createSubtitles`、`deriveSubtitleDraft`、全部异步创建、取消、重试、采用和渲染要求 `Idempotency-Key`，格式为 `^[A-Za-z0-9._:-]{8,128}$`。默认 `operation_scope={OpenAPI operationId}/{target_or_parent_id}`；无父资源的 createProject 固定为 `createProject/global`，`adoptCandidate` 固定为 `adoptCandidate/{usage_type}/{usage_id}/{input_version_id}/{input_hash}`，其中四段取自校验后的请求体，candidate_id 只进入 request_hash，因此同槽同键改选另一 Candidate 必须冲突。`request_hash=SHA-256(UTF8(RFC8785({method,operation_id,path_parameters,body})))`，其中 method 大写、path_parameters 是路由解码后的具名实参映射、缺失 body 为 null，字符串先转 NFC。API 在同一数据库事务写入该步业务事实与 IdempotencyRecord，同 scope/key 同 hash 返回保存的状态与资源引用，异 hash 返回 `409 IDEMPOTENCY_KEY_REUSED`。Render 的 pending 回执先指向 RenderSnapshot，重放继续创建/绑定内部 Task，绑定后才 completed；回执不得早于对应业务事实持久化。
- `PUT` 只允许修改 draft，使用强 ETag 与 `If-Match`；冲突返回 `412 VERSION_CONFLICT`，对 confirmed/superseded 版本返回 `409 VERSION_IMMUTABLE`。confirmed 内容再次修改必须先调用对应显式派生 Operation；superseded 内容不可直接编辑或复活，禁止原位覆盖。
- 错误使用 `application/problem+json`，包含 `type/title/status/code/retryable/request_id/detail?/errors?/metadata?`，不得返回堆栈、密钥、完整 Prompt 或签名 URL。
- Task 查询返回 `poll_after_ms: 2000`；前端仅在 `queued/running/cancelling/unknown` 时轮询，终态立即停止。供应等待与后处理只进入 `progress.phase` 和 Attempt 状态，不扩展 Task 枚举。

`getDelivery.lineage` 必须返回 RenderSnapshot、SourceRevision、ScriptVersion、CreativeAssetVersion 集合、ShotSpecVersion、SubtitleVersion、Render ProductionTask 与全部 Attempts、各 usage 的 Adoption→Candidate→MediaVersion→origin Attempt→Task→SubmissionSnapshot 引用，以及三件交付 MediaVersion；Provider/模型、FFmpeg 版本、大小和哈希均可由该响应遍历，且不含对象 URL。来源正文上限、镜头数量、Prompt/字幕长度、媒体字节和授权 TTL 使用[《06 MVP质量标准》](../requirement/06-MVP质量标准.md) §3 的定义值并进入 OpenAPI/config Schema；来源 Schema 与 project-catalog 共享校验器必须逐项执行[《02 项目与故事输入》](../requirement/02-项目与故事输入.md)的 `text-normalization-v1`。候选列表不得返回对象 URL，只有 `authorizeCandidatePreview` 可签发短期预览授权。字幕契约必须逐项返回负时长、倒序、镜头越界、重叠和映射缺失错误。来源输入类型只允许正文文本，媒体来源只允许已批准 Provider 或 FFmpeg。

## 6. Task 与内部事件契约

Task 响应必须含 `id/type/scope/status/progress/input_outdated/current_attempt_id?/result_refs/error?/resource_version/poll_after_ms/created_at/updated_at/finished_at?`。`input_outdated` 是版本兼容投影而非状态；未知状态明确返回 `unknown` 和安全处置提示，不能返回空任务或伪造 `failed`。

内部 TaskEvent 含 `event_id/task_id/task_resource_version/event_type/occurred_at/correlation_id/data`；OutboxEvent 含 `event_id/aggregate_type/aggregate_id/event_type/payload/state/lease_until/attempts/next_attempt_at`。载荷只存稳定 ID、版本和安全摘要，不含媒体字节、凭据或完整 Prompt。两者不进入 OpenAPI，也不由前端消费。

## 7. 前后端边界

- Server Component 只建立页面壳和初始项目查询；编辑器、轮询和媒体预览为 Client Island。
- TanStack Query 使用生成客户端；活跃 Task 的 `refetchInterval=2000`，离线暂停，恢复后立即权威重查。
- Zustand 不保存 Task、Adoption、Delivery 或权限事实；页面刷新从 API 恢复。
- 候选图片/视频/TTS 预览和成片下载都先请求最长 15 分钟的短期授权，再访问私有对象；授权只允许当前 Episode 中可访问的 MediaVersion，对象 URL 不写入持久缓存、日志或可分享路由。

## 8. TDD 与迁移

Plan 按以下证据顺序实施：`test/architecture` 验证 public-only/无环/Workflow 确定性边界；`test/contract` 先以 OpenAPI 示例形成失败测试；`test/integration` 使用真实 PostgreSQL、Temporal、MinIO；`test/workflows` 注入重启/超时/重复；后端 `test/e2e` 与前端 Playwright 用 Mock 跑完整成片，再执行真实 Provider smoke。

初始 Prisma 迁移从 `0001` 建表并验证空库升级/回滚策略。回滚不删除事实或对象；仅在无正式数据时允许丢弃整个本地开发卷。生成客户端、OpenAPI 和实现不一致时 CI 必须失败。

## 9. Design 验收标准

- AC-ARCH-003-001：实际目录与 §2 allowlist 完全一致，包含三个应用根、六模块和两个后端入口。
- AC-ARCH-003-002：OpenAPI 的 Operation 集合与 §5 exact-set 一致，并覆盖成功/失败示例、幂等、ETag、Task 轮询和 Problem Details。
- AC-ARCH-003-003：Prisma DMMF 与 `lanverse` 业务表在排除 `_prisma_migrations` 后都与 §3 allowlist 及数据库约束完全一致，且 `temporal/temporal_visibility` 隔离不参与比较；共享 JSON Schema/应用校验器表达 `shots_json` 不变式，并覆盖不可变版本、Task/Attempt、采用和交付谱系。
- AC-ARCH-003-004：前端只使用生成客户端和 2 秒权威轮询，TaskEvent/OutboxEvent 保持为 OpenAPI 外的后端事实。
- AC-ARCH-003-005：架构、契约、集成、Workflow 和 E2E 测试均有固定目录及可由 Plan 给出的一条执行命令。
- AC-ARCH-003-006：从任一 ready DeliveryVersion 可定位到 RenderSnapshot、Adoption、GenerationCandidate、MediaVersion、ProductionTask/ProductionAttempt、SubmissionSnapshot 和来源版本。
