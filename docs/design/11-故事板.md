# Design 11：故事板

执行编号：11；原始需求模块：15。依据[原始需求](../requirement/15-故事板需求.md)、[PRD](../prd/11-故事板.md)与[Plan](../plan/11-故事板.md)。本文件把原始需要转换成项目方案，**全部新增设计选择仍待评审**；数据对象和接口为拟议合同，不表示已有表或已实现API。共同约束见[整体设计](00-项目需求设计.md)。原始FR、质量条件与AC仍须同时满足。

## 查询投影与明确批量范围

故事板组织同项目集/场内镜头摘要和批量用例，不复制镜头输入或候选平台。查询结果含shot_id/当前input_version/selection_version、编号描述/时长/模式、可用缩略图/画面视频状态；来源为镜头、生成和媒体的授权投影。网格与表格共用筛选/稳定排序/数量，不返回全部历史或视频字节。

前端SelectionSet保存用户明确选中的shot_id及本次观察版本；首轮批量建议“全选”仅当前已加载集合，跨页选择必须显示明确ID/数量，换筛选建议清空并提示，具体政策待确认，不能暗含未加载项。

## 批量时长与批量生成采用不同事务

拟议GET /projects/{id}/storyboard?episode_id=…&scene_id=…；POST /storyboard/duration-updates提交明确ID/版本和时长；POST /storyboard/generation-batches提交冻结选择及确认；GET /generation-batches/{id}读取逐项结果。批量上限需容量与产品确认，不任意填数字。

批量时长先按稳定ID顺序锁定所有目标，核全部权限/expected_revision/模型限制；任一失败整批不写并返回安全冲突ID。全部合法才在一个事务创建每镜头新输入版本、推进指针与审计。事务保证原子参数写入，不对外部生成声称整批原子成功。

批量生成建议BatchIntent含batch_id、用户/项目、request_key、显式目标版本、逐项输入指纹和费用确认、Item与Task关联。新批次事务一次固定选择并预检；不能把总价确认用于更换项。每项通过[生成合同](10-生成.md)建立唯一Task，batch_id＋shot_id提供稳定派生项键，接管/重复批次定位原任务。创建过程必须可恢复，逐项状态包括尚未创建/排队/运行/成功/失败/未知；缺少任务不是成功。

生成执行逐项独立，失败不抹掉其他结果，unknown不再POST，不自动选定候选。若费用仅有部分可确认，建议批次准入失败并显示受影响项，是否允许明确拆批须另接受，不擅自运行可行子集收费。数量变化、过滤或选定后版本变化都需重新预检/确认。

## 原始需求到设计追踪

| 原始FR      | 项目设计与验收观察                                            |
| ----------- | ------------------------------------------------------------- |
| FR-BOARD-01 | 同查询投影/筛选/排序；两视图一致、不带全候选历史              |
| FR-BOARD-02 | 明确SelectionSet及版本；空集合拒绝，无隐藏目标                |
| FR-BOARD-03 | 全部锁定校验＋原子新版本事务；一冲突整批不写                  |
| FR-BOARD-04 | Durable BatchIntent/Item→共享Task；重复不重收费，混合结果真实 |
| FR-BOARD-05 | 真实project/episode/scene/shot上下文；目标失权不跳样例        |

验证至少两个不同模型限制镜头、一个版本冲突、并发批量时长、批次创建中断、单项未知、重复批次和分页/筛选变更；比输入版本数/Task数量与调用数，不只看进度条。

## 待评审选择与实施入口

选择跨页/筛选政策、规模上限、批次准入和费用/逐项确认、批次保留及导航关系待接受。单镜头/共享生成可用后再按[Plan](../plan/11-故事板.md)实施，不因故事板是后置模块而给首轮Demo引入批调度框架。

### 批量参数与生成的收敛

参数批改按稳定shot_id顺序锁完整SelectionSet，核每个expected_revision与duration能力，再创建全部新输入/heads/audit/回执；有一冲突全部rollback，冲突ID仅有权对象。
批次创建事务固定全部Preflight指纹与金额/外发范围、写每个Item的稳定item_key；恢复器用item_key作为该镜头generation.submit键并参加共享冻结用例，写Task链接。Item链接成功和Task创建必须同事务，防“已创建但批次找不到”；中断查原键后补链接而非重收费。实际执行与媒体准备逐项不同，BatchView只聚合真实子状态，不自动选定候选。
