## 2. 数据

| 存储 | 用途 | 关键字段 |
| --- | --- | --- |
| `identity.user`（[DES-02 §5.1](../design/02-领域与数据模型.md#51-identity)） | 账号 | `login_name`（citext，部分唯一索引）、`role`、`status`、`password_hash`、`must_change_password`、`failed_login_count`、`locked_until`、`session_epoch`、`revision` |
| `workspace.organization`（[DES-02 §5.2](../design/02-领域与数据模型.md#52-workspace)） | MVP 的唯一组织 | `id`、`name`、`status`；首位管理员初始化时若尚无组织则同事务创建，后续内置数据种子复用此组织 |
| Redis `sess:{sha256(token)}` | 会话 | `user_id`、`org_id`、`session_epoch`、`create_time`、`last_seen`；TTL = 12 小时，每次请求续期，但不超过创建后 7 天。`org_id` 用于按组织范围读取账号；Redis 只保存令牌摘要，不保存原始令牌 |
| Redis `login_fail_ip:{sha256(canonical_ip)}` | IP 维度限流 | 每 IP 每分钟最多 20 次登录尝试；计数 TTL 1 分钟。IP 规范化后仅将摘要写入 Redis 键 |

为什么需要 `session_epoch`：会话存在 Redis 中，逐个删除某账号的全部会话需要额外索引；改为在账号上维护一个递增的“会话纪元”，会话记录创建时的纪元，校验时不一致即失效（R9），实现简单且可靠。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 当前用户 |
| POST | `/api/auth/password` | 修改本人密码 |
| GET / POST | `/api/admin/users` | 账号列表 / 创建 |
| PATCH | `/api/admin/users/{id}` | 修改显示名、角色（Rev） |
| POST | `/api/admin/users/{id}/disable`、`/enable` | 禁用 / 启用 |
| POST | `/api/admin/users/{id}/reset-password` | 重置密码 |

系统初始化命令为 `lanverse admin bootstrap --login-name <name>`；可选 `--display-name` 与 `--org-name`。密码及确认值只从交互式终端读取，不接受命令行参数、管道或 `.env` 中的默认密码。命令使用 `LV_DB_DSN` 连接已完成迁移的 PostgreSQL：先读取 MVP 唯一组织；若不存在，则在全局事务锁下创建名称为 `Lanverse`（或 `--org-name` 指定值）的组织。若已有唯一启用组织则复用，存在多个组织、停用组织或任何未删除账号时拒绝初始化。首次管理员的角色为 `admin`、状态为 `active`、`must_change_password=true`，显示名默认与登录名相同。组织、账号以及 `identity.user_changed.v1` 和 `audit.recorded.v1`（`user.created`，system actor）在同一 PostgreSQL 事务提交；任一步失败全部回滚。重复执行不能创建第二个初始管理员，后续账号由已登录管理员创建。

登录：

```http
POST /api/auth/login
{ "login_name": "alice", "password": "…" }

200 OK   Set-Cookie: lv_session=…; HttpOnly; Secure; SameSite=Lax
         Set-Cookie: lv_csrf=…; Secure; SameSite=Lax
{ "user": { "id": "…", "login_name": "alice", "display_name": "Alice", "role": "producer" },
  "must_change_password": true }

401 invalid_credentials      423 account_locked { "meta": { "retry_after_s": 540 } }
```

内部登录用例接收可信调用方确定的 `org_id`（MVP 仅一个组织，不能从未认证请求体采信组织范围）。先由 Redis 记录 IP 尝试次数；Redis 不可用即返回不可用，不继续查询账号。账号不存在、密码错误、禁用均对外返回 `invalid_credentials`，审计分别记录 `login_not_found`、`password_mismatch`、`account_disabled`；超过 IP 配额返回 `rate_limited`。第五次错密把锁定状态和 `auth.login_failed`、`auth.locked` 两条审计 Outbox 放在同一 PostgreSQL 事务；锁定期间的后续请求返回剩余时间并单独记录 `auth.locked`。已知账号的登录状态按 `revision` 乐观更新，冲突后重新读取并最多重试三次。

未认证的失败、限流和锁定事件以 `system` 为 actor；已知账号的 `object` 用用户 ID，未知登录名的 `object` 用规范化后的登录名且限制长度。登录成功才以该用户为 actor。审计记录请求 ID 与规范化 IP，不记录密码、哈希和会话令牌。

密码校验通过后，先在 Redis 创建尚未返回调用方的会话，再在同一 PostgreSQL 事务更新登录状态并写 `auth.login_succeeded` Outbox；事务失败销毁新会话，Redis 创建失败则不更新账号或记录成功。调用方只在提交成功后获得令牌。会话令牌、密码和哈希均不进入审计或日志。

内部登出用例先以当前令牌校验账号与会话，再撤销 Redis 会话，最后写 `auth.logout` 审计 Outbox；重复撤销令牌是安全的。撤销成功后的审计写入使用有界、独立于请求取消的上下文，避免浏览器断开时遗漏记录。跨 Redis 与 PostgreSQL 无共同事务：若撤销失败，不写“已登出”审计并返回不可用；若撤销成功但审计写入失败，返回包含“会话已撤销”标志的错误结果，HTTP 层仍须清除 Cookie 并报告审计故障。审计事件以当前用户为 actor 和 object，包含请求 ID、规范化 IP，不含令牌。公开接口响应与 Cookie 细节仍待 DES-03 就绪评审。

创建账号：

```http
POST /api/admin/users
{ "login_name": "alice", "display_name": "Alice", "role": "producer", "initial_password": "…" }
201 { "id": "…", "login_name": "alice", "status": "active", "revision": 1, "create_time": "…" }
409 already_exists（登录名已存在，`meta.field = login_name`）
```

错误码：`already_exists`、`invalid_credentials`、`account_locked`、`password_change_required`、`unauthenticated`、`forbidden`、`state_conflict`（禁用最后一个管理员）、`revision_conflict`。

## 4. 异步与工作流

无工作流。账号变更事务内写 Outbox 事件 `identity.user_changed.v1` 与 `audit.recorded.v1`（审计只经后者写入，DES-12）。

管理员创建账号时，应用层先校验角色并计算密码哈希；PostgreSQL 事务重新读取操作人的组织、启用状态、管理员角色与强制改密状态，再写账号及上述两条 Outbox 行。任一写入失败则一并回滚。`identity.user_changed.v1` 以组织 ID 为分区键，聚合为 `{type:"user", id:<新账号 ID>, revision:1}`，`data` 只含 `change:"created"`；`audit.recorded.v1` 同样以组织 ID 为键，动作为 `user.created`，摘要只含 `role`、`status`、`must_change_password`。两条载荷均不含密码或哈希。公开写接口的幂等与 Cookie 契约仍以 DES-03 就绪评审结果为准。

管理员禁用账号时，内部命令接收已鉴权的管理员、目标账号 ID、`expected_revision` 与请求 ID。PostgreSQL 事务先取得组织级管理员变更锁，重查操作者当前状态与权限，再锁定目标行并检查修订号和最后一名启用管理员规则；成功时将目标设为 `disabled`，在同一事务递增 `session_epoch` 与 `revision`，写 `identity.user_changed.v1`（`change:"disabled"`、新修订号）和 `audit.recorded.v1`（`user.disabled`、状态前后摘要）。任一事件写入失败即回滚状态与纪元；旧 Redis 会话无需逐个删除，下一次鉴权按数据库纪元拒绝。不存在、禁用中、修订冲突与最后管理员保护保留可判定错误；公开错误映射和幂等契约仍以 DES-03 评审为准。

管理员启用账号时同样校验组织、当前管理员权限、目标修订和状态；只允许 `disabled → active`。事务内再次递增 `session_epoch` 与 `revision`，清除旧的登录失败计数和锁定期限，并写 `identity.user_changed.v1`（`change:"enabled"`）与 `audit.recorded.v1`（`user.enabled`，状态前后摘要）。已撤销的旧会话不会因重新启用而恢复。已启用、跨组织、过期修订和审计写入失败均不得改变账号状态。

管理员重置密码时先按当前账号哈希校验新密码规则与不可复用旧密码，再计算 bcrypt 哈希；明文不传入仓储、事件或日志。PostgreSQL 事务内重新校验管理员、目标账号修订和原哈希，将新哈希写入账号，设置 `must_change_password=true`，清除登录失败计数与锁定期限，递增 `session_epoch` 与 `revision`，并写 `identity.user_changed.v1`（`change:"password_reset"`）和 `audit.recorded.v1`（`user.password_reset`，只含强制改密标记前后摘要）。启用或禁用账号都允许重置，禁用账号仍不能登录；所有旧会话下一次鉴权失效。任一步失败整体回滚，公开幂等与错误映射仍依 DES-03 评审。

本人改密的内部命令先校验当前 Redis 会话及数据库账号，再核对当前密码、新密码规则与不可复用旧密码。它先在 Redis 创建仅用于当前客户端、纪元为 `session_epoch + 1` 的新会话，不将令牌返回给调用方；随后在 PostgreSQL 事务中锁定账号并复核状态、修订号、旧密码哈希和纪元，更新密码哈希、清除强制改密标记与锁定计数、递增纪元和修订号，同时写 `identity.user_changed.v1`（`change:"password_changed"`）与 `audit.recorded.v1`（`user.password_changed`，摘要只含改密前后的 `must_change_password`）。事务失败时撤销新会话；Redis 创建失败时不修改数据库。只有事务提交后才把新令牌交给当前客户端以替换 Cookie；其他旧纪元会话下一次鉴权立即失效。若提交后调用方断开，新令牌无法送达，用户须重新登录；公开 Cookie 和错误映射仍以 DES-03 评审为准。

## 5. 事件与实时

| 事件 | 触发 | 消费者 |
| --- | --- | --- |
| `identity.user_changed.v1` | 创建、修改、禁用、启用、重置、改密 | cache-invalidator（审计经 `audit.recorded.v1`） |

会话失效不依赖事件：`session_epoch` 在同一事务中递增，下一次请求即失效。

## 6. 界面

- 登录页：登录名、密码、错误与锁定提示（剩余时间）。
- 强制改密页：当前密码、新密码、确认新密码，实时显示强度规则。
- 管理 · 账号：列表（登录名、显示名、角色、状态、最后登录）、创建对话框、操作菜单（修改、禁用 / 启用、重置密码）。
- 应用外壳用户菜单：修改密码、登出。

## 7. 权限与审计

| 操作 | 权限 | 审计 action |
| --- | --- | --- |
| 登录成功 / 失败 / 锁定 | 任何人 | `auth.login_succeeded` / `auth.login_failed` / `auth.locked` |
| 登出 | 本人 | `auth.logout` |
| 创建、修改、禁用、启用、重置密码 | 管理员 | `user.created` / `user.updated` / `user.disabled` / `user.enabled` / `user.password_reset` |
| 修改本人密码 | 本人 | `user.password_changed` |

审计中不记录任何密码或哈希。

## 8. 非功能要求

| 条目 | 本功能的目标 |
| --- | --- |
| SEC-01、SEC-03 | 除登录与健康检查外全部接口要求会话；bcrypt cost 12 |
| SEC-05 | Cookie 带 `Secure`、`HttpOnly`、`SameSite=Lax` |
| PERF-02 | 登录 P95 ≤ 500 ms（bcrypt 约 250 ms） |
| PRV-01、PRV-02 | 只保存登录名、显示名、角色；日志不记录密码与会话令牌 |

## 9. 测试设计

- 单元：密码规则、锁定计数与解锁时间、会话纪元比较、最后一个管理员保护。
- 集成（testcontainers PostgreSQL + Redis）：登录 → 会话 → 禁用 → 会话失效；并发修改同一账号的版本冲突。
- 安全：未认证访问全部接口返回 401（遍历 OpenAPI）；登录名枚举不可区分；CSRF 头缺失的写请求被拒绝。
