# 领域语言与模块命名规范

- 目标状态：已接受
- StoryGraph 术语同步：已接受（`SG-D03`，2026-08-27）
- 视觉生产术语同步：已接受（`VP-D02`，2026-08-30）
- 语义契约命名同步：已接受（2026-08-31）
- 适用范围：文档、Frontend feature、Go Backend、Python Agent、API、事件、数据库与可观测字段
- 决策依据：[中文语义化文档与模块命名决策](0005-采用中文语义化文档与模块命名决策.md)

## 结论

Lanverse 的名称必须表达业务能力或运行职责，不能只表达技术形态。产品入口使用 Guided/Canvas，业务事实统一使用 Authoring；故事和生产关系使用 StoryGraph；模型供应商调用统一使用 Generation；后端生产域使用 Production，不能继续把 UI 概念 `studio` 当作领域边界。

同一个概念只有一个规范名。研究来源中的其他名称不能进入正式 DTO、package、协议或数据库模型。

项目自有名称不能使用 `v` 加序号表达新旧关系。API、Event、Topic、队列、索引、Schema、Agent Wire、文件和类型必须直接说明业务职责或处理阶段；契约改变时一次性切换生产者、消费者、测试和配置，不建立数字版本别名或双写双读入口。

`StoryGraphVersion`、`AuthoringRevision.Graph`、`WorkflowDefinitionVersion` 与 Temporal History 是四种不同事实：内容关系、创作编排、可执行定义和实际执行历史。它们可以共享 DAG 术语，但不能共享 Record、ID、Schema 或 Writer。

## 文档文件命名

文档文件名使用四位服务段编号与中文语义短语，使读者无需打开文件即可判断归属与用途。只有去除后会改变含义的技术专有名词才保留，例如“本地 Codex 分镜智能体”。

```text
docs/prd/0001-产品范围与验收基线.md
docs/design/0003-系统总体架构.md
docs/design/1001-前端应用架构.md
docs/design/2001-后端服务架构.md
docs/design/2002-后端领域模块功能设计.md
docs/plan/0007-平台0到1交付计划.md
docs/acceptance/3001-完整剧本业务闭环验收标准.md
```

规则如下：

1. 文件名采用 `NNNN-中文业务主题.md`；四位编号按 `0001–0999` 跨服务、`1000–1999` Frontend、`2000–2999` Backend、`3000–3999` Agent 分段。
2. 文档用途必须明确，例如“范围与验收基线”“系统总体架构”“模块功能设计”“实施计划”“需求规格”“验收记录”。
3. 同一业务主题跨目录时复用同一编号；一个目录内同一编号最多一份，编号分配后不重排、不复用。
4. 不把日期、状态、`最终版`、`最新版`、`新文档`、`其他`、`杂项`、`相关说明` 写入文件名。
5. 权威设计基线同样遵循编号，例如 `0001-AI短剧制作平台完整设计基线.md`；精确来源标题和版本写在正文元数据中。
6. `README.md` 作为目录入口保留行业惯例；业务文档只进入 `prd/design/requirement/plan/acceptance`，架构与决策记录统一归入 `design/`。
7. 文档标题与文件名使用同一中文主题；代码标识符、协议字段和代码路径仍使用规范英文名。

## 名称层级

同一能力可以有不同展示层，但语义必须可追溯：

| 层级 | 示例 | 规则 |
|---|---|---|
| 文档文件名 | `2002-后端领域模块功能设计.md` | 编号表示服务归属，中文主题说明用途 |
| 产品显示名 | 引导式制作、画布创作、审核工作台 | 面向用户任务，可本地化 |
| 业务能力名 | Guided Production、Authoring、Review | 用于设计和边界讨论 |
| 代码模块名 | `production`、`authoring`、`review` | 单数、稳定、无技术后缀 |
| 运行职责名 | `Workflow Runtime`、`Event Runtime` | 表达单 Backend 进程内职责；不得据此预建独立 Binary/Compose 服务 |
| 协议标识 | `PublishAuthoringRevision` | Command 使用动词，类型使用名词 |
| 存储标识 | `authoring_revision` | snake_case，不泄漏框架名称 |

UI 名称不能反向决定领域名。例如 Canvas 是一种编辑体验，不产生 `CanvasRevision`；规范业务对象始终是 `AuthoringRevision`，来源用 `authoring_mode=CANVAS` 记录。

## 规范模块目录

目标 Go Module 使用以下业务边界；`bootstrap`、`config`、`database`、`cache` 与 `telemetry` 是装配/基础设施，不是业务领域：

```text
backend/internal/
├── bootstrap/
├── access/
├── production/
├── preset/
├── authoring/
├── workflow/
├── review/
├── generation/
├── agent/
├── asset/
├── media/
├── cost/
├── quota/
├── eventing/
├── search/
├── config/
├── database/
├── cache/
└── telemetry/
```

| 业务能力 | 规范 package | 拥有的事实 | 禁止的含糊名称 |
|---|---|---|---|
| Access & Membership | `access` | 身份、Session、Workspace Membership、Role/Access Capability | `identity`、认证散落逻辑 |
| Production Management | `production` | Workspace、Project、Episode、Scene、Shot、Script、Production Bible、StoryGraph 编译关系 | `studio`、`projects`、`scripts`、`storyboards`、独立图数据库作为并列事实 Owner |
| Production Preset | `preset` | Preset/Style/Policy 版本与 Effective Snapshot | 分散的 style/model/qc/render 配置 |
| Authoring | `authoring` | Draft、Revision、Node Catalog、GraphPatch、Graph Validation | Backend `canvas` |
| Workflow Execution | `workflow` | Compiler、Compilation Receipt、Definition Version、Run、Node Run、Temporal 协调和 Cache | 泛化 `task`、`scheduling` |
| Review | `review` | Human Task、Review Decision、审核历史 | 分散的 candidate/draft decision |
| Generation Gateway | `generation` | Generation Request、Provider Job、Candidate、Generation Capability、Routing | `model`、Provider 名称或 `production` 作为生成事实 Owner |
| Agent Orchestration | `agent` | Agent/Skill/Prompt 版本引用、Invocation、Budget、Tool Policy；模型输出只到 Candidate | 进程内 harness 调用逻辑、业务 Owner、StoryGraph Writer |
| Asset Registry | `asset` | Asset、Asset Version、Artifact、Lineage、Storage Location、Rights/Consent | `file`、`media_asset`、孤立 URL 字段、分散 governance consent |
| Media Processing | `media` | Probe、Derivative、Render Manifest、Render/Export Job | 泛化 `processor`、`media task` |
| Cost Control | `cost` | Price、Estimate、Reservation、Ledger、Budget | 分散的费用预留与结算逻辑 |
| Quota Control | `quota` | Quota Policy、Usage Window、Usage Counter、Decision | 分散的限额与高成本保护逻辑 |
| Event Delivery | `eventing` | Outbox、Inbox、Envelope、DLQ、Replay、Projection Checkpoint、Audit Projection | `event`、技术 Topic 调度或同步 Audit Writer |
| Search Projection | `search` | Search Document、Index Version、Reindex Job | 泛化查询工具 |
| Platform Runtime | `config/database/cache/telemetry` | 配置、持久化适配、Cache、Telemetry、Health | 逻辑归类，不合并设计基线中的物理 package |
| Composition Root | `bootstrap` | 各 Binary 的装配和生命周期 | 含糊的 `app` |

新设计、契约和实现只使用规范名，不为研究材料中的其他名称建立兼容入口。

### Production 子域 Owner

`production` 仍是一个 Go Backend 业务域，不因下表拆出第二个 Binary、数据库或微服务。子域名只表达正式事实的唯一 Writer：

| 子域 Owner | 拥有的正式事实 | 不拥有 |
|---|---|---|
| `production/script` | `DocumentRevision`、`ScriptVersion`、`SourceSpanIndexVersion` 与规范化原文 | 身份归并、视觉设计、生成结果 |
| `production/project` | Project/Episode 身份、顺序与项目级生命周期 | Scene 语义、Asset、Artifact |
| `production/bible` | `StructureIdentitySetVersion`、SpecificationVersion、WorldRule、跨集 Claim、Evidence、ProductionBinding | Preset、Scene、Artifact、Shot |
| `production/planning` | Scene、Dialogue、NarrativeBeat、Occurrence、Causal/Continuity Claim；`InteractionClaim` 是受约束的 ContinuityClaim | AssetState、AssetVersion、视觉组合结果 |
| `production/reference` | `ApprovedReferencePlanVersion`、`SceneReferenceBindingVersion`、`InteractionReferenceBindingVersion` | 基础 AssetVersion、Provider Job、ReviewDecision |
| `production/storyboard` | Shot Intent、Shot、ShotProduction/Image/Video BindingVersion | 人物/地点/道具身份和基础版本 |
| `production/storygraph` | 只投影 StoryGraph Schema 明确列入的已确认 Owner 事实，并拥有不可变只读 DAG 版本与线性 Head | 任何上游对象的 Writer、未进入当前 Schema 的新事实 |

`production/reference` 事实及其 StoryGraph 投影的精确范围待 `VP-D05` 通过 Node/Owner/Edge/Schema Version 独立确认；本文的命名不自动使其进入当前 `storygraph-scene-production` 契约。

Go Backend `backend/internal/agent` 是持久化 `AgentInvocation`、`StageCandidateRevision`、Bundle/Prompt/Schema 引用与受控执行事实的唯一 Owner；Python Harness 只返回 Result/Candidate payload，不拥有业务写权。`SceneFactCandidate`、`IdentityResolutionCandidate` 与 `ReferencePlanCandidate` 都是可审核 Candidate，不因名称包含业务语义而获得 Owner 写权。

## 前端功能模块

Frontend feature 按用户任务命名，不能按页面框架或通用技术命名：

```text
frontend/apps/web/src/features/
├── account-access/
├── workspace-shell/
├── project-shell/
├── guided-production/
├── authoring-canvas/
├── review-workbench/
├── asset-library/
├── run-observability/
├── ai-copilot/
└── workspace-governance/
```

共享 package 使用设计接受的短名称，但必须通过语义 subpath 暴露能力：

```text
@lanverse/ui/primitives
@lanverse/ui/feedback
@lanverse/ai/stream
@lanverse/ai/tool-approval
@lanverse/canvas/graph-patch
@lanverse/canvas/run-overlay
@lanverse/sdk/rest
@lanverse/sdk/query
@lanverse/sdk/stream
@lanverse/auth/session
@lanverse/auth/capabilities
```

`ui`、`ai`、`canvas`、`sdk`、`auth` 是已接受的 package 边界，不再二次创建 `design-system`、`api-client` 等别名 package。业务语义由 feature 和 subpath 提供。

禁止 feature/package 名称：`common`、`shared`、`misc`、`utils`、`services`、`manager`、`store`、`helpers`、`studio`。若代码只有一个消费者，先保留在该 feature 内，不为“可能复用”抽包。

## 核心领域对象

| 规范名 | 含义 | 不再使用 |
|---|---|---|
| `Project` | 一部短剧项目及其生产边界 | 含糊的 `Job`、`Work` |
| `AccountEntitlement` | 不依赖 Workspace Membership 的账户级资格，例如创建 Workspace | 把 `workspace:create` 塞入不存在的 Membership |

| `Shot` | 可独立生产和重跑的镜头 | `Clip`；Clip 只用于媒体时间片 |

| `StructureIdentitySetVersion` | Gate 1 通过后由 `production/bible` 发布的不可变决议/引用快照；可反查精确上游 Candidate 修订、ReviewDecision、已接受/已解析 SceneSpan、版本内稳定身份键、完整 Mention→Identity/unresolved 映射与覆盖/内容身份 | 复制 Script/Candidate payload、Asset、Specification、AssetState、正式 Scene、Occurrence、InteractionClaim 或自动创建 StoryGraph Node；后续 Bible/物化只能消费其精确版本，不读 Candidate 或“最新”快照 |

| `StoryGraphVersion` | 已确认 Owner 事实之间的不可变内容 DAG 快照 | `StoryboardGraph`、通用 Knowledge Graph、Authoring/Workflow Graph 副本 |
| `StoryGraphHead` | 一个 Project 当前已发布 StoryGraphVersion 的线性指针 | 多分支 Graph Head、可编辑图 JSON |
| `StoryNodeKey` | 由节点类型、Owner Kind、Owner Logical ID 与 Fragment Key 派生的跨版本稳定键 | Owner Version ID、Authoring Node ID、Workflow Node ID |

| `ProviderJob` | Provider 侧异步任务 | `GenerationRequest` 的别名 |

| `CostLedgerEntry` | 不可变费用账本条目 | 可原地修改的 cost total |
| `QuotaReservation` | 高成本操作执行前的使用量预留 | Cost Reservation、Redis Counter |

Claim 只使用业务需要的严格类型，例如 `RelationshipClaim`、`ContinuityClaim`、`CausalClaim`、`ForeshadowingClaim` 和 `PayoffClaim`；不开放用户自定义 Claim/Edge Type。`CharacterAppearanceVariant`、`CharacterLook`、角色卡和地点卡只允许作为产品显示名或 typed Query View，正式事实分别仍是 `AssetState`、`AssetVersion` 和对应 Owner 组合。

### Interaction 的术语边界

产品可显示“交互”“人物拿道具”“交接”等自然语言，正式名称链只固定为：

```text
raw Mention + Evidence
→ InteractionFact in SceneFactCandidate
→ Identity/State/Occurrence resolution
→ InteractionClaim as constrained ContinuityClaim
→ optional InteractionReferenceBindingVersion
```

`InteractionClaim` 不新增数据库表、StoryGraph Node Type 或 Character-Prop 组合 `AssetState`；它是 `ContinuityClaim` 的受约束子类，`claim_type` 与 predicate 不可混用，跨场长期归属则使用 `RelationshipClaim`。具体 predicate 词表、participant 角色、状态转换、payload 与 Gate 约束必须在后续 `0010`/`3001`/`3003`/`2002` 及 Requirement 中独立接受；当前 `storygraph-scene-production` 不得在 `VP-D05` Schema 更新前投影新约束字段。`ContinuityNotes` 只能是 Candidate 辅助文本，不能替代正式 Claim、Predicate、Anchor 或 Issue。

### 四种图的名称边界

| 规范名 | 回答的问题 | 禁止冒充 |
|---|---|---|
| `StoryGraphVersion` | 剧本、实体、状态、Scene、Beat、Shot 和资产如何关联 | Authoring Graph、Workflow Definition、Temporal History |
| `AuthoringRevision.Graph` | 用户准备怎样编排生产节点和端口 | StoryGraph、已执行历史 |
| `WorkflowDefinitionVersion` | 本次运行按什么依赖执行 | 可编辑 Canvas、业务内容图 |
| Temporal History | Activity、Timer、Retry、Signal 实际发生了什么 | PostgreSQL 业务事实或查询 Projection |

## Command、Query 与 Event

### Command

Command 使用祈使动词 + 业务对象，表达一个原子意图：

```text
CreateProject
ImportScript
PublishAuthoringRevision
StartWorkflowRun
ApplyCandidateSelection
RecordReviewDecision
ReserveCostBudget
```

外部可重试 Command 必须携带 `idempotency_key`；修改并发聚合时携带 `expected_revision`。禁止 `HandleData`、`ProcessItem`、`UpdateStatus` 等无法说明业务效果的名称。

### Query

Query 的动词必须说明只读计算类型：单对象使用 `Get`，集合使用 `List`，全文检索使用 `Search/Suggest`，版本解析使用 `Resolve`，差异使用 `Diff`，只读校验使用 `Validate`，诊断说明使用 `Explain`：

```text
GetAuthoringRevision
GetStoryGraphVersion
ListHumanTasks
SearchArtifacts
ResolveEffectivePolicy
DiffAuthoringRevisions
DiffStoryGraphVersions
ValidateAuthoringGraph
ExplainWorkflowFailure
```

Query 不产生业务副作用；`Validate` 只返回临时报告，若要保存报告必须改为 Command。Query 不使用 `Create`、`Ensure`、`GetOrCreate`。

### Domain Event

Event 使用 `<context>.<aggregate>.<past-tense>`，描述已经提交的事实。名称表达事实语义，不表达发布序号：

```text
production.project.created
authoring.revision.published
workflow.run.started
generation.candidate.created
review.decision.recorded
asset.artifact.registered
cost.reservation.settled
```

Event 名称不能使用命令语气、UI 动作或 Provider 名称。payload 职责发生破坏性变化时使用新的事实语义名，并一次性切换项目内生产者和消费者；不原地改变旧 Schema，也不创建数字版本别名。

## 状态与失败语义

状态只描述一个聚合自身，不把其他系统的推测写成本地成功：

- Workflow Run：`DRAFT / RUNNING / PAUSED / WAITING / SUCCEEDED / FAILED / CANCELLED`。
- Node Run：`READY / QUEUED / RUNNING / WAITING_PROVIDER / WAITING_HUMAN / SUCCEEDED / FAILED / CACHED / CANCELLED / STALE`。
- Provider Job 必须保留 `UNKNOWN`，不能把回调丢失当作 `FAILED`。
- Human Task：`WAITING / CLAIMED / RESOLVED / CANCELLED / STALE`。
- Artifact Readiness：`PENDING_VALIDATION / READY / QUARANTINED / UNAVAILABLE / TOMBSTONED`。
- Media Job：`QUEUED / RUNNING / SUCCEEDED / FAILED / CANCELLED / UNKNOWN`。
- Generation Submission Intent：`PENDING / EXECUTION_CLAIMED / CANCEL_REQUESTED / ACCEPTED / REJECTED / CANCELLED / OUTCOME_UNKNOWN`。
- Cost Reservation：`RESERVED / EXECUTION_CLAIMED / SETTLED / RELEASED / EXPIRED / RECONCILING`。
- Quota Reservation：`RESERVED / EXECUTION_CLAIMED / CONSUMED / RELEASED / EXPIRED / RECONCILING`。

统一错误码使用稳定 snake_case：

```text
unauthenticated
forbidden
not_found
validation_failed
state_conflict
version_conflict
dependency_unavailable
rate_limited
budget_exceeded
outcome_unknown
manual_attention_required
```

错误消息用于用户阅读，错误码用于客户端分支；客户端不得解析中文或英文消息判断状态。

## API、数据库与可观测字段

- REST 资源使用复数名词：`/projects`、`/authoring-revisions`、`/workflow-runs`、`/human-tasks`。
- 项目 REST 路径直接挂载在 `/api`，不使用数字版本路径段；内部 Agent 路径使用能力名，例如 `/internal/storygraph/scene-analysis/invocations`。
- OpenAPI `operationId` 使用规范 Command/Query 名称，生成 SDK 不重新命名 DTO。
- ID 字段使用 `<entity>_id`；版本使用 `<entity>_revision` 或明确的 `<entity>_version_id`，不使用含糊 `version`。
- PostgreSQL 新对象使用 snake_case 业务名，不在表名中出现 `sqlalchemy`、`temporal`、Provider 名或 UI 路由名。
- Trace/Log 使用统一关联字段：`workspace_id`、`project_id`、`episode_id`、`shot_id`、`storygraph_version_id`、`story_node_key`、`authoring_revision_id`、`workflow_run_id`、`node_run_id`、`generation_request_id`、`asset_state_id`、`asset_version_id`、`artifact_id`。
- 已发布的表/API/Event 名称变化时使用明确的新职责名，并在同一完整任务中切换所有项目内调用方和删除旧入口。

### 数字发布后缀禁用规则

以下项目自有标识不得使用 `v` 加序号，也不得用 `legacy/current/latest` 代替业务语义：

| 标识 | 语义化示例 |
|---|---|
| REST 根路径 | `/api` |
| OpenAPI 文件 | `lanverse-public-api.json` |
| Agent Wire | `storygraph-scene-analysis-wire` |
| Kafka Topic | `lanverse.business.script-version.published` |
| Kafka Consumer Group | `lanverse.search-projector` |
| Temporal Task Queue | `lanverse-production-workflow` |
| 日志 Schema | `lanverse.log.application`、`lanverse.log.dead-letter` |
| Elasticsearch Alias | `lanverse-logs-application`、`lanverse-script-search`、`lanverse-storygraph-search` |
| 内容哈希 Domain Separator | `storygraph-scene-analysis-stage`、`story-node-key-owner-fragment` |

`StoryGraphVersion`、`WorkflowDefinitionVersion`、`version_id` 和 `version_no` 表达不可变业务版本事实，不属于发布后缀。第三方 SDK 固有 import 路径、外部 Provider API 路径以及厂商正式产品/模型名属于外部契约，保持原样；Architecture Test 必须只对白名单中的精确外部位置放行。

## 执行约束

1. 新模块创建前必须有首个真实用例、Owner、契约和测试，不创建空目录。
2. Architecture Test 禁止业务代码导入含糊名称 `studio/canvas/model/event/app` 作为领域模块。
3. API/事件/生成 SDK 增加命名漂移检查，禁止同义 DTO。
4. Architecture Test 禁止项目自有 API、Event、Topic、队列、索引、Schema、协议、文件和类型使用数字发布后缀；第三方固定名称只允许精确白名单，不允许目录级放行。
5. Code Review 遇到新名词时先更新本文或对应模块设计，再写实现。
6. 当前 StoryGraph 文档同步和实施门禁只以[文档中心的 `SG-Dxx` 队列](../README.md#当前-storygraph-设计文件推进顺序)为准；已冻结的旧 0→1 Plan 不能作为实现入口。
