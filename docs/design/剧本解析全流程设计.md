# 剧本解析全流程设计

## 1. 问题与决策

当前服务采用 Python 3.11 + FastAPI 模块化单体。剧本解析不是独立 Agent 服务：Skill Harness 与业务模块运行在同一后端代码库中，但保持“模型只给候选、业务服务写事实”的边界。显式结构优先使用确定性 Tool，只有语义理解进入模型，避免把可证明的问题交给不可重复推理。

## 2. 模块边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `scripts/documents` | 上传来源读取、原文/哈希/格式块和问题固化 | 分集物化、模型推理 |
| `scripts/planning` | 分集边界、守恒校验、Episode/ScriptVersion 物化 | 人物消歧、分镜生成 |
| `skills` | 受控工作流、分块、Tool 白名单、超时和结构化输出校验 | 数据库写入、业务批准 |
| `scripts/extractions` | 解析任务、候选持久化、证据和决定 | 绕过候选直接发布事实 |
| `scripts/narratives` | 已确认叙事单元和依赖哈希 | 模型调用 |
| `storyboards/drafts` | 冻结输入、分镜候选、逐条决定、批准与应用 | 修改剧本来源 |
| `production`/`messaging` | 持久 Task、Outbox/Inbox 和 Worker 恢复 | 作为第二业务事实源 |

## 3. 主流程

```text
DOCX/Markdown/Text
  → ScriptDocument + DocumentRevision
  → screenplay_structure Skill
      → segment_script Tool（按显式集标记/场景边界保序分块）
      → 结构化提取（场景、人物、对白、任务、镜头候选）
      → aggregate（跨分块人物与集数合并）
  → EpisodePlan 守恒校验与用户确认
  → Episode + ScriptVersion + NarrativeStructure
  → storyboard_planning Skill（逐集）
  → StoryboardDraftBatch
  → 用户逐条决定、批准、应用
  → Shot + ShotSpecVersion（可导出分镜表）
```

显式集标记必须覆盖并重建原文；没有可靠标记时，Skill 可以给出边界候选，但仍需通过无缺口、无重叠和内容哈希校验。Skill 输出中的 source range 全部使用 Python code point 索引，聚合时转换为整本文档绝对范围。

## 4. Skill Harness

`SkillDefinition` 固定名称、版本、最大输入、超时、候选策略和 Tool 白名单。`SkillHarness` 负责：

1. 校验执行上下文与 Skill 版本；
2. 只向模型发送本次分块必需的原文和已批准事实；
3. 对超时标记 `unknown`，不隐式重试；
4. 使用 Pydantic 模型校验输出和跨候选引用；
5. 在候选门禁后返回 `SkillRun`，不接触数据库写端口。

剧本结构 Skill 的聚合键使用 `episode_number + normalized name/source identity`。人物聚合必须并集合并 `episode_numbers`，`first_seen_episode=min(episode_numbers)`；场景、对白和镜头保持各自的稳定 candidate key。

分镜 Skill 使用冻结的 `StoryboardNarrativeSnapshot` 和资产版本，只允许读取：已确认叙事单元、已批准场景/人物/资产以及当前剧集目标时长。输出必须满足叙事覆盖、时长范围、引用存在性和 schema 约束。

## 5. 数据与状态

现有核心事实保持：`ScriptDocument`、`DocumentRevision`、`EpisodePlan`、`Episode`、`ScriptVersion`、`ExtractionBatch`、`ExtractionCandidate`、`NarrativeStructure`、`StoryboardDraftBatch`、`DraftShot`、`Shot` 和 `ShotSpecVersion`。

所有长流程使用持久 Task 和 Outbox/Inbox。Task 是用户可见状态，消息只负责至少一次投递。幂等键与输入哈希同时参与去重；同幂等键不同输入返回冲突。Worker 在 provider 返回前提交 running 状态，返回后在新事务内校验冻结输入再写候选。

## 6. 失败路径

| 失败 | 状态与处理 |
| --- | --- |
| 文件不可读/格式不支持 | rejected；保留来源版本和明确修正动作 |
| 分集有缺口/重叠/空集 | needs_review；禁止物化 |
| Skill 输出无效或缺少显式剧集 | failed；保存稳定错误码，不写候选事实 |
| 模型超时/响应结果未知 | unknown；用户可对账或启动新版本运行 |
| 剧本/叙事/资产版本变化 | stale/input_version_changed；新建批次 |
| 分镜缺少必需叙事覆盖 | needs_review；禁止批准和应用 |
| Worker 重投 | Inbox 去重并回读同一 Task/Batch，不产生重复事实 |

## 7. 安全与运行

公共入口只有 FastAPI。前端不能调用内部 Skill 或 Worker；Skill 不持有数据库、RabbitMQ、Redis 或通用 MinIO 凭据。后端在构造 Skill 输入前完成 Workspace/Project 授权。开发和验收直接使用本机 Python、PostgreSQL、Redis、RabbitMQ、MinIO 和 Node.js，不使用 Docker。
