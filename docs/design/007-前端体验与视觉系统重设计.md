# DES-007 前端体验与视觉系统重设计

- 状态：accepted
- 日期：2026-08-11
- 输入：[产品调研与核心能力](./001-人工智能短剧平台产品调研与核心能力.md)、[业务闭环与模块协作](./003-业务闭环与模块协作设计.md)、[平台总体需求](../requirement/001-平台总体需求概述.md)、[MVP 产品定义](../prd/001-MVP产品定义与范围.md)
- 输出：Lanverse Web 端信息架构、页面类型、品牌与视觉令牌、组件边界、状态与验收基线

## 1. 结论

Lanverse Web 端不再以传统后台侧栏和卡片墙组织功能，而以“从已确认事实继续生产”为统一体验原则。全站使用一个无侧栏的顶部导航、黑白中性色、Geist 字体、大留白和轻量分隔线；页面只在业务事实需要时使用边框、状态色和浮层。

产品面分为三类：

1. 内容首页：回答“我现在应该做什么”，突出导入剧本、继续制作、当前阻塞和最近项目。
2. 制作详情：回答“这个镜头或单集如何继续”，把画面、镜头序列、候选决策和 readiness 放在同一个工作面。
3. 管理视图：回答“有哪些事实、状态和下一动作”，使用台账式行列、筛选、搜索和明确的行操作，不使用展示型卡片网格。

三类页面共用同一品牌、顶部导航、命令入口、账户状态和组件令牌。页面可以因业务密度不同切换布局，但不得重新创建另一套导航、Logo、按钮或状态体系。

## 2. 产品目标与非目标

### 2.1 目标

- 让 owner 从首页一眼识别当前项目、完成度、阻塞原因和下一动作。
- 让单集与镜头详情围绕人工确认组织，AI 候选不能被误读为已生效事实。
- 让项目、资产、任务、治理和空间等集合页保持可扫描、可搜索、可追溯。
- 让所有主操作、阻塞、错误和恢复动作继续以服务端事实为准。
- 优先使用 shadcn/ui 组件与 Radix UI primitive，减少业务页面自建按钮、标签、选择器、对话框和浮层。

### 2.2 非目标

- 不改变后端模块、OpenAPI 契约、业务状态机或权限边界。
- 不实现一句话无人审核成片、无限画布、专业 NLE 或新的工作流引擎。
- 不以视觉稿中的模拟数字替换 API 事实，也不为视觉还原伪造已完成能力。
- 不增加第二套主题系统、图标库或页面壳。
- 本轮不以移动端为验收目标；窄屏只保证导航、表格和核心操作可达。

## 3. 信息架构与路由映射

| 页面类型 | 路由 | 用户问题 | 主布局 |
| --- | --- | --- | --- |
| 内容首页 | `/` | 下一步做什么 | 编辑式 Hero、生产阶段、当前项目、最近项目台账 |
| 管理视图 | `/projects`、`/studio`、`/governance`、`/workspaces` | 有哪些内容与状态 | 标题与摘要、筛选/搜索、无卡片台账、行级操作 |
| 制作详情 | `/projects/[projectId]`、`/studio/[episodeId]/*` | 当前对象如何继续 | 上下文标题、阶段事实、主工作面、决策/阻塞区 |
| 身份入口 | `/login`、`/register` | 如何进入工作空间 | 品牌说明、标准表单、明确错误与切换入口 |

顶部导航从同一权限定义生成，不在页面内各自维护：未登录只显示首页；`viewer` 显示首页、项目、资产；`editor` 与 `owner` 额外显示治理。空间属于所有已登录用户的账户入口，其中 Workspace 改名、归档和恢复只向该空间的 `owner` 展示。项目级页面可以在导航下方显示项目名称和制作阶段，但不得恢复常驻侧栏。

### 3.1 页面访问矩阵

| 页面能力 | 未登录 | viewer | editor | owner |
| --- | --- | --- | --- | --- |
| 首页 `/` | 可见 | 可见 | 可见 | 可见 |
| 项目与制作详情 `/projects/*` | 登录提示 | 只读 | 可编辑 | 可编辑 |
| 资产与单集工作台 `/studio/*` | 登录提示 | 只读 | 可编辑 | 可编辑 |
| 授权治理 `/governance` | 登录提示 | 403 | 可见，不显示通用审计 | 可见，显示通用审计 |
| 账户与空间 `/workspaces` | 登录提示 | 可见个人资料 | 可见个人资料 | 可见个人资料与空间管理 |

前端权限只控制入口、页面和操作的可见性，不替代后端 `ActorContext` 与 capability 校验。身份必须来自 `/me` 返回的 Membership 角色；加载角色期间不得先渲染受保护入口。直接访问未授权页面显示 403 状态，不存在的路由由根级 404 页面承接。

## 4. 品牌与视觉系统

### 4.1 Logo

- 使用黑色折叠带状标记与 `Lanverse` 字标的横向组合。
- 标记表达两个连续帧、版本与向前流动；不得使用三角形、闪光图标或彩色应用方块。
- 页面使用生成并透明化的真实 PNG 资产 `frontend/public/brand/lanverse-logo.png`，不得用 CSS、内联 SVG 或字符近似重画。
- `StudioBrand` 通过 `size` 与 `mdSize` 的 `l`、`lg`、`xl` 语义档位响应不同视口，并始终使用 `w-auto` 保持原始比例；顶栏使用 `l`，身份入口默认使用 `lg`，不得在业务页面传入固定像素宽度。
- 浏览器页签使用同一资产中的独立折叠带状标记，存放为多尺寸 `frontend/src/app/favicon.ico`，不得另画第二套 favicon。
- 顶栏显示完整锁定组合；极窄屏允许裁切为标记区域，但仍读取同一资产。

### 4.2 令牌

- 字体：Geist Sans；ID、时间、版本和快捷键使用 Geist Mono。
- 背景：纯白或接近白；前景：接近黑；弱化文本：中性灰。
- 主操作：黑底白字；次操作：透明底、轻边框；危险、警告、成功只使用低饱和语义色。
- 圆角：按钮与输入使用 6–8px；对话框 12px；内容分区默认不使用圆角容器。
- 阴影：仅用于 Dialog、DropdownMenu、Popover 等浮层；页面常驻内容不用阴影。
- 分隔优先级：留白与对齐 → 字体层级 → `Separator` → 轻表面色 → 边框。

## 5. 共享组件边界

### 5.1 `StudioShell`

负责 Logo、顶部导航、全局搜索入口、帮助、任务状态、账户菜单、项目上下文和窄屏导航。业务页面只传 `active`、`projectName`、`currentStep`、`topAction` 与 `viewer`，不得复制顶栏。

### 5.2 官方组件优先级

| 需求 | 组件 |
| --- | --- |
| 页面标题与资源上下文 | `PageHeader` 复合 `Item` + `Breadcrumb` + `Badge` + `Separator` |
| 事实指标摘要 | `MetricGroup` 复合 `ItemGroup` + `Item` |
| 主次操作 | `Button` |
| 全局搜索与命令 | `Dialog` + `Input` |
| 账户与行操作 | `DropdownMenu` |
| 顶部页面导航 | `NavigationMenu` |
| 页面/详情切换 | `Tabs` |
| 业务筛选 | `Select` 或 `ToggleGroup` |
| 管理数据 | `Table` |
| 状态提示 | `Alert`、`Badge` |
| 危险确认 | `AlertDialog` |
| 结构分隔 | `Separator` |
| 加载 | `Skeleton` 或带语义名称的进度状态 |

现有 `Card` 只保留在必须作为独立对象、表单分组或空状态的区域。项目、资产、任务和阶段默认使用表格、列表或分隔行，不用嵌套卡片。

业务页不得重复编写“`h1` + 描述 + 状态 + 操作”的 Tailwind 结构，也不直接使用原生 `select`、手工 Dialog Overlay/Content 或自绘图标。页面级标题使用 `PageHeader`，重复指标使用 `MetricGroup`，表单与浮层使用 `components/ui` 中由 shadcn CLI 管理的 Radix 实现；所有界面图标仅从 `lucide-react` 按需导入。

## 6. 页面设计

### 6.1 内容首页

首屏包含一句产品定义、`导入剧本` 主操作、`继续制作` 次操作、当前作品画幅和生产阶段。其下仅保留“当前项目 · 下一步”与最近项目台账。未登录状态将 CTA 分别指向注册和登录；登录状态必须从真实查询读取最近项目，不生成本地模拟进度。

### 6.2 制作详情

详情页遵循“导演工作台”结构：

- 顶部：项目、单集、当前对象、人工确认规则和主要继续动作。
- 左侧：当前画面或对象预览；无媒体时提供事实型空状态。
- 中部：剧本、镜头、资产版本或任务序列，清楚标示当前项和确认状态。
- 右侧：候选选择、readiness、阻塞、费用或下一动作。

不同详情路由可以替换三栏中的业务内容，但交互优先级保持一致：先理解当前事实，再处理唯一下一动作，最后查看支持信息。

### 6.3 管理视图

管理页使用“事实台账”：每行展示稳定身份、当前版本或状态、阻塞摘要、更新时间和操作。顶部摘要只显示帮助筛选与决策的数字，不使用营销型指标卡。搜索、筛选、分页和行操作使用官方组件；归档与删除遵守现有预检和失败路径。

## 7. 数据、状态与失败路径

- `current_stage`、`completion`、`blocking_reasons`、`next_actions`、readiness、Task 和费用全部来自服务端。
- 查询加载时保留页面骨架与稳定标题；不得用模拟成功状态占位。
- 未登录、无权访问、加载失败、空列表、无媒体、版本冲突和任务 unknown 必须分别呈现对应说明与可执行动作；403 与 404 使用统一状态页组件，但给出不同标题、说明和返回路径。
- AI 候选必须显示“建议，非最终”或等价语义；只有确认命令成功后才进入下游。
- Dialog、DropdownMenu、Tabs 和表单必须可用键盘操作；焦点与状态不能只靠颜色表达。

## 8. 响应式与可访问性

- 设计基准：1440 × 1024；桌面可用下限 1024px。
- 低于 1024px 时三栏详情允许变为主内容 + 右侧抽屉或纵向堆叠；主操作不得离开可视区。
- 低于 768px 时顶部导航折叠为菜单，Logo 与主操作保持可见；管理表格允许受控横向滚动。
- 正文 14–16px，主标题根据容器使用 40–64px；长段落最大约 65 个中文字符宽。
- 所有图标按钮有 `aria-label`，表单使用 `Label`，状态图标配合文本，点击目标不小于 32px。

## 9. 验收

1. 三类页面均使用同一顶部导航和真实 Logo 资产，不再出现常驻侧栏与青色品牌图标。
2. 首页首屏同时具备产品定义、主动作、生产阶段、当前项目下一步和最近项目台账。
3. 代表性详情页在同一屏展示当前事实、序列和下一决策；AI 候选的人工确认边界明确。
4. 代表性管理页使用列表/台账而非卡片墙，搜索、筛选与主操作可用。
5. 现有 API 查询、命令、错误处理和路由不因视觉重构失效。
6. `npm run lint`、`npm run typecheck`、`npm test` 与 `npm run build` 通过。
7. 浏览器在首页、项目库、项目详情、资产库与身份入口完成视觉、主交互、控制台和响应式检查；`design-qa.md` 最终为 `passed`。
