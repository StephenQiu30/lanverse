# 管理端与身份入口设计

> Design ID：DES-007
> 状态：baseline（官方脚手架与身份入口已落地）
> 日期：2026-08-22
> 上游设计：[M01 组织、身份与访问详细设计](./modules/001-M01-组织身份与访问详细设计.md)、[后端持久化与统一 HTTP 契约设计](./006-后端持久化与统一HTTP契约设计.md)

## 1. 基线决策

`admin/` 使用官方 Ant Design Pro v6 仓库作为独立管理端基线，保留官方的 Umi Max、Ant Design 6、ProComponents 3、React 19、OpenAPI、必要 Mock、权限和测试结构。

当前官方创建方式是：

```bash
git clone --depth=1 https://github.com/ant-design/ant-design-pro.git admin
cd admin
pnpm install
```

不使用已过时的 `@ant-design/pro-cli` 项目生成命令，也不在官方模板外重新搭建一套同名页面。业务代码按官方目录扩展：`config/routes.ts` 管路由，`src/app.tsx` 管全局初始状态/布局，`src/services/` 管 API 适配，`src/pages/` 管页面。

## 2. 当前官方能力

当前精简后的管理端只保留以下页面和模块：

| 模块 | 路由/目录 | 当前定位 |
| --- | --- | --- |
| 用户入口 | `/user/login`、`/user/register`、`/user/register-result` | 邮箱密码登录、注册和注册结果 |
| 管理/权限 | `/admin`、`src/pages/Admin`、`src/access.ts` | 管理入口和管理员权限基线 |
| 账号 | `/account/settings`、`src/pages/account/settings` | 账号设置模板 |
| 系统错误 | `/exception/403`、`/exception/404`、`/exception/500` | 权限拒绝、找不到页面和服务错误页面 |
| 运行保障 | `src/requestErrorConfig.ts`、Vitest、Biome、OpenAPI 插件 | 统一请求错误、测试、类型和 API 生成基线 |

国际化、语言切换、Dashboard、表单、列表、详情、结果、Welcome 和 Chatbot 等官方示例已移除，避免在业务模块尚未确定前引入无效页面和依赖。

## 3. Lanverse 接入边界

官方模板的演示 API 不视为 Lanverse 业务事实。后续接入必须遵循：

```text
admin/src/pages → admin/src/services → backend Controller Swagger 注释 → backend/docs/swagger.json → Go API
```

- `admin` 不直接连接数据库、消息队列、对象存储或 Python Agent；
- 页面不自行拼接 `Authorization`、Workspace 上下文、`X-Request-Id` 或错误 envelope；
- API 调用优先通过官方 `max openapi` 生成服务文件，使用统一 request 配置；
- 生产身份能力由 Go M01 提供，前端只消费稳定错误码、Session 和授权结果。

## 4. 登录与注册当前切片

本切片把管理端入口接到 Go M01 的最小邮箱密码认证闭环：

1. `POST /api/auth/register` 使用邮箱、密码、显示名和首个 Workspace 名称创建账户、Workspace、Admin Membership，并立即建立登录会话；
2. `POST /api/auth/login` 只使用邮箱和密码，服务端根据账户的有效 Membership 自动确定当前 Workspace；客户端不提交 Workspace ID，也不把它作为登录凭据；
3. 访问令牌是短时 HS256 JWT，仅承载用户、服务端确定的 Workspace、Session ID 和标准 `iss/aud/iat/exp/jti` 声明；业务请求从 JWT 恢复 Workspace 上下文，并回源 PostgreSQL 校验 Session 和 Membership，JWT 不替代撤销检查；
4. 刷新令牌是随机不透明值，只写入 HttpOnly Cookie，数据库只保存 SHA-256 哈希；Redis 负责身份 GCRA 限流、refresh 单航班锁和撤销标记；`POST /api/auth/refresh` 从刷新会话恢复 Workspace 并执行单次轮换，重放旧刷新令牌会撤销整个 Session family；
5. `POST /api/auth/logout` 从刷新会话恢复上下文、撤销当前会话并清理 Cookie，`GET /api/auth/me` 返回当前主体和 Workspace；页面重载时由前端自动调用 refresh，不把访问令牌或 Workspace ID 写入 LocalStorage；
6. 当前账户默认使用其首个有效 Workspace Membership；多 Workspace 选择和切换不属于本切片，未来应作为认证完成后的独立能力设计；
7. 当前不实现邮件发送和邮箱验证状态，邮箱先作为唯一账户标识；邮件提供商和验证流程作为下一切片接入，不返回可用于生产验证的明文 token。

### 4.0 认证与 Workspace 上下文边界

认证凭据和业务租户上下文必须分离：

- 邮箱和密码只负责证明账户身份，不携带 Workspace ID；
- Workspace ID 是服务端根据账户 Membership 确定并写入 Session/JWT 的内部上下文，不接受客户端提供的 `X-Workspace-Id` 作为信任来源；
- 受保护 API 只需要 Bearer JWT，后端从已验证 JWT 恢复 Workspace，再执行 RLS、Membership 和角色校验；
- Workspace 名称仅在注册时用于创建首个 Workspace，注册结果不要求用户保存 Workspace ID；
- 多 Workspace 选择必须在登录完成后单独建模，不能重新把 Workspace ID 塞回登录表单。

PostgreSQL 是账户、Membership 和 Session family 的权威事实源；Redis 不可用时，注册、登录、刷新和受保护请求 fail closed，不使用本地降级放行。

在这些接口完成前，禁止把官方示例账号、Mock 用户或表单提交结果当作 Lanverse 真实身份。

## 4.1 管理员访问与用户管理当前切片

当前角色只有 `admin`、`user`、`ban` 三种：`admin` 可以登录管理端并管理成员，`user` 是普通用户，`ban` 表示被封禁且不能登录。不存在 Owner、Producer、Operator 或 Reviewer 等其他角色。

后端管理接口固定在 `/api/admin` 下，并由已认证主体的 Workspace Membership 角色再次校验：

1. `GET /api/admin/members` 分页查询当前 Workspace 成员，支持邮箱/显示名搜索；
2. `PATCH /api/admin/members/{membership_id}` 修改成员角色或状态；角色仅使用已登记的 `RoleCode`，状态仅允许 `active`、`suspended`、`removed`；
3. Admin 不能修改自己的角色/状态；最后一个 active Admin 不可被停用、移除或降级；
4. 成员被停用或移除后，当前 Workspace 下的 Session 立即在 PostgreSQL 撤销，Redis 继续保存短期撤销标记；
5. 前端 `access.ts` 只将 `admin` 映射为 `canAdmin`，`user/ban` 进入 `/admin` 显示 403；后端不依赖前端隐藏菜单，所有管理接口独立返回 `forbidden`。

当前切片不实现邮箱验证和多 Workspace 成员选择/切换；访问审计沿用 M01 设计并已在后续纵向包落地。

## 5. 下一实施顺序

1. 用 Go Auth/Workspace 合同替换官方登录页和注册页请求，并保留 HttpOnly refresh Cookie；
2. 接入 `/api/auth/me` 和无感刷新，前端只在内存中保存短时 Access Token；
3. 接入 `/api/admin/members` 用户管理页面，完成角色和成员状态操作；
4. 在后端模块合同明确后，按需增加 Workspace、项目和任务管理页面；
5. 对跨 Workspace、Session 撤销、管理员权限拒绝和错误恢复补充前端测试及真实 API/浏览器验收。

## 6. 验收基线

官方脚手架验收命令：

```bash
pnpm run lint
pnpm test
pnpm run build
```

当前验收覆盖邮箱账户、首个 Workspace、JWT 解析、Redis 限流与撤销标记、刷新轮换、重放撤销、登出、受保护请求和管理员角色拒绝；邮件验证和多 Workspace 选择仍是后续切片，访问审计由后续纵向包覆盖。
