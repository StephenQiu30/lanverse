## 1. 基线决策

`admin/` 使用官方 Ant Design Pro v6 仓库作为独立管理端基线，保留官方的 Umi Max、Ant Design 6、ProComponents 3、React 19、OpenAPI、必要 Mock、权限和测试结构。

当前官方创建方式是：

```bash
git clone --depth=1 https://github.com/ant-design/ant-design-pro.git admin
cd admin
pnpm install
```

不使用已过时的 `@ant-design/pro-cli` 项目生成命令，也不在官方模板外重新搭建一套同名页面。业务代码按官方目录扩展：`config/routes.ts` 管路由，`src/app.tsx` 管全局初始状态/布局，`src/services/` 管 API 适配，`src/pages/` 管页面。

## 2. 当前官方能力

当前精简后的管理端只保留以下页面和模块：

| 模块 | 路由/目录 | 当前定位 |
| --- | --- | --- |
| 用户入口 | `/user/login`、`/user/register`、`/user/register-result` | 登录、注册和注册结果模板；当前仍使用官方示例服务和表单字段 |
| 管理/权限 | `/admin`、`src/pages/Admin`、`src/access.ts` | 管理入口和管理员权限基线 |
| 账号 | `/account/settings`、`src/pages/account/settings` | 账号设置模板 |
| 系统错误 | `/exception/403`、`/exception/404`、`/exception/500` | 权限拒绝、找不到页面和服务错误页面 |
| 运行保障 | `src/requestErrorConfig.ts`、Vitest、Biome、OpenAPI 插件 | 统一请求错误、测试、类型和 API 生成基线 |

国际化、语言切换、Dashboard、表单、列表、详情、结果、Welcome 和 Chatbot 等官方示例已移除，避免在业务模块尚未确定前引入无效页面和依赖。

## 3. Lanverse 接入边界

官方模板的演示 API 不视为 Lanverse 业务事实。后续接入必须遵循：

```text
admin/src/pages → admin/src/services（OpenAPI 生成） → backend/api/openapi.json → Go API
```

- `admin` 不直接连接数据库、消息队列、对象存储或 Python Agent；
- 页面不自行拼接 `Authorization`、`X-Workspace-Id`、`X-Request-Id` 或错误 envelope；
- API 调用优先通过官方 `max openapi` 生成服务文件，使用统一 request 配置；
- 生产身份能力由 Go M01 提供，前端只消费稳定错误码、Session 和授权结果。

## 4. 登录与注册当前切片

本切片把管理端入口接到 Go M01 的最小邮箱密码认证闭环：

1. `POST /api/auth/register` 使用邮箱、密码、显示名和首个 Workspace 名称创建账户、Workspace、Owner Membership，并立即建立登录会话；
2. `POST /api/auth/login` 使用邮箱、密码和 `X-Workspace-Id` 校验当前 Workspace 成员关系；
3. 访问令牌是短时 HS256 JWT，仅承载用户、Workspace、Session ID 和标准 `iss/aud/iat/exp/jti` 声明；业务请求仍回源 PostgreSQL 校验 Session 和 Membership，JWT 不替代撤销检查；
4. 刷新令牌是随机不透明值，只写入 HttpOnly Cookie，数据库只保存 SHA-256 哈希；Redis 负责身份 GCRA 限流、refresh 单航班锁和撤销标记；`POST /api/auth/refresh` 执行单次轮换，重放旧刷新令牌会撤销整个 Session family；
5. `POST /api/auth/logout` 撤销当前刷新会话并清理 Cookie，`GET /api/auth/me` 返回当前主体和 Workspace；页面重载时由前端自动调用 refresh，不把刷新令牌写入 LocalStorage；
6. 当前不实现邮件发送和邮箱验证状态，邮箱先作为唯一账户标识；邮件提供商和验证流程作为下一切片接入，不返回可用于生产验证的明文 token。

PostgreSQL 是账户、Membership 和 Session family 的权威事实源；Redis 不可用时，注册、登录、刷新和受保护请求 fail closed，不使用本地降级放行。

在这些接口完成前，禁止把官方示例账号、Mock 用户或表单提交结果当作 Lanverse 真实身份。

## 5. 下一实施顺序

1. 用后端实际 OpenAPI 替换 `config/oneapi.json` 的示例合同并运行 `pnpm run openapi`；
2. 用 Go Auth/Workspace 合同替换官方登录页请求，但不改变官方路由和 ProLayout 结构；
3. 在后端模块合同明确后，按需增加 Workspace、成员、项目和任务管理页面；
4. 增加成员、角色、项目职责、访问审计和紧急恢复页面；
5. 对登录、跨 Workspace、Session 撤销、权限拒绝和错误恢复补充前端测试及真实 API/浏览器验收。

## 6. 验收基线

官方脚手架验收命令：

```bash
pnpm run lint
pnpm test
pnpm run build
```

当前验收覆盖邮箱账户、首个 Workspace、JWT 解析、Redis 限流与撤销标记、刷新轮换、重放撤销、登出和受保护请求；邮件验证、成员管理和多 Workspace 选择仍是后续切片。
