## 1. 需要保护的资产

| 资产 | 影响 | 等级 |

## 2. 信任边界与威胁模型

```text
[互联网] ── HTTPS ──▶ [负载均衡 / WAF] ──▶ backend-api ◀─ SSE ─ 浏览器
                                              │
            ┌───────────── 私有网络（VPC）───┼────────────────────────────────┐
            │  PostgreSQL · Redis · Kafka · Temporal · backend-worker/relay     │
            │  agent-api · agent-worker ───────出站 HTTPS──▶ 模型供应商（境内 / 境外）│
            └──────────────────────────────────────────────────────────────────┘
浏览器 ⇄ 对象存储（TOS）：预签名 URL 直传直下
供应商 ─ 回调（供应商支持时）─▶ backend-api（验签）
```

| STRIDE | 威胁 | 主要对策 | 章节 |
| --- | --- | --- | --- |
| 仿冒 | 撞库、会话劫持、伪造供应商回调、伪造服务间调用 | 锁定与限速、HttpOnly Cookie、会话纪元、回调验签、服务令牌 | §3、§7 |
| 篡改 | 修改他人项目、改历史版本、篡改账本 | 服务端授权、版本表只插入、账本只追加、数据库权限 | §4、§6 |
| 抵赖 | 否认付费确认、否认删除 | 审计（只追加，含 IP、请求 ID） | §10 |
| 信息泄露 | 凭据、剧本、授权材料、预签名 URL 泄露；日志泄露 | 凭据公钥封装、最小权限、短时效签名、日志脱敏 | §5、§6、§12 |
| 拒绝服务 | 大文件、恶意媒体拖垮 FFmpeg、刷报价 | 大小与时长限制、FFmpeg 资源限制、限流 | §7、§8 |
| 权限提升 | Agent 提示注入执行写操作、SSRF 访问内网 | Agent 无写工具 + 提案确认、出站白名单 | §9、§11 |

## 3. 认证

| 项 | 设计 |
| --- | --- |
| 密码存储 | bcrypt（cost 12）；比较使用常量时间；密码规则见 REQ-06 R4 |
| 登录保护 | 账号维度：5 次失败锁定 15 分钟；IP 维度：每分钟 20 次；失败提示不区分账号是否存在 |
| 会话 | 256 位随机令牌；Redis 只存 `sha256(token)`；Cookie `lv_session`：`HttpOnly; Secure; SameSite=Lax; Path=/`；空闲 12 小时、绝对 7 天 |
| 会话失效 | `user.session_epoch` 递增（禁用、重置、改密）；每次请求比对 |
| CSRF | 双提交令牌：`lv_csrf` Cookie（非 HttpOnly）+ `X-CSRF-Token` 头；SSE 为 GET 不改状态 |
| 首次登录 | `must_change_password` 期间只允许改密接口 |
| 初始管理员 | 命令行 `lanverse admin bootstrap`，无默认账号 |
| 服务间 | Go ↔ agent-api：双向服务令牌（HMAC 签名的短期 JWT，60 秒有效，含 `aud`），密钥由密钥管理下发并定期轮换；Agent 工具调用另需会话范围工具令牌（REQ-34） |

## 4. 授权

- **模型**：两种角色（`admin`、`producer`）+ 组织范围。
- **执行点**：统一在应用层用例入口（命令 / 查询）执行，而不是只在 HTTP 中间件：`authz.Require(ctx, action, resource)`；画布、Agent 提案应用复用同一套用例，因而复用同一授权（DES-01 P6）。
- **资源范围**：所有项目级查询带 `org_id` 与 `project_id` 条件；ID 不存在与无权限统一返回 404，避免资源探测。
- **敏感动作矩阵**：

| 动作 | producer | admin | Agent 服务令牌 |
| --- | --- | --- | --- |
| 报价 | ✓ | ✓ | 仅经提案由用户触发 |
| 确认付费（`:confirm`） | ✓ | ✓ | ✗（403，REQ-21 R2） |
| 选定 / 锁定 | ✓ | ✓ | ✗ |
| 预算设置 | ✓ | ✓ | ✗ |
| 凭据、注册表、价格、账号 | ✗ | ✓ | ✗ |
| 人工核对、账本调整 | ✗ | ✓ | ✗ |
| 审计查询 | ✗ | ✓ | ✗ |
| 查看授权材料 | ✓（本项目，写审计） | ✓ | ✗ |

- **测试**：从 OpenAPI 生成越权用例（每个端点 × 无会话 / 其他组织 / 非管理员），CI 必须全部拒绝（REQ-02 SEC-02）。

## 5. 密钥与凭据

### 5.1 密钥清单

| 密钥 | 持有者 | 存放 | 轮换 |
| --- | --- | --- | --- |
| 凭据封装公钥 | backend-api | 配置 | 随私钥 |
| 凭据封装私钥 | agent-worker、agent-api | 生产 KMS / 开发本地文件 | 每年或泄露时 |
| 服务间签名密钥 | Go、agent-api | 密钥管理 | 每 90 天（双密钥过渡） |
| 数据库、Redis、Kafka、Temporal 账号 | 各服务 | 密钥管理注入环境变量 | 每 180 天 |
| 对象存储访问密钥 | backend（签名用） | 密钥管理 | 每 180 天 |
| 会话与 CSRF | 随机生成 | Redis / Cookie | — |

### 5.2 供应商凭据封装（REQ-07）

```text
管理员提交明文 secret（仅此一次，HTTPS）
backend-api：
  dek = 随机 256 位
  ct  = AES-256-GCM(dek, json(secret), aad = provider_id || credential_id)
  wrapped_dek = RSA-OAEP-256(agent_public_key[key_id], dek)
  存 provider_credential.ciphertext = wrapped_dek || nonce || ct ；key_id；last4
  内存中的明文立即丢弃；请求体不进日志（该路由关闭请求体日志）
agent-worker（执行 Activity 时）：
  Go 工作流在调用供应商 Activity 前，由 flow Activity 读取当前启用凭据的密文，放入 Activity 输入的 `credential{id, key_id, ciphertext}`（Temporal 历史中只有密文）
  agent-worker 用私钥（KMS Decrypt）解 dek → 解密 secret → 按 credential.id 进程内缓存 5 分钟 → 调用供应商
```

效果：数据库、Go 服务、备份任一泄露都无法得到明文；只有持有私钥的 Agent 服务能使用凭据（REQ-02 SEC-04）。

### 5.3 开发环境

- `.env` 不入库（`.gitignore`）；仓库只提供 `.env.example`；CI 执行 secret 扫描（gitleaks）。

## 6. 数据保护

| 层 | 措施 |
| --- | --- |
| 传输 | 外部 TLS 1.2+（HSTS）；内部服务在 VPC 内，Temporal、Kafka、Redis、PostgreSQL 启用认证，生产启用 TLS |
| 存储 | PostgreSQL 与 Kafka 数据盘云盘加密；TOS 服务端加密（SSE）；备份加密存储、异地 |
| 数据库权限 | 应用账号：业务 schema 的 DML，版本 / 账本 / 审计表仅 `INSERT, SELECT` + `UPDATE(is_delete, update_time)`；迁移账号独立；只读账号用于报表 |
| 剧本 | 全文存对象存储私有桶；日志与 Trace 只记偏移与摘要；发给境外模型前受项目开关控制（PRV-03） |
| 授权材料 | 单独前缀 `projects/{pid}/consent/`，访问经后端鉴权 + 审计后签发 5 分钟 URL |
| 删除 | 项目彻底删除同时删除对象（REQ-10）；审计按 3 年保留 |

## 7. 媒体与上传安全

| 风险 | 措施 |
| --- | --- |
| 伪装文件类型 | 服务端按 magic bytes + ffprobe 识别；不符即失败（REQ-30 R2） |
| 超大 / 超长文件 | 预签名 PUT 限定 `Content-Length` 与 `Content-Type`；ffprobe 校验时长；分片上传总大小校验 |
| 恶意媒体攻击 FFmpeg | FFmpeg 固定版本并随安全更新升级；`-protocol_whitelist file,pipe`（禁止网络协议与 concat 任意路径）；只处理已下载到隔离临时目录的文件；每个进程 CPU / 内存 / 时长限制（cgroup 或容器限制，超时 kill）；以非 root 运行 |
| 图片解码漏洞 | 缩略图用 libvips（固定版本），限制像素数 ≤ 1 亿 |
| docx 解析 | 使用纯文本抽取库，禁用外部实体与宏；解压大小上限 200 MB（防 zip 炸弹） |
| 预签名 URL 泄露 | 读 URL ≤ 1 小时；供应商读取的 URL 按预计处理时长签发且仅限该对象；日志只记录对象键 |
| 公开访问 | 桶私有、禁止列举；CDN 仅回源签名请求 |

## 8. 出站请求与 SSRF

- 接管供应商结果（`media.Ingest`）会下载供应商返回的 URL：
  - 仅允许 HTTPS；域名须在该供应商适配器声明的白名单内（如方舟、MiniMax、OpenRouter 的结果域名）；
  - 解析后的 IP 不得为私有、回环、链路本地、云元数据地址（169.254.169.254 等），并防 DNS 重绑定（连接时校验实际 IP）；
  - 限制重定向次数（≤ 3，且每跳重复校验）、响应大小（≤ 2 GB）与时长。
- Agent 服务出站只允许访问供应商域名（出口网关 / 安全组白名单）。
- 境外供应商（OpenRouter）经单独的出口，便于审计与按需关闭（CMP-06）。

## 9. 内部通信与部署安全

- 只有负载均衡对公网暴露；`agent-api`、Temporal UI、Kafka UI、Grafana 仅内网或经 VPN / 堡垒机访问，且需登录。
- 容器以非 root 运行、只读根文件系统（媒体 Worker 挂载临时卷）、最小基础镜像。
- 限流（DES-03 §8）+ WAF 基础规则（SQL 注入、路径遍历、异常 UA）。
- 供应商回调：独立路由，验签失败直接 401 并告警；回调只作为唤醒信号（DES-03 §7.4）。

## 10. 审计

- 范围与规则见 REQ-09；审计经 Outbox 写入，保证与业务事务一致。
- 记录 `actor`、`action`、对象、前后值摘要、`request_id`、`trace_id`、`ip`；Agent 提案应用记录 `via_agent_proposal_id`。
- 审计表只追加（数据库权限）；每月分区；导出本身写审计。

| 要求 | 实现 | 功能 |

| CMP-03 内容审核 | 上传素材、剧本、提示词、生成结果审核；审核不可用时不放行；拒绝内容不可选定、不可导出 | REQ-30、DES-05 §6 |

## 14. 日志与追踪脱敏

- 中间件级：请求 / 响应体日志默认关闭；凭据、登录、改密路由强制不记录请求体。
- 字段级：Zap / Python 日志统一经脱敏器，屏蔽键名含 `password`、`secret`、`token`、`api_key`、`authorization`、`cookie` 的字段；URL 去除查询串中的签名参数。
- 追踪：span 属性不记录剧本正文、提示词全文（只记长度与 hash）。
- CI 扫描：集成测试运行后扫描日志输出，出现测试凭据或测试剧本正文即失败（REQ-02 PRV-02）。
