# 调研方法与证据账本

- 编号：RES-001
- 状态：研究快照
- 调研日期：2026-08-14
- 研究对象：VibeReels、即梦、LibTV 三组公开/已授权只读产品证据，16 个 GitHub 固定提交样本
- 目标：为 Lanverse 的产品工作流、模块边界、状态与失败处理提供可追溯证据
- 非目标：移植代码、选择最终供应商、证明生成质量、完成法律意见、用 Stars 评估成熟度

## 1. 研究问题

本轮只回答八类问题：

1. 一个短剧项目如何从剧本推进到逐镜视频候选；
2. 剧本、资产、分镜、关键帧、视频候选和导出之间应如何分责；
3. 高成本异步任务如何记录提交、轮询、失败、取消、未知状态和恢复；
4. 同一镜头的多次结果如何保留，并由人明确选择当前使用项；
5. 上游变化如何使下游结果过期，而不破坏历史证据；
6. 在“不做剪辑与成片”的范围内，如何交付有序镜头视频素材包。
7. 无限画布如何与列表/分镜表共享同一业务真相，而不把布局误作执行依赖；
8. Agent/Skill 如何在最小权限、状态可观察和高成本动作确认下参与制作。

## 2. 证据等级

| 等级 | 定义 | 可支持的结论 | 不可支持的结论 |
| --- | --- | --- | --- |
| E1 | 固定提交中的模型、服务、测试或协议代码 | 该提交确实表达了字段、状态或行为 | 线上部署也按此运行、性能已达生产级 |
| E2 | 固定提交中的架构文档、README、截图说明 | 项目公开声明的定位与工作流 | 声明已被完整实现或长期稳定 |
| E3 | VibeReels、即梦、LibTV 的公开页面或已授权只读界面 | 客户端可见对象、字段、状态与交互 | 服务端技术、数据库、DAG、算法、SLA、账单准确性 |
| E4 | 多个 E1/E2/E3 共同支持的综合推断 | 可提出 Lanverse 产品决策候选 | 自动成为已批准需求或架构 |
| E5 | 尚无直接证据的问题 | 形成待验证清单 | 写成事实、验收项或已决定范围 |

每份项目文档使用以下标签：

- **事实**：可被本页固定链接直接复核；
- **推断**：从事实推得的产品或工程含义；
- **待验证**：证据不足，进入后续 PoC、访谈或设计评审；
- **Lanverse 决策**：本轮研究对当前产品的明确取舍，不代表代码实现方案。

## 3. 方法

### 3.1 样本筛选

样本按“与实际制作闭环的接近程度”筛选，而不是按 Stars 排序：

- 直接产品证据：VibeReels 逐镜制作、即梦智能画布、LibTV 无限画布/工作流/Agent；
- 短剧垂直工作台：LumenX、Jellyfish、LocalMiniDrama、director-ai、ai-story、dramai、Open-AI-Micro-Drama-Generator、Yihen-Drama、waoowaoo；
- 通用生产管线：ViMax、MoneyPrinterTurbo、ShortGPT；
- 通用工作流执行引擎：ComfyUI；
- 补充模式样本：Toonflow-app、wind-comic、drama-skills。

选择标准是能否提供至少一项可核验模式：领域对象边界、任务持久化、候选选择、媒体血缘、失效传播、检查点恢复、导出清单或独立审查。只有营销描述、没有可核验实现或与当前范围无关的项目不进入核心结论。

### 3.2 核验步骤

1. 固定默认分支的提交 SHA 和提交时间；
2. 记录 2026-08-14 查询时的 Stars，仅作检索快照；
3. 以仓库根目录许可证文件为主，GitHub API 识别结果为辅；README 自述与根许可证冲突时单独标注；
4. 阅读 README/架构说明确认项目定位，再读模型、任务、存储、导出和测试文件确认行为；公开产品页只记录可见文案/交互，不从静态资源或客户端表现反推后端；
5. 将每个模式分别写成事实、适用条件、风险、拒绝点和 Lanverse 决策；
6. 只有至少两个不同样本支持，或一个样本有明确代码与测试证据，才进入跨项目综合结论。

### 3.3 时效与可复现性

固定提交 URL 可复现代码和文档内容；Stars 是动态计数，无法由 commit 复现，因此只记录查询时点且不参与成熟度判断。最近提交表示该快照的时间，不表示维护承诺、线上稳定性或项目寿命。

## 6. Stars 与成熟度声明

Stars 只回答“该仓库在查询时被多少 GitHub 账号标记”，不回答以下任何问题：

- 真实活跃用户数、成功完成项目数或付费使用量；
- 多租户隔离、备份、恢复、容量、安全或合规水平；
- README 所列能力是否完整、是否有真实供应商账户验证；
- 维护团队规模、问题响应时间或未来维护承诺；
- 产品与 Lanverse 当前范围是否匹配。

因此综合结论不会把 Stars 作为采纳权重。ComfyUI 和 MoneyPrinterTurbo 的高 Stars 也不会覆盖其“非短剧垂直产品”的分类；dramai 的低 Stars 也不会抹去其导出实现提供的反例价值。

## 7. 许可证使用边界

本研究不建议复制或移植任何项目代码。许可证只帮助解释证据边界：

1. 无根 LICENSE：公开可读不等于有复制、修改或分发授权；
2. README 自述许可证但无根 LICENSE：证据不完整，不能按 README 一句话处理；
3. Toonflow-app：GitHub API 标记 Apache-2.0，但根 LICENSE 追加商业授权和标识限制，不能把 API 标签当标准 Apache-2.0；
4. ai-story 的 CC BY-NC-SA 4.0 与商业 SaaS 目标存在显著边界；
5. waoowaoo：GitHub API 返回 NOASSERTION，根 LICENSE 是 CC BY-NC-SA 4.0 人类可读摘要并明确 NonCommercial，不能作为商业代码来源；
6. ComfyUI 的 GPL-3.0 与本研究无冲突，因为本轮只研究公开模式，不复用代码。

最终法律判断需要逐文件版权、依赖许可证、模型与素材条款、商标和分发方式审查，本账本不构成法律意见。

## 8. 研究限制

- 未执行第三方真实图片/视频生成，不验证质量、费用、并发与供应商补偿；
- 未对所有仓库做全量安全审计或部署验证；
- README 的功能宣称只有在模型、服务或测试中得到交叉证据时，才用于强结论；
- VibeReels 未执行创建、编辑、生成、下载、取消、结算或断线恢复；
- 即梦只核验未登录官方公开页，未上传素材或验证智能画布的任务、版本、恢复与权限；
- LibTV 只核验未登录官方产品/CLI 页，未创建画布、安装 CLI/Skill 或验证登录内工作流；
- “VibeReels”是已核验产品；未找到可核验的一手 GitHub 仓库来证明名为“VibeReels/VibeReels”的开源实现；
- 供应商能力和价格随时变化，进入 Provider PoC 时必须重新核验官方接口。

## 9. 研究完成标准

本轮研究只有在以下条件同时满足时完成：

- 16 个 GitHub 样本都有固定提交、许可证边界和独立分析；
- 每份分析覆盖工作流、模块、任务恢复、媒体、导出、安全、测试、吸收模式与拒绝点；
- VibeReels、即梦和 LibTV 只写公开/已授权可见事实，并明确未登录或后端未知；
- 综合文档把事实提升为有适用条件的产品决策，而非罗列功能；
- 所有内部链接可达，GitHub 引用均绑定固定 commit。
