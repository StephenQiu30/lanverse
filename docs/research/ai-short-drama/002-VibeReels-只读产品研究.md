# VibeReels 只读产品研究

- 编号：RES-002
- 调研日期：2026-08-14
- 对象：[VibeReels](https://drama.moyuai.com.cn/)
- 证据类型：公开页面与用户已授权项目的只读界面
- 操作边界：未创建、修改、生成、下载、取消或付费；不恢复已删除截图
- 结论边界：只证明客户端可见产品事实，不推断后端数据库、队列、供应商或部署

## 1. 结论

VibeReels 最值得 Lanverse 研究的不是页面样式，而是“同一项目上下文中的逐镜生产”：剧本事实、角色/场景/道具资产、资源审核、详细镜头 Prompt、引用资源、生成历史、失败状态、星标/主选和成本提示在一个可追踪流程中连接。

只读证据没有证明整集成片、时间线剪辑、断线恢复、账单准确性或后台架构。Lanverse 因此只吸收其产品对象和操作语义，不把任何不可见实现写成技术事实。

## 2. 证据边界

### 2.1 已证明

- 首页公开展示从剧本分析、资产设计到逐镜视频制作与竖屏结果的产品叙事；
- 已授权项目界面可见项目类型、剧本/分集、角色、场景/道具、风格、视频、协作与成本等项目入口；
- 角色资源可见基础图、剧情状态、出现集、参考图等信息；
- 单镜头可见时长、Prompt、资产引用、资源槽位、模型、历史结果、成功/失败、主选/星标、费用和下载类操作；
- 在进入部分镜头生产前存在资源审核/缺失资源提示；
- 基础图、状态图和视频可分别配置模型，并可见风格与 Prompt 前后缀。

### 2.2 未证明

- 服务端语言、数据库、消息队列、对象存储、部署拓扑和多租户隔离；
- 任务是否具有幂等键、供应商 task ID、断线重连、未知提交恢复与重复扣费防护；
- 费用提示是否等于最终结算、失败是否退回、取消是否生效；
- 生成模型质量、角色一致性、审核准确性或 SLA；
- 批量下载内容是否带固定 Manifest，是否存在真实整集 MP4/SRT 导出；
- 项目类型不可修改时是否有复制迁移或完整影响说明。

## 4. 产品模块观察

### 4.1 项目与剧本

**事实**：项目承载整剧、分集、资产和镜头进度，而不是把每次生成当成无上下文会话。

**推断**：项目应保存可复用事实，Episode/Shot 应有稳定身份；否则逐镜历史、成本和导出无法长期关联。

**待验证**：改稿、拆集、合镜时是否保留旧版本，是否显示受影响资产和镜头。

### 4.2 资产与剧情状态

**事实**：角色可见基础资源与多剧情状态，场景和道具是独立类别。

**推断**：角色身份与“本集服装/伤势/年龄”等状态应分开；一张图片不应同时承担身份、状态和当前主选三个概念。

**待验证**：状态是否版本化、一个镜头如何固定引用某个状态、改图后旧镜头是否过期。

### 4.3 镜头与有序资源槽位

**事实**：单镜头把文本、导演信息、Prompt 和图片/视频/音频资源引用放在一起，Prompt 中可见有序引用语义。

**推断**：镜头规格应显式保存资源槽位及顺序；供应商请求必须记录提交时的引用快照，不能在任务完成后再读取“当前资产”。

**待验证**：槽位删除、重排、资产版本变化如何影响既有生成结果。

### 4.4 候选、主选与星标

**事实**：单镜头可见生成历史、成功/失败、主选/星标与下载操作。

**推断**：Generation Attempt、Video Candidate、Favorite 和 Selected 应分开；“喜欢”可有多个，“当前用于导出”只能有一个。

**待验证**：新结果产生时是否保留人工主选，主选失败/删除时如何处理。

### 4.5 审核与成本

**事实**：资源审核位于高成本生成之前，费用信息靠近项目和操作入口。

**推断**：Readiness 是由缺失事实计算的门禁；费用至少要区分提交前预计与执行后实际。Lanverse 当前不建设商业计费，但必须避免因未知提交状态自动重试造成重复调用。

**待验证**：审核能否解释具体阻塞对象；成本是否按请求、任务、镜头和项目逐级对账。

## 5. 体验亮点

1. 项目上下文连续：剧本、资产、逐镜视频和费用不是四个无关联工具；
2. 资产剧情状态：同一角色可按剧情阶段准备不同参考；
3. 逐镜信息完整：文本意图、资源、模型、时长、历史结果和选择位于同一决策边界；
4. 资源引用可见：创作者能理解 Prompt 与具体媒体槽位的对应；
5. 候选而非覆盖：历史结果可回看，并存在显式选择语义；
6. 高成本前置审核：缺失角色/场景/道具时先暴露问题；
7. 用途级模型配置：基础图、状态图、视频可匹配不同能力；
8. 成本靠近操作：用户在提交生成时能看到消费信息，而不是只看月底汇总。

## 6. 体验风险

- 信息密度：长页面、嵌套卡片和大量小操作在多集项目中会难以扫描；
- 状态混合：阶段状态、任务状态、资源就绪和结果状态若同时显示为“等待/生成中”，用户难以判断下一步；
- 不可逆类型：创建后不可修改，但影响说明和迁移路径未被证明；
- 技术名词：模型版本、供应商通道和审核等级可能增加普通创作者负担；
- 审核概念分散：资源审核、镜头审核、评论、主选和星标需要统一的 Issue/Decision 关系；
- 可访问性：暗色低对比、小标签、图标按钮、长滚动和密集网格需要另行实测；
- 营销与真实能力：公开首页的效率和结果展示不能转为 Lanverse KPI。

## 7. 可吸收模式

| 模式 | 适用条件 | Lanverse 吸收方式 |
| --- | --- | --- |
| 同项目上下文 | 项目包含多个剧集和大量镜头 | 项目、剧集、资产、镜头、任务、媒体通过稳定 ID 关联 |
| 资产剧情状态 | 同一角色跨场次变化 | Asset 身份、AssetState、AssetVersion、媒体候选分层 |
| 逐镜生产卡 | 用户需要局部返工 | 以 Shot 为审核、生成、候选选择和导出最小单元 |
| 显式资源槽位 | 视频模型需要多参考输入 | ShotSpec 保存有序引用，Attempt 固定请求快照 |
| 生成前门禁 | AI 调用昂贵且依赖输入 | 服务端计算 Readiness，并返回阻塞对象与下一动作 |
| 候选与唯一主选 | 同镜多次抽样和人工比较 | 多个 VideoCandidate + 一个显式 ShotSelection |
| 操作旁成本提示 | 用户控制预算 | 展示预计消耗和任务实际消耗，不扩展商业计费系统 |

## 8. 明确拒绝点

Lanverse 不从 VibeReels 推导以下做法：

- 不复制其页面、视觉风格、文案或信息布局；
- 不因前端表现推断后端架构；
- 不把星标等同主选，不用“最新成功结果”自动覆盖主选；
- 不把项目类型默认设计为不可逆；
- 不把供应商名称作为核心领域模型；
- 不把逐镜下载、连续预览或官网样片宣称为整集导出；
- 不恢复已删除的第三方项目截图，也不把只读会话数据继续保存在仓库。

## 9. Lanverse 决策

1. 当前产品主链冻结为：项目/剧集 → 剧本事实 → 资产 → 分镜 → 关键帧 → 逐镜视频候选 → 每镜唯一主选 → 素材包；
2. 不建设时间线、剪辑、字幕、配音和成片；
3. 每次视频生成是独立异步任务，保存提交时的 Prompt、模型参数和资源引用；
4. 每个成功结果形成不可变 VideoCandidate，新结果不覆盖历史或人工选择；
5. 素材包只读取显式主选，按固定镜头顺序输出独立视频与 Manifest；
6. 上游变化使相关候选变 stale，但不物理删除；
7. VibeReels 继续作为产品体验参考，不作为实现、服务端架构或验收事实来源。
