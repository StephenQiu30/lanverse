# AI 短剧产品与开源工作流研究

- 研究快照：2026-08-14
- 文档性质：产品研究与工程决策证据，不是需求、设计或实现说明
- 证据范围：VibeReels/即梦/LibTV 公开或经授权只读产品证据、16 个 GitHub 固定提交；不包含第三方代码复用建议
- 使用方式：先读方法与证据账本，再读单项目分析，最后读跨项目决策

## 核心结论

Lanverse 当前应建设的是“逐镜、可恢复、可选择、可交接”的 AI 短剧制作工作台，而不是一句话黑盒成片器。研究只吸收已经被一手证据证明有价值的产品模式：结构化剧本、可复用资产、稳定镜头身份、异步生成任务、每镜多个视频候选、显式唯一主选、失效传播以及固定素材包清单。

如果引入无限画布或 Agent，必须满足五个约束：空间视图与列表视图同源、节点是类型化领域对象、布局不是业务真相、任务状态可观察、高成本动作先预览再确认。画布与 Agent 用于提升创作效率，不替代项目、镜头、候选、选择和导出事实。

这批研究不授权移植任何项目代码。许可证、Stars、提交日期和技术栈只用于说明证据边界；Stars 不等于产品成熟度，许可证可见也不等于适合复用。

## 分类边界

| 类别 | 主要回答的问题 | 不应直接推导的结论 |
| --- | --- | --- |
| 公开/已授权只读产品证据 | 用户实际看到哪些阶段、对象、状态和操作 | 后端技术、数据模型、算法质量、计费准确性 |
| 短剧垂直平台 | 剧本—资产—分镜—逐镜生成如何组织 | 仓库已有完整生产可靠性或适合 Lanverse 直接实现 |
| 通用视频生产管线 | 长流程如何检查点、恢复、记录产物 | 通用管线等同短剧产品领域模型 |
| 工作流执行引擎 | 队列、验证、事件、取消和历史如何表达 | 节点图就是终端用户应面对的产品界面 |
| 无限画布/Agent 产品 | 空间组织、工作流复用和自然语言入口如何呈现 | 公开页面已经证明生产 DAG、任务恢复或安全边界 |
| 文本技能/规则集 | 决策、来源、失效和审查如何形成证据 | 文件工作流可替代多人产品、媒体任务与权限系统 |

## 研究使用规则

1. 单项目文档中的“公开事实”“推断”“待验证”必须分开阅读，不把推断升级为需求事实。
2. 仓库证据必须回到固定提交 URL；动态 README、动态 Stars 或项目营销文字不能作为稳定验收依据。
3. 只有跨项目重复出现、与 Lanverse 当前边界一致、且能说明失败路径的模式，才进入综合决策候选。
4. 当前不建设剪辑、时间线和整集成片；导出是有序的已选镜头视频及 Manifest，不把多个视频拼接成成片。
5. 当前不讨论商业运营模块；成本只作为高成本 AI 调用的提交前提示、执行记录和失败恢复约束。
6. 即梦和 LibTV 的公开页面只支持产品层观察；未登录字段、任务状态、后端 DAG、存储与安全机制一律标记为待验证。
7. 画布与 Agent 不能绕过正式领域命令、权限、版本、Readiness 和用户确认。
