## 文档规则

1. PRD定义产品意图，REQ定义业务与验收，Design定义模块、状态和失败合同；实现发生变化时先更新对应事实源。
2. 不在总文档复制全量端点、字段、任务和进度；HTTP事实由注解/DTO生成在线Swagger，实际数据库事实只维护Schema。
3. 需要实施的能力统一使用“计划实现”“计划接入”或“实施时须”的表述，说明模块、前置条件与验收方式；不写成已完成事实。候选默认方案与真实未验收边界明确保留。静态、模拟、技术门禁和真实产品验收分别记录，互不替代。
4. 文档规模服从实际职责，不保留调研对话、阶段流水或重复执行计划；固定来源与许可证只在NOTICE/licenses维护。
5. 根目录AGENTS维护协作规则，PROJECT维护工程工具/命令，DESIGN维护视觉标准，BACKLOG维护当前任务与未决项。
