## 结论

本计划从空数据库和无业务代码的 Backend 开始，按业务依赖递增建立唯一事实 Owner，最终完成真实剧本到成片的端到端闭环。所有 Checklist 均从未实施状态开始，只描述目标系统的正向交付。

## 实施原则

- [ ] 按“公开契约 + 领域不变量 + 事务/Receipt + 查询 + 故障验收”交付每个纵向切片。
- [ ] 每个业务事实只有一个 Owner，其他模块只保存 ID + Version、Snapshot 或 Projection。
- [ ] 同 Binary 内的跨模块原子用例使用 Coordinator + 共享 Unit of Work；跨 Binary 使用 Intent/Receipt/Outbox/Saga。
- [ ] 不为目录完整创建空模块；只在首个真实用例出现时建立必要分层。
- [ ] 未通过故障注入和重复投递验收的跨进程闭环不得作为下一阶段前置。
