## 1. PT 接受顺序

PT 按 S2 的 scripts/assets → S3 的 storyboards → S4 的 production 顺序接受，不单独领取或估算；工程实现只领取 PLAN-000 当前切片的 `DEV-*`。S2 只实现文本提取所需的最小 Task/Outbox/Worker；完整 Attempt、unknown、费用和镜头生成必须等 S4 的真实用例，不预建第二套任务框架。

## 6. 执行与验收模板

1. 从 PRD-010 取回当前 PT 的需求叶子和 Design，确认版本、权限、幂等、失败和恢复条件。
2. 先写领域、事务、外部契约和 E2E Red；确定性替身只验证内部状态，不可替代真实 AI 服务验收。若真实流程后来引入编排运行时，必须补充恢复不重复付费副作用的测试。
3. 用公开模块契约获取 ScriptVersionRef、AssetVersionRef、ShotSpecRef、RightsGate 与 MediaVersionRef；禁止跨模块 ORM。
4. 更新 OpenAPI 并生成 client，前端显示服务端 readiness、Task、费用和 next_action。
5. 真实 PostgreSQL/RabbitMQ/MinIO 通过；S4 还必须通过默认 Image/Video Provider 契约和端到端调用。
6. 记录成功、局部失败、重复投递、重启、unknown、取消和费用不变量的真实证据，再申请 accepted。

## 7. 完成门禁

- 25 个 PT 逐项 accepted，且联合链能从 Candidate 反查 Attempt、Task、Request、ShotSpecVersion、AssetVersion、ScriptVersion、MediaVersion/Lineage 和 CostEntry。
- D-003 已按 LangChain + DeepSeek 方案关闭。未提供 `DEEPSEEK_API_KEY`、实际额度或真实调用证据时，只能接受不依赖外部调用的内部契约，不得把 S2 AI 闭环标记为 accepted；S4 的 Seedream/Seedance 仍受 D-004 精确契约约束。
- 不能用“生成成功一次”替代 unknown、幂等、批量局部失败、费用和版本冲突验收。
