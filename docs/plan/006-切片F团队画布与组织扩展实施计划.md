# 切片 F：团队、画布与组织扩展实施计划

> Plan ID：PLAN-F
> PRD：[PRD-F](../prd/006-切片F团队画布与组织扩展PRD.md)
> Design：M01、M06、M12、M14、M15
> 状态：proposed；按能力分别启用

## 1. 前置 Gate

A—E 的核心命令和事实所有权稳定。每个扩展能力必须提供用户样本、采用指标、数据/权限范围、故障模式和退出条件；没有证据的能力不建立空服务或目录。

## 2. 共通基础工作包

| WP | 工作 | 验证 |
| --- | --- | --- |
| F1 | 项目角色、临时 Grant、双人批准策略 | 权限撤销和职责分离 |
| F2 | 外部审片 AccessGrant/通知策略 | 最小可见、到期、下载/撤销 |
| F3 | CanvasView/Layout/装饰边/依赖投影 | 删除节点不删业务、同命令同结果 |
| F4 | TemplateRevision/Release/实例化/迁移 Proposal | 新身份、升级不改项目 |
| F5 | ApiClient/Scope/contract/idempotency/rate limit | UI/API 一致、重复回读 |
| F6 | Webhook 签名/版本/重试/死信/重放 | 通知失败不回滚业务 |
| F7 | 私有 Capability/Extension Manifest（仅 Gate 命中时） | 无旁路、撤销停止新路由 |

## 3. 独立能力 Gate

- 完整画布：先对 B 最小视图做可用性测量，证明空间操作在 3+ 高频流程显著减少步骤；
- SSO/SCIM：确认企业 IdP、JIT/同步冲突、紧急访问和撤销 SLA；
- API/Webhook：冻结首批命令/事件消费者和弃用窗口；
- 私有模型/LoRA：完成数据、资源、健康、回滚和 Provider Adapter PoC；
- 模板：至少两个项目证明重复结构，且权利/敏感字段可安全发布。

## 4. 安全与故障验证

跨 Workspace 模板/API/画布查询、撤销客户端/成员/链接、Webhook 重放/伪造、模板依赖缺失、迁移冲突、私有能力不健康、扩展申请通配 Tool、Rate limit/第三方故障隔离。

## 5. 退出与停止条件

每项能力独立满足 PRD-F 对应验收并记录采用/故障指标后才标完成。若扩展要求数据库直写、画布保存第二套业务关系、模板复制草稿或私有能力绕过 M07/M08/M11/M14，停止该能力并回到 Design，不扩大权限。
