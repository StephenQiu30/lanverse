# 后端运行架构实施计划

- 需求输入：[后端运行架构需求规格](../requirement/2001-后端运行架构需求规格.md)

## 结论

本计划从空项目建立一套可运行、可验证、可观测的 Backend 基础，再为领域服务提供稳定运行平面。所有 Checklist 均从未实施状态开始，顺序只由目标依赖和交付风险决定。

## 实施原则

- [ ] 每个运行程序只在有首个可运行用例、Contract Test 和验收入口时创建，不预建空 Binary 或空分层。
- [ ] 核心契约、状态机和故障语义先写失败测试，再实现最小闭环。
- [ ] 数据库、事件、Workflow、ObjectStore 和投影始终保持唯一事实所有权。
- [ ] 任何外部调用都定义 deadline、幂等、已知失败、结果未知和恢复路径。
- [ ] 完成门以实际命令、输入和结果为准，不以文档复选框替代 Acceptance。

## 阶段 1：仓库、分层与契约源

- [ ] `BE-RUN-001` 建立单一 Go Module、统一工具链和禁止 Python/`go.work` 的架构测试。
- [ ] `BE-ARC-001`–`BE-ARC-005` 建立 Composition、Inbound Adapter、Application、Domain、Port/Adapter 的最小结构和 Import Direction 门禁。
- [ ] `BE-CON-001` 建立 OpenAPI、Backend Proto、Event Schema、Agent Proto 和生成代码的唯一契约源。
- [ ] `BE-CON-002` 建立契约兼容检查、生成漂移检查和 Design → Schema → Test → Generate → Implement → E2E 门禁。
- [ ] `BE-CON-003` 定义 REST 错误包络、游标分页、幂等键、版本冲突、SSE 重连和 gRPC deadline/重试契约。
- [ ] `BE-CON-004` 定义 Event Envelope Schema、严格 Decoder 与多语言 Contract Test。

完成门：

- [ ] 干净仓库可生成全部契约产物且无漂移。
- [ ] Domain 和 Application 依赖方向违反会被 CI 阻断。
- [ ] 破坏性 OpenAPI/Proto/Event 变更会被兼容检查拒绝。

## 阶段 2：数据库、配置与公共 Runtime

- [ ] `BE-DAT-001` 建立 PostgreSQL、Temporal、ObjectStore、Redis 和 Elasticsearch 的事实/投影所有权规则与架构测试。
- [ ] `BE-DAT-002` 实现版本化 Migration、Checksum、Advisory Lock、事务 Receipt 和中途失败回滚。
- [ ] `BE-STO-001` 建立私有 Bucket、短期 Presigned 直传/下载，以及内部操作地址与 Browser 签名地址的严格分离。
- [ ] 建立类型化 RuntimeConfig、Secret Provider、ServiceIdentity、BuildInfo 和配置预检。
- [ ] `BE-RUN-004` 实现公共 Health/Readiness/Version/Metrics 组件，并以一个无业务副作用的最小 API 用例验证。
- [ ] `BE-OBS-001` 实现 JSON 日志、脱敏、有界 Metric Label 和 Trace Context 组件。
- [ ] `BE-RUN-005` 实现统一的停止接流量、Drain、超时与关闭连接生命周期。

完成门：

- [ ] 空库可初始化，重复 Migration 幂等，并发 Migration 受锁保护，错误 Checksum 被拒绝。
- [ ] 配置或 Schema 不兼容时 Runtime 不接流量，Secret 不进入日志或可观测数据。
- [ ] SIGTERM 时已领取工作按策略完成或留下可恢复事实。

## 阶段 3：事件交付与可重建投影

- [ ] `BE-DAT-003` 实现领域事实 + Outbox 同事务写入。
- [ ] `BE-DAT-004` 实现 Debezium/Kafka Connect 发布、Inbox 幂等、聚合分区、DLQ、Replay 和 Projection Checkpoint。
- [ ] 以最小 AuditRecord 事件建立 `event-worker` 的首个可运行投影用例。
- [ ] 建立 Projection Snapshot + Event 全量重建和 Replay/实时消费竞态测试。
- [ ] 以最小业务 SearchDocument 建立 Elasticsearch Versioned Index、Alias 和 Reindex 用例。

完成门：

- [ ] 提交事务最终至少发布一次，回滚事务绝不发布。
- [ ] 重复、乱序、Poison Message 和 Replay 不产生重复投影事实。
- [ ] 丢弃投影后可从权威事实完整重建。

## 阶段 4：Temporal、Workflow Worker 与长任务语义

- [ ] `BE-DAT-005` 实现 Workflow Start/Control/Signal Intent/Receipt、稳定 Workflow ID 和查询投影。
- [ ] 以最小可重放 Workflow/Activity 建立 `workflow-worker`、Task Queue、Retry、Heartbeat 和 Cancellation。
- [ ] 实现 Human Wait 不占 Worker、幂等 Signal 和结果未知对账。
- [ ] 实现 PostgreSQL Run/Node 查询投影重建，并禁止投影反向驱动 Temporal。
- [ ] 建立 Temporal Replay 兼容和版本化 Workflow/Activity 发布门禁。

完成门：

- [ ] Worker 和 Temporal 重启后 Workflow 可恢复，重复 Start/Signal 收敛到同一结果。
- [ ] 代码升级通过 Replay Test，旧 History 不发生非确定故障。
- [ ] Projection 可丢弃重建，Temporal 历史仍是执行权威源。

## 阶段 5：Model Gateway、Media Worker 与受限 Agent

- [ ] 以一个经真实 Provider Contract 验证的结构化文本能力建立 `model-gateway`。
- [ ] 实现 Provider Credential 最小权限、Capability/Model Policy、路由、Fallback、限流、Callback 验签和 Unknown 对账。
- [ ] 以一个确定性 Probe/Derivative 用例建立 Go `media-worker`、临时输出、Receipt 和清理语义。
- [ ] `BE-AGT-001` 建立 Python Agent gRPC API、StructuredExecutor、ToolLoopExecutor 和受限 LangGraphExecutor。
- [ ] `BE-AGT-002` 建立 Agent 无 DB/ObjectStore/Yjs/Shell/任意网络的架构与运行时沙箱门禁。
- [ ] 实现 Run-scoped Execution Grant、Tool Allowlist、模型经 Gateway 调用和步数/调用/费用/deadline 上限。

完成门：

- [ ] Provider 超时、重复回调、Gateway 重启和返回结果未知都有可执行恢复路径。
- [ ] Media 重试不覆盖输入或产生重复最终输出。
- [ ] Agent 无法绕过 Grant、Tool API 或 Model Gateway，所有输出均为结构化 Candidate/Proposal。

## 阶段 6：全链基础设施与发布门

- [ ] `BE-INF-001` 组合 PostgreSQL、Redis、ObjectStore、Kafka、Temporal、Kafka Connect/Debezium、Elasticsearch/Kibana、OTel Collector、Prometheus/Grafana。
- [ ] `BE-INF-002` 为有状态依赖建立持久化、Health、资源限额、私有网络、Secret 注入和生产 Override。
- [ ] `BE-RUN-002`–`BE-RUN-005` 以真实用例完成五 Binary 构建、启动、Readiness、Drain 和最小凭据验收。
- [ ] `BE-SEC-001`–`BE-SEC-002` 完成认证、Workspace RBAC、Callback/gRPC 作用域、fail closed 和 Secret 泄漏门禁。
- [ ] `BE-OBS-001` 完成 HTTP → gRPC → Temporal → Agent/Generation/Media → Kafka 的 Trace 和敏感字段验收。

完成门：

- [ ] 空 Volume 可初始化，已有 Volume 可重启，单依赖失效产生正确 Readiness/Degraded 结果。
- [ ] 生产 Override 不暴露内部端口，不包含开发凭据，每个 Binary 只获得最小权限。
- [ ] 五 Binary、Agent 和所有基础设施通过重启、故障注入和可观测性验收。
