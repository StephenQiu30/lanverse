# 后端运行架构实施计划

- 状态：MVP 已通过；Workflow 持久执行演进中
- 日期：2026-08-25
- 需求输入：[后端运行架构需求规格](../requirement/2001-后端运行架构需求规格.md)
- 设计输入：[后端服务架构](../design/2001-后端服务架构.md)

## 阶段 1：先固定工具与边界

- [x] 固定单一 Go Module、Go Backend 公共入口与 Candidate-only Agent 私有入口。
- [x] 固定 GORM/PostgreSQL Driver、JSONB、Decimal、UUID、Validator、JWT、bcrypt、MinIO 客户端版本。
- [x] 建立唯一 `DATABASE_URL`、唯一 Owner Model Catalog、事务封装、行锁、Command Receipt 与架构门禁。
- [x] 删除 Migration 目录/Binary、迁移 DSN、pgx 业务 Repository和 Go→Python 公共代理。
- [x] 从 Compose 与环境模板删除 Redis/Kafka/Outbox 等 MVP 未使用依赖。

完成门：独立空库启动与重复 Catalog Sync 通过，表清单不存在 Migration 元数据；该完成门需在最终 E2E 再复验一次。

## 阶段 2：按业务所有权落地

- [x] Access：注册、登录、刷新 Session、Workspace 权限。
- [x] Media：私有上传、完整性完成与不可变版本。
- [x] Project/Script：项目、Markdown/DOCX 原稿预览、不可变 Revision。
- [x] Production Bible：持久任务、Agent Candidate、来源证据校验与人工确认。
- [x] Planning/Structure：确定性分集、原子创建/发布、场景/对白/叙事单元/制作任务与人工确认。
- [x] Storyboard/Export：Candidate、逐镜接受、批准、哈希预检、原子 Apply 与确定性 ZIP。

完成门：所有公共路由由 Go 注册，Agent 成功只进入 `needs_review`，未确认/未批准路径全部 fail closed。

## 阶段 3：职责收口与契约

- [x] Agent 启动入口只挂载 Candidate Runtime；运行依赖不包含 SQLAlchemy、asyncpg、Redis、Kafka 或 MinIO 客户端。
- [x] Backend 拥有版本化 Invocation/Result 线协议，Agent 使用严格 Pydantic 模型消费，双方使用短时 HMAC Execution Grant。
- [x] 公共 OpenAPI 由 Backend 静态源提供，删除 Agent 合并/导出公共契约的入口。
- [x] 删除未被运行入口引用的历史 Python 业务 Writer、旧前端兼容页面与旧公共 API 生成服务；保留范围已由导入、路由和全量测试复核。

## 阶段 4：验证与交付

- [x] Go 全量测试与 vet、Agent Candidate 静态/类型/契约测试、Frontend OpenAPI 生成/lint/typecheck/unit/build 通过。
- [x] 在独立空 PostgreSQL 与空 MinIO 运行注册 → 项目 → 原稿 → Bible → 五集 → 结构 → Storyboard → Apply → ZIP 全旅程；真实 Codex Playwright 结果为 `1 passed (16.3m)`。
- [x] 在最终验收前重跑 Frontend OpenAPI/lint/typecheck/unit/build、Go 全量测试/vet、Agent Ruff/Pyright/Pytest 与 Compose/镜像验证，全部通过。
- [ ] 仅在全部开发与自动化完成后，使用 `agent-browser` 执行最终浏览器、键盘、可访问性与刷新恢复验收。

停止条件：真实 Codex 不可用、候选未通过确定性门、输入发生 revision/hash 漂移或依赖未隔离时，不放宽门禁、不伪造媒体/模型输出，也不报告完成。

## 阶段 5：Workflow 持久执行演进

- [x] 为 AgentInvocation 增加单调 Claim Version 与有界 Lease，仍由唯一 GORM Catalog 定义。
- [x] 使用 PostgreSQL 行锁回收过期 `running` Invocation，并以 Claim Version 拒绝迟到结果。
- [ ] Bible 与 Storyboard Worker 使用相同 Lease/Fencing 契约，Resume 不重置 Fencing 序号。
- [x] 通过真实 PostgreSQL 的过期回收、迟到结果、重复领取和全量回归验证，并记录独立 Acceptance。

本阶段只是目标 Workflow 设计的首个可靠执行切片；Heartbeat、Temporal、Compiler、Workflow Definition、Run/Node Projection、HumanTask 与 Signal Receipt 继续由[后端领域服务与生产闭环实施计划](2002-后端领域服务与生产闭环实施计划.md)控制，不在本阶段预建空实现。
