## 1. 目标与完成定义

通过 REQ-15 §3 的 TC-15-01、TC-15-02、TC-15-03、TC-15-04，满足 DES-18 §8–10 非功能与测试设计。[PLN-02 §3.3](02-项目管理与变更.md) 要求 Red → Green → Refactor、质量门禁、演示与追踪矩阵真实更新；未运行不得报通过。

## 2. 前置条件

P0 生图与参考评测、设定集、候选、媒体和过期契约可用；真人授权先用 E-17 契约模拟，E-17 完成后重跑联调。Epic 排序及联调验收以 [BACKLOG](../../BACKLOG.md) 为准。待确认项按对应 REQ §4 与 DES 待确认节的默认方案做就绪评审。数据、接口和工作流权威规范见 [DES-02](../design/02-领域与数据模型.md)、[DES-03](../design/03-接口设计.md)、[DES-04](../design/04-工作流与生成操作.md)。

## 4. 实施顺序

1. **Red**：先为槽位必需性、本集清单、并发锁定、跨集版本与改锁传播写失败的单元/契约测试，再准备跨边界失败场景。
2. **Green**：E-15-01 → 02 → 03；Agent 04 与前端 05 在契约固定后可并行；最后执行 E-15-06。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M3：E-22 → E-15 → E-17）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，每个任务按 PLN-02 §3 独立评审。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用四个候选、20 个引用旧版的镜头、两集共享角色和单集独有角色执行 TC-15-01～04；注入审核未过、授权缺失、并发改锁及传播中断，核验本集清单、跨集复用、PERF-09/AIQ-04（REQ-15 §3；DES-18 §9；TST-02/TST-03）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- 审核或授权未完成仍锁定会留下违规参考：锁定前拒绝并显示待处理原因，旧锁定版本保持可查。
- 改锁事件丢失会使旧镜头看似新鲜：重放锁定事件并重算影响清单，不自动重做镜头。
