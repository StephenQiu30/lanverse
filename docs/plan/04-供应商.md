# Plan 04：供应商

设计入口：[Design 04](../design/04-供应商.md)。当前是待评审方案，接受后再按本次闭环细化技术工作项；原始需求与验收标识不变。

执行编号：04；来源需求模块：09。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 目标与顺序

让生成任务使用服务端可用凭据，并在配置失败时保留原可用状态。

对应[PRD](../prd/04-供应商.md)和[原始规格](../requirement/09-供应商需求.md)；在[整体顺序](00-执行顺序.md)中使用执行编号04，对应原始需求模块09。至少验证承载生图与图生视频的供应商配置，是否同一家由真实能力决定；凭据不写入PRD、浏览器或日志。

本Plan是业务交付切片与验收安排。已形成对应待评审Design，尚无已接受的新数据/接口方案；库表字段、约束及API/DTO合同见对应Design工程节；接受后补精确代码改动、运行设施差异及增量迁移清单，不按旧实现直接开工。Demo相关切片仅在[Demo Plan](06-画布生图生视频Demo.md)编排一次，本Plan用于模块追踪。

## 开工条件与容量

1. 当前切片FR范围及受影响政策已明确接受，引用基线和接受者可追踪。
2. Design说明模块边界、数据/接口、状态、并发、权限和失败路径，外部条件明确。
3. 工程/测试负责人补人员可用时间、估算和周期；目前均待确认，不把整个模块承诺为一个Sprint。
4. Sprint容量确认后，建议预留20%处理缺陷与外部不确定性；只有满足Ready的切片才纳入承诺，未Ready项保留。

## 分步交付与验证

| 顺序 | 用户结果/追踪                                                                        | 工作包（从左到右）                             | 前置与责任                                                                                                             | 通过证据                                                   |
| ---- | ------------------------------------------------------------------------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1    | [US-PROVIDER-01](../prd/04-供应商.md#us-provider-01看清当前配置状态)；FR-PROVIDER-01 | 摘要与掩码规则→管理员只读→管理页状态           | 本片政策/Design已接受；06管理员身份与服务端安全配置读取边界。工程实现，测试核验，产品验收；具体人员待定                | 角色交叉读取、缺配置、测试失败和合成秘密标记检查           |
| 2    | [US-PROVIDER-02](../prd/04-供应商.md#us-provider-02测试后替换凭据)；FR-PROVIDER-02   | 测试合同/费用接受→候选测试与替换→错误/冲突交互 | 本片政策/Design已接受；候选测试/费用及原子替换合同明确；真实供应商条件可用。工程实现，测试核验，产品验收；具体人员待定 | 可控失败与并发更新；真实有限连通验证另记录，不打印实际凭据 |
| 3    | [US-PROVIDER-03](../prd/04-供应商.md#us-provider-03核验活动配置)；FR-PROVIDER-03     | 当前版本绑定→真实测试→摘要刷新                 | 本片政策/Design已接受；已存在活动配置；测试结果需绑定对应配置版本。工程实现，测试核验，产品验收；具体人员待定          | 配置变更中的迟到回执；重复测试；服务不可用与权限拒绝       |

拆分原则：一片交付真实用户结果。估算超过已确认迭代容量时按正常路径/恢复边界继续细分，但不能把只做表单或只写接口当成该片完成。核心逻辑按Red→Green→Refactor；跨边界再接真实存储、浏览器及适用外部验证。

## 风险与阻塞边界

测试具体操作/费用/超时、短密钥掩码、结果有效期、并发替换和测试期间调用规则。

由产品负责人决定业务政策，工程负责人核方案，测试负责人补可执行数据/环境。只阻塞受影响切片；不能用mock或旧枚举填空。供应商覆盖扩展随后评估，不以配置一种供应商证明支持全部能力。

## 验收与完成定义

- 每个US覆盖PRD中的正常结果及四项验收；对照[原始AC](../requirement/09-供应商需求.md#5-验收场景)和[质量条件](../requirement/09-供应商需求.md#4-非功能性需求)补边界证据。
- 对持久写入查真实读回；对异步任务查同一身份、冻结版本与恢复事实；对查询复算范围/结果，不能以固定提示证明成功。
- 代码实施时执行[PROJECT适用门禁](../../PROJECT.md#4-质量门禁)，前端交互增加浏览器验证；外部验证与自动化结果分别记录，未执行项不得填通过。
- 当次记录环境、命令、实际结果、缺陷/限制和接受者；当前执行状态只在[BACKLOG](../../BACKLOG.md)维护。
- 发布、既有数据迁移或真实收费须满足当次明确条件；本次文档整理不执行这些操作。
