## 4. 实施顺序

1. **Red**：先为 TC-17-01～03 与 [DES-20](../design/20-真人授权.md) 的测试设计写失败的领域、契约、集成和必要的交互用例。
2. **Green**：按任务表建立数据/共享契约，接入用例接口、事件/工作流、Agent（如有）及界面；共享接口只在归属 Epic 实现一次。
3. **Refactor**：收敛依赖，执行质量门禁与故障注入，逐项核对设计清单及验收证据。契约固定后，Agent 适配器与界面可并行。
4. **阶段协调**：按 [BACKLOG](../../BACKLOG.md) 对应里程碑的 Epic 实施顺序推进；本 Epic 无后实施联调项。

## 5. 验证与验收

- 质量门禁：按 [PLN-02](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留实际命令、环境、结果和跳过项。
- 本功能专项：写实/风格化上传、授权作废前后报价与在途提交、材料访问审计；TC-17-01～03。测试数据与预期见 [REQ-17](../requirement/17-真人授权.md) §3、[DES-20](../design/20-真人授权.md) 测试设计及 [TST-02](../test/02-需求追踪矩阵.md)。

## 6. 风险与回退

- **风险与回退 1**：用户漏报真人素材：在写实项目上传入口强制回答，引用时再校验；若已流入下游，停用该素材的新引用并标记影响。
- **风险与回退 2**：授权作废与供应商提交竞态：按 P34 区分未提交与已提交；若校验失败，冻结新报价并保留已提交任务对账，不重复提交。
