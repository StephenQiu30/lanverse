完成 REQ-08 §3 的 TC-08-01、TC-08-02、TC-08-03、TC-08-04、TC-08-05，满足 DES-11 §8–10 的非功能与测试要求。遵守 [PLN-02 §3.3](02-项目管理与变更.md)：Red → Green → Refactor、相关门禁、真实演示、设计与追踪矩阵同步；未通过的门禁不可计为完成。

## 4. 实施顺序

1. **Red**：先为版本追加、参数/限制、价格及启用前校验写失败的单元/契约测试，再准备跨数据库、事件和界面的失败场景。
2. **Green**：E-08-01 → 02 → 03；前端 04在契约固定后可并行；最后运行 E-08-05。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M1：E-07 → E-08）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，按 PLN-02 §3 独立评审每个任务。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用同供应商两版模型、9 图上限、两版价格及进行中任务执行 TC-08-01～05；验证发布校验、模式切换、价格版本固化、缓存失效与模拟报价（REQ-08 §3；DES-11 §10；TST-02）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- 注册表缓存失效导致旧价报价：报价时核对权威版本，发现不一致即回源并重报。
- 错误能力或价格版本已发布：停用该模型的新报价并发布修正版，保留已确认任务原版本供核查。
