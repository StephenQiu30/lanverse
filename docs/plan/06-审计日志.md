## 1. 目标与完成定义

完成 REQ-09 §3 的 TC-09-01、TC-09-02、TC-09-03，满足 DES-12 §8–10 的非功能与测试要求。遵守 [PLN-02 §3.3](02-项目管理与变更.md)：Red → Green → Refactor、相关门禁、真实演示、设计与追踪矩阵同步；未通过的门禁不可计为完成。

## 4. 实施顺序

1. **Red**：先为动作覆盖、敏感字段摘要、消费者幂等及只追加权限写失败的单元/契约测试，再准备跨数据库、事件和界面的失败场景。
2. **Green**：E-09-01 → 02 → 03；前端 04在契约固定后可并行；最后运行 E-09-05。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M1：E-09 → E-06）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，按 PLN-02 §3 独立评审每个任务。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用账号、预算、报价、选定等动作执行 TC-09-01～03；重复投递同一 event_id、阻断 Kafka、尝试修改审计行，验证不丢、不重、只追加和 30 天查询指标（REQ-09 §3；DES-12 §10；TST-02）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- 事件通道积压使记录延迟：业务事件留在 Outbox 重放，审计页提示短暂延迟并核对补齐。
- 脱敏遗漏可能泄露剧本或凭据：阻断相关导出/详情，修正字段摘要并检查既有记录与归档后再恢复。
