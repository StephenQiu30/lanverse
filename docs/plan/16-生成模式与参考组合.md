## 1. 目标与完成定义

完成 [REQ-19](../requirement/19-生成模式与参考组合.md) §3 的 TC-19-01～04，覆盖 [DES-22](../design/22-生成模式与参考组合.md) §1 设计清单及测试设计，满足 [REQ-02](../requirement/02-非功能需求规格.md) DES-22 §8 校验性能。按 [PLN-02](02-项目管理与变更.md) §3.3 留存真实的格式、静态检查、单元/集成、Race、漏洞、契约和验收证据。

## 2. 前置条件

- BACKLOG E-19 前置：E-08, E-15, E-18, E-30, E-17；按其里程碑“Epic 实施顺序”推进（[BACKLOG](../../BACKLOG.md)）。
- 联调：E-29；后实施的 Epic 先用契约与模拟替身，完成后重跑本 Epic 验收。
- M1 适用底座与本功能测试数据、模型/供应商 P0 结论按 [PLN-01](01-实施路线与交付计划.md) 和 [BACKLOG](../../BACKLOG.md) 就绪。

## 4. 实施顺序

1. **Red**：先为 TC-19-01～04 与 [DES-22](../design/22-生成模式与参考组合.md) 的测试设计写失败的领域、契约、集成和必要的交互用例。
2. **Green**：按任务表建立数据/共享契约，接入用例接口、事件/工作流、Agent（如有）及界面；共享接口只在归属 Epic 实现一次。
3. **Refactor**：收敛依赖，执行质量门禁与故障注入，逐项核对设计清单及验收证据。契约固定后，Agent 适配器与界面可并行。
4. **阶段协调**：按 [BACKLOG](../../BACKLOG.md) 对应里程碑的 Epic 实施顺序推进；与 E-29 先固定契约及模拟数据，待其完成后重跑联调验收。

## 5. 验证与验收

- 质量门禁：按 [PLN-02](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留实际命令、环境、结果和跳过项。
- 本功能专项：模型上限与类型组合表驱动、前后端同一向量、未就绪/授权作废/新版本；TC-19-01～04。测试数据与预期见 [REQ-19](../requirement/19-生成模式与参考组合.md) §3、[DES-22](../design/22-生成模式与参考组合.md) 测试设计及 [TST-02](../test/02-需求追踪矩阵.md)。

## 6. 风险与回退

- **风险与回退 1**：模型切换使参考数量超限：保留组合并标红，停止报价；允许用户减项或换模型。
- **风险与回退 2**：引用版本更新或授权作废：保持原版本可追溯、阻止新报价；提示用户主动升级或替换，不自动改写镜头。
