## 1. 实施结论

本总 Plan 管理跨 PRD 的排序、技术基线和公共门禁；PLAN-001～PLAN-010 分别承接对应 PRD 的执行细节。全局仍以 S0–S6 纵向切片和 WP-00–WP-12 为唯一排序轴，以 69 个 PT 为产品接受单元，以本文的 `DEV-Sx-xx` 为跨模块工程执行单元。一个工程任务必须同时交付后端事实、OpenAPI/生成 client、需要的前端交互、失败恢复和自动化证据；不拆成“后端阶段”与“前端阶段”。

当前 Requirement、Design 和 PRD 均为 `proposed`，D-001 未关闭。因此本 Plan 现在只能用于评审、估算和关闭准入条件；用户/产品负责人明确接受上游文档前，不创建 backend/frontend/deploy 脚手架，不将 S0 标记为已开工。

### 1.1 冻结的实施技术基线

| 领域 | 本 Plan 只允许的选型 |
| --- | --- |
| 后端 | Python 3.11.15 + uv 0.11.31；FastAPI/Uvicorn/Pydantic v2 |
| 数据 | PostgreSQL 18.4 + SQLAlchemy 2 async + asyncpg；仅空库 `metadata.create_all()`，不引入 Alembic |
| 异步与基础设施 | PostgreSQL Task/Attempt/Schedule/Fire + RabbitMQ/aio-pika；Redis cache-aside；MinIO，上线选定后才增 OSS adapter |
| 媒体 | FFmpeg/ffprobe 8.1.2；I/O 有界线程池与媒体子进程隔离 |
| 前端 | React 19 + TypeScript + Vite + Tailwind v4 + shadcn/ui + Radix UI；TanStack Query + Zustand |
| 契约与质量 | `@umijs/openapi` 生成 client；Ruff/Pyright/Pytest/Testcontainers/Vitest/Playwright；OpenTelemetry + JSON 日志 + Prometheus |
| 交付 | Docker/Compose + GitHub Actions；不引入 Kubernetes、微服务或第二任务系统 |

### 3.2 状态与责任边界

- PT 状态仍只按 PRD 使用 `proposed → ready → in_progress → accepted`，外部条件缺失时为 `blocked`；Plan 不另建第二套产品状态。
- 工程负责人对一个 DEV 任务的前后端、数据、基础设施与回归负总责；模块负责人审查事实归属和公开契约；QA 维护验收 fixture；产品负责人决定 PT 是否 accepted。
- 一次只推进一个主切片。后续切片可进行 spike/契约调研，但不得创建业务表、空模块或宣布完成。
- 未提供团队人数、可用工时和速度数据，本 Plan 不伪造日期/故事点。当当前切片进入 ready 后，由领取人对 DEV 任务估算并排入真实迭代。

## 4. 每个工程任务的交付契约

1. 范围确认：从 PRD-010 取回 PT 对应 ENT/FR/IF/NFR，确认非目标、依赖和外部决策。
2. Red：先在 `backend/tests/` 或 `frontend/tests/` 写失败验收；业务规则优先单元测试，事务/锁/JSONB 使用真实 PostgreSQL，基础设施使用真实契约测试。
3. Green：只创建当前用例用到的 module 文件、Model、Router、Service/Repository 和前端页面/组件，不预建其他模块。
4. Contract：更新 FastAPI OpenAPI，从 URL 生成 `frontend/src/api/`，检查无手写 URL/DTO 和未提交漂移。
5. Frontend：ViewModel 通过 TanStack Query 读服务端事实；Zustand 只保存未提交草稿/选择/布局；命令失败显示服务端 `next_action`。
6. Refactor：只消除当前切片已经出现的重复，运行架构测试，禁止新建全局 `utils/common/shared` 或空转层。
7. Evidence：运行定向测试和 `make check`，在实现完成后记录真实命令、环境、结果与未验证项；中断、skip 或 fake-only 不算通过。

## 10. 风险、停止条件与变更策略

| 风险/停止条件 | 处理 |
| --- | --- |
| D-001 未关闭 | 停在 WP-00，不创建代码脚手架 |
| OIDC/Provider/合规未决 | 只允许契约测试或确定性 fake，相应切片不得退出 |
| RabbitMQ/MinIO 不可用 | S0 setup/ready 明确失败；不自动安装、不隐式启动 Docker |
| 无 Alembic/迁移能力 | 只允许空库 `metadata.create_all()`；一旦需要保留存量数据升级，停止发布并先修订 Design/PRD |
| 供应商返回 unknown | 使用原 provider_request_key 对账；未确认无副作用前禁止新 Attempt |
| 性能基线无固定环境 | 只报功能结果，不报 P95/恢复时限通过 |
| 前端开始复制 Task/readiness/审核状态 | 停止当前任务，删除平行状态机，改为服务端契约 + ViewModel |
| 发现新范围 | 先修 Requirement/Design/PRD/PRD-010，说明替代或推迟哪个 PT，再更新本 Plan |
