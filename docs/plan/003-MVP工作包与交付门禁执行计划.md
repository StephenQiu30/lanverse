## 1. 编排边界

WP 只组合产品任务并管理交付门禁，不替代 PT，也不产生第二套业务范围。代码级跨模块任务以 PLAN-000 的 `DEV-*` 为准，逐 PT 验收以 PLAN-007～PLAN-009 为准。`P003-*` 只是本表检查项编号，不创建重复 Issue、不独立分配 owner 或维护状态。本计划负责让三者在同一当前切片内收敛。

## 4. 领取与状态协议

1. Product/Design gate：定位 PRD、需求叶子、用户结果、非目标、事实所有者和错误路径。
2. DoR 审核：当前切片对应上游范围已在确定 commit 上形成接受记录；依赖 PT accepted；本切片相关外部决定关闭；验收 fixture 可运行且无密钥/真实个人数据。
3. 领取：WP 只表示当前主切片的活动分组，不维护独立任务状态；只领取同一 WP 内的 `DEV-*`，并且不得越过未完成事务/契约依赖。
4. Red → Green → Refactor：先让缺失行为可见，只实现当前用例，再消除当前切片内真实重复。
5. 契约交接：后端 OpenAPI 更新后生成 client，前端只消费生成契约；跨模块只走公开命令/查询/事件。
6. 证据交接：记录测试命令、真实基础设施、浏览器流程、失败路径、跳过项和残余风险。
7. 接受：全部 PT 与 PRD-002 当前切片同时满足后，由产品负责人标记对应 PT accepted，并记录该 WP 的退出；WP 本身不维护 accepted 状态。

## 5. Definition of Ready

- 当前切片对应 Requirement/Design/PRD 范围已在确定 commit 上形成接受记录，PRD-010 中需求叶子有 Design、PT 和验收归属；不得以未来切片仍为 proposed 为由阻塞当前切片。
- 依赖工作包已完成、依赖 PT 已 accepted；只要求当前切片所需决策有可核验关闭证据。
- 成功、失败、权限、并发、恢复和真实依赖 fixture 已明确；交付文件范围不预建未来抽象。
- 未满足任一项时状态为 proposed 或 blocked，不用占位代码制造进度。

## 6. Definition of Done

- 当前 WP 全部 PT 的后端事实、OpenAPI/client、必要前端、失败恢复和验收证据完整。
- Ruff、Pyright、Pytest、前端 lint/type/Vitest、相关 Playwright、OpenAPI 漂移及真实依赖契约通过。
- Workspace 隔离、幂等、不可变、费用、unknown、脱敏和 secret 检查不存在未处理高风险。
- diff 只含当前工作包；测试不进入生产源码目录；缓存、日志、媒体、报告和 `.env` 不进入 Git。
- fake-only、外部依赖缺失、测试中断或 P0/P1 未解决时，不得标记 accepted。

## 7. 评审节奏与变更

- 每次工作包开始前评审 DoR，结束时评审 DoD；不预设没有团队容量依据的日历工期。
- 范围变化先更新 Requirement/Design/PRD，再同步 PLAN-000、对应子计划和当前 WP。
- 工作包退出后才创建 Acceptance 文档；下一个切片的 DEV ready 不等于上一组 PT 自动 accepted。
