## 计划目标

从零建立“完整原稿 → Production Bible → 人工审阅 → 原子确认 → 分集 occurrence →
Storyboard 固定输入”的项目级事实链。计划只描述未来实施顺序，不声明任何能力已经完成。

## 执行原则

1. 先固定业务契约与失败语义，再实现模型编排和正式写入。
2. 每个阶段遵循 Red → Green → Refactor；未通过该阶段退出门不得进入下游写入。
3. 模型只产生候选，确定性 Tool Gate 和人工命令拥有正式事实的决策权。
4. 每个写命令都定义幂等键、expected revision/hash、事务边界、审计事实和冲突响应。
5. 长任务的 lease 只表达所有权，不充当业务超时或效果指标。
6. 60 集真实原稿只在全部基础契约完成后执行，并逐集保留可复查证据。

## 阶段 0：冻结领域与接口契约

### Checklist

- [ ] 定义不可变 document revision、input hash、Bible、Task、Outbox 与幂等创建契约（`PB-FR-001`）。
- [ ] 定义 entity、entity state、world entry、issue、snapshot、occurrence 和来源证据模型（`PB-FR-003`）。
- [ ] 定义 Bible 主流程、异常终态、取消、替代和合法状态迁移矩阵（`PB-FR-007`、`PB-FR-016`）。
- [ ] 定义按 Bible 与项目查询的公开字段、分页、权限和私有字段屏蔽规则（`PB-FR-006`、`PB-NFR-004`）。
- [ ] 定义 create、query、resume、resolution、confirm、cancel 与 impact analysis 的命令契约。
- [ ] 为每个命令先建立成功、幂等重放、陈旧版本、跨作用域和事务回滚的失败用例。

### 退出门

- [ ] 所有核心名词、状态、命令和错误码只有一个稳定定义。
- [ ] `PB-FR-001`、`PB-FR-003`、`PB-FR-006`、`PB-FR-007`、`PB-FR-016`、`PB-NFR-004` 的契约用例可独立复现。

## 阶段 1：实现证据化 Bible Harness

### Checklist

- [ ] 实现对完整原稿连续切块、绝对位置、逐字 anchor、hash、集号和 evidence catalog 的确定性构建（`PB-FR-002`）。
- [ ] 实现 `extract-bible-evidence` 的严格候选 schema 与来源守恒校验。
- [ ] 实现 `reconcile-bible` 的跨区间 identity、alias、state timeline 和 world entry 统一。
- [ ] 实现 `review-bible` 的独立问题发现，禁止 Reviewer 修改候选或确认结果（`PB-FR-004`）。
- [ ] 实现 schema、证据、key、同类型名称/别名、状态时间线和 world rule 的确定性门禁（`PB-FR-005`）。
- [ ] 建立伪造证据、越界引用、悬空实体、别名冲突、互斥状态重叠和世界规则冲突的失败矩阵。
- [ ] 验证 Skill 与本机 Codex 只能读取固定输入并返回结构化候选（`PB-NFR-003`）。

### 退出门

- [ ] `PB-FR-002` 至 `PB-FR-005` 的正常与失败路径均可确定性复现。
- [ ] 任一无证据、越界或冲突内容都不能进入可确认候选。

## 阶段 2：建立长任务所有权、Checkpoint 与恢复

### Checklist

- [ ] 为 evidence、reconcile、review 阶段定义版本化 checkpoint 和完整性哈希。
- [ ] 实现可续租 lease、heartbeat、唯一 run token 与所有写入点 fencing（`PB-NFR-001`）。
- [ ] 实现合法 checkpoint 的 resume，新 Task 保留旧 Task 终态与审计历史（`PB-FR-007`）。
- [ ] 实现 queued/running Bible 的显式取消和本机 Codex 终止（`PB-FR-016`）。
- [ ] 区分确定失败、Provider 结果不确定、用户取消和所有权丢失，禁止伪成功。
- [ ] 建立活跃重投、短暂续租失败、lease 过期、进程重启、旧 token 晚到和取消竞态的故障注入矩阵。

### 退出门

- [ ] 合法恢复只重跑未完成阶段，损坏或跨任务 checkpoint fail closed。
- [ ] 重投、恢复与取消均不产生重复候选、重复正式事实或旧 Worker 写入。

## 阶段 3：完成审阅、决议与原子确认

### Checklist

- [ ] 为每一种 blocker 实现类型化 resolution command，覆盖状态边界、身份合并/拆分、名称/别名、entity kind、state 增删、world entry 和 issue 判定（`PB-FR-008`）。
- [ ] 为项目资产匹配实现显式 link/unlink 命令，禁止近似字符串自动合并（`PB-FR-010`）。
- [ ] 实现 blocker 清零门与 expected revision/result hash 校验。
- [ ] 实现 entity → 唯一 Asset、state → AssetState/AssetVersion 的原子幂等物化（`PB-FR-009`）。
- [ ] 在 resolution、link 和 confirm 中写入追加式审计事实与回放 receipt（`PB-NFR-002`）。
- [ ] 建立同名不同主体、同主体多别名、双胞胎、伪装、跨时间线状态和跨作用域资产链接矩阵。

### 退出门

- [ ] 每一种 blocking issue 都可通过公开业务命令闭环。
- [ ] 冲突、重放或事务中断不会留下半 Asset、半 State、重复版本或丢失审计事实。

## 阶段 4：接通发布、分集与 Storyboard 输入

### Checklist

- [ ] 以同一 document revision 的 confirmed Bible 作为 ImportCommit 发布硬门（`PB-FR-011`）。
- [ ] 为同一导入批次的全部分集冻结统一 Bible id、revision 与 result hash。
- [ ] 将分集输出限制为 scene、dialogue、occurrence 和 continuity 候选（`PB-FR-012`）。
- [ ] 在结构确认时把 occurrence 锚定到 narrative unit version，并拒绝未知或类型不匹配引用。
- [ ] 把未知或歧义身份持久化为幂等 reconciliation issue（`PB-FR-013`）。
- [ ] 从目标剧集 occurrence 自动派生 Storyboard 资产状态与相关 world entry（`PB-FR-014`）。
- [ ] 建立发布重放、snapshot 漂移、无关全项目资产过滤和下游反向追踪用例。

### 退出门

- [ ] `PB-FR-011` 至 `PB-FR-014` 的完整链路通过，调用方无需手工注入 Bible 资产。
- [ ] 任一镜头输入都可反查 occurrence、asset state、Bible snapshot 和原文证据。

## 阶段 5：实现版本替代与影响传播

### Checklist

- [ ] 为更新 document revision 创建独立 Bible，并保持旧 snapshot 不可变。
- [ ] 确认新 Bible 时原子标记旧 Bible 为 `superseded`，确保项目有效 Bible 唯一（`PB-FR-015`）。
- [ ] 计算结构、occurrence、资产版本、Storyboard 与导出的影响集合和 impact hash。
- [ ] 在用户确认传播前冻结下游引用，禁止静默替换。
- [ ] 建立无影响、局部影响、全量影响、传播竞态和回退查阅矩阵。

### 退出门

- [ ] 新旧 Bible 均可追溯，影响预检与实际传播结果一致。
- [ ] 更新原稿不会原地改变被正式分镜固定的资产版本。

## 阶段 6：真实 Codex 与 60 集验收

### Checklist

- [ ] 固定真实原稿、独立基线、输入哈希、Codex/model/Skill 版本和验收环境。
- [ ] 对 139,723 字、60 集执行完整 Bible 生成、审阅、决议、确认和物化（`PB-NFR-005`）。
- [ ] 发布 60 集并逐集统计 scene、dialogue、occurrence、未知引用、issue 和幂等重放结果。
- [ ] 为 60 集生成 Bible-backed Storyboard candidate，并验证全量反向追踪。
- [ ] 对 E01、E07、E09、E31、E36、E60 进行独立人工细查，不以代表集替代全量机器统计。
- [ ] 注入重启、重投、短暂续租失败、lease 过期、取消和 supersede 场景。
- [ ] 记录输入、版本、环境、执行步骤、结果、失败样本、人工修订和未决风险。

### 退出门

- [ ] [完整剧本业务闭环验收标准](../acceptance/3001-完整剧本业务闭环验收标准.md)中的全部 Requirement 与 60 集条目均已由独立证据确认。
