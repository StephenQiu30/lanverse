## 4. 实施顺序

1. **Red**：先为密码规则、锁定、会话纪元、最后管理员、并发修订写失败的单元/契约测试，再准备跨数据库、事件和界面的失败场景。
2. **Green**：E-06-01 → 02 → 03；前端 04在契约固定后可并行；最后运行 E-06-05。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M1：E-09 → E-06）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，按 PLN-02 §3 独立评审每个任务。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：重点以管理员与制作者账号、双浏览器及 Redis 故障为数据，执行 TC-06-01～09；注入连续错密、禁用、重置、并发修订与 Redis 中断，验证立即失效、锁定剩余时间、最后管理员保护及 503（REQ-06 §3；DES-09 §9；TST-02）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- Redis 不可用会使登录与会话校验失败：保持拒绝访问，恢复后重新登录，不回退到免校验。
- 账号变更或会话纪元更新失败会留下旧权限：事务失败回滚账号修改，核对审计和会话失效结果后再开放操作。
