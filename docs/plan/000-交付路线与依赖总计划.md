## 1. 执行结论

首轮交付遵循 `A → B/C → D → E → F`。A 先证明不依赖 Agent 和真实 Provider 的手工事实主线；B 和 C 在 A 通过后可独立进入，C 不以 B 为前置；D、E 依赖真实媒体事实；F 不作为一个大版本，而是按能力逐项过 Gate。

```text
A 手工事实主线
├── B 受限 Agent 提案
└── C 真实生成 → D 质量修复 → E 审阅交付
                                  └── F 组织扩展（逐能力 Gate）
```

## 2. 总体交付物

| 交付物 | 固定决策 | 完成证据 |
| --- | --- | --- |
| 前后端边界 | `frontend/` 承担 View/ViewModel；`backend/` 用 Go 实现业务；顶层 `agent/` 用 Python 实现私有 Agent 微服务 | 目录边界扫描、依赖方向测试、服务身份负向测试 |
| 数据与对象 | PostgreSQL 当前 Schema、Redis、MinIO；不维护历史 migration 和兼容链 | 空库初始化、严格漂移失败、备份恢复演练 |
| 异步与执行 | backend 统一维护一个 Kafka 集群；Agent 不连接 Kafka | 重投/重平衡/进程重启故障证据 |
| 搜索与观测 | Elasticsearch 用于业务检索；OpenTelemetry/Elastic 观测与业务索引逻辑隔离 | 索引重建、租户过滤、Collector 中断证据 |
| 接口合同 | 唯一当前 OpenAPI，无 `/v1`；Go strict server、Swagger、前端生成 API 同源 | 生成无漂移、UI/API 合同一致 |
| 产品交付 | A—F 各自的 P0 验收条件全部有真实证据 | `EPK-<切片>-*` 对应的实际 EV 记录 |

## 4. 共通实现顺序

每个切片内部遵循以下顺序：

1. 接受对应 PRD/Design，冻结本切片 ID 范围和数据集；
2. 先为领域不变量、状态机和失败路径建立 Red 测试或等价失败验收；
3. 在 Go 中实现应用 Command/Query、POJO 等价 Domain、Service 和事务边界；Agent 能力只通过 backend 端口调用私有 Python 服务；
4. 更新 PostgreSQL 当前 Schema，并验证空库初始化和严格漂移；不创建 migration 版本链；
5. 异步任务只接入 backend 的同一 Kafka 集群；分布式互斥、幂等和限流按 Design 使用 PostgreSQL/Redis，不引入第二套消息队列；
6. 先修改本地唯一 OpenAPI，再生成 Go 服务边界和前端 API；ViewModel 只经 Axios `request.ts` 调用生成函数；
7. 完成最小 UI/API/任务状态路径，运行权限、并发、幂等、故障注入和端到端验收；
8. 归档实际证据、已知风险和回退策略，再决定是否进入下一切片。

## 6. 共通完成定义

- P0 验收条件都有自动化测试或明确人工步骤，且执行证据可复现；
- 真实 PostgreSQL 集成、唯一 Kafka 故障注入、契约测试和切片 E2E 通过；
- 无跨租户泄漏、重复不可区分事实、重复外部副作用或无记录长任务；
- `failed`、`unknown`、`partial` 均有用户可见状态和安全恢复动作；
- Swagger、Go 边界与前端生成 API 来自同一已提交 OpenAPI，生成后工作区无漂移；
- 缺少真实外部条件的验收保持 `not_run` 或 `blocked`，不得报告为通过。

## 7. 停止与回退条件

出现以下任一情况，停止扩大功能并回到 Requirement/Design：

- 事实所有权冲突，或 UI/API/Agent 对同一业务命令产生不同语义；
- 外部副作用无法幂等、查询或对账；
- 缺少样本版权、Provider 数据条款、代表性数据或真实故障环境；
- Agent 需要公共入口、业务库、Kafka、Redis 或 Elasticsearch 凭据；
- 搜索和观测互相成为可用性依赖，或需要按用户/Workspace 建索引；
- 为推进当前功能而引入兼容层、历史 migration、第二套消息队列或无证据的微服务。

失败发布只回退可执行制品和流量，不回写或破坏已提交业务事实；涉及 Schema 的回退必须使用已验证的备份恢复方案，不维护双版本数据模型。

## 8. 延后能力 Gate

Temporal、Kubernetes、图数据库、gRPC、完整画布、公共 API 和私有模型只在对应 Design 的证据 Gate 命中后进入 Plan。ToC 上线前必须重新进行容量与故障域评审，并把业务检索和观测负载拆成独立故障域；这不是首轮 A 的默认部署前置。
