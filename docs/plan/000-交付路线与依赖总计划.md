# AI 视频生产平台交付路线与依赖总计划

> Plan ID：PLAN-000
> 上游：[PRD 索引](../prd/README.md)、[模块 Design](../design/modules/README.md)
> 状态：proposed

## 1. 执行结论

研发按 A→B/C→D→E→F 推进。B 与 C 在 A 通过后可分别准备，但 B 不能成为 C 的前置；核心手工闭环和真实执行必须在 Agent 不可用时成立。每个切片只在退出证据齐全后关闭。

```text
A 手工事实主线
├── B Agent 提案
└── C 真实生成 → D 质量修复 → E 审阅交付
                                  └── F 组织扩展（逐能力 Gate）
```

## 2. 共通工程顺序

1. 接受对应 Requirement/PRD/Design，冻结本切片 ID 范围；
2. 为领域不变量和状态机写失败测试；
3. 在 Go 中实现应用 Command/Query、POJO 等价 Domain 与事务边界；
4. 实现 PostgreSQL `schema/current.sql` 空库初始化、严格漂移拒绝、RLS 和 Outbox；不建立 migration 版本链；
5. 接 Worker/Adapter/媒体或 Agent，先 Fake 再真实外部；
6. 实现最小 UI/API/SSE 接管路径；
7. 运行权限、并发、幂等、故障注入和端到端验收；
8. 保存验收证据、已知风险和回退策略，再更新状态。

## 3. 共通完成定义

- Requirement ID → Design → PRD → Plan → Test/Evidence 可追踪；
- 领域测试、真实 PostgreSQL 集成、契约测试和切片 E2E 全通过；
- 无越权、跨租户、重复副作用和无记录长任务；
- 失败/unknown/partial 有用户可见恢复路径；
- 指标、Trace、审计和操作手册能定位切片故障；
- 未具备外部条件的验收明确未执行，不报告通过；
- `git diff --check`、文档链接和工作区边界检查通过。

## 4. 停止条件

出现事实所有权冲突、无法幂等的外部副作用、缺少权利依据、无法构造代表性数据、Provider 不支持必要对账、Go 业务角色或 Python Agent 边界未通过故障恢复时，停止扩大功能并回到 Requirement/Design 修正。

## 5. 技术演进 Gate

语言边界已经冻结：业务后端与非 Agent Worker 只用 Go，Agent Runtime 只用 Python。容量优化不得通过复制业务规则、拆微服务或让 Python 直写业务事实解决；任何边界变化必须先修改 000 Design 并重新评审。

Temporal、Kubernetes、图数据库、gRPC、完整画布、公共 API 和私有模型按当前 Design 中证据 Gate 引入，不作为基础计划默认依赖。
