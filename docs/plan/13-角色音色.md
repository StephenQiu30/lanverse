## 1. 目标与完成定义

通过 REQ-16 §3 的 TC-16-01、TC-16-02、TC-16-03，满足 DES-19 §8–10 非功能与测试设计。[PLN-02 §3.3](02-项目管理与变更.md) 要求 Red → Green → Refactor、质量门禁、演示与追踪矩阵真实更新；未运行不得报通过。

## 2. 前置条件

TTS 模型、角色和报价能力可用；E-29 的台词音频先按契约模拟过期消费，E-29 完成后重跑联调。Epic 排序及联调验收以 [BACKLOG](../../BACKLOG.md) 为准。待确认项按对应 REQ §4 与 DES 待确认节的默认方案做就绪评审。数据、接口和工作流权威规范见 [DES-02](../design/02-领域与数据模型.md)、[DES-03](../design/03-接口设计.md)、[DES-04](../design/04-工作流与生成操作.md)。

## 4. 实施顺序

1. **Red**：先为音色枚举、修订、试听复用与配音过期范围写失败的单元/契约测试，再准备跨边界失败场景。
2. **Green**：E-16-01 → 02 → 03；Agent 04 与前端 05 在契约固定后可并行；最后执行 E-16-06。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M3：E-16；E-29 在 M4 后实施）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，每个任务按 PLN-02 §3 独立评审。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用带官方示例的 TTS 模型、37 句已生成配音和重复试听文本执行 TC-16-01～03；核验付费试听确认、同输入复用、换模型重选音色与仅该角色音频过期，检查 PERF-09（REQ-16 §3；DES-19 §9；TST-02）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- 音色下架或模型切换后旧 voice_id 不可用：阻止新报价、提示重选音色，既有音频保留但标记过期。
- 试听复用判断失效可能重复计费：冻结新试听报价，核对输入与历史结果后恢复。
