## 2. 前置条件

## 4. 实施顺序

1. **Red**：先为 TC-24-01～04 与 [DES-27](../design/27-任务中心与对账.md) 的测试设计写失败的领域、契约、集成和必要的交互用例。
2. **Green**：按任务表建立数据/共享契约，接入用例接口、事件/工作流、Agent（如有）及界面；共享接口只在归属 Epic 实现一次。
3. **Refactor**：收敛依赖，执行质量门禁与故障注入，逐项核对设计清单及验收证据。契约固定后，Agent 适配器与界面可并行。
4. **阶段协调**：按 [BACKLOG](../../BACKLOG.md) 对应里程碑的 Epic 实施顺序推进；与 E-23、E-33 先固定契约及模拟数据，待其完成后重跑联调验收。

## 5. 验证与验收

- 质量门禁：按 [PLN-02](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留实际命令、环境、结果和跳过项。
- 本功能专项：模拟供应商受理未知/未受理/重复回调/链接过期/查询 5xx，断言状态与账本；TC-24-01～04。测试数据与预期见 [REQ-24](../requirement/24-任务中心与对账.md) §3、[DES-27](../design/27-任务中心与对账.md) 测试设计及 [TST-02](../test/02-需求追踪矩阵.md)。

## 6. 风险与回退

- **风险与回退 1**：供应商超时被误当失败而重新提交：未知状态只查询对账；查询不足时转人工，停止自动重试。
- **风险与回退 2**：取消与回调竞态产生错账：以工作流事件确定终态并逐项结算；差异时进入人工核对并保留调用记录。
