## 结论

本台账在任何实现开始前分配权威事实、命令入口、事件、运行历史、对象和投影的唯一 Owner。它不是对现有 Schema 或代码的盘点，也不因目录或类型存在而改变状态。

每个资源交付时必须同时完成：Owner 状态机、Application Command/Query、持久化、版本/幂等、Outbox、权限、观测、测试、故障恢复和 Acceptance。其他模块只能持有 ID、不可变 Snapshot 或可重建 Projection。

## 所有权规则

- 一个业务事实始终只有一个 Writer；跨模块共享数据库不代表可以跨 Owner 写表。
- PostgreSQL 保存业务事实，Temporal 保存 Workflow History，ObjectStore 保存对象字节。
- Kafka 传输已提交事件；Elasticsearch、Redis、Yjs 和分析表均为可重建或临时状态。
- Browser、Agent、Provider、Media 工具和 Projection 不得直接修改 Owner 事实。
- 同一强一致旅程必须由明确 Coordinator 与共享 Unit of Work 收口；跨进程使用 Intent/Receipt/Saga。

## 运行与存储所有权

| 资源 | 权威 Owner | 规则 |
|---|---|---|
| REST/SSE | Backend OpenAPI + 对应业务模块 | Handler 只做协议转换；Command 由 Application 执行 |
| Backend gRPC | Backend Proto + 提供能力的模块 | 声明 deadline、重试、幂等和结果未知语义 |
| Agent gRPC | Agent Proto + Backend Agent Orchestration | 只传 Run-scoped Grant 与结构化结果 |
| Temporal Workflow | `workflow` | History/Timer/Retry/Signal 权威；业务投影不得反向驱动 |
| Kafka Topic/Event | 事件 Schema + 产生事实的 Owner | Producer 与 Consumer 均版本化；Consumer 以 Inbox 幂等 |
| ObjectStore Prefix | `asset` | Bucket 私有；Location/Lineage 属于 PostgreSQL 事实 |
| Redis Namespace | 使用它的 Owner | 只保存 Session、Cache、Rate Limit、临时锁；必须可过期/重建 |
| Elasticsearch Index | `search` | 只读投影；不可用不影响 Command 提交 |
| Yjs Room | `authoring` 的协作适配层 | 只做活动草稿恢复；发布事实为 PostgreSQL Revision |
| Telemetry | Platform Runtime | 指标标签有界、日志脱敏、Trace 跨协议传播 |

## 不可拆强一致旅程

| 旅程 | Coordinator | 必须同一提交的事实 |
|---|---|---|
| 注册 | `access` Application | User、Workspace、Owner Membership、Registration Receipt、Outbox |
| Bible 确认 | `production` + `asset` 公开接口 | Bible Version、Asset/State/Version、Materialization Receipt、Outbox |
| Authoring 发布 | `authoring` | Revision、Policy/Node Catalog 绑定、Publish Receipt、Outbox |
| 高成本准备 | 发起模块 Coordinator | Intent、Cost Reservation、Quota Reservation、Outbox |
| Candidate 选择 | `generation` + `review` Receipt | ReviewDecision 引用、CandidateSelection、Production Apply Intent |
| Media 完成 | `media` + `asset` 命令 | Media Receipt、Artifact/Lineage 登记、Outbox |

跨进程执行、Provider 调用和 Temporal Start 不能加入数据库事务，必须以持久 Intent、稳定 ID、幂等 Receipt 和 Reconcile 收敛未知结果。

## 单资源交付 Checklist

每个 `OWN-*` 条目在实施时复制以下清单并填写精确资源；初始均为未完成：

- [ ] Owner、状态机、不变量和失败终态已接受。
- [ ] Command/Query、认证、权限、幂等和 expected revision 契约已接受。
- [ ] 表/列/索引/Migration 或外部资源命名已接受。
- [ ] Outbox Event、Topic、Partition Key、Consumer Group 与 Schema 已接受。
- [ ] ID/Version/Snapshot/Projection 的跨模块读取边界已接受。
- [ ] Red 单元、Contract、Integration、E2E 与故障注入测试已建立。
- [ ] 事务中断、重复请求、结果未知、取消、重启和恢复均有证据。
- [ ] Log/Metric/Trace/Audit、告警阈值和 Runbook 已完成。
- [ ] Acceptance 已记录真实环境、输入、命令、结果和残余风险。

## 台账完成定义

所有 `OWN-*` 资源的单资源 Checklist 和跨资源旅程均完成前，不能宣称领域或平台已经实现。空目录、模型类、接口声明、Migration 文件或测试桩均不是交付证据。
