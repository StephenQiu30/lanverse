## 1. 目标与完成定义

通过 REQ-11 §3 的 TC-11-01、TC-11-02、TC-11-03、TC-11-04，满足 DES-14 §8–10 非功能与测试设计。[PLN-02 §3.3](02-项目管理与变更.md) 要求 Red → Green → Refactor、门禁、演示与追踪矩阵真实更新；未运行不得报通过。

## 2. 前置条件

E-10 已建 `billing.budget` 并在项目创建时写默认 0；E-11 对该表只加列或复用，并新建 `billing.ledger_entry`。预留与结算先按 E-21 契约模拟，报表读取先按 E-32 契约模拟；低余额与超支告警由 E-11 产生事实和事件、E-33 在 M1 投递通知，E-21/E-32 完成后重跑相应真实联调。Epic 排序及联调验收以 [BACKLOG](../../BACKLOG.md) 为准。待确认项按对应 REQ §4 与 DES 待确认节的默认方案做就绪评审。数据、接口和工作流权威规范见 [DES-02](../design/02-领域与数据模型.md)、[DES-03](../design/03-接口设计.md)、[DES-04](../design/04-工作流与生成操作.md)。

## 4. 实施顺序

1. **Red**：先为默认 0、调整下限、并发预留、超支分录、低额去重写失败的单元/契约测试，再准备跨边界失败场景。
2. **Green**：E-11-01 → 02 → 03；前端 04可在契约固定后并行；最终运行 E-11-05。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M1：E-10 → E-11 → E-21）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，每个任务按 PLN-02 §3 独立评审。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用余额 50/报价 80、已结算 300/预留 50、双浏览器并发和 25%→15% 阈值执行 TC-11-01～04；验证超支记事实、阻止新确认及同项目同阈值同自然日去重（REQ-11 §3；DES-14 §9；TST-02）。文档修订阶段未运行功能测试。
- 数据作用域按 DES-02 D10 的四类原则与 DDL 表级定义核对；本 Epic 的 `billing.budget`、`billing.ledger_entry` 均为项目级表，查询强制带 `project_id`，结算超支不得绕过 `ck_budget_balance`（DES-02 §5.10）。

## 6. 风险与回退

- 并发预留可能突破预算：数据库事务拒绝后确认方，刷新报价与余额后再试。
- 实际结算超出预留：仍按事实记账、标记超支并拦截新确认；对账差异只告警，管理员核对后做审计留痕的调整。
