# Plan 05：模型

执行编号：05；来源需求模块：10。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 目标与顺序

为生图与生视频提供真实可选能力及不可变模型版本。

对应[PRD](../prd/05-模型.md)和[原始规格](../requirement/10-模型需求.md)；在[整体顺序](00-执行顺序.md)中使用执行编号05，对应原始需求模块10。先提供可用生图、图生视频模型版本及各自参数约束；候选数、画幅、时长取实际发布版本，不硬编码×2或4s。

本Plan是业务交付切片与验收安排。尚无已接受的新数据/接口Design，表、路由、代码文件、设施及迁移清单在当次Design接受后补，不按旧实现直接开工。Demo相关切片仅在[Demo Plan](06-画布生图生视频Demo.md)编排一次，本Plan用于模块追踪。

## 开工条件与容量

1. 当前切片FR范围及受影响政策已明确接受，引用基线和接受者可追踪。
2. Design说明模块边界、数据/接口、状态、并发、权限和失败路径，外部条件明确。
3. 工程/测试负责人补人员可用时间、估算和周期；目前均待确认，不把整个模块承诺为一个Sprint。
4. Sprint容量确认后，建议预留20%处理缺陷与外部不确定性；只有满足Ready的切片才纳入承诺，未Ready项保留。

## 分步交付与验证

| 顺序 | 用户结果/追踪                                                                      | 工作包（从左到右）                                  | 前置与责任                                                                                                          | 通过证据                                                   |
| ---- | ---------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1    | [US-MODEL-01](../prd/05-模型.md#us-model-01管理模型草稿)；FR-MODEL-02～03          | 标识/参数合同→草稿编辑与版本冲突→管理表单/JSON/差异 | 本片政策/Design已接受；09供应商身份与参数合同；建草稿不要求先跑生成。工程实现，测试核验，产品验收；具体人员待定     | 非法与矛盾参数、重复key、并发编辑、输入保留                |
| 2    | [US-MODEL-02](../prd/05-模型.md#us-model-02发布可选能力)；FR-MODEL-01、FR-MODEL-04 | 09可用凭据及能力验证→发布/查询→生成入口选择         | 本片政策/Design已接受；已校验模型草稿、09可用配置与真实能力证据。工程实现，测试核验，产品验收；具体人员待定         | 真实能力证据；跨能力参数、草稿绕过、发布后编辑与旧任务引用 |
| 3    | [US-MODEL-03](../prd/05-模型.md#us-model-03控制新任务可选性)；FR-MODEL-05          | 在途政策→启停及提交时复核→管理与生成错误提示        | 本片政策/Design已接受；已发布模型可用；在途任务政策和新提交复核合同明确。工程实现，测试核验，产品验收；具体人员待定 | 选中后停用再提交、排队/运行中停用、恢复启用与历史读回      |

拆分原则：一片交付真实用户结果。估算超过已确认迭代容量时按正常路径/恢复边界继续细分，但不能把只做表单或只写接口当成该片完成。核心逻辑按Red→Green→Refactor；跨边界再接真实存储、浏览器及适用外部验证。

## 风险与阻塞边界

模型key格式/唯一性、参数校验、区域默认与限制、停用对在途任务的影响。

由产品负责人决定业务政策，工程负责人核方案，测试负责人补可执行数据/环境。只阻塞受影响切片；不能用mock或旧枚举填空。完整JSON/差异维护体验可在最小发布链后补齐，不能跳过实际能力校验。

## 验收与完成定义

- 每个US覆盖PRD中的正常结果及四项验收；对照[原始AC](../requirement/10-模型需求.md#5-验收场景)和[质量条件](../requirement/10-模型需求.md#4-非功能性需求)补边界证据。
- 对持久写入查真实读回；对异步任务查同一身份、冻结版本与恢复事实；对查询复算范围/结果，不能以固定提示证明成功。
- 代码实施时执行[PROJECT适用门禁](../../PROJECT.md#4-质量门禁)，前端交互增加浏览器验证；外部验证与自动化结果分别记录，未执行项不得填通过。
- 当次记录环境、命令、实际结果、缺陷/限制和接受者；当前执行状态只在[BACKLOG](../../BACKLOG.md)维护。
- 发布、既有数据迁移或真实收费须满足当次明确条件；本次文档整理不执行这些操作。

## 下一片入口

本模块选定切片验收后，再按整体顺序进入有Ready条件的下一项；Demo核心仍优先闭环。完整模块未覆盖的FR继续保留，不以局部验收关闭整个模块。
