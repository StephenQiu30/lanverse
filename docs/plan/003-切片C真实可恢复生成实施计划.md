# 切片 C：真实可恢复生成实施计划

> Plan ID：`PLAN-C`
> 上游：[PRD-C](../prd/003-切片C真实可恢复生成PRD.md)、M07/M08/M09/M11/M14 Design
> 验收：[Acceptance 规范](../acceptance/README.md)
> 状态：`proposed`

## 1. 交付目标与固定范围

交付一项真实图片生成能力和一项真实视频生成能力：用户从批准事实创建可解释且冻结的 GenerationPlan，明确批准 `start_now` 或 `hold`，backend 经唯一 Kafka 执行 Provider 调用，并在超时、重启、回调乱序、下载失败和迟到计量时安全恢复。每个成功结果形成独立 Candidate，由用户显式 Selection。

本切片不宣称多模型路由完成，不交付计费、Agent 自主启动生成、自动替换主选或无法对账时的盲目重试。

## 2. Provider 与入口 Gate

- 切片 A 为 `verified`；B 不是前置，Agent 关闭时生成主线仍成立；
- 图片/视频各选择一个真实 Provider sandbox，并记录提交幂等、查询、取消、回调、外部任务 ID、保留/训练、地域和计量能力；
- 对“提交响应丢失后如何确认是否收单”完成 PoC；无法可靠查询或幂等时，不允许自动重试；
- 真人/敏感素材权利、外发披露、批准职责、单项/项目硬上限和连接撤销规则签认；
- 唯一 Kafka、Redis、MinIO、PostgreSQL、Provider 凭据和回调网络在隔离测试环境可用；
- 真实沙箱额度、故障注入窗口和不会进入生产检索的授权测试素材已准备。

## 4. 执行顺序与并行边界

主链为 `C0 → C1 → C2 → C3 → C4 → C5/C6 → C7 → C8 → C9 → C10 → C11`。C5 和 C6 可以并行，但共享 C0—C4 的业务语义，不能各自复制 Job、限流或用量模型。下载重试只恢复下载，不触发新的 Provider 生成；限流等待持久化后释放 Kafka partition，不使用消费者 sleep。

## 5. 故障注入矩阵

| 故障点 | 预期系统行为 | 核心断言 |
| --- | --- | --- |
| 重复批准/Kafka 重投/重平衡 | 回读同一逻辑 Job，或安全继续同一 Attempt | Job 和不可区分外部 submit 不重复 |
| 提交前崩溃 | 可重新领取并用同幂等键提交 | 不丢任务，不增加第二逻辑 Job |
| Provider 收单后响应丢失 | 进入 unknown 并按原 external evidence 对账 | 在确认前不自动创建新任务 |
| Redis 不可用/Provider 限流 | fail closed 或进入持久化 retry_wait | 外调为 0，partition 不被占用 |
| 重复/乱序/伪造回调 | 拒绝或幂等处理 | Candidate/UsageEntry 不重复 |
| 下载中断/hash 或解码错误 | 隔离坏对象并复用原 external task 重下 | Provider 生成次数不增加 |
| Worker/对象存储中断 | Operation 暴露权威状态和恢复动作 | 事实不回滚，成功阶段不丢失 |
| 用量迟到/取消未知 | 追加实际记录并保留原估算依据 | 不改历史记录，不生成账单状态 |

## 7. 路由扩展 Gate

本计划完成时只有“一项图片 + 一项视频”真实能力。只有新增第二个同类视频 capability，且能验证硬过滤、选择理由、Prompt 差异、首选不可用和批准集合内 fallback，才可另行声称多模型路由成立；不得提前建立空路由服务。

## 8. 退出、停止与回退

十条 PRD-C 验收条件全部使用真实 sandbox 和故障注入得到 `passed` 后，C 才可标为 `verified`。Provider 无法查询 unknown 且没有可靠幂等证据时，停止自动真实生成，最多降级为明确风险的人工单次执行。任何自动重试可能产生第二次计费/生成、回调无法验签或连接撤销后仍可外调时，停止上线。

回退可禁用对应 CapabilityRevision 和新任务路由；已有 Job、Attempt、Candidate、Selection、Usage 和审计只读保留，不删除或伪造失败结果。
