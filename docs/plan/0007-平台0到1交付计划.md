## 结论

本计划从空项目开始交付 Lanverse V1，不使用任何既有目录、代码、测试、Schema、接口或运行服务抵扣工作量。目录创建、依赖安装、测试文件存在和单个模型调用成功都不代表阶段完成；只有本阶段定义的可运行业务结果和 Acceptance 证据同时成立，才允许进入下一发布门。

全局顺序固定为：事实与契约 → 基础设施与安全底座 → Access/Workspace → Production/Asset → Generation/Agent/Cost → Authoring/Workflow/Review → Media/Event/Search → Guided MVP → Canvas/Collaboration/Copilot → Platform Complete。

## Checklist 规则

- 本计划初始状态全部为 `[ ]`；设计被接受不能使实施项变为完成。
- 只有对应 Acceptance 记录环境、输入、命令、结果、未运行项和残余风险后，实施项才可标记完成。
- 每个目录或服务必须随首个真实用例、契约、测试、运行入口和观测一起交付，不预建空骨架。
- 每个业务事实只有一个 Owner；Projection、Cache、Workflow History、协作文档和对象字节不得成为第二 Writer。
- 每个阶段先完成 Red 验收，再实现 Green，最后 Refactor；缺外部条件时保持 `[ ]`。

## P1：工程与基础设施底座

- [ ] 建立独立 Frontend TypeScript Workspace、Backend Go Module 和 Python Agent Runtime。
- [ ] 建立 PostgreSQL、Redis、ObjectStore、Kafka、Temporal、Elasticsearch、Debezium/Kafka Connect、OTel Collector、Prometheus/Grafana 的开发与生产拓扑。
- [ ] 建立 Secret 注入、私有网络、TLS、Volume、备份恢复、资源限制和环境隔离。
- [ ] 建立 OpenAPI、Proto、Event Schema 和生成代码的单一事实源及兼容门禁。
- [ ] 建立版本化 Database Migration、空库初始化、升级、锁、Checksum、Receipt 与回滚策略。
- [ ] 建立统一配置、错误、认证 Context、幂等、日志脱敏、Trace、Health、Readiness、Metrics、Drain 和取消契约。
- [ ] 从空环境启动全部基础设施，完成重启、故障降级、备份恢复和 Secret 泄漏负向验收。

退出门：空环境可重复初始化；契约与 Migration 无漂移；单个依赖故障不会产生静默成功或无界重试。

## P2：Access、Workspace 与治理基础

- [ ] 实现身份验证、邮箱验证、Session 轮换、退出、撤权和账户安全。
- [ ] 实现 Workspace、Owner Membership、Editor/Viewer Capability 与跨租户隔离。
- [ ] 实现 User + Workspace + Owner Membership + Registration Receipt + Outbox 的原子注册旅程。
- [ ] 实现 Audit 基础事件、Inbox/Checkpoint、Projection 和查询。
- [ ] 实现 Consent、成员治理与高影响动作的显式授权。
- [ ] 通过重复注册、Ticket 重放、Session 写入失败、跨租户访问和撤权传播 E2E。

退出门：用户能安全进入唯一 Workspace 上下文；所有治理动作可审计且重复执行不产生第二事实。

## P3：Production、Script、Bible 与 Asset

- [ ] 实现 Project、Episode、Script Document/Revision、Narrative Unit 和不可变版本绑定。
- [ ] 实现 Production Bible 全文证据、Reconcile、Review、Resolution、确认与版本演进。
- [ ] 实现 Asset、AssetState、AssetVersion、Artifact、Location、Lineage、Rights 与 Readiness。
- [ ] 在一个 Unit of Work 中发布 Bible、物化 Asset/State/Version、写 Receipt 与 Outbox。
- [ ] 实现 Presigned 直传、Hash/格式验证、私有访问和对象位置迁移。
- [ ] 通过同一身份唯一性、版本不可变、未知实体闭环、重复确认和对象存储故障验收。

退出门：固定剧本可以产生已确认 Bible 与可追踪资产；任何无证据、歧义或未就绪输入都不能进入正式生产。

## P4：Generation、Agent、Cost 与 Quota

- [ ] 实现 Capability、Model Policy、Provider Binding、Generation Intent/Request/Job/Candidate/Selection。
- [ ] 实现 Price、Estimate、Cost/Quota Reservation、Ledger、Budget 与 Reconcile。
- [ ] 实现 Model Gateway 的 Claim、短时 Authorization、Callback 验签、Rate Limit 与 Provider Receipt。
- [ ] 实现受限 Agent Runtime、Structured/ToolLoop/LangGraph Executor、Skill/Prompt/Policy 版本和 Tool Allowlist。
- [ ] 所有付费调用遵循 Intent + Reserve → Claim → Execute → Receipt → Settle/Consume/Reconcile。
- [ ] 通过 Provider 超时、迟到回调、重复回调、Gateway 崩溃、Token 到期、预算竞争和未知结果故障矩阵。

退出门：第一笔真实 Provider 调用有预算、授权、幂等、Artifact 与审计闭环；未知结果不会被盲目重提。

## P5：Authoring、Workflow、Review 与 Storyboard

- [ ] 实现 Guided/Canvas 共用的 AuthoringDraft、不可变 Revision、Node Catalog 和 Graph Validation。
- [ ] 实现 Workflow Compiler、Definition Version、Temporal Run、Node 状态、Cache、Human Gate 与 Signal Receipt。
- [ ] 实现 HumanTask、Claim Lease、ReviewDecision、Production Apply 和一次性 Workflow Signal。
- [ ] 实现 Production Bible 约束下的分集结构、occurrence 与 Storyboard 候选。
- [ ] 实现本地 Codex 分镜五阶段 Harness、确定性 Gate、有限 Repair、Checkpoint、Fencing 与人工 Apply。
- [ ] 通过 Workflow Replay、重启恢复、单 Shot 重跑、取消竞态、重复 Signal 和同 Revision 等价性验收。

退出门：固定 Revision 可以可恢复地产生待审核分镜并在人工批准后原子写入正式 Shot。

## P6：Media、Render、Event 与 Search

- [ ] 实现 Media Probe、Derivative、Job、RenderManifest、Receipt、Voice、Subtitle、Mix 与 Export。

- [ ] 实现 Event Consumer、Inbox、DLQ、Replay、Reindex、Notification、Audit 和 Cost Analytics Projection。
- [ ] 实现 Search Index Version、Alias、Workspace Filter、乱序栅栏和 Degraded Query。
- [ ] 实现 HTTP → Temporal → Agent/Generation/Media → Event/Search 的统一 Trace。
- [ ] 通过损坏媒体、Worker 重启、重复/乱序事件、DLQ Replay、全量 Reindex 和成本对账。

退出门：媒体生产、事件投影和搜索均可恢复、可重建、可追踪，不改变权威业务事实。

## P7：Frontend Guided MVP

- [ ] 交付 Account、Workspace、Project 与可分享上下文路由。

## 完成定义

只有 P0–P9 全部通过且两个发布门均有独立 Acceptance，才可宣称 V1 完成。任何目录、代码量、单元测试、接口 200、模型样例或 Plan 勾选都不能单独支持该结论。
