## 4. 实施顺序

1. **Red**：先为 TC-21-01～06 与 [DES-24](../design/24-报价与二次确认.md) 的测试设计写失败的领域、契约、集成和必要的交互用例。
2. **Green**：按任务表建立数据/共享契约，接入用例接口、事件/工作流、Agent（如有）及界面；共享接口只在归属 Epic 实现一次。
3. **Refactor**：收敛依赖，执行质量门禁与故障注入，逐项核对设计清单及验收证据。契约固定后，Agent 适配器与界面可并行。
4. **阶段协调**：按 [BACKLOG](../../BACKLOG.md) 对应里程碑的 Epic 实施顺序推进；与 E-25、E-32 先固定契约及模拟数据，待其完成后重跑联调验收。

## 5. 验证与验收

- 质量门禁：按 [PLN-02](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留实际命令、环境、结果和跳过项。
- 本功能专项：计价与指纹、并发预算预留、确认后立即重启、零费复用与结算对账；TC-21-01～06。测试数据与预期见 [REQ-21](../requirement/21-报价与二次确认.md) §3、[DES-24](../design/24-报价与二次确认.md) 测试设计及 [TST-02](../test/02-需求追踪矩阵.md)。

## 6. 风险与回退

- **风险与回退 1**：并发确认突破预算或重复预留：预算约束与幂等键校验；异常时停止新确认，保留已确认任务并对账结算。
- **风险与回退 2**：确认成功而调度服务不可用：保持“已确认”并等待恢复；不让用户重复付费提交，恢复后按同一任务启动。
