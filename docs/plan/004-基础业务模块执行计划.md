## 1. 模块实施结论

四个模块按真实业务依赖逐步出现，不建设“基础平台层”或一次生成四套空 CRUD。identity 先提供可信 ActorContext；projects 建立创作边界；media 的业务事实与上传用例在 S2 出现，S0 只允许创建无业务 Model/API/Service 的 `ObjectStoragePort`；governance 在首个授权门禁出现。跨模块只交换稳定 ID、版本引用、公开 DTO 和命令/查询，不共享 ORM 与 repository。

## 2. 模块工作流

`P004-*` 是模块交接检查项，不是第二套工程任务；实现由对应 `DEV-*` 承载，产品结果由对应 `PT-*` 接受。

| 检查项 | 模块/切片 | 实施动作 | 公开交接 | 主要验收 |
| --- | --- | --- | --- | --- |
| P004-IDN-01 | identity/S1 | 注册、Argon2 登录、JWT 验证/撤销、并发注册、个人 Workspace/owner Membership 原子创建 | `ActorContext`、角色能力检查 | 错误凭据与非法令牌零副作用；并发原子；旧版本 JWT 失效；跨空间不可探测 |
| P004-IDN-02 | identity/S1 | me、Workspace 生命周期、停用与归档命令 | workspace active/archived 查询，不导出 ORM | 停用/归档阻止新写，历史仍可读；P1 邀请不进入 MVP |
| P004-PRJ-01 | projects/S1 | Project/Episode CRUD、预算专用命令、重排、归档/恢复和受限删除 | ProjectRef、EpisodeRef、写入门禁 | 完整集合重排；预算权限；删除 blockers 与并发引用保护 |
| P004-PRJ-02 | projects/S1～S5 | 从公开摘要计算 ProductionSnapshot，逐切片接入版本入口 | current_stage、blockers、next_actions、partial_failures | 依赖失败可解释，无 N+1；前端不复制阶段规则 |
| P004-MED-01 | media/S2 | UploadSession、私有直传完成校验、MediaObject/Version/Location 登记 | MediaVersionRef、短期访问能力 | 真实 MinIO 覆盖 hash/MIME/大小、重复完成、半失败和孤儿清理 |
| P004-MED-02 | media/S4～S6 | 生成/渲染输出的稳定槽登记、Lineage、修复与 Location 切换 | output/lineage 命令与摘要 | 成功下载失败可恢复；业务代码不见 bucket/key/SDK；旧位置受控退役 |
| P004-GOV-01 | governance/S2～S4 | Consent、RightsGate、撤销/过期和审计 | `allowed/blockers/consent_ids` | 权利不足可保存草稿但阻止 ready/新生成；历史事实不被篡改 |
| P004-GOV-02 | governance/S5～S6 | Review/Issue/Decision、Moderation、Label、Audit 查询 | 固定版本审核结果与交付门禁 | 并发批准与新增 Issue 安全；unknown/标识失败阻止交付；事件只追加 |
| P004-E2E | 联合/S1～S6 | 串联登录、立项、上传、授权、归档与撤销 | 四模块公开契约组合 | 新写被正确阻止，历史 Project/MediaVersion/AuditEvent 仍可读取 |

## 3. 文件与测试边界

| 范围 | 允许落点 | 禁止做法 |
| --- | --- | --- |
| 后端模块 | `backend/app/modules/{identity,projects,media,governance}/`，按当前用例创建 api/schemas/service/models/repository/domain | 全局 controller/service/repository；跨模块导入 models/repository |
| 技术装配 | `backend/app/core/auth.py`、`backend/app/integrations/minio.py`、composition root | 在业务模块复制 token 解析或直接调用存储 SDK |
| 前端页面 | `frontend/src/app/(main)/projects/`、`studio/[episodeId]/...` 等真实 URL 路由 | 增加 `pages` 中间 URL 段；按数据库表创建页面；前端计算权威 stage/rights |
| 复用组件 | `frontend/src/components/projects/`、`media/`、`governance/` | 把页面和本地状态混入顶层 features；手写 API DTO |
| 后端测试 | `backend/tests/{unit,integration,contract}/` | 测试放入 `backend/app` |
| 前端测试 | `frontend/tests/{unit,integration,e2e}/` | 测试、fixture 或 mock server 放入 `frontend/src` |

## 4. 事务与失败路径

- identity 注册的账户、Workspace、Membership 必须同事务成功；客户端角色、workspace 所属关系不能成为信任输入。
- projects 设置 current version 前必须取得所属模块 VersionRef 并比较 expected old ID；Snapshot 依赖失败返回 partial failure，不伪装为空。
- media 对象上传成功不等于业务成功；校验和数据库登记失败必须隔离对象并留下可清理事实。
- governance 的 Decision、AuditEvent 和候选权利证据只追加；权限检查先于目标详情读取。

## 5. 实施与验收顺序

1. S1：完成 P004-IDN-01/02、P004-PRJ-01 和 Snapshot 空状态；通过 identity/projects 对应 PT。
2. S2：实现 P004-MED-01、P004-GOV-01，并将真实媒体/权利摘要接入 projects。
3. S3/S4：验证固定资产/镜头版本的权利门禁；接入生成输出 Lineage 与生产摘要。
4. S5：完成 P004-GOV-02 与渲染输出登记，projects 显示审核和交付下一动作。
5. S6：完成 Location/恢复加固和 P004-E2E；运行跨空间、依赖故障和典型规模测试。

模块单测通过不能替代联合验收。每个任务以 PLAN-007 的对应 PT accepted 为完成条件；认证 secret、MinIO/OSS 或合规规则缺失时必须保留 blocked 状态。
