## 1. 执行结论

按 `确认剧本结构 → 固定资产版本 → 固定 ShotSpec → 提交生成 → 登记并选择候选` 实施。AI 结果始终是候选，人工决议或选择后才成为下游输入；任何 current 指针变化只产生影响清单，不允许改写既有稳定版本、任务、费用或审核证据。

## 2. 模块检查项

`P005-*` 只用于核对模块顺序与交接，不单独领取或维护状态；实现与产品状态分别以 `DEV-*`、`PT-*` 为准。

| 检查项 | 模块/切片 | 实施动作 | 公开交接 | 关键验收 |
| --- | --- | --- | --- | --- |
| P005-SCR-01 | scripts/S2 | ScriptSource、不可变 ScriptVersion、发布/current 比较更新与受限删除 | ScriptVersionRef | 20,000 字上限；旧版本可读；并发发布不丢失 |
| P005-SCR-02 | scripts/S2 | ExtractionBatch、最小 Task/Outbox、候选与只追加 Decision、结构确认 | 已确认 Scene/Dialogue、影响摘要 | 重复提取/决议幂等；Worker 中断恢复；未决议不能确认 |
| P005-AST-01 | assets/S2 | 六类 Asset/AssetVersion 类型化字段、媒体/授权引用与 current | AssetVersionRef、readiness | 不以任意 JSON 代替核心字段；授权撤销阻断新生产；故障不误报 ready |
| P005-AST-02 | assets/S3 | 反向引用和资产升级预检 | 影响清单；调用 storyboards 新建规格版本 | current 变化不改旧 ShotSpec/Candidate/Delivery；升级需明确确认 |
| P005-SBD-01 | storyboards/S3 | Shot 创建、完整集合重排、规格版本和固定 AssetReference | ShotSpecRef、输入摘要 | 乐观冲突不覆盖；重排原子；典型镜头无 N+1 |
| P005-SBD-02 | storyboards/S3 | copy/split/merge、readiness 与批量阻塞摘要 | 结构化 blockers/warnings/next_actions | 变换不复制任务、候选、费用、媒体和审核；依赖失败不误报 ready |
| P005-PROD-01 | production/S2 | 仅为文本提取提供最小 Task/Outbox/Worker 契约 | TaskRef/状态查询 | 不提前实现完整费用/Attempt 框架；刷新和重启可恢复 |
| P005-PROD-02 | production/S4 | ModelCapability、纯读取预检、GenerationRequest、Task/Attempt、Reservation/CostEntry、Outbox | 能力/预计成本、TaskRef、费用摘要 | 高成本未确认零副作用；提交事务原子且幂等 |
| P005-PROD-03 | production/S4 | ProviderAdapter、unknown 对账、取消竞态、结果/费用收敛 | CandidateRef、Media 登记请求、Lineage 输入 | 原请求键对账；重复消息/回调不重复发送、候选或结算 |
| P005-PROD-04 | production/S4 | 候选选择、过期版本冲突和批量局部收敛 | 已选 Candidate 摘要 | 保留未选历史；一个镜头失败不回滚其他成功；真实 Provider E2E |
| P005-E2E | 联合/S2～S4 | 从剧本导入贯穿到候选选择和成本追踪 | 完整版本与费用链 | Candidate 可反查 Script/Asset/ShotSpec/Request/Task/Attempt/Media/Cost |

## 3. 状态与事务不变量

- ScriptVersion、AssetVersion、ShotSpecVersion、Candidate 均不可变；current 或 selected 是显式比较更新/追加动作。
- 提交生成必须在一个 PostgreSQL 事务写入 Request、Task、预占/CostEntry 和 Outbox；消息只通知持久工作可领取。
- 外部发送使用稳定 `provider_request_key`。结果不明进入 unknown，确认无副作用前禁止第二次发送。
- 结果登记必须让 Candidate、MediaVersion/Lineage、Task 终态和实际费用一致收敛；成功但下载失败只重试下载。
- production 不能修改 ShotSpec、保存对象 key 或替代 governance 的审核决定。

## 4. 文件与测试边界

| 范围 | 落点 | 重点测试 |
| --- | --- | --- |
| 后端 | `backend/app/modules/{scripts,assets,storyboards,production}/` | 领域版本/状态在 unit；事务、锁、隔离在 PostgreSQL integration |
| Provider | 当前真实用例需要时在明确命名的 integration adapter 中实现 | `backend/tests/contract/` 验证能力、错误、查询/取消和费用样例 |
| 前端页面 | `frontend/src/app/(main)/studio/[episodeId]/` 下的 `script/`、`assets/`、`storyboard/`、`tasks/` | ViewModel 读取服务端 readiness/task/next_actions，不本地推导；不得增加 `pages` 中间 URL 段 |
| 前端组件 | `frontend/src/components/{scripts,assets,storyboards,production}/` 按实际复用创建 | Vitest 覆盖草稿、冲突、阻塞与局部失败；Playwright 覆盖联合路径 |
| 测试 | `backend/tests/`、`frontend/tests/` | 不进入源码；fixture 固定、最小、无真实剧本/密钥 |

## 5. 切片顺序和门禁

1. S2 先完成 scripts 与最小异步提取，再创建资产并确认结构；Attempt/unknown/费用只保留契约扩展点，不提前造框架。
2. S3 只消费已确认结构与稳定 AssetVersion，所有验收 Shot 必须得到服务端 readiness=true。
3. S4 在 D-004/D-006/D-007 关闭后扩展 production；先做预检和单镜头，再做 unknown/取消/费用，最后做批量。
4. fake adapter 用于 Red 和确定性恢复测试；Image/Video 默认 Provider 的真实契约与端到端未通过时 S4 不得 accepted。
5. 最终以 PLAN-008 全部对应 PT 和 P005-E2E 的联合证据验收，不能用单模块 CRUD 或日志推测替代追踪链。
