## 1. 执行结论

editing 是唯一新增业务模块；消息、缓存、对象存储、调度和可观测是被真实用例拉动的技术能力，不建立通用业务 CRUD 或独立服务。PostgreSQL 始终保存权威 Task/Outbox/Inbox/Schedule/业务状态，RabbitMQ 负责通知，Redis 只加速，MinIO/OSS 只保存字节。

## 2. 执行检查项

`P006-*` 是能力启用与验收检查项，不是可领取任务；实现领取 `DEV-*`，产品接受更新 `PT-*`。

| 检查项 | 能力/切片 | 实施动作 | 关键验收 |
| --- | --- | --- | --- |
| P006-EDT-01 | editing/S5 | 初始化 Timeline、revision operations、来源差异与预览 | 缺来源指出 Shot；重复初始化不重复轨道；冲突不丢编辑；刷新不覆盖用户选择 |
| P006-EDT-02 | editing/S5 | 发布不可变 TimelineVersion/Source，衔接 Review/Issue/Decision | 来源、时间、轨道、字幕、完整镜头和权利验证；新版本重新审核 |
| P006-EDT-03 | editing/S5 | Render/Task、FFmpeg/ffprobe、SRT、媒体登记、标识和 Manifest | 重启/重试不覆盖成功输出；部分输出无 Manifest；逐 Clip 血缘和 hash 完整 |
| P006-MQ-01 | RabbitMQ/S2 | Outbox Publisher、版本化信封、confirm 与最小 Worker 消费 | 崩溃/confirm 丢失/重复投递不丢持久任务、不重复业务结果 |
| P006-MQ-02 | RabbitMQ/S4/S6 | Inbox 防重、manual ack、重试、毒消息/manual_attention 与恢复 | 提交后才 ack；unknown 不盲重发；停启 MQ 后安全恢复 |
| P006-CCH | Redis/S6 | cache-aside、提交后失效、限流/去抖和降级指标 | 清库/断连不改事实；普通读回源；高成本保护失效时 fail closed |
| P006-STO-01 | MinIO/S0/S2 | ObjectStoragePort 与 MinIO 真实契约 | 私有上传/HEAD/分片/流读写/短期访问/删除临时对象通过；业务只见 MediaVersion |
| P006-STO-02 | OSS/上线条件 | 目标 OSS 确定后新增单一 adapter，重跑同一端口契约 | 未选 OSS 时保持条件任务，不预建空 adapter，不用 MinIO 结果替代 |
| P006-SCH | Scheduler/S4/S6 | DB Schedule/Fire、租约领取、misfire/退避/补跑/manual_attention | 多实例、时钟偏移、进程重启只产生一个业务触发；不用 Redis/MQ 保存未来时间 |
| P006-OBS-01 | 可观测/S0 | JSON 日志、trace_id 与基础健康指标 | 不记录 token、正文、授权证明、预签名 URL 或二进制 |
| P006-OBS-02 | 可观测/S6 | API→Outbox→Worker→Provider/FFmpeg trace、低基数指标与告警 | 积压、unknown、调度延迟、存储错误、费用异常可发现；exporter 失败不阻塞业务 |
| P006-E2E | 联合/S5～S6 | 审核返工、渲染、标识、Manifest，并注入 Redis/MQ/Scheduler/Worker 故障 | 事实和费用不重复，页面恢复真实状态，trace 能解释全过程 |

## 3. 平台能力启用顺序

| 首个真实用例 | 此时只实现 | 延后内容 |
| --- | --- | --- |
| S0 readiness | 各依赖连接预检、MinIO 端口、JSON 日志 | 不建通用队列/缓存/调度 API |
| S2 文本提取 | Outbox、Publisher、最小 Worker、消息信封 | 完整 Attempt 对账、毒消息策略到 S4 增量 |
| S4 生成 | Inbox/manual ack、unknown、DB Schedule/Fire | Redis 性能优化和全量告警到 S6 |
| S5 渲染交付 | media Worker、FFmpeg、Render 恢复、标识/Manifest | 不实现专业 NLE 或通用媒体工作流 |
| S6 加固 | Redis 降级、完整故障矩阵、指标/告警、修复调度 | OSS adapter 仅目标 OSS 已确定时实现 |

## 4. 文件与进程边界

- editing 写入 `backend/app/modules/editing/`；RabbitMQ、Redis、MinIO、FFmpeg adapter 写入 `backend/app/integrations/`；S0 存储端口只写入 `backend/app/modules/media/storage.py`，数据库与遥测原语写入既定 `core` 文件。
- API、Scheduler、I/O Worker、Media Worker 共用 `backend/app` 与同一镜像，分别由 `main.py`、`scheduler.py`、`worker.py` 装配；不创建第二 backend 或独立业务微服务。
- 时间线/审核/交付页面分别写入 `frontend/src/app/(main)/studio/[episodeId]/editing/`、`review/`、`delivery/`，复用业务组件写入 `frontend/src/components/editing/`；不得增加 `pages` 中间 URL 段，API 类型全部来自生成 client。
- 后端真实依赖测试进入 `backend/tests/integration/` 和 `contract/`；前端流程进入 `frontend/tests/e2e/`，测试不写入生产源码。

## 5. 故障验收矩阵

| 故障点 | 预期结果 |
| --- | --- |
| Publisher 在发送前/confirm 后崩溃 | Outbox 可重投，消费者防重，不重复业务副作用 |
| Worker 在外部发送或结果提交边界崩溃 | 稳定请求键和数据库状态恢复；不确定进入 unknown 对账 |
| Redis 清空/断连 | 普通读回 PG，高成本保护 fail closed，业务事实不变 |
| Scheduler 多实例/租约过期 | 唯一 ScheduleFire；安全回收或进入 manual_attention |
| FFmpeg 中断/临时对象残留 | 按固定输入与输出槽恢复；未验证输出不登记交付 |
| exporter/日志采集失败 | 业务继续，遥测降级有界并产生告警，不无限占磁盘 |

## 6. 验收门禁

- 先通过 PLAN-009 对应 PT，再执行 P006-E2E；“代码路径存在”、mock 或单次 happy path 不能作为平台能力完成证据。
- MP4 必须为 9:16、1080×1920、25fps、H.264/AAC，并有独立 UTF-8 SRT；FFmpeg/ffprobe 自动验证。
- Manifest 逐 Clip 关联 ShotSpec、AssetVersion、Candidate、Task/Attempt、费用、MediaVersion/Lineage、审核和标识。
- OSS、合规或故障环境未提供时相应任务保持 blocked；不得静默缩小验收范围。
