## 1. 执行目标

把 PRD-001 从产品定义转化为可检查的准入与发布合同。本文不直接安排模块代码，而是回答三个问题：MVP 做什么、哪些外部事实必须在相应切片前关闭、什么证据足以宣告产品可发布。

## 2. 检查项

`P001-*` 是范围治理检查项，不是可领取的工程任务；工程实现只领取 PLAN-000 的 `DEV-*`，产品接受只更新 `PT-*`。

| 检查项 | 执行动作 | 交付物 | 完成判定 | 阻塞关系 |
| --- | --- | --- | --- | --- |
| P001-01 | 与产品/工程负责人确认 owner、单集主链路、七类业务结果、MVP 非目标、固定技术基线与 S0 边界 | S0 范围评审记录；争议清单与后续切片待定项分离 | D-001 有责任人、日期、对应文档版本/commit 和明确结论 | 阻塞 S0 代码任务，不要求提前冻结 S1～S6 全部细节 |
| P001-02 | 固化单集、镜头、上传、候选、并发、交付和 API 性能 fixture | 不含真实数据的固定验收剧本、规模数据与环境说明 | 每项工作基线均有可重复输入和测量方式 | S0 可建 fixture；性能结论等 D-007 |
| P001-03 | 按 D-002～D-007 收集 OIDC、供应商、合规、基础设施和性能决策 | 决策记录、责任人、截止切片和脱敏契约样例 | 每个决定只能是 closed 或带原因的 blocked，不允许默认值伪装关闭 | 按 PRD-001 §8 阻塞 S0/S1/S2/S4/S5/S6 |
| P001-04 | 将七项成功指标转成自动化或人工验收入口 | 指标—测试—环境—证据映射 | 每项指标有唯一证据归属；fake-only、跳过或中断不能标记通过 | S1～S6 逐步产出 |
| P001-05 | 建立范围变更门禁，审查 P1、微服务、通用引擎等非目标是否渗入 | 变更记录模板与当前范围差异清单 | 新增范围说明用户结果、代价及被替代工作，否则拒绝进入切片 | 持续执行 |
| P001-06 | 执行发布评审，汇总 S0～S6、外部决定、P0/P1 与残余风险 | MVP 发布判定记录 | 所有切片 accepted、外部决定关闭、固定剧本通过且无未解决 P0/P1 | 最后执行 |

## 3. 决策关闭清单

| 决策 | 最迟门禁 | 最小有效证据 | 不满足时 |

| 产品指标 | 主要产出切片 | 最终证据 |

## 5. 执行约束与验收

- 本计划不为 `P001-*` 维护独立状态；工程 `DEV-*` 使用 `proposed → ready → in_progress → blocked/completed`，产品 `PT-*` 只有产品负责人接受证据后才能进入 `accepted`。
- P001-01 关闭前不得创建业务代码目录；P001-02 可以先准备不含密钥和个人数据的验收输入设计。
- S1～S6 分别在进入前接受对应 Requirement、Design 与 PRD；D-001 关闭不自动接受后续切片文档。
- 发布评审不得用页面截图、接口 200 或 fake provider 单独替代端到端证据。
- 验收时逐项核对 PRD-001 §3～§9；任何静默放宽基线都必须先更新 PRD，再同步本计划。
