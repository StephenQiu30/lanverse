## 执行顺序

### 0. 固定目标运行边界

- [x] 读取并对齐系统、分层、后端、Agent、Production Bible 与 Storyboard 设计。
- [x] 固定 Go Backend 为全部业务事实 Writer，Python Agent 为 Candidate-only 执行面。
- [x] 将公共 OpenAPI 迁入 `backend/api/openapi`，由 Go 入口直接提供，并删除 Agent 合并/导出公共契约的入口。
- [x] 为公共错误包络建立 OpenAPI 事实源，并由 Backend 拥有 Backend ↔ Agent 版本化线协议、Agent 严格消费与契约测试。
- [x] 建立单一 GORM 数据基础：固定依赖版本、唯一 `DATABASE_URL`、连接/Health、Owner Model Catalog、Schema Sync、事务、行锁、Command Receipt、Audit 和 Import/SQL 门禁；独立空库真实启动通过且无 Migration 元数据。
- [x] 删除手写 SQL Migration、迁移 Binary、直接 pgx 业务 Repository和 Go→Python 公共路由代理；Agent 启动入口只挂载 Candidate Runtime。
- [x] 用 GORM 重写 `production/project` 聚合并补齐持久幂等、输入哈希冲突、revision、权限和删除门禁。
- [x] 按 access → production/script/Bible → planning/structure → storyboard/export 顺序实现资源；公共路由均由 Go Backend 持有，不存在 Python Writer 回退。
- [x] Python Agent 进程不拥有公共业务 HTTP、业务 Repository、Schema 同步、数据库驱动或业务数据库凭据；锁文件也不包含 SQLAlchemy/asyncpg/Redis/Kafka/MinIO 客户端。

## 停止条件

若真实 Codex 未登录、blocking issue 尚未获得明确人工决议、依赖无法隔离或导出不确定，不绕过门禁、不改用模型桩宣称完成；在验收记录中标记未通过并保留可恢复状态。
