## 1. 执行结论

本功能作为 S4 前可独立完成的 Provider 管理控制面执行，不创建新业务模块，也不与 D-004 的图片/视频真实 Provider 工作合并。实现落在现有 production 事实所有权内，通过 identity 的 Workspace/owner 能力和 governance 的 AuditEvent 完成交接；前端复用 Workspace 设置和现有生成客户端。

执行顺序固定为：安全数据事实 → 预设与 Connection API → 受控网络检查 → Binding 与运行快照 → 凭据生命周期 → DeepSeek 真实切换 → 管理页面与全量验收。一次只允许一个 `DEV-AIP-*` 处于 `in_progress`；每项先产生能够证明缺口的 Red，再最小 Green，最后运行相称回归并形成独立 Acceptance。

PT-AIP-001～005 可以在没有任何真实图片/视频账号时完成；PT-AIP-006 必须有显式授权的真实 DeepSeek 账号/额度；PT-AIP-007 的完整浏览器闭环依赖 PT-AIP-006。缺 DeepSeek 外部条件时允许先接受 PT-AIP-001～005，但不得以 fake Provider 接受 PT-AIP-006/007 或整个 PRD。

## 3. 代码边界

Provider 管理已具有独立资源生命周期，实施时允许在 `backend/app/modules/production/providers/` 建立纵向能力包；只在对应 DEV 首次需要时创建文件，不预建空目录或万能 adapter：

| 边界 | 允许修改 | 禁止 |
| --- | --- | --- |
| production/providers | 预设目录、ORM、schemas、repository、service、API、凭据端口、探针和 Binding 解析 | 直接导入 identity/governance 内部 ORM/Repository；`generate(kind, dict)` 万能接口；第二套 Task/费用事实 |
| production 既有请求 | ExtractionBatch/GenerationRequest/Attempt 所需的版本引用和运行时解析 seam | 创建任务后读取“最新 Provider”；把 Key 放进 request snapshot、Outbox 或 RabbitMQ |
| integrations | 现有 DeepSeek 客户端改为接收受控 runtime config；每个 Provider 后续一个窄 adapter | 前端直连、通用协议代理、为 catalog-only 平台提前安装全部 SDK |
| core/composition | 主密钥 Settings、显式 Model 注册、路由装配和依赖构造 | 自动扫描插件、通用 Secret 表、把 Provider Key 继续作为稳定 runtime fallback |
| frontend | `/workspaces/providers`、Workspace 设置入口、ViewModel/组件测试、生成的 `src/api` | 手写 Provider DTO、API Key 放 Redux/localStorage、直连外部 endpoint |
| docs/tests | REQ/Design/PRD/Plan/数据库详细设计、架构/单元/集成/契约/E2E/Acceptance | 实现前创建伪 Acceptance；用 mock 成功替代真实 DeepSeek 或 Ark 证据 |

新增认证加密或 HTTP 安全依赖时，必须从官方发布源复核并精确 pin，同时更新 `backend/pyproject.toml`、`requirements.txt`、`requirements-dev.txt` 和 `pip check`；不得同时引入通用 AI Gateway SDK。

## 5. 逐任务文件与测试计划

### 5.1 DEV-AIP-01：数据与凭据安全

预计触达：

- `backend/app/modules/production/providers/models.py`、`credentials.py`、`contracts.py`；
- `backend/app/core/config.py`、`backend/app/model_registry.py`、composition root；
- `backend/pyproject.toml` 与锁定 requirements；
- `backend/tests/unit/production/providers/`、`backend/tests/integration/production/providers/`；
- `docs/design/模块设计/011-数据库表与数据生命周期详细设计.md`。

Red 必须使用随机 sentinel Key 并在失败输出中只显示测试标识的 hash，不显示原值。真实 PostgreSQL 测试创建两个 Workspace，证明密文记录不能跨 Workspace/Connection 重放。结构只为当前四实体和 HealthCheck 建表，不创建通用 Secret、EndpointPool 或 ProviderPlugin 表。

### 5.2 DEV-AIP-02/03：管理 API 与受控网络

预计触达：

- `backend/app/modules/production/providers/catalog.py`、`schemas.py`、`repository.py`、`service.py`、`api.py`、`probes.py`；
- production 根 Router 的显式 include；
- API/集成/网络安全测试与 OpenAPI schema 快照。

网络测试使用进程内受控 HTTP 服务和可控 DNS resolver seam，不访问随机公网地址。官方 Provider 的真实错误 Key/健康契约放在显式 external contract 测试中；默认 CI 仍运行全部 SSRF 与解析测试。错误翻译只保存 allowlist 字段，禁止把 `httpx`/SDK 原异常直接序列化。

### 5.3 DEV-AIP-04/05：切换、快照与生命周期

预计触达：

- Provider Binding service/repository/contracts；
- `backend/app/modules/production/models.py`、generation request/attempt 路径；
- scripts ExtractionBatch 创建/执行的公开 seam；
- audit、并发 PostgreSQL 和 Worker 恢复测试；
- 独立 credential re-encryption CLI 入口。

切换事务不得调用 Provider。探针必须在事务前完成并以固定 HealthCheck ID/revision 作为门禁；事务内只锁数据库事实。请求快照保存版本 ID/hash，不保存密钥、完整认证 Header 或原始响应。

### 5.4 DEV-AIP-06：DeepSeek 单向切换

预计触达：

- `backend/app/integrations/deepseek.py`；
- scripts 提取 composition/runtime config seam；
- 受控 import CLI、DeepSeek contract tests 和现有真实联合 E2E；
- 部署示例中主密钥的无效占位与 readiness，移除 Provider Key 稳定依赖。

切换步骤：先创建密文版本 → 真实检查 → 创建 `script_structure` Binding → 运行一条新提取 → 验证旧非终态任务恢复 → 删除测试进程中的 Provider Key env 再运行一条新提取。任一步失败都停在可解释阶段，不建立长期 env/DB 双读。

### 5.5 DEV-AIP-07：页面与全量收口

预计触达：

- `frontend/src/api/` 生成文件；
- `frontend/src/app/workspaces/providers/page.tsx` 与现有 Workspace 导航/权限；
- 最小 Provider ViewModel/组件及 Vitest；
- `frontend/tests/` 对应 Playwright 场景；
- `docs/acceptance/` 中实现后才创建的真实证据。

先运行后端并生成 API，再实现页面。Key 输入使用组件局部临时状态，成功/取消/卸载均清理；不得进入 Redux、Query cache、URL、analytics 或错误 toast。编辑页不填充占位 Key 值，只有“已配置/版本/轮换时间”状态。

## 8. 完成与停止条件

### 8.1 单个 DEV 完成

- 目标 Red 曾以预期原因失败，Green 后定向和相称回归通过；
- diff 只包含本任务文件，无 `.env`、Key、数据库、缓存、日志、截图报告或生成垃圾；
- API/日志/审计/trace 的 sentinel 扫描 0 明文命中；
- Requirement→Design→PT→DEV→Test 链完整；
- `git status --short` 中每项修改均可解释，Acceptance 不提前宣称未运行证据。

### 8.2 PRD-011 accepted

- PT-AIP-001～007 和 PRD-011 §6 十项退出标准全部满足；
- DeepSeek 数据库 Binding 真实闭环通过，Ark 仍准确 fail closed；
- 没有未解决 P0/P1 安全、租户、凭据、重复外部副作用或数据漂移缺陷；
- 存量数据库和生产 KMS 若仍未关闭，只能把新环境功能标为 accepted，发布状态继续 blocked。

### 8.3 立即停止并升级

- 发现用户工作区存在不明重叠修改或真实 secret/数据文件；
- 目标数据库存在不可丢失数据且需要 DDL 变更；
- 认证加密依赖、主密钥来源或 Provider 官方契约无法从一手资料确认；
- 健康检查只能通过产生计费/生成副作用验证；
- 任何实现需要自动重发未知 Provider 请求、放宽 SSRF、返回 Key 或让 catalog-only active；
- D-004 未关闭却需要声称 Ark 图片/视频成功。
