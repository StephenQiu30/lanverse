# Plan 07：剧本

设计入口：[Design 07](../design/07-剧本.md)。当前是待评审方案，接受后再按本次闭环细化技术工作项；原始需求与验收标识不变。

执行编号：07；来源需求模块：11。下文06～19指原始需求模块编号，FR/US追踪标识保持原值。

## 目标与顺序

将支持格式的剧本原件转为可追踪的分集与设定候选，为镜头链提供明确来源。

对应[PRD](../prd/07-剧本.md)和[原始规格](../requirement/11-剧本需求.md)；在[整体顺序](00-执行顺序.md)中使用执行编号07，对应原始需求模块11。不是首轮画布自由生图→图生视频的前置；Demo完成后按模块顺序接入剧本创作链。

本Plan是业务交付切片与验收安排。已形成对应待评审Design，尚无已接受的新数据/接口方案；库表字段、约束及API/DTO合同见对应Design工程节；接受后补精确代码改动、运行设施差异及增量迁移清单，不按旧实现直接开工。Demo相关切片仅在[Demo Plan](06-画布生图生视频Demo.md)编排一次，本Plan用于模块追踪。

## 开工条件与容量

1. 当前切片FR范围及受影响政策已明确接受，引用基线和接受者可追踪。
2. Design说明模块边界、数据/接口、状态、并发、权限和失败路径，外部条件明确。
3. 工程/测试负责人补人员可用时间、估算和周期；目前均待确认，不把整个模块承诺为一个Sprint。
4. Sprint容量确认后，建议预留20%处理缺陷与外部不确定性；只有满足Ready的切片才纳入承诺，未Ready项保留。

| ---- | ------------------------------------------------------------------------------------ | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 1    | [US-SCRIPT-01](../prd/07-剧本.md#us-script-01保存原件并追踪导入)；FR-SCRIPT-01～02   | 格式/原件授权及任务合同→接收/导入→项目入口状态 | 本片政策/Design已接受；07项目、08授权原件存储与导入规则。工程实现，测试核验，产品验收；具体人员待定                        | 伪格式/超限、重复提交、丢回执与重启恢复          |

拆分原则：一片交付真实用户结果。估算超过已确认迭代容量时按正常路径/恢复边界继续细分，但不能把只做表单或只写接口当成该片完成。核心逻辑按Red→Green→Refactor；跨边界再接真实存储、浏览器及适用外部验证。

## 风险与阻塞边界

PDF支持、文件限制、标题/分集/抽取规则、场与镜头首次形成、重导入/部分结果、安全重试及文件外发。

由产品负责人决定业务政策，工程负责人核方案，测试负责人补可执行数据/环境。只阻塞受影响切片；不能用mock或旧枚举填空。不能用复制样例分集替代导入，也不预建独立剧本工作台。

## 验收与完成定义

- 每个US覆盖PRD中的正常结果及四项验收；对照[原始AC](../requirement/11-剧本需求.md#5-验收场景)和[质量条件](../requirement/11-剧本需求.md#4-非功能性需求)补边界证据。
- 对持久写入查真实读回；对异步任务查同一身份、冻结版本与恢复事实；对查询复算范围/结果，不能以固定提示证明成功。
- 代码实施时执行[PROJECT适用门禁](../../PROJECT.md#4-质量门禁)，前端交互增加浏览器验证；外部验证与自动化结果分别记录，未执行项不得填通过。
- 当次记录环境、命令、实际结果、缺陷/限制和接受者；当前执行状态只在[BACKLOG](../../BACKLOG.md)维护。
- 发布、既有数据迁移或真实收费须满足当次明确条件；本次文档整理不执行这些操作。
