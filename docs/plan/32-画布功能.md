## 1. 目标与完成定义

完成即 TC-36-01, TC-36-02, TC-36-03, TC-36-04, TC-36-05 通过，[DES-38](../design/38-画布功能.md) 的测试设计及非功能要求有证据；依 [PLN-02 §3.3](02-项目管理与变更.md#33-完成定义dod) 完成格式、静态检查、单元/集成、Race、漏洞、契约、演示与追踪矩阵门禁。

## 2. 前置条件

- 前置 Epic：E-18（[BACKLOG](../../BACKLOG.md)）、E-19（[BACKLOG](../../BACKLOG.md)）、E-21（[BACKLOG](../../BACKLOG.md)）、E-22（[BACKLOG](../../BACKLOG.md)）、E-30（[BACKLOG](../../BACKLOG.md)）；按 [BACKLOG](../../BACKLOG.md) 对应里程碑的“Epic 实施顺序”执行。
- 底座与外部条件：PLN-01 对应里程碑的命令层、真实依赖与运行环境；测试数据为500 节点画布、参考连线、跨设备布局与冲突命令。
- 待确认：DES-38-Q1、DES-38-Q2、DES-38-Q3。确认前不把默认方案写成已批准结论。

## 4. 实施顺序

1. Red：先为 TC-36-01, TC-36-02, TC-36-03, TC-36-04, TC-36-05 所依赖的业务规则、异常与跨边界路径写失败测试；E-36-06 在各任务中持续补齐测试与验收。
2. Green：按 E-36-01 → E-36-02 → E-36-03 落实数据、接口和异步组合，逐项让测试通过。
3. Refactor：保持测试通过，整理边界与错误路径；契约稳定后 E-36-04、E-36-05 可并行，最后合并验收证据。

## 5. 验证与验收

- 质量门禁：按 [PLN-02 §3.3](02-项目管理与变更.md#33-完成定义dod) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留真实命令、环境与结果。
- 本功能特有验证：500 节点 ≥ 50 fps 的 Playwright 录制；命令冲突重放、布局跨设备、参考连线双向一致与付费命令不可撤销。
- 验收用例：TC-36-01, TC-36-02, TC-36-03, TC-36-04, TC-36-05（[TST-02](../test/02-需求追踪矩阵.md)）；数据：500 节点画布、参考连线、跨设备布局与冲突命令。

## 6. 风险与回退

- 500 节点画布帧率不足：减少同时视频播放并启用视口裁剪；PoC 未达标时采用 DES-38-Q1 的纯 React Flow 卡片方案。
- 布局命令冲突或重复重放：暂停提交未确认命令、保留本地操作，取最新文档重放并提示冲突；绝不重复执行付费命令。
