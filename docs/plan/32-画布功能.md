## 1. 目标与完成定义

完整业务画布完成须 TC-36-01～05 通过，[DES-38](../design/38-画布功能.md) 的测试设计及非功能要求有证据；依 [PLN-02 §3.3](02-项目管理与变更.md#33-完成定义dod) 完成格式、静态检查、单元/集成、Race、漏洞、契约、演示与追踪矩阵门禁。

E-36-07 完成须 DES-38 §3.1 的真实会话/首次改密、项目、PostgreSQL 文档、原子 revision/幂等与浏览器刷新恢复证据。E-36-08 完成须测量面板和固定样本/本机自选媒体的可复验记录；目标机器、真实业务媒体和跨设备缺口单列，不外推成完整 PERF-06 或 TC-36 全部通过。

## 2. 前置条件

- 本轮 E-36-07 前置为公共认证/幂等/错误/在线生成合同、真实项目读取及已落地 identity/workspace 用例。纯备注布局不等待生成、参考组合、媒体或 Agent；后续业务联动分别列出其具体合同，不要求整个前置 Epic 完成。
- 底座与外部条件：PLN-01 对应里程碑的命令层、真实依赖与运行环境；测试数据为500 节点画布、参考连线、跨设备布局与冲突命令。
- 待确认：DES-38-Q1、DES-38-Q2、DES-38-Q3。确认前不把默认方案写成已批准结论。

## 4. 实施顺序

1. Red：先为 TC-36-01, TC-36-02, TC-36-03, TC-36-04, TC-36-05 所依赖的业务规则、异常与跨边界路径写失败测试；E-36-06 在各任务中持续补齐测试与验收。
2. Green：本轮先 E-36-07 接真实备注布局，E-36-08 改进独立 PoC；后续按 E-36-01/02/03/05 的剩余业务范围实现，逐条接生成、参考和选定合同。
3. Refactor：保持测试通过，整理边界与错误路径；E-36-05 依据画布/业务合同实施，E-36-04 在 E-37 提案合同后联调，最终聚合验收证据。

## 5. 验证与验收

- 质量门禁：按 [PLN-02 §3.3](02-项目管理与变更.md#33-完成定义dod) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留真实命令、环境与结果。
- 本功能特有验证：500 节点 ≥ 50 fps 的 Playwright 录制；命令冲突重放、布局跨设备、参考连线双向一致与付费命令不可撤销。
- 验收用例：TC-36-01, TC-36-02, TC-36-03, TC-36-04, TC-36-05（[TST-02](../test/02-需求追踪矩阵.md)）；数据：500 节点画布、参考连线、跨设备布局与冲突命令。

## 6. 风险与回退

- 500 节点画布帧率不足：减少同时视频播放并启用视口裁剪；PoC 未达标时采用 DES-38-Q1 的纯 React Flow 卡片方案。
- 布局命令冲突或重复重放：暂停提交未确认命令、保留本地操作，取最新文档重放并提示冲突；绝不重复执行付费命令。
