## 2. 测试策略

核心逻辑遵循 Red → Green → Refactor：

- `skills`：分块守恒、跨块 key、人物集数聚合、超时/无效输出/Tool 越权；
- `scripts`：整本导入幂等、分集无缺口/重叠、候选证据、跨 Workspace 拒绝；
- `storyboards`：冻结输入、叙事覆盖、引用校验、批次决定与原子应用；
- Worker：Outbox/Inbox 重投、重启、unknown 和 input changed；
- 前端：上传、阶段状态、人物集数、分镜行决定和错误下一动作；
- 浏览器：真实文件上传到分镜批准，不使用假 API。

外部依赖测试只连接显式隔离的本机 PostgreSQL/Redis/RabbitMQ/MinIO；测试不得启动容器，也不得删除共享数据。

## 3. 交付门禁

每个阶段必须同时满足代码、OpenAPI、前端生成客户端、测试和本文件状态一致。任何跳过的外部测试都保持未通过，不得用单元测试替代最终浏览器验收。
