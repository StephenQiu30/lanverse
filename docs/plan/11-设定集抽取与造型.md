## 1. 目标与完成定义

通过 REQ-14 §3 的 TC-14-01、TC-14-02、TC-14-03、TC-14-04，满足 DES-17 §8–10 非功能与测试设计。[PLN-02 §3.3](02-项目管理与变更.md) 要求 Red → Green → Refactor、质量门禁、演示与追踪矩阵真实更新；未运行不得报通过。

## 2. 前置条件

至少一集结构已确认，抽取报价和 M1 Agent Skill 契约可用；准备长剧与歧义称呼样例。Epic 排序及联调验收以 [BACKLOG](../../BACKLOG.md) 为准。待确认项按对应 REQ §4 与 DES 待确认节的默认方案做就绪评审。数据、接口和工作流权威规范见 [DES-02](../design/02-领域与数据模型.md)、[DES-03](../design/03-接口设计.md)、[DES-04](../design/04-工作流与生成操作.md)。

## 4. 实施顺序

1. **Red**：先为别名合并/拆分、稳定引用、造型删除保护与说话人唯一匹配写失败的单元/契约测试，再准备跨边界失败场景。
2. **Green**：E-14-01 → 02 → 03；Agent 04 与前端 05 在契约固定后可并行；最后执行 E-14-06。实施顺序以 [BACKLOG](../../BACKLOG.md) 为准（M2：E-13 → E-14）；联调项先用契约与模拟，待对方完成后重跑验收。
3. **Refactor**：收敛边界转换、复跑回归，每个任务按 PLN-02 §3 独立评审。

## 5. 验证与验收

- 通用质量门禁按 [PLN-02 §3.3](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；实施时记录实际命令和结果。
- 本功能验证：用“小李/李明/李队”、两个“王总”、双造型角色与已引用造型执行 TC-14-01～04；验证合并/拆分后的引用、台词映射、长剧分块及 AIQ-02/CAP-01（REQ-14 §3；DES-17 §10；TST-02/TST-03）。文档修订阶段未运行功能测试。

## 6. 风险与回退

- 别名歧义可能误合并角色：仅自动处理唯一匹配，歧义回到人工说话人映射。
- 合并后旧镜头引用可能失联：保留重定向，迁移未核验前不删除旧标识，必要时撤销候选合并。
