## 4. 实施顺序

1. **Red**：先为 TC-26-01～03 与 [DES-29](../design/29-关键帧.md) 的测试设计写失败的领域、契约、集成和必要的交互用例。
2. **Green**：按任务表建立数据/共享契约，接入用例接口、事件/工作流、Agent（如有）及界面；共享接口只在归属 Epic 实现一次。
3. **Refactor**：收敛依赖，执行质量门禁与故障注入，逐项核对设计清单及验收证据。契约固定后，Agent 适配器与界面可并行。
4. **阶段协调**：按 [BACKLOG](../../BACKLOG.md) 对应里程碑的 Epic 实施顺序推进；本 Epic 无后实施联调项。

## 5. 验证与验收

- 质量门禁：按 [PLN-02](02-项目管理与变更.md) 完成定义与 [TST-01](../test/01-测试策略.md) 执行；保留实际命令、环境、结果和跳过项。
- 本功能专项：参考输入展开、上传裁剪、审核拒绝、关键帧改选后视频过期；TC-26-01～03。测试数据与预期见 [REQ-26](../requirement/26-关键帧.md) §3、[DES-29](../design/29-关键帧.md) 测试设计及 [TST-02](../test/02-需求追踪矩阵.md)。

## 6. 风险与回退

- **风险与回退 1**：上传图片画幅或分辨率不足：提示裁剪/质量风险；处理失败时不进入可选候选，保留原上传供重新处理。
- **风险与回退 2**：审核拒绝或关键帧改选后旧视频继续使用：拒绝选定不合规帧并标记依赖片段过期；保留旧候选供追溯。
