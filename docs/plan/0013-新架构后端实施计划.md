# 新架构后端文本与分镜 MVP 实施计划

- 授权：2026-09-07 用户确认按新设计推进，随后收敛为 Backend MVP，并明确“先完成文本与分镜闭环”。
- 目标依据：[0013 架构](../design/0013-创作编排与多媒体画布架构调整设计.md)、[3004 Harness](../design/3004-AgentHarness专业能力与创作流程设计.md)。
- 本机约束：直接复用本机已运行服务，不创建或重启额外基础设施；使用同一个 PostgreSQL 实例内的临时测试库，测试后精确删除该库；测试项目使用合成数据。不对既有业务库执行自动同步或清理。

## MVP 完成边界

导入原稿 → 全稿解析与设定 → 可审阅文本分镜 → 正式采纳与恢复。文本分镜是已确认的导演意图和来源映射，不宣称视觉资产就绪或可直接生成视频。沿用 Go 正式 Owner，Python 负责新流程编排和草案。2026-09-08 用户要求先打通核心能力，按 [0014 范围合同](../design/0014-LibTV核心闭环能力调研与差距设计.md) 补充必要前端接线；图片/视频生成、完整画布、计费产品、成片导出不属于本轮。

现有 Go-owned 旧候选和旧 Workflow 保持原身份；不得把旧端点存在或旧 mock 测试当成新 MVP 已打通。新 Agent 流程尚未部署时，公开状态必须说明能力未就绪，不返回伪成功。

| 顺序 | 工作范围 | 完成门 |
| --- | --- | --- |
| M01 | 原稿导入、正式源与精确来源读取 | 中文/表情/换行、固定 hash、权限、范围上限和原子发布可验证 |
| M02 | 新创作运行接受、固定路由和可靠交接 | Go 持久命令、Python 接受回执、幂等重投、失败可查；不新增 Go 创作 Workflow |
| M03 | 全稿设定与身份提案的审阅采纳 | 逐场事实有来源，别名/状态不静默合并，正式 Owner 与回执一致 |
| M04 | 文本分镜草案、审阅和正式导演意图 | 来源→节拍→镜头关联、台词覆盖、固定版本采纳、无需图片完成文本审阅 |
| M05 | 状态查询、恢复和闭环验收 | 关闭客户端/进程重启后可恢复，旧结果不覆盖新修订，本机真实接口与数据库验证 |

每项从失败测试开始，提交实现、HTTP/OpenAPI 合同、权限与失败路径。模型语义闭环使用合成原创剧本和真实 Agent，故障注入可以替身但不抵扣语义验收。测试通过范围和跳过情况分别记录。

本计划将后端范围细化、接口合同与执行清单合并，避免重复文档；上位 Design 已有产品目标。实际运行证据见 [0013 后端验收记录](../acceptance/0013-新架构后端验收记录.md)。

## 来源读取合同

`GET /api/projects/{project_id}/script-sources/{revision_id}/spans?start=…&end=…&expected_hash=…` 只读取已接受的固定源版本。start/end 为 Unicode code point 半开区间，单次最多 16,384 code points；必须提交 expected_hash。返回源身份、范围、原文和范围 hash。拒绝负数、空范围、越界、超限、hash 漂移和跨项目读取；不把旧版本引用自动定位到最新原稿。

## 接线前接口切片（历史进度）

- `GET /api/storyboard-draft-sets/{set_id}` 返回集合状态、固定 Graph/Manifest、候选引用和批次；不推进运行。
- `POST /api/projects/{project_id}/storyboard-intent-acceptances` 要求 workspace_id、candidate_revision_id/hash、expected_candidate_revision、review_decision_id 和 idempotency_key。复用 Go 现有 FreezeIntentSet，验证已完成批准、候选与来源后，原子提交 intent_frozen 状态及 Owner Receipt。同键同输入重放，同键异输入冲突。
- `GET /api/storyboard-draft-sets/{set_id}/approved-intents` 重新检查项目权限，按集合精确读取唯一采纳回执并校验内容 hash；不要求历史候选继续占据最新 Head，也不触发模型。未采纳、内容漂移或冲突回执返回 409。

当前三个分镜接口服务于现有 Go-owned 候选与正式采纳能力；它们不启动新的 Go 编排，也尚未接入 Python 草案。Python 命令/启动 Outbox 已补齐，独立提案版本、全稿设定桥接以及真实模型主链仍需按 M03–M05 实现与验收，不能用此接口切片替代完整 MVP。

## 新创作运行交接（Go 侧）

- 新增 `production/creation`，公共创建/列表/查询/重投接口已注册到现有 API 进程。正式源通过 Script Owner 查询，未接受源或错误 hash 不能创建新运行。
- `crn_runs` 保存命令、源快照、路由、调用者和接受回执；`crn_command_outbox` 保存投递租约、fence、尝试次数和下次执行时间。两表属于现有 Go GORM Catalog，创建使用一个事务，不写旧 Workflow 表。
- 项目写锁串行化同项目创建；同项目/用户/幂等键只能产生一个运行。重投使用 expected_revision，仅原创建者可操作，并重新检查当前账号/项目权限；身份令牌版本只更新授权元数据，不改变原命令。
- Dispatcher 在 API 进程内启动，取消并等待退出后才关闭数据库。先查原命令，确认不存在后才投递；未知结果按原命令退避，不另建运行。
- HMAC 使用独立 `CREATION_AGENT_SECRET`，绑定 method、path、canonical body hash 与 60 秒有效期。拒绝重定向；非本机地址需要 HTTPS。
- `CREATION_AGENT_URL` 默认空，创建返回 `creation_unavailable`；模板和 Compose 只透传显式配置。没有启动或配置新的 Python 服务，也没有修改本机 `.env`。

内部合同：POST `/internal/creation/commands` 接收 `creation-command-production`；GET `/internal/creation/commands/{command_id}` 查询 `creation-acceptance-production`。命令采用已有 production canonical JSON（NFC、整数、排序键）；Go/Python 共用 `backend/tests/production/creation/testdata/command.json`。回执身份、payload hash、流程类型和 Workflow ID 全部校验。`accepted` 仅表示 Agent 持久接受，不能作为创作完成或正式采纳的证据。

该 Go 切片最初使用 HTTP 故障夹具；后续 Python 服务已实现，见下节。旧夹具仍只抵扣故障合同测试。

## Python 可信命令服务

- `agent/app/creation` 已实现严格命令合同、独立 HMAC 授权、接受记录与启动 Outbox 原子提交、不可变回执查询、显式迁移和可取消 Dispatcher。
- Task Queue 随第一次接受保存；固定 Workflow ID、REJECT_DUPLICATE 与 memo 身份共同约束启动。租约/fence、持久退避、历史冲突阻塞及 12 小时自动启动窗覆盖响应丢失和进程退出。
- 可信进程与候选进程分别使用入口、依赖和镜像。既有 Harness 入口不能加载可信数据库/Temporal 模块，受限镜像也不复制可信模块。
- 本机原生 PostgreSQL 临时库与已有 Temporal 已验证真实 Go HTTP 客户端投递、Python 回执、Temporal 身份及 Agent 测试进程重启恢复。没有启用现有业务进程的新路由，也没有执行正式业务库迁移。
- 下一项是固定源读取桥接、真实文本 Workflow/Activity 与有来源的草案事务；在其实现前不注册占位 Workflow、不宣称文本创作或正式采纳已完成。运行方式与独立配置见 [Agent README](../../agent/README.md)。

## Harness 专业文本链（2026-09-08）

已按原始 DOC-A/DOC-C 和 3004 细化四个实际任务：全稿检查与分集、逐集分场/节拍/对白/提及、全稿身份与状态草案、单场导演与文字分镜。新增受限 HTTP 入口及独立冻结 Skill，保留旧包摘要。校验覆盖原文分配、逐字证据、重复引用定位、画内/画外/仅提及、实体类型与引用、状态分支、对白和视觉细节的镜头覆盖；上下文按场过滤未来身份。

这项完成的是专业任务执行与候选合同，M03/M04 的正式采纳门保持未勾选。生产接线仍需依次完成：Go 固定源读取桥及当前权限校验；Agent 草案/预算/OutputBinding/Outbox 原子保存；Temporal 在分集、剧稿结构、WorldBook 和分镜门等待可核验的平台回执；对应正式 Owner 转换及原回执恢复。不得将测试脚本的顺序串联注册为无审批的生产 Workflow。

### 本轮已接通的生产文本接口

- 项目 `/creation` 页面从当前原稿读取正式源 Head，CAS 发布后创建运行；现有源运行按原身份查回。
- `GET /api/creation-runs/{run_id}/execution` 返回真实状态和固定预算；`POST .../sync-proposals`、`GET .../proposals` 同步及查询可信草案；`POST .../resume` 只恢复允许恢复的原执行。
- `POST /api/creation-runs/{run_id}/proposals/{proposal_id}/adopt` 绑定已批准的 ReviewDecision、提案版本和全部阻塞问题处置；未获批准不能产生正式 Owner Effect。
- Go 内部 source/gate 与 Agent 内部 execution/draft/resume 均按独立签名合同调用；追加数据库迁移先显式执行，部署命令和配置见 `agent/README.md`。
