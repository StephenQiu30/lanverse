# 切片 A：手工事实主线实施计划

> Plan ID：`PLAN-A`
> 上游：[PRD-A](../prd/001-切片A手工事实主线PRD.md)、[剧本分析 Design](../design/004-AI视频生产平台剧本基础分析与人物拆解详细设计.md)、M01—M05/M07—M09/M11/M14
> 验收：[Acceptance 规范](../acceptance/README.md)
> 状态：`proposed`

## 1. 交付目标

交付一个不依赖 Agent、模型或真实生成 Provider 的纵向闭环：用户导入整本剧本，修订并批准拆集和叙事事实，得到人物/场景/道具/服装等全剧资产清单与人物集数矩阵，再为一集建立不少于 10 个镜头，以 Fixture 候选形成可播放 Animatic。

## 2. 入口 Gate

- PRD-000 与 PRD-A 状态为 `accepted`，对应 Design 没有影响当前合同的未决问题；
- 一份有授权的整本剧本金标数据集至少包含 3 个内容单元，并覆盖无标题、标题冲突、别名、同名人物、地点复用、道具、服装和部分解析失败；
- 一集的目标深度签认为 3—5 分钟、10—40 镜头，并准备有授权的 Fixture 图片/视频；
- PostgreSQL、唯一 Kafka、Redis、MinIO 可用；业务检索验收前 Elastic 和 OTel Collector 可用；
- 当前 OpenAPI 和空库 Schema 初始化基线可生成、可重建，无历史 migration 或兼容入口。

任一 Gate 缺失时保持 `proposed`，不得以 mock Provider、空页面或手填数据库替代切片验收。

## 4. 执行顺序与并行边界

`A0 → A1 → A2 → A3 → A4 → A5 → A7 → A8 → A9 → A10` 是主链。A6 可在 A4/A5 的 approved 投影稳定后与 A7/A8 并行，但搜索不可成为事实写入的前置；Elastic 不可用时必须返回明确 unavailable/stale，而不是空结果。前端工作随每个纵向包增量完成，不能在最后用手写 DTO 或临时 URL 接线。

## 7. 退出与停止条件

只有十条 PRD-A 验收条件和适用的 PRD-000 基线都得到 `passed` 证据，A 才可标为 `verified`。以下情况停止 B/C：

- 手工 Command/Query 语义、current revision 或事实所有权不稳定；
- 跨租户、媒体访问、Operation 恢复或 Kafka 重放存在泄漏/重复；
- 人物矩阵无法明确表达未决、部分失败或集数依据；
- approved 私有检索无法强制租户/修订过滤；
- 只有 Agent 或真实 Provider 开启时才能完成主旅程。

回退只恢复制品和流量；已批准 Revision、业务事实、审计和媒体对象不得被自动回滚。
