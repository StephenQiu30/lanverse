## 1. 前置 Gate

- 产品负责人接受 PRD-000/A 的试点内容、输入和退出标准；
- M01—M05 最小范围、M07/M08 Fixture 执行契约、Go 业务系统架构和最终数据库 Schema 策略评审通过；
- 准备一份有授权、包含不少于 3 集且覆盖同名/别名/地点复用/道具/服装的金标整本脚本，Fixture 媒体和预期 10—40 镜头范围；
- 开发/测试环境的 PostgreSQL、单一 Kafka 集群、Redis 和 MinIO 可用；进入 A10 前单一 Elasticsearch/Kibana 与 OpenTelemetry Collector 可用，不部署 Logstash/Debezium/Kafka Connect。

## 3. 测试策略

每个 WP 先写领域/状态 Red 测试，再实现应用和数据库集成。必须使用真实 PostgreSQL 验证唯一约束、RLS、乐观锁和 Outbox；在唯一 Kafka 集群的至少一次投递下验证重复消费、手工 offset、Inbox 与重平衡恢复；对象/文档/媒体使用小型授权 Golden 样本。Elastic 只通过 Go `SearchIndexPort` 集成：先验收 approved revision 强制过滤和中文词法金标，再验收 alias 重建与 checkpoint；不以 Kibana 日志证明业务事件已投递。

## 4. 故障与恢复验证

API 在 Outbox 提交后重启、Publisher 发布前后重启、Worker lease 过期、解析部分失败、媒体验证失败、并发批准/重排、成员停用、对象存储短暂不可用、Elastic 写入失败/索引删除/重建中断和 OTel Collector 中断。每项保存 Operation、数据库、审计和用户恢复截图/响应；Elastic/Collector 中断不回滚业务事实，也不伪装零搜索结果。

## 5. 退出与停止条件

满足 PRD-A 十项退出条件并通过 AC-SYS-001/007/008、AC-NAR-013 的 A 范围后关闭。若手工命令语义、跨租户隔离、Operation 恢复或搜索租户过滤不稳定，停止 B/C；不得让 Agent/真实 Provider 掩盖基础缺陷。
