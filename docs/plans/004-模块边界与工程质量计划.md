# 模块边界与工程质量执行计划

## 1. 执行时点

PLAN-004 从 PLAN-003 S0 开始持续执行，不是实现结束后的补充检查。每新增一个模块、Port、事件或 Adapter，必须同步增加架构或契约测试。

## 2. 工作包

| ID | 工作包 | 产出 |
| --- | --- | --- |
| M-W01 | 顶层与包入口 | frontend/backend 隔离及八模块 domain/application/ports 受控 export |
| M-W02 | 数据所有权 | 独立 schema、migration、repository 和禁止跨写 |
| M-W03 | 基础设施 Port | Source/Generation/ObjectStore/EventBus/Search/Moderation |
| M-W04 | 版本化契约 | Command、Event、OpenAPI schema 与兼容规则 |
| M-W05 | 可靠事件 | outbox/inbox、event ID、重投和顺序边界 |
| M-W06 | Catalog Workflow | candidate → governance → asset → catalog → search |
| M-W07 | Generation Workflow | draft → governance → generation → asset → governance |
| M-W08 | 架构门禁 | import、schema、shared、contract 和重建测试 |

## 3. Test-first 任务

| ID | 先失败的约束 |
| --- | --- |
| M-T01 | core 导入 FastAPI/Celery/SQLAlchemy/MinIO/供应商 SDK |
| M-T02 | 模块导入其他模块内部 domain/repository/ORM |
| M-T03 | repository 跨 schema 更新或建立跨模块 ORM relationship |
| M-T04 | shared 出现业务实体、供应商类型或万能 repository |
| M-T05 | Adapter 不满足 Port contract 或泄漏供应商响应 |
| M-T06 | 事件缺少版本/event_id/trace 或携带大正文/secret |
| M-T07 | 重复/乱序事件导致 Workflow 重复终态 |
| M-T08 | search 无法从 catalog 事件完整重建 |

Red 测试随 S0 首次提交；Green 只增加满足约束的最小结构。任何临时跨层导入不得以 TODO 进入 main。

## 4. 实现顺序

1. 创建 frontend、backend/contracts/core/adapters/apps 与 composition root。
2. 建立模块公开 `__init__` 和 import allowlist。
3. 为八模块创建独立 schema/migration/repository。
4. 定义 Port 与 fake Adapter，再实现真实 Adapter。
5. 定义事件 envelope、outbox/inbox 和兼容策略。
6. 实现两个 Workflow 的 fake 故障矩阵。
7. 将架构、契约和重建测试加入 `make verify`/CI。

## 6. 验证

```text
make test-architecture
make test-contract
make test-unit SCOPE=workflows
make test-integration SCOPE=adapters,outbox
make verify
```

每个真实 Adapter 必须运行与 fake 相同的 Port contract；Workflow 必须覆盖重复、乱序、超时、崩溃和补偿。

## 7. 风险与回滚

- shared 膨胀：新增内容需证明跨模块稳定且无业务语义。
- Workflow 变成领域层：规则留在模块，Workflow 只保存步骤/ID。
- schema 隔离影响查询：使用 query service/read model，不跨写。
- 回滚：保留旧契约版本直到消费者迁移；破坏性变化新建版本，不原地修改。
