# 前端工作区与端到端验收计划

## 1. 目标、准入与边界

仅在 PLAN-02～08 全部 Green 后完成最终前端与全链路。目标是用户只通过 Projects→Story→Studio→Tasks→Delivery 五个工作区，把固定故事制作为可播放 MP4，并证明刷新、Worker 重启、第三镜首次失败、局部重试和授权过期均正确恢复。

本计划不扩大产品范围；真实 Provider 凭据/额度/内容保留未批准时，真实 smoke 必须失败，Mock 结果不能替代。Acceptance 报告只在本计划全部实施完成后创建。

## 2. E2E 固定场景

| 场景 | 输入/注入 | 预期 |
| --- | --- | --- |
| Happy path | 固定获权故事、六镜头确定性 Mock | 10 分钟内 MP4 播放，SRT/Manifest 下载 |
| 重复提交 | Project/Source/媒体/Render 各 20 次同意图重放 | 每步一个逻辑资源/Task/副作用 |
| 部分失败 | 第 3 镜视频首次失败 | 其余五镜成功；只重试第 3 镜 |
| Worker 重启 | Provider 已受理未落库时终止 | 原 task_id 在目标时间内终态或 unknown，无重复调用 |
| 页面恢复 | 活跃 Task 时刷新/清空 Store | 3 秒内从 API 恢复；终态 4 秒内可见 |
| 授权过期 | 预览/下载授权失效 | 原位重申请，不新建媒体/Delivery |

## 5. 真实 smoke 关闭清单

运行前由 Product+Backend+Security+QA 确认：获权输入及权利声明；每类能力至少一个启用且默认 profile；Provider/model/region/route/schema；服务端凭据引用；预算/额度和预计上限；内容保留/训练使用边界；批准网络域；失败/取消/对账能力。任一未关闭时命令非零退出并记录缺口，不能跳过该模态或用 Mock 混合成片。

## 7. 风险、回滚与 Definition of Done

| 风险 | 预防 | 回滚 |
| --- | --- | --- |
| 前端缓存掩盖服务端状态 | 清 Store/刷新/断网 E2E | 清缓存并重新查询，不改服务端 |
| 真实供应费用失控 | profile/预算/镜头 exact-set、无 fallback | 停止新任务，保留已受理对账 |
| smoke 混入 Mock | Task snapshot/profile 审计 | 判定失败，不发布 |
| E2E 偶发 | 确定性媒体、可注入时钟、独立 run_id | 保留 trace，修根因，不增加盲目 retry |

完成条件：全部前端 AC Green；完整 Mock E2E 连续 3 次；真实四模态样片至少 1 次；`contracts-check/lint/typecheck/build/security/trace` 全部通过。随后才能创建 ACCEPTANCE-01 并逐条记录结果；任一项缺证据时结论为 `failed/insufficient`。
