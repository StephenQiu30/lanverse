# 技术功能与运行执行计划

## 1. 统一命令

S0 创建并由 CI 调用：

```text
make bootstrap / infra-up / migrate
make test-unit / test-integration / test-contract / test-e2e
make lint / build / verify
make test-provider-live   # 显式启用，最多 10 张
```

## 3. 每切片执行模板

1. 用 fixture/fake 写可失败的单元、契约或集成测试。
2. 提交 `test:` 并证明 Red 原因对应 AC。
3. 实现最小 domain/application/Adapter，提交 `impl:`。
4. 完成页面/API 用户闭环时提交 `feat:`。
5. 运行目标测试、`make lint`、`make build` 和受影响集成测试。
6. 回填 ACCEPTANCE-003；未通过不得进入下一依赖切片。

## 6. 迁移与回滚

- 每模块独立 Alembic；先扩展、切换读写、再删除旧字段。
- 迁移提供 downgrade 或不可逆说明和恢复备份。
- 发布失败优先关闭来源/生成新入口，保留现有作品只读。
- Provider 切换只改 Adapter 配置，历史 model/version/attempt 不变。
- search 可重建；对象删除不可逆，先验证引用与 receipt。

## 7. 性能与 live 验证

普通 CI 禁止真实付费调用。live 测试需凭证、余额、最新单价和负责人批准，最多 10 张。S7 固定 100K fixture、20 并发和查询分布；指标失败后才优化索引/批处理/并发，不提前新增组件。
