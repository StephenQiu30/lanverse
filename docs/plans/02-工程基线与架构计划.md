# 工程基线与架构计划

## 1. 准入、结果与边界

仅在 PLAN-01 M0 达成后执行。目标是生成可构建但不含业务占位实现的 `backend/`、`frontend/` 和根 `docker-compose.yml`，并先用架构测试锁定两个应用根、两个后端入口、模块 allowlist、公开导入方向和禁用技术。六个业务模块和五个前端 Feature 在 owning 子计划首次产生真实代码时创建，PLAN-09 再检查 final exact-set。

不创建 `deploy/build/data/env/root src/apps/packages`，不启动或管理 PostgreSQL/MinIO，不预建生产 Compose，不扫描用户环境文件。

## 4. 架构测试 exact-set

- 顶层应用目录恰为 `backend/frontend`；Compose 为文件而非应用目录。
- 出现的后端业务模块只能属于 `project_catalog/story_development/generation/production_jobs/media_library/delivery`；PLAN-09 再断言 final exact-set。
- 每个已出现模块只按真实职责包含 `domain/application/infrastructure/transport/public.py`；跨模块 AST import 只允许对方 `public.py`。
- Domain 不导入 FastAPI/Pydantic/asyncpg/Alembic/LangChain/SDK/FFmpeg。
- 不出现 ORM Model/Metadata/autogenerate、Service Locator、第三方 DI、消息总线、Event Sourcing、Temporal/Celery/Redis/LangGraph。
- 前端 Feature 名称只允许 `projects/story/studio/tasks/delivery`；PLAN-09 断言 final exact-set。不得出现 Zustand、TanStack Query、`redux-persist`、第二 HTTP sender 或手写生成目录。

## 5. 风险与回滚

| 风险 | 关闭证据 | 回滚 |
| --- | --- | --- |
| 官方模板版本漂移 | 记录命令、模板版本和生成 diff | 删除本任务新建且未被后续引用的脚手架需先确认目标；重新评审版本 |
| 原生依赖构建脚本越权 | pnpm `allowBuilds` exact-set | 阻断安装，不放宽到任意脚本 |
| 环境变量缺失/泄漏 | 只检查变量名存在，secret scan | 停止应用；不复制 `.env` |
| 模块空壳过多 | 架构测试只允许当前任务实际导入路径 | 在同任务中移除无用途空目录 |

## 6. Definition of Done

- T-SCOPE、T-ARCH、T-BOUNDARY、T-BUILD Green，EV-001 保存命令/退出码/依赖与服务 exact-set。
- 两个 lockfile、官方生成 provenance、三个应用服务、loopback 绑定和模块/Feature allowlist 可复现。
- `lint/typecheck/build` 通过，diff 无示例产物、secret 或无关文件。
- 只建立后续 PLAN-03 可用的结构，不实现任何业务 Operation，也不预建业务模块或 Feature 空目录。
