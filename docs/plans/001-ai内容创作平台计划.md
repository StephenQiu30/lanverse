# AI 内容创作平台产品执行计划

## 1. 执行原则

本 Plan 只编排用户可见产品主链；治理、安全、技术运行和模块工程分别由 PLAN-002/003/004 执行。每个产品工作包先写失败的用户/API/E2E 测试，再实现最小可见闭环。

未通过相关专业 Plan 门禁的能力不得在产品界面启用。

## 2. 跨计划顺序

```text
PLAN-004 工程边界 + PLAN-003 S0
→ PLAN-002 治理基础 + PLAN-003 身份/目录
→ PLAN-001 发现与做同款
→ PLAN-003 生成/资产 + PLAN-002 输入输出治理
→ PLAN-001 作品与管理体验
→ 四份 Acceptance 联合发布门禁
```

## 3. 产品工作包

| ID | 工作包 | 依赖 | 用户产出 |
| --- | --- | --- | --- |
| P-W01 | 产品壳与导航 | PLAN-003 S0 | 首页、探索、登录、创作、作品和管理路由 |
| P-W02 | 模板发现 | 技术目录、治理发布条件 | 首页、搜索、筛选、详情和来源展示 |
| P-W03 | 做同款/空白工作台 | 身份、模型能力 | 预填、参数编辑、不兼容提示 |
| P-W04 | 提交与任务状态 | generation API/queue | job ID、排队/运行/失败/取消反馈 |
| P-W05 | 私有作品 | asset、owner policy | 列表、详情、下载、删除状态 |
| P-W06 | 额度与异常体验 | usage ledger、provider 状态 | 三类限额和供应商故障反馈 |
| P-W07 | 管理体验 | governance/admin API | 来源、运行、额度、审核和下架 |
| P-W08 | 全流程发布候选 | 四个 Plan | 关键场景 E2E 和可访问性回归 |

## 4. Test-first 顺序

每个工作包执行：

```text
test: 固化 AC-P 对应 API/组件/E2E 失败用例
impl: 实现领域/API 最小能力
feat: 完成用户页面与状态反馈
refactor: 可选，保持测试通过
docs: 回填 ACCEPTANCE-001 证据
```

P-W02/03/04/05 的浏览器测试必须在 Green 前证明核心路径尚不可完成。

## 7. 验证

```text
make test-unit SCOPE=product-ui
make test-contract SCOPE=public,creation,generation,works,admin
make test-e2e SPEC=discover,remix,blank_create,works,admin
make lint
make build
```

证据包括桌面/移动关键截图、键盘操作、错误状态、API trace 和 AC-P 场景录像或 Playwright trace。

## 8. 风险与回滚

- 模板与模型不兼容：展示映射结果和原始参数，不承诺一致效果。
- 异步状态混乱：用户态固定五种，未知内部状态显示“同步中”。
- 功能未过专业门禁：通过 feature flag/kill switch 隐藏入口。
- 回滚：优先关闭生成和来源入口，保留公开目录或已有私有作品只读。
