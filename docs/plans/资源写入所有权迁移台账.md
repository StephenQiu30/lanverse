- 文档状态：已接受的迁移控制基线，尚未发生目标架构写入切换
- 盘点日期：2026-08-24
- 适用范围：PostgreSQL 表、REST Endpoint、Kafka Topic、Worker/Checkpoint、ObjectStore、Redis、Temporal、Elasticsearch 与协作资源
- 依据：[平台迁移与服务整合计划](平台迁移与服务整合计划.md) · [后端服务架构](../architecture/后端服务架构.md) · [后端领域模块功能设计](../designs/后端领域模块功能设计.md)

## 结论

当前全部业务写入仍由 `agent/` 中的 FastAPI 兼容运行时承担；Go 已接管公共 HTTP 入口，但尚未取得任何业务资源写入权，Temporal 与独立 Agent Executor 也尚未接管运行。本台账固定每类资源的当前 Writer、目标 Owner、不可拆切换单元、门禁和回滚方向；实施时必须把当前条目细化到本次实际变更的精确 Endpoint、表、Topic、Workflow Type、Index、Bucket Prefix 和 Redis Namespace，才允许切流。

截至盘点日，代码声明 74 张 SQLAlchemy 兼容表，`agent/openapi.json` 固定 159 个 Path（含健康与指标 Endpoint），Kafka 只有 `lanverse.io.v1` 与 `lanverse.media.v1` 两个业务 Topic；仓库没有 Temporal Workflow Type、Elasticsearch 业务 Index 或 Yjs Room。74 张表已冻结为第 1 号 Baseline Migration，生产 Schema 只允许 Go `lanverse-migrate` 修改；Python `create_all` 只保留给隔离开发/测试数据库。Agent Guard 已改为校验自身必需表/列、主键和 Migration `1..1` 版本窗口，允许目标表与新增列共存。迁移元数据位于 `lanverse_migration` 专用 Schema，旧运行时回滚时不会把它识别为未知 `public` 表。

## 台账使用规则

### 状态定义

| 状态 | 含义 |
|---|---|
| `现状` | 当前 Python 实现是唯一 Writer，目标实现不得写入 |
| `仅 Schema/无 Writer` | 当前只有表/模型/测试引导，没有已确认的生产写入口 |
| `未创建` | 目标资源尚不存在，任何文档归属都不代表已经实现 |
| `影子读` | 目标实现只读并做差异对账，不返回为权威结果 |
| `待切换` | 数据、契约和回滚已验收，等待单一切流动作 |
| `目标写入` | 目标实现是唯一 Writer，旧实现只读或返回迁移错误 |
| `排空中` | 只允许旧 Run/Task 完成，不接收新运行 |
| `已退役` | 旧 Writer、Publisher、Consumer 和 Schema 管理入口已关闭 |
| `已实现` | 不写业务事实的运行或契约能力已在目标实现生效并有自动化验收 |

当前有生产 Writer 的存量资源均为 `现状`；仅模型资源标为 `仅 Schema/无 Writer`，尚不存在的目标资源标为 `未创建`。文档中的“目标 Owner”不是已实现声明。

### 一个切换单元必须同时包含

1. REST/gRPC Command 入口及其认证、权限、幂等和错误契约。
2. 该 Command 修改的全部表、Outbox 事件和对象位置。
3. 消费其结果的 Worker、Callback、Topic、Checkpoint 与缓存失效。
4. 既有运行的排空规则、新运行的版本分界和回滚兼容性。
5. Count、Hash、金额、状态机与跨租户不变量对账 Receipt。

禁止按单张表切换一个跨表聚合，也禁止让旧 API 写旧表、目标 Worker 再补写新表。双读可以用于 Shadow；双写默认禁止。

### `prod_tasks` 入向外键与分 Lane 退役

`prod_tasks` 不能在 Temporal 首次启用时整表删除。每个目标切片先停止创建对应旧 Task，排空该 Lane，再移除本资源对 Task 的 FK；其余 Lane 继续由旧 Engine 读取，直到阶段 9 统一退役：

| Lane / 入向资源 | 分解阶段 | 门禁 |
|---|---|---|
| DB-16A `prod_attempts` → Task（Generation） | 阶段 4 | 新 Provider Job/Attempt 只绑定 DB-16C Intent/Request；旧 image/video generation Task、Attempt、Inbox 全终态 |
| DB-05、DB-06A/B、DB-08、DB-12 → Task（Planning/Extraction/Adaptation/Bible/Draft） | 阶段 5 | 新 Run 只进 Temporal；旧 Lease/Checkpoint/Task/Inbox 按 Engine Version 全终态，目标表不保存 Task FK |
| DB-13 `sbd_export_jobs` → Task（Export） | 阶段 6 | 新 Export Job 绑定 Media Job/Workflow Ref；旧 Export Task、Topic、对象清理 Receipt 全终态 |
| DB-21 Inbox → Task；`sys_schedule_fires` → Task/Outbox | Inbox 随阶段 4–6 各 Lane；ScheduleFire 阶段 6 | Target Consumer 先改用无 Task FK 的 Inbox Receipt；现有 Media Schedule Handler 到阶段 6 才停，排空 pending Task/Outbox并回填历史 Fire Receipt 后拆 FK |
| `prod_tasks` 表与兼容读 | 阶段 9 | 13 类 Task 均无 pending/claimed/Lease，所有入向 FK 为零，历史 Task/Fire Receipt 已归档并通过数量/关联对账 |
