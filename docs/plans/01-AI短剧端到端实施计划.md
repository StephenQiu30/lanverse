## 2. 唯一 MVP 实现清单

交付闭环为：单操作者创建一个项目/单集→输入符合 `text-normalization-v1`、规范化后 300～3000 个代码点且至少含一个 Han 字符的中文故事并声明权利→生成/确认剧本→生成/确认 6～10 镜头→生成图片、视频与逐句 TTS→逐镜采用→源语言字幕与服务端合成→下载 30～60 秒 MP4。

- 成片固定为 720×1280、24fps、H.264、AAC 48k、MP4；字幕使用 Noto Sans CJK SC 烧录并默认可见，音画最大偏差 100ms。
- 前端只对非终态 `GET /v1/tasks/{task_id}` 每 2 秒轮询；无 SSE、WebSocket、Webhook 或公开事件 Schema。
- 后端只含 `backend-api` 与单一 `backend-worker`；Worker 同时承担 OutboxEvent 派发、Temporal Workflow/Activity、Provider、媒体探测和 FFmpeg。
- 模块只有 `project-catalog/story-development/generation/production-jobs/media-library/delivery`；跨模块只导入 `public/index.ts`。
- ProductionTask 状态只允许 `queued/running/cancelling/cancelled/succeeded/failed/unknown`；等待供应商和后处理仅属于 progress 或 ProductionAttempt 阶段。
- 本地 Compose 服务键恰为 `frontend/backend-api/backend-worker/postgres/temporal/minio`；只有 frontend、backend-api、minio 可在 `127.0.0.1` 发布端口，应用根只允许 `backend/frontend/deploy`。

任何 Provider 未提供可验证的幂等或查询能力时，提交超时必须进入 `unknown` 并停止自动重发；不得用自动换 Provider 绕过。

实现必须原样落实 REQ-06 §3：来源最多 3,000 Unicode 代码点，单个生成 Prompt 最多 4,000，单条字幕最多 500、整集字幕最多 20,000；单实例最多 3 个并发 Provider 调用。Provider 提交/状态请求分别限时 30/10 秒，状态轮询间隔 2～10 秒；Text/Image/TTS 任务限时 120 秒，Video 任务限时 600 秒。远端结果最多重定向 3 次，Image/Video/Audio 分别最多 20/256/32 MiB，SRT/Manifest 各最多 2 MiB，最终 MP4 最多 512 MiB。

每个 FFmpeg 进程最多 2 threads、4 GiB RSS、300 秒墙钟时间和 2 GiB 临时目录；`backend-worker` Compose 上限为 4 CPU/8 GiB，超限必须失败并保留 Attempt。候选预览和成片下载授权 TTL 均为 900 秒。上述值由 T-002 进入 OpenAPI/config Schema，并由 T-005/T-007/T-008 以对应边界与超限夹具验证，不依赖真实 Provider 默认值。

## 6. 计划命令契约

以下是 T-012 完成时必须全部可执行的根脚本；每个脚本由首次使用它的任务建立并在同一任务内产生 Red/Green 结果，不得先创建空脚本或以手工步骤替代：

```bash
corepack enable && pnpm install --frozen-lockfile
docker compose -f deploy/local/compose.yaml up -d --wait
pnpm db:migrate && pnpm contracts:check
pnpm test:architecture && pnpm test:unit && pnpm test:contract && pnpm test:migration
pnpm test:integration && pnpm test:workflows && pnpm test:media && pnpm test:frontend
pnpm test:providers -- real-contract && pnpm test:e2e:flow && pnpm test:trace
pnpm test:e2e:mock -- --repeat-each=3
pnpm test:security && pnpm test:performance && pnpm typecheck && pnpm lint && pnpm build
pnpm verify:mock && pnpm verify:providers && pnpm verify
pnpm test:e2e:real
```

`pnpm verify:mock` 覆盖 T-001～010；`pnpm verify:providers` 在 T-011 增加真实 Adapter Stub 契约与安全门禁但不提前运行 `test:trace`；T-012 的 `pnpm verify` 才覆盖 `test:trace` 及除付费真实调用外的全部门禁。`test:e2e:real` 只在受控凭据环境显式执行且不进入普通 PR CI。
