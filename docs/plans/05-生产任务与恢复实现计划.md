# 生产任务与恢复实现计划

## 1. 目标与修改边界

交付所有异步业务依赖的 production_jobs 基线：原子受理、权威查询、Task/Attempt 状态、TaskEvent、TaskJob lease/heartbeat、Handler 分派、稳定 Provider request key、自动/用户重试、取消、unknown 对账和局部隔离。

修改限于 `production_jobs`、`jobs/`、根幂等基础设施、Task transport、故障 Fake 和目标测试；不生成具体 Script/Media/Delivery 业务输出，具名 Handler 在各 owning 子计划实现并注册。

## 2. 故障 fixture 与时间控制

使用可注入 Clock、确定性 Provider Fake 和两个独立 Worker 实例，覆盖：受理提交前、Job 领取后、Provider 发送前、Provider 已受理未回执、下载前后、业务登记前后、心跳丢失、取消迟到和终态重放。测试以短 lease 参数运行，产品上限通过配置契约另测；不得用真实睡眠模拟 120 秒。

## 5. 迁移、风险与回滚

不新增表；任何字段/索引变化先回到 DESIGN-06/根 SQL/PLAN-03。Runner 外部调用期间禁止持锁，数据库重试只覆盖尚无外部副作用的完整事务。

| 风险 | 预防 | 回滚 |
| --- | --- | --- |
| lease 过期重复提交 | 发送前稳定 key、继任先对账 | unknown/人工确认，绝不盲目重发 |
| 心跳竞争掩盖失活 Worker | owner+deadline CAS 测试 | 停止 Worker，让 lease 自然过期 |
| 取消被误报成功 | cancelling 与终态分离 | 保留 Attempt/迟到 blocked 输出 |
| 新版本不能恢复旧 Job | payload handler_version + 排空测试 | 保留兼容 Handler/回退 Worker 制品 |

## 6. Definition of Done

- AC-PRD-003/005/006 与 AC-MOD-TASK-001～006 的本计划范围 Green，EV-004 含五点故障差异和调用计数。
- `make test-jobs test-integration` 通过，双 Worker 竞争只有一个 owner；测试无长阻塞 sleep。
- 所有 Task Operation 与 OpenAPI 一致；前端可依赖权威查询但本计划不实现完整工作区。
- 无 Temporal/Celery/Redis/LangGraph/进程内持久队列，日志与 Job payload 无 secret/Prompt。
