## 1. 目标与原则

1. **每条验收标准都有测试**：功能文件中的每个 Given/When/Then 至少对应一个测试用例（0502），MVP 用例全部通过才算里程碑完成（0202 MNT-02）。
2. **钱与数据优先**：报价、预算、预留结算、对账、幂等、版本不可变、依赖传播是最高风险区，测试最密集。
3. **测试不依赖真实付费供应商**：CI 全部使用模拟供应商（0202 OPS-06）与录制的 LLM 响应；真实供应商只在 P0 评测与预发冒烟中使用，并受预算控制。
4. **核心逻辑先写测试**（AGENTS.md：Red → Green → Refactor）。
5. **结果如实**：跳过、受环境限制的测试在报告中列明，不计为通过。

## 3. 各层重点

### 3.1 单元测试必须覆盖的核心逻辑

| 模块 | 重点 | 关联 |
| --- | --- | --- |
| operation | 状态机全部迁移（含非法迁移）、计价（各单位与系数）、input_hash 规范化、复用判定、报价失效判定 | F16、F20、0304 §4–5 |
| billing | 预留、结算、释放、超支标记、账本平衡不变式 | F06、F30 |
| lineage | 依赖登记、传播（0304 / F29 §2.1 每一行）、清除条件、递归深度 | F29 |
| script | 编码识别、分集边界、稳定键保持（编辑、拆分、合并） | F07、F08 |
| storyboard | 台词分配校验、参考组合校验（F14 全部规则）、合并拆分 | F13、F14 |
| catalog | param_schema 与 limits 校验器（前后端共用测试向量） | F03 |
| identity | 密码规则、锁定、会话纪元 | F01 |
| agent harness | Validators、Context 切分与合并、预算、修复循环 | 0305 |

覆盖率：上述核心包行覆盖率 ≥ 80%（0202 MNT-02）；全局不设硬指标。

### 3.2 集成测试

- 每个仓储方法至少一条真实 PostgreSQL 测试；递归 CTE、报表 SQL、部分唯一索引行为必须覆盖。
- 事务一致性：业务写入 + Outbox + 依赖登记在同一事务；故意在提交前失败，断言三者都未写入。
- 消费者幂等：同一事件投递两次，结果只一次。
- 迁移：空库全量迁移；上一发布版本库升级迁移（0302 §10）。

### 3.3 工作流测试

- testsuite 模拟 Activity，覆盖 OperationWorkflow 的所有分支（成功、拒绝、not_submitted 重提、unknown → 对账找到 / 确认不存在 / manual、取消各阶段、接管重试、审核失败、复用）。
- 回放测试：CI 保存典型历史文件，每次修改工作流代码必须回放通过（0304 §14）。

### 3.4 前端测试

- 组件：报价确认组件（过期倒计时、预算不足禁用、复用项、境外提示、回车不触发确认）、参数表单（7 种组件）、参考组合上限条、候选对比键盘操作。
- 可访问性：axe 自动检查主要页面（0202 A11Y-01）。

## 5. 测试数据

| 数据集 | 内容 | 用途 |
| --- | --- | --- |
| 样例剧本集 | 10 部授权可用的剧本（竖屏短剧 6、中短片 3、单片 1；含 GBK、多文件、无集标记、超长集等边界） | 导入、解析、评测（0503） |
| 标注集 | 样例剧本的人工标注：分集、场、台词、说话人、别名 | 解析与抽取评测 |
| 媒体样本 | 各格式合法样本；伪装类型、超大、超长、畸形文件（fuzz 语料） | 上传与安全测试 |
| 合成大规模项目 | 100 集 × 150 镜头、200 造型、20,000 媒体（生成脚本 `tools/seed-large`） | 性能与容量（0202 §0.2） |
| 录制响应 | 各 Skill 的 LLM 响应录制（含不合法输出用于修复测试） | CI 中的 Harness 集成测试 |
| 模拟供应商场景 | 延迟、失败、超时但已受理、超时未受理、重复回调、结果过期 | 故障注入 |

测试数据不含真实个人信息；真人照片样本仅使用已授权或公开授权素材。

## 7. 故障注入与韧性

执行 0304 §14 的矩阵，另加：

| 注入 | 期望 | 关联 |
| --- | --- | --- |
| Kafka 停止 5 分钟 | 选定、确认等写入成功；恢复后事件补发、过期与通知补齐 | AVL-05、REL-07 |
| Redis 停止 5 分钟 | 登录与会话不可用（明确 503）；恢复后正常；缓存回源 | AVL-05 |
| PostgreSQL 主库重启 | 工作流 Activity 重试后继续 | REL-01 |
| 发布期间滚动重启全部服务 | 进行中任务不失败；SSE 自动重连补齐 | AVL-04 |
| 对象存储短暂不可用 | 上传与接管失败重试；已有页面可浏览 | 0301 §12 |

## 9. 安全测试

按 0307 §15 执行；越权用例由 OpenAPI 自动生成，新增端点自动纳入。

## 10. 可用性测试

- 每个里程碑末，邀请 ≥ 2 名未参与开发的内部成员按任务脚本操作（如“把第 1 集第 3 场做成片”），记录完成率、耗时、卡点（0202 USE-01）。
- 发现的问题按 0402 §7 记录为缺陷或改进项。

## 11. 验收测试

- 里程碑验收按 0401 各阶段验收项与 0502 中该里程碑的全部用例执行。
- MVP（M4）验收执行 0101 §8.2 的 7 个场景，在生产环境用真实供应商完成，费用在预算内。
- 结果写入 `docs/acceptance/M<n>-验收记录.md`：用例、操作步骤、数据、结果、证据（截图、追踪 ID、成片链接）、未通过项与残余风险。

## 12. 准入与准出

| 阶段 | 准入 | 准出 |
| --- | --- | --- |
| PR 合并 | — | PR 检查全部通过；新增逻辑有测试 |
| 里程碑验收 | 该里程碑任务全部完成；夜间测试最近 3 次全绿 | 0502 中该里程碑 MVP 用例 100% 通过；无 S1 / S2 缺陷；S3 缺陷有计划；性能与故障注入达标 |
| 生产发布 | 预发冒烟通过；迁移在预发演练 | 发布后冒烟通过；监控无新告警 30 分钟 |

## 13. 缺陷与报告

- 缺陷分级与处理见 0402 §7；S1 / S2 修复必须附回归测试。
- CI 生成测试报告（JUnit XML + 覆盖率）并保留 30 天；里程碑报告汇总于验收记录。
