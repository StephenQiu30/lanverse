## 1. 目标与原则

1. **每条验收标准都有测试**：功能文件中的每个 Given/When/Then 至少对应一个测试用例（TST-02），MVP 用例全部通过才算里程碑完成（REQ-02 MNT-02）。
2. **钱与数据优先**：报价、预算、预留结算、对账、幂等、版本不可变、依赖传播是最高风险区，测试最密集。
3. **测试不依赖真实付费供应商**：CI 全部使用模拟供应商（REQ-02 DEP-06）与录制的 LLM 响应；真实供应商只在 P0 评测与预发冒烟中使用，并受预算控制。
4. **核心逻辑先写测试**（AGENTS.md：Red → Green → Refactor）。
5. **结果如实**：跳过、受环境限制的测试在报告中列明，不计为通过。

现有测试命令与 CI 以 [PROJECT](../../../PROJECT.md) 和实际工作流为准；下列完整测试分层、数据集、回放、自动越权与 AI 门禁计划随业务接入，分别留真实执行证据。

## 3. 各层重点

### 3.1 单元测试必须覆盖的核心逻辑

| 模块          | 重点                                                                                          | 关联                        |
| ------------- | --------------------------------------------------------------------------------------------- | --------------------------- |
| operation     | 状态机全部迁移（含非法迁移）、计价（各单位与系数）、input_hash 规范化、复用判定、报价失效判定 | REQ-21、REQ-25、DES-04 §4–5 |
| billing       | 预留、结算、释放、超支标记、账本平衡不变式                                                    | REQ-11、REQ-32              |
| lineage       | 依赖登记、传播（DES-04 / REQ-31 §2.1 每一行）、清除条件、递归深度                             | REQ-31                      |
| script        | 编码识别、分集边界、稳定键保持（编辑、拆分、合并）                                            | REQ-12、REQ-13              |
| storyboard    | 台词分配校验、参考组合校验（REQ-19 全部规则）、合并拆分                                       | REQ-18、REQ-19              |
| catalog       | param_schema 与 limits 校验器（前后端共用测试向量）                                           | REQ-08                      |
| identity      | 当前工作区身份、组织与角色隔离；未来消费者密码、锁定、会话纪元另验                            | REQ-06                      |
| agent harness | Validators、Context 切分与合并、预算、修复循环                                                | DES-05                      |

覆盖率：上述核心包行覆盖率 ≥ 80%（REQ-02 MNT-02）；全局不设硬指标。

### 3.2 集成测试

- 每个仓储方法至少一条真实 PostgreSQL 测试；递归 CTE、报表 SQL、部分唯一索引行为必须覆盖。
- 事务一致性：业务写入 + Outbox + 依赖登记在同一事务；故意在提交前失败，断言三者都未写入。
- 消费者幂等：同一事件投递两次，结果只一次。
- Schema：同一事实源单事务初始化空库；上一发布版本实例执行已审阅增量并验证真实数据保留（DES-02 §10）。

### 3.3 工作流测试

- testsuite 模拟 Activity，覆盖 OperationWorkflow 的所有分支（成功、拒绝、not_submitted 重提、unknown → 对账找到 / 确认不存在 / manual、取消各阶段、接管重试、审核失败、复用）。
- 回放测试计划在工作流历史样本就绪后接入 CI；接入后修改工作流代码须回放通过（DES-04 §14）。

### 3.4 前端测试

- 组件：报价确认组件（过期倒计时、预算不足禁用、复用项、境外提示、回车不触发确认）、参数表单（7 种组件）、参考组合上限条、候选对比键盘操作。
- 可访问性：axe 自动检查主要页面（REQ-02 A11Y-01）。

## 10. 可用性测试

- 每个里程碑末，邀请 ≥ 2 名未参与开发的内部成员按任务步骤操作（如“把第 1 集第 3 场的镜头与配音全部生成并选定”），记录完成率、耗时、卡点（REQ-02 USE-01）。
- 发现的问题按 PLN-02 §7 记录为缺陷或改进项。

## 11. 验收测试

- 里程碑验收按 PLN-01 阶段范围与 TST-02 明确的本阶段用例执行；跨阶段联调门禁保留到相应合同就绪，模拟结果不标真实验收通过。
- 整项目验证和正式入口 Demo 覆盖 Go/前端适用检查、真实依赖、身份/项目、画布/正式资源与失败恢复；业务生成、接管、正式选定与费用计划按对应合同接入，真实供应商与付费预算单独记录。
- MVP（M5）仍执行 PRD-01 §8.2 的 9 个场景与全部对应非功能要求，费用在预算内；Demo 或画布核心技术检查通过不替代完整产品验收。
- 验收报告随交付保存到任务产物或 CI，包含用例、真实操作、结果、证据、未通过项与残余风险；仓库测试文档维护稳定策略和用例。

### 11.1 当前工作台与持久合同验收

- 正式项目与工作区、画布命令、同项目已接管媒体、持久幂等、CAS、Outbox、刷新和未知结果恢复分别验证；受控 API/组件检查不替代真实 PostgreSQL、对象存储、Workflow 或供应商执行。
- 历史读取验证未知字段、重复 JSON 键、非法 UTF-8、空 applies_to 等价与非空差异拒绝；读取前后原字节和 SHA 保持一致。
- 生命周期历史保护覆盖每 family 100000 行、合计64MiB、单件1MiB及真实 PostgreSQL 客户端 allocation；拒绝必须发生在无界载入之前。完整 Copy manifest 按自己的预算验证。
- 媒体回执时间按同一瞬间比较并统一时区，真实微秒变化仍拒绝；Workflow 重复启动必须核实已有执行并给原 run 发控制信号，不把已有 handle 当新执行。
- GIF 验证全部帧、晚帧损坏、尾随数据、帧数和像素预算；glTF/GLB 验证自包含资源、精确 MIME/字节数、原件 SHA、独立 Copy 和授权失效后的资源销毁。
- 永久清理和素材包必须验证真实对象、当前/历史引用、容量去重、取消、原键恢复、完整内容往返及人工最终动作。页面 fixture、health、生成契约和本地构建均不等于这些能力已验收。
- 性能采用60秒实际运动窗口；空闲不计交互帧率，隐藏中断，可信输入或运动不足明确标记。合成与真实媒体、目标机器和跨设备分别验证，不外推旧引擎结果。
