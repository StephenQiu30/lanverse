## 2. 处理流程

```text
管理员新增模型（model_key、供应商、能力、显示名）→ 发布版本 v1（模式、限制、参数表单、是否支持查询 / 取消 / 回调、预计最长时长）
  → 发布价格规则 v1（计价单位与规则、币种、汇率）→ 启用
制作者选择模型 → GET /api/models 返回当前版本的 param_schema 与 limits → 前端渲染表单与限制提示
报价 → 按 model_profile_version 校验输入与参数 → 按生效的 price_rule_version 计价 → Operation 记录两者的版本 ID
```

## 3. 数据

| 表                              | 关键字段                                                                                                      | 为什么需要                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `catalog.capability`            | `key`、`output_type`、`modes`、`input_roles`                                                                  | 平台内部按能力 + 模式调用，与具体模型解耦 |
| `catalog.model_profile`         | `model_key`、`provider_id`、`capability`、`status`、`current_version_id`                                      | 模型身份与启用状态                        |
| `catalog.model_profile_version` | `modes`、`limits`、`param_schema`、`supports_query/cancel/callback`、`expected_max_ms`、`moderation`、`queue` | 驱动界面、校验、工作流行为                |
| `catalog.price_rule_version`    | `unit`、`rule`、`currency`、`fx_rate_to_cny`、`effective_from`                                                | 报价与结算                                |
| Redis `catalog:models:v{n}`     | 当前生效的注册表快照                                                                                          | 高频读取；事件驱动失效                    |

Schema 约束保证 `current_version_id` 属于同一模型，版本号为正、版本载荷具有预期 JSON 类型；非人民币价格规则必须保存正的版本化汇率。管理端供应商列表的模型数量计入该供应商所有未逻辑删除的 `model_profile`，包括当前停用的模型。

`param_schema` 示例：

```json
[
  {
    "field": "duration_ms",
    "label": "时长",
    "type": "integer",
    "component": "segmented",
    "enum": [5000, 10000],
    "default": 5000,
    "for_modes": ["image2video", "omni_reference"]
  },
  {
    "field": "resolution",
    "label": "分辨率",
    "type": "string",
    "component": "select",
    "enum": ["720p", "1080p"],
    "default": "1080p"
  },
  {
    "field": "camera_fixed",
    "label": "固定镜头",
    "type": "boolean",
    "component": "switch",
    "default": false
  },
  {
    "field": "seed",
    "label": "随机种子",
    "type": "integer",
    "component": "input",
    "min": 0,
    "max": 2147483647,
    "required": false
  }
]
```

`label` 是面向制作者的必填字段名；`description` 可补充输入说明，`step` 可指定数字控件步长。界面按 `for_modes` 过滤字段，切换模型或模式时重建表单状态，避免旧模型的参数进入新报价。

发布前用 Draft 2020-12 Schema 校验结构，再校验跨字段关系。`field` 只能使用英文字母、数字和下划线且不能以数字开头，避免表单库将点号解释为嵌套路径；`__proto__`、`prototype`、`constructor` 是保留名，同一版本内不得重复字段名。`label` 不得为空白。`for_modes` 非空且只包含当前版本支持的模式。`switch` 只用于布尔值；`textarea` 只用于自由文本；`slider` 只用于带 `min`、`max` 的数值；`select`、`segmented`、`voice` 必须有与字段类型一致的非空选项，其中 `voice` 是字符串。数值上下限不能倒置，整数参数的 `min`、`max`、`step` 必须为整数；默认值必须与字段类型、选项和范围相容。

发布载荷中的 JSON 对象不得重复属性名，选项字符串不能是空白。数值参数的默认值、选项和界限必须处于 JavaScript 安全整数幅度内，整数判断和范围比较使用精确十进制数值；滑块默认值还必须落在以 `min` 为起点的 `step` 刻度上。用途限制的键须与模型能力的 `input_roles` 对照，此检查依赖发布事务读取当前能力记录。

`limits` 示例：

```json
{
  "roles": {
    "subject": { "max_count": 4, "types": ["image"] },
    "scene": { "max_count": 2, "types": ["image"] },
    "motion": { "max_count": 1, "types": ["video"], "max_ms": 15000 },
    "audio": { "max_count": 3, "types": ["audio"], "max_ms": 15000 },
    "_total_images": 9,
    "_total_videos": 3,
    "_total_audios": 3
  },
  "aspect_ratios": ["9:16", "16:9"],
  "resolutions": ["1080p"],
  "max_outputs": 4
}
```

`limits.max_outputs` 必须为正整数；每个用途的 `max_count` 是非负整数，`types` 是非空且不重复的 `image`、`video`、`audio` 集合；可选的 `max_ms`、`max_bytes` 为正整数。`min_resolution` 暂以非空字符串记录，分辨率写法由具体适配器约定，报价校验须和适配器使用同一格式。总量键 `_total_images`、`_total_videos`、`_total_audios` 是非负整数。结构 Schema 与共用测试向量分别位于 `backend/internal/catalog/adapter/paramvalidation/schema.json` 和 `backend/internal/catalog/testdata/param-schema/cases.json`；前端接入时读取同一套规则与向量。

价格规则发布契约：`per_image`、`per_second`、`per_request`、`per_1k_chars` 的 `rule` 必须含非负整数 `base_micros`（0 表示免费）；可选 `by_resolution`、`by_mode`，两者均为非空键到正十进制系数的对象。`per_1k_tokens` 必须含非负整数 `input_micros_per_1k` 和 `output_micros_per_1k`，至少一项大于 0，且不得包含 `base_micros` 或系数。微元数须使用 JSON 普通十进制整数字面量（不带小数点或指数），且不超过 JavaScript 安全整数；系数使用不超过六位小数、最大 1000000 的普通十进制写法。规则最多 64 KiB，拒绝未知字段、重复 JSON 属性、空白键和无效数值。价格发布前须有模型当前版本；`by_mode` 键须属于该版本的模式，`by_resolution` 键须属于该版本 `limits.resolutions`。CNY 汇率可留空（按 1 计算）或显式填写 1，外币必须填写正的版本化汇率。参数系数的 JSON 形状尚未确定，发布校验会拒绝该字段，计划在计价设计明确后补充校验与报价测试。

价格允许立即或未来生效，也允许补录已过去的生效时刻；发布时将 `effective_from` 四舍五入到 PostgreSQL `timestamptz` 的微秒精度，审计与存储使用同一时刻。报价取 `effective_from <= 报价时刻` 中按 `(effective_from DESC, version_no DESC)` 排序的首条。未来生效价格不会令没有当前生效价的模型提前启用。缓存的价格快照须在下一个 `effective_from` 到达前失效或重新核对数据库，避免只依赖发布事件造成跨生效点旧价。已确认任务保留报价时的价格版本。

模型启停命令携带预期修订号；同一事务内复核当前管理员、锁定模型头，并对当前状态执行 `disabled ⇄ active` 转换。启用要求当前模型版本及至少一条已生效价格，只有未来价格时拒绝；停用不依赖当前价格或凭据状态。供应商凭据不可用时按 R9 在模型查询中标记不可用，不作为管理员启用门槛。成功转换递增修订号，并与 `model.enabled` / `model.disabled` 审计 Outbox 原子提交；审计 `before` / `after` 只记录状态与修订号。在途任务保留原模型与价格版本并继续执行；新报价拒绝停用模型的读侧校验及缓存失效分别由报价实现和 E-08-03 验证。

## 4. 接口

| 方法       | 路径                                        | 说明                                                                                               |
| ---------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| GET / POST | `/api/admin/models`                         | 列表 / 新增                                                                                        |
| GET        | `/api/admin/models/{id}`                    | 详情与版本历史                                                                                     |
| POST       | `/api/admin/models/{id}/versions`           | 发布新版本（Rev）                                                                                  |
| POST       | `/api/admin/models/{id}/prices`             | 发布价格规则                                                                                       |
| POST       | `/api/admin/models/{id}/enable`、`/disable` | 启用 / 停用                                                                                        |
| POST       | `/api/admin/models/{id}/versions:validate`  | 发布前校验与表单预览（不保存）                                                                     |
| GET        | `/api/models?project_id=&capability=&mode=` | 制作者可用模型：按项目境外设置过滤，返回 `param_schema`、`limits`、`available`、`region`、价格摘要 |

R9 的实现：`GET /api/models` 对凭据不可用的供应商的模型返回 `available = false` 与 `unavailable_reason`。

项目模型查询读侧以当前 Workspace actor、组织和未归档项目为同一事务的授权边界；境外开关从项目记录实时读取。项目禁止境外模型时不返回境外模型；停用模型、停用供应商及无可用凭据的境内模型仍保留在查询结果中，供界面展示不可用状态。列表按 `model_key, id` 稳定分页，模式按当前模型版本过滤；价格摘要取查询时已生效的最新价格，生效时刻相同时以较高版本号优先。凭据只投影存在性和安全测试结果，不读取密文或密钥标识。公开响应的 `available` 判定、`unavailable_reason` 枚举与分页游标编码以注册路由的 DTO 和在线 Swagger 为准（DES-03）。

## 5. 异步与工作流

无。模型版本中的 `queue` 与 `supports_*` 被 OperationWorkflow 读取（DES-04）。

## 6. 事件与实时

`catalog.model_changed.v1`、`catalog.price_changed.v1` → cache-invalidator（清除 Redis 快照）；审计经 `audit.recorded.v1`。

## 7. 界面

- 管理 · 模型注册表：列表（模型、供应商、能力、区域、状态、当前版本、价格）；详情编辑器（JSON 编辑 + 表单预览）；版本差异对比。
- 生成面板：`ModelParamsForm` 组件按 `param_schema` 渲染；`ReferenceLimitBar` 显示各用途用量 / 上限。

## 8. 权限与审计

管理员可写；所有登录用户可读 `GET /api/models`。审计：`model.created`、`model.version_published`、`model.enabled`、`model.disabled`、`price.published`。

## 9. 非功能要求

EXT-01（同家新模型只改配置，用自动化测试“配置新模型并完成一次模拟生成”验证）；PERF-10（报价时注册表读取走缓存）。

## 10. 测试设计

- 单元：`param_schema` 与 `limits` 校验器（前后端共用同一套 JSON Schema 规则）；价格计算（按张、按秒、按 token、按字符、分辨率系数）。
- 集成：发布版本 → 缓存失效 → 报价使用新版本。
- 前端：各组件类型渲染与校验的快照测试。

## 故障约束与专项验证

- 专项验证：用同供应商两版模型、9 图上限、两版价格及进行中任务执行 TC-08-01～05；验证发布校验、模式切换、价格版本固化、缓存失效与模拟报价（REQ-08 §3；DES-11 §10；TST-02）。

- 注册表缓存失效导致旧价报价：报价时核对权威版本，发现不一致即回源并重报。
- 错误能力或价格版本已发布：停用该模型的新报价并发布修正版，保留已确认任务原版本供核查。
