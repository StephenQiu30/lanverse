## 3. 接口

| 方法       | 路径                                                  | 说明                        |
| ---------- | ----------------------------------------------------- | --------------------------- |
| GET / POST | `/api/admin/providers`                                | 列表 / 新增供应商           |
| PATCH      | `/api/admin/providers/{id}`                           | 修改并发、速率、状态（Rev） |
| POST       | `/api/admin/providers/{id}/credentials`               | 设置凭据                    |
| POST       | `/api/admin/providers/{id}/credentials/test`          | 测试当前启用的凭据          |
| POST       | `/api/admin/providers/{id}/credentials/{cid}/disable` | 停用                        |

供应商登记时 `key` 为 1–64 字节的小写 ASCII 标识，以小写字母开头，其余只允许小写字母、数字、下划线或连字符；名称最多 100 个 Unicode 字符。`adapter_key` 必须属于当前已声明凭据字段的适配器，区域、并发与每分钟速率均须通过领域校验。应用命令生成新供应商 ID，PostgreSQL 事务重新核对当前管理员后，写入供应商和 `provider.created` 审计 Outbox；审计摘要只包含 key、适配器、区域、状态和两个限额，事件写入失败时供应商登记整体回滚。公共接口的重放语义依 DES-03 §2。

供应商修改只接受状态、并发限额与每分钟速率的变更，要求当前 `expected_revision` 且拒绝空变更；`key`、名称、适配器与区域不在此命令中修改。读取与写入事务分别复核当前管理员权限，写入事务对供应商行加锁并再次核对修订号；修订冲突不能写入事件。成功修改时递增修订号，并将 `catalog.provider_changed.v1`（只含供应商 ID 与新修订号）及 `provider.updated` 审计 Outbox（前后状态与限额）与配置写入同一事务。凭据明文与密文不进入事件。公共接口的幂等与错误响应依 DES-03 §2。

内部供应商详情查询在同一 PostgreSQL 事务复核当前管理员并读取供应商与当前启用凭据；凭据查询只选择 ID、标签、末 4 位、状态、最后测试类别与时间、创建与更新时间，不查询 `ciphertext` 或 `key_id`。无启用凭据时返回空凭据摘要；已停用供应商若仍保留启用凭据，仍显示其摘要，调用方结合供应商状态判断不可用于新任务。`credential_schema` 来自适配器声明：`api_key` 为必填密码字段，MiniMax 另有必填文本字段 `group_id`；未知适配器不得推断字段。公共 GET 响应形状仍以 DES-03 就绪评审为准。

内部供应商列表同样在一个事务中复核当前管理员，按 `(create_time DESC, id DESC)` 返回有界游标页（默认 50，最多 200），包括停用供应商，排除逻辑删除。每项包含供应商安全配置、当前启用凭据的展示摘要以及该供应商未逻辑删除模型的数量（含停用模型；DES-11 §3），查询不选择凭据密文或密钥 ID。列表为空或无当前凭据时分别返回空页、空凭据摘要；公共游标编码与响应形状仍由 DES-03 评审确定。

```http
POST /api/admin/providers/{id}/credentials
{ "label": "方舟主账号", "secret": { "api_key": "…" } }
201 { "id": "…", "label": "方舟主账号", "last4": "a9F2", "status": "active", "last_test_result": null }
```

`secret` 为对象，不同供应商字段不同（方舟：`api_key`；MiniMax：`api_key`、`group_id`；OpenRouter：`api_key`），字段定义由适配器声明、在 `GET /api/admin/providers/{id}` 的 `credential_schema` 中返回。
当前三种适配器均以 `api_key` 的末 4 个字符作为 `last4`；MiniMax 的 `group_id` 不参与摘要。保存命令先按供应商的 `adapter_key` 严格校验必需字段、字符串类型及未声明字段，再封装原始 JSON。未知适配器或无效字段必须拒绝，不能将未经校验的明文交给仓储。内部命令的审计摘要只允许 `last4`，与凭据变更事件同事务写入 Outbox；该敏感命令的 `request_id` 只接受服务端提供的规范 UUID，避免将任意请求文本写入审计。公共写接口的幂等与错误响应仍依 DES-03 §2。

停用命令必须指定当前启用的凭据 ID；即使供应商本身已停用，管理员仍可撤销该凭据。读取安全元数据及写入事务分别复核管理员当前权限；写入时锁定供应商和凭据行，凭据被替换或已停用则拒绝。状态变为 `disabled`、`catalog.credential_changed.v1` 与 `credential.disabled` 审计 Outbox 在同一事务提交；审计只含 `last4`，任一事件写入失败则状态回滚。公共接口的同键重放仍按 DES-03 §2 处理。

## 4. 异步与工作流

- 测试：`backend-api` 直接执行一个短工作流 `CredentialTestWorkflow` → Activity `provider.test_credential`（`agent` 队列，超时 15 秒，不重试）。
- 工作流在调用供应商 Activity 前读取当前启用凭据的密文并随 Activity 输入传入；获授权的 Go 执行 Worker 用私钥解密，明文只保存在进程内存中，缓存 5 分钟（DES-07 §5.2）。

Activity 输入须携带 `provider_id` 供解封时验证 AAD，`adapter_key` 选择固定的测试方法；`provider_key` 仅作供应商业务标识，不能据此推断适配器。密文采用标准 Base64 传入 Temporal JSON。M1 首批仅 OpenRouter 使用[官方当前密钥查询接口](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-key) `GET /api/v1/key`，不发送生成请求；火山方舟与 MiniMax 在确认与现有 `api_key` 兼容的免费鉴权接口前返回 `unsupported`，不得将其当作测试通过。Agent 只回传上述安全结果类别，不传供应商响应体或请求原文。测试 Activity 每次解封且不缓存明文；生成适配器的缓存及事件失效计划按 §5 接入。Worker 缺少私钥配置时仍注册 Activity，对需解封的测试返回通用 `credential_test_unavailable`；公共接口接入时将其呈现为 503，不将无密钥误报为鉴权失败。

Go `flow` Worker 的短工作流先调用数据库 Activity，复核管理员账号当前状态、供应商启用状态及指定凭据仍为当前启用记录，再将仅含密文的输入发往 `agent` 队列；Agent 调用 15 秒超时且不重试。安全结果回到 Go 后，由数据库 Activity 再次复核账号和同一凭据状态，在一个事务中更新 `last_tested_at` / `last_test_result` 并写入 `catalog.credential_changed.v1` 与 `audit.recorded.v1`。管理员撤权、供应商或凭据停用、凭据被替换、Agent 不可用时不得把旧测试结果写到新凭据。结果回写使用测试 ID 生成稳定事件 ID，以抵抗 Activity 重试；审计 `credential.tested` 仍只记录 `last4`，不含明文、密文或供应商响应。

R6 的实现：任务在每个 Activity 开始时读取当前启用的凭据；停用后新提交的 Activity 返回不可重试错误 `credential_disabled`，已提交的任务的查询 Activity 继续使用提交时的凭据 ID 直至完成。

## 5. 事件与实时

`catalog.provider_changed.v1`（状态、限额）及 `catalog.credential_changed.v1`（新增、停用、测试结果）→ 注册表缓存失效；审计经 `audit.recorded.v1`。

## 6. 界面

供应商列表：名称、区域、凭据状态（末 4 位、最后测试结果与时间）、模型数量；凭据对话框为密码输入框，保存后不可查看。

## 7. 权限与审计

仅管理员。审计 action：`provider.created`、`provider.updated`、`credential.set`、`credential.disabled`、`credential.tested`；只记录 `last4`。

## 8. 非功能要求

SEC-04（凭据不出现在日志、响应、前端、追踪中，CI 扫描验证）；OBS-02（日志脱敏）。

## 9. 测试设计

- 单元：封装 / 解封；`secret` 按适配器 schema 校验。
- 集成：停用后新报价失败、进行中任务继续查询；日志与响应敏感词扫描。

## 故障约束与专项验证

- 专项验证：以方舟、MiniMax 测试账号和无免费接口的模拟适配器执行 TC-07-01～04；注入认证失败、Agent 不可用、凭据停用及在途查询，扫描响应和日志是否泄露凭据（REQ-07 §3；DES-10 §9；TST-02）。

- 供应商没有免费测试接口：展示“不支持测试”，保留未测试状态，首次付费生成前仍走报价确认。
- 凭据疑似泄露或停用广播延迟：立即禁止新提交并使缓存失效；已提交任务继续查询，核查旧密钥是否仍被新调用使用。
