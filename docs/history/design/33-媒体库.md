## 2. 处理流程

当前本机上传合同与计划接入的消费者直传合同见[上传受理与安全](#上传受理与安全)。本机 multipart 接管后显式审核；预签名直传与 MediaIngestWorkflow 计划按独立闭环接入和验收。

## 3. 数据

| 表                  | 关键字段                                                                                                                                                                                                                                                                                 | 为什么需要         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `media.media_asset` | `kind`、`origin`、`status`、`object_key`、`mime_type`、`byte_size`、`sha256`、宽高时长帧率编码、`source_operation_id`、`provider_key`、`model_key`、`region`、`moderation_status`、`aigc_marked`、`consent_record_id`、`contains_real_person`、`is_delete`、`delete_time`、`purge_after` | 统一媒体元数据     |
| `media.rendition`   | `thumb_256`、`thumb_640`、`poster`、`proxy_720p`、`waveform`                                                                                                                                                                                                                             | 列表与预览性能     |
| 对象存储            | `projects/{pid}/{kind}/{yyyy}/{mm}/{id}.{ext}`；派生版本 `…/{id}/{rendition}.{ext}`                                                                                                                                                                                                      | 按项目前缀便于清理 |

`media_asset.upload_id text` 用于分片上传 ID；`sha256` 部分索引按 `project_id, sha256 WHERE NOT is_delete` 定义（DES-02）。

素材对象键固定为 `projects/{project_id}/{kind}/{yyyy}/{mm}/{id}.{ext}`，数据层校验键中的项目、类型和素材 ID 与记录一致；派生对象键位于该素材的 `…/{id}/{rendition}.{ext}` 前缀下。`media_asset.project_id` 关联项目；生成素材的 `(project_id, source_operation_id)` 只允许指向同项目操作；`rendition` 经父素材继承项目范围，读取与写入都先核对父素材及当前用户所在组织。

## 5. 异步与工作流

`MediaIngestWorkflow`（`media-ingest/{id}`）：`media.DetectAndProbe` → `media.Hash` → `media.MakeRenditions`（并行）→ `agent: moderation.check` → `flow.MarkMediaReady`。`media-purge` 每日清理。

## 6. 事件与实时

`media.asset_status_changed.v1` → realtime；SSE `media.updated`。

## 7. 界面

媒体库网格 / 列表切换（虚拟滚动）、筛选栏、搜索；拖拽上传区（多文件进度、失败原因）；预览（图片灯箱、视频播放器、音频波形）；详情抽屉（来源、合规、引用位置）。

## 8. 权限与审计

制作者；审计 `media.deleted`、`media.restored`。

## 9. 非功能要求

PERF-07（上传速度 ≥ 带宽 70%，处理 ≤ 30 秒）；PERF-04（2,000 条筛选 ≤ 1 秒）；SEC-06、SEC-07；CMP-03。

## 10. 测试设计

内容类型识别；分片上传续传；引用检查覆盖全部引用来源（表驱动）；清理任务。

## 本地画布接管切片

回环单工作区允许有界同步接管和明确的本地人工内容/使用权限确认，记录真实人工确认来源、主体、时间与 SHA256，不声称自动审核；未确认及需要真人授权的素材不能导入。格式与大小继续遵循 REQ-30 R1，图片/视频/音频上传成功、正式资产引用与刷新恢复必须真实验证。精确合同见 [工作台上传合同](工作台设计.md)。分片续传、云自动审核与真人授权计划按消费者合同接入和验收；物理清理与完整库/包的真实链路另按素材库设计验证。

上传专用业务校验使用真实探测宽高，单边上限 8192、总像素上限 40,000,000；以 int64 相乘，在 Renderer 调用前返回 `unsupported_media_type`，不改变生成媒体的探测与派生语义。

## 上传受理与安全

当前本机工作区上传消费在线 Swagger 中的 multipart 接口，携带正式 project scope、UUID 幂等键及显式本地人工审核确认；真实内容探测、SHA、私有接管和失败恢复遵守工作台上传合同，不能凭扩展名或客户端元数据放行。

消费者直传计划先登记 uploading 资产，再发限定 object_key、Content-Type、Content-Length 的预签名 PUT 或逐片 URL；完成受理后由 Go MediaIngestWorkflow 探测、ffprobe、生成衍生物、SHA 与审核，只有实际完成才进入 ready，拒绝/失败分别保持 rejected/failed 并推送媒体状态。分片阈值与片大小仍待确认，不把这一目标流程写成当前路由。

## 故障约束与专项验证

- 专项验证：300 MB 续传、伪装类型、审核不可用、2,000 条筛选与预览；对所有正式引用来源做删除保护和 30 天清理测试；验证浏览器链接不超过 1 小时，供应商取输入的只读单对象链接不超过 24 小时、不返回前端且签发记入调用明细。

- 伪装类型或审核失败素材被引用：保持素材不可引用并显示失败原因；修正文件重新上传，绝不把 processing 当 ready。
- 分片中断或清理任务误删被引用文件：保留续传记录；引用检查失败时暂停删除与清理，只在校验通过后重新执行。
