# 历史参考 · 个人与项目素材库设计

本设计定义同一 media owner 下个人与项目素材的归属、目录、完整查询、接管、清理与包合同。结构事实以 `backend/db/schema.sql` 为准；已接入入口与执行链分别验收；业务 owner、自动清理和供应商的后续接入计划见 BACKLOG。

## 1. 归属与边界

1. 复用同一 media owner，采用闭集 project/personal 归属；personal 的原件 project_id 可空、personal_actor_id/personal_org_id 必须同属当前 active actor/org，project 原件两个新增字段均空。Schema 中 identity.user 的 UNIQUE(org_id,id) 支持个人归属使用同组织用户复合 FK；该持有约束不替代每次当前 active actor/org 和 admin/producer 的授权复核。保留既有项目 FK、复合引用、历史 JSON/上传指纹/Copy nil 字节；普通项目读写/reference 永远拒 personal/空 project。个人返回专用 safe DTO，不将 uuid.Nil 作为合法项目。既有库增量升级先在隔离非 owner PostgreSQL 验证旧合同，再按 DES-02 §10 审阅执行。
2. library/folder/item 是实际分类、文本与目录元数据，不是隐藏项目或通用资源框架。个人扁平40字符目录、项目8层60字符目录、6种样式/4主题、5种分类、同级唯一、个人删除归未分类/项目空目录删除、原子200项移动全部保留。旧项目未有 metadata 时按真实媒体事实展示根目录默认项，不能迁出或复制旧原件来建立库；读空库不写业务数据。
3. 锁顺序统一当前 actor/成员→命令 advisory lock→workspace project UUID 排序→library UUID 排序→folder/media UUID 排序。项目库修改经 workspace 所属同事务 ProjectAccess/TouchContent 更新真实 project revision 与已消费 invalidation；个人纯元数据不递增任何项目。原项目 Copy 已先持项目锁，media library Freeze/Register/Verify 随后取库锁，禁止在库锁后反向取项目。目录 placement 的个人库锁仍按其既有独立合同，media 命令不取得它。
4. UploadService 扩展实际 closed scope，一套真实探测、规范化、审核、私有对象和未知恢复。新增字段 nil 时项目永久回执、SHA 和请求指纹逐字不变；个人键含 actor/org，无伪 project UUID。个人真人素材仍拒正式引用/转移，直到真实 consent owner 已接管，用户可编辑 portraitCertified 只作来源说明。不能靠该字段通过审核。
5. 加入项目与保存到个人库使用 media 同一 Transfer owning 消费者，实际冻结/读取/校验原件和全部衍生物，独立目标 UUID/私有 key，保留来源。源可见批量部分成功沿持久逐项子结果呈现，unknown 不换 key/id，未发布目标不进普通库。项目移除只退出目录可见关系，既有业务资产/历史引用保留；物理回收、删除是独立当前引用保护命令。跨组织、任意外链或原地改变原件归属不加入范围。
6. 分页前完成搜索、类别/类型/目录/收藏/30日/状态过滤和三排序，附 UUID 尾键；保留个人40/80/120与项目20/40/80的页码/总数操作，不用已加载列表筛选替代。可编辑文字、标签、备注、来源说明不覆盖真实媒体/生成来源/权利事实。角色/环境/道具正式版本继续由已接受 bible/reference 范围拥有，必要 owner 未就绪明确阻断，不能由库 metadata 伪造。
7. 物理清理仅聚合实际已经装配的 owning 引用模块，根明确注入当前/历史 canvas、timeline/director、workspace cover/style、operation、script 和活动 Copy/Transfer/package guard；后来业务 owner 装配时同步加入。无 owner 证据或坏引用停止，禁止扫任意 JSON/直接删 source key。统计实际保有独立对象，含回收/未知清理；未配置 limit 返回 null。不预建硬额度/计费 reservation 体系。
8. 兼容 assets.json v1 兼容 reader 与自有闭合 manifest 均验证完整资源；缺 blob 明确失败。包预算压缩500 MiB、展开2 GiB、2500项、manifest16 MiB、路径512字符，单原件仍遵其正式kind预算；拒绝路径穿越、symlink、重复名、CRC错误、外部关系和多层包。GIF/glTF 须通过真实闭集准入；不把扩展名转换或 metadata 导入冒充真实资源。
9. 素材库命令遵守 `backend/db/schema.sql` 的最小授权。媒体 Copy `FinishCleanup` 只授 media_asset 的 is_delete/delete_time/purge_after 三列 UPDATE，不授 DELETE、全表 UPDATE 或改变归属/object_key；隔离非 owner PostgreSQL 验证不能替代实际应用角色链路。

## 2. 媒体归属

同一 media owner 采用闭集 `project|personal`。项目原件保留 project_id 与复合引用约束；个人原件 project_id 为空，personal_actor_id/personal_org_id 以同组织用户复合 FK 绑定，不能携带项目执行的 source_operation_id。当前 active actor/org 与实际角色须逐次复核，个人归属不替代授权。

个人素材属于当前组织内当前个人；切换 org 不共享 namespace，不泄漏私有分类、收藏和备注。旧项目 UploadRequest 指纹、历史 JSON、Copy snapshot、永久回执的 nil 扩展保持原字节与 SHA，不能以 uuid.Nil 冒充合法项目。个人使用专用安全 DTO，普通项目 Reference 和 DocumentSources 拒绝 personal/空 project。

个人真人素材在真实 consent owner 接管前拒绝正式引用或跨库消费，portraitCertified 仅是来源说明。Canvas 的正式媒体闭集仍为 image/video/audio/model，plain text/document/entity 不因此进入媒体节点。

## 3. 数据与业务端口

Library 数据属于 media owner，不新增通用 Resource/EAV/目录框架。

### 3.1 Library、Folder、Item

- `media.library`：id、kind personal/project、org_id、personal_actor_id 或 project_id、revision、时间；closed ownership；每个人scope/项目各一个。此行承担该素材库命令串行锁和 CAS，不是新工作区或隐藏project。
- `media.library_folder`：id/library_id/parent_id nullable/name/name_key/position/style/theme/revision/时间。personal parent 强制空、40字符、无样式树；project≤8层、60字符、6style/4theme、父级同library，根用NULL，不用虚构ID。style=`glass|stacked|midnight|paper|cinema|compact`，theme=`aurora|obsidian|ember|pearl`，以项目 CSS 呈现。删除personalfolder原子解分类所有成员，删除projectfolder必须空。personal rename 不修改素材原件时间/内容 SHA。
- `media.library_item`：id/library_id、**互斥** media_asset_id 或 typed plain_text、title、category闭集5、folder_id nullable、position、tags、source_label、note、favorite（personal字段）、catalog_state active/trashed、trashed_at、revision、时间。同library同asset唯一。普通现有 project media row 尚无item时按legacy默认 title=file_name/category=material/root 展示；命令首次创建metadata row，不复制资产/伪造新原件。plaintext不是media.KindDocument，也不是script正文；文本复制/用户笔记有独立闭合正文预算，项目创作版本进入正式reference owner。
- 项目角色/环境/道具与 AssetVersion：消费 bible/reference 已接受模型及实际引用，不能把角色属性、prompt、未来operation结果塞 item metadata。项目页一键“新增版本”通过该 owner 冻结实际媒体引用并生成真实版本；缺该owner会返回明确 unavailable。文本/图片描述编辑仍可作为库描述动作保留，但会影响角色版本的必须经正式version命令。
- `media.library_command`：actor/key 唯一、org/library/action/请求hash、原始闭合response、审计时间，永久 INSERT-only；当前授权后 exactreceipt replay，metadata修订后旧key仍返旧回执，不重放动作。无须新增无消费者的 folder_changed topic；HTTP成功复用TanStack失效，必要引用/任务事件用现有实际链。

资源预算：title≤240字符、个人folder≤40字符、项目folder≤60字符、batch move≤200项；tags≤32项且每项≤64字符、note≤8000字符、plain_text≤64KiB、每命令JSON≤1MiB，均拒绝非法UTF-8/NUL。ArkID 说明字段不能供 provider 执行；操作性供应商绑定须由 catalog/bible 的 typed binding 合同拥有。

### 3.2 查询与动作

`LibraryQueries` 消费小端口读取 current actor + library scoped rows，返回安全 `LibraryItemSummary/FolderSummary/FacetCounts`，不出对象键、storageURL、用户同意正文或provider凭据。详情预览即时通过既有媒体owner短授权，document只有已实现attachment下载，不作为HTML预览。

完整服务端 filter：catalog_state、kind、category、folder（all/root/UUID）、favorite、recent30days、q；personal project筛选必须来自正式 transfer 来源/目标且逐一当前project授权，不能 可编辑 metadata.projectName 字符串冒充可读项目。搜索覆盖标题/标签/来源说明/备注/plain_text及MIME。排序 updated_desc/updated_asc/name_asc 在分页前执行，附 id 唯一尾键；name使用固定规范化collation并测Unicode，不能当前页 client.sort。查询total与scope facet含义分别明确，不混为过滤后总数。

页容量保留个人40/80/120、项目20/40/80，picker20/40/80；SQL 有界 offset 保留页码操作，cursor可供既有无限加载接口使用但不得因此删掉页码/总数。任一cursor封闭到 actor/org/library/filter/order；scope切换清缓存/选择/unknown intent。频繁搜索250ms可保留纯交互，AbortSignal取消过期取数，晚到响应不覆盖新scope。全选只当前页；“导出全部”另受理服务器完整有界快照。

`LibraryCommands` 具体命令 createText/updateMetadata/updateTags/setFavorite/recycle/restore/deleteRequest、Folder create/update/delete、MoveItems，均携带 expected_library_revision/实体 revisions 和 UUID key。批量move1..200全部身份/存在/CAS/目录复核同Tx，无部分移动。批量清理逐项持久子结果，不用前端顺序loop报全部成功。

永久清理使用独立 media purge owning 作业、逐项结果、对象 intent 和永久命令，不扩充 `media.status` 或授予 DELETE。`purged_at` 与可恢复 `trashed`、仅解除目录展示的 `removed` 分离。项目受理逐项核所有已装配业务及当前/历史画布引用；缺真实 owning 查询则503，引用 blocked 不先删除资产。接受清理的 reservation 阻断新绑定、历史 Copy、Transfer 与素材包重新受理；旧冻结事实不得回写。二进制只有实际原件及所有衍生物 Remove、核实不存在并关闭未知 I/O 后才标永久清理，SQL identity/摘要和物理 proof 保留。纯文本成功清空正文、标签、备注及来源说明，标题改为固定“已永久清理”，不保留私人标题作 tombstone。Library 列表/完整 Copy 排除已永久清理条目，旧不可变快照仍按原内容和已接受回执核验。该功能实现与隔离对象验证不授权浏览器永久删除业务数据；最终不可逆产品动作仍单独确认。

锁顺序必须固定：当前actor/成员复核 → 命令advisory锁 → 必要 workspace 项目UUID排序锁与既有guard → library UUID排序锁 → folder/media UUID排序和media.Reference；不要Copy worker已持target项目锁后反向取library。受理冻结catalogRevision、folder放置、目标scope及原件 facts，同一事务保存永久command；失去权限、deleted/copying project、broken guard、未知执行对象任何一项阻断。归档项目读可用、内容写禁止；未知角色拒绝，project写角色沿既有正式授权factory，personal仅本人当前org（不自行给admin跨人私库读取）。

### 3.3 上传和资源事实

保留 UploadService 一个实现，给实际消费增加 closed UploadScope 与授权/receipt接口；旧project方法与 request hash字节保持原样，personal key空间绑定actor/org，不许以ProjectID=nil走旧方法。复用原件/normalization SHA证明、prober、实际派生图、私有UploadIntents、PutIfAbsent、unknownCommit恢复与真正review；title/tags/category是库元数据，媒体Kind/SHA/dims/codec/origin/status不可由该编辑表单写入。

批量图片/视频上传最多4个并发，逐文件保留原 File/SHA/key；失败、重试、撤权与 unknown 保留真实阶段及可证字节进度。Drop/paste 只选输入，随后进入同一上传链。GIF/自包含 JSON glTF/GLB 的实际格式和资源预算遵守工作台媒体准入；未支持类型明确拒绝，禁止改扩展名后绕过探测。

## 4. 跨库接管

“加入项目”采用同组织内 source 冻结 → 实际私有 bytes/renditions 接管 → 新 target mediaID，保留来源个人库。从项目保存到个人库沿同一 closed Transfer；不得跨项目直接引用原 ID，也不引入任意外链、云盘、跨组织或原地改变原件归属。

最小 `MediaTransferJob` 位于media owner，模式 personal_to_project/project_to_personal（project_to_project若后续确证用户入口再启用），sourceLibrary/targetLibrary/items及目标目录、metadata策略/expected revisions、当前actor/永久UUIDkey、状态与子结果、目标ID映射、冻结manifest hash、attempt/fence、ObjectIntent。不是Operation/paidquote，也不是伪 WorkspaceProjectCopy。

受理同Tx复核双方ACL、目标active/无guard退化、源ready/passed、实际同意/版权许可与全部依赖、目标目录CAS；无网络IO，冻结每个原件及全部rendition的 ID/revision/SHA/bytes/MIME/codec/probe/只读origin provenance。原scope不可见ID统一404；published不足或revision冲突409；owning依赖不就绪503。源在队列后变更/删除/撤权必须执行前及发布前复核，不仅检查初始actor字符串。

实际 Go/Temporal activity 复用media项目Copy的 **小端口**（current owned open/稳定 objectintent/PutIfAbsent/sha核验/OwnReference验证），不复制一套完整业务Copy层。Transfer对每个字节实际SHA/bytes和全部rendition核验，生成独立targetasset/privatekey。原operation/provider/upload凭据不带入；保留AIGC与真正readonly来源/真实consent合法映射，模型Origin约束不能被擅改。未发布target不进普通列表/selector；取消/失败等对象清理确证后结束，不把不确定写入当失败重跑新ID。重放永久key无新对象、无新target行。

取消意图独立持久为 `cancellation_requested`，不能仅从当前 status 推导。取消受理之后发生未知 Put/清理结果，状态即使转为 needs_reconciliation 仍保留该意图；同 key 恢复和新 worker claim 只能继续原对象清理，不得恢复复制或发布。当前授权、永久回执、worker fence 与 cancellation_requested 同事务核验，清理结果真实确证后才进入 cancelled；未知结果不先报告已停止或已删除。该事实仅属于可变传输工作记录，不改不可变原件和历史来源。

源一次多选加入项目可部分成功：目标可每行稳定子结果，明确已成功/失败/未确认，整体不假回滚已发布部分；绝不让失败第二次创建一个新成功对象。target批次保存目录位置和source lineage不可依赖前端第二请求move。项目页“移除”只退出项目库目录关系，对已有正式使用的media不物理删；正式引用尚在时提示使用位置，物理删除另走引用保护。

主图个人picker、canvas/form/reference/media录入均在Transfer成功后消费target正式image/mediaID；点击浏览个人图不等于完成项目媒体授权。不将整个个人素材清单、收藏、笔记或文件夹复制进项目共享空间。

## 5. 回收、对象删除、容量与包

### 5.1 回收与删除

库列表回收不等于模型输出审核状态。 catalog_state 与 media.status/moderation分开；回收/恢复只控制库可见性，不能把processing/pending复原为ready。旧 ListReadyAssets/picker 需定义排除已回收库metadata，legacy无entry仍可见；已有冻结业务引用是否仍可读由现有Media eligibility判定，不用目录删除撤销正文/输出内容授权。

永久删除必须通过media owning ReferenceChecker聚合实际已实现的canvas当前/历史资源、Operation冻结输入/输出、项目/导演封面、timeline、script source、正式bible/storyboard/audio/edit、以及Copy/Transfer/Package活跃快照。不能由任意JSON全文猜引用；未支持的实际owner或损坏引用会503阻断。被使用返回409及当前调用者有权看到的安全用途；不吐跨项目私有名称。聚合端口根显式注入，无通用跨模块SQL。

对象清理同现有intent/fence；记录到期策略但“30天自动清理”只有真实worker/重放/故障/cancel/当前引用门禁通过后才算完成。清空回收站是有界持久批处理，pending引用保留并报逐项错误；新引用与删除命令持相同media锁，不能先删对象再写DB。failed cleanup/unknownObject必须保留真实状态/恢复原key。

清空全部复用上述正式清理作业，每个作业最多200项，不增加父作业、另一套清理协议或独立服务。页面先无筛选读取当前库全部回收项，完整核对分页总数、唯一身份、当前scope及库/项目revision；一次明确人工确认冻结全部目标与逐项CAS。每个计划最多2000项、10个子批次，持久意图JSON最多1MiB，只保存scope、UUID、CAS、子幂等键及结果，不保存正文、对象键或私有URL；超预算明确拒绝整个计划并提示分批操作，不截断后宣称清空。子批次在本次明确确认的前台会话串行受理，前一批实际终态后才继续；页面转后台、卸载或授权失效立即停止。每批前重新读取全部回收项，仅能接受已核实由本计划成功清理或取消释放造成的revision变化。出现外部新增/修改、残留目标CAS变化或身份scope变化即停止，重新核查并再次人工确认。blocked/cancelled保留逐项结果且不自动重试，unknown停止并沿原子键显式对账/取消；刷新恢复只显示计划与当前作业，必须明确点击继续并再次核查，禁止自动发起下一批。恢复中的计划锁定关闭、Escape及外部点击；原作业未确定终态前保留原意图，只允许沿原键控制。用户明确结束计划后才能重新审阅另一批目标。持久服务器子作业负责真实结果与恢复，页面计划不将顺序请求等同于物理清理全部成功。

### 5.2 容量与生成历史

容量按当前有权owning scope的已持有唯一原件/renditions对象计算，含trash尚未清理的实际bytes，重复库链接不重计；Transfer的实际副本按新的真实对象计入。quota从已装配策略读取，未配置返回limit=null/不可用，绝不复制本地5GiB显示为服务端上限；硬额度控制计划在额度策略明确后接入；实施时须锁定 reservation 与 unknown 对象，不能仅展示容量仪表。

生成历史接正式Operation输出和可读媒体来源，分日/type/time分页，下载与回收动作仍同Library owner。不会将计费/operation状态/凭据写进可编辑library metadata；sourceeditable“生成任务”label只能表示用户说明，不能造一条正式生成历史。系统音频提取/时间线/depth仍有各自真实job来源，另以origin筛选明确呈现。

### 5.3 素材包

兼容素材v1 (`assets.json`/files) 做具体兼容reader，自有新manifest须closed kinds/items/folders/files/sha/probe及完整ID映射；项目完整包不复用“我的素材包”伪装全部项目。包丢 blob/缺 entry不静默跳过。旧storageKey仅作为包内映射键，不作为目标对象路径；旧asset IDs/time/project labels/Ark/portraitCertificate不构成目标权限/事实；任何外部http/dataURI只按明确支持的包内预算规则处理，不主动远程抓取。

包预算：压缩文件≤500MiB、最多2500entries、展开≤2GiB、单媒体不超既有Kind预算、文本/manifest≤16MiB、路径长度≤512、根文件唯一，ZipSlip/absolutepath/symlink/duplicateentry/CRC/多层嵌套拒绝。document DOCX另遵守已接受4096entries/64MiB expanded/16MiBpart/XML预算，与包总体预算分开；不是把所有文件用扩展名转换。包出口按完整scoped快照实际读取SHA匹配bytes且提供attachment，入口有界staging→逐文件真实probe/review→发布闭合集，未知结果按原key恢复。

GLTF 多文件/外部纹理、entity/角色 version 及 unsupported 类型须明确返回有类型的错误；GIF 动画遵守全部帧校验合同，不能导入metadata而称素材完整可用。正式document应保存TXT/DOCX原件，script正文只有本owner接管后实际extractor生成；其他文本条目保留plain文字不虚构文档文件。

## 6. 完整项目 Copy

ProjectCopy 必须实际复制项目所有ready/passed媒介（含document）与rendition、独立privatekey，清upload/provider/operation事实、实际sha/bytes核验；素材库不能绕过该owner，也不能在worker持target项目锁后反向取library锁。

新 `ProjectLibraryContent` 由media owner提供 Freeze/Map/Verify/Attach，Freeze在Copy受理Tx读项目library/folders/metadata/reference heads的不可变snapshot。根ProjectCopy admission先取得source/targetproject锁，再按library UUID顺序取锁，Register target媒体后同Tx绑定映射的目录/库条目，Publish重新检查actualmedia/reference/folderclosure。个人分类/favorite/私有备注不在项目content snapshot。Copy不带任务/费用/个人raw身份。

完整项目库快照包含回收目录条目、纯文本正文以及所有合法二进制条目的元数据。二进制条目声明的原件由 media 自己并入 Freeze 的实际资产选择；软删除但仍保有的原件须核实 owning revision、delete_time、purge_after、ready/passed 和真实字节后复制全部原件与衍生物，目标目录条目保留 catalog_state/trashed_at。已物理清理、缺失或不完整的原件必须拒绝整个受理，不得静默省略条目后发布。这个内部 Copy 证明不扩大普通素材读取与引用权限，也不扩大 Script 历史文件读取的 document 闭集；既有无库内容的快照、哈希和回执仍按 nil 合同保持字节兼容。

设定集不可变历史也可能引用已经退出素材目录、回收或软删除的 image/audio。由 bible owner 在当前授权事务中提供完整、带 revision/SHA/byte_size 和 rendition ID/SHA 的类型化历史事实，根协调者只转换端口类型；media 的 `FreezeWithReferenceFacts` 与独立 `ProjectCopyReferenceQuery` 负责接管，不允许客户端任意声明事实或根直接读写异模块 SQL。旧 `FreezeWithReferences` 的 UUID 列表继续仅接受 Script document，不能借此扩大普通读、引用或下载权限。新历史保留声明闭集增加 `DeclaredBy="reference"`，既有空值和 `library` 声明、无扩展快照、请求指纹及永久回执字节保持兼容。

Copy 受理中的 Freeze 只取得 owning SQL 事实、锁和确定的完整 ID 映射，不执行私有对象网络读写；尚未核验的对象事实不能视作复制成功。Transfer 与 Register/Publish 前须由 media owner 对实际 source 和独立 target 的原件及冻结衍生物执行完整 bytes/SHA 核验。source 或 target 缺失、损坏、审核撤销、权限改变或历史 retained proof 不完整时拒绝整个发布；不靠“有库条目”推定正文或媒体已接管，也不复制第二份相同对象来绕过该 owner。组合冻结顺序为 media → Script scope 映射计划 → Bible 全部历史 → Script 全部历史 → Canvas，跨模块映射由各 owner 提供确定的 typed port，禁止通用 UUID 替换。

扩展字段 nil/omitempty确保既有无library Copy snapshot、请求hash与永久receipt逐字兼容；source metadata schema未知/不完整folderparent/跨scopeasset/非法正文/缺roleowner一律unsupported_copy_content，不发布空壳。Map只改声明的project/library/folder/媒体/正式reference identities，内容/版本SHA如何重算交实际拥有它的owner；不能root generic rewriteUUID改变immutable事实。旧project没有LibraryEntry时target仍由已复制媒体提供legacy默认列表，不能因缺目录扩展把历史Copy回执重放判错。

整项目archive/delete/restore/copying/failed/cancelled必须同时定义library普通查询可见性，归档readOnly，deleted/copying不可读，未发布target失败不变正式空白库。Transfer/Package活动加入现有project guard factory，未知执行/退化也阻断回收；不能只登记一个不被消费的flag。

## 7. 模块边界与真实验收

库、传输、素材包与清理逻辑属于现有 media 的 domain/application/adapter，跨模块仅消费实际所需的小端口；结构维护在同一 Schema，不预建通用 Importer、插件框架或存储微服务。

前端查询、目录、元数据、回收、传输与素材包使用 `components/media/library-*`，实际 personal/project picker 消费安全查询和 Transfer。Next 页面保持薄职责，TanStack cache 包含 origin/actor/org/library/filter/order；只交互区放 Client Component，低频 GLB/包操作按需加载，菜单与弹窗遵循项目组件体系。

实际验收必须包含：

1. 非ownerPG role显式 currentactor+org+project ACL；跨个人/组织/项目ID404，未知角色/archived写拒，撤权后receipt不泄漏，error不会写audit成功；永久samekey同体逐字重放/异体409，过期retained旧receipt兼容。
2. 全库≥3页，搜索/三种排序/filters在分页前生效，tie稳定不重复漏项；total/facets定义明确，当前页全选；网络晚到/切org/未知写身份隔离；390px键盘focus和实际媒体lazy decode。
3. personalfolder删全部成员保留原件且unclassified；project8层边界、环/跨库/同级重名/非空delete/混合移动200完整CAS、HTTP未知字段拒绝、RowsAffected0/外层rollback保证不半提交。
4. 图片/视频/音频/GLB/TXT/DOCX经真正SHA人工review和私有object读取；批量部分失败/unknown重放原key不新target；必要GIF/GLTF既有源功能独立actualprobe gate，未过不得报完整。
5. 个人→项目Transfer真实byte+全部rendition SHA等同、新ID/新privatekey；doubleclick/reload/retry/权限变化/删source/unknownPut/cancel清理/fence到期/目标folderCAS；目标可正式Reference/cover/canvas；个人来源和source项目内容不动。

7. 回收/恢复/永久删/清空全部逐项真实结果，引用与删竞态、history/activeOperation/Copy/Transfer/Package guard故障与unknown阻断；对象清理真实确证后计费容量下降，不拿隐藏列表当物理删除通过。

真实验收分别覆盖已装配 owning 引用、实际私有对象、媒体准入、Copy 与包往返。静态检查、组件测试、fixture 和当前简单列表不能替代这些真实链路；计划补齐自动 30 天清理、后续实体/供应商接入与消费者部署，并分别验证引用保护、恢复和真实运行。
