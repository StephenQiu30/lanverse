# 历史参考 · PRD-02 产品能力与架构原则

当前范围由[当前页面字段](../../requirement/浮光页面/index.md)与[现有工作台](../../requirement/当前工作台页面与工具.md)维护。本文的跨功能原则用于已存在或经评审的功能；历史MVP/V2归类不自动成为实施范围。

## 1. 制作链与用户能力

整部剧的导入、分集、结构解析、原文追溯、设定集与锁定参考、镜头/版本、图片/视频生成、配音、引用传播和成本是结构化制作链。全能参考按实际模型能力接受图片、视频与音频，不将注册表声明当真实供应商支持证明。

自由画布与流水线并重，共享正式业务身份；画布支持资源、生成、编辑与业务视图，连线表达输入/参考。表单、批量、画布和Agent使用同一模型配置、素材、Operation、候选与正式选定。

## 2. 统一生成与模型能力

- 每次生成表达为能力、模式、模型/价格版本、闭合参数和有序带用途输入，产出版本化结果。
- 模型注册表声明能力、模式、参考上限、参数schema、价格和adapter键；表单与报价从同一schema校验，不由节点手写供应商协议。
- 结果/状态由任务持有，人工配置/选择由用户命令持有；迟到结果不能覆盖新配置或正式选定。
- 图片编辑、首尾帧、参考音频等按实际模型支持验证；费用、用量、产物和取消/未知恢复均独立成立。

## 3. 结构化事实与视图

镜头、角色、造型、分集、媒体及其不可变版本是一等业务对象；画布节点保存布局、明确编辑输入和授权业务引用。画布不成为镜头、角色、任务、费用或对象URL的第二事实源。候选/选定/input hash支持版本比较与过期标记，任务不能自动替用户选定。

## 4. 命令、执行与合规

UI、Agent和未来开放接口调用同一套当前权限、幂等、版本校验的命令。付费生成必须明确报价/确认；Agent提案不得绕过人工确认或直接操作数据库/供应商。

Operation的调度、重试、等待、对账和人工核验由Temporal持久编排，工作流由Go维护；AI执行是明确Activity。模块职责见 [DES-01](../design/01-系统架构设计.md)、[生成执行设计](../design/生成执行设计.md) 与 [工作台设计](../design/工作台设计.md)。

媒体带上传/生成来源、Operation关系、内容SHA、审核、版权和真人授权事实。模板/模型声明、浏览器checkbox、mock或技术门禁不能代替真实授权、审核与供应商证明。

## 5. 未来和未决范围

项目快照、模板、协作、开放接口和完整对话式Agent等旧设想仅保留在历史参考。当前画布工具、3D、深度与时间轴按实际输入、配置和作业承载；不预建无消费者的框架，技术原型也不冒充真实完成。
