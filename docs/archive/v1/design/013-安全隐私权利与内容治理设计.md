# DES-013 安全、隐私、权利与内容治理设计

- 状态：proposed
- 版本：v1.0
- 日期：2026-08-14
- 关联需求：CUR-SEC-FR-001～010、CUR-SEC-NFR-001～012；CUR-IAM-FR-006～009；CUR-PLT-FR-004/005/007/008/010
- 关联验收：AC-CUR-SEC-001-A～AC-CUR-SEC-010-B
- 上游：[CUR-SEC](../requirement/012-安全隐私权利与内容治理需求.md)、[DES-003](./003-身份Workspace与权限设计.md)、[DES-012](./012-平台Capability与Provider耐久任务及媒体设计.md)

## 1. 问题、范围与非目标

### 1.1 问题

平台会处理未发布剧本、Prompt、真人参考、生成媒体和 Provider 外发。“有权访问 Workspace”不等于“该固定资源在当前用途可以生成/导出”，技术能调用 Provider 也不等于其数据保留、训练和地域策略符合产品准入。治理决定必须固定对象/版本/用途/政策/时间，不能用页面缓存或一次预检永久放行。

### 1.2 范围

- 数据分类、用途绑定和 Provider 最小化外发；
- 权利登记/证明/撤销/到期/用途决定；
- 文本/图片/视频的内容检查、人工复核与申诉；
- Provider DataProcessingProfile 准入与定期复核；
- AIGC 来源/交付标识决定，但不修改原始视频；
- 媒体、权利证明、Secret、下载、回调和审计保护；
- 保留、数据导出/删除、legal hold、安全/滥用事件。

### 1.3 非目标

- 不提供法律意见、自动判定版权归属或替代人工复核；
- 不建企业 DLP、通用工单/审批平台、公开滥用透明中心或法务案件系统；
- 不因未实现成片而删除 AIGC 来源/交付标识需求；
- 不通过转码、水印或重编码修改原始候选；所需标识只进 Manifest/README 或独立元数据；
- 不以安全硬上限、保留策略或内部成本构建商业套餐。

## 2. 事实所有者与模型

Governance 是下列事实的唯一所有者：

| 实体 | 关键事实 | 版本/不变式 |
| --- | --- | --- |
| DataClassificationPolicy | 数据类别、允许用途、最小化、存储/外发/日志策略 | 政策版本化；新版不改历史决定 |
| RightsSubject/Scope | 权利对象、范围、用途、地域、期限、约束 | 稳定身份 + 追加版本 |
| RightsEvidenceVersion | 证明媒体引用、来源、提交者、效力时间 | 不可变；撤销/过期是新事实 |
| RightsDecision | 对固定资源/版本/用途/时点的 allowed/warning/blocked/evidence_required | 追加；有决定来源和政策版本 |
| ContentPolicyVersion | 分类、处置、自动/人工策略、适用范围 | 不可变版本 |
| ContentCheck/Decision | 固定输入 hash、purpose、policy、checker、结果/blocker | 追加；输入改变后不适用 |
| ReviewCase/Decision | 补证/复核/申诉范围、状态、审查者、依据 | Case 可变状态；决定只追加 |
| DataProcessingProfile | Provider 地域、保留、训练、子处理者、删除、加密、复核日期 | 版本化；过期/未知不 active |
| ProvenanceDecision | 固定输出/导出用途的 AIGC 来源/标识要求 | 追加；Snapshot 固定决定引用 |
| RetentionPolicyVersion | 数据类别、业务引用、保留/删除/匿名化策略 | 版本化；不是一个全局天数 |
| DataSubjectRequest/DeletionCase | 导出/删除请求、影响图、blocker、执行/证据 | 耐久状态机；幂等 |
| LegalHold | scope、理由类别、授权者、期限 | 只追加启用/解除决定 |
| AuditRecord | actor/service actor、Workspace、action、稳定目标/版本、结果、关联、时间 | 只追加、脱敏；不是普通日志 |
| SecurityCase | 报告、安全限制、证据摘要、处置/恢复 | 只追加决定；不改业务主选 |

Identity 拥有用户/成员/会话；Platform 拥有 Provider 技术配置、Task、Media、Lineage、Cost；业务模块拥有候选/主选/导出。Governance 可阻断新副作用或附加当前风险，但不修改已完成 Task 终态、历史 Candidate/Selection/Snapshot。

## 3. 数据分类、最小化与保护基线

### 3.1 分类提案

| 级别 | 例子 | 默认处理 |
| --- | --- | --- |
| Restricted | Provider/API/DB/Storage Secret、授权头、签名 URL、会话令牌 | 仅 Secret Manager/KMS 或内存短期使用；日志/审计/前端永不记录 |
| Sensitive | 未发布剧本/Prompt、真人媒体、权利证明、原始生成媒体 | 私有存储、用途绑定、最小化外发、短期访问、分类保留 |
| Internal | Task/Attempt/Cost、稳定 ID、脱敏诊断 | Workspace/最小权限；不公开 |
| Public-by-user | 用户明确发布的信息 | 只在后续发布范围接受后使用；当前不推断公开 |

每个跨网络或持久化边界使用 `DataUseEnvelope`：`classification`、`purpose`、`subject/resource version`、`allowed fields`、`processor`、`policy version`、`expires_at`。分类/用途未知时 fail closed。

### 3.2 Provider 输入最小化

Provider Mapper 使用 Capability 明确 allowlist 构建输入，不序列化整个 Project/Workspace 对象。例如视频生成只传固定 Prompt 投影、必需媒体字节/短期 Provider 获取能力和受控参数；不传成员资料、完整权利证明、无关剧本或平台内部签名 URL。生成前将实际字段集合与 DataUseEnvelope 写脱敏审计摘要。

### 3.3 加密与 Secret

- 公网/内部服务/对象存储传输统一 TLS；服务间身份和证书策略由部署 ADR 固定；
- PostgreSQL 和对象存储托管 at-rest 加密；Restricted/权利证明的应用层 envelope encryption 是安全 PoC 候选；
- KMS 管理密钥，Secret Manager 保存 Provider/DB/Storage 凭据；代码/数据库/事件只保存 reference、版本和脱敏状态；
- 轮换先双版可读/新版写入，验证后撤销旧版；轮换失败不自动放宽授权。

## 4. 统一治理门禁

### 4.1 Gate 输入/输出

```text
EvaluateGovernance(
  actor, workspace, purpose, fixed resource/version refs,
  capability/provider profile version?, policy time
) -> allowed | warning(confirmations) | blocked(blockers) | unavailable
```

返回包含 `decision_set_id`、每资源权利/内容/Provider 决定引用、政策版本、input hash、评估时间、有效期、blocker/warning 和 next action。unavailable 对新外部副作用 fail closed。

### 4.2 必须同步重检的边界

| 边界 | 必须重检 | 失败语义 |
| --- | --- | --- |
| AI 预检 | 权限、数据分类、权利、内容、DataProcessingProfile | 可显示 blocker；零外发 |
| AI 正式 submit | 重读固定输入、全部决定和配置版本 | 旧预检不继续；零 Provider 副作用 |
| Media ready | 实际字节安全、内容结果、来源/权利 | quarantined/blocked，不可新引用 |
| 新主选/重新确认 | Candidate/Media 版本、当前 purpose 决定 | 零 Selection 变更 |
| Export Preflight/Freeze | 每个固定输入、AIGC 标识、时点决定 | Freeze 再检失败时零 Snapshot |
| 原始媒体/包下载 | 当前 Membership、purpose、rights/security/hold | 不签发或统一不可用 |

历史 Candidate/Task/Snapshot/Manifest 的事实不因后续 blocked 被删改；新生成、重建和下载按当前政策处置并显示风险/人工下一步。

## 5. 权利登记、决定和复核

### 5.1 同步命令

| 命令/Query | 输入 | 输出/冲突 |
| --- | --- | --- |
| RegisterRightsEvidence | 对象/版本、scope/purpose/region/time、证明媒体、幂等键 | 新证据版本；不改旧决定 |
| RevokeRightsScope | scope、expected revision、理由类别 | 撤销事实 + Impact Outbox；零历史篡改 |
| EvaluateRights | 固定 resources、purpose/time/policy | 逐项 Decision/blocked/unavailable |
| RequestReview | 决定、输入 hash、补证、幂等键 | ReviewCase 或原 Case |
| DecideReview | Case、固定输入/政策、reviewer、expected revision | 追加决定；输入改变则过期冲突 |

### 5.2 状态

```text
Rights evidence: pending_validation → valid → expired | revoked | superseded
Rights decision: allowed | warning | evidence_required | blocked | unavailable
Review case: open → awaiting_evidence → under_review → decided | withdrawn
                                  └→ stale_input（新版本需新决定）
```

复核决定限定对象/版本/用途/期限，不是 Workspace 全局放行。审查者角色、冲突回避、处理时限和首发政策由安全/产品评审关闭；未决定时不预建多级审批。

## 6. 内容检查与 Provider 数据准入

### 6.1 ContentCheck

检查器使用版本化 Adapter，输入为固定文本 hash/私有媒体版本和 purpose，输出只保存受控类别、置信度/证据摘要、policy/checker version、decision 和 next action。普通日志不保存原文/原媒体或完整检查响应。

```text
requested → checking → allowed | warning | blocked | review_required | unavailable
```

检查依赖 unavailable 时新 submit/freeze fail closed；不因切换 Provider 绕过。自动检查不能产生法律结论；产品允许的 warning/review 路径必须有文字原因、修改/补证/申诉动作。

### 6.2 DataProcessingProfile

Capability active 前必须关联未过期 Profile，至少记录：合同/政策证据版本、存储/处理地域、保留期、是否用于训练及是否可关闭、子处理者、加密、删除方法、安全联系与 `review_due_at`。未知或过期时敏感输入不外发。

Provider 公开文档是证据之一，不代替实际账号/地域配置、合同或定期复核。

## 7. 媒体、下载、回调与应用安全

### 7.1 媒体入站

- 上传意图固定 Workspace、purpose、允许类型/大小/数量和过期时间；分片完成后仍重检总大小/hash；
- 实际 magic type、完整解码/ffprobe、像素/时长/轨道、压缩炸弹/资源消耗限制和受控恶意样本必须通过；
- 解析器在无权网络、最小文件系统和 CPU/内存/时间限制下运行；不安全媒体保持 quarantined；
- 原始文件名不参与对象路径；导出文件名/ZIP/CSV 做 traversal、路径碰撞、公式注入和 Unicode 正规化防护。

### 7.2 访问能力

对象存储全部 private。短期 URL 在签发时验证当前 Membership、action、Workspace/MediaVersion、purpose、GovernanceDecision、range/disposition；超时后必须重签。高风险权利证明和下载可使用服务端代理以支持更强撤销/审计，由威胁模型/性能 PoC 决定。

### 7.3 其他高风险边界

- Provider 下载防 SSRF：协议/host allowlist、DNS/IP 重验、禁内网/metadata、重定向/大小/时间上限；
- Webhook：签名、timestamp/nonce、replay window、body 上限、Provider/Task 关联、Inbox 去重；
- Web/API：Secure/HttpOnly/SameSite Cookie、CSRF、CSP、输出编码、结构化输入校验、登录/搜索/下载/高成本 action 限流；
- 依赖与镜像：锁文件、SBOM、漏洞/恶意包扫描、签名镜像、最小运行权限；
- 管理/诊断 Query 使用独立 action、最小字段、分页、限流和审计，不建万能数据搜索。

## 8. AIGC 来源与导出交接

`EvaluateProvenance` 按首发地区/用途、Capability/Provider、固定 Candidate/Media 血缘和 PolicyVersion 返回：必需 Manifest/README 字段、展示文本、证据引用或 blocked。

Export Preflight 展示要求，Freeze 时重读并在 ExportSnapshot 固定 ProvenanceDecision/PolicyVersion。PackageBuild 只把固定字段写入 Manifest/README；原始视频字节、扩展名和音轨不变。必需标识无法形成时导出 blocked，不静默转码。

## 9. 数据保留、导出、删除与 legal hold

### 9.1 分类保留

保留不使用一个全局天数。RetentionPolicy 至少区分：源剧本/Prompt、权利证明、原始/派生媒体、Task/Provider/Cost 证据、Export Package 字节、ExportSnapshot/Manifest 摘要、Audit/SecurityCase、备份。保留条件同时考虑活动业务引用、对账/申诉、删除请求、SecurityCase 和 LegalHold。

`retention_at` 是当前执行计划，不是不可变历史。到期时必须重检引用/hold；包字节可 expired，但需保留的 Snapshot/Manifest 语义不被改写。

### 9.2 数据请求工作流

```text
requested → identity_verified → discovery → blocked | scheduled
scheduled → executing → verification → completed
                         └→ partially_failed → executing
```

Discovery 建立对象/版本/媒体/备份/外部 Provider 的影响清单，检查唯一 owner、活动 Task/unknown、业务引用、legal hold、审计/安全保留和 Provider 删除能力。每个执行项有幂等键、证据、retryable 和 target date。

- 无 blocker 的数据导出在 24 小时内形成可查询处理状态；
- 删除/匿名化在 30 日目标内完成，或返回新 blocker 和日期；
- 历史 actor 可替换为受控匿名标识，不把历史动作改写为别人；
- 备份中已删数据按备份保留自然过期，恢复演练后重放 deletion tombstone，不将数据重新暴露；
- Provider 删除无可靠契约时在 Profile 中明确 blocker，不伪造 completed。

## 10. AuditRecord、诊断与 SecurityCase

### 10.1 审计边界

必须审计：身份高风险动作、成员/会话/owner 变化、Provider 外发/取消/重试/对账、权利/内容/复核决定、媒体登记/下载、主选、Export Freeze/下载、删除/hold、SecurityCase 和越权拒绝。

AuditRecord 不存密钥、授权头、签名 URL、完整剧本/Prompt、权利证明原文、人脸/声纹媒体或 Provider 原响应。日志清洗失败时宁可丢弃非必要详情，不泄露。

审计表使用只追加应用端口、限制 UPDATE/DELETE 的数据库角色和独立备份；是否增加 hash chain/WORM 由威胁模型和监管需求决定，不在未有威胁证据时伪造防篡改声明。

### 10.2 SecurityCase

```text
reported → triaged → protecting → investigating → resolved
                                             └→ monitoring
resolved → reopened
```

用户报告返回 Case ID、当前保护状态和 next action，不要求粘贴凭据。紧急限制只针对固定 Workspace/对象/能力/动作并有时限；恢复时追加新决定，不删原事件或自动修改业务主选。

## 11. 事件、失败恢复与不变式

Governance 发布最小事件：`RightsScopeChanged`、`GovernanceDecisionChanged`、`ProviderDataProfileChanged`、`RetentionPlanChanged`、`DeletionCaseChanged`、`SecurityRestrictionChanged`。事件只携带 Workspace、固定目标/版本、decision ID、purpose、schema version 和关联，不携带证明原文/媒体。

| 失败 | 行为 | 恢复 |
| --- | --- | --- |
| 权利/内容依赖 unavailable | 新副作用 fail closed，历史可读 | 恢复后重做当前决定；旧预检不复活 |
| 决定通知丢失 | 页面可延迟，高风险动作不依赖投影 | 游标恢复/轮询；正式边界同步 Query |
| Review 期间输入改变 | 决定标 stale_input | 为新版本重新检查/复核 |
| Provider Profile 过期 | Capability review_required | 重新核验 Profile 后才 active |
| 删除 Worker 中断 | Case 保持逐项证据 | 幂等继续，不重复删/伪 completed |
| Audit 写入失败 | 高风险动作零副作用；普通读可继续 | 修复审计依赖后重做命令 |
| KMS/Secret 不可用 | 新登录/外发/敏感下载 fail closed | 恢复密钥访问，不回退明文配置 |

不变式：

1. 治理决定必须固定 Workspace、对象/版本、purpose、policy version、来源和时间。
2. 任一必需决定缺失/过期/unavailable，新 Provider submit、主选、Export Freeze 或原始下载不成功。
3. 治理决定变化不改写历史 Task/Candidate/Selection/Snapshot/Cost。
4. active Capability 的 DataProcessingProfile 未过复核期。
5. quarantined/blocked 媒体不可进入新主选/导出。
6. 治理命令幂等，决定/审计只追加，重复通知不产生矛盾决定。

## 12. 可观测性

- Metric：gate result/reason、decision age、review queue age、Profile 过期、quarantine 数/age、短期访问签发/拒绝、Webhook 验签/重放拒绝、KMS/Secret 错误、DeletionCase age/blocker、SecurityCase state；
- 告警：cross-workspace 成功必须为 0；门禁 unavailable 不能回退 allowed；active Provider Profile 过期数为 0；高风险动作审计缺失数为 0；
- Trace 关联 request、actor/workspace、resource/version、purpose、decision_set、policy/checker/profile version、Task/Media/Selection/Export/Audit；
- 诊断字段使用稳定 ID/分类码，不用证明原文、Prompt、媒体或签名 URL 作 label/普通日志。

## 13. 验证与安全 Gate

| 需求/验收 | 必须证明 |
| --- | --- |
| FR-001 / AC-001-* | Provider 实际外发字段只含 allowlist；分类/用途未知时零外发 |
| FR-002 / AC-002-* | 真人证据缺失阻断；撤销在 Freeze 再检零 Snapshot；历史不变 |
| FR-003 / AC-003-* | hard blocker/unavailable 在 Provider 前 fail closed；切换 Provider 不绕过 |
| FR-004 / AC-004-* | 补证/复核限定固定输入和用途；输入改变旧决定不自动适用 |
| FR-005 / AC-005-* | 会训练且不可关闭的 Profile 阻断敏感输入；过复核日期不外发 |
| FR-006 / AC-006-* | Snapshot 固定标识决定；Manifest/README 与原视频字节分离；无法形成则 blocked |
| FR-007 / AC-007-* | 包字节过期不篡改 Snapshot；删除工作流在 24h/30d 目标内返回真实状态/blocker |
| FR-008 / AC-008-* | 伪 MIME/损坏/超硬上限不 ready；过期/跨空间媒体访问泄露数 0 |
| FR-009 / AC-009-* | 审计串联 actor/决定/Snapshot 且敏感值 0；Provider 原错误仅转受控错误/诊断 ID |
| FR-010 / AC-010-* | 报告返 Case ID/保护状态；恢复是新决定且不改主选 |
| NFR-001～012 | 全边界门禁绕过 0、跨空间 0、敏感日志 0、决定 100% 追溯、≤5s 可见、数据生命周期、Provider 准入、媒体安全、审计、WCAG、幂等恢复和加密/轮换 |

### 13.1 必做测试

- 威胁模型：Workspace 边界、Provider 外发、上传/下载、Webhook、画布深链/Agent、导出 ZIP/CSV、诊断和备份恢复；
- 自动安全：IDOR/跨空间、CSRF/XSS/CSP、SSRF/DNS rebinding、Webhook 伪造/重放、伪 MIME/解析器沙箱、ZIP slip/CSV injection、限流；
- Secret/privacy 扫描：源码、Git history、镜像、日志、Trace、Metric、Audit、前端错误和导出包；
- 恢复：决定依赖宕机、KMS/Secret 不可用、审计写失败、Review/Delete Worker 重启、备份恢复后 tombstone 重放；
- 人工评审：首发地区/用途政策、权利证明字段、Provider Profile、Review 角色/时限、AIGC 交付标识和保留分类。
