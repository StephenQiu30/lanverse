## 1. 模块定位

CUR-PLT 定义所有当前业务模块共同依赖的 Capability、WorkTask、ExecutionAttempt、Provider 交互、MediaArtifact、LineageRecord 与内部 CostRecord 产品质量：外部能力是否真实可用，长任务是否可恢复，媒体是否已持久化和校验，输入到输出是否可追溯，以及外部请求是否重复/已产生消耗和失败下一动作是否可解释。身份授权由 CUR-IAM 拥有，权利、内容、隐私、保留和审计决定由 CUR-SEC 拥有；CUR-PLT 只消费其固定门禁结果并提供必要执行上下文。

本文不规定技术框架、数据库、队列、对象存储或部署形态。下游 Design 可以在不改变用户可观察语义和验收条件的前提下选择实现。

### 1.1 用户价值

- 创作者在提交外部生成前，知道能力是否可用、输入是否符合要求和是否将产生外部请求；项目工作台不要求维护预算、币种或成本上限；
- 提交后关闭页面、断线或工作进程重启，任务仍能回到真实状态；
- 失败时用户知道是否已发送到 Provider、是否产生消耗、是否可安全重试；
- 任何候选、主选和导出文件都能追溯到固定输入和生成证据；
- CUR-IAM/CUR-SEC 未授权、已撤销或跨空间资源不会被执行层误用；
- 系统内部失败可由受控证据定位，无需让用户提供密钥、完整 Prompt 或敏感媒体。

### 1.2 成功指标

| 指标 | 目标 | 测量条件 |
| --- | --- | --- |
| 重复提交外部副作用 | 同一幂等命令不产生第二次 Provider 消耗提交 | 超时、刷新、重复点击、重复消息、执行进程重启各一次 |
| 任务恢复 | 长任务不依赖原浏览器会话恢复到服务端事实 | 关闭页面、重启执行者、重复回调与断线恢复 |
| 可导出媒体完整性 | 100% 可导出文件具有持久化位置、大小、类型、可复核 hash 和来源 | 真实文件与受控持久媒体故障注入 |
| 权限隔离 | 跨 Workspace 不可读取、引用、预览、选择或下载 | 用户读取、业务命令、异步处理和临时下载能力全覆盖 |
| Provider 消耗证据收敛 | 每个终态外部任务均能解释是否提交、供应商返回的用量/计量证据和 unknown 后处置 | 成功、失败、取消、unknown 后人工处置 |
| 用户可解释性 | 任务/导出失败都返回受控错误、可否重试和 next action | 功能验收的每个失败分支 |

## 2. 范围与非范围

### 2.1 范围

1. 真实 AI Provider 能力目录、可用性和生成前预检；
2. 服务端长任务事实、实际尝试、取消、重试、对账和 unknown 处置；
3. 请求、任务、外部提交和包生成的幂等与恢复；
4. 上传/生成媒体的私有持久化、探测、hash、短期访问和存储失败恢复；
5. 剧本、资产、ShotSpec、关键帧、候选、主选和导出文件的版本与血缘；
6. Provider 返回或平台测得的内部用量/计量证据、重复提交保护和 unknown 对账；该证据不形成项目预算功能；
7. 消费 CUR-IAM 授权和 CUR-SEC 治理门禁，在外部副作用/媒体访问前重新校验；向 CUR-SEC 提供最小审计上下文；
8. 对当前业务用例必要的 Provider/在途容量保护、真实降级、诊断关联与状态可观察性。

### 2.2 非范围

- 模型市场、任意 Provider 插件市场或用户自定义代码适配器；
- 自托管 GPU 调度、模型训练、微调、数据标注平台或通用 AI 编排引擎；
- 套餐、订阅、充值、支付、发票、客户账单、退款和会计对账；
- 把内部成本统计扩展为商业计费中心；
- 任意资源类型的通用审批引擎、企业 DLP 或复杂多级管理组织；
- 为延期的 Timeline、Render、成片或发布预建通用能力。

## 6. 详细功能需求

### 6.1 CUR-PLT-FR-001 真实能力与生成预检

**用户目标**：在提交会产生 Provider 消耗的生成之前，知道所选能力是否可用、输入是否完整、有哪些限制、预计消耗和需要显式确认的风险。

**前置条件**：用户对目标 Project/Episode/Shot 有 editor 或 owner 权限；业务模块已产生固定输入版本。

**主流程**：

1. 用户选择图片或视频生成用途；
2. 系统显示经验证的可用能力、输入类型、受控参数、限制和不可用原因；
3. 用户提交固定业务输入与参数，系统同时验证版本、权限、权利、媒体、参数、容量和预计消耗；
4. 系统返回 blockers、warnings、预计消耗、预检有效期和需要用户确认的项目；
5. 预检不创建生成任务、预占或外部副作用。

**失败/边界**：

- 凭据存在不等于能力可用；模型权限、地域、额度、参数和计量未验证时必须显示 unavailable；
- 能力配置在预检后变化时，正式提交必须重新检查；
- 任何依赖未知时不得返回“通过”；
- 未经验证的价格不得用虚构数字代替。

**UI/交互**：默认使用创作语言展示限制与 blocker；Provider 原始参数、运行地域和配置版本放入高级详情。高成本或权利风险必须使用显式确认，不得预勾选。

**验收条件**：

- AC-CUR-PLT-001-A：Given 能力未经真实账号验证，When 用户查看能力或预检，Then 显示稳定不可用原因，不返回伪参数/伪价格，不创建任务或成本记录；
- AC-CUR-PLT-001-B：Given 一项固定输入不满足能力限制，When 预检，Then 返回定位到字段/资源的 blocker 和修复动作；
- AC-CUR-PLT-001-C：Given 预检已通过但配置版本变化，When 提交，Then 拒绝旧预检且不产生外部副作用。

### 6.2 CUR-PLT-FR-002 幂等提交与快速返回

**用户目标**：确认生成后快速获得一个可恢复的任务，不因重复点击、网络超时或刷新被重复收费。

**主流程**：

1. 用户提交预检输入、幂等标识、预期固定版本和所需确认；
2. 系统在接受命令时重新验证当前事实；
3. 系统一致保存不可变请求、长任务、预占和待执行意图；
4. 接口在外部生成完成前返回任务 ID、初始状态和下一动作；
5. 同一幂等标识与相同输入只返回原事实。

**失败/边界**：同一幂等标识但输入不同必须冲突；事实与待执行意图任一保存失败时整体不可见；接口超时后客户端先使用幂等标识查询/重试，不自行换标识。

**UI/交互**：点击提交后立即进入服务端任务状态；不用纯前端倒计时伪造进度；用户重新打开页面时从服务端恢复。

**验收条件**：

- AC-CUR-PLT-002-A：Given 同一幂等标识和输入，When 连续点击、超时重试和重复消息，Then 只有一个业务请求和最多一次相应外部提交；
- AC-CUR-PLT-002-B：Given 同一幂等标识但固定输入不同，When 提交，Then 返回冲突并保留原事实；
- AC-CUR-PLT-002-C：Given 事实保存中任一步失败，When 命令完成，Then 不产生半个任务、孤立预占或无任务的执行意图。

### 6.3 CUR-PLT-FR-003 任务查询、取消、重试与对账

**用户目标**：任务始终展示真实状态，只在无双重外部副作用风险时重试。

**主流程**：用户可按 Project/Episode/Shot/类型/状态查看任务；任务返回 canonical 状态、可验证阶段、尝试摘要、脱敏错误、是否可重试和下一动作。取消必须区分本地已接受、Provider 已接受、不可取消和结果已完成。failed 任务只在已确认没有成功副作用时允许创建带 predecessor 引用的新 WorkTask/ExecutionAttempt；原 failed Task 不逆转。unknown 必须先对账，无法确认时进入 manual_attention。

**业务规则**：

- Task 不等于队列消息，Attempt 不等于轮询次数；
- `unknown` 不得伪装为 failed 后自动重发；
- 任务终态不得由前端修改；
- canonical 终态仅为 succeeded、failed、cancelled、manual_attention；unknown 是待对账状态，不是终态；
- 取消后 Provider 仍返回成功结果/消耗时，必须记录真实结果而不是丢弃；
- 单镜头失败不会改变同批其他任务的终态。

**验收条件**：

- AC-CUR-PLT-003-A：Given 执行者在任务运行中重启，When 服务恢复，Then 从 Task/Attempt 事实继续或进入可解释 unknown，不重复外部发送；
- AC-CUR-PLT-003-B：Given 任务已取得 Provider 任务 ID 但未完成，When 用户点击重试，Then 系统先查询/对账，不创建新的 Provider 消耗提交；
- AC-CUR-PLT-003-C：Given queued 任务尚未产生 Attempt，When 取消，Then 任务进入 cancelled、预占只释放一次，重复取消只回读原结果；
- AC-CUR-PLT-003-D：Given unknown 任务，When 无法取得可靠 Provider 证据，Then 保持 unknown/人工处理，不自动重发。

### 6.4 CUR-PLT-FR-004 媒体持久化、完整性与受控访问

**用户目标**：候选和导出文件不因 Provider 临时 URL 过期或存储切换丢失，且只能被有权用户访问。

**主流程**：对上传或生成结果，系统先把字节保存到受控位置，校验声明大小/类型/hash，探测真实规格，再登记可用媒体版本。预览/下载每次按用途与权限发放短期能力，永久 URL 不得成为业务事实。

**失败/恢复**：

- Provider 成功但下载失败时，有 Provider 任务 ID 的只重试下载/登记，不重新生成；
- 对象已写入但业务登记失败时，保留隔离证据并幂等补偿；
- 探测失败不删除原字节，但媒体不得进入正式主选/导出；
- 存储位置切换必须在新位置大小/hash 验证后生效，失败不改变媒体业务身份；
- 临时访问能力过期后必须重新申请，不改变媒体版本。

**验收条件**：

- AC-CUR-PLT-004-A：Given Provider URL 即将过期，When 媒体成为 Candidate，Then 字节已在受控存储中持久化，可以在 Provider URL 失效后预览；
- AC-CUR-PLT-004-B：Given 字节 hash 与声明不同，When 完成登记，Then 不产生可用 MediaArtifact，返回可恢复错误；
- AC-CUR-PLT-004-C：Given 一个跨 Workspace 用户拿到媒体 ID 或过期链接，When 尝试访问，Then 无法获得字节或探测详情；
- AC-CUR-PLT-004-D：Given 存储迁移在验证新位置前失败，When 用户继续访问，Then 原位置仍有效，MediaArtifact ID/hash 不变。

### 6.5 CUR-PLT-FR-005 版本与血缘

**用户目标**：能理解一个候选/主选/包文件使用了哪些固定输入，并在上游变化时知道影响。

**业务规则**：

1. 每个可重现输出必须固定输入版本和内容摘要；
2. 候选必须关联业务请求、实际尝试、能力配置、媒体版本和固定 ShotSpec/资产/关键帧；
3. 主选决定必须固定候选与当时业务输入；
4. 导出快照必须固定目标 StoryboardBaseline/OrderRevision、ExportScope、有序 Shot ID、每镜 ShotSpecVersion、VideoSelection、Candidate、Media 字节版本/hash、重新确认/warning、冻结人和时间；
5. 历史输出的血缘不得随“当前版本”指针变化；
6. 上游变化只产生影响/stale，不静默改写下游历史。

**UI/交互**：默认显示“来源摘要”（镜头、角色/场景/道具、关键帧、模型、生成时间）；高级详情可查稳定 ID、版本和 hash，但不显示密钥或敏感原响应。

**验收条件**：

- AC-CUR-PLT-005-A：Given 一个已选视频，When 查看来源，Then 可追溯到固定 ShotSpec、资产/关键帧、任务/尝试、能力配置与媒体 hash；
- AC-CUR-PLT-005-B：Given 上游资产切换当前版本，When 重新计算影响，Then 旧主选显示 stale，但旧 Candidate/历史包的血缘不变；
- AC-CUR-PLT-005-C：Given 一个输出缺少任一必需来源，When 尝试设为主选或冻结导出，Then 被明确阻断。

### 6.6 CUR-PLT-FR-006 Provider 消耗证据（非项目预算功能）

**用户目标**：在成功/失败/取消/unknown 后理解请求是否已外发、是否可能产生 Provider 消耗和是否可以安全重试；不建立项目预算、币种、成本上限、客户计费与支付体系。

**主流程**：预检说明是否会外发和能力计量方式；提交记录不可变用量意图；Provider 返回后追加其可核验计量证据；失败/取消记录是否已外发；unknown 保留待对账标识。普通项目工作台只显示“未外发/已外发/待对账”和安全下一动作，不显示预算编辑、币种或金额汇总面板。

**业务规则**：Provider 提供用量/金额时使用精确单位和来源版本，只追加不改写；未提供可靠计量时记录 unavailable，不自行估价；unknown 必须显示原因和对账状态；不对外语义化为预算、币种设置、余额、套餐、订单、发票或客户应付。

**验收条件**：

- AC-CUR-PLT-006-A：Given 任务成功且 Provider 返回用量证据，When 查看任务诊断，Then 可查单位、值、来源版本和关联 Attempt；项目工作台不出现预算/币种输入。
- AC-CUR-PLT-006-B：Given queued 任务未发送就取消，When 查看任务，Then 明确显示“未外发/无 Provider 消耗证据”，且重复取消不产生第二记录；
- AC-CUR-PLT-006-C：Given 任务处于 unknown，When 查看任务，Then 显示“可能已外发/待对账”，不伪造零消耗或安全重试；
- AC-CUR-PLT-006-D：Given 用户查看消耗诊断，When 打开明细，Then 看不到 Provider 密钥、完整原响应或跨 Workspace 记录，也没有项目预算编辑能力。

### 6.7 CUR-PLT-FR-007 消费统一授权与治理门禁后执行副作用

**用户目标**：只有在 CUR-IAM 当前授权与 CUR-SEC 当前治理决定均允许时，固定业务命令才可产生 Provider 提交、媒体访问、主选所需媒体引用或导出构建副作用。

**主流程**：业务模块提交 actor、Workspace、固定对象/版本、用途、动作与预检摘要；CUR-PLT 在预检和正式副作用前重新读取 CUR-IAM AuthorizationDecision 与 CUR-SEC RightsDecision/ContentSafetyDecision/ProviderDataProcessingProfile 等必要决定引用；全部 allowed 且版本有效才继续，并把决定关联到 WorkTask/ExecutionAttempt/MediaArtifact/CostRecord。

**失败/边界**：决定不存在、过期、版本不匹配或依赖不可用时 fail-closed；跨 Workspace 返回统一不可用；撤销阻止新的副作用但不改写历史 Task/Cost/Media。CUR-PLT 不登记权利证明、不创建治理决定、不提供法律结论，也不得从 Provider 是否接受反推内容合规。

**验收条件**：

- AC-CUR-PLT-007-A：Given CUR-SEC 对固定参考媒体的 RightsDecision 已过期，When 提交 Provider 生成，Then CUR-PLT 在外发前阻断并返回决定引用/下一动作，不产生新预占或 Attempt；
- AC-CUR-PLT-007-B：Given 治理预检通过后决定被撤销，When 正式提交，Then 重新读取并拒绝旧结果；
- AC-CUR-PLT-007-C：Given 历史 Task 完成后治理政策变化，When 查看历史，Then Task/Cost/Media 事实不被篡改，新访问或副作用按 CUR-SEC 当前决定处理；
- AC-CUR-PLT-007-D：Given 跨 Workspace 对象 ID，When 预检、媒体访问或任务命令，Then 统一拒绝且不暴露对象详情。

### 6.8 CUR-PLT-FR-008 向 CUR-SEC 提交最小审计上下文并保护敏感数据

**用户目标**：Provider/任务/媒体/成本动作能够由 CUR-SEC 审计串联，同时普通日志、诊断和事件不泄露创作内容或凭据。

**主流程**：在 Capability 核验、Provider 提交、取消/重试/对账、媒体登记/位置切换和成本调整时，CUR-PLT 向 CUR-SEC 提交 actor、Workspace、动作、稳定目标/版本、结果、时间、Task/Attempt/Media/Cost/诊断关联和必要原因枚举；CUR-SEC 创建并拥有 AuditRecord。CUR-PLT 只保存稳定 AuditRecord 引用（如业务恢复需要），不复制审计正文。

**禁止内容**：明文凭据、授权头、临时签名 URL、完整剧本、完整 Prompt、证明文件原文、人脸/声纹媒体和 Provider 完整原响应。上游清洗失败时宁可缺少非必要诊断，不得泄露。

**验收条件**：

- AC-CUR-PLT-008-A：Given 一次 Provider 提交后完成媒体登记和成本结算，When CUR-SEC 查询审计，Then 可通过稳定引用串联 Task/Attempt/Media/Cost，CUR-PLT 不存在第二份 AuditRecord；
- AC-CUR-PLT-008-B：Given Provider 失败响应含凭据/Prompt，When 查看普通日志、事件、指标或前端错误，Then 只出现受控错误和诊断 ID，敏感值出现数为 0；
- AC-CUR-PLT-008-C：Given CUR-SEC 审计写入暂不可用，When 高风险新外部提交，Then 按 CUR-SEC 门禁 fail-closed；只读任务查询仍可用并明确审计依赖不可用。

### 6.9 CUR-PLT-FR-009 容量保护与真实降级

**用户目标**：当 Provider、执行容量或依赖不可用时，得到真实限制和等待/修复动作，而不是伪成功、无限排队或未知数量被显示为零。

**业务规则**：Provider/Capability 的已验证并发与额度、当前在途量由 CUR-PLT 负责并返回真实 accepted/waiting/blocked；各业务模块拥有其真实样本签认的产品容量与 UI 预警，CUR-SEC 拥有防滥用/解析风险的安全硬上限。三类边界必须分别命名、显示来源和下一动作，不得把商业额度、产品容量、UI 预警或安全硬上限混写。依赖故障进入 unavailable/partial failure，不冒充为“无任务/无成本/已完成”；批量命令按目标返回结果并允许局部重试。

**验收条件**：

- AC-CUR-PLT-009-A：Given Workspace 已达在途上限，When 再提交，Then 在 Provider 调用前返回稳定限制、当前使用和下一动作，不产生新预占/外部任务；
- AC-CUR-PLT-009-B：Given 项目概览中任务摘要依赖失败，When 查看概览，Then 显示 partial failure/unavailable，不把数量当作 0 或已完成；
- AC-CUR-PLT-009-C：Given 20 个镜头的批量命令中 3 个预检失败，When 返回结果，Then 17 个可按业务规则提交，3 个返回独立 blocker，不建立一个伪全局终态。
- AC-CUR-PLT-009-D：Given 业务模块 UI 预警已触发但未达到产品容量，且 Provider 在途容量仍可接受，When 用户确认合法范围，Then 系统可继续；Given CUR-SEC 安全硬上限触发，Then 不允许用户确认绕过。

### 6.10 CUR-PLT-FR-010 脱敏诊断与支持交接

**用户目标**：在不泄露创作内容或凭据的前提下，为一个失败提供稳定诊断关联，并让受控支持人员串联请求、任务、尝试、媒体、消耗和审计。

**主流程**：用户错误界面显示错误摘要、next action、可复制的脱敏诊断 ID 和发生时间；支持人员经受控权限查询同一 Workspace 下关联事实；默认查询不返回剧本正文、完整 Prompt、媒体字节或凭据。

CUR-CAN 只消费 WorkTask、ExecutionAttempt 摘要、Media/Lineage/Cost 与 next action 作为独立叠层，并通过同一任务查询/命令交接执行取消、重试或对账；画布不得编辑 Task 终态、伪造进度或把 AgentActionProposal 当作已执行事实。

**验收条件**：

- AC-CUR-PLT-010-A：Given 一次媒体登记失败，When 用户提供诊断 ID，Then 受控支持可关联 Task/Attempt/隔离对象/错误和审计，但普通用户不可读取内部敏感详情；
- AC-CUR-PLT-010-B：Given 诊断 ID 属于其他 Workspace，When 查询，Then 返回统一不可用结果，不泄露关联事实；
- AC-CUR-PLT-010-C：Given 用户复制错误信息，When 检查内容，Then 不包含凭据、授权头、完整 Prompt、临时 URL 或 Provider 完整原响应。

## 7. 状态机与不变式

### 7.1 长任务

```text
queued → running | cancelled
running → waiting_external | succeeded | failed | cancelled | unknown
waiting_external → succeeded | failed | cancelled | unknown
unknown → succeeded | failed | manual_attention
```

- canonical 终态仅为 `succeeded`、`failed`、`cancelled`、`manual_attention`；`unknown` 不是终态，`reconciled_to_*`、`manual_resolution` 等同义值不得出现；
- canonical 终态不可被普通命令逆转；
- failed 只有在错误明确可重试且无成功副作用时允许创建带 predecessor 引用的新 WorkTask/ExecutionAttempt；原 Task 保持 failed；
- unknown 不允许盲目新 Attempt；
- 进度使用可验证阶段，不按等待时间伪造百分比。

### 7.2 媒体

```text
pending_bytes → stored → probing → ready | quarantined | failed
ready → unavailable | archived
unavailable → ready | archived
archived → ready（仅显式恢复且重新校验通过）
```

`retry_store_or_probe` 是允许动作而不是状态；安全重试形成新探测/存储尝试，不回写失败证据。只有 ready 媒体可新建为主选/导出输入。archived 媒体仍可为已有历史引用重现，但不得新建引用。

### 7.3 消耗证据

```text
estimate（非账本）
submit → reserve
provider_result → settle + release_remainder
cancel/fail_before_use → release
later_correction → adjust
```

结算、释放和调整只追加，不修改原预占或原供应商证据。

| CUR-PLT-NFR-005 | 媒体完整性 | 所有可主选/可导出媒体 100% 具有可复核大小、类型、探测规格和内容 hash；校验未完成不得 ready |
| CUR-PLT-NFR-006 | 隔离 | 通过用户读取、业务引用、异步任务、临时访问能力和导出全链路验收，跨 Workspace 成功读/写数为 0 |
| CUR-PLT-NFR-007 | 安全/隐私 | 凭据、授权头、临时 URL、完整 Prompt/剧本和敏感原媒体在普通日志、前端错误、指标和提交给 CUR-SEC 的审计上下文中出现数为 0 |
| CUR-PLT-NFR-008 | 可观察 | 请求、Task、Attempt、Provider 任务、MediaArtifact、CostRecord、导出快照和 CUR-SEC AuditRecord 通过稳定关联可串联，指标维度不使用用户/Prompt/对象 key 等高基数值 |
| CUR-PLT-NFR-009 | 可访问性 | 满足 WCAG 2.2 AA；状态、错误、治理阻断、成本和恢复动作不仅靠颜色表达；任务查询/取消/重试/对账和错误复制支持键盘完成；非 CUR-CAN 列表路径完整可用 |
| CUR-PLT-NFR-010 | 可扩展边界 | 增加第二个 Provider 不得引入第二套用户 Task、媒体、成本或主选事实；在第一个真实 Provider 闭环前不验收通用插件化 |

## 10. 异常目录与恢复

| 异常类别 | 用户语义 | 允许的恢复 | 禁止行为 |
| --- | --- | --- | --- |
| CAPABILITY_UNAVAILABLE | 能力未验证/停用/地域或额度不可用 | 切换已验证能力、等待启用、修正输入 | 用存在 Key 伪装 active |
| VERSION_CONFLICT | 预期固定输入不再是当前 | 查看新版本/影响并显式重试 | 覆盖旧版本或忽略 stale |
| EXTERNAL_STATE_UNKNOWN | 无法确认 Provider 是否已受理/完成 | 使用稳定 Provider 证据对账或人工处置 | 自动重发 |
| MEDIA_NOT_READY | 字节、探测、hash 或位置未完成 | 重试下载/存储/探测/登记 | 作为主选/导出输入 |
| RIGHTS_BLOCKED | 固定资源在当前用途/时间不可用 | 更新权利范围/证据或替换资源 | 默认通过或用旧预检结果 |
| CAPACITY_LIMITED | 当前在途或 Provider 容量已满 | 等待、减少范围、切换已验证能力 | 无限排队或伪失败 |
| COST_UNVERIFIED | 计量/价格未验证或结算待对账 | 停止 Provider 消耗提交、对账、人工处置 | 伪估算、伪释放或覆盖旧记录 |
| DEPENDENCY_UNAVAILABLE | 摘要/门禁/诊断依赖暂时不可用 | 显示 partial failure、重试查询、保留已有事实 | 显示 0/已完成/通过 |

### 12.1 已决策

- CUR-PLT 只拥有 Capability、WorkTask、ExecutionAttempt、MediaArtifact、LineageRecord 和 CostRecord；不建设第二套任务/媒体/成本，不拥有 RightsDecision、AuditRecord、数据生命周期或内容治理终态；
- 不把 Provider 临时 URL 当作 Candidate/导出文件的长期位置；
- 不在无真实外部契约时伪造参数、价格、取消或对账能力；
- Provider 消耗证据只用于防重复外发、unknown 对账和受控诊断，不扩展为项目预算、币种、成本上限、套餐、支付、客户账单或商业运营；
- 延期的时间线、成片与发布不得驱动当前平台抽象。
- CUR-CAN 只投影 CUR-PLT 事实并调用相同任务命令；画布/Agent 不得编辑 Task 终态或绕过预检与治理。

## 13. 术语

| 术语 | 定义 |
| --- | --- |
| Capability | 经当前真实契约验证、可提交某类业务生成的能力版本 |
| Task | 用户可查询、可恢复的一次长工作事实 |
| Attempt | Task 内一次真实执行/外部发送尝试 |
| unknown | 系统无法确认外部副作用是否已发生，必须对账/人工处置的状态 |
| 幂等标识 | 用于识别同一业务命令重试的稳定标识；不允许同键异输入 |
| 预占 | 提交时为可计量任务保留的内部消耗上限，不是客户付款 |
| 血缘 | 输出到固定输入、任务/尝试、能力配置和操作者的可追溯关系 |
| fail-closed | 权限、权利、能力、成本或完整性无法确认时，默认不允许新外部副作用 |
